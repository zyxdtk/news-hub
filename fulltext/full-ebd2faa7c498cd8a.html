摘要

我们研究了在四块 L4 GPU 上离线运行整个求解器最多十二小时的条件下，哪些训练和校准数据能帮助三个开放模型解决 ARC-AGI-2 任务。我们在公开任务上离线比较数据，并报告了在 120 个隐藏半私有任务上的 189 次运行。对于 NVARC Qwen3-4B 网格模型，我们构建了一个包含 12,000 条类型化语言可执行规则和 95,993 个任务的语料库；一条规则仅当其在固定探测集上的行为签名与所有已接受规则不同时才被接受，一个任务仅当其对能反驳最近竞争规则候选列表并击败 12 个捷径求解器时才被接受。在 1,920 条真实任务记录上继续微调，在所有四块 GPU 上以修订调度运行，将半私有分数从 28.96（发布模型均值）提升到 33.06（五次运行均值，最佳 34.86）；没有任何用合成任务训练的检查点（包括在全部 95,993 个语料库任务上训练的检查点）优于真实任务模型。对于 Qwen3.8-27B 推理模型，我们在其 1,036 条最终答案与已知输出匹配的自身推理轨迹上进行微调，并将该集合与添加其他模型轨迹和合成任务的集合进行比较。通过围绕模型构建的推理程序（在服务引擎内强制执行思考上限、每次回答后编写 Python 程序并在演示上检查、每个输入进行长首次尝试），分数从 26.81 上升到 44.03，即 ARC Prize 基金会在无时间限制下为基模型测量的水平（42.36）；大部分增益来自推理程序。对于 Qwen3.8-Flash-Next 混合专家模型（125B 参数，6B 激活），GPU 内存限制了并发性。通过路由加权激活显著性将每层专家从 512 剪枝到 384，使键值缓存从 0.55M 增长到 1.39M token；一个用 ARC 训练任务的路由统计适配并保留程序 token 专家的 296 专家列表，加上 FP8 索引器缓存，达到了 1.96M。借助检查程序的工具，该模型得分为 56.67，这是我们的最佳结果。

1 引言

ARC-AGI-2 要求求解器从少量演示对中推断网格变换并将其应用于新输入 [1, 2]。其隐藏任务在固定计算机上评分：求解器在四块 NVIDIA L4 GPU 上无互联网访问运行最多十二小时，覆盖 240 个隐藏任务 [2]。在此预算下，2025 年报告的最佳私有集分数为 24.03%，由 NVARC [3] 取得。在此设置中的求解器必须小型或快速。本文讨论模型在运行前学习或校准所用的数据，以及这些数据相对于服务和调度变化所能解释的测量增益。

我们使用了三个符合预算的开放模型：NVARC Qwen3-4B 网格模型（输出答案网格并在测试时对每个任务重新训练）[4, 5]；密集 Qwen3.8-27B 推理模型 [6]（在回答前思考数万个 token）；以及 Qwen3.8-Flash-Next 推理模型 [7]（一个混合专家模型，125B 参数中每 token 激活 6B）。对于每个模型，我们在公开任务上离线比较训练或校准数据，并在 120 个隐藏半私有任务上比较主要配置（共 189 次运行）。

我们的贡献如下：

  • 具有可识别性检查的 12,000 条签名不同规则语料库（第 3 节）。每条规则是一个类型化程序，仅当其在 220 个探测网格和 352 个类型化槽位上的行为签名与其他所有规则不同时才被接受，95,993 个任务中的每一个仅当其生成时对能反驳最近竞争规则候选列表并击败 12 个捷径求解器时才被接受。该语料库包含一组覆盖从 $1\times 1$ 到 $30\times 30$ 每种网格尺寸的 1,000 个任务，为下文实验提供了合成数据，包括 Qwen3.8-27B 微调实验中的 2,231 个合成任务（第 5.5 节）。

  • 网格模型的真实和合成训练数据（第 4 节）。我们比较了 NVARC 4B 在 1,920 个真实任务上的继续微调与两种 FORGE50 配方、形状平衡课程和在规则语料库上训练的检查点（表 18）。在真实任务上微调将半私有分数均值从 28.96 提升到 31.72，在所有四块 GPU 上以修订调度运行微调模型将其提升到 33.06（最佳 34.86）；没有任何用合成任务训练的检查点（单独或与真实任务模型并列）提升了均值。

  • 推理模型的答案验证自轨迹（第 5 节）。我们在 1,036 条自生成的答案与已知输出匹配的轨迹上训练 Qwen3.8-27B，通过闭包、循环和放弃过滤器选择，并将该集合与后续添加第二轮或更短轨迹、规则解释、程序目标、更难样本、其他模型轨迹和合成任务的集合进行比较（表 9）。围绕微调模型我们构建了推理程序：思考上限在服务引擎内强制执行，每次回答后编写的 Python 程序在演示上检查，每个输入的长首次尝试在任何第二次尝试之前启动。分数从 26.81 上升到 44.03，即 ARC Prize 基金会在无时间限制下为基模型测量的水平；大部分增益来自推理程序，部署调度的离线验证与半私有分数匹配。

  • 专家剪枝的校准数据（第 6 节）。我们通过路由加权激活显著性 [8] 将 Qwen3.8-Flash-Next 从每层 512 个专家剪枝到 384 个，然后到 296 个，用 ARC 训练任务的路由统计交换最少使用的专家并保留程序 token 的专家。编码校准的显著性列表和 ARC 路由频率列表选择了实质上不同的专家，仅按频率选择的列表丢失了准确性。剪枝、FP8 索引器缓存和更大的缓存预留使键值缓存增长了 3.6 倍，Qwen3.8-Flash-Next 达到 56.67，这是我们的最佳分数。

  • 固定预算分析（第 8 节）：每输入的 token 约束了分数，在 token 上限处强制给出的答案很少正确，在演示上检查的程序给出了高精度的第二答案。

  • 不成功和不完整的实验（附录 A 和 B）。我们报告了超参数和没有帮助的变体及其测量结果，包括我们拒绝的 16 个专家列表和 Qwen3.8-Flash-Next 的检查点（表 21）。

2 背景

2.1 ARC-AGI-2 及其评估协议

ARC 任务 [1] 由几对彩色网格演示对（最多 $30\times 30$ 个单元格，十种颜色）和一个或多个测试输入组成；求解器必须产生每个测试输入的精确输出网格。ARC-AGI-2 [2] 提供 1,000 个训练任务和 120 个公开评估任务（172 个测试输入），并保留 240 个隐藏任务：120 个半私有和 120 个私有任务。求解器可以对每个测试输入给出两次尝试，分数为正确回答的测试输入比例的任务均值。隐藏任务通过在四块 NVIDIA L4 GPU（每块 24 GB）上无互联网访问运行求解器最多 12 小时来评分 [2]。一次运行覆盖 120 个半私有和 120 个私有任务 [2]；按公开评估集每任务 1.43 个测试输入计算，这大约是 340 个输入。在四块 GPU 上使用 FP8 键值缓存和多 token 预测服务时，Qwen3.8-27B 每秒生成约 490 个 token，十二小时内约 21M token，每输入约 62K token，因此每个输入可以进行长首次尝试但不能进行同等长度的第二次尝试。我们用 K 和 M 表示千和百万 token；思考上限为整千（56K 上限为 56,000 token）。我们报告 120 个半私有任务上的分数，即半私有分数（SP）；撰写时私有分数不可用。

2.2 合成任务

ARC 训练集很小，2024 年和 2025 年最高分的系统在生成任务上训练 [9, 3]。re-arc [10] 为 ARC-AGI-1 训练任务提供程序化生成器，产生已知规则的新实例。BARC [11] 让 LLM 从种子程序编写新生成器程序，并用它们训练程序编写器（归纳）和直接输出网格的模型（转导）。NVARC [4] 大规模生成合成谜题并在 3.26M 增强样本上训练其网格模型。我们的生成器（第 3 节）不同之处在于每条规则是一个类型化程序，其在固定探测网格集上的行为必须与其他所有规则不同，每个任务由精确 oracle 重放。

2.3 网格模型和测试时训练

ARChitects [5] 微调 LLM 以文本形式输出网格，在测试时对每个测试任务的演示再次训练，在概率截断下通过深度优先搜索采样候选，并按多个对称视图下的似然排序 [12]；该系统在 ARC-AGI-1 私有集上达到 53.5 分 [9]，其 2025 年系统用掩码扩散模型 [13] 替换了自回归模型。Akyürek 等 [14] 表明增强留一任务的测试时训练（TTT）提高了 ARC 上的少样本准确率。NVARC 遵循 ARChitects 的设计，使用最多 4B 参数的 Qwen3 [15] 网格模型，在合成谜题加上 RE-ARC、ConceptARC [16] 和 MINI-ARC 上训练，并使用秩 256 的逐任务 LoRA TTT。它在 2025 年隐藏 ARC-AGI-2 任务上报告了 27.64%，基于 Qwen3-4B-Thinking-2507 构建的发布模型后来达到 29.72%。我们称此发布模型为 NVARC 4B（qwen3_4b_grids15_sft139）。在 ARC 数据上从头训练的小型递归网络 HRM [17] 和 TRM [18] 采取了不同的路线；TRM 以 7M 参数在 ARC-AGI-2 公开评估集上达到 7.8%。

2.4 ARC 的程序

代码训练的语言模型从自然语言规范编写程序 [19]。Greenblatt [20] 从 GPT-4o 为每个任务采样多个 Python 程序并保留那些能重现演示的程序。BARC 的归纳模型直接编写程序，SOAR [21] 在其自身搜索轨迹上微调程序编写器。重现所有演示的程序在测试输入上仍可能出错，因此测试上的精确度与演示完美程序的比例同样重要。

2.5 推理模型和拒绝采样微调

推理模型在答案前产生长思维链 [22]。在模型自身正确解决方案上训练（通过检查最终答案选择）是 STaR [23]、拒绝采样微调 [24] 和 ReST [25] 背后的思想。在 ARC 上检查是精确的：仅当轨迹的最终网格等于已知输出时才保留轨迹。Qwen3.8-27B [26, 6] 是一个 64 层的密集 27B 模型，其中 48 层使用 Gated DeltaNet 线性注意力 [27]，16 层使用全注意力，以及一个我们用于投机解码 [30, 31] 的多 token 预测头 [28, 29]。其聊天模板暴露了推理努力设置。ARC Prize 基金会在无十二小时预算的半私有集上测量了基模型：xhigh 下 42.4%，每任务 $0.45，low 下 22.8% [32]。我们用 vLLM [33] 服务它，并将权重量化为 FP8 或 NVFP4（一种 4 位浮点格式，每 16 个值块有 FP8 尺度 [34, 35]，与 Rouhani 等 [36] 的微缩放格式相关）。

2.6 混合专家模型和专家剪枝

稀疏混合专家层用许多专家和将每个 token 发送到少数几个专家的路由器替换前馈块 [37]；Switch Transformers 将每个 token 路由到一个专家并在固定每 token 计算下扩展专家数量 [38]，DeepSeekMoE 添加每个 token 都使用的共享专家 [39]。计算随激活参数增长，而内存随所有参数增长。专家剪枝在训练后移除专家。Lu 等 [40] 通过层输出在校准数据上的重建损失选择保留的专家，Li 等 [41] 在路由统计指导下合并专家。REAP [8] 通过门控值乘以其输出范数（在被路由到该专家的 token 上平均）对每个专家评分，并报告按此分数剪枝在相同压缩率下比合并更好地保持生成质量。Qwen3.8-Flash-Next [7] 是一个具有 Gated DeltaNet 层、每层 512 个路由专家和 125B 参数中每 token 激活 6B 的混合专家推理模型（第 6.1 节）。

3 12,000 条可执行规则语料库

3.1 作为类型化程序的规则

我们语料库中的规则（生成器代码中的"law"）是类型化领域特定语言中的程序，存储为 JSON 抽象语法树并由精确 NumPy oracle 执行。语言的第一版（v1，2,000 条规则）有三个阶段和一个参数：一个按度量和目标选择一个连通分量的选择器（25 种度量，最小或最大），一个应用于该分量的掩码操作符（38 种操作符，48 种含数量），一个绘制结果的渲染器（19 种渲染器，27 种含分隔符宽度），以及 4 或 8 的连通性。这给出 $50\times 48\times 27\times 2=129{,}600$ 个不同程序。第二版（v2，10,000 条规则）有七个族。其中之一是掩码管道，扩展了 v1，在掩码上添加一个或两个后操作；它跨越两种连通性的 88.4M 个语法程序，其中生产仅枚举了连通性 4。其他六个族有自己的类型化阶段，例如两个选定对象通过对齐布尔关系组合、两个框架面板通过 4 位真值表组合、对称模板中一个缺陷的修复、角色着色墙壁和源之间的射线和洪水，以及在 3 到 8 个对象上计数特征然后沿轴打包瓦片（表 1）。图 1 显示了一个程序和执行它的 oracle 分支。

输入网格不是按规则编写的。每个族的一个场景生成器为给定程序提议输入，oracle 标记它们，门控决定六个结果对是否识别该程序。每个输入在其边界携带一个 10 单元格调色板键，命名六种颜色的角色（框架、背景、对象墨水、结果、辅助、分隔符），每对绘制新调色板，因此规则从不依赖绝对颜色。发布清单记录没有语言模型编写、选择、标记或验证任何规则；规则是由确定性搜索选择的语法点。构建语料库在 14 个 CPU 工作器上从计划到生成报告花了 55.9 小时，在第一次封印尝试失败后在 8 个工作器上进行了额外的 26 小时独立审计；未使用 GPU。

3.2 接受：行为唯一性和可识别性

算法 1 给出了 v2 规则的构建，图 2 给出了通过每个门的规则数量。两个程序可以在语法上不同但计算相同的函数，因此仅当其行为是新的时才接受规则。行为向量有 572 个槽位：220 个共享探测网格、96 个面板布尔槽位和 256 个模板对称槽位。每条规则仅运行自己的段（220 个网格，或其族的 96 或 256 个类型化输入）并在每个槽位记录输出或错误类型；其他槽位持有其族的固定标记，因此不同段的规则总是不同。候选被接受当且仅当它在至少 16 个探测上执行，其向量在原始形式和八个二面体共轭 $x\mapsto g^{-1}(p(g\,x))$ 下的规范形式中都是新的，并且它与每个已接受规则的汉明距离在两种形式中都至少为 3。当两条规则在共享输入上给出不同的有效输出时，签名的差异就是函数的差异；仅在错误类型或族标记上的差异不是，因此我们称接受的规则为签名不同。在 89,600 个候选中，37,102 个通过（41.4%）：29,423 个是二面体行为重复，16,957 个有效探测少于 16 个，5,705 个是原始行为重复，413 个是近碰撞。没有两个候选具有相同的语法树，因此重复是行为问题而非语法问题。

一个任务仅当其六对（五个演示和一个测试）将规则与其最近竞争者分离时才被接受。oracle 必须精确重放所有六对；每个类型化阶段必须在至少两对上改变输出；最多 8 个候选近似规则和每个在一个语法节点上不同的规则必须在六对中的至少两对上错误，使得在这些竞争者中任何保留对由其他五个确定；12 个捷径求解器的电池必须不能解决任何一个。求解器包括常数输出、恒等、形状和颜色查找表、单色交换、二面体颜色映射、裁剪到非背景区域、固定子网格、行选择、列选择、缩放和平铺，以及复制演示输出。任务生成在每个族达到其配额的 1.25 倍有效任务时停止；在 18,635 个尝试的已接受规则中，13,166 个（70.7%）产生了有效任务。在发布前我们移除了 199 条在丢弃后阶段时归结为 v1 规则的掩码管道规则、41 条渲染器是另一条规则精确别名的规则和一条有重复输入的规则，并保留每个族的第一批规则直到其配额。

表 4 将语料库与早期 ARC 系统使用的生成器进行了对比。re-arc [10] 为每个 ARC-AGI-1 训练任务编写一个生成器，因此它添加了 400 个已知规则的新实例但没有新规则。BARC [11] 和 NVARC [4] 让语言模型编写新生成器或谜题描述，这添加了规则；它们的描述没有报告检查两个生成器是否计算不同的函数或任务的对是否确定其规则。我们的语料库将这两个属性作为明确的测试，在声明的限制内。一条规则仅当其在固定探测库上的签名与每个已接受规则的至少 572 个槽位中的三个（输出或错误类型）不同时才进入，在八个二面体共轭的规范化之后也是如此；处于二面体距离 2 的两对 v1 规则是例外。12,000 条规则因此具有 12,000 个不同的行为签名，这比 12,000 个不同程序更强但比 12,000 个不同函数的证明更弱。一个任务仅当其六对在至少两对上反驳最多 8 个候选近似规则和其程序的每个单节点变体、每个类型化阶段在至少两对上改变输出且 12 个捷径求解器都不成功时才进入。规则是由确定性搜索选择的类型化语法的点，每个标签由精确 oracle 重放，没有语言模型编写、选择或标记任何规则。可识别性相对于这个有限的竞争者集合，而不是相对于每个可能的变换。因为测试是行为性的，它们可以应用于具有可执行语义的其他程序语言。

3.6 规则与 ARC-AGI-2 的差异

词汇。 v1 规则读作"选择一个对象，变换其掩码，绘制结果"。25 个选择器度量测量连通分量：面积、边界框面积、宽度、高度、周长、密度、孔的数量和面积、四个极端坐标、中心行和列、边界接触和接触的边界边、最长行和列运行、端点、分支点、对角线和反对角跨度、垂直和水平平衡以及对称数量。38 个掩码操作符是恒等、边界框填充、轮廓、补集和角、4 和 8 连通性的对象边界和内部、孔填充、孔掩码和孔边界、行和列跨度、凸和正交凸包、七个非恒等二面体变换、膨胀、侵蚀和光晕、移位、端点、分支点和质心。19 个渲染器提取结果、将其叠加在输入上、隔离它、将其放置在源对象旁边的水平或垂直面板中，或在框架内绘制它。v2 族添加了对象之间的关系（两个对齐掩码之间的布尔关系，或按度量谓词选择的对象组上的逐单元格支持计数）、两个框架面板上的真值表、对称或周期的一个缺陷的修复、三个网格算法（射线投射、所有最短路径的并集和墙壁与源之间的有界洪水），以及在 3 到 8 个对象上计数特征然后沿轴打包每个对象一个瓦片。

ARC-AGI-2 的设计规则。 Chollet 等 [2] 描述了 ARC-AGI-2 任务被构建为要求的四个属性：同时作用并相互作用的多个规则、每一步依赖前一步的多个步骤、应用取决于网格中线索的规则，以及意义在任务内定义的符号。我们的规则仅以固定形式覆盖前两个。规则以一种顺序组合类型化阶段（选择、变换、绘制，或其族的阶段），任务应用恰好一条规则。阶段以固定顺序运行，没有条件或递归组合；某些阶段在固定算法内迭代（路径、射线和洪水、孔填充、分量标记），输入相关的选择是选择器选择的对象、路径的源、计数包的排名和模板族通过搜索找到的唯一修复。调色板键是一个符号定义，但总是相同的六个角色，在边界上四种方向之一的同一 10 单元格条带中；模型可以学会读取一次，而 ARC-AGI-2 任务中的图例在每个任务中都有新形式。真实任务的两个元素在词汇中没有对应物：具有自身含义的颜色（因为每个规则引用颜色角色）和大于输入的输出（如平铺、缩放或在对象之外绘制）。

3.7 语料库的局限性

门控保证每个任务将其规则与语料库的有限候选近似规则列表和其程序的单节点变体分离，而不是人或在真实 ARC 任务上训练的模型可以推断它；我们没有运行人类或模型可推断性测试。格式在模型可以作为捷径学习的方面与 ARC-AGI-2 不同：调色板键出现在每个输入中，每个输入有六种颜色，大多数输出比输入小（第 3.6 节）。12,000 条规则中仅 4,400 条（v1 规则和掩码管道族）有规则特定的英文描述；其他 7,600 条带有占位符。在 600 条保留规则中，457 条出现在一个派生训练集中，根据我们的笔记，498 条出现在一个独立程序集中，尽管没有对出现。第 4 和 5 节报告了后果：网格模型在合成任务上训练时拟合了它们，但没有用它们训练的模型在真实任务上更好（单独或与真实任务模型并列），最佳 NVARC 4B 配置不使用在语料库上训练的任何检查点（第 4.4 节）。

4 NVARC 网格模型的真实和合成训练数据

4.1 基础管道

NVARC 4B 是一个词汇表缩减到 16 个 token 的 Qwen3-4B 模型，包括十种颜色、换行符、角色标记、填充和序列结束；它由其作者在来自 104,539 个谜题的 3.26M 样本上完全微调，其中约 90% 为合成 [4]。发布的管道分五步解决每个任务，我们保留了这些步骤（算法 3）。第一，为任务的演示的 128 个增强副本（8 个二面体变换 $\times$ 16 个颜色排列，演示打乱）训练一个新的 LoRA 适配器（秩 256，$\alpha=32$，秩稳定，在七种投影类型加上嵌入和输出层上），学习率 $5\times 10^{-5}$，训练一个 epoch。第二，每个测试输入在 16 个视图中渲染（8 个二面体变换 $\times$ 2 个颜色排列）。第三，在 12 个合法 token 上进行深度优先搜索，保持累积概率保持在 0.2 以上的每个分支。第四，每个不同的候选（映射回原始帧）由其在 8 个新视图下的负对数似然（NLL）评分。第五，候选的分数是其搜索命中数减去其重评分 NLL，前两个是两次尝试。

在四块 L4 GPU 上，每 GPU 一个工作器，测试时训练每任务需要 193 到 870 秒，整个任务需要 517 到 1,371 秒。基模型的四次运行，三次为未更改的发布管道，一次在我们运行时中使用 12,288 token 上下文，在半私有集上得分为 28.47、29.86、29.03 和 28.47（均值 28.96，标准差 0.66）；仅三次未更改运行平均为 29.12。对于本节的每次运行，我们从产生分数的版本的源代码或日志中读取检查点；我们最初计为基运行的第五次运行加载了我们自己微调的检查点，计入第 4.2 节。

4.2 在真实任务上的继续微调

在任何逐任务训练之前，我们在所有可以标记的真实任务上继续微调 NVARC 4B：800 个 ARC-AGI-1 训练和评估任务、1,000 个 ARC-AGI-2 训练任务和 120 个 ARC-AGI-2 公开评估任务（其测试输出作为进一步演示附加）。这给出 1,920 条源记录，包含 6,427 个演示对（3,852 个不同），每条记录 16 个视图渲染（30,720 个示例）。记录覆盖 1,147 个任务标识符：767 个 ARC-AGI-1 任务重新出现在 ARC-AGI-2 训练任务中，大多以不同顺序具有相同演示，6 个出现在评估任务中并多一个演示，因此这些任务的权重是其他任务的两倍。我们训练了一个秩 256 LoRA 适配器，目标与测试时训练相同，学习率 $5\times 10^{-5}$，在两个计划 epoch（61,440 步）上余弦调度，批次 1 和 8,192 token 上下文，在一块 L4 上。运行在 10 小时后停止于步 34,273（1.11 epoch）；步 34,000 处的检查点是我们称为 ckpt-34000 的模型。在公开评估任务上训练使得对它们的本地评估对该模型及其所有后代无意义，但不触及隐藏的半私有任务。

二十二个隐藏运行使用 ckpt-34000 或同一训练运行早 2,000 或 4,000 步保存的检查点作为所有四块 GPU 上的唯一模型，在半私有集上平均为 31.72（标准差 1.52，表 6）。ckpt-34000 在其他未更改的发布管道中的一次运行得分为 31.53，22 次中的最佳为 34.44。同一记录上早期单 epoch 运行的半 epoch 检查点得分为 29.03。

4.3 合成任务

我们从多个来源添加了合成任务。用 25% 的回合来自 FORGE50 生成器（规则特定 Python 生成器目录，与第 3 节的类型化语料库分开；学习率 $10^{-5}$）继续 ckpt-34000 得到的模型单独得分为 29.31，比 ckpt-34000 均值低 2.4 点。第二种 FORGE50 配方，86% FORGE50 回合、12% 来自三个池（包括公开评估集）的真实 ARC 任务（5%）和 2% 手工任务的加权混合，得分为 28.47。来自形状平衡生成器的 36,000 个任务加上 1,090 个真实任务的课程，从在真实和规则语料库任务的 6,000 任务混合上训练的适配器开始，在一块 RTX 3090 Ti 上运行了 47.8 小时。它将其自身生成器的 72 个程序的新任务准确率从 5.8% 提高到 61.7%（240 个中的 14 到 148），并将 30 个真实评估任务的准确率从 47 个输入中的 9 个变为 8 个；在半私有集上它在步 5,500 得分为 27.22，结束时为 26.53。从基模型在 1,920 个真实任务、3,600 个形状平衡任务和 1,980 个规则语料库任务上训练 120,000 步得分为 28.06。我们还在真实任务加上规则语料库的所有 95,993 个任务（每个两个视图，191,986 个合成示例；秩 256，一个 epoch，在 RTX 5090 上）上从基模型微调了检查点。其中一个在所有四块 GPU 上单独运行得分为 28.61，比 ckpt-34000 均值低 3.1 点；在其他 GPU 上与 ckpt-34000 并列时，这些检查点在五次运行中得分为 27.64 到 32.64（均值 30.53，第 4.4 节）。

在 RTX 5090 或 RTX 3090 Ti 上约 25 个较短的受控运行测试了数据混合和损失：来自规则语料库和真实数据的 1,000 到 97,113 个任务、普通交叉熵、匹配 0.2 搜索截断的似然阈值"门"损失、硬尾加权、基模型正确 token 的 KL 锚、颜色一致性正则化，以及每任务一到八个视图。在 15 个公开评估任务（18 个输入，16 个视图，贪婪解码，无测试时训练）上，它们解决了 1 到 3 个输入，而基模型为 2 个。在相同设置中，仅逐任务测试时训练解决了 3 个，在 30 个保留合成任务上解决了 6 个而基模型为 2 个（差异的自助 95% 区间为 $+3.3$ 到 $+26.7$ 点）。

4.4 运行时更改和检查点集成

我们最佳的 NVARC 4B 配置（最佳抽样 34.86）保持算法 3 的算法和模型 ckpt-34000，并更改四块 GPU 和十二小时的使用方式。我们恢复了此配置的执行源代码及其日志和每 GPU 任务统计：

  • 每个 GPU 加载 ckpt-34000，GPU 0 到 3 上的上下文长度分别为 13,312、12,288、10,240 和 8,192 token，而不是所有四块上 8,192，因此 GPU 仅在提示中适合多少演示方面不同；
  • 任务从按估计成本排序的一个共享队列中获取，最便宜优先，每个任务获得根据剩余预算和队列计算的 1,200 到 3,000 秒之间的时间限制，而不是固定的 1,200 秒；
  • 全局截止为 12 小时加 10 分钟，而不是 12 小时减 10 分钟；
  • 搜索分数以 FP32 而非 BF16 保留，重评分视图使用每任务的确定性种子；
  • 在三个连续任务上失败的工作器退出，其他工作器接管其任务。

每个工作器解决完整任务，GPU 之间没有投票。此配置因此不包含在我们的合成数据上训练的任何检查点；其相对于基模型的增益来自在真实任务上的继续微调和运行时更改。

5.1 基模型的两个修复

思考块内的回合结束 token。 Qwen3.8-27B 在其推理中间采样回合结束 token（id 248046），通常在枚举网格行时。服务引擎然后返回空答案。在低努力下在一个十任务阳性对照集（parity10，ARC Prize 基金会评估报告为已解决的 13 个输入）上，26 个请求中的 11 个以此方式结束，在两个任务上每次尝试都如此。在停止步骤处，该 token 的概率在 5% 到 62% 之间。该失败在 BF16 输出头、BF16 键值缓存、不同的注意力后端和两个其他检查点下持续存在；所有这些运行都使用了量化权重，因此我们没有测试未量化的，但没有指向量化。我们将每次尝试按 token id 分割为两个请求：一个思考请求，其中回合结束和文本结束 token 带有 $-100$ 的 logit 偏置，并在

5.3 训练配方

我们在混合架构的十二种投影类型上训练秩 32 和 $\alpha=32$ 的 LoRA 适配器 [42]（233.5M 参数）：16 个全注意力层的查询、键、值和输出，48 个 Gated-DeltaNet 层 [27] 的五个输入和输出投影，以及所有 64 个 MLP 块的门控、上和下投影。基模型在 BF16 中保持冻结。我们使用 AdamW，学习率 $10^{-4}$，5% 预热后余弦衰减，梯度裁剪 1.0，一个 epoch，微批次 1 不打包（打包会跨示例泄漏线性注意力层的循环状态）和梯度累积 8。损失是监督 token 上交叉熵的 token 均值；提示被屏蔽并断言与推理提示逐 token 相同。最多 81,920 token 的示例通过重入梯度检查点、激活卸载到主机内存和在 8,192 个位置上分块的 MLP 适合一块 96 GB GPU。RFT v1 在 130 个优化器步和 7.06 小时内训练了 1,033 行（三行超过长度限制）；损失保持在每 token 约 0.20 nats。合并后，我们用公开 unsloth 检查点的配方将模型重新量化为 NVFP4：层 0 到 55 的 MLP 上具有组大小 16 的 NVFP4 权重；注意力、Gated-DeltaNet 层的查询键值、门控和输出投影、输出头和最后八个 MLP 上的 FP8 权重和激活；其余小投影和范数的 BF16；以及在 256 个训练任务样本上校准的 FP8 键值尺度。在相同种子和 32K 上限下，BF16 和 NVFP4 模型解决了 172 个输入中的 50 和 51 个（网格或验证程序）；64K 下的奇偶性未建立。

在 FINAL 之前，我们测量了 RFT v1 对其自身数据的拟合程度（E1）。比较基模型和 RFT v1，思考的每 token 负对数似然在训练族行上下降了 0.047 nats（0.230 到 0.184），但在评估族行上仅下降了 0.020（0.294 到 0.274）；两个下降的差异为 0.027（自助 95% 区间 0.024 到 0.030）。RFT v1 因此对长评估级轨迹的拟合不如短训练级轨迹。为解决此问题准备的更高学习率的运行（E2）被取消，以支持单次最终运行。

5.5 微调数据中的合成任务

合成任务进入了 Qwen3.8-27B 的三个训练集（表 10）：总共 2,231 个不同任务，1,435 个来自第 3 节的 95,993 任务语料库，796 个来自形状平衡生成器的 72 程序库。最大的添加 synthetic1000 是为覆盖每种网格尺寸而构建的。它有 1,000 个任务，每个有一个测试输入，测试输入从 $1\times 1$ 到 $30\times 30$（900 种尺寸）的每个有序尺寸至少出现在一个任务中。其 205 个任务保持了语料库任务的五个演示和测试输入（来自所有八个语料库族的 205 条规则），795 个是 72 个库程序中 68 个的新任务，分为两族：空间逻辑（单元格选择器、关系、对称和占用门；684 个任务）和形状序列（单元格上的顺序后跟关系、掩码或布局；111 个任务）。生成程序重放了所有 4,410 对，规范化后没有任务等于现有微调数据的任务，该集合在训练格式中占用 8.85M token（每任务最多 22,022）。每个任务都带有从程序的验证应用计算的规则说明，而非模型编写；表 3 用这些说明的措辞给出了每个族的一条规则。
