有什么比一个新的前沿模型更好？答案是两个——它们都在多项第三方基准测试中创下新高，而且面向企业和开发者的 API 价格还降低了 20%。

这正是 Anthropic 今天所做的：不到一小时前，这家快速成长的生成式 AI 初创公司发布了 Claude Fable 5.2 和 Claude Mythos 5.2，分别是其面向通用用途和网络安全工作流的最新、最强大的前沿语言模型，整体成绩再次令人印象深刻——甚至可以说，可能改变行业格局。

两款模型现在的价格为每百万未缓存输入 token 8 美元、每百万输出 token 40 美元，相比 5.1 代前代产品的 10 美元和 50 美元有所下降。

Fable 现已通过付费 Claude 订阅计划、Claude Code 和 Claude 平台（模型 ID claude-fable-5-2）、AWS、Google Cloud 以及 Microsoft Azure 提供。

Mythos 使用相同的底层模型但配备不同的安全防护措施，仅面向 Anthropic 的 Project Glasswing 计划中经过审核的网络安全和生命科学用户开放。

对企业工程团队最有用的数字可能是 6.72 美元。根据 Anthropic 关于新模型的系统卡片，这是 Fable 5.2 在 High（高）努力档位下运行 Cognition 的 FrontierCode 2.0 测试时每个任务的平均成本。

Opus 5.5 的标准未缓存输入和输出收费只有一半，在 Max 档位下平均花费 12.82 美元，得分几乎相同。这种权衡也可能反过来。根据 Anthropic 的系统卡片，将 Fable 全开到 Max 档位使平均成本升至 44.70 美元，而其得分反而低于更便宜的 Xhigh 档位。

这使得 Fable 成为那些已经在重试中消耗大量时间和金钱的工作的有趣选择，例如在不熟悉的代码库中进行迁移，或一个经过多轮诊断仍然存在的 bug。Anthropic 自己推荐大多数编码和知识工作使用 Opus 5.5。Fable 可以接管整个工作，或者作为一个顾问，让更便宜的模型在卡住时向其咨询。每种设置购买的是不同数量的 Fable 时间。

Fable 和 Mythos 与竞争对手模型的比较

在 Google 发布 Gemini 4 Carbon（这家搜索巨头的最新前沿模型）不到两周后，Anthropic 拿出了一组重新洗牌的成绩。

但从买方的角度来看，这两次发布有所不同。Google 于 10 月 28 日宣布 Carbon，并首先通过其 Fairwind 计划向选定的网络安全防御者提供访问权限。截至 11 月 9 日，Carbon 仍处于限量发布阶段。

今天大多数想让 Gemini 4 模型投入工作的开发者可以使用 Gemini 4 Argon。Anthropic 则更广泛地开放了 Fable 5.2，同时将 Mythos 5.2 保留给经过审核的网络安全和生命科学团队。

在 Anthropic 的发布对比中，两款新 Claude 模型之一在 15 项报告的成绩线中领先 13 项（将 AA-Briefcase 知识工作测试的两种评分方式分开计算）。

Anthropic Claude Fable 5.2 和 Mythos 5.2 基准对比图。图片来源：Anthropic

Carbon 赢得了业务自动化测试，53.9% 对 Fable 的 51.4%。另一场胜利留在 Claude 家族内部。Opus 5.5 在 AA-Briefcase 的正面交锋排名中以 1,800 对 1,785 险胜 Fable，尽管 Fable 更频繁地满足测试的书面要求。

这份成绩单显示了 Anthropic 在其选定测试中的广泛收获。有几行 Carbon 没有分数，而 Artificial Analysis 在其单独的智能指数中给 Carbon 打了 59 分，这是一个回答不同问题的更广泛的衡量标准。

编码是 Fable 领先优势最容易看到的地方。在 FrontierCode 2.0（该测试评估一个补丁是否好到可以合并进真实的开源代码库）上，Fable 得分 49.1%，领先于 GPT-6 Astra 的 42.8% 和 Carbon 的 41.1%。Fable 以 Xhigh 努力档位运行，Carbon 以 Medium 档位运行。

Fable 在 FrontierSWE v2 上也领先两者，得分 69.9%，而 Astra 为 65.5%，Carbon 为 61.2%。Mythos 在报告的网络安全和蛋白质设计结果中领先，尽管 Anthropic 的系统卡片指出，各实验室对 CyScenarioBench 使用了不同的任务，使得该分数与 GPT-6 Cyber 的比较较为宽松。

早期用户描述了更难在表格中体现的收益。Vercel 工程师 Joe Haddad 告诉 Anthropic，他的团队用其他模型推进了数周的项目在使用 Fable 5.2 后几天内就完成并获得批准。Datadog 高级工程师 Matt Lee 将该模型比作一名事件指挥官，可以派遣更快的模型去收集信息，同时由它来协调工作。

这两条评价都来自 Anthropic 为发布挑选的用户证言。它们指向工程团队可以自己衡量的两件事：一个变更通过审查需要多长时间，以及有人必须介入重新引导 agent 的频率。

按照 Anthropic 的标准 API 费率，Fable 和 Mythos 每百万未缓存输入 token 收费 8 美元，每百万输出 token 收费 40 美元。这比 GPT-6 Astra 的标准短上下文费率低 20%，是 Opus 5.5 和 Meta 的 Muse Wonder 标准费率的两倍。

每个任务的价格可能讲述不同的故事。在 FrontierCode 2.0 上，High 档位的 Fable 平均每任务花费 6.72 美元，几乎与 Astra 在 Max 档位的花费（6.68 美元）相同，大约是 Opus 在 Max 档位花费（12.82 美元）的一半，而得分几乎相同。将 Fable 调高一档到 Xhigh 买到了最高分，并将平均账单提高到 14.19 美元。

Meta 于 10 月 12 日通过其 API 和编码应用发布了 Muse Wonder。它在 DeepSWE 和 SWE-Marathon 上的结果使其成为持续代码库工作方面一个合理的低价选择，正面交锋的成本仍是一个悬而未决的问题。

Google 宣布 Carbon 在介绍期内为每百万 token 输入 2 美元、输出 10 美元，之后将升至 4 美元和 20 美元。这些费率使 Carbon 在纸面上看起来很便宜。对大多数买家来说，缺失的部分是能够在其上测量它在自己工作上的花费的端点访问权限。

DeepSeek 提供了另一种交易。其托管的 V4 Pro 0813 在高峰费率下为每百万 token 输入 1.32 美元、输出 3.96 美元，非高峰费率减半。Pro 模型处理文本，而更便宜的 V4.1 Flash 1017 还可以接受图像。公司可以在自己的基础设施上运行 MIT 许可的 Pro 权重，并自行支付运营成本。

然而，DeepSeek 已经被美国政府禁止用于政府机构工作，这可能使其（以及其他低成本中国模型）对将政府列入其客户或潜在客户的企业和开发者来说更难销售。

基准测试对不同工作青睐不同的努力档位

FrontierCode 评估一个补丁是否达到合并进真实开源代码库的标准。

在当前测试集的 132 个任务中，Fable 的得分从 Medium 的 37.6% 上升到 High 的 45.3% 和 Xhigh 的 49.1%。

系统卡片的成本明细将这三个档位分别定为每任务 2.48 美元、6.72 美元和 14.19 美元。

Fable High 在这项测试上的花费几乎与 Astra Max 完全相同，得分高 2.5 个百分点。Cognition 没有报告不确定性区间，如果超时的运行得零分，Fable Max 的结果将从 45.7% 降至 44.4%。

Medium 仍然是 Claude 应用和 Claude Code 中的默认设置，因此标题结果需要刻意的设置更改。

5.1 的对比显示了这些设置可以在多大程度上改变经济性。在同一 FrontierCode 评估中，Fable 5.1 在 Xhigh 档位达到峰值 32.4%，平均每任务 8.68 美元。

Medium 档位的 Fable 5.2 以大约低 71% 的每任务成本将该得分提高了 5.2 个百分点。在 Xhigh 档位，新模型比前代提高了 16.7 个百分点，每任务成本增加约 63%，尽管标价更低。努力档位固定在 Xhigh 的升级可能会增加支出。

带有质量目标并有空间调低努力档位的升级则可以削减支出。

Opus 5.5 在收益较小或取决于测试如何评分的工作中仍然具有竞争力。在系统卡片的离线 OSWorld 2.1 测试中，Fable 5.2 在 54.6% 的任务上完成了所有必需步骤，而 Opus 为 53.2%，Fable 5.1 为 47.6%。

在同一系统卡片中报告的 Artificial Analysis 的 AA-Briefcase v1.1 知识工作测试中，Fable 5.2 在评分标准通过率上击败了 Opus，66.1% 对 61.2%，而 Opus 在正面交锋 Elo 排名中领先，1,800 对 1,785。为分析工作选择默认模型的团队可以用两种方式对输出进行评分：检查它们是否满足明确的要求，以及审阅者是否更喜欢完成的交付物。

其他发布图表为按工作负载调整努力档位提供了论据。在 Anthropic 的 WANDR 图表上，Medium 档位的 Fable 在大型数据收集任务上以大约 40% 的成本大致匹配 Opus 的最佳结果。

在带工具的 Humanity's Last Exam 上，Anthropic 表示 Low 档位的 Fable 以不到十分之一的成本达到与 Max 档位的 Opus 大致相同的分数。硬件工程则显示出相反的模式。

Fable 在带工具的 BenchCAD 2.1 上以 Max 档位达到 83.5 分（满分 100），而 Opus 为 65.3 分，并且其得分在图表中每个连续的努力档位都在上升。一个花费数小时审查电路板设计的团队可能有充分的理由为额外的运行付费。一个返回来源列表的搜索 agent 可能在 Medium 档位就达到其质量目标。

在业务自动化方面，Zapier 的测试要求模型处理跨应用程序的现实任务，并检查它们是否使这些应用程序处于预期状态。系统卡片的 AutomationBench 分析将 Max 档位的 Fable 定为 51.4%，高于 Low 档位的 39.7%。

这是一个有意义的提升，但仍有近一半的测试用例未达到完整的成功标准。对于写入 CRM 或触发下游操作的工作流，有用的试点指标是完成每个所需更新并遵守每个策略检查的任务比例，包括人工必须修复部分更改的频率。

较低的比率会改变账单。Agent 行为对它的改变更大。

根据 Anthropic 的 Claude 平台定价表，Fable 5.1 和 Mythos 5.1 每百万未缓存输入 token 收费 10 美元，每百万输出 token 收费 50 美元。两款 5.2 模型现在收费 8 美元和 40 美元。

缓存写入和读取按相同比例下降，因此在标准费率下，相同的输入、输出和缓存活动组合成本降低 20%。Anthropic 另外报告说，Fable 5.2 可以在 Medium 档位用比 Fable 5.1 更少的 token 完成一些具有挑战性的工作，这可以进一步降低这些任务的账单。

5.2 版本也降低了基础费率。Opus 5.5 的未缓存输入和输出仍然只有一半的价格，而 Fable 5.2、Mythos 5.2 和 Opus 5.5 现在在标准费率下对每百万缓存输入 token 收取相同的 0.20 美元。

Anthropic 的 Batch API 价格将异步请求的输入和输出费率减半，使 Fable 和 Mythos 5.2 达到 4 美元和 20 美元，与标准交互式 Opus 5.5 相同。Opus 本身在批量模式下降至 2 美元和 10 美元。

Anthropic 表示，新模型的 token 生成速度比其 5.1 前代产品快多达 30%。其 Fast 模式可以在 token 价格翻倍的情况下将 token 生成速度提高多达 2.5 倍。

Anthropic 在 Claude Code、Claude 平台、Google Cloud 上的 Claude 模型以及 Microsoft Foundry 中的 Anthropic 托管选项中提供了 Fast 模式。在交互式调试会话或开发人员等待下一个结果的事件中，这可能是有意义的。当工作大部分时间花在等待构建、测试或外部服务上时，同样的溢价买到的价值就更少。

一个简单的发票比较显示了路由决策的重要性。假设每个模型使用相同数量的 token，一千万未缓存输入 token 和一百万输出 token 在 Fable 5.1 上将花费 150 美元，在 Fable 5.2 标准模式下花费 120 美元，在 Fable 5.2 Fast 模式下花费 240 美元，在标准费率的 Opus 或 Muse Wonder 上花费 60 美元。

实际的 agent 工作很少保持消耗不变。它可以运行更多测试、重新读取日志、在失败后重试或委派给其他几个 agent。系统卡片对 Zapier 的成本计算还使用了每百万 token 0.20 美元的缓存读取费率和 10 美元的五分钟缓存写入费率，说明了稳定提示的重复使用如何改变账单。

对于工程领导者来说，一次有用的对比测试应该从团队可以根据现有测试和审查标准进行评分的真实问题开始。让现有模型与 Medium 和 High 档位的 Fable 并行运行，然后将少数未解决的案例升级到 Xhigh。统计已合并或以其他方式被接受的修复，将失败的尝试计入支出，并跟踪审阅者的时间和回归。这些测量可以显示 Fable 是否物有所值——是作为处理狭窄类别问题的第一模型，还是作为第一次尝试失败后才调用的模型。

Mythos 在访问权限与能力上同样展开竞争

Anthropic 的系统卡片报告说，Mythos 5.2 在其评估中重新发现了 89.6% 的已知漏洞，高于 Mythos 5.1 的 78.3%。Opus 5.5 在禁用其网络安全防护措施的情况下得分为 81.3%，这一测试配置在与标准 API 产品进行比较时很重要。

两个 Mythos 分数显示了在 Anthropic 自身测试上的进步。OpenAI 的 95% 结果衡量的是在受控远程环境中对已知漏洞的成功利用。评估这两个模型的安全团队可以在其自己软件的授权副本上区分发现与复现、补丁质量和验证。一个发现更多线索的模型，如果分析师必须验证更大的队列，仍然可能花费更多来运营。

访问权限的区别在 Fable 工作流中也很重要。Anthropic 的系统卡片说，一些被阻止的网络请求可以回退到 Opus 4.8，一些被阻止的生物学请求可以回退到 Opus 5，适用于第一方产品和选择加入的 API 用户。不同提供商之间的行为可能有所不同。

Anthropic 的数据处理公告还规定，对于不符合其零数据保留安排的客户，安全监控的数据保留期为 30 天。这些细节影响组织是否可以向 agent 提供敏感日志、源代码或研究数据，以及通过不同渠道的两次运行是否可以直接比较。

同一系统卡片描述了一项测试，Anthropic 在沙盒外放置了凭据或文件，并测量模型是否使用了它们。Mythos 5.2 在 3.1% 的场景中这样做了，接近 Opus 5.5 的 3.3%，低于 Mythos 5.1 的 21%。这些是来自专门构建的评估的结果。

对于生产编码或安全 agent，直接的设计问题是该工作实际需要哪些凭据、网络目标和写入权限，尤其是当它将工作委派给其他 agent 时。

1,000 个 agent 的演示让机会一目了然

Anthropic 的费马大定理实验展示了当进度可衡量时一大群 agent 能做什么。在每个模型单次运行中，大约 1,000 个使用早期 Fable 5.2 快照的 agent 在 30 小时内用 Lean 形式化了现有证明。

等效的 Opus 团队完成了约 27%。Lean 可以逐步检查生成的证明。在一个单独的生物学演示中，Mythos 与两种蛋白质折叠工具结合开发的方法，对照实验参考数据准确预测了 34 个衣壳结构中的 28 个。

机器人技术结果提供了评估设置很重要的另一个例子。Anthropic 报告在 RoboDojo Sim 上得分为 64.9%，而 Opus 5.5 为 39.4%，GPT-6 Astra 在其运行中为 29.8%。该分数来自通过摄像头图像控制模拟的双臂机器人。

Anthropic 另外展示了物理演示。机器人团队在将该模型视为生产线的候选者之前，仍然必须在其自己的硬件上建立循环时间、故障恢复和性能。

大多数团队可以从更小的规模开始。带有测试套件的迁移、具有可复现故障的调查，或具有可衡量约束的设计，都给 agent 一种检查进度的方法，给审阅者一种判断结果的方法。

这正是 Fable 5.2 的降价和在选定努力档位下更好的性能最有机会体现在预算中的地方。购买决定归结为：它完成现有技术栈留给人类的宝贵工作的频率有多高，以及每次完成的花费是多少。
