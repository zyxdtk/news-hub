Logos：跨进程总线上的智能体框架

📅 2026-08-28 📄 arxiv 🔗 原文链接

原标题：Logos: An Agent Harness on a Cross-Process Bus

中文摘要： 本文提出Logos，一个基于ROS架构的跨进程智能体框架。针对单进程插件组合的单点故障问题，基于语言模型推理的无状态性提出四个引理，证明时空可组合性演算的可逆性保证在跨进程时依然成立。Logos将插件作为独立进程运行在总线上，仅通过只追加记录共享状态。实验表明，在进程被杀等故障下，系统能通过冷切换无缝恢复会话且无重复效应，显著降低了故障域，提升了容错能力。

摘要。
现代智能体系统在运行时组装能力，这种动态组合最近在时空可组合性演算中获得了完整的形式化处理，其中能力是带有被跟踪逆操作的组件，而智能体作为插件被组装。这种插件形式由共享单一上下文的单个进程承载，这种载体将所有组件置于一个物理故障域中，一个故障会立即挂起所有组件，而进程死亡会中断该进程承载的所有会话。本文表明，无论是模型还是演算都没有将智能体绑定到一个进程，语言模型的无状态性将所有跨步骤状态保持在模型之外，而可靠性不变量仅定义在状态空间上。这些观察浓缩为四个引理，其前提是演算的假设和语言模型推理的无状态性。基于这些引理，本文构建了 Logos，一个类似 ROS 的跨进程智能体框架，其中插件是一个进程，唯一的共享状态是一个只追加的记录。在工具调用周期的四个边界处进行杀进程操作后，八十个会话恢复且没有重复效应，与单进程参考配置的同故障比较表明，一个故障会中断每个共存会话，而在对等进程构造下，一个故障在一个节点处终止。

1.
引言
现代智能体系统在运行时组装能力，加载和卸载组件时其效应完全回滚，这种软件组件的动态组合最近在时空可组合性演算中获得了完整的形式化处理
(
Shi et al., 2026
)
。在该演算中，能力是带有被跟踪逆操作的组件，组装应用一个效应，移除应用记录的逆操作，而智能体由这些组件作为插件组装，组装和移除的每条记录都保存在一个共享上下文中。该演算证明了可逆性保证，并且该保证在单进程实现中是完整的。然而，该进程承载了所有插件、所有记录和所有会话，因此该进程是其承载的所有内容的单点故障。
在一个进程中承载所有插件会产生四项工程成本。承载进程中的物理故障、崩溃、内存耗尽或阻塞的事件循环会立即终止所有组件，一项服务的撤回会卸载其依赖项，并使它们提供给模型的工具在重新加载之前不可用，因此数学上在组件之间成立的隔离在共享进程内失去了意义。进程的死亡立即终止每个组件和每个共存会话，而恢复会重启整个栈。替换或升级一个插件需要重启进程或重新加载，这会拆除并重新运行每个依赖项，并且每个共存会话都会随重启而停止。该进程也是一个单语言环境，其中插件被限制在宿主语言中，跨语言重用需要通过翻译层和远程调用。这四项成本共同指向了跨进程的插件组合。
针对这些问题，本文提出了四个引理。引理 1，编排外部性，断言模型的每次前向传递都是无状态的纯映射，跨步骤状态已经存在于模型之外，并且输入可以在任何地方合成。在此基础上，引理 2，载体替换，允许状态移动到任何持久载体，并且在观察等价性下从载体重建的恢复等于就地恢复。引理 3，恢复局部化，利用演算关于组件独立性的假设，断言每个组件的恢复不需要与任何其他组件协调。最后，引理 4，外部解析，将依赖解析也移出进程，移到以能力名称为键的表中。这四个引理仅依赖于演算已经陈述的假设以及语言模型推理是无状态的这一事实，没有增加任何新的数学假设。因此，时空可组合性在跨进程时仍然成立。考虑到复杂系统的设计自由度和插件形式，本文因此选择 ROS 架构
(
Quigley et al., 2009
)
作为其基础，并构建了 Logos，一个基于插件的分布式系统。该系统作为一组对等进程在总线上运行。框架在一个会话上运行输入合成、模型调用和输出结算的循环。工具提供一种能力。路由器注册节点并按接收者转发消息。节点是任何符合协议的进程，规则允许的任何内容都可以作为对等方挂载。在 Logos 中，插件是一个进程，路由器仅保存其路由表，所有共享状态存在于不属于任何进程的只追加记录中。记录在会话发生时记录其每一步，并且在任何进程死亡后，新进程会从记录重建会话并继续，这种恢复形式称为冷切换。Logos 本身也消除了语言成本，Go 路由器、Python 框架和工具以及 Node.js 工具作为对等方在同一总线上运行。
运行时验证表明，Logos 传递消息无丢失、重复或重排序，每个能力名称保留一个注册器，并按顺序传递供应变更通知，确立了分布式架构的工程可行性，压力审计直接测试了每个条件，来自多达两百个并发调用方的 3,500 次调用配对无丢失、重复或误归因，在一百个对同一名称的同时声明中有九十九个收到明确拒绝而只有一个注册胜出，两名观察者在五十个提供者的三十轮变更中记录了相同的供应变更序列。在并发多智能体场景中，路由器被杀后路由自动恢复，框架的任务照常完成。十二个端到端会话经历了六次进程杀，全部通过冷切换恢复，并且恢复后没有重复先前执行的动作。另外八十个会话将覆盖范围扩展到工具调用周期的四个杀点：工具执行期间、返回后但持久化前、持久化后但通知前、以及通知后。所有八十个会话都恢复并完成，没有重复效应，恢复后重做的工作恰好等于记录尚未记录的工作。一个工具在任务期间上线，模型在注册表更新广播后 8.4 秒进行首次自主调用。总线跳转的中位数成本为 0.215 毫秒，是模型 177 毫秒首字延迟的 1/823，在模型的时间尺度上不可见。
现有的分布式架构将动作移至跨进程，MCP 及其衍生工具将工具服务器移出进程，Temporal 及其同类将执行移出进程，而组合和组装仍保留在宿主中
(
Hou et al., 2026
;
Temporal Technologies Inc., 2025
)
。Logos 将组合和组装本身移出进程，由对等节点之间的注册和广播承载。

•
定理 1 的充分条件，在其下时空可组合性演算的可逆性保证在跨进程时成立，包含四个支持引理，其前提取自演算本身和语言模型推理的无状态性，在第 4 节中陈述。

Logos 的最小构造，一个建立在 ROS 架构上的跨进程智能体框架，其中插件是一个进程，唯一的共享状态是只追加的记录，在第 5 节中构建。

对完全实现的系统的对抗性和端到端评估，涵盖路由器故障下的并发恢复、进程终止后的冷切换恢复、任务期间引入的工具的自主采用以及同一总线上的混合语言操作，在第 6 节中测量。

空间可组合性的操作要求是将键实时解析为提供者，每个键一个写者，以及需求前供应和消费后撤回，其内容完全是键到提供者的分配，即路由表。
路由表是演算中交换键的代表性情况，注册是可逆效应，因此该表驻留在状态空间的交换部分，并且通过注册事件广播维护的副本在观察上等价于内存注册表。

5.1.
总线
路由器是一个单一的 Go 进程，它注册节点并按接收者转发消息。它的三个职责是注册、转发和广播，节点注册时带有 id、角色和提供的能力列表，调用被转发到能力匹配的节点，事件被传递给每个注册的节点。路由器仅持有其路由表，它不调度任何东西也不读取任何有效载荷。消息命名其接收者，id 用于直接传递，通配符用于广播，缺少接收者则向发送者返回明确错误。网络协议是 TCP 上的 NDJSON，每行一个对象，帧最大 64 MB，跳过格式错误的行，有损流与控制消息分离，控制消息是配对的且从不丢弃。每个连接持有 1024 个条目的有界出站队列及其自己的写协程，五秒的写超时断开对等方，满队列丢弃有损流的最旧条目并在通知中计数丢弃，满的控制消息队列断开对等方。传递是分层的，控制消息至少到达一次，通过全局调用 id 进行幂等配对，有损流最多丢失一个前缀，存活的序列保持连续。断开连接的节点重新注册，重放填补空白。每次注册和每次拒绝都向其发送者返回回执，被拒绝的重复名称带有明确拒绝。总线不施加语言限制，工具是实现协议的任何进程，Go、Python 和 Node.js 进程在本系统中作为对等方在同一总线上运行。总线通过构造满足三个约束，通过全局调用 id 配对，通过明确拒绝单注册，通过串行化广播实现单一顺序。
5.2.
路由表
路由表将名称映射到连接，连同角色和提供的能力。任何节点都可以随时读取整个表，无论是否注册。注册添加一行，离开删除它，在线和离线广播将变更传递给每个节点。一个名称允许一行，冲突的声明收到明确拒绝。注册是可逆效应，通过注册事件广播维护的副本在观察上等价于内存表，遵循引理 4。
5.3.
记录
记录是不属于任何进程的只追加 JSONL 文件，是唯一的真理来源，每个会话的每一步在发生时都被写入其中。条目记录轮次、输入、带有结果的工具使用以及流式文本。向模型显示的消息是记录上的投影，长工具结果在投影中被修剪，而完整文本保留在文件中，文件本身没有任何内容被删除。只追加形式是逆数据生成元上的自由幺半群，即引理 2 的数学载体。记录的重放根据四个不变量进行检查，I1 条目遵循良构顺序，I2 标识符是单调的，I3 每次工具使用恰好有一个结果，I4 重建的投影等于会话显示的消息。结算顺序在可见之前是持久的，效应在总线上宣布之前被追加到记录中。
5.4.
事件流
观察者节点将每次广播记录到只追加文件中，即事件流。流覆盖系统行为，记录覆盖会话，两者保持分离。相同的重放检查适用于两者。
5.5.
节点
节点是符合协议的任何进程，规则允许的任何内容都作为对等方挂载。框架在一个会话上运行输入合成、模型调用和输出结算的循环，工具提供能力。节点以三种角色之一注册：框架、工具或观察者，观察者接收每次广播且不宣布任何内容。每个进程持有相同的句柄，角色仅在注册调用中不同。框架和工具作为驻留者同等计数，当没有驻留者剩余时路由器退出。算法

5.6.
组装、移除和恢复
能力是一个进程，工具挂载在自己的端点上，路由器不变。在缺少提供者的情况下挂载会使组件处于等待状态，其调用由明确拒绝回答，命名缺少的能力，随后的在线广播在没有任何一方代码更改的情况下激活它。提供者离线触发重新解析，相同能力的替换提供者重新绑定依赖项，而宣布离开的提供者等待其确认的依赖项离开后再撤回。该原则是总线后期绑定之上的软层，不遵循这三个阶段中任何一个的组件仍然运行，其调用在下一层以明确错误回答。顺序遵循定义 6，供应先于消费，撤回跟随其后。在任何进程死亡后，具有相同 id 的新进程导入记录，重建投影并继续会话。恢复没有回滚也没有分叉，重建的视图等于失败进程持有的视图，并且已经记录的步骤从不重复。重建的累加器与失败进程保留的内容组合，遵循引理 2，没有其他进程参与，遵循引理 3。外部效应（例如支付）留在边界之外，不被跟踪和恢复，只有扣留和补偿作为其路径。
5.7.
部署边界
本文的每次部署都在受信任的网络内运行，在环回总线上的单机上和私有网格上，对总线的准入是注册。信任置于挂载时，工具由审查其代码并启动其进程的人接纳。记录保持明文，其单一来源形式是设计选择。快照和压缩是归档前缀并保持重放语义不变的工程项。

6.2.
尺度分离
在 10000 次调用中，总线跳转的中位数成本为 0.215 毫秒，第 99 百分位为 0.377 毫秒，第 99.9 百分位为 0.623 毫秒，最大值为 3.045 毫秒。进程内基线的中位数为 0.005 毫秒，因此总线的成本是本地调用的 43 倍。模型端在三次调用中的首字中位数成本为 177 毫秒，完整推理中位数为 1896.8 毫秒，因此一次跳转是首字的 1/823，完整推理的 1/8822。三个数量级将两个尺度分开，拓扑在模型的步骤尺度上是静止的。
50、100 和 200 个调用方的并发负载各运行三轮，零损失，对来自 200 个并发调用方的 3500 次调用的审计将每次调用与其答案配对，无丢失、无重复、无误归因。一对计算密集型工具，每个饱和一个核心，在两个核心上 2000.8 毫秒完成，而在一个宿主中串行化需要 4001.3 毫秒，二比一的差距是宿主单核造成的。
6.3.
路由器杀
在二十次试验中杀死路由器进程使每个节点保持存活且每个会话继续运行，节点通过监督重新连接，恢复的中位数为 858 毫秒，每次试验在 857 毫秒到 860 毫秒之间。恢复窗口由监督轮询粒度设置，监督循环轮询、检测并重新启动，窗口仅跟随轮询循环。路由器的死亡将故障域从每个会话缩小到路由变更窗口，节点通过直接连接保持其会话运行。
在十次试验中杀死工具进程在 0.321 毫秒内向其调用方返回错误，提供者在生产网格上 100.5 毫秒重新挂载，记录在 I1 到 I4 下重放，没有坏行。作为比较，单进程配置中杀死整个宿主被外部看门狗在 149.5 毫秒内检测到，整个栈在 397.9 毫秒内重启，总中断 547.1 毫秒，而这里的相同故障在比较网格上的三十次试验中以 41.3 毫秒节点重新挂载结束，其他节点不受影响。
6.4.
端到端恢复
十二个会话在六次进程杀下运行，所有十二个在相同标准下交付，没有重复先前执行的动作，每次杀后的轮次分别为 3、4、2、3、2 和 4。重启成本为 1.36 秒，遵循定理 1 的路径，记录前缀作为锚点记录，重建的累加器组合到其上。事件流的白盒重放通过 I1 到 I4，标识符单调匹配，三十次恢复的扩展运行在 30 / 30 次试验中成功。
另外八十个会话将覆盖范围扩展到工具调用周期的四个杀点：执行期间、返回后但持久化前、持久化后但通知前、以及通知后。所有八十个会话恢复并完成，没有重复效应，恢复后重做的工作恰好等于记录尚未记录的工作，前两个点四轮，第三个点三轮，第四个点两轮。

远程资源离线的组件会终止其宿主。来自连接尝试的未处理拒绝传播过插件边界并在所有五次试验中结束整个进程，修复需要重新部署资源并冷重启整个栈，1105 毫秒后会话才再次运行。对等进程构造中的失败节点在所有五次试验中向其调用方返回明确错误并继续运行，修复是资源的返回，下一轮在 107.8 毫秒内恢复，因为节点从未死亡且没有东西需要重启。
宿主的死亡到达其承载的每个会话，因此中断的会话数是共存会话数，这是在一个进程中承载会话的结构性后果，而不是测量的趋势。五会话组合在两个方向上显示了这一规律。
单个承载进程在十次试验中的十次将一个会话的故障变成其承载的所有五个会话的中断。独立于故障的四个会话随宿主停止，管道在第一步重启，丢弃已完成的步骤和记录的进度。对等进程在十次试验中的十次将相同的故障变成一个节点的替换。这四个会话没有单个间隙地交付，管道单调完成，归档进度严格推进。

7.
结论
本文确立了时空可组合性演算的可逆性保证在跨进程边界时存活的充分条件。四个引理的前提是演算已经陈述的假设和语言模型推理的无状态性。在这些条件下，它构建了 Logos，其中插件是一个进程，路由器仅持有路由表，唯一的共享状态是只追加的记录，并且该构造满足引理条件和分布式载体的三个条件。
在一台机器上的测量显示，十二个会话通过六次杀恢复，另外八十个会话通过工具调用周期四个边界处的杀恢复，没有重复效应，节点重新连接并在路由器丢失后路由恢复，并且在同故障比较中，一个故障中断每个共存会话，而在对等进程构造下，一个故障在一个节点处终止。交换原则作为架构事实成立，该系统的共享可变状态是条目表，广播顺序承载供应顺序，通道的故障行为由工程证据覆盖，路由器是单个进程，其死亡将故障域缩小到路由变更窗口，而只追加的记录重放整个会话。未来的工作将每项加强为其形式化对应物，原则的逐键验证，顺序的覆盖证明，丢失、分区和重新连接的形式语义，并将构造扩展到跨机器和更大的提供者集。

A.7.
三个工程约束
跨进程执行需要超出引理条件的三个工程约束。E1 将每个响应与其自己的调用配对，E2 每个名称恰好带有一个注册，冲突声明明确拒绝，E3 向每个观察者传递相同的供应变更通知序列。该构造通过单一 NDJSON 协议和有界队列满足 E1，通过注册冲突拒绝满足 E2，通过广播顺序加上串行化注册满足 E3。这三个约束是工程实现，它们的形式化是未来的工作，异步契约的失败语义、丢失、分区和重新连接目前由工程证据覆盖。
