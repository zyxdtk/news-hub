中文摘要： 机器学习初创公司 TrueFoundry 以 MIT 许可证开源了其企业级 AI 智能体框架 TrueForge。该框架通过优化上下文管理显著降低模型调用成本，在基准测试中比 Anthropic 的 Claude Managed Agents 节省约 75% 的费用。TrueForge 支持自带模型、本地到生产的无缝部署，并与 TrueFoundry 的商业 AI Gateway 治理层互补，旨在为企业提供供应商中立且低成本的智能体运行时解决方案。

又一天，又一款新的 AI 智能体框架发布了。
只不过这一次，这款框架旨在解决随着 AI 智能体日益普及而日益增长的企业级问题：在降低成本的同时，让开发者能更好地控制智能体和工具。

TrueFoundry 是一家位于旧金山的 B2B 机器学习初创公司，由前 Meta 工程师于 2021 年联合创立。该公司已在 Github 上以宽松的 MIT 许可证发布了其定制的 TrueForge 框架。因此，开发者（或其所属企业）可以将其与任何首选的 AI 模型配合使用，也可以对其进行分叉、修改、自托管，并整合到商业产品中。

该公司在一篇博客文章中表示，当它使用 TrueForge 搭配开源的 GLM-5.2 大语言模型，在 DevRev 的 Enterprise-Bench 上成功完成了 14 项任务中的 11 项时——该基准测试用于检验跨 CRM、问题追踪和文档管理系统的多步骤工具使用情况——其成本比使用 Anthropic 由 Claude Opus 4.8 驱动的 Claude Managed Agents 框架达到同样效果低了 75%（花费为 2.90 美元，相比之下为 11.80 美元）。

图片来源：TrueFoundry

即使在两个框架中使用相同的模型（Opus 4.8），TrueFoundry 依然声称与 Claude Managed Agents 相比，使用 TrueForge 可节省约 30% 的成本（8.50 美元对 11.80 美元）。

图片来源：TrueFoundry

为什么 TrueFoundry 要免费提供这款强大且高效的框架？

“我们收到了许多客户的这种请求，”TrueFoundry 联合创始人兼首席运营官 Anuraag Gutgutia 在接受 VentureBeat 独家专访时表示。“你们具备引入智能体和 MCP 的能力——那我们能不能也获得一个可以真正启动这些托管智能体的东西？我认为这就是我们正在满足的需求。它不是替代品。人们会将其与其他框架一起使用，比如云端托管的或商业提供商托管的框架，但这将为人们提供一种以供应商中立且成本更低的方式来使用它们的方法。”

事实上，TrueFoundry 已经为企业提供了一项付费的“AI Gateway”，用于集中控制模型和 MCP 的访问、凭证、权限、预算和可观测性。相比之下，TrueForge 处理的是该网关之上发生的事情：即让模型反复推理、调用工具、接收结果并继续工作直到任务完成的循环。

对于企业开发者来说，实际的价值主张在于，他们可以通过单条命令和 SQLite 在本地启动，然后使用 Docker Compose 或 Helm 配合 Postgres 和 Redis，将相同的智能体框架迁移到共享部署中。

TrueFoundry 明确警告，本地配置仅适用于开发者的机器上，不能作为面向互联网的生产服务。

Gutgutia 表示，公司最终希望其 AI Gateway 能成为企业选择的任何智能体和框架之下的通用层。

“会有一批公司使用我们的框架作为启动托管智能体的方式，”他说道，而其他公司可能会继续使用 Claude、其他开源框架或内部系统。“但所有这些流量仍应流经我们的网关。”

上下文管理是 TrueForge 试图减少浪费的环节

TrueForge 的架构以上下文工程为中心——控制每次智能体运行步骤中发送回模型的信息量。

这包括将 MCP 工具架构的加载延迟到需要时进行，将隔离任务委派给子智能体，将过大的工具结果移入文件而不是塞进活跃的上下文窗口，通过代码处理结构化结果，以及自动压缩长时间运行的对话。

文档将默认压缩阈值设置为 50,000 个 token，不过可以针对每个智能体进行更改。

TrueForge 对沙盒的处理也不同于那些在整个运行过程中将智能体保持在隔离环境中的运行时。核心智能体循环保留在 TrueForge 服务器上；仅当智能体需要执行代码或处理文件时，才会将沙盒作为一种工具进行配置。TrueFoundry 表示，这减少了不必要的计算，并允许服务器并发运行更多智能体。

该公司认为，这些选择直接减少了模型支出。

TrueForge 与 Claude Managed Agents 及其他领先编排框架的对比

类型 / 侧重点
TrueFoundry TrueForge：专为企业部署设计的通用生产级智能体框架。
DeepSeek Harness：开源智能体框架，目前定位为开发者预览版。
OpenAI Codex CLI：专注于编码的智能体框架，主要为软件工程工作流设计。
LangChain Deep Agents：基于 LangGraph 构建的通用智能体框架。
Anthropic Claude Managed Agents：由 Anthropic 运营的完全托管的生产级智能体运行时。

许可证
TrueFoundry TrueForge：MIT。
DeepSeek Harness：MIT。
OpenAI Codex CLI：Apache 2.0。
LangChain Deep Agents：MIT。
Anthropic Claude Managed Agents：专有。

价格
TrueFoundry TrueForge：开源框架本身免费。模型、沙盒和基础设施成本另算。TrueFoundry 还通过其更广泛的平台提供可选的商业治理层。
DeepSeek Harness：无框架许可费。用户需另行支付其使用的模型提供商和基础设施费用。
OpenAI Codex CLI：该 CLI 是开源的。底层模型/API 或订阅费用另算，OpenAI 表示每位开发者每月约 100-200 美元，尽管实际支出因模型选择而异。
LangChain Deep Agents：开源，模型和基础设施费用另算。LangChain 还通过 LangSmith 提供可选的商业服务。
Anthropic Claude Managed Agents：消耗的 Claude token 加上每运行会话小时 0.08 美元，运行时按毫秒计量。

模型灵活性
TrueFoundry TrueForge：供应商中立，围绕自带模型支持设计。
DeepSeek Harness：多提供商，不局限于 DeepSeek 模型。
OpenAI Codex CLI：支持可配置的推理端点，包括兼容 OpenAI 的服务和本地模型选项。
LangChain Deep Agents：通过 LangChain 生态系统提供广泛的多提供商支持。
Anthropic Claude Managed Agents：以 Claude 为中心。

部署
TrueFoundry TrueForge：可以使用 SQLite 作为单进程在本地运行，然后使用 Docker Compose 或 Helm 配合 Postgres 和 Redis 迁移到生产部署。
DeepSeek Harness：专为本地或自托管操作设计。
OpenAI Codex CLI：主要是本地 CLI 体验，辅以 OpenAI 托管的 Codex 产品和服务。
LangChain Deep Agents：可以自托管或通过 LangChain 和 LangSmith 基础设施部署。
Anthropic Claude Managed Agents：由 Anthropic 管理运行时和基础设施。

主要特性
TrueFoundry TrueForge：MCP 和工具编排、子智能体、人工审批检查点、持久会话、上下文压缩、大结果卸载、代码模式、生成式 UI、追踪以及沙盒即工具架构。
DeepSeek Harness：可插拔的模型、工具、会话存储和智能体循环，以及沙盒、权限、审批门控和技能。
OpenAI Codex CLI：智能体循环、仓库和文件操作、Shell 执行、MCP 工具、沙盒、权限、审批和上下文管理。
LangChain Deep Agents：规划、子智能体、技能、基于文件系统的上下文管理、持久记忆、人机交互控制、MCP 支持和多种沙盒后端。
Anthropic Claude Managed Agents：托管执行环境、持久化、工具、沙盒以及用于长时间运行智能体的基础设施。

核心差异化优势
TrueFoundry TrueForge：其最突出的特点是结合了开源、供应商中立的框架，提供了从本地开发到共享生产运行时的清晰路径，并通过 TrueFoundry 提供可选的企业治理平面。
DeepSeek Harness：强调深度模块化。运行时的主要部分，包括模型、工具、存储和智能体循环，都被设计为可替换的插件。
OpenAI Codex CLI：作为一个高度发达的、特定于软件工程的框架脱颖而出，而不是通用的企业智能体服务器。
LangChain Deep Agents：受益于更广泛的 LangChain 和 LangGraph 生态系统，为构建通用智能体提供了成熟的开源路径。
Anthropic Claude Managed Agents：通过让 Anthropic 管理运行时来最大限度地减少运营负担，但这种便利性是以更紧密的模型和平台耦合为代价的。

开源并不自动意味着受治理

对于企业买家来说，最重要的区别之一在于单独的 TrueForge 与连接到 TrueFoundry 商业 AI Gateway 的 TrueForge 之间。

该开源框架可以独立运行。但它不会自动继承组织的企业访问策略。

“如果你只使用我们智能体框架的开源版本，是的，你将需要在其中或某些其他内部控制系统前面设置适当的控制措施，”Gutgutia 告诉 VentureBeat。

该公司表示，当与 TrueFoundry 的网关配合使用时，智能体可以继承已附加到模型、MCP 服务器、工具、技能和其他智能体上的身份和访问控制。Gutgutia 将该网关描述为一个可以集中执行企业 SSO、身份提供商和细粒度权限的地方，而不是为每个智能体单独重新实现。

这种区别对于评估该项目的平台工程团队来说可能很重要。TrueForge 是免费软件；TrueFoundry 的治理层是围绕它的商业控制平面。

TrueFoundry 表示，NetApp 是该框架的测试版用户，并在开发过程中贡献了需求。Gutgutia 表示，NetApp 的 IT 部门已将该技术用于事件响应和更快的工单分类，同时还将内部智能体作为自助服务工具暴露给开发者。他还指出 Automattic 也是早期用户之一。

TrueFoundry 及其迄今为止业务的背景

TrueFoundry 成立于 2021 年，旨在帮助企业部署和运营机器学习模型，包括基于 Kubernetes 的模型服务、训练和基础设施管理。

其三位联合创始人——Nikunj Bajaj、Abhishek Choudhary 和 Anuraag Gutgutia——此前分别就职于 Meta 和 WorldQuant。

Gutgutia 表示，创始人们的共同经验是在成熟系统周围工作，这些系统的基础设施和控制措施旨在防止代价高昂的错误——他们认为，随着 AI 在大公司内部投入生产，这个理念将变得愈发重要。

随着生成式 AI 在企业软件中普及，TrueFoundry 从 MLOps 基础扩展到管理 LLM 应用，并越来越多地管理其周围的模型、工具和智能体。

这一演变得到了约 2100 万美元外部融资的支持。TrueFoundry 于 2025 年 2 月在 Intel Capital 领投下完成了 1900 万美元的 A 轮融资，现有投资者 Eniac Ventures 和 Peak XV 的 Surge，以及 Jump Capital 和包括 Gokul Rajaram、Mohit Aron 在内的天使投资人参与其中。根据 Intel Capital 的公告，该轮融资使总融资额达到约 2100 万美元。

当时，TrueFoundry 表示其客户群同比增长了四倍，并且正在为机器学习工作负载管理超过 1000 个集群。

此后，该业务越来越倾向于围绕大规模企业 AI 流量。在 VentureBeat 2026 年 1 月关于 TrueFoundry TrueFailover 发布的报道中，该公司表示其在全球拥有超过 30 家付费客户，上一年度的年度经常性收入超过 150 万美元，并且每月通过其 AI Gateway 处理超过 100 亿个请求。

TrueFoundry 提及的客户和部署案例包括 NetApp、Siemens Healthineers、ResMed、Automation Anywhere、Nvidia、Games24x7 等；Gutgutia 在接受 VentureBeat 采访时还指出，NetApp、Siemens、Synopsys 和 Automation Anywhere 是与该公司合作的财富 1000 强企业。

TrueFoundry 也一直在通过收购进行扩张。2026 年 6 月，它收购了总部位于英国的 Seldon AI，这是一家老牌 MLOps 供应商，其 Seldon Core 软件已被用于生产模型服务和推理。

正如这次收购所显示的，TrueFoundry 并没有将传统 ML、LLM、工具和智能体视为独立的基础设施类别，而是试图将它们置于一个通用的部署和治理层之后。

TrueForge 将这一策略向上延伸到了智能体运行时本身。直到现在，TrueFoundry 的商业重心很大程度上还是企业 AI 工作负载下方的控制平面——决定哪些用户和应用程序可以访问哪些模型和工具、路由请求、执行策略、监控支出并保持服务可用。

TrueForge 为该公司提供了一个在该层之上的开源运行时，智能体可以在其中实际执行。Gutgutia 将这种关系描述为互补的：组织可以独立运行 TrueForge 或继续使用其他智能体框架，而 TrueFoundry 的长期商业机会是为企业选择的任何智能体提供底层的通用治理和基础设施。
