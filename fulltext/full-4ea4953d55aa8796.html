说实话，它真的_管用_。你把它指向一个真实的代码库，给它一个混乱的多步骤任务，它真的能完成：读取正确的文件，编辑它们，运行测试，然后报告结果。技能系统是我未曾预料到自己需要的一部分：你不再是期望模型表现良好，而是直接将规则（TDD、头脑风暴、代码审查）植入其中，它就会遵循。计划模式 + 子代理意味着我可以预先确定大型工作的范围，然后让它在后台运行，而我去做别的事情。还有记忆功能？改变游戏规则。我告诉它一次“不要在这个仓库中使用 uv”，下次它就会记住，而不需要我重复。

需要改进的地方

高昂的定价 (1)
学习曲线是真实存在的。把文档扔给一个新开发者然后说“祝你好运”有点刻薄。如果你让子代理放任自流，它也可能很昂贵；我希望花费能更实时地可见。有时它会重新读取刚刚编辑过的文件，或者在本可以使用更好工具的时候运行 grep，这些都是小毛病。对于安全的只读内容，权限提示很快就会让人厌烦。而且当钩子或技能悄悄出错时，调试它是一件令人头疼的事，请给我一个详细的跟踪模式。哦，还有，把系统消息适当地本地化；模型说俄语没问题，但 UI 却不行。

对比替代品

我尝试了大多数替代品。如果你生活在 IDE 中，Cursor 很棒，但我是一个终端人。Copilot 用于自动补全还可以，但当你要求它做些真正的事情时，就会觉得很肤浅。Aider 很可爱且开源，但在更大的推理任务上我总是遇到它的极限。Cody 在搜索庞大的代码库方面很扎实，但在实际修改内容方面很弱。直接 API 最灵活也最痛苦，因为你要自己构建所有的粘合代码。浏览器中的 Gemini/ChatGPT 适合出声思考，但在接触代码方面毫无用处。Claude Code 为我找到了最佳平衡点：智能的模型、真正的工具，以及一个不碍事的框架。
