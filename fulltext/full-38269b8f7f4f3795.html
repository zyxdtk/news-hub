Cursor借GitHub故障推竞品托管平台

📅 2026-08-18 📄 TechCrunch AI 🔗 原文链接

原标题：Cursor capitalizes on GitHub frustration, launches rival hosting platform

中文摘要： AI初创公司Cursor（现已并入SpaceX）推出全新代码托管平台Origin，直接对标GitHub。Origin支持代码协作、浏览编辑及拉取请求等功能，并允许与GitHub互操作同步。此举恰逢GitHub频发全球宕机及性能下降问题，导致部分知名用户流失。尽管GitHub仍拥有1.8亿开发者且稳居行业首位，Cursor仍试图借机抢占市场，并计划推出“代理原生”功能及应用生态系统。

广泛报道的宕机和性能下降问题，随着 GitHub 掉链子，Cursor 正等着捡漏。

这家现在正式成为 SpaceX 一部分的 AI 初创公司本周推出了 Origin——一个全新的代码托管平台，旨在完成开发人员通常使用 GitHub 做的所有事情：在代码库上协作、浏览和编辑代码、处理拉取请求（其他人请求将其编辑添加到主代码库中），以及将它们存储在存储库中。

对于 Cursor 来说，这似乎是顺理成章的下一步，在此之前，它的主要重点是通过其 AI 代码编辑器销售自动化 Web 开发服务。Cursor 还表示，“代理原生”功能很快将在 Origin 上线，尽管尚未分享太多细节。该公司还表示，正在构建更广泛的“应用生态系统”，以支持 Origin 内更广泛的编码工作。

有趣的是，使用 Origin 并不要求用户停止使用 GitHub。事实上，Origin 的设计初衷就是允许开发人员与 GitHub 并行工作，并以互操作的方式在两者之间来回传递代码。

Cursor 在其博客中表示：“你的 GitHub 仓库可以与 Cursor 托管的仓库并存。将 GitHub 连接到 Cursor，选择你的组织，你就会看到可以同步的仓库。选择一个，Cursor 就会把它拉进来。”

Origin 的推出恰逢用户对 GitHub 服务质量下降的持续不满。事实上，在 Cursor 推出新平台的同一天，GitHub 遭遇了相当长时间的全球性宕机。据报道，在超过六个小时的时间里，该网站的功能下降，全球错误率接近 20%。

这也不是第一次发生这种事了。今年早些时候，在经历了一连串的宕机之后，随着其可用性问题似乎不断升级，GitHub 宣布了新措施来安抚不满的程序员。LeadDev 最近的一项分析指出，更广泛地说，该平台在过去一年中遭受了 257 次宕机。LeadDev 的记者查尔斯·汉布尔写道，此类持续存在的问题导致了“知名用户的大规模流失”。

尽管如此，如果 Cursor 想要与 GitHub 竞争，它还有很艰巨的工作要做。根据 GitHub 自己的数据，截至去年 10 月，约有 1.8 亿开发人员使用其平台。该平台成立于 2007 年，于 2012 年被微软收购，目前仍是全球最大的源代码托管平台。
