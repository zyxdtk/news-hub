GenXR：创建 AI + XR 体验 XR 开发的民主化已从早期工具包如 VR Juggler (Bierbaum et al., 2001) 和 ARToolKit (Kato and Billinghurst, 1999) 演变为全面的游戏引擎如 Unity (Unity, 2022) 和 Unreal (Unreal, 2022) 。尽管这些原生引擎提供了高保真度的上限，但它们带来了陡峭的学习曲线、XR 快速原型设计的显著摩擦和可执行代码共享的高门槛。相反，WebGL 库如 three.js (three.js authors, 2022) 和框架如 A-Frame (A-Frame Authors, 2025) 提供了跨平台的可访问性，但缺乏复杂 XR 交互和无缝 AI 集成所需的高层抽象。 XR Blocks 桥接了这一差距。通过提供一个高层、网络优化的交互模型，类似于 MRTK (Authors, 2025) 、VRTK (VRTK Authors, 2025) 、XRI (Unity, 2025) 用于 Unity，我们的框架抽象了底层传感器和感知管道，使创作者能够专注于体验的“是什么”而不是“如何”。关键的是，作为一个网络原生架构，XR Blocks 使 AI + XR 原型设计本质上具有可访问性和可重现性，使社区能够无缝地共享、分叉和构建彼此的创作。 Vibe Coding XR 进一步利用此框架创建行为 AI + XR 体验，而逼真的 3D 内容创作 (Poole et al., 2022; Tang et al., 2024; Xu et al., 2024; Hu et al., 2025b) 超出了范围。 概念和模块化框架的示意图 两部分图展示了框架。面板 A，“概念抽象”，显示一个中心“脚本”节点连接到代表“用户”、“世界”、“同伴”、“代理”、“上下文”和“界面”的周围节点。面板 B，“模块化架构”，显示一个中心“核心”节点连接到周围的各个技术模块。 图 3。 XR Blocks 框架设计：(A) “现实模型”的概念抽象，以及 (B) “核心”引擎的模块化架构。标有 ∗ 的子系统尚未完全开源。 2.2. 振动编码：从 AI 到 XR 的差距 AI 社区受益于由 Hugging Face (Hugging Face, 2025) 和 TensorFlow Hub (Google, 2025) 等开放生态系统、LMArena (Chiang et al., 2024) 等基准以及 JAX (Bradbury et al., 2018) 、PyTorch (Paszke et al., 2019) 和 TensorFlow (ten, 2015) 等可组合框架驱动的“飞轮效应”。然而，XR 缺乏一个可比较的基底，用于快速、意图驱动的迭代。最近的努力已经开始通过利用 LLM 在 Unity 中生成空间对象和场景来解决这一问题，例如 LLMR (De La Torre et al., 2024) 、DreamCodeVR (Giunchi et al., 4) 和 Thing2Reality (Hu et al., 2025b) 。此外，最近的系统如 DreamGarden (Earle et al., 2025) 展示了使用 LLM 驱动的分层规划在 Unreal Engine 中生成功能性 3D 游戏环境、资产和 C++ 逻辑。 尽管这些方法成功地推动了自动化游戏设计和 3D 场景组合的边界，但它们通常依赖于在重型、封闭引擎生态系统中的异步编译工作流。这阻碍了集体“振动编码”范式 (Edwards, 2025) ，其中代理的效用从根本上与其在相关领域内合成和共享知识的能力紧密相连。 为此，我们受到 (Du et al., 2023) 的启发，致力于开发一个基于开放网络的空间计算平台。通过将 LLM (Zhou et al., 2025) 围绕 XR Blocks 框架，Vibe Coding XR 赋予创作者实时生成沉浸式、智能和物理感知交互的能力。 这种基于网络的方法确保了每个贡献都 (1) 建立在透明、网络标准的代码库之上，(2) 设计用于快速迭代，以及 (3) 可立即分发到各种设备和用户。通过优先考虑这些支柱，我们朝着一个生态系统迈进，在这个生态系统中，社区不仅仅是消费代理，而是积极驱动其进化，为 XR 开发带来真正的“飞轮效应”。 3. Vibe Coding XR 我们引入 Vibe Coding XR，一种快速原型工作流，结合了 LLM 的生成推理能力和高层模块化 XR 框架。这种协同作用使创作者能够绕过底层系统编程的摩擦，专注于纯粹塑造空间行为、AI 逻辑和交互。 3.1. 性能与延迟： 我们选择的网络技术优先考虑可访问性，但带来了已知的权衡。该框架永远无法匹配 Unity 或 Unreal 等原生引擎的渲染性能，且依赖云 AI 模型会引入网络延迟。我们的愿景目标是开发一个 LLM 驱动的跨编译器，能够将高层 XR Blocks 脚本翻译成针对 GoDot 等多个目标引擎的优化原生代码；我们邀请整个社区贡献 AI + XR 交互的常用实践 SDK，以进一步降低 LLM 令牌成本。 多感官合成： 我们专注于视听体验，但 XR Blocks 被设计为可扩展的。集成触觉、EEG 和其他感官模态的模块可以使创作者编写真正沉浸式、多感官的叙事。例如，可以通过 WebUSB 协议将 Arduino 扩展到 XR Blocks。 大规模基准测试与代理评估： 作为初步步骤，VCXR-60 远未覆盖 AI + XR 的全部范围。例如，严谨的评估应将 XR Blocks 的贡献与 three.js 解耦，并定量评估 XR Blocks 的抽象能节省多少令牌。尽管我们致力于开发更严谨的基准，但我们希望与社区一起开源 XR Blocks，以配合下一代 LLM 的发展。未来的工作将研究带有人类参与的代理测试，并最终发明更好的 AI + XR 交互范式。 6. 结论 我们提出了 Vibe Coding XR，一种端到端工作流，通过将高层创意意图转化为功能性 XR 原型，民主化了空间计算。通过将 LLM 的生成推理与 XR Blocks 框架相结合，我们展示了一种新颖的方法，将短暂的想法与有形的、物理感知的现实之间的距离缩短。这种向空间“振动编码”的转变赋予了一代新的创作者塑造 3D 网络的能力，将被动消费者转变为数字和物理环境的主动建筑师。 然而，这种人机共生仍处于其初期阶段。当前 LLM 的随机性仍会引入摩擦，偶尔生成的代码会误解物理约束、语法或复杂交互逻辑。此外，XR Blocks 目前缺乏现成的无障碍模块。为了成熟这一领域，该领域必须超越临时演示，转向严谨、正式的基准测试。正如 ImageNet (Deng et al., 2009) 加速了计算机视觉的进步，我们设想大规模、开源的“提示到交互”数据集。此类基准将通过人类评分、专家评审和代理工作流系统性地评估生成的空间行为。结合自然语言提示与空间 UI 的混合方法也将对精炼 XR 创作至关重要。 作为一个不断发展的生态系统，XR Blocks 的未来迭代必须扩展其生成词汇，以支持改进的美学和更丰富的多模态输入。这将使用户不仅通过文本和语音，还能通过凝视、微手势和跨设备交互来引导生成。同时，负责任的现实世界部署需要严谨的人类参与评估，以更好地理解设计师如何与 AI 代理共同创作，确保这些工具安全地增强人类意图，而不是引入有害的噪声。 最终，我们开源此框架作为开放邀请。我们欢迎 HCI、XR 和 AI 社区在此工作流基础上构建，填补现有工具原语和表达性的空白，并共同实现一个未来，即创建一个交互式、混合现实世界就像描述一个梦想一样自然。 致谢。 我们感谢 2025 年所有 XR Blocks 贡献者，包括 David Li、Nels Numan、Xun Qian、Yanhe Chen、Zhongyi Zhou、Evgenii Alekseev、Geonsun Lee、Alex Cooper、Min
