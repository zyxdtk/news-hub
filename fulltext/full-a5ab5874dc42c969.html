摘要

世界动作模型以语言为条件联合预测视频和动作。现有研究主要关注架构和训练机制，通常将通过视频预训练获得的语言–视频对齐视为既定基础。然而，引入动作学习可能会损害这种对齐。在动作学习过程中维持语言–视频对齐的数据和监督设计的原则性指导仍然有限。为此，我们策划了一个包含约47,000小时通用视频、自我中心视频、UMI演示和机器人演示的数据池。在此基础上，我们系统研究了语言–视频监督、语言–视频–动作监督以及这两种形式的联合使用如何影响WAM性能。特别地，我们考察了语言标注质量如何影响预训练的语言–视频能力，以及来自UMI和机器人演示的动作监督如何将这些能力扩展到语言–视频–动作建模。为了更好地扩展模型，我们进一步对联合训练方案和模型架构进行了详细研究。在固定训练预算下，混合自我中心视频和UMI演示可改善控制泛化能力。模型架构影响这些经验的使用效果，而在所选配置下扩展预训练可带来进一步收益。最终方案仅在RoboTwin Clean演示上进行后训练，在Easy（Clean-to-Clean）和Hard（Clean-to-Random）条件下分别达到88.10%和61.56%的成功率。我们的模型在三个真实世界任务中达到40.00%的成功率（SR），而最强基线为23.33%，表明在未见条件下具有更好的泛化能力。我们发布了策划的数据、训练代码和模型权重。

1 引言

预训练视频模型学习语言描述、视觉内容和视觉动态之间的关联，获取跨场景、物体和交互的视觉与动态先验 [1, 2, 3, 4]。这些经验为机器人理解操作目标和预测环境变化提供了基础 [5, 6]。世界动作模型以语言为条件联合预测视频和动作，将视觉变化与机器人动作连接起来，提供了从视频预训练到机器人控制的路径 [7, 8]。本文研究如何更好地利用这些先验，将语言条件化的视频建模扩展为可泛化的动作能力。

当我们引入动作预测时，视频预训练中获得的语言–视频能力应当被保留。这需要语言、视频和动作之间的进一步对齐。它弥合了语言描述的目标、视觉观察和执行动作之间的差距。现有的WAM工作主要关注模型架构和训练机制 [9, 10]。视频预训练方法通常将语言–视频对齐视为既定基础 [7, 8]。然而，引入动作学习提出了一个基本问题：如何保持已建立的语言–视频先验，并进一步解决语言–视频–动作失配？不同经验和监督形式在此过程中的作用，特别是对控制泛化的作用，仍不清楚 [9, 10, 11, 12]。

图2： 多源数据和模型概览。 47k小时预训练数据池的组成。 我们的世界动作模型架构，视频和动作分支通过共享掩码注意力连接。

为研究这些问题，我们首先构建了一个约47,000小时的多源数据池，包括约11,000小时通用视频、11,000小时自我中心视频、15,000小时内部UMI演示和10,000小时机器人演示，如图2(a)所示。这些来源提供了不同形式的跨模态监督。通用视频和自我中心视频主要提供语言–视频监督，分别涵盖一般视觉动态和人类交互。UMI演示记录了人类使用手持夹爪操作物体的视频和动作轨迹，而机器人演示提供了机器人任务执行过程中的观察、状态和动作。两者都包含与操作过程对应的语言描述，除语言–视频监督外还支持语言–视频–动作学习。UMI演示提供可扩展的人类操作经验，而机器人演示提供直接但更有限的机器人控制经验 [13, 14, 15]。这些来源在场景和任务覆盖以及语言和动作监督的完整性方面存在差异。因此，多源预训练需要适当组合这些经验：语言–视频监督保持视频预训练能力，而人类和机器人动作监督建立视频–动作对应关系 [16, 17, 18]。

在构建的多源经验基础上，我们在三个层面进行系统研究：语言–视频对齐、语言–视频–动作对齐和联合学习。具体而言，在语言–视频层面，我们考察如何通过语言监督设计保持预训练视频生成中的视觉先验。在语言–视频–动作层面，我们研究如何利用来自UMI和机器人演示的动作监督来帮助动作预测和机器人控制。在联合训练中，我们研究用于更好跨模态建模的数据方案和模型架构。数据方案决定了任务、场景中视觉和交互经验的覆盖以及不同经验的比例。模型架构回答了如何通过模态交互和语言条件化路径进行跨模态监督，如图2(b)所示。我们进一步检验了使用最终数据和监督方案扩展训练的收益。

我们的研究表明，保持语言–视频能力和扩展语言–视频–动作能力共同支持WAM的控制泛化。详细的操作描述和环境线索改善了语言–视频监督，保持了语言–视频对齐，从而提高了控制泛化。UMI演示改善了仿真和真实场景中的机器人控制，证明了带有动作监督的人类操作经验对机器人学习的价值。在联合学习中，多源经验的收益同时取决于数据和模型监督方案。实验表明，在所选数据和模型方案下增加训练投入可进一步提高控制泛化。这些发现为WAM中的数据收集和组织、监督设计以及联合训练提供了实证指导。从这些发现得出的预训练方案在RoboTwin Easy（Clean-to-Clean）和Hard（Clean-to-Random）设置下分别达到88.10%和61.56%的成功率。我们的模型在Hard设置下三个真实世界任务中达到40.00%的SR，超过OpenWAM的23.33%。这一结果表明对未见物体和背景具有更好的泛化能力。

2 相关工作

世界动作模型。 世界动作模型旨在将视觉观察与可执行的机器人动作连接起来 [7]。早期工作将视频视为可迁移的视觉计划或动态表示。UniPi首先生成语言条件化的视觉计划，然后通过逆动力学模块恢复动作 [19]。VPP基于视频模型的预测表示对策略进行条件化 [6]。Motus、DreamZero和LingBot-VA将视觉动态和动作预测置于统一或交互式架构中，探索离散token、潜在动作、联合流匹配和因果视频–动作建模 [20, 7, 8]。Fast-WAM和InternW0-Δ进一步区分了训练时的未来监督与推理时的动作生成，表明预测目标和部署接口可以分离 [21, 17]。VPP2和LingBot-VA通过研究操作数据组织、时间和视频表示建模以及动作分支适应如何保持视频预测能力同时支持动作学习，将视频预训练适配到机器人操作 [18, 8]。我们在此基础上，关注视频预训练的语言–视频能力如何迁移到语言–视频–动作学习和动作控制。

机器人学习的多源数据。 机器人学习越来越依赖于跨具身轨迹、通用视频、自我中心视频和人类操作演示，而非单一的机器人数据源。Open X-Embodiment、Octo和OpenVLA聚合和过滤多机器人数据以研究共享表示、观察适应和动作空间对齐，表明跨具身学习需要源规范化和接口对齐 [22, 23, 24]。通用视频和自我中心视频扩展了场景、物体和交互动态的覆盖，但通常缺乏与机器人执行直接对应的动作标签 [25, 26]。EgoMimic和EgoScale研究如何通过视角和具身对齐迁移此类人类经验，包括机器人数据有限的设置 [27, 28]。UMI通过使用便携式接口以类末端执行器的交互格式记录操作轨迹来补充这些来源，从而提供与操作过程相关的动作监督 [13, 14, 15]。EgoWAM、Ego4WAM和Motus进一步展示了视频、动作轨迹、语义描述和世界预测目标的互补作用 [29, 10, 20]。多源学习的核心问题因此不是简单地增加来源，而是理解场景覆盖、交互动态、具身接口和可用监督的差异。我们策划了约47,000小时的多源数据。我们使用该数据池系统检验经验组合和监督设计如何影响WAM预训练。

3.1 世界动作建模

3.1.1 问题表述

我们考虑语言条件化的机器人操作。给定迄今为止获得的视觉观察、语言指令和当前本体感知状态，机器人在未来区间上预测动作。设 $n$ 为从轨迹中采样的预测起始点，$K>0$ 为固定预测视界，$V_{0:n}$ 为包括当前观察的视觉历史，$P$ 为语言条件，$S_n$ 为当前状态。控制任务需要学习一个以视觉历史、语言指令和当前状态为条件的动作策略 $\pi_\theta$：

$$A_{n:n+K}\sim\pi_{\theta}(\cdot\mid V_{0:n},P,S_{n}), \tag{1}$$

其中 $A_{n:n+K}$ 表示目标区间上的动作序列，$\theta$ 表示模型参数。

主要由观察–动作对监督的控制学习必须同时解决场景理解、交互动态和动作生成。我们采用基于预训练视频模型的世界动作模型（WAM），利用视频预训练期间学习的语言描述与视觉动态之间的关联，并通过动作监督学习操作过程与执行动作之间的对应关系。该模型在同一区间上联合预测视频变化和动作。视频序列 $V_{n:n+K}$ 描述操作期间可观察的场景演化，而动作序列 $A_{n:n+K}$ 描述相应的操作行为。两个序列跨越相同的物理时间区间，但可能使用不同的采样率。

我们将视频和动作的联合预测分布表示为 $p_\theta$：

$$p_{\theta}(V_{n:n+K},A_{n:n+K}\mid V_{0:n},P,S_{n}) \tag{2}$$
$$=p_{\theta}(V_{n:n+K}\mid V_{0:n},P,S_{n})\,p_{\theta}(A_{n:n+K}\mid V_{0:n+K},P,S_{n})$$
$$=p_{\theta}(V_{n:n+K}\mid V_{0:n},P)\,p_{\theta}(A_{n:n+K}\mid V_{0:n+K},P,S_{n}).$$

最后的等式源于我们的建模选择，即视频分支不以本体感知状态为条件。第一项学习语言条件化的视频预测，对应于语言–视频学习。第二项从语言、视频信息和当前状态预测动作。两项共同构成联合语言–视频–动作学习。

从预训练视频模型出发，我们使用联合预测目标端到端训练统一的WAM。动作分支使用视频分支提供的视觉动态和语言条件信息。训练保留视频预测目标同时引入动作监督，旨在继续使用现有的语言–视频建模能力，并学习视频中操作过程与执行动作之间的对应关系。

多源经验为联合预测提供监督的不同部分。通用视频和自我中心视频提供语言–视频对应关系，用于学习语言条件化的视觉动态。UMI和机器人演示额外提供与视频时间相关的动作，使动作预测与视频学习并行。所有样本都参与视频学习。具有有效动作标注的样本额外参与动作学习。缺失或无效的动作目标不提供动作监督。因此，具有不同监督覆盖的经验可以参与统一的WAM预训练。

3.1.2 模型架构

图3： 世界动作模型架构和注意力掩码。 视频和动作DiT分支通过共享掩码注意力连接，文本交叉注意力仅在视频分支中。 教师强制下使用干净视频历史训练的注意力掩码。 推理时逐块生成视频和动作的注意力掩码。

给定视觉观察 $V={v_i}_{i=1}^{T}$、语言指令 $P$ 和可用状态 $S$，我们采用联合预测视频和动作的WAM。虽然上述 $n:n+K$ 表示轨迹级预测区间，但下面我们使用 $t$ 来索引时间对齐的视频–动作块。每个块包含2个视频潜在帧和48个动作步。对于块 $t$，设 $V_t\in\mathbb{R}^{T_v\times H\times W\times 3}$ 表示相应视频，$S_t\in\mathbb{R}^{D_s}$ 表示块起始处的可用状态，$A_t\in\mathbb{R}^{H_a\times D_a}$ 表示归一化的目标动作序列。其中，$T_v$ 是视频帧数，$H$ 和 $W$ 是帧的高度和宽度，$D_s$ 是状态维度，$H_a$ 和 $D_a$ 分别是动作步数和动作表示维度。VAE将视频编码为潜在表示 $x_t$。独立的编码器将动作和状态映射到token。文本编码器将语言指令映射为条件 $p$。

我们在图3中展示了模型架构以及训练和推理期间使用的注意力掩码。该模型采用MoT架构 [30]，视频分支从Wan [2] 初始化，动作分支随机初始化。动作DiT分支包括动作和状态编码器、transformer块和动作解码器。视频和动作维护独立的残差流，联合注意力将信息从视频单向传递到动作。视频token流通过视频分支，因果地关注当前和过去的视频token。动作token流通过动作分支，关注来自过去和当前块的视频token，以及当前块内的状态和动作token。这种单向交互允许仅有视频监督的样本继续训练视频分支，而不会通过视频目标直接更新动作分支，支持使用没有动作监督的视频。

视频分支通过交叉注意力接收编码的语言条件。动作分支仅通过与视频分支的注意力交互使用语言信息，没有直接的文本交叉注意力。这种条件化路径旨在重用视频预训练期间建立的语言–视频对应关系，使动作预测能够使用与操作过程相关的语义信息。视频分支预测视频潜在空间中的流速度，而动作分支将其输出token解码为动作空间中的流速度。

3.1.3 训练目标

对于块 $t$，$x_t$ 和 $A_t$ 分别表示干净的视频潜在表示和动作目标。设 $\tau\in[0,1]$ 表示流匹配时间。我们采样与各自目标形状相同的独立标准高斯噪声 $\epsilon_v$ 和 $\epsilon_a$，并构建噪声目标：

$$x_{t}^{\tau}=(1-\tau)x_{t}+\tau\epsilon_{v}, \tag{3}$$
$$A_{t}^{\tau}=(1-\tau)A_{t}+\tau\epsilon_{a}.$$

动作编码器将噪声动作 $A_t^\tau$ 映射到动作token。块内的视频和动作共享 $\tau$，跨块独立采样。训练使用教师强制，以过去的干净视频潜在表示 $h_t$ 作为上下文。设 $u_\theta^v$ 和 $u_\theta^a$ 分别表示视频和动作速度预测器，其输出分别与 $x_t$ 和 $A_t$ 形状相同。动作预测器 $u_\theta^a$ 表示完整的动作DiT分支，包括动作和状态编码、transformer处理和动作解码。两个流匹配损失 [31] 为：

$$\mathcal{L}{\mathrm{video}}=\mathbb{E}!\left[\left|u{\theta}^{v}(x_{t}^{\tau},h_{t},p,\tau)-(\epsilon_{v}-x_{t})\right|_{2}^{2}\right], \tag{4}$$

$$\mathcal{L}{\mathrm{action}}=\mathbb{E}!\left[\left|u{\theta}^{a}(A_{t}^{\tau},x_{t}^{\tau},h_{t},S_{t},p,\tau)-(\epsilon_{a}-A_{t})\right|_{2}^{2}\right].$$

其中，$\theta$ 表示模型参数，期望在训练样本、噪声和流匹配时间上取值。动作输出通过视频分支依赖于当前视频 $x_t^\tau$ 和语言条件 $p$。两个损失以相等权重组合：

$$\mathcal{L}=\mathcal{L}{\mathrm{video}}+\mathcal{L}{\mathrm{action}}. \tag{5}$$

所有样本都对视频目标有贡献。动作目标仅对具有有效动作标注的样本计算。

视觉内容过滤。 对于OpenVid和Panda70M等通用视频数据集，我们使用原始标注和基于VLM的内容审查来移除动画、静态场景、电视节目和其他不合适的内容。对于自我中心视频，我们使用VLM评估运动模糊、亮度、遮挡以及片段是否包含有意义的动作，减少低质量图像和无信息行为对训练的影响。下文描述的UMI和机器人演示使用类似的过滤规则。

通用视频上的视频模型适应。 我们的WAM修改了Wan的视频建模设计以支持机器人控制，这可能会破坏预训练的视觉和动态先验。为缓解这种适应，我们首先在通用视频上训练视频分支，其分布接近Wan的预训练数据。在此阶段，我们使用与后续WAM训练相同的输入帧数、空间分辨率和因果注意力方案。此阶段旨在在适应过程中保持这些先验，然后再引入具身数据。

3.2.2 语言标注

语言标注描述被操作的物体和执行的动作，还可能额外包括交互关系、操作过程和环境信息。对于WAM预训练，什么语义信息有助于将视频经验转化为控制能力？这些标注能否帮助保持语言–视频对齐并改善下游泛化？我们沿三个维度组织语言监督：操作描述的详细程度、环境信息和时间粒度。

详细程度。 任务描述涵盖操作期间执行的动作、交互物体及其属性。我们定义了三个描述详细程度级别：简略、中等和详细，要求和示例见表3。这些级别定义了受控的语言标注变体，用于评估描述详细程度如何影响预训练视频能力向机器人控制的迁移。

表3：三个详细程度的语言标注要求和示例描述。 所有示例描述同一操作片段。

详细程度 标注要求 示例语言标注

中等 用一句话总结操作，添加物体属性、空间关系或可见结果。 拿起浅蓝色包装的零食。

3.3 语言–视频–动作对齐

UMI和机器人演示遵循第3.2.1节中的视频策划和过滤程序，并使用第3.2.2节中描述的语言标注。在这些语言–视频对应关系的基础上，我们将视频片段与状态和动作记录对齐，构建语言–视频–动作监督。我们在下面描述这些演示的收集和策划。

UMI演示。 我们使用411,754条内部UMI轨迹，共计15,284.9小时。我们使用RoboPocket [15] 收集人类操作演示。该系统将智能手机与手持自适应夹爪集成为便携式收集设备。操作者通过移动、打开和关闭夹爪与物体交互。其结构和交互机制类似于机器人末端执行器，减少了人类演示与机器人执行之间的接口差异。我们的收集任务包括鼠标放置、积木分类、调味料倾倒、毛巾折叠、双手零食装袋等日常操作任务。它们涉及抓取放置、长视界操作、大幅手腕旋转、可变形物体操作和双手协调。收集环境包括具有不同光照和背景纹理的室内和室外场景。

在收集过程中，头部和双侧腕部视角分别记录整体操作场景和局部交互细节。智能手机视觉–惯性跟踪提供动作轨迹，而外部编码器记录夹爪的打开和关闭。共享的坐标系和时间参考建立了双手视频、运动轨迹和夹爪状态之间的空间和时间对应关系。收集程序包括录制前的设备检查和同步验证、录制期间的跟踪稳定性和运动学可行性检查，以及之后的视频和AR轨迹回放。这些检查识别定位漂移和轨迹跳跃等异常，并验证任务完成情况。

机器人演示。 我们从AgiBot World Alpha/Beta/2026 [37]、RoboCOIN [38]、RoboMIND [39]、InternData-A1 [40]、Galaxea Open-World [41] 和ABC-130K [42] 中策划数据。这些来源涵盖不同的机器人具身、相机配置和操作环境。我们仅保留使用双手机器人收集的、包含头部和双侧腕部视角并满足我们质量要求的演示子集，保持一致的数据接口和观察语义。我们排除缺少视角、视角语义不一致、图像分辨率不足、任务过于简单、单臂机器人具身或其他问题的子集。在应用配置的回合排除列表后，我们保留了768,356条轨迹，共计9,836.0小时。

状态–动作表示。 UMI和机器人演示使用共享的16维双手末端执行器表示。每只手具有三维位置、wxyz顺序的四维旋转四元数和一维夹爪值。状态和动作记录与其相应的视频片段关联。每个来源使用其自己的q1和q99统计数据进行归一化。

轨迹质量。 对于我们的内部UMI演示，我们从收集管道提供的状态和动作有效性标注构建动作监督掩码。视频参与视频学习，而有效的动作标签额外提供动作监督，无效标签被掩码。对于收集的机器人演示，我们首先检查动作维度、缺失值、NaN、非有限值和四元数有效性。对于具有所需关节和末端执行器状态字段的子集，我们进一步排除具有异常关节角度、相邻帧之间关节角度或末端执行器位姿过度变化或整个轨迹无运动的轨迹。通过这些质量检查的轨迹用于动作训练。

4 实验

我们旨在利用多源经验保持视频预训练中获得的语言–视频能力，并将其扩展到可泛化的机器人控制。我们的实验考察语言–视频对齐、语言–视频–动作对齐、联合训练和预训练规模如何影响下游泛化。我们围绕以下四个问题组织研究：

  • 如何建立有效的跨模态对齐？
  • 如何整合多源经验？
  • 扩展预训练是否能改善控制泛化？
  • 我们的模型在未见环境中的表现如何？

4.1 实验设置

预训练。 我们使用上述架构和多源语料库预训练模型。视频分支从Wan2.2-TI2V-5B [2] 初始化，动作分支随机初始化。训练期间更新所有模型参数。预训练和后训练都使用上述定义的联合视频和动作目标。我们使用AdamW，初始学习率为 $4\times 10^{-5}$，默认全局批次大小为256。每项研究的训练步数和具体设置在相应的实验描述和表格标题中给出。

仿真后训练。 我们使用RoboTwin 2.0 [43] 中的50个操作任务。对于主要仿真比较，我们包括VLA基线（StarVLA [44]、$\pi_{0.5}$ [45]、Xiaomi Robotics-0 [46] 和X-VLA [47]）和基于视频的WAM基线（Fast-WAM [21]、LingBot-VA [8]、OpenWAM [9]、X-WAM [48] 和4D-WAM [49]）。观察包括头部和双侧腕部相机视角以及末端执行器状态。模型预测双手末端执行器动作。每个任务提供50个Clean演示，总共2,500个演示。从相应的预训练检查点开始，我们在所有50个任务上联合后训练单个模型20k步，全局批次大小为128。

仿真评估。 我们在RoboTwin上评估两种设置下的控制泛化。模型仅在Clean演示上进行后训练。Easy在后训练使用的相同干净条件下评估所得模型（Clean-to-Clean，C2C）。Hard在随机化条件下评估相同模型，包括背景纹理、杂乱、光照、桌面高度和相机位置的变化（Clean-to-Random，C2R）。对于每个任务和设置，我们为消融研究运行25个评估回合，为主要结果运行100个回合。我们报告全任务成功率（SR）。

真实世界后训练。 我们使用双手Flexiv Rizon 4平台进行杯子堆叠、毛巾折叠和礼盒装放。对于真实世界评估，我们选择StarVLA、$\pi_{0.5}$、Fast-WAM、LingBot-VA和OpenWAM作为代表性的VLA和WAM基线。观察包括两个鱼眼腕部相机视角和一个固定的头部相机视角。所有比较的模型使用相同的任务特定后训练数据。从上游预训练权重开始，我们为每个任务适配一个单独的模型50k步，全局批次大小为128。

真实世界评估。 我们在Easy（C2C）和Hard（C2R）设置下评估。Easy改变熟悉物体的位置，Hard改变物体、背景或两者。每个任务和设置使用评估前固定且所有模型共享的十个布局。每个布局运行三次试验，每个任务和设置共30次试验。所有模型使用同步推理并以30 Hz执行动作。成功率（SR）测量完成整个任务的试验比例。部分成功率（PSR）测量每次试验完成的预定义子任务的平均比例。我们计算每个任务的这两个指标，并在三个任务上平均。

4.2 如何建立有效的跨模态对齐？

我们通过语言标注设计、配对动作监督和互补视频经验来考察语言–视频和语言–视频–动作对齐。下游控制评估衡量这些监督选择的效果。

4.2.1 语言–视频对齐

详细准确的语言描述改善下游控制泛化。 预训练视频模型从大规模语言–视频数据中学习关于场景、物体和运动的丰富信息。在WAM预训练期间，我们提供准确匹配视频内容的信息性语言监督。我们旨在帮助模型在适应机器人操作数据时保持预训练先验，减少对现有语言–视频能力的遗忘。在所有设置中，我们在自我中心视频和UMI演示的混合上预训练20k步，考察描述详细程度、场景信息和时间粒度作为语言监督的三个方面。

对于描述详细程度，我们比较三个级别：简略、中等和详细。我们还比较有和没有涵盖背景、空间布局和光照的场景描述的设置。对于时间粒度，我们比较覆盖完整轨迹的回合描述与局部操作片段的子任务描述。

我们在表4中比较这些语言监督选择。在每个时间粒度下，更详细的描述产生更高的Hard成功率。在子任务级别，Hard成功率从简略、中等到详细描述分别为47.20%、49.60%和53.52%。添加环境信息进一步将其提高到55.04%，在该组中达到最高的Easy和Hard成功率。对于时间粒度，在详细设置下用子任务描述替换回合描述将Hard成功率从51.60%提高到53.52%。

这些结果表明，更丰富的操作描述、额外的环境信息和子任务级语言监督改善下游控制泛化。我们进一步随机打乱每个轨迹内详细子任务描述与视频片段之间的对应关系，将Hard成功率从53.52%降低到52.00%。这一结果进一步突出了准确匹配的语言监督对语言–视频对齐的重要性。

4.2.2 语言–视频–动作对齐

人类操作经验提供有效的语言–视频–动作监督。 语言–视频监督将语言描述与视频中的操作过程关联，而配对的动作标签进一步为语言–视频–动作对齐提供监督。从Wan直接后训练达到34.56%的Hard SR。通过机器人数据预训练，在表5中达到56.16%，展示了机器人操作数据的价值。我们进一步考察来自UMI的人类操作经验是否能提供有效的跨具身语言–视频–动作监督。为考察UMI动作监督的贡献，我们保留所有UMI视频，仅改变预训练期间提供动作标签的轨迹比例。没有动作标签的视频继续参与视频学习。在每个覆盖率级别，提供动作监督的轨迹子集保持固定。所有设置使用相同的预训练预算，然后进行20k步的下游后训练。从表6中，我们观察到随着动作标签覆盖率从0%增加到100%，Hard成功率在所有五个覆盖率级别上都在增加，从46.72%上升到51.28%，增益为4.56个百分点。这些结果表明，来自人类操作经验的配对动作为机器人控制提供了有效的监督，尽管UMI数据在视觉上与机器人执行不同。鉴于UMI演示可以在不同场景中使用手持设备收集，这一发现支持人类操作演示作为扩展机器人控制预训练经验的来源。

4.3 如何整合多源经验？

5 讨论与结论

在这项工作中，我们研究了如何利用多源经验将预训练的语言–视频能力扩展到可泛化的机器人控制。使用约47,000小时的经验，我们系统研究了语言–视频对齐、语言–视频–动作对齐及其联合学习。我们发现详细准确的语言描述保持了预训练的语言–视频能力。同时，来自UMI演示的动作监督进一步支持机器人控制，展示了人类操作经验对机器人学习的价值。我们的发现证明了经验组织和监督使用的重要性。最终的训练方案在仿真和真实世界评估中展示了对未见条件的泛化，持续预训练带来进一步收益。我们发布数据、代码和模型权重以支持未来研究。

在预训练视频模型之上，所提出的方法对复杂推理和显式多阶段规划的支持有限，尽管在我们的控制泛化评估中优于VLA模型。有限的历史上下文也可能阻碍长程任务的执行。未来，我们计划探索记忆机制和分层规划，以支持需要对过去观察进行推理和规划后续动作的任务。

附录A 数据标注细节

通用视频保留其原始描述。对于自我中心视频、UMI演示和机器人演示，我们主要使用Qwen 3.8 Max进行子任务分割，使用Seed 2.1 Pro进行描述标注，构建操作标注。该过程包括以下步骤。

子任务分割。 我们使用Qwen 3.8 Max根据动作意图将自我中心视频和UMI录制划分为时间有序、不重叠的子任务，记录每个子任务的开始和结束时间。机器人演示较短，因此每个完整回合被视为一个子任务，无需进一步分割。

描述标注。 我们使用Seed 2.1 Pro标注每个自我中心或UMI子任务以及每个机器人回合。模型识别片段是否包含操作以及视觉证据是否足够清晰，并以多个详细程度描述场景、光照和动作。不包含操作或视觉证据不足的片段被完全丢弃。

动作质量过滤。 对于UMI和机器人数据，我们进一步筛选相关的状态和动作轨迹。未通过以下一项或多项检查的样本将从动作训练中移除：

  • 缺失或非有限值，包括NaN、无效维度或无效四元数。
  • 过大的绝对关节值，任何 $|q|>20\,\mathrm{rad}$。
  • 相邻帧关节跳变，任何 $|q_{t+1}-q_t|>1\,\mathrm{rad}$。
  • 末端执行器位置跳变，相邻三维位置之间的欧几里得距离超过 $0.2\,\mathrm{m}$。
  • 末端执行器方向跳变，任一臂相邻帧之间的旋转角度差超过 $90^\circ$。
  • 关节或末端执行器轨迹中的持续异常加加速度。

分割和描述标注提示的精简版本如下。

分割提示（精简）

角色。 你是专业的机器人操作视频分析专家。

目标。 将视频分割为连续、不重叠的原子子任务。输入视频以2 fps采样，连续帧之间间隔0.5秒。总任务是：task_name。

工作流程。
1. 观看完整视频，按时间顺序识别每个有意义的原子动作。
2. 按动作意图分割。
3. 确保子任务顺序排列，无重叠或间隙。
4. 准确命名物体。

输出。 输出包含每个子任务的描述、开始时间和结束时间的标准化JSON。

[
  {
    "description": "子任务描述",
    "start_time": 0.500,
    "end_time": 2.500
  }
]

描述提示（精简）

角色。 你是专业的第一人称操作视频分析专家和密集动作标注专家。准确、客观、简洁地描述场景和连续操作动作。

任务。 观看输入视频，仅使用视觉可观察的证据。参考任务 task_annotation: {task_name} 仅是弱提示；所有描述必须有可见视频内容支持。

片段类型分类。 输入是从完整视频中剪切的时间片段，可能不包含实际操作，例如等待、姿势调整、悬停或观察。首先确定：

  • 当片段包含对任务物体的实际操作时，segment_type = manipulation。
  • 当片段不包含对任务物体的操作时，segment_type = no_action。

视觉清晰分类。 visual_clear 字段仅描述视觉证据的质量：

  • 当主要物体和动作足够可见可以判断时，即使有普通运动模糊或局部遮挡，设置 visual_clear = true。
  • 当严重模糊、黑暗、遮挡、损坏或缺失视角使主要物体或动作不可靠判断时，设置 visual_clear = false。

场景。 用一句话描述初始操作环境。仅提及可见的工作空间、相关背景物体、大致位置和初始状态。

光照。 用一句话描述亮度、曝光、均匀性、阴影、过曝、欠曝、模糊或遮挡。

action_detail。 作为一个按时间顺序的段落描述操作，包括被操作物体、可辨识的手部动作、物体轨迹、交互、状态变化和必要的调整。

action_medium。 用一句话描述操作，添加物体属性、空间关系或可见结果。

action_short。 用2-8个词的动宾短语总结主要动作和核心物体。

输出。 仅返回一个包含以下字段的有效JSON对象。segment_type 使用 manipulation 或 no_action，visual_clear 使用JSON布尔值。描述用英文书写。对于 no_action，三个动作字段设为 none；否则仅描述观察到的动作。

{
  "segment_type": "manipulation",
  "visual_clear": true,
  "lighting": "",
  "scene": "",
  "action_detail": "",
  "action_medium": "",
  "action_short": ""
}

B.2 训练配置

初始化。 在预训练中，我们从Wan2.2-TI2V-5B [2] 初始化视频DiT，并加载其预训练的UMT5-XXL文本编码器和Wan2.2视频VAE。动作分支（包括动作和状态编码器、transformer块和动作解码器）随机初始化。对于每个实验，后训练从相应的预训练权重开始。

预训练。 训练使用BF16混合精度。消融研究的默认全局批次大小为256。在4.4节描述的扩展研究和后续机器人数据预训练以及4.5节评估的最终模型预训练中，我们将其增加到512。对于扩展研究，我们以相等概率采样自我中心视频和UMI演示，并使用带有场景和光照信息的详细子任务描述。我们评估25k、50k、75k和100k步的检查点，如图5所示。表13比较了扩展研究中的预训练与仿真和真实世界后训练。
