利用大模型增强 App Store 排序相关性

📅 2026-02-26 📄 arxiv 🔗 原文链接

原标题：Scaling Search Relevance: Augmenting App Store Ranking with LLM-Generated Judgments

中文摘要： 本文提出利用微调后的小型大语言模型（FT-3B）生成数百万高质量文本相关性标签，显著增强 App Store 排序器。该方法突破人工标注瓶颈，使行为-文本相关性帕累托前沿外移：离线 NDCG 全面提升，全球 A/B 测试显示转化率显著增长 0.24%，尾部查询效果最显著。验证了 LLM-as-a-Judge 范式的工业可扩展性。

摘要 大规模商业搜索系统以相关性为优化目标，以提升用户搜索会话的成功率，帮助用户快速找到所需内容。为最大化相关性，我们采用两个互补目标：行为相关性（用户倾向于点击或下载的结果）和文本相关性（结果与查询的语义契合度）。一个长期存在的挑战是专家标注的文本相关性标签数量远少于丰富的行为相关性标签。我们首先系统评估了多种大语言模型（LLM）配置，发现一个专用的、经过微调的小模型在生成高质量相关性标签方面显著优于一个规模大十倍的预训练模型。利用该最优模型作为“杠杆”，我们生成了数百万条文本相关性标签，有效缓解了数据稀缺问题。我们证实，将这些文本相关性标签加入生产排序器后，行为-文本相关性的帕累托前沿显著外移：行为相关性的离线 NDCG 提升，同时文本相关性 NDCG 也同步提升。这些离线提升通过全球 App Store 排序器的 A/B 测试得到验证，转化率显著提升 +0.24%，其中在尾部查询中效果最为显著——在缺乏可靠行为信号的场景下，新引入的文本相关性标签提供了稳健的排序依据。

1. 引言 大规模数字 marketplace（如 App Store）的搜索排序系统对应用发现与用户满意度至关重要。其效果直接影响用户能否便捷地发现并使用海量应用。此类系统需同时优化文本相关性（专家判定的结果与查询的语义匹配度）和行为相关性（用户点击或下载某结果的可能性）。尽管行为相关性标签数据丰富，但由人工评审员生成的文本相关性标签却极为稀缺。这导致一个根本性问题：高质量文本相关性标签成本高昂、数量有限，成为可扩展性瓶颈，使多目标训练中该目标难以充分优化。

为应对标注稀缺问题，近期研究探索将大语言模型作为可扩展的离线标注器（Zheng 等，2023；Bonifacio 等，2022）。本文在工业级规模上验证了“LLM-as-a-Judge”范式：我们对自有 LLM 进行微调，利用人工评审标注数据生成数百万条高质量文本相关性标签，覆盖多个应用商店与语言；再将这些标签作为额外输入训练生产级排序器，有效突破传统标注瓶颈。该方法不仅提升单一指标，更从根本上推动行为-文本相关性帕累托前沿外移，使排序器性能实现严格超越。

我们的贡献有四点： （1）通过多种预训练与微调自有大语言模型的大规模实验，确定了面向相关性标注任务的最优标签生成方案； （2）在多语言环境下生成数百万条点式文本相关性标签，大幅扩展训练数据； （3）证明将 LLM 生成的标签加入排序器训练数据，可使行为-文本相关性帕累托前沿显著外移，离线 NDCG 指标全面超越生产模型； （4）通过离线评估与在线 A/B 测试双重验证，证实该方法在真实商业环境中的有效性。值得注意的是，LLM 增强模型在尾部查询中带来最大转化率提升，有效弥合了行为数据最稀缺区域的相关性缺口。

2. 相关工作 大语言模型（LLMs）在零样本与少样本设置下，已通过点式、成对与列表式提示策略，在排序任务中取得成功（Zhuang 等，2023a；Thomas 等，2023；MacAvaney 和 Soldaini，2023；Chen 等，2024；Zhuang 等，2023b；Abdallah 等，2025；Pradeep 等，2023a, b；Qin 等，2023；Liu1 等，2025）。LLM4Ranking（Liu1 等，2025）提供统一框架支持上述提示策略。但这些方法主要聚焦于将 LLM 作为实时重排序器部署；而本文将 LLM 用作离线标签生成器，为生产排序器构建大规模文本相关性标注数据。

LLM 作为评审员： “LLM-as-a-Judge”范式利用 LLM 作为可扩展的离线标注器，缓解人工评审标注稀缺问题（Faggioli 等，2023；Hosseini 等，2024；Saad-Falcon 等，2023；Arabzadeh 和 Clarke，2025；Zheng 等，2024；Chiang 和 Lee，2023；Gu 等，2024；Liu 等，2023）。本文的创新在于：不仅将微调后的领域内 LLM 用于评估，更将其作为“杠杆”，生成数百万条文本相关性标签，直接作为生产排序器的训练数据。与 RRADistill（Choi 等，2024）不同——后者通过特殊架构修改将大 LLM 的语义理解蒸馏至小模型——我们采用点式标签训练生产模型，不修改其内部结构。

多目标学习排序（LTR）： 多目标 LTR 是平衡不同相关性形式或公平性等目标的规范方法（Tang 等，2024；Meng 等，2025；Hong 等，2025；Yu 等，2024；Mahapatra 等，2023；Xu 等，2024）。本文在此框架下运行，但并非引入新目标，而是通过 LLM 大幅扩展文本相关性标签覆盖范围，强化既有目标。这不同于 Liu 等（Liu 等，2024）的方法——他们结合内容与行为信号，但对 LLM 标签施加 sigmoid 变换；我们则在多目标框架内采用数据混合策略。

偏好对齐与排序目标提示： 越来越多研究关注如何将 LLM 偏好与排序目标对齐（Zhao 等，2024；Sinhababu 等，2025；Raja 等，2025；Yuan 等，2026）。这些方法的共同目标是提升 LLM 自身的排序能力。尽管我们在提示与模型设计中借鉴了这些对齐技术，但目标本质不同：我们不部署 LLM 为排序器，而是获取与人工评分标准一致的相关性标签，用于训练排序器。

工作定位： 本文贡献在于将上述方向整合于大规模生产系统。我们证明：使用微调 LLM 作为离线评审员，为多目标排序器扩充训练数据，是一种可扩展且高效的工业策略。该方法可显著外移行为-文本相关性帕累托前沿，带来离线指标与在线 A/B 测试的双重提升。

3. 提出方法 本方法系统性扩充生产排序器的训练数据，包含两个阶段： （1）生成数百万条高质量文本相关性标签； （2）将新标签集成至多目标排序器训练流程。

3.1 LLM 相关性标签生成 假设你是一名 App Store 评审员。你收到一条用户查询与一个返回的应用，以及该应用的元数据 1、元数据 2、元数据 3。目标是为该应用针对该查询选择以下标签之一：label_1、label_2、label_3、label_4、label_5。相关性等级定义如下：…… 严格要求：你的回答只能是标签，其余内容不得出现。 示例 1：query: query_1；app: app_1，关联元数据：app_metadata_1, app_metadata_2, app_metadata_3；label: label_1。 示例 2：query: query_2；app: app_2，关联元数据：app_metadata_1, app_metadata_2, app_metadata_3；label: label_5。 请为以下生成标签：query: query_target；app: app_target，关联元数据：app_metadata_1, app_metadata_2, app_metadata_3。 图 1：查询（query_target）与返回应用（app_target）的少样本提示示例。

为缓解人工评审文本相关性标签稀缺问题，我们采用“LLM-as-a-Judge”方法，使模型作为可扩展的离线标注器。我们利用跨查询聚合的历史搜索日志（含 n×m 个候选查询-应用对），为每对生成点式文本相关性标签。

本框架支持大规模预训练模型与专用微调自有模型。微调虽可使模型更好内化我们的排序标准，但高容量预训练模型仍具可行性。离线生成避免了实时 LLM 重排序的延迟约束，成为人工标注的“杠杆”。

为确保生成标签与人工评审一致，我们构建提示时使用评审员可获取的相同查询与应用元数据。图 1 展示了一个示例提示。我们探索零样本配置以实现最大可扩展性，以及少样本提示（融入人工评审的已有标注示例以引导模型判断）。我们还使用评审员标注作为微调标签。这些生成标签（文本或数值形式）被集成至多目标排序器，以强化文本相关性目标。

3.2 多目标排序器训练 我们的生产排序器旨在优化相关性，该目标在多目标框架下实现，联合优化文本与行为相关性。

为此，我们构建了独特训练数据集，源自两类标签源：（1）聚合 App Store 搜索日志中的下载与点击行为（行为相关性）；（2）显式文本相关性评审（来自人工评审员及第 3.1 节所述 LLM 生成标签）。关键在于：同一查询-应用对（具相同特征向量）可在训练数据中多次出现——一次带行为相关性标签，一次带文本相关性标签。

排序器训练是多目标优化（MOO）的实际应用，旨在寻找帕累托前沿上的最优解。我们采用标量化这一常见 MOO 技术，通过构建训练数据的加权混合，将两个目标合并为单一目标函数。“严格分离”标签源进行比较至关重要，可确保各目标梯度独立计算。

该方法允许我们通过调节数据混合比例（作为可调超参数）控制各目标的相对影响：通过采样或限制各数据源的行数，可构建任意混合比例（如 90-10、70-30、50-50）的数据集，系统训练对应帕累托前沿不同点的模型。

4. 离线实验评估 我们开展两阶段离线评估：首先评估 LLM 生成标签质量，其次评估其对生产排序器的影响。

4.1 数据集 评估使用两类主要数据源：（1）跨长时间窗口聚合的数百万查询-应用对的历史 App Store 会话日志；（2）人工评审员提供的少量历史文本相关性评审数据集。

该人工评审数据集分为训练集与验证集，用于微调与评估 LLM 评审员。随后，我们使用 LLM 评审员对大规模聚合日志数据执行推理，生成新文本相关性标签。

接着，我们构建排序器数据集：融合两类主数据源（历史聚合日志用于行为相关性、人工评审用于文本相关性）以及新生成的 LLM 标签（用于增强文本相关性），并将其划分为排序器训练集与验证集。

4.2 LLM 相关性标签离线结果 4.2.1 实验设置 我们比较了三种 LLM 配置：（1）预训练 3B：30 亿参数自有预训练模型；（2）预训练 30B：300 亿参数自有预训练模型；（3）微调 3B：在第 4.1 节所述人工评审训练集上微调的 3B 模型。

我们使用查询与应用元数据，测试多种提示配置（零样本 vs 少样本、文本 vs 数值标签）。为确定最优配置，我们在人工评审的保留验证集上评估各模型，报告精确率、召回率与 F1 分数。

4.2.2 结果 表 1：LLM 配置离线评估。微调模型（FT-3B）表现最优。预训练模型标记为 PT。

| 模型 | 精确率 | 召回率 | F1 | |------|--------|--------|-----| | PT-3B | 0.300 | 0.309 | 0.287 | | PT-30B | 0.424 | 0.402 | 0.382 | | FT-3B | 0.802 | 0.798 | 0.800 |

表 1 展示了在验证集上表现最佳的少样本提示配置结果。可见微调模型（FT-3B）在所有指标上均优于预训练模型。值得注意的是，其不仅超越同规模预训练模型，更优于参数量大十倍的预训练模型，凸显微调价值。该结果具重要工业意义：微调更小、更高效模型的效果优于更大预训练模型，为生产部署提供了低成本路径。

尽管微调 30B 模型仍是未来值得探索的方向，但本文证实微调 3B 模型已提供足够强且经济的解决方案。

为简洁起见，我们省略提示设计细节，但指出：含文本标签的少样本提示效果最佳。该最优配置（FT-3B）生成的标签用于扩充排序器训练数据，其效果将在下文评估。

4.3 排序器离线结果 表 2：排序器离线性能（NDCG）。使用 LLM 生成标签（llm-augmented）相比生产模型（prod）提升了相关性指标。

| 相关性类型 | 指标 | prod | llm-augmented | |------------|------|------|----------------| | 文本相关性 | NDCG@1 | 0.867 | 0.868 | | | NDCG@3 | 0.803 | 0.805 | | | NDCG@7 | 0.760 | 0.761 | | 行为相关性 | NDCG@1 | 0.646 | 0.652 | | | NDCG@3 | 0.479 | 0.484 | | | NDCG@7 | 0.403 | 0.407 |

生成 LLM 相关性标签后，我们开展大规模实验，测量其对生产排序器性能的影响。主要目标是观察在扩充训练数据后，文本与行为相关性的变化。

4.3.1 实验设置 我们比较两个模型：（1）prod：生产模型，使用聚合日志行为标签与有限人工文本标签训练；（2）llm-augmented：在 prod 基础上，用第 4.2 节所述 LLM 生成的数百万标签扩充训练数据。

我们保留验证集，使用 NDCG@k 指标（Järvelin 和 Kekäläinen，2002）评估性能。NDCG 计算中，各项目相关性得分依目标而异：文本相关性采用人工评审标签；行为相关性基于聚合用户点击与下载生成。

用于计算文本相关性 NDCG@k 的评审标签，不包含在 LLM 标签微调与验证所用集合中，二者为不同数据集。

4.3.2 结果 表 2 汇总了离线评估结果，展示各模型在返回结果排名 1、3、7 处的行为与文本相关性 NDCG。

结果证实核心假设：添加 LLM 生成标签可提升排序器文本相关性，同时提升行为相关性，表明扩充训练数据不仅增强结果语义匹配度，也提高用户下载/点击可能性。各 k 值结果一致，体现真正的帕累托改进——排序器性能严格超越原模型。

进一步实验表明，通过调节 LLM 标签比例，可在新帕累托前沿上移动，而非进一步外移前沿。

5. A/B 测试结果 表 3：llm-augmented 模型相比 prod 模型的转化率提升百分比（统计显著）。

| 模型 | 转化率提升 | |------|------------| | prod | —— | | llm-augmented | +0.24% |

图 2：llm-augmented 与 prod 模型转化率绝对差 vs 查询频次分桶（低频→高频：尾部→头部查询）。

我们通过全球流量大规模在线 A/B 测试验证该方法，比较 prod 与 llm-augmented 模型。

如表 3 所示，llm-augmented 模型使核心指标（至少一次应用下载的搜索会话占比）转化率显著提升 +0.24%。尽管数值看似微小，但对成熟工业排序器而言属显著改进，该提升在 89% 的应用商店中均被观测到。

为探究提升来源，我们分析不同查询频次分桶（从高频[头部]到低频[尾部]）的转化率提升。图 2 显示：最大提升出现在尾部查询。因尾部查询用户流量不足，难以生成可靠行为相关性信号；而 llm-augmented 模型在此场景下表现优异——新增文本相关性标签在行为信号稀疏或缺失时提供稳健准确的信号，有效弥合相关性缺口。

6. 结论与未来工作 通过系统评估大规模预训练与专用微调自有模型，本文证明大语言模型可作为人工评审的强大“杠杆”，有效推动生产排序流程的帕累托前沿外移。

经严格离线评估与在线 A/B 测试验证，本文证实“LLM-as-a-Judge”范式具备工业可扩展性，并强调 LLM 生成标签在尾部查询中价值最大——在缺乏可靠行为数据时提供稳健信号。

本工作为其他大规模搜索系统提供实用蓝图：借助现代 LLM 作为离线数据生成器，克服相关性标注稀缺问题，系统性提升排序模型。

未来，我们将尝试更多微调模型及提示类型，如成对与列表式配置，以生成针对特定查询的成对或列表级应用标签。
