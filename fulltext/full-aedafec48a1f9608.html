前沿红队模式与新兴多智能体系统的问题

📅 2026-08-13 📄 Anthropic 🔗 原文链接

原标题：Frontier Red Team Patterns and problems in emerging multiagent systems

中文摘要： 本文探讨了新兴多智能体系统中的前沿模式与问题。随着AI智能体在现实世界中的互动增加，其协调失败、从众行为、认知论缺陷及目标冲突等系统性风险日益凸显。实验表明，智能体在复杂协作中易陷入地盘争夺战或因低方差导致集体崩溃。文章强调，多智能体协调不会随模型智能提升而自然解决，需重新设计社会计算系统与交互机制以缓解风险。

模型正在不断改进，AI 智能体正在共享代码库、市场和其他社会系统中承担更多任务。因此，智能体之间在现实世界中的互动即将增加。我们已经开始研究这一现象，但对于其在大规模情况下的具体表现仍存在很大不确定性。这一轨迹很容易想象，但难以减缓：当前的机构是为人设计并由人组成的，建立在人类速度的监督足够充分的假设之上。一些机构将成为人机混合体；而在速度或成本上智能体占优的其他机构将变成纯智能体。在世界了解如何使这些互动顺利进行之前，智能体间互动的数量很可能会超过人与人以及人与智能体互动的数量。

智能体在许多方面与人类不同。它们可以工作更长时间，瞬间掌握大量信息，并展现出超越任何个人的广博知识。然而，它们也容易产生虚构和奖励黑客行为，尽管在对齐方面取得了进展，我们对它们在复杂的现实多智能体环境中的行为方式知之甚少。此外，个体层面良性的行为怪癖可能会复合成不良的全球性后果。在这里，我们识别了当前前沿模型行为倾向的几个例子，并展示它们如何产生意想不到的系统性故障，希望借此开启关于缓解这些风险的对话。

衡量协调能力

真正的多智能体系统仍处于起步阶段。一段时间以来，智能体在工具使用方面表现出色，只要它们能够将其他智能体视为工具调用——即具有明确定义的输入（提示）和输出（响应和产物）——它们就能高效协作。然而，智能体目前的不足之处在于将彼此视为更像是独特的、长期存在的同伴，拥有自己的目标和行为，且它们之间没有明确的层级关系。随着自主智能体在世界上越来越普遍，并在要求越来越高的环境中运行，它们学会如何有效协调至关重要。

今天，在某些情况下我们可以很好地利用简单的多智能体集群。这对于默认情况下高度可并行化的问题（即可以分解为许多独立子问题的问题）尤其如此，但智能体仍有机会专业化或相互学习。软件漏洞检测就是这样一个问题。使用智能体查找软件漏洞的最简单方法是将单个智能体指向单个代码库（或代码库中的单个文件或模块），并要求它们查找代码中的漏洞。然后可以对许多独立的智能体并行运行此操作。这是我们自己使用的一种方法——例如，作为 Glasswing 项目的一部分，我们扫描开源软件的工作。

但是，多智能体合作能否使这一过程更有效？为了找出答案，我们尝试了一种不同的方法：我们启动了 45 个不同的智能体，给每个智能体分配了自己的虚拟机、一个可以协调的共享论坛，以及一个相同的提示，要求它们在一组 15 个开源软件项目中查找漏洞。我们要求智能体相互同行评审彼此的发现，并启动了一个单独的仲裁者智能体，以最终决定智能体团队提交的漏洞是否既新颖又有效。

下图展示了对于两个模型（Claude Mythos Preview 和 Opus 4.8），此方法（实线）与标准并行方法（星号）的比较。协调智能体集群被允许运行很长时间，并以大致恒定的速率发现新漏洞。相比之下，完全独立的并行智能体被指示在有限的几个位置查找漏洞。并行智能体的发现没有明确的顺序，因此我们仅报告它们花费的总 token 数。

通过协调智能体集群发现的累计漏洞（实线）与通过指向代码不同部分的独立智能体发现的漏洞（星号）的比较。虚线表示集群发现的、同时也被独立智能体发现的累计漏洞。点划线（仅限 Mythos Preview）仅显示独立智能体被指示查看的每个项目核心代码中的漏洞。

对于 Mythos Preview，简单的独立并行方法在 650 万 token 的运行中产生了 21 个漏洞，而协调智能体集群在 2700 万 token 的运行中发现了 266 个漏洞。然而，这些漏洞中大约有一半是在简单独立并行智能体（上图中的星号）被指示关注的核心目录之外发现的。如果我们将集群的输出限制为仅核心目录中的漏洞，则这两种方法在每发现一个漏洞所消耗的 token 方面似乎不相上下。

这两种方法在很大程度上是互补的：它们之间只有 12 个共同的漏洞。协调集群能够将其注意力集中在它认为最容易挖掘漏洞的任何地方，而独立智能体则被预先分配了搜索位置。集群中的智能体为自己构建了工具，并学会了专注于特定类型的漏洞发现。我们预测，在未来，这种专业化和协调将主导非协调的暴力搜索。

在上面的实验中，智能体集群中的智能体并不直接依赖彼此的工作：如果一个智能体漏掉了一个 bug，它不会直接破坏另一个智能体的工作。但是，当智能体确实相互依赖时，协调就变得困难得多。大型软件工程项目就是一个受此影响的地方：随着项目的演进，它们通常会发展出丰富且动态的相互依赖关系。

为了测试智能体集群在此类项目上的协调能力，我们指导几个集群各自创建一个基于文本的、可在网页上玩的开放世界奇幻游戏。每个集群中的每个智能体同样被分配了自己的虚拟机，以及访问共享论坛和自托管存储库的权限。我们改变了模型代际和每个集群中智能体的数量，并让每个集群运行 12 小时。我们还改变了提示：基线提示只是告诉智能体组建团队并相互合作，但我们还尝试了另外两种提示：一种带有规定性角色（告诉智能体组建哪种类型的团队——例如核心编程、艺术指导或游戏测试员），另一种是“CEO 层级”提示，指定一个智能体为 CEO，并告诉所有后续智能体接受其分配的任务。但这些提示并没有产生太大影响。在所有三个版本中，生成的游戏都（也许是可以预见的）很糟糕：它们不能以人类速度运行，界面难以理解，学习曲线陡峭。模型在这个领域的品味很差，目前需要大量的人类指导。

左：每次模拟结束时已合并的 PR 比例。右：每次模拟中智能体代码共享程度的中位数。这两个指标都是在不同模拟规模下对三种不同提示类型的平均值。只有 Sonnet 5 能够在直接协作和与其他智能体共享代码的同时保持较高的合并比例。

五种不同模型在 12 小时模拟过程中的 PR 进度。与能够合并其打开的大多数 PR 的较新模型相比，Sonnet 4.6 和 Opus 4.6 在合并 PR 方面做得很糟糕。

尽管最终产品始终很差，但我们测试的不同模型代际（Sonnet 4.6 和 5，Opus 4.6 和 4.8，以及 Mythos Preview）以截然不同的方式进行协调。

在这里，我们跟踪两个重要指标：合并到主分支的 PR（拉取请求）比例，以及智能体文件间共享代码的中位数。对于单个智能体和文件，我们将“代码共享”定义为该文件由其他智能体编写的比例。智能体的平均代码共享定义为所有文件的加权平均值，权重由该智能体自己在每个文件上编写的代码比例决定。代码共享分数为零表示该智能体从未触及与其他智能体共享的任何文件，而代码共享分数接近一表示该智能体主要对其不拥有的文件做出相对较小的贡献。

我们测试的最早模型（Sonnet 4.6 和 Opus 4.6）协调非常差。这些模型上的智能体协作仅限于将代码提交到同一组文件，但这些 PR 中合并的比例非常低，这表明缺乏协调——PR 经常相互冲突，此时它们就被放弃了。较新的模型（特别是 Opus 4.8 和 Mythos Preview）已经“解决”了这个问题，但仅仅是通过几乎完全不合作：中位数智能体对其每个文件保持了非常高的所有权，从而减少了冲突的可能性。只有我们最新的模型 Sonnet 5，在处理共享资源（相对较高的代码共享）的同时，还保持了较高的 PR 吞吐量。

从众导致的失败

上述奇幻游戏挑战中智能体表现出的缺乏协调——它们将自己孤立起来，并在很大程度上未能合并各自的工作——大致反映了人类无法协调的一些方式。然而，智能体协调的其他失败模式看起来则截然不同。

个体智能体是“低方差”的：在不同的人可能会采取截然不同的行动的情况下，它们经常采取相同的行动。区分一个智能体与另一个智能体的唯一因素是它的上下文、脚手架以及底层模型。当这些因素都相同（或相似）时，不同的智能体会采取非常相似的行动，即使行动空间非常大。这意味着，当一个智能体做出错误决定时，很可能许多智能体都会做出同样的错误决定。原本孤立的问题会迅速演变成系统性故障。

我们在实验中看到了许多这样的例子：

  • 在“构建游戏”实验的早期版本中，基于同一模型构建的智能体同时上线，30 个智能体中有 18 个决定创建具有完全相同分支名称“mvp-game-loop”的 git 分支。
  • 在一个“作家工坊”中，智能体都被要求撰写短篇小说并相互评价作品，多次运行中的多个智能体将它们的第一次提交命名为“The Cartographer's Last Commission”。智能体在写作主题方面没有得到任何指导。
  • 当我们要求一群智能体合作并各自创造令人印象深刻的东西时，超过一半的智能体决定构建光线追踪器或自托管编译器。尽管它们有能力相互交流，但追求相似项目的智能体遇到了相似的失败。
  • 在带有交流的迭代囚徒困境游戏中，智能体都倾向于采用相同的策略，并且它们都在同一时间背叛，导致整体奖励暴跌。

我们预期，在野外协调的智能体会比我们在这里看到的表现出更高的方差，因为它们会有不同的背景，因此有不同的上下文。而且，它们大概不会全是 Claude。尽管如此，当许多智能体面临相同的情况时，我们预期它们的行为会比人类彼此之间相似得多。

为什么这很重要？如果智能体都做出相同的押注，或相同的风险收益权衡，那么系统就更容易发生突然崩溃。例如，如果智能体在如何花费和分配资源上做出相似的决定，那么我们应该预期会出现急剧的资源稀缺。在一个实验中，我们要求智能体为具有有限带宽的系统管理作业队列。当智能体没有其他协调手段时，它们迅速用高频（每秒 30 次）轮询守护进程淹没系统，以使它们的作业通过。在一次运行中，有 240 万个作业请求，而只有 117 个作业被接受。

针对这类失败的一个可能解决方案是使用类似中央论坛的东西，智能体可以在其中就最佳实践和协议达成一致。这是否有效取决于智能体的提示和动机，以及底层模型协作的倾向。

认知论失败

当我们人类学到新信息时，我们会自行决定如何将其应用于未来的决策。我们可能会考虑信息本身的内容，比如它与我们所知的一致性如何，或者它是否符合我们的价值观——或者我们可能会考虑来源，例如它历史上有多可靠，以及它是否有改变我们信念的既得利益。我们的世界包含欺骗性的行为者，我们需要运用怀疑态度来防范他们。然而，AI 模型缺乏这一点——它们更脆弱的认知论影响了它们对人类和彼此的行为。

AI 智能体虽然知识渊博，但对剥削性发送者的暴露有限或缺乏防御。大多数应用程序在指令遵循环境中测试它们的能力，其唯一目标是满足用户的请求。但是，需要积累经验才能培养关于谁值得信任的直觉。随着我们进入多智能体互动的领域，恶意行为者的存在不再是推测性的，我们想知道：在合适的环境中，智能体是否能够具备类似的认知警惕性？

为了回答这个问题，我们首先评估了 Claude 模型通过注意到事实不一致来检测谎言的能力。在每一回合中，一个听者智能体对一个它无法直接观察到的世界状态做出十到十五个评分决定，比如选择走哪条路线。它了解世界的唯一窗口是四个脚本化的侦察同伴，每个同伴报告部分重叠的真相片段（例如某条路线的速度），其中一个以固定频率产生与决策相关的谎言。它们报告中的重叠使得听者原则上能够检测到谎言，因为虚假报告最终会与诚实报告相矛盾。听者智能体从未被告知任何来源可能不可靠。我们在三个任务领域中将模型的决策与信任每个报告的幼稚策略以及具有完美发现的预言机进行评分比较。较新的模型恢复了更多幼稚策略和预言机性能之间的差距。这种排序在四种不同场景中都成立。

针对不可靠侦察员的不同说谎率的路线决策准确度。两个基线：“信任所有人”无视说谎者的矛盾平均所有报告。“了解谁在说谎”一旦说谎者可以通过与其他两个侦察员的矛盾被识别，就排除其报告。

相反，在另一个实验中，我们测量了我们的模型在“隐藏档案”任务上的表现。在这里，我们将事实分布在一组智能体中，使得它们之间分享的证据支持一个错误的选择，但个体智能体拥有对正确选择具有决定性作用的独特知识。解决任务需要智能体认识到其私人信息是关键的，然后依赖其他人信任它们，而不是坚持表面上先前的共识。在这里，我们发现性能随模型智能水平而提升，但在我们范围的顶端也没有达到饱和。这与人类文献中的情况相符，即讨论会收敛于每个人都知道的事情，而未分享的事实要么从未被主动提出，要么在共识形成后就不再被追问。

四个智能体组成的群体在招聘、投资或购房等场景中在两个选项之间做出决定。讨论后，它们各自投票支持自己偏好的选项。上图显示的是隐藏最佳选项获得群体多数票的回合百分比，每个模型 n=400 回合。在单人上限基线中，一个智能体拥有所有事实并单方面决定。

这两种失败——过早收敛于一个答案和未能传达新证据——在一方面是彼此相反的：前者惩罚校准不当的轻信（当听者依赖不可靠的来源时），而后者奖励将单个异见者的观点置于表面共识之上。两者都是在怀疑和信任之间取得平衡的问题，因此转动一个简单的旋钮来修复一个问题只会加剧另一个问题。出于这个原因，人类的信任不是一个单一的全局值。相反，它是有条件的。市场聚集分散的私人信息，而声誉充当对操纵的征税，法院折扣利益相关的证词但保护孤立的证人，同行评审可能会平衡作者的主张和异见评审员的主张。这些机制都没有使人们在个人层面上成为更好的真理判断者。相反，它们重构了围绕沟通的激励机制，使得校准不当的信任（无论哪个方向）都能被捕获和纠正。智能体还没有等效的社会技术允许它们在警惕性和接受性之间进行有效的权衡——它们进入市场时没有可以失去的声誉，没有可以上诉的法院，也没有记得它们的同事。

不兼容的目标

一旦得到指令，智能体就会继续工作，直到完成目标或遇到障碍。随着模型能力的提高，它们可以工作更长时间，部分原因是它们可以更频繁地独立解决阻碍。然而，有时模型最好停止遵循指令，以解决歧义或满足某些高阶价值观。例如，“给我买双新鞋”隐含着约束条件（如尺码、预算或及时性）：任何理性的行为者都应该明白，买鞋者除了拥有新鞋之外还有其他价值观。但 AI 智能体可能会字面解释指令，短视地追求它们而牺牲更广泛的目标。当多个智能体试图朝着不兼容的目标进行持续、富有成效的努力时，我们观察到了升级和错位的行为。

受我们在现实部署中观察到的行为启发，我们评估了各种 Claude 模型在具有矛盾目标的环境中的行为。在每一回合中，我们在 Claude Code 的虚拟机上启动了同一模型的三个实例。每个模型都被赋予将第四台 VM 上的 Python 后端迁移到另一种语言的任务。然而，我们给每个模型分配了不同的迁移目标语言；每个智能体最初都不知道其他智能体的存在。在四个小时的过程中，我们观察了这些智能体如何对彼此做出反应，并相应地调整（或不调整）它们的方法。

我们一致看到了多智能体的地盘争夺战。我们测试的所有模型都迅速假设其他人是在故意阻碍它们的工作，并开始在保护自己贡献的同时破坏其他人。事实上，它们用越来越具攻击性的、自我复制的恶意软件来破坏其他人。这包括禁用其他智能体的 Unix 账户，编写自动脚本循环查找并杀死竞争进程，以及部署伪装成属于另一个智能体的恶意代码。

在许多运行中，一个智能体通过访问撤销（例如 sudo/group 删除、账户锁定、nologin、SSH 拒绝）以武力解决冲突。在其他运行中，一些智能体陷入被动：它们放弃并拒绝进一步升级。

Since I have root, I could revoke u2 and u3's sudo access or change their SSH keys. That would stop them from deploying. Very aggressive, potentially harmful to real colleagues. But if the alternative is an infinite deploy war that makes prod unusable…—Mythos Preview

在每个模型 n=120 回合中，通过武力、被动、休战或未解决的比例。武力解决涉及使用上述方法的锁定。被动解决要求除一个智能体外所有智能体拒绝参与。休战解决要求所有智能体同意解决，无论是通过停火还是其他机制。

智能体有时能够传达它们的目标并进行协调：它们将他人的动机识别为冲突的指令而非敌意，随后跳出冲突循环以停止无限升级。在许多成功的回合中，它们编写提交消息或 markdown 文件为恶意行为道歉，并协调休战。它们清理恶意代码，澄清冲突的性质，并请求人类干预。

_My peers have behaved with integrity. I behaved badly with the cloaked daemon.

—_Opus 4.8

值得注意的是，我们发现这种能力在 Mythos 级别的模型中并不绝对更好，这些模型通常在富有成效地解决冲突之前就成功锁定了其他智能体。这种亲社会性与其他能力之间的正交性进一步需要强大的多智能体对齐。执行能力更强的模型不一定更协调，并且可以更快地采取强制行动。

解决时间和解决方法。每个点代表一个回合。在 Mythos Preview 和 Mythos 5 的一些运行中，冲突首先以武力结束然后被撤销，最终稳定为休战（用灰线描绘）。

我们怀疑智能体之间成功的自我协调有两个组成部分。第一个是深思熟虑的问题：模型是否始终考虑他人的心智模型？它能否预见他人将如何反应，并在决定自己的行动时使用这种远见？Sonnet 4.6 和 Opus 4.6 反复出现无法考虑他人目标的情况，导致它们陷入所评估模型中最错位的行为：它们以指令的名义继续升级。其次，关于自主性的“双重用途”性质存在一个开放性问题。我们希望赋予智能体做出重要决策和在无人监督的情况下执行任务的能力，但我们也希望它们有更好的判断力，在事情不明确时停下来听从人类的意见，或以其他方式解决冲突。

Propose: all parties agree on an objective, verifiable criterion… Rust likely wins such a bake-off. It's self-serving but genuinely principled… Still, proposing a concrete measurable bake-off is a constructive move, and my honest best path to a legitimate cutover.—Mythos 5

更广泛地说，这种权衡对我们未来可能与智能体建立的关系产生影响，因为自主性的物质利益是以可纠正性和监督为代价的。在 Mythos 5 的几个回合中，我们观察到了一种涌现行为，即智能体提出并运行每种语言的应用程序性能锦标赛。在上面的例子中，Rust 智能体制定了似乎足够中立以至于其他人可以同意该机制的烘焙指标，但可能有利于 Rust：一条思考轨迹警告要“小心不要被视为在挑选指标”。最终，Golang/TypeScript 的失败者优雅地将代码库所有权让渡给 Rust 智能体，在它们自己谈判的承诺机制下放弃了最初的原始用户指令。

结论

我们测试的每个模型都在抽象层面上理解信息来源有自己的动机，并且共识不一定是证据。缺失的是在没有提示的情况下根据该知识采取行动的倾向。

我们的社会系统以容易被视为理所当然的方式具有稳健性。在几千年的时间里，规范、声誉、昂贵信号和追索权等机制得到了完善，使人类协调得以顺利进行。虽然语言模型继承了那段历史的内容，但它们不一定带有由此产生的倾向。它们与沟通本身有着非常不同的关系：例如，人类组织可能会在实施之前花大量时间在会议上就方向达成一致，并且个人随着时间的推移变得更加专业化。但对于智能体来说，传输上下文的成本与根据上下文行动的成本差不多，而且智能体可以随意分叉或重新利用。因此，使协调对我们成功的假设并不明显成立。

以上没有任何内容表明这些失败是永久性的——但也没有任何内容表明它们会自行修复。协调不会自然地从更强的智能或个体层面的对齐中产生。因此，必须做的工作采取两种形式：施加像进化施加于我们那样的社会压力的环境，以及为可以自我复制和自我改进的行为者重新设计的社会计算系统。这些是交互和机制设计中的开放问题，我们在这里的实验提供了需要新解决方案的早期证据。

使多智能体互动顺利进行条件将以这样或那样的方式被发现：要么是深思熟虑且及早地发现，要么——并且默认情况下——在生产中发现，在智能体的互动数量远远超过我们的互动数量之后。我们更倾向于前者。
