原标题：Token-Efficient Data Reasoning Agents via Adaptive Structuring of Unstructured Data

中文摘要： 本文提出“智能体数据破解”方法，通过将非结构化数据自适应且推测性地结构化，作为推理的副产品，以降低LLM智能体处理复杂查询时的巨大token消耗和成本。该方法在智能体打开文档时，利用已加载的上下文分叉出子智能体提取未来可能重用的结构化知识。实验表明，该方法在保持准确率的同时显著降低了推理成本，为企业级AI应用提供了高效的数据基础设施新范式。

摘要。 在开放和企业环境中，有价值的数据仍然嵌入在非结构化来源中：网页、报告、合同、文件、财报电话会议和 PDF。企业 AI 的最大赌注是部署 LLM 智能体，对这些数据进行推理，从而为每位知识工作者解答复杂问题。智能体现在可以做到这一点，但成本高昂得令人望而却步。每个问题都需要反复打开大型文档以恢复分散的证据，消耗多达一百万个 token。然而，如果数据已经结构化，同样的问题将简化为廉价的数据库查询。例如，在 FanOutQA 基准测试中，对理想预结构化存储进行推理的成本要低 28 倍，并且随着问题扩展到更多文档，这一差距会扩大到几个数量级。然而，预先将所有内容结构化是不可行的：文档包含的可能结构远多于任何工作负载将使用的结构，而且有用的结构和文档在查询到达之前是未知的。

我们提出了智能体数据破解，这是一种借鉴数据库破解和自适应数据系统理念的方法，将非结构化数据自适应且推测性地结构化，作为推理本身的副产品。结构化是自适应的，因为观察到的查询决定了它何时发生以及什么是重要的；结构化是推测性的，因为它超越了当前问题。每当智能体打开一个文档来回答时，一个破解子智能体就会从已加载的上下文中以边际成本分叉，并提取可能服务于相关未来查询的有根据的结构。随着时间的推移，越来越多的查询完全被结构化数据覆盖，并在不打开文档的情况下得到回答，从而使智能体准确率保持在接近 RAG 的成本。在 FanOutQA 上，仅为每个测试问题扩展了一个相关问题，破解就将成本降低了 53%，同时保持了准确率，并且在每个问题节省成本的第十百分位数上，其运行成本已经低了 9 倍。智能体数据破解是迈向非结构化数据智能体推理下一代数据基础设施的第一步：模型下方的一个共享底层，在这里积累推理已经支付了发现成本的知识，因此系统会随着每个查询它的智能体和用户的使用而改进。

1. 引言

知识与见解被封装在非结构化数据中。 世界上大部分知识并没有存储在干净的表格中。它存在于非结构化来源中，如书籍、企业和法律文档、网页、SEC 文件、财报电话会议和 PDF。回答这些来源问题所需的证据分散在许多文档中。考虑这个问题：哪些演员同时与阿尔弗雷德·希区柯克和马丁·斯科塞斯合作过？在维基百科上，回答这个问题需要从他们的页面中列举每位导演的电影，从每部电影的页面中提取演员，连接生成的导演-电影和电影-演员关系，并对两个演员集合取交集。这个流程是通用的：在每一步中，从文档中收集证据，组装成中间实体、属性和关系，并传递给后续步骤。答案不是一组检索到的段落。它是一个潜在的结构化数据集，由许多大型文档内部的稀疏证据逐步构建而成。我们将这种模式称为数据推理。

对非结构化数据的数据推理已无处不在且仍在增长。 超过八十个商业和开源系统已经公开发布，用于在网络和其他大型文档集合上回答复杂问题 (Xu and Peng, 2025; OpenAI, 2025; Perplexity, 2025)，还有更多系统在企业内部私下运行 (Hebbia, [n. d.]; Glean, 2025)。真实用户提出的许多问题完全遵循数据推理模式 (Wolfson et al., 2026)。个人问题在数量上占主导地位，数百万人在开放的网络上提出这些问题。专业问题风险更高，针对企业档案和公开政府记录 (Opsahl-Ong et al., 2026)。一位金融分析师可能会问，哪些公司在财报电话会议上将问题归咎于供应链，但在年度报告中却报告库存增加，将一小时长的记录中的一句话与一份冗长文件中的一行相匹配。一个卫生部门可能会问，哪些供应商同时出现在多个城市的食品召回通知和餐厅检查报告中，而供应商名称散落在冗长的检查叙述中。回答任何一个问题都意味着在多个步骤中扩展到数百个文档。

智能体数据推理提取封装的知识，但成本高昂。 智能体系统可以执行回答数据推理问题所需的多步流程。智能体进行规划、搜索、打开文档、提取事实、执行代码、维护中间状态，并根据迄今为止收集的证据选择其下一步行动 (Chen et al., 2026; Asai et al., 2026)。与依赖参数化知识或固定 top-k 检索的模型相比，这些能力带来了更高的答案质量 (Zhu et al., 2024; Opsahl-Ong et al., 2026)。图 1（左）也显示了这一点。这种高质量是以高成本为代价的。数据推理主要是预填充密集型的：智能体反复将大型文档加载到上下文中以恢复分散的事实，而最终答案通常很短。成本随着依赖步骤、实体和文档的增加而增加。在我们的 FanOutQA 实验中，一个问题可能消耗多达一百万个 token，成本接近一美元。现实世界的数据推理问题可能具有更大的扇出、证据需求和推理深度，使其成本大幅增加 (Wolfson et al., 2026)。

读一次，付一次：查询揭示有用的结构。 如果数据被神奇地结构化了，许多这样的问题，包括我们的希区柯克例子，将简化为一个简单且低成本的 Text2SQL 查询。我们在图 1（右）中展示了这种现象。我们从 FanOutQA 中抽取了问题，手动将其答案所需的每个事实提取到数据库中，并在数据库而不是原始文档上重新运行智能体。每个任务都简化为数据发现和一个简短的查询，无需打开任何文档。这种理想的预结构化存储使推理成本降低了 28 倍。这个系数是 FanOutQA 特有的，其问题平均跨越七个文档 (Zhu et al., 2024)。一旦结构覆盖了一个问题，智能体就会跳过每个文档的打开，因此对于扩展到数百个文档的真实问题，节省的成本可达几个数量级。

虽然 LLM 非常擅长捕获这种结构，但预先将所有内容结构化是不可行的。文档包含的实体、属性和关系比任何工作负载将使用的都要多几个数量级，并且提取所有这些是一个无界的解码。此外，我们事先不知道工作负载想要哪种结构，或者它将被重用多少次。只有工作负载才能揭示哪种结构值得提取。

两个见解将这个死胡同变成了机会。首先，在工作负载级别，相关查询会重新打开相同的文档并重复大部分相同的工作，而每个查询揭示了哪些结构和关系是重要的。这种语义局部性是常态，而非例外。从用户的角度来看，对话变成了调查，用户持有相似的兴趣。从数据的角度来看，相同的文档被一遍又一遍地打开，因为它们包含查询所需的许多相关事实和证据。

其次，在推理级别，一旦智能体加载了一个文档，其预填充已经计算完毕，其 KV 缓存条目已经存在。通过仔细的提示结构、共享前缀服务 (Kwon et al., 2023; Zheng et al., 2024) 和 API 提示缓存，在相同上下文上的第二次生成可以避免或大幅减少重复的预填充成本，使解码 token 成为主要的额外工作。我们给这个解码一个固定的预算，相对于它节省的预填充来说很小，但足以产生可重用的结构。总之，这两个见解提出了一种比缓存更强大的举措。缓存的答案仅在完全相同的问题返回时才有帮助。推测有用的结构则走得更远：在文档已加载并支付费用时，提取相关但不同的未来查询将需要的、有根据的证据。

用于 Token/成本高效数据推理的智能体数据破解。 我们引入了智能体数据破解，这是一种将数据库破解和自适应数据系统的查询驱动理念引入 AI 推理的方法 (Salles et al., 2007; Idreos et al., 2007)。系统从不仅为提取结构而打开文档。相反，每当推理智能体打开一个文档来回答时，一个破解子智能体就会以低边际成本从已加载的上下文中分叉。它推测可能服务于未来查询的、有根据的、有证据支持的实体、属性和关系。系统验证并编目这些破解对象。后续查询通过结构化读取重用它们，完全避免打开文档，并在未命中时回退到原始文档。与重新组织关系的数据库破解不同，智能体数据破解在不存在的结构中创建有用的结构。

这种结构化是自适应的，因为观察到的查询指导了什么值得提取；它也是智能体化的，因为推理子智能体（而不是固定的提取器或模式）使用语义理解来阅读每个文档并推测要提取什么。

自适应结构化可实现的节省是可观的。运行时间更长的工作负载和更智能的破解可以解锁这些节省。理想存储在 FanOutQA 基准测试上便宜 28 倍，并且这一差距随着扇出而扩大。在我们的案例研究中，模拟了一个不断演变的调查，破解将成本降低了 3 倍。在 FanOutQA 上，仅为每个测试问题扩展了一次重用机会（一个早期的相关问题），破解在保持准确率的同时仍将成本降低了 53%。在节省的第十百分位数上，破解的运行成本已经低了 9 倍。重用将平均值与这个最佳情况区分开来，并且随着工作负载的运行，重用机会会不断积累。企业或 AI 服务通过使用积累的存储成为一项持久资产，一个数据护城河，与 KV 缓存不同，它可以跨模型转移。

2. 智能体推理：能力强但昂贵

潜在数据推理任务。 语言建模的一项重大进展是能够将复杂任务分解为一系列较小的推理步骤。推理任务采取不同的形式：解决 IOI/ICPC 问题、构建数据科学管道，以及解决大型非结构化语料库（例如网络、维基百科 (Zhu et al., 2024) 和企业文档集合 (Opsahl-Ong et al., 2026)）上的知识密集型问题。

在本文中，我们关注这样的推理任务：要求智能体从非结构化文档中提取知识，在每一步构建中间数据和支撑证据，并将这些产物传递给后续步骤。在这些任务中，答案来自于对构建的中间数据进行推理，而不是检索单个事实。我们将这类任务称为潜在结构化数据推理，或简称为数据推理。

两个运行示例。 在整篇论文中，我们使用两个问题来解释问题、直觉和解决方案：
(1) 每位获得过 IBM 奖的 NBA 球员的职业生涯平均每场篮板数是多少？
(2) 所有曾经同时与阿尔弗雷德·希区柯克和马丁·斯科塞斯合作过的演员有哪些？
第一个问题来自 FanOutQA (Zhu et al., 2024)，我们的主要基准测试。第二个问题是我们在案例研究中使用的更难的数据推理任务。如引言中所述，回答它需要在许多维基百科页面上进行多步构建。虽然这两个问题看起来很随意，但它们遵循与引言中的高风险问题相同的模式。

智能体解决方案：能力强但昂贵。 仅依赖参数化知识或传统检索的 LLM 在数据推理任务上的准确率很低 (Zhu et al., 2024; Opsahl-Ong et al., 2026)。相反，智能体系统通过规划一系列步骤并自适应地选择何时调用工具来模仿数据推理过程 (Chen et al., 2026; Asai et al., 2026)。智能体可以搜索语料库、打开文档、使用文件系统搜索/导航 API、提取事实、运行 python 代码，并存储中间数据供后续步骤使用。智能体不是遵循固定的管道，而是根据问题、迄今为止阅读的文档和中间状态选择其下一步行动。智能体还可以通过加载文档、提取有用事实并在使用后删除文档来管理其上下文。这些能力显著提高了准确性和基础性，但处理大型文档使得每次查询成本高昂。例如，在我们使用 FanOutQA 的实验中，使用 Haiku 模型回答一个问题最多消耗一百万个 token，成本接近一美元，使用 Haiku 模型和 FanOutQA 智能体 (Zhu et al., 2024)。这些成本限制了智能体数据推理的可扩展性和可访问性。

3. 智能体数据破解：非结构化数据的自适应结构化

我们展示了数据系统技术可以解决数据推理的成本瓶颈，大幅减少 token 消耗。我们表明，AI 推理的高成本为数据库研究创造了一类紧迫的新问题，需要围绕数据推理工作负载设计的数据系统和算法。先前的工作同样表明，数据管理运算符和抽象可以改善非结构化数据处理 (Liu et al., 2025; Patel et al., 2025; Shankar et al., 2025; Liu et al., 2026; Cetintemel et al., 2026)。

文档和预填充主导成本。 推理工作负载具有不同的推理配置文件。在数学推理中，几乎没有特定于任务的证据可用，模型在自己生成的 token 上工作；这种工作负载通常是解码密集型的。数据推理则具有相反的特征。在准确率优先的策略下，智能体无法推测缺失的事实。它必须反复打开文档，将其加载到上下文中，提取所需的事实，并可能将其删除。因此，数据推理在很大程度上是预填充密集型的。这种瓶颈随着深度（因为推理跨越依赖步骤）、广度（因为每一步扩展到许多实体和文档）和稀疏性（因为少数相关 token 分散在更大的文档中）而加剧。在我们的演员示例中，智能体为每部电影打开一个页面，尽管分散的演员姓名仅占每个页面的一小部分。

通过结构避免文档预填充及其挑战。 避免打开文档的一种方法是在数据库中神奇地将文档知识结构化。预填充密集型的工作负载变成了一个简短的 SQL 查询，无需打开文档；例如，检索希区柯克电影中的所有演员。图 1（右）展示了原始文档和预结构化数据库之间的性能差距。然而，提取很困难。基于非结构化数据的手工设计算法是特定于任务的且可能有损。LLM 更灵活，但仍然需要文档预填充。文档还包含许多实体、属性和关系，使得有用的结构及其表示不明确。提取所有内容将需要无界的解码。与组织已存在结构的数据库索引不同，穷尽的语料库提取是不可行的，并且可能永远无法摊销成本。

自适应智能体数据破解：查询指导提取什么。 我们构建系统，随着查询随着时间的推移揭示什么是有用的，从而自适应地提取结构。当回答智能体打开一个文档时，我们在其上分叉一个并行的破解分支。破解子智能体可以看到该文档上的当前和先前查询。使用语义推理、我们的指令和我们的数据模型，它推测可重用的实体集、属性和关系。至关重要的是，它不限于查询请求的属性或实体集。它还提取可能支持相关查询的附近结构。辅助算法在存储之前对输出进行规范化和验证。提取是语义的、选择性的，并受到观察到的需求的指导。这种设计从应用程序和低级 LLM 推理角度来看都是有意义的。

从应用程序的角度来看，当查询在重叠的实体集上寻求相关目标时，该方法很有效。当一个查询打开 NBA 球员页面以获取历史得分王的职业生涯每场得分时，破解子智能体也可以提取职业生涯每场篮板数。然后，我们运行的问题可以为重叠的 IBM 奖得主重用这些值，而无需重新打开他们的页面。随着对话变成调查，组织围绕相同的公司、产品、案例和人员形成重复的类别和文档热点，这种局部性也会增长。从性能的角度来看，当破解开始时，文档的 KV 缓存已经存在。我们重用缓存的前缀，并在破解指令下分叉第二次生成（图 2(a)），通过共享前缀 KV 缓存重用避免另一次预填充 (Zheng et al., 2024; Kwon et al., 2023)。破解分支并行运行且在回答路径之外，因此它不会延迟当前查询。它唯一的额外模型工作是产生结构化输出的有界解码。

我们称这种方法为智能体数据破解，因为它共享了数据库破解的核心原则：观察到的查询驱动自适应、增量组织以供未来重用。然而，与重新组织现有关系的数据库破解不同，智能体数据破解在不存在的结构中自适应地创建有用的结构。因此，这里的适应性更为重要：穷尽提取是不可行的，KV 缓存重用使开销保持较小且合理，而回报是更大的 LLM 推理节省。它仍然是持久的，并且可跨模型使用。

图 2. (a) 破解分支在共享前缀上进行解码，以填充破解对象存储供后续查询使用。(b) 带有目录查找和文档回退的推理协议。

破解对象与数据模型。 我们的系统运行在由破解子智能体提取的事实之上，该子智能体在文档进入上下文后从回答智能体分叉的推理分支上运行。我们将这些事实称为破解对象。我们将每个破解对象建模为带有基数、单位和证据注释的扩展 RDF 风格边：
$c = \langle s, r, o, \kappa, u, \varepsilon \rangle \in \mathcal{C}, \quad s \in \mathcal{E}, \quad r \in \mathcal{R}, \quad o \in \mathcal{E} \cup \mathcal{V},$
$\mathcal{V} \triangleq ({\mathsf{str}} \times \Sigma^*) \cup ({\mathsf{int}} \times \mathbb{Z}) \cup ({\mathsf{date}} \times \mathbb{D}).$
这里，$\mathcal{E}$ 和 $\mathcal{R}$ 是由破解子智能体填充的开放域。对象 ($o$) 是实体或带标签的标量，它将显式类型与值配对。当前模式支持字符串、整数和可排序日期。因此，破解对象表示实体到实体或实体到值的关系。每个破解对象都带有证据 $\varepsilon = \langle d, \rho \rangle$，其中 $d \in \mathcal{D}$ 标识其来源，$\rho$ 标识该来源内的支持区域。基数 $\kappa \in \mathcal{K} = {\mathsf{singular}, \mathsf{list}}$ 区分单对象关系和产生完整集合的关系。它定义了重用期间的完整性：一条边完成一个单数关系，而列表关系只有在所有成员都被提取后才能重用。我们将列表成员存储为单独的边，因此每个成员仍然可以独立索引和连接。可选的 $u \in \mathcal{U} \cup {\bot}$ 记录规范单位。在我们的模型中，文档是逻辑单元，可以表示文件、修订或块。

读取/推理行为：使用破解对象。 与传统的基线智能体一样，我们的主推理智能体拥有用于搜索、导航和打开文档的文件系统风格工具。但是，它还受益于新的受约束工具调用，这些调用支持从破解对象存储中按主体、关系和主体-关系对进行结构化读取。这些调用允许智能体重用紧凑的破解对象，而无需打开或预填充原始文档。当发生实体名称或关系标签不匹配时，它们会阻止检索相关的存储对象。因此我们引入了目录，这是破解对象存储上的逻辑视图。对于每个文档 $d$，目录列出了可用的主体-关系对及其规范标签和基数：
$\mathsf{Cat}(d) \triangleq \pi_{s,r,\kappa} (\sigma_{\operatorname{doc}(\varepsilon)=d}(\mathcal{C})).$
目录帮助智能体在发出结构化读取之前解析可用的主体和关系（图 2(b)）。系统在智能体决定是否打开文档之前，将其与文档搜索结果一起呈现。如果存在所需的结构，智能体会发出相应的结构化读取，并接收带有证据的紧凑值，从而避免文档预填充。否则，它将打开并预填充原始文档。缺少结构化结果意味着所需的结构不可用或未解析。原始文档访问仍然是保守的回退方式。

图 3. 有和没有数据破解的智能体数据推理性能。

写入/破解行为：产生破解对象。 当破解对象读取无法满足信息需求时，主推理智能体通过打开原始文档来解决由此产生的“未命中”。系统从不仅为破解而打开文档。相反，在文档进入上下文后，破解子智能体从推理分支分叉并针对该文档。在本地服务中，此分叉可以重用文档的 KV 缓存前缀，从而避免第二次预填充。对于带有提示缓存的 API 模型，共享前缀会命中缓存并按较低费率计费。给定文档和未命中的信息需求，子智能体不仅缓存请求的事实或提取预定义的实体和属性。它使用语义推理来推测哪些额外的实体、属性和关系可能支持未来的查询，同时仅提取有根据的事实。

在我们的 NBA 示例中，未命中一个球员统计数据可能会提示提取其他可重用的球员统计数据。因此，破解类似于缓存未命中后的预取，但用智能体发现的语义局部性取代了固定的基于地址的局部性。在固定的输出 token 预算下，子智能体发出受模式约束的 JSON。它发出完整的列表值关系或省略它。后处理验证并规范化输出，将列表扩展为单独的边，并仅插入有根据的破解对象。因为破解仍然在回答依赖路径之外，所以它既不会阻止当前答案，也不会在破解失败时阻止推理智能体使用原始文档。

读取和写入行为捕获了核心机制。实现还包括破解指令和不变性检查。例如，系统规范化数字、单位和日期，并要求每次调用破解整个逻辑文档，从而避免部分破解数据的复杂性和歧义。

4. 评估

我们测试智能体数据破解是否能在具有相关但不同目标和重叠但不同实体集的相关问题之间捕获可重用的结构。我们测量这种重用能在多大程度上降低推理成本，以及它是否保持了答案质量。

评估设置。 基线和我们的系统都建立在 Claude-Haiku-4.5 之上，使用 FanOutQA 的规范、指令、提示和工具调用来访问维基百科和文件系统。我们的系统与基线的不同之处仅在于破解接口。它添加了破解指令和破解对象读/写调用。在所有实验期间都启用了提示缓存。我们测量预填充和解码 token、API 成本和答案准确率。

我们的基准测试是 FanOutQA (Zhu et al., 2024) 和一个以阿尔弗雷德·希区柯克为中心的电影案例研究。FanOutQA 包含关于维基百科的广泛的多跳问题，从最高法院法官到 NBA 球员。它的问题几乎从不重新访问相同的文档，因此缺乏我们系统针对的局部性。这种局部性在设计上从推理基准测试中消失了，因为它们评估的是单个查询的质量。而现实世界的工作负载则是通过相关查询重新访问文档。

为了在不改变测试问题的情况下恢复这种局部性，我们将工作负载加倍：对于每个测试问题，一个 LLM (claude-opus-5) 生成一个相关但不同的问题，并由人工进行验证。每个生成的问题针对重叠实体集上的不同属性。生成器只看到目标问题和我们的标准：可从维基百科回答、实体重叠、属性不同。它不知道破解系统及其设计、实现或输出。对于我们运行的 NBA 示例，生成的问题询问历史前十名 NBA 得分王的职业生涯每场得分。缓存答案在这里无济于事。没有生成的问题重复或改写其测试问题，并且两者从不共享请求的属性。任何节省都来自于对相关属性的语义推测。在 FanOutQA 和案例研究中，所有主要指标都仅在原始测试问题上报告。首先，这使得 FanOutQA 准确率评估定义明确，因为生成的相关问题没有标准答案。其次，破解对象存储完全由前面的相关问题填充，使我们能够评估一个预热的存储，而没有空存储冷启动的噪音。我们单独报告额外的破解成本。

案例研究模拟了一个更长的调查，更接近长时间运行系统中的破解。它的测试问题比 FanOutQA 少，但围绕单一兴趣的相关问题更多。我们首先询问了 20 个关于希区柯克电影、职业和生活的问题。我们评估了 10 个重用这些破解对象的相关测试问题。该序列代表了一个不断演变的电影调查。

结果。 图 1（左）是我们的标题。破解使智能体准确率保持在接近 RAG 的成本。所有系统，包括 RAG 基线，都使用相同的模型。图 1（右）显示了自适应结构化系统的机会。无论是理想破解还是长时间运行的系统，成本都会收敛到理想的结构化存储。图 3 分解了标题。图 3(a) 显示了 token 使用情况。破解将 FanOutQA 上的平均预填充从 189K 减少到 87K token，在案例研究中从 565K 减少到 161K。在所有设置中，解码都保持在 3K token 以下。我们还将成本作为综合指标进行报告，这也是 AI 应用程序最重要的指标。图 3(b) 显示，FanOutQA 上每个问题的平均成本从 0.26 美元降至 0.12 美元，案例研究中从 0.81 美元降至 0.27 美元。案例研究总体上更昂贵，因为它的问题更难，扇出是两到四倍。它的改进也更大，因为首先出现了二十个相关问题，因此测试问题更有可能找到可重用的破解对象。图 3(c) 显示了准确率。
这两个指标都来自 FanOutQA。字符串准确率是在单词级别匹配的标准答案事实的比例。LLM 作为评委使用 GPT 根据标准答案和指令对答案进行评分，如基准测试所规定。评委对部分正确的答案更严格。LLM 评判的准确率与基线相差一个点（42% 对 43%，p 值=0.39），没有统计学上的显著差异，而词匹配准确率下降了两个点，主要是由于答案规范化。相似的准确率源于我们的设计，我们优先考虑稳健的回退。当重用未命中时，智能体会阅读原始文档。更激进的策略可以用这种稳健性换取更大的节省。

图 3(d) 显示了独立排序的每个问题的成本分布。中位数问题在基线下成本为 0.246 美元，在破解下为 0.072 美元，中位数比率为 3.4 倍。收益并不均匀。对于成对的问题逐问题成本比率，破解在第 10 百分位数上便宜 9 倍，而在第 90 百分位数上的成本是基线的 1.24 倍。这些是没有重用的问题，其中破解和数据发现增加了开销而没有节省。破解在四分之三的问题上得到了回报，并且在总体上明显获胜。

我们为每个问题设置了 4K token 的破解解码预算，分摊在破解分叉中。在 FanOutQA 上，这为每个问题增加了 12% 的开销。它包括解码成本和供应商在分叉时对先前上下文收取的缓存读取费用。该预算产生大约 150 个破解对象。更大的预算会产生成比例增加的对象，但额外的对象往往更窄，不太可能被重用。一旦一个问题的破解对象让后续问题避免了一两次文档打开，这个成本就摊销了。避免的少数打开偿还了预算，而除此之外的每次打开都节省了一次文档预填充。更智能的预算分配（例如，针对特定查询或文档）仍然是未来的工作。即使使用我们简单的分配和破解开销，图 3 中的收益也以很大优势保持。

5. 相关工作

深度研究和推理智能体通过多步搜索、文档打开和证据综合来回答大型语料库上的复杂问题 (Asai et al., 2026; Chen et al., 2026)。先前的工作引入了用于处理非结构化数据的数据管理运算符、抽象和执行策略 (Liu et al., 2025; Patel et al., 2025; Shankar et al., 2025; Liu et al., 2026; Cetintemel et al., 2026; Russo and Kraska, 2026)。智能体数据破解通过推测和积累这些智能体和运算符可以运行的可重用、有证据支持的结构来补充这两条路线，因此后续查询可以重用早期查询已经支付过费用的文档打开操作。

OpenIE 在没有预定义模式的情况下从文本中挖掘关系元组 (Etzioni et al., 2008)。知识库构建、知识图谱和基于图的 RAG 在查询到达之前构建表示 (Zhang et al., 2017; Vrandečić and Krötzsch, 2014; Edge et al., 2024)。查询驱动的文档分析仅提取当前查询所需的值 (Lin et al., 2025)。数据空间随着查询揭示重要内容而增量添加集成结构 (Salles et al., 2007)。我们的方法位于前期构建和按查询提取之间。数据模型是开放的，查询指导提取，破解从查询已经打开的文档中增量构建结构。语义缓存返回近似重复问题的答案 (Bang, 2023)。破解对象保持紧凑、有证据支持，并且可跨不同查询重用。服务系统持久化文档和共享前缀 KV 状态以跳过预填充 (Gim et al., 2024; Liu et al., 2024; Yao et al., 2025; Qin et al., 2025)。缓存的 KV 状态绑定到一个模型，比其源文本大得多，占用 GPU 或主机内存，并增加传输和缓存读取成本。破解通过读取缓存的前缀来补充 KV 缓存重用。破解结构是纯文本，因此它们可以在模型升级后继续存在，跨 LLM 转移，并复合成一种组织资产，继续节省 token 和成本。

智能体记忆系统在会话之间持久化信息 (Packer et al., 2023; Chhikara et al., 2025; Zhong et al., 2024; Xu et al., 2025; Rasmussen et al., 2025; Letta, 2025)。人们也可以将智能体数据破解视为一种记忆系统，但是一种具有推测和预取功能的记忆：它记住并推测语料库上的结构，而不是用户的偏好和过去的答案，并且它写入该结构，将提取成本摊销到未来的查询中。MemGPT 在有界上下文窗口和外部存储之间对对话历史进行分页 (Packer et al., 2023)，Letta 将该设计扩展为智能体框架 (Letta, 2025)。Mem0 从正在进行的对话中提取并整合显著事实到长期存储中 (Chhikara et al., 2025)，MemoryBank 随着时间的推移衰减和强化存储的记忆 (Zhong et al., 2024)，Zep 在对话和业务数据上维护时间知识图谱 (Rasmussen et al., 2025)，A-Mem 将记忆组织为动态链接的笔记 (Xu et al., 2025)。这些系统中的记忆写入是由对话轮次触发的，并且范围限于讨论的内容。

6. 讨论

设计决策、局限性和未来工作。 我们公开了受约束的读取函数，而不是完整的 SQL 空间。这使得工具接口保持较小、回退明确且生成的查询可靠。然而，SQL 支持计数、聚合、连接和直接多跳查询。安全地公开这些能力仍然是有趣的未来工作。我们当前的系统假设语料库是静态的。编辑可以通过丢弃受影响的破解对象或从更改中增量细化它们来处理。

我们的基准测试使用开放的、通常经过训练的维基百科内容。私人办公文档未被模型看到且特定于组织。它们还跨用户和工作流被重复查询，使其成为跨查询重用的更有趣的工作负载。为了反映现实世界的工作负载，我们需要捕获文档上长期查询历史的基准测试，最好是从部署的系统中提取的。这样的基准测试将暴露出一个巨大的实际机会，以改善单个查询和长时间运行的现实世界系统。

7. 结论

智能体数据推理可以回答非结构化语料库上的复杂问题，但反复阅读文档使其成本高昂。我们引入了智能体数据破解。它使用观察到的查询来推测有用的结构，并从推理过程中已经打开的文档中提取它。未来的查询然后可以重用这种结构。该设计两次利用了局部性：相关查询重用提取的结构，而破解本身重用文档的 KV 缓存。我们表明，智能体数据破解减少了 token 使用和 API 成本，同时保持了答案质量。与理想完全结构化存储之间剩余的差距表明，数据系统在改善智能体推理方面有着广泛的机会，特别是在跨查询出现有用结构的工作负载中。这个方向将数十年来在语义网、实体解析和自适应数据系统方面的工作与现代智能体的推理能力联系起来。结合这些基础可以使智能体推理更具可扩展性和可靠性。智能体数据破解是迈向这种 AI 推理自适应数据系统的第一步。除了我们的系统之外，该想法适用于系统反复对大型非结构化文档进行推理的任何地方。
