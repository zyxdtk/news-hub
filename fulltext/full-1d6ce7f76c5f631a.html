API新模型推进实时语音智能

📅 2026-05-07 📄 OpenAI 🔗 原文链接

原标题：Advancing voice intelligence with new models in the API Explore new realtime voice models in the OpenAI API that can reason, translate, and transcribe speech, enabling more natural and intelligent voice experiences.

中文摘要： OpenAI在API中推出三款新型实时音频模型：GPT-Realtime-2具备GPT-5级推理能力，支持复杂对话、并行工具调用及更长上下文；GPT-Realtime-Translate支持70+种输入语言到13种输出语言的实时翻译；GPT-Realtime-Whisper提供低延迟流式语音转文本。这些模型推动语音AI从简单问答向能听、推理、翻译、转录和行动的智能界面发展，赋能开发者构建更自然、智能的语音应用。

我们在 API 中推出了三款音频模型，为开发者解锁了一类全新的语音应用。借助这些模型，开发者可以构建感觉更自然、响应更智能并能实时采取行动的语音体验： * **GPT‑Realtime‑2**，我们首个具备 GPT‑5 级别推理能力的语音模型，能够处理更困难的请求并自然地推进对话。 * **GPT‑Realtime‑Translate**，一款新型实时翻译模型，可将 70 多种输入语言的语音翻译成 13 种输出语言，同时与说话者保持同步。 * **GPT‑Realtime‑Whisper**，一款新型流式语音转文本模型，可在说话者讲话时实时转录语音。 ## 体验 GPT-Realtime-2 启动会话，然后与 GPT-Realtime-2 自然交谈。 我可以问什么？ 启动会话后，尝试说以下其中一句： * 我今晚要临时举办一场晚宴。我有 30 分钟时间，两位素食朋友，一位讨厌蘑菇的人，还有一个极小的厨房。帮我计划一个简单的菜单。 * 我正在欢迎嘉宾参加日本的一场现场活动。用日语说一句温暖、自然的欢迎辞——就像主持人开启一场特别活动那样。 * 我的订单号是 Orbit-742Q。清楚地重复一遍，以便我确认是否正确。 * 帮我练习告诉我的团队我们达到了发布里程碑。首先带着平静的自信说，然后带着更多的兴奋说。 * 我正在为公路旅行策划问答游戏。给我三个听起来极其简单的陷阱问题，然后用一句话解释每个答案。 语音正成为人们使用软件最自然的方式之一。它让人可以在开车时寻求帮助，在穿过机场时更改旅行计划，以首选语言获得支持，或者无需停下来打字即可完成任务。 但是，构建有用的语音产品需要的不仅仅是快速的轮流发言或听起来自然的声音。语音智能体需要理解他人的意图，跟踪上下文，在请求改变时恢复状态，在对话继续时使用工具，并以适合当下情境的方式做出响应。 综合来看，我们推出的这些模型将实时音频从简单的问答转向了真正能够完成工作的语音界面：随着对话的展开进行倾听、推理、翻译、转录和采取行动。 ## 语音作为人与产品之间的界面 随着语音成为使用软件更自然的方式，我们看到开发者围绕语音 AI 的三种新兴模式进行构建： * **语音转行动（Voice-to-action），**人们可以描述他们的需求，系统能够对请求进行推理、使用工具并完成任务。例如，Zillow 正在构建一个助手，可以倾听、推理并执行诸如“在我的购买力范围内找房子，避开繁华街道，并安排周六看房”的请求。 * **系统转语音（Systems-to-voice），**软件可以将上下文转化为实时的语音指导。例如，旅行应用可以主动告诉旅客：“您入境的航班延误了，但您仍然可以赶上转机。我找到了新登机口，规划了穿过航站楼的最快路线，并且您的行李预计仍会正常转运。” * **语音转语音（Voice-to-voice），**AI 可以帮助实时对话跨越语言、任务或变化的上下文继续进行。例如，德国电信（Deutsche Telekom）正在构建语音支持体验，客户可以使用他们最习惯的语言说话，而模型会实时翻译对话。 这些模式也可以协同工作。Priceline 正致力于实现一个旅行者可以通过语音管理整个行程的未来：以对话方式搜索航班和酒店，处理诸如航班延误后调整酒店预订或获取 TSA 安检等待时间的实时更新等变更，并在旅行者抵达后翻译对话。 ## 实时语音：帮助语音模型推理和采取行动 GPT‑Realtime‑2 专为实时语音交互而构建，在该交互中，模型在对请求进行推理、调用工具、处理纠正或中断的同时，保持对话的进行，并以适合当下情境的方式做出响应。 * **前置短语（Preambles）：**开发者可以在主要响应之前启用简短短语，例如“让我查一下”或“稍等，我正在查看”，以便用户知道智能体正在处理请求。 * **并行工具调用和工具透明度：**模型可以一次调用多个工具，并通过“正在检查您的日历”或“现在正在查找”等短语使这些操作可听，帮助智能体在完成任务的同时保持响应。 * **更强的恢复行为：**模型可以通过说“我现在遇到了一些问题”之类的话更优雅地恢复，而不是无声地失败或中断对话。 * **用于智能体工作流的更长上下文：**我们将上下文窗口从 32K 增加到 128K，以支持更长、更连贯的会话和更复杂的任务流。 * **更强的领域理解：**模型更好地保留了专业术语、专有名词、医疗保健术语以及在生产环境中重要的其他词汇。 * **更可控的语气和表达：**模型可以更好地调整其语气——在解决问题时平静地说话，在用户沮丧时富有同理心，或在确认成功操作时语气轻快。 * **可调的推理力度：**开发者现在可以从 **minimal（极低）、low（低）、medium（中）、high（高）和 xhigh（极高）** 推理级别中进行选择，**默认为 low**，在简单交互的低延迟与复杂请求的深思熟虑推理之间取得平衡。 这些提升在与生产语音智能体密切相关的音频评估中得到了体现：在 Big Bench Audio 的音频智能评估中，GPT‑Realtime‑2（high）比 GPT‑Realtime‑1.5 高出 15.2%。在 Audio MultiChallenge 的指令遵循评估中，GPT‑Realtime‑2（xhigh）比 GPT‑Realtime‑1.5 高出 13.8%，显示出在实时对话中更强的推理、上下文管理和控制能力。 [Big Bench Audio⁠](https://artificialanalysis.ai/methodology/speech-to-speech-benchmarking) 评估支持音频输入的语言模型中具有挑战性的推理能力。[Audio MultiChallenge⁠(opens in a new window)](https://labs.scale.com/leaderboard/audiomc-audio) 评估口语对话系统中的多轮对话智能，包括指令遵循、上下文整合、自洽性以及处理自然语音纠正。 GPT‑Realtime‑2 的魔力在各种不同的用例中得以展现： 用户 我正在考虑在通勤火车站旁边开一家 900 平方英尺的独立咖啡馆。客流量在周二至周四的上午 7 点到 10 点达到高峰；周一、周五和下午的客流量则少得多。租金很贵，但我喜欢舒适的座位、慢速手冲咖啡和当地糕点这个主意。给我一个战略性的事前剖析：如果这在一年后失败了，可能发生了什么？然后建议我在致力于完整的咖啡馆之前应该测试的最小化业务版本。 0:00 1:04 0:00 0:51 在早期测试中，企业使用 GPT‑Realtime‑2 构建语音智能体，通过自然对话帮助客户和员工完成任务： > “GPT-Realtime-2 的突出之处在于它为复杂的语音交互带来的智能和工具调用可靠性。在我们最难的对抗性基准测试中，这转化为提示优化后呼叫成功率提高了 26 个百分点（95% 对 69%）。GPT-Realtime-2 在公平住房合规性方面也明显更稳健，这对我们的业务至关重要。智能体能力和防护强度的结合使其在 Zillow 的生产语音中变得可行。” — Josh Weisberg，Zillow 高级副总裁兼 AI 负责人 ## 实时翻译：构建实时多语言语音体验 GPT‑Realtime‑Translate 帮助开发者构建实时多语言语音体验，每个人都可以说自己偏好的语言，并听到实时翻译的对话和阅读实时转录。它支持 70 多种输入语言和 13 种输出语言，使其适用于为全球受众服务的客户支持、跨境销售、教育、活动、媒体和创作者平台。 对于开发者来说，实时翻译需要保持语义的同时与说话者保持同步，即使人们自然说话、切换上下文或使用地区发音和特定领域语言。例如，德国电信正在测试该模型用于多语言语音交互，其中较低的延迟和更强的流畅度可以使跨语言对话感觉更自然。 在这段视频中，Vimeo 展示了 GPT‑Realtime‑Translate 如何在产品教育视频播放时进行实时翻译，以便全球客户可以用他们偏好的语言收听更新，而无需等待单独制作的版本。 > “为印度构建语音 AI 意味着要处理多样的地区语音。我们在印地语、泰米尔语和泰卢固语的评估中，GPT-Realtime-Translate 的词错率比我们测试的任何其他模型低 12.5%，同时具有较低的回退率、较高的任务完成率以及维持自然对话的延迟。它为多语言语音 AI 设定了新标准。” — Prateek Sachan，BolnaAI 联合创始人兼 CTO ## 实时转录：构建低延迟转录体验 GPT‑Realtime‑Whisper 是一款专为低延迟语音转文本构建的新型流式转录模型。它在人们说话时转录音频，因此实时产品可以感觉更快、响应更灵敏、更自然——从即时出现的字幕到跟上对话的会议记录。 该模型使实时语音在发生时即可用于业务工作流。团队可以为会议、教室、广播和活动提供字幕；在对话仍在进行时生成笔记和摘要；构建需要持续理解用户的语音智能体；并为客户支持、医疗保健、销售、招聘和其他高容量的口语交互创建更快的后续工作流。 ## 安全性 Realtime API 包含多层安全防护和缓解措施，以帮助防止滥用。我们在 Realtime API 会话上采用主动分类器，这意味着如果检测到某些对话违反了我们的有害内容指南，它们将被停止。开发者还可以使用 [Agents SDK⁠.⁠(opens in a new window)](https://openai.github.io/openai-agents-js/guides/guardrails/) 轻松添加自己的额外安全防护。 我们的[使用政策⁠⁠](https://openai.com/policies/usage-policies/)禁止将我们服务的输出重新用于垃圾邮件、欺骗或其他有害目的，或对其进行分发。开发者还必须向最终用户明确说明他们何时在与 AI 交互，除非从上下文中已经显而易见。 ## 定价与可用性 GPT‑Realtime‑2、GPT‑Realtime‑Translate 和 GPT‑Realtime‑Whisper 已在 Realtime API 中提供。GPT‑Realtime‑2 的定价为 32 美元 / 100 万音频输入 token（缓存的输入 token 为 0.40 美元）和 64 美元 / 100 万音频输出 token。GPT‑Realtime‑Translate 的定价为每分钟 0.034 美元。GPT‑Realtime‑Whisper 的定价为每分钟 0.017 美元。 ##
