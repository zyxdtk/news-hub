原标题：Meta’s proprietary Muse Ember nearly matches Claude Haiku 5.5 at 1/3 the estimated per-task cost

中文摘要： Meta 发布专有模型 Muse Ember，在 Artificial Analysis 智能指数上以 36 分几乎追平 Claude Haiku 5.5，但每项基准任务成本仅约 14 美分，约为后者的三分之一。该模型提供百万 token 上下文窗口，20 万 token 以下输入每百万仅 0.10 美元。Ember 在业务自动化基准上明显领先，编码表现互有胜负。文章还对比了 DeepSeek、小米 MiMo、美团 LongCat 等开放权重替代方案，并建议将其用于有明确验收标准的高频规模化任务

Meta 于周一发布了 Muse Ember，为开发者提供了一个更便宜的模型，用于处理那些会让 AI 智能体在大规模运行时变得昂贵的任务。

例如，一个客服工单可能会让智能体经历一系列查询、文档读取和工具调用，才能给出答案。Ember 正是为处理这些步骤而构建的，同时也适用于运行测试和进行小规模代码修复等任务。

在独立评估机构 Artificial Analysis 的发布评估中，Ember 在最大推理努力下的智能指数（Intelligence Index）得分为 36 分，与 Anthropic 的 Claude Haiku 5.5 四舍五入后的分数相同。Ember 每项基准任务的成本约为 14 美分，而 Haiku 为 41 美分。

Meta 的底层图表显示，未四舍五入的分数分别为 35.8 和 36.2。OpenAI 的 GPT-6 Luna 在最高设置下得分为 27.8，每项任务成本约为 15 美分，但在较低设置下运行成本可低至约 7 美分，得分为 21.4。

Meta 首席执行官马克·扎克伯格在 X 上的一篇帖子中将 Ember 描述为“我们最小的、每美元智能产出高于同级其他产品的模型”。

“[Muse W]onder 负责规划，Ember 负责处理海量任务，”Meta 首席人工智能官 Alexandr Wang 在 X 上的发布帖文中写道。

百万 token 窗口与 20 万 token 价格跳档

Meta Model API 通过其 Responses、Chat Completions 和 Messages 端点以 muse-ember-1.0 的名称提供这一专有模型。

它接受文本、图像、音频、视频和 PDF 输入，并返回文本。Meta 列出的上下文窗口为 1,048,576 个 token，最大输出为 524,288 个 token。推理努力范围从最小到最大，默认为最大。Ember 也可在 Muse Code 中使用。Meta 将 Oracle Cloud 列为另一条使用途径，而 Google Cloud 的预览版文档记录了文本和图像输入。

对于不超过 200,000 个输入 token 的请求，Meta 对 Muse Ember 的收费为：每百万未缓存输入 token 0.10 美元、每百万缓存输入 token 0.004 美元、每百万输出 token 0.50 美元。

超过 200,000 个 token 后，费率分别升至 0.30 美元、0.012 美元和 1.50 美元。

公布的 API 定价使 Muse Ember 成为全球较便宜的基础级或近基础级模型之一，其 20 万 token 以下的未缓存价格与 Anthropic 的 Claude Haiku 5.5 和 OpenAI 的 GPT-6 Luna 持平。

较高的费率适用于整个请求，包括其输出。缓存输入以及通过 previous_response_id 延续的对话历史都计入分界额度。对于一个包含 200,000 个未缓存输入 token 和 10,000 个计费输出 token 的请求，模型收费为 2.5 美分。而再多一个输入 token 就会使同一请求的费用升至约 7.5 美分。

Anthropic 的标准 API 定价中，Haiku 的起始价格同样是输入 0.10 美元、输出 0.50 美元，超过 100,000 个输入 token 后升至 0.50 美元和 2.50 美元。其缓存读取起始价格为每百万 0.01 美元。

OpenAI 的标准定价中，Luna 的起始输入和输出费率相同，缓存输入为 0.01 美元。其长上下文费率为输入 0.20 美元、缓存输入 0.02 美元、输出 0.75 美元。

因此，对于提示词量大且回答较长的工作负载，OpenAI 的 GPT-6 Luna 在 token 费率上可能反而更划算，即使 Ember 在基准测试套件中成本更低。

Artificial Analysis 将 Ember 基准测试成本优势的一部分归因于更便宜的缓存读取，并报告称在最大努力下，Ember 使用的输出 token 约为 Haiku 的三分之一。

在估算生产环境账单时，这一区别很重要。一旦智能体开始推理、检索记录并将结果从一个步骤带入下一个步骤，相同的标价可能会产生截然不同的成本。

Ember 最明显的领先优势在于业务工作流

在 Meta 的发布结果中，Ember 首次尝试即完全完成了 37.8% 的 AutomationBench-AA 任务，而 Luna 为 20.2%，Haiku 为 13.9%。该测试让智能体在模拟的业务应用中执行任务。

Artificial Analysis 的主要指标（对在不违反基准规则的情况下完成的单个目标给予计分）将 Ember 评为 68.1%。这两个数字回答的是不同的问题。对于只有每个步骤全部完成才算成功的工作流，第一个数字才是相关的。

编码方面的结果则更为复杂。在 Artificial Analysis 的编码智能体指数（Coding Agent Index）中，Muse Code 中的 Ember 得分为 46 分，领先于 Claude Code 中的 Haiku（37 分）和 Codex 中的 Luna（31 分）。

但在 FrontierCode 2.0（评估代码更改是否达到可合并标准）上，Haiku 以 34.9% 领先于 Ember 的 27.2%。而在 Meta 的桌面应用评估 OSWorld 2.1 中，Ember 的 69.5% 部分得分在任务按“全有或全无”标准评分时降至 33.8%。

综合来看，这些结果更有力地支持给 Ember 分配有明确检查标准的有限任务，而不是将整个工程工单或桌面工作流交给它无人值守地处理。

开放权重替代方案的表现如何

与 Ember 最接近的比较是按工作负载和价格来划分的。Meta 一直对 Ember 的权重和参数数量保密，因此其规模无法与可下载权重的模型直接匹配。以下分数使用 Artificial Analysis 当前的 v5 方法论。该公司在 10 月修订了该指数，因此早期发布报道中的一些分数较高，属于旧版本。

DeepSeek-V4.1-Flash-1017 是低成本托管智能体工作的一个接近的替代选择，并且可以选择自行运行 MIT 许可的权重。

DeepSeek 的 API 提供百万 token 窗口和图像输入，非高峰时段每百万 token 收取 0.15 美元输入和 0.60 美元输出，高峰时段为 0.30 美元和 1.20 美元。缓存命中成本为 0.003 或 0.006 美元。

在 Artificial Analysis 的 Ember 发布对比中，DeepSeek Flash 得分为 33 分，每项基准任务成本约 0.60 美元，而 Ember 为 36 分和 0.14 美元。对于反复发送相同大量上下文的流水线来说，DeepSeek 更便宜的非高峰缓存读取以及在超长提示上更低的输出费率仍然可能很重要。

Muse Spark Open 是 Meta 自己的途径，用于在你自己控制的基础设施上运行百万 token 的多模态 Muse 模型。

Meta 的文档列出了 8160 亿总参数和每 token 420 亿活跃参数。权重受自定义的 Muse 模型许可和可接受使用政策约束。

四比特量化检查点在计入服务开销之前仍重约 537 GB。

Together AI 每百万 token 收取 1.25 美元输入和 4.25 美元输出。

Artificial Analysis 列出的当前分数为 25 分（xhigh 推理设置），每项基准任务 2.02 美元。

Spark Open 的价值在于对模型运行位置的控制以及对其进行调整的能力。对于想要在本地运行小得多的 Muse 模型的团队，Meta 的 300 亿参数 Muse Glimmer 可在 Apache 2.0 许可下使用。

小米的 MiMo-V2.6-Pro 提供 MIT 许可的权重、百万 token 窗口以及原生文本、图像、音频和视频输入。

它拥有约一万亿参数，每 token 活跃参数为 420 亿。

小米的 API 列出每百万 token 输入 0.435 美元、输出 0.87 美元，缓存输入为 0.0036 美元。Artificial Analysis 目前给它的评分为 30 分，每项任务 0.26 美元。

小米采用 MIT 许可的 MiMo-V2.6-Flash 在价格上是更接近的比较对象。它得分为 27 分，每项基准任务成本约 0.13 美元，列出的费率大约为输入 0.14 美元、输出 0.28 美元、缓存命中 0.0028 美元。

美团的 LongCat-2.5 也提供 MIT 许可的权重。它拥有 1.6 万亿参数，每 token 活跃参数约 480 亿，面向长编码任务和视觉任务。其百万 token API 支持最多 256,000 个输出 token，美团的限时定价为每百万 token 未缓存输入 0.30 美元、缓存输入 0.006 美元、输出 1.20 美元。

美团报告使用 Claude Code 在 Terminal-Bench 4.0 上取得 38.5% 的成绩，而 Meta 报告 Ember 使用 mini-swe-agent 取得 40.9%。不同的测试设置使这些数字只能作为粗略的参考。在相同代码库和相同工具上的直接比较才能让团队更清楚地了解该使用哪个模型。

Meta 如何从 Spark 走到 Ember

Meta 超级智能实验室于 4 月推出了最初的 Muse Spark。在多年分发 Llama 权重之后，Meta 最初将 Spark 保持为专有模型，并将其放入 Meta AI 和私有 API 预览中。

7 月，Spark 1.1 以公开预览的形式开放了该 API。

8 月，Spark 1.2 与 Muse Code（Meta 的支持持久后台任务的终端编码智能体）一同发布。五天后，Muse Glimmer 将可下载权重带回了 Meta 的模型阵容。

9 月初，Spark 1.3 改进了编码和多步骤工作流，其最佳发布分数来自最初受限的最大努力配置。

10 月，Muse Wonder 和 Wonder Full 为困难任务创建了更高的层级。Wonder 通过 API 和 Muse Code 发布，而 Wonder Full 在发布时面向 Muse Code 订阅者提供。

几天后，Spark Open 将 Meta 的开放权重阵容扩展到更大的多模态模型。上周五，Meta 开始向其 Muse 个人智能体和 Meta AI 的用户推出使用 Wonder 系列训练的专用模型。Meta 表示，Ember 是其首个使用 Wonder Full 训练的模型。

Ember 在生产工作流中的定位

即使工作流的其余部分已经在 Spark 上运行，Ember 也可以接管其中的单个步骤。在 Meta 与 Spark 1.3 的对比中，Ember 在最大努力下得分为 36 分，Spark 为 37 分，每项任务的基准成本分别约为 0.14 美元和 2.39 美元。

一个实用的首次部署是选择团队已经知道如何评估的步骤。编码智能体可以让 Ember 调查一个失败的测试，然后让补丁通过持续集成，并将失败情况升级给更强的模型处理。

客服智能体可以使用 Ember 对工单进行分类并获取相关记录，同时将账户更改保留在审批步骤之后。文档流水线可以给它一批扫描页面，并根据原始文件核对每个提取的字段。

这些设计让团队能够衡量每个被接受结果的成本（包括重试和升级），同时关注延迟以及上下文将请求推入更高价格档位的频率。

对于评估敏感工作负载的团队，Meta 表示标准模式下的 API 内容不会用于模型训练。Meta 为启用了该设置的账户提供单独的零数据保留条款。需要将推理保留在自己基础设施上的团队，则必须权衡可下载模型的硬件和运营成本与 Ember 的托管费率。

对于可以使用托管服务的团队，最明确的首个测试是一项频繁出现、定义明确、已有成功检查标准且调用量足够大、能让每次调用的小额节省累积成可观总额的任务。
