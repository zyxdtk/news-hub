中国 AI 初创公司 Z.ai 凭借其不断壮大、功能强大且 largely 开源的 GLM 系列语言模型在国际上享有盛誉。今天，该公司发布了 GLM-5.3，该模型在长周期编程方面取得了实质性进展，同时在网络安全能力方面实现了更为重大——且可能敏感——的跃升。

据 Z.ai 开发者布道师 Lou 在 X 上发帖称，GLM-5.3 的网络能力已经发现了一个“Cursor 中的潜在严重漏洞”，这家 AI 编程初创公司最近被 SpaceX 收购。VentureBeat 也在 X 上标记了 Cursor 以求证实，目前正在等待回复。

该公司表示，GLM-5.3 最初仅通过其 GLM Coding Plan 和 ZCode 编程环境提供，而 API 访问权限和开放权重将在“完成安全评估和加固后”于稍后推出。
Z.ai 表示计划在发布约两周后发布权重。

对于企业开发者而言，此次发布的亮点不仅仅是基准测试的又一次提升。Z.ai 表示，GLM-5.3 使用了与 GLM-5.2 相同的基础模型，其改进完全来自于在更多环境、更多样化任务以及额外强化学习计算中扩展后训练。

这使得 GLM-5.3 在某种程度上成为了一项测试，即在无需进行另一轮昂贵的预训练周期的情况下，前沿规模的基础模型能被推进到何种程度。

“扩展后训练是我们为 GLM-5.3 所做的全部工作，”Z.ai 在其技术公告中写道。

结果显示出相当大的提升空间。但这也为开源模型开发者带来了一个不寻常的问题：据 Z.ai 称，随着训练规模的扩大，网络安全能力的提升速度快于预期，特别是当任务从漏洞识别向构建完整的漏洞利用链推进时。

路透社周五报道称，Z.ai 还围绕该模型的一些高级功能引入了控制措施，包括针对敏感功能的“受信任访问”方法。

无需新基础模型，编程能力大幅跃升

GLM-5.3 构建于 GLM-5.2 背后的 7430 亿参数规模基础模型之上，而非取而代之。Z.ai 转而扩展了其已经围绕长周期强化学习组建的后训练系统。

这些环境越来越类似于完整的工程工作，而不是孤立的编程练习。

Z.ai 描述了这样一些场景：智能体获得对代码库、文档、计算集群、存储系统和实验结果的访问权限，然后必须诊断问题、修改系统、运行实验，并在保持正确性的同时展示出可衡量的改进。一些任务旨在近似经验丰富的工程师几天的工作量。

这种方法在 Z.ai 报告的评估中产生了可观的代际改进。

GLM-5.3 在 Terminal-Bench 3.0 上的得分从 4.6 跃升至 28.3，在 DeepSWE v1.1 上从 46.2 跃升至 66.9，在 AutomationBench 上从 26.2 跃升至 48.2。在 Agents' Last Exam CLI 上，它从 23.8 提升至 28.5。

该模型并未在所有前沿竞争对手中占据绝对优势。Z.ai 自己的基准测试表显示，在 Terminal-Bench 3.0 上，GPT-5.6 Sol 得分为 34.6，Claude Fable 5 为 33.7，而 GLM-5.3 为 28.3。在 DeepSWE v1.1 上，GLM-5.3 得分为 66.9，而 GPT-5.6 Sol 为 72.7，Fable 5 为 69.7。

但 Z.ai 也强调效率，而不仅仅是基准排名。

在其私有的 Z.ai Code Bench 上，GLM-5.3 在 Max 推理设置下达到了 34.5% 的成绩，同时每个任务消耗约 75,000 个输出 token。GLM-5.2 达到 23.4%，消耗约 96,000 个 token。在 High effort 级别下，GLM-5.3 在消耗约 50,000 个输出 token 的情况下达到 31.4%，而据 Z.ai 报告，Claude Opus 4.8 在消耗 120,000 个 token 时的成绩为 29.5%。

由于 Code Bench 是 Z.ai 自己的私有评估，这些比较应被视为公司报告的结果，而非独立测量结果。尽管如此，在提高任务完成率的同时减少 token 消耗，对于部署编程智能体的企业来说在运营上具有重要意义，因为长时间运行的循环会使推理成本和延迟迅速叠加。

网络能力发展超出 Z.ai 预期

更不寻常的发展在于网络安全领域。

Z.ai 将漏洞发现环境引入 GLM-5.3 的后训练组合中，期望模型在发现软件缺陷方面有所改进。然而，该公司表示，能力开始沿着漏洞利用链进一步发展。

“随着我们扩展后训练，网络能力的发展速度超出了我们的预期，”Z.ai 写道。

z.ai GLM-5.3 基准测试。图片来源：z.ai

在针对源代码测试漏洞发现和验证的 CyberGym 上，GLM-5.3 得分为 84.5%，而 GLM-5.2 为 77.2%。这也略微超过了 Z.ai 报告的 GPT-5.6 Sol（83.6%）和 Mythos 5（83.8%）的得分。

这种优势并没有扩展到整个漏洞利用栈。GLM-5.3 在 ExploitBench 上的得分为 54.4%，是 GLM-5.2（24.4%）的两倍多，但仍远落后于 Z.ai 报告的 GPT-5.6 Sol（76.5%）和 Mythos 5（78%）。

同样，在 ExploitGym 上，GLM-5.3 在标准的两小时预算内完成了 105 项任务，在六小时内完成了 130 项任务，而 GLM-5.2 分别为 29 项和 39 项。Fable 5 达到了 181 项和 247 项，而 GPT-5.6 Sol 达到了 216 项和 293 项。

发展方向可能比排行榜位置更重要。

Z.ai 表示，与中国安全团队合作的结果是，经过专家审查、筛选和去重后，在 269 个项目中发现了 2,436 个漏洞。其披露账本列出 1,097 个为严重或高危漏洞，其中 53 个已公开披露，2,383 个在发布时仍处于保密状态。

这造成了前沿模型提供商日益面临的一种紧张关系：使模型在软件工程中更有用的长周期智能体能力，同样也能使它们成为更强大的安全研究员——并可能成为更强大的攻击者。

GLM-5.3 还要求开发者改变调用模型的方式

迁移现有 GLM 应用的开发者应注意一项破坏性的 API 行为。

GLM-5.3 支持三个推理努力级别——low、high 和 max——其中 max 是默认值，也是 Z.ai 推荐的编程设置。但与之前的版本不同，思考模式无法被禁用。

当前发送 thinking.type: "disabled" 的应用程序必须在将模型标识符切换为 GLM-5.3 之前，将该值更改为 enabled 并指定推理努力级别。否则，Z.ai 表示请求将失败。

这使得 GLM-5.3 对于某些生产应用程序来说是一次真正的迁移，而不仅仅是简单的模型名称替换。

从 GLM-4.5 到 GLM-5.3：Z.ai 向智能体工程的快速推进

GLM-5.3 是 Z.ai（前身为智谱 AI）向编程智能体和长时间运行的自主工程工作负载快速转型的最新一步。

2025 年 7 月发布的 GLM-4.5 确立了这一方向的大部分内容。这个 3550 亿参数的混合专家模型旨在结合推理、编程和智能体能力，而较小的 GLM-4.5-Air 则提供了 1060 亿总参数。Z.ai 以开放权重发布了这些模型，并强调与智能体框架的集成。

GLM-4.6 紧随其后于 9 月发布，将上下文从 128,000 个 token 扩展到 200,000 个，并针对包括 Claude Code、Cline、Roo Code 和 Kilo Code 在内的环境中的编程、工具使用和智能体工作流进行了优化。Z.ai 还开始更加注重在实际编程评估中的 token 效率，而不仅仅是基准性能。

更大的架构飞跃出现在 2026 年 2 月的 GLM-5。Z.ai 将模型从 GLM-4.5 的 3550 亿参数扩展到 7440 亿，其中活跃参数为 400 亿，并将预训练数据增加到 28.5 万亿个 token。它还引入了“slime”异步强化学习基础设施，并明确将 GLM 系列重新定位为围绕“智能体工程”和长周期任务。

GLM-5.2 的定价为每百万 API 输入 token 1.40 美元，每百万输出 token 4.40 美元，缓存输入的定价大幅降低，这使 Z.ai 成为专有前沿实验室在技术和价格上的双重竞争者。

Z.ai 的雄心也扩展到了模型开发之外。路透社上月报道称，智谱 AI 通过香港股票出售筹集了约 314 亿港元（约合 40 亿美元），所得资金拟用于研发、计算基础设施、人才和业务扩张等领域。

总而言之，这些发布展示了一个一致的进展过程：GLM-4.5 统一了推理、编程和智能体；GLM-5 大幅扩展了基础模型；GLM-5.2 攻克了长上下文和长周期工程；而 GLM-5.3 现在正试图通过后训练从相同的基础中提取更多的能力。

定价、ZCode 和可用性

GLM-5.3 现已通过 Z.ai 的 GLM Coding Plan 和 ZCode 提供。

ZCode 是该公司自己的编程智能体环境，支持计划、实施、测试和验证工作的长时间运行“目标”任务。它还提供对运行中任务的远程控制，并可在 macOS、Windows 和 Linux 上使用。

个人 GLM Coding Plan 目前的促销标价起价为每月 12.60 美元（Lite 版，每周 10,000 积分）。Pro 版标价为每月 56 美元，用量为 Lite 版的六倍，而 Max 版每月 117.60 美元，用量为 Lite 版的 14 倍。团队标准版和高级版席位的标价分别为每位用户每月 88 美元和 188 美元。

Z.ai 还将 Coding Plan 转向了基于积分的配额系统，该系统单独核算输入、缓存输入和输出 token。在工作日高峰期之外调用消耗的积分为正常值的 50%。

该公司在提供的发布材料中尚未提供 GLM-5.3 API 的通用定价，这使得在分阶段 API 访问到来之前，总生产 API 成本很难直接与 GLM-5.2 或竞争的前沿模型进行比较。

这种分阶段发布可能最终成为 GLM-5.3 最重要的部分。

Z.ai 在过去一年中推行开放模型战略，核心是宽松的权重、低成本的推理以及与现有编程智能体生态系统的兼容性。GLM-5.3 展示了当这种战略在某个敏感领域可能过于成功时会发生什么：更好的自主工程也意味着更好的自主安全研究。

其结果是，该模型推进了 Z.ai 的编程雄心，同时迫使该公司直面与最大的闭源前沿实验室相同的能力与访问权限之间的权衡。

因此，对于企业开发者来说，GLM-5.3 值得关注有两个原因。其编程结果表明，无需不断重建底层基础模型，通过更好的后训练和环境就能涌现出能力越来越强的智能体。而其网络安全结果则表明，决定如何分发这些智能体，可能与决定如何训练它们一样重要。
