摘要 测试时扩展（TTS）已成为一种通过在推理期间分配额外计算来提高大型语言模型性能的有效方法。然而，现有的 TTS 策略在很大程度上是手工设计的：研究人员根据直觉手动设计推理模式并调整启发式方法，使得大部分计算分配空间未被探索。我们提出了一个环境驱动的框架 AutoTTS，它改变了研究人员设计的内容：从单个 TTS 启发式方法转变为可以自动发现 TTS 策略的环境。AutoTTS 的关键在于环境构建：发现环境必须使控制空间变得易于处理，并为 TTS 搜索提供廉价、频繁的反馈。作为具体实例，我们将宽度-深度 TTS 制定为对预先收集的推理轨迹和探测信号的控制器综合，其中控制器决定何时分支、继续、探测、修剪或停止，并且可以在不重复调用 LLM 的情况下廉价地评估。我们进一步引入了 beta 参数化以使搜索易于处理，并引入了细粒度的执行轨迹反馈，通过帮助智能体诊断 TTS 程序失败的原因来提高发现效率。在数学推理基准上的实验表明，发现的策略在强手工设计的基线上改善了整体的准确率-成本权衡。发现的策略可以泛化到留出的基准和模型规模，而整个发现成本仅为 39.9 美元和 160 分钟。我们的数据和代码将在 https://github.com/zhengkid/AutoTTS 开源。

1 引言

图2：现有的 TTS 算法作为宽度-深度控制空间的特例。每种算法追踪一条独特的路径：SC@64 wang2022self 占据固定的全预算角落；ASC aggarwal2023let 和 ESC li2024escape 仅在最大深度沿宽度轴自适应；Answer Consistency liu2025answer 仅在单链上沿深度轴自适应；ST-BoN wang2025sampling 先宽扩展，修剪为一个分支，然后加深；Parallel-Probe zheng2026parallel 从宽开始并在加深时逐步修剪。

测试时扩展（TTS）snell2024scaling; brown2024large; muennighoff2025s1 已成为一种通过在推理期间分配额外计算来提高大型语言模型性能的强大范式。然而，性能不仅取决于使用的计算量，还取决于如何分配 snell2024scaling，而现有的分配策略在很大程度上是手工设计的：研究人员手动假设何时分支、加深、探测、修剪或停止推理轨迹的启发式方法 zhao2025majority; wen2025parathinker; wang2026not; zheng2026parallel; tu2025deepprune; zhang2025alphaone，实现它们，并根据直觉调整阈值。

回顾 TTS 策略的发展揭示了一个有价值的视角。虽然现有方法在形式上有很大差异，但其中许多可以被解释为某种底层计算分配空间内手动指定的策略。一个简单的例子是宽度-深度空间，其中宽度表示探索了多少推理分支，深度表示每个分支发展了多远，如图 2 所示。在这个观点下，几种代表性方法对应于穿过空间的不同轨迹：一些通过采样更多推理分支来扩展宽度 wang2022self; aggarwal2023let; li2024escape；一些通过延长推理轨迹来增加深度 muennighoff2025s1; zhang2025alphaone；还有其他引入自适应停止、修剪或选择规则以更有选择性地在空间中移动 fu2025deep; tu2025deepprune; liu2025answer; zheng2026parallel。值得注意的是，这个观点并不是要将所有 TTS 算法简化为二维抽象，因为许多方法涉及更丰富的结构，如树搜索 yao2023tree; inoue2025wider 或验证器引导的细化 snell2024scaling; wang2024math; luo2024improve。相反，宽度-深度空间的情况表明，许多 TTS 策略可以被视为结构化控制空间内手工设计的特例。

这种观点提出了对问题的根本重新构建。在这项工作中，我们提出了 AutoTTS，一种用于自动 TTS 策略发现的环境驱动范式（图 1）。AutoTTS 不再手工制作单个分支、修剪和停止的启发式方法，而是将人类的角色转变为构建发现环境，人类通过状态、动作、反馈和目标来定义控制空间，智能体在该空间内搜索有效的分配策略。

作为概念验证实例，我们将宽度-深度测试时扩展（图 2）制定为离线回放环境中的控制器综合。对于每个问题，我们预先收集推理轨迹和中间探测信号，允许控制器重放关于何时分支、继续、探测、修剪或停止的决策。控制器观察活动分支、它们的深度、揭示的探测输出和剩余预算，并通过产生的准确率-成本权衡进行评估。由于评估重用预先收集的轨迹，候选控制器可以被廉价且确定地评估，而无需重复调用基础 LLM。然而，有效的发现面临两个额外的挑战：自动发现的控制器倾向于引入过多的超参数，使得搜索空间很大且难以在有限的轮次内导航，并且仅靠标量的准确率-成本反馈不足以告诉探索者控制器为什么失败。

为了使控制器搜索易于处理，我们引入了 beta 参数化，其中每个控制器只暴露一个标量权衡参数 $\beta$ 并从中确定性地推导出所有内部超参数，从而减少对搜索集的过拟合。此外，我们通过记录执行轨迹来解决反馈问题，这些轨迹暴露了每个控制器随时间分配计算的方式，使探索者能够诊断失败模式并提出有针对性的改进。

在数学推理基准上的实验表明，AutoTTS 发现的控制器在强手工基线上改善了准确率-成本帕累托前沿。发现的控制器可以从搜索基准泛化到留出基准以及跨模型规模，而由于固定的回放，整个发现过程仍然负担得起。这些结果表明，环境驱动的发现提供了一种可扩展且可重复使用的替代方案来替代手动设计 TTS 策略，并且投入人类精力的正确地方是环境设计，而不是策略设计。

2 测试时扩展作为算法搜索

我们考虑在多个推理分支上分配有限推理预算的自适应测试时算法。对于每个问题 $q$，控制器可以创建分支、扩展它们、探测中间信号、修剪分支，最后将探索的前缀聚合为一个答案。这涵盖了常见的策略，如 best-of-$N$、自洽性、早停和自适应分支。每个分支 $i$ 产生前缀 $z_{i,1},z_{i,2},\ldots$，其中 $z_{i,k}$ 是在 $k$ 个固定长度生成间隔后获得的。在每个间隔，分支产生一个中间答案 $\omega_{i,k}$，即从当前前缀产生的答案。只有当控制器明确采取探测动作时，才会观察到此答案。

由于我们将单位生成视为具有固定 token 长度的间隔，因此我们以间隔为单位衡量计算。设 $B$ 为总计算预算。在决策步骤 $t$，设 $m_{t}\in\mathbb{Z}_{\geq 0}$ 表示到目前为止实例化的分支数量，并使用约定 $[m_{t}]=\{1,\ldots,m_{t}\}$，其中 $[0]=\emptyset$。状态为 $s_{t}=(q,m_{t},I_{t},\ell_{t},\Omega_{t})$，其中 $q\in\mathcal{Q}$ 是问题，$I_{t}\subseteq[m_{t}]$ 是当前活动分支的集合，$\ell_{t}=(\ell_{t,i})_{i\in[m_{t}]}$ 记录每个实例化分支的当前深度（由间隔数衡量），$\Omega_{t}$ 是迄今为止揭示的探测反馈集合。对于每个实例化的分支 $i\in[m_{t}]$，$\ell_{t,i}\geq 1$ 表示在该分支上已生成了多少个固定长度的探测间隔。对于修剪的分支 $i\in[m_{t}]\setminus I_{t}$，$\ell_{t,i}$ 记录它被修剪时的深度。揭示的反馈集满足 $\Omega_{t}\subseteq\{(i,k,\omega_{i,k}):i\in[m_{t}],\ 1\leq k\leq\ell_{t,i}\}$。未揭示的探测输出不是控制器状态的一部分。状态的计算成本为 $\mathrm{Cost}(s_{t})=\sum_{i=1}^{m_{t}}\ell_{t,i}+\kappa_{\mathrm{probe}}|\Omega_{t}|$，其中 $\kappa_{\mathrm{probe}}\geq 0$ 是读取一个探测信号的成本。在将探测视为相对于生成免费的设置中，我们设 $\kappa_{\mathrm{probe}}=0$。因此，剩余预算为 $B-\mathrm{Cost}(s_{t})$。

给定 $s_{t}=(q,m_{t},I_{t},\ell_{t},\Omega_{t})$，容许动作集为 $\displaystyle\mathcal{A}(s_{t})=$ $\displaystyle\{\texttt{BRANCH}:\mathrm{Cost}(s_{t})+1\leq B\}\cup\{\texttt{CONTINUE}(i):i\in I_{t},\ \mathrm{Cost}(s_{t})+1\leq B\}$ $\displaystyle\cup\{\texttt{PROBE}(i):i\in I_{t},\ \mathrm{Cost}(s_{t})+\kappa_{\mathrm{probe}}\leq B,\ \nexists\omega\ \mathrm{s.t.}\ (i,\ell_{t,i},\omega)\in\Omega_{t}\}$ $\displaystyle\cup\{\texttt{PRUNE}(i):i\in I_{t}\}\cup\{\texttt{ANSWER}\}.$

这里 BRANCH 创建一个新分支 $m_{t}+1$ 并将其从问题推进到第一个间隔的末尾。CONTINUE(i) 将分支 $i$ 推进一个固定长度的探测间隔。PROBE(i) 揭示当前的探测信号 $\omega_{i,\ell_{t,i}}$ 而不推进分支。PRUNE(i) 从活动集中移除分支 $i$，同时保持其深度和先前揭示的反馈记录在状态中。ANSWER 终止推理并调用聚合规则。聚合规则 $\operatorname{Agg}$ 将状态作为输入并输出最终答案。形式上，初始状态为 $s_{0}=(q,0,\emptyset,\emptyset,\emptyset)$。

如果 $a_{t}=\texttt{BRANCH}$，则实例化一个新分支 $m_{t}+1$ 并推进到第一个探测点：$m_{t+1}=m_{t}+1$，$I_{t+1}=I_{t}\cup\{m_{t}+1\}$，$\ell_{t+1}=(\ell_{t},1)$，且 $\Omega_{t+1}=\Omega_{t}$。如果 $a_{t}=\texttt{CONTINUE}(i)$，则 $m_{t+1}=m_{t}$，$I_{t+1}=I_{t}$，$\Omega_{t+1}=\Omega_{t}$，且对于所有 $j\in[m_{t}]$，$\ell_{t+1,j}=\ell_{t,j}+\mathbf{1}\{j=i\}$。如果 $a_{t}=\texttt{PROBE}(i)$，则 $m_{t+1}=m_{t}$，$I_{t+1}=I_{t}$，$\ell_{t+1}=\ell_{t}$，且 $\Omega_{t+1}=\Omega_{t}\cup\{(i,\ell_{t,i},\omega_{i,\ell_{t,i}})\}$。如果 $a_{t}=\texttt{PRUNE}(i)$，则 $m_{t+1}=m_{t}$，$I_{t+1}=I_{t}\setminus\{i\}$，$\ell_{t+1}=\ell_{t}$，且 $\Omega_{t+1}=\Omega_{t}$。如果在时间 $T$ 有 $a_{T}=\texttt{ANSWER}$，则回合终止，最终答案由 $y^=\operatorname{Agg}(s_{T})$ 通过聚合规则产生。

我们的目标是找到一个代码定义的策略 $\pi$，它将状态和参数 $\beta$ 映射到容许原子动作上的分布：$\pi(\cdot\mid s,\beta)\in\Delta(\mathcal{A}(s))$。这里，$\beta$ 是一个元超参数，用于控制算法中使用的所有超参数。我们允许控制器包含其自己的终端聚合规则 $\operatorname{Agg}_{\pi,\beta}$。因此，当在终端状态 $s_{T}$ 选择 ANSWER 时，最终答案为 $\hat{y}_{\pi,\beta}(q)=\operatorname{Agg}_{\pi,\beta}(s_{T})$，计算成本为 $C_{\pi,\beta}(q)=\operatorname{Cost}(s_{T})$。

对于问答对 $(q,y)$ 上的任务分布 $\mathcal{D}$，我们的目标是选择策略 $\pi$ 和超参数 $\beta$，在控制计算成本的同时最大化准确率。在权衡参数 $\gamma$ 下，我们旨在求解 $\displaystyle\max_{(\pi,\beta)}\ \mathbb{E}_{(q,y)\sim\mathcal{D}}\left[\mathbf{1}\{\hat{y}_{\pi,\beta}(q)=y\}-\gamma C_{\pi,\beta}(q)\right].$

发现循环在代码定义的控制器空间中进行搜索。每个候选控制器在每个问题 $q$ 上通过将其最终答案与真实答案进行比较并记录计算成本来进行评估。产生的执行历史存储在内存中，用于指导后续的策略搜索轮次。最后，我们输出实现最佳准确率-成本权衡的代码定义策略。详细的实现如下节所示。

3 AutoTTS：环境驱动的发现

我们将 AutoTTS 实例化为第 2 节中目标的具体发现流程。关键挑战是使代码定义策略 $\pi(\cdot\mid s,\beta)$ 的搜索变得易于处理：在线评估候选策略需要按需生成 token 间隔 $z_{i,k}$ 和探测答案 $\omega_{i,k}$，这在搜索时是极其昂贵的。我们通过三个互补的设计选择来应对这一挑战：一个消除评估期间重复 LLM 调用的离线回放环境（第 3.1 节），防止对搜索集过拟合的 beta 参数化（第 3.3 节），以及使智能体能够诊断失败模式而不是仅依赖标量结果的执行轨迹反馈（第 3.2 节）。

3.1 回放环境构建

在线评估候选控制器的核心挑战在于，每次评估都需要调用基础 LLM 按需生成推理轨迹，这在搜索时是极其昂贵的。为了解决这个问题，我们构建了一个离线回放环境，将所有 LLM 调用移至发现过程之前，使控制器评估具有确定性和廉价性。

离线数据收集。遵循 Parallel-Probe zheng2026parallel 的数据收集协议，对于每个问题 $q\in\mathcal{Q}$，我们从基础 LLM 预先收集 $N$ 个独立推理轨迹，每个轨迹被分割为 $\Delta$ 个 token 的固定长度间隔。这直接实例化了第 2 节中引入的分支前缀 $z_{i,1},z_{i,2},\ldots$ 和探测信号 $\omega_{i,1},\omega_{i,2},\ldots$，所有数据在任何发现开始之前离线存储。然后，每个控制器决策针对此预先收集的数据执行，而不是调用 LLM，使得重复的控制器评估变得负担得起。

通过离线回放进行评估。为了评估给定 $\beta$ 的每个控制器，我们在 $\mathcal{Q}_{\mathrm{search}}$ 中的每个问题上运行它：在每个状态 $s_{t}$ 它从 $\mathcal{A}(s_{t})$ 中选择一个动作并推进，直到采取 Answer 动作。因为所有分支前缀和探测信号都是离线预先收集的，每个动作都确定性地从这个存储的数据中读取，而不是调用 LLM——例如，在深度 $k$ 对分支 $i$ 的 Probe 动作只需以零生成成本检索预先收集的信号 $\omega_{i,k}$。这使得整个 $\beta$ 扫描变得负担得起，而无需任何额外的 LLM 调用。

3.2 发现循环

我们将 $\mathcal{Q}$ 划分为搜索集 $\mathcal{Q}_{\mathrm{search}}$ 和留出评估集 $\mathcal{Q}_{\mathrm{eval}}$。AutoTTS 通过多轮循环发现有效的控制器：每轮，一个探索者 LLM (Claude Code) 读取累积的历史 $\mathcal{H}$ 并通过直接编辑代码提出一个改进的控制器；然后该控制器在 $\mathcal{Q}_{\mathrm{search}}$ 上评估，结果附加到 $\mathcal{H}$。

智能体驱动的提案。探索者读取 $\mathcal{H}$——其中存储了所有先前提出的控制器实现、其准确率-成本结果和执行轨迹——并被提示分析先前提案中的问题，并提出一个新的控制器以提高准确率同时减少 token 使用（完整提示见附录 LABEL:app:prompt）。

历史设计。虽然诸如准确率和 token 使用等标量结果提供了提议控制器是否足够好的粗略信号，但它们很少揭示控制器为什么失败。为了解决这一限制，我们用控制器在回放环境中执行的完整决策轨迹来增强历史。对于每轮，我们扫描多个 beta 并记录产生的缩放曲线作为标量组件；轨迹组件则提供细粒度的行为证据，使智能体能够诊断失败模式并在下一轮提出更有针对性的控制器。这一设计与 lee2026meta 的发现一致，即细粒度的执行反馈改进了用于线束工程的智能体发现。

控制器选择。在 $R$ 轮之后，我们选择在 $\mathcal{Q}_{\mathrm{search}}$ 上达到最高准确率的控制器和 $\beta$ 值。

3.3 用于可处理搜索的 Beta 参数化

在我们的初步实验中，我们经验性地发现智能体倾向于提出具有大量超参数（多达 10 个）的 TTS 控制器。在只有五个发现轮次的情况下，导航这个高维空间会导致智能体坍缩到极端解决方案——例如过于激进的修剪阈值——这些解决方案碰巧在搜索集上最小化了 token 成本，但不能代表稳健的分配策略。

为了缓解这个问题，我们提出了 beta 参数化：每个控制器必须只暴露一个超参数 $\beta$ 并实现一个从 $\beta$ 到所有内部超参数的映射函数。我们进一步要求此映射是单调的，使得更大的 $\beta$ 对应于更大的 token 预算。这将搜索空间坍缩为一维扫描，并防止智能体发现尖锐的、特定于搜索集的阈值。值得注意的是，映射函数是由编码智能体直接生成的。

4 实验设置

实验方案。所有实验均使用离线回放环境，每个环境由四个 Qwen3 模型（0.6B、1.7B、4B、8B）yang2025qwen3 中的特定（模型，基准）对构建。遵循 Parallel-Probe zheng2026parallel，我们在温度为 0.7 的情况下为每个（模型，问题）对预采样 128 个推理轨迹，探测间隔为 500 个 token，以构建回放矩阵。为了减少方差，每个控制器通过从 128 个预采样池中随机采样子集独立评估 64 次，并对结果取平均。对于发现，我们使用 AIME24 作为 $\mathcal{Q}_{\text{search}}$，并将 $\mathcal{E}_{\text{search}}$ 构建为所有四个模型上 AIME24 环境的联合。发现循环以 Claude Code 作为智能体运行五轮，最终控制器被选择为在 $\mathcal{E}_{\text{search}}$ 上达到最高准确率的控制器。发现的控制器（附录 LABEL:app:controller）是固定的，并在 AIME25 和 HMMT25 的留出环境上进行评估，这些环境在发现或选择期间从未使用过。

基线。为了证明我们提出的发现框架的有效性，我们将发现的算法与几种代表性的手工设计测试时扩展方法进行了比较。1) Self-Consistency (SC@64) wang2022self：一种普通的并行推理方法，首先采样 64 个推理轨迹并进行多数投票以获得最终答案；2) ASC aggarwal2023let：一种并行采样方法，逐个采样轨迹并在达到预定义阈值时停止。我们遵循阈值为 0.95 的原始设置；3) ESC li2024escape：一种基于块的混合方法，并行生成轨迹并在滑动窗口内检测到答案稳定性时提前终止。我们使用块大小 8；4) Parallel-Probe zheng2026parallel：一种最近的高效并行推理方法，利用跨分支信息动态决定何时停止推理、修剪无望的分支或继续计算。
