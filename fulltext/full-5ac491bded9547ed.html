摘要

扩散大语言模型可以并行生成多个 token，但通常需要许多轮解码才能完成一个回复。高效生成不仅取决于哪些 token 容易预测，还取决于提交它们如何帮助预测剩余位置。一个高度可预测的 token 可能提供很少有用的上下文，而揭示一个不太可预测的 token 可以帮助其他若干位置更早变得可预测。我们提出 dSpark，一个新的基于调度蒸馏的框架，用于学习何时提交 token 以实现更快的扩散语言生成。为此，我们构建解掩码调度，优先考虑那些揭示后能使其他位置更容易预测的 token，从而在解码早期降低不确定性。然后我们将这些调度蒸馏到模型中，以实现更快的并行采样，并使用 KL 散度正则化器帮助保持生成质量。我们在数学推理和代码生成任务上广泛评估了该方法。在 GSM8K 上，我们的方法在 LLaDA-8B-Instruct 和 Dream-7B-Instruct 上分别相对于各基线实现了 10.12 倍和 5.12 倍的显著加速，同时保持优越的任务性能。代码可在 https://github.com/VILA-Lab/dSpark 获取。

1 引言

大语言模型（LLM）在自然语言理解与推理方面取得了显著能力，但高效推理仍是一个根本性挑战。大多数 LLM 采用自回归（AR）范式，在所有先前 token 的条件下逐个生成 token。这种严格的从左到右依赖性限制了解码并行性：生成 L 个 token 通常需要 L 个顺序步骤。扩散大语言模型通过迭代去噪生成序列，提供了有吸引力的替代方案。dLLM 从部分或完全掩码的序列出发，并行预测多个掩码位置，并在一系列去噪轮次中逐步提交它们。LLaDA 和 Dream 等最新模型证明该范式可获得强大的语言建模、推理和编码能力，同时实现灵活的生成顺序和更大的并行解码潜力。然而，实现这一潜力需要减少将掩码序列转化为完整回复所需的多次迭代模型评估。

控制 dLLM 推理效率的核心因素是解掩码调度：每个解码轮次应提交哪些 token 位置，哪些应保持掩码以供后续细化。给定所有掩码位置的预测分布，解码器可在每次迭代中揭示一个 token、固定数量的 token 或动态选择的子集。提交更多位置会增加并行性并减少解码轮次，但过于激进的提交可能引入不可逆错误，污染用于预测其他 token 的上下文。相反，保守的调度保持生成质量，但牺牲了并行预测的大部分计算优势。现有解码策略因此通常依赖预测置信度，例如提交最大 token 概率最高的位置，其直觉是高置信度预测更安全。虽然作为简单启发式方法有效，但该策略主要根据每个掩码位置的当前局部可预测性处理它，并未显式建模揭示它将如何改变后续预测的难度。

我们认为，可预测性与效用之间的区别对高效扩散语言生成至关重要。最容易预测的 token 不一定是最值得提交的 token。考虑两个掩码位置 i 和 j。位置 i 可能已具有极其尖锐的预测分布，但揭示它可能几乎不增加关于序列其余部分的信息。相反，位置 j 可能适度地更不确定，但编码了关键的语义、语法或推理决策——一旦 j 被揭示，其他若干位置的不确定性可能大幅降低。这在数学推理和代码合成等结构化生成任务中尤为重要，因为中间决策会在下游 token 之间引起强依赖。仅基于瞬时置信度的调度可能将早期提交花费在安全但信息冗余的 token 上，而有影响力的位置则多轮未解决。因此，有效的解码问题不仅是"现在能预测哪些 token"，而是"现在应提交哪些 token，使剩余序列变得更容易预测"。

基于这一观察，我们提出 dSpark，一个通过调度蒸馏学习扩散语言生成中何时提交 token 的新框架。核心思想是根据每个提交的下游效应而非仅其置信度来构建信息丰富的解掩码调度。我们通过揭示候选 token 在多大程度上帮助降低剩余位置的预测不确定性来评估候选提交。揭示后能使多个未解决位置更容易确定的 token 被优先提前，使有用上下文更快传播。解码因此可视为上下文构建过程：每个提交的 token 不仅解决一个位置，还修改所有剩余位置的预测问题。通过考虑这种效应，我们的调度偏好具有高未来预测价值的提交，产生比传统置信度驱动调度更快降低序列级不确定性的轨迹，从而在每次昂贵的模型评估中取得更有用的进展。

然而，仅构建更好的调度可能在推理期间重复复杂 token 选择时增加计算量。因此我们进一步将这些调度诱导的行为蒸馏到模型本身。构建的调度提供训练轨迹，使模型接触到信息丰富的 token 被早期揭示、剩余预测逐步简化的提交顺序。蒸馏后，模型可在高效并行采样下利用这些学到的依赖关系，而无需在每个解码步骤对候选调度进行昂贵搜索。重要的是，激进优化快速提交可能改变模型的原始预测行为并降低生成质量。为此我们引入 KL 散度正则化器，使蒸馏模型在学习加速调度下运行时保持接近原始模型分布。调度蒸馏 thus 将计算从重复的推理时调度优化转移到训练中，提供了联合提升并行性并保持底层 dLLM 生成能力的实用机制。

我们在 LLaDA-8B-Instruct 和 Dream-7B-Instruct 两个代表性模型上，对数学推理和代码生成基准广泛评估了 dSpark。结果表明，学习何时提交是加速 dLLM 的一个强大但尚未充分探索的维度。在 GSM8K 上，我们的方法在 LLaDA 和 Dream 上分别实现 10.12 倍和 5.12 倍的基线加速，同时保持优越的任务性能。这表明生成效率不仅取决于并行预测多少 token，还取决于每次提交如何有效重构后续轮次的预测问题。主要贡献如下：

  • 我们指出现有扩散语言模型解码策略的关键局限：仅 token 置信度无法捕获提交的下游效用。我们证明揭示一个不太可预测但信息更丰富的 token 可降低多个剩余位置的不确定性，实现更快的整体解码。
  • 我们提出调度蒸馏，一种根据 token 提交在多大程度上简化未来预测来构建解掩码调度的新策略。我们进一步将这些信息丰富的调度蒸馏到模型中，实现高效并行解码，无需推理时昂贵的调度优化。
  • 我们在多个 dLLM 的数学推理和代码生成任务上广泛验证了方法。在 GSM8K 上，LLaDA-8B-Instruct 实现高达 10.12 倍加速，Dream-7B-Instruct 实现 5.12 倍加速，同时保持强大的生成质量。

2 相关工作

扩散语言模型。 离散扩散模型通过逆转腐蚀过程生成序列，后续工作开发了更强的语言建模目标，包括 SEDD、MDLM 和 RADD (Austin et al., 2021a; Lou et al., 2024; Sahoo et al., 2024; Ou et al., 2025)。LLaDA (Nie et al., 2025) 将掩码扩散扩展为从头训练的指令遵循语言模型，Dream (Ye et al., 2025) 用从自回归 LLM 初始化的模型展示了强大的推理和编码性能。其他工作将块内扩散与跨块生成结合，或通过自回归模型转换进一步扩展扩散模型 (Arriola et al., 2025; Bie et al., 2025; Zhu et al., 2026)。这些进展建立了强大的扩散骨干，但其迭代生成过程在推理效率上仍有很大改进空间。

高效扩散语言解码。 现有方法降低解码成本或步数。Fast-dLLM (Wu et al., 2026b)、dKV-Cache (Ma et al., 2025a)、Elastic-Cache (Nguyen-Tri et al., 2026) 和 dInfer (Ma et al., 2025b) 改进缓存复用和推理执行，D2F (Wang et al., 2026) 和 Fast-dLLM v2 (Wu et al., 2026a) 使用基于块的生成支持高效并行解码。其他方法将生成蒸馏到更少步骤或启用更激进的 token 更新 (Deschenaux and Gulcehre, 2025; Sahoo et al., 2025; Chen et al., 2026a)。与本文最接近的是，dParallel (Chen et al., 2026b) 使用确定性强制蒸馏使 token 更早就绪，d3LLM (Qian et al., 2026) 蒸馏伪轨迹并应用多块解码。LEAP (Zhang et al., 2026) 和 Ripple-Pivot Search (Ye et al., 2026) 等免训练方法使用前瞻识别值得早期提交的 token。

3 预备知识

3.1 掩码扩散语言模型

掩码扩散语言模型（MDLM）通过学习从部分掩码序列恢复 token 来生成文本 (Austin et al., 2021a)。对干净序列 $x_{0}\in\mathcal{V}^{L}$，线性前向过程以概率 $t$ 独立地将每个 token 替换为吸收态 $\mathtt{MASK}$：

$$q_{t\mid 0}(x_{t}\mid x_{0})=\prod_{i=1}^{L}q_{t\mid 0}(x_{t}^{i}\mid x_{0}^{i})=\prod_{i=1}^{L}\operatorname{Cat}!\left(x_{t}^{i};\,(1-t)\delta_{x_{0}^{i}}+t\delta_{\mathtt{MASK}}\right), \tag{1}$$

其中 $\mathcal{V}$ 为 token 词汇表，$\mathtt{MASK}\notin\mathcal{V}$，$\operatorname{Cat}$ 为分类分布，$\delta_{v}$ 为 $v$ 处的点质量。噪声水平 $t\in[0,1]$ 在干净序列与完全掩码之间插值。双向去噪器 $p_{\theta}(x_{0}^{i}\mid x_{t})$ 通过重加权交叉熵目标训练重建掩码 token (Sahoo et al., 2024; Lou et al., 2024)：

$$\mathcal{L}{\mathrm{MDM}}(\theta;x{0})=\int_{0}^{1}\frac{1}{t}\,\mathbb{E}{q{t\mid 0}(x_{t}\mid x_{0})}\left[\sum_{i:\,x_{t}^{i}=\mathtt{MASK}}-\log p_{\theta}(x_{0}^{i}\mid x_{t})\right]\mathrm{d}t. \tag{2}$$

该表述是 LLaDA (Nie et al., 2025) 和 Dream-7B (Ye et al., 2025) 等大规模扩散语言模型的基础，它们在迭代生成中并行预测掩码 token。

3.2 并行解码与解掩码调度

给定固定提示，解码从完全掩码的回复开始。令 $s_{r}$ 为第 $r$ 轮部分解码序列，$\mathcal{M}{r}$ 为有资格提交的掩码回复位置（如活动块或窗口内的位置）。前向传播为每个 $j\in\mathcal{M}{r}$ 计算 $p_{\theta}(\cdot\mid s_{r},j)$。解码器选择非空集合 $S_{r}\subseteq\mathcal{M}_{r}$，例如使用置信度阈值 (Nie et al., 2025) 或预测熵预算 (Ben-Hamu et al., 2025)。在贪婪 token 分配下，序列更新为：

$$s_{r+1}^{j}=\begin{cases}\operatorname*{arg\,max}{v\in\mathcal{V}}p{\theta}(v\mid s_{r},j),&j\in S_{r},\ s_{r}^{j},&j\notin S_{r}.\end{cases} \tag{3}$$

解掩码调度 $\pi=(S_{0},\ldots,S_{T-1})$ 指定每轮揭示哪些位置。

4 方法论

4.1 动机

token 揭示顺序会影响 dLLM 完成回复的速度。每次揭示为剩余位置提供上下文，但某些 token 帮助更大。我们用冻结的基础模型 $p_{\theta_{0}}$ 在正确回复 $y$ 上测量。在部分解码状态 $s$ 中，模型对掩码位置 $j$ 处目标 token 的不确定性为其惊异度 $h_{j}(s)=-\log p_{\theta_{0}}(y_{j}\mid s,j)$。图 1(a) 和 1(b) 表明，揭示不太可预测的目标 token（较大的 $h_{i}$）可降低其他位置的不确定性，并使更多预测匹配正确回复。当模型最可能的 token 匹配真值时，我们称该位置就绪。揭示一个不确定 token 比揭示一个自信 token 使其他位置就绪的数量多 5.1 倍（图 1(b)），并使其惊异度多降低 4.7 倍（图 1(a)）。因此，有用的调度应考虑每个 token 如何帮助预测剩余位置，以及模型对该 token 的置信度。

高效解码不仅关注揭示消除了多少不确定性，还关注多早消除。遵循公式 (2) 括号内的掩码 token 惊异度之和，我们定义剩余参考不确定性及其累积面积为：

$$H(s_{r};y)=\sum_{j\in\mathcal{M}{r}}h{j}(s_{r}),\qquad\mathcal{A}(\pi;y)=\sum_{r=0}^{T-1}H(s_{r};y). \tag{4}$$

面积累加了模型在每个解码轮次的剩余不确定性。若早期揭示某 token 使其他 token 更易预测，它们在后续轮次的不确定性更低，总面积更小。两个调度可产生相同回复但面积不同。图 2(a) 说明了这一点：自然调度下剩余不确定性在下降前多轮保持高位，而提升有助于其他位置的 token 使其更早下降并将整条曲线左移，从 $\mathcal{A}$ 中移除阴影区域。由于回复固定，该增益仅来自揭示顺序。更小的面积也意味着更快完成。自然调度下面积较大的回复往往需要更多前向传播（图 1(c)），优化调度以更少轮次完成验证回复，从不需要更长时间，且在需要最多轮次的回复上获益最大（图 2(b)）。我们的方法从自然调度出发，搜索早期揭示有助于其他位置更早就绪的 token。

4.2 不确定性引导的调度构建

公式 (4) 的不确定面积目标激励在轨迹早期揭示使剩余位置更易预测的 token。图 3 概述了我们的框架。给定正确回复 $y$，我们用冻结模型 $p_{\theta_{0}}$ 离线构建其解掩码轨迹。回复保持固定，仅改变 token 揭示顺序。每轮我们通过候选揭示在多大程度上降低其他掩码位置的不确定性来比较它们（如图 3 右侧所示）。这给出了基于 token 提供上下文的局部选择规则，而非仅基于该 token 已有的可预测性。

第 $r$ 轮，我们在状态 $s_{r}$ 的掩码位置 $\mathcal{M}_{r}$ 中考虑合理的目标 token：

$$\mathcal{C}{r}=\left{i\in\mathcal{M}{r}\;\middle|\;p_{\theta_{0}}(y_{i}\mid s_{r},i)\geq p_{\min},\quad\operatorname{rank}{\theta{0}}(y_{i}\mid s_{r},i)\leq k\right}. \tag{5}$$

其中 $p_{\min}$ 为最小目标 token 概率，$k$ 为词汇表 token 中允许的最大排名。对每个候选 $i$，令 $s_{r}^{(i)}$ 为揭示 $y_{i}$ 且其他位置不变的 $s_{r}$。使用每位置惊异度 $h_{j}(s)=-\log p_{\theta_{0}}(y_{j}\mid s,j)$，我们选择最降低其他位置不确定性的候选：

$$i_{r}^{}\in\operatorname{arg\,max}{i\in\mathcal{C}{r}}\sum_{j\in\mathcal{M}{r}\setminus{i}}\left[h{j}(s_{r})-h_{j}(s_{r}^{(i)})\right]. \tag{6}$$

该分数衡量其他掩码位置的不确定性降低，排除被揭示位置 $i$ 本身。我们提升具有最大正分数的候选；若无候选具有正分数则跳过提升。重复这些步骤直到回复完全揭示，产生 $\tau^{}(y)=(s_{0}^{},\ldots,s_{T}^{})$，其中 $s_{r}^{}$ 为 $r$ 轮后的状态。该优化轨迹如图 3 左侧所示。我们将其中间状态 $s_{r}^{*}$ 与正确回复 $y$ 配对，训练学生 $p_{\theta}$ 预测剩余掩码 token。

4.3 调度蒸馏

我们在优化轨迹 $\tau^{}(y)$ 的中间状态 $s_{r}^{}$ 上训练学生。正确回复提供 token 目标，调度确定每个训练样本中哪些 token 可见。因此，学生学习从信息丰富位置被更早揭示的上下文中预测剩余 token。

令 $\mathcal{D}{+}$ 为从 $\tau^{}(y)$ 采样的正确回复 $y$ 和状态 $s_{r}^{}$ 的分布。我们将交叉熵监督与置信度锐化结合。在每个状态 $s{r}^{*}$，$\mathcal{M}{r}$ 包含有资格的掩码位置，$\mathcal{R}{r}\subseteq\mathcal{M}{r}$ 包含学生最可能 token 匹配目标 token $y{j}$ 的位置。正轨迹目标为：

$$\mathcal{L}{+}(\theta)=\mathbb{E}{(s^{}{r},y)\sim\mathcal{D}{+}}\left[\ell_{\mathrm{CE}}(s_{r}^{},y)+\ell_{\mathrm{sharp}}(s_{r}^{*},y)\right], \tag{7}$$

其中 $\ell_{\mathrm{CE}}$ 使用 $\mathcal{M}{r}$ 上平均的交叉熵训练学生重建正确回复 $y$ 的掩码 token。在优化轨迹的中间状态上训练鼓励学生在解码时遵循其解掩码进展。锐化项 $\ell{\mathrm{sharp}}$ 在当前正确的位置 $j\in\mathcal{R}{r}$ 上平均预测熵 $\mathcal{H}(p{\theta}(\cdot\mid s_{r}^{*},j))$，其中 $\mathcal{H}(q)=-\sum_{v\in\mathcal{V}}q(v)\log q(v)$。最小化该项增强对正确预测的信心，支持解码期间的早期提交。

然而，锐化项本身无法区分对错。它仅应用于学生在构建轨迹上已正确的位置，但其更新的参数是共享的，因此增加的置信度会延续到学生在不成功生成路径上达到的状态。在这些状态上，更多置信度只会造成损害，因此学生必须保持基础模型的行为。为此我们保留失败轨迹用于选择性 KL 正则化。回复级失败无法识别哪些单个 token 错误，因此我们使用冻结基础模型的分布作为目标而非失败回复的 token。令 $\mathcal{D}_{-}$ 为从这些轨迹采样用于锚定的状态-位置对分布。负轨迹损失为：

$$\mathcal{L}{-}(\theta)=\mathbb{E}{(s^{-},j)\sim\mathcal{D}{-}}\left[D{\mathrm{KL}}\left(p_{\theta_{0}}(\cdot\mid s^{-},j)\,|\,p_{\theta}(\cdot\mid s^{-},j)\right)\right], \tag{8}$$

其中两个模型接收相同状态 $s^{-}$，基础模型保持冻结。这种锚定限制了无法获得可靠 token 级监督处的变化，同时使构建的正确轨迹免受 KL 惩罚。完整训练目标为：

$$\mathcal{L}(\theta)=\mathcal{L}{+}(\theta)+\beta\,\mathcal{L}{-}(\theta), \tag{9}$$

其中 $\beta$ 控制正则化强度。这些目标共同鼓励更早的自信提交以实现更快并行解码，同时保持高任务准确率。

5 实验

5.1 实验设置

训练数据。 我们为每个骨干构建单独的蒸馏语料库。两个模型的轨迹均从 GSM8K (Cobbe et al., 2021)、PRM12K (Lightman et al., 2024)、NuminaMath-CoT (LI et al., 2024) 和 AceCode (Zeng et al., 2025) 生成，最大长度 256 token，块大小 32。总体上，训练数据包含 LLaDA 的 52k 正确和 38k 不正确样本，Dream 的 80k 正确和 57k 不正确样本。训练时使用所有正确轨迹并将不正确轨迹子采样至 4:1 比例，得到 LLaDA 的 52k 正确和 13k 不正确轨迹，Dream 的 80k 正确和 20k 不正确轨迹。

实现细节。 实验使用 LLaDA-Instruct (Nie et al., 2025) 和 Dream-Instruct (Ye et al., 2025) 模型，采用 LoRA (Hu et al., 2021) 微调。我们使用类似 d3LLM (Qian et al., 2026) 的多块解码策略。公式 (5) 中目标 token 集合使用 $p_{min}=0.02$ 和 $k=10$。公式 (9) 中设 $\beta=1$。训练配置和硬件细节见附录。

评估细节。 评估涵盖 GSM8K（0-shot）(Cobbe et al., 2021) 和 MATH（4-shot）(Hendrycks et al., 2021) 的数学推理，以及 HumanEval（0-shot）(Chen et al., 2021) 和 MBPP（3-shot）(Austin et al., 2021b) 的代码生成。报告数学准确率、代码 pass@1，以及每次前向传播 token 数（TPF）和并行度下准确率（AUP）(Qian et al., 2026)。结果为三次独立评估的平均。使用 lm-eval-harness (Gao et al., 2024)。

基线。 与竞争性 dLLM 基线比较，包括原始 LLaDA (Nie et al., 2025) 和 Dream (Ye et al., 2025) 模型、免训练的 Fast-dLLM (Wu et al., 2026b)，以及为更快解码微调模型的方法：dParallel (Chen et al., 2026b)、d3LLM (Qian et al., 2026) 和 D2F (Wang et al., 2026)。

6 结论

本文从何时提交预测 token 的角度研究扩散大语言模型的高效解码。我们证明仅 token 置信度不足以进行有效调度，因为某些不太可预测的 token 可为解决剩余序列提供更有用的上下文。我们提出了由调度蒸馏实现的 dSpark，基于 token 提交的下游效用构建信息丰富的解掩码调度，并将这些调度蒸馏到模型中以实现高效并行推理。数学推理和代码生成实验显示显著加速，包括 GSM8K 上 LLaDA-8B-Instruct 和 Dream-7B-Instruct 分别实现 10.12 倍和 5.12 倍加速，同时保持强大任务性能。结果强调了解掩码调度作为扩散语言建模的重要可学习组件，并表明更好的提交策略可大幅缩小 dLLM 理论并行性与实际效率之间的差距。

伦理声明

本工作专注于提高扩散大语言模型的推理效率，不涉及人类受试者或敏感个人数据的收集。我们的方法不会引入超出底层预训练模型能力的新模型能力，因此继承其现有局限和潜在风险，包括有偏见、有害或不准确的生成。通过减少推理所需解码步骤数，所提方法还可帮助降低计算成本和能耗。

可复现性声明

我们在主论文和补充材料中提供了所提方法、训练目标、解码程序、实验设置和评估协议的详细描述，并发布实现代码和相关配置以促进可复现性。

C 评估细节

dSpark 的解码。 我们使用多块解码策略 (Qian et al., 2026)，置信度阈值 0.90 至 0.95 (Wu et al., 2026b)，可并行解码当前块和下一块。所有模型贪婪解码，最多 256 个新 token，块大小 32。最后一个活动块解码 50% 后新块进入窗口，其前驱解码 50% 后变为完全活动。主要结果不使用 KV 缓存。

指标。 每次前向传播 token 数（TPF）为基准上求和的生成 token 数（不含序列结束填充）除以前向传播次数。并行度下准确率（AUP）(Qian et al., 2026) 对并行性上的准确率积分。对按 TPF ρ 排序的点 $(\rho_{1},y_{1}),\ldots,(\rho_{n},y_{n})$（准确率为 $y$，仅保留 $y_{i}\geq y_{1}-5$ 的点）：

$$\mathrm{AUP}=\rho_{1}y_{1}+\sum_{i=2}^{n}\frac{\rho_{i}-\rho_{i-1}}{2}\bigl(y_{i}W(y_{i})+y_{i-1}W(y_{i-1})\bigr),\quad W(y)=\min\left(e^{-\alpha(1-y/y_{\max})},1\right), \tag{10}$$

其中 $y_{\max}$ 为基准上任何方法的最高准确率，$\alpha=3$。每个方法贡献其每前向传播一个 token 的点（$\rho=1$）及其报告的操作点。

D.1 候选过滤器

被提升的 token 在冻结模型自行提交之前被提交，因此按构造它是模型尚未自信的 token。公式 (5) 的过滤器因此不要求置信度，仅要求参考 token 对模型合理：在该位置 $k=10$ 个最可能 token 中，概率至少 $p_{\min}=0.02$，即惊异度最多约 4 nats，即图 1 显示的范围。两个界限互补：模型分布平坦时许多 token 超过 2%，排名界限起作用；分布尖锐时第十排名 token 概率可忽略，概率界限起作用。

为什么不用更严格的过滤器。 最有助于其他位置的 token 很少是自信的。如图 1 所示，揭示不确定 token（$p_{\theta_{0}}<0.5$）比揭示自信 token 使其他位置就绪多 5.1 倍，惊异度多降低 4.7 倍。要求置信度的过滤器会排除最有用的提升。提升这些低概率 token 也不损失准确率（表 10）。

为什么不用更宽松的过滤器。 低于这些界限时，模型实际上已在当前上下文下排除了参考 token。提升这种 token 会使调度依赖已知验证答案而非模型自身不确定性，并训练学生提交其上下文不支持的 token。这些界限还保持搜索规模小，因为公式 (6) 中每个候选用其自己的前向传播评分。我们从这些考虑设置 $p_{\min}$ 和 $k$，未在端到端训练中调整。
