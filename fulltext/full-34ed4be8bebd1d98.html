摘要
多教师在线策略蒸馏（M-OPD）已成为一种极具前景的范式，它通过密集的 token 级奖励监督，将领域专用的强化学习（RL）专家整合到一个单一的全才学生模型中。尽管在实践中取得了成功，但控制多教师能力整合的优化动力学仍不甚明了，且 conspicuously 缺乏开放、可严格复现的方案。在这项工作中，我们在 SmolLM3-3B-Base 上建立了一个带有预言机路由的受控 M-OPD 基准，将能力整合与路由歧义隔离开来。我们的调查揭示了一个显著的“能力整合鸿沟”：标准的 M-OPD 仅恢复了从混合域 SFT 到 RouteRL 提升幅度的 35.6%。指令跟随等简短任务遭受了严重的性能下降和过早停滞。在此指标下，token 级的教师分歧似乎并不是主要的瓶颈；主要的失败原因是 token 级优化预算的严重错配。我们确定了导致这种失衡的三个可分离因素：跨域的结构性序列长度差异、跨域的不同收敛速度，以及由于在共享 rollout 的重复小批量中陈旧的学生模型更新导致的奖励陈旧。为了解决这些失衡问题，我们引入了 Open-MOPD，这是一个原则性框架，结合了 token 份额平衡、间隙感知动态预算分配和学生奖励刷新。这些机制共同系统地恢复了跨域平衡，在一个学生模型中将从混合域 SFT 到 RouteRL 的提升恢复率从 35.6% 提高到了 83.4%。我们在 8×A100-80GB 学术设置上完全开源了我们的端到端后训练方案、训练轨迹和评估套件。

1 引言
强化学习（RL）已成为大语言模型（LLM）后训练的基础支柱，擅长在特定领域的模型中培养专门能力[32, 48]。然而，在实际应用中部署多个专用模型在计算上往往是不可行的，这创造了对一个能够保留这些不同优势的单一统一模型的强烈需求。为了将多个专家整合到一个学生模型中，多教师在线策略蒸馏（M-OPD）作为一种有吸引力的范式应运而生；每个输入提示被路由到相应的领域专家，该专家对学生策略生成的轨迹提供密集的每 token 奖励监督[24, 27, 4]。尽管多教师蒸馏在工业流水线中的应用日益广泛，但控制多域能力整合的基本机制仍然知之甚少，且研究界仍然缺乏一个开放且可严格复现的方案。
为了分离和检查多教师整合的核心动力学，我们构建了一个从 SmolLM3-3B-Base 初始化的完全受控的 M-OPD 实验框架。该流水线包含三域混合 SFT 初始化、三个领域专家 RL 教师（涵盖数学、编程和通用指令跟随），以及基于真实域标签的预言机路由。使用真实域标签，我们将能力整合与路由错误隔离开来。这种设计在平衡两个标准的参数规模上运行（第 2.2 节），整个流水线和消融阶梯可在 8×A100-80GB 学术设置上复现，同时模型仍具备长程推理能力。
图 1：整合鸿沟是真实存在且高度不对称的。 Naive M-OPD 和 RouteOPD 的每域宏观平均值，每个柱状图上方的数字表示该域的差距； Naive M-OPD 的每域验证轨迹，虚线表示相应域的 RouteOPD 参考； 相对于 RouteRL 恢复的理论空间，(current−π_mixsft)/(RouteRL−π_mixsft)。指令跟随（IF）表现出最大的绝对差距和最低的恢复空间，并且是最早停止改进的领域。
我们的实证调查表明，完美的路由远不足以成功实现能力整合。在标准化的六项基准评估协议下，naive M-OPD 的平均得分为 28.05，而单独在每个域上进行蒸馏的得分为 31.55。我们使用 RouteOPD 来衡量部署时的整合鸿沟。特别是，简短的指令跟随（IF）任务比其 RouteOPD 参考低 6.16 分（是数学领域性能下降的 3.3 倍），并且在训练中最早进入平台期。
通过系统的逐域测量，我们将此整合鸿沟定位于是 token 级优化预算的未管理分配，而不是灾难性的梯度冲突（第 3 节）。因为在线策略蒸馏目标聚合了跨 token 的损失值，每个域实际接收的优化份额是由其梯度 token 体积而非其提示频率决定的。因此，尽管获得了平衡的提示分配，简短的 IF 响应在梯度 token 中所占比例微乎其微，占输入提示的 20.3%，但仅占梯度 token 的 0.99%。此外，即使原始 token 预算最初是相等的，它也会在几十步内发生漂移，因为随着学生以不同的速度向不同的教师收敛，监督奖励信号以不均匀的速度衰减。这种失衡因标准的多步 rollout 重用而加剧，这使得依赖于学生的奖励组件在连续的梯度更新中保持陈旧。
为了解决这些正交的失败模式，我们引入了 Open-MOPD，这是一个原则性框架，用专门的机制针对每种失真（第 4 节）。首先，token 份额平衡将梯度预算分配与序列长度解耦，建立加权 token 份额目标，而不是固定的每批次配额。其次，间隙感知分配动态地将优化预算引向具有最大剩余学生-教师差距的领域。这防止了在第 74 步观察到的 naive 奖励归一化导致的训练崩溃，在该步骤中，预算被浪费性地引入已经收敛的领域。第三，学生奖励缓存在每个梯度步之前重新计算学生的对数概率，同时缓存教师状态，以可忽略的开销消除了样本陈旧性[17]。在累积消融实验中，Open-MOPD 在一个学生模型中将恢复率从 35.6% 提高到了 83.4%。
我们的主要贡献总结如下。
• 实证诊断。使用一个将整合动力学与路由错误隔离的预言机路由测试平台，我们识别并表征了多教师在线策略蒸馏中的“能力整合鸿沟”，揭示了简短任务中显著的跨域性能不对称和过早停滞（第 3 节）。
• 机制分解。在我们的指标下，token 级教师分歧不太可能是主要的瓶颈。我们转而确定了导致 token 级优化预算失真的三个可分离因素：序列长度差异、不同的收敛速度，以及由于在共享 rollout 的重复小批量中陈旧的学生更新导致的奖励陈旧（第 4 节）。
• 原则性方法论。我们提出了 Open-MOPD，一个结合了 token 份额平衡、间隙感知动态预算分配和学生奖励刷新的优化框架，它解决了域间失衡，并在一个学生模型中恢复了大部分可用空间（第 4 节，第 5 节）。
• 开源方案。我们在可复现的学术计算预算上完全开源了我们的端到端后训练流水线、模型检查点和评估套件（附录 8）。
2 Open-MOPD：多教师能力整合的开放方案
我们的目标是将几个领域专家的能力整合到一个统一的学生模型中。设域集合为 𝒟。在我们的基础模型上，𝒟={math, code, instruction_following (IF)}。每个域都有一个用强化学习训练的专家教师 π_ϕ_d，学生模型为 π_θ。每个训练样本携带一个域标签 d(x)，允许单个学生模型在三个不同任务（数学、代码生成和指令跟随）上接收来自相应领域专家的监督信号。在训练框架固定的前提下，Open-MOPD 旨在找到一种方案，能够稳定地将所有三个专家的能力转移到一个学生模型中。
2.1 多教师在线策略蒸馏目标
对于提示 x，学生首先从当前策略 π_θ(·∣x) 中采样一个响应 y。教师通过单次 prefill 传递评估学生的 rollout，以生成教师分布。将路由的教师写为 π_ϕ_{d(x)}。在位置 t，我们取学生分布的 top-k token 集 𝒮_t = TopK_k(π_θ(·∣x, y_{<t})), (1)，默认 k=16。对于每个 v ∈ 𝒮_t，我们首先定义教师-学生对数概率差 δ_t(v) = sg[log π_ϕ_{d(x)}(v∣x, y_{<t}) - log π_θ(v∣x, y_{log π_θ(u∣x, y_{<t}), (3)，并且 𝒮_t 之外的 token 贡献为零。位置级奖励为 r_t = Σ_{v∈𝒮_t} r_t(v). (4)。在没有 critic 的情况下，r_t 被直接放入 PPO 的优势槽中。直观上，δ_t(v) > 0 意味着教师比学生给 token v 分配更高的概率；π̃_θ 仅决定 top-k 内每个 token 对位置级奖励 r_t 的贡献份额。 因为学生生成每个响应，所以监督分布遵循学生的当前策略。这是在线策略蒸馏与在离线教师轨迹上进行监督微调之间的关键区别，后者的固定数据分布会产生分布偏移。因此，第 3 节从这个最小版本开始，它不添加进一步的训练机制，并保持后续更改的效果更容易识别。 2.2 基础模型选择 开放方案使用 SmolLM3-3B-Base 作为其基础模型。它是一个完全开放的 3B 仅解码器模型，其预训练涵盖网络、数学和代码数据，并在 64K 上下文下进行训练[13]。这种选择平衡了计算成本与运行完整方案和重复其消融实验的可行性。 实验可行性。多教师 OPD 需要同时进行学生生成、一个或多个教师前向传递、长响应训练和逐域验证；完全复现还包括混合域 SFT、三个域 RL 教师和最终的多教师蒸馏。如果基础模型从 7B 或更大开始，那么在普通学术团队可以反复进行消融的预算内，该链条将很难闭合：单次实验占用的 GPU 小时数增加，而机制比较所需的重复运行将变得无法承受。因此，Open-MOPD 将“可在单个 8×A100-80GB 节点上运行”作为方案约束，以便在有限的计算资源下可以重复执行端到端流水线和机制消融。 模型容量。基础模型还必须有足够的容量。太小的模型会让响应长度限制在长链监督进入可用轨迹之前将其截断；对于失败的实验，很难确定失败是由算法或训练配置引起的，还是由模型在响应长度限制内发现和学习解决方案的能力有限引起的。我们之前在使用较小的 Qwen3-1.7B-Base 作为基础模型时观察到了这种失败模式：在相同的 OpenR1-Math-93k 上进行五个 epoch 的 SFT，其最佳 4.1 Token 份额平衡
Token 份额平衡为每个域的 token 均值损失分配一个固定权重。设 g_d^ 为目标域预算，其中 Σ_d g_d^ = 1。在每个批次中，我们从注意力掩码计算 s_d^tok，并将域 d 的损失加权为 w_d^share = g_d^ / s_d^tok. (8)。
在此加权后，域 d 的有效份额为 w_d^share s_d^tok / Σ_j w_j^share s_j^tok = g_d^。
这直接控制了损失中的实际 token 比率，而无需依赖稳定的响应长度或过采样短答案。
主要方案使用等份额目标 g^ = (1/3, 1/3, 1/3)，这不需要针对特定语料库进行调优。在图 3 所示的 token 份额上，它产生的权重为数学 0.69，代码 0.66，IF 为 32.7。每个 IF token 被放大约 48 倍，以补偿其 25 倍的长度劣势，而等式 8 保证三个域的加权份额恰好为 33.33%。与仅更改提示采样率相比，token 份额平衡保留了数学和代码提示的多样性，同时为较短的 IF 响应提供了有意义的训练贡献。
Token 份额平衡通过 token 权重改变了每个域对损失的贡献程度；它不更改单个 token 的采样频率或奖励幅度。我们故意保留这种设计，因为奖励的大小显示了教师和学生之间的差距，简单地对其进行归一化将消除关于学习进度的有用信息。
4.2 间隙跟随分配
设 m_d 为域 d 的运行每 token 奖励幅度（例如 |r| 的指数移动平均），它作为剩余师生差距的可观察代理。
一个简单的想法是用 m_d^{-α} 对损失进行归一化，给奖励较小的域赋予更大的权重。这在训练早期似乎合理，因为小奖励可能表明一个域学习缓慢。然而，m_d 也跟踪剩余的蒸馏差距：当一个域接近其教师时，其 m_d 变小。因此，逆归一化将更多预算分配给已经取得更多进展的域。
这形成了一个不稳定的反馈循环。随着一个域收敛，其 m_d 减小，这反过来增加了其分配的权重 m_d^{-α}。然后该域接收到更多的训练预算，加速其收敛并进一步缩小 m_d。没有任何平衡力，权重不断发散并最终导致训练崩溃。我们在实验中直接观察到这种模式：在前 75 步中，IF 的 m_d 减小了 35.3 倍。设置 α=0.5 导致 IF 权重从 26.7 上升到 90.7，而代码权重从 0.44 下降到 0.27。因此，我们认为当 α 为正且不太小时，逆规则是不稳定的。
间隙跟随分配保留差距的方向，将其解释为“尚未蒸馏的能力”，并将预算分配给仍有较大差距的域。
w̃d = w_d^share · Clamp((m_d / m_ref)^α, 0.05, 20), w_d^gap = w̃_d / Σ_j w̃_j s_j^tok, (9)
这里 w̃_d 是最终归一化之前的未归一化权重。它将上一节中的 token 份额权重 w_d^share 与一个裁剪的间隙因子结合。参考值 m_ref 是当前批次中跨域的 m_d 的平均值。因此，(m_d / m_ref)^α 衡量域 d 相对于其他域的奖励幅度。我们将此因子裁剪到 [0.05, 20]，以便一个域奖励的突然变化不会使其训练权重太小或太大。除数 Σ_j w̃_j s_j^tok 是权重的 token 份额加权平均值，因此归一化后 Σ_d w_d^gap s_d^tok = 1，且批次的总损失规模保持不变。因此，当一个域接近其教师时，其 m_d 和预算一起下降，而具有较大师生差距的域接收到更多更新。因此，此分配规则跟随剩余差距，而不是对奖励幅度进行归一化；第 5.2 节显示了它在 token 份额平衡之上的好处以及当 α 取负号时发生的崩溃。
4.3 奖励刷新
前两个机制处理域之间的预算；奖励刷新处理一个 rollout 内的时间不一致性。
我们的设计借鉴了 AsyncOPD [17] 的见解：当学生发生变化时，反向 KL 信号中依赖于学生的部分应该用当前学生重新计算。我们通过在同步多教师流水线中的 K 次内部更新中的每一次之前刷新依赖于学生的奖励，将此见解应用于不同的陈旧源。学生在一个 rollout 批次内更新 K 次，而 rollout 轨迹来自这些更新之前的学生。这在奖励中造成了不匹配，奖励刷新纠正了这一点。假设一个 rollout 用于 K 个更新小批量。教师只需要一次 prefill 来计算 log π_ϕ{d(x)}(v∣x, y_{<t})，而学生概率在每次更新后重新计算。
在第 k 次内部更新的 actor 前向中，奖励刷新在相同的集合 𝒮_t 上重新计算依赖于学生的项。
δ_t^{(k)}(v) = sg[log π_ϕ_{d(x)}(v∣x, y_{<t}) - log π_θ^{(k)}(v∣x, y_{<t})], (10)

5.2 间隙跟随分配
我们在 token 份额平衡的基础上添加间隙跟随分配。与保持每个域在 1/3 左右的静态平衡不同，间隙跟随分配随着训练的进行动态更改域比率（图 7a）。在此设置中，预算流向具有最大师生差距 m̄_d 的域。在基线轨迹中间窗口计算的平均值显示，代码的 m̄_d 为 0.028，数学为 0.008，IF 为 0.003（分别是平均值的 2.16 倍、0.61 倍和 0.23 倍）。从前 25 步到 200–300 步，数学份额从 15.1% 增长到 32.6%，IF 份额从 34.5% 下降到 17.1%，而代码获得了最多的预算（平均 55.4%，峰值 87.6%）。在没有奖励刷新的情况下单独测试时，此机制带来了 +0.72 分的改进（K=1 阶梯，表 4）。
反转该因子会给差距较小的域更多预算。这有利于学生已经处理得很好的域，并创建了一个正反馈循环。在我们的实验中，IF 差距缩小了 32.5 倍，其权重从 24.4 上升到 80.9，训练在第 74 步停止（图 7b）。因此，α 的符号由差距的方向固定。

5.3 奖励刷新
奖励刷新（第 4.3 节）将密集奖励中依赖于学生的部分移入每次内部更新。教师对数概率仍然在 rollout 批次顶部进行一次 prefill 并在整个过程中重用，而学生对数概率从 PPO 已经执行的 actor 前向中读取。因此，奖励刷新不增加额外的学生前向。没有刷新时，密集奖励使用在 rollout 时保存的学生概率；有刷新时，它使用来自当前内部更新的学生概率。在这两种情况下，教师项每个外部步计算一次；只有用于评估奖励的学生参数发生变化。
我们测量了奖励刷新的额外运行时和性能增益。在 K=4 时，带刷新的密集奖励计算耗时 27.3 秒，不带刷新的耗时 27.8 秒。这些值分别占一个外部步的 2.10% 和 2.12%（图 8）。完整步骤带刷新耗时 1298 秒，不带刷新耗时 1313 秒。差异很小，在步与步的变化范围内，因此奖励刷新不增加可衡量的额外运行时成本。
在 token 份额平衡和间隙跟随分配的基础上，奖励刷新在 K=4 时进一步带来了 +0.81 分（表 4）。这一增益支持了该机制的有效性，并完成了 Open-MOPD 方案。

6 相关工作
6.1 在线策略蒸馏与多教师扩展
在固定语料库上蒸馏。知识蒸馏训练学生以匹配教师的输出分布[12]。对于序列模型，教师通常提前生成响应，学生从这个固定语料库中学习[18]。因此，学生在教师产生的前缀上进行训练，而推理使用学生产生的前缀。这种分布偏移在序列预测中产生了曝光偏差问题[30, 3]。教师和学生容量的巨大差异也会使蒸馏变得困难[5, 28, 25]。
在线策略蒸馏。在线策略蒸馏（OPD）在学生自己的 rollout 上训练学生，并在学生实际访问的前缀上使用教师反馈[11, 1]。最近的工作通过更改散度、采样规则或 token 级训练信号来改进此过程[21, 20, 42, 24]。其他研究检查训练稳定性和失败模式，包括在长前缀或漂移前缀上的不可靠反馈[9]。最近的一项调查根据反馈信号、教师访问和优化规则组织了这些方法[35]。大多数现有工作仍然使用一个教师。我们的工作研究几个教师如何共享一个学生的更新。
批次重用下的陈旧性。PPO 在一个 rollout 周期内支持多个小批量更新[31]。在异步 RL 中，当 rollout 来自落后于学习器几个更新的策略时，会发生策略滞后[8, 52, 33, 44, 10, 34]。先前的工作研究 RL 系统可以容忍多少陈旧数据[50, 23]，最近的工作检查 OPD 中的陈旧性[17, 51]。在我们的同步流水线中，每个 rollout 批次被划分为 K 个小批量并用于顺序学生更新，因此随着学生的变化，依赖于学生的奖励可能变得陈旧。奖励刷新使用 PPO 现有 actor 前向中的学生概率在每次内部更新之前重新计算此项，不增加额外的学生前向。
从单教师到多教师 OPD。MOPD 通过标准的三个阶段方案将 OPD 扩展到多个领域教师：从共享 SFT 模型训练领域专家，将每个学生 rollout 路由到其领域教师，并使用 token 级教师反馈进行训练[37, 27]。此方案已在几个公开模型中使用。Nemotron-Cascade 2 蒸馏强大的中间教师以恢复在 Cascade RL 期间丢失的能力，而 Agents-A1 结合了六个领域教师并归一化跨响应和域的损失[46, 2]。在更大规模上，DeepSeek-V4 蒸馏了十多个教师，Kimi K3 使用了由领域和推理努力定义的九个教师[7, 19]。这些研究表明 MOPD 可以在不同模型规模上整合专家。Open-MOPD 研究如何在此整合过程中平衡不同域接收到的训练。
6.2 整合领域专家
训练领域专家。在单个域上进行强化学习可以为该域产生一个强大的专家。DeepSeekMath 和 DeepSeek-R1 在数学推理方面的成功为 LLM 强化学习提供了实用的方案[32, 6]。DAPO 进一步为大规模训练开发了此方案[48]。特定领域的 RL 此后扩展到软件工程、搜索和指令跟随[15, 39, 16, 29]。每个流水线产生一个专家，而部署通常需要一个能够处理所有这些域的模型。我们的工作研究如何通过多教师 OPD 将这些专家整合到一个学生中。
数据空间中的整合。结合域的一种常见方法是在混合域数据上训练一个模型。例如，Qwen3 使用通用域 RL 来改进广泛的任务[45]。另一种方法是按顺序训练域。Nemotron-Cascade 对每个域应用单独的 RL 阶段，因此每个阶段可以使用自己的数据和训练设置[38]。在联合训练中，数据混合会强烈影响最终模型。DoReMi 在预训练中研究此问题，而 MoDoMoDo 将数据混合优化扩展到多域 RLVR[41, 26]。平等的任务采样仍然不能保证平等的培训：不同的任务可以产生幅度非常不同的梯度[40]。Open-MOPD 研究不平等的响应 token 计数、不同的师生差距和过时的奖励如何在多教师 OPD 中造成跨域失衡。
权重空间和模块空间中的整合。第二条路线是在领域专家训练后将其合并。权重空间方法将特定于任务的参数更改合并到一个检查点中。Task Arithmetic 引入了此操作，TIES-Merging 解决了冲突的参数符号，而 DARE 在合并之前稀疏化模型更改[14, 43, 47]。其他方法在整合期间保留专家结构。BTM 在不同域上训练专家，并通过集成或参数平均将其组合，BTX 将其前馈层转化为路由混合专家，而 BTS 用轻量级拼接层连接冻结的专家[22, 36, 49]。这些方法在单独训练后整合专家。多教师 OPD 从它们的输出中训练一个共享学生，而 Open-MOPD 研究如何在此共享训练中平衡不同域接收到的更新。
7 结论
我们从零开始构建了一个完全开放的多教师在线策略蒸馏流水线——混合域 SFT、三个领域 RL 教师、多教师 OPD——并用它回答了一个具体问题，即当路由已经无误时，是什么阻止了三个专家的能力被同时写入同一组参数。
我们的实验确定优化预算的分配是主要瓶颈。我们确定了导致失衡的三个可分离因素：不平等的 token 计数、不平等的奖励幅度以及重复内部更新期间过时的奖励。
Open-MOPD 的三个机制——token 份额平衡、间隙跟随分配和奖励刷新——一一对应于这三个来源，并在消融实验中分别进行了验证。它们共同将整合鸿沟从 3.50 分减少到 0.31 分，而相对于 RouteRL 的恢复率从 35.6% 上升到 83.4%。
我们发布了完整的方案和机制实现，以支持可复现的后续工作。

8 构建 Open-MOPD 方案
在本节中，我们介绍如何获得最终的 Open-MOPD 方案。我们首先在数学 SFT 上筛选能够稳定产生推理轨迹的基础模型，然后将选定的基础模型扩展到涵盖数学、代码和指令跟随的混合域 SFT。
8.1 基础模型选择
1.7B 和 7B 之间的 OpenR1 数学比较。早期筛选将相同的 93,733 个 OpenR1 数学样本分别应用于 Qwen3-1.7B-Base 和 Qwen2.5-7B-Base。两次运行均使用 32,768-token 的 SFT 长度限制、128 的全局批次和 4×10^{-5} 的学习率，每个 epoch 732 步。表 6 报告了前五个 epoch 的完整曲线。
Qwen3-1.7B-Base 的问题不在于生成长度不足：在 31K 预算下，所有五个检查点中仍有 69.17–80.42% 的样本耗尽了限制，只有 20.00–31.25% 的答案闭合；增加 epoch 也不会产生单调的改进，AIME24 保持在 7.1% 以下。这意味着后续 RL 或 OPD 阶段看到的很大一部分轨迹仅包含推理前缀，从未达到最终答案。因此，任务得分的下降不能唯一地归因于奖励、路由或跨域干扰，因为基础模型和数据混合本身尚未学会可靠地结束推理轨迹。
相同的 OpenR1 数据在 Qwen2.5-7B-Base 上显示出相反的趋势：AIME24 从 16.25% 上升到 31.25%，截断率从 42.92% 下降到 12.92%。这排除了“OpenR1 轨迹本质上太长，因此任何基础模型都会被截断”的解释，并表明扩大基础模型的容量确实可以恢复轨迹闭合。因此，Qwen2.5-7B-Base 满足能力条件，但它使学生、三个 RL 教师和完整方案的每个机制消融都处于 7B 规模；对于需要反复运行的开放研究基线来说，这种成本太高。
选择 SmolLM3-3B-Base。最终方案选择 SmolLM3-3B-Base 作为两端的折衷。在三个域上进行四个 epoch 的混合域 SFT 得到 π_mixsft：OpenR1-Math-93k、从完整 OpenCodeReasoning 集合中采样的 OCR-50k 子集以及 Instruction-Nemotron 分别贡献了大约 37.3%、28.1% 和 34.6% 的训练响应 token。逐域样本计数按响应 token 计数平衡，因此 820K 个短 IF 答案不会淹没较少但较长的数学和代码轨迹。
表 5 总结了三个候选基础模型的选择证据。
从表中可以看出，3B 因此不是对“中等模型”的任意选择，而是由两个失败边界界定的操作点：下降到 1.7B，生成被未闭合的推理和截断所主导，机制归因不再唯一；上升到 7B，单模型更强，但端到端多教师方案及其重复消融超出了我们为社区基线设定的资源边界。SmolLM3-3B-Base 保留了足够的轨迹容量，同时仍允许最终的 Open-MOPD 训练在单个 8×A100-80GB 节点上运行。
