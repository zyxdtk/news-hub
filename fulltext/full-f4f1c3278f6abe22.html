中文摘要： 本文提出 Reasoning Core，一个可扩展的过程化数据生成套件，覆盖 PDDL 规划、一阶逻辑、上下文无关文法、因果推理与方程求解等核心形式化领域。其具备高分布广度、外部求解器验证、连续难度控制及推理轨迹支持，适用于预训练与后训练。实验表明，混入其数据可提升推理能力而不损害语言建模质量，且任务对 GPT-5 等前沿模型具挑战性。

**摘要** 在可验证的符号数据上进行训练是拓展语言模型推理能力、超越标准预训练语料库限制的有前景路径。然而，现有过程化生成器常依赖固定谜题或模板，难以满足规模化所需的分布广度。我们提出 Reasoning Core——一个可扩展的过程化数据生成套件，覆盖核心形式化领域：随机域上的 PDDL 规划、带等词的一阶逻辑、上下文无关文法的解析与生成、随机贝叶斯网络上的因果推理，以及方程组求解。每项任务均配备外部求解器以严格验证，并支持连续难度控制以适配课程学习设计。示例可选地包含求解器生成的推理轨迹，从而支持从最早预训练阶段起进行监督训练；同一接口亦提供可验证的强化学习奖励函数。实验表明，将 Reasoning Core 数据混入预训练可提升下游推理能力，同时保持甚至略微提升语言建模质量。零样本评估证实，这些任务对 GPT-5 等前沿模型构成挑战。 代码与数据以 MIT 许可公开： github.com/sileod/reasoning_core hf.co/collections/reasoning-core/datasets environments/sileod/reasoning-core-env

**1 引言** 随着语言模型规模扩大，人们日益关注通过在可验证符号数据上训练来构建推理能力，而非仅依赖网页文本 [Wu et al., 2022; Liu et al., 2023; Akter et al., 2025; Jiang et al., 2026]。证据表明，后训练方法（如带可验证奖励的强化学习 RLVR [Guo et al., 2025; Lambert et al., 2024; OpenAI, 2024]）往往放大预训练阶段已隐含的策略 [Zhang et al., 2025; Yue et al., 2025; Yuan et al., 2025; Matsutani et al., 2025]。要超越这些能力，可能需暴露于更广的问题分布。这种规模需求要么依赖计算密集型的长期强化学习 [Liu et al., 2025b]，要么需借助补充性方法——符号预训练：将算法生成的形式化任务注入早期训练数据，以构建可被后训练利用的基础推理原语。

过程化生成是生成此类数据的自然工具，但其效果高度依赖分布广度。狭窄模板与固定谜题可检验模型是否已具备某能力，却未必能提供足够多样性以规模化地“植入”新推理原语。仅在单一 PDDL 规划域（如积木世界）上训练 [Valmeekam et al., 2023; Khandelwal et al., 2024] 无法泛化至微小变化；Dyck 语言预训练 [Hu et al., 2025; Jiang et al., 2026] 仅覆盖分层结构的一小部分。现有后训练套件如 Reasoning Gym [Stojanovski et al., 2025] 可为 RLVR 提供优质信号，但其侧重任务数量而非任务内分布广度，且不面向预训练规模数据生产。

为弥合此缺口，我们引入 **Reasoning Core**——一个可扩展的过程化生成套件，旨在为预训练与后训练生成高分布广度的可验证符号数据。Reasoning Core 提供的任务生成器少于广覆盖库，但聚焦更基础、更具表现力的领域：随机生成域上的 PDDL 规划（非固定场景）、完整的一阶逻辑（含等词）、任意文法的上下文无关文法解析与生成、随机贝叶斯网络上的因果推理，以及符号方程求解。每个生成器均配以外部求解器进行严格验证，并提供连续难度控制以支持课程设计，从而生成近乎无限的新实例。同一接口同时暴露训练就绪示例与可验证奖励函数，使生成数据可用于预训练、指令微调及未来强化学习。

我们的贡献如下： - 一套可扩展生成套件，覆盖核心形式化领域（PDDL 规划、一阶逻辑、上下文无关文法、因果推理、方程求解），具高分布广度并集成外部求解器验证； - **gramforge**：一个支持拓扑控制与上下文敏感推导的文法框架，用于生成结构化符号数据； - 预训练实验表明，混入 Reasoning Core 数据可提升推理能力，同时保持甚至略微提升语言建模质量； - 公开发布数据集（50 亿预训练 token、20 亿后训练 token）与代码，采用 MIT 许可。

**2 相关工作**

**LLM 生成与应用导向合成数据** LLM 常用于生成特定领域合成数据。典型如 MathGenie [Lu et al., 2024]（通过问题反译增强数学推理）、DeepSeek-Prover [Xin et al., 2024]（定理证明），以及相关方法用于编程 [Xu et al., 2025] 和指令微调 [Kaur et al., 2024]。虽对后训练有效，但 LLM 方法推理成本高、分布广度有限。相较之下，我们的纯过程化套件提供可扩展、可验证、高广度的符号数据，更适合预训练。

**过程化生成环境** 为克服静态数据集局限，过程化内容生成（PCG）已成为构建动态可扩展评估环境的流行手段 [Cobbe et al., 2020; Risi & Togelius, 2020; Liu et al., 2025a, 2026]。Reasoning Gym [Stojanovski et al., 2025] 是其前沿代表，提供大量算法可验证任务及参数化难度。其他工作聚焦特定挑战生成，如游戏 [Paglieri et al., 2025; Seely et al., 2025]、逻辑谜题 [Lin et al., 2025; Lee et al., 2025] 或视觉推理问题 [Chollet et al., 2025; Wu et al., 2025]。Reasoning Core 聚焦规划与形式逻辑等基础符号域的全广度，刻意采用更少任务但更高分布广度。例如，RG 提供 Sokoban 或汉诺塔等具体 PDDL 域，而 RC 采样随机 PDDL 域覆盖全部 STRIPS 问题类。逻辑方面，RG 固化三段论，而 RC 采用前沿一阶逻辑文法 [Sileo, 2024] 实现形式语义。

Reasoning Core 围绕四大特性设计：广度、可读性、可扩展性与严格验证。

**3.1 高广度与基础任务** 任务选择聚焦基础形式推理能力，而非狭窄谜题。包括：随机域上的 PDDL 规划、带等词的一阶逻辑、非线性方程组、上下文无关文法解析与生成、正则表达式与符号归纳、轻量检索/感知任务（如缺失元素检测、集合交集）、随机贝叶斯网络上的因果推理，以及通过 TPTP 生态系统（如公理/定理匹配、有用公理检测、证明结构）实现的形式数学任务。任务描述见附录 4。

**3.2 可扩展生成与难度控制** 每个生成器由连续“难度旋钮”控制——单个浮点数参数化调整底层因素（如证明深度、变量数、规划长度）。固有离散超参数采用随机舍入，实现对问题分布的细粒度控制，支持适配模型演进性能的自适应课程。

**3.3 外部工具验证** 仅靠内部验证难以在宽问题分布下扩展而不重复造轮子。因此我们集成外部工具：逻辑（Vampire/E）、PDDL 规划（FastDownward）、方程求解（Sympy）等，提供客观明确的奖励信号。具硬性非 Python 依赖的求解器通过 udocker/Apptainer 容器化，并提供定制封装。

**3.4 基于文法生成** 我们发布 **gramforge** [https://github.com/sileod/gramforge]，原为逻辑推理数据集设计 [Sileo, 2024]。该库支持定义上下文敏感的概率文法，生成规则可在多输出通道间同步（如同步生成自然语言及其对应逻辑形式）。将生成算法与文法分离，使生成器简洁、可审计且富表现力。我们对生成算法与资源进行了多项关键增强：

- **拓扑控制**：标准 PCFG 采样常难以满足最小深度约束而不退化为“尖刺”（深但窄的推导树，缺乏句法多样性）。我们实现带“稠密度”因子的定制算法，强制横向扩展与纵向增长并存，确保生成示例维持结构复杂性而非仅长度。 - **上下文敏感性**：为支持过程化代码生成，库现支持推导期间的状态传播，可一致追踪变量作用域与循环不变式（纯上下文无关文法无法实现）。 - **预置文法**：提供多套已实现文法：重实现 TinyPy（Python 代码合成文法 [Yamani et al., 2024]）、简化英语文法（用于语法任务）、英语/TPTP 一阶逻辑文法（用于逻辑任务）、正则文法及 CFG 元文法。

**3.5 高效数据生产** 许多 Reasoning Core 任务依赖拒绝采样与外部求解器，运行时间差异大。为支持大规模稳健生成，超时自动随难度级缩放，停滞进程被检测并终止以避免资源泄漏。引入“平衡键”机制，限制每批次内任务声明特征（通常为答案标签）的频率，防止退化分布。另提供并行生成流水线：单线程工作器通过文件锁协调，可随 CPU 核心线性扩展。

**3.6 推理轨迹** 如可能，我们在示例中添加推理轨迹，用于引导伪思维链行为。例如，重格式化逻辑与数学任务中的 TPTP 证明。当不可行时（如算术任务），通过在递归自底向上求值表达式树时记录中间步骤（使用精确分数算术）自动生成推导过程。

**4 实验** 我们通过统一接口与并行生成工具（含超时与防护）随机采样任务生成数据集。预训练数据集：80% 示例为难度等级 0，剩余 20% 分布于等级 1 和 2；后训练数据集：难度均匀采样自 0、3、5 级。发布 1000 万示例（50 亿 token）用于预训练，100 万示例（10 亿 token）用于后训练。每子集生成耗时约 3 天（48 线程 Intel(R) Xeon(R) Gold 5320）。

**4.1 零样本评估** 我们对 GPT-5 系列在 Reasoning Core 任务上进行初始零样本评估，评估两难度级（easy/knob=0, hard/knob=5），每任务每级 200 样本。设“推理努力”为 medium，超参默认（温度 1, top-p 1），系统提示为 “Output the answer in the desired format between <answer> and </answer>”。图 2 展示各任务配置的平均奖励。所有任务对 GPT-5 均具足够挑战性，多数任务的难度控制按预期生效（hard 模式失败率更高）。

虽此实验不能替代 RLVR 评估，但表明我们生成的数据对大型前沿模型（预训练与后训练）均具挑战性。

**4.2 监督微调** 我们使用 TRL 库 [von Werra et al., 2020] 在三类数据集上进行监督微调实验：FineWeb [Penedo et al., 2024] 与 SYNTH [PleIAs, 2025] 用于预训练，Dolci [Olmo et al., 2025] 用于指令微调（后训练）。

预训练：采用随机初始化 Transformer，架构为 Monad-56M [PleIAs, 2025]。 指令微调：采用预训练 Ettin-68M 解码器 [Weller et al., 2025]。

模型与数据规模选择以近似 Chinchilla 最优比 [Hoffmann et al., 2022]；每次运行约耗时 1 天（单块 Nvidia A30 GPU）。

优化器：Prodigy [Mishchenko & Defazio, 2024] + Schedule-Free 算法 [Defazio et al., 2024]，默认超参；批大小 16；上下文窗口 1024 token；训练 1 轮。

所有情况均使用自然语言数据集 D ∈ {FineWeb, Dolci, SYNTH} 的 0.5B token，并添加 r × 0.5B token 的 Reasoning Core 数据（r ∈ {0, 0.1, 0.3, 0.5, 1.0}）。如可用，对 50% 的 Reasoning Core 示例包含推理轨迹（第 3.6 节）。

评估指标：各数据集测试集及 PlatinumBench [Vendrow et al., 2025]（含 15 项跨域推理可靠性任务：数学、逻辑、表格理解）。负对数似然（NLL）为标准语言建模损失，作为答案指标，比准确率更稳定（小模型易因指令遵循问题导致准确率噪声大）。

图 3 结果表明：组合数据集可一致改善 PlatinumBench 的答案 NLL（三类语料均适用），并略微降低通用自然语言训练数据的验证损失，证实符号推理原语有助于自然语言建模。

“甜点”在于添加原数据集大小一半的 token（r=0.5），即符号 token 占总量三分之一。混合虽增加总 token 数，但过程化数据边际生成成本可忽略（不同于有限网页语料）。关键发现是：这些额外 token 可提升推理能力而不损害语言建模。

虽此实验确认任务难度，本文未报告 RLVR 训练结果。尽管所有任务原生暴露可验证奖励函数，本文贡献在于生成基础设施及其与外部求解器的集成；在高广度分布下掌握这些任务所需的 RLVR 研究需显著更大算力预算与精细多任务平衡，故大规模 RL 验证留待未来工作。

**5 结论** 在可验证符号数据上训练是构建（而非仅揭示）语言模型推理能力的有前景路径，随着训练规模扩大，更广的数据分布变得日益必要。我们提出 Reasoning Core 以支持此方向：一个可扩展数据生成套件，聚焦高分布广度的基础符号域，配以外部求解器验证与连续难度控制。实验表明，将 Reasoning Core 数据混入预训练与指令微调，可一致提升下游推理能力，同时保持甚至略微提升语言建模质量；零样本评估证实其对 GPT-5 等前沿模型构成挑战。因同一接口暴露可验证奖励函数，Reasoning Core 同样适用于强化学习；此方向及跨非符号域迁移研究留待未来。

**局限性**

**范围** Reasoning Core 范围限于形式与符号域（规划、逻辑、文法解析、方程求解及相关任务）。虽这些域所锻炼的推理能力（如系统搜索、组合推理、符号操作、规划）可能迁移至法律推理、科学假设评估、排序智能体工具调用或结构化论证等非形式场景，但本文未实证验证此类迁移。跨域泛化研究仍是重要未来方向。

**规模** 实验规模有限：微调运行使用参数量 <1 亿的模型、训练数据 0.5B token；零样本评估虽具信息量，但非完整训练研究。所观察到的收益与权衡在更大模型与数据规模下是否成立，仍是开放问题。

**缺乏 RLVR 实验** 虽 Reasoning Core 适用于带可验证奖励的强化学习（RLVR），本文未展示 RLVR 训练曲线。在本设定中，生成器有意聚焦高分布广度（如随机 PDDL 域、完整一阶逻辑）以防止过拟合。因此，学习这些任务比掌握模板化或低熵过程化数据集需更多样本。小预算 RLVR 实验（如数千回合）难以代表其预期使用场景，且可能低估其效用。严谨 RLVR 评估需海量回溯、精细多任务混合及复杂课程平衡策略，留待未来工作。

最后，尽管我们投入大量精力验证生成问题的正确性（结合外部求解器检查、LLM 辅助审阅及多轮独立人工裁决与代码审计），任何验证流程均非万无一失。生成逻辑中的细微 bug、求解器遗漏的边界情况、或自然语言表述与形式规范间的不匹配仍可能存在。用户应知悉：尽管有防护措施，少量生成示例仍可能含错误。

**更广泛影响** 生成近乎无限可验证符号数据的能力，为语言模型预训练开辟了 largely 未探索的路径。虽后训练优化已成熟，但在预训练或中期训练阶段注入过程化形式结构，为神经符号 AI 提供了可扩展路径。通过将逻辑规则与结构约束直接内化至权重 [Clark et al., 2020]，模型可在接触标准自然语言语料前即发展出稳健的基础推理能力。Reasoning Core 提供了在多样形式域中测试与扩展此方法所需的基础设施。

此外，全过程化数据规避了网页爬取数据集或从专有 LLM 蒸馏文本所伴随的严重许可模糊性与版权风险 [Longpre et al., 2024]。因每实例均为过程化新颖，Reasoning Core 亦免疫于基准污染（对静态评估套件日益关切的问题）。此外，我们生成的数据可经代码重验证，作为对抗数据投毒的防护 [Bowen et al., 2025; Cloud et al., 2025]，提供可验证的预训练组件。提示可从显式解耦元数据中完全重构；答案正确性可随时通过评分接口确定性重评估。通过将复杂验证外包给成熟外部求解器，生成代码库保持简洁且易审查。此设计确保最终数据集合法安全且可复现。

*arithmetics*：评估由随机表达式树（深度可配置）生成的算术表达式（加减乘除、幂、abs/min/max/round），叶节点为整数或浮点数。难度随树深度与输出精度上升。思维链轨迹自底向上逐行求值。 *symbolic_arithmetics*：简化含符号变量与整数常数的代数表达式，由算术运算与函数的概率上下文无关文法生成。变量数、数值范围与表达式深度随难度扩展。答案经符号简化规范化；评分基于等价性，容忍代数等价重排。 *equation_system*：求解含查询变量的线性方程组。系统可唯一确定、欠定（Multiple solutions）或不一致（No solution），各情况概率采样。唯一系统通过随机整数解与复杂度可变的系数混合行运算构建。 *conjecture_entailment*：在超置calculus下判断前提是否蕴含猜想 [Quesnel & Sileo, 2025]。问题源自 TPTP 公理在多样数学域上的饱和，控制证明深度。负例通过前提扰动生成并由自动定理证明器验证。 *proof_reconstruction*：重构形式证明的依赖图：给定乱序编号子句，识别公理与导出子句，并输出父子边（CHILD <- P1, P2）。子图取自 TPTP 公理集在十数学域上的证明器运行，具严格二元推理约束。F1 分数（基于导出边）评分。 *logic_nli*：基于口语化一阶逻辑公式的自然语言推理 [Sileo, 2024]。前提采样自随机词汇（名字与形容词）的 FOL 句子；标签（蕴含、矛盾、中性）由 Vampire 定理证明器验证。分布涵盖任意量词、否定与谓词组合。 *evidence_retrieval*：扩展 logic_nli [Sileo, 2025b]：给定编号前提与假设，识别蕴含或矛盾假设的最小子集。黄金答案通过消融验证——仅当移除某前提使证明失效时才包含之。 *planning*：为过程化生成的 STRIPS 风格规划问题（结构化自然语言呈现）生成有效顺序计划。域（动作、先决条件、效果）与实例（对象、初始状态、目标）均随机生成。计划通过字典序动作排序确保确定性。思维链轨迹追踪状态变化与剩余目标。评分接受所有有效计划（带长度惩罚）。 *graph_pathfinding*：在从多样拓扑（Erdős–Rényi、Watts–Strogatz、Barabási–Albert、规则、网格）采样的无向图中找两点最短路径，以随机文本格式（边列表、邻接表、矩阵、DOT 等）呈现。思维链轨迹追踪 BFS 执行，记录队列状态与访问集。 *graph_node_centrality*：识别无向图中所有最高度中心性节点，输出排序列表（显式处理并列）。 *graph_cycle_detection*：识别由向无环路径主干添加一条边构成的图中唯一环的精确节点集。图使用随机文本表示。输出为排序节点列表；难度随图规模上升。 *graph_isomorphism*：判断两图是否同构。图从多样拓扑生成器采样，文本表示独立选择。正例对用随机节点置换；负例用边交换并确认不同构。类分布偏向负例。 *sequential_induction*：从整数序列前缀推断递推关系 U[n]=f(U[n−1],…,U[n−d],n)。表达式从算术运算符与 prior 项的上下文无关文法采样，过滤非退化（无常数或爆炸序列）。评分奖励观测项正确性与公式简洁性。 *bayesian_association*：给定观测证据（Pearl 的 Rung 1），计算随机贝叶斯网络中目标变量的后验边缘分布。网络含离散变量与表或噪声交互 CPD（如 Noisy-AND/OR）。通过与真实值的 Jensen–Shannon 散度评分。 *bayesian_intervention*：计算随机贝叶斯网络中 do-干预（Pearl 的 Rung 2）下的后验。模型需执行图手术——切断干预变量的入边——再传播结果分布。网络分布与 JSD 评分同 bayesian_association。 *code_execution*：预测从分层文法（tinypy）采样的合成 Python 程序的标准输出，涵盖简单算术赋值至丰富控制流与表达式。连续难度参数控制构造复杂度分布。 *diff_prediction*：给定随机突变的纯文本文件历史（行插入、删除、词替换）的两个版本，生成正确的统一 diff（块格式）。源可早于或晚于目标；diff 可为空。按字符级相似性评分。 *diff_patching*：将统一 diff 补丁应用于源文本以生成目标文本。文档经随机突变演化；补丁范围从空至多块编辑，覆盖 trivial 与复杂补丁场景。按字符级相似性评分。 *parsability*：给定上下文无关文法与标记字符串，分类为 unambiguous、ambiguous 或 unparsable。文法通过元文法随机生成或从精选集（如 Dyck 语言）提取；字符串可扰动生成负例。标签由 Earley 解析计数确定；思维链追踪每解析路径。 *parsing*：为给定 CFG 下的标记序列生成完全括号化的 Lisp 风格解析树。文法采样或过程化生成；仅保留无歧义解析。tagging 变体要求标注每个标记的父非终结符与解析树深度。 *continuation*：识别给定 CFG 下前缀字符串后所有有效后续标记，及前缀是否已是完整句子（STOP）。有效延续通过 diverse 采样与精选文法的 Earley 解析精确计算。按标记集重叠（部分分数）评分。 *regex_following*：生成完全匹配给定正则表达式的字符串（正则表达式从字符类、量词、交替、分组与范围的随机文法采样）。奖励与目标模式的模糊编辑距离成反比。 *regex_induction*：推断匹配所有正例并拒绝所有负例的正则表达式。正则表达式从复杂度各异的概率文法采样；正负例与目标验证。评分奖励正确性（匹配/拒绝率）与简洁性。 *set_intersection*：计算随机域（整数、英/法数字词、日期、字母字符串）中两集合的交集。集合重叠受控以确保非平凡实例。通过 Jaccard 相似性评分（奖励部分分数）。 *set_missing_element*：识别从有序域（整数、数字词、日期、字母字符串）的连续子序列中移除的 1–3 个元素，以乱序呈现 [Sileo, 2025a]。难度随序列长度与域多样性上升。 *set_equality*：判断两乱序集合是否含完全相同元素（True/False）。第二集合为精确乱序副本或经添加/移除/替换元素扰动。域涵盖整数、数字词、日期与字母字符串。 *table_qa*：在含语义类型列（价格、评分、名称、城市等）的合成表上执行 SQL 查询，以随机格式（CSV、Markdown、JSON、LaTeX、YAML 等）呈现。查询涵盖聚合、过滤、分组摘要与去重计数。评分处理数值容差与结构比较。 *table_conversion*：在 CSV、JSON、YAML、Markdown、HTML、LaTeX 与纯文本格式间转换表。表具多样语义列类型；源与目标格式从所有成对组合均匀采样。按归一化编辑距离评分。
