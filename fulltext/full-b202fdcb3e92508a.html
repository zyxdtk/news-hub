原标题：HalluCiteChecker: A Lightweight Toolkit for Hallucinated Citation Detection and Verification in the Era of AI Scientists

中文摘要： 本文介绍了HalluCiteChecker，一个用于检测和验证科学论文中幻觉引用的轻量级工具包。该工具将幻觉引用检测形式化为NLP任务，分为引文提取、识别和匹配三个子任务。它具有易用、轻量、完全离线运行且仅依赖CPU的特点，可在数秒内完成验证。该工具旨在减轻审稿人负担，支持系统性的预审和出版检查，维护AI时代科学交流的完整性。

HalluCiteChecker：AI科学家时代幻觉引用检测与验证的轻量级工具包 Yusuke Sakai, Hidetaka Kamigaito, Taro Watanabe 日本奈良先端科学技术大学院大学 (NAIST) {sakai.yusuke.sr9, kamigaito.h, taro}@is.naist.jp

摘要 我们介绍了 HalluCiteChecker，一个用于检测和验证科学论文中幻觉引用的工具包。尽管 AI 助手技术已经改变了学术写作过程（包括引文推荐），但它们也导致了与任何现有工作都不对应的幻觉引用的出现。这种引用不仅损害了科学论文的可信度，还给审稿人和作者增加了额外负担，他们必须在审稿过程中手动验证其有效性。在本研究中，我们将幻觉引用检测形式化为一个 NLP 任务，并提供了一个相应的工具包作为解决该问题的实践基础。我们的软件包是轻量级的，可以在标准笔记本电脑上在几秒钟内完成验证。它还可以完全离线执行，并且仅使用 CPU 即可高效运行。我们希望 HalluCiteChecker 能够通过实现系统的预审和出版检查，帮助减少审稿人的工作量并为组织者提供支持。我们的代码在 GitHub 上以 Apache 2.0 许可证发布 [1](yusuke1997/HalluCiteChecker)，并通过 PyPI 作为可安装包分发 [2](pip install hallucitechecker)。演示视频可在 YouTube 上观看 [3](https://youtu.be/WG3WXgH2pok)。

1 引言 图1：HalluCiteChecker 使用场景示意图。幻觉引用通常伪装在许多正确的引用中，使得手动验证非常费力。HalluCiteChecker 易于安装，并在笔记本电脑上开箱即用。它高亮显示候选的幻觉引用，从而实现高效验证，提高作者的意识，并减少审稿人的工作量。在 Ji 和 Lu (2025) 的示例论文中，识别出了十多处幻觉引用。

图2：幻觉引用检测任务概述，由三个子任务组成：引文提取（第 2.1 节）、引文识别（第 2.2 节）和引文匹配（第 2.3 节）。

引文是科学论文的基本组成部分 (Wang 和 Barabási, 2021)。它们用于用证据证实主张，承认先前的工作，并阐明新贡献在研究领域内的定位和新颖性。除了支持科学论证外，引文还作为评估科学影响力的关键定量指标。引用次数被广泛用于评估论文、研究人员和出版场所的影响力，构成了 h-index 和影响因子等指标的基础。因此，引文不仅作为学术参考，还作为分配学术信用的机制。

最近，反映了 AI for Science 和 AI 科学家技术的进步，由大型语言模型 (LLM) 驱动的写作助手已经改变了学术写作过程，包括自动起草、改写和引文推荐。这些工具提高了生产力和可及性，特别是对于非英语母语者、初级研究人员和学生。然而，它们也引入了新的风险。幻觉引用，即不对应任何真实工作或包含错误书目信息的参考文献，开始在评审中的论文、预印本甚至同行评审出版物中越来越多地出现。最近的报告表明，它们的流行率正在迅速增加 (Sakai et al., 2026)。这种趋势对科学交流的完整性和可靠性构成了严重威胁，而科学交流传统上依赖于善意的隐含假设，即作者准确引用现有的和相关的工作 [4](错误的引用早已被发现在科学文献中存在 (Wang 和 Barabási, 2021; Sweetland, 1989; Xu et al., 2026)。虽然此类错误传统上归因于人为错误，但在 LLM 时代，幻觉引用迅速增加，包括捏造不存在的作品 (Xu et al., 2026; Oladokun et al., 2025; Walters 和 Wilder, 2023)。此外，轻微的不一致，例如书目细节的微小差异，也变得越来越普遍 (Bienz et al., 2026)。无论其来源如何，都期望对其进行系统性检测。)。

幻觉引用的日益增多将额外的验证责任转移给了审稿人，他们现在必须手动确认引用参考文献的有效性以维持出版质量。此验证过程给审稿人和出版组织者带来了显著的单方面负担。因此，包含幻觉引用的论文可能会面临桌面拒稿或其他纠正措施。尽管做出了这些努力，系统性的调查表明，包含幻觉引用的论文已被多个会议录用。这些发现凸显了手动验证的局限性，并强调了对自动化检测方法的迫切需求。

为了应对这一挑战，我们将幻觉引用检测形式化为一项新颖的 NLP 任务，并引入了 HalluCiteChecker，一个用于验证和检测科学论文中幻觉引用的轻量级工具包，如图 1 所示。我们的系统设计实用且易于访问：它可以在标准笔记本电脑上在几秒钟内完成验证，完全离线运行，并且只需要 CPU，无需外部通信或专用硬件。这使其能够无缝集成到现有工作流程中，包括作者的提交前检查、同行评审期间的审稿人协助，以及会议组织者和出版商的自动筛查。通过为幻觉引用检测提供高效且可部署的解决方案，HalluCiteChecker 旨在减少审稿人的工作量，提高出版物的可靠性，并帮助在 AI 辅助研究时代维护科学交流的完整性。

2 任务定义 我们将幻觉引用检测任务定义为一个结构化任务，由三个子任务组成：引文提取、引文识别和引文匹配。图 2 显示了这些子任务的概述。这种分解澄清了幻觉引用检测中涉及的挑战，并突出了系统性改进和未来发展的机会。

2.1 引文提取 科学论文通常以结构化文档的形式分发，例如 PDF 文件 [5](科学研究也以各种格式呈现，包括物理打印件和 HTML 页面（如博客文章）。在本文中，为简单起见，我们重点关注 PDF 文档。这些替代格式仅仅是输入格式的变化。此外，尽管文档解析研究取得了重大进展，但可靠地提取完整和准确的引文信息仍然具有挑战性。)。在此约束下，第一步是从文档中提取引文信息。引文提取涉及从原始文档中识别和解析书目条目，由于布局、格式和文档质量的差异，这带来了挑战。

此子任务提供了几个改进和扩展的方向。可以通过解析、OCR 和后校正来提高识别准确性和效率。此外，有必要隔离特定于引文的信息，例如识别参考文献部分和分离单个书目记录。此外，此子任务可以扩展以提取外围信息，包括结构信息（例如边界框坐标）和与引文相关的上下文信息。这种扩展能够实现对引文使用的结构化理解和可视化，并为下游识别和验证提供额外的信号，包括评估引文是否适当和有效。总之，此子任务侧重于从文档中提取与引文相关的信息，包括书目条目以及相关的结构和上下文元数据。

2.2 引文识别 引文信息通常表示为文档中的内联文本。因此，有必要识别和分类单个引文组件，例如标题、作者姓名、出版年份、出版地和页码。引文格式差异很大，包括标准格式（如 APA 和 MLA）以及会议和期刊特定的格式约定。此外，引文条目可能包含缺失或不完整的字段。因此，在现实场景中，朴素的基于规则的提取方法是不够的。

此子任务旨在通过确定哪些跨度对应于特定的书目组件，来识别自然状态下引文文本的语义结构。这可以被视为命名实体识别 (NER) 任务的一种专门形式，其目标是从原始引文字符串中提取结构化的书目字段。尽管现有的 NER 技术可以适用于科学文档，但由于实体类型数量庞大以及不同场所和学科遇到的引文格式多样性，仍然存在挑战。

2.3 引文匹配 给定结构化的引文信息，我们通过将其与书目数据库（例如本地数据库和基于网络的学术搜索引擎）进行匹配来确定每个引文是否有效。虽然可以使用各种引文字段进行此操作，但先前关于幻觉引用验证的研究表明，标题信息可作为可靠的匹配键 (Sakai et al., 2026; Bienz et al., 2026; Xu et al., 2026) [6](一个可能的原因是作者姓名通常以缩写或截断形式出现，例如使用首字母、省略中间名或使用“et al.”来代表多位作者。此外，出版物名称经常缩写，而页码等书目字段可能不完整或格式不一致。虽然可以要求使用 DOI 或 URL 等标识符，但这些标识符并非对所有引文都一致可用。此外，DOI 解析页面在结构和格式上各不相同，从中检索可靠的元数据会带来额外的挑战。相比之下，标题信息通常更具独特性、稳定性，并且以其完整形式呈现，使其成为引文验证的实用且可靠的键。)。

因此，在本文中，我们主要关注基于标题的引文匹配。请注意，如果有结构化的书目数据（例如 BibTeX 条目）可用，则可以直接从此子任务开始进行引文验证。然而，这种结构化元数据在实践中很少可用。因此，期望考虑整个流程，包括引文提取、识别和匹配。

3 HalluCiteChecker：设计原则 我们在设计工具包 HalluCiteChecker 时考虑了以下五个设计原则：

易于使用：该工具包应该易于安装和使用，避免复杂的设置过程。为了实现这一点，我们将工具包作为 Python 包提供，可以通过单个命令安装并通过单行命令执行。我们的目标是实现开箱即用的功能，无需额外配置，类似于广泛使用的工具如 ACL pubcheck [7](https://github.com/acl-org/aclpubcheck)。

轻量级：该工具包在典型使用环境中应该实用且高效。因此，它被设计为即使在标准笔记本电脑上也能仅使用 CPU 资源并在实际时间限制内高效运行。

离线：例如，在同行评审过程中，将手稿上传到外部 API 或 Web 服务可能会引入数据泄露的风险并违反保密政策。为了解决这些问题，该工具包被设计为完全离线运行，不依赖外部服务。虽然可以支持可选的外部集成，但核心功能在隔离的内部环境中仍保持完全可操作。

非生成式 AI：生成式 AI 工具（如 LLM）在某些同行评审政策下可能受到限制或禁止 [8](例如，ICML 2026：https://icml.cc/Conferences/2026/LLM-Policy，以及 ACL Rolling Review 政策：https://aclrollingreview.org/reviewerguidelines#q-can-i-use-generative-ai [于 26 年 4 月 27 日访问])。依赖此类工具可能会引入合规性、可重复性和幻觉问题。因此，核心实现避免使用生成式 AI，而是依赖于标准的 NLP 和 ML 技术。

简单实现：它遵循极简设计以促进可维护性和可扩展性。通过提供良好分解的组件和清晰的实现结构，在基类和特定实现之间具有明确的分离，并能够轻松跟踪数据和处​​理流程，该工具包支持以最小的努力轻松集成新方法。

4 HalluCiteChecker：系统细节 我们构建了一个框架，其中第 2 节中定义的三个子任务作为单独的组件实现，如清单 1 所示。每个类对应一个关键子任务。这种模块化设计支持轻松扩展，并能够灵活集成新方法以用于未来研究。流程通过统一的 Citation 数据类进行控制，该数据类管理跨组件的数据流，并提供清晰且结构化的工作流程。基于此设计，我们主要描述默认的开箱即用实现。

4.1 引文提取器 给定 PDF 文档作为输入，此组件提取每条引文的原始文本并返回 Citation 对象列表。我们使用 Docling (Auer et al., 2024) 仅使用 CPU 资源执行 PDF 解析 [9](Docling 提供了可选的 OCR 和基于 LLM 的校正功能，可能会利用 GPU 资源。但是，我们仅使用其内部的基于 CPU 的解析模块 docling-parse 作为 PDF 解析的前端工具。)。接下来，我们启发式地识别和提取参考文献部分，然后应用后处理来重建可能跨页 break 或行边界分割的引文字符串。此过程将引文信息生成为单行原始文本字符串。此外，还获得了诸如边界框坐标之类的结构元数据。Docling 在 MIT 许可证下可用。

4.2 引文识别器 给定从第 4.1 节获得的引文字符串，此组件提取标题信息。然而，由于引文格式的差异，基于正则表达式的启发式方法具有固有的局限性 (Bienz et al., 2026)。因此，引文识别被表述为类似于 NER 的序列标记任务，其中引文字符串中的每个标记都被标记以识别结构化的书目字段，包括标题。

我们采用 DeLFT (DeL, 2018–2024) 从引文字符串中提取结构化的书目字段，包括标题 [10](先前的分析工作 (Sakai et al., 2026; Xu et al., 2026) 使用了 GROBID (GRO, 2008–2026)，这是学术文档解析的事实标准工具。然而，GROBID 是用 Java 实现的，通常需要设置 Docker 环境，这与我们在第 3 节中描述的易于使用的设计原则不一致。因此，为了满足我们的要求，我们使用 DeLFT，它是 GROBID 序列标记模型的基于 Python 的重新实现。)。

具体来说，我们使用了带有 glove840B 嵌入 (Pennington et al., 2014) 的预训练 BidLSTM_CRF_FEATURES 模型 (Lample et al., 2016; Chiu 和 Nichols, 2016)。给定引文字符串，模型执行具有 18 个实体标签 [11](18 个实体如下：author, booktitle, collaboration, date, editor, institution, issue, journal, location, note, pages, publisher, pubnum, series, tech, title, volume, 和 web。) 的序列标记，从中提取标题字段。此组件中使用的工具在 Apache 2.0 许可证下可用。

4.3 引文匹配器 给定提取的标题信息，此组件通过将其与书目数据库匹配来验证引用的论文是否存在。基于 Sakai et al. (2026) 和 Xu et al. (2026)，我们使用 RapidFuzz 库 (Bachmann, 2025) 实现的基于归一化 Levenshtein 距离的相似度分数，对引文标题进行字符级模糊匹配，阈值为 0.9。

遵循 Sakai et al. (2026)，我们还在默认设置中包含了源自 ACL Anthology、arXiv 和 DBLP 的书目数据库。尽管清单 1 显示了一个返回布尔验证结果的简化实现，但可以通过覆盖 verify() 函数轻松扩展系统以返回相似度分数或附加元数据。

虽然外部 API 对于此任务可能有用，但为了遵守我们在第 3 节中陈述的设计原则，我们在核心模块中不包含外部 API 访问。相反，外部 API 访问被视为可选的，引文匹配主要针对内部书目数据库执行。此组件中使用的库在 MIT 许可证下可用。

4.4 统一数据类：Citation 如清单 1 所示，每个组件通过向统一的 Citation 数据类添加信息来工作，该数据类作为管理所有与引文相关的信息的中心数据结构。特别是，从一开始将每条引文表示为单个 Citation 对象消除了分配或管理顺序标识符的需要，从而实现了更简单且更易于维护的实现。此设计还允许在早期阶段获得的外围信息（例如边界框坐标）被保留，并由下游组件访问，而无需管理此类元数据的中间步骤。

此外，处理决策是基于所需字段的存在而做出的，未定义的属性被视为错误。此设计强制执行预定义且类型安全的数据结构，从而能够稳健地处理不完整或例外情况，而不会中断整体工作流程。此外，数据类提供了诸如 from_dict 和 display 之类的实用方法，它们将数据格式化和表示封装在数据类本身中。这种数据表示与流程处理之间的明确分离有助于跨流程阶段进行跟踪和调试，同时最大限度地降低实现复杂性。

4.5 后勤与基础设施 预训练权重和数据库。虽然 HalluCiteChecker 代码库可以通过 PyPI 轻松安装，但第 4.2 节和第 4.3 节中使用的某些资源太大，无法直接在包内分发。尽管用户可以在本地初始化和更新这些资源，但我们提供了对预训练权重和书目数据库的开箱即用访问，以确保易用性和高效加载。为了最小化加载延迟，glove840B 嵌入通过 Hugging Face Hub (Wolf et al., 2020) 以 Lightning Memory-Mapped Database (LMDB) 格式分发，从而实现高效的内存映射访问。引文数据库使用 Hugging Face Datasets (Lhoest et al., 2021) 分发，它利用 Apache Arrow 实现快速加载和高效存储。这些数据库自动进行版本控制并更新，无需手动干预。

开发者工具。我们提供开发者工具以促进性能测量和系统评估。这包括用于测量处理时间 的秒表实用程序和分析工具，这些工具可导出执行环境信息（如内存使用情况）。

7 结论 我们介绍了 HalluCiteChecker，一个用于检测科学论文中幻觉引用的工具包。我们将引文验证形式化为一个结构化任务，并提出了一个模块化框架，将过程分解为三个子任务，为未来的研究提供了清晰的基础。此外，如第 6 节所示，该工具包能够对每个组件的处理时间进行细粒度测量，从而促进未来开发中的系统分析和优化。

除了其技术贡献外，我们的目标是支持更透明和建设性的科学评审过程。通过实现系统且可重复的引文验证，该工具包可以帮助减少无意的桌面拒稿和不必要的审稿人工作量，从而促进作者、审稿人和组织者之间的负责任研究实践。

对可重复性和存档透明度的影响。本工作主要使用 ACL 会议的论文评估幻觉引用检测，但该工具包旨在推广到其他会议，如 ICLR 和 NeurIPS。然而，与维护已发表论文版本化存档的 ACL Anthology 不同，一些场所用更新版本覆盖手稿而不保留历史修订 [12](https://gptzero.me/news/iclr-2026/, https://gptzero.me/news/neurips/)。这种缺乏版本历史的情况使得对先前报告的幻觉引用进行独立验证变得困难。因此，我们强调透明和版本化的存档实践对于支持科学交流中的可重复性、问责制和长期验证的重要性。

有限基准的影响及未来研究。尽管并行工作已开始探索幻觉引用检测，但许多现有工具和分析不易重复，特定于环境，或者并非为跨各种出版格式的通用目的使用而设计。相比之下，HalluCiteChecker 的设计考虑了可用性、可重复性和可扩展性，从而实现了更广泛的采用和系统评估。此外，用于幻觉引用检测的综合基准仍然有限。我们希望这项工作为未来的数据集构建、基准开发和方法改进提供基础。通过发布任务表述和实现，我们旨在支持引文验证和科学可靠性方面的进一步研究。

负责任的使用和社区影响。使用 AI 辅助写作工具本身并没有问题；然而，作者仍有责任验证所有引用参考文献的准确性。当自动生成的建议在没有充分验证的情况下被纳入时，可能会产生幻觉引用。我们的目的不是阻止使用 AI 辅助研究工具，而是提供一个实用的机制，使作者、审稿人和组织者能够系统地验证引文并减少无意的错误。该工具旨在通过提高透明度、减少不必要的审稿人负担以及帮助防止因引文错误导致的可避免的桌面拒稿，来支持负责任的研究生态系统。

如果诸如 HalluCiteChecker 之类的工具在社区内得到广泛采用，类似于现有工具如 ACL pubcheck，我们鼓励社区驱动的维护和治理，以确保透明度、可持续性并与社区需求保持一致。我们希望这项工作有助于建立公平、透明和负责任的科学实践。
