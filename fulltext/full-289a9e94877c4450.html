Slack 希望将 AI 编程从终端拖入群聊之中。

这家归 Salesforce 所有的消息平台今天宣布推出 Slack Code，这是一款新产品，可将 AI 编程智能体——包括 Anthropic 的 Claude Code、Cognition 的 Devin、GitHub Copilot 和 Vercel 的智能体——直接嵌入到专门的 Slack 频道中，让整个团队可以一起观看、引导、审查和发布软件。

Slack Code 在发布时适用于任何 Slack 套餐，不过客户需要自行拥有对这些合作智能体的访问权限。

它的推销说辞看似简单：如今，大多数使用 AI 编程智能体的工作都发生在一个人与一个智能体之间，对其他人是不可见的。Slack Code 让这项工作变成了“多人模式”。当有人在任何对话中标记一个编程智能体时，该智能体会启动一个特定于项目的代码频道，公开完成工作——包括代码差异、实时预览以及可在专门标签页中查看的运行计划——并在工作完成后归档频道，留下可搜索的审计跟踪。

“我喜欢的一点是，代码不再是瓶颈，”Slack 临时首席执行官 Rob Seaman 在发布前的新闻发布会上说。“想法、品味、判断力、工艺——这些才是瓶颈，而你实际上已经将能够贡献想法、品味、判断力和工艺的人群，扩大到了你 Slack 中的任何人。”

这对 Slack 来说是一次意义重大的发布，对更广泛的企业 AI 市场也具有启示意义。到目前为止，AI 编程的繁荣一直是关于个人生产力的故事——一个开发人员独自在终端窗口中使用 Claude Code 或 OpenAI 的 Codex。Slack 押注下一章将属于那些拥有这些智能体周围协作层的公司。而它正在做出这一押注之际，其母公司正极度需要这个故事能够成功落地。

Slack Code 频道如何让 AI 编程智能体公开工作

在接受采访时（Cognition 的高管也参与了此次采访），Slack 领导层描述了一种工作流程，它看起来不像结对编程，而更像是一个新闻编辑室。

Cognition（Devin 编程智能体的制造商）新任企业总裁 Jeff Wang 演示了一个实时案例：有人在工程频道中报告了一个损坏的功能，Devin 用一个表情符号确认了它，在帖子中回复，进行了调查，并打开了一个拉取请求。“它甚至知道代码所有者，所以你可以看到它也标记了 Theo，”Wang 说。“每次 Devin 做这样的事情时，它都有自己的计算机。所以在这里，它实际上是在使用 Chrome 和开发者工具来测试该功能是否正常工作。”

从那里，工作迁移到一个专门的代码频道，任何人——工程师、产品经理、设计师——都可以加入。在 Wang 的演示中，一位设计师在任务中途将一个 Figma 文件拖入频道，智能体毫不费力地将其纳入。智能体最后发布了代码更改以及截图和证明该功能有效的录制演示。这个验证循环是该推销的核心：与在开发人员笔记本电脑上运行的智能体不同，基于云的智能体可以生成可审计的记录，证明工作是正确的。“扩展事物、审计事物、将其提供给每个人——使用这些云智能体形态比使用本地智能体要容易得多，”Wang 说。

此次发布也超越了代码频道的范畴。Slack 正在推出对智能体在产品中存在方式的更广泛改造：智能体私信（DM）表现得像与同事的对话；一个新的“智能体”标签页，为每个智能体会话提供一个带有实时状态和停止按钮的大本营；以及一个“添加到 Slack”流程，允许团队只需点击几下即可从 Lovable、n8n、OpenAI、LangChain 和 Airtable 等平台部署智能体，并自动完成 OAuth 和配置。

为什么 Slack 说编写代码不再是软件开发的瓶颈

Slack Code 背后的战略论点是，AI 颠覆了软件开发的经济学。编写代码曾经是稀缺、昂贵的一步。现在，Slack 的高管们认为，它成了廉价的一步——而限制已经向上游转移，转移到了人类的判断力上。

“我喜欢的一点是，代码不再是瓶颈，”Seaman 在新闻发布会上说。“想法、品味、判断力、工艺——这些才是瓶颈，而你实际上已经将能够贡献想法、品味、判断力和工艺的人群，扩大到了你 Slack 中的任何人。”

Cognition 提供了内部数据来支持其速度声明。“在过去的几个月里，我们看到内部合并的 PR 数量增加了 10 倍，而我们的员工人数只增加了 40% 左右，”Wang 说，他描述了一种工作流程，工程师发出一个 Devin 任务，转向其他事情，然后再启动另一个——“很快你就会让每个人同时处理几十个智能体。”

Wang 说，这种模式远远超出了工程师的范畴。“信不信由你，我们的很多 bug 都是由销售团队报告的。他们在 Slack 中报告，然后懂技术的人去修复这个 bug。”Seaman 抓住了这个例子，将其视为整个论点的缩影：“这么多这类事情以前甚至从来没有传达到产品经理那里进入待办事项列表，因为当时没有沟通工具，没有动力，也不知道它其实可以这么快被修复——而我们现在有效地打破了所有这些障碍。”

Wang 进一步阐述了他认为这最终会走向何方。繁重的工作——“修复 bug、修复 CI/CD、或修复漏洞，所有这些工程师可能不想做的事情——我们认为将被自动化，”他说。剩下的是“需要创造力、规划、业务逻辑”的工作。他补充了一个会让一些工程领导者感到不安的预测：虽然今天人类仍然把关每一次合并，但我怀疑也许在明年，它就会直接自动通过了。

公开工作能解决 AI 垃圾问题吗？

对软件开发民主化的一个明显反对意见是质量。如果公司里的任何人都可以召唤一个编程智能体，企业是否会淹没在业界所说的“AI 垃圾”——由缺乏经验的用户大规模生成的、看起来合理但构思拙劣的输出中？

Slack 的高管们有些反直觉地认为，可见性是解药，而不是催化剂。“多人模式部分实际上是对此的一种防范，因为人们可以看到你的工作，人们可以评论你的工作，”Slack 产品副总裁 Katie Steigman 说。她将其与现状进行了对比：“如果我在终端里天知道在用智能体做什么，相比之下，在一个人们可以看到我的意图并实际上改变和塑造我的工作的地方做这件事——或者打我的手告诉我那是垃圾，因为这是真实的。”

Steigman 是一名产品经理，而不是工程师，她将自己的做法描述为一种模板。“当我作为产品人员提交 PR 时，我几乎总是会标记我团队中的一名工程师。我不只是发送一个 PR 并要求批准，”她说。“几乎每次，工程师都会说类似这样的话，‘拜托，你可以把它弄得更紧凑一点，’或者他们实际上会给出一些具体的技术指导，然后智能体会再修改一次，生成在一定程度上经过工程师 touched 的代码。”

Seaman 用更宏大的措辞来阐述这个论点：“我认为多人模式 AI 的道德弧线倾向于更高质量和更少的重复。”他指出了 Shopify，他说该公司的首席执行官 Tobi Lütke 曾写过将智能体编程限制在公开频道中的文章，正是因为它“立即传播了公司正在发生的每一件事”，并创造了公平的竞争环境。尽管如此，怀疑论者的观点也有数据支持。

Gartner 去年预测，到 2027 年底，超过 40% 的智能体 AI 项目将被取消，理由是成本不断上升和商业价值不明确。而麦肯锡最近的《AI 现状》调查发现，虽然 62% 的组织至少在试验 AI 智能体，但只有大约三分之一开始进行任何规模的 AI 扩展，只有 39% 报告了对底线利润的任何影响。智能体热情与智能体价值之间的差距，仍然是 Slack 所销售市场的决定性特征。

Slack Code 的安全模型内部：没有上帝模式，没有新身份

对于企业买家来说，Slack Code 中最重要的设计决策可能是其权限模型。当被直接问及代码频道中的智能体是否会跨团队泄露访问权限——比如财务代码库对法务部门可见——时，Seaman 强调，智能体继承调用它们的人的权限，仅此而已。

“一切都是代表用户完成的，使用用户的 ACL（访问控制列表），无论是在 Slack 中还是在它们正在连接的系统中，”他说。“没有上帝权限或机器人级别的权限……在 Slack 中，智能体可以访问用户有权访问的信息，并有权访问它被添加到的频道。”

Steigman 补充说，当智能体启动一个代码频道时，“该智能体从代码频道中唯一获得的是触发它的对话上下文”。在执行方面，Wang 说 Devin 在具有“最低可行访问权限”的隔离沙箱中运行——包括一个完全没有互联网访问权限的可选模式。“你听说过所有这些关于智能体逃脱并造成破坏的故事，”他承认，“但我们有不同的安全配置。”

这种“智能体作为现有用户的扩展”模型是一个真正的差异化优势，相对于独立的智能体平台，后者通常迫使 IT 部门配置新的服务身份并管理拼凑的一次性权限。它也回答了困扰智能体工具的影子 IT 问题：因为智能体向 GitHub 生成标准的拉取请求，现有的发布关卡和审查流程仍然适用。“它降低了前期获得初始 PR 的门槛，”Steigman 说。“然后尽职调查仍然在 GitHub 中进行。”

Slack Code 对 Salesforce 高风险 AI 转型意味着什么

Slack Code 是在其母公司的一段动荡时期推出的。截至 1 月，Salesforce 的股价在过去一年中下跌了约 18%，大幅落后于纳斯达克，华尔街质疑 AI 是否会削弱对传统企业软件的需求。12 月，OpenAI 挖走了 Slack 首席执行官 Denise Dresser 担任其首席收入官，提升了当时担任 Slack 产品主管的 Seaman 担任临时首席执行官。

作为回应，Salesforce 一直在竞相将 Slack 打造为工作的 AI 前门。今年 1 月，它发布了一个由 Anthropic 的 Claude 提供支持的重建版 Slackbot，两家公司表示这成为了该公司 27 年历史上被采用最快的功能。Slack Code 将该策略从回答问题扩展到生产工件：不仅仅是消息，还有在 Slack 内部生成的工作代码、原型和文档。

今天的新闻中还嵌入了一个引人注目的战略逆转。2025 年年中，路透社报道称 Salesforce 已采取行动阻止竞争对手 AI 公司访问 Slack 数据——这是一种防御姿态。相比之下，今天的公告将 Slack 定位为一个开放平台，正是吸引这些 AI 公司作为合作伙伴，并计划向任何开发者开放代码频道 API。该公司表示，软件工程只是第一个用例；专门的智能体频道中的营销活动和法律文件审查将是下一个。其考量似乎已经从保护 Slack 的数据转变为让 Slack 成为智能体——任何人的智能体——完成其工作的不可或缺的场所。

合作伙伴不出所料地说了正确的话。“整个团队可以聚集在一个代码频道中，观看智能体工作，共同引导它，并发布预览，”Vercel 首席技术官 Malte Ubl 说。GitHub 首席产品官 Mario Rodriguez 称 Slack 是“更广泛的 GitHub 承诺的战略组成部分：人类设定方向，智能体完成闭环。”

AI 编程的未来：多人频道与单机终端将共存

Slack 的高管中没有人声称终端已经消亡。当被问及 Claude Code 和 Codex 等工具是否会过时，Seaman 预测了一种分工。“绝大多数工作实际上将发生在这些多人环境中，”他说。“但也会有一些在终端中进行的深入、沉浸、密集的单人思考工作。”重新思考代码库架构的工程师会埋头使用智能体；而标记损坏按钮的销售代表则会在每个人都能看到的频道中获得修复。

Seaman 建议，信任曲线对于任何看过团队采用早期自动化浪潮的人来说都会很眼熟。“人们一开始会打开这些东西”——阅读每一个差异、每一个思考步骤——“然后建立对系统的信任，随着时间的推移打开得越来越少。”

这就是押注，它比一次产品发布更大。麦肯锡的研究表明，从 AI 中获取真正价值的组织是那些围绕它重新设计工作流程的组织，而不是将其生搬硬套到旧流程上——而 Slack Code 从根本上说是一个打包为功能的工作流程重新设计，试图让团队而不是个人成为 AI 采用的单元。如果它奏效，这家曾经改变了同事交谈地点的公司将改变软件制造的地方。如果不奏效，所有的透明度可能只意味着每个人都能看到垃圾堆积如山。

无论哪种方式，孤独的开发者在私人标签页中与智能体窃窃私语的时代正在终结。正如 Wang 所说：“瓶颈已经转移。”Slack Code 将要回答的问题是，人群是让瓶颈变得更小——还是只是让声音更响。
