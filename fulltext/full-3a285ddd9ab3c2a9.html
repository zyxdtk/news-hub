摘要

我们提出 cuRoboV2-Fast，这是一种 GPU 加速的规划器，可同时降低无碰撞、负载感知、力矩受限运动的规划延迟和执行时间。B 样条轨迹优化减少了所需的迭代次数，而加速的机器人计算和可微分逆动力学降低了细化成本并适应变化的负载。TimeOpt 在采样的速度、加速度、加加速度和力矩约束下优化沿固定路径的遍历速度，利用局部样条支撑在 GPU 上高效求解带状牛顿系统。在 3 kg 负载下，cuRoboV2-Fast 在 RTX 5090 上实现了 4.4 毫秒的平均规划时间，比 cuRoboV2 快 14.7 倍。我们的方法在 Jetson AGX Orin 上的规划速度快于 cuRoboV1 + TOPPRA 在 RTX 5090 上的表现。在 YAM 上基于双目相机的部署实现了 5.93 秒的平均完成抓取-放置周期，比 cuRoboV2 缩短 34.6%。

I. 引言

快速操作要求运动既要快速规划又要快速执行。运动规划在杂乱环境中寻找无碰撞路径方面取得了显著进展 [1]。执行这些路径需要遵循速度、加速度和执行器力矩限制的时序。所携带的负载会改变动力学特性，并可能使原本可行的运动变得不可行。此外，仅几何路径长度并不能决定执行时间：在执行器约束下，较短的路径可能需要较慢的运动。因此，高效的运动规划必须同时考虑生成轨迹的计算成本和执行轨迹所需的时间。

先前的工作已经确立了并行规划、平滑轨迹表示和高效机器人计算的优势 [2, 3, 4]。然而，规划可执行的运动需要在轨迹优化过程中反复进行碰撞和动力学评估。降低这一成本既需要更少的优化迭代，也需要每次迭代中更廉价的计算。执行时间带来了一个互补的挑战：均匀地重新缩放时间步长无法在限制性执行器约束随位形变化的路径上重新分配时间。因此，高效的负载感知规划需要在快速约束评估的同时，对轨迹几何和时序进行灵活优化。

我们提出 cuRoboV2-Fast，一种用于无碰撞、力矩受限运动的单 GPU 规划器，可同时降低规划延迟和执行时间。B 样条轨迹优化以更少的迭代次数细化几何，而 TimeOpt 沿生成的固定路径优化遍历速度。时序样条的局部支撑产生带状系统，便于高效的 GPU 优化。并行 GPU RRT 在需要时提供路径初始化，加速的机器人计算降低了细化成本。可微分逆动力学纳入了依赖负载的力矩限制，并支持在所携带物体变化时进行运行时惯性更新。

我们为快速、可执行的运动规划做出六项贡献：

  1. 我们使用 B 样条进行无碰撞、负载感知、力矩受限的轨迹优化，在我们的收敛性基准中以 25 次初始迭代（对比 125 次）达到与 cuRoboV1 [2] 相当的成功率。

  2. 我们引入 GPU 加速的 TimeOpt，采用带状牛顿系统和原始-对偶预测-校正求解器，在采样的速度、加速度、加加速度和力矩界限下进行固定路径时序优化。它在均匀时间步长细化之外将平均运动持续时间缩短 15.7%，在 RTX 5090 上对有效的 100 g 基准查询平均耗时 0.28 毫秒。

  3. 我们加速了机器人计算和可微分逆动力学，支持无需重新编译的负载更新。轨迹优化迭代在 RTX 5090 上比 cuRoboV2 [5] 快 2.7 倍，在 Jetson AGX Orin 上快 2.6 倍。

  4. 我们通过并行 GPU RRT 实现了亚毫秒级的路径初始化：平均 0.305 毫秒，比 cuRoboV1 PRM [2] 快 43 倍，在粗略碰撞检查下比 pRRTC [6] 快 1.48 倍。将约束验证与树生长分离，使得无需更改生长内核即可添加额外检查。

  5. 我们的集成流水线在 RTX 5090 上以 3 kg 负载实现了 4.4 毫秒的平均运动规划时间，比 cuRoboV2 [5] 快 14.7 倍，同时保持相似的成功率。cuRoboV2-Fast 在 Jetson AGX Orin 上的规划速度也快于 cuRoboV1 [2] + TOPPRA [7] 在 RTX 5090 上的表现。

  6. 我们在 YAM 上演示了基于双目相机的抓取-放置流水线，在单个 GPU 上集成了感知、抓取生成和运动规划。平均完成周期时间为 5.93 秒，比 cuRoboV2 缩短 34.6%，规划仅占周期时间的 1.0%。

我们已在 github.com/NVlabs/curobo 以 Apache 2.0 许可证开源了 cuRoboV2-Fast 实现。

II. 相关工作

最近的运动规划进展在多个层面利用并行性。基于 RRT-Connect [8]，VAMP 使用 CPU SIMD 指令加速运动学和碰撞检查 [1]，而 pRRTC 将树扩展、最近邻搜索和边验证分布到 GPU 线程 [6]。cuRoboV1 结合几何初始化与并行轨迹优化来生成无碰撞运动 [2]。这些系统展示了围绕可用硬件设计规划操作的优势。我们的 RRT 遵循这一方向，同时保持验证与树生长分离，因此可以在不修改生长内核的情况下引入额外检查。

一旦初始路径可用，轨迹优化可以改善其平滑度和间隙，如 CHOMP、STOMP 和 TrajOpt 所示 [9, 10, 11]。轨迹表示也塑造了这种细化：B 样条长期以来支持无碰撞平滑和反应式变形，使用局部支撑来修改路径的局部 [3, 12]。早期的全身优化进一步展示了如何同时考虑碰撞和力矩约束 [13]。基于这些思想，我们研究并行样条评估和梯度累积如何使完整规划器内的约束细化变得高效。

固定路径时序方法在保持几何的同时优化遍历速度。Bobrow 等人 [14] 考虑执行器力矩界限，Verscheure 等人 [15] 将路径时序表述为凸优化。TOPPRA [7] 通过向后可达性和使用小型线性规划的前向构造处理速度、加速度和力矩约束。其路径受限力矩在路径加速度和速度平方上是仿射的，允许动力学系数被预计算和重用。TOPP3 [16] 通过积分最大和最小加加速度剖面并通过多重打靶连接它们来解决三阶约束。

我们在 cuRoboV2-Fast 中的 TimeOpt 采用相同的固定路径动力学约简，并在采样的速度、加速度、加加速度和力矩界限下直接优化速度平方的三次 B 样条表示。每个样本依赖于四个时序控制，为原始-对偶预测-校正求解器产生带状牛顿系统。这种局部支撑和并行约束评估实现了高效的 GPU 优化，在 RTX 5090 上对有效的 100 g 基准查询的平均 TimeOpt 延迟为 0.28 毫秒。

轨迹优化反复评估机器人运动学和碰撞并传播其导数。高效的刚体算法和运动学优化库（包括 Pinocchio 和 PyRoki）为此工作提供了可重用的构建模块 [17, 18]。对于碰撞，宽阶段修剪减少了需要详细测试的几何体 [19]，而可微分 GPU 评估支持 cuRoboV1 中的并行轨迹优化 [2]。我们基于这些原则，通过共享运动学梯度累积、并行雅可比矩阵以及自碰撞和扫掠世界查询的修剪来构建。它们在轨迹细化和抓取选择中的使用激发了批量大小为 1 以及更大批量的评估。

力矩感知优化为此工作负载增加了反复的动力学和导数评估。GRiD 通过机器人特定的代码生成、稀疏性和 GPU 并行性加速这些操作 [4]。我们专注于直接计算优化损失的梯度，并将链调度和惯性参数作为运行时数据提供。这避免了形成完整的动力学导数矩阵，并允许在约简拓扑不变时无需重新编译即可更新负载，同时保留对机器人维度的特化。

将这些方法与样条优化和几何初始化相结合，可在单个 GPU 上实现无碰撞、力矩受限的运动和抓取规划。

III. 方法

我们的运动规划器结合了无碰撞初始化、B 样条优化、用于轨迹重定时的 TimeOpt、高效的机器人计算和可微分逆动力学。规划首先细化直线种子，并在需要时调用 RRT。受约束的运动（如抓取接近和提升）使用严重惩罚偏离指定路径的成本项。

III-A. 使用 RRT 的无碰撞初始化

当直线种子不足时，我们使用来自有界双向 RRT [8] 的路径初始化优化。规划器从起点和目标以交替波的形式生长树，并行评估多个扩展。每个扩展采样一个位形，找到其最近的树节点，并以有界步长向样本转向，然后检查关节限制和自/世界碰撞（图 2）。接受的端点扩展活动树，包括被阻塞边的有效前缀，而相反的树尝试连接到它们。一旦树相遇，追踪其父链即可恢复路径。当找到连接或达到存储节点或扩展轮数的预设限制时，搜索停止。

我们的实现将生长组织为并行扩展的同步轮次。相比之下，pRRTC [6] 让 GPU 块反复异步地采样和生长树，在每个块内进行贪婪连接步骤。我们的最近节点内核将距离计算分布到存储节点和关节坐标上，以分块方式处理树并归约结果以选择每个候选的最近节点。在 pRRTC 中，每个线程为节点子集计算完整距离，然后进行块级最小归约。因此，两个规划器都并行化最近节点搜索，但以不同方式分布其工作。

我们一起检查所有提议边上的采样状态，然后确定每条边的有效前缀。并行扫描为接受的端点分配不同的存储槽，允许并发插入而无需像 pRRTC 那样以原子方式保留每个槽。每轮还评估来自相反树的有界扩展。这种组织将验证与生长分离，允许在不更改生长内核的情况下添加额外检查。重用分配的缓冲区并通过 CUDA 图重放生长操作减少了重复的调度开销。一旦找到路径，我们将其缩短并拟合样条种子以进行细化。

III-B. B 样条轨迹优化

并行评估。 我们利用均匀三次 B 样条的局部支撑来并行化轨迹评估及其反向传播。设 U ∈ ℝ^(K×d) 包含 d 个关节的自由控制点，h 为节点区间，α ∈ [0,1] 为段 k 内的坐标：

q^(r)(t) = h^(-r) Σ_{j=0}^{3} N_j^(r)(α) ũ_{k+j}，r = 0, 1, 2, 3，（1）

这里 N_j 是三次基函数，Ũ 是完整控制序列。这种成熟的表示 [3, 12] 给每个样本四个支撑控制（图 3）。我们将每个样本-关节对分配给一个 GPU 线程，该线程从这些控制点一起评估位置、速度、加速度和加加速度。因此样本独立执行，相邻线程处理相邻关节以实现合并内存访问。增加采样密度会增加并行评估工作，而不增加优化控制点的数量。

图 3： 样条评估和反向收集：每个样本使用四个控制点；u₃ 从四个橙色段收集加权样本梯度，并使用 warp 级归约原语求和。

梯度累积。 反向传播反转了这种映射：每个控制点仅从其支撑内的样本收集梯度。在图 3 中，u₃ 从四个橙色段收集样本梯度，用相应的基导数加权它们，并将它们求和到其控制梯度中。此区域之外的样本不贡献。将采样导数写为 q_i^(r) = A_i^(r) U + b_i^(r)，我们累积

∇U ℒ = Σ_i Σ{r=0}^{3} (A_i^(r))^T ∇_{q_i^(r)} ℒ.（2）

内核直接应用基权重而不是具体化矩阵 A_i^(r)。分配给控制-关节对的线程将样本贡献分割到 warp 通道。每个通道将传入的位置、速度、加速度和加加速度梯度与其相应的基权重结合；然后 warp 归约对部分贡献求和。一个通道写入最终的控制梯度。这种收集避免了来自重叠样本的原子累积和样本-控制中间张量，同时允许独立处理不同的控制和关节。

III-C. TimeOpt：固定路径时序优化

在 III-B 节中，我们以固定节点区间 Δt 优化位置控制点，并在传递之间减小此区间。这种均匀约简受到轨迹最受限制部分的限制。TimeOpt 沿固定路径优化时序，允许其他部分在尊重执行器限制的同时更快地遍历。

设 q(s) 为固定位置样条，其中 s ∈ [0,1] 表示沿路径的进度。第二个三次 B 样条表示路径速度平方，时序控制 r = (r₀, …, r_{L-1}) ∈ ℝ^L 作为优化变量：

x_r(s) = ṡ² = Σ_{ℓ=0}^{L-1} B_ℓ(s) r_ℓ.（3）

这里 B_ℓ(s) 是钳位三次 B 样条基函数，r_ℓ 是其速度平方系数。两个样条都是路径进度 s 的函数。正系数给出 x_r(s) > 0；前向遍历遵循 ṡ = √(x_r(s))，其中点表示时间导数。

TimeOpt 寻求此固定路径在速度、加速度、加加速度和力矩限制下的最短持续时间遍历：

min_r T̂(r) = 1/(N+1) Σ_{i=0}^{N} 1/√(x_r(s_i))（4）

约束条件：
r_ℓ > 0，ℓ = 0, …, L-1，
|q̇_r(s_i)| ≤ v̄，∀i，
|q̈_r(s_i)| ≤ ā，∀i，
|q⃛_r(s_i)| ≤ j̄，∀i，
τ_min ≤ τ_r(s_i) ≤ τ_max，∀i。

目标在固定的均匀样本 s_i = i/N 处平均逆路径速度以近似持续时间。界限 v̄、ā、j̄ 和 [τ_min, τ_max] 分别限制关节速度、加速度、加加速度和力矩。我们还在时序节点处和内部路径节点的两侧强制执行这些限制，并保持规定的初始速度和加速度。

时序样条确定机器人何时到达路径上的每个点：

t_r(s) = ∫₀^s 1/√(x_r(u)) du，q_exec(t) = q(s_r(t)).（5）

这里 s_r(t) 是 t_r(s) 的逆。因此，TimeOpt 在保持路径的同时改变每个路径点何时被到达（图 4）。

图 4： TimeOpt 示意图。(a) 位置样条及其控制点 u_i 保持固定；紫色标记表示路径节点处的位置。(b) 优化系数 r_i 改变路径速度平方 x_r(s)。(c) 生成的时间映射为相同路径区间分配不相等的遍历时间。在此示例中，阴影区域中较慢的遍历和其他地方较快的遍历减少了总持续时间。

我们使用标准的固定路径动力学约简 [15, 7] 来评估动力学一次并在时序变化时重用它们。力矩通过精确的仿射关系依赖于路径速度平方：

τ_r(s) = (1/2) A(s) x_r'(s) + D(s) x_r(s) + g(s)，（6）

其中撇号表示路径导数。向量 A(s) 和 D(s) 捕获惯性效应，g(s) 是重力力矩。使用 III-E 节中的逆动力学计算，我们从每个路径样本的三次评估中获得它们：(q, 0, 0)、(q, 0, q') 和 (q, q', q'')，分别得到 g、A+g 和 D+g，如 TOPPRA 实现 [20] 中那样。后续的时序更新使用公式 6 而不重复逆动力学。关节速度、加速度和加加速度由链式法则使用固定路径导数得出。

我们用图 5 所示的原始-对偶预测-校正方法求解公式 4。求解器更新时序控制 r 和正约束乘子 λ。对于每个不等式，正边距 m_j 测量到其界限的距离。预测器针对零互补性 m_j λ_j = 0；校正器跨约束平衡这些乘积以保持搜索在内部并考虑它们的二阶变化。

时序样条的局部支撑产生带状牛顿系统，采样约束在 GPU 上并行评估。两个方向计算重用相同的 Cholesky 分解。回溯选择满足非线性界限的步长，我们保留最短的可行迭代。最终轨迹经过采样的执行器和碰撞检查以及其端点条件的验证。

TimeOpt 目标是高效收敛到局部最小值，不保证全局最优性。它相对于均匀时间步长重新缩放的轨迹细化将平均运动持续时间缩短超过 15%（IV-B 节）。这些运动时间收益和低计算成本使 TimeOpt 对真实机器人部署很有用。

III-D. 加速的机器人计算

我们通过一次性准备依赖拓扑的数据并在计算之间共享中间结果来降低重复机器人评估的成本。GPU 张量操作识别每个关节的后代以及贡献于每个工具-执行器对的关节。使用这种结构，正向运动学并行计算局部连杆位姿，然后通过共享内存以树顺序组合世界位姿。生成的变换提供工具位姿和碰撞球并支持雅可比评估。

对于反向传播，我们首先将输出梯度组合成每个连杆的一个力旋量。每个执行器独立地收集受影响连杆的力旋量，将它们投影到其关节运动方向上，并在写入其梯度之前组合耦合关节贡献。一次性累积连杆力旋量避免了为每个输出反复遍历祖先链。当 IK 需要显式雅可比矩阵时，我们改为将其列分配给独立的工作者，每个工作者使用准备好的贡献者列表；轨迹优化直接消耗损失梯度（图 6）。这些快速雅可比支持 IK 求解器的 Levenberg–Marquardt 初始化。在图中，S₂ 表示世界坐标系关节螺旋，α_ℓ 描述执行器到关节的耦合。

图 6： 高效运动学：并行局部位姿馈送串行世界组合，而准备好的贡献者支持独立的雅可比列（上）。反向传播一次性累积连杆力旋量，然后按执行器收集它们，避免重复的祖先遍历（下）。

图 7： 碰撞修剪和重用。即时连杆 AABB 消除了分离连杆之间的球-球测试（左）。扫掠界限修剪远处障碍物；相邻半扫掠在 x_t 处共享 SDF 并一次性旋转其求和梯度（右）。m± 表示相邻中点。

图 8： 高效逆动力学。前向 RNEA 使用紧凑的空间操作（上）；反向直接计算损失梯度而不是形成完整的导数矩阵（下）。独立的链并发运行，在共享父节点处归约。树显示叶到根的累积。负载更新无需重新编译。

自碰撞检查测试机器人连杆上碰撞球之间的重叠。cuRoboV1 [2] 并行评估配置的球-球对，但对于由许多球表示的机器人，检查数量可能变得昂贵。我们从其当前球位置和填充半径即时计算每个连杆的轴对齐包围盒（AABB）。这些界限在连杆之间并行构建并存储在碰撞内核内的共享内存中。当两个连杆 AABB 不重叠时，我们跳过这些连杆之间的所有球-球检查。这种廉价的修剪可以大幅减少详细的对测试，特别是当连杆分离良好时。每个 GPU 块为一个机器人状态组合剩余的测试、成本降低和球梯度。

扫掠世界碰撞使用相同原理修剪远处长方体。包含球半径、激活边距和相邻半段的界限首先拒绝远处的长方体。剩余的半扫掠在它们的公共轨迹点共享距离评估，并在单次旋转到世界坐标之前组合它们的梯度（图 7）。这减少了重复的几何计算，同时保留所选的离散采样分辨率用于验证。

图 9： 抓取规划集成。IK 选择一个抓取，随后在一次规划调用中进行预抓取、接近和提升运动。接近和提升遵循笛卡尔直线运动。单独的调用规划到放置位姿的传输。

III-E. 可微分逆动力学和负载

GRiD 利用机器人特定的代码生成来优化动力学及其导数 [4]。我们的实现改为将链调度和惯性参数保持为数据，同时在编译时特化内核维度和执行选项。效率来自紧凑的空间操作、链局部执行和直接损失梯度计算；负载更新不需要重新生成或重新编译内核。

在设置时，我们合并固定主体并在 CPU 上准备链调度。独立的链并发执行，每个 GPU 工作者在本地遍历串行链。这避免了链内连续关节之间的同步；工作者仅在链间依赖处同步。

空间变换直接使用旋转和平移而不是密集的 6×6 变换矩阵。递归牛顿-欧拉算法计算连杆速度、加速度和力：

v_i = X_i v_{π(i)} + S_i q̇i，
a_i = X_i a{π(i)} + S_i q̈_i + v_i × S_i q̇_i，
f_i = I_i a_i + v_i ×* (I_i v_i) - f_i^ext，（7）

其中 X_i 是空间变换，S_i 是关节运动子空间，I_i 是空间惯性。然后力从叶向根累积，投影到每个关节的运动子空间给出 τ_i = S_i^T f_i。负载变化在运行时更新质量、质心和惯性；只要约简拓扑不变，调度仍然有效。

我们的解析反向传播将力矩-损失梯度直接映射到 (q, q̇, q̈)，然后通过公式 2 映射到样条控制。这避免了形成和收缩 GRiD [4] 返回的完整位形和速度导数矩阵，减少了导数计算和输出存储。两个传递都通过 warp 归约组合兄弟贡献，并在其值被消耗或保存后重用共享内存存储。反向传播还重用前向中间结果以避免重新计算。图 8 总结了计算和链执行。这些节省保留了对机器人惯性参数的运行时更新。

III-F. 抓取规划集成

物体可以从许多位置和方向被抓取，因此抓取规划从选择为哪个位姿规划开始。给定一组候选抓取位姿，我们使用 IK 找到可行的机器人位形，并按位姿误差和与当前位形的距离对它们排序。我们发现这对于我们评估任务中的抓取选择是足够的，使我们能够用更便宜的 IK 求解替换抓取位姿目标集上的轨迹优化。选定的位姿定义后续运动规划的目标；仅 IK 可行性并不能确定机器人可以沿无碰撞路径到达它。

然后我们规划三个连接的运动（图 9）：移动到从选定抓取偏移的预抓取位姿、沿抓取轴的接近以及物体的提升。样条优化生成预抓取运动，在需要时使用 RRT 初始化以导航障碍物，而受约束的样条优化为接近和提升产生笛卡尔直线运动。每个运动从前一个运动的终端状态开始，碰撞设置调整为允许预期的接触。

IV. 实验

我们评估路径初始化、力矩受限轨迹优化、机器人计算和抓取-放置规划。运动基准使用 Franka Panda（7 自由度），计算基准还包括 G1（29 自由度），操作任务使用 YAM。离线规划在 RTX 5090 上运行，Jetson 上有额外的计算计时；真实机器人部署使用 RTX 6000 Ada。

IV-A. 粗略检查的路径初始化

我们评估用于初始化轨迹优化的路径，粗略碰撞检查为每关节最多 0.03 弧度间距。在来自 MotionBenchMaker [21] 和 MPINets [22] 的 2,575 个查询上，我们的 RRT 实现实现了 98.68% 的初始化成功率，相比之下 cuRoboV1 PRM [2] 为 91.92%，cuRoboV2 PRM 为 88.27%（图 10）。平均规划时间为 0.305 毫秒，而两个 PRM 基线分别为 13.09 毫秒和 8.49 毫秒，对应 43.0 倍和 27.9 倍的加速。我们的 RRT 也比 pRRTC [6] 快 1.48 倍，后者以 0.450 毫秒实现 99.07% 的成功率。VAMP [1] 以 0.0573 毫秒实现 99.22% 的成功率；尽管它更快地初始化路径，VAMP + TOPPRA [7] 在有负载时的运动规划成功率低于我们的流水线（图 12）。

图 10： MotionBenchMaker 和 MPINets 上的粗略检查路径初始化（2,575 个查询）。我们的 RRT 实现比 pRRTC 快 1.48 倍。VAMP 更快地规划路径，但 VAMP + TOPPRA 在有负载时实现比 cuRoboV2-Fast 更低的运动规划成功率（图 12）。

计时和路径长度使用 2,101 个共享成功查询。规划时间包括原生捷径化并排除 IK。我们的平均路径长度为 4.93 弧度，相比之下 cuRoboV1 PRM 为 5.28 弧度，cuRoboV2 PRM 为 3.70 弧度，VAMP 为 5.00 弧度，pRRTC 为 5.32 弧度。未通过粗略碰撞检查的路径被拒绝。接受的路径作为优化种子，需要进一步的细化和验证。

IV-B. 轨迹优化收敛

图 11： 100 个 MotionBenchMaker cage_panda 查询上的轨迹优化收敛。上：仅初始成功率。下：25 次初始迭代后 93 个共享有效查询上 cuRoboV2-Fast 的平均运动时间减少。我们的 B 样条公式在小的初始预算下实现更高的成功率。TimeOpt 与使用固定时间步长重新缩放的微调相比将平均运动时间减少 16%。

图 12： 不同负载下的运动规划。cuRoboV2-Fast 实现与 cuRoboV2 相似的成功率，同时规划更快并产生更短的运动。在最重负载下，两个 V2 方法都比 TOPPRA 基线保持更高的成功率。质量面板使用 RTX 5090 结果；Fast 成功率为每个负载 2,590 个查询两次重复的平均值。运动持续时间和路径长度使用对所有方法和负载均有效的 1,599 个查询，包括两次 Fast 重复。单独的规划时间面板显示 RTX 5090 和 Jetson AGX Orin 上的 3 kg 负载，使用不同的计时尺度。

我们在 100 个 MotionBenchMaker cage_panda 查询上隔离初始优化、时间步长细化和 TimeOpt 的影响。cuRoboV1 [2] 和 cuRoboV2-Fast 使用每个查询相同的四个保存 IK 种子和单次尝试，禁用动力学和粒子优化。图 11 显示我们的 B 样条公式在小的迭代预算下实现更高的成功率：cuRoboV2-Fast 以 25 次初始 L-BFGS 迭代达到 93% 的验证成功率，相比之下 cuRoboV1 为 64%。cuRoboV1 需要 5 倍的初始迭代才能匹配此成功率。将我们的初始预算增加到 200 仅将成功率提高三个百分点。

然后我们将初始预算固定为 25 次迭代，比较 25、50 或 100 次迭代的一或两个细化传递，使用 0.8 的时间步长收缩因子。所有设置保持 93% 的成功率。在所有设置中均有效的 93 个查询上，两次 25 次迭代传递相对于仅初始优化将平均运动持续时间减少 5.5%。添加 TimeOpt 将总减少增加到 20.3%，对应于相对于细化轨迹的进一步 15.7% 减少。更长的细化计划在 TimeOpt 后将运动持续时间改善不到 0.2%。

对于报告的 cuRoboV2-Fast 计时和真实机器人部署，我们使用 50 次初始迭代后跟一次 25 次迭代细化传递（50+1×25），总预算为 75 次迭代。

IV-C. 带负载的运动规划

我们研究给定起始状态和目标位象生成用于执行的无碰撞、力矩受限运动的完整流水线。对于在规划期间不考虑力矩限制的方法，我们使用 TOPPRA [7] 后处理它们的轨迹，后者沿固定路径改变时序。

我们比较四个流水线：cuRoboV2-Fast、cuRoboV2 [5]、cuRoboV1 [2] + TOPPRA 和 VAMP [1] + TOPPRA。如图 12 所示，cuRoboV2-Fast 和 cuRoboV2 在各负载下实现相似的成功率，超过 cuRoboV1 + TOPPRA 和 VAMP + TOPPRA。在最重负载下，所有方法的成功率都下降，两个 TOPPRA 基线下降更大；cuRoboV2-Fast 对它们保持 14.5–15.7 个百分点的优势。

在所有负载下对所有方法均有效的查询上，cuRoboV2-Fast 产生最短的平均运动持续时间，在各负载上平均相对于 cuRoboV2 减少 5.8%。仅路径长度在比较运动效率时可能具有误导性。cuRoboV2-Fast 产生的平均关节空间路径比 cuRoboV1 + TOPPRA 长 0.8–4.2%，但其运动在各负载上平均持续时间短 6.8%。

对于 3 kg 规划时间比较，cuRoboV2-Fast 在 RTX 5090 上耗时 4.43 毫秒，比 cuRoboV2 快 14.7 倍，比 cuRoboV1 + TOPPRA 快 10.0 倍。VAMP + TOPPRA 规划比 cuRoboV2-Fast 快 1.7 倍，但成功率更低且其计时排除 IK。

在 Jetson AGX Orin 上，cuRoboV2-Fast 耗时 25.99 毫秒，比 cuRoboV2 快 23.2 倍，比 cuRoboV1 + TOPPRA 快 5.9 倍（图 12）。它相对于 cuRoboV2 的相对加速比在 RTX 5090 上更大。cuRoboV2-Fast 在 Jetson AGX Orin 上的规划速度快于 cuRoboV1 + TOPPRA 在 RTX 5090 上的表现。

IV-E. 轨迹优化计算

cuRoboV2-Fast 通过更快的迭代和更小的迭代预算减少轨迹优化时间（图 14）。启用逆动力学后，每次迭代在 RTX 5090 上比 cuRoboV2 快 2.8 倍，在 Jetson AGX Orin 上快 2.6 倍。

部分收益来自避免线搜索期间的重复工作。通过重用当前解处的成本，cuRoboV2-Fast 每次迭代评估 972 个机器人状态，而不是 cuRoboV2 的 1,296 个。RTX 5090 模块剖面显示组合的前向和反向逆动力学耗时 19.38 微秒，而 cuRoboV2 为 31.58 微秒（快 1.6 倍）。其他成本和减少快 4.2 倍。组合的场景和自碰撞内核时间对 cuRoboV2-Fast 为 14.01 微秒，而 cuRoboV2 为 16.22 微秒。与 cuRoboV1 相比，组合的前向和反向运动学快 2.9 倍，而 L-BFGS 和线搜索快 1.3 倍。

更小的迭代预算复合了这些节省。遵循 IV-B 节的收敛研究，我们对 cuRoboV2-Fast 使用 75 次迭代（50+1×25），而两个基线为 300 次。连同更快的迭代，这将优化循环中花费的总时间相对于 cuRoboV2 在 RTX 5090 上减少 11.0 倍，在 Jetson AGX Orin 上减少 10.5 倍。相对于 cuRoboV1 的相应减少为 6.1 倍和 3.0 倍，即使 cuRoboV1 省略逆动力学。这些计时涵盖优化迭代；初始化和其他完整求解开销被排除。

IV-F. 模拟规划实验

我们在 RTX 5090 上的模拟 YAM 抓取-放置任务上比较 cuRoboV1 [2]、cuRoboV2 [5] 和 cuRoboV2-Fast，该任务将五个立方体从一个杂乱布局排列到托盘中。规划包括抓取选择、预抓取、接近、提升和传输。所有三种方法完成所有五个立方体，保存的提升和传输轨迹通过独立的持物碰撞和负载力矩审计。图 15 显示 cuRoboV2-Fast 同时减少了规划时间和规划运动持续时间。每个立方体的平均规划时间为 26.05 毫秒，相对于 cuRoboV1 加速 12.7 倍，相对于 cuRoboV2 加速 11.2 倍。平均规划运动持续时间为 3.33 秒，比 cuRoboV1 短 26.5%，比 cuRoboV2 短 46.6%。总之，这些收益将平均周期时间（测量为规划加规划运动）减少到每个立方体 3.36 秒：比 cuRoboV1 短 31.0%，比 cuRoboV2 短 48.6%。

在固定拾取和放置位置之间的单独模拟 YAM 传输中，我们将负载从 100 g 变化到 800 g（图 16）。较重的负载改变优化的运动：运动从关节 2 转移到关节 5 以尊重关节 2 的力矩限制，说明负载感知规划如何使路径适应负载。

IV-G. 真实机器人部署

我们在 I2RT YAM 上部署 cuRoboV2-Fast 用于桌面清理和料箱拣选（图 19）。一个 RTX 6000 Ada 运行 SceneFields [23]、GraspGenX [24] 和我们的规划器（图 17）。SceneFields 提供深度、检测和机器人掩码。它构建 5 毫米体素的 TSDF 用于 GraspGenX 使用的物体表面，以及 20 毫米体素的 ESDF 用于我们规划器的碰撞检查。

测量的关节反馈显示 cuRoboV2-Fast 在臂执行期间使用更多可用速度范围（图 18）。相对于 cuRoboV2，90–100% 速度利用率下的运动时间比例几乎翻倍，而低于 50% 利用率的比例减少 21.7%。cuRoboV2-Fast 的力矩利用率在 99.6% 的运动时间内保持低于 90%，两种方法的所有记录力矩都保持在限制内。尽管有速度可行的规划，执行速度仍可能超过限制，突出了在规划执行运动时将力矩约束与速度约束一起考虑的重要性。

图 18： 真实机器人物体传输的臂利用率、运动时间和周期时间。利用率使用每个瞬间利用率最高的关节。cuRoboV2-Fast 几乎将 90–100% 速度利用率下的时间翻倍，并分别将运动和周期时间减少 44.8% 和 34.6%。

在更高速度下花费更大比例的运动时间转化为更短的臂执行时间。在 cuRoboV2-Fast 的大约 50 个完成物体传输周期和 cuRoboV2 的 15 个周期中，平均臂执行时间减少 44.8%。这种减少导致平均周期时间减少 34.6%（图 18）。

我们分解周期中运动规划、臂执行、夹爪执行以及其他处理和等待的时间（图 19）。对于 cuRoboV2-Fast，这些平均分别为 0.06、3.75、1.53 和 0.60 秒。臂执行占周期时间的 63.1%，而规划仅占 1.0%。

图 19： 使用 cuRoboV2-Fast 的真实 YAM 桌面清理和料箱拣选。53 个完成序列的平均周期分解；规划仅占 1.0%，包括每个周期内失败的规划调用和重试。其他包括剩余处理和等待。

V. 讨论

规划时间的改进来自减少优化迭代次数和每次迭代的成本。收敛实验表明我们的 B 样条公式在评估配置中以更少的初始迭代达到可比的成功率，而加速的机器人计算降低了带逆动力学的细化成本。连同快速路径初始化，这些改进产生了完整流水线的加速，同时在各负载下保持与 cuRoboV2 相似的成功率。收益也扩展到 Jetson AGX Orin，其中 cuRoboV2-Fast 的规划速度快于 cuRoboV1 + TOPPRA 在 RTX 5090 上的表现，支持在嵌入式硬件上的部署。

高效执行需要同时优化路径及其时序。负载基准表明较短的关节空间路径在执行器约束下不一定产生较短的运动。负载感知轨迹优化可以使路径适应负载，而 TimeOpt 沿生成的路径重新分配遍历时间。其在均匀时间步长细化之外 15.7% 的平均运动持续时间减少表明，时序在几何优化后仍然是改进的机会。局部样条支撑产生带状牛顿系统和并行约束评估，使这种额外优化在 GPU 上变得廉价。这些结果支持 TimeOpt 作为改善执行时间的实用方法，而不需要全局最优时序。

真实机器人实验将这些改进与执行联系起来：cuRoboV2-Fast 在速度限制附近花费更大比例的臂运动时间，并相对于 cuRoboV2 将平均臂执行时间减少 44.8%。较短的臂运动也减少完成的周期时间，尽管夹爪执行和其他处理仍然是重要贡献者。规划仅占测量周期时间的 1.0%，因此仅进一步减少规划延迟对这些周期的影响有限。因此，改善规划器产生的运动仍然是更快操作的核心，同时需要与感知、抓取生成和执行的集成。

V-A. 局限性

我们的方法整体地解决运动规划，在杂乱场景中实现高成功率，同时减少计算时间和运动持续时间。尽管它不保证全局最优性，它在真实机器人上实现了 5.9 秒的平均抓取-传输周期时间。规划在此部署中仅占周期时间的 1.0%，不再是瓶颈。主要的剩余瓶颈在于富接触操作，特别是实现可靠的抓取和成功的物体交互。
