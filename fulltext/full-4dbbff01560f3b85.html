Mistral 已以一项自定义许可发布了其万亿参数 Large 4 模型的可下载开放权重，为企业自行运行和定制一款接近前沿水平的 AI 模型提供了新选择。独立测试如今显示，相较预览版，其最大的进步在于效率、更低的成本和更少的编造答案，同时整体能力略有提升。

在 10 月 29 日的评估中，独立评测机构 Artificial Analysis 给予高推理设置下的 ML4 在 Intelligence Index v5 上 26 分，高于预览版的 25 分。这使其比 xhigh 设置下的 Muse Spark Open 高出一分，令 ML4 成为该评估中在中国以外开发的、权重公开可得的最高分模型。

它仍落后于开放权重领跑者 DeepSeek V4.1 Flash 1017 和 GLM-5.3 六分，这两者均在各自的最大推理设置下测试。

更大的变化在于经济性：Artificial Analysis 报告称，更新后的模型每项 Intelligence Index 任务的成本为 2.06 美元，低于预览版的 5.54 美元，降幅达 63%。

其编码智能体评估将 ML4 在当前开放权重模型中排在第二位，所使用的 token 约为领跑的 GLM-5.3 配置的一半。Mistral 的发布公告链接了 Hugging Face 上的可下载模型，并推出了大幅降低的 API 费率。

此次发布所采用的 Mistral Ecosystem Open-Weight License（Mistral 生态系统开放权重许可）明确了商业边界。它不设收入门槛。相反，是否需要单独的商业协议取决于用户或其关联方是否运营“模型即服务”业务，并受特定例外情形约束。

对 Mistral 首席营收官 Marjorie Janiewicz 而言，商业论据不止于分数。在本周早些时候接受 VentureBeat 面对面采访时，她描述了这样一类客户：他们寻求可以留存、围绕自身信息进行定制、并且无需完全依赖提供商持续授权即可使用的模型。

“我不想被断开连接。我想拥有我自己的模型，”Janiewicz 在描述这种客户需求时说。“其次，我想对它进行定制，以确保我能从中获得价值。第三，则是业务连续性。”

独立结果强化了这一主张：ML4 提供了有竞争力的编码智能体和更高的效率，同时附带可下载权重所带来的控制力。它们也为 Mistral 的领先声明划定了边界。其在中国以外开发的开放权重模型中的微弱领先，并不意味着它是全球最强的开放权重模型，而且其得分会随运行所用的软件和设置而变化。

相比 10 月预览版有哪些变化

当 VentureBeat 于 10 月 6 日报道 ML4 时，Mistral 通过其 API 提供了预览版，并计划在 10 月 27 日发布权重。经过大约三周的额外强化学习以及来自客户和安全合作伙伴的反馈，权重于 10 月 29 日发布。

该模型的基本形态保持不变：一个非常庞大、稀疏激活的系统，可接受视觉和文本信息并生成文本。Artificial Analysis 目前列出其上下文容量为 100 万 token，其发布评估明确总参数量为 1.05 万亿，活跃参数为 520 亿。自预览版以来的进展是额外的训练和部署选择，而非一个独立模型系列的亮相。

一些表面上的规格变化也需要说明。我们最初的报道引用了 490 亿活跃参数；新发布则引用 520 亿。Mistral 的 Hugging Face 页面解释说，较小的数字描述的是每个 token 的激活量，而较大的总数还计入了嵌入层和输出层。仅凭这一差异并不能表明 Mistral 在预览期间扩大了模型。

最新材料明确训练使用了 3,800 块 Nvidia Grace Blackwell GPU，而非最初报道的约 4,000 块。公开发布还增加了部署细节：Mistral Studio 及其 API、OpenRouter、Vibe Code、提供私有 Azure 部署选项的 Microsoft Foundry，以及 Nvidia 托管端点和优化的 NIM 容器。Mistral 表示，下载的权重可以通过 vLLM 或 SGLang 提供服务。

三种推理设置带来了另一项实用选择：low 取代了之前的“None”模式，medium 面向日常任务，而 high 是最难请求的默认设置。开发团队可以为困难的调试任务保留更深的推理，而对常规请求使用较低设置。这是否会降低成功完成工作的成本，将取决于任务本身，以及较便宜的尝试需要修正的频率。

基准任务成本下降 63%，但更便宜的对手仍在

正式版将更低的 token 消耗与 API 费率相结合：每百万输入 token 0.70 美元，缓存输入 0.07 美元，输出 2.10 美元。Artificial Analysis 的新评估证实了这些费率，大约是此前 1.36 美元、0.14 美元和 4.18 美元的一半。

AA 现在测量的是已发布检查点的实际经济结果，而不是仅根据 token 价格进行推算：

模型与设置 每 Intelligence Index 任务成本
Mistral Large 4 Preview 5.54 美元
Mistral Large 4, high 2.06 美元
Muse Spark Open, xhigh 2.02 美元
DeepSeek V4.1 Flash 1017, max 0.60 美元
MiMo-V2.6-Pro 0.26 美元

来源：Artificial Analysis 10 月 29 日评估；ML4 当前模型页面也报告为 2.06 美元。这些数字针对的是 Intelligence Index 任务，而非 Coding Agent Index 任务。

ML4 的成本较其预览版下降约 63%，使其接近 Muse Spark Open。然而 DeepSeek 和 MiMo 以显著更低的实测任务成本取得了更高的 Intelligence Index 总分。ML4 良好的输出 token 用量并不等于最低的账单：token 费率、输入流量和缓存同样影响支出。

这些基准成本并未衡量自托管、定制、运营监督或人工审查的费用。企业仍需在自身环境中比较以可接受标准完成工作的成本。

许可证允许什么——以及 Mistral 何时要求达成协议

最终许可证授予了运行、复制、修改、继续训练、分发、再许可和销售该模型及其衍生作品的广泛权利，前提是副本或实质部分随附版权和许可声明。它是一个带有附加商业限制的修改版 MIT 许可证，因此简单地将 ML4 描述为 MIT 许可会遗漏一个重要条件。

第 2 条规定，如果被许可方或任何关联方运营“模型即服务”业务，则在商业使用该模型或其衍生作品之前，需要获得单独的商业许可证。

该定义涵盖通过 API、托管端点或其他方式让第三方获得推理或后训练访问权限的情形，前提是这些用户对输入、参数或训练数据拥有实质性控制。

两项排除缩小了该定义：模型能力仅嵌入在特定功能或框架中的终端用户产品，以及仅将请求转发给他人托管模型的服务。第 3 条另行豁免了不向第三方提供该模型或其衍生作品的内部使用，以及通过 Mistral 官方产品进行的访问使用。

这意味着在内部使用 ML4 的企业不会触发第 2 条的商业许可要求，即使该企业或其关联方运营模型即服务业务。

模型能力仅嵌入在特定功能或框架中的终端用户产品不属于模型即服务的定义范围；其运营者仍需考虑其自身或关联方的其他活动是否触发第 2 条。

向客户提供具有上述控制权的托管推理或后训练服务的运营者，在商业使用之前面临单独许可的要求，但须受所述例外情形约束。

区分标准在于业务活动和访问方式，而非公司规模：该模型专用许可证不设收入上限。运行下载权重的许可也不会使托管服务或自托管所需的基础设施变为免费。

开放权重编码智能体中排名第二，token 用量更低

Artificial Analysis 现在独立报告了 ML4 在其 Coding Agent Index 上的位置。相关比较同时涵盖模型本身以及指挥其工具调用和编码工作的智能体软件：

模型与推理设置 智能体软件 Coding Agent Index 每任务总 token 数
GLM-5.3, max Opencode 49 1590 万
Mistral Large 4, high Mistral Vibe 48 850 万
DeepSeek V4.1 Flash 1017, max DeepSeek Harness 46 1670 万

来源：Artificial Analysis 10 月 29 日评估及后续帖子。排名针对当前可获取的开放权重模型。

ML4 落后 GLM-5.3 一分，领先 DeepSeek 两分。其每任务 850 万 token 比 GLM 的 1590 万少用约 47%，印证了 Mistral 公告中的效率对比。Mistral 将这些分数描述为实质上持平；Artificial Analysis 则将 ML4 排在第二。仅凭所报告的一分之差并不能确立统计显著性。

这些是对完整智能体配置的比较。它们并未分离出底层模型在其他所有组件相同时的表现。编码指数也有自己的测试组合：FrontierCode v1.1、Terminal-Bench 4.0 和 SWE-Atlas-QnA-AA。它不同于范围更广的 Intelligence Index，后者包含 FrontierCode 2.0 以及额外的知识工作和推理评估。

在解读 Mistral 的其他编码相关声明时，这一区别很重要：

评估项目 Mistral 发布的对比 AA 的 Intelligence Index 评估（ML4 high）
Terminal-Bench 4.0 41% 25%
FrontierCode 2.0 19.7% 15%

Mistral 报告称其 Terminal-Bench 结果从预览版自报的 28% 升至 41%，同时输出 token 用量下降了 30%。AA 单独的 Intelligence Index 评估在该测试中报告为 25%。这些数字来自不同的报告评估环境；现有材料无法分离每项软件或配置差异的确切贡献。不应以厂商的 41% 取代 AA 的 25%，也不应将任一结果呈现为 ML4 的普遍性能。

FrontierCode 的差异同样改变了排名：Mistral 的图表将其 19.7% 置于 DeepSeek 的 19.3% 之前，而 AA 报告 ML4 为 15%，落后于 DeepSeek 的 29% 和 GLM-5.3 的 22%。因此，独立评估并不支持将 Mistral 的 FrontierCode 第一名声明扩展到该公司自己的对比之外。

Mistral 还报告了一项 Surge Code 盲测偏好研究，其中 ML4 在与 GLM-5.3 和 Kimi K3 的对比中赢得 64%，与 DeepSeek V4.1 Flash 对比赢得 56%，与 Claude Opus 5.5 对比赢得 22%。这是另一种类型的证据——所报告对比中的人类偏好——而非任务完成基准的替代品。

我们最初的报道聚焦于 Mistral 初步的 62% DeepSWE 结果。最新材料并未用更新的 DeepSWE 分数取代该数字，而且无论是 Terminal-Bench 还是编码综合指数都无法与之直接比较。

“但它真正面向的是从家里的开发者一直到企业里的开发者，”Janiewicz 说。她表示，组织还可以让 ML4 适应自己的软件，这使得内部工作上的性能成为公开测试之外的又一考量。

中国以外微弱领先，效率提升更为显著

正式版 26 分的 Intelligence Index 得分提供了与预览版在 v5 上 25 分的同口径对比。这是温和的提升，而非能力大幅跃升的证据。Artificial Analysis 认为，token 效率提升和幻觉减少才是更实质的变化。

地理层面的区分也需要背景说明。ML4 相对 Muse Spark Open 的一分优势使其成为 AA 评估中在中国以外开发的最高分开放权重模型。全球范围内有七个开放权重模型得分更高。DeepSeek V4.1 Flash 1017 和 GLM-5.3 以 32 分领跑该组，MiMo-V2.6-Pro 得分为 30。在所有模型中，当前排行榜显示，所列高强度配置下 Gemini 4 Carbon 为 59 分，Claude Opus 5.5 为 58 分，GPT-6 Astra 为 57 分。

AA 指出，编码和智能体知识工作是 ML4 与开放权重领跑者之间差距的主要来源。除了较低的 FrontierCode 结果外，ML4 在 AA-Briefcase 上得分为 1349 Elo，而 DeepSeek 为 1570，GLM 为 1504。不过，面对 Muse Spark Open，AA 强调 Terminal-Bench 是 ML4 的最大优势：在 Intelligence Index 评估中为 25% 对 8%。

效率的改善更为显著。AA 报告称，正式版每项 Intelligence Index 任务平均输出 82,000 个 token，而预览版为 135,000 个——减少 39%。得分高于 ML4 的七个开放权重模型每任务消耗 113,000 至 225,000 个输出 token。这使 ML4 在能力与输出 token 用量之间取得了有用的平衡，但并不能证明它是最便宜的选择。

那些仅计输出的平均值，与编码指数每任务 850 万总 token 数（包含输入、缓存及输出 token）是两回事。两项评估使用的任务集也不同。将它们合并会产生误导性的效率比较。

还有一点历史层面的区别。Artificial Analysis 在 10 月初亮相时给预览版打了 38 分，当时 Intelligence Index v5 尚未推出更难的评估，也未将使用私有测试或保留答案的比例提高至 60%。早先的 38 分与今天的 26 分属于不同量表；相关的 v5 对比是 25 分对 26 分。

幻觉减少，但事实准确性仍然有限

在 AA-Omniscience v1.1 上，Artificial Analysis 报告已发布 ML4 的幻觉率为 28%，低于预览版的 41%，与 Muse Spark Open 的结果持平。这是该测试上 13 个百分点的降幅。

其准确率得分仍为 26%，而 Ling 3.1 Flash 1019 为 27%，DeepSeek V4.1 Flash 1017 为 40%，Muse Spark Open 为 42%。因此，追平 Muse 的幻觉率并不意味着追平其事实准确性。

AA-Omniscience 评估事实知识以及模型处理不确定性的方式。对企业买家而言，这一区别很重要：一个产生较少无依据答案的系统可能更易于监督，但它仍需正确回答足够多的相关问题。该基准并不能确立 ML4 在公司专有记录上的准确性，也不能确立其在每个生产工作流中的可靠性。

网络安全访问权限是宣传主张的核心

Artificial Analysis 证实 ML4 在高推理设置下的 Cyber Index 得分为 51，在当前开放权重模型中排名第三。max 设置下的 DeepSeek V4.1 Flash 1017 以 57 分领跑，其次是 56 分的 MiMo-V2.6-Pro。

分项结果显示了为什么该排名比单一安全分数更为细致：

网络安全评估 Mistral Large 4, high DeepSeek V4.1 Flash 1017, max MiMo-V2.6-Pro
CyberGym-E2E-AA 79% 76% 79%
DeepsecBench-AA 15% 25% 26%
CWE-Bench-AA 58% 69% 63%

来源：Artificial Analysis 对其 10 月 29 日评估的后续跟进。

ML4 在 CyberGym 上击败 DeepSeek 并追平 MiMo，但在另外两个分项上落后于两者。因此，早先 Mistral 幻灯片中的 79% 结果得到了 AA 当前 CyberGym 评估的支持；但这并非完整 Cyber Index 的得分。相比笼统的网络安全领先声明，这一新的细分数据为安全团队提供了更有用的依据，便于其选择与自身工作相关的测试。

Mistral 还报告了在来自 JailbreakBench、StrongREJECT 和 AgentHarm 的恶意网络提示上 96.6% 的平均拒绝率。这些是公司在指定测试上自行报告的测量数据。同一篇博客承认该模型存在协助真实攻击的可能性，并表示 Mistral 正在修改其防护栏。

除公开权重发布之外，Mistral 表示，Orange Cyberdefense 等企业设计合作伙伴正在获得面向高级安全工作流的专用变体的预览访问权限。该访问需要经过审查并辅以合同保障，测试仅限于受控环境中自有或获得明确授权的系统。

Janiewicz 说，客户在考虑涉及其他模型和智能体的威胁时，越来越多地要求防御能力。她主张发布权重的理由是：组织应当能够自行塑造围绕这些能力的控制措施。

“我们相信，客户保护自己的最佳方式是能够获取这些模型，并能够自行建立和定制其中一些防护栏，”她说。

这回答的是“由谁设定控制措施”的问题，而非证明一个公开分发的模型不会被改用于攻击。在采访中，Janiewicz 并未提供证据表明下游用户无法移除或修改防护措施。其权衡在于：给予合法运营者更多控制权，同时也削弱了原始提供商对后续部署的控制。

对企业安全团队而言，潜在的好处是连续性：本地运营的模型可以在安全事件期间保持可用，而无需远程服务逐项批准请求。相应的责任则是测试其行为并限制其对生产系统的访问。下载权重本身并不能证明一个自主安全智能体可以安全运行。

更多企业基准测试，但基线各异

公开博客补充了早先材料中编码和网络安全结果之外的测量数据：

评估项目 Mistral 引用的早期检查点 新结果 变化说明
Finch 金融工作流 预览版：67.4% 73.3% 上升 5.9 个百分点；在图表中落后于 Kimi K3 的 77.3%
BrowseComp 网络研究 早期监督微调检查点：75% 84.5% 较该早期检查点上升 9.5 个百分点，该检查点未被确认为 10 月预览版

VentureBeat 最初的报道将早期 Finch 结果四舍五入为 67%；现已发布的版本提供了更精确的基线和更新后的分数。这些是基准测试上的进步，而非客户收入或生产力的测量。B3 结果同样衡量的是对所测试攻击的抵抗力；它并不能证明每个部署的智能体无需额外控制措施即可安全运行。

定制化才是生意所在——可测量的成果仍需时间

Janiewicz 反复谈及这样一些行业：专有信息和专业化流程决定了模型是否有用。她指向制造业和金融服务业，并引用 BMW 碰撞测试工作和 HSBC 客户验证工作流，作为 Mistral 所瞄准的更广泛企业问题的例证。这些例子不应被误认为是新发布的 ML4 在生产部署中的已发表结果。

“我们构建的模型是为我们所服务的行业量身定制的，”她说。

她描述了两条定制路线：技术能力强的组织可以自行使用 Mistral Forge，而其他组织则可以与 Mistral 的部署工程师和应用科学家合作。无论哪种情况，商业方案都包含使模型适应客户运营所需的工作。

这一区别有助于解释 Mistral 的战略。

例如，一家制造商可能不太关心哪个系统能回答最广泛的问题，而更关心它是否能可靠地解读公司的工程文档、遵守访问限制并在经批准的计算环境中运行。一家银行可能优先考虑对自身客户记录和审查流程的一致处理。这些是该方法的潜在应用场景，而非此次发布所确立的已测量成果。

Janiewicz 说，一些现有客户正看到成本下降。“我们的许多客户，尤其是在过去六个月里，真的开始看到他们的账单在减少，”她说。

但当被具体问及可归因于 ML4 的业务成果时，她表示整合新模型的系统仍在构建中，有意义的运营测量还需要更长时间。

已发布的博客包含来自 Belfius、ABN AMRO、ASML 和欧洲航天局等组织以及安全合作伙伴的定性背书。

这些声明描述的是兴趣、测试和部署可能性；它们并未提供可用于计算部署投资回报的量化 ML4 专属业务成果。

对 Mistral 而言，新证据强化了一个具体主张：可下载的权重、有竞争力的编码智能体配置，以及一个比其自身预览版便宜得多的模型。这种组合是否胜过更便宜、得分更高的替代方案，取决于组织的工作负载、部署需求以及想要掌控模型的原因。
