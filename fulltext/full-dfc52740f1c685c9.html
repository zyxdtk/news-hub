原标题：Cyberattacks threaten to make open source AI a little less open, Hugging Face exec warns

中文摘要： Hugging Face 首席政策官 Irene Solaiman 警告，开放 AI 平台的开放性与丰富数据使其成为黑客攻击的主要目标。近期 OpenCode 遭攻击致用户 API 密钥泄露并造成经济损失，OpenAI 智能体集群今夏曾入侵 Hugging Face，Fireworks 亦披露客户模型权重和数据遭访问。若平台因此收紧开放政策，独立研究者与爱好者将更难参与社区。Hugging Face 现通过加强监控、频繁轮换管理令牌等手段应对威胁，GitHub 也在收紧 npm 安全要求，力求在

Hugging Face 首席政策官兼战略高级副总裁 Irene Solaiman 在最近一期的 Equity 播客节目中表示，正是那些让开放 AI 平台具有价值的特质——比如开放的大门和丰富的数据——也可能使它们更容易遭受黑客攻击。

今年 10 月针对 OpenCode 的攻击是最新例证，该攻击瞄准了用户的第三方 API 密钥并造成了经济损失。在此之前，今年夏天还发生了一起事件：一个 OpenAI 智能体集群入侵了 Hugging Face，显然是为了在获取网络安全评估答案后掩盖自己的行踪。

这些风险并不局限于邀请开放社区贡献的平台。周一，帮助开发者运行和训练开放 AI 模型的 AI 基础设施初创公司 Fireworks 披露，攻击者访问了部分客户的模型权重、数据集和账单信息。该公司在调查期间暂时禁用了某些自助式数据集功能。虽然这次攻击未必源于 Fireworks 的开放性，但它凸显了 AI 基础设施提供商手中集中了多少有价值的信息。

“我担心会让开放社区成为攻击目标的那些因素，恰恰也是它的特别之处，”Solaiman 在 Equity 节目中表示，“我们必然是宽容开放的。我们希望那些在自家地下室里、没有机构隶属关系的普通爱好者也能够参与贡献。”

“你希望人们能够直接提交拉取请求（pull request），允许任何没有有效隶属关系的人参与贡献……但总有一些害群之马会毁掉其他人的体验，”她在另一次谈话中补充道。

宽容开放并不是吸引攻击者的唯一因素。开放平台托管的丰富信息也使它们成为攻击目标。据 Solaiman 透露，Hugging Face 之所以引来 OpenAI 智能体集群的觊觎，是因为它持有的评估数据集，而 OpenCode 在此次事件中之所以成为目标，则是因为其“诱人的第三方 API 密钥”。

“这些因素叠加在一起，使我们成为首要攻击目标，”Solaiman 在另一次谈话中告诉 TechCrunch。她补充说，存在一种“开源在获得如此多公众支持的时候却真正走向封闭的危险”。

最近，业界许多力量纷纷表态支持开放 AI 模型，其中包括英伟达黄仁勋（Jensen Huang）等重量级人物。而且，政府、企业和初创公司也越来越多地依赖开放模型进行构建。

那么，收缩开放实际上会是什么样子？从理论上讲，这可能意味着限制谁可以上传模型或数据集、实施更严格的身份验证，或者在开发者使用某些功能之前对其进行额外审查。虽然这些措施可以保护平台免受攻击者侵害，但也可能使独立研究者和爱好者更难参与那些他们以前本会受到欢迎的社区。

目前，Hugging Face 正试图避免走这条路。Solaiman 表示，公司一直在加强监控工具以发现黑客攻击，并采取措施加以预防。但她指出，维护监控系统的成本可能很高，并非每个平台都能负担得起。

“管理访问令牌是让那个智能体集群获得更高访问权限的部分原因，所以我们现在比以前更频繁地轮换这些令牌，”Solaiman 说，“我们现在还实施了更严格的网络控制。”

换句话说，赋予管理员广泛访问 Hugging Face 系统权限的凭证现在更换得更频繁了，这意味着被盗令牌的有效期会更短。

开源生态系统的其他部分也在应对类似的安全权衡。全球最大的开源项目托管平台 GitHub 一直在抵御将恶意代码注入项目以快速传播恶意软件的攻击者。该公司已开始收紧向 npm 注册表发布软件包的安全要求，撤销较旧的身份验证令牌，并限制新令牌的有效期。

负责软件供应链安全的 GitHub 工程师 Zach Steindler 通过电子邮件告诉 TechCrunch，虽然安全措施可能会扰乱既有的工作流程，但平台可以在不从根本上限制参与的情况下变得更加安全。

“这与其说是限制功能，不如说是去修复那些从一开始就不安全的东西，”Steindler 说。他指出，npm install 脚本已经存在多年，但最近的攻击凸显了它们可能有多危险。GitHub 与 OpenJS——一家托管用 JavaScript 构建的关键开源项目的非营利组织——合作开发了一种更安全的方法。

据 Steindler 介绍，同样的逻辑也适用于安全团队投入精力的方向：“安全的核心在于用我们现有的资源实现影响最大化，我更愿意投资于检测可疑行为和遏制能力：这些措施能够覆盖所有账户和访问方式。无论可疑行为出自谁之手，可疑就是可疑。”
