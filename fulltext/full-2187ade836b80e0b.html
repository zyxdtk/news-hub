摘要
随着上下文在检索、工具使用和多轮交互中不断累积，智能体 LLM 流水线面临日益增加的推理成本。为了控制延迟，部署中通常会压缩输入，但这会降低任务准确性。推测解码（SD）能够无损地加速生成，但它假设起草器和验证器共享相同的上下文，这使得 SD 无法解决准确率与开销之间的权衡。我们提出了 AsymSpec，一个打破这种对称性的非对称推测解码框架：轻量级起草器读取完整输入，而大型验证器在压缩视图上运行。起草器通过对 logits 的对比性 $\delta$-融合来引导验证器，并由一个感知散度的接受门进行调节，以保持验证稳定性和高草案接受率。在四项智能体能力和两个端到端智能体基准上进行评估，AsymSpec 平均达到了全上下文准确率的约 90%，在孤立的文本能力上以 0.2-0.3 倍的计算成本实现了 1.3-1.7 倍的吞吐量提升。这些结果表明，当压缩丢弃了关键推理信号时，非对称上下文访问恰好能带来实质性的收益。

1 引言
现代 LLM 部署越来越多地以智能体流水线的形式运行——检索文档 (Lewis et al., 2020; Gao et al., 2023; Wu et al., 2025a) 、调用工具 (Yao et al., 2023; Schick et al., 2023) 、维护多轮对话和记忆 (Sirdeshmukh et al., 2025; Zhang et al., 2025b; Wu et al., 2025b) 以及处理多模态输入 (Liu et al., 2023) 。这些设置在随着每一步增长的上下文上发出重复的 LLM 调用。随着检索到的段落、工具观察结果和交互历史的累积，前向传播成为主要的延迟瓶颈，使得上下文长度成为生产环境中推理开销的主要驱动因素。

为了控制这种开销，部署中通常会压缩上下文 (Pan et al., 2024b) ：RAG 流水线总结检索到的段落，工具使用智能体仅传递 API 签名而不是完整文档，多模态工作流提供简短描述而不是原始图像。压缩降低了服务成本，但系统性地丢弃了对任务准确性至关重要的细粒度细节。因此，部署面临严格的准确率-开销权衡：要么承受全上下文生成的高昂延迟，要么接受显著的性能下降。

推测解码（SD） (Leviathan et al., 2023; Chen et al., 2023) 已成为加速 LLM 推理的标准方法：轻量级起草器提出候选 token，由大型验证器并行检查，保证在目标分布下无损生成。尽管对起草器架构 (Li et al., 2024c; Cai et al., 2024; Li et al., 2024b) 和推测循环中的对比 logit 融合 (Yuan et al., 2023) 进行了大量改进，但所有现有的 SD 方法都共享一个基础约束：起草器和验证器处理相同的输入 token。SD 加速固定的目标分布而不改变目标模型看到的内容；一旦验证器被压缩，SD 只能加速压缩后的模型——它无法恢复压缩移除的内容。要么两个模型都支付全上下文成本，要么两者都继承压缩损失。

我们的关键观察是结构性的计算不对称：每步延迟主要由大型验证器主导，而轻量级起草器增加的开销可以忽略不计。仅压缩验证器可以捕获大部分延迟节省，但标准 SD 无法利用这一点，因为它强制要求相同的输入。我们用 AsymSpec 打破了这种对称性，这是一个明确解耦上下文访问的非对称推测解码框架。验证器严格在压缩视图上运行以提高效率，而起草器读取完整输入以重建丢弃的信息。我们通过对比机制实现这种恢复：起草器处理两种上下文视图，减去它们的输出分布可以消除起草器与上下文无关的偏好，从而分离出未压缩输入提供的信息增益。这个增益信号 $\delta$ 被融合到验证器的 logits 中，并由无参数的上下文散度接受（CDA）门进行调节。通过根据上下文散度缩放注入强度，该门保持了稳定的验证和高接受率。由于只有起草器处理完整输入，AsymSpec 在压缩验证器的延迟下恢复了全上下文推理保真度，并扩展到跨模态设置（例如，原始图像上的视觉-语言起草器引导描述上的纯文本验证器）。

贡献。
1. 我们提出了 AsymSpec，一个上下文非对称推测解码框架：验证器在压缩视图上运行，而起草器消耗完整输入，开辟了一个对称 SD 无法达到的运行点——压缩的成本和接近上限的准确率，并自然扩展到跨模态设置。
2. 两个耦合机制实例化了该框架：一个同模型跨上下文 $\delta$-融合，它抵消起草器容量偏差以隔离上下文增益信号；以及一个无参数的上下文散度接受（CDA）门，它无需按数据集调整即可限制引导强度。
3. 在四项智能体能力和两个端到端智能体基准测试中，AsymSpec 在 0.2-0.3 倍计算和 1.3-1.7 倍吞吐量下恢复了约 90% 的全上下文准确率。

2 相关工作
2.1 推测解码
推测解码（SD） (Leviathan et al., 2023; Chen et al., 2023) 通过让轻量级起草器提出候选 token 并由大型验证器并行验证来加速自回归生成，通过拒绝采样保留目标分布。后续工作改进了起草器质量（EAGLE (Li et al., 2024c; Li et al., 2024b; Li et al., 2025b) ，Medusa (Cai et al., 2024) ），或通过分层或稀疏 KV 推测来降低长上下文推理延迟（TriForce (Sun et al., 2024) ，MagicDec (Sadhukhan et al., 2025) ）。所有这些方法都向起草器和验证器提供相同的输入 token，即使 KV 缓存结构在不同阶段有所不同。这种对称性阻止了 SD 利用长上下文解码中固有的计算不对称性。我们在 §3 放宽了这一约束，让两个模型在不同的上下文视图上运行而不破坏推测验证循环。

2.2 上下文压缩
上下文压缩是减少长上下文推理开销的标准机制 (Lv et al., 2026b) 。硬提示方法根据重要性修剪 token（LLMLingua (Jiang et al., 2024; Pan et al., 2024b) ），软上下文方法学习紧凑潜在表示（Gist Tokens (Mu et al., 2023) ，ICAE (Ge et al., 2024) ），KV 缓存技术直接在缓存状态上操作（StreamingLLM (Xiao et al., 2024) ，SnapKV (Li et al., 2024a) ）。综合调查 (Li et al., 2024d) 记录了这些方法。在这些文献中，准确率下降被视为不可避免的代价。我们将任何压缩器视为黑盒，并在 §3 展示全上下文起草器如何系统地恢复丢弃的信息，将压缩从有损捷径转变为可控的效率旋钮。

2.3 对比解码和 Logit 融合
对比解码 (Li et al., 2023b) 通过从专家模型中减去业余模型的 logits 来提高生成质量，放大专家特定的信号。该原理已扩展到多步推理 (O’Brien and Lewis, 2023) ，并作为推测对比解码（SCD）集成到推测循环中 (Yuan et al., 2023) 。然而，SCD 及其变体在单个共享上下文上运行，使用 logit 差异来弥合模型容量差距。同样的减法原理也被用于通过 CapCal (Lv et al., 2026a) 移除与内容无关的位置先验，通过 LICD (Zhang et al., 2026b) 减轻推理链压缩后的语言惯性，以及通过 CoSteer (Lv et al., 2025) 将局部上下文引起的偏好转移到远程模型。总之，这些方法将 logit 差异构建为信号隔离器。AsymSpec 将这种观点引入推测验证：两个 logit 项都来自全上下文和压缩上下文视图下的同一个起草器，因此 $\delta$ 隔离的是上下文增益而不是模型容量差距。我们在 §3.2 中形式化了这种跨上下文传输及其偏差消除特性。

2.4 非对称和多模态推测
最近的工作开始探索非对称配置。RAPID (Chen et al., 2025) 采用了逆向设计：检索截断的起草器引导全上下文验证器以注入外部知识，在全上下文延迟下优先考虑全上下文保真度。Speculative RAG (Wang et al., 2025b) 从检索文档子集中起草答案候选，然后进行验证。并发的多模态 SD 方法（SpecVLM, Spec-LLaVA, ViSpec (Huang et al., 2025; Huo et al., 2025; Kang et al., 2025) ；MASSV (Ganesan et al., 2025) ）专注于视觉 token 预填充加速或将两个模型保持在单一模态内。SD2 (Berdoz et al., 2026) 通过根据验证器信号调节起草器来反转引导方向。SpecSteer 使用非对称本地-云推测，将私有个性化上下文保留在本地起草器中，同时利用云规模的推理 (Lv et al., 2026c) 。在这些设计中，非对称性服务于个性化和隐私、检索分配或特定模态的加速。AsymSpec 则使用非对称上下文访问来改变效率运行点：丰富输入的起草器补偿严格压缩的验证器，在压缩验证器延迟下恢复准确率（§3；设计空间比较见表 8）。

2.5 智能体设置中的推测
大多数 SD 工作针对单轮生成；长上下文变体 (Sun et al., 2024; Sadhukhan et al., 2025) 扩展了该范围，但仍停留在提示级别。最近面向智能体的方法通过对高级动作序列 (Ye et al., 2025) 、工具调用 (Nichols et al., 2025) 或计划 (Hua et al., 2024) 进行推测来加速决策循环。DynaThink 同样通过在请求级别在快速和深思熟虑的推理之间进行选择来降低推理成本 (Pan et al., 2024a) 。这种动作和请求级别的机制与 token 级别的解码引擎正交。我们在 §5.3 中证明，AsymSpec 可以与实时智能体循环组合，每当工具输出或检索到的上下文在线压缩时，提供 token 级别的准确率恢复。

图 1：AsymSpec 推测步骤。

3 方法
3.1 问题设置
设 $L$ 为大型验证器，$S$ 为轻量级起草器（$|S|\ll|L|$ ）。任务提供完整提示 $x_{\text{full}}$ ；黑盒压缩器产生压缩视图 $x_{\text{comp}}$ ，且 $|x_{\text{comp}}|\ll|x_{\text{full}}|$ 。每步延迟主要由 $L$ 的前向传播主导，该传播随上下文长度超线性扩展。这种开销结构定义了两个基线运行点：
• $L(\cdot\mid x_{\text{full}})$ ：峰值准确率，但在智能体循环中延迟过高；
• $L(\cdot\mid x_{\text{comp}})$ ：低延迟，但准确率因压缩而降低。
仅压缩 $L$ 的输入可以捕获大部分延迟节省，而 $S$ 在 $x_{\text{full}}$ 上的额外前向传播仍然比验证器在 $x_{\text{full}}$ 上节省的前向传播便宜得多。标准推测解码无法利用这种不对称性，因为它强制要求相同的上下文访问。AsymSpec 明确解耦了两者：$L$ 严格在 $x_{\text{comp}}$ 上运行以提高效率，而 $S$ 读取 $x_{\text{full}}$ 以重建丢弃的信息。

3.2 对比 $\delta$-融合
每个推测步骤在当前序列上执行三次前向传播（图 1a）：
1. 增强起草器：$S(x_{\text{full}})$ 产生 logits $a$ 并采样 $K$ 个草案 token $d_{1:K}$ 。
2. 基础起草器：$S(x_{\text{comp}})$ 在相同的 $K+1$ 个位置产生 logits $b$ 。
3. 验证器：$L(x_{\text{comp}})$ 并行评分所有 $K$ 个草案，产生 logits $t$ 。
我们在 logit 空间中定义上下文增益信号：
$$\delta_{i}\;=\;a_{i}-b_{i},\vskip-5.0pt \quad (1)$$
其中 $a_{i},b_{i}\in\mathbb{R}^{|\mathcal{V}|}$ 是每个位置的 logits。从 $a_{i}$ 中减去 $b_{i}$ 移除了起草器与上下文无关的偏好，分离出由额外上下文引起的偏移。在拒绝草案时，$\delta_{i}$ 被融合到验证器的分布中：
$$d^{\prime}{i}\;=\;\arg\max\bigl(t{i}+\beta\,\delta_{i}\bigr),\vskip-5.0pt \quad (2)$$
其中 $\beta\in[0,1]$ 控制引导强度。这种注入将验证器的预测转向全上下文输入本应产生的内容，而无需 $L$ 关注 $x_{\text{full}}$ 。

3.3 上下文散度接受（CDA）
当完整和压缩视图差异很大时，固定的接受阈值 $\gamma$ 通常会过度拒绝草案并浪费上下文增益信号。我们用一个与上下文散度成比例放宽的阈值替换它，将每个位置的散度 $D_{i}$ 实例化为 Jensen-Shannon 散度（JSD）：
$$\begin{gathered}\gamma_{\text{eff}}(i)\;=\;\gamma\cdot\exp(-D_{i}),\ D_{i}\;=\;\mathrm{JSD}\bigl(\mathrm{softmax}(a_{i})\,|\,\mathrm{softmax}(b_{i})\bigr).\end{gathered}\vskip-5.0pt \quad (3)$$
我们特别选择 JSD 是因为它有严格的上限，这保证了 $\gamma_{\text{eff}}\in[\gamma/2,\gamma]$ 而无需裁剪或引入额外的超参数；指数形式是乘法组合公理的唯一解（推导见附录 A）。大的 $D_{i}$ 表示上下文引起的散度（不是容量引起的）——这些是压缩验证器最可能低估有用全上下文草案的位置，因此在那里放宽接受是合适的。草案 token $d_{i}$ 被接受当且仅当：
$$[\mathrm{softmax}(t_{i})]{d{i}}\;>\;\gamma_{\text{eff}}(i)\cdot[\mathrm{softmax}(b_{i})]{d{i}}.\vskip-5.0pt \quad (4)$$
在第一次拒绝时，我们从公式 2 发出 $\delta$-融合的 token（图 1b）。当 $\beta=0$ 和 $\gamma=1$ 时，该机制退化为 $x_{\text{comp}}$ 上的标准验证。严格的范围 $\gamma_{\text{eff}}\in[\gamma/2,\gamma]$ 保持了各位置接受标准的稳定性，即使在严重压缩下也能保持可预测的草案接受率。与标准 SD 不同，AsymSpec 不保留严格的目标分布；它是一个为贪婪发射校准的推测式引导方案。

3.4 跨模态扩展
跨模态非对称性直接源于该框架。由于起草器和验证器共享输出 token 词汇表 $\mathcal{V}$ ，信号 $\delta\in\mathbb{R}^{|\mathcal{V}|}$ 和 $\gamma_{\text{eff}}\in\mathbb{R}$ 完全在输出侧计算（公式 1、3、4 和 2），并且无论起草器的输入模态如何都保持良好定义：视觉-语言起草器可以将原始图像作为 $x_{\text{full}}$ 处理，而纯文本验证器将描述作为 $x_{\text{comp}}$ 读取，推测循环保持不变。视觉编码器每个请求运行一次，其输出缓存在起草器的 KV 侧，因此跨模态 $\delta$ 的每 token 开销在长生成中消失，并渐近匹配纯文本 AsymSpec 的开销。通过推测引擎的起草器预填充路由视觉嵌入是一个非平凡的 vLLM 修改，详见附录 E。

4 实验
4.1 任务和压缩协议
我们在现实压缩下评估了四个孤立的智能体能力：长上下文多跳问答（LongBench (Bai et al., 2024) ，使用其三个多跳子集）、多轮指令遵循（MultiChallenge (Sirdeshmukh et al., 2025) ）、工具使用（API-Bank (Li et al., 2023a) ）和多模态推理（MathVista (Lu et al., 2024) ）。端到端智能体性能在 GAIA (Mialon et al., 2024) 和 SimpleQA (Wei et al., 2024) 上测量，通过 smolagents (Roucher et al., 2025) 框架编排。我们在所有基准测试中执行严格的非对称协议：验证器仅接收压缩视图（例如，每轮 LLMLingua-2 (Pan et al., 2024b) 总结或 API 签名），而起草器读取完整的未压缩输入。数据集统计、压缩比和指标总结在表 9 中；每个基准测试的压缩管道和工具执行协议见附录 B。

2: 生成的序列 $y$
3: $y\leftarrow[\,]$
4: while 生成未完成 do
5: 从 $S(x_{\text{full}}\oplus y)$ 自回归采样 $d_{1:K}$ （重用 KV 缓存）；令 $a_{1:K+1}$ 为对应位置的 logits
6: $b_{1:K+1}\leftarrow S(x_{\text{comp}}\oplus y\oplus d_{1:K})$ 在相同位置
7: $t\leftarrow L(x_{\text{comp}}\oplus y\oplus d_{1:K})$
8: for $i=1$ to $K$ do
9: $\delta_{i}\leftarrow a_{i}-b_{i}$
10: $D_{i}\leftarrow\mathrm{JSD}(\mathrm{softmax}(a_{i})\,|\,\mathrm{softmax}(b_{i}))$
11: $\gamma_{\text{eff}}(i)\leftarrow\gamma\exp(-D_{i})$
12: end for
13: accepted $\leftarrow$ True
14: for $i=1$ to $K$ do
15: if $[\mathrm{softmax}(t_{i})]{d{i}}>\gamma_{\text{eff}}(i)[\mathrm{softmax}(b_{i})]{d{i}}$ then
16: $y\leftarrow y\oplus[d_{i}]$
17: else
18: $y\leftarrow y\oplus[\arg\max(t_{i}+\beta\delta_{i})]$
19: accepted $\leftarrow$ False ; break
20: end if
21: end for
22: if accepted then
23: $y\leftarrow y\oplus[\arg\max(t_{K+1})]$
24: end if
25: end while

4.3 指标
我们报告每个基准测试官方指标的任务准确率（表 9）。效率沿两个轴报告：加速比是单个加速器上全上下文上限的实际运行时间 token 吞吐量比率（表 11；附录 F）；FLOPs 是每步预填充计算量，由上限的仅验证器预填充归一化，根据 Qwen3 架构和测量的上下文长度计算，遵循 Kaplan et al. (2020) （每个基准的核算见表 5）。加速比衡量实现的延迟，而 FLOPs 衡量能量/计算成本——两者出现分歧是因为在 30B+ 规模下解码是内存带宽受限的。

4.4 基线
我们与五个参考进行比较：
(1) 下限：仅 $L$ 在 $x_{\text{comp}}$ 上；
(2) 上限：仅 $L$ 在 $x_{\text{full}}$ 上；
(3) SD：共享上下文上的标准推测解码，在 $x_{\text{full}}$ 上评估（$x_{\text{comp}}$ 上的 SD 在结构上与下限匹配）；
(4) SCD (Yuan et al., 2023) ：在共享上下文上将验证器 logits $t$ 与业余 logits $b$ 结合（这里 $L,S$ 都在 $x_{\text{comp}}$ 上），以 SD 速度弥合模型容量差距（详情见附录 B）；
(5) RAPID (Chen et al., 2025) ：逆向非对称设计（$S$ 在 $x_{\text{comp}}$ 上，$L$ 在 $x_{\text{full}}$ 上）——在全上下文计算下保留验证器的目标分布。在跨模态设置中，纯文本上限未定义；我们使用单独的 VL 起草器作为参考边界。所有吞吐量和计算指标均归一化到全上下文上限。

我们首先评估三个基于文本的智能体能力（§4）。表 1 报告了准确率和效率，LongBench 分为 hotpotQA / 2WikiMQA / MuSiQue 多跳子集。AsymSpec 占据了对称方法无法达到的运行点：它在保留压缩验证器延迟的同时提供接近上限的准确率。它达到了全上下文性能的 87-99%，将下限-上限差距缩小到 0.9-9.7 个残差点。残差差距是结构性的：验证器仍然受输入限制，无法仅从 logit 引导中完全重建多跳推理链或复杂的工具依赖关系。完整的 $K$ 和起草器大小扫描推迟到 §6。

基线比较强化了该设计的优势。标准 SD 保留了目标分布，但在结构上受限于对称上下文：它要么继承下限的准确率（在压缩输入上），要么继承上限的延迟（在完整输入上）。SCD 在所有五个单元格中保持或低于下限（例如，LongBench 平均 43.8 vs. 下限 45.0；API-Bank 56.7 vs. 57.7），表明当专家和业余者都读取压缩视图时，单上下文对比融合无法恢复压缩引起的损失——该增益特定于我们的非对称构造。RAPID 的逆向非对称设计（起草器在 $x_{\text{comp}}$ 上，验证器在 $x_{\text{full}}$ 上）达到了接近上限的准确率，但计算成本也接近上限（1.01× FLOPs）；它针对相反的权衡点，在 AsymSpec 运行的计算轴上处于劣势。在完整上下文上单独运行起草器降低了成本，但在 4B 模型缺乏足够容量的重推理子集上急剧下降（按大小排列的数字见附录 H）。AsymSpec 通过保留 32B 验证器的推理同时将上下文恢复卸载给轻量级起草器来弥合这些极端。

这些增益直接与压缩引起的信息丢失相关，而不是特定于任务过拟合。在 MultiChallenge 上，压缩几乎是无损的（上限-下限差距为 3.0 个点），AsymSpec 产生的改进微乎其微（23.5 vs. 23.4）。这种惰性支持了该机制仅在压缩丢弃关键信号时激活的诊断。我们通过在 LongBench 上扫描验证器的截断预算同时保持起草器在完整段落上（表 2）来进一步验证连续轴上的这一诊断。恢复的准确率随压缩严重程度单调缩放：在 500-token 预算下，AsymSpec 恢复了下限-上限差距的三分之二以上；在 12k token 时，随着验证器接近未压缩上限，增益自然消失。稳定的接受率（0.851-0.855）表明差距变化是由于信息恢复，而不是不稳定的验证。

5.2 多模态推理
我们接下来评估跨模态扩展，其中视觉-语言起草器处理原始图像，而纯文本验证器读取描述和 OCR 文本。由于纯文本验证器无法消耗图像，全上下文上限未定义；我们使用单独的 VL 起草器作为参考边界。表 3 报告了 MathVista 上的结果。AsymSpec 达到了 53.9% 的总体准确率，比对称 SD 高出 10.1 个点。按任务分解揭示了明显的互补模式。在几何问题求解（GPS）上，描述和 OCR 文本已经捕获了必要的结构，产生的增益最小。在视觉问答（VQA）和图形问答（FQA）上，起草器提供视觉基础而验证器提供因果逻辑，将准确率分别比下限提高了 10.0 和 16.7 个点。与单独的 VL 起草器相比的剩余差距（53.9 vs. 60.5%）是结构性的：纯文本验证器无法完全内化像素级线索。尽管如此，结果表明拥有固定纯文本验证器的组织可以将其扩展到视觉推理任务，而无需重新配置多模态基础设施。实现这些增益需要通过推测引擎正确路由视觉塔嵌入；没有这些补丁的消融将准确率降至 30.5%（实现细节见附录 E）。

5.3 端到端智能体循环
我们最后在上下文累积并在线重新压缩的实时智能体循环内评估 AsymSpec。表 4 报告了通过 smolagents 编排的 GAIA 和 SimpleQA 上的结果。AsymSpec 在 GAIA 上达到 24.2%，在 SimpleQA 上达到 65.0%，匹配或超过可用的全上下文参考（GAIA 的每个子集见表 4），并且随着上下文累积没有下降。GAIA 的总体增益掩盖了不同的子集动态：在仅 Web 的 ReAct 循环上，压缩强制更紧凑的历史编码，有利于消耗 token 的规划；在文件附件子集上，起草器的全文本访问补偿了验证器的 2000-token 截断。SimpleQA 由于压缩空间极小（1.33× token 比率）而有利于上限。在这两个基准测试中，该方法保持了稳定的草案接受率（0.88-0.90，表 13），证实在线重新压缩不会侵蚀验证质量。

计算效率直接跟踪压缩严重程度。GAIA 应用 1.91× 的每轮压缩比，产生 0.78× 的全上下文 FLOPs。SimpleQA 较轻的 1.33× 压缩产生 0.80×。这种线性关系符合核心设计前提：验证器的预填充减少与上下文缩短成比例，而起草器的双重传递仍然是较小的组件。在实时智能体循环中如同在静态基准测试中一样，压缩空间可靠地预测了准确率恢复和效率提升。

6.4 鲁棒性
除了核心机制外，广泛的扫描（附录 H 和 G）证实了 AsymSpec 在三个轴上的鲁棒性。
超参数不敏感性：性能在 $\beta\in[1.0,2.0]$ 和 $\gamma\in[0.4,0.7]$ 之间持平，无需按数据集校准。
压缩器不可知论：交换验证器的压缩器（总结、LLMLingua-2、截断）产生稳定的 63-70% 下限-上限恢复；SCD 在每个单元格中都降至下限以下。
起草器容量：$\leq 0.6$B 的模型无法提取可靠的上下文增益信号；$\geq 1.7$B 是实际最小值。
跨族可移植性。
为了测试该机制是否依赖于共享模型族，我们在 LongBench 上评估了双向 Qwen-Llama 配对。遵循 Timor et al. (2025) ，异构运行将生成限制为 109,566 个字符串相同的 token 加上配对的特殊 token，并将 $\delta$ 从起草器词汇表映射到验证器。Qwen3-4B 起草器将 Llama-3.3-70B 验证器的压缩上下文下限从 50.6 提高到 58.4 F1，而 Llama-3.2-3B 起草器将 Qwen3-32B 下限从 45.0 提高到 47.1。这些配对证明了可行的跨族转移，恢复程度因模型对而异；附录 D 报告了完整比较。

7 结论
我们引入了 AsymSpec，打破了标准推测解码的对称上下文约束。通过允许轻量级起草器读取完整上下文并通过对比 $\delta$-融合引导压缩上下文验证器，它以一小部分的计算成本实现了接近上限的准确率。从经验上看，AsymSpec 在文本任务上仅使用 0.2-0.3 倍的 FLOPs 就恢复了约 90% 的全上下文性能。至关重要的是，准确率增益随压缩损失的严重程度单调缩放，为从业者提供了一个清晰、可预测的标准，以判断在生产智能体流水线中何时需要非对称引导。

局限性
AsymSpec 的恢复机制从根本上受限于压缩视图中保留的信息以及起草器提取它的能力。在近乎无损的任务上，该方法正确地产生了最小的干预，表明它不会引入虚假幻觉或过拟合到未压缩的上下文。对于跨模态设置，准确率恢复的上限受限于模态转换的保真度（例如，图像到描述的质量）；集成更丰富的多模态起草器以直接处理原始像素以及验证器仍然是未来工作的一个令人兴奋的方向。

跨族 $\delta$-融合需要明确的词汇表和 logit 空间对齐。我们的 Qwen-Llama 研究证明了两个共享 token 对齐配对的可行性，但观察到的恢复因模型对而异；更广泛的转移可能需要更丰富的映射。

AsymSpec 还需要访问验证器 logits，因此不适用于仅公开生成文本的专有 API。此外，我们的评估侧重于确定性解码（$\tau=0$）。这是一个深思熟虑的设计选择而不是约束：智能体工作流严格要求可重现、可解析的结构化输出（例如，JSON、工具调用），其中随机采样（$\tau>0$）从根本上降低了流水线可靠性。将 CDA 边界推广到随机采样（例如，通过 Gumbel-Softmax 松弛）是一个有前途的理论扩展。

最后，在端到端智能体循环中，实际运行时间延迟是 LLM 推理、工具执行和网络 I/O 的复合。虽然 AsymSpec 严格优化了 LLM 推理瓶颈——随着上下文扩展到计算受限状态，这成为主导——但它被设计为在生产智能体框架中与系统级优化（如 I/O 重叠和异步工具执行）高度互补。

附录 A
CDA 门的推导
我们要求每个位置的有效阈值 $\gamma_{\text{eff}}$ （§3.3）满足：
• $\gamma_{\text{eff}}(0)=\gamma$ （无散度 $\Rightarrow$ 标准 SD 规则）；
• $\gamma_{\text{eff}}$ 连续且在 $D_{i}$ 中单调非减；
• 独立散度信号上的乘法组合（独立上下文偏移应该乘法组合，映射独立概率）：
$\gamma_{\text{eff}}(D_{1}+D_{2})=\gamma_{\text{eff}}(D_{1})\,\gamma_{\text{eff}}(D_{2})/\gamma$ 。
定义 $f(D)=\gamma_{\text{eff}}(D)/\gamma$ ，第三个性质是柯西型乘法方程 $f(D_{1}{+}D_{2})=f(D_{1})f(D_{2})$ 。在连续性下，这固定 $f$ 为指数形式 $f(D)=\exp(-D/T)$ 对于某个尺度 $T>0$ ，给出
$$\gamma_{\text{eff}}(i)\;=\;\gamma\cdot\exp\bigl(-D_{i}/T\bigr). \quad (5)$$
为了在不引入超参数的情况下消除 $T$ ，我们将 $D_{i}$ 实例化为 Jensen-Shannon 散度。设 $Z_{i}\sim\mathrm{Bernoulli}(\tfrac{1}{2})$ 为选择 $x_{\text{full}}$ vs. $x_{\text{comp}}$ 的潜在指示器，$X_{i}$ 为起草器的下一个 token。则 $D_{i}=I(X_{i};Z_{i})$ ，即 token 与上下文源之间的互信息。由于对于任何二元信道 $I(X_{i};Z_{i})\leq H(Z_{i})=\ln 2$ ，$D_{i}$ 是普遍有界的。设 $T=1$ 将尺度吸收到界限中，得到公式 3 并保证 $\gamma_{\text{eff}}\in[\gamma/2,\gamma]$ 而无需裁剪。

附录 C
与自适应和智能体 LLM 系统的更广泛联系
智能体记忆和深度研究系统。
长期智能体将交互历史组织为持久记忆或分配额外计算用于搜索和细化。代表性系统将对话记忆结构化为句子图 (Wu et al., 2025c) ，为深度研究开发强化学习基础 (Li et al., 2025a) ，通过步骤级反馈细化搜索轨迹 (Zhang et al., 2026a) ，将多模态文档解析与深度研究统一 (Dong et al., 2026) ，或使搜索强度适应问题难度 (Shi et al., 2025) 。这些方法在 token 级解码器之上运行；当它们积累的证据被压缩时，AsymSpec 提供了互补的解码底物。
小-大协作和推理时引导。
相邻的训练时机制使用师生对齐、保真度控制的递归自我改进，或基于奖励动态和数据效用的自定进度课程 (Zhang et al., 2024; Zhang et al., 2026d; Zhi et al., 2026) 。其他工作使用后续可能性作为对齐信号 (Zhang et al., 2025a) ，跨模态的轻量级引导模块 (Feng et al., 2025) ，或用于高效信息提取的设备上专家模型 (Wen et al., 2025) 。这些方法优化训练或特定任务模块，而 AsymSpec 在解码期间协调小型起草器和大型验证器。
结构化和多模态接口。
基于检索的具有可控生成的知识集成 (Shen et al., 2026) ，参数高效的多模态融合 (Liang et al., 2022) ，检索增强的模式适应 (Liang et al., 2025a) ，以及参数化工具模式 (Liang et al., 2025b) 提供了向语言模型公开结构化或多模态信息的互补方式。AsymSpec 不规定这些上游接口；它在生成时跨其丰富和紧凑视图传输信息。
推荐作为智能体长上下文工作负载。
以用户为中心和交互式推荐越来越多地结合设备-云智能体、多步规划和持久或终身用户历史 (Zhang et al., 2026c; Yu et al., 2025; Zhou et al., 2026) 。这些工作负载激发了通过检索和细化高效处理长行为上下文 (Xu et al., 2025; Shen et al., 2024) ，跨域表示转移 (Zhang et al., 2025d) ，实时用户特定推理 (Xie et al., 2025) ，以及可扩展的长序列架构 (Ye et al., 2026; Pan et al., 2025) 。相关工作还统一了检索和排名 (Zhang et al., 2025c) ，开发了基于 LLM 的生成推荐 (Wang et al., 2025a) ，并研究了大型模型设计和缩放行为 (Guo et al., 2024; Shen et al., 2025) 。这些应用和架构级别的进步与 AsymSpec 正交，后者通过非对称起草器-验证器上下文分配优化 token 级生成。
