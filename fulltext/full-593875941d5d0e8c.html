摘要

GUI 网页智能体需要真实且可交互的环境，并且这些环境在评估和训练期间都保持稳定。实时网站评估存在内容变化、访问限制以及认证工作流覆盖不足等问题，而现有的用于训练的合成环境往往缺乏功能深度和视觉保真度。我们提出 WebHarbor，这是一套由 153 个可执行、Docker 化的网站环境组成的套件，可在确定性控制下忠实重建真实世界网页服务的视觉界面、内容和功能工作流。我们通过任务驱动的人机协作来构建 WebHarbor：环境随着新任务扩展其功能范围而进化，编码智能体实现所需的更改，人类贡献者审计视觉保真度、功能正确性和任务有效性。最终套件包含 3,518 个任务，涵盖多步骤和认证后工作流，而这些正是现有工作往往未能覆盖的。除了可靠的评估之外，WebHarbor 还为高性价比的强化学习（RL）提供了高保真的合成网页环境。我们证明，在 WebHarbor 中通过 RL 训练的 Qwen 4B 级别 GUI 智能体能够泛化到未见任务，并在四个基准上与领先的开源 GUI 网页智能体表现相当。代码和数据已公开于 https://github.com/aiming-lab/WebHarbor。

1 引言

由具备多模态能力的大语言模型（LLM）驱动的网页智能体通过解读渲染后的网页并借助浏览器交互来完成任务（Deng 等，2023；He 等，2024；Zheng 等，2024；Qin 等，2025）。它们的进步依赖于能够支持可靠评估和训练的环境。评估需要稳定且可复现的结果，而强化学习（RL）还需要可执行的状态转换和可重复的重置（Qi 等，2025；Bai 等，2024；Wei 等，2025；Lai 等，2025）。实时网站提供了真实的界面，但内容变化、机器人检测和地域限制会破坏实验控制。此外，实时网页基准很少涵盖认证工作流，尽管这类工作流对许多日常用户请求非常重要（He 等，2024；Xue 等，2025）。在我们的实验中，约 38% 的 Online-Mind2Web 任务被机器人检测拦截，22% 的 WebVoyager 任务因网站变化而过时。这些失败给评估引入了不受控的变异，也使智能体无法学习隐藏在认证之后的众多工作流。

理想的替代方案应当将真实的视觉观察、功能性交互和持久的认证状态与离线执行和可靠重置结合起来。实现这种平衡颇具挑战：商业网站包含海量的内容和功能，完整重建并不现实；而视觉上相似的复制品可能缺乏正确的搜索、账户管理、预订或交易逻辑。即使表面上功能正常的环境也可能暴露捷径、省略合理的替代操作，或通过界面泄露答案，从而损害任务有效性。我们的目标是：在确保可复现性以及对评估和 RL 的实用性的同时，既匹配智能体所观察到的内容，又匹配网站对其操作的响应方式。

人工构建的基准（如 WebArena 和 VisualWebArena）提供了可复现的应用，但覆盖的网站数量非常少（Zhou 等，2024；Koh 等，2024）。手动重建真实网站可以提高保真度，但需要大量人力且难以扩展。最近的方法可以自动合成多样化的功能性网站（Zhou，2026；Zhang 等，2026；Wu 等，2026；Cao 等，2026；Wang 等，2026a）。然而，这些方法通常强调新生成的"世界"，而非针对真实网站、以任务为导向的重建，或者只提供有限的多模态内容和认证后功能。表 1 总结了这一覆盖差距：现有的已发布环境无法同时提供广泛的网站覆盖、离线执行、图像丰富的内容和基于登录的工作流。图 1 的案例研究直观展示了视觉保真度方面的局限：被比较的生成环境要么遗漏了目标网站，要么简化了其布局、商品层级和特定产品的图像。

为填补这一差距，我们引入 WebHarbor——一套从 WebVoyager 和 Online-Mind2Web 所覆盖的网站空间中选取的 153 个可执行网站环境。WebHarbor 采用任务条件化构建：目标任务规定了每个环境必须支持的页面、数据和交互工作流，从而为重建大型网页内容提供了可控的范围。随后，编码智能体通过一套标准化的环境构建技能来实现前端、后端、数据库和视觉内容。人类贡献者检查渲染后的网站，执行目标工作流，并修正视觉保真度、功能正确性、数据真实性和任务有效性方面的缺陷，而修复实现由编码智能体完成。这一人机协作过程产出了 Docker 化的环境，它们无需访问目标服务即可运行，可重置到受控的初始状态，并支持公开的信息寻求任务以及认证背后的深度工作流。最终资源包含 3,518 个任务，涵盖信息检索、账户管理、预订和交易，既可用作稳定的基准，也可用作可执行的训练环境。

概括而言，我们的贡献有三方面：

（1）我们提出 WebHarbor，一套包含 153 个可控网页环境和 3,518 个任务的套件，其认证工作流和持久状态变化是实时网页基准中普遍缺失的。

（2）我们开发了人机协作构建流程，将编码智能体的任务条件化网站实现与人类对视觉保真度、功能正确性和任务有效性的迭代审计相结合，直至审核通过。

（3）在三个网页智能体基准上的实验表明，在 WebHarbor 中通过 RL 训练的 Qwen 4B 智能体能够泛化到未见任务，并在实时网页基准上取得与领先开源网页智能体相当的性能。

2 相关工作

GUI 网页智能体 网页智能体已经从基于 HTML 或无障碍表示进行操作的系统（Zheng 等，2024；He 等，2024），发展为整合网页理解、推理与规划、动作定位和序列决策以执行用户指令的多模态智能体（Gur 等，2024；Koh 等，2025；Putta 等，2024）。虽然先前的工作主要关注从演示中学习（Hong 等，2024；Cheng 等，2024；Xu 等，2024；Qin 等，2025；Wang 等，2025），但最近的方法如 WebRL、WebAgent-R1 和 OpenWebRL 进一步通过基于环境交互的强化学习来优化智能体策略（Qi 等，2025；Wei 等，2025；Yang 等，2026）。这些方法凸显了对能够提供真实视觉观察、可执行状态转换和可复现初始条件的环境的需求。WebHarbor 正是为 GUI 网页智能体在多样化网站界面上的高效训练和可靠评估提供了这样的基础设施。

网页智能体基准 现有基准在网站覆盖、交互深度和实验控制之间进行权衡。MiniWoB++ 和 WebShop 为浏览器交互和购物提供了受控环境（Liu 等，2018；Yao 等，2023），而 Mind2Web 扩大了网站覆盖范围，但依赖缓存快照，限制了交互式探索（Deng 等，2023）。实时网页基准如 WebVoyager、Online-Mind2Web 和 DeepShop 在多样化网站上提供真实交互（He 等，2024；Xue 等，2025；Lyu 等，2025）。Online-Mind2Web 即便有定期的任务更新，仍然容易受到网站变化、机器人检测、CAPTCHA 以及网络或地域限制的影响，同时对认证和状态更改工作流的覆盖有限。相比之下，自托管基准如 WebArena、VisualWebArena 和 WorkArena 在受控设置下支持复杂交互（Zhou 等，2024；Koh 等，2024；Drouin 等，2024）。然而，其有限的网站覆盖、重量级部署和昂贵的环境重置使重复评估和在线 RL 训练变得复杂。REAL 提供了 11 个真实网站的确定性副本并支持持久状态变化，但从预认证状态开始（Garg 等，2025）。WebHarbor 以 153 个图像丰富且可执行的网站和 3,518 个任务弥合了这些权衡，同时涵盖信息寻求以及认证和状态更改工作流。其轻量级的 SQLite 架构支持快速重置，便于可复现评估和跨大量网站的可扩展在线 RL 训练。

合成网页环境 最近的工作通过环境和任务合成来扩展网页智能体训练。WebArena-Infinity 和 InfiniteWeb 从文档、规范和视觉参考中合成功能性浏览器环境（Zhou，2026；Zhang 等，2026）。AutoWebWorld、CUA-Gym 和 WebForge 进一步探索了可验证的状态转换、任务生成和难度控制（Wu 等，2026；Wang 等，2026a；Yuan 等，2026）。GUI-GENESIS 和 VeriEnv 将真实应用重建为可用于智能体训练的可执行环境（Cao 等，2026；Chae 等，2026）。然而，仅依靠编码智能体的合成流程无法保证视觉保真度和现实的工作流深度。相比之下，WebHarbor 强调对真实网站进行以任务为导向的重建，并具备人工验证的质量。我们覆盖了 WebVoyager 和 Online-Mind2Web 的所有网站，并将任务覆盖扩展到复杂的认证和状态更改工作流。这些任务指导编码智能体迭代地实现和扩展网站功能，而人类审阅者则审计视觉保真度、功能正确性和任务有效性。这种方法产出了 153 个图像丰富的环境，将广泛的网站覆盖与人工审计的质量相结合，支持可靠的评估和可扩展的 RL 训练。

3 WebHarbor

给定一个目标网站和一组相关任务，WebHarbor 会重建一个可执行的本地环境，保留任务相关的界面、内容和状态转换。我们将这一过程称为"停靠"（docking）：用本地资产、种子状态和受控重置来替代实时依赖，同时保留可识别的视觉和功能行为。图 2 展示了这一迭代工作流。目标任务定义重建范围，编码智能体使用可复用技能实现前端、后端、数据库和视觉内容，人类贡献者审计生成的环境。人类反馈指导编码智能体修复视觉和功能缺陷。随着新任务揭示出缺失的功能或捷径，同一过程会不断扩展和完善环境，同时保持确定性执行和可靠重置。

图 2：WebHarbor 概述。 实时网站提供目标界面和工作流，但引入访问障碍（CAPTCHA、网站变化、访问限制、人工验证、结果不稳定、认证）。 目标任务界定全栈重建范围，然后编码智能体实现和进化每个环境，而人类审阅者审计视觉保真度、功能正确性和任务有效性直至批准。 Docker 化环境支持确定性和快速的状态重置以及基于证据（答案+截图）的奖励，用于评估和 RL 训练。

3.1 任务驱动的停靠

考虑到 Amazon 的产品目录或 YouTube 的视频库等服务的庞大规模，重建整个商业网站是不切实际的。因此，我们采用任务驱动的重建过程，将每个环境的范围限定为其目标任务所需的功能和内容。每个任务规定了入口页面和终端页面、可观察的实体和属性、所需的浏览器操作以及持久状态变化。这些要求定义了任务相关的"支持面"：实现真实交互所需的页面、路由、图像内容和数据。

我们从 WebVoyager 的 15 个网站和 643 个任务入手（He 等，2024），其实时网页评估已因网站变化而变得不太可靠。随后，我们将覆盖范围扩展到 Online-Mind2Web 中的所有网站（Xue 等，2025），但排除了其原始任务，因为这些任务主要关注信息寻求而非认证和状态更改工作流。对于这些网站，人类贡献者识别核心功能区域，LLM 利用其对常见网页服务的知识将其扩展为候选工作流。人类贡献者随后从功能覆盖、可行性和交互深度等方面审查和完善这些任务。最终的任务涵盖账户管理、预订、购买、收藏项目和其他持久操作。任务驱动的范围界定还通过明确定义必须复现的观察和状态转换，促进了视觉和功能保真度。除任务完成本身外，环境还保留了自然的导航路径和周边内容，包括可防止琐碎捷径的合理替代项和近似干扰项。这种方法在保留评估和训练所需交互复杂性的同时，控制了重建工作量。153 个网站的完整列表见附录中的表 19 和表 20。合成提示见附录 B。

3.2 技能驱动的合成与进化

任务驱动的停靠定义了环境应支持什么，而技能驱动的合成与进化则将这些需求转化为可执行的离线网站。对于每个网站，编码智能体首先通过渲染的浏览器探索目标服务，记录其任务相关的页面层级、导航路径、URL 模式、交互控件和视觉外观。渲染后的 DOM 和解析出的资产 URL 为重建客户端渲染页面和延迟加载内容提供了参考。在这些观察和可复用构建技能（见附录 B）的指导下，编码智能体构建一个由 SQLite 支持的独立 Web 应用，并捆绑本地视觉资产。这些资产要么从目标网站下载，要么用从公共来源获取的视觉上相似的替代品替换。随后通过反复执行目标任务来完善初始重建。对于每个任务，编码智能体与渲染后的界面交互，并找出第一个不受支持的观察或状态转换。缺失的页面促使其创建新的路由和视图，不完整的工作流需要额外的表单处理器和持久状态更新，内容不足则推动新增数据库记录和任务相关的替代项。每次修订后，环境都会重置到种子状态，并重新执行完整的工作流。这一迭代过程使得越来越多样化和更具挑战性的任务能够不断扩展和完善环境，直到所有目标工作流都能通过可见界面端到端完成，并产生预期的持久状态变化。

3.3 人在回路的迭代改进

自动化合成对视觉保真度、长程行为和任务有效性的质量控制较弱。编码智能体可能完成了目标工作流，但周边界面却视觉不准确、功能浅显或被人为地简化。在我们对 26 个网站的试点研究中，13 个环境存在视觉或资产缺陷（例如图像与描述不匹配），14 个存在损坏或浅显的交互（例如无响应的按钮）。这类问题在长程环境构建过程中常被编码智能体忽视，却很容易被人类审阅者发现。图 1 展示了全自动重建如何可能捕捉到粗略的网站布局，同时却简化了功能或遗漏了重要的视觉内容。

为提高环境质量，我们引入了人在回路审计和迭代协作。具体而言，我们将人类参与组织为两种角色。贡献者负责指定目标网站和高层功能需求，并在构建过程中指导编码智能体。指定的审阅者随后将重建的环境与目标网站进行对比，端到端地执行每个任务，检查任务可行性、预期的交互序列以及视觉和功能保真度。审阅者将识别出的缺陷转化为给编码智能体的可操作请求，并重新评估受影响的工作流，直至审核通过。平均而言，每个环境经历 2–3 轮审查，每轮耗时 1–2 小时。审阅者还开发特定任务的验证器和评判标准，为 LLM-as-a-Judge（Zheng 等，2023）或 agent-as-a-Judge（Zhuge 等，2024）定义评分准则。所有贡献者和审阅者均为列入作者名单的社区志愿者。

3.4 环境套件

4 实验

4.1 实验设置

RL 训练与基线 我们使用 OpenWebRL-4B（Yang 等，2026）作为主要基线，因为它是通过在实时网站上进行在线 RL 训练的 SOTA 开源智能体。合成环境套件 WebArena-Infinity、AutoWebWorld 和 CUA-Gym 未发布训练好的检查点。OpenWebRL 在 704 个实时网站的 2,102 个 WebGym 任务上训练（Bai 等，2026）。我们的镜像训练策略从相同的 SFT 检查点 OpenWebRL-4B-SFT 出发，并复用相同的多模态多轮 GRPO（MM-GRPO）目标和 ReAct 风格的 GUI 框架。在每一轮中，策略观察当前状态截图、文本动作反馈和完整的交互历史，并通过浏览器工具（如 MOUSE_CLICK）执行操作。对于 WebHarbor 训练，每个实例通过 Orchard 接口（Peng 等，2026）在隔离且确定性种子的沙箱中运行。表 7 测得的延迟表明，我们的环境支持高效的有状态回合切换和及时验证，适合大规模 RL 训练。为保持训练框架和智能体配置一致，我们保留了 OpenWebRL 的格式门控 GPT-4.1 最终答案奖励。我们将环境和任务作为主要差异变量进行隔离，研究离线合成环境中的 RL 能否媲美实时网站上的 RL。附录 E 提供更多细节。

基准 我们在四个基准上评估泛化能力。Online-Mind2Web 包含 100 多个实时网站上的 300 个真实任务，提供广泛的网站和用户领域覆盖（Xue 等，2025）。WebVoyager 包含 15 个热门实时网站上的 643 个任务（He 等，2024）。WebArena 包含可复现的自托管网站中的复杂任务（Zhou 等，2024），我们使用 Sun 等（2025）和 Wang 等（2026b）采用的 226 个任务子集。为测试认证工作流，WebArena-NL 禁用自动登录，并在任务描述中提供账户凭据。我们还在 WebHarbor 测试集上进行评估，该测试集不受实时网页干扰，且覆盖多样化的网站。

5 结论

我们提出了 WebHarbor，一套包含 153 个可执行网站环境和 3,518 个任务的完整套件，将真实世界的网页交互带入可控的离线环境。通过任务驱动的停靠和人机协作，这些环境不断进化以支持更丰富的功能，同时保持视觉保真度和任务有效性。最终套件提供广泛的网站覆盖、图像丰富的界面和复杂的认证工作流，轻量级的状态重置支持可靠评估和高效 RL 训练。我们的保留测试集进一步为评估现有基准经常忽视的 GUI 网页智能体能力提供了稳定的基准。此外，我们证明完全在 WebHarbor 中训练的 Qwen 4B 智能体能够有效泛化到未见任务，并在四个基准上取得与领先开源网页智能体相当的性能。我们相信 WebHarbor 能够促进 GUI 网页智能体环境的可复现评估、可扩展 RL 训练和持续的社区驱动进化。

局限性

作为面向 GUI 网页智能体的环境套件，WebHarbor 存在若干局限性。

（1）WebHarbor 是对目标网站的模仿而非等同，我们的结论受限于所提出的任务和人类审阅者的保真度审计。客户端繁重的行为（如交互式地图、实时行情）被近似处理或替换为静态替代品。

（2）尽管对 WebHarbor 测试集进行了评判一致性检查，脚本化验证器和基于模型的评判者仍可能忽略有效的替代解决方案或细微的失败。这是网页智能体评估的常见局限，需要在未来工作中采用更稳健的评估协议。

（3）为验证我们合成的离线环境的训练价值，我们主要与 OpenWebRL（Yang 等，2026）——一个通过在实时网站上进行在线 RL 训练的 SOTA 开源智能体——进行比较。我们没有系统地探索替代的监督微调（SFT）数据、通用框架（如 OpenCode（anomalyco，2025）和基于 CLI 的智能体）或其他 RL 算法。受计算资源限制，我们仅训练了一个 4B 模型，将跨模型家族和规模的泛化留待未来工作。

伦理声明

WebHarbor 旨在支持 GUI 网页智能体评估和训练的开放研究。环境构建涉及参考真实网站，并从原始服务或公开可用的替代来源获取视觉资产。我们承认网站设计、商标和视觉资产可能受第三方权利约束。我们的环境仅用于研究和基准测试，而非对原始服务的商业复制。重用或再分发这些材料的研究人员应遵守适用的许可和知识产权。通过将网站重建为自包含环境，WebHarbor 使智能体能够在不反复访问或修改实时服务的情况下练习复杂交互。认证工作流、账户管理、预订和交易都在受控的本地状态中运行，降低了在实时网站上实验的相关风险。然而，合成环境无法完全捕捉真实网站的多样性和动态性，包括不断演进的内容、个性化界面、访问限制和外部依赖。在 WebHarbor 中的优异表现并不能保证在实时网站上的同等表现或安全行为。面向现实部署的智能体需要额外的验证和适当的保障措施。我们希望可获取、可复现的环境能够支持更透明、更负责任的 GUI 网页智能体研究。

阶段 1：克隆目标网站 技能：clone-website
目标：基于观察到的网站构建一个新的可执行 WebHarbor 镜像，包含浏览器捕获的证据、对齐的真实资产、可用的交互、认证状态和确定性种子数据。目标网站：<REAL_URL>。网站别名：<SLUG>。

构建镜像：抓取真实的目标图像和品牌资产；记录稳定的实体键、上游 URL、本地路径和 SHA-256 摘要。实现 Flask 和 SQLAlchemy 模型、密码认证、搜索、账户状态、实体详情页面和所需的 CRUD 流程。构建 Jinja2 模板以复现目标网站的层级、排版、导航和响应式行为。每个可见的过滤器、选项卡、排序控件、表单和持久操作都必须更改有意义的状态。

阶段 2：设计任务契约 技能：design-tasks
目标：为 sites/<SLUG>/tasks.jsonl 创建 15-20 个基准任务。将每个任务视为自然语言指令、镜像界面、其数据库状态和验证器之间的可执行契约。逐字复用适用的 WebVoyager 任务，然后添加基于目标网站真实工作流的任务。

阶段 4：环境加固 技能：harden-env
目标：沿四个维度审计每个可执行任务：答案去泄露、近似干扰项、目录广度和跨字段一致性。环境必须在保持任务可行性的同时，防止智能体通过可见答案、单一明显结果或不一致数据获得成功。
A. 去除答案泄露：使用任务的自然查询进行搜索，在打开任何详情页之前检查渲染的 DOM 和截图。从项目名称中移除约束值、从摘要中移除答案文本、移除预计算比较、可见列表计数、问题式标题、固定的答案标注和揭示算法的标签。检查所有已知的泄露模式，包括模糊搜索淹没答案桶、将目标排在首位的排序顺序，以及复现任务措辞的预策划查找表。将所需证据移入一致的规格、描述、历史或详情视图。
B. 添加近似项：对于每个任务，保留 1-3 个完全匹配项，并添加至少五个符合类别但恰好违反一个约束（如价格、尺寸、颜色、日期、品牌、位置、可用性或所需功能）的合理项。保持完全匹配密度不高于 50%。替代项必须看起来真实并支持有意义的比较；不要添加任意噪声。
C. 扩充目录：要求每个自然查询从多个相关子类别返回至少六个项目。用看起来真实的实体、有用的元数据和对齐的图像扩充薄弱的类别页面和搜索索引。保留目标网站的层级，使更广的覆盖增加决策复杂性而不改变预期答案。
D. 强制一致性：将结构化规格视为事实来源。每当字段更改时，重新生成每个依赖的描述、功能要点、标签、变体选项、可用性标签和显示的摘要。确认列表卡片、详情页、账户记录和交易历史一致。除非真实网站将约束值用作产品标识，否则不要将其放入名称中。
逐任务验证：使用 Playwright 运行自然查询，捕获结果，在渲染的 DOM 中搜索答案，计算完全匹配和近似项，验证结果多样性，通过界面点击正确的详情页，并比较所有相关字段。记录所有四个维度的通过/失败证据。静态模板审查和 HTTP 探测不能替代此检查。
最终不变量：每次数据更改后重建，重置网站，并确认运行时和种子数据库的字节相等。重新运行认证和状态更改工作流，检查桌面和窄视口，并验证所有必需的图像都能解码。以零答案泄露、每个任务至少五个近似项、广泛的搜索结果、一致的字段和不变的任务可解性结束。
