Salesforce 正在详细介绍其 Agent Fabric 平台的下一阶段计划，包括旨在识别故障 AI 智能体并启动纠正措施的评估功能，以及扩展的发现能力和此前已公布的支出与治理控制功能。

10 月 27 日的公告为 Agent Evals 设定了 11 月进入 beta 测试、2027 年 1 月正式发布（GA）的目标，该功能由 MuleSoft 于 9 月在其年度 Dreamforce 大会上首次公布。公告还概述了 API Evals——一款用于测试智能体所依赖的软件连接的即将推出的工具，启动了自定义智能体扫描器的 beta 测试，并将评估触发的智能体紧急停止开关（kill switch）安排在 1 月。

对于企业买家而言，这份公告将即将推出的功能与扩展功能和现有工具结合在一起。基础版紧急停止开关已于 9 月正式发布，而 MuleSoft 在整个夏季概述了预算控制、支出仪表板和节省 token 的功能。9 月的公告还描述了将失败的评估与纠正措施相连接。

更宏观的主张是缩短从发现问题到解决问题之间的距离。一家公司可能知道某个智能体会产生错误答案或消耗过多资源，但仍需要确定其所有者、导航到另一个平台并获得暂停它的许可。

在接受 VentureBeat 采访时，Salesforce 旗下 MuleSoft 高级副总裁兼总经理 Andrew Comstock 描述了该公司方案背后的常见问题。

“我的智能体太多了。这些技术完全不同。彼此之间无法通信。所有东西都在孤岛中运行。”Comstock 在描述促成 Agent Fabric 诞生的客户挑战时说道。

即使客户是在竞争对手的平台上构建这些智能体，Salesforce 也希望对其进行管理。

“我要强调，这不是 Salesforce 专属的。它覆盖一切。”他说。

Agent Evals 迈向 beta 测试

Salesforce 已在 9 月的 Dreamforce 大会上介绍过 Agent Evals，包括生成测试、根据成功标准衡量结果以及将失败与修复措施相连接。

10 月的公告补充了发布日期，并描述了评估如何从部署前的测试扩展到检查生产环境中的智能体、语言模型和模型上下文协议（Model Context Protocol）服务器。其目标是识别超出组织阈值的行为并启动适当的响应，包括在政策要求时执行审批步骤。

在 Salesforce 的示例零售场景中，将智能体迁移到更便宜的模型会导致订单状态问题的回答变差。评估检测到这种下降，并启动一个流程来隔离该智能体、在需要时获得批准，然后对其进行修改和重新测试。这是一个假设性的工作流程，而非已报道的客户实际结果。

Comstock 表示，评估还可以帮助公司执行对智能体沟通方式的期望。例如，一个面向客户、本应听起来积极乐观的智能体，不应该突然变得尖酸刻薄。

即将推出的 API Evals 工具解决系统的另一个部分：从 API 规范生成功能和性能测试。两款评估产品都计划于 11 月进入 beta 测试，并于 2027 年 1 月正式发布。

紧急停止开关已经存在；评估触发的干预即将到来

紧急停止开关本身并不是本次公告的新内容。MuleSoft 于 6 月引入了这一概念，并于 9 月正式发布了基础能力。它使用网关控制来阻止受治理的流量，可以选择将干预范围限定在请求、会话、智能体或租户级别，并在之后恢复访问。

这一区别很重要：通过网关阻止智能体的访问，并不一定会终止托管它的外部平台上运行的每一个进程。

Salesforce 现在列入 1 月路线图的是“触发式智能体紧急停止开关”（Triggered-Agent Kill Switch），将检测到的问题与策略驱动的干预相连接。9 月的评估预览已经讨论过将失败与修复措施关联；10 月的公告为这一触发能力提供了更具体的发布目标。

对于买家来说，实际区别在于：一个是已经可用、用于停止受治理活动的控制手段，另一个是将评估结果与该响应相连接的即将推出的机制。

现有发现功能获得自定义扩展

智能体发现功能同样早于今天的公告。MuleSoft 于 4 月介绍了其智能体扫描器，作为在受支持环境中识别智能体的一种方式。

今天进入 beta 测试的新增功能是“自定义智能体扫描器”（Custom Agent Scanner），旨在将发现能力扩展到内部系统、防火墙后的环境以及更多平台。正式发布计划在 1 月。

Comstock 表示，该注册表并不要求客户将智能体迁移到 Salesforce。

“我要强调，我们不会移动智能体；智能体仍在原地运行。”他说，“我们只是提取指针，这样你就可以获得覆盖所有智能体的统一注册表。”

管理员连接相关环境，并将其元数据导入共享注册表。Comstock 表示，客户无需使用 Salesforce 自有的智能体平台 Agentforce 即可使用 Agent Fabric。

他还指出，这种需求更多取决于公司智能体部署的多样性，而非其规模。一家使用多种智能体框架和供应商的企业，即使不是大型企业，也可能遇到协调问题。

支出控制建立在夏季路线图之上

公告还重点介绍了 FinOps 仪表板、Model Wallet 预算以及旨在减少模型消耗的策略。

这些并非全是新引入的功能。MuleSoft 的 8 月版本概述介绍了模型访问、成本优化、钱包和仪表板改进。9 月对 Model Wallet 的说明描述了按供应商或模型设置美元或 token 预算，并可设定每日、每周或每月限额。

这些控制功能解决了一个常见的矛盾：单个开发者可能为了更快完成任务而选择昂贵的模型，而组织则需要了解总体的账单。

Comstock 表示，可见性不应仅限于减少总支出，还应延伸到识别造成这些支出的团队和项目。

“所以这不仅仅是降低成本。这显然是其中一部分，但也要确保你能将其与真正推动组织变革的正确团队和项目关联起来。”他说。

Salesforce 的 10 月版本介绍了语义缓存、载荷压缩和响应裁剪等优化技术。该公司声称在测试场景中可减少多达 75% 的 token 消耗。这是厂商的测试结果，并不能保证客户的整体 AI 账单会相应减少。

跨供应商网关策略同样早于今天

Salesforce 还重点强调了 Open Policies，用于在联邦化网关（包括 Azure、Apigee 和 Kong）之间应用治理。

这一底层能力并非今天首次亮相。MuleSoft 于 9 月介绍了 Open Policies，而其 10 月的版本说明记录了 Universal Policies 更名为 Open Policies 以及相关增强功能。

对企业来说，吸引力在于能够在其已经运营的基础设施上应用统一的控制。实际覆盖范围仍取决于受支持的集成以及流量通过可执行控制的位置。

Comstock 将这种治理视为更广泛部署的前提条件。

“如今，治理实际上是你的加速器，因为你处于受治理状态。你可以更好地回答问题。你会感到更有信心、更安心，这让你走得更快。”他说。

MuleSoft 列出 2000 美元起价，但评估功能定价仍不明确

Salesforce 公开的 MuleSoft 定价页面列出了更广泛产品组合每月 2000 美元的起价，并使用 Mule Credits 在各项功能之间通用。

该页面上的智能体管理产品包含 Agent Fabric 的功能，如发现、编排、治理和预算，但引导买家联系销售团队。因此，2000 美元这一数字不应被视为本次公告中所述特定 Agent Fabric 配置的已确认独立价格。

定价材料概述了预付积分包、年最低消费 5 万美元的预付承诺选项以及自定义定价的无限制选项。它没有为 Agent Evals 或 API Evals 设定单独的公开价格，也没有提供足够的细节来计算特定评估工作负载的成本。

Comstock 在采访中用作示例的 2000 美元项目预算是假设性的，并非产品价格披露。

微软、ServiceNow 和 OpenAI 竞逐企业智能体监管市场

Agent Fabric 处于一个不断增长的市场中，即跨组织管理智能体，尽管竞争产品以不同方式组合监管和执行。

在企业行政管理方面，Microsoft Agent 365 是一个相近的对比对象。微软描述了智能体注册表、访问和生命周期控制、分析功能，以及与 Entra、Defender 和 Purview 等产品的安全集成。

ServiceNow 的 AI Control Tower 同样瞄准跨供应商的发现、观察、治理、安全和度量。其公布的功能包括对风险活动的控制，以及对 AI 成本和业务成果的可见性。

OpenAI Frontier 是另一个相关的竞争对手，其主张更为广泛，包括构建和运营智能体、连接业务系统和上下文、评估性能以及管理权限。重叠之处在于企业智能体管理，尽管其范围与 Agent Fabric 强调的在现有环境中治理智能体并不完全相同。

Anthropic 的 Claude Managed Agents 在基础设施层面有所重叠，但对比性不那么直接。它提供运行智能体的托管设施，包括执行环境和编排。Agent Fabric 的核心卖点是发现并治理可能继续在别处运行的智能体。

Anthropic 公布的 Managed Agents 运行时价格为每活跃会话小时 0.08 美元，另加适用的模型和工具费用。这与 MuleSoft 的产品组合起价或协商达成的 Agent Fabric 合同没有直接可比性。

这些区别是对各厂商已公布能力的解读，而非声称这些产品可以互换。根据集成支持和现有基础设施的不同，一家企业可能既需要智能体运行时，也需要单独的治理层。

买家现在能使用什么——以及还有什么在前方

本次公告中最直接可用的新增功能是自定义智能体扫描器的 beta 测试。基础版紧急停止开关和重点介绍的支出控制功能已经正式发布。

Agent Evals 和 API Evals 计划于 11 月进入 beta 测试，并于 2027 年 1 月正式发布。自定义扫描器也计划于 1 月正式发布，与触发式智能体紧急停止开关同步。

对于评估这份公告的买家来说，核心问题是 Salesforce 能否在他们实际使用的智能体之间，将发现、测试、支出可见性和可执行的干预连接起来。即将发布的版本将决定这一工作流程中有多少能够作为一个互联系统运行。
