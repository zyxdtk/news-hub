推出 Claude Opus 5

📅 2026-07-24 📄 Anthropic 🔗 原文链接

原标题：Introducing Claude Opus 5

中文摘要： Claude Opus 5 今日发布，以一半价格提供接近 Fable 5 的前沿智能。在编码、知识工作和科研评估中创下新纪录，具备更强的自主验证和迭代能力。它在保持与前代相同成本的同时大幅提升性能，并成为 Anthropic 迄今为止最对齐、最安全的模型，在网络安全和生物学领域设有严格防护。

Claude Opus 5 今日起可用。这是一个深思熟虑且积极主动的模型，以一半的价格接近了 Claude Fable 5 的前沿智能。
在 Frontier-Bench 和 GDPval-AA 等编码和知识工作评估中，Opus 5 创下了新的行业最佳（SOTA），尽管在网络安全任务上仍落后于 Mythos 5。
Opus 5 专为日常使用而设计：它比其他模型工作效率更高。它是 Claude Max 的新默认模型，也是 Claude Pro 上最强大的模型。

性能与成本效益

Claude Opus 5 在与前代 Opus 4.8 相同的成本下，提供了大幅提升的性能。本节中的图表显示了性能如何根据模型的“努力程度”（effort）设置而变化，客户可以利用此设置来优化智能表现，或节省 token 以获得更快、更便宜的结果。
Opus 5 在有价值的软件工程任务中表现出色。例如，在 Frontier-Bench v0.1 上，Opus 5 超越了所有其他模型，并在每项任务成本更低的情况下，将 Opus 4.8 的性能提高了一倍以上。在 CursorBench 3.2 上，在最大努力程度下，该模型的性能与 Fable 5 的峰值得分相差不到 0.5%，但每项任务的成本只有一半；在 high、xhigh 和 max 努力程度下，它在给定成本下也取得了比所有其他模型更好的性能。
我们在知识工作和问题解决任务上也看到了类似的结果。例如：
* 在 ARC-AGI 3（一项要求模型解决新颖问题的评估）上，Opus 5 的得分是次优模型的三倍。
* 在 Zapier AutomationBench（衡量模型能否从头到尾完成业务任务的测试）上，在相同单任务成本下，Opus 5 的通过率约为次优模型的 1.5 倍。即使在最低努力程度设置下，Opus 5 通过的任务也比任何其他模型都多。
* 在 OSWorld 2.0（一项计算机使用基准测试）上，Opus 5 在任何给定成本下的表现都优于所有其他模型，仅以略高于三分之一的成本就超越了 Fable 5 的最佳结果。
它也是我们在几项相关评估中表现最好且最具成本效益的模型：
对于科学研究，Opus 5 相比 Opus 4.8 有显著改进。它在我们的所有生命科学评估（涵盖结构生物学、有机化学和生物信息学等主题）中都表现出比 Opus 4.8 更好的性能。其改进在有机化学任务上最为显著，例如根据光谱数据推断分子结构（在我们的内部基准测试中得分比 Opus 4.8 高出 10.2 个百分点），以及在蛋白质相关任务上，如预测蛋白质序列变异如何影响其功能（在此项上得分高出 7.7 个百分点）。

使用 Claude Opus 5 工作

Claude Opus 5 在验证其工作并仔细迭代直到成功方面要强大得多。在评估和早期访问测试中，我们和我们的用户发现了许多展示 Opus 5 自主性和彻底性的例子：
* 在一项 Frontier-Bench 任务中，Opus 5 得到了一张机器零件的图纸，并被要求编写代码将其重建为 3D FreeCAD 模型。然而，在这项任务中，模型被故意设置为无法直接_查看_图纸。Opus 5 的反应是编写自己的计算机视觉管道，从原始像素中提取几何形状，然后重建了完整的机器零件。它反复成功地做到了这一点；在相同设置下，没有任何竞争模型能在五次尝试后解决该问题。
* 针对一个流行的开源包管理器中的真实 bug，Opus 5 找到了根本原因，并修复了社区补丁遗漏的一个边缘情况。而另一个竞争模型只修复了表面症状（而非根本原因），然后报告 bug 已解决。
* 一家交易公司的一名工程师在一次会话中使用 Opus 5 为一个新的交易所构建了市场数据源。以前的模型根本无法完成这项任务，即使有工程师提供的详细计划。由于找不到实时数据源进行验证，Opus 5 甚至构建了自己的测试工具，以检查其代码是否正确解析了交易所的数据。

在 FrontierCode 1.1 上，Claude Opus 5 以一半的成本接近了 Fable 级别的性能。在 Devin 中，它在困难的调试和根本原因分析任务上也表现出特别的优势。

Claude Opus 5 以 Opus 的速度和成本提供了接近 Fable 5 的智能。在 CursorBench 上，它仅略低于 Fable 5，并且有许多相同的行为。我们很期待看到开发者在 Cursor 中如何使用它。

Claude Opus 5 在没有比以前的 Claude 模型花费更多 token 的情况下，登顶了 Zapier 的 AutomationBench 排行榜。它获取了一个原始的账户健康工作簿，并端到端地运行了完整的流失预防序列：标记有风险的账户、提醒相应的负责人，并为留存运营进行总结。以前的模型没有通过；Opus 5 达到了 100%。

在我们的基因组学分析工作中，Claude Opus 5 的表现比我们运行过的任何模型都更像一位严谨的科学家。它会寻找合适的统计检验来排除混杂因素，通过独立方法交叉检查自己的结果，并在漫长的多步骤分析中保持正轨。

在我们的内部评估中，Claude Opus 5 超越了其同系列的所有模型。它不仅在我们最困难的智能体编码任务上表现更好（比 Opus 4.7 提高了 22%），而且更稳定，每次运行的方差要小得多。对于 Lovable 上的数百万构建者来说，这种一致性至关重要。一次又一次构建的可靠结果。

Claude Opus 5 是 Opus 系列自 4.5 以来最大的一次飞跃。在相同的全栈应用构建中，前端首先展示了这一点：这是我们见过的 Opus 模型中最好的动画、游戏和 3D 作品。

我们非常喜欢 Claude Opus 5。对于我们的智能体处理的那种开放式分析工作，它是对 Opus 4.8 的全面升级，而且提升最大的地方恰恰是在最关键的地方：更难、更模糊的任务。响应更清晰、更简洁，而且我们在更高的努力程度下也看到了效率的提升。

对于我们的分析师每天进行的金融研究工作流，Claude Opus 5 相比 Opus 4.8 有了显著的改进。它在数值推理、表格处理以及精度至关重要的更敏锐的批判性思维方面表现出色。

Claude Opus 5 提供了分析专业企业内容所必需的行业智能和准确性。Box 发现 Opus 5 的表现比 Opus 4.8 高出 8%，并在技术、医疗保健和公共部门组织每天依赖的数据分析（提升 11%）和尽职调查（提升 17%）工作流中带来了显著的性能提升。

Claude Opus 5 显然比 Opus 4.8 跨越了一代。在一个周末，我赋予了它管理我开发环境的“幕僚长”角色：它构建了自己的监控器，驱动每台机器，只在需要做判断时才找我。

Claude Opus 5 在我们的基本面研究助手代码库中进行了大规模更改，在整个智能体工作流中适应反馈，并比我们使用过的任何模型都更清晰地解释了其推理。它处理了我们通常会被拆分成更小部分的工作。

在我们一些最困难的金融建模任务上，Claude Opus 5 在准确性和效率上都比 Opus 4.8 有了明显的提升。它的性能下限有了实质性的提高，特别是在深度的金融领域逻辑上。在各个努力程度下，它的平均准确率提高了 9 个百分点，而轮次和工具调用次数减少了三分之一，时间减少了 60%。

Claude Opus 5 像真正的开发人员一样检查自己的工作。在我们的基准测试中，它在浏览器中以桌面和手机宽度打开了页面，发现了隐藏在移动折叠下方的产品和屏幕外的结账按钮，并在交回工作前修复了这两个问题。

与之前的 Opus 模型相比，Claude Opus 5 在法律智能体工作上的性能有了明显提升，我们在公司治理和仲裁等业务领域看到了最大的收益。Opus 5 在较低推理水平下保持质量的能力也给我们留下了深刻印象，与 Opus 4.8 在最大推理水平下相比，它在实现相似性能的同时平均减少了 26% 的 token 生成。

对我们来说，Claude Opus 5 最大的提升在于长期视野的工作：构建一个完整的演示文稿，然后对其进行修改。产出物的质量决定了我们发布哪个模型，这是我们见过的最明显的进步——更好的视觉理解、更清晰的格式、更少的幻灯片问题。

Claude Opus 5 的判断力是其突出之处。在交接 PR 时，它不会急于发布：它会验证分支，检查模板，并考虑测试的影响，以确保交接干净利落。旧模型往往急于求成，在我们的检查中被发现。

在一次重新架构的会议中，Claude Opus 5 反对我提出的一个设计，而且在我坚持时没有妥协。相反，它准确地解释了我的想法中哪些是有价值的，将其反对意见缩小到一个设计问题上，并提出了一个折中方案，保留了好的部分同时修复了缺陷。正是这种判断力让我们可以在较少监督的情况下信任它。

在首轮红线标记上，Claude Opus 5 在我们测试的所有模型中得分最高，几乎是 Opus 4.8 的两倍。注释也更好：在 NDA 上，它以更少的时间和更少的步骤完成红线标记，同时保持或提高了准确性。

Claude Opus 5 编写出干净、紧凑的 diff，没有死代码，而且它在发现微妙的、特定于代码库的问题上是更强大的“危险探测者”。我们正在将其应用于生产工作负载。

我们肯定会将 Cosmos（我们的统一智能体平台）中的一些用例迁移过来。我们期待越来越多地使用 Claude Opus 5 进行代码审查，我有信心地说，我们宁愿人们使用 Opus 5 而不是 Opus 4.8。

Claude Opus 5 的突出之处在于判断力。它在编写一行代码之前会进行更深入的思考，在规划阶段而不是事后发现自己的逻辑错误，并推理为什么答案是正确的，而不仅仅是是否可行。这是我们见过的 Claude 模型之间在解决问题方面最明显的飞跃，我们期待看到它在 JetBrains IDE 中被采用。

Claude Opus 5 是我们在交易基准测试中测试过的最强大的 Opus 模型，而且它使用的推理 token 大约只有 Opus 4.8 的七分之一，延迟不到一半。以一小部分计算量获得更好的答案。

Claude Opus 5 允许监控智能体在生产环境中管理自己的部分记忆，使其在更长的时间跨度内更加自主和可靠。该智能体将其上下文视为一个动态文档：在标记了我们某项服务中的一个潜在异常后，它根据生产环境重新检查了自己的假设，发现信号是良性的，将更正写入其记忆中，并自行停用了其监控查询。

Claude Opus 5 是一个强大的智能体编码模型，专为长时间运行、多步骤的工作而构建。它深入理解你的代码库，在复杂任务中保持主线，并比 Opus 4.8 更有效地确定功能开发和错误修复的需求。开发者现在可以在 Kiro 中使用 Opus 5 进行构建，利用其高级功能来应对雄心勃勃的项目。

对齐与安全

对齐。 在部署前测试中，我们的自动化行为审计发现 Opus 5 是我们迄今为止最对齐的模型（如下图所示）。它比 Opus 4.8、Sonnet 5 或 Fable 5 更好地遵守了 Claude 的宪法；表现出最低的欺骗行为率；并且最不容易被诱骗而滥用。在避免可能产生难以逆转的副作用的鲁莽行动方面，它也是我们迄今为止最安全的模型。

在我们的自动化行为审计中，Opus 5 在总体不对齐行为上得分为 2.3，是我们近期模型中最低的。
安全。 Opus 5 并没有推进高风险、两用能力的前沿。在与私营部门和政府合作伙伴一起进行的严格评估中，我们发现在生物学研究和进攻性网络安全方面，它仍然落后于 Mythos 5。有关这些评估的更多信息可以在我们的 系统卡片 中找到。
与其前身 Opus 4.8 一样，我们有意避免在网络安全任务上训练 Opus 5。然而，由于通用能力的提升，该模型在这些任务上有了显著改进，在_发现_网络安全漏洞方面接近了 Mythos 5。但是，在_利用_这些漏洞方面——即将漏洞转化为实质性的网络威胁——它仍然大大落后于 Mythos 5。
Opus 5 在 OSS-Fuzz 上的表现说明了这一点，这是我们开发的一项评估，旨在评估模型在没有大量人类指导的情况下发现和利用漏洞的能力。尽管 Mythos 5 和 Opus 5 在识别漏洞方面的成功率相似，但 Opus 5 在漏洞利用开发方面的得分远远落后于 Mythos 5。

在 OSS-Fuzz（我们的网络安全评估之一）上，Opus 5 在识别软件漏洞方面接近 Mythos 5（左），但在为其开发漏洞利用方面则成功率低得多（右）。

Opus 5 的安全防护

Claude Opus 5 的安全防护旨在允许该模型在网络安全和生物学领域的有益使用。它们与我们应用于 Opus 4.8 的防护类似，除了在少数网络安全任务上设置了一些更强的护栏。
网络安全。 Opus 5 的网络安全分类器在限制性上比例低于 Fable 5。它们允许 Opus 5 在源代码中查找漏洞，但阻止“基于二进制”的漏洞扫描（一种更可能与恶意行为者相关的方法）、渗透测试和漏洞利用生成。
根据我们的测试，我们预计分类器的干预频率将比 Fable 5 低约 85%。在 Claude.ai、Claude Code 和 Claude Cowork 中，任何被标记的请求默认将回退到 Opus 4.8。也可以在 API 上启用向 Opus 4.8 的回退。
我们的 网络安全验证计划 (CVP) 促进了原本会被模型安全防护阻碍的网络安全工作。已经是 CVP 一部分的企业和研究人员可以立即访问具有较少安全限制的 Opus 5 版本。
生物学。 由于 Opus 5 拥有与 Opus 4.8 类似的一套安全防护，它现在是我们用于科学研究的最强大的通用模型。尽管如此，该模型在长时间运行的自主研究任务上仍然显示出重要的局限性，而这正是我们预计 AI 模型会构成最大生物学相关风险的地方。（Mythos 5 在这类生物学工作上仍然是更强大的模型。）作为此次发布的一部分，在 Fable 5 上被阻止的生物学相关请求现在将路由到 Opus 5 而不是 Opus 4.8。

开始使用

Claude Opus 5 今日起在所有平台上可用，定价为每百万输入 token 5 美元，每百万输出 token 25 美元（与 Opus 4.8 相同）。开发者可以在 Claude API 上开始使用 claude-opus-5。
它还提供快速模式，运行速度大约是默认速度的 2.5 倍。与 Opus 4.8 一样，快速模式在 Claude 平台上的价格为 Opus 5 基础价格的两倍，并可通过 Claude Code 中的使用额度获取。
除了 Opus 5，我们还在测试版中发布了两个更新：
* Claude 平台上的对话中工具更改。 在对话中，开发者现在可以更改 Claude 可以使用的工具，而不会使提示缓存失效。
* API 上的自动回退。 用户现在可以选择将 Opus 5（或 Fable 5）上被我们的安全分类器标记的请求自动路由到另一个模型。开启自动回退后，API 请求默认始终路由到最佳可用模型，而不是被阻止。
与之前的 Opus 模型一致，Opus 5 对通用访问没有数据保留要求。
有关如何充分利用 Opus 5 的更多指导，请参阅我们的 提示指南。
