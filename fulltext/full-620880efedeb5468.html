摘要

背景。 需求审查（RI）是在软件生命周期早期检测需求制品潜在缺陷的一项成熟实践。大型语言模型（LLM）的最新进展激发了人们对其支持需求工程（RE）任务潜力的兴趣。然而，关于将 LLM 作为人工执行 RI 的协作助手时其影响的实证证据仍然很少。
目的。 我们旨在调查 LLM 支持对人工执行 RI 的影响，考虑审查有效性（包括异味识别和严重性分类，即有害与无害）以及审查持续时间。
方法。 我们进行了一项包含 34 名参与者的对照交叉设计实验，参与者在有和没有 LLM 支持的情况下审查文本规范，识别并分类需求异味，同时记录审查时间。我们为每个结果变量使用一个贝叶斯回归模型分析数据，考虑了交叉设计引起的有效性威胁以及协变量和中介变量。
结果。 结果表明，LLM 支持对异味检测准确性产生负面影响，但对异味分类或任务持续时间没有显著影响。实验周期存在学习效应，但如果首次使用 LLM 支持执行 RI，该效应会减弱。
结论。 我们的发现提供了实证证据，表明 LLM 支持不一定能提高性能，反而可能阻碍新手审查员的表现。此外，结果表明，从一开始就使用 LLM 支持学习 RI 可能会减缓技能习得过程，这意味着 LLM 支持的学习存在威胁。

1 引言

软件审查是一项成熟的质量保证实践，涉及对软件制品的系统性检查，目标是在开发生命周期早期识别缺陷。自 20 世纪 80 年代中期形式化以来，审查已被认为是提高软件质量、降低整体开发成本的有效且高性价比的技术 [Fagan1986AdvancesIS, fagan2011history]。
审查可以在可执行制品存在之前进行，这使其在需求工程（RE）阶段检测需求制品中的缺陷尤为有价值。需求审查（RI）——专注于这些制品的专门审查形式——在确保质量方面发挥着关键作用，因为在 RE 阶段引入的缺陷往往会向下游传播并变得修复成本高昂 [fernandez2017naming]。

在此背景下，需求异味的概念引起了越来越多的关注。需求异味是潜在质量问题的指标——如歧义、模糊或不可验证性——可能阻碍理解或导致错误解释 [Femmer17]。虽然并非所有异味都对应实际的缺陷，但它们作为违反理想质量属性的早期预警信号。因此，区分有害（即造成损害的）和无害的异味至关重要，因为这使得审查员能够优先处理更可能对下游活动产生负面影响的问题 [chantree2006identifying]。

生成式 AI 和大型语言模型（LLM）的最新进展激发了人们对其用于支持 RE 活动的兴趣。先前的工作研究了基于 LLM 的方法来分析和转换需求制品，包括在代码生成 [Liu2022]、测试场景生成 [Arora24, wang2025requirements] 以及从自然语言需求推导 UML 序列图 [ferrari2024model] 等方面的应用。最近，Vogelsang 等人 [vogelsang2025impact] 研究了需求异味对 LLM 在需求到代码可追溯性任务中性能的影响，进一步突显了基于 LLM 的技术对需求质量的敏感性。

然而，现有的研究主要评估模型性能和输出质量 [wolf2025quality]。相比之下，关于人机协作（其中 LLM 作为人工审查的支持助手）如何影响审查性能的实证证据在很大程度上仍未被探索。这一差距对于新手需求分析师尤为关键，他们面临过度依赖 LLM 的风险，可能会阻碍技能发展。同时，组织越来越多地采用 AI 辅助的入职培训，以弥补资深专家在传统指导方面的有限可用性 ¹¹¹ https://newsletter.getdx.com/p/ai-cuts-developer-onboarding-time-in-half （访问于 2026 年 1 月 22 日）。

为了填补这一空白，我们进行了一项对照交叉实验 [vegas2015crossover]，其中作为新手审查员的学生在有和没有 ChatGPT（GPT-4o/GPT-4.1 模型）支持的情况下执行了 RI 任务。在实证 RE 研究中，将学生视为新手需求分析师是常见的做法 [BanoZ0S20, bano2018learning]。
鉴于其潜力的初步证据 [fantechi2023rule]，在可用的 LLM 中选择了 ChatGPT。我们的研究侧重于需求异味的识别和严重性分类（即有害与无害），以及审查持续时间。

我们的结果表明，使用 ChatGPT 作为支持工具对需求异味检测产生负面影响，而对异味严重性分类没有显著影响。此外，审查性能受到学习效应的影响：参与者在第二次执行任务时通常表现更好。然而，当首次在 ChatGPT 支持下执行审查任务时，这种学习效应在各个周期中会减弱。我们还观察到，出乎意料的是，较长的审查时间与较差的表现相关。
最后，异味检测和分类性能呈正相关，表明识别出更多异味的参与者也倾向于更准确地对它们进行分类。

本工作的主要贡献是：
* 对使用 LLM 进行 RI 的影响的一项新颖的实证调查。
* 新手审查员在 LLM 支持的 RI 中学习和顺序效应的证据。
* 关于新手分析师如何（不）使用 LLM 进行 RI 的实用见解。

本文的其余部分结构如下。第 2 节介绍关于 RI、需求异味以及有害和无害异味分类的背景概念，并回顾相关工作。第 3 节描述实验设计。第 4 节展示结果，而第 5 节讨论发现。第 6 节讨论对有效性的威胁。最后，第 7 节总结全文并概述未来的工作方向。

2 背景与相关工作

2.1 需求审查与异味

软件审查包含一系列结构化的审查技术，旨在识别软件制品中质量属性的违规情况 [Fagan1986AdvancesIS]。当应用于 RE 时，审查侧重于系统地检查需求制品，以识别可能损害下游开发活动的缺陷、不一致和不良质量指标。

在软件生命周期早期检测需求制品中的缺陷对于防止其传播到后期开发阶段至关重要，在这些阶段它们可能导致返工、延误和下游活动的质量问题，并且其修正变得越来越困难和昂贵 [fernandez2017naming, shull2000perspective]。

在此背景下，引入了需求异味作为需求制品中潜在质量问题的可观察指标 [Femmer17]。需求异味本身不一定对应于缺陷，而是预示着可能阻碍理解、引入歧义或增加误解可能性的情况。因此，异味提供了一种实用的手段，通过将注意力吸引到需要仔细审查的需求上来指导审查活动。

2022 年，发布了一个包含 206 个需求质量因素（即异味）的目录 [Frattini2022]，该目录源自对 105 篇相关论文的系统映射研究 [Montgomery2022]。Frattini 等人将这些异味分为三大类： 词汇异味，与可能被误解的词汇或术语有关； 句法异味，具有有问题的词汇或句子结构； 语义异味，涉及在其使用上下文中对需求的解释。

在异味中，区分良性问题和可能导致误解和缺陷的问题非常重要。在 21 世纪初，Chantree 等人引入了有害和无害现象之间的区别 [chantree2006identifying]。
有害问题可能导致利益相关者的解释产生分歧，并因此导致不正确或不一致的实施。相比之下，无害问题可能在表面上表现出潜在的问题特征，但通常被一致地解释，因此不太可能导致误解。
因此，虽然异味表明了潜在的质量问题，但并非所有异味都一定需要纠正措施。一些异味可以通过上下文和领域知识轻松消除歧义，因此可以被认为是无害的 [krisch2015myth]。其他异味可能引起多种合理的解释，因此如果不加以解决，就代表了有害风险 [frattini2025applying]。
区分有害和无害的异味使审查员能够优先处理更可能对下游开发活动产生负面影响的问题。

2.2 相关工作

最近的研究越来越多地调查了 LLM 在支持需求质量保证方面的使用。
Wolf 等人的系统文献综述综合了 26 篇关于基于 AI 的需求质量评估的同行评审研究（2019–2025），突显了自 2023 年以来向 LLM 驱动的方法和语义更丰富的评估的转变 [wolf2025quality]。
部分工作将 LLM 视为质量缺陷检测器 [fantechi2023inconsistency, mahbub2024can, raj2024enhancing]，而其他工作则部分考虑了人类视角，以及使用 LLM 进行审查的影响 [boukhlif2024using, bashir2025requirements, seifert2024can, lubos2024leveraging]。

LLM 作为检测器。
在第一组中，Fantechi 等人 [fantechi2023inconsistency] 探索了使用 GPT-3.5 检测自然语言需求中的不一致性。他们的研究根据学生提供的参考评估评估了 LLM 的预测。结果表明，该模型可以识别某些不一致性，提供了可行性的证据，同时也突显了检测准确性的变异性，这取决于不一致性类型和需求表述。
Mahbub 等人 [mahbub2024can] 评估了 GPT-4 在检测需求制品中多类缺陷（包括歧义、不一致和不完整）方面的性能。他们的研究定量评估了模型在这些缺陷类型和不同需求版本中的精确度。结果表明，GPT-4 在识别不完整需求方面表现优于检测不一致和歧义。作者得出结论，尽管结果令人鼓舞，但由于领域特定推理的局限性，在零样本设置中 LLM 无法取代人类分析师。
Raj 等人 [raj2024enhancing] 提出了一个利用 LLM 来识别、分类和解决软件需求制品中歧义的框架。评估侧重于 LLM 识别歧义类型和生成替代表述的能力，在一个小型评估集上提供了 LLM 支持与歧义相关的质量改进潜力的初步证据。

LLM 与人类视角。
在这一组中，Lubos 等人 [lubos2024leveraging] 调查了使用 LLM 根据 ISO/IEC/IEEE 29148 标准评估软件需求质量。他们的方法采用 LLM 来评估质量特性，解释其判断，并提出需求的改进版本。该方法在软件工程师的参与下进行了评估，工程师们检查了 LLM 支持的分析的实用性。结果表明，LLM 可以为需求质量评估和改进提供有价值的支持，特别是通过解释和建议的改进。
Bashir 等人 [bashir2025requirements] 实证研究了在工业需求中使用 LLM 进行歧义检测和解释。作者评估了三个工业数据集上的性能，并报告说，与零样本设置相比，使用十样本提示在分类性能上平均提高了 20.2%。此外，他们与行业专家进行了人工评估，专家们在自然性、充分性、有用性和相关性等维度上评估了生成的解释，平均得分为 3.84/5。
Boukhlif 等人 [boukhlif2024using] 检查了使用 LLM 识别软件需求中的歧义、不一致和差距，特别关注其对软件测试的影响。该研究使用定量指标以及生成见解的定性评估，将基于 LLM 的分析与传统的 SRS 分析技术进行了比较。结果表明，LLM 可以提高需求分析的准确性和效率，特别是在检测模糊术语和揭示传统方法可能忽略的不一致方面。
最后，Seifert 等人 [seifert2024can] 报告了一项关于需求审查实验的复制，以评估 LLM 能否与人类审查员竞争。他们评估了 GPT-4-Turbo 作为 LLM 审查员。虽然结果表明 LLM 可以识别某些问题，但作者指出，与原始人工审查设置的可比性受到必要调整（例如，LLM 的训练方式和提供的材料）的限制，因此应谨慎解释结果。

贡献。
总体而言，现有的工作提供了关于 LLM 识别和推理文本需求中质量问题的潜力的宝贵实证证据。然而，先前的研究主要集中在评估 LLM 输出——通常人类的参与仅限于评估模型生成结果的正确性、有用性或合理性——而不是检查它们在以人为中心的审查过程中的作用。
然而，人在回路中的场景更接近现实的工业实践，在工业实践中，LLM 越来越多地被视为支持工具，在软件工程活动中协助而不是完全取代人类的推理和决策 [natarajan2025human, takerngsaksiri2025human]。这在任务关键型环境中尤为重要，在这些环境中，需求质量和人类监督仍然至关重要。
此外，基于聊天的 LLM 的使用本质上是迭代和对话式的，实现了一个协作的意义构建过程，在这个过程中，人类细化提示、评估建议，并将领域知识应用于审查决策。
与先前的工作不同，本研究采用了这种现实的以人为中心的视角，评估了审查员在 RI 期间使用 LLM 作为支持工具时的表现，重点关注有效性、学习和顺序效应以及审查持续时间。
通过采用这种视角，我们的工作补充了现有研究，并解决了关于 RI 中人机协作实证证据的一个重要空白。

3 研究设计

实验设计和程序是根据 Jedlitschka 等人 [jedlitschka2008reporting] 和 Vegas 等人 [vegas2015crossover] 报告的指南进行的。

3.1 目标与研究问题

实验的总体目标如下：
了解使用 LLM 支持 RI 对新手审查员的潜力，以及使用 LLM 对其学习行为的影响。

为了实现该目标，我们的目的是回答以下研究问题：
RQ1 LLM 支持对执行 RI 所需时间有何影响？
RQ2 LLM 支持对需求异味识别的准确性有何影响？
RQ3 LLM 支持对将识别出的需求异味分类为有害的准确性有何影响？

3.2 受试者选择

参与者是佛罗伦萨大学计算机工程专业的本科生，选修了工业计算机科学课程。他们根据可用性被机会主义地招募。参与是自愿的，并给予课程考试的加分奖励；然而，无论是否参与，学生都可以通过标准考试过程获得高分。在实验之前，所有参与者都被告知研究的目的和程序，并提供了书面知情同意书。他们被明确告知，收集的数据将仅用于研究目的，以匿名和汇总的形式进行分析，并且不会保留其身份与记录响应之间的任何联系。

参与者被分为两个实验组（组 1 和组 2，每组各包含 17 名参与者）。
在将参与者分配到各组时，我们根据在前测问卷中（参见第 3.3 节）以五点顺序量表收集的RI 熟练程度和使用 LLM 的熟练程度因素进行了区组划分。
他们使用基于这两个变量的马氏距离的最佳匹配被分配到各组中。
最终，两个实验组在两个因素的量表五个级别中均包含相似数量的参与者（最大差异为 2）。
这样，这些因素的影响在各组中均匀分散，不会混淆所关注的效应。

3.3 实验对象与任务

实验分两次进行，期间参与者执行了 RI 任务。
为了执行任务，参与者获得了 需求文档， 提供所选异味类型定义和示例以及有害/无害区别的参考文档，以及 支持 RI 的测试文档。

参与者被要求审查提供的需求文档中的每个需求，并确定其是否表现出预定义的异味类型之一；将识别出的异味分类为有害或无害；记录审查任务的开始和结束时间。
此外，参与者在审查会议之前获得了 前测问卷，在每次审查会议之后获得了 后测问卷。

(i) 需求文档。
两次会议中使用的文档包含了两个不同视频游戏实现的需求集：第一次会议是打砖块游戏，第二次会议是贪吃蛇游戏。这些文档包含有异味和无异味的需求，旨在在大小和异味数量上具有可比性（即，打砖块：40 个需求，21 个异味；贪吃蛇：39 个需求，19 个异味）。包含的异味涵盖了 [Frattini2022] 中表 1 列出的九种异味类型。我们还将每种异味分类为有害或无害。

需求文档是 [vogelsang2025impact] 中先前使用的两个文档的扩展版本。从这些原始文档开始，其中一位作者扩展了文档并注入了额外的异味，以确保涵盖所有九种选定的异味类型，每种异味类型在文档中至少出现一次，并且每个需求最多包含一种异味 ²²² 限制每个需求最多包含一种异味的选择虽然不能完全代表现实世界的需求文档，但是为了简化参与者的审查任务和随后的分析而做出的。特别是，允许每个需求有多个异味会增加参与者的标注歧义，并使性能指标（例如精确率和召回率）的计算和解释复杂化。 。同一位作者还对注入的异味进行了初步的有害/无害分类。

随后，另外两位作者独立审查了需求文档，识别异味的存在并将其分类为有害或无害。然后，三位作者通过迭代的、以共识为导向的讨论过程共同审查了所有识别出的差异，直到对每个需求达成共同决定。
鉴于需求异味及其感知严重性的固有主观性和上下文依赖性 [gervasi2019]，我们采用了对话式协调过程，而不是依赖正式的评分者间一致性度量。该过程一致地应用于异味识别和有害/无害分类。基于最终商定的文档版本，为每个需求建立了参考标注，指定了异味的存在或不存在、异味类型及其有害或无害分类。这个标注版本的文档作为后续分析参与者审查性能的真实基准。尽管其中一位作者的初步标注可能会使真实基准产生偏差，但我们认为多次迭代和重新评估减轻了这种可能的偏差。

(ii) 参考文档。
参与者收到了一份参考文档，其中包含每种异味类型的定义，以及两个说明性示例及其相应的解释。该文档还包括有害和无害类别的定义，以及每个类别的两个示例。

总的来说，在所有会议和实验条件中，后测问卷收集了关于审查任务的定性评论和反馈、参与者对两种变体（LLM 支持与非支持）的偏好，以及自我报告的英语熟练程度。当使用 LLM 支持时，参与者报告了 LLM 版本以及在 LLM 辅助下审查的需求数量。

3.5 实验程序

3.5.1 实验阶段

实验始于一个培训阶段，参与者参加了一节入门课程，旨在提供成功执行审查任务所需的所有信息。课程涵盖以下主题：RI、需求异味、有害和无害异味之间的区别，以及提示工程的基本原则。为了提高参与度和积极性，课程通过将活动设定为模拟招聘场景（参与者是一家视频游戏公司的员工，正在竞争“月度最佳员工”的荣誉）融入了游戏化元素。

在入门课程之后，参与者被要求在第一次审查任务会议之前不超过三天完成一份在线前测问卷。
在入门课程一周后，参与者进入了审查阶段，这构成了实验的核心阶段。该阶段分两次会议（周期 1 和周期 2）进行，中间间隔一周的洗脱期。审查任务在没有时间限制的情况下进行。参与者在课堂会议期间开始审查，如果必要，允许在课堂外完成，前提是他们准确记录了任务的开始和结束时间。尽管工作条件的这种可变性降低了控制力，但做出这一选择是为了优先保证数据的完整性，并避免完全完成和部分完成的审查之间的比较。只有两名参与者在课堂会议后继续进行了审查。

在每次审查任务会议之后，参与者将完成的测试文档上传到标有参与者 ID 的共享在线文件夹中，并完成了一份在线后测问卷，该问卷根据实验周期和分配的条件而有所不同。前测和后测问卷通过在线调查平台进行管理。

3.5.2 测量程序

为了量化参与者识别需求异味的表现，我们通过将每位参与者的标注与真实基准进行比较来计算有效性指标。
每位参与者通过为每个需求标记预定义异味类型的存在或不存在来完成 RI 任务。
与真实基准的比较是在单个异味类型级别上进行的。具体来说，对于每位参与者和每种异味类型，我们通过将跨所有需求识别该异味视为二元分类问题来计算 $F_1$ 分数。真阳性、假阳性和假阴性是通过对齐参与者标注和真实基准标签（基于需求标识符）得出的。

参与者级别的表现通过计算跨异味类型的宏观平均 $F_1$ 分数来总结。该指标在 RE 任务评估中很常见 [berry2021empirical]。尽管 $F_\beta$ 可以提供更细致和实际相关的视角 [berry2021empirical]，但计算 $\beta$ 的实际值需要进行专门的实验评估，这留待未来的工作。

分类表现（同样根据真实基准进行评估）仅针对正确识别的异味进行计算，因为分类以成功检测为前提；包含未检测到的异味会将检测错误与分类错误混淆，因此不能反映分类能力本身。对于每位参与者，通过将有害标签的分配视为对正确识别的异味集合的二元分类问题来计算分类有效性。具体来说，真阳性、假阳性和假阴性是通过对齐参与者的有害分类与真实基准有害标签得出的。我们关注有害类别，因为在实践中正确识别有害异味至关重要，因为如果不加以解决，这些异味更可能导致误解和下游缺陷。参与者级别的分类表现使用 $F_1$ 分数进行总结。上述关于 $F_\beta$ 的相同考虑也适用于此任务。

3.6 数据分析

为了分析收集的数据，我们在统计因果推断（SCI）框架内使用了贝叶斯数据分析（BDA）[siebert2023applications, pearl2009causal]。
BDA 技术的应用比频率派方法更复杂，但提供了更丰富的见解，更直观易懂，且对不确定性更稳健 [furia2019bayesian, frattini2024second]。
在我们的特定分析中，BDA 允许我们使用最大熵的分布族对结果变量进行适当建模 [jaynes2003probability]。
频率派方法仅区分正态和非正态分布的结果，而 BDA 区分了更多的分布族 [gren2021possible]。
由于我们的结果变量均不服从正态分布，BDA 是更合适的选择 [mcelreath2018statistical]。

SCI 框架确保在收集的数据范围内，识别出的效应是因果的而非相关的 [pearl2009causal]。
对于 overarching SCI 框架，我们遵循了 Siebert [siebert2023applications] 提出的三步过程，该过程基于 Pearl [pearl2009causal] 的开创性工作。
尽管 SCI 原则在分析观察数据方面特别有效 [furia2022applying]，但它们也通过区分总效应和直接效应来支持分析实验数据 [frattini2025applying]，并明确指导交叉设计实验中的分析 [vegas2015crossover, frattini2024crossover]。
对于 BDA，我们遵循了 McElreath [mcelreath2018statistical] 和 Gelman 等人 [gelman1995bayesian] 的权威教科书。

3.6.1 建模

在 Siebert [siebert2023applications] 提出的第一步“建模”中，我们明确地将因果假设编码在一个有向无环图（DAG）中 [glymour2008causal]。
在 DAG 中，节点代表相关变量，有向边假设这些变量之间的因果关系。
对于每个 RQ，我们围绕暴露（即使用 ChatGPT）和相应结果变量（即持续时间、检测性能和分类性能）之间的关系建立了一个 DAG。
图 2 显示了 RQ1 的 DAG，暴露为红色，结果为青色。
RQ2 和 RQ3 的 DAG 仅在 相应的结果变量，以及 包含持续时间作为中介变量方面有所不同。

3.6.2 识别

基于每个 RQ 的 DAG，我们执行了 SCI 框架的第二步，称为“识别”[siebert2023applications]。
在此步骤中，我们识别了主要暴露（LLM 支持）之外的所有变量，我们需要对其进行统计控制以避免任何偏差。
为此，我们应用了 d-分离 [pearl2009causal]，它识别了去混淆所关注因果效应所需的调整变量集。
在图 2 中 RQ1 的示例 DAG 中，变量周期和顺序混淆了 LLM 支持对持续时间的效应，因此必须包含在调整集中 [pearl2009causal]。
变量 LLM 使用情况作为中介变量，我们将其包含在内以隔离所关注的直接效应 [mcelreath2018statistical]。
最后，其余变量作为简单的协变量，我们将其包含在内以提高效应估计的精度 [cinelli2024crash]。

3.6.3 估计

在为每个 RQ 确定了调整集之后，我们进行了最后的“估计”步骤 [siebert2023applications]，以估计统计控制变量对结果变量的影响方向和强度。对于这个过程，我们遵循了 BDA 的通用指南 [mcelreath2018statistical, gelman1995bayesian]。

我们首先为三个结果变量中的每一个选择了具有最大熵的分布族 [jaynes2003probability]：
我们将每个结果变量视为随机变量，并选择了与所有认识论和本体论假设一致的限制最少的分布族 [mcelreath2018statistical]。
这产生了两个不同的分布族：
* 结果变量持续时间被建模为负二项式（或：伽马泊松）分布，因为该变量表示具有过分散（$VMR=7.2>1$）的离散计数（以分钟为单位）。
* 结果变量检测性能和分类性能均被建模为 beta 分布，因为它们被测量为介于 0 和 1 之间的 $F_1$ 分数。鉴于两个变量中都存在 0.0 和 1.0 分数，我们专门使用了零一膨胀 beta 分布变体。

接下来，我们为每个 RQ 设计了一个贝叶斯回归模型。
我们使用包含调整集中所有变量的线性模型指定了每个分布的形状定义参数。
例如，RQ1 的回归模型定义如下：
$$duration_{i} \sim \text{NegBinom}(n_{i},p_{i})$$
$$\text{logit}(p_{i}) \leftarrow \alpha + \alpha_{\textit{ID}} + \beta_{\textit{llm}}\cdot{llm}{i} + \beta{\textit{llm}\times\textit{prof.llm}}\cdot{llm}{i}\cdot\textit{prof.llm}{i} + \dots$$
$\dots$ 代表模型中包含的其余因素，即表 2 中列出并显示在图 2 中的所有其余因素。为了简洁起见，我们在手稿中掩盖了它们。

回归模型 $\text{logit}(p_{i})\leftarrow\dots$ 由几个部分组成：
* 一个群体级别的截距 $\alpha$，代表实验任务的一般难度。
* 一个组级别的截距 $\alpha_{\textit{ID}}$，代表参与者的一般技能。这模拟了受试者级别的变异性 [vegas2015crossover]。
* 群体级别的效应 $\beta_{X}\cdot X_{i}$，其中 $X_{i}$ 是观察 $i$ 中变量 $X$（例如，使用 ChatGPT，标记为 llm）的值，$\beta_{X}$ 是代表这些值对结果变量影响的概率分布。
* 交互效应 $\beta_{X\times Y}\text{X}{i}\cdot\text{Y}{i}$，其中一个变量 $Y$ 调节另一个变量 $X$ 对结果的影响。

每个截距（$\alpha$ 和 $\alpha_{\textit{ID}}$）和效应系数（所有 $\beta_{X}$ 和 $\beta_{X\times Y}$）都是相应因素对结果变量影响强度的概率分布。
对于每一个，我们分配了一个先验概率分布，即在观察数据之前编码我们对可行效应强度的假设 [mcelreath2018statistical]。
由于缺乏针对这些因素中任何一个的强有力实证证据，我们使用了无信息先验，如 $\mathcal{N}(\mu=0,\sigma=1)$ [wesner2021choosing]，即以 0 为中心、方差为 1 的宽正态分布。
这代表了一种信念，即任何因素都可能对结果产生正面（$\mu>0$）、负面（$\mu<0$）或不存在（$\mu\approx 0$）的影响。

为了评估所选先验的资格，我们进行了先验预测检查 [wesner2021choosing]。
在此过程中，我们从贝叶斯回归模型中抽样，而没有通过收集的数据更新先验。
先验预测检查的结果直观地显示，潜在结果的范围包含了实际结果，证实了先验的合理性。
在确认了先验的资格后，我们继续进行模型训练。
我们使用 R 库 brms [burkner2017brms] 作为统计建模语言 STAN [carpenter2017stan] 的接口实现了分析。
在训练过程中，哈密顿蒙特卡洛马尔可夫链（MCMC）根据收集的数据更新了系数分布 [brooks2011handbook]。
这样，系数分布的参数（例如，$\mu$ 和 $\sigma$）被调整以更好地反映基于预测变量值的结果变量。

训练后，我们评估了几种诊断以确保训练过程的有效性。
Gelman-Rubin 收敛统计量显示所有系数的 $\hat{R}\in]0.99,1.01[$ 值可接受 [gelman1992inference]。
同样，所有系数的有效样本量比例高于阈值 $\frac{n_{\textit{eff}}}{n}>0.1$ [mcelreath2018statistical]。
我们没有观察到发散转换，这引起了对训练过程的担忧。
最后，我们通过从现在更新的系数分布中抽取样本来执行后验预测检查，这证实了训练过程将估计值移动得更接近且更紧密地围绕观察值。
请注意，由于我们的目标不是样本外预测，而是因果推断，因此我们没有对可用数据进行训练-测试集拆分。
为了获得关于结果空间的可解释结果，我们计算了边际和条件效应并绘制了它们的分布。
边际和条件效应是通过仅改变一个或两个因素而将所有其他因素保持在代表性水平不变来从模型中估计的。
这样，该因素对结果变量的孤立效应就变得清晰，显示了它如何影响结果变量。

5 讨论

与先前研究孤立 LLM 的工作提出的 LLM 可能均匀提高 RE 任务性能的普遍预期相反 [mahbub2024can, bashir2025requirements, boukhlif2024using]，结果突显了更细致的情况。
特别是，虽然 ChatGPT 支持没有显著影响审查时间或异味分类准确性，但它与异味检测准确性的降低以及首次在 LLM 支持下执行审查时学习效应的减弱有关。基于这些发现，我们讨论了相关的观察结果和影响。

5.1 关键观察

潜在的过度依赖和自动化偏见。
LLM 支持对异味检测准确性的负面影响表明，对于新手审查员来说，LLM 的可用性可能会干扰仔细、系统的需求分析。一个合理的解释是，参与者可能将部分审查工作委托给了 LLM，依赖其响应而不是深入参与需求。这与先前研究中提出的关于过度依赖 AI 生成的建议和自动化偏见的担忧相一致，特别是当用户缺乏强大的领域专业知识时 [passi2022overreliance, carnat2024human]。
在其他软件工程活动中的人机协作的定性研究中也报告了类似的担忧。Hamza 等人观察到，在使用 ChatGPT 的专业软件工程师的实践研讨会期间，参与者有时表现出社会懈怠和过度依赖 AI，减少了智力参与和批判性思维 [hamza2024human]。

异味检测和严重性分类中不同的认知过程。
有趣的是，一旦正确识别了异味，LLM 支持并没有显著影响异味严重性分类的准确性。这表明，当参与者成功检测到异味时，无论是否有 LLM 支持，他们通常都能推理出其严重性（有害与无害）。
在先前关于 RI 的工作中观察到了类似的模式，一旦正确识别了违规，审查员就会提供准确的理由，而与支持的表现形式无关 [broccia2026rolecognitiveabilitiesrequirements]。因此，分类可能更多地依赖于对质量风险的概念理解，而不是对异味指标的机械检测。这种区别强调了在 RI 中将检测和分类视为两个认知上不同的活动的重要性。

早期 LLM 支持导致技能发展减缓。
在实验周期中观察到的学习效应与交叉设计中的既定方法论实践相一致，该方法论要求明确检查和考虑学习效应 [vegas2015crossover, frattini2024crossover]。参与者在第二次审查会议中表现更好，表明重复接触任务导致了有效性的提高。然而，当首次在 LLM 支持下执行审查任务时观察到的学习效应减弱尤为相关。它表明，早期依赖 LLM 可能会阻碍审查技能的发展，这可能是通过缩短新手审查员内化审查策略和质量启发式方法的反思过程来实现的。

较长的持续时间并不意味着更好的性能。
较长的审查持续时间与性能之间的负相关表明，在任务上花费更多时间并没有转化为更高的准确性。较长的持续时间可能不是反映彻底性，而是反映了不确定性、缺乏策略或理解需求方面的困难。参与者自我报告的中等英语熟练程度（1-5 分制平均 3.5 分）可能加剧了这些困难，这可能阻碍了需求理解。这进一步支持了这样的解释，即有效的审查更多地依赖于结构化推理而不是单纯的时间投入。

5.2 对实践、研究和教学的影响

对实践的影响。
对于从业者来说，这些结果警告不要不加批判地将 LLM 作为 RI 中的支持工具，特别是对于新手审查员。虽然 LLM 可以生成合理的解释和建议，但它们的使用可能会在无意中减少审查员对需求的参与并削弱检测性能。因此，将 LLM 引入审查工作流程的组织应考虑将其使用限制在特定阶段（例如，审查后或理由细化），而不是作为初始缺陷检测期间的主要辅助工具。
在软件开发环境中，也报告了关于早期使用生成式 AI 对技能发展影响的类似担忧，开发者担心新手会变得过于依赖生成式 AI 工具，从而错失培养编码和解决问题技能的机会 [stray2025human]。
缺乏时间节省表明 LLM 支持不一定会带来审查任务效率的提升。从业者不应假设 LLM 辅助的审查会更快或更有效，除非在其特定环境中进行仔细评估。
在其他软件工程活动中也观察到了类似的模式。
Stray 等人 [stray2025developerproductivitygithubcopilot] 报告称，尽管开发者强烈感觉到效率提高，但引入 GitHub Copilot 并未与开发任务中可观的、可一致衡量的生产力提升相关联。这种感知收益与观察到的收益之间的差距强化了我们的发现，即不应假设 LLM 支持会带来性能或效率的提升，除非经过仔细的、特定于环境的评估。
另一方面，当 LLM 被定位为学习和导向的辅助工具，而不是人类推理或任务执行的替代品时，它们仍然可以支持新手工程师的入职。最近的研究表明，LLM 可以帮助新人浏览文档、减少信息过载，并以自主的方式探索不熟悉的技术材料。然而，有效的入职仍然需要持续的人类指导和监督 [azanza2024can, adejumo2024towards]。

对研究的影响。
从研究的角度来看，本研究为仍然探索不足的 RI 中人机协作领域提供了实证证据。结果突出了超越孤立评估 LLM 输出质量，转向研究 LLM 如何塑造人类行为、学习和决策过程的需要。
未来的研究应调查替代的集成策略，例如受限或分阶段的 LLM 使用，并检查不同的提示风格、解释或透明度机制是否可以减轻此处观察到的负面影响。需要对专业审查员和更复杂的工业需求进行复现研究，以评估这些发现的普遍性，并了解专业知识如何调节 LLM 支持的影响。

对教学的影响。
这些发现对 RE 教学也有重要影响。在审查培训中过早引入 LLM 可能会限制学生发展基础审查技能和批判性阅读能力的机会。因此，教育工作者在将 LLM 整合到 RE 课程中时应谨慎，并考虑首先让学生掌握手动审查技术，然后再让他们接触基于 AI 的辅助。
这些影响与最近在 AI 时代以人为中心的软件工程教育的呼吁相一致，这些呼吁警告说，如果不仔细整合到课程中，过早或无结构地使用生成式 AI 工具可能会破坏基础学习、反思性实践和技能发展 [abrahao2025software]。
在教育软件工程环境中新手与 LLM 交互的研究中出现了互补的实证证据。Rahe 和 Maalej 报告称，使用 ChatGPT 的编程学生经常将大部分问题解决委托给 LLM，经常进入生成、复制和提交解决方案的重复循环，而没有进行更深入的推理 [Rahe_2025]。他们的分析还表明，增加的交互时间并没有转化为性能的提升。尽管在任务上花费了更多时间且感知有用性很高，但没有观察到相应的学习或有效性提升。这些发现密切反映了我们在 RI 中的观察，强化了无结构的 LLM 支持可能会减少认知参与并阻碍新手用户的学习，而不是增强审查有效性的担忧。
同时，如果是有意使用，LLM 仍然可以发挥宝贵的教学作用，例如，作为初始手动审查后进行讨论、反思或比较的工具。以这种方式使用，LLM 可以帮助学生表达推理、理解替代解释并反思质量问题，而不会取代基本的学习过程。

6 有效性威胁

我们遵循 Wohlin 等人 [wohlin2012experimentation] 讨论适用于本研究的有效性威胁。

构建有效性。
几个协变量（例如，使用 LLM 的熟练程度和 RI 的熟练程度）可能存在有限的构建有效性。这些自我报告的李克特量表变量是所关注潜在构建的粗糙代理。
鉴于将此类潜在概念操作化的困难，我们采用了在粗糙量表上自我报告的常见做法。
因此，这些协变量对结果变量缺乏显著影响可能源于这种有限的构建有效性，我们避免就它们对实验任务的影响得出结论。
真实基准的构建也可能威胁构建有效性。尽管标注过程涉及多位作者的独立审查，随后进行了迭代的、以共识为导向的协调讨论，但没有计算正式的评分者间一致性指标。我们通过集体审查和讨论直到对每个需求达成共识来减轻这种威胁。

内部有效性。
数据收集没有包括对参与者一般技能或动机的明确衡量，这两者都可能影响所有结果变量。
在 RQ2 和 RQ3 中，这威胁到内部有效性，因为技能或动机可能会混淆持续时间与其他结果变量之间的关系。
因为技能高或积极性高的学生可能既表现得更快又更好，缺乏针对技能或动机的明确变量会在这些变量之间诱发虚假关联 [mcelreath2018statistical]。
图 4(b) 支持了这种解释：较长的任务持续时间出乎意料地与较低的检测准确性相关。因此，我们假设这种关联是非因果的，并受到技能或动机的混淆。由于此类潜在构建难以操作化，并且使用学生成绩等代理变量会引起伦理问题，我们选择不收集这些数据。
允许参与者在课堂外继续审查任务也可能引入了工作条件的可变性并降低了实验控制。
然而，做出这一选择是为了优先保证数据的完整性，并避免完全完成和部分完成的审查之间的比较。在实践中，这种情况仅发生在周期 1 中的两名参与者身上（占总审查任务执行的 2.9%）。

外部有效性。
获得的结果受到几个外部有效性威胁的影响，这限制了结论的范围。具体来说，实验在三个维度上没有完全反映真实的 RI 实践：参与者（即实验对象）、需求（即实验对象）和 RI 任务本身（即实验任务）。
参与者是没有丰富 RI 实践经验的计算机工程本科生。虽然“使用学生作为参与者仍然是实验室环境中所需的有效现实简化”[falessi2018empirical]，但对于具有既定审查策略和领域知识的经验丰富的工业从业者来说，观察到的效应可能有所不同。
同样，用于审查的需求比工业需求更简单，以便在实验范围内保持可理解性。此外，每个需求最多包含一种异味。虽然这简化了标注和性能分析，但工业需求可能包含多种相互作用的异味，这限制了对更复杂环境的普遍性。
最后，RI 任务仅限于需求异味的检测和分类，并依赖于预定义的异味类型集，而不是完全开放的识别。尽管这些异味类别是从基于工业实践的经验证实的分类法中选择的 [Frattini2022]，但这一选择可能影响了参与者的审查行为，并使任务与现实世界的 RI 环境相比得到了简化。
这些简化对于使实验可行是必要的，但限制了受控教育环境中新手审查员之外的结果的外部有效性。

结论有效性。
我们结果的结论有效性受到数据分析两个方面的威胁。
首先，34 名参与者的样本量相对有限。
其次，分析涉及主观选择，包括选择具有最大熵的概率分布族、线性模型参数和先验概率分布。
然而，贝叶斯数据分析在两个方面减轻了这些威胁。首先，它自然地保留了结果中的不确定性，这反映在可信区间中 [furia2019bayesian]。其次，它使所有分析步骤明确化，包括主观决定，允许其他研究人员在必要时审查和修改它们。

7 结论

本文介绍了一项对照交叉设计实验，调查了 LLM 支持对人工执行 RI 的影响。研究侧重于需求异味识别、有害/无害分类和审查时间，提供了证据表明 LLM 支持不一定能改善新手审查员的审查结果。特别是，结果表明 LLM 支持对异味检测准确性产生负面影响，对异味分类或任务持续时间没有显著影响，并且从一开始就使用与学习效应减弱相关。这些发现表明，早期依赖 LLM 可能会阻碍而不是支持系统审查技能的发展。

未来的工作应研究将 LLM 整合到 RI 工作流程中的替代方法，例如受限、分阶段或事后使用，以减轻本研究中观察到的负面影响。需要对专业审查员和更复杂的工业需求进行复现，以评估这些发现的普遍性，并了解专业知识如何调节 LLM 支持的影响。进一步的研究还应探索不同的交互设计、提示策略和解释机制如何影响审查有效性和学习，目标是确定 LLM 可以支持人类审查技能的配置。
