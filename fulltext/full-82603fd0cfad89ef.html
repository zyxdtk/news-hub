摘要

将新的发电和负荷接入电网依赖于两项稀缺技能：对照庞大且不断变化的法规体系审查申请，以及运行决定项目在何处、以何种方式接入的网络研究。我们提出 Grid Agents，一个将两者结合的 AI 系统，以及我们用来评估它的方法。Grid Ontology（电网本体）是其知识系统。它表示电网工作所依赖的法规、标准和工程知识，使其可被搜索，并随着智能体在使用中学习而演进。从中得出的每个答案都立足于智能体引用的证据。Grid Studio 是一个专为电力系统工程定制的智能体系统。它在自己的工程环境中工作，配备领域工具和研究框架，依托 Grid Ontology，其报告的每个数字都依赖成熟的求解器。在这两者中，均由工程师做出决策。我们将此前散见于不同论文的八个已发表电力系统基准测试家族整合为一个包含 519 项任务的套件，并且不仅验证每个答案，还通过重放智能体的工具调用来验证其背后的工作。Grid Ontology 比通用编码智能体或检索流水线更频繁地引用正确的法规证据，在 LegalBench-RAG 上领先，并在 Enterprise RAG Challenge 和 ViDoRe V3 的公开排行榜上排名第一。Grid Studio 在 519 项电力系统任务上得分最高，并且是我们所比较的所有系统中最快的，两者均具有统计显著性。在优化器参与的情况下，其加固方案的成本平均比智能体单独设计的方案低 33–67%。

1 引言

如今，限制能源转型的与其说是发电，不如说是并网。2023 年，全球至少有 3,000 GW 的可再生项目在并网队列中等待 [18]。仅在美国，截至该年年底就有约 2,600 GW 的发电和储能项目在寻求互联 [45]。作为回应，美国和英国都已改革了其并网流程 [9, 38]。

每个并网请求需要两类专家工作。法规工作将申请对照立法、电网准则和标准进行审查，这些文件长达数千页，并随着改革进程而变化。工程工作通过在网络模型上运行潮流、预想事故（N-1）和短路研究，决定项目可以在哪里接入以及需要什么加固 [25, 63]。两者都很慢，而且都缺人。

基于大语言模型（LLM）的智能体进行规划、调用工具并根据结果采取行动 [67, 48, 61]，这适合上述两项任务。但它们也存在三种在此至关重要的失败方式。它们会写出没有任何来源支持的流畅文本 [20]。它们在大型网络方程的算术运算上不可信任。最后，正确的答案并不能表明其背后的工作是正确的。同一个数字可能来自正确的研究、来自记忆或来自对错误电网状态的研究，而大多数基准测试只对数字评分。然而，并网决策会承诺代价高昂的网络工程，并可能受到申请人或监管机构的质疑，因此工程师必须能够展示哪项研究在哪个网络上运行。

我们提出 Grid Agents，一个围绕这些失败模式设计的系统。它有两个部分（图 2）：

  • Grid Ontology 是 Grid Agents 的知识系统。它表示电网工作所依赖的法规、标准和工程知识，使其可被智能体搜索，并随着智能体在使用中学习而演进，共享的内容需经人员批准。¹ ¹ 我们使用"本体"指有组织的领域知识体系，而非概念化的形式规范 [13]。智能体据此回答问题和审查申请，每个答案都立足于其引用的证据。

  • Grid Studio 是一个专为电力系统工程定制的智能体系统。它在自己的工程环境中工作，配备领域工具和一个将研究从接入点选择贯穿到最终报告的框架，并连接到 Grid Ontology 以获取其研究所需的知识。它报告的每个数字都由成熟的求解器计算。

贡献。

  1. 一种用于受监管工程工作的智能体设计，建立在三项原则之上，带有在人工批准下从使用中学习的记忆（第 3 节）。
  2. 一个电力系统基准套件，由八个已发表基准测试家族组成的 519 项任务，涵盖 4 至 9,241 条母线的网络，在同一深度尺度上以相同方式评分（第 4.1 节）。
  3. 结果与发现，针对编码智能体、检索流水线、排行榜条目和前沿模型，每个智能体的工作都对照其运行的研究进行验证（第 5 节）。Grid Ontology 比任何其他系统都更频繁地引用正确的法规证据。Grid Studio 在得分和智能体工作时间上均以统计显著性优势领先最好的编码智能体，且其在最大网络上的领先幅度最大。优化器参与使加固更便宜。

2 背景与相关工作

检索与引用。 检索增强生成以针对问题获取的段落为条件来约束模型 [27]。在其常见形式中，流水线搜索一次，模型根据返回的内容作答。搜索可以是词法或稠密的，通常后接重排序器 [47, 24, 37]。它也可以在从语料库构建的图上运行 [7]，或遵循文档自身的层级结构 [58]。更长的上下文窗口并不能消除良好检索的必要性 [28]。智能体方法则让模型决定检索什么并判断其找到的内容 [1]，或从编程环境探索语料库 [69]。由于审查者必须能够核查每个来源，引用与答案同样重要。关于归因生成的工作衡量引用是否支持论断 [10]，模型评判器对忠实度和答案质量评分 [8, 71]。LegalBench-RAG [42] 构建于 CUAD [15] 之上并与 LegalBench [14] 相关，以精确的字符跨度对检索评分，从而将找到正确文档与找到正确条款区分开来。

工具使用智能体及其评估。 工程工作需要一个既能阅读又能行动的智能体。ReAct 交错进行推理与行动 [67]，Toolformer 学习何时调用工具 [48]，Reflexion 加入自我批评 [52]，AutoGen 组合多个智能体 [65]，MANTA 让多智能体系统在运行时调整其智能体的协作方式 [17]。随着智能体开始行动，其评估从评判文本转向检查结果。SWE-bench 运行代码库的测试 [22]，AgentBench 覆盖多种环境 [29]，τ-bench 将最终数据库状态与目标状态进行比较 [68]。我们的严格通过通过检查每项研究所运行的电网状态，将这种基于状态的评分引入工程研究。

智能体记忆。 一个与同样的人共事数月的智能体也应该保留它学到的东西。CoALA 将语言智能体的记忆组织为工作、语义、情景和程序性存储 [53]，沿袭人类记忆中的区分 [57]。MemGPT 在上下文和外部存储之间分页信息 [39]。Generative Agents 和 Reflexion 将经验转化为指导后续行为的反思 [41, 52]，ExpeL 从过去的轨迹中提炼洞察 [70]，Voyager 则生长出一个技能库 [60]。这些系统自主学习。在受监管的工作中，一位工程师的会话不得悄悄改变同事的智能体，因此我们在 3.2 节描述的记忆加入了人工批准。

电力系统研究。 在工程工作中，智能体采取的行动是对电力系统分析的调用，这些分析的方法早已确立。潮流计算求解 AC 网络方程以获得一个运行点的电压和潮流 [63]。安全标准要求系统在任何单一可信停运下都能存活 [36]，因此预想事故（N-1）分析对每个元件停运重复潮流计算。短路、稳定和动态研究涵盖故障水平及扰动后的数秒 [25]，最优潮流（OPF）在网络约束内寻找成本最低的调度。MATPOWER [72]、pandapower [54] 和 PowerModels.jl [5] 等开源求解器实现了这些分析，若干基准测试从它们获取答案键。对工程师和智能体而言，困难不在于计算本身，而在于选择在哪个网络状态上运行哪些研究，以及对照规则解读结果。

电力系统的语言模型。 语言模型直到最近才被应用于这项工作。综述梳理了机遇与风险 [16, 32, 11]。智能体系统包括多智能体仿真框架 [21]、用于分析和运行的智能体 [23, 62]、用于并网影响评估的智能体 [49] 以及电力系统软件的工具服务器 [43]。其中若干在各自的任务集上评估 [23, 62]，这使得它们难以比较。共享基准测试随之出现。它们涵盖潮流问题（PFBench [50]）、智能体研究（PowerAgentBench [35]、PSAB [56]）、自然语言研究任务（PowerCodeBench [64]）、负荷、调度和拓扑变化下的潮流（PFΔ [46]，用 Ipopt 求解 [59]）以及自然语言 OPF 修改（ProOPF [51]）。较早的数据集提供独立参考，其中包括 PGLib-OPF [2]、OPFData [31]、Grid2Op/L2RPN 和 RL2Grid [6, 34, 33] 以及 IEEE PES 小信号基准系统 [4]。

3 系统概述

3.1 设计原则

P1. 证据先于答案。 每个答案和结论都锚定到源文件或申请人提交材料中的一段文字。

P2. 由成熟求解器计算。 模型选择、排序和解读研究，求解器产生每个数字。

P3. 人类决策权。 智能体准备工作，人做决策。智能体的判定与人的判定并列，决策需要指定人员的签核，研究在决策点暂停 [40]。

3.2 Grid Ontology

知识库。 Grid Ontology 存放申请所对照审查的立法、电网准则、标准和流程文件。我们实验中的 GB（英国）语料库有 27 份文件共 6,347 页，包括其中的图表。

有据答案。 智能体根据这个知识库回答问题和审查申请。它只根据找到的证据作答，并且必须引用其答案所依赖的段落。

记忆。 文件陈述规则，记忆保存智能体在应用规则时学到的东西。遵循 CoALA 分类法 [53]，它保存三类内容（表 1）。

表 1：记忆承载智能体在文档之外学到的东西。Grid Ontology 中保存的三类记忆。

类型 保存内容
语义 关于领域、运营商及其项目的事实，以及响应规则
程序性 技能，即为某项任务（如并网研究）编写的成文方法
情景 经验及从中得出的教训

自演化记忆。 三类记忆都随使用而变化。从近期工作中得出的教训 [41, 70] 成为经验，事实、规则和技能随着工作暴露智能体的不足而被添加或修订。会影响他人的更改只有在人批准后才生效。因此，智能体随使用而改进，同时每个共享的更改都保持可见和可归因，这是原则 P3 在学习上的应用。

3.3 Grid Studio

通过成熟求解器的研究。 Grid Studio 将电力系统研究作为工具提供给智能体。智能体选择运行哪些研究以及在哪个网络状态上运行，并解读结果，而每个数字都由成熟的求解器计算（P2）。

加固规划。 当项目需要加固时，智能体调用一个优化器来提出成本最低的工程方案，秉承输电扩展规划的精神 [26]。5.2 节对其进行了评估。

法规知识。 GB 法规集是我们自己的一套关于英国电网法规的 45 个问题，针对 GB 语料库的 27 份文件（6,347 页）提问。R1 问题由单个段落回答，R2 问题由图或表回答，R3 问题只能通过组合多个段落回答。我们以证据优先的方式构建它。从语料库中采样段落和图表，模型据此编写问题，证据不支持或无需证据的问题被丢弃，其余由领域所有者批准（附录 D）。Enterprise RAG Challenge 对 100 份公司年度报告（14,454 页）提出类似问题，约一半在报告中没有答案，因此系统还必须识别何时没有答案。LegalBench-RAG（R4）要求给出长合同中条款的精确跨度，我们使用其 CUAD 子集 [15] 的固定 50 题样本，该子集的 462 份合同是无页码的纯文本（约 390 万词）。ViDoRe V3 [30] 对 19,252 页英文和法文的视觉丰富文档提出 2,419 个问题，并对系统返回页面的排序评分。其自身的问题标签给每个问题一个深度（附录 D）。

电力系统工程。 八个基准测试家族在 4 至 9,241 条母线的网络上提供 519 项任务。L1 任务在已发布的网络上运行一项研究，L2 任务先应用陈述的变化，L3 任务必须先找到要改变什么，例如负载最重的线路。L4 任务重建一个包含 20 至 261 个值的已发布运行点，L5 任务将书面要求转化为改变后的优化问题。没有一个基准提出多阶段研究，因此 5.2 节单独测量了一项。

4.2 评估指标

法规知识。 我们对每个系统引用的证据评分。被引用项若来自同一文档且与锚点跨度重叠、位于锚点一页之内，或即为锚定图表，则视为匹配金标锚点。我们报告召回率、精确率、MRR、nDCG@10 [19] 和命中率，并由模型评判器对照金标答案为每个答案打分 [71]。LegalBench-RAG 和 Enterprise RAG Challenge 保留各自的指标和评分脚本，ViDoRe V3 保留其榜单的 nDCG@10（在其各集合上取平均）。

4.3 评估方法

比较的系统。 在法规基准测试上，我们将 Grid Ontology 与通用编码智能体（Claude Code，将语料库作为文件并拥有自己的文件和 shell 工具）、一次性检索流水线（搜索一次并从其前八个结果作答）进行比较，并在 Enterprise RAG Challenge 和 ViDoRe V3 上与其已发表的条目比较。在电力系统基准测试上，我们将 Grid Studio 与两个开箱即用的编码智能体（Claude Code 和基于 GPT-6.1 sol 的 Codex CLI，各配备 shell、Python 和作为文件的网络）进行比较。我们还将其与 Power-Agent [43, 44]（将 PowerMCP 的 pandapower 工具和 PowerSkills 的操作手册安装到 Claude Code 中）以及十一个基础模型（不带工具、以文本形式获得网络作答，其中包括前沿模型 GPT-6.1 sol 和 Fable 5.1）进行比较。Claude Code 和 Power-Agent 与我们的智能体运行在同一模型上，Power-Agent 按其作者发布的方式使用其工具和操作手册。我们还对每个系统的智能体工作时间（花在模型轮次和工具运行上的时间）计时。附录 D 给出了评估协议。

5 结果

5.1 Grid Ontology

要点：Grid Ontology 比任何其他系统都更频繁地引用正确的法规证据（召回率 0.967）。它还在 LegalBench-RAG 上领先（F1 0.980），并在 Enterprise RAG Challenge 和 ViDoRe V3 的已发表条目中排名第一。

表 3 给出了所有四个基准测试的结果。在 GB 法规集和 LegalBench-RAG 上，每个系统用同一模型作答，因此差异来自各自找到并引用的证据。在 Enterprise RAG Challenge 和 ViDoRe V3 上，Grid Ontology 在公开榜单上排名第一。

GB 法规集。 两个智能体都正确回答了每个问题，因此它们的差异在于引用的证据。Grid Ontology 比 Claude Code 在更多问题上引用了正确的证据（召回率 0.967 对 0.856），且差距在要求给出数字的单段落问题上最大（1.000 对 0.625）。这在审查中很重要，因为引用了错误段落的正确答案仍需人工核查。检索流水线正确回答的问题较少。带重排序器的向量检索最接近，而 PageIndex 和 GraphRAG 找到证据的问题不到一半。附录 A 中的示例 A 展示了一个问题。

LegalBench-RAG。 Grid Ontology 达到 0.980 的 F1，领先所有基线。它每个问题引用一份合同，而检索流水线最多引用五份，因此正确的合同通常在它们之中，但错误的也在。它唯一的一次失误是一份提交了两次的合同，它引用了签署副本，而答案键给出的是未签署草稿。在该基准更严格的条款级别上，它对流水线的领先是一个数量级（附录 E）。

Enterprise RAG Challenge。 该挑战自己的脚本对精确答案及其引用的页面评分，满分 150 [55]。Grid Ontology 得 124.5 分，而最佳已发表条目为 123.7 分，并且它对 51 个报告无法回答的问题中的 45 个正确地予以拒绝。

ViDoRe V3。 该榜单用 nDCG@10 对每个英文问题返回的前十页评分，在八个公开集合上取平均。Grid Ontology 得 70.23 分，而最佳已发表流水线为 70.01 分，并在八个集合中的四个上领先（附录 F）。

5.2 Grid Studio

要点：Grid Studio 得分最高，为 99.9%，在 519 项任务中的 516 项上有经验证的工作，并且它是最快的系统，每任务智能体工作时间中位数为 13.9 秒。两项领先均具有统计显著性。在优化器参与的情况下，其加固方案最多便宜 67%。

基础模型。 最好的基础模型 GPT-6.1 sol 正确回答了 519 项任务中的 250 项（48%）。给定文本形式的网络，最强的基础模型能手工求解小型潮流，但没有一个在超过 39 条母线的网络上有经验证的工作。没有一个能回答超过 30% 的 PFΔ 任务（需求解已发布的运行点），或七项 RL2Grid 任务中的两项以上（需比较开关操作），也没有一个端到端得分超过 41%。

得分与时间。 图 1 将每个得分与智能体工作时间对照。Grid Studio 每任务需要中位数 13.9 秒，而 Codex CLI 最多 21.6 秒，Claude Code 22.0 秒，因此它以最少的时间得到最高分。阅读网络并写出求解状态使基础模型每任务花费中位数 20 秒到近 3 分钟，因此所有其他系统都比 Grid Studio 慢且得分更低。更多时间并不能缩小差距：GPT-6.1 sol 和 Fable 5.1 每任务花费约 1 分钟和 3 分钟，仍低于 41%。

领域工具必须触达研究。 Power-Agent 将 PowerMCP 的 pandapower 工具和 PowerSkills 的操作手册安装到 Claude Code 中，与 Grid Studio 运行在同一模型上，得分接近 Grid Studio。其 PowerMCP 工具仅在 519 项任务中的 46 项上被调用，并独立完成了 16 项。其余 503 项需要智能体自己编写 pandapower 代码，473 项从未调用 PowerMCP，而 409 项遵循了 PowerSkills 操作手册。因此，其结果主要来自智能体为每项任务编写的代码，而非领域工具。Grid Studio 的工具触达基准测试要求的每项研究，这正是使其工作既可验证又快速的原因。

真实研究规模更大。 基准网络最多有 9,241 条母线。运营商的规划模型可达数万条母线，而一项并网研究串联多项研究，从筛选方案到设计加固。基线系统在基准测试的高端已经力不从心。在超过 2,000 条母线网络上的 109 项任务中，Power-Agent 通过 106 项，Codex CLI 90 项，Claude Code 74 项，而 Grid Studio 通过 108 项，基础模型一项也未通过。Grid Studio 的数字来自成熟的求解器而非为每项任务编写的代码，其工作可以在每一步被检查，这使其成为真实规划研究的更好设计。

6 结论

Grid Agents 建立在三项原则之上。答案立足于被引用的证据，数字来自成熟的求解器，工程师做出决策。Grid Ontology 比通用编码智能体或检索流水线更频繁地引用正确的法规证据，在 LegalBench-RAG 上领先，并在 Enterprise RAG Challenge 和 ViDoRe V3 的公开排行榜上排名第一。在来自八个已发表电力系统基准测试家族的 519 项任务上，Grid Studio 得分最高且所需智能体工作时间最少，两者均具有统计显著性。在优化器参与的情况下，其加固方案的成本平均比智能体单独设计的方案低 33–67%。

附录 B 电力系统指标

每项电力系统任务按系统报告的答案和产生该答案的工作评分。本附录定义式 1 的各项术语、工作如何验证以及各项如此加权的原因。

为何对工作评分。 大多数答案是标准 IEEE 和 PGLib 网络上的电压、负载率或成本，因此一个数值可以从已发表结果中回忆、侥幸猜近或通过对错误电网状态的研究得到。工程师只有在其背后的研究已知正确时才会据此行动，因此只有答案正确且工作经过验证才能获得满分。

单项任务的术语。 对任务 i，设 a_i 为报告值，g_i 为答案键，按基准测试自身的容差比较。

  • 正确答案：若 a_i 在 g_i 的容差之内且每个指定选择（如示例 A 中的停运对）与答案键匹配，则 r_i = 1，否则 r_i = 0。
  • 验证的工作：若记录的工作显示所需研究在所需电网状态上运行，则 v_i = 1，否则 v_i = 0。
  • 严格通过：s_i = r_i v_i。
  • 数值接近度：容差内 c_i = 1，否则为 max(0, 1 − |a_i − g_i| / max(|g_i|, 1))。

A、P 和 c̄ 是 r_i、s_i 和 c_i 在全部 n 项任务上的均值，因此 E 是 e_i = 0.25 c_i + 0.25 r_i + 0.5 s_i 的均值。当任务答案正确且工作经验证时得 1 分，仅答案正确时得 0.5 分，答案错误时至多 0.25 分，无答案时得 0 分。系统无法执行的任务（例如因缺少工具）保留在均值中。将其排除会使该系统在较容易的子集上被评分。

验证工作。 所需工作来自任务本身，绝不来自答案键：问题固定的电网状态（已发布网络加上每个陈述的变化）、研究类型、任何陈述的研究参数，以及（对于比较类任务）每个候选状态。表 7 显示了对每类系统检查的内容。基例已持有的值可以重述或保持不变，但任何其他变化（如额外断开的线路）都会构成不同的状态并导致失败。

为何如此加权。 严格通过占一半权重，因为它是实际使用中重要的结果，因此工作无法展示的系统至多得一半分数。答案准确率占四分之一，因此无验证工作的正确答案仍胜过错误答案。接近度占最后四分之一。它在每个正确答案上等于 1，只区分接近失误和大偏差。对标幺值电压接近 1 的猜测能获得其大部分，因此它从不决定通过与否。

附录 D 评估协议细节

GB 法规集。 页面和图表用带种子的生成器从语料库中采样，绝不通过被测系统。模型只看到采样的段落或图表，并编写问题、答案和逐字引用。单独的检查丢弃证据不支持的问题和无需证据即可回答的问题 [12]，其余由领域所有者批准。每个问题保留其证据锚点（文档、页码、字符跨度或图表）。45 个问题（25 个文本、14 个图表、6 个多跳）来自 27 份文件中的 23 份。

ViDoRe V3 深度。 根据基准测试自身的标签，203 个多跳问题为 R3，另外 1,312 个由表格、图表、信息图或图像回答的为 R2，其余 904 个为 R1。

电力系统问题。 每项任务都表述为关于指定网络、需报告一个数值的问题，使每个系统收到相同的措辞并以相同方式评分。PFBench、PowerCodeBench 和 ProOPF-B 发布了此类问题，我们按其作者的原话提问。当某问题遗漏其答案所依赖的数值或选择时（352 项 PowerCodeBench 中的 156 项和 19 项 ProOPF-B 中的 6 项），我们从该项自身的记录中恢复，绝不添加答案。PFΔ 和 PGLib-OPF 发布了网络和求解结果但没有问题，因此我们用固定模板表述每项任务，指明网络、任何陈述的变化和要报告的数值。PowerAgentBench-SS 发布了任务规范但没有问题集，PSAB 的任务为处理文件的智能体而构建，RL2Grid 对强化学习回合而非答案评分。对这三个基准，我们保留各自测试的研究类型并自己编写问题，答案来自参考求解器。总之，519 个问题中 389 个用其作者的原话，130 个是我们的。我们的来自固定模板，而非语言模型。

答案键。 答案键绝不来自被测系统。法规类答案键是已发布的，GB 法规集的除外（由领域所有者批准）。PFBench、PowerCodeBench 和 ProOPF-B 使用其作者发布的答案，PFΔ 使用其作者的 Ipopt 解，PGLib-OPF 使用其发布的 OPF 基线（其潮流任务用参考求解器）。三个适配家族（表 2）对照参考求解器评分，因此我们将其视为较弱的证据。在无模型运行时，参考求解器复现了 PFBench、PFΔ、PowerCodeBench 和 ProOPF-B 的每个已发布答案（460 项任务），因此求解器差异绝不计为智能体失败。

隔离。 每个编码智能体任务在自己的容器（2 vCPU、8 GB）中运行，无答案键且无网络访问，获取了任何内容的任务将计为未回答。没有任务这样做。对每次带文件访问的 GB 法规集运行的审计未发现读取答案键。Grid Studio 在关闭记忆的情况下运行，其计时运行使用相同的容器大小，每容器一项任务。

智能体工作时间。 智能体工作是花在模型轮次和工具运行上的时间，从每个智能体自身的时钟读取。它不包括启动时间，启动涵盖容器的启动和拆除以及智能体的启动，对 Grid Studio 还包括其求解器的启动。Codex CLI 不报告这种拆分，因此其时间是整个进程的运行时间，为上界。基础模型的所有时间花在一次补全上。图 1 报告 519 项任务上的中位数。编码智能体在自己的脚本内加载库，而启动 Grid Studio 的求解器（我们测量时平均 6.7 秒）不计入。
