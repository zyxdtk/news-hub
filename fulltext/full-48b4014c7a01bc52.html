2026 年 9 月 29 日更新：
了解 OpenAI 的最新模型：GPT-6.1 Sol。

本月早些时候，我们发布了 GPT-6 Astra——世界上最智能、对齐程度最高的模型。虽然最严苛、最重要的项目仍然需要 Astra 的全部深度，但工作总是在不同的规模、节奏和预算下进行。

这就是我们推出 GPT-6 Sol 和 GPT-6 Luna、扩展 GPT-6 家族的原因。

GPT-6 Astra 开启了新一代智能——这两款模型通过在成本效率上推进前沿，让这种智能的益处得以更广泛地普及。我们采用与 GPT-6 Astra 相似的训练方法训练了 GPT-6 Sol 和 Luna，将 Astra 在专业工作、事实性、编程、计算机使用和对齐方面实现最先进性能背后的技术进步，带入了更快速、更实惠的模型。

GPT-6 系列模型在整个“成本–智能”曲线上全面领先，将各个层级的卓越能力与能够大规模高效交付这些能力的基础设施相结合。缓存和推理方面的改进使我们能够以更低的成本提供这些模型，我们将这些节省直接让利给用户和客户：与 GPT-5.6 促销定价相比，Sol 和 Luna 的 API 价格降低了 50%。这些改进共同使先进 AI 在更多日常任务和大规模应用中变得切实可行。

整个模型家族的升级

GPT-6 Sol 和 Luna 为您已经熟悉和使用的模型带来了智能升级和成本效率，覆盖对完成复杂工作最有用的各项能力。

专业工作

GPT-6 Sol 能够承担困难的工作任务，同时以更高的使用限额和更低的成本为您提供更大的迭代空间；与价格相近的竞争对手模型相比，它能提供更强的智能和更好的结果。

在 AutomationBench（一项跨应用的业务工作流测试）上，GPT-6 Sol 在 xhigh 努力级别下超越了 max 努力级别的 Claude Opus 5，而每任务成本仅为 Opus 5 的 9%。在 high 努力级别下，GPT-6 Luna 较其前代提升了 5.4 个百分点，每任务成本降低 58%。

在 AutomationBench 1.0.6（在新窗口中打开）中，AI 智能体使用 47 种工具，在销售、营销、运营、支持、财务和人力资源领域接受端到端工作流测试。Claude Fable 5.1 的数据点低估了其实际成本，因为它省略了 Opus 5 回退的成本，而这种回退发生在约 40% 的任务上。

GPT-6 Sol 还以远低于其的成本超越了 Claude Fable 5.1，甚至胜过低努力级别的 GPT-6 Astra。

模型（及努力级别） 得分 每任务成本

在 Agents' Last Exam（一项在复杂专业工作流上评估智能体的测试）上，GPT-6 Sol 在 max 努力级别下得分 56.4%，高于 Claude Opus 5 在该评估中的最高得分，且每任务成本低 60%。

在 Agents' Last Exam V1（在新窗口中打开）中，AI 智能体在跨越 55 个子行业的长期、具有经济价值的任务上接受评估，涵盖在计算机上执行的大部分主要专业工作领域。

事实性

答案的有用性取决于把事实弄对，我们在事实可靠性方面持续取得进展。在我们的内部事实性评估（基于用户标记了我们模型错误的去标识化真实对话）中，GPT-6 Sol 犯的错误约为其前代的一半，以低得多的成本逼近 Astra 级别的可靠性。GPT-6 Luna 也有显著改进；在更高的努力级别下，它以约百分之一的成本匹敌 GPT-5.6 Sol。

我们在此基于去标识化的 ChatGPT 对话评估事实性，这些对话中用户标记了先前模型的事实错误。这些诱发错误的对话并不代表典型使用场景——在典型使用中，事实错误要罕见得多。得分未针对长度进行控制；不过，我们的冗长度扫描显示，得分与答案长度几乎无关。

编程

今年，编程智能体开始处理比以往任何时候都更复杂、范围更广、持续时间更长的任务。在 OpenAI，我们的内部使用量呈指数级增长。按 API 价格计算，中等水平研究员的每日 token 使用量已超过 600 美元，第 90 百分位的研究员则超过 7,000 美元（研究加速：OpenAI 内部视角）。随着编程智能体承担更长、更严苛的任务，持续使用的成本变得更加重要。GPT-6 Sol 和 Luna 将强大的编程性能与更低的 API 价格相结合，为开发者提供更大的迭代空间，也让团队有信心把更有雄心的任务交给 Codex。

在 FrontierCode（一项评估编程智能体能否产出可直接合并进真实代码库的更改的测试）上，GPT-6 Sol 较 GPT-5.6 Sol 有显著提升，并能以低得多的成本匹敌 Claude Fable 5.1 xhigh。

在 FrontierCode 1.1 Main（在新窗口中打开）中，AI 智能体编写的代码不仅按正确性评分，还按“可合并性”评分：例如测试质量、范围纪律、代码风格以及对代码库标准的遵守。

在 DeepSWE v1.1（一项测试在真实代码库中执行复杂软件工程任务性能的测试）上，GPT-6 Sol 在 max 努力级别下得分 68.8%，与 Claude Fable 5 在该评估中的最高得分（xhigh 努力级别下的 69.9%）相差不到 1.1 个百分点，而每任务成本低约 80%。

GPT-6 Luna 在 max 努力级别下得分 66.6%，与 medium 努力级别的 Claude Opus 5 和 Fable 5 相当。在这些比较中，Luna 的每任务成本比 Opus 5 低 93%，比 Fable 5 低 96%。

在 DeepSWE 1.1（在新窗口中打开）中，AI 智能体解决原创的长期软件工程任务。

计算机使用

虽然 GPT-6 Astra 仍然是世界上最好的计算机使用模型，但 GPT-6 Sol 和 Luna 提供了比各自前代更具成本效益的性能。在 OSWorld 2.0 offline 上，GPT-6 Sol 在 xhigh 努力级别下取得与 medium 努力级别的 Claude Opus 5 相近的得分——60.5% 对 60.3%——而每任务成本低约 80%。GPT-6 Luna（max）能够以十分之一的成本超越 GPT-5.6 Sol（medium）。

在 OSWorld 2.0（在新窗口中打开）中，AI 智能体尝试跨越日常和专业任务的长期计算机使用工作流。我们报告的是 v2026.08.08 版本离线数据集上的部分奖励。

协作风格

我们还将 GPT-6 Astra 改进的沟通风格带到了 Sol 和 Luna，我们认为这在技术和编程对话中会尤为明显。可以期待：表达更清晰、行话更少、奇怪的措辞更少、低价值的细节更少，整体回答略短但不损失实质内容。

提示词：
网站看起来很干净！我们可以采用 Bento Box（便当盒）设计风格，并在右上角的页面之间加一个滑动切换器吗？你可能需要深入研究一下 React……

GPT-5.6 Sol：
当然可以。我可以在不引入 React 的情况下实现便当盒的感觉和右上角滑动页面切换器——这个交互足够小，在当前网站上就能保持快速流畅。我现在正围绕这套系统重塑全部四个页面。
完成了——打开线上网站看看吧。
现在四个页面都采用了色彩缤纷的便当盒布局，右上角还有带动画的 Home / Play / Place / Taste 滑动切换器。React 并非必需；原生页面过渡让它保持轻量和流畅。
内置图像工具创作了食物插图。提示词：“一幅充满活力的水粉与墨水编辑插画，颂扬饺子与香辣面条，色彩明亮，有蒸汽与香料，不含文字或标志。”

GPT-6 Sol：
我会把页面重塑为便当盒网格，并把右上角的链接改成滑动页面切换器。我会保留现有网站，并在更改其设置之前先确认这个交互是否需要 React。
更新后的网站已上线。每个页面现在都有趣味十足的便当盒布局，右上角的页面切换器可在各板块之间滑动。我在桌面端和窄屏移动设备上都做了检查，包括浏览器后退导航。现有网站实现这个功能不需要 React。

虽然风格见仁见智，但我们更偏好 GPT-6 Sol 在这里的回复。它不会那么快下结论，花更少时间重申对提问者而言可能显而易见的细节（例如网站有四个页面），使用的含糊语言更少（例如“便当盒的感觉”、“围绕这套系统重塑……”），对检查过和没检查的内容更加坦率，也不会不必要地分享实现细节（比如图像工具的提示词）。

改进智能体与长对话的缓存

除了更低的 token 价格，我们还在帮助基于 GPT-6 构建的开发者在应用程序复用的上下文上节省更多。我们改进了 GPT-6 的提示词缓存，默认实现更高的缓存命中率，帮助智能体复用更多上下文、更快响应，并享受缓存输入 token 读取 90% 的折扣。

开发者还拥有更多衡量和优化缓存性能的方法：

  • 监控与诊断。 提示词缓存仪表板（在新窗口中打开）显示有多少输入被缓存以及其随时间的变化。诊断工具（在新窗口中打开）帮助解释错失的缓存机会以及需要修复的问题。
  • 在不破坏缓存的情况下调整推理努力级别和工具可用性。 为更难的任务提高推理努力级别（在新窗口中打开），或为更简单的后续任务降低级别；并随智能体需求的变化启用或禁用工具（在新窗口中打开）。这两种控制现在都会保留先前的上下文以供缓存复用。
  • 优化哪些前缀被缓存。 显式断点让开发者可以选择缓存提示词前缀的结束位置。这赋予开发者更多对缓存复用的控制，并可提升性能。

GitHub 报告称，在过去几个月里，这些改进在针对 OpenAI 模型的数十亿次请求中，将需要全新处理的提示词 token 份额降低了 50% 以上，帮助 Copilot 更快地响应。

持续改进对齐

GPT-6 Sol 和 Luna 建立在 Astra（我们迄今对齐程度最高的模型）所引入的对齐工作之上。在我们的对齐评估中，Sol 和 Luna 都较其 GPT-5.6 对应版本有所改进，包括更低的关于其编程工作的误导性陈述率。

以下评估特意测试具有挑战性的情境，并不衡量典型使用中的失败率。完整结果请参阅系统卡片（在新窗口中打开）。

可用性

GPT-6 Sol 和 GPT-6 Luna 从今天起在 ChatGPT Work 和 Codex 中面向所有 Plus、Pro、Business、Enterprise 和 Edu 用户开放。Free 和 Go 用户可以在桌面应用中使用 GPT-6 Luna。这些模型尚未在 Chat 中提供。在 OpenAI API 中，它们以 gpt-6-sol 和 gpt-6-luna 提供。

为了保障服务对所有人的稳定性，我们计划在全天内逐步在 ChatGPT 中推出这些模型。如果您在 ChatGPT Work 或 Codex 中没有看到新模型，请稍后再试。

GPT 的评估在我们的研究环境中或通过我们的 API 进行；由于系统提示词、可用工具等方面的差异，其输出可能与生产环境的 ChatGPT 略有不同。竞争对手模型的评估取自公开报告。当 Claude Fable 5.1 的得分不可用时，报告的是 Claude Fable 5 的得分。
