进化以学习：面向模型自我提升的梯度对齐经验进化

作者：Haoyuan Li、Gangyi Zhang、Dong Wang、Yang Liu、Daoxuan Liu（中国科学技术大学、阿里巴巴集团）、Jiancan Wu、Shiu-hong Kao、Wu Liu、Yicong Li、Yongdong Zhang（中国科学技术大学、新加坡国立大学）

摘要

自进化语言模型可以通过测试时交互、反思和提示优化持续获得有用经验，但将这种经验转化为模型本身以确保自我提升仍然具有挑战性。在策略自蒸馏（OPSD）为将测试时信息内化到模型参数提供了一种自然机制，但它很大程度上假设生成的经验值得学习。我们表明这一假设并不总是成立：提升测试时性能的经验可能提供有限甚至有害的训练信号。为了更好地刻画哪些经验应该被内化，我们系统地分析了多个任务和反思模型中的多样化突变经验，发现基于梯度的对齐比即时的测试时改进更能可靠地指示下游蒸馏收益。基于这一发现，我们提出了E2L，一个根据估计的训练效用迭代生成、评估和蒸馏经验的自进化框架。E2L闭合了经验生成和参数学习之间的循环，使智能体能够自主产生适合自我提升的经验。

1 引言

大语言模型（LLM）智能体可以通过交互持续获得任务特定经验（Ouyang等，2025），但这种经验往往局限于外部上下文（Wang等，2025b；Ouyang等，2025；Fernando等，2024；Agrawal等，2026）。因此，模型必须重复检索相同的经验作为上下文来保持行为，使模型的行为容易受到检索失败的影响；同时，随着经验的积累，其推理成本越来越高。最近的上下文蒸馏方法通过将文本经验转移到模型参数中来解决这一差距，使上下文经验能够内化为模型能力（Zhao等，2026；Ye等，2026b）。这使得通过反复内化模型为自己编写的经验来实现持续自我提升的循环成为可能。

然而，并非每个经验都值得内化。如图1(a)所示，GLM-5.2生成的两个候选经验在AIME25上实现了相同的上下文条件准确率。一个提供了逐步推理和验证的简洁指令，而另一个指定了更详细的检查和输出约束。然而，经过20步在策略自蒸馏后，得到的模型分别达到21.11%和18.06%的准确率，差距为3.06个百分点。这提出了一个基本问题：在将经验蒸馏到模型之前，我们能否确定它是否值得学习？

一个直观的标准是指令遵循性能——模型在候选经验条件下实现的推理时准确率。直观上，实现更高推理准确率的经验应该对蒸馏更有信息量。这一标准广泛用于在推理时评估和优化经验（Agrawal等，2026；Yuksekgonul等，2025），使其成为经验选择的自然起点。

然而我们发现，指令遵循性能不一定反映经验内化的信息量。事实上，在图1(b)中，在我们评估的33个候选中，推理时准确率和蒸馏后准确率基本不相关（ρ=-0.059，p=0.746）。原因是推理时准确率是在经验作为上下文给出的情况下测量的，因此它无法分离经验提供的内容和模型实际获得的内容——一个阅读答案的模型和一个学会推导答案的模型看起来是一样的。但经验不会在蒸馏中存活，存活的只是它引起的参数更新。因此，要评估经验内化的价值，我们需要衡量模型在学习它之后自身会如何变化。

这促使我们通过经验更新的参数直接评估经验。对于模型目前做错的样本，监督损失的梯度提供了参数应该如何变化以减少这些错误的参考。因此，我们将此梯度与蒸馏候选经验引起的梯度进行比较。它们的一致性，我们称之为梯度对齐，衡量这个经验是否会把模型推向解决其当前缺陷的方向。如图1(c)所示，梯度对齐与候选中的蒸馏后准确率相关（ρ=0.48，p=0.006），而推理时准确率基本没有预测信号。

基于这些发现，我们提出了Evolve-to-Learn（E2L），它将梯度对齐从事后评估信号转变为迭代驱动经验进化的目标。在每次迭代中，变异器（Agrawal等，2026）使用执行轨迹和评估反馈来修改选定的经验。E2L保留基于帕累托的探索，同时引入基于对齐的候选接纳和父代选择通道。这种设计保留了替代搜索分支，并给高对齐经验额外的机会来生成更多候选。进化后，E2L选择具有最高梯度对齐的经验，并通过在策略自蒸馏将其内化。

图1：相同的推理时准确率可能导致不同的内化结果。(a) GLM-5.2生成的两个经验在AIME25上实现相同的上下文条件准确率（20.83%）。经过20步在策略自蒸馏后，较高对齐的经验（上）产生21.11%的准确率，而较低对齐的经验（下）为18.06%，差距为3.06个百分点。(b-c) 在33个候选经验中，指令遵循准确率与蒸馏后准确率几乎无相关性（ρ=-0.059），而模型错误上的梯度对齐与蒸馏后准确率相关（ρ=0.484）。

我们的主要贡献有三方面：

  • 我们研究如何评估经验可蒸馏性，发现经验条件准确率并不总是预测自蒸馏收益。我们提出梯度对齐作为评估信号，并实证验证其在经验选择中的有效性。
  • 我们提出E2L，一个结合基于帕累托和基于梯度对齐的选择策略的经验搜索框架，使智能体能够通过自蒸馏自动生成、完善和选择提示以提升自身能力。
  • 我们在数学问题、问答和安全任务上评估E2L。E2L-Alignment在所有四个基准上取得最佳结果，且在推理时无需所选经验即可保持收益。

2 预备知识

2.1 在策略自蒸馏

我们使用经验 c 表示额外的文本信息，如反思、技能、解决方案策略或任务摘要。我们将在线策略自蒸馏视为自蒸馏基线，其中以额外经验为条件的模型作为其无条件对应模型的教师（Ye等，2026b）。条件信息可能包括目标答案（Zhao等，2026）、任务相关技能（Yang等，2026）或其他有用内容。给定输入 x 和 c，学生 π_θ 在不观察 c 的情况下生成响应 y，而条件教师在同一学生生成的轨迹上提供token级监督。

设 p_{θ,t} = π_θ(·|x, y_{<t})，q^c_{θ̄,t} = π_θ̄(·|x, c, y_{<t})。（1）

学生通过最小化反向KL散度来训练匹配教师分布：

L_OPSD(θ;c) = E_{x~D, y~π_θ(·|x)}[1/|y| Σ_{t=1}^{|y|} D_KL(p_{θ,t} ‖ sg[q^c_{θ̄,t}])]，（2）

其中 D 表示训练输入分布，sg 停止通过教师分布的梯度，θ̄ 表示教师参数。

2.2 反思性经验搜索

反思性变异。文本经验可以在保持模型参数固定的情况下使用执行反馈进行优化。给定候选池 P 中的父代经验 c_p，反思模型检查其执行轨迹 τ_p 和评估反馈 f_p 以产生修改后的经验（Agrawal等，2026）：

c' = Mutate(c_p, τ_p, f_p)。（3）

反馈可能包括任务分数和观察到的错误，这些信息用于修改父代经验。

基于帕累托的接纳。设 v(c)=(v_1(c),…,v_m(c)) 表示经验 c 在 m 个验证实例上的分数。如果一个经验的分数在每个实例上都不低于另一个，并且在至少一个实例上严格更高，则称其支配另一个。对于候选集 S，我们定义 Pareto(S) 为在至少一个验证实例上达到最高分数的非支配经验（包括并列）。我们使用以下谓词表示基于帕累托的接纳：

ParetoAccept(c', v(c'), P) = 1[c' ∈ Pareto(P ∪ {c'})]。（4）

此标准保留在验证实例上具有互补优势的候选。集合构造和变异提示在附录D中提供。

3 方法

我们引入E2L来解决两个问题：什么使经验值得内化，以及智能体如何自动生成此类经验？E2L将基于帕累托的评估与梯度对齐相结合，后者衡量经验诱导的蒸馏更新是否与改进任务性能的参考方向对齐。这些标准共同管理经验进化期间的候选接纳和选择，之后选定的经验通过在策略自蒸馏内化。图2展示了整体框架。

3.1 梯度对齐作为可蒸馏性标准

经验条件准确率衡量模型在经验下的表现，而可蒸馏性关注模型在学习它之后的改进程度。这些目标不一定一致：具有相似推理准确率的经验可能在蒸馏期间引起不同的参数更新。因此，我们通过经验引起的学习方向来评估经验，使用梯度对齐来评估该方向是否支持目标任务的改进。

梯度对齐。设 θ=(φ,ψ) 表示学生参数，其中 φ 包含用于梯度评估的参数。为了保持计算成本可控，我们使用最后四个Transformer层的参数作为 φ（Killamsetty等，2021；Zhang等，2023）。设 D_err 是有标记参考集的固定子集，包含初始学生在没有额外经验的情况下回答错误的问题。我们使用这些问题的参考解 y* 定义参考损失：

L_ref(θ) = -1/|D_err| Σ_{(x,y)∈D_err} log π_θ(y|x)。（5）

对于候选上下文 c，设 L_OPSD(θ;c) 表示学生生成轨迹上的蒸馏损失，通过上下文条件教师停止梯度。两个梯度及其对齐 A(c) 为：

g_ref = ∇_φ L_ref(θ)，g_c = ∇_φ L_OPSD(θ;c)，（6）

A(c) = cos(g_ref, g_c) = g_ref^T g_c / (‖g_ref‖_2 ‖g_c‖_2)。

两个梯度在同一学生检查点评估，参考答案在不使用候选经验的情况下使用。参考解指导经验选择，不用于OPSD更新。

局部解释。考虑 φ 上的一步SGD，保持 ψ 固定：φ' = φ - ηg_c。一阶展开给出：

L_ref(φ', ψ) ≈ L_ref(φ, ψ) - η‖g_ref‖_2‖g_c‖_2 A(c)。（7）

对于足够小的步长和相等的更新范数，更高的对齐因此预测参考损失的更大局部下降。这激发 A(c) 作为比较候选经验的标准。当蒸馏更新所有模型参数时，所选层上的对齐作为代理。

3.2 经验进化与自蒸馏

设计动机。我们的目标是发现对自蒸馏有价值的经验。然而，当前对齐度低的经验仍可能通过变异产生高对齐的后代。仅使用对齐作为接纳标准可能会丢弃有用的搜索分支。我们保留基于帕累托的探索并引入额外的对齐通道，给高对齐经验进入候选池并生成更多候选的机会。详见附录D。算法1展示了整体过程。

候选生成与接纳。从初始候选 c_0 开始，我们维护已接纳候选的池 P。在每次迭代中，我们选择父代 c_p 并使用2.2节中定义的变异算子生成候选：

c' = Mutate(c_p, τ_p, f_p)。（8）

我们评估其验证性能 v(c') 和梯度对齐 A(c')。如果满足 ParetoAccept 或在纳入后排名对齐Top-N之中，候选进入 P。对于有效对齐分数，后一条件为：

|{c∈P_valid: A(c)≥A(c')}| < N，（9）

其中 P_valid 包含具有有效对齐分数的已接纳经验。两个接纳通道独立运行。

父代选择与池维护。父代选择结合基于帕累托的采样和对齐Top-N经验的额外采样机会。这允许来自两个通道的候选为后续经验生成做出贡献。我们通过额外采样权重或其各自采样分布的等概率混合来实现；详细信息在附录D中提供。池成员使用缓存评估更新，同时保留所有已接纳的候选及其父代关系。在预热期间，当|P|≤N时，接纳使用小批量改进，父代选择使用基于帕累托的采样。

最终选择与自蒸馏。在耗尽搜索预算后，我们选择具有最高有效对齐的已接纳经验：

c* = argmax_{c∈P_valid} A(c)。（10）

然后我们使用公式2中的目标内化 c。学生在不观察 c 的情况下生成响应，而经验条件自教师在这些轨迹上提供token级监督，通过教师分布停止梯度。参考解用于构建经验评估的参考方向；蒸馏目标来自自教师。

4 实验

我们评估哪些经验值得蒸馏，这些知识是否可以指导经验进化，以及由此产生的收益来自哪里。我们的实验解决两个研究问题：

  • RQ1：E2L是否识别值得蒸馏的经验并提升模型性能？
  • RQ2：哪些组件对E2L的有效性有贡献？

4.1 实验设置

模型与阶段。E2L包括经验进化和自蒸馏。在经验进化期间，Qwen3-8B生成轨迹（Yang等，2025），而Qwen3.7-Max、DeepSeek-V4-Pro和GLM-5.2生成反思和候选经验（Alibaba Cloud，2026；DeepSeek-AI，2026；GLM-5 Team，2026）。参考梯度从有标记的诊断示例计算。在自蒸馏期间，Qwen3-8B从其自身经验条件预测中学习。

数据与评估。我们在数学推理、HotPotQA（Yang等，2018）和JailbreakBench（Chao等，2024）上进行评估。对于数学，我们将AIME（美国数学协会）2022–2024分为45个训练和45个验证问题，并在AIME 2025、AIME 2026上评估。我们报告数学准确率，AIME每题12个样本，LiveBench Math每题一个样本。所有评估使用非思考模式并省略所选经验。A.2总结了数据集大小和任务特定指标。

训练协议。我们在相关性研究中每个候选运行20个OPSD步以限制评估许多经验的成本，主实验运行50步。完整数据分割、参考梯度构造、提示以及训练和解码配置在附录A中提供。

5 相关工作

自进化语言模型与智能体。基于经验的自我进化通过更新文本经验同时保持模型参数固定来改进模型行为。代表性方法包括Reflexion中的反思记忆（Shinn等，2023）、GEPA中的反思提示搜索（Agrawal等，2026）和ACE中的累积策略（Zhang等，2025）。这些方法激发了我们的经验进化过程，但主要优化经验条件性能而非经验对后续参数学习的效用。

上下文蒸馏与在策略自蒸馏。上下文蒸馏将上下文条件行为转移到模型参数（Snell等，2022）。在策略蒸馏在学生生成的轨迹上提供教师监督（Agarwal等，2024）。在这一范式内，OPSD和SDFT使用特权信息或演示构建自教师（Zhao等，2026；Shenfeld等，2026），而OPCD内化经验知识和优化提示（Ye等，2026b）。SDAR将技能条件自蒸馏与强化学习相结合（Lu等，2026），Flux-OPD与学生一起更新上下文监督（Wang等，2026）。这些研究开发了构建和内化上下文监督的机制，留下了如何评估候选经验对下游训练效用的问题。我们研究进化经验的推理时性能与其后续自蒸馏收益的关系。E2L使用基于梯度的诊断来评估候选经验引起的更新，并将此信号纳入经验进化以选择值得蒸馏的经验。

6 结论

我们研究如何识别和进化值得通过在策略自蒸馏内化的上下文。我们确定梯度对齐作为上下文可蒸馏性的有用信号，并引入E2L，一个结合基于帕累托和基于梯度对齐选择策略的上下文搜索框架。该框架使智能体能够自动生成、评估和完善通过自蒸馏提升自身能力的提示。在数学推理、问答和安全评估中，E2L-Alignment在推理时无需所选上下文即可改进Qwen3-8B优于基础模型，在表1中的所有四个基准上取得最佳结果。这些结果证明了E2L在将自动进化的上下文转化为模型能力增益方面的有效性。

我们的实验集中在三个任务领域的Qwen3-8B。将E2L扩展到其他模型规模和重复自我进化周期是未来工作的自然方向。当前实现使用有标记的诊断示例计算参考梯度，并在上下文搜索期间需要额外计算。探索替代参考信号和更高效的上下文搜索方法可以拓宽其适用性并降低搜索成本。自蒸馏本身也可能不稳定，导致训练结果的可变性。改进底层蒸馏过程的稳定性是未来工作的互补方向。

A.1 数据集

AIME。AIME是美国数学协会的15题邀请数学考试，每个答案为0到999的整数（美国数学协会）。我们将2022–2024年的90道题汇总，45/45分割用于训练和验证，而2025和2026版本构成保留测试集。

HotPotQA。HotPotQA是一个基于维基百科的多跳问答数据集，其中问题需要对多个文档进行推理，并包括句子级支持事实注释（Yang等，2018）。我们使用固定种子从官方训练分割中抽取150个训练问题，从官方验证分割中抽取300个验证和300个保留测试问题。

LiveBench。LiveBench是一个经常更新的基准，具有自动评分任务（White等，2025）。我们使用其168个示例的数学评估集来评估在AIME 2025和AIME 2026上评估的相同AIME训练检查点。LiveBench仅用于评估，没有单独的上下文搜索或在LiveBench示例上的训练。

A.2 数据集与评估指标

数学推理。我们使用AIME 2022–2024的90道题，分为45个训练和45个验证问题。我们使用种子0到AIME 2022–2024池和45/45分割。AIME 2022–2024的45个训练和45个验证问题用于GEPA树构造。它们与用于前/后相关性分析的评估集不同：该分析中的训练前和训练后准确率都在相同的30道AIME 2025问题上测量。在AIME上训练后，我们在AIME 2025、AIME 2026和168个示例的LiveBench Math测试集上评估相同检查点。LiveBench示例不用于经验构造、梯度诊断、训练或检查点选择。

对于AIME，我们每个问题生成12个响应并通过平均所有响应的正确性来估计pass@1：

pass@1 = 1/(12N) Σ_{i=1}^N Σ_{j=1}^{12} 1[ŷ_ij正确]，（11）

其中N是测试问题数。这通过每题平均12个样本来估计单响应成功概率；它不会仅因为其12个响应中的任何一个正确就将问题计为正确（pass@12）。

对于LiveBench Math，我们每个示例生成一个响应并报告严格完全准确率：

FullAcc = 1/N Σ_{i=1}^N 1[s_i ≥ 1.0]，（12）

其中s_i是示例i的评估器分数。部分正确的响应不计为正确。

HotPotQA。我们使用Hugging Face HotpotQA配置，分别使用种子0和2从官方训练分割中抽取150个训练问题，从官方验证分割中抽取300个验证和300个保留测试问题。主要结果中的HotPotQA分数是Answer EM。评估协议为每个测试问题采样四个独立种子的响应。项目评估器提取最后的Final Answer行，并应用小写、标点和冠词移除以及空格规范化。Answer F1在补充搜索统计中单独报告；这些值与主要结果Answer EM不直接可比。

JailbreakBench。我们评估20个保留的JailbreakBench对，每对包含一个有害和一个良性请求。有标记的对齐参考池是20个有害和20个良性示例的单独确定性混合。有害侧由Qwen3.7-Max评判器评分安全性，良性侧评分有用合规性。对于重复r，设H_r和B_r为20对上的平均有害安全性和良性效用。报告的分数是：

Balanced = 1/4 Σ_{r=1}^4 h(H_r, B_r)，其中 h(H,B) = 2HB/(H+B)（若H+B>0），否则为0。

这是重复级调和平均值的平均值，而不是二元F1。良性过度拒绝是效用失败。每个保留对在四次重复中评估。主表中的JailbreakBench结果使用20个OPSD训练步、批量大小64和非思考Qwen3-8B响应。

数据使用。最终测试集从上下文搜索、参考梯度构造和模型选择中排除。附录B中基于测试的训练前准确率预测器仅用于回顾性相关性分析。对于AIME，45个训练问题用于反思反馈和蒸馏，45个不相交的验证问题用于候选比较和梯度诊断。AIME 2025/2026和LiveBench Math从这些阶段保留。回顾性前/后相关性分析在相同的30道AIME 2025问题上配对训练前和训练后准确率；其训练前准确率预测器与GEPA验证分数不同。HotPotQA使用150个训练问题进行训练和反思，300个验证问题用于开发检查，300个保留问题用于最终评估。JailbreakBench使用单独的训练、验证和保留对文件。

附录B 相关性指标与计算

分析单位与符号。相关性分析将一个候选提示及其产生的20步蒸馏运行视为一个配对观察。对于压缩度量研究，我们分析了正文中报告的33个候选经验，结果按反思模型汇总和分层。此分析计数不是单个搜索树中的节点或叶数。训练前准确率预测器pre_test_pass_at_1和训练后结果post_test_pass_at_1都在相同的30道AIME 2025问题上测量，每个阶段每题12个响应（每阶段每候选360个响应）。训练前预测器测量蒸馏前候选上下文的准确率；训练后结果测量不带该上下文的蒸馏学生。45示例AIME 2022–2024评估分割在GEPA构造期间使用，而不是作为此相关性分析中的训练前准确率变量。梯度和分布诊断使用单独指定的冻结诊断展开。设i=1,…,M索引配对诊断样本，b表示不带候选提示的Qwen3-8B，c表示带候选提示c的相同模型。写q_{s,it}(v)表示在条件s∈{b,c}下位置t处词汇token v的下一个token概率，当两个条件都在同一冻结候选响应上教师强制时。设⟨z_i⟩=M^{-1}Σ_i z_i，⟨z_t⟩_i表示样本i的有效响应位置上的平均值。此共享候选响应重放用于分布KL和熵诊断；它不重新定义用于计算主方法OPSD候选梯度的学生生成轨迹。

以下十个指标描述了本附录涵盖的指标族。族的其他成员（例如，每样本标准差或求和而非平均对数概率）是敏感性分析，不是额外的独立指标定义。

1. 上下文梯度对齐（alignment_ct）。设φ表示最后四个变换器层，V是固定的有标记验证参考集。设y_i*是正确的参考目标，包括其解决方案解释（如果可用）。定义不带候选上下文的参考损失为：

ℓ^ref_{i,b} = -log p_θ(y_i|x_i) = -Σ_{t=1}^{|y_i|} log p_θ(y_{it}|x_i, y_{i,<t})。

此序列求和约定遵循正文参考损失。候选和全参考梯度为：

g_c = ∇φ L_OPSD(θ;c)，g_V = 1/|V| Σ{i∈V} ∇φ ℓ^ref{i,b}。（13）

OPSD梯度在不带候选上下文的学生生成轨迹上评估，通过上下文条件教师停止梯度，并使用附录A.4中的top-256近似。全参考对齐为：

A_CT(c) = cos(g_c, g_V)。（14）

梯度在取余弦之前平均，而不是平均每样本余弦。

2. 错误参考梯度对齐（alignment_error）。设E⊆V包含冻结的无候选提示重复0基线回答错误的问题。定义：

g_E = 1/|E| Σ_{i∈E} ∇φ ℓ^ref{i,b}，A_E(c) = cos(g_c, g_E)。（15）

基线错误的限制适用于参考方向，不适用于候选样本集。此错误参考对齐是主方法指定的量；全参考对齐作为诊断单独报告。

3. 辅助边际对齐（alignment_aux）。对于每个i∈E，设â_{b,i}为基线提取的错误答案，定义ℓ^wrong_{i,b} = -log p_θ(â_{b,i}|x_i)，使用相同的序列求和约定。边际参考梯度为：

g_margin = 1/|E| Σ_{i∈E} ∇φ (ℓ^ref{i,b} - ℓ^wrong_{i,b})，A_aux(c) = cos(g_c, g_margin)。（16）

候选OPSD梯度g_c由这三个预测器共享；只有参考方向改变。

4. 训练前准确率。规范字段是pre_test_pass_at_1：N=30道AIME 2025问题，训练前每题K=12个采样答案：

Acc_pre(c) = 1/(NK) Σ_{i=1}^N Σ_{j=1}^K 1{ŷ_cij = y_i}。（17）

这是样本准确率，不是问题级pass@12，后者如果其12个响应中的任何一个正确则将问题计为正确。因为此字段使用测试问题，它仅在此回顾性相关性分析中使用，不用于选择上下文或训练检查点。

5. 上下文翻转分数。按问题ID和重复索引配对基线和候选展开。设B_0={i: r_{b,i}=0}和B_1={i: r_{b,i}=1}，其中r是二元最终答案正确性分数。C(c)=Σ_{i∈B_0} r_{c,i}纠正和R(c)=Σ_{i∈B_1}(1-r_{c,i})回归，规范pre_context_flip_score为：

F(c) = C(c)/|B_0| - R(c)/|B_1|。（18）

相关的净准确率变化(C-R)/M是敏感性字段。如果各自的基线组为空，则比率未定义。

6. 回归率。规范pre_context_regression_rate隔离之前正确的基线响应在上下文下变错：

Reg(c) = R(c)/|B_1|。（19）

它与翻转分数保持分离，以便基线错误上的改进不会隐藏基线成功上的损失。

7. 奖励增益。对于每个诊断样本，用AIME精确匹配奖励r_{s,i}∈{0,1}评分基线和候选最终答案。规范pre_diag_reward_gain是样本均值：

ΔR(c) = ⟨r_{c,i} - r_{b,i}⟩。（20）

其基线、提示和分散摘要属于同一奖励族的其他成员。

8. KL差距。在精确token重放下，比较每个生成token处提示和无提示模型的完整词汇分布。规范pre_diag_kl_gap为：

K(c) = ⟨⟨Σ_v q_{c,it}(v) log(q_{c,it}(v)/q_{b,it}(v))⟩_t⟩_i。（21）

记录的kl_gain是-K(c)。此诊断KL比较推理分布；它与top-256 OPSD训练损失不同。

9. 熵变化。定义条件s下的平均token熵为H_s = ⟨⟨-Σ_v q_{s,it}(v) log q_{s,it}(v)⟩_t⟩_i。规范pre_diag_entropy_delta为：

ΔH(c) = H_c - H_b。（22）

正值表示重放响应位置上较少集中的提示分布。

10. 黄金答案对数概率增益。对于黄金答案token序列y_i=(y_{i1},…,y_{iL_i})，定义G_s(i) = L_i^{-1} Σ_{t=1}^{L_i} log p_θ(y_{it}|s, x_i, y_{i,<t})。规范pre_diag_gt_logprob_gain_mean为：

ΔG(c) = ⟨G_c(i) - G_b(i)⟩。（23）

两个条件评分相同的黄金答案token；求和对数概率变体在答案长度处理上不同。

相关性统计与范围。对于候选级预测器x_k和训练后结果z_k，我们报告Pearson's r = Σ_k(x_k-x̄)(z_k-z̄)/sqrt(Σ_k(x_k-x̄)^2 Σ_k(z_k-z̄)^2)和Spearman's ρ = r(rank(x), rank(z))，并列使用平均排名。汇总、仅DeepSeek和仅GLM分析分别包含33、16和17个候选。双侧置换检验使用20,000次置换。在每个范围内，Benjamini–Hochberg校正应用于源分析中的13个规范预测器，分别用于Pearson和Spearman检验。本附录定义了其中十个预测器；报告的q值保留原始13预测器校正族。其他源预测器是gradient_norm、trajectory_gradient_norm和process_metadata；后者计算被长度限制停止的响应。

附录D 反思提示进化机制

本节描述遵循GEPA（Agrawal等，2026）的基线反思提示进化机制。这里的目的是使搜索状态、父代选择规则、变异算子和接纳测试直接可重现。基于对齐的接纳和E2L使用的Top-N通道是主方法中描述的附加机制，不属于下述基线程序。

搜索在两个操作之间交替。首先，分数缓存转换为一组每实例获胜者，从中采样父代，以便互补优势保持可用。其次，选定的父代暴露于反馈小批量；反思模型使用观察到的轨迹和反馈重写一个提示。重写在同一个小批量上测试，只有局部改进的重写才在完整帕累托评估集上评估并插入搜索树。

D.1 符号与搜索状态

我们将复合系统写为Φ=(M,C,X,Y)，其中M=⟨M_1,…,M_{|M|}⟩是语言模型模块，C是控制流，X,Y是输入和输出模式。模块M_j包含提示π_j和冻结模型权重θ_j。优化器更新提示集合Π_Φ=⟨π_1,…,π_{|M|}⟩同时保持Θ_Φ=⟨θ_1,…,θ_{|M|}⟩固定。候选Φ_k因此是完整的提示配置，而不是新的模型参数集。

优化数据分为反馈集D_feedback和帕累托评估集D_pareto={(x_i,m_i)}{i=1}^{n_pareto}。前者用于产生轨迹和用于变异的文本反馈；后者用于评分初始系统和通过共享小批量门的提案。设P=[Φ_0,…,Φ{K-1}]为当前候选池，a(k)为候选k的父索引（a(0)=∅）。搜索缓存分数矩阵：

S_{k,i} = μ(Φ_k(x_i), m_i)，S∈R^{K×n_pareto}，（24）

其中分数越大越好。每个接纳的候选存储其提示、父链接、每实例分数和发现它所消耗的展开预算；拒绝的提案不添加到P。

算法2 反思进化提示优化器

1:  系统Φ，训练数据D_train，度量μ，反馈函数μ_f，展开预算B
2:  小批量大小b和帕累托集大小n_pareto
3:  将D_train分为D_feedback和D_pareto，|D_pareto|=n_pareto
4:  P←[Φ]；a(0)←∅
5:  for all (x_i, m_i)∈D_pareto do
6:      S_{0,i}←μ(Φ(x_i), m_i)
7:  end for
8:  while 预算B未耗尽 do
9:      k←SelectCandidate(P,S)
10:     (Φ',s',u)←Mutate(Φ_k,D_feedback,D_pareto,b,μ,μ_f)
11:     if u=accept then
12:         将Φ'附加到P并设置a(|P|-1)←k
13:         S_{|P|-1,:}←s'
14:     end if
15: end while
16: return 最大化S平均行的Φ*

D.3 反思变异

轨迹收集。选择父代Φ_k后，程序从D_feedback中采样大小为b的小批量B，并在B中的每个示例上执行父代。适配器记录模块输入、模块输出、中间推理、工具调用和任何评估器侧诊断。任务度量μ提供小批量门使用的数字分数；反馈函数μ_f提供评估器反馈（例如，失败的标准、错误消息或缺失的检索事实）。此文本信号允许反思将信用分配给特定模块，而不是将最终标量奖励视为未分化的梯度。

模块更新。模块选择策略选择要修改的模块（原始实现对模块使用轮询策略）。反思模型接收选定模块的当前指令以及小批量输入、输出、轨迹、分数和反馈。它必须返回替换指令，而不是任何示例的完整答案。新候选Φ'是Φ_k的副本，仅替换选定的提示；所有其他提示、控制流和模型权重不变继承。在可选的系统感知合并变体中，可以组合多个父提示，但这里描述的单亲变异是源方法使用的基线。

接纳门与完整评估。父代和提案在同一个小批量上评估。μ̄B(Φ)=|B|^{-1}Σ{(x,m)∈B}μ(Φ(x),m)，提案仅当以下条件满足时被接纳：

μ̄_B(Φ') > μ̄_B(Φ_k)。（25）

失败的提案被丢弃，不接收帕累托评估或新树节点。对于通过公式25的提案，变异程序在D_pareto中的每个实例上评估Φ'并将其分数向量返回给优化器。优化器将接纳的候选附加到P，存储父索引a(|P|-1)=k，并更新分数矩阵和实例级前沿。此顺序防止未局部改进其父代的提案的昂贵全集评估。

算法3 反思变异与接纳规则

1:  父代Φ_k，反馈集D_feedback，帕累托评估集D_pareto，小批量大小b，任务度量μ，反馈函数μ_f
2:  B←从D_feedback采样大小为b的小批量
3:  在B上执行Φ_k并收集轨迹、分数和μ_f反馈
4:  j←SelectModule(Φ_k)
5:  π'_j←Reflect(π_{k,j},B,轨迹,分数,反馈)
6:  Φ'←Φ_k的副本，模块j提示设置为π'_j
7:  在相同B上评估Φ'；重用记录的父代分数
8:  if μ̄_B(Φ')≤μ̄_B(Φ_k) then
9:      return (Φ',∅,reject)
10: else
11:     s'_i←μ(Φ'(x_i),m_i)，对于每个(x_i,m_i)∈D_pareto
12:     return (Φ',s',accept)
13: end if

D.4 端到端程序与E2L的关系

主循环结合上述两个子程序。基础系统在D_pareto上评估一次。每次后续迭代使用GEPA程序采样父代（Agrawal等，2026），在新的反馈小批量上收集反馈，应用Mutate，仅在提案通过局部门后才在帕累托集上评估。一旦展开预算耗尽，返回的候选是：

Φ* = argmax_{Φ_k∈P} 1/n_pareto Σ_{i=1}^{n_pareto} S_{k,i}。（26）

最终选择是缓存帕累托集评估上的总分数；它与搜索期间使用的频率加权父代采样不同。在E2L中，基于帕累托的候选选择和梯度对齐共同指导上下文进化，如主方法所述。父代选择和反思变异遵循原始GEPA实现，E2L的额外采样和接纳机制在搜索期间应用。我们使用0.3的额外采样权重和Top-N接纳通道的N=3，如表6所总结。帕累托成员资格从每实例任务分数计算，变异使用展开轨迹和文本反馈，新树边仅为接纳的候选创建。基于对齐的接纳和Top-N通道是E2L扩展而不是基线GEPA目标的组件。
