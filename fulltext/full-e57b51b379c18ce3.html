摘要
交互式对话游戏测试了一种静态基准在很大程度上隐含的能力：模型必须在多轮对话中携带状态、解释反馈，并在不断变化的约束下选择有效的动作。
我们在 LM Playschool 挑战赛中使用 2B 开源权重模型研究了这一设定，发现许多失败不仅是广泛的知识失败，也是局部的决策失败：重复猜测、格式错误的动作，以及违反模型刚刚看到的反馈。
这些诊断促使我们围绕三个步骤组织了一个训练方案：通过监督微调（SFT）获取广泛的游戏参与能力；使用轮次局部偏好对在一个目标对话游戏家族内修复机械可验证的失败；并保持这些对话游戏之外的一般能力。
在官方最终评估中，我们的提交将公开 clemscore 从 10.67 提升至 38.92，封闭域内得分从 13.41 提升至 41.17，同时大致保持了静态基准的总体性能（44.14 对比基线的 44.24）。
域外 clemscore 保持在 7.88 的较低水平，最大的提升集中在目标家族的未见变体中。
我们的结果表明，广泛的 SFT 带来了模型大部分的能力提升；当失败检测精确时，轮次局部监督是有效的，观察到的迁移主要集中在家族内部。

1 引言
对话游戏将语言模型评估为智能体，其下一句话语会改变它们随后必须推理的状态。
猜词排除了字母；线索限制了伙伴的动作；导航命令改变了解释下一个命令的房间。
clembench 基准和 Playpen 学习环境（Chalamalasetti et al., 2023; Horst et al., 2025）使这些依赖关系变得明确：成功不仅需要产生合理的语言，还需要维持状态、解释反馈，并在累积约束下选择有效动作。
Playpen 将这一设定构建为从对话游戏反馈中学习（Horst et al., 2025）：对轨迹进行程序化的、目标导向的反馈，而不依赖于对孤立响应的习得评判器。
反馈本身并不能定位交互在哪里停止取得进展；需要交互式失败诊断来为强化学习构建轮次局部偏好对。
因此，对于对话游戏智能体来说，问题不仅在于对话游戏数据是否有帮助，还在于轨迹的哪一部分应该接受监督。

小模型是这一设定的自然目标。它们的部署成本更低，更适合低延迟交互，对于本地助手或资源有限的助手来说更具可行性，但它们的交互行为很脆弱。在 LM Playschool 挑战赛中，官方 Qwen3.5-2B 基线（Qwen Team, 2026）在最终评估中得分为 10.67 clemscore，远低于其 27B 版本的 60.30 分。

本文描述了围绕该问题构建的 playornotplay 团队提交。我们首先使用广泛的模仿使模型参与游戏，然后诊断剩余的失败，使用轮次局部偏好对修复一个薄弱且机械可诊断的游戏家族中的失败，最后缩放学习到的更新以保持一般能力，这是通过总体静态性能来衡量的。

在官方最终评估中，提交的模型达到了 38.92 的公开 clemscore 和 41.17 的封闭域内得分，高于官方 4B 和 9B 基线，同时大致保持了 2B 基线的总体静态性能（44.14 对比 44.24）。

主要贡献是对小型交互式智能体监督放置位置的实证说明。锚定在反馈后真实轮次上的少量偏好对在我们的流程中产生了最清晰的积极偏好调整信号，而全对话偏好调整在我们的实验中破坏了协议合规性。

后续实验进一步表明，更新的有用性取决于应用它的阶段和父模型。总之，这些结果将轮次局部偏好学习定位在从获取到修复和模型选择的更广泛进程中。

2 任务和评估设定
LM Playschool 挑战赛评估在会话交互中学习是否提高了智能体能力。Playpen 是对话游戏反馈的学习环境（Horst et al., 2025）：它在对话游戏轨迹上组织展开、训练数据和在线采样。对话游戏在 clembench（Chalamalasetti et al., 2023）中实现，其中程序化游戏主持人调解轮次、跟踪状态并强制执行输出协议，而特定游戏的评分器计算质量。

在此处使用的公开验证设定中（来自 playpen-data 数据集 2 ），交互套件包含 14 个 clembench 游戏和 67 个固定开发运行集。

LM Playschool 挑战赛使用 Clemscore 和 Statscore 作为指标。
Clemscore 结合了每个游戏 g 的两个量：Played，即未被评估器标记为中止的集百分比，以及 Quality，即已玩集的任务得分。设 G_Q = {g ∈ G : Played_g > 0}，我们将其报告为：
C = (1/|G| ∑{g∈G} Played_g/100) × (1/|G_Q| ∑{g∈G_Q} Quality_g)。
对于没有已玩集的游戏，Quality 是未定义的，因此 Quality 宏平均仅在 G_Q 上运行。因此，模型可能会因为未能游戏或在留在游戏中后表现不佳而失去分数。playpen-data 验证拆分包含 430 个静态基准实例，取自 BBH（Suzgun et al., 2023）、CLadder（Jin et al., 2023）、EQ-Bench（Paech, 2023）、IFEval（Zhou et al., 2023）和 MMLU-Pro（Wang et al., 2024）；应用相同的聚合可得到 Statscore。

固定的公开拆分为每个代表的游戏-实验组合贡献了一两个集，这个小样本是运行间方差的主要来源：应谨慎对待几分的差异。因此，我们使用配对的同主机比较来进行开发决策，并将官方最终评估作为主要结果报告。

3 我们的方法
我们的方案是 Playpen 启用的训练机制的狭窄实例化：成功的记录支持 SFT，配对的替代项支持 DPO，新的展开支持在线奖励学习。Playpen 本身包括轮次级 DPO（Horst et al., 2025）；我们的具体选择是使用游戏特定的检查，在反馈后的机械可验证失败处构建偏好对。我们使用广泛的 SFT 使模型参与，然后针对那些诊断出的决策。

3.1 诊断小模型游戏失败
阶段 A 对 playpen-data 训练拆分中仅成功的交互执行 SFT，平衡为每个游戏最多 700 个示例（在重建的训练时快照中总计 9,522 行；各游戏计数见表 6）。这将模型在固定公开开发集上从 13.05 提升到 43.85。模型已经学会了游戏玩法的表面形式，但原始 Wordle 质量仍然为零：它仍然重复被拒绝的猜测并违反即时反馈约束。Wordle 不是唯一剩余的弱点，但它的失败很频繁，局限于单个决策，并且机械可验证，因此我们选择它作为所有后续优化的目标。阶段 B 和 C 仅使用 Wordle 数据；报告的每个 clemscore 仍然是完整的 14 场游戏套件。

3.2 轮次局部修复
给定一个诊断出的失败模式，我们构建共享相同对话状态的偏好对。对于历史 h，被拒绝的补全 y− 表现出一个机械错误，而偏好的补全 y+ 是来自干净成功集的有效替代。然后我们应用直接偏好优化（DPO；Rafailov et al., 2023）：
L_DPO = -E log σ(β [r_θ(h, y+) - r_θ(h, y−)]), (2)
策略-参考对数比率为 r_θ(h, y) = log π_θ(y|h) / π_ref(y|h)。保持 h 固定是关键：对比落在少数决策 token 上，这些 token 决定了模型是重复猜测、使用错误长度、产生无效单词还是重复答案字段。这种构造并没有识别出单个失败；它枚举了干净成功集中所有符合条件的反馈后轮次，并在每个轮次创建一个合成负样本。

阶段 B 分两遍应用：第一遍处理重复猜测和长度错误（1,905 对，β=0.1）；第二遍处理无效单词和重复的答案字段（1,906 对，β=0.1）。在第一遍之后，旧的重复循环不再出现在原始 Wordle 探测中，但出现了无效单词和重复的答案字段。第二遍纠正了这些问题；其聚合套件效果在两个评估轨道上符号不一致（表 8）。

在使用合成对处理了固定的失败类别后，我们转向当前模型自身轨迹中出现的错误。阶段 C 使用当前检查点玩训练拆分的 Wordle，在早期决策点进行分支（因子 2，轮次 1–3，T=0.7），并将来自得分最高和最低的同级的立即分歧响应配对。针对冻结参考（β=0.20）的 DPO 旨在解决残余分布差距。

3.3 保持一般能力
至此，每个强大的交互候选者都付出了专业化代价：在我们固定的开发集上，statscore 从起始检查点下降了几个点。我们没有添加更多数据或重放，而是将保持视为一个后训练权重空间问题。我们缩放学习到的增量，W(s) = W_base + s Δ_LoRA，并通过受约束的模型选择选择标量 s ∈ [0,1]：
s = arg max_s S(W(s)) (3)
s.t. C(W(s)) ≥ C_min,
其中 C_min 是固定公开开发集上的配对交互门控。在 s=0.85 时，两次 clemscore 评估的平均值为 50.43（表 2）。该操作无需训练，可与任何普通的 LoRA 适配器组合，但必须在两个轴上选择标量：太低的值无法通过交互门控。在官方最终评估中，提交的 fp32 合并得分为 38.92 公开 clemscore，statscore 为 44.14，而 2B 基线为 44.24。

在固定的公开开发集上，四阶段轨迹从 13.05 经过 43.85（阶段 A）、46.83 和 45.52（阶段 B 过程）和 48.52（阶段 C）发展到增量缩放后的平均 50.43（表 2）。相对于总体增益，大多数相邻阶段的差异很小，并且 Wordle 之外的各游戏变化是混合的（表 13 和 14），因此我们将这些报告为轨迹，而不是分解为因果效应。

5 讨论
官方评估结合了巨大的域内增益和微弱的域外迁移。训练轨迹及其后续实验指向一个共同模式：当监督与当前策略仍然缺乏的内容相匹配时，它是最有用的。广泛的模仿创造了参与能力，局部偏好修复了机械可识别的决策，而权重空间选择选择了一个保留由此产生的增益的操作点。

5.1 获取为局部修复创造条件
阶段级的证据来自固定的公开开发轨迹和受控的单主机活动（附录 A.5）。阶段 A 是该轨迹中最大的单步（表 2）。已玩急剧上升，同时条件质量也有所提高（附录 B），最终模型的官方分解与这种广度一致：其最大的隐藏域内增益出现在没有后期阶段针对的游戏中（TMW GraphReasoning、ImageGame、AdventureGame；表 11）。这些最终模型增益的广度与唯一的全游戏训练阶段的作用一致。

后期阶段在更狭窄的机制下运行。只有轮次-DPO 第一遍在提交模型轨迹和受控活动上都有正向的 clem 边际（+2.98 和 +1.49）；第二遍和分支-DPO 在两个轨道上符号不一致（表 2 和 8）。最清晰的修复信号仍然在 Wordle 家族内部：三个保留的 Wordle-crazy 配置占总正向域外移动的 82.5%，而目标 Wordle 家族在隐藏域内集上保持接近零（表 12 和 11）。因此，观察到的迁移集中在相关的 Wordle 变体中。

局部性似乎是关键。在早期的一个实验中，偏好覆盖了整个剩余对话，而不是反馈后的下一个动作。未过滤的全对话 DPO 得分为 12.35，并产生了违反 Wordle、Codenames 和其他游戏协议的自然语言前奏；将选定方过滤为更强的源模型部分恢复得分至 25.76，但保留了主要的中止模式（附录 A.6）。总而言之，积极的轮次局部结果和全对话失败表明，当对比附加到机械可验证的反馈后决策时，会出现最清晰的偏好信号。全对话 DPO 将整个剩余交互配对，而不是单个响应，即使在源过滤后也没有保持协议行为。

5.2 作为权重空间模型选择的保持
增量缩放解决了一个与获取和修复不同的问题。它不添加监督，也不采取梯度步骤；相反，它沿着学习到的 LoRA 更新选择一个点。在官方评估中，总体静态性能大致保持（44.14 对比基线的 44.24），而交互增益仍然很大。然而，总体隐藏了重新分配：BBH 质量从 0.00 上升到 30.47，而 IFEval 从 68.52 下降到 51.85，EQ-Bench 质量从 64.78 下降到 56.43。
因此，保持是沿着学习更新的模型选择问题，而不是另一个监督问题。增量缩放在交互增益和总体静态性能之间选择一个操作点，具有组件级的重新分配。

5.3 训练效果取决于阶段和父模型
为了测试基于纠正的偏好训练在模型选择后是否仍然有用，我们使用求解器纠正、成功与失败对或教师纠正从选定的 s=0.85 父模型继续 DPO。五个分支中没有超过 50.43 开发终点的；它们的得分从 44.15 到 48.92 不等（附录 A.6）。在流程的这个时刻，额外的基于纠正的训练并没有产生更强的模型。
缺乏进一步增益并不意味着 2B 基础已经耗尽了其提升空间。DAIR 的纯 SFT 系统使用相同的 Qwen3.5-2B 基础，达到了 46.01 公开、46.57 隐藏域内和 15.62 隐藏域外 clemscore。这种同基础比较指向了获取：更强的广泛监督可以在局部修复开始之前创建更好的起始策略。
获取更新的效果也取决于其父模型。在匹配的 4B 探测中，对 700 个离策略成功集进行的低剂量 SFT 在相同的主机、数据集修订和评估轨道上将 clemscore 从 40.75 降低到 24.36。另一个 4B 探测在 303 个自生成的成功对话上进行训练，达到了 35.06（附录 A.6）。与后期延续结果一起，这些探测表明训练效果是路径依赖的：当缺乏参与能力时，广泛模仿有帮助；一旦失败变得机械可识别，局部偏好学习有帮助；而在策略或父模型改变后的进一步更新反而会降低模型已经拥有的行为。

5.4 模型选择塑造了泛化内容
在十一次提交中，公开 clemscore 与封闭域内得分强相关（r=0.93），但与封闭域外得分仅弱相关（r=0.30）。我们流程中的每个决策都是在公开开发集上做出的，最终结果反映了该选择信号：巨大的公开和隐藏域内增益，但域外 clemscore 为 7.88，域外已玩低于未训练的基线。公开集对隐藏域内进展提供了信息，但对广泛迁移几乎没有提供指导。
这种模式暴露了方案开发过程的一个实际限制：终点结合了对薄弱起点的巨大改进和有限的绝对域外能力。更广泛的迁移将需要超越 Wordle 家族和公开开发分布的诊断或选择信号。

6 结论
交互式对话游戏失败可以反映广泛的能力缺陷和局部决策错误。在我们的流程中，广泛的 SFT 产生了最大的改进，而轮次局部偏好对在我们测试的偏好调整变体中提供了最清晰的正向修复信号。
结合广泛的 SFT、轮次局部修复和增量缩放，将官方公开 clemscore 从 10.67 提高到 38.92，封闭域内得分从 13.41 提高到 41.17，高于官方 4B 和 9B 基线，同时大致保持了总体静态性能。
域外迁移仍然有限：clemscore 为 7.88，已玩低于未训练的基线。结果支持一种获取域内游戏参与能力和修复精确家族内失败的范围化方案，迁移集中在相关的 Wordle 变体中。

局限性
机械可验证修复的范围。
轮次局部修复依赖于游戏特定的诊断，即验证反馈后动作是否违反了显式状态约束。这种精度将演示覆盖范围限制在 Wordle 家族，这是阶段 B 和 C 构建偏好数据的唯一游戏；该方法尚未在需要语义或战略判断的失败上进行测试。演示的域外覆盖是相关变体的迁移：三个保留的 Wordle-crazy 配置占了 84.86 总正向移动中的 70.02（82.5%）。提交的工件使用单一的 Qwen3.5-2B 基础，因此规模适用性仍未测试。

对获取阶段父模型的未测试依赖。
在应用修复之前，广泛的 SFT 占了大部分测量到的改进。修复阶段在一个特定的、有上限的广泛 SFT 方案之后进行评估；该研究在保持修复语料库和训练配置固定的同时，没有改变获取阶段父模型的强度或覆盖范围。因此，实验无法确定轮次局部修复是补充了更强的模仿阶段，补偿了提交父模型特有的弱点，还是在更强的获取之后变得不那么有用。局部修复在该父模型创造的机制中是有用的；其在不同训练的父模型下的贡献仍然未知。

阶段归因和模型选择的局限性。
官方评估验证了提交的终点，但顺序轨迹没有识别每个阶段的因果贡献。阶段和缩放选择重用了 67 集的公开开发集，后期阶段的边际在两个评估轨道上并不一致。两个后期阶段在轨道上符号不一致：轮次-DPO 第二遍在开发轨迹上为 -1.31，在受控活动上为 +1.34；分支-DPO 为 +3.00 和 -2.07。只有第一遍在两者上都是正的（+2.98 和 +1.49）。相邻检查点差异结合了训练、顺序依赖、重复选择和评估方差，因此它们描述的是轨迹而不是加性因果效应。终点比基础有大幅改善；个别后期阶段的幅度和必要性仍然不确定。

总体而非组件级的保持。
增量缩放大致保持了官方总体 statscore（44.14 对比 44.24），同时保留了交互增益。保持目标本身是总体的：公式 3 在总体交互门控下最大化总体静态得分，因此一个组件的增益可以按设计抵消另一个组件的损失。BBH 质量从 0.00 上升到 30.47，而 IFEval 从 68.52 下降到 51.85，EQ-Bench 质量从 64.78 下降到 56.43。合理的结论是总体级别的权衡控制，而不是保持每种一般能力。更强的主张将需要组件级的下限或多目标选择标准。

A.3.3 轮次局部偏好构建
阶段 B 从干净的成功 Wordle 集构建偏好对。资格分三步决定：
1. 源行的游戏为 wordle，结果为 success。可选的源模型过滤器为空，因此所有成功的集都有贡献。
2. 如果任何用户消息包含“not a valid word”或任何解析的助手猜测在集内重复，则整个集被拒绝。
3. 选定的助手回复包含可解析的小写 guess: 字段，是助手轮次 2 或以后，并且紧接在包含 guess_feedback: 的用户消息之后。
提示是该回复之前的精确对话历史。偏好的补全 y+ 是来自干净成功集的未修改响应；它不是教师生成的纠正。被拒绝的补全 y− 对该相同响应应用四种确定性损坏之一：
• repeat_last：用前一个猜测替换当前猜测；如果已经相等则跳过。
• bad_length：用至少五个字符的猜测的前四个字符替换。
• invalid_word：尝试固定的单字母替换，然后是固定的候选词，取官方 Wordle 词典中不存在的第一个五字母字母 token，以 zzzzz 作为后备。
• duplicate_guess_keyword：在未更改的响应后追加第二行 guess:。
第一遍使用 repeat_last 和 bad_length；第二遍使用 invalid_word 和 duplicate_guess_keyword。未启用一负采样，因此每个适用的配置损坏都会产生一对。

阶段 C 加载训练拆分实例配置，过滤到 Wordle，使用 seed 42 洗牌，并选择 27 个实例。当前检查点在轮次 1–3、温度 0.7 和每轮最多 256 个生成 token 的情况下以分支因子 2 玩每个实例。同级分支按共享的游戏快照来源分组，一个组需要至少两个分支。在一个组内，同级按完整下游集的得分排名，该得分结合了终端结果、速度、接近度、策略以及对重复、无效、长度错误、重复、缺失或反馈不一致猜测的惩罚；它不是二元赢/输标签。选定和拒绝的项目只是得分最高和最低同级的立即分歧助手响应，以共享历史作为提示。当两个得分相等时，该组被丢弃。
该运行产生了 90 条轨迹、295 个分支点和 77 个 DPO 对（73 个训练，4 个评估）。

A.4 移除的两个名义阶段
提交模型的训练过程最初被描述为六个阶段。名义阶段 2 是对最弱游戏的继续 SFT 过程；名义阶段 3 是在 Wordle 上使用密集奖励的 GRPO（Shao et al., 2024）探测，该奖励解析反馈并惩罚六种机械违规。由于两个不相关的原因，两者都没有改变任何权重。
名义阶段 2。
运行通过推理加载器加载了广泛 SFT 适配器，该加载器设置 is_trainable=False，并且热启动路径传递了 peft_config=None，因此没有创建新的可训练适配器。TRL 的 enable_input_require_grads() 阻止了前向和反向传播引发异常，因此运行完成并写入了检查点。输出适配器与广泛 SFT 检查点字节相同（372 个张量中有 372 个相等），其优化器状态包含零参数。
名义阶段 3。
在 β ≠ 0 的情况下，TRL 0.29.1 中的 GRPOTrainer 通过使用相同的配置对象调用 add_adapter 来构建冻结参考，该对象仍然带有 inference_mode=True。因此，适配器注入默默地重新冻结了每个适配器，包括策略，并且优化器随后在空参数集上构建。日志报告了 16.8M 个可训练参数和 54 个非零梯度范数，但每个梯度都被计算并丢弃；KL 项在所有 54 步中都相同为零。
行为证实。
在固定拆分上以温度 0 重新评估三个名义检查点，14 个游戏中有 13 个产生了字节相同的记录。唯一的分歧是 AdventureGame，追溯到 PYTHONHASHSEED 下的 Python 集迭代顺序。因此，三个分数 43.85、44.09 和 43.35 是一组权重的三次评估，其 0.74 点的差距是对此套件上评估噪声的直接测量。
更正的重新运行。
两个阶段都在单个主机上修复了错误后重新运行，使用与原始相同的种子、学习率、批次几何和奖励塑造。由于更正的运行使用论文固定的数据集修订版而不是原始快照，弱游戏 SFT 语料库从 2,119 行变为 2,224 行，GRPO 实例集偏移了两个任务 ID。因此，更正的运行用稍微不同的语料库重现了方案家族。更正的弱游戏 SFT 得分为 42.07（比其 43.85 父级低 -1.78），更正的 GRPO 得分为 43.55（比该父级高 +1.48），两者净低 -0.30。训练动态证实了真正的优化：原始显示为零的非零梯度范数，以及原始相同为零的非零 KL 项。
