摘要

LLM智能体日益驱动自身的学习。自我改进方法将模型优化的多个组成部分委托给模型本身。随着模型能力的增强，这引出了一个基本问题：这些日益强大的模型是否仍需要我们指定其自我改进的方式？本文研究一种自主范式：给定基本原语、资源和自我改进的总体目标，智能体自行构建基于上下文优化的自学习算法。以游戏玩法作为测试平台，一个冻结的LLM智能体被给予计算预算以及收集经验和更新文本文档的工具，并可在没有外部强加循环或真实世界数据访问的情况下自由实验。我们发现，足够强大的模型在这些条件下确实能自我改进，展现出与经典的自我调节学习认知框架以及机器学习文献中自生成课程构念相一致的策略。此外，我们研究了所学文本产物向外部基准的迁移程度，观察到在不同游戏视野、机制和3D导航上的改进。

1 引言

想象给一个智能体一台电脑，要求它提高玩益智游戏的能力。它会做什么？电脑没有预装游戏；智能体如果想练习，必须自己编写游戏。它必须决定尝试什么类型的游戏、保留哪些经验教训，以及如何衡量进展。

这些关于学习程序设计的决策通常由人类从业者做出。然而，随着LLM智能体能力的提升，我们越来越多地将机器学习过程委托给学习者本身。各种工作利用模型生成监督数据、构建交互环境，甚至重写自己的工具和框架（????）。

与开发更好方法的努力并行，人们对防范未对齐自我改进的保障措施的需求日益关注。这两个方向都引出了一个基本问题：强大的模型是否仍需要我们指定其自我改进的方式？

我们研究LLM智能体在被提供通过上下文操作进行自我改进的原语工具和资源，但未被包裹在显式自我改进算法中时的自然行为。我们不为经验生成和学习者更新设计循环，而是允许智能体将动作组合成自学习程序。该智能体无法访问真实世界任务或验证分数。它必须在受限的沙盒中试验不同的任务生成方式、反思失败和评估进展。

我们的设置对理解能力和安全性都很重要：在能力方面，模型可能不再需要规定的自我优化算法；在安全性方面，没有指定循环并不一定阻止自我改进。

我们发现，足够强大的模型成功地自组织学习程序并在保留任务上自我改进。

我们在有限信息的游戏玩法设置中检验这一现象。一个玩家智能体在严格的计算和游戏视野预算下玩具有未公开机制的回合制游戏。这项任务需要多样化的推理技能，包括高效探索、信息获取、多步规划和世界建模。

同一智能体的一个实例充当教师。教师被给予通过文本（例如编辑提示、创建技能文件）改进玩家的一般目标、计算预算以及用于观察玩家尝试自生成游戏和编辑玩家上下文的工具集。我们不指示教师何时使用这些工具；教师与玩家自由实验。

在一组有效的自学习者中，来自不同家族的模型采用相似的反复出现、可识别的学习策略，例如生成具有校准难度的游戏、运行受控的A/B比较，以及开发验证套件来衡量进展。这些策略与社会认知的自我调节学习框架所描述的行为一致（??）。我们还发现，智能体在更难的任务上投入更多精力，类似于非对称自博弈中的可学习性目标（???）。此外，自构建的学习程序具有泛化能力：学到的文本文件可迁移到需要在不同的游戏视野、引擎和表示上进行推理的多个基准。我们研究了如何通过上下文或环境约束向教师提供评估设置信息，从而塑造这种下游泛化。

我们的主要发现是：

  1. 仅给定通过上下文操作进行自我改进的原语工具，足够强大的智能体能构建有效的学习程序，提高其在保留游戏玩法上的表现。
  2. 来自不同家族的模型实施与自我调节学习框架和机器学习文献中自生成课程相一致的可识别策略。
  3. 学到的文本在游戏基准和表示之间泛化。评估设置意识使教师偏向相关任务，但也可能鼓励过拟合。

2 预备知识：有限信息的游戏玩法

我们的目标是研究需要多步推理的交互设置中的智能体自我改进。作为测试平台，我们使用具有未公开机制的游戏玩法设置。智能体玩一个对规则和目标了解有限的回合制游戏。要成功，它必须在给定的视野内高效获取信息、规划和执行。此设置锻炼了多样化的能力，包括自适应效率、目标发现、规划和世界建模（?）。

我们考虑部分可观测马尔可夫决策过程设置。对于每个游戏 g，令 s_t ∈ 𝒮 表示第 t 回合的状态，o_t ∈ 𝒪 为玩家收到的观测，a_t ∈ 𝒜 为玩家的动作。游戏引擎确定转移动力学 s_{t+1} ∼ P_g(·|s_t, a_t) 和相应的观测 o_{t+1} ∼ O_g(·|s_{t+1})。奖励是二元的，r_t = R_g(s_t, a_t, s_{t+1}) ∈ {0,1}；玩家在达到获胜状态时获得奖励 1，否则为 0。回合在成功时或最多 H 回合后终止。

玩家 π_θ 无法访问 P_g 或 R_g，并通过交互推断游戏机制。它基于其交互历史 h_t = (o_1, a_1, …, o_t) 和上下文 c（例如提示）行动，a_t ∼ π_θ(·|h_t, c)。

LLM智能体在给定文本编辑和经验生成的原语工具后，能否将这些工具组合成有用的自我优化程序？并且能否在无法访问人类编写的游戏的无数据设置中实现？我们在受控环境中研究这些问题：一个冻结模型（教师）被给予预算、提示和有限的工具集，并允许自由实验。教师被给予优化文本（例如提示、技能文件）以改进玩家在未见游戏上表现的一般目标，其中玩家是同一模型的另一个实例。我们通过在保留游戏基准上的表现来衡量成功。

我们的设置与非对称自博弈有显著相似之处，其中教师为学生生成待解决任务（?）。应用于LLM时，同一模型通常扮演两个角色（?）。这些方法规定了采样任务和展开、评估任务学习价值以及更新学生和教师的程序。相比之下，我们不规定教师必须如何使用其预算和工具，并在文本空间而非权重空间中进行优化。教师的角色超越了任务生成，涵盖了构建学习程序本身。

3.1 教师-玩家设置

令 π 表示具有冻结权重 θ 的LLM。LLM被实例化为具有上下文 c = (c_P, c_L) 的玩家智能体 π_player，其中 c_P 是玩家提示，c_L 是辅助文本文件（例如技能文件）。由 c 诱导的玩家策略为 π_player(a_t|h_t, c)，用于游戏轨迹 h_t。同一LLM的另一个实例，即教师智能体 π_teacher，修改 c。我们将更新定义为对 c 中一个文件的单次编辑工具调用。令 c_0 为初始上下文状态（例如最小提示），c_final 为教师最终更新后 c 的状态。

上下文优化使我们能够研究闭源模型，但也具有有用的属性。基于梯度的学习处于连续空间并与预定义奖励绑定。在文本优化中，教师可以反思玩家展开并动态决定生成任务、经验或知识更新。这些更新以文本形式保存，为玩家行为的变化保留了可读的解释。

3.2 教师环境

教师是持久沙盒框架会话（Claude Code、Pi）中的智能体。该框架是最小化的；我们禁用默认系统提示、自动记忆、网络搜索、子智能体等功能（附录C.1）。教师只能访问我们明确提供的沙盒文件和功能：上下文、指定的工具集和预算。

工具。 教师被授予用于沙盒文件的 Read/Write 工具、用于终端命令的 Bash（受沙盒约束），以及 Gameplay 工具。Gameplay 工具允许教师观察玩家在教师授予的上下文下玩游戏。教师使用游戏源文件调用该工具，并可选择指定包含玩家文本产物的目录路径。该工具在全新的外部玩家会话中执行游戏，并向教师返回玩家得分和记录。

在我们的主实验中，Gameplay 工具使用 PuzzleScript，这是一种用于基于2D网格的益智游戏的领域特定语言。PuzzleScript 包含共享基本结构和动作空间的多样化游戏，为研究泛化提供了受控设置。教师以 PuzzleScript 文本文件的形式发布游戏；Gameplay 工具拒绝无法编译或获胜状态可验证不可达的游戏。我们在改用基于 Python 的 Gameplay 工具的实验中消融 PuzzleScript 约束。

这些工具可以作为向教师提供信息的机制。例如，我们可以允许教师在 Gameplay 工具中指定游戏视野（回合预算），或者我们自己施加这样的预算——有效地通过约束传达评估游戏视野。

上下文。 教师的系统提示指定主要目标：通过编写文本产物提高玩家在单人游戏上的表现。我们还指定泛化目标：产物应对具有不同任务或机制的未见游戏有用。我们不指导如何构建产物，而是允许教师自由创建和修改玩家文本文件，包括提示。当被授予 PuzzleScript Gameplay 工具时，教师还会收到官方 PuzzleScript 文档。完整提示见附录 C.5。

预算。 教师有两部分资源预算。更新预算是可以应用于玩家上下文 c 的更新数量，指定为教师沙盒中的目录。对 c 的每次编辑工具调用即为一次更新。游戏玩法预算是教师可以观察的游戏玩法数量。当任一预算耗尽时，教师会话结束。如果教师在未完全消耗任一预算的情况下结束其动作序列，我们会提示它继续。

4.1 新一代模型更好地自我教学

我们首先询问哪些模型在我们的设置中自我改进。图4显示了 PuzzleScript-t20 上的评估结果。跨模型家族，三个更新发布且能力更广泛的世代在默认上下文玩家基线之上改进（Claude Opus-5 为 +20%，GPT 6-Astra 为 +10%，GLM 5.3 为 +6%）。然而关键的是，这种效应并非对所有模型都明显；旧代表现出很少或没有改进。这一差距表明了一种潜在轨迹，其中自组织自学习在连续的模型世代中日益明显。

5 自组织自我改进何时泛化？

第4.1节确立了一类强大的模型在 PuzzleScript-t20 上以最少的指导自我改进，该基准与自学习设置共享关键属性。现在，使用 Claude Opus-5，我们从三个角度评估泛化：跨环境迁移、在不同信息条件下以及跨模型。

5.1 自学习产物跨环境迁移

图9显示学到的上下文迁移到与自优化设置差异越来越大的环境。我们绘制自学习轨迹上均匀间隔的玩家表现。在上下文更新 k 处，我们用 c_k 在保留基准上评估一个全新的玩家会话。在20回合 PuzzleScript 游戏玩法下优化的上下文（表示为 Gameplay (PS-t20)）将 PuzzleScript-t20 表现提高20%，PuzzleScript-t30 提高9%，ARC-AGI-L1 提高21%，MazeBench SPL 提高0.15。这展示了跨游戏引擎、网格大小、核心机制、3D空间导航、更长视野推理和状态表示的迁移。

这些趋势也扩展到不同的自我改进设置。我们运行三个比较，每个都有三个独立教师会话在匹配的教师预算下。(1) 教师只有 Read/Write 工具，(2) 有 Bash 访问，(3) Gameplay 工具限制为30回合 PuzzleScript 游戏。Gameplay (t-30) 在基准上表现最佳，甚至在 PuzzleScript-t20 上优于 Gameplay (PS-t20)。Read-Write 优于基线，表明 Gameplay 设置中观察到的一些改进源于教师对先验知识的自我反思。在除 MazeBench 之外的所有基准上，Read-Write 恢复的 Gameplay 教师性能增益不到50%，表明从生成的经验中受益。Read-Write-Bash 优于 Read-Write，但未能恢复单独游戏玩法的全部增益。值得注意的是，在一个 Read-Write-Bash 会话中，教师仍然在沙盒中编写并运行游戏模拟器来测试其建议，尽管其提示中没有提到游戏玩法（附录 E）。

对于一个具有 Bash 的足够强大的教师，显式的 Gameplay 工具可能是不必要的。

我们还评估允许教师发布 Python 游戏；Python 游戏玩法在4个案例中的3个中恢复了 PuzzleScript 游戏玩法的几乎所有性能增益（图10），表明 PuzzleScript 意识对教师学习可迁移上下文不是严格必要的。我们在下一节进一步研究基于 Python 的生成。

6 相关工作

有关相关工作的扩展视图，见附录 A。我们根据学习过程的哪些组成部分保持外部指定、学习如何发生以及研究的泛化范围来分类自我改进方法。

非对称自博弈。 在非对称自博弈中，教师为学生生成具有挑战性的问题，产生涌现的、自适应的课程（?）。此类方法在后训练推理LLM中取得成功（???????）。在这些方法中，教师通过综合学生问题自生成经验来源，而学习在权重空间中进行。优化程序（例如更新计划、教师奖励、批次中采样任务的数量）保持外部指定。此类方法还可能遭受多样性或性能崩溃（?），促使额外的机制来评估生成问题的学习价值。各种方法使用评判器（?）或将智能体基于真实数据困难问题作为目标柱（?）。这些机制有助于稳定自博弈，但引入了关于什么构成有用学习经验的额外外部指定选择。崩溃还可以通过根据教师生成的问题是否诱导学生在外部困难问题上的改进来奖励教师来解决（?）。在这种情况下，反馈是外部获得的，同时仍然依赖自生成的数据来驱动学习。最近的工作让教师生成交互环境而不是问答任务（?），但保留外部指定的优化和任务选择程序。

上下文和框架优化。 另一条工作线考虑通过对模型的上下文或智能体框架的更新进行自我改进（????）。GEPA 使用对执行轨迹的自然语言反思通过进化搜索优化模型提示（?），而 ACE 维护一个不断发展的策略手册，积累以前交互的策略（?）。这些工作仍然利用外部指定的任务分布和预先指定的上下文优化程序。MCE 通过将上下文与上下文工程技能共同演化部分放松了后者（?）。Meta-Harness 将优化对象进一步扩展到可执行的框架代码，允许模型更改上下文的管理方式，包括存储和检索什么信息（?）。优化仍然使用外部提供的任务，候选框架用外部指定的目标评估。最近关于自我修改智能体的工作进一步扩展了模型控制下的组件。达尔文哥德尔机迭代地修改自己的智能体代码并在外部基准上评估生成的智能体（?），而 Hyperagents 使用于生成未来改进的元级程序本身可编辑（?）。这些方法允许自我改进机制的越来越多的部分发生变化，同时仍在外部指定的任务和评估设置中运行。

自构建的学习程序。 ? 引入了开放式优化，其中目标、可用交互、资源预算、数据边界和评估是固定的，但模型自己组织改进过程。表现是在用于优化的同一基准设置的保留示例上评估的。

最接近我们的设置，在同期工作中，? 引入了 ASPIRE，一个从模糊能力目标自我演化的基准。智能体（有时是更强的教师优化较小的学生）通过访问外部数据改进权重或框架，并在某些设置中从隐藏评估中聚合分数。表现是在同一目标的隐藏项目上测量的。相比之下，我们研究一个仅从自生成经验改进自身的模型，并评估向不同环境的迁移。

7 讨论与局限

我们的结果与深度学习的基本趋势一致：随着模型变得更广泛地强大，它们需要更少的人类强加的归纳偏置。我们在元优化层研究这一现象，表明LLM智能体以最少的指导组合自己的自我改进循环，并展示可识别的学习策略。

模型在自我改进方面正在改进。 关键的含义不一定是单代智能体有效地自我改进，而是这种元能力跨代改进。在我们实验中有效自我改进的智能体比旧代智能体需要更少的脚手架，但仍然受益于显式提供的观察子智能体玩游戏的工具。下一代智能体可能需要更少的脚手架。我们的实验指出了这种可能性；在我们的 Claude Opus-5 Read-Write-Bash 实验中，一个教师会话通过运行命令行游戏模拟来测试其笔记，而没有任何提供的 Gameplay 工具或在其提示中提及模拟游戏（第 E 节）。事实上，一个足够强大的模型可以简单地在它的思维链中执行游戏，而无需编写的程序或单独的智能体实例。

安全性。 我们发现的另一个后果是，自组织改进不是一个等待发生的发现。我们在受控设置中、在短视野和相对简单的基于益智的任务上观察到这种能力。随着这种能力的改进并可能在更复杂的设置中观察到，科学地理解它并表征模型行为非常重要。

超越平台期？ 我们的实验表明，持续修订可能有递减的回报（图9）。在附录 D.3 中，我们显示额外的教师更新和游戏玩法预算可以带来更高的表现，但仍然观察到平台效应。这可能反映了自我改进能力的局限性，甚至是基于上下文学习的局限性。我们研究20次更新上的自我改进；模型要继续改进100次更新或1000次需要什么？传统学习算法在某些条件下改进直到最小化给定目标；这些模型的学习能力是否表现出类似的特性仍不清楚。

局限性。 我们的实验表明，几种人类可解释的自学习策略被有效的自我改进模型更频繁地展示。然而，这些结果并未完全理清自我调节策略与自我改进之间的因果关系。也可能较少人类可解释的行为也塑造了智能体表现；如何有效测量和表征此类行为仍然是一个开放问题。

另一个开放问题是，我们观察到的趋势是否扩展到模型具有较弱先验的更开放的领域。游戏有关于课程设计和可学习任务生成的广泛文献，模型可能已经吸收。PuzzleScript 的使用可能暗示真实世界环境或偏置模型，尽管我们的 Python 游戏消融显示 PuzzleScript 不是自我改进的关键因素。尽管如此，游戏提供了具有多个可控变化轴的丰富设置，包括游戏机制、游戏视野和观测表示。

附录A 扩展相关工作

我们根据学习过程的哪些组成部分保持外部指定以及学习如何发生来分类自我改进方法。我们考虑四个主要轴：经验来源，无论是外部提供还是由学习者自己生成；学习程序的结构，无论是规定的还是由学习者组织的；学习期间反馈的来源，例如外部定义的奖励或评估器与通过学习者自己的交互获得的反馈；最后，更新什么，例如模型权重或基于文本的上下文。另一个比较轴是所提出方法研究的泛化范围：一些评估在优化期间使用的相同任务分布或领域内的改进，而另一些测试学习的适应是否迁移到这些条件之外的新环境和领域。

非对称自博弈方法让教师为学生生成具有挑战性的问题，产生适应学生需求的涌现课程（?）。这些方法在后训练LLM中也取得了成功，例如编码、数学和科学推理领域（???????）。这些是经验来源由教师自生成的方法示例，即教师综合学生学习的问题，而学习通常通过对底层模型权重的基于梯度的优化进行。然而，优化程序本身保持外部指定，例如教师在批次内生成多少问题，学生多久在给定问题上被评估以确定其是否具有挑战性，以及随后教师如何被奖励。

相关想法出现在无监督环境设计中，其中环境从预定义的、通常是参数化的环境空间生成或选择，以形成适应学习者的课程（??????）。SPADE（?）通过利用 UED 的遗憾原则来训练产生环境而不是静态问答任务的教师，弥合了 UED 与LLM非对称自博弈之间的差距。与其他非对称自博弈工作类似，优化程序和任务选择保持外部指定。

非对称自博弈方法还可能遭受多样性或性能崩溃（?），促使额外的机制来决定哪些生成的问题提供有用的学习经验，例如使用评判器（?）或将智能体基于真实数据困难问题作为目标柱（?）。这些机制可以帮助稳定自博弈，但引入了关于什么构成有用学习经验的额外外部指定选择。还可以通过向模型提供关于在教师提出的问题上训练是否导致外部困难问题子集的改进的反馈来解决这种崩溃（?）。在这种情况下，反馈不再纯粹通过学习者自己的交互获得，同时仍然依赖自生成的数据来驱动学习。

另一条工作线考虑通过对模型的上下文或智能体框架的更新进行自我改进，而不是通过对模型权重的更新（????）。GEPA 使用对执行轨迹的自然语言反思通过进化搜索优化模型提示（?），而 ACE 维护一个不断发展的文本策略手册，积累以前交互的策略和经验教训（?）。在这些工作中，优化仍然相对于外部指定的任务分布进行，并且更新上下文的程序是预先指定的。

MCE 通过将上下文与指导上下文如何表示和更新的上下文工程技能共同演化部分放松了后者（?）。Meta-Harness 将优化对象进一步扩展到可执行的框架代码，允许模型更改上下文的管理方式，包括存储和检索什么信息（?）。优化仍然使用外部提供的任务，候选框架使用外部指定的目标评估。

关于自我修改智能体的相关工作进一步扩展了模型控制下的组件。达尔文哥德尔机迭代地修改自己的智能体代码并在外部指定的基准上评估生成的智能体（?），而 Hyperagents 额外使用于生成未来改进的元级程序本身可编辑（?）。这些方法因此允许自我改进机制的越来越大的部分发生变化，同时仍在外部指定的任务和评估设置中运行。

? 引入了开放式优化，其中目标、可用交互、资源预算、数据边界和评估是固定的，但模型可以自由组织改进过程本身。在此优化期间使用的任务仍然是外部提供的，并且生成的表现是在同一基准设置的保留示例上评估的，而不是研究超出优化发生环境的迁移。

最接近我们的设置，在同期工作中，? 引入了 ASPIRE，一个从模糊能力目标自我演化的基准。智能体（有时是更强的教师模型优化较小的学生）通过访问外部数据改进权重或框架，并在某些设置中从隐藏评估中聚合分数。表现然后在同一目标的隐藏项目上测量。相比之下，我们研究一个仅从自生成经验改进自身的模型，并评估向不同环境的迁移。

C.1 教师-玩家运行

框架细节。 单次运行由在持久框架会话中初始化的教师智能体和几个短暂的玩家框架会话组成。Claude 模型在 Claude Code（v2.1.232）中运行，所有其他模型在通过 OpenRouter 访问的 Pi（v0.85.1）中运行。所有框架会话在具有以下设置的 Singularity 容器内运行：

  • 会话在智能体可查看为 /workspace 的全新沙盒目录中运行。
  • 框架的默认系统提示被我们的替换（见附录 C.5）。
  • 工具仅通过允许列表授予；所有其他扩展、技能、提示模板、上下文文件等都被禁用。这包括网络搜索、网络获取、子智能体和任务管理工具等工具。
  • 自动记忆被禁用。
  • 自动压缩保持开启，但由于我们的教师和玩家预算，没有会话消耗足够的令牌来触发压缩。
  • 与人类操作员的交互被禁用；与会话的消息以编程方式管理。

可能的教师授予工具是 Read/Write 工具（包括用于管理文件的 Edit、Glob 和 Grep）、Bash 和我们的自定义 Gameplay 工具。

教师工作目录初始化为：
- player_folder：玩家文本产物的指定目录，初始化为包含默认玩家提示的 player_prompt.md（附录 C.5）。教师更新通过对 player_folder 的 Write/Edit 工具调用进行跟踪。
- puzzlescript_docs/ 包含 PuzzleScript Gameplay 运行的 PuzzleScript 文档，以及详述 Python Gameplay 运行预期 Python 类接口的 game_interface.md（附录 C.5）。

游戏玩法。 教师使用源游戏文件（PuzzleScript 或 Python）调用 Gameplay 工具，并可选择指定教师希望授予玩家的文本产物文件夹的路径。如果省略路径，玩家收到默认提示而没有辅助文件。PuzzleScript 游戏如果在 PuzzleScript JavaScript 引擎中无法编译，或者 BFS 求解器验证获胜状态不可达（如果 BFS 求解器超时，则接受游戏），则被拒绝。Python 游戏同样检查编译和安全检查（网络访问、文件访问等）。Gameplay 工具运行只有 Read 和 Glob 工具的全新玩家会话，并向教师返回以下输出：

  • 玩家得分。
  • 游戏结束原因（回合预算、令牌预算或玩家获胜）。
  • 教师游戏玩法和更新预算的状态。
  • 包含玩家推理、动作和观测的记录路径。

C.2 工具/预算意识消融

在第5.2节中，我们通过工具约束消融教师对评估设置的了解。我们运行以下设置的各3个种子，使用默认教师更新预算：

  1. Read-Write：教师只能访问文件管理工具。
  2. + Bash：上述工具和 Bash 访问（受沙盒约束）。
  3. + Gameplay (PS)：上述工具和 Gameplay PuzzleScript 工具。我们不为每个游戏玩法施加回合或令牌预算；相反教师选择它，实现了另一个自由轴。教师不是获得游戏玩法预算，而是获得玩家令牌预算和玩家回合预算，每次游戏玩法从中提取。我们将回合预算设置为3000，令牌预算设置为3.75M，从而计算匹配 t-20 约束设置（150次游戏玩法×20回合/游戏和150次游戏玩法×25k令牌/游戏）。

  5. + t20 回合预算：这是我们的规范设置，其中教师有游戏玩法预算，Gameplay 工具施加 t20 回合和令牌预算（20回合和25k令牌）。

C.6 自我调节学习标注

我们使用改编自 Zimmerman 自我调节学习循环阶段模型的评分标准（?）对每个教师会话进行评分。评分标准最初使用 GPT 6-Astra 从 ?? 改编，然后由作者审查和完善。分析单元是教师-玩家系统。我们使用 GPT 6-Astra 作为评判器（中等推理努力）进行标注。

评分标准涵盖三个阶段的13个子过程。每个子过程以0-3的尺度评分其存在和质量：

  • 0，无功能或省略：子过程缺失、未使用，或以违背其目的的方式执行。
  • 1，弱：功能可识别，但实质性差距限制其有用性。
  • 2，足够：它以适当的特异性、契合度和执行服务于其功能。
  • 3，强：它在相关机会中一致地服务于其功能，并很好地处理重要的限制和相反证据。

每个项目都有1-3分的描述；完整评分标准见附录 F。一个项目可以被标记为无法评估，但只有在无法分配可辩护分数时才能如此。注意原始 Zimmerman 框架包含17个子过程，但我们过滤掉了评判器在初始试点中对所有模型一致判断为无法评估的4个。

每个教师会话分批评判。单批是一轮教师动作（例如 Bash 命令、Gameplay、思考），以对玩家文本产物的修改结束。对于每批，我们采用两轮评判协议：

  • 第一轮：评判器接收初始输入，包含评分标准、教师-玩家设置的简短描述、教师的系统提示和资源预算、当前批的教师动作记录以及批游戏玩法索引。为了将当前批置于上下文中，我们包括以前批次的教师动作记录。评判器返回支持判断的额外证据请求，例如教师工具调用的完整输入/输出和游戏玩法记录。
  • 第二轮：评判器接收请求的证据并返回13个子过程各自的分数，以及引用的证据、反证和简短理由。

对于每个教师会话，我们对所有批次的每个子过程分数取平均。
