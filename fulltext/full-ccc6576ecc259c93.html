作为独立创始人，我在 Supabase 上构建了一个完整的交易市场（身份验证、postgres、RLS、存储、边缘函数、实时、无服务器网页）。如果我自己连接所有这些，我需要一个小型的后端团队。底层的 Postgres 意味着我永远不会被锁定，也永远不会与自定义 DSL 作斗争。
特别是 RLS（行级安全）是关键解锁，安全策略与数据并存，而不是埋没在会失去同步的中间件中。

对比替代品

看过 Firebase（无 SQL，供应商锁定）、Pocketbase（单一二进制文件很棒但没有托管扩展），以及在原始 Postgres + Hasura + 自定义身份验证上自己搭建。
Supabase 胜出是因为它为你提供了真正的 Postgres，并且已经完成了生产环境的配置，但并没有用主观设定掩盖数据库。迁移是 SQL 文件。查询是 SQL。

Supabase 是 Firebase 的绝佳替代品，提供了一系列强大的功能，如实时数据库、身份验证和存储，并采用了更开源的方式。不过需要注意的是，应用在一段时间不活动（比如一周）后可能会被暂停，这可以通过触发一个简单的读取请求来重新激活服务来解决。总的来说，我已经在几个自由职业项目中使用了 Supabase，对其可扩展性和易于集成的特点印象深刻——非常适合小型和大型应用。
