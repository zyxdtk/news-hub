摘要。
程序化表示为3D内容创建提供了一个引人注目的范式，能够实现细粒度编辑、可解释性和显式结构控制。
然而，依赖大语言模型（LLM）编写3D程序的智能体工作流仍然很脆弱，往往无法将高层意图转化为一致的低层几何。
我们将这种脆弱性归因于现有程序化接口与LLM推理优势之间的不匹配，LLM更倾向于语义结构和空间关系，而不是脆弱的数值选择。
在本文中，我们联合设计了一个以智能体为中心的领域特定语言（
aDSL
）和一个角色专门化的多智能体系统来弥合这一差距。
aDSL
通过强调可组合性和空间推理来桥接语义逻辑和几何约束；它使智能体能够通过关系运算符而不是脆弱的绝对坐标来操纵几何。
在
aDSL
的基础上，我们无需训练的多智能体系统遵循“计划-执行-评估”循环来分解请求、合成代码，并使用执行反馈迭代修复错误和约束违规。
实验表明，这种协同设计提高了鲁棒性、可控性以及对用户意图的忠实度。
我们的方法在文本到形状和图像到形状任务上优于先前基于LLM的基线，同时保留了显式结构、可编辑性和可解释性。它还支持铰接对象创建和结构化场景组合等下游应用。

aDSL
支持平移、旋转、缩放和一般仿射变换，以控制放置和方向。
可组合性
我们将
aDSL
嵌入到Python中，重用其解析器、运行时和熟悉的抽象机制，包括可重用的函数和类、对象层次结构以及结构化控制流（如
for

将评估委托给Python宿主使DSL保持紧凑，同时保留确定性的、可验证的执行语义，并为基于LLM的生成、编辑和修复提供自然接口。
在这种嵌入中，可组合性由显式的父子部件附件表示：资产作为命名的层次结构组装，实现了组件重用、局部细化和跨细节级别的增量构建。
相同的层次结构还支持铰接，因为移动部件在程序中保持语义标识。
我们通过父部件方法附加运动学关系，例如
.revolute(, ...)
，
其中每个关节指定其原点、轴和运动限制。
因此，单个
aDSL
程序定义了资产的几何和运动，并可以直接导出为标准化的URDF模型，如
Section
4.4
中通过铰接对象创建所演示的。
空间推理
aDSL
通过用于布局和约束驱动程序合成的紧凑
空间推理
基元层增强了CSG建模。
对于每个几何基元或组合部件，
aDSL
暴露了轴对齐边界框（AABB）属性，包括中心、范围和每轴的最小/最大值，作为一等关系查询。
这些AABB查询仅用于描述关系和布局约束。
底层几何仍由基元、CSG操作和几何变换表示，允许建模非轴对齐和更复杂的形状。
在这些查询的基础上，
aDSL
提供了
声明式
布局运算符，如放置、中心对齐和分布，它们将常见的空间关系表达为单个程序语句，而不是脆弱的、低层的数值选择。
这些运算符自然地支持智能体生成-验证-修复循环。
在生成过程中，智能体将高级要求转换为显式空间约束，并选择性地应用适当的运算符来满足它们。
执行后，可以通过渲染和程序状态检查生成的几何。
当检测到违规时，通过调整运算符参数（偏移量、轴、顺序和分布参数）或插入额外的布局步骤来修复程序，并重复该过程直到满足所有约束。
通过通过这些声明式运算符路由合成，
aDSL
减少了对脆弱数值的依赖，并在我们的实验中提高了可靠性。

智能体系统

aDSL
程序的智能体系统。
该系统由四个阶段组成：规划、编码和执行、评估以及记忆/上下文管理。
每个阶段由专门的智能体处理，如

规划阶段
工作流从规划阶段开始，将用户请求转换为显式的、可检查的规范。
Planner
解析输入并输出包含三个组件的建模规范：
-
组件分解：
目标资产的层次分解，带有指导几何构建的自然语言描述，并与
aDSL
的组合结构对齐；
-
空间关系：
组件之间的连接、对齐和相对放置约束，以可部分映射到
aDSL
空间推理基元的形式表示；
-
评估检查表：
从用户需求中得出的一组精确、可验证的标准，包括组件存在性、数量、支撑/接触关系和对齐约束。
我们将组件分解和空间关系转发给
Coder
，以将实现建立在稳定的架构计划中，并将检查表提供给
Critic
以进行系统验证和定向修改。
编码和执行阶段
在
Planner
输出的条件下，
Coder
通过实例化基元、将它们组合成命名的部件层次结构并应用变换和布局运算符来合成
aDSL
程序，以满足指定的约束。
Executor
运行程序以生成几何并将其导出为网格表示。
成功执行后，渲染器通过生成多视图快照来捕获视觉证据，以供下游评估，这些快照最小化自遮挡并提高局部几何细节的覆盖率。
如果执行失败（例如，由于无效参数、缺失定义或运算符使用不当），
Debugger
分析错误信号并提出针对性补丁。
这些修复返回给
Coder
进行修改，将细化建立在可观察的程序行为基础上，并确保在评估之前具有可执行性。
评估阶段
成功执行后，工作流进入将视觉检查与程序级验证耦合的细化阶段。
首先，
Image Critic
将多视图渲染与
Planner
的检查表进行比较，识别感知和结构差异（例如，缺失组件或比例不正确），同时忽略次要的渲染伪影。
这些视觉观察被转发给
Code Critic
，它作为最终裁决者。
Code Critic
将视觉反馈与底层的
aDSL
程序进行交叉引用，使用相同的代码结构来验证所报告问题的有效性。
此验证确保自校正循环是由编程错误驱动的，而不是由遮挡或透视模糊引起的幻觉驱动的。
记忆和上下文管理
为了防止上下文溢出同时确保迭代细化过程中的长期稳定性，我们使用了一种
选择性记忆
机制，将持久约束与瞬态工作状态分开。
用户输入和
Planner
的输出形成
持久记忆
，在所有智能体中保留，以确保原始目标永远不会丢失。
所有其他中间结果被视为
瞬态记忆
，并由特定规则修剪。
Coder
维护一个滑动窗口，仅保留固定的要求和最近的代码合成，同时丢弃过时的代码和调试日志以保持工作区清洁。
Critic
对“数据密集”内容实施严格的重置策略：具体来说，多视图渲染在每轮之后从历史记录中删除，而先前反馈的文本记录被保留。
这种设计防止了过时视觉的污染，并在反馈流中保持了跨轮次的连续性。

5.
结论
在本文中，我们提出了一个通过联合设计以智能体为中心的DSL和角色专门化的多智能体系统来实现智能体3D创建的无需训练的框架。
通过将3D资产表示为可执行的、结构化的程序，我们的方法弥合了高级语义意图和低层几何之间的差距。
核心贡献是这种联合设计：一个具有空间推理运算符的组合DSL，与用于迭代生成、验证和修复3D程序的“计划-执行-评估”循环紧密耦合。
我们的评估表明，这种协同设计提高了鲁棒性、可控性和可编辑性，同时自然地支持了铰接资产建模、形状编辑和场景级组合等下游应用。
我们当前的系统仍然存在一些局限性和明确的未来工作方向。
首先，最终输出质量仍然受到DSL及其几何基元的表达能力的限制；高度复杂的几何、外观和材质效果可能需要与学习到的高保真生成器进行更紧密的集成。
其次，尽管
Critic
为迭代修复提供了有用的反馈，但其验证仍然主要基于2D渲染，并且可能受到透视模糊的影响。
第三，该框架目前依赖于强大的专有LLM来进行可靠的长期空间推理和修复，这限制了其可访问性。
将这些能力提炼到开源语言模型中，是使智能体3D内容创建更广泛可用的重要下一步。
