## 摘要 随着大语言模型（LLM）越来越多地被用作代码应用中的评判者，它们应在能够捕捉部分上下文和模糊意图的真实交互场景中进行评估。 我们提出 **TRACE**（**T**ool for **R**ubric **A**nalysis in **C**ode **E**valuation，代码评估中的评分标准分析工具），一个用于评估 LLM 评判者预测人类偏好的能力，并自动提取评分标准项以揭示人类与模型在各项权重分配上系统性偏差的框架。 在三种交互模式——基于聊天的编程、IDE 自动补全和指令式代码编辑中，我们使用 TRACE 来衡量 LLM 评判者与开发者偏好的匹配程度。 在 13 个不同模型中，表现最佳的评判者仍比人类标注者低 **12-23%**。 TRACE 识别出跨交互模式下人类与评判者之间 35 个显著的不一致来源，其中大多数对应现有的软件工程代码质量标准。 例如，在基于聊天的编程中，评判者倾向于更长的代码解释，而人类则偏好更简短的解释。 我们在大多数现有代码质量维度上发现显著的不一致，表明在真实编程应用中，LLM 评判者与人类偏好之间存在明显的对齐差距。

## 1 引言 随着基于大语言模型（LLM）的工具加速发展，它们正被广泛应用于代码生成、自动补全、代码审查等任务中。在这些场景中，LLM 不仅生成代码，还常被用作“评判者”，对代码质量进行评估或排序。然而，当前对 LLM 评判能力的评估大多基于静态、理想化的设置，缺乏对真实交互场景中上下文不完整、意图模糊等复杂因素的模拟。

在真实开发环境中，开发者在编写代码时往往面临不完整的信息、模糊的需求或动态变化的上下文。例如，在与 LLM 交互时，开发者可能仅提供部分代码或简要描述，期望模型生成或修改代码。此时，评判者（无论是人类还是 LLM）需要在有限信息下做出判断，其决策过程可能受到多种因素影响，如代码长度、可读性、效率、安全性等。

现有研究通常通过人工标注或静态评估指标（如 BLEU、ROUGE）来衡量 LLM 输出质量，但这些方法难以捕捉人类开发者在真实交互中对代码质量的主观偏好。更重要的是，LLM 评判者可能在某些维度上系统性地偏离人类偏好，例如过度偏好“更长的解释”或“更复杂的结构”，而人类开发者可能更看重简洁性或可维护性。

为解决这一问题，我们提出 **TRACE**，一个用于分析 LLM 评判者与人类偏好对齐程度的框架。TRACE 不仅评估 LLM 是否能准确预测人类偏好，还通过自动提取评分标准项（rubric items），揭示人类与模型在各项权重分配上的系统性偏差。

在三种典型交互模式下——基于聊天的编程、IDE 自动补全、指令式代码编辑——我们使用 TRACE 对 13 个主流 LLM 模型进行评估。结果表明，即使是最优模型，其与人类标注者的一致性仍存在 12-23% 的差距。此外，TRACE 识别出 35 个显著的不一致来源，其中多数与现有软件工程代码质量标准高度相关，如可读性、简洁性、正确性、效率等。

例如，在聊天编程场景中，我们发现 LLM 评判者显著偏好更长的代码解释，而人类开发者则更倾向于简明扼要的解释。这种偏差在真实开发中可能导致 LLM 生成“过度解释”的代码，降低开发效率。

本研究揭示了 LLM 评判者在真实编程应用中与人类偏好之间存在的系统性偏差，强调了在设计和评估 LLM 评判系统时，必须考虑真实交互场景中的上下文动态和人类主观偏好。TRACE 为未来研究提供了可扩展的框架，以系统性地分析和改进 LLM 在代码评估中的对齐能力。

3 方法论 给定一组人类偏好数据和一组候选的LLM评判者，我们如何确定哪个评判者最符合人类偏好，并比较人类与评判者之间的偏见？ **TRACE** 通过三个阶段回答这些问题（见图 2）：（1）我们测量LLM评判者是否与人类的成对偏好一致；（2）我们生成可解释的评分标准条目，以捕捉区分响应对的评估标准；（3）我们量化评判者相对于人类在这些评分标准条目上赋予的不同重要性。 在后续章节中，我们将展示如何将 **TRACE** 应用于多个交互数据集，用于代码评估。

3.3 在评分标准项目上比较人类与判断模型的偏差 为了刻画人类与LLM判断模型之间的分歧，我们分析评分标准项目 R R 如何影响偏好决策。我们通过训练逻辑回归模型来量化每个评分标准项目的贡献，这些模型使用第3.2节中引入的评分标准项目，预测第3.1节中的判断偏好。为了将自然语言形式的评分标准项目纳入模型，我们首先将其映射为数值特征，具体方法如下所述。然后，我们比较人类和判断模型各自学习到的系数，以识别在评分标准项目权重分配上的不一致。

偏好建模。 我们描述使用评分标准项目训练偏好模型（逻辑回归）以预测判断偏好的过程。 对于每个样本

和评分标准项，一个大语言模型（LLM）排序器会为每个响应分配一个分数，分数属于集合 $\{-1, 0, 1\}$，表示响应 $y_A$ 更好地满足评分标准项（-1），响应 $y_B$ 更好地满足（1），或两者同等满足（0）。我们将数据集中所有样本的这些分数组合起来，构建一个特征矩阵 $S$，其中行对应响应对，列对应评分标准项。

我们分别使用 $S$ 作为输入特征，为人类评估者和每个 LLM 评估者训练独立的逻辑回归模型。人类判断结果作为人类模型的标签，而每个 LLM 评估者的判断结果则作为其对应模型的标签。这得到了一个人类系数向量 $\beta_H$ 和每个评估者特定的系数向量 $\beta_J$，其中 $\beta^{(i)}$ 表示评分标准项 $R^{(i)}$ 的系数。这些系数之间的差异反映了人类和 LLM 评估者在使用相同输入特征表示 $S$ 时，对评分标准项的不同加权方式。
