📅 2026-07-01 📄 VentureBeat AI 🔗 原文链接

原标题：Claude Code turned every engineer into three. Now companies need more product thinkers

中文摘要： 文章指出，AI编程工具（如Claude Code）使工程团队产出达到以往的三倍，导致软件开发瓶颈从“编写代码”转移至“决定开发什么”。随着工程师产能激增，传统的产品经理与工程师比例失衡，公司亟需更多具备产品思维的人才。未来十年，优秀的工程师不仅需掌握底层基础知识以审查AI代码，更要深入理解客户需求，主动参与产品决策，而非被动等待任务分配。

Anthropic最近告诉其增长团队，要多招产品经理，而不是少招。正如行业报道所述，原因是Claude Code已悄然将其工程团队变成了一个产出相当于其实际人数三倍的团队，瓶颈也从集成开发环境（IDE）转移到了决定要开发什么的人身上。
在各种AI生产力的喧嚣中，这个细节很容易被忽略。这也是整个行业目前正在经历的结构性转变。软件的瓶颈不再是打字，而是决定打什么字。那些将此视为他人问题的工程师即将遇到职业瓶颈。
在过去十年的大部分时间里，这个决定权在别人手里。软件工程是一门你慢慢吸收的技艺，然后在一个漫长、可预测的序列中实践：深入研究技术，编写代码，卡壳时问Stack Overflow，Stack Overflow失效时升级给高级工程师，交付任务。产品经理负责漏斗，工程师负责构建。双方都将这种分工视为物理定律。
然后，漏斗在五个阶段中坍塌。

工程师的一天如何被压缩的简史

Stack Overflow时代（2014年至2022年底）：工程师的思考方式集中在一个地方。但自2022年11月以来（巧合的是，这正是ChatGPT发布的时间），Stack Overflow上的每月新问题数量下降了约77%。这种下降不是对该网站的公投，而是对它所代表的工作流的公投。
浏览器标签页时代（2022年底至2024年）：第一代ChatGPT存在于IDE之外。工程师们运行着与以往相同的循环，只是用了一个更快的“神谕”：在浏览器中写提示词，将答案粘贴回VS Code，重复。工作仍然是单线程和工程师驱动的。杠杆效应是真实的，但也是局部的。
IDE原生时代（2024年至2025年）：Cursor和Claude Code将模型移到了编辑器内部，并让它能访问整个代码库。向高级工程师升级求助的路径基本消散。多年来，资深工程师中的普遍看法是，Bash是技术栈中保质期最长的工具。到2026年，对于相当一部分在职开发者来说，在全新终端中输入的第一个命令是claude。
规范驱动时代（2025年至2026年）：更大的上下文窗口将单次会话工作变成了以前需要任务单、设计文档和冲刺才能完成的事情。据报道，亚马逊的Kiro IDE团队使用他们正在交付的相同规范驱动工作流，将功能构建从两周压缩到了两天。一个AWS工程团队描述了一项为期18个月的架构重构，最初计划由30名工程师完成，结果由6个人在76天内完成。瓶颈不再是编写代码需要多长时间，而是团队能多清晰地描述“正确”应该是什么样子。
例行程序时代（2026年）：4月，Anthropic发布了Claude Code Routines：定时、持久的智能体，可按节奏、在Webhook上或在笔记本电脑合上过夜时运行。Cron回来了。Hooks回来了。工程师的工作现在有一部分是编排：睡前启动一个集群，早上审查一堆拉取请求。像OpenClaw这样的第三方封装工具（曾在4月被Anthropic短暂暂停，后部分恢复）从开源的角度证明了同样的观点。

瓶颈转移了；大多数团队还没有

工程产出大约增加了两倍。产品管理却没有动静。传统的产品经理与工程师1:8的比例本已捉襟见肘，现在由于每个工程师每天交付得更多，实际比例接近1:20。例如，LinkedIn用“Product Builder”项目取代了其助理产品经理轨道，该项目培养跨产品、设计和工程的多面手。Anthropic正在招聘更多的产品经理，而不是更少。这种模式在真正在生产环境中部署智能体工作流的公司中是一致的：系统产出已构建功能的速度，快于产出关于应该构建什么的决策。
对于工程师来说，这是十年来最重要的职业信号，也是在生产力故事占据信息流时最容易忽略的信号。

第一性原理更重要了，而不是更不重要

在智能体时代宣布基础知识过时的直觉，完全误解了这一趋势。
当凌晨3点内存泄漏导致生产环境崩溃，而原因被证明是4年前推送的一个微妙的所有权错误时，目前市面上没有任何智能体能够端到端地闭环解决这个问题。操作系统、网络、并发和查询计划仍然决定了谁能解决真正的故障。它们也决定了谁能发现智能体的输出在表面上看起来正确，但在底层却悄悄地、代价高昂地出错的时刻。编写了现代代码库中70%代码的智能体，无法可靠地告诉任何人它对线程安全、内存所有权或事务隔离的假设在何处偏离了运行时。能够阅读差异并捕捉到这一点的工程师，正是团队其他成员需要的工程师，而这位工程师是建立在基础知识之上的，而不是提示词技能。
必然的结果是，基础知识现在是一种杠杆技能，而不是一种基础卫生技能。在2014年，了解TCP重传的工作原理可以更快地关闭调试任务单。在2026年，同样的知识可以防止整个智能体驱动的发布流水线大规模发布回归错误。了解底层发生了什么的工程师的影响范围增加了，而不是减少了。

审查就是新的编写

2026年的工程师生成代码的速度超过了他们中任何人能仔细阅读的速度。能够快速交付并存活下来的团队，其工程师会以至少与编写代码时相同的严谨态度来审查AI生成的代码。2025年Stack Overflow开发者调查显示，84%的开发者使用AI工具，其中46%表示他们不信任输出结果，较去年的31%大幅上升。这种高使用率与低信任度之间的差距，正是审查技能现在最为重要的地方。推送大量代码却很少审查的程序员正在积累债务，这些债务将在第一次真正的故障中到期，而能够偿还债务的工程师，是那些将代码产量与对相关系统的深厚第一性原理知识相结合的人。

新的差异化优势是产品漏斗

这两者都是必要的。但都不足够。在2026年，重要的工程师是那些不再等待以Jira任务单形式出现的漏斗的人。
这意味着要做这个角色在历史上被允许跳过的事情。
与客户交谈。观察他们实际如何使用产品。阅读支持队列。旁听销售电话。产品团队通过三层摘要获得的信号，工程师现在可以在一个下午直接获得。
产生想法，而不仅仅是估算。过去为8名工程师寻找想法的产品经理，无法以同样的保真度为20名工程师寻找想法。带着经过验证、范围明确的机会出现的工程师，不再是在做产品经理的工作。工程师正在做新比例所要求的工作。
从客户出发逆向工作。亚马逊二十年来一直坚持先写新闻稿。这种纪律同样适用于单人团队和智能体集群。如果没有在编写任何代码之前明确说明“客户获胜”意味着什么，两者都会产生大量方向错误的有效软件。
不要再躲在带宽后面。对于“你有精力做这个想法吗？”这个问题的诚实回答过去是“没有”。有了例行程序、Hooks和协作的智能体堆栈，诚实的回答更接近于“这个想法值多少钱？”这是一个不同的对话，如果没有对客户的真正见解，这个对话会困难得多。

未来十年奖励什么

上述五个阶段的历史实际上并不是工具的历史。它是关于人类必须完成工作中哪一部分的历史。仍然是人类的部分，并且在可预见的未来仍将是人类的部分，已经向上移动到了漏斗：从打字，到审查，到决定，到选择要服务的客户和要解决的问题。
2026年版本的优秀工程师不是编写最多代码的人。而是那个知道要构建什么，能证明它值得构建，并拥有智能体集群和审查纪律来交付它，而不会让系统在其自身速度下崩溃的人。
将此内化的工程师将在未来十年从事软件有史以来产生的最有趣的工作。等待任务单的工程师将在这十年里看着任务单被他们旁边的智能体写出来。
