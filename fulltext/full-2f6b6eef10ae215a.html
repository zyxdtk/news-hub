TrustedRouter推出三款加密融合模型

📅 2026-11-12 📄 VentureBeat AI 🔗 原文链接

原标题：TrustedRouter launches three new encrypted 'fusion' models that combine multiple LLMs, including one exclusively with U.S. model providers

中文摘要： TrustedRouter推出三款加密融合模型：Prometheus 4.0整合六个开源权重模型的独立答案，Liberty 4.0仅采用NVIDIA、Reflection AI和Meta三家美国提供商的模型，Polyphemus 1.0则按请求选择单一模型。公司估算其成本相比Claude Fable 5.1可降低约60%至80%。这些产品是纽约代币交易所（NYTE）计划的一部分，旨在将AI推理变为可交易的大宗商品市场，并借助机密计算保护数据隐私。

为公司选择一个 AI 模型已经够难了，而为每项工作选择合适的模型则更难。你应该把一次棘手的代码审查交给 Anthropic 的 Claude Fable 5.2，尝试美团的开源权重模型 LongCat-2.5，还是使用其他模型？答案可能因任务而异，即使在同一个应用程序中也是如此。

幸运的是，已经涌现出一批公司，试图通过智能地将不同任务或任务的一部分路由给最适合以最具成本效益方式完成它们的模型，来自动为你解答这个问题。

其中最新的一家是初创公司 TrustedRouter，它还致力于通过符合条件的机密路由为企业和开发者提供保持数据私密的额外好处——这些路由让用户提示词始终保持加密状态，直到到达运行模型的提供商处经过验证的硬件。

企业无需将每个请求直接发送给 OpenAI、Anthropic 或其他模型开发商，而是可以使用 TrustedRouter 根据成本、可用性、模型能力和隐私要求，将工作负载引导至不同的提供商。

提示词在该受保护环境中解密，该环境旨在防止提供商的运营人员接触到提示词。保护程度取决于路由和调用者的隐私设置。

现在，TrustedRouter 正通过其现有 API 推出基于这一理念打造的三款加密“组合”模型。开发者可以通过纽约代币交易所使用以 nyte/ 开头的模型 ID 访问它们。

Prometheus 4.0 将六个开源权重模型组成的评审团的独立答案合并为单一响应。Liberty 4.0 同样合并多个答案，采用的是 NVIDIA、Reflection AI 和 Meta——三家美国 AI 模型提供商的模型。Polyphemus 1.0 则为每个请求挑选单一模型作答。TrustedRouter 文档将其标注为标准隐私。

这三款模型均使用与 TrustedRouter 网关的加密连接。对于 Liberty 4.0 和 Prometheus 4.0，提供商端的机密处理为可选项目。Polyphemus 1.0 使用标准隐私。

在接受 VentureBeat 的独家视频采访中，创始人兼 CEO Joseph Perla 解释了这些模型的工作原理，以及公司为何希望为开发者提供更多将模型与工作相匹配的方式。

“每个人都应该使用路由器，因为没有任何一家提供商是 100% 可靠的，”Perla 说。“即使是 Claude 有时也会宕机，所以你必须使用路由器。”

这三款新模型各自决定将请求路由到何处以及如何路由到底层模型。一个困难的研究问题可能受益于多个独立答案，而常规分类可能只需要一个模型。每个预设都有自己的路由和隐私特性。

据 Perla 介绍，该系统使用 NVIDIA GPU 支持的机密计算技术，在 AI 请求处理期间对其进行加密，防止基础设施提供商和交易所本身读取客户的敏感信息。

它还旨在验证实际处理每个请求的是哪个 AI 模型，降低客户为昂贵模型付费、却在不知情的情况下收到来自更便宜替代模型的结果的风险。这些能力是 Perla 论点的核心：企业可以通过共享市场安全地从陌生的基础设施提供商处购买 AI 服务。

Perla 表示，这三款产品是纽约代币交易所更大计划的一部分。Lore Hex Corp 运营着这两项服务。

TrustedRouter 是将应用程序连接到模型和托管提供商的网关。NYTE 利用该网关按需销售 AI 处理能力，并提供提前容量预订。

这两个 API 地址共享密钥、账户余额和路由行为，开发者可以使用 nyte/ 或 trustedrouter/ 前缀调用相同的预设。

发送提示词之后会发生什么？

据 TrustedRouter 介绍，Prometheus 和 Liberty 会要求多个模型独立且并行地回答一个提示词。一次单独的评审调用评估它们的答案，一次合成器调用生成最终响应。一次完整的 Prometheus 请求使用八次模型调用，一次完整的 Liberty 请求使用五次。

一个遗漏了来源或在计算中走错方向的模型可以与其他模型对照检查。合成器必须识别哪个答案有更充分的支持。

如果多个评审团成员犯了同样的错误，仅凭一致意见，合成器几乎没有理由纠正它们。运行评审团的成本和合成所花费的时间是这种权衡的一部分。

Prometheus 4.0 是开源权重评审团。公布的阵容包括小米的 MiMo-V2.6-Pro、Z.ai 的 GLM 5.3、月之暗面的 Kimi K3、DeepSeek V4.1 Flash、MiniMax M3 和阿里巴巴的 Qwen 3.8。TrustedRouter 为该预设列出了 100 万 token 的上下文窗口。其滚动别名 nyte/prometheus 跟随最新版本，而 nyte/prometheus-4.0 则选择此版本。

TrustedRouter 尚未说明由哪个模型合成生产答案、合成开始前必须有多少评审团成员完成，以及当各组件模型的上下文限制不同时，宣传的上下文限制如何适用。

Liberty 4.0 汇集了来自 NVIDIA、Reflection AI 和 Meta 这三家美国开发商的模型。组件目录列出了 NVIDIA 的 Nemotron 3 Ultra、Reflection 的 Beam 和 Meta 的 Muse Spark Open。

TrustedRouter 表示，每个评审团成员独立作答，由 Meta 模型合并这些响应。如果 Meta 模型不可用，则由 Beam 接管合成。如果某个评审团成员未能作答，Liberty 可以使用它收到的响应继续工作。

Polyphemus 1.0 在生成答案之前做出选择。选择器检查请求并选择一个模型，由该模型通过单次调用作答。其模型文档指定了 Responses API 和 65,536 token 的上下文窗口。

它按每百万估计选择器输入 token 收取 0.05 美元，外加所选模型的正常费用。如果选择器失败，则由 TrustedRouter 的通用自动路由处理请求，选择器费用也会取消。开发者可以重用会话 ID 并在每一轮发送对话历史，以提高重用缓存输入的机会。

会话在一小时不活动后过期。文档列出了此预设的标准隐私。选择器的合格模型池、决策标准以及相对于固定模型基线的性能仍是悬而未决的问题。

一个答案要花多少钱？

TrustedRouter 的模型目录显示，Prometheus 4.0 的组件路由费率约为每百万输入 token 0.01 至 1.48 美元，每百万输出 token 0.13 至 7.39 美元。Liberty 4.0 的输入费率约为 0.42 至 1.32 美元，输出费率为 1.27 至 4.48 美元，同样按每百万 token 计。这些费率描述的是请求的组成部分。

评估评审团的买家需要的是总账单，包括每个模型以及评审和合成器所做的工作。TrustedRouter 对预付文本的标准加价为 5.5%，无需订阅。该公司记录了选择加入签名推理回执的托管预付请求的 12% 总服务费。

TrustedRouter 估算了每个预设相对于 Claude Fable 5.1 的每请求成本。评审团估算涵盖了完整请求中的所有调用。Polyphemus 的估算节省取决于它选择的模型。

Liberty 4.0：TrustedRouter 认为 Fable 5.1 的每请求成本是 Liberty 的 2.3 至 2.9 倍，即 Liberty 大约节省 60%。完整运行共进行五次调用：三个美国开源权重模型作答，一次调用评审它们的响应，一次调用合并它们。

Prometheus 4.0：TrustedRouter 认为 Fable 5.1 的每请求成本是 Prometheus 的 2.5 至 3 倍，即 Prometheus 大约节省 60% 至 65%。完整运行共进行八次调用：六个开源权重模型作答，另外两次调用用于评审和合成。

Polyphemus 1.0：TrustedRouter 估计，当路由器选择 Claude Opus 5.5 时成本降低约 60%，选择 GPT-6.1 Sol 时降低约 80%。

TrustedRouter 提供的是相对节省数据。底层的美元成本、任务、质量和延迟测量，以及 Polyphemus 的数据是否包含选择器费用，仍属未知。

TrustedRouter 为 Prometheus 系列发布的最具体的基准测试结果来自更早的版本。

在其 7 月的测试结果中，TrustedRouter 报告 Prometheus 2.0 在 Perplexity 的 DRACO 深度研究基准全部 100 项任务上得分 77.4。其报告列出了 Claude Fable 5 的 65.3 分、GPT-5.5 的 63.3 分和 Claude Opus 4.8 的 60.3 分作为单模型参考分数。

Perla 在解释为何预期评审团在困难查询上优于单个模型时提到了这些研究测试。该结果适用于研究基准上的早期配置。只有在匹配任务上进行比较，并同时报告成本、质量和延迟，才能显示这些节省是否适用于买家的工作负载。

在 VentureBeat 的一次测试中，Claude Code 通过 TrustedRouter 调用了 DeepSeek Flash。它正确地返回了巴黎作为法国首都。Claude Code 随后估计，对同一个问题，Fable 5.1 的成本约为其 70 倍。这一估计说明了一个简单请求的价格差异。

更严格的测试将衡量评审团获得更便宜的单模型所遗漏的可用答案的频率，以及这些额外工作的成本。

TrustedRouter 与 GitHub、Sakana、OpenRouter 和 Arcade 的比较

GitHub Copilot Fusion 在编码代理内部做出选择。根据任务和努力程度设置，它可以使用单一模型，先使用高效模型并在质量检查后升级，或让一个模型审查另一个模型的草稿。GitHub 让企业管理员控制合格模型。

在 Artificial Analysis 的独立测试中，Fusion Max 平均每个编码任务花费 5.59 美元，而在 Max 设置下运行 Claude Opus 5.5 的 Claude Code 为 11.42 美元，两者在编码代理指数上相差两分。

正如 VentureBeat 此前报道的那样，该比较是在相同测试上测量完整的编码代理。TrustedRouter 发布的 DRACO 分数测量的是深度研究，因此它们回答的是不同的问题。

Sakana AI 的 Fugu Max 和 Fugu Ultra v2 在开发者使用方式上更接近 TrustedRouter。它们提供了一个隐藏多模型协调工作的 API。Fugu Max 从池中选择组合以平衡质量和成本。Ultra 则使用更深层的代理组来处理更难的工作。

OpenRouter Fusion 是与评审团设计更接近的竞品。其文档记录的管道可以将提示词并行发送给多个模型，让评审比较它们的工作，并将该分析传递给撰写答案的模型。

开发者可以配置评审团和评审。TrustedRouter 则为开发者提供具有明确用途和版本化 ID 的命名预设。

企业可以在同一个应用程序中将工具发现与模型路由结合使用，因为前者选择可用的操作，后者决定由哪个模型处理请求。

当多个模型看到提示词时，隐私问题变得更难

TrustedRouter 表示，其网关运行在密封的计算环境（即飞地）中，协调模型调用的逻辑也在其中运行。客户可以根据已发布的源代码核对网关的硬件证明。TrustedRouter 表示其网关不保留任何提示词或输出日志。

TrustedRouter 告诉 VentureBeat，客户可以要求 Liberty 或 Prometheus 请求中的每次模型调用都使用机密硬件。机密端点需要端到端加密、提供商端机密计算和零数据保留。该要求涵盖评审团成员、评审、合成器和回退路由。如果网关无法为某次必需的调用找到合格的路由，请求就会失败。

据 TrustedRouter 称，Liberty 4.0 仅路由到总部位于美国的提供商，如果否则必须路由到总部位于其他地方的提供商，请求就会失败。至于数据中心的物理位置，TrustedRouter 依赖其提供商告知的信息。

签名回执可以识别模型和提供商，并记录上游验证的级别。

“那只是文字输出而已，”Perla 在谈到仅凭答案识别模型时说。

其他与部署相关的细节包括：回退调用如何在账单上显示、实测延迟，以及三个预设对流式传输、工具调用和结构化输出的支持。

TrustedRouter 的起源

在推出 TrustedRouter 之前，Perla 职业生涯的大部分时间都在 AI、云计算和大规模技术基础设施的交叉领域工作。

在普林斯顿大学学习计算机科学和机器学习后，他曾在桥水基金工作，创立了音乐初创公司 Turntable.fm，随后加入 Facebook，担任其移动版 News Feed 的技术负责人。

此后，他攻读人工智能博士学位，之后离开学术界，于 2013 年联合创立了 Terminal.com——一个早期的 GPU 云计算平台，允许开发者和数据科学家在容器而非传统虚拟机中运行工作负载。

Terminal.com 最终被 Udacity 收购，此后 Perla 加入 Lyft，成为其最早的 50 名工程师之一，参与开发其自动驾驶汽车项目。最近，他在另一家音乐初创公司工作，他说该公司于 2025 年被收购。

Perla 重返 AI 基础设施领域，源于与 OpenAI 和 Anthropic 等主要 AI 实验室及云提供商的联系人的交谈。他说，这些讨论使他确信，企业正在向 AI 提供商暴露敏感商业信息，却没有充分理解他们的数据可能如何被保留或重用，即使他们已经谈妥了隐私保护。

Perla 开始研究机密计算——一种可以在远程硬件上处理信息时对其加以保护的技术——并发现了将这种能力与 AI 模型路由服务相结合的机会。

“几乎没有人知道你其实可以加密 AI 聊天，”Perla 告诉 VentureBeat。“我认为这是我最棒的一个发现。”

Perla 说，他大约在一年前开始开发 TrustedRouter，从一开始就将其设想为一个更大 AI 市场的基石。他没有运营自己的 GPU 基础设施，而是构建了一个路由服务，将客户与能够使用机密计算技术运行 AI 模型的外部提供商连接起来。

“基本上，我们建立的是一个交易所，聚集了所有这些拥有支持加密的 GPU 的提供商，比如 Private Mode，这样的提供商只有少数几家，”他解释道。“还有几家我们路由到的提供商，我们为其运行路由。我们想推广它们，我们想告诉世界：你可以做到这一点。”

据 Axios 报道，TrustedRouter 于 5 月开始公开测试，并于 8 月 31 日正式公开发布，同时完成了 125 万美元的种子融资。

早期投资者包括 Slow Ventures 的 Sam Lessin、Bill Tai、Linda Avey 和 George Xing。Perla 于 10 月 15 日宣布了该交易所。第二天，Semafor 报道称 TrustedRouter 完成了由 Sierra Ventures 领投的 600 万美元种子轮融资。

这一概念已演变成一项更宏大的事业：通过让私有托管、相互竞争的模型更容易被访问和在价格上进行比较，来挑战主要 AI 提供商的主导地位。

该公司表示，它在平常一天清算的加密 token 超过 30 亿个。其目录收录了来自 100 多家提供商的 600 多个模型。这些总数涵盖更广泛的目录，机密路由资格则单独评估。

TrustedRouter 的长期目标是将 AI 推理变成一个竞争性的大宗商品市场，同时让加密处理成为标准。正如 Perla 所说：“我们的目标是到明年，让大多数 GPU 都像这样加密。”

纽约代币交易所（NYTE）将如何运作

纽约代币交易所是一个拟议中的 AI 推理代币买卖和交易市场——AI 推理代币是人工智能模型处理和生成的文本及其他信息的计量单位。它旨在把对 AI 模型及运行这些模型的计算基础设施的访问变成一种商品，让企业可以从相互竞争的提供商处购买，而不必与每家 AI 公司单独谈判合同。

该交易所建立在 Perla 现有的服务 TrustedRouter 之上，后者通过单一界面将客户连接到数百个 AI 模型和基础设施提供商。

该公司发布按模型能力分类的价格指数，并提供以 10 亿 token 为一块、供 2027 年使用的固定价格预订。

这些预订只能通过 NYTE 自己的计划转售，并受其条款约束。在供应方面，NYTE 为希望使其硬件获得资质并销售推理的运营商提供了一个早期开源软件栈。

TrustedRouter 表示计划在 1 月推出期货计划。该公司的公开材料在其路线图中列出了期货和衍生品。

NYTE 打算通过两个互补的市场运作：

  1. AI 代币现货市场：企业可以从参与的提供商处购买即时使用的 AI 推理能力。客户无需与众多 AI 公司和云运营商逐一建立关系，而是通过交易所访问相互竞争的模型和基础设施。拥有可用 GPU 能力的提供商也可以在同一个市场中销售其服务。

  2. AI 代币期货和远期市场：企业可以提前商定，以预定价格购买指定数量的 AI 代币，在未来某个日期交付。这将使企业能够锁定可预测的 AI 运营成本，同时为基础设施提供商提供一种确保未来收入、并有可能为额外 GPU 和数据中心融资的途径。

例如，一家预计明年消耗 10 亿 AI 代币的公司，可以通过 NYTE 谈判一份合同，以今天商定的价格购买这部分容量。

基础设施提供商可以利用由此产生的收入或融资安排购买额外的 GPU，然后在需要这些代币时通过交付推理服务来履行合同。

如果客户后来发现自己需要的代币比预期的少，Perla 设想允许其通过交易所转售未使用的合同容量，而不是白白损失预付承诺的价值。

该市场还旨在容纳运营自己 GPU 集群的企业。一家在夜间或周末拥有闲置计算能力的大型企业，或许可以通过 NYTE 销售推理服务，同时成为买方和卖方。

Perla 希望通过分发开源软件来鼓励这种模式，让企业更容易建立自己的 AI 基础设施并参与市场。

更宏大的目标是将 AI 模型的开发与运行模型的基础设施分离开来，就像发电和输配电曾经演变成拥有多个竞争供应商的市场一样。

模型开发者可以专注于构建更好的 AI 系统，基础设施公司可以竞争以高效地服务这些模型，企业则可以按市场价格购买由此产生的计算服务，而无需绑定单一提供商。

Perla 相信，这将使 AI 推理更便宜、更可靠、更容易做预算，同时为当今领先 AI 公司青睐的垂直整合商业模式提供一种替代方案。

融合模型的发布为公司提供了一种在自己现有工作上检验 Perla 市场论断的途径。他们可以在同一组提示词上比较评审团、任务路由器和现有模型。真正重要的数字是：获得可用答案的成本、得出答案所需的时间，以及证明处理请求的每个提供商都符合公司规则的证据。
