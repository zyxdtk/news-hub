挑战循环
您可能会遇到挑战循环的情况，即挑战不断重复出现而无法解决。这通常发生在我们检测到强烈的机器人信号的特定情况下。如果您是真实人类，可以按照以下的故障排除指南来解决问题或提交反馈报告。挑战循环的发生可能有以下几个原因：
网络问题
：网络连接较差或不稳定可能导致挑战无法完成。
浏览器配置
：某些浏览器设置或扩展程序可能会阻止执行挑战所需的脚本。
不受支持的浏览器
：使用了 Turnstile 不支持的浏览器。
JavaScript 被禁用
：Turnstile 依赖 JavaScript 才能正常运行。
检测错误
：如果 Turnstile 怀疑有类似机器人的行为，您可能会遇到重复的验证挑战。
大多数挑战都能快速完成，通常只需几秒钟。如果耗时较长，请确保您的网络稳定并按照
故障排除步骤
操作。
Private Access Token 请求返回 401 响应
当挑战页面加载时，浏览器可能会从
/cdn-cgi/challenge-platform/.../pat/...
端点请求
Private Access Token (PAT)
。在无法颁发令牌的设备、浏览器或网络上，此请求将返回 HTTP
401
。
此响应是
预期内
的，并不意味着访客被阻止或组件失败。Cloudflare 会回退到标准挑战，访客可正常继续操作。此请求返回的
401
（例如，在浏览器开发者工具或 HAR 抓包中看到的）本身并不是配置错误、误报或被阻止的标志。有关更多详细信息，请参阅
Private Access Tokens
。
Turnstile 挑战期间子域网络请求失败
在查看浏览器开发者工具或为 Turnstile 捕获 HAR 时，有时会注意到由于 DNS 主机查找错误导致对特定子域的某些请求失败。这些子域位于
challenges.cloudflare.com
的父域下，这些请求是 Turnstile 正常执行的一部分。也就是说，不应将这些错误视为失败的根本原因，因为它们对访客是
非阻塞
的。
鉴于这些 DNS 主机查找失败对于 Turnstile 的执行是
预期内
且
非致命
的，请避免将它们作为致命的执行错误抛出，特别是在基于处理程序的 Turnstile 集成（例如 WebView 嵌入）中。如需更精细的控制，请考虑丢弃源自
*.challenges.cloudflare.com
通配符请求的网络错误，同时保留对
challenges.cloudflare.com
顶点域的错误可见性。
故障排除
请按照以下步骤操作，以确保您的环境已正确配置。
验证您的浏览器兼容性。
Turnstile 支持所有主流浏览器，但不包括 Internet Explorer。
确保您的浏览器已更新至最新版本。有关更多信息，请参阅我们的
支持的浏览器
。

禁用您的浏览器扩展程序。
某些浏览器扩展程序（如广告拦截器）可能会阻止 Turnstile 运行所需的脚本。
暂时禁用所有扩展程序并重新加载页面。
启用 JavaScript。
Turnstile 需要 JavaScript 才能运行。请确保在浏览器设置中已启用它。有关启用 JavaScript 的说明，请参阅您的浏览器文档。
尝试无痕或隐私模式。
使用浏览器的无痕或隐私模式，以排除由扩展程序或缓存数据引起的问题。
测试其他浏览器或设备。
切换到其他浏览器或设备，查看问题是否特定于您当前的设置。
避免使用 VPN 或代理。
某些虚拟专用网络 (VPN) 或代理可能会干扰 Turnstile。请暂时禁用它们进行测试。
切换到其他网络。
您当前的网络可能存在导致 Turnstile 挑战失败的限制。请尝试切换到其他网络，例如移动热点。
