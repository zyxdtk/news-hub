摘要
大语言模型（LLM）驱动的具身智能体基于环境状态表示进行规划和行动，使得面向规划器的状态接口成为感知、规划和执行之间的完整性边界。先前的工作展示了对抗性信息通过具体的传感器和中间件路径到达LLM控制的机器人的方式。我们研究了交付后的互补条件性问题：如果恰好一个面向规划器的状态生产者被攻破，规划器能否采用保持模式（schema-preserving）的虚假记录并将其实现为有针对性的最终状态后果？我们定义了一个组件范围、谓词局部且非自适应的对手，并提出了环境状态文本注入（ESTI），它将预先选择的对抗目标编码为现有且可交互的对象、关系、可供性、任务阶段约束或执行反馈上的虚假状态证据，同时保持用户指令、规划器和执行器不变。ESTI-Bench 在 ProgPrompt/VirtualHome、VoxPoser/RLBench 和 AI2-THOR/iTHOR 中针对 Vanilla IPI、EIRAD 和 BADROBOT 评估了这种下游状态到执行的传播。ESTI 分别将规划级和执行级的攻击成功率比最强基线提高了多达 89.32 和 43.69 个百分点。重要的是，所有消融设置都共享数据集级的可落地性。在这种匹配条件下，载体兼容性和表示级一致性强烈影响规划采纳，而移除运行时重新落地仅使 P-ASR 和 E-ASR 变化 1.92 和 3.85 个点。因此，我们的结果表征了在成功交付状态条件下的下游后果；它们既不估计获得写访问权限的概率，也不将规划偏差视为等同于物理攻击成功。
1 引言
大语言模型（LLM）在上下文学习、任务分解、逐步推理和代码生成方面展现出的能力，推动了它们从文本生成模型逐渐演变为能够感知环境、调用工具和执行任务的智能体核心。传统的 LLM 智能体通常通过网页、文档、数据库或外部工具获取信息，并根据用户目标生成相应的调用序列；当这项技术进一步与机器人系统集成时，大语言模型开始承担任务理解、高级规划和行为决策等功能。SayCan 将语言模型的任务推理能力与机器人技能的可供性相结合，而 Code as Policies 和 ProgPrompt 分别通过策略代码和程序化提示生成机器人任务计划，VoxPoser 则使用语言模型和视觉-语言模型构建三维价值地图以指导机器人操作 [1, 29, 49, 21]。视觉-语言-动作模型（如 PaLM-E、RT-2 和 GR00T N1）进一步加强了语言、视觉感知和机器人动作之间的联系 [15, 6, 5]。在这类 LLM 驱动的具身智能体中，模型不仅需要理解用户指令，还需要结合场景状态、物体属性、空间关系和执行反馈来完成任务落地，然后将生成的动作计划交给技能库、运动规划器或控制器执行。

如图 1 所示，将大语言模型纳入机器人任务规划流程提高了机器人的一般任务理解和自主决策能力，同时也显著扩大了系统的安全边界。传统语言模型的输出主要停留在文本空间，而具身智能体生成的规划结果进一步作用于机器人本身及其周围环境，使得模型对输入信息的错误解释沿着“状态感知–任务落地–动作规划–物理执行”的链条传递到现实世界。在规划过程中，具身智能体除了接收用户指令外，还需要不断读取环境状态，如场景描述、物体属性、空间关系、可供性信息、任务阶段规则和执行反馈。这些信息通常被模型视为可信的环境事实和规划证据。一旦这些信息中的状态语义被污染，攻击者即使不直接修改用户指令，也可能影响规划器对目标物体、操作位置、动作序列和故障恢复策略的判断，最终诱导机器人操作错误的物体、移动到错误的位置或执行非预期的行为。因此，LLM 驱动的机器人不仅继承了 LLM 智能体面临的提示注入风险，还进一步将攻击后果从错误响应、信息泄露或未经授权的工具调用扩展到物理环境的实际改变。
针对 LLM 智能体的现有攻击研究主要集中在间接提示注入、提示越狱和工具调用劫持。这类攻击通常将恶意命令嵌入网页、文档、电子邮件或工具输出中，并利用模型无法可靠区分外部数据与可执行指令的弱点 [18, 61, 62, 12]。针对具身系统的研究（包括 EIRAD、BADROBOT、RoboPAIR 和 CHAI）进一步表明，对抗性后缀、越狱查询和欺骗性视觉文本可以影响机器人决策 [30, 63, 9, 41]。最近，RIPA 提供了这种威胁的具体上游实现。它表明通过传感器或中间件通道引入的对抗性信息可以转化为环境状态表示，交付给 LLM 控制的机器人流程，随后影响机器人的决策和动作 [14]。
这些研究确立了对抗性信息可以通过承载指令、传感器或中间件通道进入具身智能体流程并最终影响机器人行为。ESTI 解决了一个互补的下游问题：一旦损坏的任务级状态跨越了上游状态构建过程并对规划器可见，是什么属性允许它被作为规划证据采纳并在具身执行中存活？与数字智能体不同，具身计划必须满足实体存在、空间可达性、可供性、动作前提条件和平台接口。因此，我们仅在可用实体和交互可实例化的对抗目标上评估模式兼容的虚假证据。这种数据集级的可落地性是每种比较方法和消融共享的准入条件，而不是由基准建立其因果效应的机制。
评估针对 LLM 驱动的具身智能体的状态语义攻击提出了几个相互关联的挑战。首先，虚假内容必须符合被攻破的规划器可见字段的语义角色和表示格式，而不是表现为显式的竞争命令。其次，基准必须排除由不存在的实体或不支持的交互导致的平凡失败。第三，证据在被攻破组件允许发出的记录之间必须保持足够一致，以影响目标绑定、目的地绑定、动作排序或故障重规划。最后，评估必须区分规划器是否采纳了对抗性谓词与该谓词在执行后是否变为真。我们分别命名本文中使用的两种落地操作：数据集级的可落地性过滤基准实例的准入条件，而运行时重新落地在构建有效载荷时解析和刷新实体绑定。第 4.8 节的消融仅移除了后者。
为了应对这些挑战，我们提出了 ESTI（环境状态文本注入），一种针对 LLM 驱动具身智能体的下游状态语义完整性评估。ESTI 不将环境状态损坏本身视为新的攻击原语，也不声称建立如何获得写访问权限。相反，它假设一个状态生产者被攻破，并研究如何通过该组件的原生记录编码预先选择的对抗目标。ESTI 执行组件范围、谓词局部的重写，同时保持用户指令、模型参数、规划器代码和执行器不变。ESTI 不插入显式的竞争命令，而是更改现有且可交互的对象、关系、可供性、任务阶段规则或面向规划器的反馈上的原生语义值。我们构建了 ESTI-Bench，并在 ProgPrompt/VirtualHome、VoxPoser/RLBench 和 AI2-THOR/iTHOR 中评估状态语义操纵，分别测量规划采纳和执行实现。总体而言，本文的主要贡献如下：
1. 我们在 LLM 驱动的具身智能体中隔离了规划器可见语义状态边界处的下游完整性问题。我们不将环境状态损坏视为新的攻击原语，而是研究损坏的任务级状态证据一旦暴露给规划器，能否穿越落地、动作前提条件和执行约束，产生有针对性的最终状态后果。
2. 我们形式化了 ESTI 的组件范围、谓词局部、模式保留的威胁模型。对抗目标在回合前固定，攻击者只能重写一个被攻破的状态生产者被授权发出的任务相关记录；它不能写入任意的高权限上下文或适应规划器输出。
3. 我们在具有匹配可落地性的基准实例上提出了表示兼容的状态语义构造。ESTI 将数据集级的准入与可选的运行时重新落地分开，并通过对象、空间关系、可供性、任务阶段规则和执行反馈编码虚假证据，同时保留原始用户指令、规划器和执行器。
4. 我们构建了 ESTI-Bench，一个规划-执行闭环评估框架。ESTI-Bench 区分了对抗目标的规划级采纳与可验证最终状态谓词的执行级实现，能够显式测量规划到执行的转移差距。
5. 我们系统地评估了异构具身系统中的条件状态到执行传播。消融表明，在匹配的可落地性下，载体兼容性和表示级一致性驱动规划采纳；真实机器人的概念验证测试了下游传播，而不是端到端的传感器攻破。
2 相关工作
2.1 LLM 驱动的具身规划
LLM 的上下文学习、思维链推理、零样本推理和代码生成能力为具身智能体的高级规划提供了基础 [8, 56, 11, 24]。SayCan 将语言模型规划与机器人动作可供性相结合，使生成的计划更接近可执行的动作空间 [1]。Code as Policies 将 LLM 输出转换为可执行程序；ProgPrompt 通过程序化提示显式建模场景对象和可用动作；VoxPoser 使用三维价值地图表达空间约束和操作目标 [29, 49, 21]。Zero-Shot Planners、Inner Monologue、Voyager 和 SayPlan 分别通过零样本任务分解、环境反馈推理、开放世界探索和三维场景图规划进一步扩展了基于 LLM 的具身规划 [20, 22, 53, 39]。总的来说，这些研究表明高级规划不仅由用户语言决定，还持续依赖状态证据（包括对象、关系、可供性和反馈）来落地任务。然而，它们的评估主要强调任务成功率、可执行性和泛化能力，而对状态语义来源的可信度、状态字段之间的一致性以及由此产生的对决策影响的关注有限。
视觉-语言-动作模型进一步加强了基础模型与机器人行为之间的联系。PaLM-E、RT-2 和 GR00T N1 在日益统一的模型架构中集成了视觉观察、语言指令和动作输出 [15, 6, 5]。Gato、Visual Language Maps、VIMA、PerAct、Flamingo 和 CLIPort 分别通过通用序列建模、视觉语言地图、多模态提示、六自由度操作、视觉语言表示学习和语言条件操作扩展了具身智能体的能力 [40, 19, 23, 46, 2, 45]。在评估方面，AI2-THOR 为导航、物体操作和家庭任务研究提供了可复现的室内场景、对象级交互接口和结构化状态信息 [25]。ALFRED、ALFWorld、Habitat、VirtualHome、BEHAVIOR 和 TEACh 为指令遵循、基于文本的交互、导航、活动模拟和人机协作提供了互补的测试平台 [47, 48, 42, 37, 50, 33]。这些平台通常将感知观察或模拟器状态转换为智能体可消费的表示，但很少将对这些状态表示的误信视为独立的安全变量。
2.2 针对 LLM 智能体的间接提示注入
LLM 智能体将语言模型从文本生成扩展到工具使用、网页浏览、文件处理和多轮交互。ReAct 交错推理和动作，而 Toolformer 使模型能够学习何时以及如何调用外部工具。ToolLLM、API-Bank、Gorilla 和 ToolBench 进一步拓宽了 LLM 选择和调用真实世界 API 的能力 [60, 43, 38, 28, 34]。Reflexion、WebGPT、WebShop、Mind2Web、OSWorld、SWE-agent 和 OpenDevin 分别通过自我反思、浏览器辅助问答、在线购物、真实网页任务、桌面环境交互、软件工程任务和通用计算机操作推进了智能体系统 [44, 32, 59, 13, 57, 58, 54]。随着模型从问答系统演变为行动系统，外部内容进入其决策上下文的频率越来越高。然而，对于数字智能体，此类内容通常来自网页、文档或工具结果，而不是必须与物理实体、空间关系和动作约束保持一致的环境状态。
间接提示注入利用了 LLM 无法可靠区分数据与可执行指令的弱点。Greshake 等人表明，嵌入在网页或文档中的恶意提示在由 LLM 集成应用程序处理时可以劫持任务 [18]。BIPIA 通过基准构建和防御评估研究间接提示注入 [61]，而后续工作进一步将嵌入在外部内容中的可执行命令确定为这类攻击的定义机制。InjecAgent 和 AgentDojo 将问题扩展到涉及电子邮件、网站、银行和旅行预订的工具集成智能体的系统评估 [62, 12]。关于提示注入、越狱、对齐失败、自动化红队和提示泄露的研究也表明，上下文操纵会导致模型无视原始指令或执行非预期行为 [31, 36, 64, 55, 35, 10]。这些研究确立了不可信上下文的风险，但其典型的有效载荷是命令式提示，其成功标准侧重于模型响应、资源访问或工具调用。
我们将这种原始的基于命令的构造实例化为 Vanilla IPI 基线，并在相同的任务、对抗目标和状态输入位置下将其与 ESTI 进行比较。在具身系统中，即使这种有效载荷引起了规划偏差，它也可能不符合状态表示，无法确定偏差是否会跨越任务解析和执行约束。因此，传统的 IPI 是一个重要的基线，但它不能直接表征具身状态完整性风险。
2.3 具身模型的攻击与安全评估
机器人安全研究长期以来一直研究可达性分析、控制障碍函数和安全的人机交互 [3, 4, 27]。在感知层，对抗样本、物理世界攻击、对抗补丁和传感器欺骗表明，视觉系统可以被精心制作的扰动或环境模式误导 [51, 17, 26, 16, 7, 52]。这些研究确立了对外部输入的扰动可以影响机器人行为，但大多数关注视觉模型、传感器输入或低级控制组件。它们的核心关注点通常是观察误差或控制安全，而不是虚假状态语义如何被高级语言规划器采纳为任务证据。
随着 LLM 被纳入具身智能系统，攻击目标已从感知和控制扩展到任务理解和决策。EIRAD 评估了针对基于 LLM 的具身模型的决策级对抗扰动 [30]。BADROBOT、Jailbreaking LLM-Controlled Robots、RoboPAIR 和 CHAI 进一步表明，对抗性提示、越狱查询和视觉交付的指令可以诱导不安全或攻击者期望的机器人行为 [63, 9, 41]。
最近，RIPA 研究了基于 ROS 2 的 LLM 控制机器人中的传感器向量提示注入 [14]。其视觉、音频和激光雷达通道展示了对抗性信息如何跨越传感器或中间件接口，进入 LLM 上下文并影响机器人动作。ESTI 从这个上游边界之后开始：它假设一个状态生产组件已经交付了损坏的任务级记录，并测量表示兼容的证据是否被规划器采纳并由未更改的执行器实现。因此，RIPA 和 ESTI 表征了互补的上游交付和下游传播问题。ESTI 不重现 RIPA 通道，其 ASR 绝不能被解释为端到端的攻破概率。
3 ESTI：环境状态文本注入攻击
本节介绍 ESTI，一种环境状态文本注入攻击，评估损坏的环境状态语义是否可以通过具身规划-执行循环传播。我们首先定义威胁模型，包括系统边界、对抗能力、攻击目标和成功条件。然后我们介绍核心构造和传播机制。
3.1 威胁模型
3.1.1 系统模型
我们考虑由高级语言规划器 $\pi$、执行器和环境 $\mathcal{E}$ 组成的具身智能体。在步骤 $t$，规划器接收良性用户指令 $U$ 和规划器可见的状态表示 $S_{t}=\langle O_{t},R_{t},Q_{t},F_{t}\rangle,$ (1)，其中 $O_{t}$ 包含对象及其属性，$R_{t}$ 包含空间或任务关系，$Q_{t}$ 包含可供性和任务阶段约束，$F_{t}$ 包含执行反馈。规划器生成动作计划 $A_{t}=\pi(U,S_{t})$，由原始执行器翻译为环境动作。执行更新物理或模拟状态 $x_{t}$ 并产生下一个规划器可见的状态 $S_{t+1}$。

3.1.2 对抗入口点、能力和范围
我们考虑一个具身智能体流程，其中规划器可见的状态由多个状态生产组件组装而成，例如语义地图适配器、任务内存或状态缓存提供者、任务阶段管理器和执行反馈适配器。这些组件暴露结构化记录，随后被序列化并提供给高级语言规划器。
我们假设一个灰盒对手，它恰好攻破了一个这样的组件 $c$ 或其输出通道，例如通过共同部署的插件或中间件/状态缓存漏洞。建立或测量该攻破超出了我们的下游评估范围。对手只能更改 $c$ 被授权发出的记录；它不能修改用户指令、隐藏的系统提示、模型参数、规划器代码、执行器、技能库、低级控制器、模拟器动态、物理状态或另一个组件拥有的记录。
对手知道文档化的模式并观察 $c$ 发出的干净记录，包括暴露的实体标识符、关系、可供性和任务阶段，但无法访问未暴露的地面真值或中间规划器输出。它不能发明不存在的标识符、更改原始传感器或模拟器数据，或直接更改执行器结果。对抗目标 $G_a$ 在回合前固定。ESTI-Bench 中特定于样本的目标实例化此目标以进行构造和评分；它不是运行时预言机。对手可以使用 $c$ 的攻击前输出，但不能更改 $G_a$ 或使有效载荷适应规划器输出。
设 $W_{c}(S_{t})$ 表示组件 $c$ 被授权生产的状态记录集，设 $\operatorname{Rel}(G_{a},S_{t})$ 表示直接涉及 $G_a$ 所需的实体、关系、动作或阶段的记录。ESTI 将可写集限制为 $\mathcal{I}{\theta}\subseteq W{c}(S_{t})\cap\operatorname{Rel}(G_{a},S_{t}),$ (2)，$\mathcal{I}{\theta}$ 之外的所有记录保持不变。预算是结构性的：重写保留原生模式、字段名、记录数、序列化器和周围上下文，并且只能替换现有的语义值。它不能添加记录或提示部分、引入不支持的实体或表达显式的竞争指令。如果 $c$ 拥有的多个记录被重写以保持一致性，则所有记录必须支持相同的谓词。原生接口固定了它们的数量、类型和生命周期；我们不声称在数字字段或令牌预算下具有鲁棒性。初始状态攻击影响一个快照，而阶段或反馈依赖的攻击针对一个原生事件预装并仅在该记录的生命周期内持续。
因此，此威胁模型代表的是单个面向规划器的状态生产者被攻破，而不是对机器人流程的不受限制的控制。由于受影响的记录可能与任务相关，其语义效果可能类似于更改任务参数。我们不主张规划器对任意高权限重写的响应是令人惊讶的。安全区别在于来源和范围：$U$ 保持不变，虚假值通过一个生产者的原生状态模式到达，并且其他所有组件保持可信。ESTI 评估该攻破的条件性下游后果：一旦交付了准入的虚假记录，它是否在任务落地期间被采纳，并通过未更改的规划器和执行器传播到可验证的最终状态后果？
3.1.3 攻击目标与成功边界
对手寻求使规划器由于虚假状态证据而采纳 $G_a$，并在平台约束允许时，使相应的谓词在最终环境状态中变为真。预期的偏差包括选择攻击者指定的对象、使用对抗性目的地、插入可行的额外步骤或在重规划期间采纳攻击者指定的回退。攻击不寻求任意的任务退化：随机失败或与 $G_a$ 无关的更改不被视为成功。
具身攻击必须跨越两个连续的边界。首先，操纵的状态必须导致规划器生成实现特定样本对抗目标的计划。其次，偏差计划必须在执行期间通过实体存在、可达性、可供性、动作前提条件和接口有效性检查。有效载荷交付、注入文本的重复或未执行的计划片段不计为有针对性的成功。
3.2 方法概述
ESTI 将对抗目标转换为模式兼容的虚假状态证据，而不是将其表达为竞争的用户命令。如图 2 所示，该方法包含三个逻辑阶段。这些阶段共同将固定的对抗目标转换为与目标环境的表示结构保持兼容的规划器可见证据。
首先，目标规范化和运行时重新落地将 $G_a$ 映射到可验证的谓词，并解析当前状态中预验证的实体和交互。此步骤确保使用当前基准实例中实际存在的实体来实例化目标偏差。其次，状态语义构造通过兼容的对象属性、场景关系、可供性、任务阶段规则或面向规划器的反馈来表达固定目标。生成的证据不是插入自由格式的对抗指令，而是根据相应状态载体的语义角色来制定的。第三，闭环注入仅将所需的证据写入等式 2 允许的记录中，对于依赖于事件的样本，保留相同的目标和绑定。
该构造保留了预先选择的对抗目标，在已知可落地的基准实例中解析引用的实体，将每个有效载荷与其载体的语义角色匹配，并保持不相关记录不变。与命令式 IPI 不同，ESTI 不将对抗目标表达为竞争指令。两者都使用相同的可落地 $G_a$，但 Vanilla IPI 缺乏原生载体构造、运行时重新落地和跨记录验证。因此，该比较隔离了将相同的对抗目标表示为落地的状态证据（而不是作为附加命令）是否会改变操纵通过规划和执行传播的方式。
3.3 匹配可落地性下的状态语义构造
3.3.1 数据集级可落地性和运行时重新落地
我们区分了被“落地”一词混淆的两种操作。数据集级可落地性是一项资格规则：在评估之前，只有当样本的对抗谓词可以用现有实体、支持的可供性和可观察的后置条件实例化时，才保留该样本。这种过滤在模型推理之前固定，由每个基线和消融共享，并且不是对手可用的运行时预言机。运行时重新落地是完整 ESTI 使用的可选构造步骤：在授权重写之前，它将预验证的实体解析为当前标识符，并刷新可供性和关键前提条件检查。无运行时重新落地消融跳过此刷新并重用数据集验证的绑定；它不删除数据集级的可落地性。
ESTI 将 $G_a$ 规范化为对支持的动作、受影响的对象、可选的目的地或参考对象以及预期的最终属性或关系的谓词。它仅保留满足语义匹配、平台可供性和关键前提条件的实体，并确定性地解析多个候选者，而不更改场景或使规划器采纳的可能性增加。由于不可落地的样本已被移除，这种运行时刷新预计在我们的大部分静态任务中具有有限的增量效应。
3.3.2 证据构造与约束重写
ESTI 不将 $G_a$ 重述为指令，而是将虚假证据 $e_a$ 构造为现有状态记录的值，同时保留其字段名、记录数、语法和上下文。
设 $\mathcal{I}{\theta}\subseteq L_{a}$ 表示选定的载体字段，$p_{\theta,j}$ 表示分配给字段 $j$ 的证据。ESTI 应用字段级转换 $[T_{\theta}(S_{t})]{j}=\begin{cases}\operatorname{Rewrite}{j}(S_{t,j},p_{\theta,j}),&j\in\mathcal{I}{\theta},\ S{t,j},&j\notin\mathcal{I}{\theta}.\end{cases}$ (3)
重写保留周围的表示，并仅更改 $G_a$ 所需的语义单元。仅当候选有效载荷 指预验证的实体和交互， 匹配其载体的语义功能和语法， 直接支持 $G_a$，以及 在操纵的状态中不引入显式的标识符、关系或任务阶段冲突时，才保留该候选。这里的一致性是表示上的而非事实上的：证据仍然是对抗性的，因为它与用户的预期任务相冲突。
ESTI 支持对象属性、场景关系、可供性、任务阶段和执行反馈载体。选定的载体取决于目标谓词：对象替换主要使用属性或实体关系；目的地操纵使用空间关系或目的地可供性；排序操纵使用任务阶段规则；恢复操纵使用执行反馈。
3.4 闭环传播与攻击成功
初始状态证据在规划前注入 $S_0$；恢复或阶段依赖的证据使用相同的固定 $\theta$ 并仅在其预定义的原生事件中激活。ESTI 既不从模型输出中得出新目标，也不更改执行器的实际结果，因此证据必须通过原始的落地、规划、执行、反馈和重规划循环传播。数据集级可落地性和运行时重新落地不会绕过可达性、对象状态、排序或接口约束。设 $D{\theta}$ 表示通过被攻破的组件成功交付 $T_{\theta}(S_{t})$。ESTI 的条件构造目标是 $\displaystyle\max_{\theta} \displaystyle\Pr!\left[g_{a}^{P}(A^{a})=1\land g_{a}^{E}(x_{T}^{a})=1\mid D_{\theta}\right]$ (4) s.t. $\displaystyle U,\pi,\mathcal{E},x_{0}\ \text{unchanged},$ 其中 $g_{a}^{P}$ 检测有针对性的规划偏差，$g_{a}^{E}$ 测试最终状态谓词。此构造目标是确定性实例化的，而不是用梯度优化的，并且排除了攻破 $c$ 或实现 $D_{\theta}$ 的概率。
规划级和执行级的成功分别测量：$\operatorname{Succ}{P}=\mathbb{I}[g{a}^{P}(A^{a})=1],\qquad\operatorname{Succ}{E}=\mathbb{I}[g{a}^{E}(x_{T}^{a})=1].$ (5)
如果 $\operatorname{Succ}{P}=1$ 但 $\operatorname{Succ}{E}=0$，则攻击影响了规划器，但被具身执行层阻止。如果两者都等于 1，则对抗目标已从规划器可见的状态文本传播到最终环境状态。第 4 节报告了相应的规划攻击成功率（P-ASR）和执行攻击成功率（E-ASR）。两者都是在成功交付状态后评估的条件性下游指标，而不是系统攻破的端到端概率；它们的差异量化了计划-执行差距。

表 1 显示，在状态交付的条件下，ESTI 在 ProgPrompt、VoxPoser 和 AI2-THOR 中实现了最强的 P-ASR 和 E-ASR。其 P-ASR 分别达到 100.00%、97.37% 和 100.00%，而相应的 E-ASR 值为 47.06%、42.11% 和 48.08%。在三个环境中平均，ESTI 实现了 99.12% 的 P-ASR 和 45.75% 的 E-ASR。相比之下，提供了最强整体基线性能的 Vanilla IPI 实现了 80.49% 和 34.62% 的平均 P-ASR 和 E-ASR 值。因此，ESTI 分别将这两个指标提高了 18.63 和 11.13 个百分点。这些比较涉及共享规划器可见入口点后的构造，并不意味着 ESTI 更容易通过上游漏洞交付。
基线方法表现出较弱或较不稳定的性能，因为它们的攻击机制没有专门与具身智能体依赖状态的规划过程对齐。EIRAD 主要通过对用户侧提示的对抗性扰动起作用，而 BADROBOT 变体侧重于上下文越狱、安全错位或概念欺骗。这些策略可以影响语言模型行为，但它们没有显式建模当前环境的对象、关系和动作约束。这种限制在 AI2-THOR 中变得尤为明显，其中 EIRAD 仅实现了 17.31% 的 P-ASR 和 12.50% 的 E-ASR，而 BADROBOT-上下文越狱仅达到 8.65% 和 6.73%。这些方法在不同环境中的巨大性能差异表明，当规划器必须对结构化的环境状态和可执行动作进行推理时，通用的提示级或越狱式攻击不能一致地转移。
Vanilla IPI 的表现优于大多数其他基线，因为直接的竞争指令可以强烈影响规划器，因此产生相对较高的规划级攻击成功率。例如，它在 ProgPrompt、VoxPoser 和 AI2-THOR 上的 P-ASR 分别达到 66.18%、86.84% 和 88.46%。然而，其相应的 E-ASR 值下降到 32.15%、34.21% 和 37.50%。这种差距表明，更改规划器的输出不一定会产生有效的具身攻击。尽管其目标目标来自相同的可落地基准实例，但 Vanilla IPI 不通过原生状态载体编码它们，也不在运行时刷新和交叉检查相关记录；因此，生成的计划可能会遗漏所需动作、违反排序或未能满足平台约束。这一观察支持了提示级采纳和具身执行成功之间的区别，而不将差距归因于不匹配的场景可行性。
相比之下，ESTI 通过预验证实体上的原生对象属性、空间关系、任务规则和面向规划器的反馈来表达攻击目标。因此，该表示与规划器的正常输入格式更加一致。尽管如此，P-ASR 和 E-ASR 之间仍然存在明显差距，例如在 ProgPrompt 上为 100.00% 对 47.06%，在 AI2-THOR 上为 100.00% 对 48.08%。因此，成功的规划采纳不足以实现具身攻击成功：动作前提条件、可达性、计划质量和平台约束仍然决定了是否实现了目标谓词。

4.3 ASD 的独立图形分析
干净-攻击 ASD 测量攻击前后动作序列的整体差异，表征攻击扰动具身智能体执行行为的程度。与仅确定是否成功实现攻击目标的 ASR 不同，ASD 进一步反映了原始行为轨迹是否被更改以及更改程度。因此，即使攻击最终未能满足 E-ASR 标准，ASD 也能捕捉到行为效果。例如，攻击可能在执行期间更改了目标对象、动作顺序或移动路径，但在后续步骤中失败，因此不计为成功的执行级攻击。在这种情况下，ASD 仍然捕捉到攻击引入的行为偏差。因此，ASD 通过揭示攻击是否成功以及它多大程度上改变了智能体的正常执行行为来补充 P-ASR 和 E-ASR。
然而，ASD 的大小并不直接对应于攻击成功率。较大的动作序列差异仅表示较强的行为偏差，但不一定意味着该偏差与攻击者的目标一致。例如，在使用 DeepSeek-V4-Pro 的 ProgPrompt 上，Vanilla IPI 实现了 4.59 的 ASD，高于 ESTI 的 3.01，而其 E-ASR 仅为 32.15%，低于 ESTI 的 47.06%。同样，在 VoxPoser 上，EIRAD 达到了 14.30 的 ASD，高于 ESTI 的 9.95，但仍然实现了较低的 E-ASR。这是因为某些攻击可能会引入不相关、冗余或不可行的动作，这些动作增加了序列分歧，而没有有效地驱动智能体达到攻击者期望的最终状态。相比之下，ESTI 倾向于通过操纵规划证据（如对象属性、空间关系、任务规则和执行反馈）来诱导关键动作的有针对性更改。因此，ASD 更适合用作衡量行为扰动程度的补充指标，而 P-ASR 和 E-ASR 评估是否实际实现了攻击目标。这些指标共同区分了攻击影响的三个层次：规划操纵、行为偏差和攻击目标的成功执行。

4.4 规划到执行的攻击转移
表 2 进一步分析了 ESTI 从规划级欺骗到执行级后果的转移。P-ASR 主要反映注入的状态语义是否能成功欺骗 LLM 规划器并诱导出与攻击者一致的计划。ESTI 在大多数模型-环境组合中实现了持续高水平的 P-ASR；例如，DeepSeek-V4-Pro 达到了 99.12% 的平均 P-ASR，而 Qwen-3.6-Plus 达到了 97.04%。这些结果表明，操纵的规划器可见状态可以有效影响 LLM 规划器使用的决策证据。
然而，成功的规划器欺骗并不一定会转化为成功的执行。E-ASR 还受到生成计划质量和模拟环境约束的影响，包括缺失或不可行的动作、对象可用性、空间可达性、动作原语和交互前提条件。例如，DeepSeek-V4-Pro 实现了 99.12% 的平均 P-ASR，但 E-ASR 仅为 45.75%，导致 53.37 个百分点的差距，而 GPT-5.6-luna 尽管具有较低的 P-ASR，却显示出更高的转移率。因此，P-ASR-E-ASR 差距表征了从规划器欺骗到执行实现的转移损失，而不是简单地表示攻击失败。

4.7 规划模型的影响
三个模型的结果表明，ESTI 在规划级别的有效性受底层 LLM 的影响。ESTI 在 DeepSeek-V4-Pro 上实现了 99.12% 的平均 P-ASR，在 Qwen-3.6-Plus 上实现了 97.04%，表明这两个模型都极易受到操纵的规划器可见状态语义的影响。相比之下，GPT-5.6-luna 实现了较低的平均 P-ASR（79.06%），这主要是由于其在 AI2-THOR 上的 P-ASR 为 47.62%，尽管它在 ProgPrompt 上仍达到 98.18%，在 VoxPoser 上达到 91.38%。这种差异表明，不同的 LLM 根据环境信息被解释和纳入规划的方式，对状态语义操纵表现出不同的敏感性。尽管如此，ESTI 在所有三个模型和环境中在 P-ASR 上始终优于基线攻击，表明该攻击并不依赖于特定的 LLM。
有趣的是，模型之间的差异在执行级别变得更小。DeepSeek-V4-Pro、GPT-5.6-luna 和 Qwen-3.6-Plus 的 ESTI 平均 E-ASR 值分别为 45.75%、46.44% 和 47.77%。特别是，GPT-5.6-luna 尽管总体 P-ASR 较低，但在 ProgPrompt 上达到了 63.64% 的 E-ASR，而 Qwen-3.6-Plus 在 AI2-THOR 和 VoxPoser 上分别达到了 50.49% 和 48.39% 的 E-ASR。这些结果表明，在规划级别更容易被欺骗的模型不一定会成比例地获得更高的执行级别攻击成功率。E-ASR 还取决于生成的恶意计划的质量和可执行性以及特定于环境的约束，这表明模型易感性和规划到执行的实现是影响 ESTI 最终有效性的两个不同因素。

表 5 确定表示级采纳（而非可落地性）是本实验支持的主要效应。移除载体兼容性使 P-ASR 降低 87.50 个百分点（从 100.00% 降至 12.50%），移除表示级一致性使其降低 62.50 个百分点（降至 37.50%）。在这些设置中，E-ASR 也会下降，因为首先达到攻击者一致计划的样本要少得多。这些边际比率不能证明这两个组件都能改善条件转换 $\Pr(\operatorname{Succ}{E}\mid\operatorname{Succ}{P})$。
移除运行时重新落地仅使 P-ASR 变化 1.92 个百分点，使 E-ASR 变化 3.85 个百分点。这种小效应是预期的，因为在构建基准时已经检查了对象存在、候选目的地、可供性和关键前提条件。因此，该表不能支持运行时落地是攻击传播主要原因的主张；它仅显示了在样本已经可落地的数据集之上的适度增量收益。
消融也没有评估上游 RIPA 式的交付通道。RIPA 提供了传感器或中间件攻破可以交付对抗性信息的证据，而 ESTI 测量的是交付后的下游采纳和执行。在一个端到端实验中结合这两个边界仍然是未来的工作。
5 结论
我们提出 ESTI 来研究被攻破的面向规划器的状态生产者的条件性下游后果。在组件范围、谓词局部和模式保留的重写下，表示兼容的虚假记录可以更改高级计划，有时会产生可验证的最终状态后果，同时用户指令、规划器和执行器保持不变。在 ProgPrompt/VirtualHome、VoxPoser/RLBench 和 AI2-THOR/iTHOR 中，规划到执行的差距表明，仅靠规划器采纳不足以表征具身攻击成功。我们的消融进一步支持了比一般落地主张更窄的结论：在数据集级可落地性保持固定的情况下，载体兼容性和表示级一致性强烈影响规划采纳，而运行时重新落地仅提供较小的增量收益。真实机器人研究是下游概念验证，而不是端到端的感知或中间件攻破。
未来的工作将通过跨平台数据集、多模态状态注入、更强的防御和从模拟到真实的评估来扩展 ESTI-Bench。一个方向是集成机载感知和构造的多模态状态，实现从感官输入到物理后果的闭环评估。另一个方向是研究状态来源跟踪、跨模态一致性检查以及任务和真实机器人平台上的执行时验证。我们计划研究长时域和动态任务中的自适应状态损坏，其中反馈可能会随着时间的推移产生复合效应。
