VentureBeat 使用 OpenAI ChatGPT-Images-2.6 制作

OpenAI 于周二发布了其新款 AI 模型 GPT-6.2 Astra 和 GPT-6.2 Sol，两者均取得新的基准测试高分，且前者的应用程序编程接口（API）价格下调了 20%——那么，为什么这两款新模型却招致多位在发布前参与测试的 AI 高级用户的尖锐批评？

投资人、HyperWrite AI 前首席执行官 Matt Shumer 表示，他不会像以往为 OpenAI 前几代旗舰模型所做的那样发布一篇较长的书面评测。Shumer 在 X 平台的帖子中写道，这些新模型“基本无法使用”。开发者兼 YouTuber Theo Browne 也在 X 上发帖称，6.2 Astra 是“OpenAI 有史以来发布的最差模型”。两人特别指出了该模型在委派任务和创意任务方面的短板。

沃顿商学院教授 Ethan Mollick 对 Astra 的体验则褒贬不一。该模型在 Blender 和 Unity 中构建出了一个可玩的太空电梯，但他发现这个模型“非常不稳定且怪异”，比竞争对手的模型更难驾驭。

Astra 目前的定价为每百万未缓存输入 token 8 美元、每百万输出 token 40 美元，而 GPT-6.2 Sol 则保持其前身 6.1 Sol 每百万输入 2 美元、输出 10 美元的费率。

两款模型均为专有托管模型。它们现已面向 Plus、Pro、Enterprise 和 Edu 用户登陆 ChatGPT Work 和 Codex，并可通过 OpenAI API 以 gpt-6.2-astra 和 gpt-6.2-sol 的名称调用。

OpenAI 将 Astra 定位于诸如修改复杂代码库、构建可运行的 Web 应用程序、或生成遵循公司模板的文档等任务。Sol 则是面向常规编码、写作以及需要多个步骤的工作流的更低价选择。

此次发布距竞争对手 Anthropic（正值上市前夕）推出广受好评的 Claude Fable 5.2 和 Mythos 5.2 仅过去八天——后者的标准输入和输出 token 价格同样为每百万 8 美元和 40 美元；一周前，Google 也以与 Sol 相同的入门价格开放了其广受好评的 Gemini 4 Carbon。

换句话说，竞争正在加剧，而这可能是 OpenAI 最不该失手的时候，尤其是在其新旗舰和中端模型的口碑上。

早期测试者对写作、编码和设计的评价

生成式 AI 媒体 Every 的首席执行官 Dan Shipper 表示，他的团队花了数周时间测试这两款模型。他说，Astra 在 Every 的大多数编码基准测试中表现与其前身大致相当，但在端到端构建中经常过早停止。他发现，该模型对简洁的追求可能让文字难以理解，或遗漏必要的解释。

他称赞了该模型默认的设计直觉，但表示其输出难以做出变化，并带有一种“明显的固有风格”。对于需要让一个模型服务于多个品牌、或针对不同读者调整解释深度的团队来说，这一区别很重要。

Browne 在 X 上的一篇后续帖子中描述了他和另一位测试者如何各自独立地让 Astra 为不同的游戏——《星际拓荒》和《姆吉拉的假面》——设计新关卡。两次都得到了以音乐和钟声为核心的水主题关卡，且名称相同，都叫“Bellwether”。这两次运行表明，即使项目不同，Astra 的选择也可能高度雷同。

Browne 在一篇题为《为什么我讨厌 GPT-6.2 Astra》的长篇 X 帖子中列出了更多反对意见，并称这是他在早期测试期间发给 OpenAI 的一封信的全文。

在 Browne 用 Rust 重写实验性 TypeScript 编译器的项目中，他说 Astra 花了七天时间没有取得任何改进，并在专注于减小体积后产出了一个运行速度慢 56% 的版本。当他重新引导它提升速度时，他说它又花了四天时间没有落实任何更改。

不过，Browne 确实肯定了 Astra 在代码审查中发现其他模型所遗漏问题的能力，并称赞了其 3D、游戏开发和计算机操作能力。他说，Astra 帮他设计了一个反向代理，预计每月可为他节省 25,000 美元。他的批评集中在：很难让 Astra 在长期项目中持续推进，也很难在事后弄清它究竟做了什么。

据 Browne 透露，OpenAI 在发布前解决了他的部分抱怨，但在开发工作上，他仍然更偏好 Claude Opus 5.5。

就 Shumer 而言，他说他曾让 Astra 作为子智能体去执行工作，而监督它的 Claude 模型把这些工作重做了一遍。

一位以 Jacob 之名发帖的 X 用户呼应了 Shumer 的不满，并推测这源于 OpenAI 训练模型行为方式的问题。

据 Mollick 所说，他的太空电梯演示模拟了失重效果，但他表示自己仍然会转而使用其他模型。

在其关于该演示的帖子的 LinkedIn 评论中，他称这是自 GPT-4.5 以来他第一次不认为 OpenAI 的前沿模型发布是明确的进步，不过他也表示仍可想象 6.2 在某些特定类型的复杂工作中表现出色。发布当天的帖子反映的是特定任务和特定测试者的情况。

其他 AI 高级用户，如 Raindrop.ai 首席技术官 Ben Hylak 和 AI 顾问 Ashe Magalhaes，则对 GPT-6.2 Astra 表达了更为积极的看法，称赞其在动画视觉、动态图形、VFX 以及智能体式 AI 视频编辑方面的优势。

与此同时，OpenAI 表示，其许多员工已经将 Sol 作为技术及其他工作的默认模型。

GPT-6 和 GPT-6.2 Sol 在每个标准/快速以及短/长上下文层级上的价格完全相同，而 GPT-6.2 Astra 在基准层级上比 GPT-6 Astra 便宜 20%——在本表中为 48 美元对 60 美元——且这一优惠延续至长上下文和快速层级。OpenAI 明确记录了旧款 GPT-6 模型同样适用超过 27.2 万 token 的费率倍数以及 2 倍快速定价结构。

Anthropic 对写入五分钟 Fable 缓存收取每百万 token 10 美元，一小时为 16 美元。OpenAI 列出的价格为：按短上下文标准费率，30 分钟 Astra 缓存 10 美元，12 小时 20 美元。

Google 的 Carbon 价目表仅列出隐式缓存，并将思考 token 计入输出费率。Carbon 在 12 月 1 日的价格调整将使其从 Sol 和 Sonnet 的输入输出费率档位升至 Opus 的档位。

新的 Astra 和 Sol 均拥有 105 万 token 的上下文窗口，并支持最多 12.8 万输出 token。对于输入超过 27.2 万 token 的请求，OpenAI 将对整个请求的输入和缓存费率加倍，输出费率乘以 1.5。这使得标准长上下文 Astra 请求的价格为每百万未缓存输入 token 16 美元、每百万输出 token 60 美元。这一分界线对于反复向模型发送大型代码库或文档集合的智能体来说十分重要。

OpenAI 的模型文档列出了半价批处理，并对快速模式收取相应标准费率的两倍。其更快的 Ultrafast API 层级对这两款模型的起步定价为标准价格的三倍，并将于 2027 年 3 月 1 日（太平洋时间）起升至六倍。

在 ChatGPT Work 和 Codex 中，Pro 500 订阅用户可在两款模型上使用 Ultrafast，Pro 200 订阅用户可在 Sol 上使用。符合条件的 Enterprise 和 Edu 工作区可通过管理员启用访问权限。

基准测试对此次升级的评价

这些比较使用的是各模型图表上的最佳得分，因此不同运行之间的推理设置可能有所不同。独立的 Codex 测试也发现 Astra 表现持平，而 Sol 出现退步。

OpenAI

OpenAI 的系统卡同样显示了喜忧参半的结果。两款模型在经过长度调整的 HealthBench Professional 上有所改进，但在原始版本上得分更低。OpenAI 表示，大多数对齐结果与 GPT-6 Astra 相似。两款新模型在模拟工作场所任务中采取不当行为的次数更少，但更常未能披露阻碍其工作的障碍。

OpenAI Deployment Safety Hub

GPT-6.2 Astra 是 OpenAI 在 Artificial Analysis 智能指数上得分最高的模型，为 62 分，比 GPT-6 Astra 高出五分，总体排名第二，仅次于 Claude Fable 5.2。

Epoch AI 给 Astra 和 Fable 的点估计值相同，均为 174，而 GPT-6 Astra 为 169，且两者的不确定度范围相互重叠。OpenAI 自己的综合评分也显示新 Astra 领先其前身，为 170.1 对 168.4。单项测试可能产生不同的排名。例如，OpenAI 专门配置的 Astra for Law 在 Harvey LAB-AA 上的得分高于基础版 Astra。

在 Terminal-Bench-Science 0.1（一项包含 70 个任务的终端研究工作测试）上，OpenAI 报告称，新 Astra 以不到三分之一的成本比其前身提高了九个百分点，在其发布图表中达到约 77%。

Artificial Analysis 使用其 mini-swe-agent 设置测得 Fable 在最大推理下的得分为 73.3%。Anthropic 报告称，使用 Claude Code 时 Fable 的得分为 74.6%，Mythos 为 75.3%。这些结果表明，在已公布的各项运行中，各模型的水平相当接近，而不同的智能体软件和设置也限制了这些差距所能说明的问题。

在法律工作方面，OpenAI 表示，Astra 在 Harvey LAB-AA 上的通过率是 Fable 的两倍以上，而成本仅约为其六分之一。图表还显示 Astra 的最佳结果约为 15%。该基准测试只有在工作满足所有评分标准且避免实质性幻觉时才判定为通过。

OpenAI 单独配置的 Astra for Law 增加了法律搜索索引和研究指令，得分更高。ChatGPT Enterprise 客户可以通过 OpenAI 的 Trusted Access Program（可信访问计划）请求该配置，包括用于 API。

Google 和 Anthropic 在两个价位上展开竞争

Anthropic 将 Opus 5.5 定位为面向编码和知识工作的通用模型，Fable 用于更难的任务，Sonnet 则是更便宜的选择。

这使得 Sol 的费率与 Sonnet 相同，基础输入和输出价格为 Opus 的一半。Fable 的可选快速模式将其输入和输出费率加倍，为团队提供了不同于 Astra Ultrafast 层级的速度与价格权衡。

Google 的产品阵容在较窄的价格区间内做出了同样的选择。Google 将 Carbon 描述为其最深入的推理模型，并表示它比 Gemini 4 Argon 消耗更多 token，尽管两者共用一张价目表。Google 指出 Carbon 在 CursorBench、WANDR 和 AutomationBench 上表现强劲，这些测试分别涵盖软件工程、网络研究和工作流自动化。

其 Gemini 4 Hydrogen 的每标准输入或输出 token 价格比 Sol 低 25%，面向更快的执行速度。Agents' Last Exam 排行榜显示 Hydrogen 的得分为 71.4%（使用 Antigravity 命令行智能体），这说明了为什么在选择较便宜的模型时，工作负载和智能体设置都很重要。

安全团队还面临不同的访问规则。OpenAI 表示，两款新模型均达到了其“关键”网络安全阈值，并配备了更严格的控制措施，这可能会拦截部分合法的漏洞研究。在发布时，其 Daybreak 计划仍将获批用户引导至 GPT-6 Astra 或 GPT-6 Cyber 进行授权安全工作。

Anthropic 对 Fable 和 Mythos 使用相同的底层模型，Mythos 的访问权限可通过其验证计划获得，用于符合条件的网络和生命科学工作。对于评估这些模型用于防御性安全的团队来说，他们能够投入生产的版本以及该版本将接受的请求，与基准测试得分同样重要。

开放权重改变部署决策

Moonshot 的 Kimi K3.1 Pro 为买家提供了一种选择：在自有基础设施上运行权重可下载的模型。在 Agents' Last Exam 上，已公布的 Kimi Code 运行得分为 74.4%，通过了 43.4% 的任务。该模型总参数量达 2.8 万亿，因此为其提供推理服务所需的基础设施是比较中的一个重要因素。Moonshot 的自定义许可证允许内部使用和微调。

该许可证还在特定商业场景中（包括大型模型即服务业务）施加了单独的协议和署名要求。将 Kimi 嵌入产品的企业以及通过推理 API 直接提供该模型的企业，需要将这些条款与其部署计划进行对照审读。

DeepSeek V4.1 Flash 1017 以 MIT 许可证提供权重，且其第一方托管 token 价格要低得多。其已公布的 Agents' Last Exam 运行（使用 OpenClaw）得分为 65.4%，通过了 36.1% 的任务。对于工作负载定义明确的买家来说，这仍然留下了一个重要问题。

如果该模型通过了他们在信息抽取、分类筛选或限定范围编码任务方面的验收测试，价格差距便可以换来多得多的调用次数。在内部运行它会将账单转移到加速器、服务基础设施以及运维人员身上。使用 DeepSeek 的 API 则保留了按 token 计费的模式，但会在数据路径中引入一个托管提供商。

采购比较最终归结为：获得一个企业可用的输出需要多少成本。对于一个准备财务工作簿的智能体来说，这包括 token、任何数据查询、未通过验证的运行，以及分析师花在修正文件上的时间。

代码智能体还要加上测试执行和审查环节。Shipper 的经验表明，应该统计某人不得不把编码智能体打发回去完成原始任务的频率。

Mollick 的演示则表明，即使结果令人印象深刻，也应追踪需要多少轮引导才能获得可用的结果。

OpenAI 的此次发布使 Astra 的按量计费更便宜，并让 Sol 在现有价格上更具说服力。两者是否能降低完成工作的成本，取决于它们在企业已使用的软件中、在相应权限下、在既定审查规则下把工作做对的频率。
