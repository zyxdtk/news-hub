中文摘要： Perplexity 联合 Nvidia 推出 Portable Computer，将 AI 代理工作负载从云端转移至本地设备。该平台支持 DGX Spark 及配备 RTX GPU 的 Linux 设备，实现模型、文件和任务全程本地化，零 token 消耗。通过协同设计精简代理框架与本地模型，解决了小型模型在长上下文和复杂任务中的瓶颈。其混合架构允许在本地模型受限时安全升级至云端前沿模型。此举大幅降低了代理长时间运行的边际成本，兼顾企业隐私与支出控制，标志着本地 AI 从发烧友阶段迈向实用工具

Perplexity 今天推出了 Portable Computer，这是其代理式“Computer”平台的一个版本，完全在用户已有的硬件上运行——首先支持 Nvidia 的 DGX Spark 台式超级计算机以及配备 Nvidia RTX GPU 的 Linux 机器。

此次发布是与 Nvidia 密切合作开发的，是将严肃的 AI 代理工作负载从云端转移到本地设备的最激进的尝试之一。模型、用户的文件以及工作本身都可以留在机器上。在本地完成的工作不消耗任何计费额度，该公司表示，每个任务默认从设备上开始——系统在将任何单独步骤发送到云端更强大的前沿模型之前，都会请求许可。

Perplexity 基础设施和企业工程副总裁 Nate 在周一的新闻发布会上表示：“我们基本上将完全相同的 UI 引入了一个完全本地的应用程序。这包含了代理框架、推理以及在本地完成工作所需的一切。”

对于过去两年一直向世界推销万亿美元 AI 数据中心的 Nvidia 来说，这一宣布传达了一个更微妙但在战略上重要的信息：这家芯片制造商认为，本地 AI 已经跨过了一个门槛，从业余爱好者的猎奇变成了实用工具——而且它想销售运行它的硬件。

“本地 AI 达到了一个转折点，”Nvidia 专注于开发者工具和开源的开发者技术总监 Nader 说。“在很长一段时间里，它只是爱好者和发烧友的玩物，他们运行那些被量化得超级小的模型……虽然这很酷，但并不太实用。但随着许多超级有用的新开源模型的出现，一切都改变了。”

Portable Computer 如何将完整的本地 AI 技术栈打包进单一应用

Perplexity Computer 是该公司用于知识工作的代理式平台，可编排 AI 模型、文件、工具和网络访问，以完成多步骤任务——审查文档文件夹、分析数据、生成报告以及将结果推送到业务系统中。

Portable Computer 在本地复制了这种体验：本地模型、代理框架、推理引擎、工具、应用连接器和安全沙箱被打包在一个系统中。这种捆绑正是其核心所在。在当今的大多数本地 AI 技术栈中，用户必须单独组装和操作这些组件——下载模型权重、搭建推理服务器、将工具连接在一起以及调整性能。

“从历史上看，搭建本地 AI 技术栈一直非常痛苦，”Nate 说。“有了 Portable Computer，我们真正专注于让这成为一种非常直观的体验，让你可以非常快速地启动并运行。”

在周一的一场演示中，系统扮演了一名散户投资者，审查一个包含 1099 税表和投资文档的文件夹——这是许多用户会犹豫是否上传到云服务的敏感财务材料。在 DGX Spark 上以满 GPU 利用率运行 270 亿参数的 Qwen 模型时，该代理审查了每份文档，并标记出这位假设投资者支付不必要费用的案例。Nate 指出，通常显示云额度消耗计数的界面元素“就停在零”，因为所有这些都是在设备上发生的。”

第二场演示展示了产品的混合特性。Nate 扮演一名初创公司创始人，要求代理在本地分析一份包含用户漏斗数据的 CSV 文件，然后使用 Perplexity 的连接器生态系统将完成的分析推送到 Slack 频道——这证明了本地优先并不意味着断开连接。

该系统还连接到 Google Drive、Gmail 和 GitHub，并且可以在本地模型达到极限时升级到前沿云端模型。在发布时，用户可以设置 Qwen 3.8 27B 或 PPLX 27B（Perplexity 在自己的框架上进行后训练的一个版本），Nvidia 的 Nemotron 3.5 Lightning 即将推出。

Portable Computer 今天面向 Linux 上的 Pro、Max、Enterprise Pro 和 Enterprise Max 订阅用户推出，Windows 支持将于 9 月跟进。任何至少具有 24GB VRAM 的 RTX GPU——大约是 GeForce RTX 3090 或更新的型号——都能达到这个门槛，Nate 称这个门槛为“我们真正希望确保能提供出色体验的底线，但也要平衡使其广泛可用。”

为什么模型与代理框架的协同设计优于通用框架

伴随此次发布，Perplexity 发表了一篇研究论文，认为有效的本地代理需要将模型和代理框架——即围绕模型的提示、工具和编排逻辑的脚手架——协同设计。核心洞察是：通用框架假设存在一个前沿模型，能够吸收海量上下文、驾驭庞大的工具界面并进行长周期规划。小型本地模型在这些需求下会不堪重负。

Perplexity 根据经验发现，尽管像 Qwen 3.8 27B 这样的模型宣称有 26 万 token 的上下文窗口，但超过 10 万 token 后它们就开始挣扎。因此，该公司构建了一个刻意精简的框架：简洁的系统提示、一小组核心工具，以及作为按需“技能”加载和卸载的功能，而不是永久停留在上下文中。它将 Gmail 和 GitHub 等流行的连接器从消耗大量 token 的 MCP 服务器转换为紧凑的命令行工具，添加了监控任务健康状况的自验证钩子，并强制执行始终开启的操作系统级沙箱。如果沙箱不可用，框架会自行禁用，而不是在没有保护的情况下运行工具——这与默认以用户完全权限运行命令的开源框架形成鲜明对比。

Perplexity 报告的基准测试结果令人瞩目，尽管这些结果来自该公司自己的评估。在其内部的 Local Knowledge Work Bench 上——包含涵盖深度研究、财务分析和文档创建的 53 项任务，Perplexity 表示计划将其开源——在 DGX Spark 上运行 Qwen 3.8 27B 的 Computer 得分为 82.6%，而开源 Pi 框架为 77.6%，运行相同模型的 Hermes 为 74.0%。

Perplexity 后训练的 PPLX 27B 将得分推高至 85.4%。在更难的任务上，差距显著扩大：在网页研究基准 BrowseComp 上，Computer 的准确率达到 66.7%，而 Pi 为 50.2%，Hermes 为 43.9%，同时使用的实际时间比 Pi 少 51%，token 比 Pi 少 70%。在多模态文档理解方面，Computer 得分为 65.1%，而 Hermes 为 34.6%，Pi 为 13.9%。

推动 AI 代理从云端走向本地硬件的 Token 经济学

当你考虑到 AI 工作负载是如何变化的，此次发布背后的战略逻辑就变得清晰了。聊天是突发性的——一个问题，一个答案，结束。代理则不同。

“有了代理，如果可以的话，你希望这些代理始终在线。你希望代理尽可能多地消耗 token，”Nader 说。“我们看到的是对 token 的无限需求，这正是让本地 AI 如此伟大的原因。正如你通过所有这些演示所看到的，你不会被 token 计量。你不需要为 token 付费。所以它对代理来说真的是杀手级应用。”

这重新定义了本地硬件的价值主张。一个运行数小时来审查文档、验证自身工作并迭代分析的代理，在云端会累积巨额的 API 账单。在用户已经拥有的设备上，这些 token 的边际成本接近于零。Perplexity 的论文明确提出了这一论点的企业版本：随着代理在各个工作流和整个组织中扩展，token 支出和数据移动“变得越来越难以治理”。本地优先执行同时解决了这两个问题——支出，因为推理是免费的；隐私，因为敏感的 token 永远不会离开设备边界。

也许在商业上最有趣的结果涉及混合的中间地带。在具有挑战性的编码基准 Terminal Bench 2.1 上，完全本地的 Qwen 模型在基本零边际成本的情况下得分为 59.6%。让它升级到云端的 Claude Opus 5 “顾问”，在每项任务估计花费 0.415 美元的情况下将得分提高到了 73.0%。单独运行前沿模型在每项任务花费 0.65 美元的情况下得分为 82.4%。换句话说，升级以大约三分之二的成本恢复了大约五分之三的前沿性能差距——而且由用户决定何时进行这种交易。在任何顾问调用之前，框架会对传出的上下文运行 PII（个人身份信息）分类器，并向用户准确显示哪些内容将离开设备。远程模型仅返回文本指导；它从不触碰本地文件或工具。

Portable Computer 与 Ollama 及 DIY 本地 AI 技术栈的对比

The Deep View 的 Jason Hiner 追问两家公司 Portable Computer 与 Ollama 等现有本地推理工具的关系。Nate 的回答划清了界限：这些工具解决问题的层级不同。

“这里的大部分努力都集中在代理框架层面，”他说，并指出系统在底层使用 vLLM 来托管模型推理，并为想要插入自己推理端点的用户提供了高级模式。“我们对正在合作的 Qwen 和 Nemotron 模型进行了大量的后训练，以真正获得尽可能好的结果……我们的重点是真正自上而下地打磨整个技术栈，将模型推理和框架结合在一起。”

Nader 的表达则更为生动。“在 Spark 上快速运行推理——有一条顺畅的路径。你可以使用 Ollama。你可以完成设置。但是，当你开始做更复杂、更具代理性的事情时，突然你需要更高的性能。你开始寻找不同的模型。你开始寻找不同的框架，这有点像海洋。你越往深处走，它就越深。”

这种类似家电的推销似乎至少打动了一位与会者。Ben 描述了自己尽管是一名工程师，但在设置自己的 DGX Spark 时却步履维艰——“这种体验太糟糕了，我们必须解决它”——他说这款产品感觉就像是“人们真正感受和理解代理式意味着什么”所需的解锁，而你需要正确的 UX 来实现它。Nvidia 还强调该硬件具有可扩展性：通过共享内存连接两台 Spark 可以运行 DeepSeek 最新版等前沿级开源模型，连接四台可以运行 GLM 5.2 或 Nemotron Ultra。“我甚至见过八台 Spark 连接在一起，”Nader 说。

不断深化的 Nvidia-Perplexity 联盟对两家公司意味着什么

此次发布将双方建立了一年多的合作关系进行了延伸。2025 年 6 月，Nvidia 和 Perplexity 宣布合作，将主权 AI 模型带给欧洲出版商和电信公司，这是 CEO 黄仁勋游说各国政府的全球活动的一部分，旨在说服政府——正如美联社在巴黎 VivaTech 大会上报道的那样——“每个国家都需要国家智能基础设施”。主权 AI 的推销——用黄仁勋的话说，数据“属于你的人民、你的国家、你的文化”——在哲学上与 Portable Computer 在单个桌面规模上提出的论点相同：你控制的智能，运行在你拥有的硬件上。

这对两家公司来说都有出于自身利益的逻辑。Perplexity 在面临出版商对其内容做法的法律压力（包括《纽约时报》于 2025 年 12 月提起的诉讼以及早些时候与《福布斯》的公开纠纷）的同时，一直在不断攀升的估值下筹集资金。如今，它获得了一款其经济学不依赖于对每个 token 进行计量的产品，以及一个打入法律、医疗和金融等隐私敏感型企业的差异化切入点。Nvidia 则为 DGX Spark 获得了一款杀手级应用，据周一发布会与会者承认，这款设备一直处于“买起来容易，用起来难”的状态。当一名记者问及 Spark 是否会预装 Portable Computer 和 Nemotron 模型出售时，Nader 既没有肯定也没有排除这种可能：“那会很酷……目标只是确保对每个用户来说这都是一种超级顺畅的体验。”

问题依然存在。Perplexity 最令人印象深刻的数据来自其内部基准测试，该公司也承认，在困难的推理任务上，紧凑型模型仍然明显落后于前沿模型——顾问升级“缩小了但没有完全消除差距”。此次发布目前仅限 Linux，24GB VRAM 的门槛将绝大多数消费级 PC 排除在外，而苹果芯片——一些最热情的本地 AI 极客的聚集地——在路线图中明显缺席。“我们现在非常专注于 Nvidia 硬件，”Nate 在被问及此事时说。

但发展趋势是毋庸置疑的。Perplexity 的研究人员将此次发布描述为“一种更广泛转变的一部分，即能力越来越强的代理从远程基础设施转移到个人和本地设备”，两家公司都押注芯片和开源模型的进步将不断扩大桌面上这个盒子能做的事情。在周一的演示中，最能说明问题的细节不是基准测试分数——而是屏幕角落里的额度计数器，当代理费力地处理一个装满税务文件的文件夹时，它一动不动地停在零。两年来，AI 行业一直以吉瓦和每美元 token 数来衡量其雄心。Portable Computer 提出了一种不同的计量表，一种永远不会运转的计量表。
