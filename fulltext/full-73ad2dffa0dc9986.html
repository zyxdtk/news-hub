摘要

AI 智能体正在物理研究中扮演越来越重要的角色。然而，现有的物理基准测试仅评估固定问题、孤立的子任务或提供解答的论文复现，很少在正确性之外同时检查研究质量。我们推出 FrontierPhysics，这是一个端到端基准测试，包含由 42 位物理学家基于自身研究构建的 56 项任务，涵盖理论、计算和实验物理的九个领域。每项任务要求智能体综述文献、制定研究计划、开展研究与实验，并产出结构化输出和科学手稿。FrontierPhysics 结合确定性验证器与专家撰写的评分标准，评估智能体的研究是否正确且可发表。在 26 种配置下测试的 22 个模型中，没有任何配置在其 168 次 rollout 中通过超过 46 次。对智能体轨迹的人工审查表明，前沿智能体的主要弱点是推理不够严谨和专家直觉有限，而非物理知识缺口或执行错误。

1 引言

大型语言模型（LLM）正从被动的科学助手演变为承担研究过程部分环节的智能体。配备外部工具后，这些智能体可以搜索和总结文献、提出假设、编写和调试科学代码，并撰写技术报告。最近的系统已经展示了化学领域的工具增强推理 [30, 6, 29, 37, 17, 4, 33, 41, 20, 22, 18, 31, 15]、基于代码的迭代实验、多智能体假设生成、科学软件优化，甚至与实验室仪器的交互。这些系统指向能够为更完整的科学工作流程和项目做贡献的智能体，而不仅是完成孤立的子任务 [9]。

评估朝这一目标迈进的进展，需要能够捕捉科学研究开放性、多阶段本质的基准测试。因此，科学基准测试正从教科书级别的问题 [16, 23, 48, 35, 44] 转向专家级别的封闭式问题 [8] 和研究级别的问题 [40]。在现有的研究级基准中，一些评估科学推理 [10, 50, 34, 25, 46]，另一些评估智能体在现实科学工作流程中完成单项任务的能力 [43, 19, 31, 28, 7, 21]。然而，这些基准针对的是孤立的能力，而且由于其中许多任务是具有确定性答案的封闭式问题，模型很快就会使其饱和，基准因此失去区分信号。为了迈向端到端研究，一些基准将任务设计为整篇论文的复现 [36, 12, 49, 14]。但由于智能体会得到原始论文，研究问题和解决方案结构在很大程度上已被预先指定，限制了其评估开放式科学探究的能力。更近期的基准通过将已发表的研究转换为不透露解决方案的研究问题来解决这一局限 [32, 45, 47, 24]。然而，设计和评估此类任务涉及许多需要原作者专业知识的微妙之处：例如，如何撰写在避免假阴性的同时尽可能保留开放性的指令，以及如何判断智能体的失败反映的是真正的科学误解还是缺乏专家直觉和经验。据我们所知，尚无现有基准能够完全做到：完全智能体化、由物理学家基于自身研究构建、同时从论文质量和结果正确性两方面评分，并通过人工任务审查和失败模式分析来处理上述微妙之处（表 1）。

本文推出 FrontierPhysics（图 1），一个评估 AI 智能体能否在理论、计算和实验物理领域开展端到端研究的基准。FrontierPhysics 的任务由活跃的物理研究人员（包括博士生、博士后和研究科学家）基于他们亲自完成的研究项目设计。平均而言，每位任务作者拥有 420 次引用。为了在保留开放性的同时尽量减少假阴性和假阳性，每项任务都经过人工通用审查、领域专家同行评审和失败模式分析。

对于每项任务（图 2），智能体会收到一个高层提示，类似于研究项目开始时首席研究员（PI）给出的指令。然后，智能体必须开展研究，并产出一篇科学手稿和可被确定性验证的数值输出。这一过程的大部分是开放性的：智能体必须调研主题、制定研究计划、选择合适的方法、验证结果，并确立其发现的意义。为了评估这些能力，FrontierPhysics 结合了确定性验证器（检查数值输出的测试脚本）与由评审智能体进行的基于评分标准的评分。

2.1 任务设计

任务旨在重构端到端的研究项目。图 3b 展示了一个示例任务，附录 A 给出了其完整指令和提案。任务可能会给出一些需要弄清的重要问题或值得探索的方向，但不会指定明确的方法论或解决方案路径。必要时，任务环境中会提供输入数据和其他支持文件（图 3b），使智能体能够配置并执行相关的计算或实验工作流程。

每项任务要求两类最终交付物：确定性产物（如计算量、仿真输出或处理后的数据），以及以 paper.pdf 形式提交的论文手稿。论文需达到同行评审论文的标准，清晰地呈现研究背景、方法、结果和结论，同时忠实地纳入任务执行过程中产生的证据和计算产物。

基于评分标准的评估包括全局评分标准和任务特定评分标准。全局评分标准评估行为一致性，包括奖励作弊 [1, 38]、幻觉，以及包括文献综合、结果验证和使用证据支持科学主张在内的一般研究实践；任务特定评分标准则由领域专家制定，用于评估智能体对底层物理的理解、科学表达以及研究任务的执行。由于评分标准设计需要特定任务的专业知识，我们请每位贡献者为自己的任务和研究项目设计评分标准。视任务而定，评分标准可能会评估智能体是否识别并正确使用了关键参考文献、是否通过调研发现了关键科学思想、是否考虑了现实的实验约束，或者是否在论文中为其工作提供了良好的动机。

2.2 任务策划与质量审查

通用质量审查。 当贡献者创建任务提交时，我们首先评估其真实性和来源（图 3a）：贡献者必须提供支持信息（如参考文献或专利链接），以证明他们亲自完成了该项目。我们要求贡献者提供项目背景、原始研究过程的时间线以及完成研究所花费的时间。我们要求底层项目至少涉及两周的研究工作量。然后我们检查 task.md 和 rubric.json 是否人类可读并包含真实的人工输入，拒绝看起来纯粹由 AI 生成的任务。

领域同行评审。 我们的目标是让每项任务都由密切相关领域的专家评审。为了实现规模化，我们邀请贡献者在自己的任务通过第一阶段通用质量检查后成为领域评审员。因此，我们的领域评审员都在其领域开展过研究，主要由博士生（47%）和博士（37%）组成。每位新评审员通过一对一会议进行入职培训，我们审计其首次评审的质量以统一评审员之间的标准。当领域评审员判断任务可以合并时，我们会对照我们的标准进行最终检查。

每位领域评审员都会获得一份领域评审清单，涵盖三个方面：第一，评审员验证 task.md 没有过度指定问题：提示不应包含有能力的研究者应当知道或能够弄清的领域知识，从而使任务尽可能保持开放。第二，评审员确认 rubric.json 编码了只有做过该研究的人才会拥有的真实物理洞察，而非 AI 生成评分标准中典型的低信号标准。第三，评审员在获得智能体轨迹后检查失败模式：贡献者必须使用 SOTA 智能体进行至少三次本地运行和初步失败模式分析，评审员检查这些轨迹以发现潜在的假阳性和假阴性。常见问题包括：使实现正确物理模型的智能体失败的不合理数值容差，或导致智能体误解的模糊指令。

当所有检查通过后，由六位来自不同子领域背景的物理学博士研究人员组成的管理团队批准并将提交合并到最终任务集中。最终，从全球 26 个机构、9 个物理领域的 42 位物理学研究人员提交的 182 份初始任务中，接受了 56 项任务。摘要见图 4。其中 18 项任务的底层研究已发表在任务贡献者共同署名的论文中，包括四项基于 Nature 论文的任务，其他期刊包括 Nature Communications、Physical Review Letters 和 Physical Review X。贡献者报告平均每项任务的原始项目花费约 270 天，总计超过 8,000 小时的研究。

2.3 评估

在每次任务 rollout（图 3c）中，我们的评估方案旨在评估智能体结果的客观正确性及其研究的整体质量。为此，我们将程序化确定性验证器与“智能体即评审”（Agent-as-judge）相结合。确定性验证器将结构化输出与参考值进行比对。智能体运行结束后，智能体轨迹文件、验证器结果以及包括 paper.pdf 在内的输出文件会被记录和保存。然后这些文件被复制到另一个沙箱中，由评审智能体基于 rubric.json 对轨迹文件和 paper.pdf 进行审查和评分。我们使用智能体而非单次 LLM 调用作为评审，是因为许多评分标准（如关于奖励作弊、结果幻觉和文献搜索的标准）必须对照智能体的轨迹、代码和输出文件进行检查，而不仅是 paper.pdf。所有 rollout 均由同一评审智能体评分，即 Codex CLI 中的 GPT-5.6 Sol（xhigh）。第 3.3 节将其评分与专家审计（表 5、图 6）以及作者本人论文（表 11）进行核对。用 Claude Code CLI 中的 Claude Opus 5.5 作为评审智能体对第一轮评估的 rollout 重新评分，对几乎所有 GPT-6 Astra rollout 给出相同的通过/失败判定，但 Opus 5.5 评审员对来自其自身模型家族的 rollout 更为宽松（表 6）。评审智能体的工作区文件和轨迹文件以相同方式收集到 HuggingFace 数据集中以供后续分析。

基于评分标准的评分已被广泛用于涉及开放性探索或智能体性能定性维度的基准测试 [39, 3, 13, 36, 11]。确定性验证确立输出是否正确，而基于评分标准的评估则评估更多方面，例如智能体是否良好地开展并传达了研究。受 FrontierCode [11] 评分标准设计的启发，我们将评分标准分为阻断项（blockers）和非阻断项（non-blockers）。阻断项是二元门槛，代表对任务科学有效性至关重要的要求。因此，智能体必须满足每个阻断项以及确定性验证器才能通过。非阻断项捕捉工作的定性方面。每个非阻断项按三级量表评分：0 表示要求缺失或不正确，1 表示部分满足，2 表示完全满足。这些级别的具体锚点为每项标准单独定义。任务作者还为每项标准赋予 1 到 10 的整数权重，表示其相对重要性。阻断项权重作为评分标准元数据保留，但不计入数值质量得分。任务的最终得分：

S_final = (Σ_{i∈𝒩} w_i·s_i) / (2·Σ_{i∈𝒩} w_i) × 100，若 D=1 且对所有 j∈ℬ 有 b_j=1；否则为 0。 (1)

其中 𝒩 和 ℬ 分别表示非阻断项和阻断项，s_i ∈ {0,1,2}，w_i 为标准权重，D 为确定性验证器结果，b_j 为阻断项结果。S_final = 0 表示结果不可发表，而 S_final ≠ 0 时的数值衡量出版物的质量。非阻断项的高分无法弥补错误的确定性结果或未通过的阻断项。反之，智能体可能通过所有确定性检查，却产出一篇动机不足、支撑不充分或表达糟糕的手稿。这样的提交能通过验证器和阻断项，但 S_final 很低。

3 实验

我们评估了四个智能体框架中的 22 个前沿模型。每个模型以其可用的最高推理力度尝试所有 56 项任务各三次，另有四个 GPT 模型也在 xhigh 级别运行。

3.1 实验设置

与 SkillsBench [27] 和 ClawsBench [26] 一样，我们使用 BenchFlow CLI [5]——一个用于创建 RL 环境、后训练和评估的研究基础设施命令行工具——来运行实验并跟踪智能体轨迹、验证器和评分标准结果。GPT 模型使用 Codex CLI，Claude 模型使用 Claude Code CLI，Grok 模型使用 Grok Build，Gemini 模型使用 Antigravity CLI。其他七个模型——DeepSeek V4 Pro、DeepSeek V4.1 Flash、GLM-5.3、Kimi K3、Kimi K3.1 Pro、MiMo V2.6 Pro 和 Mistral Large 4——也在 Claude Code CLI 中运行。每个智能体运行时在并行云沙箱中启动。对于资源需求低于 4 vCPU、16GB 内存和 10GB 存储的任务，我们使用 Daytona 作为沙箱提供商。对于资源需求更高的任务，我们在 Azure 虚拟机中使用 Docker 并提供 Lambda API 访问，以便模型按需调用 GPU 资源。

3.3 评估验证器和评分标准的可靠性

评审后仍可能存在验证器和评分标准缺陷。缺陷的一个主要来源是对抗性验证器或评分标准设计，旨在压低任务通过率，使得即使是人类专家产生的正确解决方案也可能失败。为缓解这一问题，我们有一个三阶段流程：

首先，我们请每位任务贡献者对三次 GPT-6 Astra rollout 做失败模式报告（因为分析开始时这是单智能体框架下表现最好的模型），检查智能体轨迹和输出文件，并解释智能体在哪里失败以及为什么。其次，我们的管理团队评审员重读这些贡献者的失败模式报告，并对照智能体轨迹和输出文件进行双重检查。在审查了约 60 次 rollout 后，评审员将反复出现的失败归纳为表 4 中的分类体系。在此过程中发现了假阴性（智能体给出了正确结果却被验证器或评审智能体判定失败），并在附录 E 中标注。如表 5 所示，仅含错误失败的 rollout 会导致通过率被低估。总计 168 次 rollout 中有 9 次被错误地判定为失败。

这与最近的研究 [2] 相吻合，该研究中领域专家对一些领先基准重新评分，发现许多失败源于评分器错误、错误的参考解决方案以及模糊或欠指定的问题。这表明发现假阴性既需要领域专业知识也需要时间，但对维持高基准质量至关重要。

非阻断性评分标准得分更难评估，因为它们涉及更多主观判断。第三，作为对评分标准质量的健全性检查，我们请作者在可能的情况下将自己的论文或手稿作为参考材料纳入 oracle。33 项任务包含了这些材料。对于有可用参考的任务，我们选择了用于对这些材料评分的手稿级评分标准，包括针对作者参考工作的阻断项和非阻断项评分标准。然后我们使用与主实验相同的配置，在沙箱中运行评审智能体，用评分标准对这些文件评分。作者自己的材料在相应评分标准下平均得分 96.2%（表 11），表明评分标准评分与人类专家材料之间具有良好的对齐。

图 6 显示，智能体的失败大多并非源于物理错误（如计算错误、对物理概念的误解或物理知识缺乏），这与人们对物理基准的预期相反。相反，它们常常难以严谨地推理（48%）、在决策时运用良好的物理直觉（34%）以及综合文献（27%）。典型的严谨思维失败包括：循环自验证，即智能体自己的验证方法依赖于其错误假设，因此永远无法发现自己的错误；以及边缘情况，即智能体未能考虑其方法或代码的所有边缘情况，导致在某些隐藏测试中失败。第三常见的失败在于文献。在很多情况下，智能体未能找到（任务作者指定的）研究关键文献，难以从文献搜索中综合信息并为项目提供动机，或难以在手稿中用文献支持其论点。缺乏物理直觉是另一个主要失败模式。此失败模式的典型例子包括：智能体无法确定实验的主要误差来源，这不是因为它们不理解，而是因为它们没有识别重要因素的专业直觉；调试时，智能体无法意识到问题的根源，却不断调整错误的旋钮。除前三大失败模式外，指令遵循占失败的 26%。这可能是智能体遗漏了指令中的某些要求或误解了指令。在很多情况下，任务作者认为含义对人类领域专家应该是清楚的，而智能体无法获得显式/隐式的信息。

当前的失败模式分析聚焦于 GPT-6 Astra 模型（见第 3.3 节），因为任务作者手动阅读涉及子智能体的轨迹文件具有挑战性。其他模型或其他模型-框架组合可能以不同方式失败，包括此分类体系之外的方式。也正因如此，我们只能准确标注 GPT-6 Astra rollout 的假阴性，并因此仅修正 GPT-6 Astra 的最终通过率。

4 结论

我们推出了 FrontierPhysics，一个包含 56 项任务的基准数据集，评估 AI 智能体在九个领域开展物理研究的能力。FrontierPhysics 表明端到端物理研究对当前模型仍然具有挑战性，因为通过率最高的配置——Claude Code CLI 中的 Opus 5.5——在其 168 次 rollout 中仅通过 46 次。基于人类专家对 168 次 SOTA 智能体 rollout 轨迹和输出文件的审计，我们构建了失败模式分类体系并手动标注了所有这 168 次 rollout。从分类体系分布中，我们得出结论：缺乏严谨思维（例如循环自验证）以及缺少专家直觉——而非物理知识不足或执行错误——是前沿 LLM 智能体的主要弱点。

有能力的物理研究智能体应当超越指定任务，仅在高层次指导下独立探索科学问题，从问题定义到新发现。训练和评估此类智能体将需要更开放的研究任务和能够评估探索性推理、部分进展和意外发现的灵活评估框架。
