自发布以来，DeepSeek 的 V4 Flash 模型登顶了各大模型排行榜，并被开发者誉为“性能怪兽”。但在实际测试中，它仅完成了一批复杂智能体任务的 53.8%。

Composio 让该模型在 30 个刻意增加难度的多步骤任务中，通过了八种不同的智能体框架（包括 Claude Code、Codex 和 OpenCode）进行测试，这些任务涉及 Gmail、GitHub、Slack 和 Google Sheets 等实时工具。在总共 240 次运行中，只有 129 次通过——并且在所有接受测试的框架中，仅有 6 个工作流被成功完成。

这一差距说明了为什么决定该模型能否在企业环境中取得成功的，是编排能力而非纯粹的模型能力：同一个模型根据其运行的框架、工具配置、缓存行为、重试机制和提供商技术栈的不同，产生了截然不同的结果。

DeepSeek 表示将上调 V4 Flash 和 Pro 的价格，这两款模型已迅速成为构建编程助手和智能体的开发者的最爱。

虽然此举似乎会削弱其吸引力——即前沿提供商无法匹敌的超低价格和惊人能力——但它也将故事推向了超越如今已老生常谈的“廉价中国模型”的叙事，因为早期的用例开始涌现，企业正在弄清楚不同的模型应如何融入其技术栈，以及应针对哪些工作流。

DeepSeek 颠覆成本结构，采用量“疯狂”

DeepSeek 于 7 月 31 日推出了 V4 Flash 公开测试版，并于 8 月 13 日正式发布 V4 Pro。拥有 2840 亿参数的 Flash 专为高吞吐量和速度而构建，而拥有 1.6 万亿参数的 Pro 则面向更复杂的工作流。

两款模型均具备灵活的推理能力（低、高、最大）以及应用思维链（CoT）推理以提高回答准确性的“思考模式”。

用户立即对 Flash 的能力印象深刻。自发布以来，它一直占据 OpenRouter 使用量排行榜的榜首，目前是该平台按每周 Token 量计算使用最多的模型。

“DeepSeek V4 Flash 最初的采用数据非常疯狂，”ML 研究员 Nathan Lambert 在 X 上发帖称，并补充说新版本“得分与 GLM 5.2 相同”，使其成为将被广泛使用的“性能怪兽”。

DeepSeek 转变成本模型增加了一个有趣的维度。根据模型、Token 类型和时间的不同，V4 API 费率最高上涨了 1,100%。新的定价结构如下：

Flash 非高峰期每百万输入 Token 为 22 美分，每百万输出 Token 为 66 美分；高峰期每百万输入 Token 为 44 美分，每百万输出 Token 为 1.32 美分。这相当于上涨了 57% 到 371%。

Pro 非高峰期每百万输入 Token 为 66 美分，每百万输出 Token 为 1.98 美分；高峰期每百万输入 Token 为 1.32 美分，每百万输出 Token 为 3.96 美分。这相当于上涨了 51% 到 355%。

与此同时，缓存命中（当模型重用提示词而不是从头开始时）的费率上涨了 52% 到 1,100%。

DeepSeek 表示，提供低 50% 的非高峰期使用费旨在鼓励“更灵活的工作负载调度”。每 24 小时中有 17 个小时保持半价，而新结构实际上使其本土市场的定价最高。

“这不是简单的价格上涨，”Greyhound Research 的 Sanchit vir Gogia 说。“这是一种让推理时机成为经济变量的定价架构。”

可以等待的工作——如批量评估、合成数据生成和通宵开发运行——转移到廉价时段；而交互式智能体和实时运营则不能。Gogia 表示，开发者和企业的不满是真实且强烈的，但 DeepSeek 过去的低价并不意味着它有义务永远保持廉价。

乍一看，这确实像是“一个仍在努力与更成熟的 AI 模型供应商建立信誉的平台做出的自杀式举动，”科技分析师 Carmi Levy 说。涨价肯定会侵蚀 DeepSeek 的价格优势，并迫使客户更加沉重地权衡对该公司的中国背景的担忧。

不过他也表示，相较于 OpenAI、Anthropic、Google、Cohere、xAI 等竞争对手的模型，DeepSeek 在所有定价指标上仍然要便宜得多。

Levy 说，因此，虽然此举将迫使 DeepSeek 强调性能和安全性而非成本，但这几乎不会消除其本已引人注目的性价比优势，并且仍然给客户留下了充足的回旋余地来证明将其用于特定工作负载是合理的。只是计算需要更加精打细算。

“随着 DeepSeek 不可避免地继续使定价与市场现实接轨，这种优势可能会随着时间的推移而削弱，但目前仍然很容易做出商业论证，”Levy 说。

DeepSeek Flash 能在企业环境中的哪些地方发挥作用？

由于成本、能力、可靠性、数据治理、安全和其他因素，企业内部的采用仍然是一个未知数。

Levy 说，一个用例是批处理。这类工作通常是常规和重复性的，不需要顶级智能，因此使用更便宜、更高效的模型是有意义的。“它是一个高性能推理引擎，企业可以考虑将其用于特定解决方案的工作负载，而不是作为现有产品的全面替代品，”Levy 说。

他指出，部分采用可能涉及孤立的、非敏感的工作负载，这些工作负载具有明确界定的成功指标、严格的监督、权限控制以及失败时的备用模型。更广泛的部署将需要 DeepSeek 及其托管合作伙伴展示强大的可靠性、安全性、隐私性、可审计性和部署选项。他说，随着 DeepSeek 根据需求调整价格结构，它还必须保持足够大的性价比优势来证明承担任何风险是合理的。

随着 IT 团队熟悉新模型并弄清楚何时以及如何将其提交给高层领导以获得预算批准，预计在后端实验室和受控测试环境中会出现未经批准的小规模使用。

“DeepSeek 已经赢得了作为全球颠覆者的当之无愧的声誉，”他说，“很明显，它向更广泛的企业采用迈进的趋势将继续积聚动力。”

在多工具工作流中测试 DeepSeek

虽然许多用例仍处于实验阶段，但 Meta 软件工程师 Naman Ahuja 提供了一个可以直接转化为企业环境的用例。在一个与其雇主无关的项目中，他用 DeepSeek V4 Flash 构建了一个家庭自动化智能体，以探索较低成本的模型如何作为真实多工具工作流的推理/编排层来执行。

当他离开家时，智能体会在原本独立的系统中协调几个动作：比如将恒温器设置为“离开”以减少不必要的能源消耗，布防 Ring 安全系统，关门并上锁。

“让我感兴趣的不仅仅是模型能否理解命令，而是它能否在可靠性至关重要的情况下，将意图转化为跨多个工具的一系列动作，”Ahuja 说。

最大的教训是，一旦模型可以采取行动，可靠性与智能同样重要。系统需要结构化的工具输出、验证动作是否真正成功、重试/失败处理，以及围绕模型允许执行的操作设定明确的边界。

在企业的情况下，“架构是相似的。”家庭设备变成了工单系统、数据库、CRM 平台或基础设施 API。最有用的智能体可能会在多个系统中协调重复的工作流，并具备范围权限、可审计性、可观测性以及对高风险操作的人工批准。

“许多有价值的 AI 智能体将不会是聊天机器人；它们将是响应事件协调 API、基础设施和业务系统的后台智能体，”他说。

企业需要切实的用例

但 Gogia 指出，Flash 的 API 仍处于公开测试阶段，目前还没有成熟的企业采用、实际部署和具名客户的证据链。

“基准测试的故事比其流传的版本要松散，产品组合的故事比看起来要新，而经济学已经转移到围绕模型的系统中，”他说。开发者的主流化已被证明；企业的标准化则不然。“从流量来看，该模型已成为主流，但从合同来看仍未得到验证。”

他说，DeepSeek 自身的集成指南是一个重要的考量因素：其针对至少一种流行智能体环境的文档指出，如果没有兼容性覆盖，内置的 V4 条目不足以实现可靠运行。

“这是供应商在准确地告诉市场，基准测试性能不能代表生产就绪，”Gogia 说。“一个模型可以得分很漂亮，但一旦工具、凭证和状态介入，它仍然可能行为失常。”

服务层的表现也不例外：由不同主机运行的相同开放权重在吞吐量和正常运行时间上表现出明显差异。“因此，选择 Flash 回答了一个采购问题，却又引出了三个问题：谁来提供服务，在哪里运行，以及围绕它有哪些控制措施，”Gogia 说。

为多模型未来做好准备

DeepSeek 为多模型未来提供了一个微妙的案例。Gogia 指出，V4 Flash 正被部署为各种环境中的大容量工作者：它处理常规生成、检索和后台自动化，而更困难或敏感的任务则转移到其他地方。

“问题在于其性能是否足以满足企业实际运行的真实工作流，而不是它是否在每个基准测试中都名列前茅，”他说。企业必须确定哪种模型、框架和提供商的组合能以最低成本安全地完成工作。

EmpirioLabs AI 的首席执行官兼创始人 Adam Dalloul 指出，越大并不总是越好；工作流应取决于任务。例如，他在 EmpirioLabs AI 的团队——在一个 API 上托管了包括 DeepSeek V4 Flash 在内的 100 多个模型——最近正在将其网站翻译成不同的语言，而完成这项任务并不需要像 GPT 5.6 Sol 或 Opus 5 这样的大模型。

“这就是子智能体派上用场的地方，”他说。

他推荐的方法：生成更便宜的子智能体并根据任务进行调整。例如，日常工作使用 Flash 变体，需要更强大功能时使用 Pro 变体。“这取决于你的应用程序的性质。”

Dalloul 指出，许多公司正在转向自己的内部基准测试，以有效地路由模型。例如，他的团队有一个工作流，可以让模型通过各种关卡和指令。这有助于他们识别出具备任务所需速度和准确性的模型。

在另一个例子中，他的一个企业客户专门希望访问 DeepSeek V4 Flash。他们测试了多种模型，V4 Flash 是唯一一个满足其速度、成本和“适当智能阈值”标准的模型。

Meta 的 Ahuja 同意，更小、更高效的模型可以处理频繁的、定义明确的智能体任务，而更昂贵的前沿模型可以保留给“模糊的、困难的或高风险的决策”。相关的衡量标准越来越成为每个成功完成的工作流的成本，而不仅仅是每个 Token 的成本。

然而，权衡是，廉价的推理并不自动意味着廉价或安全的自动化，他说。一旦 AI 系统可以采取行动，可靠性、验证、权限、失败处理和安全性就变得重要得多。

“失败的文本回复只是带来不便；而运营工作流中失败的动作可能会产生真实的后果，”Ahuja 说。
