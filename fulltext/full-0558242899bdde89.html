原标题：ReproBridge: Building Reproducibility into ML Research Artifacts

中文摘要： ReproBridge 是一种智能体工作流，将机器学习实验复现中恢复的流程和决策标准化为四组件精炼工件：精炼代码库、环境设置、实验启动器和复现指南。配套基准 ReproBridge-Bench 涵盖 36 篇论文的 1,029 个任务，每个任务配五个人工验证参考分数。实验显示，精炼工件将四个模型的平均复现成功率从 76.4% 提升至 92.6%，API 成本平均降低 19.7%，跨模型差距从 21.6 缩小至 3.9 个百分点。消融研究表明代码和环境组件最为关键。

ReproBridge：将可复现性构建到机器学习研究工件中

作者： Yubo Wang（滑铁卢大学；Google）、Rui Meng（Google）、Jaehyun Nam（Google）、Tomas Pfister（Google）、Jinsung Yoon（Google）

摘要

复现机器学习实验需要从散布于论文、已发布代码和辅助工件中的信息重建实验流程。对于编码智能体而言，复现成功与否可能取决于其填补缺失细节的能力，而不仅仅取决于已发布的工件。我们探讨这样一个问题：保存已恢复的流程和决策是否能改善后续的独立复现。我们定义了一种标准化的工件设计，包括精炼代码库、环境设置、实验启动器和复现指南，并介绍了 ReproBridge——一种用于构建这些精炼可复现工件的智能体工作流。ReproBridge-Bench 提供了来自 36 篇论文、387 个实验的 1,029 个任务，每个任务由五个人工验证的参考分数锚定。智能体在全新会话中使用原始代码或精炼工件尝试任务；独立的审计器检查执行证据。在四个评估模型中，精炼工件将平均复现成功率从 76.4% 提升至 92.6%，并平均降低下游 API 支出 19.7%。跨模型成功率差距从 21.6 个百分点缩小到 3.9 个百分点，所有四个模型的平均成功率均超过 90%。消融研究中移除任何组件都会降低成功率，其中移除代码和环境造成的损失最大。这些结果表明，保存执行知识可以帮助原始代码成功率较低的模型更可靠地复现实验，并降低 API 成本。

1 引言

复现机器学习实验通常需要恢复论文和已发布代码中未明确说明的细节。复现者可能需要解决不兼容的依赖关系、确定预期配置、修复数据加载器，并弄清运行输出如何变成报告的分数。即使是成功的尝试，这些决策也可能被埋没在对话或 shell 历史记录中，迫使下一个复现者重复调查。代码发布是必不可少的起点（Pineau 等，2021）；保存在执行过程中恢复的流程是迈向可复用研究工件的进一步一步（Stodden 等，2016）。

编码智能体基准通过未解决的依赖关系和错误识别的输出（Siegel 等，2024）、缺失的实现细节（Xiang 等，2025）以及从未成为完整实验的计划（Starace 等，2025）暴露了这种重建负担。查阅被引用的论文可以恢复一些缺失的细节（Zhao 等，2026b），但成功的执行可能仍然依赖于有能力的智能体隐式提供的知识。

复现成功在多大程度上取决于已发布的工件，又在多大程度上取决于复现者弥补缺失细节的能力？

本文中，复现指使用作者发布的材料独立重新执行机器学习实验，目标是数值兼容的测量结果。研究工件包括支持研究的代码、数据、检查点、环境规范和文档。

我们的假设是：保存在复现过程中恢复的流程和决策可以改善计算可复现性。依赖解析可以变成安装流程；实验发现可以变成专用启动器；修正可以变成带有理由和受影响任务的文档化选择。我们通过三项贡献来研究这一假设。

工件设计。 我们将精炼可复现工件标准化为四个组件：精炼代码库、环境设置、实验启动器和复现指南（图 1；第 3.2 节）。它们共同保存了可执行的流程以及其设置和修复的原因。组件移除实验测试每个部分的贡献，而普通输出对照实验测试在没有标准化交付的情况下代码、脚本和日志的复用。

构建工作流。 ReproBridge 从论文及其官方存储库构建这些工件（第 3.1 节）。人类定义工作流、交付标准和协议；智能体指定实验、准备并执行实验，并通过审查和打包保存生成的流程。后续复用在全新的复现者会话中评估，这些会话接收原始代码库或精炼工件。

基准和实证评估。 ReproBridge-Bench 提供了来自 36 篇论文、387 个实验的 1,029 个任务，每个任务有五个人工验证的参考分数（第 2 节）。数值兼容性根据观察到的执行及其变异性进行评估；独立的审计器检查执行证据，因为仅匹配数字可能掩盖被替换的测量。在四个编码智能体中，精炼工件将成功率提高 5.5 至 23.2 个百分点，并将下游 API 支出降低 16.8% 至 23.7%。鲁棒性分析、组件消融、案例研究以及完整性检查的人工验证研究了这些收益的范围和机制（第 4 节）。

2 问题表述与 ReproBridge-Bench

2.1 执行偏差与参考变异性

任务指定要复现的数据、模型配置、训练或评估流程以及报告统计量。论文所述的设置优先于冲突的代码。设 μ 为忠实执行指定实验时该统计量的期望值。发表的分数是一个观测值，而不是 μ 的无误差值。

对于产生测量值 Y 的尝试，我们写成 Y = μ + D + ε。这里 D 是偏离指定实验的执行选择导致的期望偏移，ε 是在这些选择条件下的零均值变异。这一工作模型借鉴了测量中系统效应和随机效应的区分（国际计量学指南联合委员会，2020；Taylor 和 Kuyatt，1994）。随机训练在不同运行之间可能有所不同（Nagarajan 等，2018）。独立重复可以减少对固定流程均值的不确定性（Bouthillier 等，2021），但不能消除持续性偏移 D。ReproBridge 旨在通过保存忠实执行的流程和决策来减少 |D|，而 ε 仍然存在。

我们对每个任务使用五个同一统计量的人工验证参考观测值。假设忠实且独立的参考执行（D=0），它们的均值估计 μ，其离散程度表征 ε。预测区间容纳了估计中心的不确定性和新观测值 Y 的变异（美国国家标准与技术研究院，n.d.）。第 2.3 节描述了收集和验证。数值兼容性与第 4.1 节中的执行完整性检查相结合：仅一个接近的数字并不能表明预期的实验已被执行。

2.3 参考收集与任务验证

参考协议指定五名人类复现者在独立的服务器上工作，从相同的固定原始提交开始，使用独立的执行目录和编码智能体会话。他们不得复用其他参与者生成的脚本或测量、精炼工件或下游复现痕迹。允许编码智能体协助，但人类会检查实际使用的脚本、配置、编辑和测量提取。在聚合之前，五名复现者的执行设置与论文指定的设置和通用任务定义进行了交叉验证。每个参考观测值测量指定的任务统计量：多种子均值或 best-of-N 统计量是一个观测值，不能与单种子分数互换。

验证者必须在检查分数之前固定未指定的重复和种子选择，并且不得调整流程或重复有效测量直到它们接近发表值。诊断运行和修正后的重新运行与替换原因分开记录；仅数值不一致不足以证明丢弃有效执行是合理的。附录 A.3 给出了完整的验证和证据保留协议。

数值兼容性。 根据第 2.1 节，五个观测值估计 μ 和参考变异 ε。对于任务 j，设 p_j 为发表分数，x_j1,…,x_j5 为参考观测值，样本均值为 x̄_j，样本标准差为 s_j。报告的范围由其中点表示。兼容区间为：

I_j^(q) = [x̄j − r_j^(q), x̄_j + r_j^(q)]，其中 r_j^(q) = max{t((1+q)/2,4) · s_j · √(1+1/5), 0.01|x̄_j|}　（公式 1）

默认值为 q=0.95。如果没有明确的 1% 容差下限，这是在独立、近似正态的工作模型下同一统计量新观测值的 Student-t 预测区间（美国国家标准与技术研究院，n.d.）。它同时容纳了参考均值的不确定性和新观测值的变异。阈值在原始和精炼工件条件下固定不变；q=0.80 提供第 4.3 节中更严格的评分检查。

参考变异性和任务资格。 类别 1 和类别 2 都要求 p_j ∈ I_j^(.95)，仅在相对参考变异性上有所不同。我们定义：

V_j = 100 · (max_i x_ji − min_i x_ji)/|p_j|（p_j≠0）；V_j = +∞（p_j=0）　（公式 2）

稳定任务满足 V_j ≤ 10，意味着参考范围最多为绝对发表分数的 10%；更高变异性的任务超过此阈值。两个类别都进入下游评估。我们在主比较中将它们合并，并在第 4.3 节中分别检查。附录 A.4 给出了不确定性推导和数值规则的额外细节。

3 ReproBridge：工件设计与构建

ReproBridge 将复现工作转化为后续研究者或智能体无需访问构建对话即可使用的工件。交付物包括精炼代码、环境设置、实验启动器和复现指南。其构建工作流既保存执行选择背后的证据，也保存可执行步骤本身。

独立审查测试证据和交付物。 审查者在与被审查角色分开的上下文中检查计划、执行记录和完成的工件。它将局部化发现返回给负责的阶段进行修订和重新检查。交付还要求从干净的 shell 测试提供的入口点，包括低成本的真实重复以及对输出结构和分数提取的检查。交付的环境必须与用于构建测量的环境匹配。人类参考信息在整个构建过程中被保留。附录 B 给出了完整的角色规范和交付检查。

3.2 四个组件保存执行知识

后续复现者需要知道运行什么代码、如何准备其环境、如何获得请求的测量以及为什么做出特定选择。四组件精炼可复现工件（图表中的 RRA）满足这些需求。精炼代码库修复执行缺陷并提供缺失的实验支持。环境设置指定兼容的依赖以及数据或检查点获取。实验启动器将任务连接到配置、执行范围、输出和测量提取，区分计分运行和冒烟测试。复现指南（包括其更改记录）解释设置、论文-代码差异、报告统计量以及资源或数值敏感性。第 4.5 节通过移除实验测试每个组件的贡献。

指南将指令与其理由联系起来。每个歧义条目记录其来源位置、差距、采用的解决方案和理由、敏感性以及受影响的任务。更改记录区分执行修复、正确性修复和便利性更改，同时保留陷阱和开放选择。重复指导保留指定的报告单位并表征变异 ε，而不选择有利的结果。图 3 展示了 SCIQL 的指南如何将测量决策和失败检查链接到可执行支持；附录 B.2 展开了其十二节结构。

4 实验

4.1 评估协议与设置

Opus 5 为主实验构建精炼工件。全新的复现者会话接收论文、选定任务以及原始代码或其精炼工件。构建对话、隐藏的参考观测值和替代条件被保留。会话提交新的测量和执行证据；我们比较成功率、token 使用量和 API 支出。

Sonnet 4.6、Sonnet 5、Opus 5 和 Gemini 3.8 Flash（图表中的 Gemini 3.8）尝试来自 36 篇测试论文的所有 1,029 个任务，每次评估中每个论文-模型-条件组合使用一个全新会话。原始代码和精炼工件条件均使用每篇论文 24 小时的墙上时钟限制。GPU 实验使用八块 H100-80GB GPU。Codex 是主要审计器。不同供应商的测试框架不同，因此跨模型比较是描述性的。论文级、分层和任务级诊断使用第一次评估。附录 C 详细介绍了测试框架、信息边界和审计。

执行完整性审计。 独立的审计器检查每个报告结果的证据链，将值追溯到其输出位置、执行记录和生成脚本。它使用账本时间戳检查执行和提取顺序，并使用可用的脚本和输出哈希验证检查的文件与记录的版本匹配。审计器交叉检查执行的代码、日志和提取的值，以定位复制的测量、更改的输出或替换的计算。

在机械筛选识别线索后，Finder（查找者）检查执行的代码和记录并提出局部化违规。独立的 Refuter（反驳者）试图通过检查证据、其对测量的影响以及任务规范来推翻每个提议的无效化。未经证实的发现仍然不确定。如果证据仍有争议，小组检查其支持、测量效果和替代解释。审计器在复现之后运行，不向复现者提供反馈。

无效化标准和任务成功。 五个合格的违规类别区分：未测量而复制值、替换测量仪器、更改预期公式使用的操作数、根据观察值条件选择报告结果以及计算错误的统计量。无效化需要由局部化证据支持的合格违规、对测量的实质性影响以及失败的反驳。数值不匹配、崩溃的运行、硬件差异或没有局部化工件的怀疑不会自动满足这些条件。论文-代码差异根据相同的标准评估。

当任务的结果位于固定兼容区间（公式 1）内且未被主要审计器无效化时，任务成功；缺失或不兼容的结果失败。不确定的审计发现不计为无效化。第 4.6 节检查此评分规则对审计器的敏感性，并根据人工审查验证审计判断。

案例研究和定性分析使用第一次评估。在配对的任务-模型结果中，813 个原始失败变为成功，而 136 个逆转（图 5）。恢复包括 348 个数值不匹配、210 个因执行或资源障碍而未执行的任务（未运行）和 255 个审计无效的数值匹配。这些记录表明了两个互补的贡献：完成模糊或不完整的测量规范以及保存可执行流程以供复用。

完成和澄清测量规范。 在 Mixture of Concept Bottleneck Experts（De Santis 等，2026）中，多个树编辑距离的归约未指定，且已发布的代码缺少表 1 的收集器。Sonnet 5 的原始尝试将四个距离相加，报告 60 而不是 15。精炼工件通过指定每个表达式的均值并提供收集器来解决这一歧义；后续尝试报告 15。SCIQL 的已发布代码类似地将运行输出到表条目的映射留为不完整；精炼工件指定了输出字段以及跨标准和种子的聚合。这种澄清和实验到结果的映射共同占案例审查归因分布的约 35%。

恢复的配置变为可执行：HELIX。 对于 HELIX（Zhang 等，2026a），Opus 5 在原始代码上恢复了论文的架构，但保留了附带的批大小和学习率。精炼工件识别出与该架构匹配的存储库修订版本，将其记录为采用设置的来源，并通过启动器公开它们。后续尝试为两个示例任务产生了数值兼容的 MAE。指南记录了选择的证据，启动器使其可复用（附录 D.5）。

兼容的环境跨会话转移：WBMM。 对于 WBMM（Song 等，2026）中的六个 COCO 任务，Sonnet 4.6 的原始尝试未能为 H100 安装兼容的视觉库栈。精炼工件保存了依赖版本、构建先决条件和目标架构的源码构建路线。后续会话在没有代码补丁的情况下执行了所有六个任务；其框和掩码 AP 值在数值上与报告的目标一致。这个案例展示了环境修复如何成为可复用的安装流程（附录 D.5）。

修复已发布代码中的错误。 在 Effective Model Pruning（Wang 等，2026）中，已发布的加载器静默地将所有 10,000 张 TinyImageNet 验证图像标记为一类。在构建过程中，ReproBridge 添加了一个按真实标签组织图像的脚本和一个要求准备数据的启动器检查。在配对的 Gemini 3.8 Flash 运行中，ResNet-18 验证损失从原始代码的 8.898 变为精炼工件的 2.288，接近论文的 2.303。下游更改代码的模型-论文会话从 113/144 下降到 54/144，并且每个模型的首次计分执行中位时间都有所减少（图 5，右）。结合较低的 token 使用，这表明重建减少了。

明确的流程也帮助构建它们的模型。 更清晰的代码组织和明确的执行决策可以减少重复搜索和上下文需求，即使对于构建工件的模型也是如此。在 ETTFS（Che 等，2026）中，原始 Opus 5 尝试在 6,377 行 Python 中搜索发布中缺失的测量代码。精炼工件将添加的测量代码组织到专用的分析模块、排序训练和分析的启动器以及文档化的输出字段中。全新的 Opus 5 会话遵循此结构并完成了之前受阻的测量。

剩余的失败。 两种交付物共有的失败主要反映了论文-代码设置不匹配、论文中的排版错误或将测量置于兼容区间之外的实验变异性。精炼也可能保留或引入不正确的实验选择。从原始成功到精炼失败的 136 个逆转包括 84 个数值不匹配、31 个资源/访问失败、11 个审计无效匹配和 10 个执行障碍。AuxiliaryMCMC 和 LiME 分别占 50 和 14 个逆转，合计 47.1%。LiME 案例（Kowsher 等，2026）说明了未能完成训练和评估的尝试；AuxiliaryMCMC（Yuan 和 Wang，2026）说明了时间压力下的数值脆弱性、硬件敏感性和协议偏差（附录 D.3）。

4.7 重复复用可以抵消构建 API 成本

构建 36 个工件的 API 使用成本为 5,026 美元（每篇论文 139.61 美元）。按照表 3 中的平均下游成本，Sonnet 4.6、Sonnet 5 和 Opus 5 分别需要 8、13 和 9 轮复用才能达到收支平衡。每轮重复所有 36 篇论文；该场景将全部构建成本计入一个模型，保持价格和节省固定，并排除 GPU、审计和维护成本。相应的 API 节省分别为每完整复用轮次 653 美元、409 美元和 615 美元。更高的成功率伴随着这些节省，因此复用在逐步收回构建投资的同时改善了复现。附录 E 详细介绍了会计费率和收支平衡计算。

5 相关工作

科学信任与计算可复现性。 科学信任依赖于集体审查和可访问的证据（Oreskes，2019；Nosek 等，2015；Munafò 等，2017）；AI 辅助研究保留了这些要求（Messeri 和 Crockett，2024）。按照 ACM 术语，可复现性指独立执行作者的工件，而不是独立重新实现或按位相同的重放（美国计算机学会，2020；Peng，2011）。可复现性增强原则和 NeurIPS 可复现性计划促进明确的依赖、代码发布和报告清单（Stodden 等，2016；Pineau 等，2021）。

研究复现基准。 PaperBench 通过涵盖代码、执行和结果的专家评分标准评估重建（Starace 等，2025）；SciReplicate-Bench 也研究实现重建（Xiang 等，2025）。REPRO-Bench 和 ReplicationBench 将评估扩展到社会科学和天体物理学（Hu 等，2025；Ye 等，2025）。CORE-Bench 测试已发布的 Code Ocean 胶囊的执行及其输出相关问题（Siegel 等，2024）。ReproBridge-Bench 通过二元任务成功评估已发布的工件，将基于五次人工验证执行的变异性区间与独立完整性审计相结合。任务包括 GPU 训练和评估。表 4 在 CORE-Bench 的评分规则下比较交付物。

自动化复现与可复用经验。 PaperCoder 通过规划和代码生成构建存储库（Seo 等，2026）。AutoReproduce 从被引用的论文中恢复隐式细节并评估执行保真度（Zhao 等，2026b）。VERITAS 执行研究流程并产生修补的代码、修复记录和声明评估（Liu 等，2026a）；我们的外部比较测试其交付物的复用。Reflexion 保留言语反馈，而 Voyager 积累可执行技能（Shinn 等，2023；Wang 等，2023）。智能体原生研究工件编译器（ARA）（Liu 等，2026b）在其 PaperBench 研究中将论文和存储库与专家评分标准打包；模型评判者根据这些评分标准对复现进行评分。我们构建可运行的四组件交付物，无需评估评分标准或人工参考分数，并通过四次组件移除和普通输出对照评估其价值。

6 讨论与局限性

四个组件契约使复现经验可复用，ReproBridge-Bench 为评估提供已验证的参考分数。我们共同研究它们的作用；交付协议指导 ReproBridge 在构建过程中恢复和保存的内容。在第 2.1 节的表述中，目标是减少可避免的偏差 D，同时记录关于预期实验的不确定性。

6.1 提交前使用和后续复现者使用

主要预期用途是作者在提交论文和发布其工件之前应用 ReproBridge 作为可复现性检查。执行论文指定的设置可以暴露缺失的细节、执行障碍和论文-代码不一致，为作者提供在提交之前检查和纠正的具体问题。第三方复现者同样可以以相同的格式保存其工作，以降低后续尝试的成本。人类读者可以使用设置路线和启动器执行实验，然后检查指南和更改记录以评估设置和修复。我们的实验测量编码智能体的复用。

6.2 论文-代码不一致

当论文和已发布的代码冲突时，ReproBridge 严格遵循论文的设置，并标记差异以及来源位置和受影响的任务。例如，Manifold-Aware Perturbations 指南识别出论文中的学习率为 10^-4，而已发布代码中为 10^-3。此类记录帮助作者在上述提交前审查期间检查其手稿和实现之间的一致性。

一项独立的智能体辅助静态分析记录了 238 个涉及 669 个不同选定任务的范围内矛盾发现。矛盾需要明确的论文陈述和冲突的实现行为；缺失的实现和论文未提及的选择被单独记录。这些发现是执行偏差 D 的可能来源，但它们对测量性能的影响需要受控比较。它们既不是人工验证的错误率，也不是测量收益的解释。该分析独立于主要成功率评分，其记录未提供给被评估的复现者。附录 D.6 记录了范围、类别和证据。

6.3 局限性

评估以保留的论文、固定的参考区间和测试的智能体为条件；它不是会议范围的复现率。五个参考观测值是协议选择，不是充分不确定性估计的保证。数值兼容性不证明科学有效性或对所述实验的完全保真度，精炼工件可能保留不正确的假设。自动化审计也遗漏了一些违规，如根据人工验证量化的。

完整的工件干预包括上游调查、修复、审查和打包。普通输出和精炼工件在具有可比上游资源使用的独立运行中产生。该比较共同评估构建工作流和产生的交付物；它不隔离重新组织相同输出的效果。组件消融测量以剩余材料为条件的损失。案例注释和变异性分层描述模式而不是隔离因果效应。

API 节省涉及下游复现者会话。构建、独立验证、GPU 执行、维护和人工审查有单独的成本；复用估计假设固定的价格和节省。人类时间节省和理解需要单独的研究。

7 结论

ReproBridge 将恢复的复现流程和决策标准化为四个可复用组件：精炼代码库、环境设置、实验启动器和复现指南。ReproBridge-Bench 提供已验证的参考分数来评估其价值。复现成功共同取决于工件质量和复现者能力。所有四个评估模型使用精炼工件都达到 90% 以上的平均复现成功率，包括那些原始代码成功率较低的模型。跨模型成功率差距和下游 API 支出均有所下降。移除代码或环境设置造成最大的消融损失；在其他组件保留的情况下移除指南或启动器也会降低成功率。

未来的工作应该评估人类研究者的复用，并测量跨重复尝试构建、验证和维护工件的全部成本。

对于参考收集，人类验证者是负责复现实验和检查其执行证据的参与者。以下要求适用于第 2.3 节中的五名参与者；该角色与下游审计器的人工验证不同。

共同起点与独立执行。 每个验证者必须使用独立的服务器和相同固定原始存储库提交的新检出，以及论文、通用任务规范和授权的辅助工件。执行目录和编码智能体会话必须保持独立。验证者不得复用其他参与者生成的脚本或测量、构建的精炼工件或下游复现痕迹。发表的分数在论文中保持可见，但不能替代新计算的测量。

实验保真度与文档化修复。 在聚合参考测量之前，五名验证者执行的脚本、配置和报告程序进行了交叉验证，以确认执行遵循了论文指定的设置和通用任务定义。验证必须根据该设置检查任务的数据集和分割、预处理、模型配置、训练流程和评估指标，包括所需的硬件和数值精度，并检查已发布的实现以保持一致性。训练任务不能被检查点评估替代；当任务明确指定仅评估复现时，允许使用官方检查点。必要的环境或实现修复必须保留预期实验，并记录其理由和与起始提交的差异。重大歧义必须被文档化，而不是通过选择最匹配发表分数的解释来解决。

智能体辅助工作的人类责任。 编码智能体可以协助设置、调试和脚本准备。人类验证者必须检查实际执行的脚本和配置，包括智能体生成的编辑、数据加载、检查点选择和指标提取。验证必须将报告的值与产生它的计算联系起来，而不是仅依赖智能体的摘要、成功的退出代码或数值接近性。无法建立执行保真度的测量不得被接受为参考分数。
