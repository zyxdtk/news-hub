摘要
尽管近期的大语言模型（LLMs）在单个专利撰写任务上取得了可喜的成果，但它们从根本上未能研究现实世界专利撰写中的核心挑战：直接从早期发明材料生成完整且法律上连贯的专利申请。先前的工作主要假设输入为后期阶段、高度结构化或已经法律化的文本。然而，真实的专利工作流程始于发明人撰写的非正式、去法律化的披露。为了弥合这一差距，我们引入了 Dis2Pat，一个从披露到专利的数据集，该数据集要求直接从发明人风格的去法律化披露生成完整的专利申请，从而反映了真实的专利工作流程。鉴于长篇幅、受法律约束的专利撰写的固有困难以及严格的隐私要求，我们进一步提出了一个名为 Patent-MAF 的强基线。它是一个可本地部署的专利撰写多智能体框架。基准测试结果表明，当前的 LLMs 在专利撰写方面存在局限性，而 Patent-MAF 提供了一个强大的基线，其表现始终优于所评估的开源模型，并与大型闭源模型保持竞争力。

专利撰写是一个关键且昂贵的过程，它将发明人的技术思想转化为具有法律效力的文件，包括权利要求和详细的说明书 (European Patent Office, 2000)。权利要求定义了专利的法律范围，而说明书提供了发明及其具体实施例的全面描述，通常参考附图 (Jiang and Goetz, 2025)。尽管近期大语言模型（LLMs）的进展在单个专利撰写任务上取得了可喜的成果——例如权利要求生成 (Jiang et al., 2025d; Jiang et al., 2025a; Jiang et al., 2025b) 和说明书撰写 (Wang et al., 2024a; Yang et al., 2026; Shea and Yu, 2025)——但从早期发明材料生成完整的专利申请仍然是一个开放性问题。

现有基准与真实世界专利撰写工作流程之间的不匹配带来了一个关键挑战。在实践中，发明人通常提交非正式的发明披露，描述问题、核心思想、实施细节和说明性附图；专利律师然后将这些材料转化为法律结构的权利要求和说明书 (LLP, 2023)。然而，大多数先前的数据集和模型在后期阶段或高度结构化的输入上运行，例如用于权利要求生成的完整说明书 (Jiang et al., 2025d) 或用于说明书撰写的权利要求 (Wang et al., 2024a)。因此，当前系统的评估通常绕过了专利撰写中最具挑战性的方面：将发明人风格的披露转化为法律结构的专利申请。

最近的工作开始探索端到端专利生成，包括草稿转专利 (Wang et al., 2024b) 和论文转专利设置 (Knappich et al., 2025)。尽管这些方法更接近整体撰写，但它们的输入通常是以正式或技术风格撰写的，与真实的发明披露有很大不同。此外，尽管专利附图在传达具体实施例中的技术结构和特征方面发挥着核心作用，特别是在机械和面向系统的发明中，但大多数现有数据集要么省略了附图，要么仅以有限的方式包含它们 (Jiang et al., 2025d; Jiang et al., 2025a; Jiang et al., 2025b; Wang et al., 2024a; Shea and Yu, 2025)。多模态输入的作用在很大程度上未被充分探索。

在这项工作中，我们引入了 Dis2Pat，一个从披露到专利的数据集，针对更现实和实用的专利撰写场景。Dis2Pat 将去法律化、发明人风格的披露连同附图作为输入，并要求模型生成完整的专利申请，包括权利要求和完整的说明书。由于保密和法律限制，真实的发明披露不公开，我们通过受控的基于 LLM 的提取过程从授权专利中构建了伪披露。该过程保留了底层技术内容，但系统地删除了明确的发明特征结构、专利特定的法律语言和风格格式。

在 Dis2Pat 的基础上，我们提出了 Patent-MAF，这是一个多智能体专利撰写框架，旨在使用可本地部署的开源模型运行，其动机是现实世界专利撰写中固有的严格隐私和保密要求 (Shea and Yu, 2025)。在许多实际场景中，发明披露不能与外部 API 或专有服务共享，这使得本地模型部署成为必需。Patent-MAF 将专利生成分解为协调的角色：管理者智能体分析和构建披露以路由子任务，专门的撰写者智能体生成权利要求和说明书，最后由润色者智能体完善跨部分一致性、法律风格和整体连贯性。

主要贡献如下：
(1) 我们引入了 Dis2Pat，这是第一个用于披露到专利生成的数据集，其中包含发明人风格的披露以及相关的附图和专利文本。
(2) 我们提出了一个名为 Patent-MAF 的强基线，这是一个多智能体框架，它运行管理者智能体来构建披露并协调专门的撰写者智能体，同时配备润色者智能体来完善最终的专利文本。
(3) 我们对纯文本、多模态、开源和闭源 LLMs 进行了系统的基准研究。我们还表明，Patent-MAF 始终优于所有评估的开源模型，并实现了与最先进的闭源模型相竞争的性能。

2
相关工作

现有的专利生成工作大致可分为三个任务：以权利要求为中心的生成、说明书生成和端到端专利申请撰写（表 1）。

权利要求撰写。早期的研究主要集中在从短输入（如专利摘要）生成专利权利要求 (Lee and Hsiang, 2020; Lee, 2020)。随着语言模型最近变得更强大并支持更长的上下文长度，后续工作引入了大规模数据集，如 HUPD-DCG (Jiang et al., 2025d) 和 EPD (Jiang et al., 2025a)，以研究从完整专利说明书生成权利要求。这些研究强调了从冗长且高度技术性的输入中忠实恢复发明范围的困难。作为直接生成的补充，Patent-CR (Jiang et al., 2025b) 将权利要求修订制定为后编辑任务，将驳回的申请权利要求与授权的权利要求配对，以研究在真实的专利审查轨迹下具有法律意识的编辑。

说明书撰写。另一条研究路线将注意力转向专利说明书生成，这需要生成长篇幅、连贯且技术性的文本。PatentFormer (Wang et al., 2024a) 探索了以权利要求和附图说明为条件的说明书生成。后续工作进一步扩大了输入模态的范围：PatentVision (Yang et al., 2026) 大规模纳入了专利附图中的视觉信息，而 PatentDesc (Shukla et al., 2025) 研究了直接仅从附图生成说明书。AutoSpec (Shea and Yu, 2025) 研究了一个更受限制的设置，专注于仅从权利要求生成说明书。

专利申请撰写。除了单个组件之外，最近的一些数据集和任务还针对端到端专利撰写，其中系统从单个输入生成权利要求和说明书。Draft2Patent (Wang et al., 2024b) 制定了一个将专利草稿转化为完整专利申请的任务，而 Pap2Pat (Knappich et al., 2025) 研究了将科学文章转化为专利申请。Dis2Pat 专注于披露到专利的设置，其中输入由以非法律、发明人风格形式撰写的自然语言专利披露以及附图组成。此设置更接近现实世界的专利撰写工作流程，其中发明最初被非正式描述并由说明性附图支持，然后被转化为特征、法律结构的权利要求和说明书。

3
Dis2Pat 数据集

3.1
构建

源语料库。由于保密和法律限制，现实世界的发明披露无法公开获取。因此，无法直接构建大规模的披露到专利数据集。为了解决这一限制，我们在 LLMs 的帮助下从公开的授权专利中创建了一个伪披露数据集。我们提取了技术内容，系统地删除了专利特定的法律风格，并模糊了专利语言中以特征为焦点的风格。

在现实世界的专利撰写中，发明披露通常不仅包括文本描述，还包括传达核心技术思想的说明性附图。PatentDesc 数据集 (Shukla et al., 2025) 筛选了带有高质量附图的专利，最初设计用于附图到说明书的生成。因此，我们采用 PatentDesc 提供的专利公开号（专利申请公开时分配的唯一标识符）作为源语料库来构建我们的数据集。

过滤标准。我们首先从 PatentDesc 语料库中提取了所有公开号，并仅保留了授权专利。对于每个选定的专利，我们从 Google Patents Public Dataset 2

3.2
统计和质量分析

表 2 总结了我们数据集的语料库统计和质量分析。平均而言，每项原始专利包含 11,207 个 token，包括权利要求中的 1,594 个 token 和说明书中的 9,477 个 token，以及每份文档 6.7 张附图和 19.7 项权利要求。相比之下，相应的伪披露要简洁得多，平均长度为 1,196 个 token。这种减少反映了在保留核心技术内容的同时去除了专利特定的法律结构。Token 数量和技术术语密度（从 0.05 降至 0.001）的显著下降进一步表明，伪披露有效地消除了法律化和重复性的专利语言。

为了评估生成的伪披露的忠实度和质量，我们随机抽取了 100 个样本进行人工评估。专利专业人士从四个维度评估了每份披露：(1) 幻觉：披露包含专利不支持的程度。(2) 缺失细节：披露省略了专利中存在的基本技术信息的程度。(3) 矛盾：披露与专利相矛盾的程度。(4) 去法律化：披露在保持技术含义正确的同时，如何有效地删除法律化的专利语言。

所有评估得分均以十分制报告，数值越高表示质量越好。如表 2 所示，伪披露在所有指标上均取得了持续的高分，包括幻觉（9.8）、细节（9.8）、矛盾（10.0）和去法律化（9.7）。结果表明，基于 LLM 的重写过程在最小幻觉或不一致的情况下保留了事实和技术内容，并成功去除了专利特定的法律语言。为了进一步量化与源专利的表面形式差异，我们测量了词汇重叠。平均 ROUGE-L F1 为 0.08（最大值 0.11），而平均 4-gram 重叠为 0.006（最大值 0.013），这表明伪披露不是其源专利的词汇副本。

为了进一步检查这些评估的稳定性，我们使用 Cohen's d 测量了评估子集之间的效应量。具体来说，100 个验证样本被随机分为两组大小相等的组，得到的效应量约为 0.1，根据标准基准这对应于可忽略的效应。这种小的效应量表明样本间的得分变化很小，这为数据集的可靠性和稳健性提供了额外的证据。因此，Dis2Pat 为专利撰写阶段提供了一个受控且可扩展的代理。

4
Patent-MAF

我们提出了一个用于从发明披露生成专利权利要求和说明书的多智能体基线，即 Patent-MAF。图 1 说明了 Patent-MAF 的整体工作流程。该框架首先命令管理者智能体构建披露并协调专门的撰写智能体，随后由润色者智能体将生成的专利文本完善为连贯且法律一致的申请。

问题表述。设 D=(T,F) 表示一项专利披露，其中 T 是发明的去法律化文本描述，F 是一组相关的附图。目标是生成一份专利草稿 P=(C,S)，由权利要求集 C 和说明书 S 组成。

管理者智能体。管理者智能体作为框架的中央协调器。其角色是将原始披露 D 转化为结构化的撰写材料 M=(M_C, M_S)，分别针对权利要求撰写和说明书撰写进行定制。具体来说，管理者智能体产生两个结构化工件：(1) 权利要求撰写材料 M_C，强调法律上必不可少的特征和定义范围的元素；(2) 说明书撰写材料 M_S，强调技术背景、详细解释、实施例和对附图的参考。管理者智能体使用基于提示的推理和明确的输出模式来实现，以确保透明度和一致性。

撰写者智能体。Patent-MAF 使用专门的撰写者智能体来生成专利的不同组件，每个智能体独立运行，同时以管理者智能体的输出为基础。

权利要求撰写者智能体从 M_C 生成完整的专利权利要求集 C，包括至少一项独立权利要求和多项从属权利要求。鉴于权利要求撰写的高度形式化和法律约束性质，该智能体可以选择进行微调，以提高结构正确性和法律稳健性。

说明书撰写者智能体从 M_S 生成专利说明书 S，包括背景、概述和详细实施例。该智能体优先考虑技术清晰度和完整性，并遵循传统的专利风格叙述结构。

润色者智能体。独立生成的权利要求和说明书随后被传递给润色者智能体，其角色是全局完善而不是内容创建。具体来说，润色者智能体执行权利要求和说明书之间的术语统一，进行一致性检查以消除权利要求语言和描述性文本之间的不匹配，以及风格规范化以确保专业的专利写作基调。重要的是，润色者智能体不引入新的技术内容，而仅修改现有文本以提高连贯性、一致性和正确性。

开源模型要求。Patent-MAF 的一个核心设计要求是所有智能体都在可本地部署的开源语言模型上运行。这一要求是由现实世界专利撰写中固有的隐私和保密约束所驱动的，其中发明披露通常包含敏感技术信息，不能与外部 API 或专有服务共享。因此，在许多实际部署场景中，依赖闭源或云端托管模型的框架是不切实际的。

Patent-MAF 与先前的智能体专利系统的区别在于：(1) 隐私感知的本地部署：所有智能体都在开源模型上运行，没有任何对专有服务的 API 调用，这是现实 IP 实践中不可协商的约束；(2) 基于领域的角色分解：管理者、撰写者和润色者角色直接反映了专业专利审查中的劳动分工，而不是通用的任务分解；(3) 多模态基础：说明书撰写者启用了视觉功能，以解决附图中的空间和结构歧义。

实验

5.1
模型

我们在相同的解码配置下评估所有模型，以确保公平比较。实验细节在附录 C 中提供。

纯文本输入。我们与各种强大的 LLMs 进行了比较，包括 Qwen3-32B、Qwen3-VL-32B、Qwen3-VL-72B (Yang et al., 2025)、LLaMA-3.3-70B、LLaMA-3.2-90B-Vision (Grattafiori et al., 2024)、GPT-4o 和 GPT-5 (OpenAI, 2025)。这些模型直接从披露文本生成专利权利要求和说明书，而无法访问视觉信息。由于专利说明书长度极长，我们不针对说明书生成对模型进行微调。相反，专利权利要求要短得多，并受到严格的风格和结构约束，这使得它们适合于参数高效的微调。因此，我们对 Qwen3-32B 应用了 LoRA 微调 (Hu et al., 2022) 以生成权利要求，以提高法律一致性和结构规范化。

文本和图像输入。为了评估视觉信息的影响，我们额外评估了将披露文本和相关附图作为输入的多模态基线，包括 Qwen3-VL-32B、Qwen3-VL-72B、LLaMA-3.2-90B-Vision、GPT-4o 和 GPT-5。此设置反映了在生成过程中纳入附图的最近多模态专利撰写方法。

我们的方法。Patent-MAF 采用多智能体撰写框架，其中不同的智能体由特定任务的模型实例化。我们实现了负责披露结构化和任务路由的管理者智能体，以及负责全局一致性和风格完善的润色者智能体，两者均基于带有提示的 Qwen3-32B。对于内容生成，我们使用两个专门的撰写者智能体：说明书撰写者基于 Qwen3-VL-32B，以处理文本披露和相关附图，而权利要求撰写者基于经过微调的 Qwen3-32B，以更好地捕捉专利权利要求的严格风格惯例。Qwen3-32B-FT 基线使用与 Patent-MAF 权利要求撰写者完全相同的微调检查点；区别在于直接生成与完整的智能体工作流程。在初步实验中，我们观察到视觉输入对权利要求撰写的好处有限，因为权利要求主要编码的是抽象的法律范围，而不是具体的视觉结构。因此，我们决定在生成权利要求时仅使用文本输入。

(iii) w/o polisher，省略了最终的一致性和风格完善阶段。

5.2
评估指标

我们结合自动指标、LLM 作为评判者的质量评估和专家人工评估来评估生成的专利说明书和权利要求。

文本重叠指标。我们报告了专利说明书和权利要求的 BLEU (Papineni et al., 2002)、ROUGE-1 (R-1) 和 ROUGE-L (R-L) (Lin, 2004)，以衡量与相应黄金参考的表面级词汇重叠。

语义相似度指标。为了评估词汇重叠之外的语义对齐，我们额外报告了说明书和权利要求的 BERTScore (Zhang et al., 2019) 和 BERT-for-Patent 嵌入相似度 (Chikkamath et al., 2022)。

基于 LLM 的内容质量评估。我们进一步使用 LLM 作为评判者的方法 (Li et al., 2025) 评估内容质量。对于说明书和权利要求，我们设计了特定任务的评估提示，将生成的输出与黄金参考进行比较，并按 0-100 分制打分，分数越高表示质量越好。详细的提示在附录 D 中报告。

对于说明书，评估侧重于：(1) 完整性（技术背景、问题表述、核心解决方案、实施细节和实施例是否得到充分覆盖）；(2) 逻辑清晰度（结构连贯性和技术流程）；以及 (3) 法律质量（遵守专利撰写规范）。对于权利要求，评估强调：(1) 技术范围（候选权利要求是否捕捉到了黄金权利要求的核心发明概念）；(2) 权利要求合法性（符合专业权利要求撰写标准）；以及 (3) 逻辑清晰度（技术清晰度和明确的术语）。

专家人工评估。为了补充自动评估，我们对 60 个随机抽样的测试用例进行了专家人工评估。为了降低标注成本并仍实现高评估可靠性，我们采用成对比较协议而不是绝对评分。对于每个样本，专利专家会看到两个系统的输出，并被要求决定哪个更好。比较侧重于第一项独立权利要求和描述该发明的选择性说明书段落。专家根据专利审查中常用的四个标准对每一对进行判断：完整性、清晰度、合法性以及权利要求和说明书之间的一致性。附录 E 介绍了人工评估的细节。我们进一步在附录 D 中报告了自动评估和专家判断之间的一致性，以结合背景说明自动评估的可靠性。

6.2
权利要求生成结果

表 4 报告了不同模型在专利权利要求生成方面的性能。

视觉输入的影响。总体而言，在权利要求生成中纳入视觉输入并未带来性能提升。例如，Qwen3-VL-32B 的总分从 78.9（纯文本）略微下降到 78.6（文本+图像），而 Qwen3-VL-72B 从 80.7 略降至 79.8。GPT-5 也观察到类似趋势，当启用视觉输入时，其总分从 91.1（纯文本）下降到 90.7（文本+图像）。这种趋势也延伸到文本重叠和语义相似度指标。结果表明，与说明书撰写不同，专利权利要求生成主要依赖于发明范围和法律结构的精确文本建模，附图没有明显的好处。

Patent-MAF 的优势。Patent-MAF 在所有评估的开源系统中取得了最强的整体性能，总体质量得分为 86.7。尽管闭源 GPT-5 达到了 91.1 的最高总体质量得分，但 Patent-MAF 实现了更高的语义相似度，BERTScore 为 88.3，而 GPT-5 为 83.8；BERT-for-Patent 得分为 96.4，而 GPT-5 为 95.9。结果表明，所提出的多智能体框架显著缩小了性能差距，并显示出与特定领域的权利要求语义的强烈对齐。

消融研究。消融结果进一步说明了 Patent-MAF 中各个组件的贡献。移除管理者智能体会将总分从 86.7 降低到 84.2，这突出了结构化披露组织对于定义权利要求范围的重要性。移除微调使总分降低了 5.1 分（86.7 降至 81.6），这证实了特定任务训练对权利要求撰写的重要性。移除润色者导致了最大的退化，下降了 6.6 分（86.7 降至 80.1），这突出了其在法律一致性和风格正确性方面的作用。

6.3
总体结果

结果揭示了权利要求生成和说明书撰写的不同行为。说明书撰写从多模态输入和全局一致性完善中受益更多，这导致完整性和清晰度的显著提高。相比之下，权利要求生成对精确的文本建模和遵守法律惯例更为敏感，其中特定任务的微调发挥着更核心的作用。

图 2 展示了成对专家评估的结果，其中标注者使用第一项独立权利要求和描述核心发明的说明书段落，将 Patent-MAF 与四个强基线（Qwen3-32B、Qwen3-VL-72B、LLaMA-3.2-90B-Vision 和 GPT-5）进行比较。针对所有开源基线，Patent-MAF 在所有四个标准（完整性、清晰度、合法性和一致性）的大多数情况下都更受青睐。结果表明，所提出的智能体框架在超越单次生成的专利撰写中是有效的。

与 GPT-5 的比较显示出不同的模式。GPT-5 在完整性、清晰度和合法性方面更常受青睐，而两个系统在一致性方面势均力敌。同时，很大比例的平局表明 Patent-MAF 仍然与 GPT-5 具有竞争力，特别是在保持跨部分一致性方面。因此，即使与最先进的闭源模型相比，显式的任务分解和完善似乎对于确保全面的覆盖和保持权利要求与说明书之间的连贯性特别有益。更多结果（包括定性分析）在附录 F 中介绍。

7
结论

我们引入了 Dis2Pat，这是第一个旨在对现实的披露到专利撰写进行建模的数据集。我们提出 Patent-MAF 作为一个强大的基线，这是一个为可本地部署的开源模型优化的多智能体框架。通过消除对外部 API 的依赖，Patent-MAF 保护了敏感的发明披露。该框架将撰写过程分解为协调的角色：管理者智能体分析披露并路由子任务；专门的撰写者智能体生成权利要求和说明书；润色者智能体完善输出以实现跨部分一致性和法律连贯性。总体而言，结果将 Dis2Pat 确立为披露到专利撰写的挑战性基准，并表明我们的多智能体框架是一个强大的可本地部署基线。

局限性

尽管取得了可喜的结果，这项工作有几个局限性，为未来的研究指明了方向。由于保密和法律限制，Dis2Pat 依赖于通过受控的基于 LLM 的提取和重写从授权专利生成的伪披露。尽管我们仔细约束了重写过程，并通过自动和专家评估验证了披露质量，但这些伪披露可能无法完全捕捉发明人提交的现实世界发明披露中存在的多样性、不完整性或模糊性。未来的工作可以探索与行业或律师事务所的合作，以研究匿名或部分合成的披露。此外，Patent-MAF 主要在英语专利上进行评估。将该框架适应多语言或特定司法管辖区的专利撰写标准（例如 EPO 或 CNIPA）是一个自然的延伸。我们在推理过程中不进行超参数调整；相反，我们在所有实验中保持超参数固定，以确保公平比较。

附录 A
专利背景

专利文件是保护知识产权（IP）和交流技术创新的主要机制。它们通过明确授予专利所有人的专有权范围，提供了发明的法律效力表示。在公开或授权后，专利变得可公开获取，并构成法律实践和科学研究的关键技术披露来源。

尽管格式上存在司法管辖区的差异，但专利文件通常遵循标准化结构。核心要素通常包括标题、书目信息、分类代码、现有技术引用、摘要、说明性附图、详细描述（说明书）和一组权利要求。在这些组件中，权利要求通过精确划定专利保护的范围而具有法律效力，而说明书提供支持性的技术细节、实施例和上下文解释，以确立和解释权利要求。

从自然语言处理（NLP）的角度来看，专利提出了独特的挑战。先前的工作 (Jiang and Goetz, 2025) 强调，与专利相关的任务要求模型在跨越多个部分和视觉元素的极长上下文中进行推理，准确解释高度专业和技术性的语言，并保持法律要求所规定的严格精确性和内部一致性。这些因素使得专利撰写比典型的文本生成任务复杂得多，从而推动了专门建模和评估方法的开发。最近关于专利 NLP 或 LLMs 的研究包括分类 (Jiang et al., 2026a; Yoo et al., 2025b)、新颖性预测 (Knappich et al., 2026)、生成 (Jiang et al., 2026b; Yoo et al., 2026a)、质量评估 (Song et al., 2026)、评估 (Zuo et al., 2024; Yoo et al., 2025a; Yoo et al., 2026c; Jiang et al., 2025c; Yoo and Pan, 2026; Yoo et al., 2026b)。

关于统计分析，我们在比较 Patent-MAF 与基线的所有自动指标上进行了配对 t 检验。所有报告的改进在统计上都是显著的（p < 0.05）。

F.3
计算开销
关于计算开销，Patent-MAF 产生的 token 使用量大约是单次基线的 2.5 倍，由于管理者和润色者智能体的中间推理步骤，延迟也按比例增加。

F.4
定性分析
我们识别出三种主要的错误模式。首先，管理者路由遗漏：当管理者未能从披露中提取关键技术特征时，下游的撰写者智能体会生成不完整的权利要求或说明书，而执行一致性而非完整性检查的润色者无法恢复丢失的信息。其次，跨部分术语不一致：由于权利要求和说明书撰写者独立运行，他们偶尔会对同一对象使用不同的术语；润色者成功解决了大多数此类情况，但当不一致跨越长上下文时，残留的不匹配仍然存在。第三，纯文本生成中的空间描述错误：当缺少附图信息时，说明书撰写者有时会错误识别组件；启用视觉的撰写者通过将描述建立在附图基础上来解决这些问题，这为多模态整合提供了具体的理由，尽管其总体收益微乎其微。
