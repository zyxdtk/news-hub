Block开源Berd：AI智能体的桌面工作台

中文摘要： Block公司宣布开源Berd，一款专为AI智能体设计的桌面优先工作台。Berd支持跨多个模型和框架（如Goose、Claude Code等），提供持久化项目、本地优先数据存储及可视化智能体身份。它采用Apache 2.0许可，免费且支持多平台。Berd定位为智能体编排层而非运行时，强调操作状态可见性与数据可移植性。未来Block计划将其单人体验融入多人协作平台Buzz中。

Block，这家由前 Twitter CEO Jack Dorsey 创立的科技公司（旗下拥有 Square、Cash App 和音乐流媒体服务 Tidal），正在开源 Berd。这是一款桌面应用程序，最初是为公司员工构建的，旨在为跨不同模型、工具和项目使用 AI 智能体提供统一环境。

Berd 是一款本地安装的图形化桌面应用程序，而非基于浏览器的工作区。它现在已在 GitHub 上提供，采用宽松的 Apache 2.0 许可证——这意味着任何人都可以使用、修改和重新分发它，包括用于商业用途——并提供适用于 macOS、Windows 和 Linux 的免费可下载构建版本。该代码库于 8 月 18 日更新至 0.6.2 版本，这是其第七次公开发布，目前列有 91 位贡献者。

“Berd 是桌面优先的，因为其大部分价值来自于直接处理项目、本地文件、工具、代码库以及运行在用户计算机上或与用户计算机连接的智能体，”Block 人工智能能力负责人 Brad Axen 在回复 VentureBeat 的电子邮件中表示。

AI 智能体的日常工作台

Block 将 Berd 定位为“日常 AI 工作台”：用户可以在一个统一的地方发起聊天、附加文件或文件夹、选择智能体和模型、在持久化项目中工作、配置 AI 提供商、管理技能和扩展、查看会话历史记录以及构建自动化流程。

其设计目标不仅仅是为了方便。根据 Berd 的产品规范，用户应始终能够辨别哪个项目、文件、智能体、模型、提供商和会话状态正在积极影响当前的对话。Block 表示，这种对可见操作状态的强调，正是 Berd 与普通聊天机器人封装工具的区别所在。配置——包括提供商、扩展、技能、自动化和项目——被视为工作流的一部分，而不是被埋没在管理层中；界面设计旨在清晰地暴露故障、不可用的提供商以及加载和流式传输状态，而不是用助手式的友好界面来掩盖它们。

Berd 源于 Block 内部的一个实际问题。员工们已经在使用功能强大的智能体——Block 自家的 Goose、Anthropic 的 Claude Code 和 OpenAI 的 Codex——但围绕这些智能体的体验已经变得碎片化。

“我们通过 Goose、Claude Code 和 Codex 拥有了强大的智能体，但在它们之间进行切换意味着要适应不同的界面、配置系统和上下文管理方式，”Block 技术通讯部门的 Lucinda Bell 在一封电子邮件中表示。她说，Berd 为 Block 的团队提供了“一个跨模型和底层框架一致的桌面应用程序”。

对于企业而言，这一层的重要性可能不亚于模型能力的又一次渐进式提升。持久化项目意味着用户可以返回到已建立的文件、指令和智能体配置集合中，而无需为每个任务重新构建上下文。Block 还明确设计 Berd，旨在让工程领域之外的人员也能使用智能体工作，让人们从简单的对话开始，并根据工作需要添加工具、上下文和结构。

Block 并未将 Berd 定位为移动端产品。Axen 表示，公司的开源协作平台 Buzz 已经提供了移动端体验，是 Block 首选的移动办公环境。

Block 认为智能体不同，外观也应不同

对于大多数企业 AI 产品都未明确解决的问题——用户如何区分一个已配置的智能体和另一个，Berd 采取了一种不同寻常的方法。

Berd 没有将每个智能体视为另一个空白的聊天窗口，而是赋予了它们角色、指令、技能、工具和可识别的视觉身份。Block 创建了一系列动画角色集合——其旗舰设计被称为“Gloopies”——Berd 的官方网站展示了预定义的角色，如 Berdy、Pushback、Choosey、Copycat、Tinker 和 Wildcard，每个角色都围绕不同的工作风格构建：Pushback 在草稿中扮演魔鬼代言人的角色，Choosey 帮助缩小决策范围，Copycat 学习以用户的风格进行写作。

视觉层并不意味着用个性取代实质。Block 在一篇关于 Berd 设计的公司博客文章中给出了功能性表述：“头像使智能体具有辨识度。它的角色、技能和工具使其发挥作用。”

Berd Gloopies 截图。图片来源：Block

当员工同时处理多个专业智能体时，这种区分可能会变得更加重要。可识别的身份充当了原本不可见的指令、工具和权限包的可见简写——智能体以独特的动画角色形式出现在工作区中，而不是聊天列表中相同的条目，因此用户可以在打开对话之前区分它们。

产品规范防止这些角色使 Berd 沦为新奇事物。它将预期的个性描述为“专注、有能力、友好陪伴”，同时明确拒绝了玩具般的呈现方式、过大的装饰性 UI 以及用友好界面隐藏操作状态的界面设计。

编排层，而非另一种模型或智能体运行时

在架构上，Berd 既不是新的基础模型，也不是新的智能体运行时。该应用程序使用 Tauri 2 和 React 19（用于使用 Web 技术构建轻量级桌面应用程序的框架）构建，并通过名为代理客户端协议（ACP）的标准与 Block 于 2025 年 1 月推出的开源智能体框架 Goose 进行通信。Goose 作为捆绑的“边车”进程在 Berd 旁边静默运行，并处理底层的智能体循环；Berd 则在其上处理项目、会话、上下文、智能体和配置。

对于不熟悉 Goose 的读者来说，它是一个与模型无关的智能体框架和运行时，最初专注于软件开发工作流。它将大型语言模型连接到文件、命令和外部系统——包括通过模型上下文协议（MCP），这是一种将 AI 系统连接到外部工具和数据的开放标准——从而使智能体能够采取行动，而不仅仅是生成文本。

Goose 可与专有模型提供商以及本地运行的开源模型配合使用。Block 后来将 Goose 捐赠给了 Agentic AI Foundation，这是 Block 于 2025 年 12 月与 Anthropic、OpenAI 等公司共同协助建立的 Linux 基金会下属机构，为该框架以及 MCP 提供了一个与供应商无关的家。

Axen 明确划定了界限：像 Goose、Claude Code 和 Codex 这样的智能体框架管理模型、其上下文和工具之间的循环，而 Berd 在这些框架周围提供一致的桌面环境。在公开发布的版本中，用户可以配置他们想要的任何提供商和框架，而不是继承 Block 选择的模型堆栈。

该项目的 README 添加了一个对评估该软件的人来说很重要的操作细节：Berd 不会简单地拉取碰巧是最新的 Goose 构建版本。它的构建过程通过锁文件固定了特定的 Goose 后端版本，验证缓存二进制文件与该固定版本匹配，并将其与应用程序打包在一起。开发人员可以明确替换另一个 Goose 二进制文件以进行本地测试。对于检查 Berd 的组织来说，这在桌面应用程序及其默认智能体后端之间创建了一个明确的版本边界，而不是让后端默默漂移。

Berd 与 Codex、Claude Code、Cursor 和 Goose 的比较

这种分离很重要，因为智能体工具市场已经在向管理日益自主的 AI 工作者的产品汇聚。OpenAI 将其 Codex 应用程序描述为智能体的“指挥中心”，具有独立的项目线程和并行运行的多个智能体。Anthropic 的 Claude Code 是一个用于读取代码库、编辑文件和执行命令的智能体，现在横跨终端、IDE 和桌面应用程序。Cursor 将其最新版本 Cursor 3 描述为带有智能体的软件开发统一工作区，包括本地和云端智能体之间的交接以及多代码库工作流。而 Goose 本身仍然可以直接使用，作为面向技术熟练用户的免费命令行工具和桌面应用程序。

因此，Berd 的差异化不在于发明智能体工作区，而在于使该工作区开源、支持多框架并在编码之外具有潜在用途。下表中的其他所有产品要么绑定于单一供应商的模型，要么定价为订阅制，要么完全针对开发者——在大多数情况下，这三者兼有。

可移植性是 Block 宣传的一部分。Axen 表示，Berd 中大部分底层工作被刻意保持可移植：文件夹、Git 代码库、文件和纯文本指令在应用程序之外仍然可以访问；技能是基于文件的；Berd 智能体可以在 Berd 用户之间导出和共享，并保持其指令和设置完整。

他指出，ACP 和 MCP 是 Block 致力于“尽可能采用清晰、用户拥有的格式和开放协议”方向的一部分。这并不能使每种状态在每个框架之间都可以互换，但它使可移植性成为明确的架构目标，而不仅仅是使用本地文件的副作用。

本地优先数据、遥测和企业分发

Berd 围绕本地优先的数据模型设计。Axen 表示，对话历史记录存储在用户设备的本地 Goose 会话数据库中，而凭据默认存在于操作系统密钥链中。

这并不意味着所有 AI 处理都在本地进行。“本地优先并不意味着没有数据会离开设备，”Axen 说。当用户要求配置的模型处理特定上下文时，相关的提示和材料会被发送到该模型的提供商——因此，实际的数据路径以及管理它的合同条款取决于组织选择的提供商。

遥测——软件发送回其制造商的使用数据——在官方 Berd 分发版中默认禁用。如果用户选择加入，Block 表示它会收集一个随机安装标识符和一组有限的预定义使用事件，同时从遥测负载本身中排除提示、消息、文件、源代码、凭据、姓名、电子邮件地址和 IP 地址（Block 及其服务提供商仍会处理 IP 地址以进行传输、安全和速率限制）。用户可以在设置中再次关闭遥测。Block 警告说，第三方分支可以修改或重定向遥测系统，因此评估自定义构建版的企业需要审查该构建版的实际行为，而不是假设 Block 的默认设置会延续。

公共代码库构建了一个独立、通用的分发版，不依赖于私有包注册表或企业凭据——技术团队无需访问 Block 的基础架构即可构建和评估它。但 Block 也创建了所谓的“分发接缝”：定义的节点，组织可以在这些节点上覆盖受管理的提供商设置、私有智能体、运行时配置、可选的配套工具、自己的更新渠道以及自己的签名和发布基础架构，所有这些都无需将私有材料添加到公共源代码树中。

Block 自己的部署展示了企业如何围绕该架构实施治理。Axen 表示，Block 在批准的设备上使用批准的模型提供商基础架构、受管理的配置和受控的工具连接来运行其托管分发版。“应用程序可以保持开放和可检查，而组织可以决定哪些模型、工具、权限和策略适合其环境，”他说。

一个注意事项：“企业分发”不应被理解为完整的企业管理平面。README 没有描述诸如单点登录、集中强制执行的管理员策略、组织范围的权限控制、数据保留规则或审计日志等功能。它确立了公司可以自定义和分发 Berd；它本身并没有解释这些安装在部署后如何进行集中治理。Berd 应被理解为安装在用户计算机上的端点软件，而不是集中托管的 SaaS 产品。

定价、模型和封闭的贡献模式

Block 尚未公布 Berd 的订阅价格，也没有迹象表明即将推出。这并不意味着使用智能体是零成本的：组织仍需支付其产生的任何模型、API 或提供商费用。Berd 网站上的经济宣传点是灵活性——用户可以根据工作匹配模型，而不是为每个任务支付昂贵的前沿模型。正如网站所言：“有些任务需要大智慧。大多数不需要。”

Block 的公告和 README 都没有提供支持模型提供商的确切矩阵，也没有推荐特定模型。在内部，Block 不会将任何一个模型视为永久的默认选项：Axen 表示，公司的托管分发版向员工展示了“精心挑选的前沿模型和开放权重模型的组合”，并且目录会随着模型的改进而改变。“最佳选择取决于工作，”他说。

开发人员还应注意一个治理上的区别。尽管 Berd 的源代码是公开的，并且 Block 征求问题和反馈，但该代码库不接受外部拉取请求——外部代码贡献会自动关闭。

README 说 Berd 由“Block 的一个小团队”构建，并引导外部参与者提交格式良好、可重现的错误报告。用户可以自由检查、构建和派生代码，但 Block 保留了严格控制的上游。对于将 Berd 视为基础架构而非实验的公司来说，这使得 Block 的长期维护和支持计划值得澄清。

Block 今天并没有将 Berd 作为创收产品推出。Axen 表示，第一笔投资回报来自 Block 自己对该软件的使用——使内部智能体工作更加一致，同时让公司了解员工实际如何使用智能体——开源它增加了杠杆作用，让外部人员可以检查、调整并对架构提供反馈。围绕企业部署的商业层可能最终会跟进。

“支持希望在工作中部署智能体的组织是我们感兴趣的领域，”Axen 说，并补充道，当有更多内容可以分享时，Block 会分享更多。

从私人智能体工作到多人工作流

Berd 提供个人桌面体验；另一个 Block 项目 Buzz 则专注于共享房间，人员和智能体可以在其中针对共同的、可搜索的记录进行协作。

Buzz 是 Block 为人类和 AI 智能体提供的免费、Apache 2.0 许可的协作工作区。它建立在去中心化的 Nostr 协议之上，将熟悉的团队功能——频道、线程、直接消息、语音和媒体共享——与拥有自己加密身份和定义权限的智能体结合在一起，这些智能体可以参与对话、代码审查和批准的自动化工作流。与 Berd 的本地单用户焦点不同，Buzz 明确是多人参与的，可以自托管或通过 Block 托管的基础架构使用。它同样是与模型和框架无关的：团队可以引入由 Goose、Claude Code、Codex 或其他工具驱动的智能体。

Axen 将这两款产品之间的部分区别界定为信任边界问题。“本地智能体可能有权访问您的文件系统和凭据，”他说。“共享 Buzz 房间中的智能体拥有自己的身份，并通过中继器进行范围访问。”Berd 从一个人和对该人机器的比较特权访问开始；Buzz 从多个参与者、明确身份和共享工作区权限开始。

更重要的路线图细节是，Block 并不打算让这两款产品保持独立。“展望未来，我们的重点是 Buzz，我们计划将 Berd 单人体验中最优秀的部分融入其中，”Axen 说。Block 希望工作从私下开始，并在用户不切换工具或重建上下文的情况下变得协作，跨设备连续性——包括通过 Buzz 实现的移动端——是这一雄心的一部分。Axen 表示，与此同时，Berd 仍作为开源桌面应用程序提供，但 Buzz 是 Block 鼓励人们下载和改编的产品。

企业采用者应了解的内容

对于 IT 和安全团队的简短版本：默认情况下，对话历史记录保留在本地；凭据使用操作系统密钥链；发送给模型的上下文会根据配置的提供商提供的条款离开机器；官方遥测默认关闭，并排除提示、文件和源代码；组织可以打包自己受管理的分发版——尽管中央管理工具尚未记录在案。

此次发布背后更大的想法可能更重要。模型和编码智能体正在成为更大工作流中日益可互换的组件。Berd 押注于周围的上下文——项目、技能、工具、身份和持久的工作环境——将成为稳定的层。
