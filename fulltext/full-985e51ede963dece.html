今天，我们在 ChatGPT（作为 GPT‑5.4 Thinking）、API 和 Codex 中发布了 GPT‑5.4。这是我们针对专业工作最强大、最高效的前沿模型。我们还在 ChatGPT 和 API 中发布了 GPT‑5.4 Pro，供那些在复杂任务上需要最高性能的用户使用。

GPT‑5.4 将我们最近在推理、编码和智能体工作流方面的最佳进展整合到一个前沿模型中。它融合了 GPT‑5.3‑Codex⁠ 业界领先的编码能力，同时改进了模型在工具、软件环境以及涉及电子表格、演示文稿和文档的专业任务中的工作方式。其结果是，该模型能够准确、有效且高效地完成复杂的实际工作——以更少的反复沟通提供您所要求的结果。

在 ChatGPT 中，GPT‑5.4 Thinking 现在可以预先提供其思考计划，因此您可以在它工作时在响应中途调整方向，并在无需额外轮次的情况下获得更符合您需求的最终输出。GPT‑5.4 Thinking 还改进了深度网络研究，特别是对于高度具体的查询，同时在需要更长思考时间的问题上更好地保持上下文。这些改进综合起来意味着更高质量的答案，到达速度更快，且与手头任务更相关。

在 Codex 和 API 中，GPT‑5.4 是我们发布的第一个具有原生、最先进计算机使用能力的通用模型，使智能体能够操作计算机并跨应用程序执行复杂的工作流。它支持高达 1M token 的上下文，允许智能体在较长的时间跨度内规划、执行和验证任务。GPT‑5.4 还通过工具搜索改进了模型在大型工具和连接器生态系统中的工作方式，帮助智能体更高效地查找和使用正确的工具，而不会牺牲智能。最后，GPT‑5.4 是我们迄今为止token 效率最高的推理模型，与 GPT‑5.2 相比，解决问题所需的 token 显著减少——这意味着 token 使用量减少和速度提升。

结合通用推理、编码和专业知识工作的进步，GPT‑5.4 在 ChatGPT、API 和 Codex 中实现了更可靠的智能体、更快的开发者工作流和更高质量的输出。

知识工作

在 GPT‑5.2 通用推理能力的基础上，GPT‑5.4 在对专业人士至关重要的现实任务上提供了更加一致和精细的结果。

在 GDPval⁠（测试智能体在 44 个职业中产生明确规范的知识工作能力）上，GPT‑5.4 达到了新的最先进水平，在 83.0% 的比较中匹配或超过了行业专业人士，而 GPT‑5.2 为 70.9%。

在 GDPval 中，模型尝试从对美国 GDP 贡献最大的 9 个行业中跨越 44 个职业的明确规范的知识工作。任务要求真实的工作产品，例如销售演示、会计电子表格、紧急护理时间表、制造图表或短视频。GPT‑5.4 的推理努力设置为 xhigh，GPT‑5.2 设置为 heavy（ChatGPT 中略低的级别）。

计算机使用和视觉

GPT‑5.4 是我们第一个具有原生计算机使用能力的通用模型，标志着开发者和智能体迈出了重要一步。它是目前可供构建在网站和软件系统中完成真实任务的智能体的开发者使用的最佳模型。

我们将 GPT‑5.4 设计为在各种计算机使用工作负载中表现出色。它非常擅长通过 Playwright 等库编写代码来操作计算机，以及响应截图发出鼠标和键盘命令。其行为可通过开发者消息进行引导，这意味着开发者可以调整行为以适应特定的用例。开发者甚至可以通过指定自定义确认策略来配置模型的安全行为，以适应不同的风险容忍度。

该模型的性能和灵活性反映在测试不同环境下计算机使用的基准测试中。在 OSWorld-Verified（衡量模型通过截图和键盘/鼠标操作在桌面环境中导航的能力）上，GPT‑5.4 达到了最先进的 75.0% 成功率，远超 GPT‑5.2 的 47.3%，并超越了 72.4% 的人类表现。1

在 WebArena-Verified（测试浏览器使用）上，GPT‑5.4 在同时使用 DOM 和截图驱动的交互时达到了领先的 67.3% 成功率，而 GPT‑5.2 为 65.4%。在 Online-Mind2Web（同样测试浏览器使用）上，GPT‑5.4 仅使用基于截图的观察就达到了 92.8% 的成功率，优于 ChatGPT Atlas 的 Agent Mode（成功率为 70.9%）。

GPT‑5.4 改进的计算机使用建立在模型改进的通用视觉感知能力之上。在 MMMU-Pro（测试模型的视觉理解和推理）上，GPT‑5.4 在不使用工具的情况下达到了 81.2% 的成功率，优于 GPT‑5.2 的 79.5%。改进的视觉感知也转化为更好的文档解析能力。在 OmniDocBench 上，未设置推理努力的 GPT‑5.4 的平均误差（通过模型预测与真实值之间的标准化编辑距离测量）为 0.109，比 GPT‑5.2 的 0.140 有所改进。

我们还在改进对保真度至关重要的密集、高分辨率图像的视觉理解。从 GPT‑5.4 开始，我们引入了 original 图像输入细节⁠(opens in a new window)级别，支持高达 10.24M 总像素或 6000 像素最大尺寸（以较低者为准）的全保真感知；high 图像输入细节级别现在支持高达 2.56M 总像素或 2048 像素最大尺寸。在与 API 用户的早期测试中，我们观察到在使用 original 或 high 细节时，定位能力、图像理解和点击准确性有显著提升。

编码

GPT‑5.4 结合了 GPT‑5.3‑Codex 的编码优势以及领先的知识工作和计算机使用能力，这在长时间运行的任务中最为重要，模型可以在这些任务中使用工具、迭代并在较少的手动干预下推进工作。它在 SWE-Bench Pro 上匹配或优于 GPT‑5.3‑Codex，同时在各种推理努力下延迟更低。

我们通过查看模型的生产行为并离线模拟来估计延迟。延迟估计考虑了工具调用持续时间（代码执行时间）、采样 token 和输入 token。实际延迟可能差异很大，并取决于我们模拟中未捕获的许多因素。推理努力从 none 扫描到 xhigh。

开启后，Codex 中的 /fast 模式使用 GPT‑5.4 可提供高达 1.5 倍的 token 速度。它是相同的模型和相同的智能，只是更快。这意味着用户可以在保持心流的状态下完成编码任务、迭代和调试。开发者可以通过使用优先处理⁠(opens in a new window)在 API 中以同样快的速度访问 GPT‑5.4。

在评估和内部测试中，我们发现 GPT‑5.4 擅长复杂的前端任务，其结果比我们以前发布的任何模型都更具美感和功能性。

作为模型改进的计算机使用和编码能力协同工作的演示，我们还发布了一个名为“Playwright (Interactive)⁠(opens in a new window)”的实验性 Codex 技能。这允许 Codex 以可视化方式调试 Web 和 Electron 应用程序；它甚至可以用来测试它正在构建的应用程序，就在它构建的时候。

工具使用

借助 GPT‑5.4，我们显著改进了模型与外部工具的协作方式。智能体现在可以在更大的工具生态系统中运作，更可靠地选择正确的工具，并以更低的成本和延迟完成多步骤工作流。

工具搜索

在 API 中，GPT‑5.4 引入了工具搜索⁠(opens in a new window)，允许模型在给定许多工具时高效工作。

以前，当为模型提供工具时，所有工具定义都预先包含在提示中。对于拥有许多工具的系统，这可能会向每个请求添加数千甚至数万个 token，增加成本、减慢响应速度，并用模型可能永远不会使用的信息挤占上下文。

借助工具搜索，GPT‑5.4 会收到一个轻量级的可用工具列表以及工具搜索功能。当模型需要使用工具时，它可以查找该工具的定义并在那一刻将其附加到对话中。

这种方法显著减少了工具密集型工作流所需的 token 数量并保留了缓存，使请求更快、更便宜。它还使智能体能够可靠地处理更大的工具生态系统。对于可能包含数万 token 工具定义的 MCP 服务器，效率提升可能是巨大的。

为了证明效率提升，我们在 Scale 的 MCP Atlas⁠(opens in a new window) 基准测试中评估了 250 个任务，启用了所有 36 个 MCP 服务器，分为两种模式：(1) 在模型上下文中直接公开每个 MCP 函数，以及 (2) 将所有 MCP 服务器置于工具搜索之后。工具搜索配置将总 token 使用量减少了 47%，同时达到了相同的准确性。

示例 token 计数来自 MCP-Atlas 公共数据集中 250 个任务的平均值。

智能体工具调用

GPT‑5.4 还改进了工具调用，使其在推理期间决定何时以及如何使用工具时更加准确和高效，特别是在 API 中。与 GPT‑5.2 相比，它在 Toolathlon（测试 AI 智能体如何使用现实世界的工具和 API 完成多步骤任务的基准测试）上以更少的轮次实现了更高的准确性。例如，智能体需要阅读电子邮件、提取作业附件、上传它们、评分并将结果记录在电子表格中。

工具让步是指助手让步以等待工具响应。如果并行调用 3 个工具，然后再并行调用 3 个工具，则让步数为 2。工具让步是比工具调用更好的延迟代理，因为它们反映了并行化的好处。

对于偏好推理努力为 None 的延迟敏感用例，GPT‑5.4 进一步改进了其前身。

在 τ2-bench⁠⁠(opens in a new window) 中，模型必须使用工具来完成客户服务任务，其中可能有一个模拟用户可以进行通信并对世界状态采取行动。推理努力设置为 None。

改进的网络搜索

GPT‑5.4 在智能体网络搜索方面表现更好。在 BrowseComp（衡量 AI 智能体持续浏览网络以查找难以定位信息的能力的指标）上，GPT‑5.4 比 GPT‑5.2 绝对跃升了 17%，GPT‑5.4 Pro 创下了 89.3% 的新最先进水平。

在实践中，这意味着 GPT‑5.4 Thinking 在回答需要从网络上的许多来源提取信息的问题时更强。它可以更持久地在多轮中搜索以识别最相关的来源，特别是对于“大海捞针”式的问题，并将它们综合成一个清晰、推理充分的答案。

在 BrowseComp 中，我们使用了包含基准答案的网站搜索阻止列表，以防止污染并确保公平的性能衡量。GPT‑5.4 的测量时间晚于 GPT‑5.2，因此分数反映了模型、我们的搜索系统和互联网状态的变化。GPT‑5.4 使用了更长、更新的阻止列表进行测试。模型使用 ChatGPT 搜索工具，这与 API 搜索可能存在微小差异。

可引导性

与 Codex 开始工作时概述其方法类似，ChatGPT 中的 GPT‑5.4 Thinking 现在将为更长、更复杂的查询提供前言以概述其工作。您还可以在响应中途添加指令或调整其方向。这使得更容易将模型引导至您想要的确切结果，而无需重新开始或需要多个额外轮次。此功能现已在 chatgpt.com⁠(opens in a new window) 和 Android 应用程序上可用，即将推出到 iOS 应用程序。

该模型还可以在困难任务上思考更长时间，同时保持对对话中较早步骤的更强意识。这使其能够处理更长的工作流和更复杂的提示，同时始终保持答案的连贯性和相关性。

安全性

在过去的几个月里，我们在准备部署 GPT‑5.4 的同时，继续改进我们在 GPT‑5.3‑Codex 中引入的安全保障。与 GPT‑5.3‑Codex 类似，根据我们的准备框架，我们将 GPT‑5.4 视为高网络能力，并且我们正在部署相应的保护措施，如系统卡⁠(opens in a new window)中所述。这些包括扩展的网络安全堆栈，包括监控系统、可信访问控制，以及对零数据保留 (ZDR) 表面上较高风险请求的异步阻止，以及对更广泛安全生态系统的持续投资。

由于网络安全能力本质上是双用途的，我们在继续校准我们的策略和分类器的同时，对部署保持谨慎态度。对于 ZDR 表面上的某些客户，请求级别的阻止仍然是我们网络风险缓解堆栈的一部分；因为分类器仍在改进中，随着我们不断完善这些保障措施，可能会出现一些误报。这些更新旨在改进保障措施在实际中的运作方式，包括减少不必要的拒绝和过度附加说明的响应，同时保留对滥用的强大保护。

我们继续对思维链 可监控性进行安全研究，以更好地了解模型如何推理并帮助检测潜在的不良行为。作为这项工作的一部分，我们引入了一个新的开源评估，CoT 可控性⁠，衡量模型是否可以故意混淆其推理以逃避监控。我们发现 GPT‑5.4 Thinking 控制其 CoT 的能力很低，这对安全性来说是一个积极的属性，表明模型缺乏隐藏其推理的能力，并且 CoT 监控仍然是一种有效的安全工具。

可用性和定价

GPT‑5.4 今天正在 ChatGPT 和 Codex 中逐步推出。在 API 中，GPT‑5.4 现在可作为 gpt-5.4 使用。GPT‑5.4 Pro 也可在 API 中作为 gpt-5.4-pro 使用，供需要最复杂任务最高性能的开发者使用。

在 ChatGPT 中，GPT‑5.4 Thinking 从今天开始向 ChatGPT Plus、Team 和 Pro 用户开放，取代 GPT‑5.2 Thinking。GPT‑5.2 Thinking 将在模型选择器中的旧版模型部分下为付费用户保留三个月，之后将于 2026 年 6 月 5 日停用。Enterprise 和 Edu 计划的用户可以通过管理员设置启用早期访问。GPT‑5.4 Pro 适用于 Pro 和 Enterprise 计划。ChatGPT 中 GPT‑5.4 Thinking 的上下文窗口⁠(opens in a new window)与 GPT‑5.2 Thinking 保持不变。

GPT‑5.4 是我们第一个整合了 GPT‑5.3-codex 前沿编码能力并在 ChatGPT、API 和 Codex 中推出的主线推理模型。我们将其称为 GPT‑5.4 以反映这一飞跃，并简化使用 Codex 时模型之间的选择。随着时间的推移，您可以预期我们的 Instant 模型和 Thinking 模型将以不同的速度发展。

Codex 中的 GPT‑5.4 包含对 1M 上下文窗口的实验性支持。开发者可以通过配置 model_context_window 和 model_auto_compact_token_limit 来尝试此功能。超过标准 272K 上下文窗口的请求将以正常费率 2 倍的速率计入使用限制。

在 API 中，GPT‑5.4 的每 token 定价高于 GPT‑5.2，以反映其改进的功能，而其更高的 token 效率有助于减少许多任务所需的总 token 数量。Batch 和 Flex 定价为标准 API 费率的一半，而优先处理为标准 API 费率的两倍。
