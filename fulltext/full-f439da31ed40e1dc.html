摘要

如今的智能体系统通常由单一开发者设计、构建和部署，该开发者对所有参与的智能体拥有完全控制权。虽然这简化了开发，但也限制了智能体系统的潜在规模。我们研究多开发者智能体系统（MDA），使开发者能够协作构建智能体系统，将前沿能力推向任何单个开发者独自无法达到的水平。我们构建了开发者的实证和理论模型，以比较MDA与单开发者智能体系统（SDA）。在通用助手基准GAIA上，一群各自智能体单独准确率不超过35%的专业化开发者，当其智能体在MDA中组合时达到70%。该MDA比中位数通用SDA高出12个百分点，而后者的构建预算是每个专家开发者的数倍。我们的理论模型展示了MDA如何激励专业化并鼓励更高效地利用聚合的开发者资源。总之，我们的结果为MDA作为一种新的扩展轴提供了初步论证，使具有多样化能力和资源的开发者能够协作推进智能体AI。

1 引言

图1：MDA跨开发者组合互补智能体，为扩展智能体系统提供了超越单一开发者系统的新扩展轴。

如今的智能体系统，无论是单一还是多智能体（例如使用子智能体的Claude（Anthropic, 2025b）），还是庞大的10,000智能体集群（OpenAI, 2026），通常都在单一开发者（例如OpenAI）之下设计、构建和部署。这些单开发者智能体系统（SDA）的优势在于开发者对所有智能体、其能力和编排拥有完全控制权。开发者可以随意添加或删除智能体，并根据需要更改任何智能体的行为。

虽然SDA易于设计和实现，但它们并非广泛扩展能力的好方法。例如，设想一下，如果我们当前统一的互联网被多个相互竞争的互联网取代，每个互联网都充斥着来自各个开发者的网页和服务。这样的单开发者互联网可能具有更好的安全性、优化和可维护性。但每个开发者将被迫重建已经存在的组件，从而浪费资源，并迫使最终用户在多个较差的选项之间来回切换。

同样，单开发者智能体系统被迫从头重建基础智能体能力，而不是在现有能力的基础上发展。¹

¹ 例如：编排、网络搜索、文档解析、运行实验室实验、制作3D模型等。

相比之下，设想一个共享系统，编排来自数万个独立开发者的数百万个智能体，这些开发者基于彼此的智能体进行构建，引入具有新颖、专业和互补能力的智能体。这样的多开发者智能体系统（MDA）（图1）具有众多潜在优势：(1) MDA提供了一种新的扩展轴，允许多个贡献开发者构建超越单个开发者所能实现的系统。(2) 开发者可以专注于构建新的互补能力，而不是重新实现整个基础能力栈。这降低了进入门槛，使小型专业化开发者能够为AI能力前沿做出贡献。最后，(3) 当一个开发者的智能体得到改进时，所有其他智能体和开发者也都受益，将影响放大到单一系统之外。

虽然先前的工作已经研究了智能体之间的互操作性和协调，但一直缺乏对跨开发者扩展的评估。为此，我们构建了开发者的实证和理论模型，以探究两种设置：一种是开发者各自构建SDA，另一种是单个MDA在每个任务上调用所有开发者的智能体。在GAIA基准（Mialon et al., 2024）上，我们展示了一群各自智能体单独准确率不超过35%的专业化开发者，在组合其能力的MDA中达到70%。与使用每个专家开发者数倍开发预算构建的通用SDA相比，该MDA比中位数高出12个百分点，比最佳SDA高出3个百分点。

此外，我们展示了单个开发者可以专门为MDA开发一个互补智能体，将其准确率从40%提升到53%，即使该智能体单独使用时仅达到19%。这些结果说明有必要扩展最优智能体设计的概念，以考虑智能体在部署时将如何与其他智能体交互。

我们用理论模型支持实证发现，这些模型展示了MDA如何激励构建具有专业化能力的智能体，并鼓励比SDA更高效的资源使用（第6节）。

最后，我们探索了MDA的收益无法抵消其更高协调开销的设置。在SealQA（Pham et al., 2025）上，任务完全是网络搜索，MDA在更高成本下可能表现不如SDA基线。

总之，我们的结果提出了三个要点：(1) MDA通过跨开发者组合能力，提供了一条有前景的新能力扩展轴。(2) 智能体的开发应考虑其部署环境，因为它们对共享系统的贡献可能远远超过独立性能所显示的水平。(3) 协调异构开发者的目标、能力和激励应成为MDA和智能体系统设计的核心组成部分。我们相信，MDA可以作为"智能互联网"（internet of intelligence）的基础，使具有多样化能力和资源的开发者能够协作推进智能体AI前沿。我们的工作无法替代MDA在现实世界中的部署和验证，但我们希望它能激发对这一新兴扩展轴的挑战与前景的进一步研究。

2 相关工作

多开发者生态系统。 多智能体系统（MAS）框架将智能体组织成协作工作流程（Hong et al., 2024; Wu et al., 2024），包括具有异构底层LLM的系统（Ye et al., 2025）。在这些工作中，单一开发者设计和控制系统中的所有智能体。最近的论文呼吁建立开放、标准化的智能体生态系统（Sharma et al., 2025; Yang et al., 2025b）。关于跨智能体互操作性的工作通过工具访问和通信协议（Anthropic, 2024; Google, 2025）、异构智能体之间的编排（Chen et al., 2024; Lu et al., 2024; Yang et al., 2025a）以及通过市场的智能体协调（Zhuge et al., 2023; Montes Sanabria and Alvarez Vecino, 2025; Tomašev et al., 2025）来解决这一问题。相关研究考察了协调失败以及对故障智能体的鲁棒性（Cemri et al., 2025; Zhu et al., 2025; Huang et al., 2025）。

在这些先前的工作中，MDA中的开发者是隐含的或次要的。我们通过明确建模具有异构资源、能力和激励的开发者群体的行为、交互和输出来补充这些方法。这使我们能够直接比较MDA和SDA，并揭示关于跨开发者的能力扩展、开发和专业化的洞见——这些洞见在仅考虑智能体之间的协调和互操作性时会被遗漏。

MAS设计与部署。 先前关于单一开发者下资源分配的工作涵盖计算最优扩展（Hoffmann et al., 2022）、单智能体与多智能体系统（MAS）架构（Gao et al., 2025; Kim et al., 2025），以及专家型与通用型智能体（Belcak et al., 2025; Żywot et al., 2026）。类似地，路由和编排方法优化跨模型和工具的成本/质量权衡（Chen et al., 2023; Ong et al., 2024; Su et al., 2025）。虽然这些方法评估什么是 optimal 的并为有限资源的单一开发者建立扩展规律，但我们将这些问题扩展到异构开发者生态系统。我们展示了在单一开发者情境下最优的方案，对整个生态系统而言可能并非最优。这说明了有必要在多开发者情境下研究智能体系统，其中智能体系统设计需要应对相互竞争的开发者激励和目标，以有效地统一和扩展跨开发者的能力。

在方法论上，我们用于建模开发者的实证测试平台类似于LLM模拟（Park et al., 2023; Li et al., 2023; Karten et al., 2025），而我们的专业化和资源效率思想大量借鉴了比较优势（Ricardo, 1817）和劳动分工（Smith, 1776）的经典经济学思想。

3 多开发者与单开发者智能体系统

图2：SDA（上）通过单一开发者构建的单一智能体系统 a_i 解决任务 x。路由SDA（rSDA）通过路由器（σ）将整个请求 x 路由到多个SDA之一。δ-MDA（下）将 x 分解为子任务 x_1, …, x_{k(x)}，独立路由每个子任务，并组合响应 y。

预备知识。 我们首先形式化开发者和智能体系统的概念。设 ℒ 为通信语言（本工作中为英语），设 𝒳, 𝒴 ⊆ ℒ 表示所有可能请求和回复的空间。设 𝒫 = {d_i}{i=1}^n 为开发者群体，每个开发者 d_i 使用固定的开发者预算 b_i 恰好贡献一个智能体系统 a_i: 𝒳 → 𝒴（多智能体或单智能体）。这些系统共同构成全局智能体池 A = {a_i}{i=1}^n。每个 a_i 可能提供不同的能力和权衡。例如，它们可能由不同的LLM骨干驱动，拥有不同的工具，在不同的运行框架下工作，或由其开发者针对特定任务进行专门微调。协调机制 Ω 描述 A 中的系统如何组合进行推理。²

² 注意，在先前的工作（Kim et al., 2025）中，Ω 用于表示多智能体SDA内部的编排策略。在本工作中，Ω 处于更高一层，描述多个此类SDA如何用于推理。

给定任意大小的有限池 A 和请求 x ∈ 𝒳，它返回回复 y = Ω(A, x) ∈ 𝒴。该机制及其路由器可能是随机的，随机性在此记号中隐含不表。

单开发者智能体系统（SDA）。 根据定义，每个 a_i（无论是单智能体还是多智能体）都是单开发者智能体系统（SDA），因为其所有组件均来自单一开发者 d_i。大多数现有的智能体系统研究孤立地考虑SDA，同时隐含地忽略 A 中的其他智能体系统（图2（上））。

对于固定的SDA a_i ∈ A，相应的协调机制为：

Ω^SDA(A, x) = a_i(x). (1)

然而，孤立情况下最优的SDA {a′} 在考虑更广泛的生态系统 A ∪ {a′} 及其如何补充现有系统时，可能是次优的。例如，a′ 可能复制现有能力，而不是推进新能力。

路由SDA（rSDA）。 现实世界中的智能体系统总是被部署到由其他开发者构建的现有智能体系统池中。目前，用户或选择算法（Chen et al., 2023; Aubakirova et al., 2026）从 A 中的不同SDA中进行选择（例如，针对不同任务选择Claude或ChatGPT）。我们使用路由SDA（图2（中））来刻画这种行为。设 σ_SDA(A, x) ∈ {1, …, n} 表示路由器³为请求 x 选择的SDA的索引。

³ 路由器是选择行为的抽象模型，可能既包括算法决策也包括人类决策。

路由SDA基线将整个请求委托给所选系统：

Ω^rSDA(A, x) = a_{σ_SDA(A,x)}(x). (2)

虽然 Ω^rSDA 通过在整个智能体池 A 中进行选择从而调用所有开发者及其系统，但胜出的SDA仍然孤立地执行请求 x，不与其他开发者的智能体系统交互。因此，rSDA介于纯SDA和完整MDA之间。

多开发者智能体系统（MDA）。 多开发者智能体系统（MDA）协调 A 中的智能体系统以共同解决任务实例 x ∈ 𝒳。

我们研究MDA的一种实例化，称为δ-MDA，它分解请求并将子任务路由到 A 中的各个系统（图2（下））。注意，这只是实现MDA的多种可能方式之一。

设 δ 将请求分解为子任务，γ 将其回复组合成最终响应。设 σ(A, x) ∈ {1, …, n} 表示路由器为请求 x 从 A 中选择的系统的索引。δ-MDA将查询 x 分解为 k(x) 个子任务 (x_1, …, x_{k(x)}) = δ(x)，将每个子任务路由到 A 中的一个系统，然后组合它们的回复。此过程可重复多轮。为方便起见，以下公式展示一轮：

Ω^δMDA(A, x) = γ(y_1, …, y_{k(x)})，其中 y_ℓ = a_{σ(A,x_ℓ)}(x_ℓ). (3)

比较MDA与SDA。 在SDA和路由SDA中，开发者的智能体系统独自处理每个任务，因此它们必须部署最低限度的通用能力广度。在MDA中，多个开发者的智能体共同解决一个任务，因此开发者可以专注于互补能力，并依赖其他系统来填补空白。因此，对于需要多种技能的任务，在某些技能上强而在其他技能上弱的开发者在δ-MDA中贡献其最佳能力，但在（路由）SDA中贡献其平均能力。然而，MDA必然会产生分解、通信和组合方面的额外开销。优势是否超过开销取决于任务、开发者 𝒫 及其部署的系统 A。我们在第5节的实证结果中探讨这些因素。

MDA与MAS的区别。 MDA在许多方面与传统MAS不同。例如，MAS的开发者对系统中的智能体及其行为方式拥有完全控制权，但MDA无法强制第三方开发者向 A 中部署什么。因此，MDA的一个关键设计挑战是确保"看不见的手"激励自利的开发者部署其行为能推进集体能力的智能体。我们在第6节探讨不同协调机制 Ω 如何激励不同的开发者策略及其对能力扩展的影响。此外，最优MDA设计不能与开发者群体 𝒫（例如开发者数量及其资源规模和能力）割裂开来。例如，依赖广泛能力的通用智能体的设计，可能无法与小型专业化开发者群体形成互补。我们在第5节探讨不同协调机制如何从不同的开发者群体中受益。

开发者群体。 我们考虑两大类开发者群体：(1) 部署具有广泛能力智能体系统的通用型开发者，以及(2) 部署专注于较窄能力子集系统的专业型开发者。并非每个开发者都拥有部署有竞争力的通用系统所需的知识和手段。专业化降低了进入门槛，使较小的开发者能够为前沿做出有意义的贡献。它还允许开发者将资源集中于其固有的比较优势（例如零售商构建购物智能体），在这些领域他们的贡献最具影响力。尽管先前已有支持专业化系统的论点（Belcak et al., 2025），但现有生态系统仍在很大程度上由通用型开发者主导（见第7节）。我们在第5节和第6节探讨MDA如何激励和实现专业化，以支持跨开发者扩展。

4 实证模型与设置

我们旨在不同的开发者群体中将MDA与SDA和路由SDA进行比较。理想情况下，这些比较可以使用现实世界中的真实开发者进行，但这在实验上并不现实。为了说明我们的核心思想，我们使用元智能体流程来表示开发者生态系统，该流程生成开发者并在固定预算下自动生成SDA。我们构建了三个开发者群体，生成三个智能体池：包含许多专业化智能体的 A_S，以及分别包含较少通用型单智能体和多智能体系统的 A_G 和 A_MAS。我们在所有三个池中保持相同的全局预算。我们使用中心化编排器智能体构建δ-MDA，并实现路由智能体（第3节中的σ），在δ-MDA和路由SDA中均使用它。我们在下文概述每个步骤，细节见附录B。

生成开发者。 我们通过生成描述开发者智能体系统目标功能的JSON规范 Z_i 来生成开发者。每个规范包含独特的有用信息，例如智能体在部署中可能遇到的示例查询。这些规范刻画了开发者专业知识的差异，并受到长度限制以反映任何开发者的有限知识资源。给定从 𝒳 中抽取的未标注数据集 𝒟^spec = {x_1, …, x_N}，规范智能体生成一组 k 个规范 𝒵 = {Z_1, …, Z_k}，覆盖解决 𝒳 中请求所需的能力。⁴

⁴ 我们确保用于生成规范的数据始终与任何评估数据不相交。

我们为通用型开发者设置 k=1，为专业型开发者设置 k>1。对于 k>1，k 的确切值可能因 𝒟^spec 而异。在任何智能体池中，我们都多次重复生成过程，从而产生多个相互竞争且能力重叠的开发者，正如现实世界中的情况一样。

我们通过以下变化来反映开发者之间的额外异构性：(1) 元智能体开发流程所使用的LLM，以反映开发者行为的差异，⁵

⁵ 我们使用 gpt-5.2（OpenAI, 2025）、claude-opus-4.5（Anthropic, 2025a）和 gemini-3-pro-preview（Google DeepMind, 2025），均采用高推理级别。

以及(2) 所部署智能体的LLM骨干，分为三个不同的性能-成本层级，分别标记为高（H）、中（M）和低（L），其中高层最昂贵也最强大。⁶

⁶ 高层智能体使用低推理级别的 gpt-5.2。中层和低层智能体分别使用中等和低推理级别的 gpt-5-mini。推理级别指LLM API设置。

这些层级反映了开发者资源规模的差异，因为并非每个开发者都能发布前沿级别的系统。我们在这些配置中重用规范集 𝒵，以获得每种类型的多个开发者。

智能体池。 我们构建三个智能体池：(1) 通用型池 A_G，包含由通用型开发者（k=1）构建的单智能体SDA；(2) 专业型池 A_S，包含由专业型开发者（k>1）构建的单智能体SDA；以及(3) 多智能体池 A_MAS，其中每个SDA是一个MAS，包含规范智能体单次运行（k>1）产生的一组互补专家，由中心化编排器智能体协调。A_S 旨在刻画大量潜在的拥有专有能力但可能缺乏构建通用系统的专业知识或资源的小型开发者，而 A_G 和 A_MAS 代表当今主导生态系统的前沿通用型开发者。

开发。 我们使用元智能体（图3（中））来建模开发者构建智能体的过程。给定规范 Z_i 作为输入，元智能体生成工具、依赖项和系统消息，并自动编译成可运行的ReAct智能体（Yao et al., 2023）。元智能体发出测试查询、观察轨迹并进行迭代改进。每一轮改进都会提升下游智能体的能力和鲁棒性，我们使用改进的总轮数作为开发者的预算 b_i。

生成的ReAct智能体在交互循环中运行，动作包括 toolcall、image（将图像添加到上下文）和 code（运行代码片段）。智能体以XML块的形式接收结果，直到发出 reply 或达到迭代限制。对于每个生成的智能体，元智能体会生成一份突出该智能体能力的智能体描述。路由器会读取这种（通常过于乐观的）能力描述，以此建模开发者吸引流量到自己智能体的竞争激励。

A_S 中的每个专家通过5轮迭代改进构建。A_G 和 A_MAS 中对应的通用型开发者获得均分的相同全局预算，以保持三个智能体池的总全局开发预算 B = Σ_i b_i 相同。

路由。 与现实世界一样，每个池中的智能体相互竞争请求。由于能力可能重叠，且智能体描述可能不完全忠实，因此需要一种基于经验选择智能体的机制。我们将路由建模为一个自我改进的LLM智能体，即σ-智能体（图3（右））。它在δ-MDA中实现子任务路由的σ，在路由SDA中实现完整任务选择的σ_SDA。σ-智能体的参数包括：(1) 元智能体步骤中生成的智能体描述，以及(2) 部署期间积累的关于池 A 中系统的经验。给定任务输入 x_j ∈ 𝒳，路由器选择一个系统 a_i ∈ A 并获得其回复 a_i(x_j)。它将交互存储在缓冲区 ℬ = {(x_j, a_i(x_j), y_j^⋆)}_j 中，其中 y_j^⋆ 是任务级别的真实答案。为了更新路由器的经验，ℬ 通过更新智能体进行总结，生成：(1) 系统的全局排名，以及(2) 上下文排名列表，例如"a_i 擅长A，但不擅长B"。⁷

⁷ 我们使用中等推理级别的 gpt-5 作为路由器，超高推理级别的 gpt-5.2 作为更新智能体。我们在附录B中更详细地介绍更新智能体如何使用缓冲区生成排名。

δ-MDA和路由SDA。 我们通过为σ-智能体配备处理请求分解（δ）和组合（γ）的δγ-智能体来实现δ-MDA（图2（下））。δγ-智能体接受请求 x 并将其分解为子任务 (x_1, …, x_{k(x)})，每个子任务传递给σ-智能体。它们的回复被传回δγ-智能体，后者可以发起新一轮子任务或返回最终响应 y。这些智能体共同实现了公式3中的共享协调机制 Ω^δMDA。我们使用中等推理级别的 gpt-5 作为δγ-智能体。

我们通过将完整任务实例 x 直接传递给σ-智能体来实现路由SDA，σ-智能体从所选池中选择一个单智能体或多智能体SDA。该系统使用自己的智能体处理请求。由于δ-MDA支持顺序多步交互，我们允许rSDA路由器在提交最终响应之前尝试不同的SDA。它返回某个SDA的答案，而不跨SDA组合子任务。⁸

数据集和指标。 我们评估准确率和执行（API）成本，并通过跨智能体层级的路由调用份额来衡量开发者参与度。协调成本是运行σ和δγ智能体所产生的成本，除非另有说明，我们始终将其纳入分析。我们特别选择了两个在广度上不同的流行智能体基准，以便在两种不同机制下评估MDA和SDA：

  • GAIA（Mialon et al., 2024）：一个多样化的助手基准，需要网络搜索、多模态分析（音频和图像）以及各种文件类型（.docx、.pptx、.pdf、.xlsx）的处理。问题结合了多种技能，使其非常适合测试异构能力的系统组合。我们使用未标注的测试分割来开发规范，并将验证集按50/50分割以训练和评估σ-智能体。对于GAIA，我们实例化了9个通用型开发者来构建 A_G 和 A_MAS，以及54个 k=6 的专业型开发者来构建 A_S。

  • SealQA（Pham et al., 2025）：一个以网络搜索为中心的问答数据集。它需要比GAIA更窄的能力分布，使我们能够在任务范围非常集中时比较MDA和SDA。对于路由实验，我们使用never-changing子集进行评估，使用slow-changing和fast-changing子集进行训练。我们实例化了42个 2≤k≤8（平均：3.8）的专业型开发者来构建 A_S，以及11个通用型开发者来构建 A_G 和 A_MAS。

MDA比rSDA更善于利用非前沿开发者。 在图4(c)中，我们部署了一个修改版的δ-MDA，它在排除高层智能体的 A_S 子集上运行。这个修改后的MDA以9美元的成本达到67%的准确率。相比之下，A_G 中最佳的中/低层SDA仅以8美元的成本达到60%的准确率。δ-MDA特别擅长利用较弱的智能体，使更多没有前沿资源的开发者能够为全局智能体能力做出贡献。

6 开发者与MDA理论

实证结果展示了具有互补专业化智能体的MDA的优势。然而，MDA无法直接控制开发者选择部署什么。在本节中，我们构建一个风格化的理论模型，以说明协调机制如何影响开发者激励并影响多开发者生态系统内的扩展。我们专注于高层直觉和要点，并以非正式方式陈述命题。完整的设置、定义、假设、证明和局限性讨论见附录A。

开发者。 n 个开发者中的每一个通过将其预算 b_i > 0 分配到 m 个技能维度（例如编码）来构建一个SDA a_i。分配 q^i ∈ ℝ^m_{≥0} 定义了一个具有该能力概况的智能体。我们用 ‖q^i‖₂ ≤ b_i 来刻画开发者之间不同的开发能力，其中ℓ₂约束作为每项技能内收益递减的模型。系统 a_i 在请求 x 上的能力为 ϕ_i(x) := ⟨q^i, s(x)⟩，其中 s(x) 是刻画 x 所需技能的非负技能概况向量（例如，x 可能需要强大的网络搜索技能但不需要编码）。

如果所有分配共线（即所有系统以不同规模共享相同的能力概况），我们称该分配池为通用型，记为 A_G。当每个开发者将其预算集中在单一技能上，且不同开发者覆盖不同技能时，我们称该池为专业型，记为 A_S。我们假设多开发者极限，使得每个开发者的相对资源相对于全局总和较小（max_i b_i / Σ_j b_j → 0）。¹⁰

¹⁰ 对于有限数量的开发者，我们在A.3节中展示策略概况仍为ε-纳什均衡，其中 ε = O(max_i b_i / B)。

路由和收益。 我们将路由器σ建模为一场竞赛，以与能力 ϕ_i(x) 成比例的概率选择每个SDA。¹¹

¹¹ 此路由规则是Tullock竞赛，广泛用于建模竞争（Tullock, 1980; Konrad, 2009; Vojnović, 2016）。

路由SDA对每个请求做出一次此选择。δ-MDA对每项技能分别应用相同的规则，并组合所选系统的贡献。总福利 W(A; Ω) 是智能体池 A 在协调机制 Ω 下交付的预期能力，在任务分布 μ 和路由上取平均。除非另有说明，我们让开发者的收益等于其预期福利贡献。

命题1（路由SDA诱导通用主义）。在路由SDA下，唯一的收益最大化纳什均衡策略产生智能体池 A_G。

命题1表明，在路由SDA下，即使是小型开发者（b_i ≪ (1/n)Σ_j b_j）也可能被激励部署缩小的劣质通用系统，而不是在长尾能力上推进前沿。先前的工作将专业系统的稀缺性归因于基础设施和认知等各种壁垒（Belcak et al., 2025）。命题1表明，已部署系统的协调方式可以塑造激励，推动理性开发者构建通用系统。这一结果得到了我们图5(a)中实证结果的支持。在rSDA中，A_S（62%准确率）明显差于 A_G（68%）和 A_MAS（67%）。我们在C.3节对偏离理论 A_G 均衡的情况进行了进一步的实证研究。总之，这些结果表明，开发者专业化只有在得到能够激励和利用它的系统（即MDA）的支持时才可行。

命题2（δ-MDA支持专业化）。在δ-MDA下，存在每个开发者专注于单一技能的纳什均衡，产生智能体池 A_S。

在δ-MDA中，开发者的理性策略是部署沿不同技能分布的专业化系统。沿需要不同能力的不同子任务进行的竞赛使开发者（包括较小的开发者）能够在现有能力的基础上发展，并将精力导向尚未填补的利基市场。这些结果呼应了图5(c)中添加互补智能体的收益，并展示了MDA如何减少重叠工作。

引理3（弱优势）。在任何智能体池上，δ-MDA的福利至少与路由SDA一样好，当且仅当智能体池为 A_G 时取等号。

引理3的直觉是，路由SDA浪费了跨开发者的多样性：一个编码强但网络搜索弱的系统贡献其平均能力，稀释了其在编码技能上的优势。相比之下，δ-MDA为每项技能提取每个开发者的优势。当没有异构优势可提取时，δ-MDA不提供额外的好处，且很可能产生额外的开销。

如果(1)没有开发者能从重新分配其预算中获利，且(2)在固定的 A 上从 Ω 切换到另一个协调机制 Ω′ 不会带来福利增益，则称 (Ω, A) 为联合均衡。

命题4（联合均衡）。命题1中的 (Ω^rSDA, A_G) 和命题2中的 (Ω^δMDA, A_S) 都是联合均衡。后者在福利上严格优于前者。

尽管 (Ω^δMDA, A_S) 的福利更高，命题4表明当前反映AI现状的 (Ω^rSDA, A_G) 配置可能作为次优联合均衡而持续存在。在 A_G 下引入δ-MDA不会带来即时的福利增益，而现有开发者在现有的路由SDA机制下没有专业化的激励。

尽管存在福利差距，这些联合均衡的共存突显了需要同时考虑智能体池组成 A 和协调机制 Ω。这一"鸡生蛋、蛋生鸡"的问题在我们的实证结果中得到了呼应。在图5(a)中，在 A_G 上，从rSDA切换到δ-MDA没有带来准确率增益，而成本却增加了一倍以上。同时，在rSDA上，如果开发者从 A_G 切换到 A_S，整体准确率从68%下降到62%。这些结果突出了在现实世界中实现MDA的关键挑战，并表明MDA可能需要以现有的专业化智能体作为种子，以鼓励向 A_S 的过渡。

命题5（流量份额补偿诱导通用主义）。如果开发者最大化流量份额而不是预期福利贡献，那么每个纳什均衡都会产生智能体池 A_G。

命题5表明，如果开发者仅最大化其获得的流量而不是其预期福利贡献，那么包括δ-MDA在内的每个协调机制都将导致通用型均衡。因此，MDA设计需要超越系统架构，考虑诸如开发者的收益和补偿等决策如何塑造智能体池，从而影响MDA的下游性能。

我们的理论分析强化了实证结果，指出了当前智能体生态系统的缺陷，展示了MDA的比较优势，并确定了实现采用需要克服的关键障碍。更广泛地说，我们的结果说明有必要扩展现有的智能体系统设计概念，将异构、自利开发者群体如何与系统交互纳入其中。

7 讨论与结论

独立扩展的局限性。 开发者是否推进了集体能力，不能通过其孤立贡献来衡量，而必须考虑其能力如何补充现有系统。目前，少数开发者正在构建和扩展独立的、通用的、单开发者智能体系统（SDA）。然而，如果孤立的最优系统复制现有能力而不是引入新颖的互补能力，那么它可能是生态系统资源的次优使用。

此外，如果前沿能力总是等同于最佳单一系统，那么其上限将始终由最大单一开发者的资源决定。与此同时，在狭窄领域拥有宝贵数据、专业知识或集成能力的小型开发者，可能没有资源或技术能力来构建自己具有竞争力的通用系统，从而无法为集体AI能力做出贡献。

跨开发者扩展AI。 这些单体单开发者系统的局限性激发了扩展智能体AI的另一种方法：跨开发者组合能力，以利用超越任何单一组织的资源和专业知识。实现这种方法提出了一个核心问题：我们如何激励并使更广泛的开发者群体构建能够集体推进AI前沿的系统？

回答这个问题需要将开发者群体（而不仅仅是他们的智能体）视为一等实体。开发者有不同的目标、资源和比较优势。一个有效的多开发者生态系统必须：(1) 使开发者利益与集体进步保持一致，(2) 支持来自具有多样化能力和资源规模的开发者的贡献，以及(3) 使开发者能够专注于其专有能力和比较优势。

我们的结果为这一愿景提供了初步支持。MDA可以将开发者的互补能力转化为集体性能增益，同时使专业化变得可行且有利。在GAIA上，单独达到至多35%准确率的专业化智能体在MDA中组合时达到70%，超过了我们评估的每一个个体SDA。

我们的分析还表明，开发者智能体的使用和协调方式可以塑造开发者被激励部署的内容。当独立系统竞争处理整个请求（路由SDA）时，开发者被激励构建具有广泛能力的通用系统。当MDA组合跨开发者的贡献时，互补能力的专业化可以变得对个体有利。总之，我们的结果表明，MDA既可以受益于互补能力，也可以激励将互补能力部署到智能体生态系统中。这为拥有非前沿资源或狭窄专业知识的贡献者改进集体系统奠定了基础，该系统的能力甚至超越了最大单一开发者的触及范围。

让更广泛的群体参与智能体AI。 除了我们实验中固定的开发预算外，MDA还可以吸引原本不会进入智能体开发的资源。几乎没有激励或手段构建通用助手的组织，可以围绕其现有专业知识、数据或服务部署专业化智能体。他们的参与可以将原本无法访问或专有的能力带入更广泛的生态系统，同时使这些组织获得补偿并保留对其系统的控制。

图7说明了这种参与如何运作。在SDA示例（图7，上）中，AI提供商依赖抓取来访问第三方内容和服务。这种访问可能面临技术限制以及围绕许可、内容使用和补偿的法律争议。¹²

¹² 例如，Cloudflare推出了阻止AI爬虫和对访问收费的工具，而Amazon起诉Perplexity涉嫌未经授权访问Amazon.com。这些发展表明，对外部内容和服务的访问存在争议，这促使人们寻求让开发者能够设定自身贡献条款的方式。

在MDA示例中，开发者（我们示例中的新闻提供商和零售商）贡献对内容和服务有直接访问权的第一方智能体。这些组织可以(1) 通过其拥有的独特能力（例如集成购物体验）改进共享系统，(2) 保留对其服务提供方式的控制，以及(3) 因其贡献获得补偿。

图7：SDA和MDA的示意性部署。SDA通过抓取访问第三方服务，这可能被阻止。MDA整合来自服务提供商的第一方智能体，实现直接访问、对最终用户更好的服务质量以及跨开发者的公平补偿。

尽管部署智能体目前需要大量技术专业知识，但开发工具和流程的改进可以使更广泛的人群能够使用它。例如，在互联网早期，创建和托管网页即使对大型企业也是一项技术工作。然而，工具和托管服务的改进帮助使网站和网络服务变得无处不在且人人可及。

创造和分享经济价值。 小型零售商可能难以吸引足够的用户来维持一个独立的购物智能体，而MDA从整个系统的第三方智能体汇集请求，可能为小型专业化服务产生更多的请求量。我们在图5(a)和5(b)中实证表明，相同的中层专家在为MDA做贡献时获得56%的调用，而作为SDA竞争时仅为33%。此外，收益不一定是零和的。在相同的实验中，MDA还将整体准确率比竞争SDA提高了8个百分点。通过扩大市场并通过新的智能体间服务实现更好的能力，MDA可以产生额外的经济价值，同时更公平地分享回报，为现有提供商和新参与者提供受益机会。

民主化AI发展的塑造权。 更广泛的开发者参与智能体AI，为更多利益相关者提供了塑造全局AI能力的直接方式。服务广泛用户群的开发者可能几乎没有激励去优先考虑小社区的需求。通过MDA，该社区可以将其有限的开发资源集中于解决其未满足需求的狭窄专业化智能体。将此智能体与现有能力相结合，将使社区能够塑造一个具有广泛能力的系统，而无需自行开发完整的通用助手。我们的实验说明了单一互补智能体如何为共享系统添加定向能力。在GAIA上，添加一个独立准确率为19%的智能体，将现有MDA的准确率从40%提高到53%（图5(c)）。因此，多样化的利益相关者可以通过他们构建和部署的内容影响共享AI系统的能力，将开发优先级民主化，超越最大提供商的优先级。

局限性和开放挑战。 我们的工作是这一研究路线的起点，许多开放问题仍然存在。我们展示了MDA的协调开销可以抵消理论收益，其实用性取决于任务。MDA在所有设置中都优于SDA是不太可能的。还需要解决其他挑战，包括路由和分解/组合如何大规模实现。在协作智能体之间分配价值以及决定谁承担运行共享MDA基础设施的成本，仍然是开放问题。

此外，在并非所有参与者都可以信任的MDA中，安全、隐私和问责挑战被放大。需要建立强有力的措施，以确保单一恶意或性能不佳的系统不会造成灾难性的下游后果。我们的δ-MDA只是解决多开发者系统某些独特挑战的初步步骤。我们预计更好的协调机制和MDA设计将随之而来。

没有任何理论或实证模型能够完美捕捉将智能体部署到集体系统中的真实开发者群体的复杂动态。MDA的真正考验将是它们在现实世界中实现之时。当它们实现时，我们相信它们将使多样化的开发者群体能够集体扩展一个动态、不断演化的智能系统，其能力远远超越任何单一开发者的触及范围。我们希望这项工作是朝着实现这一愿景迈出的一步。

附录A 理论模型设置与证明

A.1 设置

我们研究公式2和3中定义的协调机制 Ω^rSDA 和 Ω^δMDA 的理论实例化。

开发者和智能体池。 n ≥ 2 个开发者中的每一个用预算 b_i > 0 构建一个SDA a_i。这些系统共同构成智能体池 A = {a_i}{i=1}^n。我们记 B := Σ{j=1}^n b_j 为总预算，b_max := max_j b_j 为最大预算。开发者 i 将其预算分配到 m ≥ 2 个技能维度（例如表示网络搜索和编码等技能），并从可行集中选择分配向量：

q^i ∈ C_i := {q ∈ ℝ^m_{≥0} : ‖q‖₂ ≤ b_i}.

分配 q^i 表示已开发的能力。预算上的ℓ₂约束建模了每项技能内的收益递减。因此，b_i 衡量开发能力，B 是这些能力规模的总和。我们在A.4节讨论这一生产假设。

请求位于具有需求分布 μ 的有限集合 𝒳 中，其中 μ(x) ≥ 0 且 Σ_x μ(x) = 1。每个请求具有技能概况向量 s(x) ∈ ℝ^m_{≥0}。SDA在该请求上的标量能力为：

ϕ_i(x) := ⟨q^i, s(x)⟩.

我们记 Φ(x) := Σ_j ϕ_j(x) 为 x 上的总能力，Q_d := Σ_j q^j_d 为技能 d 上的总能力。下标 -i 表示去除开发者 i 的贡献：Φ_{-i}(x) := Φ(x) − ϕ_i(x) 以及 Q_{-i,d} := Q_d − q^i_d。分配 {q^i}_{i=1}^n 表示智能体池 A。如果所有分配共线，我们称其为通用型，记为 A_G。如果每个开发者将其全部预算分配给单一技能且至少有两种技能被覆盖，我们称其为专业型，记为 A_S。

设 s := Σ_x μ(x) s(x) 为平均任务技能概况。不失一般性，我们限定为被需求的技能和非零请求：对每个 d 有 s_d > 0，且每当 μ(x) > 0 时 s(x) ≠ 0。我们对未覆盖的技能和请求采用 0/0 := 0 的约定，它们贡献零福利。

路由和福利。 我们全程使用指数 r=1 的规范Tullock路由规则（Tullock, 1980; Konrad, 2009; Vojnović, 2016）。每个路由决策以与被路由的请求或技能子任务上的能力成比例的概率选择一个SDA。对于路由请求 x，这给出：

Pr[σ_SDA(A, x) = i] = ϕ_i(x) / Φ(x). (4)

设 W(A; Ω) 表示智能体池 A 在协调机制 Ω 下交付的预期能力，在请求需求和路由上取平均：

W^rSDA := W(A; Ω^rSDA)，W^δ := W(A; Ω^δMDA).

相同的上标约定适用于开发者收益 U_i 和流量份额 T_i。

路由SDA。 路由SDA通过 σ_SDA 对每个请求应用一次公式4中的Tullock规则，如公式2所示。其在 x 上的预期交付能力为 Σ_i Pr[σ_SDA(A,x)=i] ϕ_i(x)，得出福利：

W^rSDA = Σ_{x∈𝒳} μ(x) Σ_{i=1}^n ϕ_i(x)² / Φ(x). (5)

δ-MDA。 我们如下实例化公式3中的 Ω^δMDA。分解 δ 为每个所需技能创建一个子任务，路由器 σ 为每个子任务独立选择一个SDA。对于技能 d，开发者 i 以概率 q^i_d / Q_d 被选中并贡献能力 q^i_d。组合 γ 通过将这些能力贡献相加来建模，并以请求的技能需求 s_d(x) 加权。在路由结果上取平均得出：

W^δ = Σ_{x∈𝒳} μ(x) Σ_{d=1}^m s_d(x) · Σ_{i=1}^n (q^i_d)² / Q_d. (6)

该模型假设技能贡献可加，并省略了分解和组合成本。

A.2 假设与开发者目标

(A1) 多技能需求。 μ 支持集中的每个 s(x) 至少有两个正分量。这建模了组合多种能力的请求，例如检索信息并对其进行推理。即使是特定领域的请求也可能需要共享技能，如语言理解和呈现回复。

(A2) 多开发者。 没有开发者的预算相对于其竞争者显著：在路由SDA中，对每个 i 和被需求的 x 有 b_i·‖s(x)‖₂ ≪ Φ_{-i}(x)；在δ-MDA中，对每个 i 和维度 d 有 b_i ≪ Q_{-i,d}。多开发者极限将这些比率在开发者和请求或技能上一致地趋于零。这建模了一个具有广泛参与的池，其中一个开发者可以将总竞争视为近似固定。在我们分析的概况中，两个条件都简化为 b_max / B → 0。

(A3) 连通技能图。 设 {1, …, m} 上的图在某个被需求的任务同时需要 d 和 d′（s_d(x) > 0 且 s_{d′}(x) > 0）时，在 d 和 d′ 之间有一条边。我们假设此图是连通的。诸如语言理解之类的共享基本技能可以连接原本不同的任务族，这激发了此条件。

(C) 覆盖。 每项技能都获得正的总能力，即对每个 d 有 Q_d > 0。A2中δ-MDA的条件蕴含C。我们为引理3中的相等性刻画单独陈述C，该刻画不需要A2。

A.3 证明

命题（命题1的正式版本）。假设A2和A3，并令开发者最大化 U_i^rSDA。在多开发者极限中，路由SDA博弈具有唯一的纳什均衡，产生智能体池 A_G：

对每个 i 有 q^i = b_i ŝ，其中 ŝ := s / ‖s‖₂，

证明。 对 q ∈ C_i，

U_i^rSDA(q) = Σ_x μ(x) ⟨q, s(x)⟩² / (Φ_{-i}(x) + ⟨q, s(x)⟩).

由Cauchy–Schwarz不等式和A2，

⟨q, s(x)⟩ / Φ_{-i}(x) ≤ η_i := b_i max_{x∈supp(μ)} ‖s(x)‖₂ / Φ_{-i}(x) = o(1)，

因此

q^⊤ M_i q / (1+η_i) ≤ U_i^rSDA(q) ≤ q^⊤ M_i q，其中 M_i := Σ_x μ(x)/Φ_{-i}(x) · s(x)s(x)^⊤. (9)

对称且逐项非负的矩阵 M_i 由A3知是不可约的。Perron–Frobenius定理和Rayleigh–Ritz定理给出 q^⊤ M_i q 在 C_i 上的唯一最大化子：b_i 乘以其正单位Perron特征向量。

在共线概况 q^j = b_j u（u > 0 且 ‖u‖₂ = 1）处，

M_i u = Σ_x μ(x) s(x)⟨s(x), u⟩ / ((B − b_i)⟨u, s(x)⟩) = s* / (B − b_i).

因此，u 是Perron特征向量当且仅当 u = ŝ，从而确立极限均衡 q^i = b_i ŝ。

在A2下，Φ_{-i}(x) = Φ(x)(1 − o(1)) 在 i 和 x 上一致成立，因此

M_i = (1 + o(1)) M_∞，其中 M_∞ := Σ_x μ(x)/Φ(x) · s(x)s(x)^⊤.

每个极限最佳响应都遵循共同的Perron方向 u，且 M_∞ u = s*/B 强制 u = ŝ。因此，满足A2的每个精确均衡序列都有 max_i ‖q^i/b_i − ŝ‖₂ → 0。∎
