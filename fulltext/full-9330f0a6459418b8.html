摘要

随着预训练规模的扩大，医学语言模型在临床问答领域取得了快速进展。然而，它们能否通过持续干预实现有效的生理控制，仍缺乏系统的定量评估。1型糖尿病提供了一个具体的研究场景：胰岛素分泌受损导致对外源性胰岛素的依赖，给药剂量需根据进餐、运动、疾病和血糖测量信息不断调整。我们推出 DiabAgent，一个面向智能体生理控制的研究套件，包含智能体生理控制（APC）框架、DiabetSim 模拟器和 SweetBench 基准测试。APC 通过医疗设备工具控制血糖，利用持续观测推断个体状态、积累个人经验并选择治疗行动。我们构建 DiabetSim 来模拟不同的患者、事件和设备条件，以实现可扩展的虚拟测试与训练。利用 DiabetSim，我们将32个场景设计实例化为212个血糖控制任务，构建了 SweetBench。在 Claude Opus 5.5 和一小时的固定决策间隔下，APC 实现了73.5的 COGI 得分，而开源闭环基线 OpenAPS 为71.2。消融实验进一步表明，个体化适应和上下文信息能改善血糖控制。将高频基于规则的控制与较低频率的智能体决策相结合，显示出平衡控制性能与计算成本的潜力。我们的工作为智能体参与人体生理控制提供了框架、模拟器和评估基础。

1 引言

随着预训练规模的扩大，医学语言模型在临床问答和治疗建议方面取得了快速进展（Singhal et al., 2023; Arora et al., 2025）。智能体将语言模型与工具、记忆和环境反馈相结合，以执行多步骤任务（Yao et al., 2023; Shinn et al., 2023）。它们在软件和服务环境中完成长程任务，并在后续决策中复用经验（Yang et al., 2024; Yao et al., 2024; Zhao et al., 2024）。医学智能体进行诊断对话、分析治疗方案并操作电子健康记录（Tu et al., 2025; Gao et al., 2025; Jiang et al., 2025）。这些任务的评估主要关注回复或信息操作。评估语言模型能否通过持续干预控制生理，需要对由此产生的生理轨迹进行系统评估。

1型糖尿病为这一问题提供了具体场景。1型糖尿病患者胰岛素分泌受损，依赖外源性胰岛素进行血糖控制。给药需求随进餐、运动、疾病和个体状态而变化，而胰岛素的作用持续数小时，将当前决策与先前的治疗和后续事件联系起来（Holt et al., 2021; Riddell et al., 2017）。个体差异、胰岛素需求的日常变化，以及血糖测量的延迟、噪声或缺失，使控制成为一个长程任务，需要持续的状态推断、治疗调整和反馈跟踪。自动胰岛素输送和基于学习的闭环控制器已推进了血糖控制（Brown et al., 2019; Sherr et al., 2022; Hettiarachchi et al., 2024; Sarkar, 2026）。现有的动力学模型和评估指标也为模拟血糖动态和评估控制结果提供了基础（Deichmann et al., 2023; Battelino et al., 2019）。这些条件共同支持系统研究智能体如何结合上下文信息、个人经验和设备工具进行持续生理控制。

基于规则的闭环控制通常围绕结构化的血糖测量、胰岛素记录、碳水化合物估计和处方治疗参数来组织给药（OpenAPS community, 2026）。要使用变更后的膳食计划、疾病恢复或设备问题的描述，需要将它们映射到预定义的输入和响应规则。这种映射限制了控制器利用自由文本上下文和个人治疗记录中线索的方式。相互作用的罕见事件和个体差异也要求判断哪些线索能解释当前的血糖变化和后续给药需求（Holt et al., 2021）。智能体能否解释这种上下文和个人经验，通过医疗设备工具行动，并将这种理解转化为更好的生理控制？这一问题激发了我们在 DiabAgent 中研究的智能体生理控制（APC）框架。

我们用五个模型评估 APC。使用 Claude Opus 5.5 时，它实现了73.5的 COGI，而 OpenAPS 为71.2。进一步的实验表明，记录和回顾支持在无需权重更新的情况下实现跨天改进，并且在测试案例中，添加上下文比提高智能体决策频率更能改善控制。更频繁的智能体调用也会增加计算量。CL 开/关案例研究表明了将频繁的后台血糖调节与较低频率、整合观察和个人经验的智能体决策相结合的潜力。

我们做出三项贡献：

  1. 我们引入 APC，一个将人体生理视为交互环境的智能体控制框架，并将其应用于血糖控制。它通过监测设备获取信息，通过医疗设备输送药物，并根据反馈调整决策以优化血糖控制指标。
  2. 我们构建 DiabetSim，一个可配置的血糖控制模拟器，整合了个体生理、医疗设备、事件和观测条件。它重建了 APC 面临的交互环境，并为可重现的虚拟测试提供了基础。
  3. 我们构建 SweetBench，一个包含212个血糖控制任务的基准测试。使用 Claude Opus 5.5 的 APC 实现了73.5的 COGI，而 OpenAPS 为71.2。进一步的消融实验表明，借助个人记录和日终回顾可实现跨天的控制改进。

2 智能体生理控制

2.1 APC 框架

APC 将治疗视为一个控制问题，其中控制器是智能体，传感器和执行器是医疗设备。

定义1（智能体生理控制）。 一个 APC 问题由具有隐藏状态的生理系统、测量并作用于该系统的医疗设备、来自患者的报告以及基于生理轨迹的评分组成。APC 智能体反复观察、通过设备行动并决定何时重新评估，以最大化期望得分。

状态 x_t 包括生理、设备状态和上下文，并在个体参数 θ 下演化。设 d 表示设备配置，ρ 表示报告配置，后者指定患者报告什么、何时报告以及报告的准确程度。则有：

x_{t+1} ∼ P_θ(· | x_t, a_t)，o_t ∼ O_{d,ρ}(· | x_t)，a_t ∈ A_d(h_t)。

这是一个部分可观测马尔可夫决策过程（Kaelbling et al., 1998），其中设备同时决定观测模型和动作集。智能体维护可见历史 h_t = (o_{≤t}, a_{<t}) 以及总结与同一个体过去交互的个人记录 M_t，并使用策略 π(a_t | h_t, M_t) 选择动作。得分由真实生理变量 m_t = f(x_t) 计算，智能体从不直接观察这些变量。在时间范围 T 上，目标为 max_π E_π[S(m_{0:T})]。

APC 智能体有四个组件来闭合这一循环（图2）。决策选择干预、测量或等待，并陈述其理由。设备工具执行操作并返回读数和输送日志。监控监视传入的观测，并在其选择的等待间隔结束或指定条件发生时将控制权交还给智能体。个人记录将已学到的关于个体的信息带入后续决策。

该设计满足三项要求。可解释性使行动的依据可通过决策规则或明确的理由追溯。信息整合结合血糖测量、自然语言和多模态报告以及个人历史来推断隐藏状态并选择干预。长尾事件适应利用上下文报告在事件重叠或超出预定义响应类别时调整治疗。

要在新领域实例化 APC，需指定生理变量和得分 S、具有观测模型和操作的设备（O_{d,ρ}，A_d）、患者可提供的报告，以及可安全评估智能体的环境。第2.2节针对1型糖尿病做出这些选择，第3节和第4节构建环境和任务。

2.2 血糖控制

基于规则的血糖控制器围绕结构化的血糖和治疗记录组织给药（Holt et al., 2021; OpenAPS community, 2026）。LLM-T1D 将强化学习策略蒸馏到语言模型中，用于胰岛素给药并解释其决策（Sarkar, 2026）。

我们将 APC 实例化用于1型糖尿病的血糖控制，结合设备观测与上下文报告和个人经验。状态包括血糖、仍在起作用的胰岛素、碳水化合物吸收和设备状态；进餐、活动和疾病会扰动该状态。APC 观察传感器或血糖仪读数、输送日志和警报，以及进餐、活动和设备问题的报告。其行动包括：通过大剂量推注、临时基础率或注射进行胰岛素输送；测量请求（如扫描和指尖采血）；设备管理（如取消、暂停和恢复）；以及等待。得分结合目标范围内时间、低血糖和真实血糖的变异性（第4.2节；Battelino et al., 2019）。理想化的参考是健康的胰腺，它无需设备或报告即可连续调节血糖。

在每次决策中，APC 审查最近的读数、仍在起作用的胰岛素、报告的事件及其个人记录，并估计血糖走向。然后它选择当前设备支持的一项操作并说明原因。同一决策还确定何时再次查看，以及哪些事件（如新读数、报告的进餐或警报）应提前唤醒它。监控保持控制直到其中之一发生。

个人记录存储关于该个体对进餐、活动和胰岛素反应的笔记。在多天回合中，对话每天重置而记录持续存在，修订后的治疗设置在实验条件允许的情况下持续保留。因此，适应是在模型权重固定的情况下通过经验发生的，第5.3.1节评估了保留记录的效果。附录B指定了观测和行动接口。

3 DiabetSim

DiabetSim 是一个用于血糖控制智能体虚拟测试的可配置环境。它包括生理引擎、监测和输送设备模型以及实例生成器。这些组件共同模拟个体血糖反应、日常事件和设备介导的干预。智能体观察设备读数和事件报告；评估器记录底层血糖轨迹用于评分。

3.1 模拟器引擎

引擎使用 Deichmann et al. (2023) 的模型对血糖-胰岛素动力学建模，包括体力活动的影响。个体参数 θ 指定胰岛素敏感性和依赖体重的反应。模拟器包括八种具有不同体重和黎明现象的生理类型，以及胰岛素敏感性的日间变化。进餐引入碳水化合物吸收，而活动和疾病改变后续的生理反应。模拟器将治疗设置与生理参数分开配置，允许处方治疗与个体的胰岛素需求不同。事件驱动调度器在外部事件发生和治疗行动执行时推进生理和设备状态。

3.2 设备

观测。 监测设备决定智能体可用的测量。模拟器包括八种传感器模型和六种血糖仪模型，参数化自已发表的精度规范（Vettoretti et al., 2019; International Organization for Standardization, 2013）。实时连续血糖监测仪（CGM）每五分钟产生读数；扫描传感器在扫描时返回读数，血糖仪在指尖测量时返回读数。模型表示传感器预热、数据间隙和压迫伪影。扫描和指尖测量是智能体行动，使观测时机成为控制策略的一部分。报告配置 ρ 额外指定关于进餐、活动和其他事件的报告的可用性、时机和准确性。

动作集。 输送设备决定可用的治疗操作及其约束。模拟器包括五种泵模型、10种笔模型和10种胰岛素制剂。每个设备配置 d 定义动作集 A_d：泵支持设备特定的大剂量推注、临时基础率、延长大剂量、取消和暂停或恢复的子集；笔支持离散注射。胰岛素制剂决定相应的吸收和作用曲线。设备接口根据剂量增量、剂量限制、推注间隔和设备状态验证命令，并记录被拒绝的命令及其原因。阻塞和暂停会改变实际输送，将请求的干预与实际接收的剂量区分开来。

3.3 实例生成

一个实例指定患者参数、设备和报告配置、事件时间表、初始生理和设备状态、回合前历史、评估时间范围和随机种子。生成器分配代表性参数值或从配置范围中采样，然后组合这些规范以产生具有不同患者、设备、事件和观测条件的实例。事件组合、时机和幅度可独立于患者和设备参数进行配置。保存解析后的规范可固定初始化、外部事件时间表和随机种子，用于回放和控制器之间的比较。

4 SweetBench

SweetBench 将 DiabetSim 转化为一组固定的212个评估任务。每个任务是一个固定的患者-场景配置，指定个体、事件日历、设备、智能体可用的信息、初始状态和时间范围，每个任务基于真实血糖轨迹评分。

现有的医学基准对单次就诊或所提供历史的答案、记录或计划进行评分。SweetBench 则对多天控制进行评分，其中智能体的行动塑造其后续观察的内容，并且每个得分均从真实轨迹以程序化方式计算（表1）。

4.2 指标

所有指标使用每5分钟采样的真实血糖轨迹。设 g_1, …, g_n 表示这些样本（单位 mg/dL）。我们计算目标范围内时间：

TIR = (100/n) Σ_{j=1}^{n} 1{72.064 ≤ g_j ≤ 144.128}

以及低于范围时间：

TBR = (100/n) Σ_{j=1}^{n} 1{g_j < 70}

作为百分比。TIR 在主要实验和消融中均使用4–8 mmol/L（72.064–144.128 mg/dL）。该范围比共识目标更严格，为本基准特定，而70 mg/dL 的低血糖阈值遵循 CGM 共识（Battelino et al., 2019）。

血糖标准差为 σ_g = √((1/n) Σ_{j=1}^{n} (g_j − ḡ)²)，其中 ḡ = (1/n) Σ_{j=1}^{n} g_j。

总体得分。 我们采用 COGI，它以0.50、0.35和0.15的权重结合目标范围内时间、低血糖和血糖变异性（Leelarathna et al., 2020）。我们的研究变体 COGI-4-8（下文简称 COGI）将已发表的70–180 mg/dL TIR 区间替换为4–8 mmol/L，同时保留低血糖和总体标准差分量。设 c(x) = min(1, max(0, x))。其三个子得分为：

S_TIR = TIR
S_Hypo = 100 · c(1 − TBR/15)
S_GV = 100 · c((108 − σ_g)/90)

低血糖子得分从零 TBR 时的100降至15% TBR 时的零。变异性子得分从标准差18 mg/dL 时的100降至108 mg/dL 时的零。总体得分为：

S = 0.50 · S_TIR + 0.35 · S_Hypo + 0.15 · S_GV

COGI 及所有三个子得分范围为0到100，值越高表示控制越好。结果报告其在回合上的均值，每个任务权重相等。

5 实验

5.1 设置

协议。 我们在 SweetBench 的212个任务上评估所有方法。每个72小时回合固定患者、初始状态、事件日历和随机种子，并使用模拟的 Dana-i 泵、门冬胰岛素和 I2 下的实时 CGM。进餐和其他事件保持未报告。每种方法通过相同的设备接口仅使用可见的测量和记录行动；环境在决策之间继续演化。主要评估不添加单独的后台 HCL 控制器。我们从每个回合的864个五分钟真实血糖样本计算 COGI 及其三个子得分，然后以相等权重对完成的回合取平均（第4.2节）。

基线设置。 我们比较三个控制器。基础-大剂量遵循处方的基础时间表，并根据报告的碳水化合物、血糖、碳水化合物比率、胰岛素敏感性和体内胰岛素计算进餐和校正大剂量（Holt et al., 2021; Fox et al., 2020）。事件感知基础-大剂量（BB+Rules）用针对血糖趋势、报告的运动和疾病以及设备问题的预定义规则增强该 BB 策略（Riddell et al., 2017）。OpenAPS 使用其开源给药核心从血糖反馈计算临时基础调整和微量大剂量。三个控制器均使用15分钟决策间隔和相同的可见观测。附录C.2指定了公式、规则和 OpenAPS 实现；案例研究也使用 OpenAPS 作为参考。

APC 设置。 我们使用共享的控制目标、设备工具接口和个人记录机制，评估具有五个语言模型后端的 APC。固定决策间隔为60分钟，推理力度设为「高」。

6 讨论

6.1 不完整信息下的决策

信息消融实验指出了改进智能体结合测量、事件上下文和个人历史方式的机会。在测试案例中，添加上下文比仅提高决策频率更能改善控制。显式的不确定性估计和有针对性的测量请求可帮助智能体区分胰岛素需求变化与输送或传感器问题。个人记录可保留这些推断并指导后续重新评估。

6.2 安全性

胰岛素在输送后持续起效，使剂量历史和重新评估时机成为生理控制的核心（Holt et al., 2021）。剂量限制、体内胰岛素估计和低血糖监测为改进智能体设计提供了具体机会。CL 开/关案例还启发将频繁的后台调节与较低频率的智能体决策相结合。独立的低血糖得分和行动记录支持将这些设计与整体控制性能一同评估。

6.3 仿真到现实的差距

患者特定的重建为提高模拟器保真度提供了路径。真实的 CGM 和设备记录可为生理、传感器误差和事件模式提供信息；保留的记录则可评估重建的环境。Real2Sim2Real 循环将使智能体能够在该环境中发展策略，并随着更多患者观察的获得而同时改进策略和环境。

7 相关工作

医学AI和基准。 MultiMedQA 和 HealthBench 评估临床知识和健康相关回复，而 AMIE 研究诊断对话和纵向疾病管理（Singhal et al., 2023; Arora et al., 2025; Tu et al., 2025; Liévin et al., 2026）。AgentMD 和 TxAgent 将医学推理连接到临床计算器和生物医学证据（Jin et al., 2025; Gao et al., 2025）。AgentClinic、MedAgentBench、LongMedBench 和 HealthAgentBench 通过模拟会诊、电子健康记录、纵向数据和临床工具工作流评估智能体（Schmidgall et al., 2024; Jiang et al., 2025; Xu et al., 2026; Liu et al., 2026）。

长程智能体。 ReAct 将推理与环境行动交错；WebArena、OSWorld 和 SWE-agent 研究网络、桌面和软件任务中的扩展工具使用（Yao et al., 2023; Zhou et al., 2023; Xie et al., 2024; Yang et al., 2024）。SayCan 和 Code as Policies 将基于语言的规划连接到机器人技能和控制接口（Ahn et al., 2022; Liang et al., 2022）。Reflexion、ExpeL 和 Voyager 保留反馈、经验或可执行技能，以在不更新模型权重的情况下改进后续决策（Shinn et al., 2023; Zhao et al., 2024; Wang et al., 2023）。

1型糖尿病和血糖控制。 CGM-Agent 分析个人血糖记录；DM-Bench 和 HealthLoopQA 评估对所提供历史的决策和时间推理（Cui et al., 2026; Cardei et al., 2025; Niu et al., 2026）。DIETS 和膳食规划智能体利用血糖预测优化候选干预（Zeng et al., 2024; Huang et al., 2026）。UVA/Padova 和 simglucose 支持虚拟患者评估，而自动胰岛素输送和强化学习控制器从血糖反馈调整治疗（Visentin et al., 2018; Xie, 2018; Brown et al., 2019; Sherr et al., 2022; Hettiarachchi et al., 2024; Khamesian et al., 2026）。LLM-T1D 将强化学习策略蒸馏到语言模型中用于胰岛素速率控制，并在随机24小时模拟中评估（Sarkar, 2026）。

8 未来工作

强化学习。 APC 通过其个人记录进行适应而权重保持固定。DiabetSim 还使直接基于生理结果的训练成为可能。强化学习可更新治疗、测量和重新评估时机的策略，将其与记录结合将使智能体同时获得通用技能和特定个体的知识。

Real2Sim2Real。 我们计划从真实的 CGM 和设备记录重建患者特定环境。智能体首先在个体的重建环境中建立其记录和策略，然后协助该个体，每个新观察都用于同时改进环境和智能体。

超越1型糖尿病。 APC 适用于设备可测量并作用于生理系统、且其结果可被评分的任何场景。候选领域包括其他通过药物输送设备管理的疾病以及重症监护治疗，后者中学习型治疗策略已被研究（Komorowski et al., 2018）。每个新领域需要自己的设备、环境和得分，构建它们是我们希望与社区共同开展的工作。

9 结论

我们推出了 DiabAgent，包括 APC 框架、DiabetSim 模拟器和 SweetBench 基准测试。APC 将智能体决策与医疗设备行动联系起来，并将该控制循环应用于1型糖尿病的血糖管理。DiabetSim 提供跨患者、事件、设备和观测条件的虚拟测试。SweetBench 将该环境转化为212个任务，用于评估智能体决策的生理结果。这些组件共同为智能体生理控制建立了可重现的研究环境。我们希望 DiabAgent 为智能体参与人体生理控制提供基础，并支持将这一研究扩展到其他生理系统。

BB 和 BB+Rules。 我们用处方基础时间表和大剂量计算器实现 BB（Holt et al., 2021; Fox et al., 2020）。计算器返回 u = max(0, fC/CR + q)，其中 C 为报告的碳水化合物摄入，CR 为碳水化合物比率，BB 中 f = 1。设 c = (G − G_target)/ISF，其中 G 为观察到的血糖，ISF 为胰岛素敏感性。当 c > 0 时校正项为 q = max(0, c − IOB)，否则 q = c；IOB 表示非负的大剂量体内胰岛素，以总体内胰岛素作为后备。剂量取整、设备限制和最小大剂量间隔约束执行。BB 还包括低血糖治疗和对明确设备提示的响应。我们的 BB+Rules 扩展调整 f，将 CGM 趋势纳入 G，并添加针对运动、疾病、临时基础变化和设备维护的预定义规则（Riddell et al., 2017）。两者均只使用可见报告和记录，主要评估中咨询间隔为15分钟。进餐大剂量需要可用的进餐报告。

OpenAPS。 我们的 OpenAPS 基线使用官方 OpenAPS 存储库 npm 版本0.7.1的 oref1 算法（https://github.com/openaps/oref0）及其 MIT 许可的给药核心（OpenAPS community, 2026），启用了超微量大剂量（SMB）和未报告进餐（UAM）预测。我们的适配器从可见 CGM、输送记录、个人治疗参数和碳水化合物估计构建输入，并强制执行设备限制。UAM 偏差斜率和敏感性适应采用近似实现。

OpenAPS 决策频率。 我们将该基线的固定决策间隔从15分钟变化到240分钟。将间隔从240缩短到15分钟使 COGI 从56.84提高到71.19（表12），显示了更频繁反馈对该控制器的益处。

HCL。 HCL 表示默认的 DASH 后台控制器：DASH 有 CL 启用它，DASH 无 CL 禁用它。该软件层遵循公开的闭环设计并集成 OpenAPS 核心，在新的 CGM 读数到达时调整基础输送（OpenAPS community, 2026）。智能体保留其决策时间表并选择剂量、碳水化合物摄入和设备行动；智能体设置的临时基础优先生效直至到期或取消。独立参考以相同实现每五分钟运行，在匹配的 DASH/Fiasp、患者、种子、事件和 CGM 条件下，采用基于规则的传感器维护且无智能体。
