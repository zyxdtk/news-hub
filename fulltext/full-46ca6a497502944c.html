摘要

大多数企业办公环境都实施了策略和技术控制，限制在客户端终端上存储敏感数据。因此，勒索软件操作者不断演化出新的变种，将其攻击面从本地系统扩展到网络驱动器和共享存储资源。由于传统的终端检测机制主要关注本地系统行为，被攻陷的客户端可以影响远程文件服务器（例如加密共享数据），而不会直接在服务器上触发行为变化。本文提出了一种混合检测框架，用于在集成的文件服务器和客户端环境中检测加密勒索软件入侵。该框架基于一种称为"感兴趣区域"（Region of Interest, RoI）的新技术，用于分析网络流量并提取入侵指标。IoC 仓库作为额外的规则集，用于增强 EDR 和 IDS 等现有安全工具，同时 RoI 衍生的特征用于训练机器学习模型，以检测高度规避型变种。本研究纳入了更广泛的勒索软件家族，并根据领域专业知识精心选择了良性行为，确保覆盖可能干扰勒索软件检测的常见用户操作。除了基于签名方式运作的 IoC 之外，我们的机器学习模块实现了 99.64% 的检测精度，假阴性率为 0%，假阳性率极低。此外，所提方法支持早期检测，能够在重大损害发生之前识别勒索软件入侵，准确率达到 99.44%。

关键词： 勒索软件检测、网络流量分析、入侵指标、机器学习、早期检测、规避型勒索软件、终端保护、入侵检测、网络安全

1 引言

尽管勒索软件通常被视为网络安全领域的新兴现象，但将计算机数据作为人质的概念可以追溯到 1989 年出现的 AIDS 木马。该木马由进化生物学家、哈佛大学校友 Joseph Popp 博士开发，在斯德哥尔摩举行的世界卫生组织（WHO）艾滋病大会之后被分发。Popp 通过邮件将受感染的软盘发送给与会者，标志着已知最早的为经济利益而勒索个人的恶意软件实例之一。

AIDS 木马的受害者最初被要求支付约 189 美元以重新获得对加密数据的访问权限 [smith1990aids]。此后，每年都有新的变种和勒索软件家族出现，在复杂性和影响力方面不断演化。与传统计算机病毒不同，勒索软件通常不会对操作系统造成永久性损害。然而，它可以禁用某些系统服务，通常使系统无法使用，直到受害者支付赎金。其中最普遍的勒索软件类型之一是加密勒索软件，它加密受害者的数据并要求以付款换取解密密钥。从破坏性角度来看，加密勒索软件因其能够锁定关键数据，仍然是最重大的威胁之一。

对抗勒索软件攻击的策略涉及电子和非电子方法的结合。非电子策略主要侧重于教育用户了解网络安全威胁，特别强调网络犯罪分子使用的社会工程学技术。电子策略则涉及在目标终端上部署专用软件，以防止勒索软件或其他形式的恶意软件成功执行。

到目前为止，电子方法已被证明是抵御勒索软件攻击最可靠的防御手段。然而，目前用于检测勒索软件的软件工具往往未达预期，特别是由于网络犯罪分子采用的新型高级技术导致的零日攻击。为了缓解零日漏洞带来的挑战，大量学术文献（如 [1] 中所述）建议利用机器学习（ML）的力量来增强现有检测工具的有效性。

除零日攻击外，勒索软件操作者越来越多地采用先进技术和黑客手段来攻陷目标，确保勒索软件载荷成功执行。这种做法通常被称为"规避"（evasion）。为了应对这些不断演变的威胁，建议增强检测工具，使其能够在不完全依赖主机系统状态的情况下识别事件。一种可能的方法是通过纳入其他信息源（如网络流量）来扩大检测范围，从而提供对攻击的额外洞察。

大多数企业办公环境都实施了策略和技术控制，限制在客户端终端上存储敏感数据。在 Windows 环境中广泛使用的文件共享技术之一是服务器消息块（SMB）协议。

SMB 于 1983 年开发，旨在实现网络上计算机之间的文件共享，允许远程设备（服务器）通过 TCP/IP 连接向客户端提供文件访问。自诞生以来，SMB 经历了多次改进。SMBv1 随 Windows Server 2003 实现，但被发现容易受到 EternalBlue 漏洞利用的攻击，随后在 2003 年被弃用。SMBv2 在 Windows Server 2008 和 Windows Vista 中取代了 SMBv1，尽管存在窃听漏洞（因为服务器和客户端之间交换的所有消息均以明文传输），但仍被广泛使用。

最新版本 SMBv3 支持数据加密以解决这些安全问题。SMBv2 和 SMBv3 仍然受到支持并被积极使用 [SMB1vsSMB2]。例如，当代 Microsoft 操作系统（包括 Windows 10、Windows 11 以及 Windows Server 2019、2022 和 2025 等版本）默认启用 SMBv2 及更高版本，并在通信过程中协商最高双方支持的 SMB 方言。

除通用 IT 系统外，SMBv2 还常见于遗留和受限环境中，包括物联网和运营技术系统，这些环境中设备生命周期长、供应商依赖性强以及固件更新能力有限，往往延迟了新 SMB 方言的采用。SMBv2 也广泛实现在非 Windows 平台上，如基于 Samba 的系统和网络附加存储设备，实现异构网络间的互操作性。

SMB 数据由客户端发起的命令组成，用于访问和操作远程服务器上托管的远程文件。SMB 数据结构包括承载不同命令的各种头部 [opcode]。当数据通过 OSI 模型的各层时 [Encapsulation]，会经历封装过程。如图 1 所示，SMB 数据被传递到传输层，在此根据一次可传输的最大字节数被划分为更小的块（称为段或流）。这些段的大小由 TCP 标准控制的协商过程确定。在传输层，TCP 头部被添加到每个段中，然后传递到网络层。网络层为段添加 IP 地址，确保它们可以在网络中路由。此时，段被称为数据包，被转发到数据链路层进行最终交付。

该协议的典型用例是由文件服务器和多个客户端 PC 组成的环境。客户端 PC 通过映射的网络驱动器访问文件服务器上托管的文件。

虽然文件共享环境中的勒索软件检测研究并非新课题，但先前的研究仍存在若干局限性，例如：

  • 数据集和环境偏差风险： 将真实用户流量作为良性基线并不能保证环境中立性。用户行为受组织背景、系统使用模式和访问控制的强烈影响，这可能限制不同环境中良性和恶意流量的可比性。此外，无法保证观察环境中的合法用户活动能够生成与勒索软件操作相当的行为模式，特别是在文件访问率、目录遍历和网络共享交互方面。因此，检测模型可能捕获的是环境特定的工作负载特征，而非勒索软件行为的不变指标。

  • 可重复性和可比性有限： 从真实生产环境中收集的网络流量通常受隐私和保密性约束，因此不太可能被共享。此类数据集的不可用性限制了其他研究人员复现结果、独立评估所提技术或与替代方法进行公平比较的能力。

  • 数据集不完整： 缺乏同时包含恶意和良性样本的数据集仍然是勒索软件检测研究面临的重大挑战。

2 相关工作

在本节中，我们回顾先前学术文献中提出的用于文件服务器环境中勒索软件检测的各种技术。

[Berrueta2019] 中提出了 REDFISH 算法。Morato 等人分析了网络流量中的 SMBv2 协议，设计了文件共享环境中的勒索软件检测算法。该研究涉及来自 19 个勒索软件家族的 50 个样本。该算法通过分析文件共享网络流量（特别是共享目录上的 SMB 操作）来早期检测勒索软件活动。它监控文件读取、写入和删除操作的序列和时序，寻找勒索软件特征性的模式，如快速读取文件后立即写入加密内容。当在短时间窗口（$T$）内发生预定义数量的文件删除（$N$）且平均读/写吞吐量超过阈值（$V_{\text{thres}}$）时，REDFISH 会触发告警。通过实时关联这些事件，该算法能够在重大数据丢失发生之前识别勒索软件活动，而无需在终端上安装任何软件。REDFISH 算法的一个显著局限是它需要解析所有网络流量以提取文件路径和 SMB 命令，这可能在高吞吐量网络中引入大量计算开销。此外，该算法假设共享环境中存在某些文件和目录结构；组织布局或文件夹层次结构的变化可能影响早期检测的准确性。另外，该方法依赖于文件共享流量的可见性，因此加密或混淆的 SMB 会话可能影响其有效性。

[EduardoBerrueta2022] 中最近提出了一种机器学习（ML）模型。E. Berrueta 等人（2022）扩展了 SMB 流量研究，重点关注较新的 SMBv3 协议。该研究将客户端和服务器之间交换的 TCP 数据包与勒索软件相关的文件操作（包括读取、写入和其他命令活动）相关联。这些事件在一秒时间窗口内聚合，生成的数据集特征代表不同时间间隔内累积的字节量。虽然不同的 ML 模型在不同时间间隔下进行了测试，但神经网络（NE）保持了 99% 以上的准确率。

3 所提方法

基于前述勒索软件检测方面的差距，本节介绍用于在文件共享环境中检测加密勒索软件的混合框架的详细信息。

该框架严重依赖于称为感兴趣数据包（$PoI$）和入侵指标（$IoC$）的数据包代码。我们提取了加密（SMBv3）和非加密（SMBv2）环境的代码。然而，为了保持论文简洁性，我们使用 SMBv2 代码来展示框架。SMBv3 的等效代码保留在单独的 IoC 数据集中。该框架的主要模块包括逐包 IoC 检测、逐 RoI 检测和基于机器学习的检测。

如图 2 所示，这些组件的组合实现了早期检测、自动修复和有效的事件管理。系统使用 IoC 检查每个网络数据包是否存在已知行为。如果数据包匹配任何 IoC，表明是已知攻击，系统立即触发自动修复，停止进一步处理。如果数据包不包含任何 IoC，则通过感兴趣区域（RoI）流程处理。该方法分析数据包的上下文和行为，以识别可疑活动或未知攻击模式。如果 RoI 分析将数据包识别为恶意，系统会向安全运营中心（SOC）团队发出告警以进行进一步调查和响应。

3.1 逐包 IoC 检测阶段

该模块针对已知指标（如勒索信息投放的存在）扫描单个数据包，并在检测到匹配时立即启动修复。勒索软件必须告知受害者所造成的损害并提供付款说明。常用的方法是在受害者设备上的一个或多个文件夹中投放勒索信息。这是唯一不会被加密的文件。此类文件的长度或大小取决于其包含的信息；不同家族有所不同。由于每个家族具有唯一的消息大小，它成为已知勒索软件家族的入侵指标。在实验中，可以通过文件属性手动确定消息大小，然后存储在 $IoC$ 仓库中，供实时流量检查时参考。我们目前发现的此类文件的一些特征包括：

  • 在一个文件夹中出现一次
  • 始终是 $C410$（新创建文件）的结果
  • 在所有文件夹中大小相同
  • 可以拆分为小块以规避检测

我们使用算法 1 中的过程来检查网络数据包。对于 SMBv2 长度为 410 的数据包之后的每个网络数据包，如果数据包长度值与我们收集的任何 $IoC$ 匹配，则该数据包为恶意，触发告警或纠正操作。如果没有匹配，该数据包进入下一阶段。

3.3 基于机器学习的检测阶段

该模块通过分析感兴趣区域数据包中偏离既定模式的异常行为来检测新型勒索软件变种。这些行为可能包括加密数据的存在或对共享文件的不规则访问，这些是潜在勒索软件活动的指标。

机器学习（ML）在人工智能（AI）中扮演着关键角色，使计算机能够模仿人类思维。ML 涉及各种算法，使用分层、概率或决策树等技术对数据进行分类。每种 ML 技术采用多种方法来捕获和操纵现有数据中的模式，从而允许对未见数据进行分类。这些方法的知名示例包括支持向量机（SVM）、神经网络、逻辑回归、判别分析、随机森林、线性回归、朴素贝叶斯、K 近邻和决策树。值得注意的是，神经网络已发展成为一个独立的领域，称为深度学习，在 AI 研究中引起了广泛关注。选择哪种 ML 技术或方法取决于所分析数据的性质和复杂性。

所有 ML 方法的一个共同特征是它们依赖基准数据集，作为训练算法的基础。一旦建立了基准数据集，下一个关键步骤是特征选择，即确定应使用哪些数据模式来训练模型。这一步骤是传统机器学习与深度学习之间的关键区别，特别是在处理大型数据集时。在传统 ML 中，通常需要人工干预来选择最相关的特征进行训练。相比之下，深度学习模型（特别是神经网络）可以自主识别哪些特征最相关，最大限度地减少手动特征选择的需求。在本框架中，我们使用 Random Committee 机器学习模型。选择 Random Committee 而非其他 ML 技术是基于第 6 节讨论的实验结果。

4.1.2 良性样本

在先前的工作中，有少量论文详细描述了良性样本的获取。例如，Edwardo 等人 [EduardoBerrueta2022] 通过截获真实生产环境中的网络流量来创建良性样本。Fernando 等人 [Fernando2024] 使用 VeraCrypt、AxCrypt、BitLocker 和 7-Zip 作为良性样本。

对于我们的方法，我们采用了广泛的方法来生成良性样本。我们尝试模拟大多数可能的正常用户操作，这些操作会产生接近勒索软件的行为，如下所述并呈现在表 3 中。

  1. 数据加密。 实际上，在用户访问集中托管文件服务器的生产环境中，允许用户加密其数据是罕见且不安全的。IT 部门更愿意在文件服务器上部署此类工具；这就是为什么大多数商业加密工具仅限于本地和扩展磁盘分区。然而，有少数工具用户仍可在需要时用于加密数据。

  • Hicrypt： 我们搜索并发现 Hicrypt 是少数能够在网络共享上加密文件的工具之一。该工具允许用户在网络共享中创建一个空文件夹然后加密它。之后添加到该文件夹的所有新文件将自动被加密。因此，我们清空网络驱动器并使用 Hicrypt 加密，然后将其导入同一数据文件夹，同时捕获网络数据包。

  • Windows 加密工具： Windows 加密工具可以加密本地和网络文件。虽然在生产环境中很少被允许，但我们决定捕获此操作的行为，以便如果由于某种原因发生这种情况，我们的检测模型应保持准确和精确。

  • WinRAR、Winzip、7Zip： 我们发现大多数文件压缩工具（如 WinRAR、WinZip 和 7Zip）都有加密压缩数据的选项。因此，我们使用加密选项运行这些工具，然后捕获网络流量。此操作的结果是一个压缩和加密的文件。我们在执行另一个工具之前删除压缩文件。

  1. 批量数据导入和删除。 用户通常在网络共享上执行的操作之一是从其他存储导入大量数据。此操作会触发接近勒索软件的行为，因为会创建许多新文件，同时写入大量数据。为了模拟此操作，我们使用了 Windows 复制工具，因为它是现实生活中最常用的工具。我们还使用了第三方工具 TeraCopy 和 UltraCopier，因为一些用户更喜欢它们而非 Windows 工具。我们清空网络驱动器，然后粘贴到用于勒索软件分析的同一文件夹中，反之亦然。

  2. 数据压缩。 有时，用户可能需要通过电子邮件、FTP 传输大量文件或与外部合作伙伴共享。这可以通过将多个文件和文件夹压缩为一个来实现。这样做会创建一个新文件（容器），文件会更改扩展名，这与勒索软件在加密后更改所有文件扩展名并重新创建文件内容的行为非常相似。虽然有许多第三方工具用于压缩文件，但我们选择使用 WinRAR、WinZip 和 7-Zip，因为它们是 Windows 环境中最常用的工具。WinRAR 和 WinZip 有用户可以从中选择的输出扩展名（.zip 和 .rar）。我们在捕获网络流量的同时运行这些工具。

4.2.1 感兴趣区域 RoI

处理网络流量跟踪用于机器学习应用面临重大挑战，因为单个网络数据包本身通常包含有限的信息。因此，将机器学习应用于网络流量的关键步骤是将单个数据包聚合为更具信息量的数据样本。在本研究中，我们引入了一种称为"感兴趣区域"（RoI）技术的新方法来解决这个问题。RoI 方法旨在将相关数据包聚合为连贯的数据样本，确保聚合的信息捕获下游分析和特征提取所需的上下文。

服务器消息块（SMB）消息通常由用于会话建立和终止、文件打开、读取、写入、状态检查及其各自响应的数据操作命令组成 [opcode]。我们的研究观察到，SMB 客户端经常在目录中导航，以来回方式枚举内容。此行为由一个特定数据包促成，该数据包无论环境或访问的目录路径如何，大小始终一致（260 字节）。它作为 SMB 客户端进程的指示器，向其发出当前目录中所有项目是否已被枚举以及客户端是否需要遍历回或前进到其他子目录的信号。我们将此数据包称为 $p260$，并使用算法 3 提取。

算法 3 中概述的过程需要一组从第一个 $p260$ 出现到后续 $p260$（不包括后者）之间收集的网络数据包跟踪。因此，我们将感兴趣区域（RoI）定义为两个连续 $p260$ 数据包之间的活动集合。

加密过程将明文作为输入送入密码算法以产生密文。这意味着原始文件内容被密文替换。勒索软件更进一步，更改文件的扩展名。我们发现，此任务使用称为感兴趣命令（$CoI$）的特殊 SMB 命令完成，如下所述。

  1. 在某个时刻，客户端想要读取一个尚不存在的文件；因此它将创建它，服务器将回复确认新文件已创建。此响应/反向数据包被发现具有 410 的静态长度，无论环境或文件路径如何。此 $CoI$ 称为 $rp410$。

  2. 在某个时刻，客户端将读取当前目录中的任何文件；此前向数据包被发现具有 171 的静态长度，无论环境或文件路径如何。此 $CoI$ 称为 $rq171$。

  3. 在某个时刻，客户端将向当前目录中的文件写入数据，服务器将回复写入该文件的字节数。此反向/响应数据包被发现具有 138 的静态长度，无论环境或文件路径如何。此 $CoI$ 称为 $rp138$。

  4. 在某个时刻，客户端尝试打开文件/文件夹，服务器以 $rp378$ 响应。

  5. 在某个时刻，客户端想要在文件上设置新信息（如重命名）。此前向数据包被发现具有 124 的静态长度，无论环境或文件路径如何。此 $CoI$ 称为 $rq124$。

  6. 在某个时刻，客户端将关闭打开的文件/文件夹。此前向数据包被发现具有 $rq146$ 的静态长度。

4.3 训练机器学习模型

在本小节中，我们使用前面小节中创建的数据集来创建一个基于历史样本数据检测勒索软件的学习模型。来自测试平台的原始数据集不平衡，包含 844 个良性样本和 1600 个勒索软件数据样本。

  • 数据清理。 我们移除了与 $IoC$ 对应的数据样本。我们这样做是因为这些数据具有所有勒索软件家族的知名且独特的特征，在良性样本中不会出现。这些数据被收集在单独的 $IoC$ 仓库中，如前所述，用于 $IoC$ 检测阶段。这将勒索软件数据样本减少到 1262 个。

  • 数据平衡。 在训练 ML 模型时使用平衡数据集始终是一个好主意，我们使用 Python 函数从 1262 个勒索软件样本中随机选择 844 个。此任务在勒索软件样本仍带有标签（勒索软件家族名称）时完成，以确保所有家族都被代表。然后我们将结果子数据集中的实例标记为勒索软件。

  • 训练与测试。 监督机器学习需要带标签的样本数据进行训练和未标记的数据进行测试。这可以通过将整个数据集拆分为训练和测试子数据集或使用 K 折交叉验证 [K-FOLD] 来实现。拆分数据集通常通过随机采样实现。该方法的问题在于，单次运行可能选择不相关的数据，导致有偏学习。另一方面，K 折交叉验证技术将数据集拆分为多个样本组（K），产生偏差较小的学习模型。因此，在本研究中，我们使用了 10 折交叉验证。

  • 评估。 我们使用不同的传统机器学习技术测试了数据集，并评估了每种技术的性能。与 ML 适用的其他领域不同，高假阴性率使企业面临比假阳性率更高的风险。换句话说，被检测为恶意的良性应用程序只会造成时间浪费，而公司数据保持完好。但未被发现的恶意应用程序将导致数据/系统损坏、财务损失，并花费更多时间进行恢复 [Maniriho2022]。虽然大多数先前的工作根据公式 2 和 3 分别基于准确率和假阳性率评估 ML 模型，但在本研究中，我们将评估扩展为包括假阴性率指标，如公式 4 所示。

$$Accuracy=\frac{(fp+tp)}{(tn+fp+tp+fn)} \quad (2)$$

$$FPR=\frac{(fp)}{(fp+tn)} \quad (3)$$

$$FNR=\frac{(fn)}{(fn+tp)} \quad (4)$$

其中：
- $fp$ == 被分类为勒索软件的正常样本数
- $fn$ == 被分类为正常的勒索软件样本数
- $tp$ == 被分类为勒索软件的勒索软件样本数
- $tn$ == 被分类为正常的正常样本数

5 结果与讨论

在本节中，我们分析实验结果及其对勒索软件检测进展的贡献。

早期检测。 早期检测是指在执行的载荷完成所有任务之前捕获动态特征的模型。目标是在入侵造成最大损害之前检测到它 [Cen2024]。不同的学术文献（如 [Deng2023]）提出了专用于基于主机的勒索软件早期检测的方法。Berrueta 等人 [Morato2018] 提出了一种使用阈值基于 SMB 网络流量进行勒索软件早期检测的方法。

在我们的数据集中，最小的勒索软件数据样本大小为 8（Ako 和 Coronavirus）。因此，对于每个勒索软件家族，我们首先创建了一个 8 个 $RoI$ 的滑动窗口。这意味着第一个测试场景有 176（8×22）个样本，第二个有 352（16×22）个，以此类推。对于每个测试场景，我们从良性数据集中随机选择等效的良性样本，然后以与完整检测相同的方式对数据进行分类。产生高准确率的窗口大小被认为是早期检测的最佳大小。如图 4(a) 所示，前 48 个 $RoI$ 产生了 99.44% 的准确率，仅比完整检测准确率低 0.24%。

由于不同的勒索软件家族具有不同数量的 $RoI$，每个家族在早期阶段可被检测的程度显然不同。例如，图 4(b) 显示 Lockbit 可以在其执行的 36% 时被完全检测到。只有 Ako、Coronavirus、Netwalker 和 Avoslocker 需要完成执行，因为它们产生的 $RoI$ 数量相当少。

数据集和 $IoC$ 仓库。 作为实验结果的一部分，我们从 22 个勒索软件家族和 15 个良性应用程序创建了 $RoI$ 数据集。良性和勒索软件样本均从同一环境（测试平台）收集。良性样本涵盖了大量良性应用程序，以模拟人类可以执行的、与勒索软件行为几乎相似的操作。我们发现并提取了新的基于网络的 $IoC$，将其存储在仓库中，用于签名或基于规则的检测技术。

6 结论与未来工作

本文提出了一种新的框架，通过将感兴趣区域（RoI）技术应用于 SMB 网络流量来检测加密勒索软件。该框架在三个不同阶段运行：前两个阶段以签名模式运作，针对已知入侵指标检查单个和聚合数据包，而第三阶段采用 Random Committee 学习模型，实现了 99.64% 的令人瞩目的准确率，没有勒索软件未被检测到。此外，我们评估了机器学习模型的早期检测能力，实现了 99.44% 的显著准确率。

此外，我们的研究发现了新的 IoC，可用于签名和基于规则的检测系统。这一贡献在学术和工业方面都具有重要意义。实验在 SMBv3 上对加密和非加密网络流量进行了测试，所呈现的 IoC 对应于非加密流量。然而，每个代码在加密流量中都有对应的代码。在未来的工作中，我们计划扩展分析以包含更多勒索软件家族，并持续更新我们的数据集。
