原标题：Google’s Gemini Decision 1 model scores up to 1,000 questions in one API call

中文摘要： 谷歌 DeepMind 发布 Gemini Decisions API 及 Gemini Decision 1 模型，可在一次调用中对同一材料回答多达 1000 个问题，支持文本、图像、音频、视频和 PDF 混合输入，每百万输入 token 收费 0.10 美元，输出免费。该模型在谷歌自家基准测试中领先且校准误差最低，但独立指数仅列第九。文章对比了 TypeSafe Jev、OpenAI GPT-6 Luna、亚马逊 Strands Decider 等竞品的价格与性能，并给出生产环境部署决策模型

卡尔·弗兰森（Carl Franzen）
太平洋时间 2026 年 11 月 11 日下午 3:03
图片来源：VentureBeat，由 OpenAI ChatGPT-Images-2.6 制作

谷歌 DeepMind 于周三发布了 Gemini Decisions API，面向需要软件快速做出一系列小型判断的开发者。例如，理赔受理系统可以在一次请求中发送扫描表格、受损照片以及客户来电记录，询问该理赔应进入哪个队列、证据是否缺失、以及需要多紧急地进行人工审核。该 API 会返回答案和置信度分数，应用程序可据此推进案件处理。

谷歌的新模型 Gemini Decision 1 可以在一次处理中对同一材料回答多达 1,000 个问题。谷歌按每百万输入 token 收取 0.10 美元，输出免费。这使谷歌进入了一个已有玩家竞争的市场：TypeSafe 的 Jev 已经在处理低成本分类任务，OpenAI 的 Decisions API 运行在 GPT-6 Luna 上，而亚马逊的 Strands Decider 则让开发者可以选择在自己的基础设施上运行模型。

Gemini 的企业级应用场景始于请求中包含的内容。需要处理录音、视频片段和 PDF 的团队可以一起评估这些文件。而只对短文本工单进行路由的团队则有更便宜的托管选择，且 Artificial Analysis Decision Index 显示 Jev 和 Gemini 在整体质量上不相上下。

一次请求即可覆盖整个检查清单

《Decisions API 指南》描述了三类问题。是非题返回某一条件成立的概率。多选题从 2 到 255 个命名选项中进行选择，并报告每个选项的概率。评分标准题则返回加权分数以及开发者自定义量表上的各项概率。

应用程序可以利用这些概率将模糊案例转给人工处理，或请求第二个模型做出判断。

该模型只需对输入进行一次遍历即可为所有可用选项评分。它可以同时读取文本、图像、音频、视频和 PDF，开发者可以调整图像和视频的分辨率，以控制模型看到的细节量以及媒体消耗的 token 数。262,144 个 token 的上限涵盖了共享证据以及所有问题的指令和选项。

每个问题都独立评估。如果第二个决策依赖于第一个决策，应用程序可以在代码中处理这种依赖关系，或者进行后续调用。诸如起草解释说明或从文件中提取任意发票号码之类的任务，仍然需要单独的生成或提取步骤。

谷歌表示，Gemini Notebook 使用该模型将查询路由到不同的模型和推理努力级别。该公司报告称，在该工作流中常规查询的延迟最多降低了 40%，路由步骤可以将更耗时的模型留给更难的请求。

谷歌的定价页面对每次请求中的共享输入只计费一次，并对每个问题新增的 token 进行计费。以一份 4,000 token 的记录和 20 项各新增 50 token 的检查为例。按谷歌的费率，一次 5,000 token 的请求每 1,000 条记录的成本约为 0.50 美元。而 20 次单独调用（每次都重新发送记录）每 1,000 条记录的成本为 8.10 美元，这还不包括任何重试或后续调用。该示例假设这些 token 数量即为计费总量。当完整输入在另一次请求中被重复使用时，谷歌会再次对其收费。

开发者可以从 Gemini Developer API 的 v1beta 端点以及 Google AI Studio 的免费层级开始使用。谷歌列出的免费层级限制为每分钟 200 次请求和 50,000 个输入 token。OpenRouter 和 Vercel AI Gateway 也列出了该模型。Vercel 引导使用音频、视频或 PDF 的开发者使用其 AI SDK 7 集成。谷歌表示，Google Cloud 中对 Gemini 的支持即将推出。

对于使用客户记录进行测试的团队，Gemini API 条款对付费和免费访问进行了区分。谷歌表示，付费服务的提示和响应不会被用于产品改进，日志仅保留有限一段时间，用于政策执行和必要的披露。其免费服务条款允许将数据用于产品改进，但有地区性例外。

谷歌的基准测试领先优势取决于具体任务

在谷歌的发布基准测试中，Gemini Decision 1 在所有四个模型共同参加的七项测试中的五项里领先。它在 JevBench 上得分为 92.2%，领先于 GPT-6 Luna 的 90.9% 和 Jev 1.14 的 90.0%。

Jev 在浏览器任务基准 Mind2Web Multimodal 上以 86.8% 对 86.2% 领先，在测试工具使用决策的 When2Call 上以 82.0% 对 79.9% 领先。

在两项媒体测试中，谷歌将 Decision 1 与 Gemini 3.5 Flash-Lite 进行了比较。Decision 1 在音频基准 MMAU 上得分为 71.8% 对 67.7%，在 Video-MME 上得分为 69.1% 对 63.3%。

在谷歌的对比中，Decision 1 的校准误差最低，为 0.0250，约为 Jev 的 0.0494 的一半。校准衡量的是模型的置信度与其正确频率的吻合程度。当置信度阈值决定有多少案例需要人工审核时，这一点非常重要。谷歌还报告称，其共享测试的成本为：使用 Decision 1 花费 0.88 美元，使用 Jev 花费 0.68 美元，而通过 Interactions API 使用 Gemini 3.5 Flash-Lite 则花费 4.14 美元。在该工作负载上，Flash-Lite 的成本约为 Decision 1 的 4.7 倍。

谷歌报告的 150–250 毫秒端到端延迟适用于最多 16K token 的输入，当请求从 1 个问题增加到 100 个问题时变化不大。谷歌估计在这些条件下模型计算的中位耗时为 50–100 毫秒。计划使用完整上下文窗口或 1,000 个问题上限的团队，应该测量自己的文件和检查清单所需的时间，包括上传媒体所花费的时间。

独立的 Artificial Analysis Decision Index v2.1 在发布时将 Gemini 排在 18 个模型中的第九位。该指数综合了六项评估，包括文档审查、工具调用、知识和推理。其延迟数据是各测试中位数的加权平均值，成本列估算的是按各模型标称费率计算、该测试组合下一百万个任务的成本。

模型 Decision Index 得分 每任务耗时 每百万任务成本
Drex Max v1.1 72.62 283 毫秒 103 美元
Jev 1.14 66.23 92 毫秒 156 美元
Gemini Decision 1 65.98 211 毫秒 345 美元
GPT-6 Luna（Decisions） 60.25 206 毫秒 339 美元
Clef-Omni 57.75 192 毫秒 529 美元

Gemini 在独立测试套件的知识和推理测试中领先。在 AA-Paperclip（对每份简历、研究论文、发票或收据提出 15 个问题）上，Gemini 在 33% 的文档上全部答对，而 Jev 为 35.5%，Drex Max v1.1 为 63%。

要求每个字段或每项检查都正确的工作流会关注这种"全对或全错"的指标，即使单个答案的得分很好。在 Artificial Analysis 的 When2Call 测试中，Drex Max 的准确率为 94.6%，在这三个模型中紧随其后的是 Jev 的 80.8% 和 Gemini 的 75.2%。

Jev 在文本路由上更便宜，OpenAI 可跨调用复用上下文

TypeSafe 将 Jev 1.14 的价格定为每百万输入 token 0.042 美元，输出免费。与 Gemini 一样，它可以在一次调用中评估关于共享记录的多个问题。Jev 的标准限制是整个请求 64K token，共享材料加上任何单个问题为 32K token。

一项实验性设置可将这两个限制都提高到 262K。Jev 可以接受文本和结构化 JSON，其可选开启的图像支持允许开发者将 PNG 或 JPEG 附加到共享材料或单个问题上。1.14 版本还新增了实验性的边界框答案，用于定位图像中的对象。对于简短的支持工单或常规工具选择，Jev 的价格及其在独立测试套件中 92 毫秒的成绩使其成为一个很好的基线选择。

OpenAI 于 10 月 22 日正式全面推出其 Decisions API。GPT-6 Luna 是该端点上唯一支持的模型。一次请求最多可以提出 400 个问题，并可使用文本、图像、原生 JSON 或先前工具调用的记录作为证据。图像也可以放入单个问题中。

开发者若要将产品照片与共享参考进行比对，可以为每个问题附加不同的图像。对于语音应用，OpenAI 的 GPT-Live 集成可以根据部分转录文本触发决策。

OpenAI 对未缓存的输入 token 每百万收取 0.10 美元，输出免费，与谷歌的基础费率一致。其缓存读取价格为每百万 token 0.01 美元，缓存写入另行收费。这为需要跨多次请求重复发送相同政策手册、产品目录或参考图像的团队提供了一个选择。可复用的前缀需要至少 1,024 个匹配的 token，特定于某个问题的内容则位于该前缀之外。区域处理和长上下文定价也会影响账单。OpenAI 为符合条件的客户提供零数据保留选项，并支持在美国、欧洲经济区和瑞士进行区域处理。

在输入格式合适的情况下，还有两个竞争者值得纳入考虑。Nace AI 的 Drex Max v1.1 每百万输入 token 收费 0.03 美元，支持文本、JSON 和图像，其独立的文档和工具使用测试结果值得与公司自身的业务进行对照验证。

在音频和视频方面，Cloudflare 的 Clef-Omni 支持这两种格式，在 Workers AI 上提供 64,000 token 的窗口，价格为每百万输入 token 0.15 美元。Cloudflare 还公开了模型权重，为需要在自己的环境中运行媒体评估的团队提供了又一个选择。

亚马逊的 Strands 让自托管成为切实可行的选择

亚马逊于 10 月发布了 Strands Decider 2B，VentureBeat 在发布时进行了报道。其当前基于 Qwen3.5 的 2B 检查点支持对文本进行是非题、多选题和评分标准题。它以 Apache 2.0 许可证提供，附带服务代码和训练方案。团队可以在 CPU 或 GPU 上运行它，并自行承担计算和运维费用。这使得它对希望将决策步骤保留在自己网络内部的公司颇具意义。

亚马逊报告称，2B 检查点在使用 4,096 token 窗口的情况下，在 JevBench v1 的 231 项公开任务上达到 77.9% 的准确率。其较早的 v19 检查点在本地 RTX 3090 上回答单个问题的中位耗时为 115 毫秒，第 95 百分位耗时为 299 毫秒。亚马逊后续的 Gemma 4 变体在同一公开测试集上的准确率为 77.9% 至 89.6%。

谷歌和亚马逊报告的 JevBench 结果来自不同的运行。权衡这些选择的买家应该在两种部署上测试相同的问题，并测量从请求到答案的完整耗时。

亚马逊的一个内部工单路由部署更好地展示了自托管如何带来回报。工程师们在切换应用标签的模型之前，将 Strands Decider E4B 与 Claude Sonnet 4.6 并行运行。他们缩短了 20 个标签的判定标准，并裁剪了长工单上最早的评论，以适应模型。

亚马逊报告称，平均每次调用耗时从约 4.2 秒降至 0.9 秒。按照公布的 AWS 价格及其观察到的实例利用率，该团队估算成本约为每百万张工单 500 美元，而 Sonnet 工作流的成本为 22,200 美元。考虑采用相同方法的买家需要为自己的容量以及运维人员的时间进行成本核算。

决策模型在生产环境中的部署位置

当同一事项以多种格式到达并触发检查清单时，Gemini 是一个很好的首个试点选择。客服中心可以发送带有订单元数据的录音，并要求模型识别问题、选择审核队列，并标记通话中是否出现了必要的披露内容。

在基于照片的损坏评估工作流中，同一请求可以将表格中的证据与多张照片进行核对。在这两种情况下，都应单独审查各项决策。队列路由的出色表现并不能说明模型漏掉罕见披露内容的频率。

对于构建智能体的开发者来说，决策模型可以放在工具调用之前。询问所提议的工具是否相关、对话中是否出现了必要的细节、以及该操作是否应该由人工审核。为可用选项之外的情况定义明确的升级处理选项。

将访问控制、审批要求和交易限额保留在应用程序代码中。在 VentureBeat 报道的一次提示注入测试中，一个植入的字段就将 Jev 阻止某项操作的概率从 0.76 降至 0.48。

在让候选模型的输出更改客户记录之前，先让其与现有工作流并行运行。使用来自真实流量的标注样本，包括罕见案例和拍摄质量差的媒体。为每个决策和每个模型设置置信度阈值。

对于多选题，谷歌使用所选选项的概率作为其置信度分数。在 TypeSafe 的示例中，Jev 为某个选项分配了 0.61 的概率，但返回的置信度分数为 0.42。

跟踪进入人工审核的案例比例、模型自动处理案例中的错误率，以及第 95 百分位的端到端延迟。对于短文本，可在同一数据集上运行 Jev 或 Drex。

对于录音和视频，可在相同片段上比较 Gemini 和 Clef-Omni，并测量每项服务计费的 token 数量。当应用程序可以跨请求复用较长的参考材料时，可将 Luna 纳入比较；当可以在自己的环境中提供服务时，可将 Strands 纳入比较。

比较每个正确处理案例的成本和时间，包括那些仍需要人工处理的案例。
