摘要

长视频问答通常被作为帧选择问题来研究：视觉-语言模型应该看到哪几帧？我们提出了 VideoRouteAudit，这是一项受控审计，将这一选择与另外两种替代方案区分开来：注入非视觉证据和路由到另一个回答模型。该审计固定骨干模型、帧预算、解码、提示词和评分器，每次只改变一个决策。在完整的 Video-MME 长视频桶（n=900，K=8）上，没有任何被测试的选择器显著优于均匀采样：最大的仅选择估计值为 +1.9 个百分点（95% 置信区间 [-1.2, +5.0]），我们的级联为 +1.2 个百分点 [-1.7, +4.1]；所有方法在 ±5 个百分点内与均匀采样等效。然而，在常用的 n=200 子集上，四个匹配对比中有三个比完整桶大最多 3.8 倍，一个符号反转，并且从完整桶中进行子采样在 35.8% 的抽取中反转了完整桶效应的符号。该审计还纠正了我们自己的初步结果：异常域的"+ASR"实验组没有注入任何文本，因此汇总的 +4.7 个百分点增益是选择加上开发前缀的结果；有了转录文本后，当 ASR 附加在问题之后时，XD-Violence 准确率下降 10.0 个百分点，而放在问题之前则完全没有影响，UCF-Crime 则两种方式都下降 13.0 个百分点，而在 Video-MME 上，将文本放在最前面为均匀采样和级联都增加了约 4（Qwen2-VL 上为 7）个百分点（事后分析，未调整）。更换回答模型产生了最大的对比（MUSIC-AVQA 上 +15.1 个百分点，其最差类型上 +33.3 个百分点），但同一个音频-视觉专家在其音轨被静音后仍保持了 92% 的增益（使用不匹配音轨时为 69%）：主要是模型替换。代码、逐项预测和重新计算每个统计量的脚本可在 https://github.com/mikeslin-ir/long-video-qa-audit 获取。

1 引言

图 1：长视频问答声明的三个障碍。 K 帧必须覆盖 44 分钟的时间线。 真实的 MUSIC-AVQA 问题需要声音，而不仅仅是像素。 在我们缓存的 n=900 结果的 20,000 个随机 n=200 子集中，35.8% 反转了完整桶效应的符号。

长视频问答的核心问题是将正确的证据呈现在模型面前。长视频无法整体输入视觉-语言模型（VLM）：标准流程采样一小组 K 帧——通常 K=8——并将其前向传播。但对于事件稀疏的视频，即回答问题的证据集中在数千帧中的少数几帧中，文献所关注的问题——选择哪 K 帧——只是问题的一半。即使有了正确的帧，询问旁白、屏幕文本或屏幕外事件的多项选择题也可能无法仅凭像素回答（图 1）。

花费决策的三个地方。 长视频流程决定 视觉-语言模型看到哪些帧， 注入哪些非视觉信号（Whisper 转录、帧上 OCR）到其提示词中，以及 哪个模型回答。社区在 上投入巨大——学习和次模选择器、智能体工具调用、树结构搜索——而 只是字幕增强基线的实现细节， 很少被视为路由选择。本文在同一个协议下测量所有这三者。

一项审计，而非排行榜条目。 比较已发表的长视频问答系统几乎是不可能的：它们在推理器容量、帧预算、提示词内容、答案评分协议和评估子集上同时不同。因此我们引入 VideoRouteAudit，一个单一的无训练框架，其中每个轴都是一个可消融的阶段——视觉轴的四阶段提出-过滤-对齐-选择级联，文本轴的注入阶段，以及模型轴的专家分发步骤——并每次只改变一个决策，其他一切（包括评分器）保持固定。审计协议及其测量结果优先，可复用的框架其次；我们不声称有普遍优越的选择器或规划器。

我们的发现。

  • (F1) 在完整的 Video-MME 长视频规模上，没有任何被测试的选择规则显著优于均匀采样。 在完整桶（n=900，K=8）上，我们最好的仅选择级联为 +1.2 个百分点，95% 置信区间 [-1.7, +4.1]，并且对均匀采样的 ±5 个百分点等效性检验排除了该规模的增益——这是一个有界效应，而不仅仅是不存在的效应——而几个百分点的增益并未被排除。
  • (F2) 几百项的子集估计不稳定。 在我们的 n=200 开发前缀上，四个对比中有三个比 n=900 时大最多 3.8 倍（级联+ASR 对比均匀 +6.5 → +1.7 个百分点），一个符号反转。从完整桶预测中重采样 200 项子集在 35.8% 的抽取中翻转完整桶效应的符号，最小可检测效应为 8.3–10.4 个百分点，大于该文献从几百个问题报告的 1–5 个百分点增益：在我们的设置中，这样的子集既不能建立效应也不能证明紧密的零假设。我们将此视为核心结果；F1 和 F3 支持它。
  • (F3) 路由增益依赖于领域、协议和模型，且比最初看起来要小。 在三个 n=200 子集上，选择+注入对均匀的汇总增益（+4.7 个百分点，分层 McNemar p=0.0017）不是注入效应：异常域的"+ASR"实验组没有注入文本，在 Video-MME 开发前缀之外，汇总对比为 +1.6 个百分点（p=0.24）。有了转录文本后，附加在问题之后的 ASR 使 XD-Violence 准确率降低 10.0 个百分点，将相同文本放在问题之前消除了该损害，但在 UCF-Crime 上不行，其中无声镜头的幻觉转录无论哪种方式都损失 13.0 个百分点。在 Video-MME 上，文本放在最前面为均匀和级联帧都增加了约 4 个百分点（p=0.002、0.024；事后分析，未调整）。更大的是哪个模型回答：将 MUSIC-AVQA 分发给音频-视觉专家使其最差类型提升 +33.3 个百分点，微平均提升 +15.1 个百分点（n=9,129），但同一专家在其音轨被静音后仍保持了该增益的 92%（使用另一个视频的音轨时为 69%），所以这主要是模型替换，而不是关于音频的证据。

2 相关工作

与问题无关和单一信号的选择。 均匀采样和基于镜头的选择器忽略问题，仍然是长视频 VLM 的事实基线；通用视频摘要 [10] 将任务视为仅多样性的子集选择。学习和基于语言的变体各自承诺一个信号——SeViLA [45] 训练定位器，Q-ViD [31] 为 LLM 编写问题条件的帧字幕，LLoVi [46] 密集字幕然后查询——当证据是局部化的且对该信号不可见时，这是脆弱的。发布的默认提出器是 STACFP [22]，一种内容自适应的时空聚类采样器，在长镜头聚类和镜头边界捕捉之间自我适应；审计的运行早于它（第 3.3 节）。

字幕和提示感知的帧评分器。 KeyScore [22] 在 CLIP/PE 嵌入级别计算上下文丢弃信号，用于字幕和查询感知的帧评分，并通过闭式标量将其与语义相似性和时间代表性相结合。AKS [38] 将提示感知的自适应关键帧采样表述为提示相关性和时间覆盖的优化。KeyVideoLLM [21] 通过文本-帧相似性选择关键帧以压缩 VideoLLM 数据。Logic-in-Frames [9] 添加视觉-逻辑依赖。2025-2026 年的浪潮保持相同的嵌入空间前提，同时改变规则：top-K 评分 [11]、时间曲率 [28]、小波语义边界 [3]、预测惊喜 [14]、事件锚点 [2]、语义-视觉共识 [35]、基于重新思考的问题感知选择 [15]，以及熵门控预算调度 [19]。最接近我们的级联，Zhang 等 [48] 和 Huang 等 [12] 将选择表述为单调次模覆盖并带有贪婪近似保证，后者还按类型将每个问题路由到预设。我们的贡献不是更好的规则：在 K=8 的完整 Video-MME 长桶上，我们移植的三个规则没有与均匀分离（第 4.2 节）；我们没有测试该家族的其余部分。

智能体/工具使用的视频推理。 VideoAgent [41]、MoReVQA [27]、TraveLER [33] 和 VideoTree [42] 使用 LLM 在几个阶段或轮次中规划、字幕、检索和重新定位，通常每个问题有多次模型调用。这些系统是端到端评估的，因此控制器的贡献没有与它拉入的额外证据分离。我们的规划器轻量得多（一次规划器调用，≤1 秒，针对固定的工具注册表），我们用 inject_only 消融（第 3.7 节）隔离其贡献，使无注入分支与非智能体基线按位相同——这是我们在先前智能体视频工作中没有报告过的控制。

审计，以及超越选择。 我们的立场遵循在受控条件下重新测量已发表增益并发现它们更小或不存在的工作——在推荐 [6] 和度量学习 [29] 中。长视频问答异常暴露：评估集有时很小，推理器足够昂贵以至于很少有论文重新运行基线，开放式评分增加了协议自由度。最接近我们的是 KFS-Bench [20]，它同样认为帧采样仅通过问答准确率间接评估，并用场景级真值回答。我们采取互补路线：我们保持问答准确率——文献实际声称的数量——并控制其周围的协议，然后询问报告的差异在使用的样本量下是否可测量。同时的方法侧工作也超越了固定帧集——VideoRouter [13] 协调全局和局部证据视图，GenEvA [25] 在选择后聚合证据——或按问题路由：VisualRouter [47] 按查询类型选择采样策略，HiMu [1] 将谓词分发给视觉、OCR 和音频专家，一个接近我们的方案。那些工作提出机制；我们提供受控测量并将其扩展到他们保持固定的轴：哪个模型回答。

文本证据注入和字幕增强的视频问答。 一条平行线给 LLM 文本证据：LLoVi [46] 和 Q-ViD [31] 输入帧字幕，上面的智能体系统添加字幕和检索的文本，通常代替帧。这些系统将注入与其流程的其余部分捆绑；我们将其视为受控选择 × 注入因子设计（第 4.3 节）中的可消融阶段，并展示块在提示词中的位置改变其效果（第 4.4 节）。

程序性记忆、MoE 和次模选择。 记忆增强的 LLM 智能体——ReAct [44]、Reflexion [36]、Voyager 风格的技能库 [39]——跨回合积累经验；我们的程序性记忆是一页 markdown 先验，从我们自己开发前缀的结果编写并逐字附加，没有梯度更新。Token 级 MoE [34] 和工具使用的 LLM [32] 共享专家门控的风味，但在一个网络内部或同质工具上操作，而我们的专家轴跨单独训练的多模态模型分发。选择阶段使用惰性贪婪单调次模最大化，它是 (1-1/e)-近似的 [30]。

长视频和音频-视觉 MLLM。 Qwen2-VL [40] 和 LLaVA-NeXT-Video 是以视觉为中心的；音频语言模型 [5, 7] 专门从事声学理解；音频-视觉 LLM 如 VideoLLaMA2-AV [4] 以更高的成本整合两者。跨这个异构池的路由没有被先前的选择方法解决。

3 方法

给定视频 V、问题 q 和帧预算 K。标准的长视频问答流程选择最多 K 帧的子集 F ⊆ V，并将 (F, q) 前向通过固定的视觉-语言模型（VLM）e_VLM。我们将"在 VLM 面前放什么"视为比"选择哪些帧"更丰富的选择：非视觉证据（Whisper 转录、帧上 OCR）是第二个正交的放置轴。VideoRouteAudit 将两者实现为由读取过去结果程序性记忆的轻量级 LLM 规划器编排的单一无训练流程。

3.1 概述：五阶段、两轴流程

VideoRouteAudit（图 2）逐步将数千个候选帧缩小到 K，然后在 VLM 调用之前用文本证据增强结果视觉上下文：

V →propose C₁ →filter C₂ →align (u_q) →select F，
(F, q, V) →inject (F, q ⊕ E) →e_VLM â，

其中 |F| ≤ K，E 是附加到提示词的（可能为空的）文本片段束。阶段 1-4 形成视觉轴；阶段 5（注入）是文本轴。一个小的 LLM 规划器发出 JSON 计划，按问题决定使用哪些提出器、对齐器和注入源。没有组件被训练；我们实验中的每个选择器和注入策略在相同的预算 K 下输入相同的 e_VLM，因此差异不是由于推理器；它们反映整个流程（候选池、过滤器、锚点），而不仅仅是一个规则。

3.2 技能库和规划器

级联利用统一接口后面的可复用技能。提出和过滤使用廉价技能（每帧 O(N)，无 GPU 编码器）：始终开启的 uniform_stride 骨干、事件音频/视觉提出器（EARS [23]）、内容自适应的 stacfp 提出器、运动差异过滤器和冗余过滤器；PySceneDetect 镜头边界是可选的。对齐技能对每个候选针对 q 评分：semantic_siglip、object、ocr_text、asr_whisper、clap_alm 和 audio_energy。一个固定的 VLM 回答。运行的规划器配置固定它启用哪些廉价技能；每个审计的 Video-MME、XD-Violence 和 UCF-Crime 运行使用第 3.3 节的 audit 配置。

规划器在此固定注册表上发出 JSON 计划：提出器和对齐器、融合权重 w^ev、多样性带宽 τ、均匀锚点分数和注入源 S^inj ⊆ {asr, ocr}。基于规则的规划器（CPU 绑定，回退）通过关键词匹配将 (q, 数据集 id) 映射到计划。LLM 规划器（Qwen2.5-3B-Instruct，每个问题一次调用，≤1 秒）额外读取 markdown 程序性记忆（第 3.7 节），并在其 JSON 格式错误时回退到基于规则的计划。补充材料给出了注册表、关键词规则、规划器提示词和模式。

3.3 提出和过滤

提出将启用的提出器的输出合并到候选池 C₁ 中。在 audit 配置中，超过 120 秒的视频获得 66 个事件注意力峰值和 66 个均匀间隔的帧（132 个候选；较短剪辑为 64 个均匀间隔的帧）。该提出器融合音频能量与光流幅度，但其运动信号仅覆盖视频的前 4,096 帧，因此其峰值落在开头几分钟，而均匀一半跨越整个视频。这些运行还计划了 PySceneDetect 镜头边界提出器，但 PySceneDetect 未安装，路由器静默跳过该提出器，我们在为发布重新运行流程时才发现这一点。发布的 audit 配置重现了执行的池（在 24 个重新检查的项中有 24 个选择了相同的帧），并且路由器现在在计划的工具失败时发出警告。

过滤然后保留池中与其前驱相比灰度变化最大的 32 个候选（仅长视频）。该帧差异规则偏爱高运动帧，可能丢弃静态证据，如静止的说话者或屏幕上的标志。发布的默认配置而是用 STACFP [22] 提出，它聚类颜色直方图加时间戳描述符，并在长镜头和剪辑视频之间适应，同时去除近乎重复的帧但保留静态但独特的帧。在完整规模（n=900）下，它得分为 46.4%，比均匀高 +0.2 个百分点（[-2.7, +3.2]，在 ±5 个百分点内等效），比审计的级联低 -1.0 个百分点。

3.4 对齐：问题条件效用

对于每个候选 n ∈ C₂，每个启用的对齐技能 s_i 针对问题产生归一化相关性分数 σ̃_i(n) ∈ [0,1]。规划器的融合权重将它们组合成每帧效用

u_q(n) = Σ_{i∈S^ev} w_i^ev σ̃_i(n) + λ_u U(n)，

其中 U(n) 是可选的通用信息量先验（例如帧熵），λ_u 是小权重。在这里融合多个线索是否实际产生更好的帧是本文测量的问题之一（第 4.2 节）。

3.5 选择：次模最大化

给定效用 u_q，我们定义时间覆盖核

k_τ(t, t') = exp(-(t-t')²/2τ²)

和设施选址集效用

f_q(F) = Σ_n u_q(n) max_{m∈F} k_τ(t_n, t_m)，|F| ≤ K。

f_q 是单调非减和次模的；惰性贪婪 [30] 返回 F̂，满足 f_q(F̂) ≥ (1-1/e) f_q(F*)。硬指示器特例（k_τ ∈ {0,1}）恢复时间 NMS；高斯核使相关性/多样性权衡连续。每个审计的级联保留均匀底线：K 帧中的 round(K/2) 是忽略对齐分数的均匀间隔锚点（Python 舍入），因此在 K=8 时，四帧来自设施选址，四帧是均匀的，而在 K=1 时没有保留锚点。底线保证在对齐分数平坦时的基线时间覆盖，并限制任何级联可以从均匀采样移动多远。

3.6 文本证据注入

注入阶段将短文本块附加到 VLM 提示词。对于 asr，每个选定帧 ±w_inj 秒内（w_inj=4 全程）的缓存 Whisper (tiny.en) 转录块成为最多 240 个字符的"[mm:ss]"行，后跟最多 400 个字符的转录摘要；对于 ocr，EasyOCR 读取每个选定帧（每帧最多 160 个字符）。该块跟随问题和选项，由"Additional evidence extracted from the video (treat as context, not ground truth):"引入；放置是第 4.4 节通过将相同块移动到问题之前来消融的协议选择。在 n=900 运行中，ASR 注入平均添加 1,344 个字符（中位数 1,320，第 95 百分位数 1,724；900 项中有 865 项非空），OCR 添加 274（782 项非空）。没有缓存转录的视频不接收文本，框架现在报告注入了多少项。注入是可消融的并在视觉预算和解码配置中匹配：视觉上下文、K、骨干模型和解码配置在所有注入策略中保持固定，因此准确率差异仅反映提示词侧的文本。总上下文故意不匹配——注入的文本是干预。

3.7 程序性记忆和仅注入隔离

朴素的 LLM 规划器可能重写每个计划字段，将"我想要什么级联"与"我应该在这个问题上注入文本吗"混淆。因此我们使用两个构造。

程序性记忆是一页 markdown 先验文件——哪些注入源对哪些问题表型有帮助（"为旁白或对话注入 ASR；对纯视觉问题抑制它"）以及哪些组合有害（Video-MME long 上的 ASR+OCR）——逐字附加到规划器提示词；没有参数更新。每个规划器运行加载这一个文件（在补充材料中重现）；v1 和 v3 命名规划器配置（自由计划；inject_only_mode）。该文件引用 n=200 Video-MME 评估前缀上的结果，因此规划器数字是测试集知情的诊断，而不是泛化的证据。

仅注入隔离硬覆盖除 S^inj 之外的每个计划字段，使用基于规则的级联，因此仅使用 LLM 的逐问题注入决策，无注入分支与无注入基线按位相同；没有它，LLM 在 200 个计划中的 113 个中静默交换了对齐器。

3.8 推理

推理按顺序运行第 3.1 节的五个阶段。VLM 调用主导我们计时的阶段成本；规划器添加 ≤1 秒，解码候选帧大约需要 VLM 调用的三分之一。一次性预处理不在逐项时间中：Whisper 转录每个 Video-MME 长视频大约需要 94 秒然后缓存，因此每问题 ASR 注入是字符串连接，而 EasyOCR 在推理时对选定帧运行（每项约 9 秒；端到端每问题约 31 秒；补充材料，计算成本）。

4.1 设置

统计。 成对显著性是逐项正确率上的双侧精确 McNemar。标题对比还获得 95% 配对自助法置信区间（10,000 次重采样）、不一致对计数及其最小可检测效应（MDE），以及在声称零假设的地方，90% 置信区间上的 TOST 判定。±5 个百分点边距是该文献声称的选择轴增益范围（1-5 个百分点）的顶部；这是一个选择，而不是噪声底限，因此"等效"仅意味着该规模的增益被排除。我们还报告 ±3 个百分点，没有完整桶选择对比通过。Video-MME long 每个视频询问三个问题，因此每个完整桶区间用视频聚类自助法重新计算：其标准误最多是项级标准误的 1.02 倍，没有判定改变（补充材料）。F1 的完整桶对比和 F3 的专家对比是确认性的；表 2 的单元格、汇总 F3(a) 对比（仅在 200 项开发前缀之外确认）、放置对比、预算扫描和补充扫描是探索性的，带有未调整的 p 值。p＞0.05 从未被描述为胜利。

其背后的算术。 McNemar 检验仅使用不一致项：n=200 时级联对比均匀有 37 个（b=22，c=15）和 80% 功效下的最小可检测效应（MDE）8.5 个百分点；在四个选择轴对比中，MDE 为 8.3-10.4 个百分点（补充材料）。这样的比较既不能建立几个百分点的效应也不能证明紧密的零假设，因此这样的声明需要完整桶规模或报告的 MDE。

4.4 F3 — 路由增益取决于领域和回答模型

如果选择和注入在 Video-MME 的完整规模上都不分离，什么分离？两件事，都与子集规模数字建议的不同。

(a) 注入取决于领域和文本在提示词中的位置。 我们的协议将证据块附加在问题、选项和答案指令之后。在叙事视频上，如此附加的 ASR 在 200 项开发前缀上的级联内增加 +3.0 个百分点（p=0.18），在完整桶上增加 +0.4 个百分点（[-1.6, +2.4]，p=0.75）：没有建立效应。在异常剪辑上，已发表的"+ASR"实验组没有注入任何内容：没有为它们计算转录，因此它们对均匀的 +4.0 和 +3.5 个百分点是普通级联的选择效应（表 2）。为所有 400 个剪辑构建 Whisper 转录后，附加块将 XD-Violence 准确率从 91.0 降低到 81.0%（-10.0 个百分点，95% 置信区间 [-14.5, -5.5]，b/c=2/22，p＜10⁻⁴），UCF-Crime 从 85.0 降低到 72.0%（-13.0 个百分点，[-18.0, -8.5]，b/c=1/27）。在 XD 上，损害是放置效应：相同文本放在问题之前使准确率保持在 91.0%，级联的水平（0.0 个百分点，[-3.0, +3.0]；比附加高 +10.0 个百分点，p=0.0003）。在 UCF-Crime 上不是：将文本放在前面给出相同的 72.0%，因为该无声监控镜头的 200 个转录中有 160 个包含 Whisper 幻觉的"thank you for watching"。在 Video-MME 上，文本放在前面将级联提升到 50.2%（+2.8 个百分点，p=0.055），均匀采样提升到 50.7%（+4.4 个百分点，[+1.8, +7.2]，p=0.002），两者不可区分（p=0.83），而附加给出 +0.4 个百分点：增益跟随文本及其位置，而不是帧。使用均匀帧，问题与选项之间或选项与指令之间的文本仅给出 +1.0 和 +1.9 个百分点（不显著），像附加（+1.6）一样；只有问题之前的文本给出 +4.4（补充材料）。在 Qwen2-VL-7B 上它重现：文本在前 52.7%（+7.2 个百分点，p＜10⁻⁶），附加 47.2%（+1.8，p=0.09）。放置是在异常结果之后变化的（未调整）；注入效应在符号上是协议和转录敏感的，不仅仅是大小。

已发表的汇总估计也不是注入效应。 在三个 n=200 子集上，级联+ASR 比均匀高 +4.7 个百分点（95% 置信区间 [+1.8, +7.7]；分层 McNemar p=0.0017），但异常实验组是普通级联，前 200 个 Video-MME 项是开发和规划器记忆所基于的前缀。在该前缀之外（n=1,100），对比为 +1.6 个百分点（p=0.24），异常实验组有转录时为 -3.0 个百分点（[-6.2, 0.0]）。规划器从未在异常剪辑上注入，因此它在那里的 ±2 个百分点差异位于 F2 量化的噪声带内。

(b) 更改哪个模型回答产生最大的测量对比，但其中很少是音频。 在完整 MUSIC-AVQA 分割（n=9,129，相同问题，两个模型都在 K=8，相同评判器）上，通用视觉 VLM（Qwen2-VL-7B）在 AV-Temporal 上达到 37.6%——"哪个乐器首先响起"——而音频-视觉专家 VideoLLaMA2-AV [4] 达到 70.9%（+33.3 个百分点，95% 置信区间 [+29.6, +37.1]，精确 McNemar p=2.8×10⁻⁵⁴），微平均从 66.1 移动到 81.2%。每个类型都改善，但这是模型替换：纯视觉的 Visual-Location 移动 +27.3 个百分点，专家的音频-视觉训练组合包括约 35k AVQA-music（MUSIC-AVQA）条目 [4]。因此我们重新运行相同专家，其音轨在每种类型 200 个问题（1,799 个可用）上被数字静音替换，所有三个分支在相同问题上并由相同评判器评分（图 4）。后分层到完整分割的类型组合，静音专家得分 80.9%，而有声音为 82.1%，音频盲模型为 67.0%：静音移除 +15.1 个百分点替换的 1.3 个百分点（95% 置信区间 [-0.1, +2.6]），因此 92% 的增益随模型而来。给每个视频另一个视频的音轨得分 77.5%：专家确实读取音频（错误音轨对比静音损失 3.4 个百分点，p=10⁻⁵，正确的比它增加 4.7），但它仍然比音频盲模型高 +10.5 个百分点（替换的 69%）。对比主要是模型替换，带有较小的音频部分。

5 讨论和局限

解释审计。 覆盖饱和和推理器不敏感都符合 F1；我们不分离它们。F2 涉及我们受控对比的精度，而不是在其原始协议下重新运行先前系统。F3 来自回答模型的准确率空间不建立更便宜的推理。

局限。 专家对比是模型替换：VideoLLaMA2-AV 和 Qwen2-VL-7B 在音频访问之外的差异远多，专家在 MUSIC-AVQA 数据上训练，音频控制（静音、不匹配）覆盖类型分层子集、一个专家、一个随机音轨分配。 F1 在 Video-MME long 上建立，K=8，n=900，使用 Qwen2.5-VL-7B；等效性在 ±5 成立但不在 ±3 个百分点。 审计的级联是一个配置（事件注意力和均匀提出、运动过滤器、50% 均匀锚点；第 3.3 节）；发布的默认配置不同。移植的选择器仅重新实现选择规则；结果不涉及原始版本。 规划器的记忆是在检查 n=200 开发前缀后编写的，因此规划器数字是测试集知情的，表 2 和放置变体是事后和未调整的；异常问答集是二元转换；超出这些数据集、模型和 K 的泛化未测试。

6 结论

我们通过分离帧选择、证据注入和回答模型选择来审计长视频问答。在 K=8 的完整 Video-MME long 上，没有被测试的选择器显著优于均匀（在 ±5 内等效，不在 ±3 个百分点），子集估计不稳定。审计还推翻了我们自己的初步结果：异常域的"+ASR"实验组没有注入任何内容，汇总增益在开发前缀之外缩小，注入效应取决于文本在提示词中的位置。最大的专家对比主要是模型替换（92% 在静音音轨下存活，69% 在不匹配音轨下），仅问题分发恢复准确率而没有证明节省。

下一步不是简单地选择更好的帧、注入更多证据或路由到更强的模型，而是识别哪个决策限制性能，在匹配条件下测量其贡献，并且仅在增益可靠的地方添加复杂性。

附录 A 程序性记忆：扩展分析

记忆是什么（和不是什么）

程序性记忆是单个 2,028 字符的 markdown 文件（configs/procedural_memory_v1.md，下面重现），在少样本示例之前逐字附加到规划器 LLM 的系统提示词。它不是学习参数、嵌入存储或检索索引：LLM 为每个问题重新读取文本。每个报告的规划器运行加载这一个文件。主论文和我们运行名称中的标签"v1"、"v2"和"v3"表示规划器配置，而不是不同的记忆文本：v1 让 LLM 重写整个计划，v2 冻结对齐器组合，v3 是 inject_only_mode。第二个文件 procedural_memory_v4.md 已起草但没有报告运行使用它。记忆文本是：

单一受控自由度

为了干净地将准确率变化归因于 LLM 的路由决策，我们部署 inject_only_mode：除逐问题 inject_text 之外的每个计划字段都被基于规则的级联硬覆盖。这确保 LLM 规划器的无注入分支与无注入级联基线按位相同。没有这种隔离，观察到 LLM 静默交换对齐器（Video-MME long 上 200 个计划中的 113 个将 semantic_siglip 切换到 object_siglip），这将污染对规划器注入决策的归因。

评估独立性。 记忆是测试集知情的：它是在检查 n=200 Video-MME 评估前缀上的结果后编写的，其文本引用它们。v2 和 v3 配置也在检查该前缀后修订。n=900 规划器行因此混合了 200 个开发项和记忆和配置都未见的 700 个项。在这 700 个项上，规划器得分 47.0%，对比始终注入 ASR 的 45.4%（+1.6 个百分点，精确 p=0.17）和均匀的 45.1%（+1.9 个百分点，p=0.31）；在 200 个开发项上它得分 53.5%，对比始终注入 ASR 的 56.5%。两个保留差异都不显著，因此规划器准确率不是泛化的证据，匹配的选择器和注入对比承载审计发现。

规划器何时收回成本

规划器每个问题进行一次调用（≤1 秒），但没有建立比始终注入 ASR 更好：在 n=200 前缀上，差异是 Video-MME 上 -3.0 个百分点，XD-Violence Fighting/Normal 子集上 +1.5 个百分点，UCF-Crime 上 -2.0 个百分点，两个异常域对比都不显著。在异常剪辑上，规划器从未选择注入（400 个问题中没有），因此这些差异反映 LLM 选择的工具，而不是其注入决策；这些剪辑也没有 ASR 转录存在（第 H 节）。在 n=900 时，规划器在数值上最强（48.4%），但在 ±3 个百分点内与始终注入 ASR 等效。每个规划器运行的逐项决策随预测发布，因此规划器行可以在不调用 LLM 的情况下重新计算。

XD-Violence。 本地测试分割包含 120 个 Fighting、84 个 Shooting 和 300 个 Normal 视频。文件在按 Fighting、Shooting、Normal 排序的文件夹内排序；正例和正常列表在截断前交替。因此，报告的 n=200 确定性前缀包含 100 个 Fighting 和 100 个 Normal 视频，没有 Shooting 视频。每个接收"这个视频是否包含暴力活动，如打斗或射击？"选项 {A: 是, B: 否}；Fighting/Shooting 映射到 A，Normal 映射到 B。因此我们将此结果解释为 Fighting 对比 Normal 的 XD-Violence 子集，而不是完整类别覆盖。

选择器移植

所有三个移植消耗相同的前端：跨越整个视频的 256 帧池的 SigLIP-base 图像和文本嵌入（早期池仅覆盖每个视频的前约 42 秒；已发表的移植行来自修复后的重新运行），相关性是与问题提示词的最大余弦相似性。AKS：相关性被 min-max 归一化，官方二分法以 t₁=0.8、t₂=-100 和深度 5 运行，深度 d 的每个终端段贡献其顶部 max(1, ⌊K/2^d⌋) 帧；结果按分数修剪到 K 或用均匀间隔帧填充。KeyScore：α=0.85（语义）、β=0.05（与平均池化视频嵌入的相似性）和 γ=0.10（丢弃影响，闭式），每个 min-max 归一化，按分数取 top K。VideoTree：K-均值（K 个聚类，4 次初始化，种子 0）在图像嵌入上，聚类按峰值相关性排序，顶部 K 个聚类中每个的最相关帧；其迭代 LLM 引导的扩展和字幕未被移植。scripts/port_fidelity.py 在相同分数数组上与参考比较规则。在来自 Video-MME long 的 100 个真实 SigLIP 分数轨道（每个 256 帧池）上，KeyScore 移植与参考实现的分数匹配到 3.5×10⁻⁵，并在所有 100 个上选择相同的 top-8 集；其权重是参考 FrameScorer 默认值，参考 API 的当前默认值（0.70/0.10/0.20）改变 4% 的 top-8 集。对于 AKS，官方例程在其默认深度 5 和 K=8 下运行，在 100 个轨道中的 100 个上根本不返回帧：没有段在 min-max 归一化分数上达到 t₁=0.8 峰值阈值，因此每个段分裂到深度 5，其中 ⌊8/2⁵⌋=0 帧保留。官方例程为 32-64 帧的预算设计。因此移植在构建上不同：它是时间分箱的 top-K（32 个深度 5 箱中每个的最佳帧，按分数修剪到最佳 K=8），与朴素 top-8 的 Jaccard 指数为 0.66，与深度 3 的官方例程（仍然发出 8 帧的最深设置）为 0.47。VideoTree 没有发布的用于比较的选择例程。因此 AKS 和 VideoTree 行限定适应 K=8 的选择规则，而不是已发表的系统。
