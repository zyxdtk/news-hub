摘要
智能体外壳通过协调智能体与环境的交互，显著提升了长周期任务的表现。然而，通过复杂外壳进行强化学习在很大程度上仍未被探索，因为将此类训练扩展到长周期智能体任务带来了根本性挑战。在本研究中，我们提出了一个统一的黑盒强化学习框架，用于通过复杂外壳对通用智能体进行稳定且可扩展的优化。具体而言，我们首先构建了一个基于沙盒的执行基础设施，将任务环境和外壳隔离在临时沙盒中，以实现大规模并发展开。然后，我们将策略优化与不透明的外壳执行解耦，并在模型边界放置一个服务代理来捕获模型调用。为了重构多轮轨迹并提高训练效率，我们将捕获的调用组织成前缀树，并进一步适配基于评论家的 PPO 和无评论家的 GRPO，以在恢复的树结构上进行优化。同时，我们在整个优化过程中保持训练-推理一致性。最后，我们引入了混合外壳训练，允许单个模型由异构外壳联合优化。使用 Qwen3-30A3B，黑盒强化学习通过 OpenClaw 和 Claude Code 分别在 ClawGym-Bench 上将 Pass@1 提高了 9.98 和 14.81 个百分点，并在 200-400 步优化中保持稳定。此外，该框架在 JobBench 和 OfficeQA 等更具挑战性的任务上也产生了一致的收益。总体而言，我们的框架实现了通过黑盒外壳对通用智能体进行有效、稳定且可扩展的优化，支持跨异构执行系统的统一训练。

1 引言
智能体外壳 [30] 已成为自主智能体系统的基础操作层，在任务解决过程中协调大语言模型 [38] 与其环境的交互。它们通常将系统提示、工具接口、上下文管理、工作流编排以及重试和恢复机制集成到一个统一的运行时中。诸如 Claude Code [2]、Codex [17] 和 OpenClaw [19] 等生产级系统表明，精心设计的外壳可以显著提升智能体在复杂长周期任务 [24] 上的表现。随着这些外壳变得越来越强大，它们正在加速通用自主智能体的发展，这些智能体可以在 diverse 真实世界工作区中运行，并解决跨越软件工程 [16, 7]、办公应用 [21, 8]、AI 助手工作流 [36, 23] 和支持 MCP 的工具使用 [13, 5] 的任务。最近的进展是由外壳设计、优化和自我进化方面的推理侧进步 [31] 驱动的。然而，日益强大的外壳带来的好处不仅取决于它们的设计，还取决于底层模型利用它们的有效程度。如果一个强大的模型没有经过适当的训练，即使在一个强大的外壳中也可能表现不佳，这促使人们通常通过强化学习（RL）算法来努力使模型更好地利用这些智能体外壳。

现代外壳的一个决定性特征是其固有的复杂性：设计和实现足够复杂。因此，针对外壳的强化学习训练算法可能与在纯文本 [6] 或其他简单环境 [28, 27] 中使用的算法大不相同。在较简单的单轮或轻量级智能体设置中，交互过程是显式且直接可观察的，允许强化学习优化明确定义的模型轨迹，而无需考虑复杂的隐藏执行逻辑。相比之下，对于现代外壳，主流方法 [32, 11] 是将内部控制流和执行逻辑视为不透明的，并设计黑盒强化学习算法。事实上，黑盒强化学习已成为开发和利用通用智能体强大外壳的关键技术基石 [37]。然而，通过此类外壳对通用智能体任务进行稳定且可扩展的策略优化在现有文献中仍然相对缺乏探索。因此，本研究聚焦于以下研究问题：
如何通过外壳执行黑盒强化学习以稳定地优化通用智能体？
为了回答这个问题，我们将调查集中在三个根本挑战上：
∙ 黑盒强化学习的可扩展和稳定基础设施。通用智能体任务在强化学习期间需要专用的、有状态的环境，大规模并发展开给执行基础设施带来了巨大压力。对于长周期任务，运行时延迟和故障会在交互步骤中累积并使整个轨迹无效，使得大规模及时可靠的数据生成变得困难。
∙ 从碎片化的黑盒轨迹中进行高效有效的策略优化。黑盒外壳暴露的是碎片化的、分叉的且通常冗余的模型调用，而不是完整的交互轨迹，这使得这些轨迹难以直接用于强化学习。此外，不透明的内部操作可能会进一步放大训练-推理不一致性，导致训练不稳定。
∙ 跨异构外壳的可扩展性。外壳在交互协议、工具接口、上下文管理和执行工作流方面差异很大。一个实用的框架应该支持 diverse 的外壳，只需最少的系统特定适配，并实现跨外壳的统一训练，而不是为单个执行系统优化策略。

为了应对这些挑战，我们开发了一个统一的黑盒强化学习框架，通过任何复杂外壳稳定地优化通用智能体。
首先，为了在展开期间维持稳定、大规模并发的环境执行，我们构建了一个保持忠实模型行为的执行和数据基础设施。每个特定任务的环境及其执行外壳都封装在一个临时沙盒中，该沙盒按需配置并在完成后销毁，为每次展开提供隔离的工作区，同时实现大规模并发。
其次，我们通过将外壳视为不透明的展开引擎，将策略优化与外壳执行解耦，同时服务代理拦截每个模型调用。这种设计允许外壳保留其原生执行逻辑并独立运行。为了恢复可靠的多轮训练轨迹并提高训练效率，我们将每次展开捕获的调用组织成前缀树。然后，我们适配基于评论家的 PPO [25] 和无评论家的 GRPO [26]，以在恢复的树结构上进行优化。通过黑盒 token-in-token-out 机制 [9] 和 token 级别重要性采样展开校正 [34] 进一步保持了训练-推理一致性，这减轻了由底层推理和训练引擎之间的差异引起的偏差。额外的保障措施稳定了展开执行和策略优化。
最后，将每个外壳封装在沙盒中，将特定于外壳的执行与训练流水线隔离，允许为不同的任务环境轻松选择或替换不同的外壳。在这种模块化设计的基础上，我们引入了混合外壳训练，其中每个任务-外壳对形成一个基本的训练实例，来自多个异构外壳的展开被联合用于优化单个模型。

我们在两个具有代表性且结构不同的外壳上验证了黑盒强化学习框架：用于个人助手任务的通用外壳 OpenClaw，以及为长周期代码和终端交互设计的成熟外壳 Claude Code。来自 ClawGym [4] 的通用智能体任务用于在这两个外壳下进行训练。从 Qwen3-30A3B [33] 主干开始，黑盒强化学习训练产生了 ClawII-OC-30A3B（通过 OpenClaw 训练）和 ClawII-CC-30A3B（通过 Claude Code 训练），在 PinchBench 上将 Pass@1 分别提高了 11.71 和 17.28 个百分点，在 ClawGym-Bench 上分别提高了 9.98 和 14.81 个百分点。此外，训练在 200-400 步优化中保持稳定，证明了我们的黑盒强化学习框架在复杂外壳上优化通用智能体任务的有效性和鲁棒性。
此外，在混合外壳训练下，训练后的模型匹配甚至超越了仅使用任一外壳训练的对应模型的性能，这表明黑盒强化学习可以在我们统一的训练流水线中无缝集成异构外壳。
除了这些设置之外，我们还将框架扩展到 JobBench [14] 和 OfficeQA [20] 中更具挑战性的任务设置，其中黑盒强化学习继续提供一致的改进。

我们的主要贡献总结如下：
• 我们建立了一个统一且可扩展的通用智能体黑盒强化学习框架，该框架适应通过任何单个不透明外壳进行的训练，并进一步通过跨异构外壳的联合优化实现混合外壳训练。
• 我们开发了用于稳定和可扩展黑盒强化学习的基础设施和优化技术，支持可靠的并发展开、忠实的轨迹恢复、使用 PPO 和 GRPO 的树结构优化以及训练-推理一致性。
• 我们在 OpenClaw 和 Claude Code 上验证了该框架，展示了一致的性能提升和稳定的优化，以及通过混合外壳训练跨异构外壳的可扩展性，并扩展到更具挑战性的任务，如 JobBench 和 OfficeQA。

2 预备知识
2.1 通用智能体任务的问题表述
通用智能体任务由用户指令和执行任务的隔离、有状态环境组成。环境从工作区初始化，并提供执行上下文，包括文件、目录、文档、软件存储库、运行服务和其他特定于任务的资源。为了完成任务，智能体通过外部工具（如网络搜索、文件编辑、代码执行 [3]、shell 命令或 API 调用）与此环境进行多轮交互，逐步将其状态向期望目标转变。结果反映在最终环境状态中，通常通过生成的工件（例如文档、演示文稿或报告）或成功完成的操作（例如修复软件存储库或配置系统）。我们将任务表示为 q=(u,𝒲₀)，其中 u 是用户指令，𝒲₀ 是初始工作区，并使用 ℰ_q 表示从 𝒲₀ 初始化的关联执行环境，任务从 q∼𝒟 中采样。
在执行期间，智能体在观察和动作之间交替，并产生轨迹 τ=(o₁,a₁,…,o_T,a_T)，其中 o_t 表示步骤 t 的观察，a_t 表示相应的智能体动作。当任务完成或执行停止时，交互终止，产生最终工作区状态 𝒲_T。然后评估此最终状态以获得展开级别的奖励。
在实践中，任务评估通常遵循两种范式。基于规则的奖励通过确定性程序（如单元测试、程序执行或精确匹配验证）验证最终工作区的正确性。基于评分标准的奖励依赖更强的评估器（例如 LLM-as-a-Judge）根据特定任务的评估标准评估生成的工件或最终工作区的整体质量。

2.2 外壳驱动的智能体执行
现代通用智能体越来越多地通过成熟的外壳部署，如 OpenClaw、Claude Code 和 Codex。与基于标准 ReAct [35] 范式的传统手工制作智能体循环相比，这些外壳 [1, 10] 在语言模型和外部工作区之间提供了更丰富的执行抽象。它们将工具编排、上下文管理、内置技能、子智能体委派和故障恢复等能力集成到统一的运行时系统中，使智能体能够解决更复杂的长周期任务，同时从模型中抽象出许多低级执行细节。
在这种执行范式下，模型不再直接与工作区交互。相反，给定模型动作 a_t，外壳执行相应的工具，更新工作区和执行上下文，并返回处理后的观察以供下一次决策。这种交互可以抽象为 (𝒲_{t+1}, o_{t+1}, c_{t+1})=ℋ(𝒲_t, c_t, a_t)，(1) 其中 ℋ 表示外壳，𝒲_t 是工作区状态，c_t 是维护的执行上下文，o_{t+1} 是返回给模型的观察。因此，交互轨迹由模型和外壳共同决定，而不是仅由模型决定，这使得外壳成为现代长周期智能体系统的基本执行抽象。

2.3 智能体强化学习算法
我们研究了两种主流的强化学习范式，主要区别在于它们对显式价值模型的依赖：作为基于评论家方法的近端策略优化（PPO），以及作为无评论家方法的组相对策略优化（GRPO）。
在整个过程中，我们让状态 s_t 表示动作 a_t 之前的交互历史 (o₁,a₁,…,o_t)，因此策略 π_θ(a_t∣s_t) 和价值函数 V_ϕ(s_t) 都是在此历史上定义的。

3 通过复杂智能体外壳的统一黑盒强化学习
我们的黑盒强化学习公式直接通过未修改且不透明的智能体外壳优化可训练模型，同时将策略优化与外壳执行解耦。本节介绍了用于可扩展黑盒展开的执行基础设施、从捕获的模型调用中恢复和优化训练轨迹，以及跨异构外壳训练的扩展。

3.1 可扩展黑盒强化学习执行的基础设施
通用智能体任务的黑盒强化学习需要大规模并发执行专用的、有状态的环境。与无状态生成不同，每次展开可能会在许多交互步骤中修改文件、进程、工具状态和其他特定于任务的资源，这使得隔离执行变得至关重要。对于每个任务 q，我们从其初始工作区 𝒲₀ 初始化一个特定任务的环境，并在临时沙盒内启动选定的外壳。沙盒提供了外壳所需的隔离工作区和运行时依赖，防止并发展开之间的干扰。每个沙盒在展开开始时配置，在完成后释放，允许执行随着可用的沙盒容量进行扩展。
除了隔离任务状态外，每个沙盒还提供展开期间所需的外部能力。除了选定外壳原生提供的基本工具外，通用能力（如网络搜索）以及特定任务的工具通过在沙盒内启动的模型上下文协议（MCP）服务器公开。标准化的 MCP 接口确保在整个执行过程中可靠地访问这些服务，并允许在不修改原生外壳工作流的情况下集成新功能。
我们将策略优化与外壳执行解耦。训练引擎负责策略优化，而推理引擎在展开期间为当前策略提供服务。外壳本身驱动沙盒内的交互，并保留对工具使用、上下文管理、重试和环境交互的控制。这种分离避免了在训练流水线中重新实现特定于外壳的控制流，并使不同的黑盒外壳能够以最少的适配集成。
虽然外壳的内部控制流是不可访问的，但模型行为在模型服务边界仍然是可观察的。每个模型生成的动作都是通过跨越此边界的模型请求产生的。因此，我们在边界处放置一个服务代理作为外壳使用的模型端点。对于每个请求，代理调用当前展开策略，以外壳期望的协议返回生成的响应，并记录确切的输入 token、生成的 token、展开对数概率和相关的任务元数据。这种边界级别的捕获提供了优化所需的模型侧信息，而无需对内部外壳逻辑进行插桩。
如图 1 所示，每次展开在沙盒内启动任务环境和外壳，之后所有模型请求都通过服务代理。完成后，验证器评估最终工作区状态并产生展开级别的奖励。捕获的模型调用记录和奖励被传递给训练流水线，在其中调用被重构为可训练的多轮轨迹，如第 3.2 节所述。然后训练引擎更新策略模型，并将参数同步到推理引擎以进行下一次迭代。

3.2 桥接黑盒外壳执行与策略优化
服务代理捕获优化所需的模型侧记录，但这些记录必须首先转换为结构化的多轮训练轨迹。我们将捕获的调用组织成前缀树，在恢复的树结构上优化 PPO 和 GRPO，并在整个策略优化过程中保持训练-推理一致性。

3.2.1 前缀树构建
在黑盒展开期间捕获的模型调用是碎片化的、分叉的且可能冗余的。独立优化这些调用将破坏长周期交互结构，并重复训练在连续调用中重复出现的共享历史。因此，我们将从每次展开捕获的模型调用组织成展开级别的前缀树 [12]，该树重构了它们的共享交互结构，并提供了执行策略优化的训练表示。
具体而言，考虑产生模型调用 𝒞={(x_i,y_i)}_{i=1}^m 的展开，其中 x_i 是第 i 次调用的输入上下文，y_i 是相应的模型响应。在不间断的交互段中，后续输入扩展了早期调用建立的历史。上下文压缩或子智能体执行可能会从缩短或替代的上下文开始一个新段，之后后续调用继续扩展新建立的历史。
我们构建一棵以初始任务提示为根的树 T，并将每个调用附加到其累积历史构成 x_i 最长前缀的现有节点。通过将子调用的输入与累积的父历史和记录的父响应进行比较，我们还恢复了外壳引入的中间非模型内容，包括工具输出和其他环境反馈。
叶子节点是没有后续调用扩展的调用，每个从根到叶子的路径定义了一个候选多轮轨迹。成熟的外壳可能会通过上下文管理或子智能体调度引入多个叶子，这会启动新的交互分支而不是继续当前分支。
通过用公共树节点表示共享交互历史，前缀树只存储一次每个共享前缀，同时将不同的延续保留为单独的分支。由此产生的叶子按第 3.2.2 节所述进行处理，过滤后的树随后用于策略优化，详见第 3.2.3 节。

3.2.2 轨迹提取与过滤
前缀树表示任务解决过程中暴露的模型调用结构，将有效叶子追溯回根可恢复候选多轮训练轨迹。然而，并非每个叶子都对应主任务解决过程的完成，因为有些叶子源于故障处理、上下文管理或子智能体过程。我们过滤由此产生的轨迹以保留适合训练的轨迹。
移除死叶子。当推理服务器重试请求或外壳重新生成无效响应时（如 OpenClaw 在格式错误的工具调用后所做的那样），单个轮次可能会被生成多次。被取代的尝试不会得到进一步延续，而是作为死叶子保留在前缀树中。我们将候选轨迹划分为由上下文压缩点分隔的交互段，并在每个段内保留具有最长有效延续的叶子。在重试引起的死叶子处终止的较短兄弟轨迹被丢弃。
丢弃过度分支的任务。当展开的前缀树分支成过多的叶子时，该展开通常已进入重复或失败的生成，而不是合法的交互分支，由此产生的轨迹提供的有用训练信号很少。一旦叶子数量超过预设阈值，我们就丢弃相应的展开，牺牲少量数据以防止损坏的信号进入梯度更新。
排除辅助轨迹。子智能体和压缩轨迹被排除在外，因为它们在外壳中的角色与主任务解决轨迹的角色不同，且它们的贡献与展开级别的任务奖励没有直接对齐。将相同的终端奖励广播到这些辅助交互会引入模糊的信用分配和嘈杂的优化信号，可能会破坏训练的稳定性。因此，我们只优化主智能体轨迹，并将辅助交互的有效利用留待未来工作。

3.2.3 树结构上的策略优化
一旦构建了前缀树并过滤了无效叶子，单次展开可能会保留多个共享交互历史部分的有效从根到叶子轨迹。我们没有将它们折叠成单个轨迹，而是保留了这种多轨迹结构，并在恢复的树上优化策略。由于每次展开根据其最终工作区状态评估一次，因此从同一次展开恢复的所有轨迹继承相同的终端奖励。
在优化期间，所有保留的轨迹共同贡献于恢复树上的策略损失。分支特定延续上的可训练 token 节点正常包含，而共享前缀中的节点每次展开只计算一次，防止分支较多的展开获得不成比例的优化权重。
形式上，我们用 {g₁,…,g_n} 表示任务 q 的 n 次展开，其中展开 g_i 包含轨迹 {τ_{i,1},…,τ_{i,m_i}} 并被分配在这些轨迹间共享的终端奖励 R_i。接下来我们描述如何适配 GRPO 和 PPO 以在此多轨迹结构上进行优化。关键的适配是保留展开级别的奖励语义，同时允许从同一黑盒展开重构的所有轨迹贡献于策略优化。
GRPO 的优势估计。GRPO 自然地适应了这种结构：它从同一任务的一组展开中估计优势，并且不需要价值模型。我们将该组作为 q 的 n 次展开，并根据组统计量归一化每次展开的奖励，

其中 ε 防止除以零。优势 Â_i 在每次展开时计算一次，并分配给 g_i 中保留轨迹覆盖的所有可训练 token 节点，共享前缀中的 token 对损失的贡献只计算一次。
PPO 的优势估计。PPO 采用额外的价值模型 V_ϕ 来估计 token 级别的优势，并联合优化策略和价值模型。完全建模分叉轨迹之间的依赖关系需要在恢复的树结构上进行更复杂的信用分配。因此，我们采用了 PPO 的简化变体，其中同一展开内的轨迹被视为独立的，且 γ=1 和 λ=1。具体而言，每条轨迹 τ_{i,j} 在其自己的最终 token 处接收分配给其展开的奖励 R_i，并独立执行 GAE 反向传播。没有优势信号在连接兄弟轨迹的分支点之间传播。在此设置下，标准的 GAE 递归退化为

其中优势仅与最终奖励和当前状态的价值估计有关。这种简化要求价值模型从中间状态估计长周期回报，并且由于不应用时序折扣，可能会增加优势方差。更原则性的分叉轨迹处理留待未来工作。

3.2.4 训练-推理一致性
在强化学习期间，策略模型必须在展开期间生成的确切 token 序列上进行训练，以便呈现给训练引擎的序列与策略实际采样的序列相匹配。在黑盒设置中，这一要求因外壳侧转换（如工具调用规范化和助手消息重新序列化）而变得复杂，这些转换可能会在模型输出重新进入后续交互之前改变其表示。简单地重新分词重构的从根到叶子的轨迹将编码外壳转换后的模型响应，产生可能与展开期间最初采样的序列不同的 token 序列。
为了保持训练序列与生成序列相同，我们采用了黑盒 token-in-token-out 原则 [9]，该原则为每个模型调用维护两个解耦的视图。由推理引擎生成的 token 被直接嫁接到前缀树上，并构成训练数据的唯一来源，而外壳接收的结构化文本纯粹是为了让外壳采取行动而从这些相同的 token 解码而来的，并且永远不会被编码回训练轨迹中。一旦工具调用完成，由此产生的环境响应将完全按照下一个模型请求中呈现的那样被编码为 token 序列，并附加到前缀树中。
因此，这两个视图服务于不同的消费者：外壳从解码的文本驱动交互，而训练则逐字读取生成的 token。无论外壳如何重新格式化或标准化它显示并馈送到后续轮次的内容，这些编辑都保留在其自己的视图上，不能扰动 token 记录，因此交给训练引擎的序列在构造上与策略模型采样的序列相同。
确切的 token 序列是不够的，因为采样 token 的概率可能与训练时归因于它的概率不同。推理引擎实现展开策略 π_rollout 并记录每个采样 token 的对数概率，而训练引擎在单独的前向传递中重新计算 token 概率，记为 π_old，在不同的数值精度、内核和并行化下。即使对于相同前缀下的相同 token，这两个概率也可能不同：
π_rollout(a_t∣s_t) ≠ π_old(a_t∣s_t)。(9)
忽略这种不匹配会在梯度估计器中引入离策略偏差 [15]。为了减轻这种残留的不匹配，我们应用了重要性采样展开校正 [34]。原则上，序列级别的重要性比率 [15] 产生无偏估计器，但在长轨迹上可能表现出高方差。由于 π_rollout 和 π_old 之间的不匹配通常很小，我们采用 token 级别的重要性采样比率，以估计偏差换取较低的方差。具体而言，每个训练 token 的损失按以下因子缩放：
w_t=min(exp(logπ_old(a_t∣s_t)−logπ_rollout(a_t∣s_t)), c̄)，(10)
其中 logπ_rollout 由推理引擎在展开时记录，logπ_old 由训练引擎在策略更新前重新计算，截断阈值 c̄ 限制了来自异常比率的方差。

3.3 混合外壳训练
外壳在交互协议、工具接口、上下文管理策略和控制流方面可能差异很大。因为我们的框架将每个外壳连接到相同的模型服务边界和恢复的轨迹表示，所以不同的外壳可以很容易地集成到统一的训练流水线中，而无需修改底层的策略优化过程。这种设计支持在公共接口下通过任何单个外壳进行直接且灵活的训练。
然而，通过单个固定外壳进行训练可能会鼓励策略专门化于其工具使用约定、上下文管理策略和执行工作流。当同一任务通过具有不同交互模式的另一个外壳执行时，这种专门化可能会限制更广泛的泛化。因此，我们引入了混合外壳训练，它在同一次训练运行中联合使用来自多个异构外壳的展开优化共享策略。
对于每个具有环境 ℰ_q 的任务 q，我们通过将任务与不同的兼容外壳 H_k 配对来构建单独的训练实例 (q,ℰ_q,H_k)。由于环境由任务唯一确定，我们将每个实例称为任务-外壳对。与不同外壳关联的实例在每个训练批次中随机混合，并通过共享训练流水线共同处理。
主要的额外考虑是展开分组。对于基于分组的优势估计，组内的展开必须保持可比性。因此，我们通过任务-外壳对而不是单独通过任务来定义每个优化组。同一任务在不同外壳下的展开可能出现在同一批次中，但它们的优势在单独的任务-外壳组内进行归一化。这防止了依赖于外壳的交互模式和奖励分布扭曲相对优势估计，同时允许所有组共同更新共享策略。
我们使用两个具有代表性的外壳 OpenClaw 和 Claude Code 实例化了单外壳和混合外壳训练。OpenClaw 是一个支持 diverse 工作区接地任务的通用 AI 助手外壳，而 Claude Code 是一个为长周期编码和终端交互设计的成熟外壳。详细的实证结果在第 4.3 节中提供。

3.4 可靠训练的保障措施
通过真实外壳和远程配置的沙盒运行强化学习会引入故障和不规则性，这些故障和不规则性源于执行基础设施而不是策略模型本身。我们采用了几种额外的工程保障措施来提高展开收集和训练的可靠性。
鲁棒的沙盒执行和故障处理。黑盒强化学习依赖于远程配置的沙盒来执行真实外壳，使得执行超时、连接丢失和瞬态平台错误等基础设施级别的故障不可避免，但与策略模型本身无关。如果不加以处理，这些故障可能会阻碍展开收集或将无效轨迹引入训练。为了提高训练的鲁棒性，我们采用了几种故障安全机制。一旦达到挂钟超时，长周期任务将被强制终止，而那些遇到明确沙盒故障（如 HTTP 错误或初始化失败）的任务将被丢弃，并排除在优势估计和策略优化之外。
缓冲伪流式解析。大多数黑盒外壳通过流式生成与智能体交互，并依赖增量工具调用解析器在线恢复结构化工具调用。然而，在极少数情况下，由于解析错误，即使模型生成了正确的响应，增量解析也可能过早终止工具调用。为了解决这个问题，我们采用了伪流式解析方案。在生成期间，输出 token 被缓冲，同时合成服务器发送事件（SSE）被持续发出以保持流式连接活跃。在整个轮次完成后，使用非流式解析器对缓冲输出进行一次解析，消除了增量解析错误，同时保留了流式接口。
通过稳定实现完整轨迹捕获。由于黑盒外壳异步执行，并且可能在后台执行重试或故障处理，因此外部请求的完成或失败并不能保证所有轨迹记录都已写入。因此，立即收集它们可能会产生不完整的轨迹。在轨迹组装之前，我们等待直到记录数量在几次检查中保持不变且没有待处理的记录。固定的超时防止无限期等待。

4.2 跨外壳的训练动态
我们研究黑盒强化学习的训练动态，以检查所提出的框架是否支持跨异构外壳和强化学习算法的稳定策略优化。
使用 Qwen3-30A3B，我们通过 OpenClaw 和 Claude Code 进行训练，使用基于评论家的 PPO 和无评论家的 GRPO。如第 3.2.3 节所述，两种算法都经过适配以在恢复的多轨迹树结构上进行优化。
所有实验均使用 ClawGym-SynData 中的任务，并在 ClawGym-Bench 上进行定期评估。由于前面描述的数据可用性限制，OpenClaw 运行从冷启动策略模型初始化，而 Claude Code 运行直接从相应的基础模型开始。GRPO 使用 32 个任务的批次，每个任务 8 次展开，而 PPO 使用 256 个任务的批次，每个任务 1 次展开，导致每次更新的展开预算相同。在这种匹配的展开预算下，PPO 每次更新覆盖更多独特的任务，而 GRPO 为每个任务分配多次展开以进行基于分组的优势估计。PPO 额外需要一个价值模型，该模型在强化学习优化之前通过专门的价值预训练阶段进行初始化。

4.3 混合外壳训练
我们进一步调查单个模型是否可以在统一的黑盒强化学习流水线内通过多个异构外壳联合优化。直接从 Qwen3-30A3B 开始而不进行冷启动初始化，我们使用 OpenClaw 和 Claude Code 进行 GRPO 训练。
如第 3.3 节所述，对于每个任务，我们分别通过 OpenClaw 和 Claude Code 执行相同的任务环境来实例化两个任务-外壳对。来自两个执行系统的任务-外壳对在同一训练批次中随机混合，而 GRPO 分组和相对优势归一化独立于每对执行。因此，通过不同外壳生成的展开可以共存于同一批次中，但不共享相同的组统计量或优势基线。来自所有任务-外壳组的由此产生的梯度在同一优化步骤内聚合，以联合更新单个策略模型。单外壳和混合外壳设置都使用相同的展开批次配置，即 32 个任务-外壳实例，每个实例 8 次展开，并在 ClawGym-Bench 上进行定期评估。
如图 4 所示，混合模型表现出与相应单外壳模型相当的训练奖励。在 OpenClaw 下，它在训练结束时逐渐缩小了初始差距，而在 Claude Code 下，其训练奖励与仅 Claude Code 模型保持持平或更高。在下游评估中也观察到类似的模式，其中混合模型在两种外壳下都匹配或略优于相应的单外壳模型。总体而言，结合来自异构外壳的展开不会引入明显的训练不稳定或系统性的性能下降。这些结果表明，在我们统一的黑盒强化学习框架内，可以联合利用来自异构外壳的学习信号来优化共享策略模型，而在任一执行系统下都没有明显的性能下降。

4.4 在更具挑战性的任务上训练
为了进一步评估我们统一框架的通用性，我们将黑盒强化学习扩展到 JobBench [14] 和 OfficeQA [20] 中更具挑战性和结构多样化的任务设置。JobBench 针对包含 diverse 文件格式（包括图像、数据库和原生 Office 文件）的异构工作区上的专业工作流，要求智能体跨多个来源解释和整合信息以完成复杂任务。OfficeQA 则强调在大型文档语料库上以答案为中心的推理，其中智能体必须检索相关证据，执行多步分析或计算，并产生可验证的最终答案而不是工作区工件。这两个基准共同涵盖了截然不同的复杂智能体交互形式，从面向工件的工作区执行到基于文档的分析推理。
遵循它们各自的任务格式，我们合成了 JobBench 风格和 OfficeQA 风格的训练任务，并在 Qwen3-30A3B 上以 Claude Code 为展开外壳进行黑盒强化学习。在我们统一的框架下，新任务可以通过简单地将其表述为指令、初始化工作区和验证器的三元组直接纳入训练，而无需对强化学习流水线进行特定于任务的修改。如图 5 和图 6 所示，评估性能在 JobBench-Easy 上从 20.46 提高到 27.20，在 OfficeQA-Full 上从 8.53 提高到 21.54。训练奖励在整个优化过程中也保持清晰稳定的上升趋势。这些结果表明我们的框架不依赖于特定的任务格式或评估范式：相同的统一黑盒强化学习流水线可以很容易地扩展到截然不同且更苛刻的任务分布，同时继续提供有效和稳定的策略优化。

我们使用 Qwen3-30A3B 研究冷启动初始化对通用智能体任务黑盒强化学习的效果，以 OpenClaw 为展开外壳，GRPO 为优化算法。具体而言，我们比较了两种初始化策略：在 ClawGym-SynData 的部分轨迹上进行轻量级监督训练，以及从基础模型直接初始化。

4.6 与白盒 AgentLoop 强化学习的比较
与黑盒强化学习（它与不透明的外壳交互并仅在服务边界观察模型调用）不同，白盒强化学习通过显式构建的智能体循环 [29] 直接暴露完整的交互过程，包括系统提示、工具接口、观察表示、上下文管理和工作流。这些组件可以独立设计和组装以形成不同的智能体循环。
在展开期间，模型生成、工具执行、观察返回和上下文更新被直接记录为完整的多轮轨迹。这使得直接在智能体循环产生的确切交互轨迹上进行优化成为可能。
具体而言，我们实例化了一个具有五类基本工具的白盒智能体循环：bash、search、fetch、code interpreter 和文件操作。我们在基于沙盒的环境中通过此智能体循环进行强化学习训练，并在相同的白盒智能体循环和外部黑盒外壳下评估由此产生的策略模型，以评估循环内性能和白到黑泛化转移。所有实验都遵循与黑盒对应物相同的数据集和评估设置，确保跨训练范式的公平比较。

5 结论
在本文中，我们将黑盒强化学习确立为一种实用且可扩展的方法，用于直接通过复杂部署外壳训练通用自主智能体。原生外壳被视为未修改且不透明的展开引擎，从而将策略优化与外壳执行解耦。我们开发了一个端到端的基础设施，将展开隔离在临时沙盒中，在服务边界捕获忠实的模型行为，使用前缀树重构分叉的多轮轨迹，并保持训练-推理一致性。在此基础设施的基础上，我们适配 PPO 和 GRPO 以处理可能产生多个轨迹的任务，并进一步将公式扩展到混合外壳训练，使单个模型能够在统一的优化流水线内从异构外壳联合学习。
在两个结构不同的外壳 OpenClaw 和 Claude Code 上的实验验证了此公式的有效性和稳定性。使用 Qwen3-30A3B，黑盒强化学习在 ClawGym-Bench 上将 Pass@1 分别提高了 9.98 和 14.81 个百分点，在 PinchBench 上分别提高了 11.71 和 17.28 个百分点，同时在 200-400 步优化中保持稳定。相同的框架也扩展到 JobBench 和 OfficeQA 中更具挑战性的任务设置，其中黑盒强化学习继续提高下游性能。这些结果表明，复杂的部署外壳可以作为有效的训练接口，为在它们运行的执行系统中直接优化通用智能体提供了实用基础。
在未来的工作中，我们将探索将辅助交互（如压缩和子智能体轨迹）纳入策略优化，而不是将它们排除在训练之外。我们还计划将我们的框架扩展到更广泛的通用智能体任务和更多样化的执行设置，以进一步评估其可扩展性和通用性。
