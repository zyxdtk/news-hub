CacheGraft：基于潜在空间文档增强的RAG

📅 2026-11-05 📄 arxiv 🔗 原文链接

原标题：CacheGraft: Enhancing Retrieval-Augmented Generation via Latent-Space Document Enrichment

中文摘要： CacheGraft将KV缓存翻译技术从实时多智能体通信拓展至检索增强生成（RAG）。该系统在离线索引阶段利用C2C融合框架，将大模型（Qwen3-4B）的KV缓存融合进小模型（Qwen3-0.6B）的KV空间；查询时仅需小模型加载融合缓存即可解码作答。在五个知识密集型问答基准上，CacheGraft在30项比较中29项优于纯文本基线（17项统计显著），且融合器零样本、未经检索数据训练。该方案尤其适合推理时只能部署小模型的算力受限场景，主要局限在于KV缓存的存储开销。

摘要

机器学习领域的最新工作已经证明，基于Transformer的语言模型智能体不仅可以通过文本传递状态，还可以通过键值（KV）缓存直接在潜在空间中传递状态。在本文中，我们论证了这种缓存到缓存的翻译所能提供的效用超越了其最初的激励性应用——实时智能体通信，并且可以被用于检索增强生成（RAG）。基于缓存到缓存融合框架，我们提出的CacheGraft系统在离线阶段将语料库中的每个段落编码为较大的共享模型（我们实验中为40亿参数）与较小的接收模型（6亿参数）之间的融合KV缓存表示，使得该缓存可以在查询时注入接收模型，而无需较大的模型。在五个问答基准和两个独立本地运行的评判模型上，CacheGraft在30项比较中有29项优于纯文本接收器基线的答案质量，其中17项具有统计显著性。值得注意的是，这些增益相对于融合器而言是零样本的，该融合器从未在检索数据上训练过。这些初步结果表明，潜在空间文档增强可能是提升RAG系统性能的一条有前景的途径，尤其是在推理阶段只能部署小模型的计算受限环境中。

关键词： 检索增强生成、KV缓存、模型协作、缓存翻译

1. 引言

图1. 共享器和融合器仅在离线阶段运行，每个语料库段落运行一次，且不感知任何查询。融合后的KV缓存是跨越离线/在线边界的唯一产物：在查询时，接收器加载该缓存并独立解码，在潜在空间中读取段落 [p d]，以文本形式读取问题 [q]。（图中流程：阶段1——离线，每个段落一次：段落 d 分别由共享器（4B）与接收器（0.6B）预填充，融合器生成融合KV缓存并持久化；阶段2——在线，每次查询：接收器（0.6B）以KV形式加载 [p d]，以文本形式读取问题 q，并生成答案 [q]。）

机器学习社区的最新突破（Fu et al., 2026；Dery et al., 2026；Rossi et al., 2026）已经证明，基于Transformer的大语言模型（LLM）智能体不仅可以借助标准的文本媒介相互传递信息，还可以通过将键值（KV）缓存从发送方模型翻译到接收方模型的内部向量空间，在潜在空间中传递信息。值得注意的是，这种翻译（通常通过学习一个独立的适配器模型来完成）即使两个模型的权重数量和层数不同也是可行的（Fu et al., 2026；Dery et al., 2026；Rossi et al., 2026）。

推动KV缓存翻译研究的总体动机，是让异构LLM在实时多智能体系统中通过KV缓存向量（而非原始文本）传递状态以实现协作的愿景。通过在潜在空间中运作，KV缓存翻译有望同时提升多智能体计算的质量（因为KV缓存构成了以LLM原生语言表达的更丰富的信息概念表示）与此类系统的性能（通过省去模型将文本输入转换为KV向量的初始步骤）。

本文背后的核心观察是：KV缓存翻译的用处可以超越其最初的激励目标——实时多智能体LLM通信。为此，我们引入CacheGraft框架，将KV缓存翻译范式应用于检索增强生成（RAG），即LLM在生成回答之前从外部语料库调取知识以增强其上下文的任务。将KV缓存翻译应用于RAG并非显而易见，因为典型的RAG部署通常只包含单个LLM；尚不清楚跨模型缓存翻译能在何处发挥作用。我们的关键洞察是：可以在RAG流程的离线索引阶段利用KV缓存翻译，通过将一个较大模型（无法在查询时部署）的KV缓存与一个在线运行的小模型的缓存相融合，来丰富文档的表示。由此，较大的模型充当了事实上的教师，引导较小的接收模型更好地“阅读”文档内容。

与多智能体通信不同，RAG流程的离线阶段对延迟并不敏感，这使得KV缓存融合的开销比实时通信场景中更容易接受。此外，这一离线阶段还使得使用更强大但计算开销高昂的LLM进行索引成为可能。这些洞察推动了我们CacheGraft框架的开发。总而言之，我们在本文中做出以下贡献：

  • 概念洞察： 据我们所知，本工作是首个观察到KV缓存翻译可以被应用于实时智能体间通信这一经典激励示例之外的工作。特别地，我们证明了缓存到缓存（C2C）融合技术（Fu et al., 2026）能够在检索增强生成（RAG）场景中带来生成质量的提升。
  • 概念验证评估： 我们使用C2C团队发布的现成预训练KV缓存融合模型¹（https://huggingface.co/nics-efc/C2C_Fuser）实例化CacheGraft，该模型将Qwen3-4B-Base模型的KV缓存与Qwen3-0.6B模型的缓存融合到后者的KV空间中。我们在五个知识密集型RAG问答基准上评估了我们所提出的系统²（我们的代码可在 https://github.com/vihan-lakshman/CacheGraft 获取），这些基准与原始C2C评估基准不同，后者主要聚焦于推理任务。有趣的是，CacheGraft使用一个并未针对这些检索应用进行专门训练的缓存融合模型就实现了这些增益。
  • 长期研究愿景： 除了概念验证实验结果之外，我们论证了面向RAG应用的KV缓存融合是一个内涵丰富且研究不足的领域，并为社区指出了若干开放性研究问题。

2. 相关工作

本文的工作位于机器学习与信息检索中三条此前互不关联的研究脉络的交汇处。首先是前述的KV缓存翻译研究线（Fu et al., 2026；Dery et al., 2026；Rossi et al., 2026），包括我们在实验中直接使用的C2C框架（Fu et al., 2026）。我们在CacheGraft的评估中专注于使用C2C，因为据我们所知，它在共享器与接收器模型之间展示了最大的参数差距（40亿对6亿参数），因而构成了迄今为止最具可扩展性的翻译方法。

其次，在RAG方面，已有若干工作提出预计算并存储模型对文档的KV缓存表示，并在查询时使用缓存而非原始文本来降低延迟，其方式是省去将文本转换为KV值的步骤（Lu et al., 2025；Chen et al., 2026；Yao et al., 2025；Ma et al., 2025）。然而，这些方法都只使用单个模型的KV缓存，并未考虑用来自另一个更强大LLM的信号来丰富缓存表示，这正是本文方法与之不同的地方。

最后，还有多项研究考察了文档增强问题，即对语料库中的文本进行预处理，使其更适用于RAG应用（Chen et al., 2025；O'Nuallain et al., 2026；Uzan et al., 2026；Lei et al., 2026）。CacheGraft也可以被视为一种文档增强策略，只不过是在潜在空间而非文本层面进行。

3. 背景：缓存到缓存（C2C）

在本节中，我们简要回顾C2C框架（Fu et al., 2026）的细节，因为CacheGraft正是将该融合模型重新用于离线文档增强。简而言之，C2C使一个共享器LLM能够通过将其键值（KV）缓存融合进接收器LLM的缓存，直接在潜在空间中向接收器LLM传递上下文理解。两个底层模型均保持冻结；唯一被训练的组件是一个轻量级的逐层融合器网络。更形式化地，设 x=[x₀,…,x_{n−1}] 表示输入词元序列（在我们的设置中即RAG提示；见第4节）。该序列由每个模型独立分词。随后两个冻结模型在相同输入上进行预填充：接收器为其各层 n=1,…,N 产生逐层KV缓存 𝒞_n(x)，共享者则为其自身的层 m=1,…,N′ 产生缓存 𝒞^𝒮_m(x)。文本输入被消费两次，每个模型的预填充各一次。

由于两个模型的深度可能不同，需要一个层映射策略 𝒢 为每个接收器层 n 指定一个共享器层 𝒢(n)；C2C采用末端对齐策略，先配对最后一层再逐层向前回溯。随后，逐层融合器 ℱ_n 产生融合缓存：

(1) 𝒞^ℱ(x) = { ℱ_n( 𝒞_n(x), 𝒞^𝒮_{𝒢(n)}(x) ) }_{n=1}^{N}

融合缓存 𝒞^ℱ(x) 完全存在于接收器的KV空间中，与输入具有相同的序列长度 n（不引入额外的词元位置），并替换接收器原有的提示缓存。

在推理时，接收器独自执行文本生成。给定已生成前缀 y_{[0:i]}=[y₀,…,y_{i−1}] 以及接收器在该前缀上普通自产的缓存 𝒞(y_{[0:i]})，下一个词元预测为：

(2) y_{i+1} = 𝒫( y_i | 𝒞^ℱ(x) ⊕ 𝒞(y_{[0:i]}) )

其中 ⊕ 表示按序列拼接。融合完成后，共享器不再扮演任何角色：新生成的词元在融合提示缓存之后追加接收器原生的缓存条目，与标准自回归解码完全一致。

这一构造的两个性质对CacheGraft中的RAG设置至关重要。第一，融合缓存是一个自包含的产物：公式2只需要 𝒞^ℱ(x) 和接收器，而不需要共享器或融合器。第二，在因果注意力下，给定位置的融合条目仅依赖于更早位置的词元。这两个性质共同使得公式1的融合步骤可以完全移至离线执行，对每个文档只计算一次且不感知任何查询。

C2C框架在交互式多智能体场景中的一个局限是，它需要让文本输入 x 同时通过共享器和接收器两个模型进行前向传播，这限制了延迟节省的总幅度。KV缓存翻译后续工作（如Latent Cache Flow（Rossi et al., 2026））的一个主要目标就是消除这一缺陷。然而，在RAG场景中，这种融合方式并不构成显著障碍，因为缓存增强步骤发生在离线阶段而非查询时。

4. CacheGraft：将C2C适配于RAG

我们现在描述CacheGraft系统的细节。作为符号约定，我们将RAG提示表示为 x=[p,d,q]，它是固定前导语 p（也称为系统提示）、检索到的文档 d 和问题 q 的拼接。我们将注意力集中在知识密集型问答应用上，这类应用需要一个通常无法在模型自身权重中找到的事实性答案。

在因果注意力下，两个模型在位置 i≤|pd| 处的预融合缓存条目独立于任何位置 j>i 的词元；投影器在这些条目上逐位置、逐层地作用；并且 [pd] 的融合不依赖于 q。因此，一次性计算 [p,d,q] 与单独计算 [p,d] 在 [p,d] 上产生完全相同的KV。由此，对于使用固定前导语的top-1检索，文档始终占据相同的位置范围，因此无需进行RoPE重旋转（Chen et al., 2026）。我们将扩展框架以支持 k>1 的top-k检索（借助诸如TurboRAG微调（Lu et al., 2025）或CacheBlend（Yao et al., 2025）等技术）留作未来工作。

图1描绘了完整的CacheGraft流程。离线阶段，对于每个段落，我们启用融合对 [p,d] 进行预填充，并以内容哈希为键持久化接收器空间的KV。我们还维护一个额外的文档嵌入向量数据库索引。在线阶段，我们基于嵌入相似度识别与查询最相关的文档，将该文档的融合KV缓存加载到基础接收器中并解码问题。至关重要的是，查询路径上我们不需要来自共享器或缓存投影融合器模型的任何东西。

5. 实验

5.1. 实验设置

我们在单块NVIDIA A100-40GB GPU上进行所有实验，并在推理时使用标准贪心解码。

模型。 在所有报告的实验中，我们使用Qwen3-0.6B（Yang et al., 2025）作为接收器，Qwen3-4B-Base（Yang et al., 2025）作为共享器，并使用针对该模型对发布的C2C投影器。该投影器在通用聊天蒸馏数据上训练，从未见过检索数据，因此所有结果相对于融合器训练而言都是零样本的。

数据。 我们使用五个标准的知识密集型问答基准进行RAG评估：SQuAD v1.1（Rajpurkar et al., 2016）、AdversarialQA（Bartolo et al., 2020）、CovidQA（Möller et al., 2020）、QASPER（Dasigi et al., 2021）和TriviaQA（Joshi et al., 2017）。在搜索方面，我们使用bge-small（Xiao et al., 2023）嵌入执行稠密top-1检索。在评估方面，每个黄金段落我们保留一个问题。我们还在“检索”和“oracle（完美检索）”两种条件下运行实验，以理解搜索质量对整体RAG性能的影响。

指标。 我们采用LLM作为评判者的机制（Zheng et al., 2023）作为主要评估指标。我们使用两个评判者评估所有RAG输出，二者均为本地运行的开权重模型，对原始未修改的生成内容进行评分：phi-4（Abdin et al., 2024）和Gemma-2-9B（Team et al., 2024）。我们还报告contains指标，它衡量生成的答案是否包含测试数据集中的黄金标准答案。我们还基于评估问题集合使用精确双侧配对McNemar检验计算统计显著性。我们不依赖精确匹配（EM）和F1分数等传统RAG指标，因为我们观察到融合KV缓存产生的答案往往更为冗长（如表2所示），这会损害这些以词元为中心的指标上的表现。

在表3中，我们观察到QASPER上共享器与接收器之间的RAG质量差距最小，这解释了缓存融合在该数据集上结果较为混合的原因：共享器能够提升接收器的空间有限。总体而言，表3表明CacheGraft要在知识密集型RAG任务上产生价值需满足两个前提条件：共享器必须相对于接收器有提升空间，且文档必须提供共享器能够利用的事实信号。

我们还在表2中给出了CacheGraft在SQuAD数据集上部分成功与失败案例的示例。我们观察到，缓存融合确实能在多个案例中将接收模型引导至段落的相关部分，但也会出错。我们还注意到，CacheGraft的输出往往比接收器和共享器模型都更冗长，这也限制了CacheGraft的总延迟收益，如表4所示。尽管如此，表4仍然表明CacheGraft在GPU内存消耗方面具有优势。我们推测，CacheGraft融合KV缓存所带来的冗长度增加，可以通过针对检索任务进行显式训练来缓解，我们将此作为未来工作的另一个方向。

6. 局限性与开放问题

6.1. 局限性

我们方案的首要实际局限是存储问题：我们必须为每个文档存储KV缓存，这可能消耗比原始文本高出几个数量级的空间（在没有任何优化的情况下，10万个文档约在太字节量级）。这一问题继承自先前提出为检索预计算KV缓存的工作，如TurboRAG（Lu et al., 2025）、Block Attention（Ma et al., 2025）和CAG（Chan et al., 2025），并可以通过与本文工作互补的KV缓存压缩技术（Shi et al., 2024）加以缓解。我们当前研究的另一个局限是，我们只关注检索单个文档，且在评估中仅考虑了单个C2C融合器模型。将我们的系统扩展到支持top-k检索和更多模型，是未来工作的另一个有前景的方向。

6.2. 开放问题

本文的结果是对KV缓存融合增强RAG应用的概念验证演示，并为该领域的未来研究开辟了许多方向。下面我们着重指出两个特别有趣的方向：

(1) 训练面向RAG的定制融合器模型： 如前所述，我们使用的是一个并未针对检索任务的现成C2C融合器模型。我们能否通过使用检索专用的训练目标和数据集来训练融合器模型，从而提升CacheGraft的性能？在缓存融合失效之前，共享器与接收器模型之间的差距能扩大到什么程度？我们甚至能否训练融合器使其更具可压缩性，以增强标准的KV缓存压缩技术？

(2) 与文本文档增强相结合： 先前的工作如EnrichIndex（Chen et al., 2025）和AutoIndex（O'Nuallain et al., 2026）提出修改文档文本来提升RAG性能。文本级的文档增强与我们方法的潜在空间策略之间如何相互作用？是否存在一种文本增强方法，能够超越直接使用原始文档而增强KV缓存翻译的效果？

7. 结论

迄今为止，将KV缓存从一个LLM翻译到另一个可能截然不同的模型的思想，仅被应用于实时多智能体系统中的状态通信。本文核心的关键洞察在于：同样的思想可以通过在离线阶段于较大的共享器模型与较小的接收器之间对文档进行KV缓存翻译，从而重新应用于RAG，以增强接收器的在线答案质量。事实上，我们认为RAG可能是比实时智能体通信更适合缓存到缓存融合范式的场景，因为让文本输入同时通过共享器和接收器模型进行前向传播（C2C的要求）对于离线文档索引而言是可忽略的成本，但在实时推理场景中则可能构成限制。我们将这一洞察落实为CacheGraft——一个利用C2C融合、以查询时不运行的大模型信号来增强小接收器模型KV缓存表示的原型RAG系统。我们的初步评估将C2C扩展到融合器训练中不存在的零样本知识密集型问答任务，结果表明，在较大共享器模型拥有可迁移提升空间的数据集上，CacheGraft相对于仅接收器的文本基线持续改进了生成质量。或许令人惊讶的是，这些问答任务上的积极结果来自一个在任何方面都未针对检索调优的现成预训练C2C融合器模型。我们的发现还引出了许多有趣的未来工作问题（我们在6.2节中概述），我们希望这些问题能推动面向RAG应用的潜在空间文档增强的进一步研究。
