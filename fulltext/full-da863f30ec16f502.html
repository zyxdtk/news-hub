摘要

测试时扩展方法在部署阶段投入额外计算资源，以提升大语言模型在困难目标问题上的性能。大多数方法依赖于验证器来对候选解的正确性进行评分，并用它在模型输出中进行选择或精炼。然而，在许多部署场景中，目标问题上无法获得强验证器。我们提出了测试时自博弈（TTSP），一种使用非对称自博弈且不依赖验证器的测试时扩展方法。在 LiveCodeBench v6 的难度校准子集上，TTSP 在我们评估的所有验证器强度下都是表现最佳的方法，且随着验证器变弱，与最强基线的差距进一步扩大；在无验证器的极限情况下，TTSP 在 mean@8 上实现了 35% 的绝对提升。这些增益在一系列验证器强度下均成立，除非基础策略对正确答案的覆盖率接近于零。

1 引言

图 1： TTSP 在弱验证器区间内优于所有基线测试时扩展方法。TTSP 和 ACE 在收敛检查点处评估；FMV 使用公开和私有输入测试用例。

当模型没有相关训练数据且没有可靠方法检验自身答案时，如何在一个困难的单一目标问题上取得改进？每当大语言模型的基础知识原则上足以解决某个问题，但模型很少或从未生成正确解时，就会出现这个问题。这类例子遍布各个领域，包括竞技编程（Zheng 等，2025）、定理证明（Tsoukalas 等，2024）和分子生成（Gao 等，2022）。

测试时扩展旨在弥合这一差距，在部署阶段投入额外计算资源以提升目标问题上的性能。许多测试时扩展方法，如拒绝采样（Snell 等，2024），依赖于目标问题的验证器来判断某次尝试是否正确。类似地，诸如 ACE（Zhang 等，2026a）等提示优化方法使用执行反馈来演化提示。其他方法依赖于辅助数据，通常是从大型语料库中检索的相似问题，用于在目标问题的邻域上进行训练（Hübotter 等，2025；Hübotter 等，2026）。另一类方法既不需要验证器也不需要辅助训练数据，而是通过多数投票聚合模型自身在目标问题上 rollout 的信号（Zuo 等，2025；Du 等，2026；Shafayat 等，2025；Launer 等，2026）。

我们提出了测试时自博弈（TTSP），一种不依赖辅助训练数据或强验证器的测试时扩展方法。TTSP 的灵感来自训练时的非对称自博弈方法，如 Absolute Zero（Zhao 等，2025）和 R-Zero（Huang 等，2025），这些方法仅从自生成的合成问题中学习。我们将这种方法适配到单一目标设置中，将合成问题集中于一个目标问题而非基准分布上。TTSP 唯一的外部需求是一个交互式环境（如 Python 解释器）来为模型提供基础。

我们的贡献如下：
(i) 我们定义了无辅助数据且验证器缺失或微弱的测试时扩展设置，并刻画了现有测试时扩展方法的行为。
(ii) 我们提出了 TTSP，一种基于非对称自博弈、对弱验证器具有鲁棒性的测试时扩展方法。

图 2：测试时自博弈概览。 给定目标问题 $x^{\star}$ 和先前生成的合成问题，提议者策略 $\pi_{\phi}$ 生成目标条件化的合成问题 $\mathcal{D}$，包括问题陈述、测试和参考解。求解者策略因正确解决合成问题而获得奖励，而提议者因生成位于求解者当前学习前沿附近的合成问题而获得奖励（两者均通过 GRPO；见红色箭头）。合成问题历史为提议者提供上下文并填充回放缓冲区 $\mathcal{B}$。经过足够次数的迭代后，测试时训练的求解者便可以尝试目标问题。

2 相关工作

测试时扩展。 在部署阶段投入额外计算以提升目标问题上的性能，已在测试时扩展（Snell 等，2024；Brown 等，2024）和测试时训练（TTT）（Sun 等，2020）的框架下得到研究。基于采样的测试时扩展反复从策略中抽取 rollout，并使用验证器或投票在其中进行选择（Brown 等，2024；Launer 等，2026）。权重更新型 TTT 将模型权重特化到每个目标问题，在抽象推理（Akyürek 等，2025）、语言建模（Hardt 和 Sun，2024；Hübotter 等，2026；Sun 等，2025）和视频生成（Dalal 等，2025）方面取得成功，使用来自外部数据的目标问题邻域上的监督损失（Hardt 和 Sun，2024；Hübotter 等，2026；Bertolissi 等，2025；Bagatella 等，2025）或输入序列上的自监督损失（Sun 等，2025；Dalal 等，2025）。与我们的工作最相关的是，Zuo 等（2025）将 TTT 扩展到测试集上的 RL，使用多数投票作为伪标签，而 Simonds 和 Yoshiyama（2025）在测试时生成问题变体，并通过符号积分中的数值验证进行 RL 训练。这连接到更广泛的无监督 RL（Zhang 等，2025；Agarwal 等，2025；Zhang 等，2026b；Du 等，2026）和 LLM 自我改进（Zelikman 等，2022；Gulcehre 等，2023；Lee 等，2025）主题。如何在没有外部数据或监督的情况下，仅从模型本身为测试时扩展获得强学习信号，仍然是一个开放问题。

课程学习。 课程学习由 Bengio 等（2009）提出，其原则是将训练样本从易到难排序可以加速优化并提升泛化能力。此后它已成为现代 LLM 训练的核心设计模式，支撑着预训练和中期训练（DoReMi，Xie 等 2023；OLMo 2，Team OLMo 等 2025；Phi-4，Abdin 等 2024），尤其是基于 RL 的推理后训练，其中 DeepSeek-R1（Guo 等，2025）、Kimi k1.5（Kimi Team 等，2025）以及自适应方案如自演化课程（Chen 等，2025b）和从易到难泛化（Sun 等，2024）始终优于均匀采样。

自博弈。 自博弈是强化学习许多里程碑式成果的基础（Schmidhuber，1991；Tesauro，1995；Silver 等，2016；Silver 等，2017；Silver 等，2018；Berner 等，2019）。与固定数据集不同，自博弈课程与学习者共同演化且原则上无界，这一特性最近被论证为在人类生成数据的限制之外持续进步的核心（Silver 和 Sutton，2025）。最近的工作通过为模型分配提议者策略和求解者策略的双重角色，并从自动验证器（如代码执行、多数投票或证明检查器）获得学习信号，将这一特性引入 LLM 后训练（Zhao 等，2025；Huang 等，2025；Chen 等，2025a；Kuba 等，2025；Liu 等，2026）。然而，由此产生的课程往往集中在任务空间的狭窄区域，完全无数据自博弈的收益通常受基础模型覆盖范围的限制（Chae 等，2025）。先前的 LLM 自博弈方法在训练时运行，目标是跨基准分布的广泛能力提升。我们相反在测试时应用自博弈，使用目标问题分解来构建专门化的课程，将适配集中在目标问题上。

上下文优化。 一条互补的研究路线通过修改上下文而非模型权重来适配 LLM 行为。GEPA（Agrawal 等，2026）通过反思性提示演化优化文本参数，使用验证器反馈提出变异，并使用帕累托式选择保留互补的提示变体。ACE（Zhang 等，2026a）通过结构化的生成器-反思者-策展人分解扩展了这一范式：生成器尝试任务，反思者从执行反馈中提取可复用的经验教训，策展人逐步更新长篇攻略上下文同时保留有用的细节。这种分解使 ACE 能够积累比 GEPA 提示级变异更细粒度的领域知识，并且 ACE 在推理和工具使用基准上报告了对 GEPA 的一致增益。

3 预备知识

我们研究针对单个目标问题的测试时扩展。设 $x^{\star}$ 表示目标问题，$y$ 表示候选解。策略 $\pi$ 生成 rollout $y\sim\pi(\cdot\mid x^{\star})$。先知验证器 $v^{\star}(y;x^{\star})\in{0,1}$ 指示 $y$ 是否为 $x^{\star}$ 的正确解。先知用于评估，但假定在测试时的训练或反馈中不可用。部署时的目标验证器 $v$ 可能微弱或缺失。我们进一步假设没有辅助训练数据（即与 $x^{\star}$ 相关的问题及其真实解 $(x,y)$）可用。

我们问测试时扩展方法在此设置下能否具有鲁棒性。我们提出这可以通过从合成问题而非直接从目标问题导出学习信号来实现。

合成问题 $\hat{x}$ 是在测试时以 $x^{\star}$ 为条件生成的自包含问题。我们在竞技编程设置中评估 TTSP，其中 $\hat{x}$ 由自然语言陈述、输入/输出规范、示例输入/输出对、保留的输入测试用例和参考 Python 程序组成。参考程序不会展示给求解者。在保留的输入测试用例上执行参考解产生真实输出，与输入结合定义合成验证器 $v_{\mathrm{syn}}(\hat{y};\hat{x})\in{0,1}$。该验证器判断尝试的解 $\hat{y}$ 是否通过所有保留测试用例。我们将合成问题定义为具有确定性验证机制的自包含训练任务。我们不要求合成问题 $\hat{x}$ 与 $x^{\star}$ 之间存在形式化的分解关系；TTSP 中对目标问题的依赖是通过将提议者以 $x^{\star}$ 和合成问题历史为条件来引入的。

算法 1：测试时自博弈

输入： 目标问题 $x^{\star}$，提议者策略 $\pi_{\phi}$，求解者策略 $\pi_{\theta}$，迭代次数 $T$
1: 初始化合成问题历史 $\mathcal{H}\leftarrow\emptyset$
2: for $t=1$ to $T$ do
3: $\mathcal{D}{t},\mathcal{B}{t},\mathcal{R}{\theta},\mathcal{R}{\phi}\leftarrow\emptyset$
4: // 生成合成问题
5: $\mathcal{C}{t}\leftarrow\textsc{ConstructContexts}(x^{\star},\mathcal{H})$
6: for each $c\in\mathcal{C}{t}$ do
7: ${\hat{x}^{(i)}}\sim\pi_{\phi}(\cdot\mid c)$
8: $\mathcal{A},\mathcal{I}\leftarrow\textsc{Filter}({\hat{x}^{(i)}})$
9: $\mathcal{D}{t}\leftarrow\mathcal{D}{t}\cup\mathcal{A}$
10: $\mathcal{R}{\phi}\leftarrow\mathcal{R}{\phi}\cup\textsc{InvalidPenalty}(\mathcal{I})$
11: end for
12: // 从历史中采样
13: $\mathcal{B}{t}\leftarrow\textsc{SampleHistory}(\mathcal{H})$
14: // 求解者策略尝试合成问题
15: for each $\hat{x}\in\mathcal{D}{t}\cup\mathcal{B}{t}$ do
16: ${\hat{y}^{(j)}}\sim\pi{\theta}(\cdot\mid\hat{x})$
17: ${r_{\theta}^{(j)}}\leftarrow v_{\mathrm{syn}}({\hat{y}^{(j)}};\hat{x})$
18: $\mathcal{R}{\theta}\leftarrow\mathcal{R}{\theta}\cup{(\hat{x},\hat{y}^{(j)},r_{\theta}^{(j)})}$
19: $\mathcal{H}\leftarrow\textsc{UpdateHistory}(\mathcal{H},\hat{x},{\hat{y}^{(j)}},{r_{\theta}^{(j)}})$
20: end for
21: // 分配提议者策略奖励
22: $\mathcal{R}{\phi}\leftarrow\mathcal{R}{\phi}\cup\textsc{ProposerReward}(\mathcal{D}{t},\mathcal{R}{\theta})$
23: // 更新提议者策略和求解者策略
24: 使用 $\mathcal{R}{\theta}$ 通过 GRPO 更新求解者策略 $\pi{\theta}$
25: 使用 $\mathcal{R}{\phi}$ 通过 GRPO 更新提议者策略 $\pi{\phi}$
26: end for
27: return 适配后的求解者策略 $\pi_{\theta}$

4 TTSP：测试时自博弈

测试时自博弈（TTSP）通过在目标条件化的合成问题上训练，使求解者策略适配到单个目标问题 $x^{\star}$。提议者策略生成合成问题，求解者策略尝试它们，执行提供奖励，两个策略都用 GRPO 更新。目标问题验证器在 TTSP 训练期间不使用。图 2 展示了非对称自博弈循环。

自博弈设置。 TTSP 在共享的冻结 Qwen3-8B 骨干上使用两个 LoRA 适配器（Hu 等，2022；Yang 等，2025）：提议者策略 $\pi_{\phi}$ 和求解者策略 $\pi_{\theta}$。提议者策略以 $x^{\star}$ 和训练历史为条件设计合成课程，而求解者策略在生成的合成问题上训练。分离适配器为每个角色提供自己的奖励信号，并避免了我们在为两个角色使用单个适配器时观察到的梯度冲突。内存成本仍接近单个 8B 模型，因为骨干是共享的，只有适配器被更新。

算法概览。 TTSP 算法的一步 $t$ 从构建提议者的提示开始。提示（或上下文）包含先前生成的合成问题的小样本及其求解率（来自求解者策略）。上下文还包括目标问题和指导提议者基于先前合成问题生成有效、相关且难度适当的合成问题的指令。第一步的提示不包含先前的合成问题。

然后提议者生成候选合成问题和参考程序。无效候选由领域特定的启发式过滤器 Filter 移除。有效的合成问题 $\mathcal{D}{t}$ 被添加到旧合成问题缓冲区 $\mathcal{B}{t}$，后者从合成问题历史 $\mathcal{H}$ 中采样。求解率在 $[0.1,0.8]$ 范围内的问题被均匀随机采样。

然后求解者策略为合成问题的组合集 $\mathcal{D}{t}\cup\mathcal{B}{t}$ 生成解。为每个解计算合成奖励。

历史 $\mathcal{H}$ 用新的合成问题、求解者 rollout 和奖励更新。然后使用合成奖励通过 GRPO 更新求解者。提议者使用求解者奖励的变换 $\textsc{ProposerReward}(\mathcal{D}{t},\mathcal{R}{\theta})$ 通过 GRPO 更新。该变换在本节后面描述。

经过足够多的步骤后，目标是让求解者策略在目标问题 $x^{\star}$ 上具有更准确的解分布。然后可以使用求解者来尝试目标问题。

合成问题在直接在 $x^{\star}$ 上训练会稀疏、误导（由于弱目标问题验证）或不可用（如果没有目标问题验证器）的情况下提供密集的训练信号。TTSP 产生许多目标条件化的合成问题，这些问题既处于求解者能力的边缘（由于在最佳难度范围内重新采样先前的问题，以及提议者奖励变换），又锚定到目标问题（由于上下文构建）。TTSP 伪代码见算法 1。

合成问题生成。 提议者分两个阶段生成每个合成问题。首先，解提议以 $x^{\star}$ 和最近的合成问题历史 $\mathcal{H}$ 为条件，然后产生合成问题草稿和 Python 参考程序。其次，问题精炼从参考程序重建干净的问题陈述、输入/输出规范、示例 I/O 和保留输入测试。保留输出通过执行参考程序获得。这种排序使测试和陈述符合程序的实际行为，而不是要求单次解码过程保持陈述、测试和解相互一致。子目标生成提示模板列在附录 F 中。

然后我们应用 Filter，它拒绝超时、运行时错误、仅重复测试集或常数输出行为的候选。接受的问题进入新问题集 $\mathcal{D}_{t}$，并在求解者尝试后添加到历史中。无效候选不进入求解者批次，并接受固定的提议者惩罚。

合成问题历史。 TTSP 维护已接受合成问题的历史 $\mathcal{H}$ 以及求解者在它们上面最近的 rollout。在每次迭代中，求解者批次将新的合成问题 $\mathcal{D}{t}$ 与从 $\mathcal{H}$ 采样的先前问题缓冲区 $\mathcal{B}{t}$ 混合。采样器偏向当前求解率位于可学习性窗口内的问题：已解决的问题提供很少的训练信号，而几乎不可能的问题产生几乎全零的奖励。由于 UpdateHistory 覆盖每个问题的最新 rollout 和求解率，提议者上下文和缓冲区采样都跟踪当前求解者而非过时的快照。

奖励。 求解者接收二元合成奖励 $r_{\theta}(\hat{y},\hat{x})=v_{\mathrm{syn}}(\hat{y};\hat{x})$，当且仅当求解者 rollout $\hat{y}$ 通过合成问题 $\hat{x}$ 的所有保留生成测试时等于一。

提议者因生成位于求解者当前前沿附近的问题而获得奖励。设 $\bar{r}_{\theta}(\hat{x})$ 为 $\hat{x}$ 上 rollout 的平均求解者奖励。对于已接受的合成问题，我们定义

$$r_{\phi}(\hat{x})=1-2\left|\bar{r}_{\theta}(\hat{x})-\tfrac{1}{2}\right|, \tag{1}$$

对无效生成有固定惩罚。三角形轮廓针对稀疏伯努利奖励在 GRPO 下诱导最大组相对信号的区域，因此提议者策略因保持求解者策略接近其前沿而获得奖励（Hübotter 等，2025）。缓冲区资格窗口选择为匹配该轮廓的高奖励部分。

优化。 我们使用 GRPO（Shao 等，2024）、DAPO 风格的非对称裁剪（Yu 等，2025）和零 KL 正则化优化两个适配器，遵循 Hübotter 等（2025）的测试时适配设置。超参数列在附录 B.1 中。

5.2 评估协议

每个方法的输出被评估为一组八个目标问题提交。对于聚合比较，该集合来自收敛或最终的方法输出；对于训练曲线诊断，相同的定义应用于每个检查点 $t$。

设 $Y={y_{1},\ldots,y_{8}}$ 表示 $x^{\star}$ 的八个提交候选。对于验证器 $v\in{v_{0},v_{25},v_{50},v_{75},v_{\mathrm{pub}},v_{\mathrm{priv}},v^{\star}}$，我们形成接纳子集 $A(v)={y\in Y:v(y)=1}$。对于非空接纳集，我们报告过滤后的 mean@8 分数

$$\mathrm{mean@}8(v)=\frac{1}{|A(v)|}\sum_{y\in A(v)}v^{\star}(y).$$

在 $v_{0}$ 下，没有候选被过滤掉，因此 $A=Y$，mean@8 是所有八个候选中通过 $v^{\star}$ 的比例。在整篇文章中，mean@8 指的是这种过滤后的分数；我们写未过滤 mean@8 表示所有八个提交候选中通过 $v^{\star}$ 且无评估时过滤的比例。空接纳集由附录 A.5 中的前向延续规则处理。由于相同的过滤过程应用于所有方法，mean@8 的差异反映了候选质量的差异而非评分的差异。

TTRL（Zuo 等，2025）虽然以其多数投票奖励而闻名，但设计用于基准级适配，通过每个提示的多数投票奖励联合训练一组测试问题，与我们的逐问题设置不同。TTRL 也仅在数学上评估，而 FMV 是为竞技编程创建的，其中由于测试用例的存在，多数投票可以以更具策略性的方式进行。

上下文优化。 我们的提示优化基线是 ACE（Zhang 等，2026a）。我们在每个验证器强度下分别运行 ACE，使用该验证器下的通过/失败结果作为其生成器-反思者-策展人循环的奖励信号。然后将评估时过滤过程应用于 ACE 的最终提交。我们使用 ACE 而非 GEPA（Agrawal 等，2026），因为 ACE 在我们的初步运行中是更强的上下文优化变体。完整的实现细节在附录 C.1 中提供。

5.4 结果

跨验证器强度的鲁棒性。 TTSP 在我们评估的每个验证器强度下都是表现最佳的方法（见图 1）。TTSP 曲线在整个扫描中近似平坦，而所有三个基线随着验证器变弱而下降，与 TTSP 的差距相应扩大。TTSP 的训练时奖励是自博弈循环固有的，因此验证器强度轴仅在评估时变化；基线都依赖验证器进行选择（拒绝采样、FMV）或作为奖励信号（ACE），它们的性能受验证器判别能力的限制。

TTSP 训练动态。 图 5 显示了 TTSP 随训练步骤的性能。大部分改进发生在前 10 个训练步骤内，之后曲线保持稳定至检查点间噪声。验证器强度条件之间的差距也在训练期间缩小。这些动态表明合成课程快速将概率质量转移到在后续评估时过滤下仍然有用的候选上。

扩展基线方法。 图 3 报告了沿每个基线原生计算轴的扩展研究。Qwen3-8B 拒绝采样和 FMV 面板改变 rollout 预算 $k$，而 ACE 面板改变上下文优化迭代次数并对当前 ACE 提交评分。Qwen3-8B 拒绝采样主要在验证器足够强以拒绝错误候选时随更大 rollout 预算改进。FMV 随额外 rollout 改进，因为功能一致性变得更有信息量。ACE 仅在验证器提供信息性通过/失败反馈时随迭代改进；在 $v_{0}$ 下，它保持在基础策略水平，因为没有采取优化步骤。这些结果表明增加计算并不能消除基线对目标验证器信息的依赖。

无验证器设置。 在 $v_{0}$ 设置中，验证器接纳每个候选。在此设置中，ACE 无法改进，因为它没有获得任何验证反馈。FMV 仍然限于从基础策略采样的目标问题 rollout 中选择，而 TTSP 相比所有基线有显著改进。

TTSP 受目标问题难度限制。 TTSP 要求正确的 rollout 以非平凡的质量存在于基础策略的支持中。将 HardLCBv6 拆分为 MidHardLCBv6 和 VeryHardLCBv6 揭示了急剧的截止（图 7）。在 MidHardLCBv6 上，TTSP 相对基础策略的改进在强验证器下很小，并随着验证器变弱而急剧上升。在 VeryHardLCBv6 上，改进在整个扫描中近似为零——在最强验证器下略为负，其中基础策略上的拒绝采样仍可以浮现罕见的正确 rollout，在最弱验证器下仅略微为正。低于 $\mathrm{mean}@512\approx 0.1$ 时，提议者策略无法引导组合回 $x^{\star}$ 的课程。

TTSP 何时最有效？ 图 5 在逐目标层面总结了相同的模式。当基础模型覆盖非平凡且评估时验证器弱时，TTSP 占主导。当验证器足够强以识别罕见的正确 rollout 或基础模型覆盖太低以至于 TTSP 无法构建有用的课程时，基础模型拒绝采样占主导。由此产生的边界将 TTSP 置于一致性区间：它在正确或部分有用的目标相关行为存在但在直接采样下不可靠时最有用。

6 讨论

测试时自博弈（TTSP）改变了测试时扩展学习信号的来源。现有方法从目标问题上的验证器导出其选择或学习信号，其有效性随着该验证器变弱而退化。在 TTSP 中，求解者策略而是在由提议者策略生成的合成问题的执行反馈上训练（两者都从相同的基础策略初始化），目标问题验证器被排除在训练循环之外。结果是一个对弱和缺失目标验证器实质上更鲁棒的测试时扩展算法，前提是基础策略对目标问题 $x^{\star}$ 具有非平凡的覆盖。

图 7：TTSP 与 Qwen3-8B 之间 mean@8 的差异。 随着验证器变弱，差距在 MidHardLCBv6 上大且为正。在 VeryHardLCBv6 上，差距接近零：在最弱验证器下仅略微为正。

局限性。 TTSP 针对每个目标问题进行适配，不在目标之间分摊计算，适用于每个目标足够有价值以值得专门适配预算的部署场景。TTSP 也仅解决一致性区间：当基础策略对目标答案的覆盖有效为零时，提议者策略可以合成的任何课程都无法组合回它（图 7）。此外，像其他自博弈算法一样，TTSP 完全从自生成内容而非任何外部验证的目标导出其训练信号。这使得训练时稳定性成为一个应被主动监控的问题。提议者策略可能漂移到破解其奖励函数的合成问题而非组合回 $x^{\star}$ 的问题，并且求解者策略的熵在窄分布上的持续训练下可能崩溃（Bailey 等，2026）。训练动态的进一步讨论见附录 D。

未来工作。 若干自然扩展来自放松 TTSP 的约束。每当存在非退化的目标问题奖励时，提议者策略的合成问题集可以用 $x^{\star}$ 本身增强，将课程驱动和目标驱动的训练结合在一个系统中。当外部语料库可用时，该集合还可以用从外部语料库检索的最近邻合成问题增强（Hübotter 等，2025），在不失去课程结构的情况下摄取辅助数据。此外，TTSP 可以应用于具有丰富工具的其他领域，包括具有执行沙箱、仿真引擎或数据库引擎的领域。最后，解决发现区间（基础模型对目标问题解的覆盖接近零）仍然是一个重要的开放方向；它可能需要外部信息或比课程本身提供的实质性更强的搜索。

A.2 验证器强度轴

验证器是应用于原始目标问题 $x^{\star}$ 候选解的选择规则。强验证器拒绝大部分错误候选程序，而弱验证器接纳许多假阳性。我们在一系列验证器强度下评估，将测试时扩展问题分解为候选生成和候选选择，遵循正文中的动机，即当选择信号弱时，仅测试时计算是不够的（Snell 等，2024；Brown 等，2024）。

最弱的条件是 $v_{0}$，定义为对每个 rollout $y$ 有 $v_{0}(y)=1$。它对应于无过滤：所有生成的候选被视为可接纳，方法仅通过其未过滤候选通过先知 $v^{\star}$ 的频率来评估。校准的人工验证器 $v_{25}$、$v_{50}$ 和 $v_{75}$ 构造为拒绝大约指定比例的错误校准 rollout。自然的 LiveCodeBench 验证器 $v_{\mathrm{pub}}$、$v_{\mathrm{priv}}$ 和 $v^{\star}$ 分别由公开测试、私有测试和它们的并集构建（Jain 等，2024）。公开+私有验证器 $v^{\star}$ 既是最强的评估时过滤器，也是用于测量最终正确性的先知。

A.3 自然 LiveCodeBench 验证器

LiveCodeBench 为每个目标问题提供公开和私有测试用例（Jain 等，2024）。我们使用这些测试套件作为自然的验证器访问级别。公开验证器 $v_{\mathrm{pub}}$ 模拟了部署时只有示例或公开测试可用的现实编程竞赛或实时编码场景。私有验证器 $v_{\mathrm{priv}}$ 和公开+私有验证器 $v^{\star}$ 提供更强的选择规则，并作为高验证器访问参考点。

所有报告的正确性分数都是针对 $v^{\star}$ 计算的。因此，即使评估时过滤器弱于 $v^{\star}$，最终测量也询问接纳的候选是否通过完整的公开+私有评估器。这一约定保持了目标量在不同验证器强度条件下固定，并使图 1 中的曲线可比。

A.4 人工验证器校准

校准的弱验证器 $v_{25}$、$v_{50}$ 和 $v_{75}$ 从包含保留的生成测试以及公开和私有 LiveCodeBench 测试的候选池中选择。我们称这些验证器为人工的，因为子集的选择是为了匹配目标经验拒绝率，而不是因为每个选定的测试都是生成的。生成的候选输入使用 Qwen 3 8B（Yang 等，2025）产生，采用与 TTSP 重建合成问题测试相同的精炼式提示模式；此模式镜像的 TTSP 精炼提示在附录 F.4 中报告。这些测试不用于训练 TTSP。它们仅用于构建受控的评估时过滤器，其假阳性率可以比自然的公开/私有拆分更精细地变化。

生成的输入不带有可信的真实输出，因此我们通过在 $v^{\star}$ 下已经正确的基础模型程序的共识来标记它们。公开和私有 LiveCodeBench 测试使用其提供的标签。对于每个目标问题，我们采样 512 个 Qwen 3 8B 基线 rollout，并使用 $v^{\star}$ 将它们划分为正确和错误的程序。对于生成的输入 $z$，我们在 $z$ 上执行正确的基础程序。如果正确的程序不一致，则丢弃 $z$；如果它们一致，则共识输出用作参考标签。此步骤旨在减少假阴性：仅当已知能解决目标问题的程序在其输出上一致时，才保留生成的测试。

然后我们将验证器构造简化为错误校准 rollout 上的覆盖问题。每个保留的候选测试用例 $t_{j}$ 具有相关的拒绝集 $E_{j}\subseteq\mathcal{Y}{\mathrm{incorrect}}$，其中 $E{j}$ 包含在 $t_{j}$ 上执行失败或产生与共识输出不同输出的错误校准 rollout。对于由测试子集 $S$ 定义的候选验证器，其经验强度为

$$c(S)=\frac{\left|\bigcup_{t_{j}\in S}E_{j}\right|}{|\mathcal{Y}_{\mathrm{incorrect}}|}.$$

该定义考虑了测试之间的重叠：拒绝相同错误 rollout 的两个测试不会累加地增加验证器强度。

对于每个目标问题，$v_{25}$、$v_{50}$ 和 $v_{75}$ 被选择为保留候选测试的子集，其经验覆盖 $c(S)$ 分别最接近 0.25、0.50 和 0.75。由此产生的过滤器有意允许假阳性，因为弱验证器应该接受一些错误的程序。我们将 $v_{\mathrm{pub}}$、$v_{\mathrm{priv}}$ 和 $v^{\star}$ 保持为单独的自然验证器条件，而不是将它们折叠到此校准的人工扫描中。

C.1 ACE 基线实现

我们包含 ACE（Zhang 等，2026a）作为测试时上下文优化基线。与 TTSP 相反，ACE 不更新模型权重。相反，它维护一个特定问题的文本攻略，从执行反馈修订该攻略，并在修订后的攻略上条件化后续候选生成。因此 ACE 测试是否可以从仅上下文适配而非 TTSP 的权重更新策略适配中获得增益。

为了进行受控比较，所有 ACE 角色使用与我们的 TTSP 实验相同的基础模型 Qwen3-8B。每个 ACE 迭代由几轮生成-反思组成。在每轮中，生成器使用当前攻略提出 Python 解，候选在当前验证器条件下可用的反馈测试上执行，反思者将产生的执行信号转化为对尝试的具体诊断。在一迭代的轮次完成后，策展人将积累的反思转化为攻略的结构化更新，然后在下一迭代中使用。

我们在与其他测试时基线相同的反馈机制下评估 ACE：公开测试、私有测试、公开+私有测试和校准的人工验证器测试。暴露给 ACE 的反馈限于相应条件下可用的测试。完整的公开+私有评估器 $v^{\star}$ 仅用于每轮和每迭代后的保留监控，除公开+私先知条件外不向攻略透露。

ACE 以在线模式评估，每个目标问题一个演化攻略。我们使用 15 次 ACE 迭代，每次迭代最多 5 轮生成-反思，攻略演化期间确定性解码，最大生成长度 16,384 tokens，最大模型上下文长度 40,960 tokens。

C.2 功能多数投票基线

我们按照 Launer 等（2026）实现功能多数投票（FMV）。FMV 选择规则仅使用输入：它使用目标问题输入通过功能行为比较候选程序，但不需要目标问题输出。

设 $\mathcal{C}={c_{1},\ldots,c_{N}}$ 为候选程序，$\mathcal{X}={x_{1},\ldots,x_{K}}$ 为用于功能比较的目标问题输入用例。在输入 $x_{k}$ 上执行候选 $c_{i}$ 产生输出字符串 $o_{i,k}$。我们丢弃在比较输入上执行失败的候选，并将剩余的有效候选表示为 $\mathcal{C}{\mathrm{val}}$。对于每个有效候选 $c{i}\in\mathcal{C}_{\mathrm{val}}$，我们计算 FMV 分数

$$S(c_{i})=\sum_{\begin{subarray}{c}c_{j}\in\mathcal{C}{\mathrm{val}}\ j\neq i\end{subarray}}\sum{k=1}^{K}\mathbf{1}{o_{i,k}=o_{j,k}}.$$

该分数计算候选 $c_{i}$ 与其他有效候选在比较输入上的成对功能一致性。

原始 FMV 选择规则返回 $\arg\max_{c_{i}\in\mathcal{C}{\mathrm{val}}}S(c{i})$ 中的候选。在我们的实现中，当多个候选达到最大分数时，我们保留所有并列的最大化者：

$$\mathcal{C}{\mathrm{FMV}}=\left{c{i}\in\mathcal{C}{\mathrm{val}}:S(c{i})=\max_{c_{j}\in\mathcal{C}{\mathrm{val}}}S(c{j})\right}.$$

对于图 1 中的验证器强度比较，我们用当前验证器条件包装此仅输入 FMV 规则。给定验证器 $v$，我们首先形成验证器接纳的候选池 $\mathcal{C}{v}={c\in\mathcal{C}:v(c)=1}$。然后我们将上述 FMV 规则应用于 $\mathcal{C}{v}$，使用可用的目标问题输入用例进行功能比较。此包装器使用与评估扫描其余部分相同的验证器条件，而表 2 报告 FMV 投票规则本身所需的访问权限。选定的候选然后传递给附录 A.5 中的通用过滤评估协议；当相同的验证器已用于形成 $\mathcal{C}_{v}$ 时，此最终过程除共享的空集处理约定外是幂等的。

附录 D 合成课程质量和动态

自生成训练引入了两个具体的稳定性风险。首先，提议者可能生成无效或无信息量的合成问题。其次，求解者可能过度特化到狭窄的生成分布。本节报告了 HardLCBv6 上 TTSP 适配期间这些风险的诊断。这些诊断仅用于分析记录；它们不用作奖励、过滤器或检查点选择标准。

操作标准。 合成问题只有在通过第 4 节中的有效性过滤器后才用于求解者训练。在接受的问题中，公式 1 中的提议者奖励有利于中等求解者成功率，回放缓冲区采样最近求解者求解率位于附录 B 中资格窗口内的问题。因此相关的检查是操作性的：拒绝的生成应在求解者更新前排除，提议者奖励应保持非退化的高奖励尾部，生成的课程不应塌缩到单一策略或程序族。这些检查解决了第 6 节中指出的稳定性问题；类似的问题出现在最近的无数据和自博弈 LLM 训练方法中（Zhao 等，2025；Huang 等，2025；Chae 等，2025；Bailey 等，2026）。
