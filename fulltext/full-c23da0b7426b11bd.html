开启两项设置使ARC-AGI-3得分提升两倍

📅 2026-07-29 📄 OpenAI 🔗 原文链接

原标题：How enabling two settings tripled our scores on the ARC-AGI-3 benchmark How two API settings improved GPT-5.6 performance on ARC-AGI-3, boosting scores and efficiency by retaining reasoning and enabling compaction.

中文摘要： 本文介绍了OpenAI通过在ARC-AGI-3基准测试中开启“保留推理”和“启用压缩”两个API设置，使GPT-5.6 Sol的得分提高了两倍，同时大幅减少了输出token。研究发现，模型此前表现不佳主要由于官方测试框架丢弃了模型的私有推理并使用滚动截断导致记忆丢失。采用Responses API的设置后，模型能更好地记忆和制定策略，显著提升了性能和效率。

_GPT‑5.6 Sol 尝试在 ARC-AGI-3 基准测试中解谜的加速视频，左侧为官方测试框架，右侧为我们的 Responses API 框架，该框架保留了推理并启用了压缩。在_[_此游戏_⁠(opens in a new window)](https://arcprize.org/tasks/cd82)_的排行榜上，没有前沿模型能通过第一关之后的任何关卡。而在我们的框架中，GPT‑5.6 Sol 解开了全部六个关卡。_ GPT‑5.6 Sol 已经解决了数学界长期悬而未决的难题，如[圈双覆盖猜想⁠(opens in a new window)](https://cdn.openai.com/pdf/04d1d1e4-bc75-476a-97cf-49055cd98d31/cdc_proof.pdf)，并通关了《宝可梦 火红》等游戏。但在 ARC-AGI-3（一个 2D 益智游戏基准测试）中，GPT‑5.6 Sol 仅获得了 7.8% 的得分，而 GPT‑5.5 几乎无法玩这些游戏，得分仅为可怜的 0.4%。 难道 2D 益智游戏对我们的模型来说异常困难吗？还是另有隐情？ 基准测试很少孤立地衡量 AI 模型。它们还衡量了关于 API 设置、测试框架设计和提示词等不那么显眼的选择。在 ARC-AGI-3 的案例中，我们发现，开启我们在 ChatGPT 和 Codex 中使用的两个 API 设置——保留推理和压缩——使得分提高了两倍，并在公共任务集上将输出 token 减少了 6 倍。 _使用官方测试框架时，GPT‑5.6 Sol 在 ARC-AGI-3 公共集上的得分为 13.3%。在保留推理并启用压缩后，其得分为 38.3%。得分衡量的是相对人类动作效率（_[_RHAE_⁠(opens in a new window)](https://docs.arcprize.org/methodology)_）——这是一个将模型表现与人类基准进行比较的指标。基于_[_官方游戏日志_⁠(opens in a new window)](https://huggingface.co/datasets/magic-sword/arc_agi_3_public_demo_human_testing)_，我们估计人类测试者的平均得分为 48%。模型不会被告知如何打分，并且在整个过程中无法看到自己的得分——动作仅返回每一帧的文本表示及其所在关卡。_ ## ARC-AGI-3 ARC-AGI-3 是一个旨在衡量 AI 智能体学习和推理能力的基准测试。智能体在没有明确指令的情况下探索陌生的 2D 游戏并推断其运作方式。你可以在 [arcprize.org/tasks⁠(opens in a new window)](https://arcprize.org/tasks) 玩 25 个演示游戏。 ARC-AGI-3 使用了一个有意设计的通用测试框架，没有工具或特殊功能。ARC 的理由是，简单的框架能让模型的缺点更加明显，并使模型之间的比较更加公平。相比之下，商业开发者会针对每个模型的特点和怪癖优化测试框架。 ![Image 1: GPT-5.6 Sol in Codex completing a randomized daily challenge in Slay the Spire 2.](https://images.ctfassets.net/kftzwdyauwt9/AET0YzpXrzZVTN2i7GvZA/25cca071d556d3201a562d7a8ca2e92c/Tweet.png?w=3840&q=90&fm=webp) _Ethan Mollick_[_展示_⁠(opens in a new window)](https://x.com/emollick/status/2075950897029374334)_了 Codex 中的 GPT‑5.6 Sol 通关了《杀戮尖塔 2》的随机每日挑战，该游戏是在 GPT‑5.6 Sol 的知识截止日期之后发布的。_ 但随着我们深入研究，我们发现模型的许多困惑并非模型本身固有的，而是由于测试框架中的设置造成的。 首先，我们注意到在每次游戏动作之后，所有私有推理都会被丢弃。这意味着在每次动作时，GPT‑5.6 Sol 都被要求重新弄清楚游戏，无法记住它过去的思考。模型仍然可以看到过去移动的记录和简短的附带说明，但它无法看到导致这些动作的计划、见解或想法。 其次，我们看到该框架使用了滚动截断窗口，导致随着历史的增长，较早的动作变得不可见。因此，GPT‑5.6 Sol 不仅无法记住它过去的思考，而且也在失去对过去动作的记忆。 总之，测试框架的这两个特征——丢弃推理和滚动截断——有助于解释为什么 GPT‑5.6 Sol 难以随着时间的推移进行学习。 ## 智能体在记住自己做过的事情时表现最好 我们的模型被训练为在输出回复或工具调用之前，使用私有推理消息进行思考。这些私有的思考消息作为对话历史的一部分被保留下来。如果对话变得太长，我们会对其进行总结并继续。 这就是我们模型的训练方式，也是它们在 ChatGPT 和 Codex 中的部署方式。为了更好地匹配我们的生产环境，我们使用 [Responses API⁠(opens in a new window)](https://developers.openai.com/blog/responses-api) 实现了 ARC-AGI-3 测试框架。我们的 API 使管理上下文变得容易：对于 GPT‑5.6，传递先前的响应 ID 会自动跨工具调用和轮次保留推理。 在保留推理的情况下，我们注意到了两个重大变化。首先，GPT‑5.6 Sol 在每次动作之前花费的思考时间减少了，因为它不再需要每轮都从头解释游戏。其次，当它能够记住过去的思考时，GPT‑5.6 Sol 在随时间学习和采用连贯策略方面表现得更好。 下一个改进来自于用[压缩⁠(opens in a new window)](https://developers.openai.com/api/docs/guides/compaction)（Responses API 中的另一个设置）替换滚动截断。 ARC-AGI-3 测试框架通过滚动截断来解决上下文限制。当对话上下文超过 175,000 个字符时，最早的消息将被丢弃。 滚动截断有两个缺点。首先，模型会丢失早期的观察和动作。其次，它在大部分任务中都在较满的上下文窗口下运行，这可能会略微损害性能。 当我们在 ARC-AGI-3 上启用压缩时，GPT‑5.6 Sol 能够更好地在较长的运行中保留它对每款游戏所学到的知识，并以更少的输出 token 获得了更高的得分。 为了说明保留推理和启用压缩的效果，这里有一个动画，展示了 GPT‑5.6 Sol 的 175K 上下文窗口在使用每个测试框架解决一系列 ARC-AGI-3 谜题时的情况。 _中间两列描绘了每个测试框架对模型上下文窗口的不同使用方式。凭借对过去更好的记忆，GPT‑5.6 Sol 每次动作的思考更少，并且进行得更快。注意：我们的实现使用 175,000 个 token 而不是字符的限制，但最终结果非常相似，因为绝大多数文本是动作网格，我们的分词器以 1:1 的比例对其进行分词。_ 总之，保留推理和压缩使得 GPT‑5.6 Sol（max）以减少 6 倍的输出 token 获得了大约 3 倍的得分。 ## 结论与建议 我们希望这些实验能作为一个提醒，即评估很少孤立地衡量模型——它们还衡量了关于 API 设置、测试框架设计和提示词等一系列不那么显眼的选择。这已经不是我们第一次在公共基准测试中因低分而感到惊讶，然后发现评估运行器使用的是丢弃推理消息的通用测试框架了。 如果你是一名试图最大化性能的 API 开发者，我们建议使用我们在自己产品中部署的相同设置： * 使用我们的 Responses API，而不是我们旧版的 Chat Completions API * 保留推理 * 使用压缩 如果你在比较模型，我们建议依赖使用上述设置的评估，这些设置最符合 ChatGPT 和 Codex 中的实际使用情况。 我们感谢 ARC 多年来在 AGI 评估方面的创造性工作，并感谢他们的分析启发了我们在这里进行更深入的研究。
