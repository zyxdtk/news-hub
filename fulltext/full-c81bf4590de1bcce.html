摘要
当一个场景必须包含多个指定人物时，保持身份的图像生成变得越来越不可靠。除了保留每个身份外，模型还必须将每个参考图像绑定到特定的人物和位置，同时训练时的身份损失必须在多个含噪声的预测人脸之间建立对应关系。我们提出了 WithEveryone，这是一个用于生成多达十个参考身份的群组图像的统一框架。WithEveryone 将每个选定的身份作为寻址令牌注入，预测结构化的身份-布局规划，并将该规划渲染为视觉条件。其关键目标 Layout-Grounded ID Loss 利用标注的人脸区域直接监督目标身份，避免了不稳定的基于嵌入的人脸匹配；ID Representation Forcing 还在图像合成前为每个身份训练一个预测。在身份不相交的基准测试中，WithEveryone 实现了最高的目标-上下文身份相似度，将人脸相似度从 GPT-Image 2 的 0.462 提高到 0.499，同时将复制粘贴伪影从 0.169 降低到 0.055。它进一步覆盖了 97.3% 的请求身份，重复率仅为 2.8%。这些结果表明，显式的身份-布局定位使得保持身份的生成能够扩展到更大的群体，而无需依赖直接复制参考人脸。

引言
最近的图像生成模型，尤其是统一多模态模型（UMM），在视觉保真度、文本理解和可控性方面取得了快速进展，而保持身份的生成进一步允许用户通过一张或多张参考图像指定人物 (31; 55)。然而，现有的开放学术方法主要处理一个或少数几个人物，通常从一到五个参考身份（ID）生成 (63; 7)；即使是强大的专有系统（如 Nano Banana Pro）也最多支持七个人 (16)。真实的群组图像创建需要联合生成更多指定的人物，而不是重复生成独立的单人图像。我们研究在一张语义和视觉连贯的图像中，从五到十个参考 ID 生成群组图像。
据报道，随着参考 ID 数量的增加，身份相似度会下降 (63; 26; 71; 21)，并且模型倾向于在多人场景中复制人脸或合并 ID (2)。当更多的参考图像、视觉令牌和身份条件共享一个生成上下文时，每个身份信号更容易被稀释，跨身份干扰和错误绑定的可能性也更大。因此，提供参考图像或身份嵌入作为条件并不能保证模型在生成过程中持续读取每个身份：大群体生成需要一种机制，既能提供每个参考身份，又能约束上下文以保留其表示。
先前的工作还表明，仅靠条件是不够的，直接用身份损失监督生成的人脸对于强大的身份保留是必要的 (18; 63)。然而，这些损失是为单个人或最多两个人制定的。将它们扩展到一大群人并不是多次运行相同的损失，因为损失必须首先决定哪张生成的人脸属于哪个参考，而现有的公式通过匹配生成图像中的人脸嵌入来恢复这种对应关系。在训练初期和高噪声水平下，模型预测的人脸几乎完全相同，因此这种匹配几乎是任意的，每个错配的人脸都会将一个身份拉向另一个身份。因此，现有的身份损失无法扩展：本应锐化个体的监督反而相互抵消了。
更多的参考也使空间和身体关系复杂化。身份相似度回答了生成的是谁，但没有回答人们出现在哪里、采取什么姿势或如何组织。随着群体的增长，成对关系成倍增加，一个错位的人会通过周围的构图传播错误，使得重叠、肢体错误和拥挤的布局特别容易发生。因此，我们将这种规划负担卸载到图像生成之前的统一模型的理解侧。
为了应对这些挑战，我们提出了 WithEveryone，一个如图 1 所示的统一 UMM 框架。在身份方面，我们为每个参考人物提取一个身份嵌入，将其投影到一个 ID 令牌中，并将该令牌绑定到它应该控制的规划人物上，从而使参考形成一个寻址集，而不是一个无序池。因为 ID 令牌在长的多 ID 序列中很容易被忽略，ID Representation Forcing 将 representation forcing (56) 适应于身份，要求模型在合成之前预测与每个目标人物对齐的表示。在输出层面，我们引入了一个兼容流匹配的 Layout-Grounded ID Loss（LG-ID Loss），它消除了上述匹配问题而不是近似它：对应关系是从布局标注中读取的，因此无论图像中有多少人，每个身份都在其自己的标注区域中受到监督。
在理解侧，模型自回归地预测一个结构化的 Layout Chain of Thought（Layout CoT），包含人物索引、边界框、身份-布局绑定和姿势关键点，将 ATLAS 风格的规划 (35) 扩展到身份感知的设置中，其中每个规划的人物都与一个参考身份绑定；然后，一个确定性的渲染器将规划转换为视觉条件。ID 令牌和 Representation Forcing 决定生成谁，Layout CoT 决定每个人在哪里以及如何出现，而身份-布局绑定将两者连接在一个规划中。
我们在一个五到十人的基准测试上评估 WithEveryone，与学术、开源和专有系统进行比较，包括 GPT-Image 2、Nano Banana 系列和 Seedream 系列。WithEveryone 达到了最高的相似度，Sim(Tgt) 得分为 0.499，而 GPT-Image 2 为 0.462。它的复制粘贴伪影得分 (63) 为 0.055，而 GPT-Image 2 为 0.169，表明这种相似度与直接复制参考人脸的一致性较低。这些结果表明，在身份、复制和图像质量之间取得了比我们比较的任何单一系统更好的整体平衡。我们的贡献有三个：
•
我们提出了在单个统一模型内交错的身份和布局推理：每个选定的参考作为 ID 令牌加载，结构化的 Layout CoT 通过身份-布局绑定和人脸区域、身体范围和姿势的联合预测扩展了 ATLAS 风格的规划，确定性的渲染器将规划转换为视觉条件。ID Representation Forcing 通过在图像合成之前添加有监督的每个身份预测来适应 representation forcing，鼓励选定的身份在共享上下文中保持可寻址性。
•
我们提出了 LG-ID Loss，它将输出侧的身份监督建立在布局标注中，而不是基于嵌入的人脸匹配中。这消除了阻碍现有身份损失应用于两人以上的失败模式，并且是我们系统中身份增益的最大单一来源。
•
我们构建并系统评估了一个用于五到十人的群组图像生成系统。在身份不相交的基准测试上，它以较低的复制粘贴伪影（0.055 对 0.169）实现了比 GPT-Image 2 更高的目标-上下文身份相似度（Sim(Tgt) 0.499 对 0.462），并且我们的分析将规划预测与规划执行区分开来，作为剩余错误的不同来源。

相关工作
保持身份和身份一致的生成。
保持身份的生成已经从单人方法 (55; 31; 51; 54; 65; 61) 发展到多人定制 (71; 21; 26; 7)。然而，现有方法仍然局限于小群体，并且可能会为了复制粘贴行为而牺牲身份相似度 (6; 37; 25; 63)；WithAnyone 和 UMO 报告的例子分别最多包含四个人和三个人。输出侧的身份监督同样有限：PuLID (18) 处理一个身份，而 WithAnyone 使用基于嵌入的匈牙利匹配，最多处理两个。在训练时的噪声下，随着人脸数量的增加，这种匹配变得不可靠。我们的 LG-ID Loss 则从布局标注中获取对应关系，从而实现对五到十人的输出侧监督。
文本-图像到图像模型和统一模型。
参考条件生成现在由开源模型 (1; 57; 49; 11; 4) 和专有系统 (17; 16; 3; 39; 40) 支持。统一架构（如 HunyuanImage 3 和 BAGEL）在共享上下文中生成文本和图像，从而在合成之前进行上下文内规划 (5; 8; 72)。
布局规划和生成。
大多数基于布局的方法使用单独的规划器和图像生成器 (15; 20; 66; 70; 14; 13)，而 ATLAS 和 PlanGen 在一个上下文序列中统一了规划和合成 (35; 22)。我们将此设置从文本到图像扩展到身份条件生成：每个规划的人物都绑定到一个参考身份，并将联合预测的人脸区域、身体范围和姿势渲染为视觉条件。

方法
3.1
概览
我们考虑从文本提示和一组五到十个参考身份生成群组图像。我们的模型遵循 transfusion 风格 (72) 的混合 Transformer 多模态架构 (8; 5)，其中文本和结构化推理通过自回归预测，而目标图像潜变量通过流匹配 (33) 学习。这种共享的因果上下文使得在图像生成之前做出的高层决策能够直接条件化后续的图像令牌。
如图 3 所示，WithEveryone 在合成目标图像之前准备了三个互补的条件：它选择参与场景的参考身份并为每个身份加载一个紧凑的表示，预测结构化的多人布局以及身份与规划人物之间的关联，最后从累积的上下文中预测目标身份表示。渲染的布局条件和表示支架共同条件化基于流的图像生成。

3.2
交错的身份和布局推理
ID 绑定和 ID 令牌。
提示可能只需要可用参考人物的一个子集，也可能描述没有参考图像的人物，因此模型首先识别参与的身份。类似于 ViT (12) 和 VAE 嵌入在不同特征级别的互补作用，我们用编码身份特定信息的高级 ID 嵌入来补充低级参考图像特征：对于每个选定的人物，我们提取一个 512 维的 ArcFace (10; 9) 嵌入，用轻量级 MLP 将其映射到模型隐藏维度，并将其注入到相应的 ID 令牌位置。选择和绑定是有序的而不是相互依赖的：模型发出选定身份的列表并为每个选择加载一个 ID 令牌，而与具体人物的绑定在布局阶段（第 3.2 节）中随之而来。这种 ID-布局绑定赋予了每个加载的身份一个空间角色，而不是将参考视为一个无序的集合。
ID Representation Forcing。
加载 ID 令牌本身并不能保证图像生成会使用它们。每个人物由一个连续的令牌表示，从一个 512 维向量投影而来，位于一个 10-20K 令牌的交错序列中，因此对注入的身份令牌的生成侧注意力可能是分散的且与身份无关的。
受 representation forcing (56) 的启发，我们因此引入了 ID Representation Forcing。对于每个具有目标对应关系的选定参考身份，我们在目标图像之前放置一个表示令牌；主干网络从前面的提示、视觉参考、ID 令牌和布局推理中计算其隐藏状态 𝐡_i^rep，输出投影器 g_out 将其映射到 ArcFace 空间：

结构化 Layout CoT。
保持身份的生成还必须解决人物之间的空间和身体关系，我们将其表述为结构化的 Layout CoT。遵循 ATLAS (35)，模型自回归地预测身份-布局绑定、人物和人脸区域、身体范围和姿势关键点，使用包含 2,002 个令牌的离散化坐标词汇表，对应于每个轴上的 1,001 个位置。各个阶段以固定的因果顺序发出，因此每个决策都以已经确定的身份和区域为条件；简短的自然语言连接词在各阶段之间传递场景状态，而空间字段保持可解析并直接受到监督。然后，我们解析预测的规划并将其渲染为画布，在目标纵横比的空白图像上绘制规划的人脸区域、身体区域和姿势骨架，并将其作为条件图像插入到上下文中。

Layout-Grounded ID Loss。
对生成的人脸进行身份损失是先前工作中保持身份的有效且必要的要素 (18; 63)，但现有的两个公式都必须首先决定哪张生成的人脸属于哪个参考。PuLID 监督单个身份，从不面临这个问题；WithAnyone 通过对人脸嵌入进行匈牙利分配从生成图像中恢复对应关系，并报告最多用于两个人。这正是随着群体增长而崩溃的原因：在训练期间，单步估计是有噪声的，五到十张人脸几乎无法区分，因此分配几乎是任意的，每个错配的人脸都会将一个身份拉向另一个身份，从而抵消监督而不是锐化任何个体。
我们消除了匹配问题而不是改进匹配器，因为对应关系已经从监督 Layout CoT 的标注中得知：每个引用的身份都有一个固定的目标人脸边界框及其关键点。在这些相同的区域裁剪预测和目标图像，使得每对裁剪在构造上都是正确的，因此每个身份都独立受到监督，无论图像中有多少人共享。在标注区域裁剪预测图像假定生成的人脸落在那里，流匹配在早期就强制执行了这一点：规划遵循在身份保留之前很好地收敛（第 4.4 节）。裁剪由 ArcFace (10) 编码，并且损失仅低于时间步阈值应用，高于该阈值单步估计不包含可识别的人脸；附录 B.5 给出了阈值和程序。我们将此目标称为 Layout-Grounded ID Loss 或 LG-ID Loss。将身份监督建立在布局中而不是生成的像素中，是使得输出侧监督在五到十人中可用的原因，并且它是我们系统中身份增益的最大单一来源（第 4.3 节）。

实验
4.1
实验设置
基准测试。
现有的多身份基准测试关注少数几个人，因此无法衡量身份保留如何扩展到更大的群体。我们构建了一个包含 210 个真实群组图像示例的基准测试，涵盖五到十个参考身份，每个目标包含与参考完全相同数量的检测人脸，并且没有重复身份。该基准测试在训练中是身份不相交的：其中的每个身份都被保留，并且包含这些身份的所有训练示例都被移除，因此比较衡量的是对未见过的泛化能力，而不是图像级别的记忆。对于按群体规模的分析，它被分层为 60、50、40、30、20 和 10 个示例，分别包含五到十个参考。
比较模型。
我们与三组强大的基线进行比较。学术保持身份的方法包括 UMO (7)、WithAnyone (63)、UniPortrait (21)、DreamO (37) 和 ID-Patch (71)。开源通用模型包括 FLUX.2 Klein (30)、Qwen-Image-Edit (57)、LongCat-Image-Edit (49)、OmniGen2 (58)、SenseNova U1 (11)、BAGEL (8) 和 HiDream-O1 (4)。我们进一步评估了专有的 Nano Banana (16; 17) 和 Seedream (3) 系列以及 GPT-Image 2 (40)。
评估协议。
每个模型都在所有 210 个示例上进行评估。每个系统以其支持的最高分辨率生成。WithEveryone 在表 1 的主要比较中以 2K 分辨率生成，在所有其他报告的设置（包括所有消融）中以 1K 分辨率生成。我们向 ID-Patch 和 WithAnyone 提供真实布局，因为这些方法无法自主规划布局。
评估指标。

4.3
消融研究
我们将消融组织为来自相同基础模型的三个增量分支：布局条件（P1-P3）、ID 令牌和 Representation Forcing（P1、P4 和 P5）以及 LG-ID Loss（P1 和 P6）。P7 报告了完整配置。所有变体都在相同的配方下独立训练和评估，只是 P7 额外使用了文本到布局语料库。
Layout CoT 的效果。
表 2 的 P1-P3 行隔离了布局条件。P1 是默认模型，在相同的数据集上训练，但没有 Layout CoT 或 ID 令牌；P2 和 P3 使用 Layout CoT 训练，并分别在推理时使用模型预测的布局和真实布局。模型预测的布局将 Sim(Ref) 从 0.339 提高到 0.364，Count 从 0.771 提高到 0.828，Coverage 从 0.741 提高到 0.813，而 Sim(Tgt) 仅略有改善。真实布局进一步将 Sim(Ref) 和 Sim(Tgt) 提高到 0.412 和 0.367，并改善了所有布局度量；因为该布局是从目标图像派生的，所以 P3 是一个先验上界，而不是对可实现的规划增益的估计。这个上界确立了高质量的布局条件可以改善构图和身份保留，而两者之间的差距将规划质量确定为重要的剩余错误来源。P7 额外在附录 C.1 的文本到布局语料库上进行训练，并在两者上的得分都高于 P2，但它也添加了其余组件，因此该比较并没有隔离语料库。
ID 令牌和 Representation Forcing 的效果。
P1、P4 和 P5 行构成了 ID 令牌和 Representation Forcing 的增量分支。单独添加 ID 令牌会产生微小但一致的增益，其中最大的是 Count，从 0.771 到 0.827。在 ID 令牌之上添加 Representation Forcing 将 Sim(Ref) 从 0.351 提高到 0.364，Sim(Tgt) 从 0.313 提高到 0.328，分别增加了 +0.013 和 +0.015。在图 9 所示的示例中，每个受监督的身份预测优先关注其相应的 ID 令牌。端到端的增益是适度的，因此我们将此证据解释为与改进的身份可寻址性一致，而不是作为身份增益的巨大直接来源。
LG-ID Loss 的效果。
P1 和 P6 行显示，直接的输出侧身份监督在测试的单独添加中提供了最大的改进。仅 LG-ID Loss 就将 Sim(Ref) 从 0.339 提高到 0.506，Sim(Tgt) 从 0.304 提高到 0.435。它还改善了构图，将 Count 从 0.771 提高到 0.845，Coverage 从 0.741 提高到 0.947：因为每个身份都在其标注的区域内受到监督，所以只能通过将正确的人放在正确的位置来减少损失，因此基于布局的身份监督既携带空间信息也携带身份信息，而上面归因于布局条件的效果是一个下界。P7 将 LG-ID Loss 与 ID 令牌、Representation Forcing、Layout CoT 和额外的文本到布局语料库相结合，达到 Sim(Ref) 0.555 和 Sim(Tgt) 0.461。这个完整配置比仅 LG-ID 分支有所改进，但由于几个组件和训练语料库一起改变，我们不将差距归因于任何单独的添加。所有行都在 1K 下评估；第 4.2 节中引用的 0.614 是在主基准流程下以 2K 评估的相同模型，因此这两个值在推理分辨率和评分流程上都有所不同。

5
结论
我们提出了 WithEveryone，一个用于从五到十个参考身份生成连贯群组图像的统一多模态框架，解决了保留和区分多个身份以及组织其空间和身体关系的两个耦合挑战。它将每个参考绑定到一个 ID 令牌，并使用 ID Representation Forcing 在图像合成之前训练每个身份的预测，使用兼容流匹配的 LG-ID Loss 监督生成的人脸，该损失将身份对应关系建立在布局标注中，而不是匹配生成图像中的人脸，并通过结构化的 Layout CoT 将多人规划转移到理解侧，该 CoT 被渲染为视觉条件。
在五到十人图像的身份不相交基准测试上，WithEveryone 获得了最高的目标上下文身份相似度（Sim(Tgt) 0.499 对 GPT-Image 2 的 0.462），Copy-Paste 得分为 0.055 对 0.169，并且与我们比较的任何系统相比，覆盖了更多请求的身份，碰撞更少。在测试的单独添加中，基于布局的输出侧监督贡献了最大的身份增益，而布局分支主要改善了身份覆盖和空间控制。更一般地说，多人生成中的身份监督受益于一个明确的空间地址，该地址指定了每个身份应该出现在哪里。我们的诊断进一步表明，规划预测而不是规划执行是重要的剩余错误来源。在这个基准测试及其参考范围内，结果支持将显式身份监督与结构化关系规划相结合。附录 E 讨论了局限性、未来工作和负责任的使用。

B.2
人脸大小和扩展退化
本节扩展了第 4.4 节中总结的分析，并始终参考图 7。对于基准测试上的每个生成人脸，我们记录了其与其绑定的参考的 ArcFace 相似度，以及其框的大小，以图像边的比例和像素为单位测量。分析是按人脸进行的，下面的每个陈述都涉及条件均值。每张人脸的标准差为 0.21-0.24，并且主要由身份难度、姿势和遮挡决定，因此人脸大小仅占任何单个人脸方差的一小部分。
如图 7(a) 所示，每个基线都强烈依赖于相对人脸大小。Nano Banana 2 每相对人脸边百分比获得 0.016 ± 0.003 的相似度，Seedream 5.0 Pro 为 0.017 ± 0.003，GPT-Image 2 为 0.019 ([+0.015, +0.023])。WithEveryone 在 2K 下是平坦的，为 -0.002 ± 0.002。这很重要，因为增加群体几乎不会改变人脸有多大：从五个参考增加到十个参考仅将平均相对人脸边从 11.9% 移动到 9.4%。在图中以灰色显示的该狭窄区间内，Nano Banana 2 失去了 0.040 的相似度，Seedream 5.0 Pro 失去了 0.042，而 WithEveryone 获得了 0.006。
然后，我们在所有六个群组大小上拟合相似度与参考数量的关系，一次有协变量人脸大小，一次没有。对于 GPT-Image 2 和 Seedream 5.0 Pro，控制人脸大小消除了大部分群组大小斜率，剩下的区间包含零；因此，缩小的人脸与其退化的大部分相关。对于 WithEveryone，斜率没有移动，保持在 -0.014，区间不包含零。因此，人脸分辨率的降低并不能解释我们剩余的退化，但该分析没有区分跨身份干扰、遮挡、构图复杂性或随群组大小变化的其他因素。我们没有引用人脸大小关联的数值份额，因为该比率的区间太宽而没有信息量。
图 7(b) 以绝对像素重复了该分析。这里的系统在输出分辨率上有所不同，因此必须在像素带内而不是沿轴比较曲线。在共同的带内，WithEveryone 在 200 px 以下是最强的，并且其差距在最小的人脸上最大：在 112 到 150 px 之间，它达到 0.611，而 GPT-Image 2 为 0.561，Seedream 5.0 Pro 为 0.388，Nano Banana 2 为 0.383。GPT-Image 2 仅在 200-260 px 带内超过 WithEveryone，为 0.654 对 0.616，并且其只有 8% 的人脸落在那里。因此，我们的优势集中在小脸上。这种模式在定性上与 GPT-Image 2 较高的 Copy-Paste 一致，尽管它没有将复制确立为差异的原因。
1K 曲线是一个参考点而不是受控消融，因为它在参考图像配置以及分辨率上都与 2K 曲线不同。然而，它提供了关于分辨率的信息。在 1K 下，61% 的人脸小于 ArcFace 编码器的 112 px 输入，而在 2K 下为 3%，因此附录 B.3 中报告的高分辨率训练的大部分好处相当于将人脸移出该状态。

C.6
布局得分
布局得分衡量最终生成图像的整体有效性，作为 [0, 1] 中七个子得分的加权汇总。如果无法计算某个组件，则将其省略并重新归一化剩余权重。
计数。
设 N 为目标中的预期人数，M 为检测到的生成人脸数。我们计算
S_count = 1 - min(1, |M-N| / max(1, N)),

覆盖、唯一性和独特性。
我们构建参考和生成人脸之间的余弦相似度矩阵。最大相似度匈牙利分配决定一对一匹配，当参考的匹配相似度至少为 0.20 时，该参考被覆盖；S_cover 是被覆盖参考的比例。对于唯一性，如果多个生成的人脸与其相似度至少为 0.20，则该参考被标记为过度声明，S_uniq 是 1 减去过度声明参考率。独特性捕获了相反的碰撞：每个参考独立选择其最相似的生成人脸，S_distinct 是 1 减去其最佳人脸也被另一个身份选择的参考比例。表 1 的 Dup 列报告了这种独特性碰撞率，即 1 - S_distinct。
对匹配阈值的敏感性。
0.20 的相似度阈值在设计上是宽松的，以便只要生成的人物可以识别为预期的人物，参考就算作被覆盖。然而，覆盖率对其不敏感：对于 P7，将阈值提高到 0.25、0.30 和 0.35 会将覆盖率降低 0.010、0.017 和 0.027，将其降低到 0.15 会将覆盖率提高 0.012。只有 3.6% 的参考的匹配相似度在 [0.15, 0.30) 内，而匹配相似度的中位数为 0.554，因此很少有决策位于边界附近。
匿名泄漏和空间有效性。
不是有效匈牙利匹配的生成人脸被视为匿名。如果匿名人脸与任何参考的相似度至少为 0.25，则被计为身份泄漏；S_noleak 是 1 减去泄漏的匿名人脸率。空间有效性是根据成对重叠计算的。人脸 IoU 大于 0.30 和身体 IoU 大于 0.50 被视为严重重叠。当两种检测都可用时，S_spatial 是 1 减去人脸和身体重叠率的平均值；否则，仅使用人脸重叠率。
规划遵循。
我们将生成的人脸框与可用的布局框进行匹配，并对匹配的 IoU 求平均。当真实布局可用时，使用真实框；否则，使用从模型 CoT 规划中解析的框。这个平均 IoU 定义了 S_plan。
C.7
相对布局得分和 Plan IoU
相对布局得分 (RLS) 采用 T2i-R1 24 中的“R-spatial”，在不使用生成图像的情况下，针对真实布局评估模型文本规划的相对配置。它结合了相对计数、位置和大小，都在 [0, 1] 内，越高越好。
人物匹配。
具有相同参考身份的规划和真实人物直接匹配。其余人物由人脸中心表示，或者在人脸不可用时由身体中心表示。每个布局中的中心在匈牙利几何匹配之前由其均方根扩散居中和归一化，以防止全局平移或缩放主导对应关系。
相对计数。
人脸和身体计数使用与上述 S_count 相同的归一化基数规则，使用规划和真实计数独立评分。然后，可用的人脸和身体计数得分被平均到 S_count^rel 中。
相对位置。
对于每对匹配的人物，我们检查他们在规划和真实之间的左右和上下顺序是否一致，给出两个顺序一致性项 S_order-x 和 S_order-y。我们还使用非反射 Umeyama 相似变换将规划中心对齐到真实中心，并将归一化的残差距离转换为类似 OKS 的软对齐得分 S_align。拟合比例惩罚防止坍缩的布局仅仅因为普氏对齐可以放大它而获得高分。顺序一致性和对齐中心得分共同定义了位置项，
S_order = 0.6 S_order-x + 0.4 S_order-y,
S_pos^rel = 0.6 S_order + 0.4 S_align,
(7)

对于每个匹配的人脸或身体框，其面积除以同一布局中匹配框的平均面积。规划和真实归一化面积之间的截断绝对对数比衡量相对大小一致性。我们还比较了两种布局之间的平均绝对人脸面积，以在每个规划人物均匀太大或太小时保留惩罚。可用的人脸、身体和绝对大小得分被平均到 S_size^rel 中。
