中国实验室已成为企业可下载、定制并在自有基础设施上运行的 AI 模型的首选来源。阿里巴巴的 Qwen、DeepSeek 以及月之暗面（Moonshot AI）的 Kimi 为开源权重系统树立了竞争标杆，为开发者提供了除通过商业 API 访问的专有模型之外的替代选择。

这一转变不仅体现在基准测试上，也体现在实际采用率上。Hugging Face 2026 年 3 月的评估显示，中国模型占此前一年下载量的 41%，超过了美国模型。今年 9 月，OpenRouter 报告称，开源权重模型处理了其平台上来自美国请求的 60% 的 token 量，其中中国实验室贡献了其大部分开源模型流量。

如今，Meta 发布了 Muse Spark Open——一个拥有 8160 亿参数的模型，Meta 称其为“迄今最强大的美国开源权重模型”。该模型于 10 月 15 日官宣，为企业提供了又一个可自行运行和改造大型模型的美国开发选项——而且还是能在相对平价的消费级硬件上运行。

地理限定词对 AI 实验室之间的竞争以及有特定采购要求的买家而言都很重要。对于基于实际考量进行选择的企业团队来说，真正的考验在于任务完成能力、可靠性、许可条款和运营成本。模型的研发地本身并不能决定业务数据的处理位置：OpenRouter 已经为中国模型提供美国境内的托管服务，包括 DeepSeek V4 Pro 和 Kimi K3。

Meta 公布的结果使 Spark Open 成为一名拥有特定优势的竞争者，而非全面领先的开源权重霸主。其模型卡显示，其 Artificial Analysis Intelligence Index（智能指数）得分为 39，低于 MiMo-V2.6-Pro 独立发布的 46 分。

Meta 的表格显示，Spark Open 在 JobBench 和 MCP-Atlas 工具使用测试中领先于所列竞争对手，但在终端编码、扩展软件工程任务以及 GDPVal-AA 专业工作评估中落后于 Kimi K3 和 GLM 5.3。截至发稿时，无法核实 Artificial Analysis 对 Spark Open 的单独公开评估。

该公告并未确立成本优势：它没有公布托管 token 费率，而 Meta 的桌面配置所使用的两台 M5 Ultra Mac Studio 采用了一种尚未公开发售的内存配置。

Spark Open 的价值主张在于企业能从其特定的能力、硬件支持与商业条款组合中获得什么。仅凭“美国领先”这一点，并不能敲定这笔采购决策。

可在消费级桌面配置上运行的大型模型

根据 Spark Open 模型卡，该模型采用混合专家设计，每个 token 激活 8160 亿参数中的 420 亿。它支持最多 100 万 token 的上下文，可接受文本、图像、视频和音频输入，输出则为文本。

这一区别对潜在应用至关重要。开发者可以用该模型解读录音、检视截图，或结合书面指令分析文档。但这次发布并不意味着 Spark Open 是一款图像、音频或视频生成器。

Meta 的桌面配置由两台 M5 Ultra Mac Studio 组成，每台提供高达 512GB 的统一内存。Meta 在发布公告中将这对设备描述为可提供 1TB 内存，并表示借助 MLX 可实现本地运行。

这一桌面方案有个问题：苹果的 512GB 内存配置要到 10 月底才会上市，且价格尚未公布。按目前的价格推算，这需要数万美元的投入。苹果官网列出的配备 1TB SSD 的 256GB M5 Ultra 工作站售价为 10,799 美元；四台这样的机器可以在税前、不含配件的情况下以 43,196 美元提供相同的 1TB 总内存。这为当前组装同等内存容量的成本提供了参考，但并非 Meta 双机配置的确认价格。

模型卡列出，NVFP4 版本至少需要 700GB 加速器内存，BF16 版本则需要 2TB。生成过程中仅激活模型的较小部分，并不会让上述内存需求降低到独立运行 420 亿参数模型的水平。

Meta 描述了本地演示场景：由 Spark Open 驱动的 Muse Code 修改了 Ice Cubes Mastodon 应用，并操作 DaVinci Resolve 审看素材、准备竖屏裁剪。这些均为公司演示；公告并未提供双机配置的实测 token 生成速率或完整硬件成本。

开发者还可以使用熟悉的推理服务软件。Meta 列出了 SGLang、vLLM、TensorRT-LLM、Transformers、MLX、llama.cpp 和 Unsloth，支持范围涵盖 AMD、苹果、英特尔和英伟达硬件，并指出可借助 PyTorch 的 TorchTitan 进行进一步调优。

Meta 在模型卡中报告了 39 的 Intelligence Index 得分。截至发稿时，VentureBeat 无法核实 Artificial Analysis 对 Spark Open 的单独公开评估；因此该得分仍应视为来自 Meta 的表格。Artificial Analysis 对托管版 Spark 和 Wonder 模型的评估针对的是另外的独立发布版本。

在不使用工具的 HLE-Diamond 测试中，Spark Open 也领先于所列模型，得分为 26.1，而 Kimi K3 为 22.2，Qwen3.8 为 17.3。在使用工具的视觉评估中，它在 ZeroBench 上取得 50 分（Kimi K3 为 41 分），在 SimpleVQA 上取得 73.6 分（后者为 71.9 分）。

Meta 标题声明中的“美国”限定词很重要。其表格列出 Inkling 的 Intelligence Index 得分为 26，Nemotron 3 Ultra 为 23，均低于 Spark Open 的 39。但其他几个开源权重竞争对手的得分更高。这些结果支持这是一次具有任务特定优势的、有竞争力的美国发布；但并未确立全面的性能领先。

这一“美国”属性有助于解释《Interconnects》作者 Nathan Lambert 的热情。“我等了这么久，美国开源权重模型终于重新变得重要了，”他在 X 上写道，“还有更多工作要做！”

Artificial Analysis 的独立榜单让这一地理差异更加凸显。该评估机构列出小米 MiMo-V2.6-Pro 得分为 46，GLM-5.3 为 45，Kimi K3 为 44；GLM-5.3-Flash 为 42，而 Qwen3.8 2.4T A95B 和 Qwen3.8-Flash-Next 各得 40 分。这六个已公布的得分全部超过 Meta 报告的 Spark Open 的 39 分。

在 Meta 发布的检查点结果获得独立确认之前，这些对比仍属暂定。但它们表明，为什么“美国开发的开源权重模型中的领先”比“全球可下载模型中的领先”是一个更狭窄的主张。Spark Open 为企业团队增加了一个美国选项，而若干中国模型更高的已公布得分仍是竞争格局的一部分。

免费商业使用存在一项特定例外

《Muse 模型许可证》授予运行、修改、微调、蒸馏和再分发该软件的权利，但须遵守其条件和使用政策。

其收入条款针对以模型即服务方式提供模型的企业。当被许可方及其关联公司在任意连续 12 个月内的总收入合计超过 2000 万美元时，许可证要求其在模型服务业务中提供 Spark Open 或其衍生模型之前，先通知 Meta 并另行签订书面协议。

收入衡量范围涵盖被许可方及其关联公司，而不仅限于可归因于 Spark Open 的收入。但该条款明确豁免了内部部署、研究、模型服务之外的商业活动，以及在公司自有产品内部的使用（前提是该产品本身并非模型即服务产品）。

对于开发内部助手或将 AI 功能融入应用的企业而言，这一豁免意义重大。2000 万美元这一数字并不是免费商业部署的总体上限。

其他义务仍然适用。产品必须在允许的位置标注“Built with Muse Spark Open”（由 Muse Spark Open 构建）署名，位置可以是文档、网站或设置页面。许可证对衍生模型的定义也足够宽泛，甚至涵盖使用 Spark Open 输出改进的模型。Meta 声明其不对生成内容主张所有权。

因此，恰当的描述是：这是一次采用自定义许可证的开源权重发布。可下载获取并不意味着许可证的商业条件和使用限制随之消失。

异常详细的下载门槛，且有先例可循

Spark Open 的 Hugging Face 访问通知要求申请者提供“完整法定姓名”、“出生日期”以及“包含所有公司标识符的完整组织名称”。

通知要求避免使用缩写和特殊字符，说明所提交的表单无法编辑，并警告不遵循说明可能影响对该模型及 Hugging Face 上其他模型的访问。通知称这些信息受 Meta 隐私政策管辖。

与 Hugging Face 默认的访问门槛相比，这一要求异常详细。该平台文档描述的默认流程是：用户与模型作者共享用户名和电子邮件地址。发布者可以添加字段并自定义通知；出生日期并非从 Hugging Face 下载模型的普遍要求。

不过，这种措辞有明确的先例。Meta 的 Llama 4 Scout、Meta-SecAlign-8B 和 OMol25 的 Hugging Face 页面显示了相同的说明。

Meta 之外的一款发布——Trillion Labs 的 Tri-21B——也显示相同的通知，并援引 Trillion Labs 的隐私政策。

这些例子为已发布的请求建立了先例，但并未说明各发布者如何核实所提交的信息。对企业评估者而言，直接的区别在于“获准运行下载的权重”与“从特定存储库获取权重时被要求提供的个人信息”之间。

托管访问因提供商而异

Meta 的公告将 Baseten、Fireworks AI、Groq、Modal、Nebius、OpenRouter 和 Together AI 列为 API 访问渠道，并列出 Amazon SageMaker AI、Google Cloud Model Garden、Hugging Face 和 Microsoft Foundry Models 作为获取权重的途径。

企业应将这些列表与“每项服务均提供同等支持”区分开来。Meta 的部署文档称，Groq 访问需要组织层面的审批，并描述 GroqCloud 上的上下文限制为 131,072 token；Fireworks 则列为 1,048,576 token 上下文。因此，托管方可能会限制模型宣传中的能力上限。

Together AI 列出的 Spark Open API 定价为：每百万输入 token 1.25 美元、每百万缓存输入 token 0.15 美元、每百万输出 token 4.25 美元。这意味着，就 API 而言，它的定价处于以下水平：

Wonder 提升性能，Full 访问范围更窄

Spark Open 发布之际，Meta 的开发者产品线正迎来更广泛的扩张。

10 月 12 日，Meta 推出了 Muse Wonder 和 Muse Wonder Full，面向软件工程以及涉及法律文件、金融和健康等主题的专业任务。Meta 的研究博客描述了更强大的底层模型，以及旨在保留有用上下文、在遇到障碍时仍能持续推进工作的能力。

独立测试提供了进展的证据。Artificial Analysis 报告称，在最大推理努力下，Wonder 的 Intelligence Index v4.3 得分为 52，Full 为 56，而 Spark 1.3 在最大努力下为 48。

在其编码智能体指数上，运行于 Muse Code 中的 Full 得分为 68，与搭配 Sonnet 5.5 的 Claude Code 持平（68 分），高于所列 Opus 5.5 配置的 66 分；Wonder 得分为 63。这些是“模型+智能体”组合的结果。

该评估机构还报告了 Full 的 GDPval-AA v2.1 得分为 1,857 Elo，处于 Opus 5.5（1,866）和 Sonnet 5.5（1,838）的置信区间之内。这表明各系统在这项专业工作评估中水平接近。

访问方式和成本为这些结果加上了限定条件。Meta 的定价文档将 Wonder 定为每百万输入 token 4 美元、缓存输入 0.20 美元、输出 20 美元。Meta 的 Wonder 产品页面为两个版本均列出 100 万 token 上下文，但 Full 没有公布的 token 价格：它可通过 Muse Code 每月 50 美元的 Power Usage 或 200 美元的 Maximum Usage 订阅获得。

根据 Meta 的订阅规则，这些订阅适用于 Muse Code，而非任意 API 密钥。用量限制依然存在，单独的密钥将产生按量付费费用。

订阅还默认开启 Contributor 模式，允许 Meta 使用提交的内容进行模型训练，以换取更高的用量。用户可以关闭该设置，且无论处于哪种模式，两个 Wonder 模型均可在符合条件的套餐中使用。在团队提交专有代码或文档之前，这一设置值得留意。

性能提升也伴随着更高的实测运营成本。Artificial Analysis 估计，在测试配置下，Wonder 每个 Intelligence Index 任务的成本为 4.52 美元，而 Spark 1.3 为 1.60 美元、Gemini 4 Argon 为 1.99 美元、GPT-6.1 Sol 为 0.72 美元。这些基准成本无法预测所有生产工作负载，但它们说明了为什么仅凭 token 价格无法决定模型对比。

Glimmer 与 Spark 标志着同一扩张的不同阶段

Meta 于 4 月 8 日推出了最初的 Muse Spark，称其为重组后的超级智能实验室组织产出的首个模型。初期访问通过 Meta AI 的网站和应用进行，API 预览仅限部分选定用户。

那次发布强调多模态推理和工具使用。Meta 也承认在编码和需要持续执行的任务方面仍存在差距——这些领域在其后续发布中得到重点体现。

后来的托管版 Spark 模型仍比 Wonder 便宜。Meta 的现行费率将 Spark 1.1、1.2 和 1.3 列为标准模式下每百万输入 token 1.25 美元、输出 4.25 美元。1.2 和 1.3 的 Contributor 版本分别为 0.10 美元和 0.20 美元，条件是允许使用客户内容进行训练。这些费率针对的是托管版 Spark，而非 Spark Open。

8 月 10 日发布的 Muse Glimmer 满足的是另一种部署需求。它是一个基于 Apache 2.0 许可证的 300 亿参数模型，专为能够使用工具、解读图像并从失败步骤中恢复的本地智能体而设计。

Meta 表示，其压缩后的语言模型权重占用空间不到 20GB，使整套设置可在 24GB 或 32GB 内存配置中运行。这比 Spark Open 的硬件要求小得多。托管使用方面，Together AI 将 Glimmer 列为每百万输入 token 0.35 美元、输出 1.50 美元。

Llama 先例与更加多元的商业策略

Meta 的可下载模型历史早于 Muse。该公司于 2023 年 2 月发布了最初的 LLaMA，参数规模最高达 650 亿，最初采用面向研究的非商业许可证。

Llama 2 于 2023 年 7 月接踵而至，将可用性扩展至商业应用。2024 年 7 月，Meta 发布了 Llama 3.1 的 4050 亿参数模型及更小的版本。

2025 年 4 月的 Llama 4 发布带来了可下载的 Scout 和 Maverick 模型，将原生多模态处理与混合专家设计相结合。这些架构思路也体现在 Spark Open 中。

综合来看，Meta 2026 年的一系列发布显示出更加细分的商业策略：Glimmer 以 Apache 2.0 提供相对紧凑的下载；Spark Open 提供体量大得多的下载，但附带自定义商业条件；托管版 Spark 提供更低的 token 价格；而 Wonder 和 Full 则通过 API 和订阅瞄准要求更高的工作。

对企业买家而言，实际选择如今涵盖能力、部署控制权、许可、数据使用和运营成本。Spark Open 为准备运行或定制自有基础设施的团队增加了一个重要的新选项。这一选项是否划算，取决于它在实际任务上的表现——以及完成这些任务的成本。
