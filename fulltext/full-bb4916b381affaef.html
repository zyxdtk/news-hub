摘要
大型语言模型能够为孤立问题编写正确的代码，但在自主机器学习开发方面仍然较弱。在自主开发中，智能体必须根据数小时的反馈修改数据流水线、模型和验证过程，且在大多数竞赛中，其最终成绩仍低于人类强劲选手。基于结果的基准测试记录了这一差距，但未记录其原因，因为它们仅对最终提交进行评分，而丢弃了其背后的开发过程。我们引入了 TraceML，它在一个版本级模式下将人类和智能体在相同竞赛中的工作配对：包含来自 134 项竞赛的 4,465 条人类 Kaggle 轨迹，其中 7 项竞赛也由两种智能体框架完成，产生了 430 条配对的人类轨迹和 207 条智能体轨迹。每个代码版本都带有其分数、时间戳，以及针对所采取的动作、意图、编辑大小和分数影响的标签。通过这种方式阅读，差距变得具体。专家会交替进行数据处理、验证、模型更改和集成，并重新审视他们曾搁置的方法。然而，每个智能体框架都陷入了狭窄的循环：Codex 将其步骤花在重新加权集成和调整提交上，MLEvolve 则在原地修改其模型，两者既未以人类的频率进行方向转换，也未重新开启被放弃的工作。从人类实践中提炼的简短规划提示词，将其中指明的行为推向人类模式并提高了分数，但其努力特征仍保持智能体形态：指令仅弥合了可还原为指令的那部分差距。我们在 https://huggingface.co/datasets/jerryyan/TraceML 发布了语料库、模式、标注器和提取流水线。

1 引言
大型语言模型（LLM）能够为定义明确、孤立的任务编写正确的代码。自主机器学习开发的要求更高：智能体必须加载和清洗数据、选择和训练模型、读取验证信号，并在数小时内修改其方法，且每个决策都以前一个决策为条件（Jiang et al., 2025; Guo et al., 2024; Li et al., 2024）。在通过可执行提交进行评分的 Kaggle 风格任务中，智能体在一次运行中能取得稳步进展，但在大多数问题上仍低于人类强劲选手，且从额外工作时间中获得的收益不如人类（Chan et al., 2024; Wijk et al., 2025）。

基于结果的基准测试记录了这一差距，但并未解释它（Jing et al., 2025; Huang et al., 2024）。它们对最终提交进行评分，却未看到其背后的编辑序列，因此即使一次运行经过精心实验而另一次盲目调参，只要分数相同，看起来就一模一样。智能体的工作流与专家的分道扬镳之处，是一个关于过程的问题。

要回答这个问题，需要以一种在人类和智能体解决同一问题时可比较的形式提供过程级数据。TraceML 将每次运行表示为代码版本的有序序列，每个版本都有其排行榜分数、时间戳以及代码内容的标签；版本之间的每次转换都包含所采取的动作、意图、编辑大小及其对分数的影响。相同的模式涵盖了人类 Kaggle 提交和智能体运行，因此可以并排阅读解决同一竞赛的人类和智能体。TraceML 包含来自 134 项 Kaggle 竞赛的 4,465 条人类轨迹；其中，一个匹配的 7 项竞赛子集由人类和两种智能体框架（Codex 和 MLEvolve）共同完成。

这些轨迹显示出一致的差异（图 1）。人类在探索、诊断、验证、模型更改和集成之间交替；Codex 将其大部分步骤花在面向提交的簿记上，而 MLEvolve 则花在局部模型和训练变异上。与人类相比，两种框架在探索每个新领域时都消耗了更多的预算。基于这些观察构建的规划框架缩小了一些行为差异，并提高了部分竞赛的分数；但智能体的努力特征仍保持智能体形态。

我们的贡献是：（1）数据集：TraceML，一个版本级轨迹数据集，与提取和标注代码、标注器检查点及干预框架一同发布。（2）模式：用于 Kaggle 笔记本、命令行界面（CLI）提交和树搜索日志的统一提取和标注模式。（3）分析：关于人类与智能体在探索、验证、模型切换、集成和重复局部优化方面差距的过程级证据。（4）用例：基于这些诊断构建的规划框架，它缩小了部分行为差距，并有利于智能体在某些竞赛中的性能。

2 相关工作
2.1 LLM 智能体与 ML 智能体基准测试
将推理、工具使用和环境反馈交替进行的 LLM 智能体（Yao et al., 2023b; Shen et al., 2023）已被应用于机器学习开发，其中智能体检查数据、编写代码、运行实验并改进其自身结果（Jiang et al., 2025; Guo et al., 2024; Li et al., 2024; Grosnit et al., 2024）。我们研究的两种框架在搜索方式上有所不同。Codex 是 OpenAI Codex 命令行智能体（codex-cli 0.146.0）：

2.2 行为诊断与人机轨迹
许多智能体框架旨在使多步行为更加深思熟虑，其中包括 Tree of Thoughts（Yao et al., 2023a）和 Reflexion（Shinn et al., 2023）。对这些机制的评估主要询问智能体是否能在抽象层面、在经典规划领域而非 ML 开发中产生有效的计划（Valmeekam et al., 2023; Wang et al., 2026），从而留下了这种行为在数小时的真实 ML 开发中如何发挥的疑问。人类比较提供了一个参考点：RE-Bench 表明，有时间预算的人类基线揭示了最终分数隐藏的缩放模式（Wijk et al., 2025），而 HCAST 将自主性评估建立在人类校准的任务尝试之上（Rein et al., 2025）。两者都没有为 Kaggle 风格的 ML 工程提供任务对齐的人机轨迹，也没有提供中间决策的共享版本级表示。TraceML 提供了这两者，表 1 将其与相关基准测试进行了对比。

3.2 智能体轨迹收集
TraceML 将人类语料库与其中 7 项竞赛的智能体轨迹配对：11 次 Codex 基线运行，7 次带有 §5 规划提示词的 Codex 运行，以及 13 次 MLEvolve 搜索，这些搜索被线性化为根到叶的分支（表 2）。这 7 项竞赛定义了配对子集，其中 430 条涵盖所有作者等级的人类轨迹在 12 小时的智能体预算下与智能体运行相遇；§4 和 §5.1 中的每一项人机比较都在此计算。

两种框架留下了不同的痕迹。我们通过 Codex 在其单个工作目录上的辅助 Git 提交来跟踪它。MLEvolve 编写搜索日志，为每个版本分配一个父级，并将跨分支重用保留为单独的引用边，因此我们将每条根到叶的路径视为一条轨迹，并将节点的分数传递到通过它的每个分支。我们使用留出的 MLE-bench 评估器对每个智能体版本进行重新评分，而不仅仅是最终提交。然后，我们丢弃具有泄漏特征、截止日期后数据或比竞赛更新的预训练工件的运行。这些阶段作为一个命令行工具运行，目前已应用于五个框架（附录 B.5）。

3.3 对齐人类和智能体轨迹
比较这两个来源要求人类版本和智能体版本表示相同类型的事件。
单位：人类版本是 Kaggle 保存版本，是故意保存而非自动保存；其智能体类似物是产生提交的提交或搜索节点，相邻的相同状态被折叠。
测量：双方均按竞赛自身的指标评分。由于该指标因竞赛而异，因此将行为与结果相关联的分析使用竞赛内百分位数。
可观察性：公开历史记录的是保存的版本，而非所有工作，因此双方到达我们这里时的过滤方式不同。两项检查限制了其影响：将人类限制为带分数的、已提交的版本（与智能体版本相同的事件类型），并将人类保留过滤器应用于智能体运行。每一个主要差距都在两者中存活下来（附录 B.3）。平台外工作逃脱了任何检查，因此我们将人类语料库作为公开实践的参考分布。

3.4 过程级标注模式
仅靠排序并不能使代码可分析。该模式沿两个轴提供该层：版本包含的内容和编辑的作用。两个词汇表都与竞赛无关，因此该模式适用于相同格式的任何轨迹，包括此处未研究的框架。
版本状态将每个版本分配给 8 个粗略 ML 流水线阶段中的一个或多个（例如特征工程和集成），其下有一个 136 标签的精细词汇表。附录 C 展示了真实转换上的完整模式输出（图 6）。
转换带有大部分行为信号。每个转换都是从一个版本到下一个版本的更改。所有四个标签均从差异、其周围代码和评分器中分配：
• 动作：编辑执行的操作，作为精细词汇表上的多标签集合。
• 意图：其服务的目的，从动作和周围代码中读取。
• 幅度：它重写了多少工作代码。
• 分数影响：相关指标是改善、停滞还是倒退。

3.5 标注可靠性与数据集发布
手工标注 151,088 个版本是不可行的，因此我们将该模式提炼为开放权重的标注器：一个教师模型在精选轨迹上发出受模式约束的标签，这些标签训练两个 Qwen3-1.7B（Yang et al., 2025）学生模型，一个用于版本状态，一个用于转换动作。我们通过三种方式检查学生模型：模式合规性、与独立标注者的一致性，以及它们重现预期结构的行为检查（表 9）。一致性在意图上最低，在更粗略的三类折叠下成立，该折叠使所有发现保持不变，并且在智能体转换上不低于人类转换。我们还手工审计了按人类、Codex 和 MLEvolve 步骤分层抽样的样本，结果相同（附录 C.1）。

许可和隐私。我们仅重新分发具有宽松许可的内核的人类笔记本源代码，并针对 Meta Kaggle 代码镜像逐个内核进行验证，并在发布中逐个内核记录。注释、模式和代码在 CC BY 4.0 下发布；标注器权重从其 Qwen3 基础继承 Apache 2.0；Kaggle 竞赛数据本身不被重新分发。我们保留作者用户名和等级，因为它们是公开的 Meta Kaggle 元数据，且等级是表 2 的群体变量。笔记本执行输出在提取时被剥离，因此偶然捕获的个人数据不会进入语料库。

4 实证发现
我们在 §3 的表示下，在 §3.2 的配对子集上，并在相同的 12 小时智能体预算下，将 Codex 和 MLEvolve 与人类排行榜百分位数群体进行比较，人类轨迹通过排行榜排名分为顶级群体和其他群体。人类没有预算匹配，也不可能匹配，因此我们将他们作为参考分布而非对照组阅读。所有区间均按运行聚类，附录 B.4 给出了各群体的计数。

4.1 动作特征：粗粒度模糊，细粒度清晰
我们首先询问人类和智能体轨迹是否占据粗略动作空间的不同区域。每条轨迹变成一个点，即其转换在粗略动作类别上的分布。我们用 PCA 投影这些点，并将两个群体之间的距离测量为其汇总动作分布之间的 Jensen-Shannon 散度（JSD）（图 3）。分离是部分的。四个人类群体在一个区域重叠，而 MLEvolve-best 明显分开，距离每个人类群体 0.09–0.12 比特，Codex 与顶级人类的距离大约与人类群体彼此之间的距离一样近。粗略动作混合干净地分离了一个框架，而使另一个与强劲的人类无法区分。人类块也不是一个点，因此任何差距都必须在广泛的人类变异下阅读。

细粒度的动作使用分离了粗略混合未分离的内容（图 3；标签在附录 E 中）。人类将编辑分散在词汇表中，交替进行数据和特征工作、验证、模型和检查点更改以及集成，没有单个标签主导一次运行。每个框架反而陷入一个频段。Codex 围绕提交工作，以人类速率数倍的频率重新加权集成、堆叠模型、添加成员和微调后处理，所有这些都是完善手中已有解决方案的局部编辑。MLEvolve 在原地修改模型，平均种子、编辑层和更改周期计数以扩展其已有内容的邻近变体。两个框架都没有做的是更改或检查方向：交换检查点、交换预训练源和重新运行未更改的代码以验证结果，这些都比人类速率低一个数量级。

4.2 智能体方向转换过少或过多
动作混合说明了每个群体做什么；更尖锐的问题是运行何时改变方向。我们在动作层面定义“方向转换”：更改主干、表示、目标或验证方案的编辑（附录 E）。
Codex 和 MLEvolve 从相反的方向错过了人类速率。人类在 25% 的转换中进行方向转换，Codex 为 9%，MLEvolve 为 58%，并且在保持代码状态固定的情况下，对比依然存在：与处于相同状态的人类版本匹配时，Codex 的方向转换仍然以一比三落后。
频繁的方向转换并不意味着是好的转换。将方向转换后的三个步骤中的每一个编码为改善（+1）或倒退（-1），匹配的人类平均为 +0.089，而 MLEvolve 为 -0.008：其收益和损失相互抵消。Codex 很少转向；MLEvolve 转向但没有收益。

4.3 智能体恢复了分数但未恢复被放弃的方法
人类会回到早期的工作；智能体实际上从未这样做。当一个版本与其自身轨迹中较早的、非相邻的版本的相似度超过与其前一个版本的相似度，且在此期间达到了某些不相似的内容时，该版本即“返回”，因此停滞不符合条件。顶级人类在 9% 的合格版本上返回，且这些返回中有 78% 最终高于其返回到的版本。在所有运行中，Codex 返回一次，MLEvolve 从未返回，而人类速率预测有几十次；在这种规模下的单次返回是偶然相似，而非一种实践。
智能体缺乏的是记忆，而不是恢复。Codex 从挫折中爬升的速率高于顶级人类群体，因此失去进展的运行确实会重新获得它；它从未做过的是重新开启它曾放弃的工作线。通过向前调优来恢复分数和返回到早期方法是不同的能力，智能体拥有前者而没有后者（附录 D.3）。连同方向转换的结果，这描述了一种没有记忆的搜索：从给定状态出发，智能体不转向，也不回头。

4.4 智能体仅名义上集成
前几小节描述了机制；本小节询问哪些行为与最终排名一起变动。仅对人类将所有 19 个轨迹特征与最终排行榜排名相关联，突出的是运行如何集成以及其编辑有多大（附录 E.1；是关联，而非原因）。
集成将共享名称的工作分开。三个群体都进行集成，但 Codex 78% 的集成编辑是重新加权它从未增长的成员集，MLEvolve 主要是平均种子，而顶级人类将最大份额放在添加新成员上。在一次运行中，添加或更改成员的集成步骤将下一个人类版本改善的几率提高了 6.4 个百分点，而仅重新加权的步骤则降低了 5.8 个百分点，对于 Codex，两者都没有影响：一个仅询问智能体是否集成的检查表会将 Codex 排在顶级人类群体之上，而其集成工作却毫无作用。
编辑大小从另一面讲述了相同的故事。人类跨越幅度范围，而每个框架在一个频段内工作：Codex 编辑小并以步骤付出代价，MLEvolve 编辑大并以浪费付出代价（§4.2）。这两种实践都可以按名称要求，这正是使 §5 的干预成为测试而非猜测的原因。

5 从人机差距到规划框架
§4 将人机差距定位到具名行为中。我们现在询问在提示词中命名它们是否会改变它们。干预是一个探针：提示词转移的是可还原为指令的那部分差距，而抵抗的部分标志着它未触及的部分。

5.1 框架实验
提示词设计。该技能是一个大约一千个 token 的紧凑提示词块，结合了四种机制。
反循环约束禁止维持单循环的动作：单一留出验证、重复的超参数或后处理微调，以及在存在工作基线之前的大型首版本重写。
人类先验实践要求尽早提供可重用结构：从第一个版本开始进行 K 折、早期集成、缓存折外预测以及多种子或多模型混合。
定期自检每 30 到 60 分钟验证一次验证是否仍然跟踪排行榜，以及运行是否未陷入单一任务类别。
特定任务先验使模板适应模态。完整提示词在附录 F.2 中。
实验设置。我们提出两个问题：技能是否将行为推向人类模式，以及这种移动是否达到分数。行为在 §4 的轨迹特征上读取；性能是最佳的有效留出分数，置于人类百分位数带之上，以便一个数字在不同的评分规则之间具有可比性。该研究涵盖所有 7 项配对竞赛，预算同为 12 小时。我们固定后端、工具、提取流水线和评分器，仅改变提示词：基线臂保留标准任务提示词，与 §4 与人类轨迹配对的运行相同，而框架臂在运行开始时添加规划技能，并每 30 分钟重新注入一次。另外两个臂隔离了技能的贡献：一个提供单个内容块而不是完整技能，另一个保持重新注入节奏但移除规划内容。重复的相同条件运行将噪声限制在每项竞赛指标的大约 0.01（附录 F.1）。

5.2 结果
三种行为移向人类值（图 4）。智能体停止在应该添加成员的地方重新加权集成，将注意力转移到集成上，并开始进行它之前几乎完全 skipped 的小型早期编辑。修正并非微不足道：重新加权下降约五倍，小型早期编辑从接近零上升到高于顶级人类速率。这三者的共同点是移动的空间。
提示词未命中的地方，它以两种方式未命中。它超出了它禁止的内容：普通留出降至零，远低于顶级人类仍使用它的四分之一状态，因为禁令给出了方向但没有给出目的地。而且它在规定的内容上饱和：Codex 在被要求之前已经以等于或高于人类的速率运行 K 折平均并持久化折外预测，因此要求更多两者都不会移动任何东西。
分数提高，而内容正是起作用的原因。七项竞赛中有五项改善，两项在噪声范围内，没有倒退（附录 F.1）。在保持注入计划的同时移除规划内容，在所有地方都达到或低于基线，因此收益来自技能所说的内容，而不是它重复的频率。
当指令命名了智能体尚未达到的水平时，实践就会转移。当指令是一个没有目的地的方向（这就是禁令）时，或者当智能体已经站在人类值之外时，它就不会转移。因此，提示词作为修复不如作为探针有用：它标记了指令能触及和不能触及之间的边界，而越过边界的是改变智能体本身。

6 讨论与未来工作
将开发视为一个过程，将“智能体分数较低”转化为智能体未做的具体事情，其中两件看起来像是设计问题而不是模型问题。第一是记忆。智能体从不回到它们搁置的工作（§4.3），而回去的决定并不是它们所缺少的：Codex 从挫折中恢复得和顶级人类一样好，并在它确实改变方向的罕见情况下获得人类所获得的收益。它缺乏的是以其可搜索的形式存在的自身历史，这使得对运行早期状态的检索成为一件可构建的具体事物。第二是控制。两个框架从相反的方向错过了人类方向转换速率，且只有人类的方向转换有回报（§4.2），然而每个框架都始终遵循一个策略，因此想要的是一个读取运行所处位置的控制器，而不是更强的基模型。任何一个想法现在都很便宜测试。最终分数无法区分这些情况，实践是否发生的检查表也无法区分，因为三个群体都进行集成，只有人类的集成改变了任何东西（§4.4）。发布的流水线在几分钟内将任何命令行智能体的运行转化为 TraceML 轨迹和针对人类群体的报告，我们已将其应用于五个框架（附录 B.5）。人类语料库是固定的，而智能体不断变化，因此它可以作为新系统出现时被阅读的参考，而不是随它们老化的基准。

7 结论
TraceML 在一个版本级模式下将人类和智能体在相同竞赛上的 ML 开发配对，因此可以通过提交背后的工作而不是仅通过提交来比较两次运行。配对数据显示智能体和专家的开发方式不同，且不是一个干净的差距。两个框架从相反的方向错过了人类模式，一个在不改变方向的情况下进行调优，另一个在不巩固的情况下改变方向。基于这些诊断构建的规划提示词转移了可还原为是或否检查的行为，并留下了其余部分，这就是指令停止和智能体设计开始的地方。我们发布了语料库、模式、标注器和提取流水线，以便新智能体出现时可以与人类实践进行对比阅读。

D.3 回到早期工作
§4.3 报告智能体不回头，§6 将此视为数据命名的最清晰机制。表 14 给出了这些陈述背后的两个测量值，由发布的 solution_revisit.py 和 setback_recovery.py 在附录 B.4 的 12 小时范围上计算。一旦轨迹至少有四个版本且它不在前两个之列，该版本就符合条件。
这两行测量不同的事物。解决方案重访询问运行是否回到早期方法：当一个版本的状态签名与其较早的非相邻版本的相似度超过与其自身前一个版本的相似度，且运行在此期间达到了某些不相似的内容时，该版本符合条件，因此停滞不算。挫折恢复仅询问一个跌至自身最佳分数以下的运行是否爬升回来，这可以通过纯粹的局部编辑实现，而无需返回到早期工作。智能体以等于或高于人类的速率恢复分数（Codex 恢复了 89% 的挫折），而几乎从不重访解决方案。

F.2.2 规划技能块（仅框架）

ML 策略

时间预算：你有 {{HOURS}} 小时。节奏：前约 25% 基线 + K 折 + 第一次集成；接下来约 50% 迭代 + 混合 + OOF 堆叠；最后约 25% 定稿。如果调试依赖项超过 30 分钟，放弃该路径。

第 1 部分 -- 避免这些模式

  • 不要使用 ‘train_test_split‘ / 单一留出。从版本 1 开始使用 K 折。
  • 不要锁定在单动作循环中（例如，5 个连续的“微调超参数”步骤）。循环通过验证 -> 特征 -> 模型 -> 集成 -> 重新验证。
  • 不要以主要重写作为 v1 开始。从小型工作基线开始并迭代。
  • 不要在跨多次迭代的环境/依赖调试上浪费轮次。将它们批处理为一个集中的 20-30 分钟会话，然后继续。
  • 不要停留在后处理微调循环中（重复的舍入/裁剪/校准）。设置一次后处理并继续。

第 2 部分 -- 核心实践

  • K 折 CV，跨折平均预测。
  • 在时间预算的前约 25% 内进行第一次集成调用——而不是在最后。
  • 生成折外（OOF）预测，并通过元学习器（Ridge / LGBM-on-OOF）或加权混合将它们堆叠。
  • 混合来自多个模型或种子的预测。
  • 当排行榜指标相对于默认训练损失是分层、加权或不平衡时，调整 ‘sample_weight=‘ / 损失。
  • 不断增加集成成员；不要停在一个模型上。
  • 将 OOF 数组 + 训练的模型工件缓存到磁盘，以便可以重访任何基础模型而无需重新训练。
  • 使用多个模型家族（例如，transformer + 表格提升器 + Ridge 头），而不是单一架构。

第 3 部分 -- 润色

  • 早期进行许多小/微观幅度的更改；避免在前 20% 进行大扫描。
  • 实现镜像排行榜的自定义验证指标。
  • 当默认值与指标不对齐时，使用自定义损失/目标。
  • 对每个基础模型跨多个种子平均。

第 4 部分 -- 任务类型条件

  • 文本 / NLP：多个预训练 transformer 主干（DeBERTa、RoBERTa、Electra...）；混合预测；每个主干多种子平均。
  • 表格：迭代派生特征——groupby 聚合、比率、事件后时间窗口、分类的目标均值编码。在微调超参数之前，每次迭代添加 2-3 个新的工程特征。
  • 图像 / CV：测试时增强（测试输入的翻转/旋转/裁剪版本，平均）；重度训练时增强（随机裁剪、颜色抖动、mixup）。
  • 时间序列 / 信号：高效 I/O（parquet、polars）；基于窗口的聚合特征。

第 5 部分 -- 每 30-60 分钟自检

  1. 我的验证策略是 K 折，而不是单一 train_test_split 吗？
  2. 我的 CV 指标是否与排行榜指标完全匹配？

  4. 我是否已经进行了第一次集成调用？如果超过预算的 25%，现在就做。
  5. 我是否已将每个基础模型的 OOF 预测保存到磁盘？
  6. 我是否混合了至少 2 个模型或 2 个种子？
  7. 我是否在同一任务类别上卡住了 3 个以上连续步骤？
