GLM-5.4：28层循环两次，媲美四倍规模模型

📅 2026-11-24 📄 VentureBeat AI 🔗 原文链接

原标题：Z.ai's GLM-5.4 aims to match models up to four times its size by running 28 layers twice

中文摘要： Z.ai 发布旗舰模型 GLM-5.4，首次采用循环 Transformer 架构，将 GLM-5 基座 28 层循环执行两次，不增加参数即提升计算深度，号称媲美 2T-3T 参数模型。模型新增视觉能力，主打“广义编码”，并以门控渐进更新、混合 KV 缓存等三项改进控制部署成本。其主要受控证据来自 30B 测试模型。社区肯定其代码审查与安全测试能力，但批评速度偏慢、与 Opus 5.5 差距明显。模型已上线，API 与开放权重稍后推出。

GLM-5.4 是 Z.ai 首款基于循环 Transformer（Loop Transformer）架构打造的旗舰模型。该架构通过多次复用相同的层而非堆叠新层，使模型在不增加参数的情况下获得更大的深度和每个 token 更多的计算量。Thinking Machines Lab 上周发布的 Inkling 2 Mini 模型中也使用了循环 Transformer。

GLM-5.4 模型还新增了视觉能力，并瞄准 Z.ai 所称的“广义编码”（Generalized Coding）——将代码应用于机械设计和 3D 建模等工程与设计工作，而不仅限于软件。GLM-5.4 是继 GLM-5.3 之后的又一模型，后者于今年 8 月发布，具备高级网络安全能力。

GLM-5.4 现已通过 Z.ai 的 GLM Coding Plan、ZCode 和 Z.ai Chat 提供使用。API 访问被列为“即将推出”，Z.ai 表示开放权重将在完成安全加固后跟进，但未给出具体日期。

Z.ai 发布了一张将 GLM-5.4 与其他三个模型进行对比的胜率图，但未说明评估方法。其主要受控基准证据来自使用 30B 模型的单独测试，且 Z.ai 承认 GLM-5.4 可能陷入过长的推理循环。

GLM-5.4 的工作原理：28 层运行两次，而非增加参数

Z.ai 将大规模软件工程、网络安全、3D 建模和物理控制描述为超长链推理任务，这类任务要求在保持全局逻辑一致性的同时遵循多步因果链。

Z.ai 表示：“堆叠参数和记忆数据无法解决这些问题。”

传统 Transformer 在每次前向传播中只处理每层一次。而 GLM-5.4 会将中间表示两次送入同一组层，在不增加参数的情况下提升计算深度。

研究人员早在 2018 年的 Universal Transformer 中就探索过层复用，不过后续的大部分工作都集中在较小的模型上。

GLM-5.4 在 750B 规模上对 GLM-5 基座的 28 层进行两次迭代循环，并通过继续训练从已有的预训练模型改造而来。

图片来源：Z.ai

循环本身也有代价，因此 Z.ai 做出了三项架构调整，以在性能与部署成本之间取得平衡。

门控渐进更新。 反复更新模型的内部表示可能导致不稳定。Z.ai 表示，GLM-5.4 使用逐 token 门控来控制每次迭代对表示的改变幅度。

Z.ai 报告称，训练后第一遍会构建全局上下文并进行保守写入；第二遍则打开门控进行完整更新。门控还会根据 token 难度调整步长，因此更难的 token 在第一遍会获得更激进的写入。

混合 KV 缓存。 GLM-5.4 不为每次迭代维护完整的 KV 缓存，而是复用第一遍的稀疏 KV 缓存，并将第二遍的额外存储限制在一个滑动窗口内。

稀疏注意力索引复用。 第二个循环复用第一个循环索引器生成的注意力索引，从而避免了第二次索引过程。Z.ai 的实验表明，这与每次重新计算索引的性能几乎相同。

早期测试显示 30B 模型有所提升，但 GLM-5.4 的性能仍存疑问

Z.ai 称 GLM-5.4 达到了与 2T-3T 参数模型相当的智能水平，但未解释这一结论是如何得出的。

其主要受控证据来自一个 30B 测试模型，其中循环版本比同规模的非循环基线多使用了约 10% 的训练算力。Z.ai 报告称，模型在数学、科学推理和长上下文任务上的提升最大，同时平均输出更短，在 MMLU-Pro 上约为 15%，GPQA-Diamond 上约为 12%。这些结果是在较小的测试模型上测得的，而非 GLM-5.4 本身。

图片来源：Z.ai

社区反响：测试者称赞其查错和安全能力，但指出速度问题及与 Opus 5.5 的差距

在发布最初几小时试用 GLM-5.4 的开发者报告称，其在代码审查和安全测试方面表现出色，但也对速度以及竞争对手的领先地位提出了批评。

AICodeKing 在 X 上的一篇帖子中，将 GLM-5.4 在其 KingBench 4 编码基准上排在第七位。在最大推理力度下，GLM-5.4 完成测试耗时 431 分钟，而 Google 的 Gemini 4 Neon 仅需 109 分钟；它需要 1,128 步，Neon 为 244 步。

AICodeKing 写道：“我不建议你直接使用这个模型，但把它留作工作审查员，让它处理更复杂的架构或搜索 bug 和安全漏洞，在我看来真的很值得。”

据 Migel Tissera 在 X 上的帖子，他将 GLM-5.4 作为黑盒攻击者对一个私人实验室环境进行了测试，并表示它成功完成了一条多步骤远程代码执行链。

并非每位测试者都被说服。

Loktar 在 X 上写道：“抱歉，GLM 5.4 远不及 Opus 5.5，目前没有任何开放模型能做到。”

Darek Gusto 对内置视觉功能和额外配额表示欢迎，但指出了缺失的编码基准分数。Gusto 在 X 上的帖子中写道：“GLM 5.4 发布后，我也想让我的下巴惊掉，某种程度上确实如此……当我意识到就连博客里都没有编码基准分数的时候。”

Reddit r/LocalLLaMA 上的一位发帖人对该模型在编码之外的任何用例都提出了尤为尖锐的批评。该发帖人还抱怨说，模型把思维链的一半 token 浪费在推理“某件事是否可行”上。

定价、Coding Plan 与可用性

GLM-5.4 现已通过 GLM Coding Plan、ZCode 和 Z.ai Chat 提供使用。对于使用每周配额计划的用户，Z.ai 表示 GLM-5.4 的配额是 GLM-5.3 的 1.5 倍。

根据 Z.ai 的开发者文档，GLM-5.4 接受文本、图像、视频和文件输入并返回文本，拥有 100 万 token 的上下文窗口和最大 128K token 的输出。其前身 GLM-5.3 仅接受文本。发布文章中没有给出视觉基准分数。

通用 API 定价尚未公布。

Z.ai 表示，API 访问将在完成安全评估后很快推出。

作为参考，Z.ai 文档中列出的 GLM-5.3 定价为每百万输入 token 1.40 美元、缓存输入 26 美分、每百万输出 token 4.40 美元。GLM-5.4 未出现在该页面上。

Z.ai 尚未给出开放权重的日期，也未说明将采用哪种许可证。

该公司表示：“我们计划在完成必要的安全加固后，负责任地开源模型权重。”
