推出 Claude Opus 4.7 模型

📅 2026-04-16 📄 Anthropic 🔗 原文链接

原标题：Introducing Claude Opus 4.7

中文摘要： Anthropic 推出最新模型 Claude Opus 4.7，其在高级软件工程、多模态理解、指令遵循和长期任务处理方面显著优于 Opus 4.6。模型支持更高分辨率图像（最高 2576 像素），在金融、法律、代码审查、多步骤工作流等领域表现卓越。Opus 4.7 具备更强的自主性、可靠性和安全性，同时引入“xhigh”努力级别和任务预算等新功能。该模型已通过多项基准测试，广泛应用于企业级开发与安全场景，并提供迁移指南以帮助用户从 Opus 4.6 平滑过渡。


我们的最新模型 Claude Opus 4.7 现已全面发布。
Opus 4.7 在高级软件工程方面相较于 Opus 4.6 有显著提升，尤其在最困难的任务上表现突出。用户反馈称，他们可以放心地将最复杂的编码工作——过去需要密切监督的任务——交给 Opus 4.7。Opus 4.7 能够严谨且一致地处理复杂、长期运行的任务，精准遵循指令，并在汇报前设计方法验证自身输出。
该模型在视觉能力方面也有显著提升：能够以更高分辨率识别图像。在完成专业任务时，它更具审美和创造力，能生成更高质量的界面、幻灯片和文档。尽管其综合能力不如我们最强大的模型 Claude Mythos Preview，但在多个基准测试中，Opus 4.7 的表现优于 Opus 4.6：

上周我们宣布了 Project Glasswing，强调了 AI 模型在网络安全领域的风险与益处。我们表示将限制 Claude Mythos Preview 的发布，并优先在能力较弱的模型上测试新的网络安全防护措施。Opus 4.7 是首个此类模型：其网络安全能力不如 Mythos Preview（事实上，在训练过程中我们尝试了差异化降低这些能力）。我们发布 Opus 4.7 时已内置自动检测并阻止涉及禁止或高风险网络安全用途的请求的安全机制。这些安全机制在实际部署中获得的经验，将帮助我们实现最终广泛发布 Mythos 级模型的目标。
希望使用 Opus 4.7 从事合法网络安全工作的安全专业人员（如漏洞研究、渗透测试和红队演练）可加入我们的新 Cyber Verification Program。
Opus 4.7 现已在所有 Claude 产品、API、Amazon Bedrock、Google Cloud 的 Vertex AI 和 Microsoft Foundry 上提供。定价与 Opus 4.6 保持一致：每百万输入 token 5 美元，每百万输出 token 25 美元。开发者可通过 Claude API 使用 claude-opus-4-7。

测试 Claude Opus 4.7

Claude Opus 4.7 在早期测试用户中获得了积极反馈：

在早期测试中，我们看到 Claude Opus 4.7 为开发者带来了显著提升的潜力。它在规划阶段能自行发现逻辑错误，并加速执行，远超之前的 Claude 模型。作为服务于数百万消费者和企业的金融科技平台，这种速度与精确度的结合可能具有变革性：加速开发速度，更快交付客户每天依赖的可信金融解决方案。

Anthropic 已经在编码模型领域树立了标杆，而 Claude Opus 4.7 在市场上以最先进模型的身份进一步推动了这一标准。在我们的内部评估中，它不仅在原始能力上突出，更在处理真实世界异步工作流方面表现出色——自动化、CI/CD 和长期任务。它对问题的思考更深入，并带有更强的主观见解，而非简单附和用户。

Claude Opus 4.7 是 Hex 评估过的最强模型。它在数据缺失时能正确报告，而非提供看似合理但错误的替代方案，并能抵抗即使 Opus 4.6 也会陷入的不一致数据陷阱。它是一个更智能、更高效的 Opus 4.6：低努力的 Opus 4.7 大致相当于中等努力的 Opus 4.6。

在我们的 93 项编码基准测试中，Claude Opus 4.7 相比 Opus 4.6 解决率提升了 13%，包括四项 Opus 4.6 和 Sonnet 4.6 均无法解决的任务。结合更快的中位延迟和严格的指令遵循，这对复杂的长期编码工作流尤其有意义。它减少了多步骤任务的摩擦，让开发者保持流畅，专注于构建。

根据我们的内部研究代理基准测试，Claude Opus 4.7 在多步骤工作方面表现出最强的效率基线。它在六个模块中以 0.715 的总分并列第一，并在我们测试的所有模型中展现出最一致的长上下文性能。在最大的模块“一般金融”中，它相比 Opus 4.6 有显著提升，得分 0.813 对比 0.767，同时在披露和数据纪律方面表现最佳。在演绎逻辑方面，Opus 4.6 曾表现挣扎，而 Opus 4.7 表现稳健。

Claude Opus 4.7 扩展了模型在调查和完成任务方面的能力极限。Anthropic 显然优化了长期推理的持续性，其市场领先表现也证明了这一点。随着工程师从一对一与代理协作转向并行管理，这种前沿能力解锁了新的工作流。

我们在 Claude Opus 4.7 的多模态理解方面看到了重大改进，从阅读化学结构到解读复杂技术图表。更高的分辨率支持帮助 Solve Intelligence 构建了生命科学专利工作流的顶级工具，涵盖起草、诉讼、侵权检测和无效性图表绘制。

对于 Replit 来说，升级到 Claude Opus 4.7 是一个轻松的决定。在用户日常工作中，我们观察到它在更低成本下实现了相同质量——在日志和追踪分析、查找漏洞、提出修复方案等任务上更高效、更精准。我个人喜欢它在技术讨论中提出反驳，帮助我做出更好决策。它真的感觉像一个更好的同事。

Claude Opus 4.7 在 BigLaw Bench 上为 Harvey 展现了强大的实质性准确性，高努力下得分为 90.9%，在审查表格中表现出更好的推理校准，并在模糊文档编辑任务中明显更智能。它能正确区分分配条款与控制权变更条款，这是过去前沿模型一直面临的挑战。在我们的评估中，实质性内容始终被评为强项：正确、全面且引用充分。

Claude Opus 4.7 是一个非常出色的编码模型，尤其在自主性和更具创造性的推理方面。在 CursorBench 上，Opus 4.7 的能力实现了显著提升，以 70% 的成功率超越 Opus 4.6 的 58%。

在复杂的多步骤工作流中，Claude Opus 4.7 是明显的升级：相比 Opus 4.6 提升 14%，且使用更少的 token，工具错误减少三分之一。它是首个通过我们隐性需求测试的模型，并能在过去会让 Opus 停止的工具失败后继续执行。这种可靠性提升让 Notion Agent 真正成为可靠的队友。

在我们的评估中，核心协调代理的工具调用和规划准确性实现了两位数提升。当用户利用 Hebbia 在检索、幻灯片创建或文档生成等场景中规划和执行时，Claude Opus 4.7 展现出提升代理决策能力的潜力。

在 Rakuten-SWE-Bench 上，Claude Opus 4.7 解决的生产任务是 Opus 4.6 的三倍，代码质量和测试质量均有两位数提升。这是一次显著的提升，也是对我们团队日常工程工作的明确升级。

对于 CodeRabbit 的代码审查工作负载，Claude Opus 4.7 是我们测试过的最敏锐的模型。召回率提升超过 10%，揭示了我们最复杂 PR 中最难发现的漏洞，同时在覆盖范围增加的情况下精确率保持稳定。它在我们的测试框架中比 GPT-5.4 xhigh 稍快，我们已将其用于发布时最繁重的审查任务。

对于 Genspark 的 Super Agent，Claude Opus 4.7 在三个最关键的生产差异化方面表现出色：循环抵抗、一致性以及优雅的错误恢复。循环抵抗最为关键。一个模型在 18 个查询中有 1 个无限循环会浪费计算资源并阻塞用户。更低的方差意味着生产中更少的意外。Opus 4.7 实现了我们测量过的最高的每次工具调用质量比。

Claude Opus 4.7 对 Warp 来说是一次显著升级。Opus 4.6 已经是开发者中最好的模型之一，而这个模型在其基础上更全面。它通过了之前 Claude 模型失败的 Terminal Bench 任务，并解决了 Opus 4.6 无法攻克的棘手并发漏洞。对我们来说，这就是信号。

Claude Opus 4.7 是构建仪表盘和数据丰富界面的世界最佳模型。其设计品味令人惊喜——它做出的选择是我真正愿意发布的。它现在是我每天的默认选择。

Claude Opus 4.7 是 Quantium 测试过的最强大的模型。通过我们专有的基准测试方案与领先 AI 模型对比，最大的提升出现在最关键的领域：推理深度、结构化问题构建和复杂技术工作。更少的修正、更快的迭代和更强的输出，解决了客户带来的最困难问题。

Claude Opus 4.7 在智力上感觉是一次真正的飞跃。代码质量明显提升，它正在剔除过去堆积的无意义包装函数和备用框架，并在过程中自行修复代码。这是自 Sonnet 3.7 升级到 Claude 4 系列以来我们见过最干净的提升。

对于 XBOW 自主渗透测试的核心计算机使用工作，新的 Claude Opus 4.7 是一次质的飞跃：在我们的视觉敏锐度基准测试中得分为 98.5%，而 Opus 4.6 仅为 54.5%。我们最大的 Opus 痛点几乎消失，这解锁了之前无法使用它的一整类工作。

Claude Opus 4.7 对 Vercel 来说是一次稳固的升级，且无任何退步。它在一次性编码任务上表现出色，比 Opus 4.6 更正确、更完整，并且更诚实面对自身局限。它甚至在开始工作前对系统代码进行证明，这是早期 Claude 模型从未展现的新行为。

Claude Opus 4.7 非常强大，对 Factory Droids 来说，其任务成功率比 Opus 4.6 提升了 10% 至 15%，工具错误更少，验证步骤更可靠。它能将工作完整执行到底，而非半途而废，这正是企业工程团队所需要的。

Claude Opus 4.7 自主构建了一个完整的 Rust 文本转语音引擎——从神经模型、SIMD 内核到浏览器演示——然后将其输出通过语音识别器验证是否匹配 Python 参考实现。数月的高级工程工作，由其自主完成。从 Opus 4.6 的提升显而易见，且代码库已公开。

Claude Opus 4.7 通过了三个之前 Claude 模型无法完成的 TBench 任务，并修复了我们之前最佳模型遗漏的问题，包括一个竞态条件。它在识别真实问题方面表现出极强的精确性，并揭示了其他模型放弃或未解决的重要发现。在 Qodo 的真实世界代码审查基准中，我们观察到其精确度处于顶级水平。

在 Databricks 的 OfficeQA Pro 上，Claude Opus 4.7 展现出更强的文档推理能力，处理源信息时错误比 Opus 4.6 减少 21%。在我们的数据代理推理基准中，它是企业文档分析表现最佳的 Claude 模型。

对于 Ramp，Claude Opus 4.7 在代理团队工作流中表现突出。我们观察到更强的角色忠实度、指令遵循、协调能力和复杂推理，尤其是在跨越工具、代码库和调试上下文的工程任务中。与 Opus 4.6 相比，它需要更少的逐步指导，帮助我们扩展工程团队运行的内部代理工作流。

对于 Bolt 的长期应用构建工作，Claude Opus 4.7 明显优于 Opus 4.6，最佳情况下提升高达 10%，且没有我们通常从高度自主模型中预期的退步。它提升了用户在单次会话中能交付的上限。

以下是我们在 Opus 4.7 早期测试中的一些亮点和笔记：
* 指令遵循。Opus 4.7 在遵循指令方面有显著提升。有趣的是，这意味着为早期模型编写的提示有时现在会产生意外结果：之前模型可能宽松解释或跳过部分指令，而 Opus 4.7 会逐字执行。用户应相应调整其提示和框架。
* 多模态支持改进。Opus 4.7 对高分辨率图像的视觉能力更强：可接受长边达 2,576 像素（约 3.75 兆像素）的图像，是之前 Claude 模型的三倍以上。这为依赖精细视觉细节的多模态应用打开了大门：计算机使用代理读取密集截图、从复杂图表中提取数据、以及需要像素级参考的工作。1
* 实际工作。除了在金融代理评估中取得的最先进分数（见上表），我们的内部测试显示 Opus 4.7 比 Opus 4.6 更有效的金融分析师，能生成严谨的分析和模型、更专业的演示文稿，并在任务间实现更紧密的整合。Opus 4.7 在 GDPval-AA 上也处于最先进水平，这是对金融、法律等领域的经济价值知识工作的第三方评估。
* 记忆。Opus 4.7 更擅长使用基于文件系统的记忆。它能在长期、多会话工作中记住重要笔记，并利用它们推进新任务，从而减少新任务所需的前置上下文。

安全与对齐

总体而言，Opus 4.7 与 Opus 4.6 具有相似的安全性：我们的评估显示其在欺骗、谄媚和滥用合作等令人担忧行为方面的发生率较低。在某些指标上（如诚实性和对恶意“提示注入”攻击的抵抗），Opus 4.7 相比 Opus 4.6 有所改进；在其他方面（如对受控物质提供过度详细的风险缓解建议），Opus 4.7 略弱。我们的对齐评估结论是该模型“总体对齐良好且可信，但行为并非完全理想”。请注意，根据我们的评估，Mythos Preview 仍是训练出的对齐效果最好的模型。我们的安全评估详见 Claude Opus 4.7 系统卡。

我们自动化行为审计的整体对齐行为得分。在此评估中，Opus 4.7 相比 Opus 4.6 和 Sonnet 4.6 有小幅改进，但 Mythos Preview 仍表现出最低的对齐行为发生率。

今日同步发布

除了 Claude Opus 4.7 本身，我们还推出了以下更新：
* 更多努力控制：Opus 4.7 引入了新的 xhigh（“超高”）努力级别，位于 high 和 max 之间，让用户在处理难题时能更精细地控制推理与延迟的权衡。在 Claude Code 中，我们已将所有计划的默认努力级别提升至 xhigh。在测试 Opus 4.7 的编码和代理用例时，建议从 high 或 xhigh 努力级别开始。
* 在 Claude 平台（API）：除了支持更高分辨率图像，我们还推出了任务预算的公开测试版，让开发者能引导 Claude 的 token 消耗，使其在长期运行中优先处理工作。
* 在 Claude Code：新的 /ultrareview斜杠命令 会启动一个专用的审查会话，逐行检查变更并标记仔细审查者会发现的漏洞和设计问题。我们为 Pro 和 Max Claude Code 用户提供三次免费超审查试用。此外，我们已将 自动模式 扩展至 Max 用户。自动模式是一种新的权限选项，允许 Claude 代表您做决定，意味着您可以运行更长的任务，中断更少——且风险低于完全跳过所有权限。

从 Opus 4.6 迁移到 Opus 4.7

Opus 4.7 是对 Opus 4.6 的直接升级，但有两个变化需要规划，因为它们会影响 token 使用。首先，Opus 4.7 使用了更新的分词器，改进了文本处理方式。代价是相同输入可能映射到更多 token——根据内容类型约为 1.0–1.35×。其次，Opus 4.7 在更高努力级别下思考更多，尤其是在代理设置中的后续回合。这提升了其在难题上的可靠性，但也意味着它会产生更多输出 token。
用户可通过多种方式控制 token 使用：使用努力参数、调整任务预算，或提示模型更简洁。在我们自己的测试中，净效果是积极的——在内部编码评估中，所有努力级别的 token 使用均有改善，如下图所示——但我们建议在真实流量上测量差异。我们编写了 迁移指南，提供从 Opus 4.6 升级到 Opus 4.7 的进一步建议。

在每个努力级别下，基于内部代理编码评估的 token 使用量得分。在此评估中，模型从单个用户提示自主工作，结果可能不具代表性，无法反映交互式编码中的 token 使用。有关调整努力级别的更多信息，请参见 迁移指南。
