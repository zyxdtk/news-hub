摘要

解决视觉谜题既需要对视觉证据的准确解读，也需要在任务特定规则下的可靠计算。将视觉假设和任务约束直接嵌入求解代码中，会使所表示的问题难以被独立检查和修改。我们提出了 Vis2State，一个免训练的智能体框架，它将视觉谜题抽象为连接视觉检查与执行的显式、可修改的问题状态。视觉检查引导状态的构建与精化，而生成的程序则求解所表示的问题。模型在无需预定义谜题模式或求解流程的情况下构建状态和程序。检查与执行反馈使其能够独立修改问题表示和求解流程。Vis2State 在四个基准测试上取得了最先进的性能。跨模型评估进一步证明了持续的增益。消融实验、错误分析以及固定程序的状态干预进一步支持了以状态为中心的设计的有效性。代码将公开提供以促进未来研究。

1 引言

视觉谜题考察模型在任务特定规则下将图像观察转化为解决方案的能力。除了识别物体之外，模型还必须推断它们之间的关系和任务约束，以引导搜索或计算。涵盖算法谜题、空间推理、视觉逻辑和抽象模式的基准测试 [14, 34, 47, 9] 揭示了感知与推理之间的这种联系。它们紧密耦合的感知和计算需求使视觉谜题成为理解多模态推理在何处成功、在何处失效的一个富有启发性的测试平台。

弥合视觉感知与计算之间的鸿沟，需要将视觉证据组织成待求解问题的表示。所需的信息因任务而异。迷宫需要连通性，颜色匹配需要对应关系，推箱子需要位置和合法的状态转移。现有方法提供了互补的能力。思维链提示 [42, 23] 引发中间推理，视觉搜索 [44] 检索相关细节，视觉编程 [17, 36] 将感知连接到可执行操作。仅凭这些能力并不能确保所表示的问题及其求解流程都正确。一个健全的算法可能因约束被误解而失败，正如准确的观察可能因不完整的搜索而被破坏一样。当视觉假设和任务约束被直接嵌入求解代码时，这两种错误来源就会纠缠在一起，使得问题表示难以被独立检查和修改。

我们的核心思想是，视觉谜题可以被抽象为显式的、可修改的问题状态。我们提出了 Vis2State，一个免训练的智能体框架，它将这些状态用作视觉检查与执行之间的接口。通过检查，模型构建一个编码相关物体、关系、约束和目标的任务相关状态，然后生成一个程序来求解所表示的问题。状态模式和程序都不是预定义的。这种分离使模型能够独立于求解流程来精化其对谜题的解读。

显式状态赋予检查和执行不同但互补的角色。检查通过解决不确定的物体、关系或约束，将状态建立在视觉证据的基础上。执行以状态和生成的程序为输入，返回计算结果或错误。这些观察引导模型的下一步行动，可能涉及进一步检查、状态修改或程序精化。这种反馈驱动的过程使模型能够在建立问题和解决问题之间交替进行，而不是遵循固定的检查–执行顺序。图 1 展示了这两种角色。在 中，检查纠正了一个误读的坐标；在 中，执行使用显式状态找到最短路径。

在四个视觉推理基准测试上的实验表明，Vis2State 达到了最先进的准确率，比直接思维链提高了 8.1–15.5 个百分点。跨模型评估证实了持续的增益，而消融实验、错误分析和固定程序的状态干预则支持其以状态为中心的设计的有效性。

我们做出了三项贡献。

  • 显式状态作为推理接口。 我们提出了 Vis2State，一个免训练的智能体框架，它将视觉谜题抽象为显式的、可修改的问题状态，将所表示的问题与其求解流程分离。
  • 以状态为中心的检查与执行。 我们开发了一种自适应推理过程，利用视觉检查来构建和精化状态，利用生成的程序来求解所表示的问题，并以执行反馈引导进一步的修改。
  • 强大的性能和广泛的分析。 Vis2State 在四个基准测试上达到了最先进的准确率，并比直接思维链基线取得了一致的增益。组件消融、错误分析和固定程序的状态干预进一步证实了以状态为中心的设计的有效性。

2 相关工作

视觉检查与工具使用。 视觉工具通过获取和转换与任务相关的证据来支持推理。V* [44] 引导视觉搜索关注相关的图像细节。Visual Sketchpad [19] 通过中间草图支持推理，而 ReFocus [12] 通过高亮和遮蔽引导视觉注意力。Thyme [52] 和 CodeDance [33] 使用可执行代码进行图像操作和计算。为了学习视觉工具的使用，Pixel Reasoner [35] 将指令微调与好奇心驱动的强化学习相结合，而 DeepEyes [53] 通过强化学习学习主动感知。VTool-R1 [43] 使用结果奖励训练视觉编辑，ToolsRL [11] 引入直接工具监督，而 VC-Tooler [45] 学习工具组合以及对返回观察的适应。CodeV [18] 评估证据相关性并训练忠实的工具使用，而 See2Think [48] 研究对中间视觉状态的依赖。Vis2State 将检查引导向构建和检查一个显式问题状态，生成的程序在不访问图像的情况下使用该状态。这一接口使计算的视觉前提显式化且可修改。

基于程序的推理。 基于程序的方法使中间推理可执行。在思维链 [42, 23] 的基础上，PAL [13] 和 Program of Thoughts [8] 将计算委托给解释器。Faithful CoT 将符号转换与确定性求解分离 [25]，而 Chain of Code 将执行与语言模型仿真相结合 [24]。执行也可以为后续推理提供信息。ReAct 将推理与动作和观察交织在一起 [49]，而 CodeAct 使用可执行代码作为其动作空间 [41]。在视觉领域，程序组合视觉模块 [21, 17, 36]，显式场景表示支持符号推理 [50, 26]。Vis2State 将这一过程集中于一个可修改的问题状态，该状态被提供给一个在没有图像访问的情况下运行的生成程序。它将任务相关的物体、关系、约束和目标与程序分开表示，使问题表示和求解流程能够被独立修改。

3 Vis2State

Vis2State 通过显式问题状态连接视觉检查和计算求解（图 2）。检查提供证据来构建和精化状态，而执行应用生成的程序来求解所表示的问题。视觉-语言模型 M_θ 协调这些互补的过程，利用积累的反馈来确定下一步检查、修改或计算什么。给定图像 x 和问题 q，模型选择其下一个动作为

a_t = M_θ(x, q, H_{t-1}; 𝒫), H_0 = [], (1)

其中 𝒫 是共享提示，H_{t-1} 记录先前的动作和观察。每个动作 a_t 检查图像、执行程序或提交答案。在调用和时间预算的限制下，模型可以根据需要重新进行检视或执行，而不是遵循固定的顺序。

所有数据集和模型共享相同的提示和工具指令。详细信息见补充材料。

3.1 状态抽象

问题状态独立于求解流程，编码来自图像和问题的任务相关信息。对于步骤 t 的执行动作，我们将问题状态表示为

s_t = {k_i : v_i}_{i=1}^{K_t}, (2)

其中 s_t 是具有 K_t 个键–值字段的 JSON 对象。模型构建字段 k_i 及其值 v_i 来表示任务相关的物体、关系、约束和目标，而无需预定义任务或模型特定的模式。

将此表示与程序分开，使模型能够独立于求解流程修改其对谜题的解读。例如，在推箱子中，状态记录墙壁、玩家、箱子和目标位置，而程序实现合法的状态转移和搜索。误读的墙壁需要纠正状态，而错误的状态转移实现则需要修改程序。模型可以在后续动作中更新任一组件，先前的观察和结果保留在交互历史中。检查和答案提交不需要状态。记录的状态示例见补充材料。

3.2 视觉检查

视觉检查将问题状态建立在图像证据的基础上。模型请求有针对性的视图或测量，以引导状态构建并解决当前表示中的不确定性。在步骤 t，它在请求列表 R_t 中指定工具及其参数，得到

a_t = Inspect(x, R_t) ⟶ o_t, (3)

其中 o_t 表示执行动作 a_t 后返回的观察。表 1 中的工具执行确定性的图像操作，而模型在任务的上下文中解释其输出。例如，连通颜色组件标识一个像素组，但模型必须确定该组对应的是墙壁、目标还是其他任务实体。这些观察将任务相关的属性和关系建立在视觉证据的基础上。

模型根据积累的观察自适应地选择检查调用，可以在执行之前，也可以在计算反馈引发对状态的不确定性时进行。

3.3 执行与反馈

对于执行，模型提供一个状态–程序对 (s_t, f_t)，其中 f_t 定义 solve(state)。执行将 f_t 应用于 s_t 并返回一个观察，

a_t = Exec(s_t, f_t) ⟶ o_t. (4)

程序以提供的状态为输入，不访问图像，返回计算结果或错误。在每次非终止交互之后，动作和观察被追加到历史中，

H_t = H_{t-1} ∥ [(a_t, o_t)], (5)

其中 ∥ 表示序列拼接。利用这一历史，模型可以检查不确定的视觉细节、修改状态或程序，或提交答案。因此，执行反馈支持问题表示和求解流程的迭代精化。

4 实验与分析

4.1 实验方案

数据集。 我们在四个基准测试上评估了 5,968 道多选题。AlgoPuzzleVQA [14] 包含 18 个算法谜题类别的 1,800 个问题，包括迷宫、推箱子、地图着色和汉诺塔，需要规则约束的搜索和计算。VisualPuzzles [34] 包含 1,168 个问题，涵盖算法、类比、演绎、归纳和空间推理，几乎不需要专业知识。VisuLogic [47] 包含 1,000 个以视觉为中心的逻辑问题，涵盖数量、空间性、位置、属性、风格和其他类别，包括计数、折叠、旋转和图形组合，以测试视觉属性和关系。PuzzleVQA [9] 包含来自 20 个模板的 2,000 个抽象模式问题，通过需要视觉模式归纳的四个单概念和六个双概念类别，涵盖数字、颜色、形状和大小。

评估方案。 我们使用每个基准测试发布的答案提取和评分程序报告准确率。直接思维链遵循每个基准测试的官方思维链提示 [14, 34, 47, 9]。遵循 VisualPuzzles [34] 的做法，当没有产生最终答案时，我们使用固定种子均匀采样一个有效选项。在 VisuLogic 评估中，由于模型可用性问题，我们使用 DeepSeek V4.1 Flash 代替已发布评估器的 GPT-4o-mini [28]。

实现细节。 DeepSeek-V4.1-Flash-260910 [46] 用于主实验，GLM-5.3-Flash-260828 [51] 用于跨模型评估。模型接收图像和问题（包括答案选项），但不接收参考答案或解释。在我们的实验中，启用了思考模式，每次模型调用的最大输出长度为 65,536 个 token。截断的响应返回步骤错误反馈，并允许在剩余预算内继续。补充材料提供了提示和运行时详细信息。

4.3 组件消融

我们使用同一 DeepSeek 模型的五种配置来考察视觉检查、程序执行和显式问题状态对准确率的贡献（表 7）。直接思维链使用基准测试的官方思维链提示，不使用工具进行回答。仅检查添加了五种视觉检查工具，而仅执行提供 Python 执行和反馈。检查 + 执行结合了两种能力，但不需要显式状态。Vis2State 进一步引入了状态构建指导和 solve(state) 接口。

4.4 错误模式与纠正

我们使用补充材料中的标注方案，在相同的 1,709 个诊断问题上考察直接思维链在哪里失败以及 Vis2State 解决了哪些失败（图 4）。主要错误类型因基准测试而异。感知是 AlgoPuzzleVQA、VisualPuzzles 和 VisuLogic 上最大的错误组，分别占错误的 44.2%、54.8% 和 46.5%。在 PuzzleVQA 上，状态/推理占 43.6%，凸显了识别视觉模式背后关系的困难。这些特征将提取视觉证据的失败与表述和求解所表示问题的失败区分开来。

Vis2State 通过有效提交正确回答了这些问题中的 971 个，不包括随机补全。纠正率因错误组而异。搜索/计算的总体纠正率最高，为 75.9%，这在很大程度上反映了 AlgoPuzzleVQA 的情况，其中 97.7% 的案例被纠正。感知产生了最大数量的纠正，但其纠正率为 55.4%；状态/推理仍然较低，为 50.8%。这一模式与执行在获得合适状态后支持系统搜索和计算相一致。感知和状态/推理较低的纠正率表明，提取视觉信息和推断相关规则对 Vis2State 来说仍然具有挑战性。

5 局限性与未来工作

状态有效性。 显式状态可能编码错误的观察或规则，生成的程序可能忽略相关的状态字段，如第 4.5 节所讨论的。因此，仅凭成功的执行并不能保证正确的解读或解决方案。未来工作应根据图像和任务约束验证状态和推断的规则，利用检测到的不一致性引导进一步检查。

计算效率。 Vis2State 使用的平均输出 token 是检查 + 执行的 1.7–2.8 倍。详细信息见补充材料。选择性检查和重用先前构建的状态可以减少这种开销。

6 结论

Vis2State 使显式问题状态成为视觉理解和计算推理之间的接口。其核心贡献是将解决方案背后的物体、关系和约束编码为一种可以被检查、修改并被生成程序使用的表示。在四个基准测试和两个模型上的实验，加上组件消融和状态干预的支持，证明了这种设计的有效性，并提供了生成程序使用所提供状态的证据。这些发现凸显了显式状态构建作为结合感知与计算的视觉推理系统的有用设计原则。

算法 S1：Vis2State 的核心推理循环

1: 输入：图像 x，问题 q，预算 B, T
2: H_0 ← []
3: for t = 1, …, B while 已用时间 < T do
4: a_t ← M_θ(x, q, H_{t-1}; 𝒫) ▷ 选择下一个动作
5: if a_t 提交最终答案 y then
6: return y
7: else
8: 执行 a_t 并接收 o_t ▷ 检查或执行
9: end if
10: H_t ← H_{t-1} ∥ [(a_t, o_t)] ▷ 追加反馈
11: end for
12: return 未提交

算法 S1 总结了 Vis2State 的推理循环。给定图像 x 和问题 q，视觉-语言模型 M_θ 遵循共享提示 𝒫，并使用先前动作和观察的历史 H_{t-1} 选择每个动作 a_t。历史从空开始。检查收集用于构建或精化状态的视觉证据，而执行在提供的状态上运行程序。每个动作及其返回的观察 o_t 被追加到历史中，使模型能够在选择下一个动作之前修改状态或程序。当模型提交最终答案或耗尽任一预算时，循环结束。

Vis2State 提示

通过构建、检查和求解显式状态，从图像和问题中解决谜题。

状态构建。 选择一个最小的 JSON 对象，包含回答所需的事实、关系、规则和目标。自行定义其字段和结构，无需预定义的谜题模式。区分观察到的事实和假设，并保留相关的坐标约定和动作前提条件。

视觉检查。 使用源图像工具检查所提出状态中与答案相关的事实。将它们的实际输出和原始图像与表示进行比较，修复缺失或不一致的事实。成功的测量并不能确立语义正确性。在求解之前解决可能改变答案的不确定性。

执行与修改。 编写定义 solve(state) 的 Python 代码，读取已检查的状态并返回 JSON 兼容的结果。将 JSON 编码的输入对象放在 state_json 中，程序放在 source 中。程序接收此对象时保持不变，不访问图像。将观察到的值复制到状态中，而不是引用测量输出。在计算中验证任务规则和目标。如果状态发生变化，重新计算受影响的结果。

动作格式。 返回一个符合所提供模式的 JSON 动作。使用 measure 进行检查，code 进行计算，final 进行提交，或者在关键证据仍未解决时使用 unsupported。仅在 code 时提供 state_json，其他动作将其设置为空字符串。将未使用的文本字段设置为空字符串，未使用的 requests 设置为 []。在 reason 中简要解释每个动作。

答案提交。 提交前检查工具反馈。将计算结果映射到所请求的答案。对于多选基准测试，answer_json 必须编码一个显示的大写选项字母。

S5.3 状态干预方案

我们通过在保持程序固定的同时改变状态，来测试保存的程序是否使用所提供的状态。

子集选择与组成。 我们从 AlgoPuzzleVQA 和 PuzzleVQA 中各选择 200 个问题，这些问题中最后保存的 DeepSeek Vis2State 程序正确求解原始状态，且独立的参考程序可以证明干预答案。原始状态准确率按构造为 100.0%。选择不要求保存的程序正确求解反事实或对照。AlgoPuzzleVQA 包括水壶（61）、颜色重排（39）、汉诺塔（31）、跳棋移动（26）、腐烂猕猴桃（22）、N 皇后（17）和棋盘铺砖（4）。PuzzleVQA 包括数字网格（55）、颜色网格（32）、大小网格（30）、维恩图（28）、颜色六边形（21）、数字三角形（17）、多边形边数（12）和数字–颜色关联（5）。

干预与独立验证。 每个问题有三个状态条件：原始状态、改变答案的反事实和保持答案的对照。两种干预都修改任务相关的值、位置或配置；更改属性的重复表示被一致地更新。独立的参考程序验证原始答案与基准参考匹配、反事实有效且映射到不同的现有答案选项，以及对照保持原始答案。这些检查独立于被评估的保存程序建立目标答案。

重放与评分。 我们只替换提供的状态，保持程序、答案选项和执行限制固定，不进行新的模型推理。400 个问题产生 1,200 条条件记录。每个输出都根据其状态条件的独立验证答案进行评分；当同时返回值和选项时，两者都必须正确。所有干预失败都保留在分母中，没有问题因不正确的干预输出而被替换。

结果。 反事实准确率在 AlgoPuzzleVQA 上为 98.0%（196/200），在 PuzzleVQA 上为 93.5%（187/200）。对照准确率分别为 100.0%（200/200）和 98.5%（197/200）。在 17 个反事实失败中，9 个计算出正确的新值但返回不一致或缺失的选项；其余 8 个返回错误或缺失的答案。独立验证证明干预答案，但不保证保存的程序产生这些答案。在这些原始正确的子集上，结果表明程序通常对改变答案的状态编辑做出正确响应，同时在保持答案的编辑下保持正确性。

以下六个摘录展示了来自所有四个基准测试记录轨迹的模型生成状态。它们涵盖了配置和合法移动、空间占用、判别属性和测量数量。每个摘录都与其支持的计算配对。

水壶数量和目标配置。 在 AlgoPuzzleVQA 中，每个列表位置指的是同一个水壶。例如，第一个水壶容量为 11，最初包含 1 个单位，最终必须有 5 个单位。所有条目都使用谜题的体积单位。

{"capacities": [11,9,8,4,3],
 "initial":    [1,1,8,3,1],
 "target":     [5,0,3,3,3]}

程序使用容量来确定合法的倒水操作，并从初始配置搜索到目标配置。记录的解决方案需要四步。

迷宫连通性。 在 AlgoPuzzleVQA 中，每个字符串是一行网格。符号 # 表示墙壁，. 表示空闲单元格，G/B 表示入口/出口。摘录显示了第一行和最后一行。中间的行遵循相同的编码。

{"grid": ["#######",
          "G...#.#",
          ...,
          "#.....B",
          "#######"]}

程序搜索相邻的空闲单元格，最小化访问的单元格数，然后最小化转弯数。它返回 23 个单元格和八个转弯，包括入口和出口。

推箱子中的物体和移动约束。 在这个 AlgoPuzzleVQA 推箱子示例中，任务是使用最少的推箱子次数到达目标。位置使用零基（行、列）坐标。(1,3) 处的墙壁直接位于 (2,3) 处的箱子上方，阻止玩家站在那里向下推。省略的墙壁条目描述了网格边界。

{"grid_size": [6,6],
 "box": [2,3], "goal": [3,4],
 "player": [4,4],
 "walls": [..., [1,3]]}

程序跟踪箱子和玩家的位置，并在每次推之前检查玩家的可达性。最少是四次推。

模式叠加中的占用位置。 在 VisualPuzzles 中，每个模式是 3×3 网格中黑色单元格位置的集合，使用零基（行、列）坐标。这里 A、B 和 C 标识三个输入模式，而不是答案选项。

{"patterns": {
   "A": [[0,0],[0,1],[2,1],[2,2]],

用于图形分组的判别属性。 在 VisuLogic 中，id 标识一个图形，segments 记录其直线段的数量。六个记录的计数是 12、10、12、10、12 和 10。下面显示了两个条目。

{"panels": [

   {"id":"2", "segments":10}, ...]}
