预览 GPT-5.6 Sol：下一代模型

📅 2026-06-26 📄 OpenAI 🔗 原文链接

原标题：Previewing GPT-5.6 Sol: a next-generation model OpenAI previews GPT-5.6 Sol, a next-generation model with stronger capabilities in coding, science, and cybersecurity, paired with its most advanced safety stack.

中文摘要： OpenAI发布了GPT-5.6系列模型的有限预览，包括旗舰版Sol、均衡版Terra和经济版Luna。GPT-5.6 Sol在编码、生物学和网络安全方面展现出更强的代理能力，并引入了新的`max`推理努力和`ultra`模式。该系列配备了最强大的安全堆栈，通过分层保障措施和自动化红队测试来抵御现实攻击。模型定价按每百万token计算，并引入了更可预测的提示缓存。OpenAI计划在未来几周内全面推出这些模型，并正与美国政府合作制定相关框架。

我们开始对 GPT-5.6 系列进行有限预览：Sol，我们的旗舰模型；Terra，适用于日常工作的均衡模型；以及 Luna，快速且经济的模型。Terra 的性能与 GPT-5.5 相当，但成本低 2 倍，而 Luna 则以我们最低的成本提供强大的功能。 GPT-5.6 Sol 搭载了我们迄今为止最强大的安全堆栈发布。我们加强了对高风险活动、敏感网络请求和重复滥用的保护，并花费数周时间寻找弱点、对系统进行压力测试，并强化其以抵御现实世界的攻击。 我们坚信应实现广泛访问，并计划在未来几周内全面推出 GPT-5.6 Sol、Terra 和 Luna。作为我们与美国政府持续接触的一部分，我们在今天的发布之前预览了我们的计划和模型的能力。应他们的要求，我们首先向一小部分受信任的合作伙伴进行有限预览（其参与情况已与政府共享），然后再向更广泛的范围发布。在此次预览期间，我们将继续测试并与合作伙伴密切协调，以实现更广泛的可用性。我们不认为这种政府访问流程应成为长期的默认设置。它使得最需要这些工具的用户、开发者、企业、网络防御者和全球合作伙伴无法使用最好的工具。我们采取这一短期措施是因为我们相信，这是在未来几周内实现更广泛可用性的最强有力途径，同时我们将与政府合作制定网络行政命令框架以及未来模型发布的可重复流程。 ## 功能 GPT-5.6 Sol 是我们迄今为止最强大的模型。为了预览模型性能，我们分享了一组评估结果，突出了在编码、生物学和网络安全方面改进的代理能力，更多安全和准备情况评估可在我们的[系统卡⁠（在新窗口中打开）](http://deploymentsafety.openai.com/gpt-5-6-preview)中查看。当我们全面推出该模型时，我们将分享更广泛的评估结果套件。 在 GPT-5.6 中，我们引入了新的 `max` 推理努力，让 Sol 有最多的时间进行深度推理。此外，我们还引入了新的 `ultra` 模式，通过利用子代理来加速复杂工作，从而超越单个代理的能力。 对于编码工作流，GPT-5.6 Sol 在 **Terminal-Bench 2.1** 上创下了新的行业记录，该基准测试用于测试需要规划、迭代和工具协调的命令行工作流。 GPT-5.6 Sol 在生物学工作流方面也显示出广泛的改进。在评估长期基因组学和定量生物学分析的 **GeneBench v1** 上，它在使用更少 token 的同时取得了比 GPT-5.5 更好的结果。 GPT-5.6 Sol 是我们迄今为止在网络安全方面能力最强的模型。它改变了长期安全任务（包括漏洞研究和利用）的性能效率前沿。在 **ExploitBench**² 上，GPT-5.6 Sol 仅使用约 1/3 的输出 token 就能与 Mythos Preview 相媲美。在由加州大学伯克利分校研究人员与 OpenAI 及其他前沿实验室合作创建的基准测试 [**ExploitGym**⁠（在新窗口中打开）](https://arxiv.org/abs/2605.11086)3 上，随着我们增加推理能力，GPT-5.6 Sol、Terra 和 Luna 模型均在网络能力方面展现出强大的提升。 ## 更强大的网络能力与更强大的保障措施 我们开发了具有迄今为止最强大保障措施的 GPT-5.6 Sol、Terra 和 Luna，其配置与每个模型的能力相匹配。随着模型能力的增强，我们设计的保障措施能够越来越多地承受现实世界的对抗性压力，同时保留对合法工作（如代码审查、漏洞研究、补丁开发、调试、安全教育和防御性测试）的访问。我们的目标是使被禁止的攻击性活动变得更加困难、不确定和可检测，而不会不必要地限制这些有益的用途。根据我们对模型和保障措施的评估，我们预计将为合法的防御性工作带来实质性好处，同时有意义地限制被禁止的攻击性使用。 GPT-5.6 Sol 在帮助人们查找和修复漏洞方面比可靠地执行端到端攻击更出色。随着这些能力的不断进步，我们的首要任务是确保它们能够到达并造福防御者，防御者可以使用这些工具来发现弱点、开发补丁并更广泛地加强系统。 根据我们的[准备框架⁠](https://openai.com/index/updating-our-preparedness-framework/)，GPT-5.6 Sol 未达到网络关键阈值。在涉及 Chromium 和 Firefox 的评估中，它识别了错误和利用原语（漏洞利用的构建块），但在测试条件下并未自主产生功能完整的全链漏洞利用。尽管如此，基准阈值无法涵盖模型可能被使用或与其他工具组合的所有方式。这种不确定性，加上模型能力的更广泛阶跃变化，是我们将模型增强的能力与更强大的保障措施和分阶段发布相配合的原因。我们在 [GPT-5.6 预览系统卡⁠（在新窗口中打开）](http://deploymentsafety.openai.com/gpt-5-6-preview)中分享了有关我们保障措施的更多细节。 ## 分层保障堆栈 没有任何单一的保障措施足以应对蓄意或自适应的滥用。在整个 GPT-5.6 预览版中，我们使用了分层保障措施，各模型的具体配置有所不同，并对其进行了针对现实世界攻击的压力测试。这些措施包括训练到模型中的保护、生成期间的实时检查、账户级信号、差异化访问、监控、执行和持续测试。 GPT-5.6 经过训练，可以拒绝被禁止的网络协助，包括当用户试图伪装其意图或越狱模型时。这些模型级别的保障措施确立了模型应该和不应该协助什么的第一道边界。 实时网络和生物学滥用分类器通过在生成时评估输出，提供了另一层保障。对于高风险案例，如果它们检测到潜在的违规行为，生成可能会暂停，同时由更大的推理模型审查对话及其上下文。如果输出被评估为不允许，则会在到达用户之前将其保留。 被标记的活动还可能触发跨相关对话和风险信号的账户级审查，这与我们有关内容保留和审查的条款和政策一致。超越单次对话的视角有助于我们的系统区分持续的恶意行为和合法的双用途安全工作，在这些工作中，相似的技术概念可能出现在非常不同的上下文中。 这些层共同使整体方法比任何单一保障措施都更加稳健。模型行为降低了有害响应的可能性，实时系统可以在生成过程中进行干预，账户级审查可以识别更广泛的模式，而差异化访问则保留了重要的防御性工作，而不会默认广泛提供最敏感的功能。 特别是在预览期间，用户可能会遇到阻止或拒绝某些请求的保障措施。其他请求可能需要更长时间，因为生成暂停以进行额外审查。保障措施偶尔可能会干预合法工作，特别是在防御性和攻击性活动最初看起来相似的双用途领域。 这是预览旨在测试的内容之一。我们不仅想了解保障措施是否限制了滥用，还想了解合法用户是否仍然能够可靠且高效地完成正常工作。预览期间的反馈将帮助我们减少不必要的阻止和延迟，改进保障措施解释上下文的方式，并在更广泛发布之前创造更流畅的体验。 我们还在与企业客户合作制定长期方法——包括隐私保护检测、客户操作的安全控制以及根据客户、用户或工作负载的风险校准的访问——以在推进安全的同时支持企业的隐私要求。 ## 通过自动化红队测试提高稳健性 当攻击者调整策略时，保障措施也需要保持有效。仅对一组固定的已知攻击有效的保护对于前沿模型来说不够稳健。 这就是为什么我们在安全方面投入了比以往更多的智能和计算资源，使用我们自己的模型来发现弱点并更快地改进保障措施。我们投入了超过 700,000 个 A100 等效 GPU 小时进行自动化红队测试，旨在寻找通用越狱：即可以在许多提示或上下文中起作用的攻击，而不仅仅是一个狭窄的设置。专注于这些更难、更通用的攻击让我们能够在一组固定的已知故障之外测试保障措施。它还让我们能够探索比仅靠人工测试所能涵盖的多得多的攻击模式，更早地识别故障模式，并缩短从发现弱点到解决弱点的路径。 除了自动化红队测试外，我们还与第三方测试人员合作进行了广泛的人工专家红队测试，这将在预览期间继续进行。人工红队测试通过测试保障措施以对抗试图以我们的系统可能无法预料的方式滥用模型的创意专家，从而补充了自动化工作。 没有任何评估可以代表所有的产品配置、多步骤攻击或现实世界的工作流。因此，我们维持着一个快速响应流程，以重现、评估、优先处理和修复新发现的越狱，然后将它们添加到我们正在进行的评估中，以便我们能够在未来针对类似的故障进行测试。 ## 可用性和定价 在预览期间，GPT-5.6 模型最初将通过 API 和 Codex 提供给选定的一组受信任的合作伙伴和组织。我们计划尽快向使用 ChatGPT、Codex 和 API 的更广泛人群提供这些模型。 在 GPT-5.6 引入的这个新命名系统中，数字标识模型的代次，而 Sol、Terra 和 Luna 标识可以按照自己的节奏发展的持久能力层级。结合起来，该系列为人们和开发者在智能、速度和成本之间提供了更清晰的选择。 GPT-5.6 按每 100 万 token 对三种模型尺寸进行定价：Sol 为 5 美元输入 / 30 美元输出；Terra 为 2.50 美元输入 / 15 美元输出；Luna 为 1 美元输入 / 6 美元输出。GPT-5.6 还引入了更可预测的提示缓存，包括对显式缓存断点和最少 30 分钟缓存生命的支持。对于 GPT-5.6 及更高版本的模型，缓存写入按模型未缓存输入速率的 1.25 倍计费，而缓存读取继续享受 90% 的缓存输入折扣。 我们还将于 7 月在 Cerebras 上推出 GPT-5.6 Sol，速度高达每秒 750 个 token，以前所未有的速度为客户带来前沿智能。随着我们扩大容量，访问权限最初将仅限于部分客户。 我们很高兴能够继续从这次预览期中学习，并尽快将 GPT-5.6 Sol、Terra 和 Luna 带给更多人。 * * * 1. 我们通过查看模型的生产行为并进行离线模拟来估计延迟和 API 成本。这些估算考虑了工具调用细节、采样 token 和输入 token。现实世界的结果可能会有很大差异，并取决于我们的模拟中未捕获的许多因素。我们以快速 API 速度模拟延迟，并以常规 API 定价模拟成本。 2. 所有模型均使用带有 5 个种子和推理连续性的 ExploitBench API 工具进行评估。 3. 我们在 alpha API 上运行了 ExploitGym，该 API 输出响应的速度比我们的公共 API 快，然后重新调整以匹配我们的公共 API。在将延迟重新调整为公共 API 预期的速度时，这导致一些估计的延迟超过了 2 小时和 6 小时的时间限制，尽管在评估运行中已正确遵守。为了在时间敏感的工作中获得更快的速度，我们在 API 中提供优先处理⁠，在 Codex 中提供快速模式⁠。 4. 未报告输出 token、延迟或成本的模型绘制为水平虚线。 *
