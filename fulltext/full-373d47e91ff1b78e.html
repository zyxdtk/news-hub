摘要

联邦学习服务器使用固定的聚合规则组合客户端模型，而每种常用规则都是针对某一类异构性设计的。我们研究了一个能够检查客户端模型的大语言模型（LLM）能否自行选择规则，而无需在服务器上进行任何训练。在FedReason中，LLM每十轮被调用一次。它通过在受限的服务器端沙箱中运行代码来分析权重，只能看到打印结果，可以在500张图像的代理集上为少数候选模型评分，并提交一个简短的Python聚合程序。服务器应用该程序直到下一次调用，并在其输出无效时回退到FedAvg。完整的权重张量永远不会离开服务器。我们使用Claude Opus 5.5在CIFAR-10和CIFAR-100上以ResNet-18评估了FedReason，实验条件包括Dirichlet标签偏斜、宽度异构子模型和拜占庭客户端，共168次运行，对比14个基线方法。在12组配对标签偏斜运行中，它平均比FedAvg高1.26个百分点（10次获胜），比一个将相同每轮代理预算用于在标准规则中做选择的对照组高1.08个百分点。它是CIFAR-100上最强的服务器端规则，但没有击败改变客户端训练方式的SCAFFOLD。在十个客户端中有三个恶意客户端的情况下，它从第一轮起就排除了所有符号翻转客户端，并且在无需训练根模型的情况下仅比FLTrust低约一个百分点。在没有代理反馈的情况下，某个种子的准确率从73.8%下降到38.8%。60轮运行的平均API费用为0.79美元。

关键词：联邦学习、模型聚合、大语言模型、统计异构性、模型异构性、拜占庭鲁棒性、权重空间编程

1 引言

本文探讨：一个读取联邦学习（FL）服务器上客户端模型的大语言模型（LLM），能否决定如何组合这些模型，并且比固定聚合规则做得更好。我们在客户端标签分布不同、可训练模型宽度不同或诚实性不同的情况下测试这一点。每种标准聚合规则都编码了一种关于"出了什么问题"的假设，而实际部署很少能预先知道哪种假设成立。我们添加了一个保持比较公平的约束：服务器不进行任何训练。它可以在一个小的带标签代理集上以固定次数评估模型，但不能通过梯度下降向该集合拟合任何参数。

我们的想法是让LLM将聚合规则编写为程序。在FL的每一轮中，服务器持有一组新训练的相同架构模型，这些模型携带了加权平均会丢弃的信息。客户端分类器的行显示该客户端见过哪些类别。其更新的大小和方向显示它是否与其他客户端一致，而中毒更新通常在这两方面都很突出。在FedReason（图1）中，服务器每T轮调用一次LLM。LLM通过在服务器上的受限沙箱中运行Python代码来检查权重，并且只读取该代码打印的内容。它可以在代理集上为少数候选模型评分。然后它提交一个简短的函数aggregate(ctx)，服务器在每一轮执行该函数直到下一次调用。

程序可以表达证据支持的任何规则：样本加权平均、大更新的裁剪、排除看起来恶意的客户端、对分类器行的单独处理，或带动量的服务器步长。当证据变化时，LLM会替换它。由于LLM在选择之前查看证据，服务器不必预先知道其客户端是否存在偏斜、算力受限或恶意。程序在调用之间持续运行，因此60轮运行只需六次调用，API成本有界，且大多数轮次不会产生LLM延迟。服务器在每一轮检查程序的输出，并在输出无效时回退到联邦平均，因此故障程序不会中断训练。每个决策都以代码形式存储，连同LLM给出的理由，可在训练后进行审计。原始权重张量保留在服务器上，客户端运行普通的本地训练。

FL在保留于客户端的数据上训练共享模型[1, 2]。FedAvg按样本数对每个客户端模型加权[1]，大多数替代方法将此公式替换为另一个在训练开始前固定、并为某一问题设计的公式，例如标签偏斜[3, 4]、不同宽度的子模型[5]或恶意客户端[6, 7]。在训练期间自适应的方法则调整客户端权重或从固定菜单中选择一个规则[8, 9]。近期的FL LLM智能体设计整个系统，或根据规范、数据特征、客户端画像和标量指标在规则中选择[10, 11, 12]。它们都没有查看权重。Takehi等人[13]最近在一篇未经同行评审的博客文章中报告，前沿LLM能够从小型策略网络的权重中判断它是在哪个游戏上训练的。该LLM还能在不进行梯度训练的情况下编写或编辑小型网络。作者将"超越权重平均的模型合并"列为可能的用途。FedReason在FL中对这一建议进行了受控测试。

我们做出四项贡献：

  1. 我们形式化了元聚合问题：服务器在训练期间将聚合算子选择为根据观察到的客户端模型编写的程序序列，受LLM成本和代理评估预算约束，且无需服务器端训练。它推广了固定规则中的逐轮选择[9]（第3节）。

  2. 我们提出FedReason：一个使用工具的LLM在服务器端沙箱中检查客户端模型，并编写聚合程序；服务器在每一轮检查该程序，检查失败时回退到FedAvg。客户端保持不变，每个API调用都被记录（第4节）。

  3. 我们在CIFAR-10和CIFAR-100上以168次运行评估FedReason，涵盖标签偏斜、宽度异构和两种拜占庭攻击，对比14个基线，其中包括一个将相同每轮代理预算用于在标准规则中做选择的对照。FedReason在12组配对标签偏斜运行中的10组击败FedAvg，是CIFAR-100上最准确的服务器端规则，但没有击败SCAFFOLD。在攻击下，它在不在服务器上训练的情况下与FLTrust相差约一个百分点（第5和6节）。

  4. 我们通过保留权重或代理反馈的消融实验、对主要运行中接受的所有120个程序的审计，以及对其推断错误案例的分析，剖析了LLM的行为（第6和7节）。

2 相关工作

当客户端数据非同分布时，局部最优解各不相同，客户端模型的平均值会偏离全局目标的最优解。这种效应随标签偏斜程度和本地计算量的增加而增大[14, 15]，带浓度参数的Dirichlet标签划分是实验中控制标签偏斜的常用方法[14, 15]。一些补救措施改变本地训练：FedProx添加近端项[16]，SCAFFOLD用控制变量校正客户端漂移，代价是每个客户端需发送第二个向量[3]。其他方法只改变服务器：FedAvgM添加服务器动量[14]，FedAdam将自适应优化器应用于平均更新[4]，FedNova按本地步数归一化更新[17]。第三类工作在训练期间调整客户端权重：FedAdp从每个本地更新与全局更新之间的夹角推导权重[8]；FedLAW通过在服务器持有的代理数据上进行梯度下降，同时学习权重与全局收缩因子[18]；FedAWA从客户端更新向量优化权重而无需额外数据[19]。FedStrategist在每一轮通过由更新诊断驱动的上下文老虎机，从固定的鲁棒聚合器集合中选择一个规则[9]。这些方法要么在训练前固定规则形式（自适应的至多是一组客户端权重或服务器优化器的状态），要么从固定菜单中选择。FedReason搜索更大的空间，因为程序可以单独处理分类器行、裁剪或排除客户端，并随时间改变服务器步长。它通过分析和少量前向评估而非梯度下降在该空间中进行选择。FedLAW是其最接近的基于梯度的对应方法，因为它也依赖服务器端代理数据。

当客户端无法训练完整模型时，它们可以训练从中提取的子模型。HeteroFL给每个客户端每层一组固定的前导通道，在覆盖该坐标的客户端上对每个坐标求平均，并使用静态批归一化（sBN）评估——该方法在训练后重新计算归一化统计量[5]。FedRolex在轮次间滚动提取窗口，使所有通道得到均匀训练[20]。两者都使用固定权重进行逐坐标平均。FedReason保持HeteroFL的静态提取，因此两者之间的任何差异都来自聚合。

恶意客户端可以通过精心构造的模型更新[21]或翻转的训练标签[22]毒害FL。Krum选择最接近其邻居的更新[6]。逐坐标中位数和截尾均值限制少数受损客户端的影响，截尾均值需要其比例的上界[23]。FLTrust在服务器上保留一个小的根数据集，并在每一轮在其上训练服务器更新；它将每个客户端更新缩放到该服务器更新的范数，并按两者之间的整流余弦相似度加权[7]。鲁棒聚合规则假设诚实更新彼此相似，而标签偏斜破坏了这一点[24]，因此它们可能丢弃有用的诚实更新。FedReason使用与FLTrust相同类型的服务器数据，但仅用于前向评估。对不可信方的另一种回应是完全停止共享参数。在我们最近的工作中，异构对等方通过交换隐私保护查询改进模型，拜占庭弹性委员会在使用答案前对其进行过滤[25]。FedReason针对更常见的场景：服务器确实接收客户端模型，且必须决定如何组合它们。

LLM可以从评分反馈中改进候选解。OPRO从评分历史中提出新解[26]，FunSearch将LLM编写的程序与自动评估器配对以发现新构造[27]。FedReason遵循相同的"提出-评估"模式，以有预算的代理集作为评估器，程序作用于模型权重。LLM智能体也已用于FL：Helmsman从规范出发用协作智能体合成完整的FL系统，并在部署前在沙箱模拟中细化[10]；FL-MAESTRO在运行时使用智能体设置通信拓扑、每客户端资源和聚合规则[11]；Pang等人让LLM从用户提供或检测到的数据特征推断合适的聚合策略[12]。这些系统作用于规范、数据描述、客户端画像或标量指标。FL之外确实存在直接编辑训练权重的方法。例如，近似机器遗忘通过单次牛顿式更新移除选定训练数据的影响，我们的TensorUnlearn通过用张量网络压缩Kronecker因子化估计，使宽层的所需曲率计算变得可行[28]。在这类方法中，编辑遵循固定公式。Takehi等人[13]的报告表明，LLM可以通过处理权重来决定编辑本身。据我们所知，此前没有FL方法让LLM在训练期间读取客户端模型并编写聚合代码。我们的仅指标消融实验测量了这种访问权限带来了什么。

3 问题形式化

我们考虑K个客户端 i∈{0,…,K−1}。客户端i持有包含nᵢ个样本的私有数据集𝒟ᵢ，标签 y∈{0,…,C−1}，记 N=∑ᵢ nᵢ，pᵢ=nᵢ/N。训练参数为 w∈ℝᵈ 的模型 f(·;w) 以最小化：

F(w)=∑ᵢ pᵢ Fᵢ(w)，Fᵢ(w)=(1/nᵢ)∑₍ₓ,ᵧ₎∈𝒟ᵢ ℓ(f(x;w),y)，　(1)

其中ℓ为交叉熵损失。训练运行R轮。在第t轮，服务器将全局模型Gᵗ或由索引映射ℐᵢ选择的子模型ℰ(Gᵗ;ℐᵢ)发送给客户端i，客户端本地训练后返回Wᵢᵗ。记 Uᵢᵗ=Wᵢᵗ−ℰ(Gᵗ;ℐᵢ) 为客户端的更新，mᵢᵗ为其元数据（样本数、本地步数、平均训练损失和宽度）。服务器随后应用聚合算子：

G^(t+1)=𝒜ₜ(Gᵗ,{Wᵢᵗ},{mᵢᵗ})。　(2)

FedAvg在每一轮使用 𝒜^avg=∑ᵢ pᵢWᵢᵗ。服务器优化器（如FedAvgM和FedAdam）、自适应加权（如FedAdp）以及鲁棒规则（如中位数、截尾均值和Krum）都是公式(2)的实例，其中一些具有内部状态。

在模型异构下，客户端i训练的网络各层保留全局模型通道数的比例 rᵢ∈{1, 1/2, 1/4}。索引映射取每层的前导通道（静态提取，如HeteroFL）或逐轮移动的窗口（滚动提取，如FedRolex）。将Wᵢᵗ散射回完整模型的坐标得到 Ŵᵢᵗ∈ℝᵈ 和二值覆盖掩码Mᵢᵗ。具有客户端系数 cᵢ≥0 的逐坐标聚合，对每个至少被一个 cᵢ>0 的客户端覆盖的坐标j设置为：

[G^(t+1)]ⱼ = ∑ᵢ cᵢ[Mᵢᵗ]ⱼ[Ŵᵢᵗ]ⱼ / ∑ᵢ cᵢ[Mᵢᵗ]ⱼ，　(3)

其他坐标保持[Gᵗ]ⱼ。HeteroFL和FedRolex使用 cᵢ=1/K，逐坐标FedAvg使用 cᵢ∝nᵢ。在攻击下，服务器未知的客户端集合ℬ为恶意。符号翻转客户端[24]返回 Gᵗ−sUᵢᵗ（s=3），标签翻转客户端在标签 y↦C−1−y 上训练[21]。

服务器持有一个小的、干净的带标签代理集𝒫，如FLTrust所假设[7]；在我们的实验中，𝒫是类平衡的且与所有客户端数据不相交。前向评估ev_𝒫(G)返回模型G在𝒫上的准确率、损失和每类准确率。测试集对任何聚合器都不可见。

元聚合器ℳ在训练期间选择算子。在调用轮 t₁=1<t₂<⋯<t_J，它观察：

𝒪ₜⱼ=(𝒞^tⱼ, ℋ^tⱼ, νⱼ₋₁, πⱼ₋₁)，𝒞ᵗ=(t, Gᵗ, {Wᵢᵗ}, {Uᵢᵗ}, {mᵢᵗ})，　(4)

即轮次上下文𝒞ᵗ、代理指标和聚合系数的历史ℋ、它在上一次调用中的笔记νⱼ₋₁和上一个程序πⱼ₋₁。它输出程序 πⱼ∈Π，其中Π是将轮次上下文映射为具有Gᵗ的键和张量形状的模型的程序集合；服务器对 tⱼ≤t<tⱼ₊₁ 应用 G^(t+1)=πⱼ(𝒞ᵗ)，其中 t_J₊₁=R+1。元聚合问题为：

max_ℳ E[Acc_test(G^(R+1))]　s.t.　∑ⱼ₌₁ᴶ κⱼ≤B，eⱼ^inv≤b_inv ∀j，eₜ^prog≤b_prog ∀t，　(5)

其中κⱼ是第j次调用的API成本，eⱼ^inv是第j次调用期间使用的代理评估次数，eₜ^prog是活动程序在第t轮使用的次数。期望遍及划分、本地训练和ℳ的随机性。还有两个结构性约束：ℳ和任何程序都不得在服务器上运行基于梯度的优化；完整的权重张量永远不会发送给外部模型提供商。

测试准确率永远不会被观测到，因此ℳ必须根据权重空间证据和少量代理评估来决策。集合Π包含本研究的每个纯服务器端基线（FedAvg、FedAvgM、FedAdam、FedNova、FedAdp、中位数、截尾均值、Krum和HeteroFL平均），因为每个都是关于𝒞ᵗ和持久状态的短程序。因此，一个"神谕"元聚合器在每个设置中都能匹配这些规则中的最佳者。FedProx和SCAFFOLD位于Π之外，因为它们改变了客户端的计算；FLTrust位于其外，因为它在服务器上训练。

4 FedReason框架

FedReason是问题(5)的一个元聚合器，只改变服务器（图1和算法1）。在第一个程序被接受之前，FedAvg是活动规则。在每个满足 (t−1) mod T=0 的轮次，服务器与LLM开启新的工具使用对话，将轮次上下文加载到分析沙箱，让LLM调查它，直到它提交一个在当前轮次通过试运行的程序。该程序聚合当前轮次及之后的每一轮，直到下一次调用。因为第一次调用发生在第1轮（第一次聚合之前），除非程序失败，每一轮都由LLM编写的程序聚合。调用之间没有API调用。

4.1 在服务器端沙箱中读取权重

调用期间LLM有两个工具：python（在服务器上的持久命名空间中运行代码并返回其打印内容）和submit_policy（提交程序）。命名空间持有全局模型G、客户端模型W、更新U、元数据meta以及代理指标和系数历史的只读副本，还持有一个层表和设置描述（数据集、类数、架构、客户端宽度、当前轮次和预算）。辅助函数可计算余弦相似度、样本加权和一般加权平均（子模型为逐坐标，公式(3)）、张量单行按各自客户端系数的平均（例如分类器中的逐类）、客户端×参数更新矩阵，以及服务器步长 Gᵗ+η(G̃−Gᵗ)。一个有预算的函数proxy_eval在代理集上评估任何候选模型，每次调用最多 b_inv=6 次。

辅助函数summary()打印一个紧凑表格，为LLM提供起点。对每个客户端，表格列出样本数、本地步数和训练损失，并添加带鲁棒z分数（中位数和中位数绝对偏差）的更新范数，以及各层组（主干、四个阶段和分类器）的相对更新大小。留一余弦将客户端的更新与其他客户端的样本加权平均更新进行比较（整体模型和逐层组），偏移分数概括其归一化统计量的变化。该辅助函数还打印更新的成对余弦，以及每个客户端的分类器偏置和行变化最大的类别。在标签偏斜下，客户端未见过的类别的分类器行所受更新与其见过的类别系统性地不同。因此，客户端的标签组成可以从其权重中读出，尽管服务器从未见过其数据。客户端标签直方图、恶意客户端的身份和测试集永远不会被放入命名空间。

每次调用的打印输出被截断为6,000个字符，此输出是LLM获得的权重的唯一视图。代码在禁用梯度、受限内置函数和导入白名单（numpy、torch、scipy、math和若干标准模块）下运行。任何代码运行之前，对其语法树的检查会拒绝私有和反射属性访问以及一系列文件、进程和自动微分函数。运行期间，解释器审计钩子阻止文件写入、套接字和子进程。错误以回溯形式返回，使LLM能够纠正其代码。

4.2 聚合程序与调用

程序是一个Python函数aggregate(ctx)，与简短理由和供下一次调用使用的笔记一起提交。每一轮服务器以上下文ctx调用它，该上下文暴露沙箱的对象和辅助函数。上下文还持有跨轮次和程序持久化的字典ctx.memory（用于服务器动量、平滑统计量或每客户端怀疑计数器），以及一个限制为每轮 b_prog=3 次调用的代理评估器。程序返回一个与Gᵗ的键和张量形状完全相同的模型，并可报告其客户端系数以供记录。提交时，服务器在当前轮次对程序进行试运行。若失败，错误返回给LLM，LLM总共最多可重新提交三次。每一轮都会检查输出的键集和形状、有限值、非负运行方差，以及更新范数 ∥G^(t+1)−Gᵗ∥ 不超过最大客户端更新范数的十倍。若程序抛出异常或输出未通过检查，该轮使用FedAvg，ctx.memory被回滚，错误在下一个简报中报告。

每次调用是一个最多十次模型请求的新对话。调用之间，LLM只记住服务器写入第一条消息的内容，我们称之为"简报"。它包含设置描述、客户端元数据、代理指标和系数的历史，以及上一个程序及其理由、每轮代理准确率、错误和打印诊断，还携带LLM自己在上一次调用中的笔记（最多4,000字符）和剩余预算。若轮次限制内没有接受任何程序，上一个程序保持活动。

系统提示是静态的。它定义了服务器端元聚合器的角色，记录接口并设置七条规则。LLM不得在服务器上训练：自动微分、优化器和任何对代理数据的迭代拟合都被排除，有预算的proxy_eval是唯一的前向传递。文件和网络被禁止。提示将预期测试准确率设为目标，警告客户端可能是异构的、偏斜的或恶意的，要求编写廉价且数值安全的程序，并要求每次调用以submit_policy结束。它还说明500张代理图像上的准确率约有±2个百分点的噪声，小差异不应决定候选之间的取舍。一份简短指南列出了启发式方法，如逐层更新几何、标签偏斜的分类器偏置证据、归一化统计量、裁剪、中位数或截尾均值、基于余弦的降权、服务器步长和动量。一个最小示例程序展示了接口，包含样本加权主体、分类器行的类证据加权和服务器动量。因此，提示建议了构建模块而不强制规定任何模块，第6.3节将显示其建议之一可能造成损害。

当FedReason与不使用服务器数据的方法比较时，代理访问是一个混杂因素，因为能评估候选的服务器可以简单地在标准规则中挑选。因此我们对其设置预算，并添加对照ProxySel，它将相同的每轮三次评估用于在三个标准候选中选择（第5节）。FedReason还可在每次调用中使用六次评估用于分析。当每个程序都在第一次提交时被接受时（我们的运行中全部如此），带六次调用的60轮运行最多可请求 6·6+60·3=216 次评估，而ProxySel为180次；被拒绝的试运行最多可再增加54次。实际程序使用的远少于此（第6.3节）。

4.3 保障措施、隐私与成本

FedReason保持通常的FL信任模型，即诚实但好奇的服务器接收单个客户端模型。与Krum和FLTrust一样，它需要这些单个模型，因此无法与安全聚合[29]结合，且服务器面临与FedAvg下相同的从更新重建训练数据的风险[30]。新的一方是LLM提供商，我们同样将其视为诚实但好奇。它接收静态系统提示、简报（服务器端聚合信息如样本数、损失、代理指标和系数，以及LLM或其程序先前编写的文本）、LLM代码的截断输出和服务器对提交的回复。完整权重张量永远不会离开服务器。但打印输出仍可能包含单个权重值，LLM要求的许多统计量会揭示客户端的标签组成。LLM还会将此类推断写入其笔记，并随后续简报再次发送。FL服务器本已持有这些信息，但FedReason多共享了一方。

恶意客户端控制其权重和报告的数字，但无法注入文本，因为简报中每个依赖客户端的字段都是服务器格式化的数字。LLM编写的代码可能包含缺陷和安全弱点[31]，因此我们将其视为不可信：它在受限命名空间中运行，其输出在每一轮都被检查并有FedAvg回退。然而，受限的Python命名空间并非安全边界，部署应在操作系统层面增加隔离。

每个API调用都记录其令牌计数、服务模型和延迟。一次具有n_in个未缓存输入令牌、n_cw个缓存写入令牌、n_cr个缓存读取令牌和n_out个输出令牌（含思考）的调用成本为：

c=10⁻⁶(n_in·p_in + n_cw·p_cw + n_cr·p_cr + n_out·p_out) USD，　(6)

我们所用模型的每百万令牌标价为 p_in=4、p_cw=5、p_cr=0.20 和 p_out=20 美元[32]。系统提示和工具定义在调用间相同，并从提示缓存中提供。一次运行有六次调用（在每五轮调用LLM的消融中为十二次），每次最多十个请求外加一个请求提交的最终请求。因此其成本既不随模型参数数量增长，也不随调用间轮数增长。一旦研究总支出达到全局预算，所有API调用即停止。

图8跟踪种子0的运行；面板显示LLM从未见过的客户端标签计数。第一个程序是FedAvg的保守变体，采用样本计数权重、两倍中位数更新范数的裁剪和缓慢的怀疑计数器，因此两个最小的客户端（336和1,610张图像）的权重与FedAvg下一样小。该种子中FedAvg在轮次间波动，第11至14轮为35.5%、41.8%、36.7%和47.8%。第11轮，LLM发现分类器更新占分类器范数的44%到118%，且每类代理准确率逐轮剧烈波动。它测得分类器步长减半的代理准确率为50%，FedAvg为36%，于是提交了一个抑制分类器更新的程序，此后第11至14轮准确率为47.1%、49.2%、51.6%和52.1%。第31轮，它将样本权重与从分类器偏置变化估计的类平衡权重混合，将权重移向持有稀有类别的客户端（图8a中第31轮的变化）。代理增益很小（68.4%对67.6%），用其自己的话说"在噪声范围内但有原则"。它对单个客户端的陈述与隐藏划分一致：它将客户端0描述为类2的唯一持有者，客户端5描述为持有类9的单类客户端。划分证实了这两点：客户端0的4,955张图像中有4,944张属于类2，其他客户端持有该类图像均不超过两张；客户端5的4,617张图像中有4,512张属于类9。它对持有多个类别客户端的估计在调用间变化，LLM自己将其归因于噪声。从第51轮起，程序还在每轮为最弱类别尝试0、0.8和1.6的偏置偏移，并在其三次评估内保留代理集上得分最高者；没有任何内容通过梯度下降拟合。任何客户端模型的混合都无法再现这样的偏移，因此第51至60轮中有效权重只能粗略解释所应用的更新（相对残差高达0.88，而之前约为0.05）。

在20次主要运行中接受的120个程序里，LLM形成了一套一致的工具组合。几乎所有程序都裁剪更新范数（98%）并降低更新方向与其他客户端不一致的客户端权重（91%）；每个程序都在ctx.memory中维护每客户端怀疑计数器，并从异常处理程序返回FedAvg。分类器行的类感知聚合出现在38%的程序中，非1的服务器步长出现在22%中，服务器动量出现在35%中（从未出现在拜占庭运行中）。宽度感知加权出现在宽度异构设置92%的程序中，在代理集上做候选选择出现在45%中。程序平均每轮使用其三次评估中的0.95次；算上分析评估，一次主要运行请求74次候选评估，而ProxySel为180次。没有程序使用逐坐标中位数或截尾均值进行聚合，一次运行仅将中位数用作余弦评分的参考方向。12次标签偏斜运行中，没有程序给任何客户端零权重，而拜占庭程序在240轮中的225轮排除了客户端。在第一次之后的调用中，28%的情况下LLM原样重新提交上一个程序。平均而言，程序输出与FedAvg的差异在标签偏斜下为FedAvg更新范数的0.40倍，攻击下为0.82倍。

审计发现了一个编程错误，LLM自己发现并修复了它。CIFAR-100 α=0.1（种子0）上，第11轮提交的程序在分类器加权中相乘了形状不兼容的张量。其自身的异常处理程序捕获了错误并回退到样本加权分类器更新，因此服务器未记录失败。错误消息出现在程序的打印诊断中（下一个简报包含它），第21轮LLM写道"policy_011有一个广播错误，所以它的头总是回退到普通FedAvg"，并提交了修正后的程序。另有三次修订涉及在宽度异构运行中误触发的启发式方法——留一余弦因客户端的宽度而非其数据而惩罚它们。CIFAR-100上，LLM在第11轮注意到其规则将三个全宽客户端的权重压低到约0.02，称之为"异构宽度的伪影"并替换了该规则。

并非每个误判都被捕获。CIFAR-10宽度异构运行种子0中，LLM将客户端3和5（均为×1/2）的强烈负类9偏置变化解读为标签翻转中毒（"这符合9翻转中毒"，第51轮）。它从第21轮起在40轮中的36轮排除了它们。该设置没有攻击者，且两个客户端都没有一张类9图像——这恰恰是诚实训练将类偏置推低的情况。排除提高了类9的代理准确率，但代理集只评估完整模型，看不到×1/2子模型。该子模型在第30、50和60轮（两个客户端被排除时）达到53.7%、52.5%和53.8%，而在第20和40轮（未被排除时）为58.5%和63.4%。这解释了表3中×1/2结果的大差异。

一次调用平均需要3.9±1.5次模型请求（2到9次）、2.9次沙箱调用和2.9次分析评估。它读取约60,000个输入令牌（83%来自提示缓存），写入约3,600个输出令牌（含思考）。成本为0.13±0.05美元，耗时41±18秒（中位数36秒）。带六次调用的60轮运行平均成本0.79美元（0.56到1.26美元）。图7的和展示了成本如何在运行中累积，以及一次调用的令牌如何分为缓存读取、缓存写入和输出。第一次调用最小，约46,000个令牌，后续调用为62,000到73,000个。24次FedReason运行（含消融）共花费20.38美元；研究的API账单为20.51美元，因为还包含一次运行的中止启动。在我们的模拟中，FedAvg一轮约16秒，60轮16分钟。FedReason运行的六次调用总计约4分钟（约四分之一），执行程序每轮增加约1.6秒（每次运行1.5分钟）。FedReason运行的实测墙上时间更长（平均37分钟），但差异主要在客户端训练——两种方法完全相同，只是被共享GPU的其他运行拖慢。在轮次需要数分钟或更长的跨机构部署中，调用的相对延迟更小。

7 讨论与局限性

结果支持一个适度的结论：仅改变服务器并使用少量前向评估预算，一个读取客户端模型的LLM所编写的程序在大多数配对标签偏斜比较中击败了FedAvg，并在大多数比较中击败了具有相同每轮代理预算的对照。它还在第一轮就从权重中识别出符号翻转客户端。标签偏斜下的增益约一个百分点，在CIFAR-100上最大。FedReason没有击败SCAFFOLD，攻击下没有击败FLTrust，且由于一个错误推断，在CIFAR-10子模型上不如HeteroFL。我们的实验在训练期间没有"制度变化"——划分固定、攻击者从第一轮开始行动——因此"程序可以跟随变化情况"这一动机仍未得到检验。

代理集比仅凭权重更重要。没有它，LLM在整个运行中坚持有害的启发式，而完整方法在十轮后就放弃了同一启发式。我们的代理集是最有利的类型：训练分割（因而也是测试分布）的类平衡样本，尽管很小（CIFAR-100上每类5张图像）。FLTrust和ProxySel做了相同假设。有偏、错误标注或类不平衡的代理集可能误导所有三者，我们未研究这一点。ProxySel表明，将代理访问用作三个固定规则间的选择无法解释FedReason的增益，但FedReason更自由地使用其预算，例如评估单个客户端模型，这是固定对照不做的。

理由和笔记是模型编写的日志，而非经过验证的解释。在我们对照LLM从未见过的信息检查的案例中，大多数陈述是正确的，例如单类客户端和符号翻转客户端的身份。其他则不然：宽度异构运行中对两个诚实客户端的标签翻转诊断，以及在调用间变化的标签组成估计。因此，排除应被视为需要证实的假设；应评估每一个被服务的子模型宽度；审计应阅读执行的代码而不仅是理由。作者在了解我们评估的三种异构性的情况下编写了系统提示。其启发式和示例程序塑造了LLM首先尝试的内容（如类证据加权所示），而基线使用其原论文的超参数且未调优。FedReason的部分增益可能来自提示中的领域知识而非权重分析，保持提示但保留权重的仅指标消融只能部分区分两者。

该模型不接受采样参数，因此其输出无法做到确定性，且提供商可能更改或下线模型版本。三个种子只能揭示大效应，消融各仅基于单个种子。每个被接受的程序都记录了其活动的轮次，因此决策可以在没有LLM的情况下重放，但我们未测试此类重放，且降低精度的GPU训练不保证重现相同轨迹。

FedReason与模型提供商共享每客户端统计量。在我们的转录中，LLM经常陈述单个客户端的标签组成，并在其笔记中延续这些陈述。输出限制约束了披露的数量但不约束内容。该方法需要单个更新，因此无法与安全聚合结合。我们未评估两个明显的缓解措施：过滤沙箱输出或向其添加噪声；在本地运行开放权重模型使任何内容都不离开服务器。在持有每个客户端模型的服务器上执行LLM编写的代码，还需要超出受限Python命名空间的隔离。我们评估的攻击简单且非自适应。知道元聚合器并塑造更新以通过其范数、余弦和分类器检查的攻击者（如自适应攻击针对固定鲁棒规则那样[21]）未被测试。

评估使用十个完全参与的客户端、两个图像数据集、一个架构、60轮和一个LLM。具有部分参与的大型跨设备群体、更大的模型和其他模态可能同时改变收益和成本。每轮数千个客户端时，沙箱无法暴露每个客户端模型，分析将不得不基于草图或客户端集群的摘要进行。

8 结论

FedReason用LLM在读取服务器上客户端模型后编写的程序，取代了FL的固定聚合公式。LLM从不在服务器上训练，每个聚合都被检查和记录。在CIFAR-10和CIFAR-100上涵盖标签偏斜、不同宽度子模型和拜占庭客户端的168次运行中，FedReason在标签偏斜下平均比FedAvg提高1.26个百分点，是CIFAR-100上最强的服务器端规则，但没有击败SCAFFOLD。它在第一轮就从权重中识别出符号翻转客户端，并在不在服务器上训练的情况下与FLTrust相差约一个百分点，每次运行成本0.79美元。消融中，移除代理反馈损失35个百分点，保留权重约损失6个百分点（各在一个种子中），而转录显示LLM的推断可能出错。在这些限制内，如权重空间编程所建议的[13]，一个读取权重并编写代码的LLM是FL服务器的可行组成部分：其成本预先固定，每个决策都可在事后审阅。开放问题包括本地部署开放权重模型、LLM所读统计量的隐私核算、与SCAFFOLD等客户端侧方法的结合，以及更大的客户端群体。

def aggregate(ctx):
    torch, np = ctx.torch, ctx.np
    K = ctx.num_clients
    n = np.array([m['num_samples'] for m in ctx.meta], dtype=float)
    cids = [m['cid'] for m in ctx.meta]
    w0 = n / n.sum()
    try:
        M = ctx.update_matrix()
        Gm = M @ M.T
        nr = Gm.diag().clamp_min(1e-12).sqrt()
        C = (Gm / (nr[:, None] * nr[None, :])).numpy().astype(float)
        np.fill_diagonal(C, np.nan)
        medcos = np.nanmedian(C, axis=1)
        norms = nr.numpy().astype(float)
        mednorm = float(np.median(norms))
        gmed = float(np.median(medcos))
        flag = (norms &gt; 3.0 * mednorm) | ((medcos &lt; 0.0) &amp; (medcos &lt; gmed - 0.05))
        mem = ctx.memory.setdefault('susp', {})
        for i, c in enumerate(cids):
            h = mem.setdefault(str(c), [0, 0])
            h[0] += int(flag[i]); h[1] += 1
        excl = flag.copy()
        for i, c in enumerate(cids):
            h = mem[str(c)]
            if h[0] &gt;= 3 and h[0] &gt;= 0.5 * h[1]:
                excl[i] = True
        if (~excl).sum() &lt; 3:
            excl = norms &gt; 3.0 * mednorm
        if (~excl).sum() &lt; 3:
            excl = np.zeros(K, dtype=bool)
        w = w0.copy(); w[excl] = 0.0
        w = w / w.sum()
        # 将接受的更新裁剪至被接受客户端的中位数范数
        accn = norms[~excl]
        cap = float(np.median(accn))
        scale = np.minimum(1.0, cap / np.maximum(norms, 1e-12))
        coef = torch.as_tensor(w * scale, dtype=torch.float32)
        upd = (coef[:, None] * M).sum(0)
        d = ctx.unflatten(upd)
        bn_keys = [k for k, _, kind, _ in ctx.layers if kind == 'bn_stat']
        new = ctx.weighted_average(w, keys=bn_keys)
        new = dict(new)
        for k, v in d.items():
            new[k] = ctx.G[k] + v
        print(f'excl={[cids[i] for i in range(K) if excl[i]]} medcos={np.round(medcos,2).tolist()}')
        return new, {'weights': w.tolist()}
    except Exception as exc:
        print(f'fallback FedAvg: {exc}')
        return ctx.fedavg(), {'weights': w0.tolist()}
