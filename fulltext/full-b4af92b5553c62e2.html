摘要
自主科学研究智能体正越来越多地应用于端到端的科学工作流程中，包括文献综述、数据分析、实验和报告生成。然而，开放式的研究任务通常没有明确规定完成任务所需的分析、方法和成功标准。因此，智能体可能会遗漏重要的分析、使用不恰当的方法，或者得出缺乏证据支持的结论。
为了解决这个问题，我们提出了
AutoSciRub
，这是一个“评估优先”的框架，它会在研究执行之前归纳出特定于任务的可执行评分规则，并利用它来指导执行、标准级别的验证以及迭代修订。AutoSciRub 将未充分指定的指令分解为原子科学目标，将它们与相关文献和任务可见数据相结合，并综合出具体的、可操作的且可验证的标准。由此产生的评分规则将隐含的实验和证据要求显性化，为实验和分析提供指导。在修订过程中，评分规则引导的验证会识别未满足的标准，并能够对研究报告及其支持性工件进行有针对性的细化。
在 ResearchClawBench 上，AutoSciRub 持续改进了所有测试配置，在固定的 Codex 框架下，三个骨干大语言模型（LLM）的平均增益为
2.08
分，在使用固定 DeepSeek-V4-Flash 骨干的三个智能体框架下平均增益为
2.95
分。在随机抽样的 20 个 AstaBench E2E Discovery 任务子集上，AutoSciRub 在三个智能体框架上进一步实现了平均
16.8
分的提升，同时保持或增加了成功完成的任务数量。这些结果表明，评估优先的指导为自主科学研究提供了一种有效且可泛化的控制机制

科学指令通常只规定一个高层目标，而将中间目标、方法论要求、预期证据和成功条件隐含其中。因此，智能体可能会产生一份看似合理的报告，但却遗漏了必要的分析，使用了不恰当的程序，或者提出了实验证据不支持的声明。图

为什么自主研究智能体在开放式研究任务中会遇到困难。
现有的科学智能体基准测试使用可执行的指标、专家编写的评分规则和基于 LLM 的判断来评估研究输出

)

最近关于自动评分规则生成的工作提供了一种有前途的替代方案，它从自然语言指令和上下文信息中推导出特定于任务的标准

Siro, Aliannejadi, and Aliannejadi 2026

Ding 2026

此外，现有科学智能体基准测试中的评分规则主要被视为
事后
评估工具。它们对完成的工件进行评分，但不帮助智能体确定应该产生什么证据或如何改进不完整的工件。我们认为，评分规则应该作为
中间科学规范
。它们应该明确研究任务的隐含要求，并将任务解释、研究执行、输出验证和迭代修订联系起来。在这种观点下，一个可靠的研究智能体应该
学会在改进之前进行评估
。
基于这一原则，我们引入了
AutoSciRub
，这是一个自动归纳基于证据的科学评分规则并使用它们来指导迭代研究改进的框架。
AutoSciRub 由两个阶段组成。
首先，
自动评分规则归纳
将原始指令分解为原子科学目标，并将它们建立在相关文献、网络证据、可用的任务数据和环境限制的基础之上。由此产生的特定于任务的评分规则明确了所需的分析、证据和成功条件。
其次，在智能体产生研究报告和支持性工件之后，
评分规则引导的迭代修订
逐条标准地评估可用证据，识别未满足的科学要求，并为修订提供有针对性的反馈。
我们在 ResearchClawBench 的所有 40 个任务和 AstaBench 的 20 个端到端科学发现任务的固定子集上评估了 AutoSciRub。
在 ResearchClawBench 上，AutoSciRub 在固定的 Codex 框架下为三个骨干 LLM 带来了平均
2.08
分的提升，在使用固定 DeepSeek-V4-Flash 骨干的三个智能体框架下带来了平均
2.95
分的提升。
在 AstaBench 上，它在三个智能体系统上进一步将分数平均提高了
16.8
分。
这些结果表明，自动归纳的、基于证据的评分规则可以提供可扩展的评估标准，同时也可以作为自主科学研究的有效指导。

评估维度。
特异性。
特异性衡量评分规则陈述要做什么和产生什么的精确程度。一个具体的评分规则在使预期分析明确无误的水平上命名相关的方法或实验、变量、条件、指标、比较器、阈值和预期工件。特异性涉及规范的具象性；它本身并不确立该计划是可执行的、科学上有效的或针对正确的科学目标的。
可操作性。
可操作性衡量一个胜任的智能体是否可以在不发明计划的重要部分的情况下使用可用输入执行评分规则。一个可操作的评分规则提供足够的操作步骤、依赖关系、参数或方法选择、决策规则和预期输出以支持实施。可操作性不奖励与执行无关的细节，也不保证可执行的计划解决了任务的科学核心。
证据可验证性。
证据可验证性衡量评分规则是否要求可检查和可追溯的证据，允许对任务完成情况和由此产生的科学声明进行独立验证。可验证的证据可能包括定量表格、图表、机器可读输出、对照、基线比较、不确定性估计、来源以及声明和生成结果之间的明确链接。该维度评估证据的可检查性和诊断价值，而不是请求的工件数量。
科学核心覆盖率。
科学核心覆盖率衡量评分规则忠实地覆盖和操作化任务核心科学成功条件的程度。它评估评分规则的目标、方法或科学上等同的替代方案、指标、比较、工件、范围、惯例、证据和所需结论是否共同针对预期的科学问题。当重要的成功条件被遗漏或权重不足、评分规则偏向相邻问题或核心目标被非等同的代理取代时，分数会降低。当替代方法和工件为相同的核心声明提供科学上等同或更强的证据时，它们将获得满分。
这四个维度捕获了互补的属性。一个评分规则可能具有高度的特异性和可操作性，但如果它精确地操作化了错误的分析，则科学核心覆盖率得分会很低。相反，一个简洁的评分规则可能识别出正确的科学核心，但如果重要的实施选择仍未明确，则特异性或可操作性得分会较低。证据可验证性是单独评估的：一个科学上一致且可执行的计划如果不要求可检查的输出直接支持其结论，可能仍然难以验证。

实验配置和共享初始化。
我们在所有 40 个 ResearchClawBench 任务上比较了评分规则引导的修订与无评分规则的整体自细化。所有检查点 0 的报告、验证调用、有针对性的修订和无评分规则的修订都是使用带有
deepseek/deepseek-v4-flash
的 OpenClaw 执行的。没有单独实例化的验证器模型。相反，同一个 OpenClaw 智能体在任务会话中调用
report-verifier
技能。
两种修订策略都从相同的 40 个冻结的检查点 0 报告和图表开始。这些检查点 0 的输出是在特定于任务的可执行评分规则下，经过规划、文献基础、实验设计、实验执行、图表生成和初始报告撰写之后，但在任何验证器调用或验证器驱动的修订之前生成的。它们的平均 ResearchClawBench 分数为 18.309083，在正文中报告为 18.31。
对于无评分规则的条件，规范的检查点 0
report.md
文件及其图表被复制到一个新的隔离工作区中。在复制前后计算 SHA-256 哈希值，以验证起始报告和图表未被更改。我们不声称这两种策略共享完全相同的工作区：检查点 0 的代码和输出目录没有被冻结或复制，因为它们可能包含与评分规则相关的状态和后来的反馈。相反，无评分规则的工作区再次被提供原始指令、任务数据和相关工作，智能体可以在细化过程中创建新的代码、输出和分析。
标准级别验证。
在每次引导修订之前，当前工件由同一个 OpenClaw 智能体通过仅验证调用来评估。验证器检查当前报告、生成的实验和结果、图表和表格、定量值、结论以及机制或分析解释。它还检查特定于任务的可执行评分规则要求的工件是否存在或在报告中明确表示，包括它们的文件名、标题、说明、显示名称和详细描述。
验证器被指示区分生成的实验证据和仅由先前文献支持的声明。只有当结论遵循当前任务执行中产生的证据时，才认为结论得到了充分支持。
对于每个科学目标，验证器记录报告是否包含所需的实验、结果、图表或表格、结论以及机制或分析解释。它还评估单个评分规则项目，并产生稳定的反馈项目，指定剩余的问题和所需的纠正措施。
