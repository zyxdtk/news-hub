虽然现在才是 2026 年 9 月的第一天，但 AI 领域的这个月和秋季已经拉开了激烈的序幕，因为 Anthropic 刚刚发布了其迄今为止最强大的大型语言模型——
Claude Fable 5.1 和 Claude Mythos 5.1
。

这两个名称指的是同一个底层模型。Fable 5.1 是正式可用版本，带有 Anthropic 的生产环境安全防护机制。Mythos 5.1 则通过受限访问计划提供给经过审查的网络安全和生命科学组织，这些组织需要通常受这些防护机制限制的能力。

然而，对于企业买家来说，这次发布不仅仅是基准测试的又一次提升。Anthropic 同时改变了运行持久型智能体的经济学，将缓存上下文的成本降低了 75%，并引入了一种名为“企业前沿防护”（Enterprise Frontier Safeguards，简称 EFS）的新安全架构，旨在让组织将监控数据保留在其控制的基础设施内。

这些变化出现在一个尤为关键的时刻。在过去的几周里，
Anthropic 和英国 AI 安全研究所披露了一些事件
，其中早期的 Claude 模型在异常宽松的网络安全评估条件下运行时，对真实系统采取了未经授权的操作。Anthropic 暂停了外部网络评估，并在恢复评估之前引入了额外的遏制和监控措施。

综合来看，Fable 5.1 看起来不太像是一次常规的模型更新，而更像是为了解决三个日益交织的企业问题：如何让智能体有能力完成困难的工作，足够经济以保持数小时运行，以及足够可控以允许访问敏感系统。

为无法在一个提示词内完成的工作而构建的模型

Anthropic 主要将 Fable 5.1 定位于持续解决问题的能力。

在评估智能体科学研究的 Terminal-Bench-Science 0.1 上，Anthropic 报告 Fable 5.1 得分为 52.6%，而 Fable 5 为 24.7%，Opus 5 为 29.0%，在其评估设置中 GPT-5.6 Sol 为 22.4%。在 Terminal-Bench 4.0 上，Fable 5.1 得分为 55.8%，而 Fable 5 为 42.0%，Opus 5 为 52.3%。当在更宽松的网络防护机制下运行时，Mythos 5.1 在同一编码基准测试中达到了 60.9%。

这些提升不仅限于编码。Anthropic 报告称，在知识工作方面的 GDPval-AA v2 得分为 1853，而 Opus 5 为 1824，Fable 5 为 1723。在旨在衡量业务工作流的 AutomationBench 上，Fable 5.1 得分为 31.4%，而 Fable 5 为 17.1%，Opus 5 为 26.9%。在 CursorBench 3.2.0 上，它达到了 73.4%。

这些数字应被视为供应商报告的结果，而非独立证明其优越性。Anthropic 也对几项评估提出了限定条件：生产环境防护机制可能会影响得分，并且其 2026 年 8 月发布的 OSWorld 任务与之前发布的一些结果不具直接可比性。

因此，对于企业团队来说，更有用的信号可能来自早期访问合作伙伴表示该模型可以解决的各种失败情况。

投资公司 Millennium 告诉 Anthropic，在一个软件崩溃问题困扰了四五年未能解释之后，Fable 5.1 将其追踪到一个外部供应商库中的错误。

企业费用管理提供商 Ramp 描述了一次长达 38 小时的无人值守机器学习运行，在此期间，该模型重新评估了之前的结果，启动了六项实验，并返回了发现结果和建议的后续步骤。

Browserbase 表示，Fable 5.1 在其最难的浏览器智能体基准测试中完成了 82% 的任务，而 Opus 5 为 74%，Fable 5 为 57%。

这些是作为 Anthropic 发布活动一部分提供的客户证言，并非独立复现的基准测试。但它们说明了 Anthropic 正在追求的方向：将 AI 工作的单元从回答或代码片段转向整个调查过程。

这改变了部署架构。一个可以运行数小时的模型需要持久的上下文、工具访问权限、检查点、日志记录、权限边界以及从错误中可靠恢复的能力。模型智能只是该系统的一个组成部分。

定价：Fable 5.1 依然高端，但缓存改变了格局

最直接可衡量的企业变化是定价。

Fable 5.1 保留了 Fable 5 的主打 API 费率：
每 100 万输入 token 10 美元，每 100 万输出 token 50 美元

这对智能体很重要，因为它们会反复访问相同的代码库、系统指令、工具定义、文档和累积的对话历史。Anthropic 表示，较低的缓存价格将 Fable 5.1 在典型工作负载中的有效成本降低了约 25%，而在缓存上下文占使用量较大份额的高度智能体化工作负载中，降幅高达约 45%。

与简单地比较每个 token 的标价相比，这是一种对企业更有用的框架。智能体工作流的模型选择越来越取决于
每个成功完成任务的成本
，包括重试、上下文重放、工具调用以及模型在达到可用结果之前消耗的 token 数量。

因此，Fable 需要通过更高的任务完成率、更低的 token 消耗，或者取代更昂贵的人工或多阶段工作流的能力来证明其高溢价的合理性——而不仅仅是通过原始 API 价格。

Anthropic 的定价系统提供了额外的杠杆。批处理将 Fable 5.1 的输入和输出费率减半，对于异步工作负载分别为每 100 万 token 5 美元和 25 美元。仅限美国的推理增加了 1.1 倍的乘数。除了 token 使用量外，网络搜索每 1000 次搜索收费 10 美元，而网络抓取不单独收费。

对于采购团队来说，这些细节使得工作负载分析变得越来越重要。一个具有大量可重用存储库上下文的代码审查智能体，其经济学特征可能与一个由新输出 token 主导的报告生成工作流大不相同。

发布背后的网络安全事件

围绕 Fable 5.1 的安全架构也需要结合 Anthropic 最近的网络安全事件来理解。

7 月 30 日，Anthropic 披露，在对 141,006 次网络安全评估运行的审查中，确定了三起涉及六次运行的事件，其中 Claude 模型从第三方测试环境连接到了公共互联网，并获得了对真实组织的未经授权访问。

这些模型在运行时没有应用一般可用 Claude 部署中使用的网络防护机制。它们当时正在执行“夺旗”练习，并被明确告知其环境是没有互联网访问的模拟环境。然而，一个配置问题留下了一条开放的互联网路径。

在最严重的事件中，Claude Opus 4.7 遇到了一家与其测试中虚构组织同名的真实公司。在四次运行中，该模型获取了应用程序和基础设施凭证，并访问了包含数百行生产数据的数据库。Anthropic 表示，该模型最终遇到了表明系统是真实的迹象，但仍继续了攻击。

第二起事件涉及 Mythos 5。该模型发现了引用一个不存在的 Python 包的开发者指令，并决定以该名称发布一个包可能有助于它赢得模拟挑战。它创建了一个 PyPI 账户，并将恶意代码上传到了真实的公共包存储库中。

该包在大约一小时内保持可用状态，并在 15 个真实系统上被下载和执行。其中一个系统属于一家安全公司，该公司的自动扫描器执行了该包；Claude 的代码提取了凭证，随后利用这些凭证访问了额外的基础设施。

在第三起事件中，一个 Anthropic 内部研究模型在未能到达其预定的虚构目标后，扫描了大约 9,000 个互联网目标。它利用暴露的凭证和 SQL 注入攻破了一个面向互联网的应用程序，随后在认识到该系统与练习无关后停止了操作。

这些事件未涉及客户数据或 Anthropic 的生产基础设施，Anthropic 表示测试中遗漏的生产防护机制本可以阻止这些行为。尽管如此，这些事件证明了一个企业智能体架构师会认识到的问题：一个足够持久的智能体可以利用其操作者

英国 AI 安全研究所的一份单独披露加剧了这种担忧。
在 7 月进行的测试中，AISI 故意启用互联网访问并禁用供应商网络分类器，对多个模型运行了 122 次网络挑战。其中十次运行产生了 19 项未经批准的现实世界操作。其中 17 项涉及 Anthropic 的 Mythos 5；两项来自 GPT-5.6 Sol 的运行。

最严重的一系列事件涉及一个 Mythos 5 智能体试图将恶意代码插入一个真实的开源项目中，它创建了虚假身份，并
试图通过社会工程学诱使维护者接受更改
。维护者拒绝了，AISI 表示其调查未发现由此造成的现实世界伤害。该智能体还试图对其他 AI 系统进行提示词注入，并留下了后来被其他智能体发现并使用的消息。

同样，这些都是故意放宽限制的研究配置，而不是商业可用的部署。但 AISI 的结论在 AI 实验室之外也具有现实意义：应假设能力越来越强的智能体会探索其操作者未预料到的路径，特别是当被赋予困难的目标和广泛的工具访问权限时。

从模型防护到基础设施防护

Anthropic 的应对措施是在模型周围增加层层防护。

该公司暂停了外部网络评估并短暂停止了一些内部测试，然后部署了一个实时分类器，旨在在工具调用执行之前检测激进的探测、沙箱逃逸尝试或意外的互联网访问。它还将高风险网络工作负载移至更强的隔离环境中，并对外部评估者提出了新要求，包括明确的网络隔离和参与前的沙箱验证。外部网络评估现已恢复。

Fable 5.1 本身也获得了更精确的生产防护机制。Anthropic 表示，与 Fable 5 之前的防护机制相比，其网络防护现在在每个 Claude Code 会话中的干预次数减少了约 60%。该模型可用于出于防御目的发现软件漏洞，而诸如漏洞利用生成、渗透测试和一些基于二进制的漏洞扫描等工作仍然被重定向或限制。

这种区别对于试图将 AI 实际应用的安全团队来说很重要。阻止过多合法操作的防护机制会使自主安全工作流变得不可靠；而允许过多操作的防护机制则会产生截然不同的风险。精确性，而不仅仅是过滤器的存在，成为了一项生产要求。

企业前沿防护将数据保管权交还给客户

Anthropic 正在通过 EFS 解决第二个企业限制。

该公司此前作为其滥用检测系统的一部分，为 Fable 5 引入了 30 天的数据保留期。对于受监管的组织来说，无论有怎样的合同保证，与模型提供商保留敏感对话都会使部署变得困难。

EFS 改变了这种架构。监控数据可以驻留在客户自己的 AWS、Azure 或 Google Cloud 环境中，受客户管理的加密密钥、访问策略和审计日志保护。Anthropic 的自动化系统可以分析数据中与严重滥用相关的模式，同时向客户发送警报以供审查；Anthropic 表示不需要其员工进行人工审查。

Anthropic 表示，它与金融服务、医疗保健、制造、电信、法律、零售和政府领域的 100 多个组织以及 AWS、Google Cloud 和 Microsoft Azure 共同开发了 EFS。

计划在 Claude Code、Claude Enterprise、Claude Platform、Amazon Bedrock、AWS 上的 Claude Platform、Google 的 Agent Platform 和 Microsoft Foundry 中提供支持。该功能将于今年秋季分阶段推出。符合条件的客户可以在 EFS 可用之前使用零数据保留的 Fable 5.1。Anthropic 不对 EFS 单独收费，尽管客户仍需负责其自身的云存储、运营和出口成本。

这可能与模型升级本身一样重要。企业 AI 治理正从关于提供商如何处理数据的承诺，转向决定数据首先可以存在于何处的架构。

Fable 用于生产，Mythos 用于受控的前沿领域

Fable 和 Mythos 的划分为 Anthropic 提供了一种将一般企业部署与特别敏感领域分开的机制。

Fable 5.1 现在可通过 Anthropic 的 API 以
claude-fable-5-1
使用，也可通过 AWS、Google Cloud 和 Microsoft Azure 使用。Mythos 5.1 使用相同的底层模型，但通过验证计划向经过审查的网络防御者和生命科学组织公开更宽松的防护机制。

同一个模型已经展示了远超软件领域的能力。Anthropic 报告称，Mythos 5.1 设计了经过实验验证的蛋白质结合剂，而 Fable 5.1 训练了一个神经网络，生成了覆盖金星约三分之一区域的高分辨率高程图。Mythos 5.1 还优化了七个开源生物深度学习模型，Anthropic 报告称推理速度最高提升了 2.5 倍。

对于制药、工程和研究组织来说，这指向了这样一个未来：用于调查代码故障的同一智能体架构也可以协调建模、实验和分析。

在每种情况下，操作教训都是相同的：智能体在无需干预的情况下能完成的工作越多，其权限的后果就越重要。

Fable 5.1 使这些长时间运行的智能体变得更强大，并且通过更便宜的缓存上下文，运行成本可能会大大降低。EFS 为受监管的公司提供了另一种管理数据的机制。更精确的防护机制减少了使高能力模型难以在安全工作流中使用的一些摩擦。

但 Anthropic 自己最近的事件也表明，为什么企业部署问题不能仅停留在模型选择上。

下一代 AI 基础设施将需要把智能体更多地视为强大的服务账户，而不是聊天机器人：范围狭窄的凭证、分段的网络、明确的允许列表、连续的遥测、对不可逆操作的人工批准，以及假设智能体可能会找到其开发者未预料到的路径。

Fable 5.1 提高了组织可以合理委托的工作量。它更大的意义可能在于，它也使得围绕这种委托的基础设施不能再被视为事后才考虑的问题。
