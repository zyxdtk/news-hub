摘要。
软件和系统安全工作流通常是程序化的：分析师检查异构工件，形成假设，调用工具，解释输出，并修改计划。基于大型语言模型（LLM）的智能体能够跨多步工作流进行规划、使用工具、保持状态和修改行动，目前正被迅速采用以实现这些工作的自动化。鉴于将安全决策委托给自主系统所带来的后果，理解这些智能体是如何构建、使用和评估的至关重要。然而迄今为止，对于这一领域已经取得了哪些成果以及我们处于什么阶段，仍然缺乏系统的理解：“智能体”一词的应用不一致，应用的风险差异很大，而且评估协议往往无法比较。为了获得对该领域全面且连贯的视图，从而为相关的未来研究提供信息，本文对同行评审文献（涵盖该领域出现的 2023–2026 年）进行了系统的文献综述，包括 (1) 技术方法，包括智能体架构、感知、记忆、推理与规划、动作空间、编排和自我改进；(2) 应用，涉及所服务的安全任务；以及 (3) 评估，包括所考虑的数据集、结果和轨迹指标、安全措施以及基线。我们的综合分析揭示了一个现状：该领域已经构建了能够采取行动的智能体，但尚未构建出权限受到限制或行为可审计的智能体。除了知识系统化之外，我们还将我们的见解扩展到当前方法、应用和评估设计的局限性和面临的挑战，这为未来潜在的有前景的研究方向提供了启示。

1.
引言
软件和系统安全越来越依赖于对异构工件的推理：源代码、二进制文件、配置、日志、漏洞报告、执行跟踪、网络服务、工单以及人类编写的策略。安全工作也具有内在的程序性。分析师很少通过孤立地产生一个答案来解决任务；他们检查证据，形成假设，调用工具，解释输出，修改计划并交流发现。这使得安全成为大型语言模型的一个自然但要求苛刻的设置。现代 LLM 可以解释代码和自然语言，但许多安全任务需要的不仅仅是文本生成。它们需要能够规划、使用工具、维护任务状态并在多步工作流中行动的系统。
基于 LLM 的智能体提供了满足这一需求的一种回应。在更广泛的 AI 文献中，智能体 LLM 系统已被开发用于交织推理和行动、调用外部工具并在交互环境中运行
(
Yao et al., 2023
;
Schick et al., 2023
)
。在软件工程中，诸如 SWE-bench 之类的基准表明，实际任务通常需要仓库级别的上下文、环境交互和迭代修复，而不是孤立的代码完成
(
Jimenez et al., 2024
)
。这些特征在安全领域更为显著。漏洞分析智能体可能需要检查仓库、跟踪数据流、查询漏洞数据库、运行概念验证并解释可利用性。渗透测试智能体可能需要执行侦察、选择工具、解释命令输出并适应失败的尝试。修复智能体可能需要定位缺陷、合成补丁、运行测试并保留功能。安全运营中心（SOC）智能体可能需要关联警报、丰富证据、减少幻觉并生成面向分析师的叙述。
最近的研究反映了从作为答案生成器的 LLM 到作为运营安全智能体的 LLM 的转变。诸如
PentestGPT
(

)

(

)

CVE-Bench
(
Zhu et al., 2025
)
在可执行的漏洞环境中评估智能体。

(
Guo et al., 2025
)
研究仓库级别的漏洞审计，而
PatchAgent
(
Yu et al., 2025
)
则针对漏洞修复。
Cognitive SOC
(
Sheikhi et al., 2025
)
说明了多智能体设计如何支持基于证据的安全运营。这些例子展示了当前工作的广度：基于 LLM 的智能体正被应用于漏洞检测、漏洞利用开发、红队测试、模糊测试、恶意软件分析、逆向工程、事件响应和访问控制评估等众多领域。
与此同时，基于 LLM 的安全智能体的兴起引入了新的科学和实践挑战。首先，“智能体”一词的使用不一致。一些论文将单个使用工具的 LLM 描述为智能体；另一些则构建具有规划器、执行器、评论器、记忆、检索和策略层的多智能体系统。其次，安全应用的风险差异很大。一个总结警报的智能体与一个执行漏洞利用、扫描面向互联网的资产、修补生产代码或更改访问控制策略的智能体具有不同的安全特征。第三，评估很困难。最终任务的成功很重要，但它并不能说明智能体是否忠实地使用了证据、是否保持在范围内、是否避免了幻觉、是否尊重了工具权限，或者是否消耗了实际的时间和金钱。
这些问题使得如果没有系统的组织，文献就很难解释。现有论文在架构、自主级别、记忆设计、工具接口、安全目标、数据集、基线和报告的指标方面各不相同。一些专注于端到端的攻击工作流；另一些专注于仓库审计、修补、SOC 支持、网络防御模拟或基准构建。一些针对真实世界系统或可执行环境评估智能体，而另一些则使用合成任务、精选数据集或受限工件。然而迄今为止，对于这一领域已经取得了哪些成果以及我们处于什么阶段，仍然缺乏系统的理解。如果没有一个共享的分类法，就很难比较智能体是如何构建的、确定它们服务于哪些安全任务以及哪些任务仍然未被充分探索，或者判断报告的结果是否可重现、安全且可跨研究比较。
为了解决这一差距，我们系统性地回顾了 100 篇关于用于软件和系统安全的基于 LLM 智能体的同行评审论文，发表时间从 2023 年 1 月到 2026 年 3 月——这一窗口涵盖了这一新兴领域的整个历史，因为作为这些智能体底层模型的功能强大的 LLM 直到 2022 年底才出现。我们从三个维度组织文献：
方法
捕获智能体架构、感知、记忆、推理与规划、动作空间、编排和自我改进；
应用
捕获所服务的安全任务；以及
评估
捕获数据集、结果和轨迹指标、安全措施、基线和实验协议。
本综述做出三个主要贡献：
•
我们提供了一个广泛的文献搜索和选择协议，产生了涵盖该领域出现的 100 篇同行评审论文语料库。
•
我们推导并应用了一个分类法，从方法、应用和评估三个方面对综述文献进行表征，从而能够对智能体设计、安全任务、数据集、指标和基线进行结构化比较。

2.1.
基于 LLM 的智能体
大型语言模型（LLM）是在大规模文本语料库上训练的神经网络，能够生成、解释和推理自然语言和代码
(
Zhao et al., 2023
)
。基础规模的 LLM——包括 GPT
(
OpenAI, 2023
)
、Claude
(
Anthropic, 2024
)
、Gemini
(
Gemini Team, Google, 2023
)
以及 LLaMA
(
Touvron et al., 2023
)
和 DeepSeek
(
DeepSeek-AI, 2024
)
等开放权重模型——在与适当的提示策略一起使用时，在代码理解、程序修复和安全推理方面展示了广泛的能力。
基于 LLM 的智能体
将独立的 LLM 扩展为一个面向任务的系统，该系统能够感知其环境、对观察结果进行推理、规划多步行动、调用外部工具并从反馈中学习
(
Wang et al., 2024
)
。虽然纯粹的 LLM 处理单个提示并返回单个响应，但智能体在循环中运行：它观察当前状态（例如，工具输出、代码上下文、警报数据），选择一个动作（例如，运行扫描器、查询知识库、生成补丁），执行该动作，然后对结果进行推理以决定下一步。这种观察-推理-行动循环可能会重复多次迭代，然后智能体才会产生最终输出。
有几个组件将智能体与独立的 LLM 使用区分开来：
智能体架构。
智能体可以是单个自主实体，也可以是多个智能体协调的团队。单智能体设计在一个模型中处理整个任务循环，而多智能体设计将任务分解为通过消息传递、共享内存或分层委托进行通信的专门智能体。
记忆。
智能体通过上下文工作记忆（当前提示窗口）、外部短期记忆（例如，存储在上下文之外的探索轨迹）和长期或持久记忆（例如，先前发现的向量数据库、已发现资产的知识图谱）跨步骤保持状态。记忆实现了连续性：智能体可以记住它已经扫描了什么、哪些假设失败了，以及什么证据支持当前的发现。
感知。
感知涉及原始工件——源代码、二进制反汇编、执行跟踪、日志条目、网络数据包、警报记录——如何转换为 LLM 的推理就绪上下文。常见机制包括直接摄取到提示中、从外部语料库进行检索增强生成（RAG）、冗长工具输出的摘要以及基于嵌入的语义匹配。
推理和规划。
智能体采用各种推理范式来决定下一步做什么。ReAct
(
Yao et al., 2023
)
交织推理、工具行动和观察。思维链
(
Wei et al., 2022
)
使中间推理显性化。反思和自我批评允许智能体在继续之前评估自己的中间产品。规划策略包括动态/反应式规划（根据新的观察修改步骤）、分层任务分解（将高层目标与低层执行分离）以及失败时回溯。
动作空间和工具。
动作空间定义了智能体可以调用的操作：静态分析工具（linter、污点分析器、形式化验证器）、动态分析工具（fuzzer、调试器、执行沙箱）、代码执行环境（shell、编译器、容器）、信息检索工具（代码搜索、文档检索、RAG）以及安全特定平台（CTF 环境、渗透测试框架、SIEM/SOAR 系统、MITRE ATT&CK 集成）。动作空间的广度很大程度上决定了智能体可以处理哪些安全任务。
自我改进和学习。
一些智能体通过会话反馈的上下文学习、跨会话轨迹存储、已解决任务的微调或基于环境奖励信号的强化学习来随时间调整其行为。这些机制允许智能体在重复任务上改进，而无需手动进行提示工程。
2.2.
软件和系统安全
软件和系统安全包括保护软件工件、计算基础设施和网络环境免受损害其机密性、完整性或可用性的威胁
(
Anderson, 2020
)
。安全生命周期跨越了一系列广泛的任务，从主动分析到被动响应：
漏洞发现和管理。
这包括对源代码、编译二进制文件、智能合约、API 和基础设施配置中软件弱点的检测、定位、分类、优先级排序和跟踪。传统方法依赖静态分析、动态测试和手动代码审查；基于 LLM 的智能体通过对代码上下文的自然语言推理、自动假设生成和迭代细化来增强这些方法。
攻击性安全。
渗透测试、红队测试、漏洞利用开发和对抗模拟通过主动尝试破坏已部署系统来评估其弹性。这些任务本质上是交互式和多步骤的，使其成为能够规划、执行和调整攻击策略的智能体工作流的自然选择。
防御监控和响应。
入侵检测、事件响应、日志分析、异常检测、威胁情报和 SOC 工作流监控已部署系统是否存在主动或近期的入侵。这个领域的智能体对异构运行时遥测数据——日志、警报、网络流——进行推理，并且必须将信号关联为可操作的防御决策。
低级工件分析。
二进制分析、逆向工程、协议推断和恶意软件分析对源代码级别以下的工件进行推理。这些任务要求智能体通过将 LLM 推理与既定的分析工具相结合，来弥补缺失的结构——没有源代码、没有规范，或者只有外部可观察的行为。
修复和加固。
自动程序修复（APR）、补丁生成、代码加固和安全策略执行产生防御性修改，以关闭已知的弱点或防止未来类别的漏洞。智能体方法通过将故障定位、补丁合成和验证集成到一个单一的迭代循环中，扩展了传统的 APR。

4.1.
阶段 1
我们在 Google Scholar 和主要学术出版门户/数字图书馆（如 ACM DL、IEEE Xplore、Scopus 和 DBLP）上广泛搜索所有潜在相关的研究论文。我们使用以下两组主题相关关键字及其（成对）组合作为查询：

我们使用这些查询，因为它将智能体相关术语与常见的软件/系统安全任务相结合，包括漏洞检测、渗透测试、漏洞利用分析、模糊测试、安全测试、漏洞评估、入侵检测、恶意软件检测和网络攻击。

4.2.
阶段 2
为了提高关键字匹配之外的覆盖率，我们从 48 篇种子论文开始进行了手动的前向和后向雪球法。后向雪球法识别了种子论文引用的相关论文，而前向雪球法识别了引用它们的后续论文。在此过程中，我们考虑了每篇候选论文是否涉及基于 LLM 的智能体，以及其任务是否涉及软件或系统安全。
雪球阶段将候选池扩大到 144 篇论文。然后这个池被传递到下一阶段。

5.3.1.
方法
在这个方面，我们表征用于软件和系统安全的基于 LLM 的智能体在技术上是如何构建和运行的。如表
2
所述，我们识别了七个属性。前三个属性，
智能体架构
、
智能体感知
和
智能体记忆
，描述了智能体的结构基础。智能体架构捕获系统是单智能体还是多智能体、其内部组件是如何组织的以及骨干 LLM 扮演什么角色。智能体感知捕获智能体通过哪些输入和观察机制来理解代码、日志、二进制文件、轨迹、环境或自然语言工件。智能体记忆捕获在任务期间或跨任务如何保留、检索、更新和重用安全相关信息。
其余属性描述了智能体随时间如何行动。
智能体推理与规划
记录了用于推导和修改决策的推理范式、规划策略和不确定性处理机制。
智能体动作空间
指定了智能体可用的工具和外部操作，包括分析工具、执行环境、检索系统、安全平台、智能体间通信和人机交互。
智能体工作流与编排
捕获过程结构，例如顺序、迭代、并行、分层或人机参与的工作流。最后，
智能体自我改进与学习
记录了智能体是否从反馈中适应、存储成功的轨迹或通过奖励驱动的交互进行改进。这些属性共同将 LLM 安全智能体视为一个运营系统，而不是一个单一的提示-响应模型。
5.3.2.
应用
在这个方面，我们检查了基于 LLM 的智能体所应用的具体安全任务。由此产生的分类法包含十一个应用领域。几个领域遵循漏洞生命周期：
漏洞检测与分析
涉及发现、定位、分类、分类或解释弱点；
漏洞利用开发与分析
涉及构造、链式组合、检测或分析漏洞利用；
渗透测试与红队测试
涵盖分阶段或端到端的攻击性评估；以及
漏洞修复与加固
解决修补、验证、安全编码、代码审查和防御性加固。
其他领域捕获专门的安全分析任务和运营防御。
模糊测试与测试生成
、
恶意软件分析与检测
和
逆向工程
涵盖测试、恶意代码分析以及低级软件或协议理解。
入侵与威胁检测，事件响应
、
访问控制与身份验证评估
和
威胁情报与安全运营
捕获防御监控、警报分类、访问策略评估、威胁情报合成和分析师支持工作流。最后，
模型攻击生成与鲁棒性评估
说明了 LLM、ML 组件或智能体工作流本身成为安全评估目标的工作。这些领域按任务目标组织，因此即使不同的论文使用不同的架构、数据集或工具，它们仍然适用。
5.3.3.
评估
在这个方面，我们检查了综述工作如何评估基于 LLM 的安全智能体。由于这些智能体通常通过多步轨迹行动，评估不能局限于最终答案的正确性。因此，我们围绕数据集和指标组织评估。对于数据集，
数据集来源
区分了真实世界的主题与合成或受控环境，而
数据集特征化轴
记录了现实性、标签质量、规模、工件形态、漏洞覆盖率和可访问性等属性。
按安全任务划分的数据集
进一步指示了数据集支持哪个应用领域，例如漏洞检测、渗透测试、修复、网络防御模拟、恶意软件分析或 SOC/SOAR 工作流。
对于指标，我们区分了面向结果、面向安全、面向过程和比较性的测量。
任务有效性指标
捕获智能体是否达到了预期的安全结果，例如成功检测、利用、修补、覆盖或报告生成。
安全性与可靠性指标
捕获智能体在对抗或高影响条件下是否保持鲁棒、有界和一致。
智能体过程/轨迹指标
评估智能体如何达到其结果，包括工具调用、幻觉、成本、迭代、工件和解释。最后，
比较与基线指标
记录了结果是否与非 AI 工具、先前的 ML/DL 方法、没有智能体脚手架的纯 LLM、人类、其他智能体系统或消融变体进行比较。
