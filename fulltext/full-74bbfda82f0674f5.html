使用 Cursor 的模式有：
1. 在右侧边栏使用 Agent 模式描述一个功能或 bug。
2. 在编辑器中查看 diff + 使用 AI 自动补全。
我会审查 Agent 输出的每一行代码。而且我发现我自己经常需要编辑代码。Agent 输出的代码仍然过于冗长，有时甚至无法维护。
价格也很不错。20美元/月非常合理。

需要改进的地方

我发现了 Auto 模型模式的 3 个问题（与选择特定模型相比）：
1. 它可能非常冗长。在这方面 @Claude Code 要好得多。
2. 在复杂问题上会失败。遇到这些问题时，我最终都会手动选择 gpt-5。
3. 有点慢。搭配 Grok Code 的 @opencode 在处理简单提示词时似乎至少快了 10 倍。
另外，我不喜欢使用过时的 VS Code 分支。我一直在考虑切换到 VS Code + @Github Copilot 扩展，因为这样我就能使用最新的原生 VS Code。
最后，Cursor 几乎每天都要求更新，这需要重启。我喜欢使用最新的软件。但频繁重启非常烦人。我在编辑器内置终端中运行开发服务器。因此，每次重启编辑器时，我都需要重新启动开发服务器。

评分

上下文感知 (13)
Cursor 非常出色，因为它将 AI 深度整合到了核心编码工作流中，而不是将其视为一种外部工具。它能够理解项目上下文、代码结构以及开发者的意图，从而在编辑器内部直接实现精准的代码生成、重构和导航。通过显著减少上下文切换并加速问题解决，Cursor 帮助开发者更快速、更自信地编写、理解和迭代代码。

需要改进的地方

订阅成本 (6)
尽管 Cursor 功能强大，但仍有一些需要改进的地方。在大型或复杂的代码库中，上下文选择有时不够精确，导致建议的相关性降低。对 AI 正在使用哪些文件和符号提供更透明的控制，将有助于开发者更好地引导模型。此外，针对长时间运行会话的性能优化，以及在 AI 置信度较低时提供更清晰的反馈，将进一步提升信任度和可用性。

对比替代方案

我选择 Cursor 是因为它以深度上下文感知且适用于实际开发的方式，将 AI 直接整合到了编辑器中。与独立的 AI 工具不同，Cursor 能够理解代码库的结构，并支持跨文件的重构、调试和推理等任务。这使其成为开发工作流的自然延伸，在显著减少上下文切换的同时，提高了整体生产力。
