平价闭环物理操作评估：3.5美元GPU的价值

原标题：Closed-Loop Physics-Based Manipulation Evaluation at a Commodity Price: What 4.4 L4 GPU hours at $3.50 Buys You

中文摘要： 本文提出可复现的无服务器评估工具封装，在商品级GPU上以约3.50美元、38分钟完成200次rollout闭环物理操作评估（4.4个L4 GPU小时、8个并行分片）。作者据此报告稀疏数据下动作分块的负面结果：三个独立训练的分块检查点在780次rollout中零真实成功，单步检查点成功率为2.6%–11.8%，失败被定位到分块预测而非开环执行。整个研究复现成本约34美元，为资源有限的团队提供低成本评估方案。

摘要

以统计规模运行接触丰富的机器人操作评估，此前基本上只有资源充足的实验室才能实现，这凸显了为更广泛受众提供经济高效方案的必要性。我们提出了一种可复现的评估工具封装，基于先前研究，在无服务器商品级GPU上以200次rollout的规模进行评估，每次重复的成本约为3.50美元、实际耗时38分钟（跨八个并行分片共计4.4个L4 GPU小时）。利用该工具，我们报告了一项关于稀疏数据下动作分块的部分受控负面结果：三个独立训练的分块检查点在780次rollout中未产生任何真实成功，而三个单步检查点的成功率介于2.6%至11.8%之间。逐步重规划控制部分地将分块预测（而非开环分块执行）隔离为失败机制，失败被定位到训练方案与多步预测。本工作通过我们的可复用工具进一步普及了基于物理的策略开发与评估。

I 引言

高保真基于物理的仿真 [1,2,3,4,5,6,7] 的进步，加上经济高效的GPU访问，为顶尖机器人学术与工业实验室之外的更广泛受众创造了独特机会，使其能够攻克接触丰富的机器人操作中的难题。GPU访问历来是一个瓶颈 [8]，但 Modal 等服务最近使得访问GPU集群变得经济且便捷，无需在 Azure、Amazon Web Services 和 Google Cloud Platform 等主要云服务商上处理配额、网络和 IAM 权限等问题。此外，该领域的仿真基准越来越多地以 Python 包的形式分发（例如 [1]），与其他语言编写的包相比拥有庞大的用户群体。机器学习领域的可复现性文献将环境与依赖重建列为首要技术障碍 [9]，但其所涉及的具体工作却很少被记录。在我们的案例中，这意味着GPU容器配置、无头渲染设置以及策略服务管道的搭建。

在本研究中，我们搭建了一个评估工具封装，在无服务器商品级GPU上端到端地运行 Barreiros 等人 [1] 的基准，针对单个仿真任务训练了我们自己的策略，并以每次3.49美元、38分钟实际时间的成本运行了重复的200次rollout闭环评估。（该基准自身的文档指出，基于CPU的OpenGL栈会产生非常慢的评估吞吐量，这使得GPU访问成为该工作负载的实际先决条件，而非一种优化。）得益于经济高效的GPU访问，我们的瓶颈并非算力，而是未被记录的环境要求——一个EGL供应商ICD文件、资产下载脚本中的解释器路径假设，以及在训练与服务之间发生漂移的检查点格式。我们的贡献是：(1) 发布了一个无服务器评估工具封装与报告协议，用于以商品级成本对仿真任务进行200次rollout闭环评估；(2) 一项受控实验，表明当训练数据稀疏时，动作分块会降低策略性能。

II 方法

II-A 扇出架构

我们选择将评估工具封装基于 Barreiros 等人 [1] 构建，因为它是迄今为止对仿真和现实世界大型行为模型在统计上最严格的评估之一，提供了一个现实的基于物理的基准，需要GPU来高效训练和评估策略。Barreiros 等人 [1] 在 Drake 桌面双臂操作仿真中使用了两个 Franka FR3 机器人手臂。我们在 pick_and_place_box 上进行评估，这是 lbm_eval 基准 GitHub 仓库附带的一项技能，并被其 README 推荐为起点 [1]。任务 pick_and_place_box 评估右 Franka 手臂能否在15秒内成功拾起桌上随机放置的盒子并将其放入桌子中央的圆形区域（见图2）。该任务未出现在论文的仿真评估套件中（Barreiros 等人 [1] 表S2），且论文未报告其成功率，这使其非常适合基础设施与消融研究工作。

我们的评估以无服务器扇出方式运行于 Modal 上的容器（图1）。Drake 的模型资产在构建时被烘焙到容器镜像中，渲染在 Xvfb 下通过 EGL/OpenGL 无头运行。一次重复通过不相交的场景索引切片进行分片，每个容器一个分片；由于该工具从每个rollout的索引派生其随机种子，各分片的并集可精确复现未分片的运行。在一个分片内，评估串行运行，因此并行性仅来自分片数量。策略由一个独立进程通过 gRPC 提供服务，该工具作为客户端连接到它，这将策略保持在工具之外，并使一个检查点无需重新训练即可在不同执行参数下提供服务。每个分片将每回合结果写入持久卷；聚合随后将其读回，因此没有任何结果依赖于调度进程在运行期间存活。有两个构建时步骤是必需的，但在任何地方都没有文档记录：GPU运行时挂载了 NVIDIA 驱动程序但未挂载用户空间 GL 库，因此镜像写入了 Drake 渲染器所期望的EGL供应商ICD文件；Drake 的资产下载脚本假设了基础镜像不使用的解释器路径，因此构建添加了一个经过验证的符号链接。其余技术栈为 Debian-slim 基础镜像、Python 3.12、四个公开的 lbm_eval wheel 包和 PyTorch。

II-B 报告协议

由于从 TRI 仓库 lbm_eval [1] 仅获得100个样本，我们训练的单任务策略成功率较低。为了应对可能左右结果的评估伪影，我们采用了三条规则：

R1： 记录为一秒以内完成的回合作为基准伪影被排除。200个场景中有五个（索引6、94、116、140、146）在策略有意义地行动之前约0.3秒即告成功，而所有失败都持续到15秒限制，验证了一秒规则。相同的五个、且仅有这五个，出现在我们保留结果的每次评估中，跨越两种解码器家族和多个独立训练的检查点，表明这是基准初始条件的属性而非任何策略的属性。所有结果均在由此产生的195个场景分母上报告。

R2： 每个声称的成功都通过视觉检查其录像来验证，从不仅凭工具标志判定。

R3： 结果报告为 N/195，并附带95% Wilson分数置信区间 [10]，相比正态近似更受青睐，因为它在比例接近零时仍表现良好。完整的每回合JSON被保留并发布。若省略R1，一个什么都不做的策略将仅凭伪影被报告为2.5%的成功率。

图2： 三行展示三个不同场景，各列展示 v1 基线下三次rollout的首帧和末帧。在每个场景中，策略指示右机器人手臂拾起红色盒子并将其放入桌面上圆形目标标记的内部，rollout被判定为成功或失败。在场景125中，手臂将盒子运送到目标标记上，rollout被评为成功。在场景3中，手臂伸向盒子、发生过冲，并在回合剩余时间内保持位置而未移动盒子。红色箭头为 Drake 水弹性接触力向量。场景6是初始条件将盒子直接置于目标上方的五个场景之一；它在双臂静止的情况下于0.3秒内记录成功，并根据R1被排除。各录像之间的相机位置略有不同。

II-C 策略描述

我们注意到，所有模型共享一个公共编码器：在单一相机视图上的 ImageNet 预训练 ResNet-18，与18维末端执行器位姿的多层感知机（MLP）嵌入相拼接，预测20维动作（双臂末端执行器的位置与6D旋转位姿，加上两个夹爪宽度）[2,11]。它们从相同的预处理数据（99个可用回合、4,203个关键帧）训练而来，仅在解码器家族和数对 (H,K) 上有所不同，其中 H 为每次推理预测的动作数，K 为重规划前执行的动作数：策略“v1”是 H=1 时使用均方误差（MSE）损失的行为克隆（BC）回归器；策略“v2a”是单步去噪扩散概率模型（DDPM），也在 Barreiros 等人 [1] 中被使用；策略 v2b 是 (16,8) 的分块DDPM；策略 v2b-bc 是 H=8 的分块BC回归器，与 v1 共享解码器家族，其目标从 v2b 的窗口中切片而来。带种子的行是独立训练的检查点，仅在初始化和批次顺序上有所不同；训练/验证划分在所有行中保持固定。作为参考，源套件中每个任务的演示数量从49到490不等，大多数任务为196。

III-B 稀疏数据条件下的负面结果

表II表明，多步预测与训练方案（包括动作分块）导致了策略性能崩溃：在四次评估和780次rollout中，没有任何分块检查点产生真实的完成，而所有三个单步检查点得分均高于零。我们在检查点级别而非汇总rollout层面报告这一结果，因为同一检查点内的rollout并非相互独立。在 K=1 下提供服务的分块训练策略（v2b-bc）成功率为0%，而所有三个 v1 检查点均具有非零性能，表明动作分块导致了性能退化。我们注意到，验证集MSE无法转化为成功率（相似MSE下成功率为2.6%对11.8%），且所有分块检查点均为0%。此外，使用规则R2（视觉检查）表明，基线策略因累积漂移而失败，而分块检查点因生成即使每步重规划也无法跟踪场景的轨迹而失败。

IV 结论与未来方向

我们提出了一个可复现的无服务器评估工具封装，使原始实验室之外的研究者能够以每次重复低于3.50美元、四十分钟的成本，在200 rollout规模上运行基于 Drake 的闭环操作基准。得益于 Modal 等经济实惠的无服务器GPU，算力并非障碍；未被记录的环境要求以及训练与服务之间的格式漂移才是限制所在。仔细地运行评估改变了原本会被报告的结果：200个场景中有5个在策略行动之前即告成功，而一个标准设计选择——动作分块——导致了三个独立训练检查点的策略性能崩溃，逐步重规划控制将损害部分定位在分块预测中。本研究仅覆盖一个任务、一个数据集规模和一个模型规模区间，分块结果不应被假定能推广到这些范围之外。动作分块在数据丰富的环境中得到充分支持 [11,12]，但在大约一百个演示、策略成功率仅为几个百分点的情况下，它可能在分块预测阶段而非执行阶段损害策略。未来研究应将工具扩展到其他单任务和多任务基准。该工具还将受益于引入新数据来训练更好的策略，包括使用 Castro 等人 [5] 的柔顺接触仿真来生成合成训练数据，以在 pick_and_place_box 等任务上创建成功率更高的策略，但转而应用于多任务学习。

我们的工作将使主要机器人实验室之外的更广泛受众能够准确评估自己的策略，从而服务于新的科学发现，并构建市场目前尚未考虑到的新应用和产品。我们相信，赋能这些研究者将带来快速的迭代，若没有我们的工具，这些迭代对他们而言将是缓慢的（或不可行的）。
