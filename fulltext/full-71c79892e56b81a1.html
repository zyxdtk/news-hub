语言模型的低比特 N 元组嵌入

Stephen Chung（所属机构：DualverseAI）
Wenyu Du（所属机构：DualverseAI）

摘要

近期许多开放权重的语言模型使用 n 元组嵌入表来提升性能。这些表存储短词元序列（如连续词元的二元组或三元组）的学习表示，模型在处理过程中检索这些表示。然而，它们可能需要大量内存：例如，DeepSeek-V4.1-Flash 为其 Engram n 元组记忆分配了 1960 亿个参数。因此，我们研究能否在保持这些表带来的性能提升的同时降低内存成本。我们提出以低精度存储 n 元组嵌入，并系统地研究了不同的量化方法和跨表的比特分配。在从头训练的 nanochat、Llama 和 GPT-2 系列模型上，四比特表可节省约 75% 的表内存，同时保留添加表所带来的验证损失改进的 99% 以上。使用更少的比特会导致更大的性能下降，但我们发现短暂的微调阶段可以恢复其中很大一部分损失。此外，将节省的内存重新投入到更大的表中，可以在使用更少内存的同时获得超越原始全精度表的性能。这些表内存节省也适用于大型现有模型：在 DeepSeek-V4.1-Flash 和 Qwen3.8-Flash-Next 上，低比特表节省了 47–55% 的表内存，困惑度增加不到 1.2%，下游任务性能基本保持不变。这些发现确立了低比特精度作为一种降低 n 元组嵌入内存需求的实用方法，并可利用节省的容量来提升模型性能。

脚注：本工作扩展了 rStation 智能体（https://rstation.ai/）在我们的自主研究计划（https://dualverse.ai/auto_research）中做出的经人工验证的发现。关于 AI 使用的讨论见第 6 节。

1 引言

近期研究表明，n 元组嵌入表可以在几乎不增加计算量的情况下提升语言模型性能 [1, 2]。这些表存储短词元序列（如连续词元的二元组或三元组）的学习表示。在每个位置，模型检索相应的表示以补充其对文本的处理。由于每次查找只访问少量嵌入，这些表可以在保持每词元计算量较小的同时增加大量模型容量。这种方法已被 DeepSeek 的 Engram 记忆采用，其在 DeepSeek-V4.1-Flash 中包含 1960 亿个参数 [3]。然而，存储这些大型表需要大量内存，这促使人们研究能以更小内存占用保持其性能优势的方法。

内存成本源于可能的词元组合数量巨大。为了容纳这些组合，现有方法将 n 元组映射到固定数量的表嵌入中，允许多个 n 元组共享同一嵌入 [1, 2]。更小的表迫使更多不相关的序列共享表示，这可能会降低它们对模型的益处。增加嵌入数量可以缓解这个问题，但需要更多内存。因此，我们研究了一种不同的降低表内存的方法：保留嵌入，但每个嵌入值使用更少的比特。这也带来了一个机会：如果较低的精度能保留表的大部分益处，节省的内存可以支持更多嵌入，最终提升性能。

我们提出通过以低精度存储每个值来压缩 n 元组嵌入表。在如此低的精度下，可表示值的选择会影响嵌入的保留程度。因此，我们系统地比较了均匀间隔值、从正态分位数中选择的值，以及使用 Lloyd–Max 量化 [4, 5] 拟合学习嵌入分布的值。我们还研究了二元组和三元组表是否能从不同精度级别中受益，从而可以根据它们对压缩的敏感度来分配比特。这些实验共同为选择量化方法和比特分配提供了实用指导，以平衡表内存和模型性能。

我们在从头训练的 nanochat、Llama 和 GPT-2 系列模型上评估了这种方法 [6, 7, 8, 9]。我们训练了带和不带 n 元组表的每个模型，以确定这些表对性能的提升程度。然后，我们将训练好的表压缩到不同精度，并测量节省的表内存和保留的改进。除了单纯压缩之外，我们还研究了短暂的微调阶段能否恢复失去的性能，以及将节省的内存重新投入到额外嵌入中能否超越原始全精度表。为了测试这些节省是否适用于大型现有模型，我们还压缩了 DeepSeek-V4.1-Flash 和 Qwen3.8-Flash-Next 中的表，节省了 47–55% 的表内存，同时基本保持了下游任务的性能。

我们的主要贡献如下：

  • 以极小的性能损失实现大幅表内存节省。 在三种模型架构上，三比特 n 元组表可节省 80% 的表内存，同时保留添加表所带来的验证损失改进的约 97%。我们还在 DeepSeek-V4.1-Flash 和 Qwen3.8-Flash-Next 中展示了大幅的表内存节省。
  • 关于量化和精度分配的实用指导。 我们系统地比较了码本构建、缩放因子拟合以及二元组和三元组表之间的精度分配。
  • 通过微调恢复性能。 短暂的微调阶段大幅减少了低比特压缩带来的性能损失，使激进压缩更加有效。
  • 通过重新投入节省的内存获得更好性能。 嵌入数量为四倍、以两比特存储的表，实现了原始表改进的 122–126%，同时仍使用少 46–48% 的表内存。这表明降低精度可以实现更大、更有效的 n 元组记忆。

2 方法

n 元组嵌入表。 遵循 Over-Tokenized Transformer [1]，我们使用四个嵌入表：两个用于二元组，两个用于三元组，如图 1 所示。这些表中的嵌入与语言模型联合学习，每行存储一个嵌入。在每个词元位置，以当前词元结尾的二元组和三元组各自从其对应的两个表中各检索一个嵌入。然后将这四个嵌入拼接并加到词元嵌入上。先前的工作表明，这种方法可以提高语言建模性能，且随着嵌入数量的增加还有进一步的增益 [1]。

形式上，令 x_t 表示当前词元，E 表示嵌入维度为 d 的词元嵌入矩阵，T_1, …, T_4 表示四个表。我们将模型输入构造为：

u_t = E[x_t] + Concat_{j=1}^{4} T_j[h_j(x_{t−n_j+1}, …, x_t)]， (1)

其中二元组表的 n_1 = n_2 = 2，三元组表的 n_3 = n_4 = 3。这里，哈希函数 h_j 通过将词元序列映射到表 T_j 中的地址来确定检索哪个嵌入。这些检索到的嵌入各自的维度为 d/4，因此将所有四个拼接起来得到与 E[x_t] 相同的维度。

低比特嵌入。 我们提出通过以低精度存储嵌入来降低这些训练表的内存成本。为此，我们为每个表提供一组最多 2^b 个代表值（通常称为码本），并用指向这些共享码本值的 b 比特索引来表示每个嵌入分量。为了考虑嵌入之间的幅度差异，我们还为每个嵌入存储一个 16 比特的缩放因子。在重建过程中，索引选择一个码本值，然后将其乘以嵌入的缩放因子。因此，嵌入 r 中位置 i 处的原始分量 w_ri 被重建为：

ŵ_ri = s_r · c_{q_ri}，q_ri ∈ {0, …, 2^b − 1}， (2)

其中 s_r 是缩放因子，c_k 是码本值 k，q_ri 是存储的索引（图 1b）。

这种低比特表示大幅减少了表内存。对于具有 p 个分量的嵌入，内存使用从 16p 比特降至 pb + 16 比特。例如，当 p = 128 时，两比特精度将每个嵌入所需的内存减少约 87%，从 2,048 比特降至 272 比特。

然而，二元组和三元组嵌入表示不同的上下文模式，因此它们可能需要不同的精度来保持对模型性能的贡献。因此，我们提出在两种 n 元组阶数之间使用混合比特宽度，在固定的表内存预算内，将更多比特分配给对量化更敏感的表。

选择码本值。 我们考虑三种码本族。首先，均匀码本使用等间距值。例如，在两比特时，码本值为 {−1, −1/3, 1/3, 1}。我们还测试了一个包含零的变体，使用 {−1, 0, 1}，以便可以精确表示零。其次，正态分位数码本从标准正态分布的分位数中取值，将更多值放在零附近。第三，我们使用 Lloyd–Max 量化 [4, 5] 从每个表的训练嵌入中学习码本值。

为了学习 Lloyd–Max 码本，我们首先用每个嵌入的均方根对其进行归一化，使不同幅度的嵌入可以共享码本。我们在归一化分量的分位数处初始化码本值，然后反复将分量分配给其最近的码本值，并用分配给它的分量的均值替换每个值。此拟合在压缩期间运行一次，仅使用训练好的嵌入。附录 A.2 给出了实现细节。

选择嵌入缩放因子。 一旦码本值确定，我们考虑三种方法来选择每个嵌入的缩放因子 s_r。首先，基于最大值的缩放将码本的最大绝对值与嵌入的最大绝对分量相匹配。其次，均方根（RMS）缩放使用嵌入的整体幅度，计算为 s_r = sqrt((1/p) Σ_i w_ri²)。第三，误差拟合缩放选择缩放因子以最小化原始嵌入与其重建之间的均方误差。我们比较这些选择，以考察缩放因子的选择如何影响压缩质量。

在确定码本值和嵌入缩放因子后，我们将它们与低比特索引一起存储，以替代原始嵌入表。在推理过程中，模型从这个存储的表示中检索嵌入，而无需重复拟合过程。

3 实验

3.1 实验设置

模型和数据。 我们从头训练五个语言模型：参数量分别为 26M 和 50M 的 nanochat、参数量为 30M 的 GPT-2 系列模型，以及参数量分别为 31M 和 322M 的 Llama 系列模型。默认情况下，每个模型使用四个 n 元组表，包括两个二元组表和两个三元组表，每个表约 262k 个嵌入。我们在 ClimbMix [10] 上训练，并用三个随机种子重复每个实验。附录 B.1 给出了模型配置和训练设置。

评估。 对于每个模型，我们首先使用相同的实验设置训练两个版本，一个带有全精度（16 比特）n 元组表，一个不带表。我们在保留的验证数据集上评估两者，它们的验证损失差异衡量了添加表带来的改进。然后，我们降低训练表的精度并再次评估模型，以测量保留了多少改进。我们将其报告为保留原始改进的百分比，其中 100% 对应全精度表，0% 对应不带表训练的模型。除这一性能指标外，我们还报告节省的表内存百分比。结果为三个种子的平均值，并在适当处显示标准差。

3.2 表内存节省与模型性能

我们首先问：在模型失去 n 元组嵌入的益处之前，可以移除多少表内存。我们使用带拟合缩放因子的 Lloyd–Max 码本将训练好的表压缩到一至四比特。为了测试更大的表是否能承受相同的压缩，我们还将 26M nanochat 模型和两个 Llama 系列模型中每个表的嵌入数量从默认的 262k 增加到 1M。

3.4 在大型现有模型上的评估

接下来，我们测试低比特压缩能否减少大型开放权重语言模型中 n 元组嵌入表使用的内存。我们评估了 DeepSeek-V4.1-Flash [3] 和 Qwen3.8-Flash-Next [11]，压缩它们的 n 元组表，同时保持每个模型的其余部分不变。

统一精度。 我们首先测试对所有 n 元组嵌入表使用一种低精度能否在不明显改变模型性能的情况下节省大量表内存。我们使用 WikiText-2 验证数据 [12] 上的困惑度将两至五比特表与原始表进行比较。结果如图 4a 所示。四比特表节省了约一半的表内存，DeepSeek 的困惑度增加 1.26%，而 Qwen 的困惑度几乎不变。更强的压缩对两个模型的影响不同：在三比特时，Qwen 的困惑度仅增加 0.52%，而 DeepSeek 增加 5.06%。

图 4：统一精度和混合精度在 DeepSeek-V4.1-Flash 和 Qwen3.8-Flash-Next 中提供了不同的内存–性能选择。 每个表两至五比特，标签给出每个值的比特数。 按 n 元组长度排序的代表性混合分配。两个面板均使用 WikiText-2 验证困惑度。

混合精度。 为了考察某些 n 元组表是否需要比其他表更高的精度，我们测试了各 n 元组阶数上两至五比特的所有组合。图 4b 表明，即使在相同的内存成本下，精度分配也很重要。对于 DeepSeek，将额外的一比特给三元组或四元组（4/5/4 或 4/4/5）比给二元组（5/4/4）能更好地保持困惑度。在 Qwen 中，额外的一比特对二元组更有用：4/3 优于 3/4。因此，更好的分配方案在两个模型之间有所不同。

除 WikiText-2 外，我们还在 Penn Treebank 和 C4 [13, 14] 上进一步评估了使用 4/5/4 比特表的 DeepSeek 和使用 4/3 比特表的 Qwen。在所有三个保留数据集上，这些设置将困惑度变化保持在 1.2% 以内，同时节省了 47–55% 的表内存。

下游性能。 除了衡量下一词元预测的困惑度外，我们还考察了低比特表如何影响下游任务性能。我们在 HellaSwag、ARC-Challenge 和 WinoGrande [15, 16, 17] 上评估了使用 4/5/4 比特表的 DeepSeek 和使用 4/3 比特表的 Qwen。这些任务的平均准确率仅下降 0.93%（DeepSeek）和 0.27%（Qwen）（图 5）。这些结果表明，表内存节省的同时下游性能也几乎没有变化。

3.5 通过低比特训练恢复性能

压缩 n 元组表会改变模型学习使用的嵌入，这可能降低性能。因此，我们问：短暂的微调阶段能否恢复这一损失，或者在整个预训练过程中使用低比特嵌入是否更有效。为了使用低比特嵌入进行训练，我们保留一个 BF16 副本用于梯度更新，但在每次前向传播中对检索到的嵌入进行量化。嵌入和模型的其余部分都保持可训练，使模型能够适应所选的精度。我们比较了四种序列：(1) 压缩 → 预训练，(2) 预训练 → 压缩 → 微调，(3) 预训练 → 微调 → 压缩，以及 (4) 预训练 → 压缩。比较压缩前后的微调可以检验恢复是来自适应低比特嵌入，还是仅仅来自更多的训练。

图 6：压缩后的微调恢复了大部分 n 元组改进。在 31M Llama 系列模型上保留的改进，相对于具有相同训练预算的全精度和无表模型。误差条表示三个种子上的样本标准差。

结果总结在图 6 中。我们观察到，压缩后的短暂微调阶段恢复了在极低精度下损失的大部分性能。微调后，一比特和两比特表分别保留了全精度表所提供改进的 65.3% 和 92.0%。令人惊讶的是，当在整个预训练过程中使用一比特嵌入时，其表现更好，保留了全精度表改进的 77.0%。这表明，当模型从一开始就学习使用它们时，即使每个嵌入分量只有一比特，也能保留 n 元组表益处的大部分。附录 C.5 给出了完整结果，附录 C.6 则考察了替代哈希方法如何影响低比特嵌入的性能。

最后，我们问：压缩节省的内存能否支持更大的表并提升性能。我们使用存储为 16 比特精度的 262k 嵌入表作为基线。然后，我们将每个表增加到 1M 嵌入，并测试较低的精度，以查看更大的表能否在使用比基线更少内存的同时提升性能。我们相对于基线表相对于无 n 元组嵌入模型所提供的改进来衡量性能。

结果如图 7 所示。我们观察到，将压缩节省的内存重新投入到更多嵌入中可以提升性能，同时仍减少总表内存。例如，将每个表从 262k 增加到 1M 嵌入并以两比特精度存储，仅使用原始表内存的 52–54%，同时提供比原始 16 比特表多 22–26% 的改进。三比特表在使用原始表内存的 77–79% 的同时进一步提升了性能。

我们还遵循第 3.5 节，在压缩后的更大表上测试了短暂的微调阶段，以评估适应是否能带来进一步的改进。微调提升了所有三个模型的性能，其中一比特时的恢复最大：在相同的微调预算下，先压缩后微调实现了原始表改进的 97–111%，而先微调后压缩仅为 44–63%。在两比特时，微调在相同的内存成本下将改进从 122–126% 提高到 129–145%。这些结果提出了一种内存高效部署的实用方法：使用更多嵌入进行预训练，然后压缩表并短暂微调模型以恢复性能。

4 相关工作

语言模型中的 n 元组和查找记忆。 学习的局部上下文表示可以追溯到神经 n 元组模型 [18]，而哈希在许多键之间共享参数 [19, 20]。N-Grammer 在离散潜在码上添加 n 元组嵌入 [21]，BLT 在字节上使用哈希 n 元组嵌入 [22]。Over-Tokenized Transformer [1] 将多组输入哈希到大型输入嵌入表中，这正是我们研究的操作。深度稀疏嵌入（DSE）[2] 将哈希 n 元组记忆放置在网络内部，采用上下文感知门控和短卷积，将其与混合专家容量进行平衡，并从主机内存提供服务。其他设计对 n 元组嵌入进行分解 [23, 24]，或使用频率感知哈希和别名混合 [25]。SCONE 预计算上下文化的 n 元组嵌入并将其存储在加速器之外 [26]。记忆层从乘积键记忆中检索 [27, 28]，外部数据存储在推理时增加容量 [29, 30]。

压缩嵌入表。 推荐系统中的大型嵌入表通过带码本的每嵌入四比特量化 [31]、组合嵌入 [32] 和混合嵌入维度 [33] 进行压缩；词嵌入可以用学习的组合码替换 [34]。由于哈希嵌入已经是共享的，我们直接比较更少的嵌入与每嵌入更少的比特。

5 结论

我们提出了 n 元组嵌入表的低比特精度，并系统地研究了其对内存使用和模型性能的影响。在从头训练的模型上，四比特表节省了约 75% 的表内存，同时保留了全精度表所提供改进的 99% 以上。选择合适的嵌入缩放因子比码本的选择更重要，混合精度允许不同的 n 元组表使用它们所需的精度。在较低的精度下，短暂的微调阶段可以恢复大部分损失的性能。这些发现也适用于 DeepSeek-V4.1-Flash 和 Qwen3.8-Flash-Next，压缩节省了 47–55% 的表内存，困惑度和下游性能几乎没有变化。除了减少内存使用外，将节省的内存重新投入到更多嵌入中可以比原始全精度表获得更好的性能。总之，我们的结果为提高 n 元组记忆的效率并利用节省的容量构建更好的语言模型提供了实用指导。

附录 A 详细方法

A.1 n 元组哈希与查找

遵循 Over-Tokenized Transformer [1]，我们通过对以每个词元结尾的二元组和三元组进行哈希来检索嵌入。对于位置 t 处的词元 ID x_t、词表大小 V = 8192 和基数 B = V + 1，我们的从头训练实验使用以下键：

k_t^(2) = x_t + B·x_{t−1}，k_t^(3) = x_t + B·x_{t−1} + B²·x_{t−2}。 (3)

缺失的前驱取值 V。二元组地址为 k_t^(2) mod m 和 k_t^(2) mod (m+2)，三元组地址为 k_t^(3) mod (m+4) 和 k_t^(3) mod (m+6)。基础表大小默认为 m = 262,141，1M 嵌入实验中为 m = 1,048,573。然后按第 2 节所述使用检索到的嵌入。

A.2 码本构建

如第 2 节所述，我们考虑三种码本族：均匀、正态分位数和 Lloyd–Max。每个码本提供一个表中嵌入共享的代表值。每个分量 b 比特时，码本最多可包含 K = 2^b 个值，记为 c_0, …, c_{K−1}。

均匀码本。 我们在 −1 和 1 之间等间距放置 K 个值。在两比特时，这给出 {−1, −1/3, 1/3, 1}。我们还测试了以零为中心的变体，记为 Uniform*，它使用 K−1 个等间距值以包含零。其两比特码本为 {−1, 0, 1}。

正态分位数码本。 我们在标准正态分布的分位数处放置值，将更多值集中在零附近。对于超过两比特的情况，我们在概率 (k + 1/2)/K（k = 0, …, K−1）处取分位数，然后将所有值除以其最大绝对值。在两比特时，我们改用固定码本 {−1, −0.3186, 0.3186, 1}。

Lloyd–Max 码本。 为了使码本适应训练嵌入，我们从其分量分布中学习其值 [4, 5]。我们首先对每个嵌入进行归一化，使幅度差异不会主导共享码本。令 w_ri 为嵌入 r 的第 i 个分量，p 为其分量数。初始归一化缩放因子 s_r^(0) 是嵌入的均方根，z_ri 是其归一化分量：

s_r^(0) = sqrt((1/p) Σ_{i=1}^p w_ri²)，z_ri = w_ri / s_r^(0)。 (4)

在实现中，我们将归一化缩放因子限制为至少 10^−12，以避免除以零。

然后我们将码本拟合到这些归一化分量上。我们每个表最多采样 4M 个分量，并在该样本的分位数 (k + 1/2)/K 处初始化 K 个码本值。每次 Lloyd–Max 迭代有两个步骤。首先，我们将每个采样分量分配给其最近的码本值。其次，我们将每个码本值替换为分配给它的分量的均值。形式上，对于索引为 j 的采样分量，分配 a_j 和更新值 c_k^new 为：

a_j = argmin_{0≤k<K} |z_j − c_k|²，c_k^new = (1/|S_k|) Σ_{j∈S_k} z_j，S_k = {j : a_j = k}。 (5)

这里，S_k 包含分配给值 k 的采样分量的索引。如果该集合为空，则该码本值保持不变。我们重复这两个步骤 60 次，并将拟合值以 bfloat16（BF16）格式存储。一旦码本固定，我们使用以下方法之一选择嵌入缩放因子。

A.3 嵌入缩放因子

如第 2 节所述，我们比较了三种选择嵌入缩放因子的方法：基于最大值、均方根（RMS）和误差拟合缩放。对于嵌入 r，缩放因子 s_r 乘以每个选定的码本值，因此分量 w_ri 被重建为 s_r · c_{q_ri}，其中 q_ri 是所选码本值的索引。以下方法在固定码本下如何选择 s_r 方面有所不同。

基于最大值的缩放。 我们将码本的最大绝对值与嵌入的最大绝对分量相匹配。对于码本值 c_k，缩放因子为：

s_r^max = max_i |w_ri| / max_k |c_k|。 (6)

均方根（RMS）缩放。 我们使用嵌入的整体幅度作为缩放因子，即：

s_r^RMS = sqrt((1/p) Σ_{i=1}^p w_ri²)。 (7)

误差拟合缩放。 为了基于重建质量选择缩放因子，我们测试了 RMS 缩放以及从基于最大值缩放导出的一系列缩放因子。具体来说，候选值为 s_r^RMS 和 α·s_r^max，其中 α 是取值 1.00, 0.95, …, 0.30 的乘数。较小的 α 使代表值更接近，允许对较小分量进行更精细的近似，同时裁剪较大的分量。对于每个候选值，我们将缩放因子舍入到 BF16，将每个分量分配给其最近的缩放码本值，并以 BF16 重建嵌入。我们选择相对于原始嵌入均方误差最低的候选值。这是主要压缩比较中使用的误差拟合方法。

B.4 使用低比特嵌入进行训练和微调

本节描述第 3.5 和 3.6 节中使用的训练和微调程序。

使用低比特嵌入训练。 我们保留每个嵌入的 BF16 副本用于梯度更新，并在前向传播中对检索到的嵌入进行量化。在反向传播过程中，我们将量化视为恒等操作，通过直通估计器将梯度传递给 BF16 副本。嵌入缩放因子在每次前向传播时拟合，Lloyd–Max 码本在前 100 次更新中每次更新都重新拟合，之后每 25 次更新重新拟合一次。

微调细节。 对于 262k 嵌入表，微调在未见过的训练序列上进行 381 次额外更新，每次更新 32 个序列。所有权重保持可训练，使用全新的 AdamW 状态、20 次预热更新和 0.1 倍原始峰值的学习率。

对于 1M 嵌入实验，较小的模型使用新的训练序列进行微调，322M 模型则复用预训练序列。

C.6 替代哈希方法

为了考察 n 元组共享嵌入参数的方式是否影响低比特性能，我们将传统的整嵌入哈希与两种逐分量替代方案进行比较。传统哈希将一个 n 元组映射到每个表中的一个嵌入，并一起检索其所有分量。因此，映射到同一嵌入的两个 n 元组共享每个分量。替代方案则为每个输出分量选择单独的地址，同时保持相同的表大小和嵌入维度。

同列哈希。 我们将表保留为矩阵，每行一个嵌入，每列一个分量。为了构造 n 元组嵌入的第 j 个分量，我们将 n 元组与 j 一起哈希以选择一行，然后检索该行第 j 列的值。因此，不同的分量可以来自不同的嵌入，但第一个分量总是来自第一列，第二个来自第二列，依此类推。

完全随机分量哈希。 我们将同一个表展平为向量，并将 n 元组与每个分量索引一起哈希，以选择该向量中任意位置的值。与同列哈希不同，选定的值可以来自任何列以及任何行。在两种变体中，哈希地址都是固定的：同一个 n 元组总是检索相同的分量，其值在训练过程中学习。

实验设置。 我们在 nanochat 26M、GPT-2 系列 30M 和 Llama 系列 31M 上比较所有三种方法，使用默认的每表 262k 嵌入、ClimbMix 和三个种子。每次比较使用相同的训练设置，并评估 16 比特和两比特表。遵循附录 B.4，两比特模型在整个预训练过程中使用量化嵌入。我们在收集分量之前使用 Lloyd–Max 码本和误差拟合缩放对每个表进行量化，因此每个选定的分量保持其源嵌入的缩放因子。
