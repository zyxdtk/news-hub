摘要

人类不断从经验中学习，而传统的大语言模型（LLM）评估忽略了模型通过推理时交互进行改进的能力。在本文中，我们研究了 LLM 在测试时如何从迭代经验中学习，这一设定我们称之为“经验链”，即模型通过与自身或环境反馈的迭代交互来积累经验轨迹，从而形成超越零样本推理的持续改进循环。我们用多种反馈机制实例化了 CoE，包括模型自我反馈以及正确性或公共代码测试通过率等环境信号，并使用包括 GPT-5、Gemini-2.5 Pro、Claude-4.5 Sonnet 在内的 8 个 LLM 在数学、编程和知识领域进行了评估。我们的研究表明，利用迭代经验始终优于无反馈基线，仅凭自我反馈就获得了显著收益，在所有任务和模型中实现了 5.6% 的整体提升和 19% 的 API 成本降低。我们进一步表明，结合互补的反馈通道（例如，模型和正确性信号）会产生额外收益，并且 CoE 比现有的测试时策略具有更高的每 Token 准确率。我们观察到 LLM 基础能力与改进能力之间存在正相关，并表明模型在弱反馈或伪反馈下仍保持鲁棒性，不同的反馈对不同的改进方面有所贡献，且大部分收益出现在迭代早期。

1 引言

人类自然而然且不断地从经验中学习，每一次成功或失败都有助于形成不断演进的理解，从而为未来的决策提供信息。当代机器学习系统——特别是现代大语言模型（LLM）(1; 53; 16; 29; 67)——的行为却截然不同：一旦训练完成，它们就会以固定状态部署，将每次推理视为孤立事件，忽略了问题解决过程本身所蕴含的丰富反馈。相反，学习应该是一个连续的过程，LLM 不仅应该在训练期间改进，还应该在测试时通过与环境的迭代交互来改进——处理反馈、进行反思以不断更新其理解，或者简而言之，从自身的知识和经验中改进 (48; 49)。

受强化学习成功的启发，基于搜索的方法探索了大量的解决方案。启发式策略 (69; 20)，包括多数投票 (59; 56)，旨在利用由语言模型并行生成的候选答案中的验证器来识别更高质量的答案。然而，这些方法中的模型经验仍然是临时的，通常被合并为一个单一答案然后被丢弃，导致模型在解决每个问题时都要重新开始，没有积累洞察力。另一种范式是自我精炼，其中模型被允许通过自我批评和纠正进行迭代改进 (33; 46)，在单个上下文中内化反馈。诸如自我调试 (9) 和 Reflexion (46) 等扩展引入了代码执行信号等外部信号，但它们在迭代经验的使用上仍然是碎片化和浅层的。在这些尝试的基础上，我们概念化了经验链，其中模型在反馈的参与下进行迭代问题解决，并研究：“LLM 如何在测试时通过交互和反馈从积累的经验中进化以实现改进？”

我们使用 CoE 框架系统地探讨了跨四种反馈类型的长时间环境交互：无、模型反馈、代码任务的执行器反馈和一般任务的正确性反馈。

图 1： 在数学、代码和知识领域的四个基准测试上对四个 LLM 的汇总结果。CoE 下的迭代问题解决提供了三个好处：上图：通过在 CoE 中结合反馈，四个 LLM 的平均性能优于其他测试时增强方法；左下图：模型能够通过反馈以更低的 API 成本实现更好的性能；右下图：在任务上表现更好的 LLM 通过 CoE 显示出更好的改进能力，具有中等到强的皮尔逊相关性。我们在第 4.1 节中给出了关于基线的更多解释。

为了评估基于 CoE 的算法，我们提示了八个最先进的模型，包括 GPT-5、o3、Gemini-2.5 Pro、Claude-4.5 Sonnet，涵盖了数学、编程和知识领域。对四种反馈类型（来自现有算法和我们设计的范式，即无、执行器、模型和正确性反馈）的大量实验表明，带有反馈的 CoE 始终产生显著的改进（图 1）。特别是，简单的 CoE 方法大大优于依赖其他任务经验的测试时扩展方法 (51; 74)，仅凭自我反馈就比这些算法平均提高了 7-9%（平均从 62.9% 提高到 71.0%）。此外，利用迭代经验和反馈的模型推理更高效，在所有任务和模型中实现了 5.6% 的整体提升，API 成本降低 19%，且每 Token 准确率更高。结合互补的反馈通道（例如，模型和正确性/执行器信号）会产生进一步的改进，而在任务内应用的基于记忆的选择方法并没有超过完整的经验轨迹，这表明过度压缩可能会丢弃关键的中间推理。我们进一步观察到反馈带来的学习收益与基础能力之间存在明显的正相关，在五个基准测试中平均皮尔逊相关系数为 +0.5，表明更强的模型能更有效地从经验中进化。最后，我们的分析揭示了更深层次的行为洞察：模型在伪反馈或弱反馈下保持鲁棒，大部分收益发生在迭代早期，并且在不同反馈类型下出现了不同的改进轨迹。

2 相关工作

无训练测试时策略。 大语言模型可以通过各种测试时提示策略在没有额外训练的情况下进行推理。思维链 引发了逐步推理，并改进了算术、常识和符号任务 (63)，催生了一系列“X链”方法 (71; 27; 21; 12)。代表性的变体包括对比 CoT (12)、从少到多提示 (78)、任务专用形式如解释链、笔记链和知识链 (21; 71; 27)，以及思维树，它通过搜索探索多条推理路径，并在规划任务上优于 CoT (69)。随着 OpenAI o 系列 (22) 和 DeepSeek R1 (18) 等大型推理模型的出现，基于验证器在并行生成中进行选择的方法重新获得了关注，包括步骤级 (28; 57; 72) 和输出级 (76; 6; 31) 验证。虽然这些方法作为使用外部反馈的后处理是有效的 (30; 58; 55; 60)，但它们缺乏用于模型进化的迭代循环。我们的 CoE 也是无训练的，但不同之处在于使用反馈来驱动推理期间的迭代自我进化。

从经验中学习。 从经验中学习是人类智能和 AI 系统的基础。强化学习通过策略梯度和演员-评论家方法将经验形式化 (65; 44)，在游戏、机器人和控制方面取得了成功 (47)，最近通过在线生成的后训练来改进对齐和推理 (3; 17; 45; 70)。除了训练之外，经验也可以在推理期间积累。对于跨任务经验，动态备忘单 (DC) (51)、智能体上下文工程 (ACE) (74) 和相关方法 (77; 61; 75) 维护持久的推理时记忆，以提炼可重用的策略，而智能体支架允许跨智能体共享集体经验 (52; 8; 39; 19)。对于同任务经验，Reflexion (46)、Self-Refine (33)、Self-Debug (9)、S* (26)、Iteration-of-Thought (40) 和 ReVeal (25) 使用自我反馈或执行信号迭代地精炼输出，而最近的流程进一步利用离线模型经验来改进智能体 (73; 10)。最近的工作 (66; 54) 也扩展了这种范式到现实世界的使用。与之前的工作相比，我们提出了一个统一的框架，将模型的整个解决历史视为经验，并系统地研究了不同的反馈信号，以在测试时实现持续改进。

3 通过 CoE 实现模型改进

在本节中，我们首先提供迭代问题解决设置的一般概念，称为经验链，然后详细讨论四种不同的反馈类型以增强模型经验。最后，我们解释了如何扩大经验迭代以探测模型在测试时的学习性能。

3.1 概述

在传统的问答设置中 (50; 41; 43; 5)，当给定一个问题 $Q$ 时，大语言模型将从条件分布 $P(A\mid Q)$ 中采样生成一个合理的响应 $A$。为了将这一范式扩展到经验时代 (48)，我们引入了一个环境反馈变量 $F$，以表示当响应在交互环境中落地时，可观察到的后果或评估。形式上，反馈 $f$ 从条件分布 $f\sim P^{\prime}(F\mid Q,A)$ 中采样，其中 $P^{\prime}$ 由一个环境建模，该环境可以实例化为代码执行环境、智能体的内部世界模型，甚至真实世界环境，它为给定序列提供生成性 (38; 34) 或环境反馈 (45; 33)。在本文中，我们研究了一种将单轮公式扩展为顺序决策过程的范式，其中步骤 $i$ 处的每个响应 $a_i$ 取决于先前尝试的完整历史和相应的环境反馈；我们将此设置称为经验链。生成过程定义为：
$$a_{t}\sim P(a_{t}\mid Q,e_{0},e_{1},\ldots,e_{t-1}) \quad (1)$$
其中 $e_i$ 是第 $i$ 次经验，由 $(a_i, f_i)$ 组成。

图 2： 我们的研究中语言模型迭代改进循环的概述。模型 $\mathcal{M}$ 通过与环境 $\mathcal{E}$（例如，模型模拟或编码环境）的反复交互来学习。在每个周期中，$\mathcal{M}$ 根据输入和积累的经验生成动作，然后从 $\mathcal{E}$ 接收反馈以形成新的经验。我们在本研究中调查了四种特定的反馈：无、执行、模型和正确性反馈。

3.2 反馈谱系

为了充分表征不同形式的经验如何塑造模型的迭代进化，我们沿着丰富度的谱系对反馈进行分类——从完全隐式到强显式信号。每种反馈类型对应于环境响应的特定实例化，这反过来通过 CoE 生成过程影响下一步动作。通常，模型可以根据以下公式更新：
$$a_{t}\sim P(a_{t}\mid Q,(a_{0},f_{0}),\ldots,(a_{t-1},f_{t-1}))$$
其中函数 $f_i$ 是我们在第 $i$ 次迭代中采用的反馈。下面，我们描述了本研究中使用的这四种反馈类型及其正式定义。

无反馈。 环境不提供评估或信号，即 $f_i = \varnothing$。经验简化为 $e_i = (a_i, \varnothing)$，下一个动作从 $a_{t}\sim P(a_{t}\mid Q,a_{0},a_{1},\ldots,a_{t-1})$ 中采样，这意味着任何改进都必须来自对先前尝试的反思，而没有外部指导。

执行反馈。 对于基于可执行或交互环境（例如，带有解释器或单元测试的编码任务）的任务，反馈通过在环境 $\mathcal{E}$ 中运行模型的响应 $a_i$ 来生成：
$$f_{i}\sim P^{\prime}(F\mid Q,a_{i})=\mathcal{E}(Q,a_{i})$$
其中 $f_i$ 可能包括执行跟踪、错误消息、运行时日志或测试用例结果。

模型反馈。 一个（可能是相同的）辅助语言模型 $\mathcal{M}{\text{fb}}$ 充当评判者或批评者：
$$f{i}=\mathcal{M}{\text{fb}}(Q,a{i})$$
其中 $f_i$ 可能包括文本批评、偏好分数或结构化评估。这使得即使在没有外部环境的情况下也能进行精炼，纯粹依赖于基于语言或偏好的信号。

正确性反馈。 当有特定领域的验证器可用时，环境提供二元的正确性信号：
$$f_{i}=\mathbf{1}{a_{i}\text{ is correct}}\in{0,1}$$
这种类似预言机的信息提供了对成功和失败的明确细粒度评估。尽管这种类型的反馈在真实世界设置中通常是不切实际的，因为真实验证成本高昂或不可用，但我们仍然将其作为高信号参考设置，以近似迭代精炼收益的上限。

基线。 至于基线，我们检查模型在 (1) 利用不同级别的内置推理或 (2) 利用先前解决问题的经验方面的技能。为了控制推理深度，OpenAI 和 Claude 模型可以调整为产生不同数量的推理 Token。对于从先前示例中吸收经验的方法，我们采用少样本上下文学习 (ICL) (5) 作为标准基线。对于更复杂的方法，我们选择了动态备忘单 (DC) (51) 和智能体上下文工程 (ACE) (74)，它们维护一个不断更新的可重用策略的外部记忆。尽管后续工作 (39; 7) 在类似的处理循环中引入了更细粒度的精炼，但我们使用这两个作为代表性基线。我们为 ICL、DC 和 ACE 选择最相关的 $k\in[1,5,8,12,15,20]$ 个解决方案以形成它们的上下文，我们在附录 D 中给出了基线细节。

4.2 经验扩展

图 3： 五个最先进的 LLM 在六个基准测试上使用不同生成技术的结果。在具有不同级别反馈（正确性/执行器、自我和二元执行器反馈）的 CoE 下的模型通常优于基线策略（无反馈、DC、ICL 以及具有不同推理努力的那些）。结果是 3 次运行的平均值，我们用较浅的颜色遮蔽标准差，并绘制条形图显示模型在不同推理努力下的性能。完整结果在附录 H 中。

发现 1：性能：带有反馈的经验链设置在各种任务上提升了推理 LLM。 配备反馈的 LLM 始终优于几乎所有基线和设置。如图 3 所示，在六个基准测试中，经验链 范式——模型迭代地吸收和重用先前的反馈——提供了显著的性能提升（完整结果在附录 H 中）。通过自我反馈或执行器/正确性反馈（作为上限），八个现代推理模型比其无反馈的对应模型平均提高了 5.6% 和 11.1%，突出了基于结果的显式信号对模型精炼的价值。对于以编程为中心的任务，如 LiveBench (Code) 和 LiveCodeBench (V6)，从公共测试用例验证中得出的程序化执行器反馈推动了平均 8.6% 的准确率提升（从 66.4% 到 75.0%），而自我判断反馈仍然提供了 7.0% 的提升。这表明模型可以将细粒度和抽象的反馈线索内化到后续推理中。在非编程任务（例如，AIME 2025、OmniMath、GPQA Diamond）上，同样的趋势也成立：正确性反馈确立了上限，而自我反馈——虽然有噪声——仍继续促进改进（例如，75.1% > 67.1% > 62.5% 无反馈）。相比之下，尽管 ICL、DC 和 ACE 仍被广泛使用，但在高级推理模型下都没有表现出可靠的扩展性。在表 3 中的六个基准测试中平均，ICL、ACE 和 DC 分别仅达到 62.1%、64.0% 和 62.7%，都落后于一个简单的无反馈基线 (66.8%)。相反，结合显式反馈会产生一致的收益：带有模型自我反馈的结果达到 71.0%（比 ICL/ACE/DC 高 7-9%），而最佳反馈信号进一步将性能提高到 79.3%。总体而言，这些结果证明反馈驱动的 CoE 充当了一个更通用和有效的测试时扩展框架，使 LLM 能够在无反馈推理和其他基线的基础上跨领域自主改进。

图 4： 每个模型在任务完成上的总成本与其在 20 次迭代内的最佳性能的对比。带有反馈的 LLM 通常以更少的成本获得更高的分数（在左上方），而没有反馈的迭代经验通常落后（在右下方）。我们在附录 H 中提供了六个基准测试的完整结果。

发现 2：效率：带有反馈的 LLM 在性能和 API 调用成本之间取得了平衡。 如图 4 所示，将反馈纳入 CoE 不仅提高了性能，还提高了效率——带有反馈的模型倾向于以较低的 API 成本获得较高的准确率（子图的左上方）。在所有任务中，大多数使用基于反馈变体（蓝色对象）的 LLM 始终主导无反馈基线（灰色方块），除了 Gemini 2.5 Pro。完整结果见图 12，附录 H。对于两个编程任务，自我反馈成为一种具有成本效益的折衷方案：它捕获了执行器的大部分性能增益（即 73.4% 对 75.0%），同时减少了 13.4% 的 API 调用（例如，70.7 美元 对 81.6 美元），此外，比无反馈的对应方案成本低 20%。类似地，在 AIME 2025 和 EvaLearn 上，自我反馈提供了信息更丰富的输入，同时大幅降低了 API 成本，在所有八个 LLM 中分别减少了 47.3% 和 7.0%，甚至与无反馈方案相比（例如，AIME 25 上 8.8 美元 对 4.6 美元，EvaLearn 上 325.3 美元 对 302.4 美元），同时仍分别产生平均 4.4% 和 6.9% 的准确率提升。一个例外是 Gemini 2.5 Pro，其自我反馈产生更冗长的输出，收益较小，表明它在自我评估方面可能不如其他 LLM 有效。除了 API 成本之外，我们还在表 5（附录 I）中进一步分析了 Token 级别的效率。带有正确性/执行器反馈的 CoE 以与其他多轮方法相当的总 Token 数实现了最佳准确率，从而产生更高的每 Token 回报。例如，在 AIME 2025 上，正确性反馈以 108K Token 达到 84.6%，而 DC 仅使用 11K Token 却达到较低的 74.7%，无反馈 CoE 消耗相似的 Token (107K) 但落后于 74.1%。这种模式在基准测试中始终成立，证实了 CoE 将计算重新分配到反馈迭代中并生成较少冗长的输出，而不是简单地增加提示长度。

图 5： 模型的零样本性能（基础能力）和学习增益显示出正的皮尔逊相关性 (r)，表明表现更好的 LLM 具有更大的改进能力。分数是 3 次运行的平均值。

发现 3：改进能力：在任务上表现更好的 LLM 在测试时显示出更高的学习增益。 我们使用 $\Delta_{\mathcal{M}}=\frac{S_{\text{max}}-S_{\text{base}}}{1-S_{\text{base}}}$ 计算模型 $\mathcal{M}$ 的改进能力，其中 $S_{\text{base}}$ 表示模型在无反馈情况下的初始零样本性能，$S_{\text{max}}$ 表示在我们的 CoE 设置下通过模型自我反馈达到的峰值准确率。所有数字均为三次运行的平均值。在图 5 中，我们观察到在基准测试中基础性能和改进能力之间存在明显的正相关趋势。例如，两个编程任务上的模型，例如 LiveBench (Code) ($r=0.97$) 和 LiveCodeBench (V6) ($r=0.83$) 显示出强相关性，表明具有更强初始推理能力的模型倾向于更有效地从反馈中学习。尽管 AIME 2025 ($r=0.33$) 和 OmniMath ($r=0.24$) 等任务显示出相对较弱的相关性，但总体趋势仍然一致，平均任务级皮尔逊相关系数为 0.50。这些发现表明，从经验中学习是一种随模型容量扩展的涌现属性——更强的 LLM 本质上更擅长消化反馈并通过交互进行改进。

5 进一步讨论与结论

为了进一步研究 LLM 在 CoE 下的学习能力，我们对迭代问题解决设置进行了消融研究，包括伪反馈、改进模式分析、双重反馈组合和原则性经验选择。我们还研究了模型在不同反馈强度（附录 F.3）和扩展经验迭代（附录 F.2）下的行为。

从伪反馈中学习。 为了研究 LLM 在伪反馈下的鲁棒性，我们设计了一个实验，模型专门接收不正确或正确的反馈（例如，总是声明“答案不正确”或反之亦然）。我们在表 2 中报告了 20 次迭代中的最佳模型性能。此设置评估模型是否可以从误导性反馈信号中恢复（甚至在误导性反馈下受益）。我们发现伪反馈通常会在 AIME 2025 上平均降低 7.6% 的性能，在 GPQA-Diamond 上降低 2.6%。然而，更强的模型如 GPT-5 mini 表现出更大的鲁棒性，仅下降 2.5% 和 0.6%，而 o4-mini 的下降幅度为 12.8% 和 4.6%。为了进一步提高可靠性，我们引入了选择性多数投票，它通过在前 $n$ 次有效尝试中进行多数投票来聚合最终答案。有趣的是，在 GPQA-Diamond 上，带有不正确反馈的 SelMV 超过了模型反馈 0.9%（79.4% → 80.3%），而在 AIME 2025 和 GPQA-Diamond 上，SelMV 后的准确率分别平均提高了 1.2% 和 2.3%，突出了推理 LLM 尽管面临对抗性信号但仍具有鲁棒性。关于伪反馈和不同级别反馈的进一步结果在附录 F.1 和 F.3 中。

改进模式分析。 为了更好地理解 LLM 通过迭代反馈改进的原因，我们设计了实验来分析 LLM 从错误答案到正确答案的每次翻转背后的“原因”。我们收集了所有任务和五个模型（即 GPT-5、GPT-5 mini、o4-mini、o3、o3-mini）的 6,630 个示例，并利用最新的 GPT-5 模型分析原因。为了验证这种自动分析，我们在 100 个随机抽样的轨迹（每个类别 25 个）上计算了 GPT-5 和人类评分之间的 Cohen's Kappa，达到了 76.8% 的一致性，表明具有实质性的一致性（详情见附录 F.5）。我们定义了 LLM 改进背后的四个因素：用于从轨迹反馈中改进的反馈保真度，用于参考自我反思的自我反思，用于根据问题和/或格式要求进行纠正的规范召回，以及用于模型因其他原因改进的随机性。我们在附录 F.4 和 K 中给出了这些因素的详细标准和提示。在图 6 中，我们观察到：(1) 47.7% 的改进是由反馈驱动的，证实了 LLM 有意义地解释并作用于反馈信号。(2) 在编程任务中，30.0% 的改进源于规范召回，反映了这些任务对格式和语法敏感的性质。(3) 模型生成的反馈比其他来源引发了更高比例的与反馈相关的改进（例如，58.7% 对 41.1%），表明自我生成的反馈在上下文上更一致。

双重反馈 CoE。 为了测试多个反馈通道是否互补，我们使用 Claude 4.5 Sonnet 将模型反馈与正确性（数学）或执行器反馈（编程）相结合。如表 1 所示，双重反馈显示出明显的互补性：在 AIME 2025 上，双重反馈达到 76.7%，超过了仅正确性 (70.0%) 和仅模型 (60.0%)；在 LiveBench (Code) 上，双重反馈达到 81.2%，而执行器为 78.1%，模型为 57.8%。在更具挑战性的 OmniMath 上，收益微乎其微（73.5% 对 74.5% 仅正确性），正确性信号通常将最佳轮次推后。这些结果表明反馈通道提供了互补信号，尽管边际效益取决于任务难度。完整结果在附录 J 中提供。

具有原则性经验选择的 CoE。 我们进一步调查基于记忆的选择和压缩机制是否在完整经验轨迹之外增加益处，方法是在相同的任务内协议（无跨任务泄漏）下将 CoE 与动态备忘单 (DC) (51) 和 SimpleMem (32) 相结合。如表 1 所示，这些方法并没有超过纯自我反馈：在 AIME 2025 上，仅模型反馈达到 60.0%，而 (+DC) 为 50.0%，(+SimpleMem) 为 56.7%；在 LiveBench (Code) 上，为 57.8% 对 51.6% (+DC) 和 54.7% (+SimpleMem)，这表明过度压缩可能会丢弃关键的中间推理。

结论。 我们对经验链 进行了全面分析，表明 LLM 可以在推理期间通过迭代反馈和积累的经验进行改进。在数学、编程和知识任务中，CoE 中的方法始终如一地提高了性能和效率，证明了反馈驱动的测试时学习的有效性。我们的分析还揭示了模型能力和改进能力之间的正相关，并表明即使存在弱反馈或伪反馈，大部分收益也会在早期出现。最后，我们分析了这个迭代过程中的各种模型改进模式。

附录 D 基线

内置推理： OpenAI 模型中实现的原生测试时扩展机制允许在低和高之间调整推理努力。我们将其视为一个内置且直接的扩展基线，并在附录 A 中提供更多细节。
少样本上下文学习 (ICL)。 在少样本 ICL 中，每个演示都是一个先前解决的问答对。随着模型按顺序处理任务，所有过去的对都存储在经验缓冲区中。对于新问题，我们使用 OpenAI 的 text-embedding-3-large 模型 [35] 的嵌入检索 $k$ 个最相似的过去问题，并将它们的原始问答格式作为演示，然后是新问题。当少于 $k$ 个示例可用时，使用所有先前的示例。我们评估 $k\in[1,5,8,12,15,20]$ 的 ICL。
动态备忘单 (DC) [51]。 动态备忘单 (DC) 是一种测试时学习方法，它维护一个自适应的外部记忆，其中包含从先前解决方案中提炼的可重用策略或代码片段。随着新问题的解决，DC 从选定的过去任务中总结高级策略——使用真实答案进行干净的经验整理——并将它们存储为结构化的备忘单。过去任务使用与少样本 ICL 相同的基于相似性的检索来检索；当少于 $k$ 个任务存在时，使用所有可用的示例。与 ICL 一致，备忘单是从最近的 $k\in[1,5,8,12,15,20]$ 个相关解决方案中合成的。
智能体上下文工程 (ACE) [74]。 智能体上下文工程 (ACE) 是一个上下文适应框架，它将提示视为不断演进的剧本，而不是静态演示。它通过生成-反思-整理的过程逐步提炼可重用的策略和领域洞察，产生保留先前知识并避免单体重写的局部上下文更新。与少样本 ICL 类似，ACE 检索相关的过去轨迹，并将来自最近 $k\in[1,5,8,12,15,20]$ 个轨迹的洞察整合到其不断演进的剧本中。

在本节中，我们展示了不同讨论的完整版本。

F.1 带有所有伪“正确”反馈的 LLM

在图 7 中，我们进一步展示了模型在两种极端条件下的性能：接收统一的“正确”反馈（例如，答案正确）和 SelMV 增强的结果。我们观察到，尽管在暴露于这种不正确的反馈后性能最初会下降，这表明在适应不一致的监督时出现了暂时的混乱。模型很快恢复甚至改进，因为它们适应了潜在的模式。有趣的是，GPT-5 mini 和 o4-mini 在暴露于完全不正确的反馈时都表现出更大的增益，因为这种反馈迫使模型重新评估其推理并验证其输出。相反，持续的正面反馈往往会导致过度自信，误导模型在不进行批判性重新评估的情况下接受其初始响应。这一观察表明，矛盾的是，建设性噪声（以看似负面的反馈形式）有时可以刺激更深层次的推理并增强迭代测试时学习的鲁棒性。
图 7： 使用恒定“不正确”和“正确”反馈的模型性能。通过利用选择性多数投票，LLM 在面临数学任务上的伪反馈时表现出不错的性能。

F.2 扩展迭代轮次

图 8： GPT-5 mini、o4-mini 和 o3-mini 在数学任务上将经验迭代扩展到 50 次的性能。我们用蓝色标记前 20 次经验迭代内的性能点，用绿色标记第 20 到 50 次迭代的性能点。
为了进一步探测 LLM 的学习能力，我们将经验迭代次数从 20 次扩展到 50 次，如图 8 所示。在 AIME 25 和 OmniMath 上，我们观察到大多数性能提升发生在前 20 次迭代中，而后期阶段仅产生微小的改进（例如，AIME 25 上平均 16.7% > 2.2%；OmniMath 上 21.2% > 3.5%）。这种趋势在不同模型中始终成立，表明 LLM 在早期阶段快速内化和巩固有用的反馈信号，之后学习达到饱和。这些结果强调，CoE 下的大部分测试时学习发生得很快——我们 CoE 中较短的适应循环对于大多数推理任务来说已经足够了，而长时间的经验积累带来的回报不太显著。

F.3 反馈强度

图 9： GPT-5 和 GPT-5 mini 在两个数学任务上具有外部模型反馈的模型性能。
对于具有模型反馈的经验，一个直观的探索是设计具有不同反馈提供者的 CoE。具体来说，我们将 GPT-5 和 GPT-5 mini 聚类为一对，并允许每个在数学和编程任务上作为另一个的反馈生成器，如图 9 所示。有趣的是，外部模型反馈在这两个基准测试上被证明是非常有效的，它甚至略微超过了基于正确性/执行器的反馈。例如，GPT-5 mini 在模型反馈下达到 94.4% 的峰值准确率，而在正确性反馈下为 93.0%；类似地，GPT-5 达到 93.3% 对 92.2%，这表明高质量的模型生成判断信号可以替代显式的正确性监督。在更具挑战性的 OmniMath 基准测试上，GPT-5 继续帮助其 mini 变体超越其自我反馈基线。然而，由于 GPT-5 mini 的零样本准确率仅为 62.5%，它无法提供足够可靠的反馈来改进 GPT-5，导致性能不如正确性反馈。此外，GPT-5 和 GPT-5 mini 的表现都不如其在 AIME 2025 上的结果（≥60% 对 ≥80%），并且正确性反馈仍然明显优越：GPT-5 在正确性反馈下获得 82.8%，而在外部模型反馈下仅为 74.5%。总体而言，这些发现突出了一个一致的趋势：反馈质量与验证器在任务上的基础能力相关，并且模型生成的反馈只有在验证器足够强大时才能与正确性监督相媲美，这为在迭代经验框架中部署模型作为评判者提出了一个实际阈值。

F.4 改进模式分析

我们展示了我们用于分类的详细标准：
* 反馈保真度： 直接由外部反馈驱动的改进，其中模型明确地将提供的指导或纠正纳入其下一次响应中。
* 自我反思： 源于模型自身推理的改进，在很少依赖外部反馈的情况下识别和纠正错误。
* 规范召回： 由任务指令或格式要求驱动的调整，因为模型重新与原始问题或输出模式对齐。
* 随机： 没有可识别原因的更改，通常是与反馈或规范无关的轻微措辞或风格变化。

双轴提升/变更归因评判者
你是一个双轴归因评判者。
你的工作是识别在同一问题的两次连续尝试之间，模型为什么改变以及具体改变了什么。
不要决定整体解决方案是否正确——提供了正确性标签。
相反，沿着两个正交维度归因观察到的变化：
* 变更驱动因素 (为什么) – 变更背后的动机或触发因素。
* 变更表现 (什么) – 所做修改的具体位置或类型。
—
I. 变更驱动因素 (发生变更的原因)
这些类别捕获了第二次尝试中更新的来源或动机。
1. 反馈保真度 – 模型直接使用提供的反馈来修改其输出。
信号： 编辑匹配失败的测试或批评位置；添加的子句反映反馈。
2. 自我反思 / 内部推理 – 模型在没有（使用）显式反馈的情况下自我识别错误或改进，或测试不同的方法以查看其是否表现更好。
信号： “我意识到...”，“之前我算错了...”，或者在没有反馈或没有反馈时进行内部一致的重新表述。
3. 规范召回 / 合规意识 – 模型记住或重新与任务指令或格式要求对齐。
信号： 添加“FINAL ANSWER:”包装器，遵守请求的模式，恢复提示中明确提及的省略步骤。
4. 随机 / 漂移 / 未知驱动因素 – 无法推断动机；变更似乎是随机的或风格上的。
信号： 表面措辞，微小的顺序变化，与反馈或指令没有逻辑联系。
—
II. 变更表现 (改变了什么)
这些类别描述了尝试之间变更的技术或结构形式。
A. 结构计划 / 算法修订 – 一种新的高级方法或重新表述（例如，蛮力 → DP，启发式 → 公式）。
信号： 重写主结构，新的辅助函数，复杂性或数据表示的变化。
B. 局部步骤健全性和不变量修复 – 在保持总体计划的同时纠正局部逻辑、变量、算术或不变量违规。
信号： 修复循环中的差一错误，纠正变量更新，修复代数推导。
C. 边缘 / 边界条件处理 – 为极端/特殊情况添加或修复防护（例如，空、零、溢出、平局）。
信号： if n == 0，<= <，添加 epsilon，处理 len == 1。
D. 输出 / 格式合规 – 在不改变算法内容的情况下调整呈现或输出模式。
信号： 添加“FINAL ANSWER:,”，修复 JSON/CSV 布局，仅打印所需的 token。
E. 其他 / 模糊变更 – 无法清楚地分配给 A–E 或证据不足。
信号： 风格编辑，重新排序，或无关的清理。

附录 L 局限性

我们的评估主要集中在数学、知识和编程基准测试上。虽然这些领域提供了受控设置来探测迭代改进，但在一些交互密集的场景中，经验会在很长的视野中展开 [24, 68]，CoE 范式应该自然地扩展到这些场景。此外，我们在本研究中不更新模型参数。这一选择将经验链机制作为一个测试时范式孤立出来，但这也意味着观察到的改进源于经验的上下文重用，而不是真正的学习；结合权重更新以将经验内化，仍然是朝着训练具有持久“从经验中学习”能力的模型迈出的重要下一步。
