我在自己的应用生产环境中使用 Stripe，总结起来很简单：它就是好用。
API 文档完善，支付结算可靠，订阅和 Webhooks 的表现与文档描述完全一致，我从来不需要怀疑某笔扣款是否真的成功了。对于一个正在交付真实产品的独立开发者来说，这种可靠性价值连城。我不需要把工程时间花在四处救火处理支付问题上，这意味着我可以把时间花在产品本身上。

设置复杂 (9)用户友好的仪表盘 (1)
Stripe 比它需要的要复杂得多。产品功能面呈爆炸式增长：Payments、Billing、Connect、Checkout、Payment Links、Elements、Tax、Radar、Terminal、Issuing，要弄清楚对于一个基本用例你到底需要哪些产品组合，比原本应有的难度大得多。
仪表盘也反映了这一点：功能强大，但你需要在嵌套菜单中苦苦寻找那些本应一键即达的设置。除了单次一次性付款之外的任何设置，都需要拼凑多个文档页面才能完成，而且（例如）Checkout、Elements 和 Payment Intents 之间的区别并不明显，直到你...

e already picked wrong once. It works.
I'm not switching, but a "I'm a solo dev, I just want to take recurring payments, give me the minimum viable path" mode would save a lot of people a lot of time.

vs Alternatives

Honestly, I went with Stripe because it's the default for indie builders and the documentation/community make it the path of least resistance.

Stripe won out. The cost of going with anything else is mostly self-inflicted friction.
