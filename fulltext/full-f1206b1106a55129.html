This Work
Our approach reverses this. Tools adapt to operators, not the reverse, through three principles:
Natural language objectives.
Operators describe goals—what to probe, why, how aggressively—and the agent autonomously generates, executes, and analyzes attack workflows.
Automatic intelligence generation.
Every attack produces structured, traceable evidence. Findings are automatically classified by severity, mapped to compliance frameworks (OWASP LLM Top 10, MITRE ATLAS, NIST AI RMF), and aggregated into dashboards with drill-down from project risk posture to individual adversarial prompts.
Conversational refinement.
The agent maintains context across interactions, letting operators refine strategy naturally: “try a different attack,” “add persona-based transforms,” “focus where we saw partial failures.”.

Interaction Layer
The primary interaction modality is a conversational agent embedded in a Dreadnode Terminal User Interface (TUI). The AI red team operator describes objectives in natural language, and the agent translates these into executable AI red teaming workflows. The agent operates through a structured loop: it assembles assessment context, calls the underlying model to reason about attack strategy, dispatches tools to generate and execute attacks, and collects results for analysis. The agent has access to:
•
Attack generation tools
that compose attack strategies with appropriate parameters, transforms, and scorers based on the operator’s ob

•
Execution management tools
that launch, monitor, and collect results from attack runs against the target system.
•
Assessment registration tools
that create structured assessment records and upload results to the Dreadnode Platform for analytics and reporting.
•
Campaign context
from prior interactions within the session, enabling iterative refinement. The agent preserves which attacks have been run, what results were observed, and what strategies the operator wants to explore next, without re-specifying background information.
The generated workflows are Python scripts built on the open-source SDK. Every workflow is reproducible, inspectable, and extensible by the operator.

Unified generative AI and traditional ML attack support.
This framework represents the first unified approach to AI red teaming that seamlessly supports both generative AI attacks (prompt-based) and traditional ML attacks (input perturbation-based) through a single interface. For generative AI systems, attacks operate through natural language prompts and responses, leveraging techniques like Tree of Attacks with Pruning, Crescendo, and prompt injection to bypass safety guardrails and elicit harmful outputs. The attack loop involves generating adversarial prompts, evaluating model responses against safety criteria, and iteratively refining based on feedback. For traditional ML systems, attacks operate through input space perturbations, using gradient-free optimization techniques like SimBA, NES, ZOO, and HopSkipJump to craft adversarial examples that fool classifiers while maintaining semantic similarity to original inputs. The attack loop involves generating input perturbations, evaluating model predictions against target classes, and optimizing perturbation magnitude within specified distance constraints.
The unification is achieved through a common abstraction layer that treats both prompt-based and perturbation-based attacks as iterative optimization problems over different input spaces. Both attack types share the same workflow structure: objective specification, iterative candidate generation, target evaluation, scoring against success c

riteria, and refinement. The key insight is that whether attacking a language model with adversarial prompts or attacking a computer vision model with adversarial images, the underlying algorithmic pattern remains consistent: propose → evaluate → score → refine. This eliminates the traditional need for separate libraries (e.g., PyTorch for adversarial examples, specialized prompt injection tools for LLMs) and enables operators to apply the same methodology across their entire AI system portfolio. Execution Layer
Attacks execute with full OpenTelemetry (OTEL) instrumentation, whether running locally on the operator’s machine or remotely on dedicated compute infrastructure. Every prompt sent to the target, every response received, every scorer evaluation, and every transform application is captured as a structured trace span. This instrumentation is transparent to the operator and produces the raw data that the analytics layer consumes.
The execution layer supports both local and remote execution. In both modes, the same tracing pipeline captures identical structured data, ensuring consistent analytics regardless of where the attack runs.

Discussion
7.1
From Attack Libraries to Agentic Workflows
The central argument of this work is that the AI red teaming field is undergoing a transition analogous to what happened in software development: from library-driven development (where the programmer selects and composes primitives) to agent-assisted development (where the operator states intent and the agent generates implementation). This transition does not diminish the importance of the underlying attack algorithms; it changes
who manages their composition and execution
.
We observe that this transition is driven by two forces. First, the combinatorial explosion of attack strategies, transforms, and target configurations makes manual navigation increasingly impractical. Second, the consumers of AI red teaming results increasingly include non-specialist stakeholders (compliance officers, executives, model product managers) who need structured findings rather than raw attack outputs.
7.2
Operator Cognitive Load
Our framework reduces operator cognitive load along several dimensions:
•
Recall
→

\rightarrow
recognition.
The operator does not need to remember the names, parameters, and empirical characteristics of 45+ attack strategies. They describe what they want to test, and the agent selects appropriate methods.
•
Implementation
→
\rightarrow
specification.
The operator specifies the goal, not the code. Transform composition, scorer configuration, and execution management are delegated to the agent.
•
Interpretation
→
\rightarrow
analysis.
The operator receives structured findings with severity, compliance tags, and evidence, rather than raw scorer outputs that require manual aggregation.
•
Stateless
→
\rightarrow
contextual.
The agent maintains assessment state across interactions, eliminating the need for the operator to re-specify context or manually track what has been tried.
7.3
The Role of Human Judgment
We emphasize that the agentic interface does not replace human judgment; it restructures where human judgment is applied. The operator’s expertise is deployed at the strategic level (what to probe, how to interpret findings, what constitutes acceptable risk) rather than the implementation level (which Python function to call, which parameters to set). The human-in-the-loop review capability ensures that automated classifications can be overridden by expert assessment, with full audit trails.
7.4
Generalization Beyond Jailbreaking
While the case study focuses on jailbreak testing, the framework is designed for the broader scope of AI red teaming that has emer

ged with agentic systems. The attack catalog includes tool-use manipulation, MCP server poisoning, multi-agent trust boundary probing, supply chain attacks, reasoning exploitation, and multimodal adversarial perturbation. As AI systems become more agentic, the attack surface expands beyond text-in/text-out to include tool calls, API interactions, inter-agent communication, and autonomous decision-making. Our framework’s extensible architecture accommodates this expanding surface.
8
Limitations
We acknowledge several limitations.
Agent reliability.
The agentic interface depends on the capability of the underlying LLM to correctly interpret operator objectives, select appropriate strategies, and generate valid workflows. Agent errors (misinterpreting objectives, selecting suboptimal strategies) are a practical concern, though the operator retains the ability to redirect at every step.
Scorer accuracy.
Automated LLM-based scorers are subject to the same biases and failure modes as the models they evaluate. The human-in-the-loop review capability mitigates this but does not eliminate it.
Coverage completeness.
While the framework integrates over 45 attack strategies, the space of possible adversarial techniques is open-ended. New attack vectors emerge continuously, and no fixed catalog can claim complete coverage.
Case study scale.
The case study completed in approximately 3 hours because it used a limited set of attack strategies, transforms, and goal categories. A full end-to-e
