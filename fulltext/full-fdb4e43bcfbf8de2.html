X推出MCP服务器，方便AI工具使用其平台

📅 2026-06-30 📄 TechCrunch AI 🔗 原文链接

原标题：X now offers an MCP server to make its platform easier for AI tools to use

中文摘要： X（原Twitter）推出托管MCP服务器，使Claude、Cursor等AI助手能直接通过用户账户权限连接X API。此举省去了开发者自行搭建服务器的麻烦，便于AI应用检索和分析X上的实时数据。为防滥用，该工具不支持写入API，无法用于自动发帖，且仍受X的API规则和提价政策限制。

X 正在通过一个新的托管 MCP 服务器，让 Claude、Cursor、Grok Build 和其他兼容 MCP 的应用等 AI 助手更容易地直接连接到该平台。

周一，这家由埃隆·马斯克拥有的社交网络[发布](https://devcommunity.x.com/t/announcing-the-hosted-x-mcp/269558)了一个[托管模型上下文协议 (MCP) 服务器](https://docs.x.com/tools/mcp)，允许 AI 工具使用用户自己的账户权限与 X API 进行通信。

背景信息：MCP 是一个开放标准，定义了 AI 模型连接到外部工具和服务的通用方式。以前，如果开发者希望 Claude 或 Cursor 等 AI 助手访问 X，他们必须构建自己的 MCP 服务器，托管它，连接到 X API，并处理身份验证。现在，X 托管了 MCP，用户使用自己的 X 账户权限进行身份验证。

这使得开发者可以节省花在集成工作上的时间，从而专注于他们实际构建的内容。

长期以来，开发者一直能够使用该平台的 API 搜索 X、阅读帖子、查找用户、分析对话和趋势等。托管 MCP 并没有在这方面增加新功能；它只是让这些功能更容易暴露给 AI 应用。通过这样做，X 可以将自己定位为一个充满实时数据以供检索和分析的信息网络，而不仅仅是一个社交聚集地。

此举意味着 X 加入了越来越多现在提供自己官方 MCP 服务器或端点的公司行列，如 [GitHub](https://github.com/github/github-mcp-server)、[Slack](https://slack.com/intl/en-gb/help/articles/48855576908307-Guide-to-Model-Context-Protocol-in-Slack)、[Notion](https://github.com/makenotion/notion-mcp-server)、[Stripe](https://docs.stripe.com/mcp) 和 [Salesforce](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/servers-reference.html)。

当然，人们总是担心，通过消除基础设施障碍，X 会使自己面临更多的自动发布或垃圾信息。

然而，X 向 TechCrunch 澄清，MCP 工具与 X 的 Write API 端点不兼容，因此无法使用它在 X 上自主（或完全）发帖。

还值得注意的是，托管 MCP 并没有绕过 X 的 API 规则，如果公司检测到垃圾信息行为，这些规则[将继续限制其使用](https://docs.x.com/developer-terms/restricted-use-cases)。

X 还在今年早些时候更新了其 [API v2](https://devcommunity.x.com/t/x-api-v2-update-addressing-llm-generated-spam/257909)，以解决 AI 生成的垃圾信息问题，特别是对对话的程序化回复。此外，它最近更新了 API 定价，[将发布帖子的成本提高到](https://techcrunch.com/2026/04/22/x-makes-it-more-expensive-to-post-links-through-its-api/) 0.015 美元，发布链接的成本提高到 [0.20 美元](https://x.com/XDevelopers/status/2044919377544261979)。X 当时表示，提价旨在“遏制滥用的途径”——这意味着在 X 上发垃圾信息至少变得越来越昂贵了。

_在 X 确认后，文章在发布后进行了更新，包含 MCP 工具将不提供“写入”权限的信息。_
