SwarmEvolve：面向演化发现与优化的潜空间智能体集群

George Em Karniadakis

摘要

LLM 引导的演化搜索利用 AI 智能体来改进数学与计算问题的程序，其方式是迭代地精化解并组合高分方法。然而，这一过程往往很慢，因为 LLM 每一轮都要生成很长的文本思维链，并且必须多次重复这一生成过程以维持种群多样性。

我们提出 SwarmEvolve，一个框架，其中每轮有数百个低成本智能体以集群方式协作，在潜空间中推理而无需解码为文本，并通过传递 KV 缓存来共享信息。每个集群从不同角度研究问题。新颖性过滤器通过直接测量智能体隐藏状态向量之间的距离，保留差异最大的智能体想法。想法的交叉在潜空间中自然发生：摘要智能体接收所有集群成员合并后的 KV 缓存。

在 21 个数学发现与科学计算问题上，SwarmEvolve 取得最高平均分，并且只需中位数 3 到 8 分钟即可达到其他最先进框架在 60 分钟内才能达到的最佳分数。在若干问题上，使用 Qwen3 8B 的 SwarmEvolve 改进了 AlphaEvolve 最初用前沿 LLM 找到的解。

我们的工作表明，在潜空间中通信的智能体集群为科学问题的程序搜索提供了一种快速、低成本的途径。

1 引言

数学和科学计算中的许多问题可以表述为对好程序的搜索。例子包括符号回归、优化不等式中的常数，以及为微分方程构建鲁棒的求解器。这种搜索可以通过演化计算来执行，这是一种通过变异、交叉和选择迭代改进候选程序的方法 [32, 39]。

最近，LLM 已被用作此类演化过程中的变异和交叉算子 [43, 49, 73]。这些 LLM 引导的框架在许多开放问题上取得了强劲进展。特别是，FunSearch 发现了新的帽集构造 [54]，AlphaEvolve 发现了一种更高效的 4×4 复矩阵乘法算法 [50]。后来的工作将这种方法应用于解决数学和计算机系统中的更多问题 [24, 20, 12]。这些框架的主要区别在于探索方式。FunSearch 在独立的岛屿上演化程序，而 AlphaEvolve 及其开源变体添加了 MAP-Elites 存档以保持程序的多样性 [59, 1, 37]。为了节省 LLM 调用，一些方法拒绝近乎重复的提案、自适应分配搜索预算，或演化搜索策略本身 [42, 10, 46]。其他方法用更好的上下文来引导探索，例如过去的更改如何影响分数、相关文献、模拟同行评审，或分为多个步骤的求解器 [34, 45, 78, 40]。

最近的工作还扩大了搜索规模。一些方法运行许多并行轨迹 [77]，或用强化学习针对每个问题训练 LLM [79, 64, 70]。其他方法使用更多具有不同角色的智能体，例如 AlphaEvolve 中的前沿 LLM 集成、多智能体辩论，以及通过共享内存或协调器协作的编码智能体 [35, 52, 69]。当智能体相互借鉴彼此的发现时，它们在开放问题上产生了新的结果 [9, 7]。这些工作表明，多样化的提案、想法的交叉授粉和迭代改进是在开放科学问题上取得新发现的关键。

然而，在大多数这些框架中，搜索既慢又昂贵。每个智能体都要用文本编写一条长长的思维链。不断增长的解存档、评估器反馈和智能体之间的文本消息使 LLM 上下文非常长。扩展到更多智能体、更大模型或测试时训练会使成本成倍增加。因此，搜索无法以许多开放问题所需的规模运行。我们由此提出问题：

低成本智能体集群能否让演化搜索更快、更好？

我们提出 SwarmEvolve，一个演化搜索框架，其中低成本潜空间智能体集群在潜空间中推理并通过传递 KV 缓存进行通信。它建立在最近关于潜空间推理的工作之上——LLM 用连续向量而非采样 token 进行推理 [29, 80, 60, 74, 82]——以及潜空间通信的工作之上——LLM 交换 token 嵌入 [51]、激活 [53]、隐藏状态 [81, 19, 84] 或 KV 缓存 [61, 23]，而非文本消息。特别是，LatentMAS 无需训练即可将两者结合：其智能体在潜空间中推理，并将它们的 KV 缓存传递给撰写答案的摘要器 [85]。我们使用这种机制作为大规模、低成本演化搜索的基础。

因为潜空间推理和通信很便宜，SwarmEvolve 在每轮演化中运行数百个智能体。智能体形成不同的集群，每个集群有自己的关注点，例如实现文献中的构造或使用教科书方法。在集群内部，每个智能体从其独特的视角进行 40 个潜空间步骤的推理。然后，新颖性过滤器保留每个集群中潜空间推理轨迹在余弦距离上相距最远的智能体。最后，每个集群的摘要智能体读取被保留智能体的 KV 缓存并编写一个新程序。

与现有框架相比，SwarmEvolve 具有三个优势：

  1. 更大的多样性。 现有方法一次生成一个响应或运行一个小的智能体团队，而 SwarmEvolve 每轮运行 450 个潜空间智能体，每个智能体具有不同的专业化、父程序和思维方式，因此能采样到更多样的提案。
  2. 内置交叉。 SwarmEvolve 直接在潜空间中重组想法。摘要智能体读取研究了不同父程序的智能体的 KV 缓存，并编写一个结合它们想法的程序。
  3. 更高的吞吐量。 由于智能体在步骤之间不解码或编码文本，SwarmEvolve 每小时评估的程序比现有 SOTA 框架多 5 到 13 倍，并在中位数 3 到 8 分钟内达到它们 60 分钟的分数。

我们在来自数学发现和科学计算的 21 个问题上将 SwarmEvolve 与 OpenEvolve、ShinkaEvolve 和 CodeEvolve 进行比较。每个框架使用 Qwen3 8B、14B 和 32B-FP8 [75] 在单 GPU 上运行 60 分钟（图 1）。SwarmEvolve 在所有三个模型上都取得最高平均分。使用 Qwen3 8B 时，它的得分高于使用 Qwen3 32B-FP8 的所有三个基线。仅 15 分钟后，它的得分就已经高于所有基线在任何模型下的 60 分钟平均值。在三个问题上，使用冻结 Qwen3 8B 的 SwarmEvolve 还改进了 AlphaEvolve 最初用前沿 Gemini 模型找到的构造。这些结果表明，低成本潜空间智能体集群是利用 AI 进行开放数学和科学发现的一种快速且可扩展的方式。

2 预备知识

在本节中，我们介绍我们方法的预备设置和符号。

2.1 LLM 与 KV 缓存

我们使用仅解码器的 transformer LLM [68]，它将位置 t 的输入 token 嵌入为向量 e_t ∈ R^d，其中 d 是隐藏维度，并将序列通过 L 个 transformer 层。最后一层在位置 t 的输出是最后隐藏状态 h_t ∈ R^d。LLM 从 h_t 计算下一个 token 的分布。

在每一层内部，位置 t 的查询 q_t 关注所有位置 j ≤ t 的键 k_j 和值 v_j。因为一个位置的键和值只取决于到该位置为止的 token，LLM 将它们存储在 KV 缓存 {(K^(ℓ), V^(ℓ))}_{ℓ=1}^{L} 中，其中 K^(ℓ) 和 V^(ℓ) 堆叠层 ℓ 中所有位置的键和值。于是每个新 token 只需单个位置的一次前向传播，它关注 KV 缓存并将其自身的键和值附加到其中。共享前缀（例如问题陈述）的 KV 缓存通常只计算一次，并被延续它的每个序列重用以提高效率。

我们使用的 Qwen3 模型采用旋转位置编码（RoPE）[63, 75] 编码位置。RoPE 将位置 i 的每个查询和键乘以旋转矩阵 R_i，其角度随 i 线性增长，因此注意力分数只取决于两个位置之间的偏移：

(R_i q)^⊤ (R_j k) = q^⊤ R_{j−i} k. （公式 1）

因此，将 KV 缓存的一个块从位置 0, 1, 2, … 移动到位置 δ, δ+1, δ+2, … 需要将每个缓存的键乘以 R_δ，因为值不携带位置信息。

2.2 潜空间推理

LLM 通常通过解码文本思维链进行推理 [71, 38]。在潜空间推理中，LLM 而是将最后隐藏状态 h_t 反馈为下一个输入嵌入 e_{t+1}，因此它在连续嵌入空间中推理而不采样 token [29, 80, 83]。

LatentMAS 将潜空间推理应用于 LLM 智能体而无需训练 [85]。智能体读取其输入后，每个潜空间推理步骤将最后隐藏状态 h_t 直接映射到下一个输入嵌入 e_{t+1}。该映射有两部分。首先，对齐矩阵 W_a 将 h_t 映射到输入嵌入空间。其次，结果被重新缩放到范数 γ，其中 γ 是词汇表上输入 token 嵌入的平均范数。矩阵 W_a 是岭回归解（正则化权重为 ρ），它将每个 token 的输出嵌入映射到其输入嵌入：

e_{t+1} = γ · W_a h_t / ‖W_a h_t‖， W_a = W_in^⊤ W_out (W_out^⊤ W_out + ρI)^{-1}， （公式 2）

其中 W_in, W_out ∈ R^{|V|×d} 分别是输入和输出嵌入矩阵，|V| 是词汇表大小。智能体采取公式 2 给出的固定数量的潜空间推理步骤，不解码任何文本。每个潜空间推理步骤向 KV 缓存添加一个位置。

2.3 潜空间通信

LatentMAS 智能体通过传递 KV 缓存而非文本进行通信 [85]。在标准的分层设置中，J 个智能体（通常具有不同的专业化）各自采取自己的潜空间推理步骤，然后由摘要智能体撰写最终答案。设 K_j^(ℓ) 和 V_j^(ℓ) 为智能体 j 在层 ℓ 的键和值，j = 1, …, J。设 K_sum^(ℓ) 和 V_sum^(ℓ) 为摘要器自身提示在层 ℓ 的键和值。摘要器的 KV 缓存沿序列维度将它们拼接：

K^(ℓ) = [K_1^(ℓ); …; K_J^(ℓ); K_sum^(ℓ)]， V^(ℓ) = [V_1^(ℓ); …; V_J^(ℓ); V_sum^(ℓ)]，对每层 ℓ。 （公式 3）

摘要器随后将答案解码为文本，同时关注其自身的输入和所有 J 个智能体的潜空间推理步骤。当智能体并行运行时，每个智能体的 KV 缓存从位置 0 开始。因此，我们使用公式 1 中的旋转将每个缓存移动到其在拼接中的偏移位置。

3 SwarmEvolve

SwarmEvolve 是一个演化搜索框架，运行潜空间推理智能体集群以在多轮中改进程序。它维护所有候选程序的存档，连同它们的分数和评估反馈。在每一轮中，它从存档中选择父程序进行改进和交叉。搜索需要一个初始程序，通常是一个简单的基线解。如图 3 所示，每轮包含以下步骤。

组建集群。 为开始一轮，SwarmEvolve 组建 10 个集群，每个集群 45 个潜空间智能体。集群中的所有智能体共享一个主要焦点。每个智能体接收一个独特的提示，它将该焦点的五种表述之一与九种思维方式之一结合，例如从第一性原理推理或重新审视假设（补充表 4）。每个集群还接收一组父程序，这些程序轮流分配给其智能体，使每个智能体恰好读取一个程序。10 个集群分为四种类型：

  • 四个改进集群各接收存档中两个最佳程序之一，每个程序配两个集群。每个集群采用迄今为止对该程序使用最少的主要焦点，例如其数学表述或其对时间预算的使用。它们的目标是改进最佳程序。
  • 三个杂交集群各接收从十个最佳程序中随机抽取的五个程序，因此每个程序由九个智能体读取。它们的目标是将最强的想法组合成一个新程序。
  • 两个探索集群各接收从整个存档中随机抽取的四个程序。九个智能体读取每个程序，另外九个智能体只读取问题陈述而没有父程序。它们的目标是探索较少被考虑的方向。
  • 一个全新开始集群只接收初始程序。它的目标是找到与现有方法不同的新途径。

在潜空间中推理。 每个潜空间智能体读取问题陈述、其焦点提示以及分配给它的父程序及该程序的评估结果。然后它采取 40 个潜空间推理步骤。所有 450 个智能体在一个批次中运行。读取相同程序的智能体通过分页注意力 [41] 关注其 KV 缓存的一个共享副本。

新颖性过滤。 在每个集群中，新颖性过滤器保留推理差异最大的 30 个潜空间智能体，丢弃其余 15 个。设 h_{j,t} 为智能体 j 在潜空间推理步骤 t 的最后隐藏状态。每个智能体由其在 40 步上的平均隐藏状态表示：

h̄j = (1/40) Σ{t=1}^{40} h_{j,t}， j = 1, …, 45. （公式 4）

然后，每个智能体的平均隐藏状态 h̄_j 以集群均值 μ 为中心，并归一化为单位向量 z_j = (h̄_j − μ)/‖h̄_j − μ‖。保留集合 K 从最接近 μ 的智能体开始。随后在余弦距离中进行贪心最远点选择 [26]，一次添加一个智能体，选择

j* = argmax_{j∉K} min_{i∈K} (1 − z_j^⊤ z_i)， （公式 5）

直到 K 包含 30 个智能体。

传递 KV 缓存。 每个摘要器通过一个 KV 缓存读取其 30 个被保留智能体的推理（图 3）。在每层 ℓ 中，此 KV 缓存是以下拼接：

K^(ℓ) = [K_prob^(ℓ); K_1^(ℓ); …; K_30^(ℓ); K_{p1}^(ℓ); …; K_{pQ}^(ℓ); K_ins^(ℓ)]，
V^(ℓ) = [V_prob^(ℓ); V_1^(ℓ); …; V_30^(ℓ); V_{p1}^(ℓ); …; V_{pQ}^(ℓ); V_ins^(ℓ)]， （公式 6）

其中 K_prob^(ℓ) 和 V_prob^(ℓ) 是问题陈述的键和值。对于 j = 1, …, 30，K_j^(ℓ) 和 V_j^(ℓ) 是第 j 个被保留智能体的焦点提示和 40 个潜空间推理步骤的键和值。对于 q = 1, …, Q，K_{pq}^(ℓ) 和 V_{pq}^(ℓ) 是集群的第 q 个父程序 p_q 的键和值。K_ins^(ℓ) 和 V_ins^(ℓ) 是摘要器指令的键和值。在拼接之前，每个潜空间智能体的键 k 被旋转为 R_δ k（公式 1），其中 δ 是其块在 K^(ℓ) 中的位置。值不携带位置信息，因此原样拼接。

编写程序。 接收到 KV 缓存后，摘要器综合并解码其智能体的潜空间推理轨迹。摘要器输出其方向的简短描述以及解决问题所需的一个完整程序。

调优参数。 每一轮，参数调优智能体读取最佳程序、其评估结果以及该程序所有数值参数的列表。然后它为其中一个参数提出一个新值以改进程序。SwarmEvolve 每轮评估最多 8 个这样的单数字编辑。

评估。 生成新程序后，框架丢弃与早期程序重复的程序，检查语法，并自动添加标准包名称的缺失导入。然后确定性评估器在 CPU 核心上为每个新程序评分。评估器完成后，已评分程序连同其分数、日志和错误消息进入存档。

SwarmEvolve 在运行的时间预算内迭代这些步骤。运行结束时，存档中得分最高的程序作为最终解返回。

5 讨论

SwarmEvolve 表明演化搜索可以同时做到快速、廉价且强大。潜空间智能体跳过了编写文本的缓慢步骤，因此一个 GPU 可以在每轮中运行数百个智能体。在相同的模型和相同的时间预算下，SwarmEvolve 评估比基于文本的框架更多的程序，在运行早期达到它们的最终分数，并以更高的分数结束。即使使用小型开源权重 LLM，它也改进了 AlphaEvolve 用前沿 LLM 找到的若干构造。

潜空间推理是这一收益的关键部分。当我们用文本推理替换潜空间推理步骤时，分数会下降（附录 A.1），即使给智能体的文本 token 预算高于潜空间 token 预算。更长的文本使每轮更慢，因此搜索在相同时间内评估更少的程序并以更低的分数结束。潜空间推理给每个智能体足够的思考空间，同时保持每轮简短。

扩展集群中智能体的数量也有助于在搜索早期改善框架性能（附录 A.2）。由于更大的集群从更多角度研究每个父程序，每轮在初期探索更多的设计空间。当每次评估很昂贵时（例如科学或工程中的大型模拟，只能评估少数程序），这种早期优势最为重要。在搜索后期，不同大小的集群达到相似的分数，而扩展到更大、更智能的 LLM 仍会持续提高最终分数。

更广泛地说，SwarmEvolve 使在单个 GPU 上进行大规模新程序搜索变得经济可行。这为数学和科学计算中的许多问题打开了这种方法的大门。在数学中，集群可以搜索新的构造和证明策略。在计算领域，它们可以改进算法的速度和精度。在科学计算中，它们可以编写更好的 PDE 求解器、通过符号回归发现公式，并设计更高效的数值方法。许多这类问题都有明确的评估器或期望的结果，例如更高的精度或更快的速度，而这正是演化搜索所需要的。

SwarmEvolve 有三个局限性。首先，所有潜空间智能体和摘要器共享一个 LLM，因为摘要器只有在其智能体的 KV 缓存来自同一模型时才能直接读取它们。不同模型 KV 缓存之间的可学习翻译 [23] 可以将 SwarmEvolve 扩展到智能体运行不同模型的集群。其次，我们的实现需要具有标准注意力的 LLM。线性注意力、状态空间和混合模型将过去压缩为固定大小的状态 [36, 27, 76]，因此它们之间的潜空间通信需要一种合并多个智能体状态的方法。第三，一轮 KV 缓存的内存随智能体数量、潜空间推理步骤数和层数线性增长，因此我们测试的最大 LLM 需要大型 GPU。压缩的潜空间消息 [11] 和分布在多个 GPU 上的轮次可以让 SwarmEvolve 扩展到更大的模型和更长的运行。

6 总结

我们介绍了 SwarmEvolve，一个演化搜索框架，其中低成本智能体集群在潜空间中推理并通过传递 KV 缓存进行通信。这种设计让一个 GPU 在每轮中运行数百个智能体，因此搜索在相同时间内探索更多的设计空间。在来自数学发现和科学计算的问题上，SwarmEvolve 比基于文本的框架更快地找到更好的程序，并且使用小型开源权重 LLM 改进了 AlphaEvolve 用前沿 LLM 找到的若干结果。这些结果表明，大规模搜索新的数学构造、算法和科学计算方法不一定需要前沿模型或大量计算预算。小型潜空间智能体集群可以使这种 AI 驱动的科学发现快速、廉价、强大且广泛可用。

  2. 潜空间中的新颖性检查。 为了检查新颖性，ShinkaEvolve 用单独的嵌入模型嵌入每个新程序的代码，当其与存档程序的余弦相似度超过 0.99 时，询问 LLM 两个程序是否不同。这些额外的 LLM 调用每次运行需要几分钟。SwarmEvolve 的新颖性过滤器则是比较潜空间智能体的平均隐藏状态，这些状态已经在 GPU 内存中，每次运行只需几秒钟。

实现。 我们用 PyTorch 和 Hugging Face Transformers [72] 的 Qwen3 模型实现 SwarmEvolve。一轮的潜空间智能体作为一个批次运行，读取相同程序的潜空间智能体通过 vLLM 的分页 FlashAttention 内核 [18, 41] 关注其 KV 缓存的一个共享副本。一轮的摘要器作为一个批次解码，使用分页 KV 缓存和提示查找推测采样——后者通过从上下文中的程序复制 token 来起草 token [57]，并用推测采样的接受规则验证它们，因此样本完全遵循模型的分布 [44]。使用 Qwen3 14B 和 32B-FP8 时，SwarmEvolve 还将其解码步骤捕获在 CUDA 图中，并使用 vLLM 的融合内核，包括 H100 GPU 上的 FlashAttention-3 [58]。三个基线用 vLLM 服务模型，vLLM 连续批处理请求、缓存共享前缀并运行 CUDA 图，因此它们的解码以生产级服务引擎的速度运行。CodeEvolve 以八个岛屿（每个 CPU 核心一个）运行其 Qwen 模型配置。所有四个框架运行 Qwen3 32B-FP8，使用 Qwen 发布的 FP8 权重。
