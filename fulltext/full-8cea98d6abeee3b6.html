摘要

机器人操作视频提供了丰富的视觉经验，但从RGB观测中恢复机器人动作与夹爪状态标注仍然具有挑战性。我们采用与本体无关的工具中心点（TCP）位姿作为动作空间，提出 TCP4D——一个统一模型，其共享的4D场景表示既能跟踪观测到的TCP运动，又能生成未来的TCP轨迹。给定单目视频和初始2D TCP查询，跟踪器直接恢复SE(3)中的度量TCP位姿与夹爪状态，同时得到场景几何和相机参数。生成器从同一4D表示中沿恢复的TCP轨迹采样局部特征，再结合机器人观测和语言指令预测未来TCP状态。我们提出的全新跨本体增强流水线，通过重定向恢复的运动并合成相应观测，将现有RGB视频转换为其他本体的演示数据，无需记录的源机器人状态。实验表明，跟踪器在DROID和RoboLab上的绝对轨迹误差分别为7.60和16.07毫米，且仅需十条演示即可适应新本体；生成器在RoboTwin上取得69.19%的平均成功率，并在两个真实任务上超越成熟的策略模型，同时源数据与增强数据的联合训练相比仅用增强数据训练将目标机器人成功率提升41.5%。

1 引言

大规模机器人操作视频数据为学习多样化技能提供了丰富的经验来源。这些数据为现代视觉-语言-动作（VLA）模型和世界动作模型（WAM）提供了重要基础，其训练依赖于动作监督。然而，并非所有视频都包含同步的动作标注，仅从RGB视频中恢复这些标签仍然是一个非平凡的挑战。

恢复末端执行器的运动为从视频中获取此类监督提供了一条实用途径。该运动可由工具中心点（TCP）位姿（即SE(3)）表示，它指定末端执行器工具坐标系的位置和方向。在共同参考坐标系下，TCP提供了统一的动作表示：相同的位姿在不同机器人平台上编码相同的任务空间目标，即使它们的关节配置不同，因为每个机器人（若在工作范围内）可通过自身的逆运动学（IK）到达该位姿。

最近的4D点跟踪方法可从RGB视频恢复场景几何并跟踪3D表面点。然而，TCP是虚拟工具坐标系的原点，可能位于夹爪手指之间的自由空间中，其图像投影因此可能落在背景像素上。此外，点跟踪器仅预测3D位置而非工具方向，因此即使TCP原点的轨迹再准确也无法确定完整的TCP位姿。从这些跟踪器恢复完整TCP位姿依赖于额外的机器人特定先验和多阶段后处理，误差会沿流程累积，可能导致位姿不准确或跟踪失败。

为应对这一挑战，我们提出 TCP4D，一个从共享4D场景表示中跟踪观测TCP运动并生成未来TCP轨迹的统一模型。给定单目RGB视频和每个手臂的初始2D TCP查询，跟踪器直接估计观测序列中SE(3)的TCP位姿和夹爪状态，以及度量场景几何和相机参数，无需额外的机器人先验或后处理。跟踪器还能以少样本方式适应新本体。

TCP位姿为机器人控制提供了动作接口，使预测的未来TCP轨迹可作为机器人动作执行。生成器沿跟踪的运动提取局部视觉特征，扩散Transformer（DiT）将这些特征与共享场景表示结合，生成任务条件的未来TCP和夹爪状态，作为操作策略。

由于恢复的TCP运动与本体无关，TCP4D进一步实现了一种新颖的跨本体数据增强流水线，将源机器人的现有RGB视频转换为目标本体的演示。与需要记录源机器人状态的现有方法不同，我们的流水线直接从视频恢复TCP轨迹和夹爪状态，通过分割与修复移除源机器人，并通过IK以恢复的轨迹驱动渲染目标本体。因此，单个视频即可为任何能够到达恢复运动的目标本体生成演示，无需额外数据收集。

大量实验在TCP跟踪、操作和跨本体数据增强方面验证了TCP4D。对于跟踪，TCP4D在DROID和RoboLab上分别实现7.60和16.07毫米的绝对轨迹误差，在UR5上仅使用十条演示实现8.85毫米。作为操作策略，它在RoboTwin上实现69.19%的平均成功率，在两个真实任务上实现78.33%。源数据与增强数据的联合训练提升了源机器人和目标机器人的成功率。

我们的主要贡献如下：

  • 我们提出TCP4D，一个直接从RGB视频恢复TCP位姿和夹爪状态、并根据观测和指令生成未来TCP轨迹的统一模型。TCP4D仅需少量演示即可有效适应新的机器人本体。
  • 我们开发了一种新颖的跨本体增强流水线，通过恢复的TCP运动将RGB演示转换为目标机器人训练数据，无需记录的源机器人状态轨迹。
  • 在仿真基准和真实世界设置中的多样化任务上的大量实验，证明了TCP4D在TCP跟踪和操作方面的强大性能，以及其跨本体数据增强的有效性。

2 相关工作

4D重建与点跟踪。 最近的4D重建前馈方法包括密集几何预测和基于查询的框架，可灵活访问跨时空的场景几何与运动。除了跟踪观测运动外，最近的方法还通过3D轨迹预测与补全预测未来点云动态。这些方法主要表征场景几何和点位置，局部方向是隐式的。并行工作MoSE3通过在被跟踪场景点的软聚类中拟合刚体运动，将运动估计扩展到密集的每像素SE(3)变换。相比之下，TCP4D直接跟踪虚拟TCP的SE(3)位姿，无需对应的物理表面点或刚体分组。

基于点的操作策略。 先前工作使用预测的2D点轨迹指导操作策略。在3D中，世界模型预测几何运动以支持规划与动作学习。其他方法从视觉预测中推断路标点或位姿，或将运动线索纳入VLA策略。基于点的策略还使用深度导出的场景几何来落实动作预测。DP3基于稀疏点云的紧凑特征对动作扩散进行条件化，Act3D在3D特征场中搜索下一个末端执行器位置，3D Diffuser Actor基于3D场景特征对位姿轨迹去噪。TCP4D使用TCP位姿和夹爪状态作为运动跟踪与动作生成之间的共享接口，在从RGB视频重建的4D场景表示中跨观测帧对其进行跟踪。

跨本体增强流水线。 现有机器人数据增强方法包括基于仿真的演示合成和图像空间语义增强，可在不额外收集真实数据的情况下扩展运动和场景多样性。对于本体迁移，Mirage使用测试时交叉绘制将目标机器人呈现为预训练策略期望的源机器人。RoVi-Aug使用基于扩散的图像生成将源机器人外观替换为目标本体，同时保留相关任务空间运动。OXE-AugE进一步通过基于仿真的轨迹重定向、背景修复和目标机器人渲染扩展本体增强。然而，RoVi-Aug和OXE-AugE假设可访问记录的源末端执行器位姿和动作。相比之下，TCP4D从RGB视频恢复SE(3)中的TCP轨迹和夹爪状态，并通过IK获得目标关节配置，实现无需记录源机器人状态的增强。

3 方法论

图2：TCP4D概览。① TCP4D跟踪器以单目视频为输入构建4D场景表示。给定初始帧中TCP的2D位置作为查询，它解码场景几何、TCP的SE(3)运动和夹爪状态。② TCP4D生成器沿TCP轨迹提取局部特征构成查询，并融入机器人状态。以当前4D场景表示、腕部RGB视角和语言指令为条件，它预测未来h步的TCP运动和夹爪状态。

我们提出TCP4D，一个从机器人操作单目视频中跟踪和预测SE(3)中TCP运动的前馈框架，如图2所示。我们首先在3.1节中阐述任务，在3.2和3.3节中介绍TCP4D跟踪器和生成器，在3.4节中描述两阶段训练。最后，3.5节介绍使用TCP4D的新颖下游数据增强流水线。

3.1 问题表述

TCP跟踪。 给定RGB序列 I = {I_i}（i=1,...,N）和指定参考帧中TCP像素坐标的2D TCP查询 u_1^a = ⟨x_1^a, y_1^a⟩，我们的目标是在每个观测帧中跟踪TCP状态 x_i^a = (T_i^a, g_i^a) ∈ SE(3)×[0,1]。这里 T_i^a = (R_i^a, t_i^a) ∈ SE(3) 表示帧i相机坐标系中的TCP位姿，包括方向 R_i^a ∈ SO(3) 和位置 t_i^a ∈ R³；g_i^a 表示夹爪状态，a ∈ {l, r} 索引左或右机器人手臂。TCP4D联合预测场景几何（度量深度图 D̂_i ∈ R^(H×W)）和相机光线图 M̂_i ∈ R^(H/2×W/2×6)，后者通过每像素光线方向和原点编码相对于第一个相机帧的相机内参和外参。我们将TCP4D跟踪器 T_θ 写为：

{{x̂_i^a}, D̂_i, M̂_i}（i=1,...,N）= T_θ(I, {u_1^a})。 (1)

TCP生成。 给定语言指令 ℓ，我们的目标是生成在时间t可用观测条件下的h步范围内的未来TCP状态。这些观测包括L个过去和当前RGB帧 {I_i}（i=t-L+1,...,t）、当前关节和夹爪状态 s_t、以及当前腕部相机RGB观测 I_t^(w,a)。我们将这些观测收集为 O_t = ({I_i}, s_t, {I_t^(w,a)})，并将语言条件生成器 G_θ 写为：

Â_t = G_θ(ε; O_t, ℓ) = {x̂_(t+k)^a}（k=1,...,h）， (2)

其中 ε ~ N(0, I) 是轨迹生成的初始噪声。所有未来TCP位姿均在相机坐标系中表示。

3.2 TCP4D跟踪器

4D场景表示编码。 遵循4RC，我们使用基于DINOv2的Transformer将输入视频编码为统一的4D场景表示。每帧被划分为patch token，并用可学习的相机token和时间token增强。主干交替进行帧内自注意力与跨帧全局自注意力，以捕获空间结构和时间对应关系。我们写作：

F = E_θ(I) = {(F_i, c_i, e_i)}（i=1,...,N）， (3)

其中 F_i 包含编码的4D表示token，c_i 是总结相机几何的相机token，e_i 是聚合帧i时间上下文的时间token。

几何头。 具有Dual-DPT解码器的几何头将编码的4D表示token映射到度量深度图 D̂_i ∈ R^(H×W) 和相机光线图 M̂_i ∈ R^(H/2×W/2×6)，以及它们的置信度图。轻量级相机头额外将 c_i 解码为相对于机器人基座的相机位姿和视场。

稀疏TCP查询。 为识别每个手臂的TCP，视觉查询编码器 Q_θ 从 F_1 中围绕 u_1^a 双线性采样3×3邻域。残差适配器和可学习的臂与偏移嵌入编码局部外观和查询身份。我们在四个主干层级提取这些稀疏查询token，并在目标帧中重复。我们首先在参考帧中编码TCP查询，然后在每个目标帧解码其表示：

Q_1 = Q_θ(F_1, {u_1^a})， Z_i = D_θ(Q_1, F_i; e_i)， (4)

其中 Q_1 包含所有手臂的稀疏TCP查询token，Z_i 包含它们在帧i的解码表示。每层首先应用交叉注意力（查询序列提供查询，F_i 提供键和值），然后在查询序列内应用自注意力。参考帧采样位置和目标帧patch位置通过2D RoPE进入注意力操作。时间token e_i 额外通过AdaLN调制自注意力和前馈层。最后，轻量级预测头回归TCP平移 t̂_i^a、连续6D旋转表示、夹爪状态 ĝ_i^a 和位姿置信度。旋转预测投影到SO(3)形成 T̂_i^a，连同 ĝ_i^a 得到跟踪状态 x̂_i^a。

3.3 TCP4D生成器

跟踪条件表示。 生成器建立在4D场景特征 F_i 和TCP轨迹 {x̂_i^a}（i=t-L+1,...,t）之上。我们使用预测的相机内参将每个跟踪的TCP平移 t̂_i^a 投影到其观测帧中获得图像查询 û_i^a，并使用共享编码器 Q_θ(F_i, {û_i^a}) 提取局部TCP token。我们向局部TCP token添加空间和时间嵌入，以编码其图像位置和观测顺序。

条件运动生成。 DiT采用由机器人状态 s_t 嵌入、局部TCP token和带噪声的未来动作token连接而成的单一序列。自注意力联合更新此序列，而交叉注意力使用当前场景特征 F_t、腕部图像特征和语言特征作为键和值。共享的冻结DINOv2编码腕部图像 I_t^(w,a)，冻结的T5-base编码器编码指令 ℓ。我们使用流匹配训练DiT。对于归一化的目标动作序列 A，噪声输入和目标速度为：

A_τ = (1-τ)ε + τA， v* = A - ε， (5)

其中 τ ∈ [0,1) 是流时间。输出头将未来动作token映射到预测速度 v_φ(A_τ, τ; O_t, ℓ)。推理时，四次欧拉更新将 ε 转换为未来动作序列，经去归一化并解码为 Â_t。

3.4 训练目标

我们使用不同的目标和训练策略分两阶段训练TCP4D。损失定义、归一化和组件权重见附录A。

阶段1：几何与TCP重建。 我们联合训练视觉主干、几何头和TCP跟踪器，以重建可用手臂的度量场景几何和TCP状态：

L_stage1 = L_geo + λ_tcp·L_tcp^(1)。 (6)

几何损失 L_geo 结合置信度加权的深度和光线回归与多尺度深度梯度项。TCP监督 L_tcp^(1) 结合置信度加权的刚体点位姿误差、旋转对齐、时间速度一致性和夹爪预测。

阶段2：条件TCP生成。 我们从阶段1初始化主干和跟踪器模块，并与条件模块和DiT联合微调：

L_stage2 = L_geo + λ_tcp·L_tcp^(2) + λ_fm·L_fm。 (7)

流匹配损失 L_fm 监督两个手臂的位置、旋转和夹爪分量的预测速度。L_tcp^(2) 保留位姿和夹爪监督，省略时间速度项。

3.5 跨本体增强流水线

4 实验

我们从四个维度评估TCP4D：(1) TCP跟踪性能，(2) 跨本体数据增强的有效性，(3) TCP生成器的机器人操作性能，(4) 物理机器人平台上的真实世界操作性能。

4.1 训练设置

数据集与基准。 我们使用由PointWorld标注的DROID子集，包含33,966集（67,932个相机序列）的Franka Panda 7自由度机械臂数据。我们使用90%的集进行训练，并从剩余10%中随机抽取100集作为评估集。对于野外评估，我们额外收集了RoboLab中100个不同任务的100集。为评估机器人操作，我们使用RoboTwin并为48个任务各收集50个干净演示，采用第三人称视角。我们在这些演示上训练，并在clean2clean和clean2random两种设置下评估。

实现细节。 阶段1中，我们分别在DROID和RoboTwin上训练两个独立的TCP跟踪器，从预训练的4RC权重初始化其视觉主干和几何模块。RGB图像分辨率对DROID为320×180，对RoboTwin为320×240。我们采样阶段1片段时使用随机起始帧、从1-5随机选择的每片段时间步长以及时间反转。阶段2中，我们仅使用RoboTwin数据训练TCP生成器。每个样本包含L=4个连续观测帧与接下来h=32个TCP状态配对，保持时间顺序。阶段1跟踪器和完整TCP4D模型分别包含约1.522B和2.272B参数（包括冻结模块和保留的头）。更多实现细节见附录C。

4.2 TCP4D跟踪性能

基线。 我们在DROID和RoboLab视频上将TCP4D与VGGT-Omega、DA3、MapAnything、4RC、VDPM、Any4D、Track4World、CoTracker3和MoSE3进行比较。由于没有现有方法直接跟踪TCP，我们对点跟踪基线预测的点轨迹进行后处理以恢复TCP轨迹和位姿。

评估指标。 我们报告3米内深度的AbsRel、MAE和δ₁；3D TCP跟踪的平均点百分比（APD）和平均位置误差（MPE）；SE(3)跟踪的绝对轨迹误差（ATE）、相对旋转误差（RRE）和相对平移误差（RTE）；以及跟踪成功率（SR）。夹爪准确率使用0.5阈值。指标定义和评估协议见附录D。

图4：TCP跟踪的定性比较。我们将TCP4D的TCP跟踪与后处理的密集跟踪基线进行比较。左侧为输入视频。第一帧中的红点标记TCP4D使用的查询，绿点表示基线跟踪的刚体点组。更多可视化见附录D.8。

结果。 如表1所示，TCP4D在两个基准的大多数评估指标上实现了最先进的性能。在DROID和RoboLab上，它分别实现74.78%和43.71%的APD分数，是最强基线的四倍以上，并将ATE降至7.60和16.07毫米。TCP4D还在两个数据集上实现100% SR，成功处理所有评估的跟踪窗口，而最佳基线SR分别为89.64%和96.33%。竞争的点跟踪方法依赖于跟踪刚体点组并在后处理中拟合刚体变换以恢复TCP位姿；不准确或不一致的点轨迹可能产生不可靠的位姿估计或导致恢复失败。通过在统一的前馈框架中直接预测TCP位姿和夹爪状态，TCP4D避免了这一恢复步骤，即使在未见过的操作场景中也能提供准确可靠的跟踪。图4直观比较了TCP4D与其他基线。更多结果见附录D.8。

少样本跨本体适应。 TCP4D在DROID数据集上预训练后展现出强大的少样本跨本体适应能力。我们在Berkeley AUTOLAB UR5数据集上评估，该数据集包含使用UR5-WSG跨不同任务的1,000个演示集，共97,939个视频帧。我们在两种设置下微调TCP4D：(1) 使用三个随机选择集的三样本迁移；(2) 使用十个随机选择集的少样本迁移。如表2所示，三样本适应将APD从MoSE3的14.39%提升至48.27%，ATE从44.56降至12.22毫米。使用十个集时，APD进一步提升至64.28%，ATE降至8.85毫米，夹爪准确率达到98.48%。这些结果表明TCP4D跟踪器仅需少量数据即可轻松迁移到新环境和机器人本体。可视化见附录D.9。

结果。 我们在48个RoboTwin任务上评估TCP4D，每个任务100次试验，并在表3中报告成功率。TCP4D在clean2clean下实现了69.19%的最高报告平均成功率。它分别超过已建立的操作策略ACT、RDT和DP3达39.94%、35.27%和14.92%，并且也优于多个VLA模型，包括EventVLA（65.71%）、GalaxeaVLA（62.73%）和π₀（45.21%）。这些结果支持从4D场景表示预测未来TCP运动的有效性，并突出了该范式在机器人操作中的潜力。所有48个任务的完整结果见附录F.1。在clean2random下平均成功率降至10.94%，其中环境随机化引入了分布偏移。我们的TCP生成器仅在干净演示上训练。纳入大规模本体数据预训练或来自更广泛来源混合的3D几何数据可提升对随机化环境的泛化能力，这是我们留待未来工作的方向。

4.5 真实世界评估

真实世界设置。 我们在CoBoT Magic平台上进行真实世界实验。我们评估两个任务：1)放置笔和2)用左右手臂堆叠碗。两个任务都需要大的TCP位移。我们为每个任务收集60条演示轨迹用于训练。我们使用cuRobo库求解IK。

评估协议。 我们将TCP4D与两个已建立的策略DP3和ACT进行比较，使用相同的演示数据进行微调，并对所有方法采用相同的评估协议。对于每个任务和方法，我们进行30次试验并报告二元任务成功和阶段式进度分数。任务特定的进度分数计算预定义任务序列中已完成阶段的数量（最多四个），其评分标准见附录F.2。

图8：真实世界任务性能。实心柱报告使用左轴的成功率，而斜线柱报告使用右轴的平均进度分数。

结果。 如图8所示，TCP4D在两个真实世界任务上的成功率和进度分数均优于DP3和ACT。它在放置笔上实现83.33%的成功率，在堆叠碗上实现73.33%。两个任务平均，TCP4D达到78.33%的成功率，而DP3为63.33%，ACT为31.67%，分别提升15.00和46.67个百分点。其平均进度分数为4分中的3.50分，表明它在试验中完成了更多任务阶段。DP3基于从深度观测重建的稀疏3D点云对其策略进行条件化。相比之下，TCP4D直接从RGB视频推断场景几何和TCP运动，在推理时无需测量深度即可实现更高的任务成功率。这些结果证明了我们的4D场景几何表示在操作中的有效性，同时减少了部署时对深度感知的依赖。

5 结论

我们提出了TCP4D，一个使用共享4D场景表示从RGB视频跟踪TCP运动并根据恢复的轨迹生成未来动作的统一模型。我们的跨本体流水线将视频转换为目标机器人演示。实验证明了准确的跟踪、少样本适应、有效的操作以及通过增强数据改进的策略学习。TCP4D有潜力随着更多样化的数据和机器人本体而扩展。

附录A 详细训练目标

本节详细介绍公式6和7中的损失，重点在于TCP跟踪监督。我们使用与主论文相同的TCP状态 x_i^a = (T_i^a, g_i^a) 和位姿 T_i^a = (R_i^a, t_i^a)。这里 R_i^a ∈ SO(3) 和 t_i^a ∈ R³ 是帧i相机坐标系中的TCP方向和位置，g_i^a ∈ [0,1] 是夹爪状态。索引a标识可用手臂，a ∈ {l, r} 用于双手操作。对于监督输出，带帽符号表示预测，无帽量表示真值。

A.1 几何监督

给定RGB视频 I = {I_i}（i=1,...,N），几何头预测深度图 D̂ = {D̂_i} 和相机光线图 M̂ = {M̂_i}，其中 D̂_i ∈ R^(H×W)，M̂_i ∈ R^(H/2×W/2×6)，H、W为图像高度和宽度。每条光线包含在第一个相机帧中表示的观察方向和相机原点。我们用 M_i 表示光线图，保留 R_i^a 用于TCP旋转。深度和光线置信度图分别记为 Ŷ_d 和 Ŷ_r。遵循4RC和Depth Anything 3，几何目标结合深度回归、空间深度梯度和光线回归：

L_geo = L_depth + L_grad + L_ray。 (8)

所有三项具有单位权重。深度和相机平移保留度量尺度。

置信度加权回归。 对于预测 x̂ ∈ R^d、目标x和正置信度ŷ，定义：

ℓ_reg(x̂, x) = (1/d)‖x̂ - x‖₁， (9)
ℓ_conf(x̂, x, ŷ) = ŷ·ℓ_reg(x̂, x) - α·log ŷ，

其中 α = 0.2，与下面TCP监督使用的置信度正则化一致。深度使用 d=1，光线使用 d=6。设p索引像素及其视频帧，Ω_d 和 Ω_r 分别表示有效的深度和光线网格位置。

深度损失。 对于预测深度 D̂、真值D和置信度 Ŷ_d，在有效深度像素上平均：

L_depth = (1/|Ω_d|) Σ_{p∈Ω_d} ℓ_conf(D̂p, D_p, Ŷ{d,p})。 (10)

深度梯度损失。 为保持锐利边缘和平滑平面区域，我们惩罚预测与真值深度梯度之间的差异：

L_grad = ‖∇_x D̂ - ∇_x D‖₁ + ‖∇_y D̂ - ∇_y D‖₁。 (11)

这里 ∇_x 和 ∇_y 是水平和垂直有限差分算子。实践中，我们在 J=4 个二进制度（步长2^j，j=0,...,J-1）上评估此项并平均结果，仅使用端点具有有效深度的差异。

光线损失。 对于六通道光线预测 M̂、真值M和置信度 Ŷ_r：

L_ray = (1/|Ω_r|) Σ_{p∈Ω_r} ℓ_conf(M̂p, M_p, Ŷ{r,p})。 (12)

公式9中的因子1/d在六个光线通道上平均残差。

A.2 TCP跟踪监督

图9：TCP跟踪监督说明。左侧绿色Robotiq夹爪表示真值TCP，右侧橙色Robotiq夹爪表示预测TCP。我们将每个TCP扩展为七个虚拟点的刚体集合，从而在不额外标注的情况下增强TCP位姿SE(3)监督。TCP位姿在每个观测帧自身的相机坐标系中被监督。手臂索引a遍历可用手臂（如左臂和右臂），因此相同的公式适用于单臂和双手跟踪。

虚拟点位姿监督。 遵循基于点的位姿监督，我们通过对齐刚体变换的参考点来监督TCP平移和方向。如图9所示，仅TCP中心不提供方向约束。因此我们将每个TCP扩展为七个虚拟点的刚体集合：其中心和沿正负局部坐标轴位移的六个点。其偏移为：

{δ_j}（j=1,...,7）= {0, ±r·e_k: k=1,2,3}， (13)

其中 e_k 为笛卡尔基向量，r = 0.03 m。目标和预测点通过应用相应TCP位姿获得：

y_{i,j}^a = t_i^a + R_i^a·δ_j， (14)
ŷ_{i,j}^a = t̂_i^a + R̂_i^a·δ_j。

这些目标无需额外标注。其空间范围使点对齐对TCP平移和方向均敏感。我们通过下式测量归一化点误差：

e_{i,a}^point = (1/7) Σ_{j=1}^7 ρ̄((ŷ_{i,j}^a - y_{i,j}^a)/s_p)， (15)

其中 s_p = 0.1 m，ρ̄ 在三个坐标上平均单位过渡的Smooth L1惩罚。对于标量残差z，当|z|小于1时惩罚为z²/2，否则为|z|-1/2。我们额外使用测地角监督旋转对齐：

d_R(R̂, R) = arccos((tr(R̂^⊤R) - 1)/2)。 (16)

具有预测位姿置信度 c_i^a 大于0，位姿目标为：

e_{i,a}^pose = e_{i,a}^point + λ_R·d_R(R̂i^a, R_i^a)/π， (17)
L_pose = ⟨c_i^a·e{i,a}^pose - α·log c_i^a⟩_valid，

其中 λ_R = 0.5，α = 0.2。平均值包括小批量中的有效帧-臂对；无效的参考查询排除该臂的轨迹。置信度正则化防止仅通过降低置信度来抑制重建误差。

时间速度一致性。 我们还通过虚拟点的有限差分监督运动。设 s_i 为采样帧i的时间戳，Δ_i = s_i - s_{i-1}。目标和预测速度为：

v_{i,j}^a = (y_{i,j}^a - y_{i-1,j}^a)/Δ_i， (18)
v̂{i,j}^a = (ŷ{i,j}^a - ŷ_{i-1,j}^a)/Δ_i。

使用实际的有符号间隔可适应可变帧采样和反转片段。我们定义：

e_{i,a}^v = (1/7) Σ_{j=1}^7 ρ̄((v̂{i,j}^a - v{i,j}^a)/s_v)， (19)
L_temp = ⟨c̃i^a·e{i,a}^v - α·log c̃_i^a⟩_pair，

其中 s_v = 1 m/s，c̃i^a = min(c_i^a, c{i-1}^a)。平均值包括每个可用手臂的有效相邻帧对。将此损失应用于扩展点可约束平移和方向的时间变化。这些有限差分在提供的每帧相机坐标标签中计算。

夹爪与阶段式TCP目标。 我们用二元交叉熵监督预测夹爪状态 ĝ_i^a 对应 g_i^a ∈ [0,1]，在相同的有效帧-臂对上平均。连续目标使用未加权损失；二元目标在两类均存在时使用负正标签比率的正类重新加权。将此损失记为 L_grip，两个TCP目标为：

L_tcp^(1) = L_pose + 0.2·L_temp + 0.2·L_grip， (20)
L_tcp^(2) = L_pose + 0.2·L_grip。

因此阶段1监督位姿、时间运动和夹爪重建，而阶段2保留位姿和夹爪重建。

A.3 条件流匹配监督

动作表示与归一化。 真值未来TCP位姿在归一化前转换到当前观测的相机坐标系。每个手臂贡献10D动作 (t, r, g)：度量位置 t ∈ R³、旋转矩阵前两列 r ∈ R⁶ 和夹爪状态 g ∈ [0,1]。因此双手目标轨迹 A 的形状为 h×20，其中 h=32 为预测范围。位置使用有效训练目标的第1和第99百分位数对每个手臂和坐标分别归一化，跨未来步骤汇集并排除填充。仿射变换将此范围近似映射到[-1,1]，不裁剪异常值。6D旋转保持未缩放，夹爪状态从[0,1]线性映射到[-1,1]。推理时，相同的统计量恢复度量位置；旋转列被正交化，夹爪状态在零处阈值化。

流匹配目标。 条件 O_t 包含L个过去和当前RGB帧、当前关节和夹爪状态 s_t 以及腕部相机图像 I_t^(w,a)；ℓ 为语言指令。高斯噪声 ε ~ N(0, I) 和流时间 τ ∈ [0,1) 定义公式5中的插值输入 A_τ 和目标 v*。我们记 v̂ = v_φ(A_τ, τ; O_t, ℓ)。生成目标为：

L_fm = E_{A,ε,τ}[Σ_{q∈{pos,rot,grip}} ⟨‖v̂_q - v_q*‖²⟩_f / d_q]， (21)

其中 d_pos = 3、d_rot = 6、d_grip = 1 为每臂分量维度。对每个轨迹，⟨·⟩_f 在有效未来步骤和可用手臂上平均；填充步骤被排除。期望还在轨迹、采样噪声和流时间上平均。三个分量均值均具有单位权重；除以 d_q 防止6D旋转仅因维度较大而获得更大权重。

B.1 增强流水线

TCP4D通过直接从RGB演示恢复任务空间运动来实现跨本体增强。如图3所示，流水线包括运动恢复、本体重定向和视觉合成。给定源视频和初始TCP查询，TCP4D预测TCP轨迹、夹爪状态和相机几何。恢复的位姿在共同坐标系中对齐，并通过使用目标机器人运动学模型的逆运动学进行迁移，产生遵循演示任务空间运动的关节配置。

我们使用SAM3或在可用时使用其几何模型和记录状态来分割源机器人。ProPainter补全掩码区域以重建背景。然后我们以恢复的配置渲染目标机器人，并使用对齐的相机几何将其合成到补全后的帧中。结果图像与目标配置配对形成增强演示。

来自TCP4D的深度可选择性地提高分割质量或区分前景与背景，但流水线不依赖深度。在重定向期间，如果IK在目标机器人的初始基座放置处失败，流水线自动搜索附近的机器人基座平移并在整个轨迹上重试IK（默认启用auto_base）。基座方向在此搜索期间保持固定，仅当每帧都通过IK时才接受目标手臂。有关跨本体增强中机器人基座调整的更多细节，请参阅OXE-AugE论文和项目页面。
