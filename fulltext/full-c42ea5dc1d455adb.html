与Mozilla合作提升Firefox安全

📅 2026-03-06 📄 Anthropic 🔗 原文链接

原标题：Partnering with Mozilla to improve Firefox’s security

中文摘要： Anthropic与Mozilla合作，利用Claude Opus 4.6在两周内发现Firefox 22个漏洞，其中14个为高危，占2025年Firefox高危漏洞近五分之一。AI在漏洞发现上表现卓越，但利用能力仍有限。研究强调任务验证器对提升AI补丁质量的重要性，并呼吁开发者加强软件安全。Anthropic发布协调漏洞披露原则，推动AI赋能安全协作，同时警示未来AI利用能力提升的风险。

AI模型现已能独立识别复杂软件中的高危漏洞。正如我们最近所记录的，Claude在经过充分测试的开源软件中发现了超过500个[零日漏洞](https://red.anthropic.com/2026/zero-days/)（即软件维护者未知的安全缺陷）。 在本篇文章中，我们分享了与Mozilla研究人员合作的细节：Claude Opus 4.6在两周内发现了22个漏洞，其中Mozilla将14个评定为[高危漏洞](https://www.mozilla.org/en-US/security/advisories/mfsa2026-13/)——几乎占2025年修复的所有Firefox高危漏洞的五分之一。换句话说：AI正使严重安全漏洞的检测速度大幅提升。 ![Image 1: A graph showing how Opus 4.6 was responsible for a substantial increase in the number of Firefox security vulnerabilities detected per month.](https://www.anthropic.com/_next/image?url=https%3A%2F%2Fwww-cdn.anthropic.com%2Fimages%2F4zrzovbb%2Fwebsite%2Fc3fe844b8a437af0e44027bad81523c88b89b1ab-4584x2580.png&w=3840&q=75) _每月从所有来源报告的Firefox安全漏洞。Claude Opus 4.6在2026年2月发现了22个漏洞，超过2025年任何单月报告的数量。_ 作为此次合作的一部分，Mozilla接收了大量我们提交的报告，帮助我们理解哪些发现值得提交漏洞报告，并在[Firefox 148.0](https://www.firefox.com/en-US/firefox/148.0/releasenotes/)中向数亿用户推送了修复补丁。[他们的合作](https://blog.mozilla.org/en/firefox/hardening-firefox-anthropic-red-team/)以及我们学到的技术经验，为AI赋能的安全研究人员与维护者如何协作提供了范例。

**从模型评估到安全合作** 2025年末，我们注意到Opus 4.5几乎能解决[CyberGym](https://www.cybergym.io/)中的所有任务，该基准测试评估LLM是否能重现已知安全漏洞。我们希望构建一个更难、更现实的评估，包含更多技术复杂的漏洞，如现代浏览器中常见的漏洞。因此，我们构建了一个包含以往Firefox常见漏洞和暴露（CVE）的数据集，以测试Claude是否能重现这些漏洞。 我们选择Firefox，因其代码库复杂，且是全球最经过测试和最安全的开源项目之一。这比我们之前用于测试模型的开源软件更具挑战性。数亿用户每天依赖它，而浏览器漏洞尤其危险，因为用户频繁接触不受信任的内容，依赖浏览器保护自身安全。 我们的第一步是让Claude在旧版Firefox代码库中找出已知CVE。令人惊讶的是，Opus 4.6成功重现了相当比例的历史CVE，尽管每个漏洞都耗费了大量人力。但结果的可信度仍存疑，因为部分历史CVE可能已存在于Claude的训练数据中。 因此，我们让Claude在_当前_版本的Firefox中寻找新漏洞——按定义，这些漏洞此前从未被报告过。我们首先聚焦于JavaScript引擎，随后扩展到浏览器其他部分。JavaScript引擎是理想起点：它是Firefox代码库中可独立分析的部分，且因处理用户浏览网页时的不受信任外部代码，安全至关重要。 仅20分钟后，Claude Opus 4.6报告在JavaScript引擎中发现Use After Free漏洞（一种内存漏洞，允许攻击者用任意恶意内容覆盖数据）。我们的研究人员在独立虚拟机中验证了该漏洞，并将报告转发给另外两名Anthropic研究人员，他们也验证了漏洞。随后，我们在Mozilla的[Bugzilla](https://bugzilla.mozilla.org/enter_bug.cgi?)中提交了漏洞报告，附带漏洞描述和由Claude生成、团队验证的补丁建议，以帮助定位根本原因。 在外部软件中进行漏洞挖掘时，我们始终意识到可能遗漏关键代码细节，导致误报。我们尽量自行验证漏洞，但仍存在误差空间。我们非常感谢Mozilla在漏洞分类过程中的透明度，以及帮助我们调整方法，确保仅提交他们关心的测试用例（即使并非所有都与安全相关）。Mozilla研究人员此后也开始在内部尝试使用Claude进行安全研究。

**从漏洞识别到原始利用** 为衡量Claude网络安全能力的上限，我们开发了新评估，测试Claude是否能_利用_我们发现的漏洞。换句话说，我们想了解Claude是否能开发黑客用于执行恶意代码的工具。 我们让Claude访问提交给Mozilla的漏洞，并要求其为每个漏洞创建利用程序。为证明成功利用，我们要求Claude展示真实攻击：具体来说，需在目标系统中读写本地文件，如同攻击者所为。 我们用不同起点进行了数百次测试，花费约4000美元API费用。尽管如此，Opus 4.6仅在两种情况下成功将漏洞转化为利用程序。这说明两点：一是Claude在发现漏洞方面远优于利用漏洞；二是发现漏洞的成本比创建利用程序低一个数量级。然而，Claude能自动开发出原始浏览器利用程序（即使仅在少数情况下）这一事实令人担忧。 “原始”是重要限定词。Claude编写的利用程序仅在我们的测试环境中有效，该环境故意移除了现代浏览器的部分安全功能，最重要的是[沙箱](https://wiki.mozilla.org/Security/Sandbox)，其目的正是降低此类漏洞的影响。因此，Firefox的“纵深防御”足以缓解这些特定利用。但沙箱逃逸漏洞并非罕见，而Claude的攻击是端到端利用的一个必要组成部分。更多关于Claude如何开发Firefox利用程序的细节可参见我们的[Frontier Red Team博客](https://red.anthropic.com/2026/exploit/)。

**AI赋能网络安全的未来** 这些早期迹象表明，AI驱动的利用开发凸显了加速防御方“发现-修复”流程的重要性。为此，我们分享一些在分析中发现的技术和流程最佳实践。 首先，在研究“补丁代理”（使用LLM开发和验证补丁的工具）时，我们开发了几种方法，希望帮助维护者更快地使用Claude等LLM进行漏洞报告的分类和处理。 我们的经验表明，当Claude能用其他工具自我检查时表现最佳。我们称这类工具为“任务验证器”：一种可信方法，用于确认AI代理的输出是否真正达成目标。任务验证器在代理探索代码库时提供实时反馈，使其能深度迭代直至成功。 任务验证器帮助我们发现了上述Firefox漏洞，且在独立研究中，我们发现它们对_修复_漏洞同样有用。一个优秀的补丁代理需验证两点：漏洞是否真正消除，以及程序预期功能是否保留。在我们的工作中，我们构建了自动测试工具，检查补丁后原漏洞是否仍可触发，并运行测试套件以捕获回归（即意外破坏其他功能）。我们预计维护者最了解如何为自己的代码库构建这些验证器；关键在于，为代理提供可靠方式验证这两点，能显著提升输出质量。 我们无法保证所有通过测试的代理生成补丁都可立即合并。但任务验证器增强了我们对补丁的信心：它能修复特定漏洞并保留程序功能——这被视为可行补丁的最低要求。当然，在审查AI生成的补丁时，我们建议维护者施加与审查任何外部作者补丁相同的严格审查。 从提交漏洞和补丁的流程来看：我们知道维护者工作量巨大。因此，我们的方法是提供维护者所需的信息，以建立信任并验证报告。Firefox团队指出，我们提交报告中的三个关键部分对信任结果至关重要： 1. 附带的最小测试用例 2. 详细的概念验证 3. 候选补丁 我们强烈鼓励使用LLM驱动漏洞研究工具的研究人员，在提交基于此类工具输出的报告时，包含类似的验证和可复现证据。 我们还发布了[协调漏洞披露操作原则](https://cdn.sanity.io/files/4zrzovbb/website/0039d6b020038aae6eaf0b3a46c70912b3a298dc.pdf)，描述了与维护者合作时将采用的流程。目前我们的流程遵循行业标准，但随着模型能力提升，我们可能需要调整流程以跟上发展步伐。

**当下的紧迫性** 前沿语言模型已成为世界级的漏洞研究人员。除了在Firefox中发现的22个CVE，我们还用Claude Opus 4.6在Linux内核等重要软件项目中发现了漏洞。未来数周和数月，我们将持续报告模型使用情况及与开源社区的合作，以提升安全性。 Opus 4.6在识别和修复漏洞方面远优于利用漏洞。这为防御方带来优势。随着[Claude Code Security](https://www.anthropic.com/news/claude-code-security)在有限研究预览中发布，我们正将漏洞发现（和修复）能力直接提供给客户和开源维护者。 但根据进展速度，模型在漏洞发现与利用能力之间的差距可能不会持续太久。如果未来语言模型突破利用障碍，我们需要考虑额外防护措施或行动，防止模型被恶意行为者滥用。 我们敦促开发者利用这一窗口期，加倍努力提升软件安全性。我们计划大幅扩展网络安全工作，包括与开发者合作寻找漏洞（遵循上述CVD流程）、开发帮助维护者分类漏洞报告的工具、以及直接提出补丁。 _如果您希望支持我们的安全工作——编写新框架以识别开源软件漏洞；分类、修复和报告漏洞；并为AI时代开发稳健的CVD流程——[请在此申请加入Anthropic](https://job-boards.greenhouse.io/anthropic/jobs/5123011008)。_
