摘要
上下文化对于生产级自动语音识别（ASR）系统至关重要，在这些系统中，必须在严格的延迟约束下准确识别用户提供的短语。尽管许多上下文偏置方法提高了识别准确率，但它们通常没有解决现代生产级 ASR 系统的实际需求：流式推理、高效的批量解码、特定于用户的上下文列表以及低运行时开销。我们提出了 TurboBias 2.0，这是一个面向生产级的框架，用于在基于 Transducer 的 ASR 系统中进行高效的短语提升。该框架通过引入不区分大小写的提升图和每流批量解码扩展了 GPU 加速的 TurboBias，允许批次中的每个话语使用独立的上下文偏置配置。这使得为多个同时在线的用户提供个性化的上下文偏置成为可能，而不会共享或混合他们的上下文列表。所提出的框架支持离线和流式推理，并可用于贪心解码和束搜索解码。实验表明，TurboBias 2.0 提高了上下文短语识别率，同时保持了低延迟和高吞吐量。

I 引言
现代自动语音识别（ASR）系统在通用基准测试中取得了很高的准确率，但在处理罕见词、特定领域术语和用户自定义术语时仍然常常遇到困难。这些术语在训练数据中可能很少见，但它们对于转录文本的可用性往往至关重要。因此，上下文偏置仍然是生产级 ASR 系统的重要组成部分，特别是对于会议、财报电话会议、医疗转录和语音助手等场景。

目前已经提出了多种上下文偏置方法。深度融合方法通过额外的注意力机制、适配器或专门的训练目标，将上下文信息直接注入到 ASR 模型中 [1, 2, 3, 4, 5]。这些方法可能很准确，但通常需要修改模型并重新训练。最近的语音和语音语言模型也可以使用带有上下文短语的文本提示 [6, 7]，但它们的行为可能对提示设计、上下文列表长度和延迟约束很敏感。相比之下，浅融合和关键词提升方法会修改与预定义上下文列表匹配的假设的解码分数 [8, 9, 10, 11]。这使得它们对生产环境很有吸引力，因为它们通常可以在不重新训练 ASR 模型的情况下应用。

最近的一些工作集中在高效的上下文 ASR 上。基于 CTC 的词定位器通过将 CTC 对数概率与上下文图进行匹配来检测关键词，然后纠正贪心 ASR 输出中相应的跨度 [12]。虽然有效，但这种方法需要一条 CTC 评分路径和一个识别后的纠正阶段。对于基于 Transducer 的 ASR（RNNT [13], TDT [14]），它最适合于混合 Transducer-CTC 模型或带有独立 CTC 模型的流水线。TurboBias 引入了一种 GPU 加速的短语提升树，用于浅融合上下文偏置，并展示了对 CTC、Transducer 和注意力编码器-解码器模型的高效支持 [15]。最近，Contextual Earnings-22 引入了一个公开的上下文 ASR 基准测试，其中包含来自财报电话会议的真实自定义词汇表，以及包含干扰项的局部上下文和全局上下文列表的评估设置 [16]。尽管取得了这些进展，但高负载流式生产 ASR 的几个需求仍未得到充分解决。

首先，现代 ASR 系统通常会产生带有标点符号和大小写的格式化转录文本，因此上下文偏置应该对用户提供的短语和模型输出之间的大小写差异具有鲁棒性。可以通过小写、大写和首字母大写变体来扩展每个短语，但这会增加树的大小、编译时间和内存使用量。一个更实用的解决方案是在提升结构中直接支持不区分大小写的匹配。

其次，生产工作负载通常需要为许多同时在线的用户提供个性化的上下文偏置。在批量 ASR 中，不同的流可能对应于不同的会议、医疗对话、财报电话会议或客户支持会话，每个流都有自己的上下文列表。共享的提升树可能会在流之间引入干扰项和错误接受，因此一个可用于生产环境的系统应该支持在单个 GPU 批次内进行独立的每流提升配置。

第三，许多应用程序需要具有严格延迟约束的流式识别。因此，上下文偏置应该在流式贪心和束搜索解码中工作，而不仅仅是离线束搜索。这对于广泛应用于生产流式 ASR 的基于 Transducer 的模型尤为重要。上下文偏置带来的额外开销也必须相对于整体 ASR 推理时间保持较小。

在这项工作中，我们提出了 TurboBias 2.0，这是 TurboBias 框架的面向生产级的扩展，用于在流式 Transducer ASR 中进行高效的上下文偏置。所提出的框架引入了不区分大小写的 GPU 短语提升图，支持流式贪心和束搜索解码中的短语提升，并为批量推理实现了每流提升图。这允许多个同时在线的流使用独立的上下文偏置配置，同时保留高效的 GPU 执行和低延迟流式识别。

我们在 Contextual Earnings-22 和一个内部医疗领域测试集上使用现代流式 ASR 模型评估了 TurboBias 2.0。我们将提出的不区分大小写图与区分大小写和短语扩展的替代方案进行了比较，分析了离线和流式解码模式，并研究了关键词 F 分数、束大小和流式延迟之间的权衡。

本文的主要贡献是：
- 不区分大小写的 GPU 短语提升图，避免了额外的短语列表扩展，如小写、大写和首字母大写变体。
- 批量推理中的每流上下文偏置图，其中每个用户/请求都有一个独立的短语列表，用于高效的批量解码。
- 流式 Transducer 束搜索支持，以提高实时语音应用中的提升性能。

提出的 TurboBias 2.0 框架已作为 NVIDIA NeMo 工具包的一部分开源 [17]¹。

II 方法描述

II-A 不区分大小写的提升
原始的 TurboBias 将上下文列表表示为带有后缀链接的 GPU 短语提升树，其中每个短语由 ASR 模型分词器进行分词，并且每个匹配的词元在解码期间都会获得一个浅融合奖励 [15]。这种结构很高效，但它是区分大小写的：一个提升条目 hello 不一定会匹配诸如 Hello 或 HELLO 这样的假设。这对于现代格式化 ASR 系统是一个实际限制，因为模型可能会在句子边界或命名实体处发出大写字母，而用户提供的上下文短语通常是未格式化的。

一种直接的解决方法是插入每个短语的多种拼写形式，例如小写、首字母大写和大写变体。然而，这增加了提升树中的路径数量，并且仍然不能覆盖所有混合大小写的输出。对于字符分词模型，一种更简洁的结构很简单：每个字符弧可以替换为一对用于大小写变体的平行弧，如图 1d 所示。这保留了紧凑的图，并使匹配独立于发出的大写字母。

图 1：单词 hello 的分词图。

同样的想法不能直接应用于贪心 BPE 分词。BPE 词汇表通常不包含每个词元的大小写变体；例如，可能存在词元 _he，但可能不存在 _He 或 _HE，并且分词器可能会以不同方式对带有大小写的拼写进行分段。因此，我们首先将每个短语转换为变分 BPE 表示，如图 1c 所示。给定一个短语，我们取其贪心 SentencePiece 分词 [18, 19]，并将每个词元分解为其规范字符级片段。对于该字符链中的每个位置，我们添加相应的单片段词元弧，并且对于其规范分解跨越该链中连续段的每个词汇表词元，我们在该段上添加一个合并弧。由于 SentencePiece 分词器是由字符片段构建的，因此此处考虑的模型可以使用字符级链，并且词汇表查找足以枚举有效的合并弧。

对于不区分大小写的提升，规范表示将转换为小写。每个词汇表词元都映射到在分解前将其片段小写所获得的规范序列，并且只要该规范序列与小写的短语路径匹配，就允许将其作为弧。因此，该图接受对应于同一个小写短语的具有不同大小写的 BPE 分段，如图 1e 所示。生成的结构不再是一棵树，因为多个弧可能会跳过不同数量的字符位置并收敛到同一状态。除了显式的后缀链接外，它仍然是无环的，因此它仍然可以被编译成 TurboBias 使用的相同的基于 NGPU-LM 的数据结构 [20]。

变分表示还改变了分配提升分数的方式。在原始树中，一个弧对应于来自贪心短语表示的一个分词器词元，因此 TurboBias 词元分数可以直接存储在该弧上。在不区分大小写的变分图中，对于相同的短语跨度，路径可能包含不同数量的弧。为每个弧分配相同的分数会使逐字符路径获得比合并词元路径更大的总奖励，而仅向合并弧分配分数会延迟奖励并削弱部分匹配。

我们通过在状态上存储累积分数势能并将每个弧分数定义为目标势能与源势能之间的差值来解决此问题。势能是根据小写的贪心 BPE 分词计算的，它作为评分的主干。如果第 $k$ 个贪心 BPE 词元具有 TurboBias 分数 $w_k$ 并分解为 $m_k$ 个字符片段，我们使用以下公式在内部字符状态上分配 $w_k$：
$$\Delta_{k,i}=w_{k}\frac{\exp((i+1)^{\tau})}{\sum_{j=0}^{m_{k}-1}\exp((j+1)^{\tau})},\quad i=0,\ldots,m_{k}-1,$$ (1)
其中 $\tau$ 控制分数在词元末尾的集中程度。设置 $\tau=0$ 会给出均匀分割，而较大的值则接近原始 TurboBias 行为，即大部分分数在完整的 BPE 词元匹配后应用。在实践中，终点集中的设置对于贪心解码是保守的，而更平坦的分布有助于束搜索，因为部分短语匹配会更早地获得提升。由于所有以相同状态结尾的带有大小写和合并的替代方案共享相同的势能，因此每个被接受的拼写都会获得相同的总短语奖励，而与其 BPE 分段无关。

II-B 每流上下文偏置
在生产级 ASR 服务中，上下文短语通常是特定于请求的。单个服务器可能会将来自多个客户的流进行批处理，其中每个流都有一个小的名称、产品术语、医疗实体或其他短语的列表，这些短语只应针对该流进行提升。这就产生了单一全局提升树无法满足的两个要求。首先，一个客户的短语列表不得影响同一批次中其他流的识别质量。其次，随着流的开始和结束，必须动态添加和删除短语列表，而无需重新加载 ASR 服务器或重新实例化解码器。

TurboBias 2.0 通过建立在相同的 NGPU-LM/TurboBias 张量表示之上的每流上下文偏置模型来解决此问题。每个提升树仍然被编译为带有与弧相关的张量（如标签、目标状态和弧权重）和与状态相关的张量（如出弧范围、后缀链接目标、后缀链接权重和最终权重）的加权接受器。我们不再存储一个活动的树，而是将所有活动提升树的张量连接到合并的多模型存储中。对于每个模型 ID，多模型将相应的状态和弧范围作为偏移量存储到合并的张量中，连同该模型的提升权重。

在批量解码期间，每个流都带有一个偏置模型 ID。非负 ID 为该流选择短语列表，而 ID -1 表示无偏置。融合评分操作接收当前的 TurboBias 状态和每流模型 ID。对于每个批次项，GPU 内核首先读取与其模型 ID 关联的状态和弧偏移量，将张量指针移动到所选范围，然后运行与单树 TurboBias 前进操作相同的后缀链接遍历。如果模型 ID 为 -1，内核将返回零提升分数且无有效的下一个状态，因此该流的解码方式与无偏置流完全相同。因此，同一 GPU 批次中的不同流可以使用独立的短语列表，而不会共享干扰项。

合并的表示支持频繁的模型生命周期更新。添加模型会将其弧和状态张量附加到合并存储中，并记录其偏移量。删除模型会将其 ID 标记为非活动状态，并将随后的弧和状态范围向左移动以填补删除的间隔；由于这些是连续的张量操作，因此更新在 GPU 上被高效并行化。模型 ID 与物理张量偏移量分开跟踪，允许解码器保持稳定的每流 ID 接口，同时对底层存储进行压缩。

这种布局保留了单一全局提升树的计算特征。一旦合并存储在 GPU 上，每个流仍然在一个选定的树上执行一次提升前进，并在词汇表上写入一个分数向量。与单树情况相比，额外的工作仅限于在标准弧/状态遍历之前读取每流模型 ID 和两个偏移量。在我们的测量中，相对于使用一个全局树，这没有引入明显的解码速度下降，同时避免了由于不相关短语导致的跨流质量回归。

剩余的主要成本是在创建流时编译和传输提升模型。在实际部署中，每流列表通常很小，并且单个提升模型通常低于 1 MB，因此保留数百个已编译的模型是切实可行的。为了减少模型生命周期开销，我们使用了三级缓存策略：用于持久化预编译提升树的磁盘存储、用于可以按需复制到合并 GPU 模型中的已编译模型的 CPU 内存存储，以及用于在识别会话之前已知的模型的解码器级注册。第一级对于大型或重复的短语列表很有用，内存级将动态每流更新保持在较小的开销内，而解码器级注册则完全消除了解码循环中的更新成本。

II-C 流式束搜索
[21] 引入了用于基于 Transducer 模型的离线批量解码算法，通过树结构假设存储、完全基于 GPU 的计算和 CUDA Graph 执行，缩小了贪心和束搜索解码之间的延迟差距。我们将这种方法扩展到实时流式 ASR。与离线解码不同，流式解码逐块处理编码器输出，要求束搜索状态在块边界之间保持。我们的流式扩展通过将最终确定的块级假设及其累积分数和边界解码器状态存储在扁平化的树中来保持这种连续性。然后，这些存储的状态用作在后续块中继续、合并和修剪新扩展假设的锚点。该实现仍然与 CUDA Graph 和完全基于 GPU 的批量操作兼容，从而实现了低延迟的流式 Transducer 束搜索，同时保留了离线算法的执行模式。

III 实验设置

III-A ASR 模型
为了进行评估，我们使用了公开可用的基于英文 Transducer 的 ASR 模型。作为一个强大的离线基线，我们使用了流行的 parakeet-tdt-0.6b-v2 [22] (TDT-v2)，这是一个基于 FastConformer 编码器 [23] 和 TDT 解码器 [14] 的 6 亿参数模型。

对于低延迟流式实验，我们使用了 nemotron-speech-streaming-en-0.6b [24] (Nemotron-streaming)，这是一个具有缓存感知 FastConformer 编码器和 RNNT 解码器的 6 亿参数模型。该模型在重用先前块的缓存编码器状态的同时处理音频块，使其成为准确率-延迟权衡中低延迟端的强大流式基线。

我们还评估了 parakeet-unified-en-0.6b [25] (Unified)，这是一个支持离线和流式推理的 6 亿参数模型。该模型使用 FastConformer 编码器和 RNNT 解码器，在离线和流式模式之间共享参数。在流式模式下，它应用块限制的自注意力和动态分块卷积，而 MCR-RNNT 训练减少了离线和流式识别之间的差距 [26]。

所有模型都支持标点符号和大小写，这对于研究不区分大小写的短语提升很重要。

III-B 评估数据
我们在代表不同生产导向场景的两个英文数据集上评估了提出的上下文偏置框架。第一个数据集是 Contextual Earnings-22（在本文其余部分称为 C-Earnings22），这是一个建立在 Earnings-22 之上的公开基准，用于评估带有自定义词汇表的上下文 ASR [16]。它侧重于财报电话会议转录，其中准确识别人名、公司名和产品名至关重要。每个样本都是一个以至少一个上下文关键词为中心的 15 秒剪辑，带有手动审查的转录文本和上下文列表。该基准提供了两种上下文机制：一个仅包含目标剪辑中关键词的局部列表，以及一个由完整的通话级关键词清单构建的包含真实干扰项的全局列表。

我们还使用了一个内部医疗领域测试集来评估该方法在专业术语上的表现。该数据集包含大约 3 小时的英文医疗语音，带有诸如疾病、手术和药物临床条件等上下文短语。

Contextual Earnings-22 论文报告了一种修改后的 CTC-WS 集成策略，但未提供确切复现所需的任何实现细节。因此，我们尽可能使用相同的公开可用 ASR 模型和标准 CTC-WS 方法。

III-D 指标
我们使用完整 ASR 输出上的 WER 和仅上下文短语上的关键词精确率、召回率和 F 分数来评估识别质量。如果一个短语出现在假设中，并且在文本归一化后与相应的参考短语匹配，则该短语被计为正确识别。设 $N_{\mathrm{TP}}$、$N_{\mathrm{FP}}$ 和 $N_{\mathrm{FN}}$ 分别表示真阳性、假阳性和假阴性上下文短语匹配的数量。则：
$$P=\frac{N_{\mathrm{TP}}}{N_{\mathrm{TP}}+N_{\mathrm{FP}}},\quad R=\frac{N_{\mathrm{TP}}}{N_{\mathrm{TP}}+N_{\mathrm{FN}}},\quad F=\frac{2PR}{P+R}.$$ (2)

解码效率使用逆实时因子来衡量：
$$\mathrm{RTFx}=\frac{T_{\mathrm{audio}}}{T_{\mathrm{eval}}},$$ (3)
其中 $T_{\mathrm{audio}}$ 是总音频时长，$T_{\mathrm{eval}}$ 是 ASR 解码时间。RTFx 越高表示解码越快。我们使用单个 NVIDIA RTX A5000 24GB GPU。

我们评估了三种上下文列表配置。在 full 设置中，单个上下文列表由所有流的所有上下文短语构建。在 per-stream global 设置中，每个流都有自己的上下文列表，仅包含与该流相关的短语，模拟个性化的高负载生产推理。在 per-stream local 设置中，上下文列表进一步限制为与每个流内当前音频段相关的短语。

对于流式实验，我们使用基于块的（TDT-v2 和 Unified）或缓存感知解码（Nemotron-streaming）。我们将流式延迟报告为 ASR 模型的最坏情况算法延迟，计算为块大小和使用的右上下文的总和。

所有模型都使用贪心（label-looping [28, 29]）和束搜索（ASLD++ [30, 21]，beam_size=32）解码进行评估。验证集用于选择提升参数，最终结果在测试集上报告。

IV 结果
图 2 总结了基于 CTC-WS 的上下文偏置与通过 TurboBias 2.0 进行的直接 Transducer 短语提升之间的主要比较。我们将 Contextual Earnings-22 基准测试中的 Argmax CTC-WS 结果作为参考点。该系统不是一个单模型上下文解码器：它将 TDT-v2 ASR 转录文本与来自与 TDT 目标联合训练的 CTC 模型的关键词检测相结合。基准测试论文还描述了一种修改后的 CTC-WS 集成，但无法获得确切复现所需的实现细节和评分脚本。因此，我们单独报告已发表的 Argmax 结果，并将其与我们使用 TDT-v2 和 CTC-WS 的最接近的复现进行比较。这个复现的设置将 Earnings22 上无上下文的 TDT-v2 基线的 F 分数从 64.9 提高到 82.0，并将 WER 从 14.7% 降低到 13.7%，但仍低于报告的 88.2 F 分数和 12.7% WER 的 Argmax 点。结果证实了 CTC-WS 的有效性，同时也突出了其实际复杂性：它需要辅助 CTC 推理路径、合适的混合 TDT-CTC 模型以及识别后的文本纠正阶段。

TurboBias 2.0 通过在 Transducer 解码内部直接应用偏置分数来提高上下文识别率。对于离线 TDT-v2 模型，每流全局提升比未适配的模型有显著的提升，在束搜索下在 Earnings22 上达到了 83.0 的 F 分数和 13.3% 的 WER。最强的总体结果是由 Unified ASR 模型获得的。在离线设置中，Unified 模型在 Earnings22 上达到了 87.5 的 F 分数和 12.6% 的 WER，这接近于报告的 Argmax CTC-WS F 分数，并且给出了更低的 WER。它也大大优于我们的 TDT-v2 + CTC-WS 复现。在内部医疗集上，同样的趋势成立：直接的 TurboBias 2.0 提升在上下文 F 分数上产生了巨大的改进，同时也降低了 WER，表明该方法可以迁移到具有专业术语的领域。

图 2 中的流式结果表明，在延迟约束下，ASR 模型的选择至关重要。流式 TDT-v2 配置相对于其离线模式遭受了很大的质量下降，并且上下文偏置无法完全弥补这一损失。相比之下，Unified 模型保留了更强的流式准确率，并且 TurboBias 2.0 带来的相对增益与离线观察到的相当。在 Earnings22 上，1.12s 最坏情况延迟（块 0.56s，右上下文 0.56s）下的 Unified 流式模型在全局提升和束搜索后，F 分数从 62.2 提高到 81.7，WER 从 16.3% 提高到 14.3%。较低延迟的 0.56s（块 0.16s，右上下文 0.40s）配置遵循相同的趋势。Nemotron-streaming 模型在 Earnings22 上的表现相似，并从束搜索中获得了稍大的收益。然而，在内部医疗集上，Unified 模型明显更强：在 1.12s 延迟下，它达到了 71.1 的 F 分数和 14.0% 的 WER，而 Nemotron-streaming 为 68.2 的 F 分数和 18.0% 的 WER。

每流提升通过避免同一批次中来自其他流的不相关短语来进一步提高识别率。在每流全局上下文中，每个流接收其目标短语以及真实的干扰项，F 分数在贪心解码中增加到 81.5，在束搜索中增加到 87.5，而 WER 分别下降到 13.1% 和 12.6%。每流局部设置仅包含每个话语的目标短语，给出了最好的绝对数字：贪心解码的 F 分数为 85.4，束搜索为 91.2。然而，此设置假设了解话语中出现的确切短语，因此对大多数生产部署的代表性较低。因此，我们将每流全局提升视为主要的现实操作点。

V 结论
我们提出了 TurboBias 2.0，一个用于基于 Transducer 的 ASR 系统中上下文短语提升的高效框架。提出的不区分大小写的提升图使解码对用户短语列表和格式化 ASR 输出之间的大小写差异具有鲁棒性，而无需将短语扩展为多种大小写变体。我们还引入了用于批量推理的每流上下文偏置，允许每个流使用独立的上下文列表，并避免来自不相关干扰项的干扰。

我们进一步将短语提升扩展到流式推理，并为流式 Transducer 解码适配了 GPU 束搜索。在 Earnings22 和一个内部医疗领域集上的实验表明，上下文 F 分数和 WER 有一致的改进，束搜索在离线和流式设置中都提供了比贪心解码更大的增益。这些结果表明，解码器级别的短语提升可以以低开销提供强大的上下文准确率，而无需辅助 CTC 推理、识别后纠正或模型重新训练。
