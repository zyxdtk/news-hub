摘要

尽管语言模型的能力已大幅提升，检索仍在很大程度上依赖词法匹配或固定嵌入空间中的相似度。这造成了一种能力不对称：检索器未能找到的内容，即使是最强大的生成器也无法挽回。我们提出 DecisionRAG，它利用决策模型将预训练语言模型的能力引入检索——这些决策模型在单次前向传播中联合评估候选分支，且不生成任何 token——并证明在共享上下文中评判候选者能使其相关性估计具有可比性。如同在图书馆中浏览的人一样，DecisionRAG 利用语料库的固有结构，从宽泛主题逐层导航至具体段落，在每一层级决定哪些分支值得探索。无需任务特定训练或第一阶段检索器，DecisionRAG 在 MultiDoc2Dial 上以 13.8 个 R@1 点、在 Natural Questions 上以 17.4 个 Hit@1 点超越配备 8B 重排器的稠密检索。在包括 268 万维基百科段落的语料库在内的四个基准上，每次查询的检索仅需 0.7–1.8 秒。

1 引言

图 1：能力不对称：简单的检索器成为强大 LLM 的瓶颈；决策模型拉平了竞争环境。

检索增强生成（RAG）已成为现代语言模型流水线的核心组件（Lewis 等，2020；Guu 等，2020；Gao 等，2023b）。通过在推理时从外部语料库获取证据，RAG 使模型能够访问其在训练期间从未见过的最新信息（Lewis 等，2020；Vu 等，2024），并将其回答建立在可验证的来源之上（Shuster 等，2021；Gao 等，2023a）。

然而，尽管语言生成模型的能力已大幅提升（OpenAI, 2026b；Anthropic, 2026），决定它们所见内容的检索器却未能跟上步伐。大多数检索系统仍然通过基于词频的启发式方法（如 BM25（Robertson 和 Zaragoza, 2009））或固定嵌入空间中的最近邻（Karpukhin 等，2020；Izacard 等，2022；Zhang 等，2025）对每个段落进行评分。这在检索器和生成模型之间造成了显著的能力不对称（图 1）：检索器遗漏的任何内容，无论生成器能力多强都无法挽回（Barnett 等，2024）。

理想情况下，应该由一个与生成器同样强大的模型来决定检索什么。智能体方法让 LLM 逐步导航语料库（Yao 等，2023；Chen 等，2023；Jin 等，2025），但在智能体循环中每一步都生成大量 token，使其对许多应用而言过于缓慢和昂贵（Jeong 等，2024；Yang 等，2026）。重排器提供了更便宜的折中方案（Nogueira 和 Cho, 2019；Sun 等，2023；Reddy 等，2024），但它们只能对第一阶段检索器已返回的结果进行重新排序。

决策模型已成为一种新范式，可以在不采样任何 token 的情况下快速利用预训练语言模型的能力（TypeSafe AI, 2026；OpenAI, 2026a；Li 和 Wagle, 2026）。给定一个上下文和一组问题，诸如 Jev（TypeSafe AI, 2026）之类的决策模型会针对每个问题返回其答案选项上的概率分布（对于是非题，即 P(yes)），在单次前向传播中针对共享上下文并行回答许多问题。这使它们天然适合检索，将 LLM 的能力带入检索内容的选择。此外，联合评分候选者使其决策彼此可比（Chen 等，2025；Gupta 等，2025）。因此，使用决策模型来选择检索什么，有望拉平检索器和生成器之间的竞争环境。

我们提出 DecisionRAG，它通过导航而非搜索进行检索（图 2）。大多数语料库具有主题、文档、章节和段落的固有结构，人类利用这种结构高效地查找信息（Pirolli 和 Card, 1999）。DecisionRAG 通过层级决策利用这种结构（Geva 和 Berant, 2018；Liu 等，2021）：在每一层级，决策模型联合评估候选者以识别最有前景的分支，逐步将搜索从宽泛的类别（例如主题或文档标题）缩小到具体段落。每个决策只需单次前向传播，不生成任何 token，即使对于大型语料库也能保持检索快速。因此，DecisionRAG 将预训练语言模型的能力直接带入检索，无需查询时的第一阶段检索器、预计算索引或任务特定训练。

我们在四个基准上评估 DecisionRAG，涵盖多轮对话（Feng 等，2021；Katsis 等，2025）、基于场景的问题（Sun 等，2022）以及超过 268 万维基百科段落的开放域搜索（Kwiatkowski 等，2019；Wang 等，2024）。无需任务特定训练，DecisionRAG 在 MultiDoc2Dial 上以 13.8 个 R@1 点、在 Natural Questions 上以 17.4 个 Hit@1 点超越配备 8B 重排器的稠密检索。在共享上下文中评判候选者有助于这些提升，与独立判断相比，准确率最多提高 7.7 个点（第 6.1 节）。尽管在每个阶段都利用了语言模型的能力，DecisionRAG 的检索仅需 0.7–1.8 秒，每次查询成本为 0.2–2.3 美分。与在同一层级上逐 token 生成导航决策的 LLM 相比，它以低 34–145 倍的延迟实现了相当的准确率（第 6.3 节）。在领域内数据上训练专门的 8B 决策模型，进一步将 MultiDoc2Dial 上的 R@1 提高到 60.7，超越已发表的最好的任务训练检索器 5.7 个点，表明随着决策模型的改进仍有很大提升空间。

2 相关工作

图 2：匹配式检索与决策式检索的对比。 BM25 和 稠密检索匹配查询词或嵌入，可能错过相关页面。 DecisionRAG 遍历语料库层级：决策模型在一次前向传播中判断一层级的所有候选者，保留前 k 个文档，然后保留前 r 个段落；被剪枝的文档永远不会被展开。图 中的词频、IDF 值、BM25 分数和排名仅为示意。

传统检索方法，包括 BM25（Robertson 和 Zaragoza, 2009）和稠密检索器（Karpukhin 等，2020），使用词法匹配或学习的嵌入相似度对段落进行排序。神经重排序方法使用基于语言模型的相关性估计来优化这些排序。交叉编码器评估单个查询-段落对（Nogueira 等，2020），而基于 LLM 的重排器通过生成排列（Sun 等，2023）或从子集中迭代选择候选者（Zhuang 等，2024；Li 等，2026）执行列表式排序。尽管重排序可以提高检索质量，它仍然受限于初始检索阶段的候选召回率。

另一条研究路线将语言模型直接集成到检索过程中。智能体方法将推理与搜索引擎的使用交织在一起，以迭代地识别相关证据（Yao 等，2023；Jin 等，2025）。其他方法使用层级表示来指导检索。MemWalker 导航由长文档构建的摘要层级（Chen 等，2023），而 PageIndex 使用文档目录进行 LLM 引导的导航（VectifyAI, 2025）。LATTICE 将层级导航扩展到语料库级检索，构建语义树并使用 LLM 生成的相关性评估在每一层级选择分支（Gupta 等，2026）。这些方法需要在每个检索步骤顺序生成 token，当导航涉及多轮推理时，这会产生大量延迟。

最近的工作探索了更高效的基于语言模型的排序方法。FIRST 从单个生成的标识符的 logits 中导出列表式排序（Reddy 等，2024），而 ICR 和 BlockRank 从联合呈现的候选者的注意力模式中提取排序信号（Chen 等，2025；Gupta 等，2025）。决策模型提供了另一种在不生成 token 的情况下评估多个候选者的方法（TypeSafe AI, 2026；OpenAI, 2026a）。给定共享上下文和一组问题，这些模型在单次前向传播中产生每个问题答案选项上的概率分布。这使得能够对多个候选者进行并行相关性判断，每个候选者都针对相同的上下文信息进行评估。

层级检索也被研究作为减少大型文档集合中搜索空间的手段。DocQN 学习使用强化学习导航文档树（Geva 和 Berant, 2018），而稠密层级检索使用训练好的编码器逐步选择文档和段落（Liu 等，2021）。RAPTOR 构建递归生成的摘要层级以支持不同抽象级别的检索（Sarthi 等，2024）。相关工作还强调了文档级上下文对段落检索的重要性（Wang 等，2024；Xu 等，2025；Zhang 等，2026）。

DecisionRAG 将层级检索与非生成式相关性判断相结合。它在可用时使用现有的文档结构，否则构建文档组（第 4.1 节）。与传统的重排序流水线不同，DecisionRAG 不需要第一阶段检索器来构建候选池。与 LLM 引导的层级搜索不同，它通过单次前向传播中的并行相关性判断评估每一层级的候选者，而不生成 token。

3 方法

3.1 问题形式化

我们考虑一个语料库 𝒟 = {D₁, …, D_N}，其中每个文档 D_i 由段落 d_{i1}, …, d_{iM_i} 组成。给定一个查询 q（可能包括之前的对话轮次），我们的目标是检索包含回答它所需证据的段落（图 2）。更一般地，我们将语料库视为一棵树，其叶子是段落，其内部节点以递增的粒度对它们进行分组，例如帮助中心、主题簇、文档或章节标题。每个节点都有一个简短的文本描述：段落就是文本本身，文档是标题，簇是一句话摘要。我们将树的每个深度称为一个层级，将决策模型的每轮请求称为一个阶段；大多数层级占用一个阶段，最终的重排序本身是一个阶段。作为运行示例，我们使用查询“克里斯托弗·诺兰 2000 年的电影的主角是谁？”（公式 1），它可以由维基百科语料库回答。

3.2 使用决策模型的相关性判断

诸如 Jev（TypeSafe AI, 2026）和 OpenAI 的决策模型（OpenAI, 2026a）之类的决策模型针对上下文评估问题，并返回预定义答案选项上的概率，而无需自回归生成。我们使用它们的两种推理模式：并行二值判断和多选判断，两者都针对共享上下文 s（图 3）。

并行二值判断。 给定共享上下文 s 和一组二值问题 𝒬 = {Q₁, …, Q_n}，决策模型在单次前向传播中并行评估所有问题。对于每个问题 Q_i，它产生回答“是”的概率 p_i^bin = P(Yes | s, Q_i)（公式 2）。每个问题都针对相同的上下文进行评估，但其答案概率仅在“是”和“否”之间归一化，而不是跨问题归一化。因此，所得的分数之和不必为一。二值判断因此除了模型的上下文长度外，对候选者数量没有限制；较大的层级会被拆分到并行请求中（第 3.4 节）。

多选判断。 给定上下文 s、问题 Q 和一组答案选项 𝒜 = {a₁, …, a_m}，决策模型产生选项上的概率分布 p_i^mul = P(a_i | s, Q, 𝒜)，∑_{i=1}^m p_i^mul = 1（公式 3）。与并行二值判断不同，多选判断将答案选项作为单个决策中的竞争替代方案进行评估。答案选项的数量是有限的（Jev 为 255 个），因此我们仅将此模式应用于二值判断选出的顶部候选者。

图 3：决策模型的两种判断模式，每种都针对模型读取一次的共享上下文。 针对共享上下文 s_D 对文档 D_i 的并行二值判断。 针对相同共享上下文 s 对二值判断选出的顶部段落进行多选重排；概率之和为一。

在共享上下文中评判候选者。 因为每个问题都看到相同的上下文，每个概率都是在考虑替代方案的情况下形成的：一个单独看起来相关的候选者，当存在明显更好的候选者时，会得到较低的 P(Yes)。共享上下文因此将各个概率置于整体视角中，使它们在候选者之间具有可比性。我们的消融实验支持这一点：将候选者一起评分而不是分开评分，在 MultiDoc2Dial 上将 R@1 提高 7.7 个点，在 Natural Questions 上将 Hit@1 提高 6.5 个点（第 6.1 和 6.2 节）。它们还显示了这种比较在哪些地方重要：将一个池拆分为较小的请求会降低 Hit@1 但保持 R@10 不变。因此，来自单独请求的分数足以进行筛选（此时召回率重要），而最终排序则受益于一个共享请求。

3.3 层级检索

算法 1 DecisionRAG

输入：查询 q；具有 L 个层级的语料库树；预算 k₁, …, k_{L−1}；返回段落数 r；重排入围大小 m ≤ r
1: 𝒞 ← 根节点的子节点
2: for ℓ = 1, …, L−1 do
3: p^bin ← BinaryJudge(q, 𝒞) {公式 2}
4: 𝒞 ← ⋃_{c ∈ top-k_ℓ(𝒞, p^bin)} children(c)
5: end for
6: p^bin ← BinaryJudge(q, 𝒞)
7: R ← top-r(𝒞, p^bin)
8: if 启用多选重排 then
9: p^mul ← ChoiceJudge(q, R[1:m]) {公式 3}
10: 按 p^mul 递减重新排序 R[1:m]
11: end if
12: return R

DecisionRAG 不是单独对语料库中的每个段落进行评分，而是通过遍历语料库层级逐步缩小搜索空间。在每一层级，决策模型评估正在考虑的候选者，并保留最有前景的候选者以供进一步探索。未被选中的候选者被剪枝，其后代永远不会被评估。我们在图 2(c) 中使用公式 1 中的运行示例说明此过程。

文档筛选。 我们首先使用并行二值判断评估候选文档（公式 2）。共享上下文 s_D 包含查询和所有候选文档的描述，而每个二值问题询问某个特定文档是否值得为该查询进行探索。如图 3(a) 所示，模型在单次前向传播中评估所有候选者，为每个候选者分配相关性分数。在我们的运行示例中，“克里斯托弗·诺兰”和“《记忆碎片》（电影）”的页面被保留，而“《角斗士》（2000 年电影）”被丢弃，尽管后者与查询存在关键词重叠。我们根据相关性分数保留前 k 个文档，并剪枝其余分支。

段落评分。 接下来，我们将保留的文档展开为它们的段落，并使用并行二值判断评估它们（公式 2）。共享上下文 s_P 现在包含查询和所有候选段落，使模型能够相互参照地评估它们的相关性，从而使它们的概率直接可比（第 3.2 节）。我们根据二值相关性分数对段落进行排序，并在所有选定的文档中保留前 r 个。在 Natural Questions 上，段落阶段跨越 30 个页面，每个段落的分数首先乘以其页面的分数（第 B.5 节）。在我们的运行示例中，来自“《记忆碎片》（电影）”描述其主角伦纳德·谢尔比（Leonard Shelby）的段落提供了回答查询所需的证据。

可选的段落重排序。 为了优化最终排序，我们可选择对二值评分选出的前 m ≤ r 个段落应用多选判断（公式 3）。选择上下文仅列出这 m 个段落（第 B.6 节）。它们的选择概率决定它们的顺序，而其余段落保持其二值排序。我们使用 m = 20，但在 Natural Questions 上使用 m = 5。在 MTRAG 上，我们仅将概率最高的选择提升到第一位，保持所有其他段落的相对顺序。如图 3(b) 所示，模型在单个决策中将入围段落作为竞争替代方案进行比较。

二值判断适合内部层级：它们没有选项限制，可以并行运行，并且有利于召回率，这在搜索缩小时很重要。多选判断保留到最后，它直接比较二值判断选出的顶部段落并锐化顶部排名（第 6.4 节）。算法 1 总结了任意深度层级的过程。

预算与剪枝。 剪枝是不可逆的：在某一层级被丢弃的分支不会针对此查询重新访问。因此，预算 k_ℓ 倾向于召回率，以覆盖范围换取成本（第 6.6 节）。预算也可以是概率阈值，例如，当最高分数低于 0.8 时保留次优的帮助中心（第 B.2 节）。

3.4 层级构建与扩展

高阶层级。 文档-段落层级只是 DecisionRAG 最简单的实例。对于更大的语料库，可以使用现有的语料库结构或对相关文档进行分组，将文档组织成更高阶的组，例如主题、类别或产品。然后递归地应用相同的过程：在每一层级，并行二值判断识别有前景的组，只有它们的子节点在下一层级被评估。例如，在搜索完整的维基百科语料库时，可以在到达“《记忆碎片》”的单独页面之前，遍历与电影和克里斯托弗·诺兰相关的类别。因此，DecisionRAG 可以扩展到更深的层级，而不需要一次评估所有文档。当语料库缺乏这种结构时，可以通过对文档嵌入进行聚类离线构建层级，例如使用递归 k-means（Nistér 和 Stewénius, 2006）或可扩展的凝聚聚类（Bateni 等，2017；Monath 等，2021；Dhulipala 等，2023），如我们在 Natural Questions 上所做的那样（第 4.1 节）。树不必是均匀的：在 MTRAG 上，仅在包含超过 60 个段落的页面下方插入标题层级。

对于单个请求过大的层级。 一个层级可能包含超过单个请求容量的候选者；在 Natural Questions 上，保留的 150 个簇包含大约 17,500 个页面标题。然后我们将该层级拆分为并行请求，每个请求都有自己的共享上下文。这成本很低：共享上下文的收益在每次请求约 50 个候选者时趋于平缓（第 6.2 节），并且汇总的分数足以进行筛选。在需要更仔细比较拆分层级的顶部候选者时，我们在一个请求中重新评分，如 MTRAG 上的前 50 个页面（第 B.4 节）。

与检索器结合。 DecisionRAG 不需要第一阶段检索器，但它可以使用一个：将稠密检索器的顶部段落添加到最终候选者中，可以恢复被剪枝丢弃的证据（+稠密候选者；第 5.1 节）。

随语料库规模扩展。 因为一层级的所有候选者都被并行判断，延迟取决于层级结构有多少层级，而不是语料库包含多少段落。假设一个大致平衡的层级结构，其中每个节点最多分组 b 个子节点，例如 100 个文档的主题，每个文档有 100 个段落。每增加一个层级，可达段落的数量最多乘以 b，因此包含 N 个段落的语料库需要大约 ⌈log_b N⌉ 个层级。每个层级增加一个顺序决策，因此每个查询的延迟为 T(N) ≈ t_req ⌈log_b N⌉（公式 4），其中 t_req ≈ 0.2 秒是一次请求的延迟。当 b = 100 时，即使 10⁹ 个段落也只需要五个决策，大约一秒钟（图 4）。相比之下，成本随判断数量增长：每层级保留的 k 个节点各有 b 个子节点。公式 4 限制的是顺序深度而不是总计算量，但因为每个层级只保留其前 k 个节点，没有层级评分超过 k·b 个候选者。

图 4：分析模型：顺序阶段随层级深度增长，而非语料库大小。每查询的理论延迟（公式 4，b=100），假设平衡层级和足够的推理服务容量以并行判断每一层级：每增加 100 倍的段落增加一个层级，即多一个顺序决策（约 0.2 秒）。

6 理解 DecisionRAG

是什么让基于决策的检索有效？我们研究共享上下文如何锐化相关性判断、多选排序何时有帮助，以及导航策略和预算如何在检索质量与效率之间进行权衡。

6.1 在共享上下文中评分候选者

DecisionRAG 的一个核心设计选择是在共享上下文中评判候选者，而不是独立评判。对于 Natural Questions 设计问题，我们从 BM25、SPLADE-v3 和 e5 检索的黄金段落和困难负例中构建 5 到 1,000 个候选者的池（图 5）。共享上下文二值判断始终优于在单独请求中评分每个候选者，多选排序在其 255 个选项限制内表现最佳。超过该限制，对二值判断前 255 名进行多选排序保留了这种优势的大部分：1,000 个候选者时 Hit@1 为 53.7%，而仅二值判断为 47.6%。

图 5：Natural Questions 上的 Hit@1 随候选池增长而变化，所有 N 个候选者在一个请求中评分（150 个问题）。

这种优势延续到完整的流水线：在 MultiDoc2Dial 上，将所有选定页面的段落一起评分而不是逐页评分，将 R@1 从 36.7% 提高到 44.4%（+7.7 个点，95% CI：[3.3, 12.2]；第 D.1 节）。

6.2 请求大小

在共享上下文中，每个概率都是在考虑替代方案的情况下形成的：一个单独看起来相关的候选者，当存在明显更好的候选者时，会得到较低的 P(Yes)。共享上下文因此将各个概率置于整体视角中，使它们在候选者之间具有可比性。我们分析这种校准如何随着上下文中候选者数量的增加而改善。

为此，我们将池固定为 200 个候选者，并将其拆分为不同大小的请求（图 6）。Hit@1 从每个候选者单独评分时的 47.8% 增加到每次请求 50 个候选者时的 54.3%，更大的请求几乎没有进一步改进，因此大池可以拆分为大约 50 个候选者的并行请求而不损失。所有 200 个候选者的多选排序达到 60.6%，比在一个请求中对所有 200 个进行二值判断再高 6.8 个点（95% CI：[2.5, 11.0]）。

图 6：当固定的 200 个候选者池被拆分为每请求 m 个候选者并一起排序时，Natural Questions 上的 Hit@1（289 个问题；带状：95% 区间）。

6.3 决策与生成

先前的工作也使用语言模型导航层级，但让生成式 LLM 通过生成 token 在每一层级做出决定（Chen 等，2023；VectifyAI, 2025；Gupta 等，2026）。为了分离通过并行判断而不是生成来做决定的效果，我们保持 DecisionRAG 的层级和预算固定，并将其决策模型替换为 GPT-5（低推理努力），它读取每层级的候选者并写出要保留的候选者编号，风格类似于 LATTICE（Gupta 等，2026）。在 ConditionalQA 上，它选择 652 个页面中的 3 个并对其段落排序；在 Natural Questions 上，它选择 1,000 个簇中的 150 个（当它列出的较少时，我们在同一对话中要求其余的），然后从它们的标题中选择 30 个页面，并像 DecisionRAG 那样对顶部页面的段落排序。

6.4 多选排序是否改善检索？

在二值判断之后，DecisionRAG 可选择对顶部候选者应用多选排序以优化最终排序。我们研究这个额外步骤是否在仅并行二值判断之外改善检索。

6.6 导航预算与层级

最后，我们研究导航预算如何影响检索。在顶层进行剪枝使大型语料库上的导航保持廉价，但这也是证据可能丢失的地方：被丢弃簇中的页面永远无法被检索。我们研究必须保留多少簇才能匹配直接评分每个页面的召回率，改变 DecisionRAG 保留的 1,000 个 Natural Questions 簇的比例，直到对所有 108,626 个页面标题进行平铺评分（图 7）。Recall@10 在大约 10% 的簇之前急剧上升，然后保持平稳：保留 15% 即可匹配平铺评分（86.2% 对 84.5%），成本仅为五分之一（每查询 2.3¢ 对 12.1¢），延迟为三分之一（1.7 对 4.5 秒）。低于 5% 时，包含黄金页面的簇经常被丢弃，recall@10 在 1% 时下降到 63.7%。

7 局限性

DecisionRAG 依赖于语料库层级，其结构和节点描述需要允许决策模型识别相关分支。因此，组织不良的文档或无信息量的描述会损害检索质量。此外，导航不可逆地剪枝分支，因此如果相关段落的祖先被丢弃，它们可能会被遗漏；我们表明更大的探索预算和互补的稠密检索可以缓解这一问题。

8 结论

我们介绍了 DecisionRAG，它通过使用非生成式决策导航语料库层级，将大语言模型的能力带入检索。在每一层级，候选者在共享上下文中被联合评估，使其相关性能够相互参照地判断。通过逐步缩小搜索空间，DecisionRAG 在平衡层级下以仅随语料库大小对数增长的顺序决策数量检索相关证据。随着决策模型的改进，检索可以直接继承它们的能力。

A.1 MultiDoc2Dial

MultiDoc2Dial（Feng 等，2021）包含基于来自四个美国政府帮助中心的 488 个文档的目标导向对话。我们从数据集的元数据构建“帮助中心-页面-段落”层级。帮助中心由领域字段给出，去除 #1/#2 部分后缀后共享标题的文档形成一个页面，共得到 413 个页面。我们使用基准的官方基于结构的分割，得到 4,110 个段落。

段落由其全文及其页面和父标题路径表示，页面由其标题和章节标题表示，四个帮助中心由根据其名称手动编写的一行描述表示。我们在官方验证集（661 个对话，4,201 个轮次）上评估。每个轮次有一个包含代理回答依据片段的黄金段落。发布的测试集没有提供可用的评估示例。

A.2 ConditionalQA

ConditionalQA（Sun 等，2022）包含关于英国政府指南的基于场景的问题，其答案可能取决于多个条件和段落。其语料库包含 652 个指南。我们从 HTML 标题（h1、h2）恢复其结构，并从 p、li 和 tr 元素中提取 58,483 个段落级单元。页面由其标题和顶层部分标题表示，段落按其标题路径分组。检索搜索完整语料库，而不是假设已知相关指南。我们在标记开发集的 285 个问题上进行评估，其中 271 个有标注证据（平均约四个段落）。

A.3 MTRAG–IBM Cloud

我们使用 MTRAG 的 IBM Cloud 子集（Katsis 等，2025），包含 8,578 个文档页面和 72,442 个段落，保留基准的文档文件和段落块。页面根据其 URL 中 /docs/ 后的第一个路径段分组为 172 个产品。由于语料库不保留 HTML 标记，我们从文本布局（由空行分隔的短行）恢复章节标题。页面由其标题和恢复的标题表示，段落由其文本和标题表示。产品描述由产品名称、其着陆页的开头和三个页面标题自动构建。

保留的评估集包含 26 个人类编写的对话，共 205 个轮次，其中 188 个有标注证据（一到七个黄金段落）。

扩展的相关性判断。 MTRAG 的黄金段落是从标注者的 ELSER 检索会话中选择的，因此 ELSER 未呈现的相关段落不能成为黄金段落。因此，我们将 LLM 判断的相关段落添加到黄金段落中。对于每个轮次，我们汇总在 MTRAG 上评估的所有 18 个系统的前五个段落，包括发布的 ELSER 以及最后一轮和重写查询基线，连同黄金段落，相同文本只表示一次。GPT-5 接收对话、参考回复和打乱的候选者，不知道哪个系统检索了它们，并将每个段落评为答案所需（2）、相关但不充分（1）或不相关（0）。2 级段落被添加到相关集合中，所有原始黄金段落都被保留。GPT-5 将 87.9% 的黄金段落评为所需。扩展的标签减少了对 ELSER 的依赖。表 12 比较了所有系统。

A.4 Natural Questions

我们使用 Natural Questions（Kwiatkowski 等，2019）的 DAPR 版本（Wang 等，2024），其语料库将 108,626 个维基百科页面分割为 2,682,017 个段落。我们在 DAPR 测试集（取自 NQ 开发集）的 3,610 个问题中固定的 500 个随机样本上进行评估。一个问题的黄金段落（一到三个）位于单个页面上。由于维基百科在页面之上没有结构，我们使用每个页面标题和首句的 e5-base-v2 嵌入（Wang 等，2022）上的 k-means 将页面聚类为 1,000 个组。每组包含 15 到 350 个页面（中位数 106）。每个组由 Qwen3-8B 从其页面标题编写的一句话描述（第 B.5 节）。页面由其标题表示，段落由其文本表示，按其页面标题分组。

A.5 设计集与配置选择

检索配置（候选者表示、路由规则和保留预算）在与评估集不相交的设计集上选择。选择过程不更新 Jev 的参数。MultiDoc2Dial 使用其训练集的样本，ConditionalQA 使用 300 个训练问题。MTRAG 没有训练集，因此我们使用 50 个合成 IBM Cloud 对话（292 个轮次）和来自 MTRAG-UN（Rosenthal 等，2026）的 131 个 IBM Cloud 轮次，其对话与评估集不相交。

附录 B 检索配置细节

B.1 候选者表示与问题

在每个阶段，判断器接收包含查询和编号候选者描述的上下文，后跟每个候选者一个是/否问题。候选者按文档顺序列出，并在适用时按其父页面分组。每个阶段构建新的上下文；早期阶段的概率不包括在内。对话查询包含最近的六个对话轮次。

对于对话检索，页面和段落问题是“代理下一次回复所需的信息是否在页面 n 上？”和“代理的下一次回复是否应基于段落 n？”对于 ConditionalQA 和 Natural Questions，它们是“回答用户问题所需的信息是否在页面 n 上？”和“段落 n 是否包含回答用户问题所需的信息？”

B.2 MultiDoc2Dial 与对话记事本

路由上下文描述四个帮助中心，每个中心一个问题。我们保留得分最高的中心、当最高概率低于 0.8 时的次优中心，以及最近检索页面的所属中心。页面阶段对保留中心的页面进行评分并保留十个。这些页面的所有段落，加上两个最近记事本页面的段落，在一个共享上下文中评分。

记事本在 MultiDoc2Dial 和 MTRAG 上使用，按最近检索列出不同的页面标识符。在每个轮次之后，排名最高段落的页面移到最前面。页面阶段上下文列出记事本页面。记事本仅由系统自己的检索决策构建，从不来自黄金证据，并且先前检索的段落既不标记也不排除。

B.3 ConditionalQA

页面阶段在一个请求中对所有 652 个指南评分并保留三个，其段落按标题路径一起评分。

B.4 MTRAG

主配置直接对页面评分，而不是通过产品路由。在第一遍中，所有 8,578 个页面标题在输入大小限制下拆分为并行请求，保持每个产品的页面在一起，并按汇总分数保留前 50 个页面。因为这些分数来自不同的上下文，第二遍将这 50 个页面连同其产品名称和标题一起重新评分，并保留十个。

包含超过 60 个段落的页面经过一个额外的阶段，对其标题评分并保留前八个。这些标题的最多 60 个段落（按文档顺序）继续进入段落阶段。

B.5 Natural Questions

每个簇由 Qwen3-8B 描述，给定其页面标题（最典型的在前，最多 300 个）和提示：“写一句话（最多 30 个词）描述这组页面是关于什么的。说出它涵盖的主要主题类型，包括不太典型的类型，以便读者能够判断给定的维基百科页面是否属于这一组。”判断器在八个并行请求中对 1,000 个簇描述评分，对每个簇询问“包含回答用户问题所需信息的页面是否可能在主题 n 中”，并保留 150 个簇。它们的页面标题（每个问题约 17,500 个）在最多 20k token 的并行请求中评分。段落阶段对前三个页面的所有段落、排名 4–10 页面的前十个段落以及排名 11–30 页面的前三个段落在一个共享上下文中评分，每个问题约 230 个段落。每个段落的概率乘以其页面的概率。

B.6 多选排序

多选问题遵循二值评分。其答案选项是 P(yes) 最高的前 20 个候选者（Natural Questions 为前五个），其上下文仅列出这些候选者，按阅读顺序并以二值评分的格式排列。在 MultiDoc2Dial、ConditionalQA 和 Natural Questions 上，选择概率对入围名单重新排序，所有其他候选者保持其二值顺序。在 MTRAG 上，只有概率最高的选择移到第一位。与完整二值上下文上的选择请求相比，较短的上下文在每个数据集上最多改变检索结果一个点，并将 MTRAG 选择请求从 0.30–0.37 秒缩短到 0.14 秒。没有选择步骤的检索在第 6.4 节中评估。

附录 G 开放权重判断器训练

模型。 开放权重判断器是 Qwen3-Base 模型（1.7B、4B 和 8B），其语言模型头被评分头替换。每个候选者作为自己的问题提出，答案选项为“否”和“是”，附加到共享上下文。所有问题都从紧接上下文之后的位置开始，不能相互注意，因此不同候选者的判断仅依赖于共享上下文，如公式 2。评分头将问题结束 token 和每个选项结束 token 的隐藏状态投影到公共空间，用学习的逆温度（上限为 100）缩放它们的余弦相似度，并用 softmax 在问题的选项上归一化；P(yes) 是“是”的概率。训练最小化选项上的交叉熵。在通用和仅 MultiDoc2Dial 检查点中，问题两个选项的结束 token 也可以相互注意；LoRA 检查点不使用此链接。

通用训练。 通用模型在公共多选和分类数据集的混合上训练，包括阅读理解（RACE、QuALITY）、科学和常识问答（SciQ、ARC、CommonsenseQA、HellaSwag）、自然语言推理（MNLI）、意图和主题分类，以及对话、工具使用和网络导航决策（MultiWOZ、xLAM、Mind2Web）。每个示例的标签是数据集的黄金选项；替代方案是其自己的干扰项，或者对于分类，是类标签的随机子集。混合中不包含 MultiDoc2Dial 或 ConditionalQA 数据。

检索训练数据。 MultiDoc2Dial 训练示例从其训练集与导航的路由、页面和段落阶段一起生成；3% 的训练对话被保留用于监控。生成器以 0.65 的概率用黄金页面模拟记事本，以 0.85 的概率将黄金页面包括在三个候选者中，并以 0.17 的概率添加第二个帮助中心负例阶段；黄金段落的相同文本副本从不用作负例。ConditionalQA 示例由导航自身的页面和段落阶段构建，因此它们的输入与推理时的输入匹配。页面阶段示例列出所有 652 个页面，黄金页面标为“是”
