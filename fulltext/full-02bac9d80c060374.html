重新思考交互式世界模型的视频自编码器

作者：Adrien Ramanana Rahary、Yutong Bai、Nicolas Dufour、Patrick Pérez、David Picard

邮箱：{adrien.ramanana-rahary, david.picard}@enpc.fr，nicolas.dufour@kyutai.org，yutongbai@berkeley.edu

*本工作在 Kyutai 期间完成。

机构：Kyutai；LIGM, ENPC, IP Paris, CNRS, UGE；UC Berkeley

摘要

视频世界模型从过去的帧和动作预测未来帧。它们充当模拟器，供智能体训练、规划或评估之用，并且人类可以交互式地控制。这些模型在视频自编码器的潜在空间中生成，而自编码器的压缩率决定了每帧的成本以及每个动作需要等待多久才能生效。然而，世界模型往往复用文本到视频生成器的自编码器，这类编码器是为离线生成而设计的，没有考虑智能体等待的问题，而且由于缺少训练数据和代码，无法在其他压缩率下重新训练。因此我们提出问题：世界模型应当如何压缩、在哪里压缩、压缩多少。我们构建了 CADRE，一个涵盖多种时空压缩率的开放因果扩散表示自编码器家族。其成员仅在冻结特征上的一个小瓶颈上有所不同，并共享一个经自蒸馏后只需一步或几步的扩散解码器。我们在两个领域（操作和导航，各含两个环境）中，在每个自编码器上训练同一个世界模型。CADRE 构成了延迟-质量前沿的大部分，尤其是在相机移动的情况下。我们的研究还得出四项发现：在高压缩率下，扩散解码器比感知回归更锐利；在机器人操作中，时间压缩放在自编码器中比放在世界模型中更有效；操作和导航需要相反的压缩策略——相机静止时时间压缩代价小，相机移动时空间压缩代价小；令人惊讶的是，相机静止时，更粗的空间 token 对运动质量的损害远大于对图像质量的损害。

1 引言

图 1：合适的视频自编码器让交互式世界模型快速响应，同时保持高图像和运动质量。在 CADRE 上，世界模型在单块 H100 上以 20 fps 运行，响应时间低于 230 毫秒，低于人类可察觉的动作延迟（Shimada 等，2009，左上），并在运动保真度（FVD）和动作跟随（ARR；左下）上构成大部分延迟-质量前沿。右：给定动作的推演结果，其中动作延迟使操作变得困难（杂耍、折叠）或危险（驾驶）。

世界模型是环境的学习型模拟器（Ha & Schmidhuber, 2018）。给定过去的帧和智能体的动作，视频世界模型生成接下来的帧，可用于训练智能体（Hafner 等，2025；Alonso 等，2024）、评估机器人策略（Yang 等，2024）、规划动作的结果（Bar 等，2025），或 simply 玩游戏（Bruce 等，2024；Valevski 等，2025；Hu 等，2026）。

为了支持所有这些应用，需要优化两个不同的方面：吞吐量（衡量每秒生成的帧数）和延迟（衡量动作与其在输出上生效之间的时间差）。吞吐量限制模拟进行的速度，而延迟限制模拟的反应性和保真度。

大多数视频世界模型在视频自编码器的潜在空间中运行（Bruce 等，2024；Valevski 等，2025）。为避免设计专门的自编码器，许多方法（He 等，2025；Li 等，2025a；Zhu 等，2026a）复用文本到视频生成器（如 LTX-2（HaCohen 等，2026）、Wan 2.2（Wan 等，2025）或 HunyuanVideo（Kong 等，2024））的自编码器，因此继承了随之而来的吞吐量和延迟。然而，这类自编码器的设计并未考虑世界模型的吞吐量-延迟权衡，而且由于时间压缩对视觉质量影响很小，它们往往进行大规模时间压缩。典型的 8 倍时间压缩在每秒 20 帧下使每个动作至少延迟 400 毫秒。人类会注意到自身动作延迟超过约 230 毫秒（Shimada 等，2009），而只有低于 100 毫秒时交互才感觉即时（Miller, 1968；Claypool & Claypool, 2006）。这引出了一个问题：其他吞吐量-延迟权衡如何影响推演质量和动作跟随。

为回答这个问题，我们提出 CADRE，一个为交互式世界模型构建的开放因果扩散表示自编码器家族。其成员仅在冻结特征上的一个小瓶颈上有所不同——瓶颈决定压缩率——并共享一个只需一步或几步的因果扩散解码器。为了跨设置研究压缩，我们在每个自编码器上训练同一个世界模型（遵循 MIRA（Hu 等，2026）的因果扩散 transformer），涉及两个领域：操作（机器人和人手）和导航（驾驶和室内）。我们将 CADRE 与 Wan 2.2、Cosmos（NVIDIA 等，2025）和 LTX-2 的自编码器、图像自编码器 DC-AE（Chen 等，2025b）以及在我们的数据上重训的 MIRA 自编码器进行比较。CADRE 构成了大部分延迟-质量前沿，尤其是在相机移动时（图 1）。

有趣的是，我们的研究指向四项发现。(1) 在高压缩率下，扩散解码器比感知回归更锐利，而通过渐进自蒸馏训练的少步流模型是合适的选择。(2) 在机器人操作中，时间压缩放在自编码器中比放在世界模型中更有效：在世界模型内部做 patch 化会损失细节，在 8 帧时还会损失动作跟随。(3) 操作和导航需要相反的压缩。操作中相机静止，因此时间压缩代价小而空间压缩代价大。导航中相机移动，平衡反转，因此保留帧并做空间压缩（低延迟选择）是划算的。(4) 令人惊讶的是，相机静止时，更粗的空间 token 对运动的损害远大于对图像质量的损害，在机器人操作中还损害动作跟随。

贡献：

  • 交互式世界模型中压缩控制什么。我们明确阐述了自编码器的空间和时间压缩如何决定世界模型的吞吐量和动作延迟，并将"压缩多少"与"在哪里压缩"分开（第 2 节）。
  • CADRE，面向交互式世界模型的因果扩散表示自编码器。七种时空压缩率的开放模型，其解码器通过渐进自蒸馏在单阶段学习一步或少步解码，无需对抗损失（第 3 节）。
  • 在哪里压缩视频、压缩多少。在四个环境中通过推演和动作跟随评判的对照研究（第 4 节和第 5 节）。

2 交互式世界模型中压缩控制什么

在研究如何压缩之前，我们先明确压缩控制什么。交互式世界模型在一个自编码器的潜在空间中生成，该自编码器将视频片段在时间上压缩 τ 倍、空间上压缩 s 倍，记作 τ×s×s：2×32×32 表示时间压缩 2 倍、空间压缩 32 倍。这两个因子决定世界模型的成本、动作延迟和吞吐量。压缩本身可以发生在自编码器中或世界模型中（第 5.1 节）。

压缩决定世界模型的成本。我们研究的世界模型是一个因果的、时空分解的扩散 transformer，从之前的帧和当前动作或动作块预测下一个潜在帧（第 4 节，附录 D）。其成本随处理的 token 数量增长，而这只由空间和时间压缩决定：T 帧、尺寸 H×W 的片段变为 N=(T/τ)(H/s)(W/s) 个供世界模型处理的潜在 token。

图 2：每帧注册一个动作，其效果在 τ 帧后出现。只有在所有 τ 个动作都到位后才预测一个潜在帧，因此更大的 τ 节省世界模型调用次数但延迟动作。

一个潜在帧等待其所有动作。每帧注册一个动作。一个潜在帧跨越 τ 帧，因此只有在所有 τ 个条件动作已知后，世界模型才能预测它。因此它按块消耗动作，一个块的动作塑造下一个块（图 2）。智能体因此在看到效果之前提交 τ 个动作，就像动作分块策略那样（Zhao 等，2023；Chi 等，2024；Black 等，2025）。块之间保持因果性。在一个块内，τ 帧从同一个潜在表示解码，它们的顺序从真实视频学习。

时间压缩延迟每个动作。一个块的第一个动作等待 τ/f 让块闭合（f 为帧率），然后 t_gen 让世界模型生成潜在帧，t_dec 让自编码器将其解码为 τ 帧，这决定了吞吐量：

latency = τ/f（块闭合）+ t_gen + t_dec（生成与解码），throughput = τ/(t_gen + t_dec)。（公式 1）

没有任何加速手段能缩短第一项，在 τ=8、每秒 20 帧时为 400 毫秒，超过人类注意自身运动延迟的 230 毫秒（Shimada 等，2009）。作为交换，更大的 τ 提高吞吐量，并且在固定空间因子下削减 token 数 N。

3 CADRE：因果扩散表示自编码器

研究压缩意味着在多个压缩点训练自编码器。文本到视频生成器的自编码器发布了权重但没有发布训练数据或代码，因此无法重训。我们转而为世界模型设计一个开放的自编码器家族，每个压缩点一个（图 3）。其成员共享一个配方，仅在压缩率上不同，各自从头训练，因此在它们之上训练的世界模型仅因压缩率而异。

图 3：CADRE。冻结的特征提取器（蓝色；DINOv3）和训练的瓶颈将片段压缩 τ×s×s。因果扩散解码器对其进行去噪，潜在表示在三个位置条件化（i–iii，第 3.1 节）。只有瓶颈、提升层和时间 patch 大小依赖于 τ×s×s。

3.1 架构

冻结特征和一层训练层编码片段。如 MIRA（Hu 等，2026）中那样，编码器是表示自编码器（Zheng 等，2026）的编码器。冻结的 DINOv3 提取器（Siméoni 等，2026）将每帧编码为每个 p×p patch 一个特征，如 RAEv2（Singh 等，2026）中那样聚合多层。一个训练的 3D 卷积，核为 (τ,k,k)、步幅为 (τ,s′,s′)，将 τ 帧、s′² 个 patch 压缩为确定性潜在表示，其中 s=ps′（附录 B）。

因果扩散解码器保持纹理锐利。强压缩的潜在表示保留场景布局和语义但几乎没有纹理，因此感知回归解码器会将与其一致的纹理平均成模糊（Xu 等，2026）。因此我们使用扩散解码器（Preechakul 等，2022；Pernías 等，2024；Chen 等，2025d），它在潜在表示条件下采样片段。它是 q×q patch 网格上的时空分解 transformer（Bertasius 等，2021；Arnab 等，2021），其块先在空间上做注意力，再在时间上因果地做注意力。大多数块为每个潜在帧处理一个 token，即每 τ 个视频帧一个 token。然后线性映射将每个 token 分裂为 τ 个 token（每帧一个），使最后的块能解析潜在帧内的运动。潜在表示在三个位置条件化扩散解码器： 通过转置卷积提升并与 patch 化的噪声片段相加， 通过每个块中的空间 AdaLN（Park 等，2019；Zhu 等，2020；Dufour 等，2022；Yu 等，2026），它还接收流时间 t 和跳跃长度 d（解码器所走去噪步的大小，第 3.2 节，附录 B）， 通过零初始化的跳跃连接进入轻量卷积头。解码器是时间因果的，因此可以逐块流式处理。

3.2 训练

解码器通过流匹配和感知损失学习。解码器 g_θ 使用流匹配的 x 预测、x 损失形式（Li & He, 2026）。它从潜在表示 z 和噪声片段 x_t = t·x + (1−t)·ε 预测干净片段 x，其中 ε∼N(0,I)，t=0 为纯噪声。如扩散强制（Chen 等，2024a）中那样，每个 τ 帧的块抽取自己的 t∼U(0,1)。损失为

L_fm = E_{x,ε,t} ℓ_rec(g_θ(z, x_t, t, 0), x)（公式 2）

其中最后一个参数（跳跃长度 d）在此为零。ℓ_rec 项求和平均绝对误差、两个感知距离（LPIPS（Zhang 等，2018）及其在 DINO 特征空间中的类似物）和如 LTX-Video（HaCohen 等，2024）中的 3D 小波项，通过梯度平衡加权。CADRE 在 76k 小时的网页、机器人、驾驶和相机视频混合数据上训练（附录 C）。

自蒸馏使一两步解码足够。流匹配轨迹是弯曲的，因此沿其前进需要许多步，而交互式世界模型需要单步或少步解码。捷径模型（Frans 等，2025）和自蒸馏流映射（Boffi 等，2025）让网络以步长为条件，训练一个大步与两个小步一致。遵循它们，g_θ(z, x_r, r, d) 预测从 r 到 r+d 的跳跃落点，通过 x_{r+d} = x_r + d/(1−r)·(x̂ − x_r)，隐含速度 v_θ = (x̂ − x_r)/(1−r)。从 r 到 t 的一次跳跃被训练落在通过 u=(r+t)/2 的两次半跳跃的落点处（记法中省略 z），

L_psd = E‖(1−r)(v_θ(x_r, r, t−r) − sg[½(v_θ(x_r, r, u−r) + v_θ(x̂_u, u, t−u))])‖₂²（公式 3）

其中 sg 停止梯度，x̂_u 是前半跳跃到达的点。与在第二阶段蒸馏解码器的一致性解码器（OpenAI, 2023）和 SSDD（Vallaeys 等，2026）不同，CADRE 解码器是自己的教师，在单阶段学习一步或少步跳跃解码。

4 通过世界模型评判自编码器

自编码器被训练来重建其输入，但在潜在生成中，重建和生成之间存在权衡（Yao 等，2025；Hansen-Estruch 等，2025），一系列工作转而为生成器塑造潜在空间（Leng 等，2025；Kouzelis 等，2025；Zheng 等，2026；Xie 等，2026；Ramanana Rahary 等，2026b）。因此我们为推演而非重建打分（附录 F）。如 MIRA（Hu 等，2026）中那样，我们通过在其潜在表示上训练的世界模型的推演来评判每个自编码器；世界模型、片段和动作共享，只有潜在表示不同。

四个环境覆盖操作和导航。我们在四个环境中训练世界模型，两个操作、两个导航（表 1），使没有结论依赖于单一环境。操作中，机器人视角是静态的，人头戴相机视角接近静态，因此主要是手臂或手及其操作的对象在移动。导航中，视角本身在移动，整个画面都在变化；我们将驾驶（其他道路使用者自行移动的动态场景）与静态场景中的室内导航分开。动作复杂度从驾驶的 2 维到双手的 102 维不等。所有视频重采样为每秒 20 帧、288×512。评估使用留出的回合，驾驶使用官方划分。

一个世界模型配方服务所有自编码器。世界模型是 1.2B 参数的因果扩散 transformer，以每个潜在帧的 τ 个动作为条件，用扩散强制训练（Chen 等，2024a）（附录 D）。每个自编码器（包括 CADRE）使用 MIRA（Hu 等，2026）的相同配方，其潜在表示用自身统计量标准化。遵循 SD3（Esser 等，2024）和 RAE（Zheng 等，2026），我们的调优包括根据每个自编码器的潜在大小和 token 数移动噪声调度。

推演按图像和运动质量以及动作跟随打分。每个世界模型接收 40 帧真实视频（2 秒）及其动作，在记录的动作下生成接下来的 96 帧（4.8 秒），在每个环境的 2048 个跨自编码器共享的留出样本上进行。我们为最后 16 个解码帧打分。FID（Heusel 等，2017）测量图像质量，FVD（Unterthiner 等，2019）还惩罚不合理运动和时间接缝。PSNR 和 LPIPS（Zhang 等，2018）测量与记录未来的接近程度；PSNR 应始终伴随分布性指标，因为它奖励模糊。动作跟随由动作可恢复性比率（ARR）测量，它扩展了 MIRA（Hu 等，2026）的逆动力学评估：冻结探针从推演中读回动作，其决定系数（R²）用探针在真实视频上的 R² 归一化，因此 ARR 为 1 意味着达到真实视频的可恢复性（附录 E）。

我们将七个 CADRE 自编码器与五个近期自编码器比较。七个仅在压缩率 τ×s×s 上不同，我们命名每个为 CADRE-τ×s×s（图 12，附录 G）。其他中，四个是现成的、以其原生压缩率使用：Wan 2.2（Wan 等，2025）（4×16×16）、Cosmos（NVIDIA 等，2025）（8×8×8）、LTX-2（HaCohen 等，2026）（8×32×32）和图像自编码器 DC-AE（Chen 等，2025b）（1×32×32）。第五个在我们的数据上以 2×32×32 重训 MIRA 配方（Hu 等，2026）。LTX-2 解码器读取未来潜在表示，因此我们解码每个前缀并保留其最新帧，如流式系统那样。它们来自的生成器在远多于我们的视频上训练，如 Cosmos 的 20M 精选小时，可能包括此处使用的许多数据集。

4.1 解码器应该用感知回归还是扩散？

解码器可以从潜在表示回归一个视频，或通过扩散采样一个。MIRA（Hu 等，2026）走第一条路：它用感知损失（LPIPS 和 DINO）替换自 VQGAN（Esser 等，2021）以来使用的对抗损失，在 Rocket League 上效果良好。它也是除 CADRE 外唯一在人类注意的 230 毫秒延迟内以每秒 20 帧运行的自编码器（图 1）。为在游戏之外测试这条路线，我们在我们的混合数据（附录 C）上以 2×32×32、用我们的提取器和预算重训 MIRA 配方（图 4a）。与 CADRE 解码器相比，它在每个环境中给出更高的 PSNR 但更差的 FID 和 FVD。一步中，CADRE 解码器以相似的动作跟随将 FVD 降低 1.4 到 2.5 倍。第二步将 FID 再降低最多 23%。

解码器应该用感知回归还是扩散？——用扩散解码压缩的潜在表示。这样的潜在表示拟合许多视频。感知回归输出它们的模糊平均，而扩散输出一个锐利的视频。经自蒸馏，它一步解码与回归一样快，FVD 低 1.4 到 2.5 倍，动作跟随相似；第二步进一步改善。

4.2 自编码器如何在质量和延迟之间权衡？

为在两个轴上同时比较自编码器，我们绘制推演质量与动作延迟（图 4b 为机器人操作，图 1 为驾驶，图 14 为全部）；当一个自编码器没有其他自编码器既更快又更好时，它位于帕累托前沿。CADRE 自编码器在每个环境中构成该前沿的大部分。在与 MIRA、Wan 2.2、Cosmos 和 LTX-2 的 48 个比较中的 42 个（四个环境；FID、FVD 和 ARR）中，一个 CADRE 自编码器至少一样快且好超过 2%；DC-AE 比所有都快，在下面比较。两步解码时，每个环境的最佳 FID 属于 CADRE，最常见的是 CADRE-4×16×16，最佳 FVD 也是如此，除了机器人操作中 CADRE 与 Cosmos 持平。相机移动时差距扩大：导航中，除一个外所有 CADRE 自编码器在 FID 和 FVD 上击败所有其他，而 Wan 2.2 的 FVD 从机器人操作的 53 增长到导航的 600 或更多，LTX-2 的 ARR 在室内降至 0.04。CADRE 在 64 秒机器人操作推演中漂移也最小（附录 H）。

在快速端，CADRE-1×48×48 的反应与 DC-AE 大约一样快，在导航中击败它；DC-AE 在操作中获胜。很少有自编码器既流畅又响应迅速：在单块 H100 上以八个去噪步流式运行时，只有 CADRE-2×32×32、CADRE-2×16×16 和 MIRA 在人类注意的 230 毫秒延迟内以每秒 20 帧运行（Shimada 等，2009）（图 1）。图 5 的世界模型流畅运行，每秒 29 到 58 帧（附录 D），并且从相同上下文跟随从未与其一起记录的动作，如保持静止或转向另一边（图 22）。

图 5：跟随记录动作的实时推演。从 2 秒真实视频（左）及其动作，CADRE 世界模型生成所有其他帧，机器人操作中有接触，人类操作中有布料动力学，驾驶中有合理的未来，室内场景 3D 一致。

5 如何为交互式世界模型压缩

我们现在问三个问题：哪个组件应该做时间压缩、一个潜在帧应跨越多少帧、更粗的空间 token 用什么换取速度。比较遵循第 4 节的协议，因此各分支仅在视频压缩方式上不同。

5.1 自编码器还是世界模型做时间压缩？

图 6：自编码器或世界模型中的时间压缩，在机器人操作中相同 token 网格下比较。自编码器在除 2×32×32 外的所有设置中给出更锐利的帧、更接近记录的未来、更合理的运动。动作跟随几乎不变，8 帧除外。

时间压缩可以发生在自编码器或世界模型中。CADRE 的替代方案是图像自编码器，时间上不压缩帧，由世界模型对其潜在表示做时间 patch 化。两条路线给出相同的 token 网格，但由不同的模型学习压缩。在机器人操作中，我们通过在世界模型内 patch 化 CADRE-1×16×16 的潜在表示第二次达到每个网格（图 6）。只有压缩改变。动作和噪声水平保持每帧，patch 化的 token 接收其覆盖的每帧的动作。

自编码器中的时间压缩比世界模型中的给出更好的帧。在自编码器中压缩在每个时间网格上给出更好的 FID、FVD、PSNR 和 LPIPS，2×32×32 的 FVD 除外（那里空间也被压缩）。FVD 差距随因子增长，从压缩 2 帧时的 9 点到压缩 8 帧时的 28 点。解码器容量不能解释它，因为 patch 化分支用 CADRE-1×16×16 解码，其中重建最好的（表 6）。我们将其归因于训练目标。自编码器被训练重建像素，因此其压缩保留外观。世界模型被训练预测潜在表示，因此其压缩只保留有助于该预测的内容。这与图像和视频生成一致，其中在自编码器中压缩胜过 patch 化（Chen 等，2025b；Gupta 等，2024）。

时间压缩发生在哪里几乎不改变动作跟随。例外是 8 帧，patch 化将 ARR 从 0.72 降到 0.56。动作跟随取决于动作引起的运动，世界模型的压缩被训练保留它。

自编码器还是世界模型做时间压缩？——让自编码器做时间压缩。在相同 token 数下，其压缩的帧看起来更锐利、运动更真实，动作跟随相似。它学习压缩以重建像素，而世界模型只保留有助于预测的内容。

5.2 一个潜在帧应跨越多少帧？

图 7：时间压缩和空间 token。绿色在固定 token 大小下提高 τ；橙色在固定 token 预算下，因此其网格变粗（空间因子 s）。静态视图可以将八帧放入一个潜在帧而无代价；移动视图随帧数增多而损失质量。完整结果见图 15。

为将时间压缩与更粗 token 的代价分开，我们在两次扫描中变化 τ（图 7）。第一次固定 s=16，隔离时间压缩。第二次固定每 16 帧片段约 1100 个 token，因此在给定 τ 下它与第一次的差距测量更粗空间 token 的代价。所有世界模型在训练步数和总训练帧数上匹配。

操作中潜在帧应跨越许多冗余帧，导航中应少。操作中相机大多静止，因此连续帧冗余，一个潜在帧可以无代价跨越许多帧（图 7 绿色曲线）。导航中相机移动，视图在一个长潜在帧内移动超过一个 token（附录 I），因此长潜在帧降低运动质量，FVD 比两帧潜在帧高出最多 64%。动作跟随变化较小（附录 G）。相机运动是我们的主要解释，尽管领域在动作和场景上也有差异。

在 64 秒机器人操作推演中，长潜在帧不会使误差累积：CADRE-8×16×16 从约 13 秒起最好，最终 FVD 最低（附录 H）。长潜在帧确实留下接缝，即块之间可见的跳跃。边界超出量将块边界上的帧间变化与块内变化比较，相对真实视频（附录 K）。它在所有四个环境中随 τ 增长，τ=8 时达 1.6–1.8（表 10）。移动视图时，接缝也体现在 FVD 中，τ=8 比 τ=2 增长 1.6 到 2.1 倍。

固定 token 预算下，导航偏好每潜在帧少帧，操作偏好多帧。沿图 7 橙色曲线，自编码器每 16 帧片段给出约 1100 个 token。导航中，低延迟的 CADRE-2×32×32 最好，两帧加更粗 token。操作中，CADRE-8×16×16 给出最合理的运动，八帧加细 token。

一个潜在帧应跨越多少帧？——操作和导航需要相反的压缩。操作中相机静止，每个 token 看到时间冗余的内容：时间压缩代价小，但空间压缩损失被处理的小物体。导航中相机移动，每个 token 看到新内容：时间压缩显示接缝，但空间压缩代价小，因为整个视图在移动。

5.3 更粗的空间 token 用什么换取速度？

给定 τ，更粗的空间 token 削减世界模型的成本，两次扫描之间的差距隔离它们在质量和动作跟随上的损失。

当动作小且保持在视野内时，细空间 token 最重要。机器人操作中，动作体现在保持在视野内的小区域。τ=2 时，更粗的空间 token 使 FVD 乘以 2.4 并降低动作跟随，FID 几乎不变（图 7 橙色对绿色）。导航中，动作移动整个画面，粗 token 已经捕获，差距几乎消失（附录 G）。FID 可能错过局限于小区域的错误，但读取运动本身的 ARR 也下降（附录 G）。

更粗的空间 token 用什么换取速度？——令人惊讶的是，更粗的 token 对运动和动作跟随的损害远大于图像质量，尤其是在操作中。操作中，每帧质量几乎不变，但运动退化，机器人操作中动作跟随也退化。导航中整个视图移动，它们代价很小。

6 相关工作

世界模型及其自编码器。视频世界模型服务驾驶（Russell 等，2025）、机器人（Yang 等，2024）和开放场景（Bruce 等，2024）。交互式的实时流式运行（Valevski 等，2025；Alonso 等，2024），通常通过蒸馏文本到视频生成器，继承其自编码器（He 等，2025；Li 等，2025a）。很少有工作研究该自编码器。SANA-WM（Zhu 等，2026a）离线交换其中两个，MIRA（Hu 等，2026）通过世界模型评判自己的，但仅在单个游戏上。我们通过四个环境中的世界模型比较十二个不同压缩的自编码器。

潜在结构和压缩。生成质量取决于潜在结构（Rombach 等，2022；Yao 等，2025）。表示自编码器在冻结自监督编码器的空间中生成（Zheng 等，2026；Xie 等，2026），为单一压缩率。视频自编码器大多空间 8 倍、时间 4 倍压缩（Wan 等，2025；Kong 等，2024），有些远多于此（HaCohen 等，2024；HaCohen 等，2026；Chen 等，2025b）。生成器也可以通过 patch 大小压缩（Peebles & Xie, 2023；Gupta 等，2024）。图像上，DC-AE（Chen 等，2025b）发现在自编码器中压缩胜过 patch 化。我们对视频世界模型测试这一点，并构建跨越七种时空压缩的表示自编码器。

少步扩散解码器。扩散解码器避免对抗损失（Preechakul 等，2022；Chen 等，2025d）但需要许多步，或需要第二阶段达到一步（OpenAI, 2023；Vallaeys 等，2026）。捷径模型和流映射从自身预测在单阶段学习少步生成（Frans 等，2025；Boffi 等，2025）。我们的因果视频解码器以此方式学习一步或两步解码，无对抗损失或第二阶段。附录 L 扩展本节。

7 结论

交互式世界模型从其自编码器继承每帧成本、动作延迟和大部分质量，因此其压缩是一个设计选择。为研究这一选择，我们构建 CADRE，一个跨越七种压缩的开放家族，并在操作和导航中的每个上训练同一个世界模型。CADRE 构成大部分延迟-质量前沿，尤其是相机移动时，我们的研究指向四项发现。高压缩下，扩散解码器比感知回归锐利，即使一两步。机器人操作中，时间压缩在自编码器中比世界模型中更有效。操作和导航需要相反的压缩：相机静止时时间压缩代价小，相机移动时空间压缩代价小。令人惊讶的是，相机静止时，更粗的空间 token 对运动的损害远大于图像质量，机器人操作中还有动作跟随。

我们的世界模型各覆盖一个环境；这些发现是否推广到通用模型，以及策略训练和规划，仍是开放问题。我们的操作数据使用静止或接近静止的相机；腕装相机会移动，因此我们的解释预测它们偏好导航的压缩。我们希望开放的自编码器能让从业者将世界模型的压缩适配到其场景以及用户所需的延迟和吞吐量。
