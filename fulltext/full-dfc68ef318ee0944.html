摘要

中期训练越来越被认为是塑造大语言模型能力的关键阶段。最近的工作表明，有针对性的中期训练可以增强数学和科学等推理密集型能力，也可以改善软件工程环境中的智能体能力。在这项工作中，我们研究了平行但较少被探索的智能体能力：通用工具使用。我们提出了 MidTool，这是一个用于智能体工具使用中期训练的开放语料库构建流水线，它将大规模的网页、PDF 和代码数据与来自真实世界工具 API、MCP 技能和基于文档的工作流的合成监督相结合。MidTool 旨在教模型如何识别工具可供性、从上下文中确定参数基础、组合工具调用工作流，以及从不完整的信息中恢复。我们在 MidTool-Mix 上对 Qwen3-4B-Base 和 Qwen3-8B-Base 进行了中期训练，然后应用了包含监督微调和强化学习的后续后训练。与基线相比，MidTool-Mix 在 BFCL、$\tau^{2}$-Bench 和 MCP Universe 上，无论是在 SFT 还是 RL 下，都能持续提升下游性能。这些结果表明，与其他重要的大语言模型能力一样，通用工具使用也受益于专门的中期训练，而不是完全留给后训练。

1 引言

工具使用正成为大语言模型（LLM）智能体的决定性能力。强大的系统必须决定何时需要外部工具，将调用建立在工具模式之上，从冗长且嘈杂的上下文中提取参数，将多个工具组合成工作流，并在信息不完整时进行恢复。这些行为现在在函数调用、API 编排、交互式智能体基准测试和新兴的模型上下文协议（MCP）生态系统中都至关重要 (21; 13; 17; 14)。

然而，最近在工具使用方面的进展大多来自后训练。在精选轨迹上进行监督微调（SFT）和强化学习（RL）已经显著改善了函数调用和智能体行为 (23; 12; 19; 33)，但它们也给后训练带来了沉重的负担。模型必须从相对狭窄的监督中同时获得一组原子智能体能力，包括工具识别、基于模式的参数构建、缺失信息下的澄清以及多步执行。更根本的是，支撑成功工具使用的知识并不仅仅存在于明确的轨迹中。它分布在开发人员文档、手册、PDF、代码库、API 规范和结构化工具定义中，其中大部分从未作为干净的智能体演示出现过 (20; 13; 33)。

这提出了一个自然的问题：通用工具使用能力能否通过专门的中期训练更早地塑造，而不是几乎完全留给后训练？

中期训练是多阶段预训练的一个独特阶段，弥合了通用预训练和后训练阶段之间的差距 (27)。最近的工作表明，有针对性的中期训练可以实质性改善推理密集型能力 (28; 25)，并且新兴的努力已经开始探索用于深度研究 (24; 26)、编码 (37; 36; 32) 和软件工程（SWE）(34; 38) 的智能体中期训练。然而，作为中期训练的目标，通用工具使用仍未得到充分探索。与数学或 SWE 任务相比，工具使用数据需要覆盖更广泛、更异构的能力面，包括自然语言文档、可执行代码模式、结构化模式、多工具工作流以及由信息缺失引起的失败案例。

在本文中，我们介绍了 MidTool，一个用于构建通用工具使用智能体中期训练数据的可扩展流水线，以及由此产生的 20.3B token 混合数据集 MidTool-Mix。我们的流水线从四个互补的来源系列开始：网页、PDF、代码库和结构化工具工件（如 API 和 MCP 技能）。然后，它通过两个针对工具使用两个核心缺陷（基础和执行）的合成分支将这些来源转换为训练监督。

第一个分支，上下文基础的轨迹增强，通过将文档和代码转化为识别工具边界、推断参数和从混乱的真实世界工件中恢复工作流结构的监督来解决基础问题。

第二个分支，原生智能体轨迹合成，通过直接从真实 API、MCP 技能和收集的 rollout 轨迹构建可执行轨迹来解决执行问题，教授多轮规划、澄清和恢复，并对模式基础、轮次顺序、必需参数和工具响应一致性进行明确验证。

由此产生的混合数据集旨在教模型不仅存在哪些工具，还包括识别其可供性、将其组合成工作流以及在信息不完整时恢复所需的原子智能体能力。表 1 将我们的工作置于具有代表性的开放语料库和中期训练努力之中。相对于先前的开放努力，我们的目标既不是通用领域的混合数据集，也不是针对数学、深度研究或软件工程的特定领域语料库，而是一个专门用于通用工具使用的智能体语料库。

我们通过在 MidTool-Mix 上对 Qwen3-4B-Base 和 Qwen3-8B-Base 进行中期训练，随后应用相同的下游 SFT 和可选 RL 方案，来评估这种中期训练是否提供了超越标准后训练的价值。在 BFCL (17)、$\tau^{2}$-Bench (1) 和 MCP-Universe (14) 上，我们观察到一个一致的模式：MidTool-Mix 比仅使用 SFT 的基线提高了下游工具使用性能，而 RL 通常会进一步增加这些收益。这些收益在更难的多轮和交互式设置中尤为明显。

贡献。 我们的主要贡献有三个：
(1) 据我们所知，我们引入了 MidTool，这是第一个为通用工具使用设计的开放流水线和中期训练数据集，并构建了 MidTool-Mix，一个 20.3B token 的混合数据集，它将网页、PDF、代码和工具工件与上下文基础增强和原生智能体轨迹相结合。
(2) 我们表明，在 SFT 和 RL 下的三个基准测试中，专门的工具使用中期训练持续提高了 4B 和 8B 模型的下游通用工具使用性能，这表明中期训练为后续后训练提供了更强大、更稳定的基底。
(3) 我们表明 MidTool-Mix 有助于揭示一个有意义的能力边界：它对广泛的工具使用能力和迁移的益处最大，而更专业的探索行为则保持独立。这表明诸如深度搜索之类的能力可能需要超出纯粹通用工具使用混合数据的专门中期训练数据，为未来的智能体中期训练研究提供具体指导。

2 MidTool：用于智能体中期训练数据合成的可扩展流水线

在本节中，我们介绍了构建大规模中期训练语料库的流水线，包括数据源收集、数据预处理和智能体轨迹合成阶段。

2.1 阶段 1：数据源收集

如图 2 所示，我们的数据收集阶段旨在涵盖智能体工具使用所需的互补信号。有效的工具使用行为不仅取决于明确的轨迹，还取决于广泛的技术知识、面向工具的文档、可执行代码模式和有根据的工具模式。因此，我们收集了四个来源系列：网页文档、PDF、代码库和结构化工具工件。

网页数据。 我们使用来自 FineWeb (18) 处理过的 Common Crawl 转储作为主要的大规模网页来源。我们抽取了 2020 年至 2025 年的多个转储，以捕获最近的技术内容，包括 API 参考、开发人员文档、故障排除页面、教程和 CLI 风格的说明。相对于后来的轨迹合成，网页语料库大规模地提供了工具相关概念、术语和工作流描述的广泛覆盖。

PDF 数据。 许多高价值的工具使用资源（如手册、产品手册和平台文档）以 PDF 而非干净的 HTML 页面形式分发。因此，我们使用 FinePDFs (8) 作为补充爬取来源，并仅保留英文子集。与网页相比，PDF 贡献了标准网页快照中通常缺失的较长形式的过程内容和文档，但它们也需要更严格的下游过滤，因为提取噪声要高得多。

代码数据。 工具使用与软件工件紧密耦合，因此我们从两个互补的 GitHub 切片收集存储库数据。我们从 Snowflake GH Archive 事件数据 (4) 初始化存储库发现，然后应用特定任务的过滤。第一个切片针对从 GitHub 事件数据获得的与智能体相关和与 MCP 相关的存储库，并对新近度、活动性和选择性许可进行过滤。该切片捕获了具体的工具接口、编排模式和新兴的智能体工程实践。第二个切片针对具有强大社区信号和近期活动的主要编程生态系统（如 Python、Java、JavaScript、TypeScript、Go、Rust、C/C++、C#、SQL、Shell 和 Dockerfile）的高质量公共存储库。我们进一步保留可能包含有用的库、SDK、框架、示例或教育技术内容的存储库，同时删除会增加噪声或泄露风险的个人项目、分支以及基准或数据集存储库。特别是，我们通过在数据收集期间积极维护的黑名单，明确地从 GitHub 代码切片中排除已知的基准和评估存储库；更多详细信息见附录 A.1。

工具数据。 最后，我们单独收集结构化工具工件，包括 REST API 和 MCP 技能，以支持原生智能体轨迹合成。与网页、PDF 和代码来源不同，这些工件直接暴露了可执行的模式、参数结构和工具边界。因此，它们为在后续合成阶段构建有根据的工具调用、多工具计划和恢复行为提供了最忠实的基底。

总而言之，这四个来源系列有意地权衡了广度和结构。网页和 PDF 数据提供了广泛的技术背景，代码库贡献了可执行模式和开发人员工作流，而工具工件提供了明确的模式和可调用接口。后续的预处理和合成阶段将这种异构的原始语料库转换为用于智能体中期训练的统一训练混合数据集。

2.2 阶段 2：数据预处理

代码。 遵循 9 和 30，我们应用多阶段过滤来构建用于有效训练的高价值子集。我们调整基于扩展名的过滤列表，以排除二进制数据、模型权重和日志等文件。然后，我们采用 StarCoder (9) 的启发式方法进行基于内容的过滤，包括行数、平均行长、最大行长和字母比率。我们还将 Jupyter Notebook 文件转换为 Python 文本文件。对于去重，我们通过对规范化文本进行 SHA-256 哈希处理来删除完全重复项，并使用 MinHash LSH 删除近似重复项。对于接受的高质量存储库，我们应用一个仅匹配文档类目录（如 docs、examples、tutorials、guides、samples 和 cookbook）的过滤器。

网页和 PDF 数据。 对于网页和 PDF 中期训练来源，我们使用四阶段流水线：高召回率关键词/URL 预筛选、在 LLM 标记的种子数据上训练的轻量级 fastText (7) 分类器、文档级质量过滤和 MinHash LSH 去重。该流水线旨在保留面向开发人员的文档和技术参考材料，同时抑制通用的网页噪声和 PDF 提取工件，对 PDF 使用更严格的阈值。完整详细信息见附录 A.2。

2.3 阶段 3：智能体轨迹合成

正如我们后来的研究所表明的，有效的工具使用中期训练必须解决两个互补的缺陷。

第一个是基础：模型通常无法从混乱的真实世界工件（如文档、PDF 和代码）中推断工具边界、必需参数和工作流结构。

第二个是执行：即使有工具模式可用，模型仍然难以跨多轮进行计划、请求缺失信息、正确排序调用以及从不完整的交互中恢复。

因此，我们实例化了一个双分支合成流水线，将非结构化文档和结构化工具工件都转换为规范化的智能体轨迹。

上下文基础的轨迹增强。 许多网页、PDF 和代码文档暴露了工具可供性和工作流，但不包含明确的交互痕迹，因此我们将它们用作面向基础的分支。我们首先应用轻量级的基于关键词的预过滤器，然后使用 Qwen3-235B-A22B-Instruct-2507 为每个剩余文档标注质量分数和结构化的可供性配置文件。可供性配置文件记录是否可以推断工具响应，以及关于模式/API 结构、代码或 CLI 用法、工作流结构、工具拓扑和领域术语的证据。低于质量阈值的文档保留而不进行增强，而对于保留的文档，基于规则的规划器将提取的可供性转换为合成计划。规划器将监督量与文档质量联系起来，为多样化的问答类型分配有限的预算，并且每个文档最多允许一个多轮链。常规问答将工具使用分解为原子智能体能力（如工具选择、基于模式的参数提取、格式约束调用、工作流识别和多/并行使用），而轨迹样本涵盖顺序执行、参数澄清、工具切换和长上下文推理。我们使用 Qwen3-235B-A22B-Instruct-2507 合成增强数据。只有通过解析和语义质量控制的问答对和轨迹才会合并到最终的训练混合数据集中。

原生智能体轨迹合成。 对于结构化工具来源（包括 API 组和 MCP 技能），我们使用第二个分支直接从可执行接口教授执行和计划。我们首先通过对相关端点或技能进行分组、解析工具定义并使用轻量级预筛选删除低信号来源来构建工具清单。然后，我们使用 GPT-5 为每个来源分配质量分数以及轨迹家族的可行性配置文件，包括简单的单次调用使用、复杂的多/并行工具使用和信息缺失设置。对于通过质量过滤器的来源，我们恢复面向开发人员的文档上下文，将可用工具规范化为规范的可执行模式，并仅在参数描述不充分时应用有针对性的模式细化。接下来，我们合成多样化的用户角色，并让模型提出候选轨迹计划，但最终分配由确定性的质量自适应预算控制器强制执行，该控制器以来源质量、工具数量、参数结构和可行性约束为条件，优先考虑多轮轨迹。这防止了过度生成琐碎样本，并将生成转向针对高能力来源的更丰富的多轮行为。最后，特定类别的生成器实例化计划的轨迹，使用 GPT-5、GPT-5.1 和 GPT-5.2 的混合进行生成。由此产生的轨迹在轮次排序、模式基础、必需参数和工具响应一致性方面受到严格验证；无效生成在丢弃前会额外使用质量控制反馈进行重试。我们还混合了从智能体世界模型（AWM）(29) 合成环境中收集的 rollout 轨迹，以便模型不仅学习孤立的原子能力，还学习它们如何组合成稳健的智能体行为。最后，我们还整合了来自 Nemotron Agentic 数据集 (2) 的过滤后的智能体轨迹，以进一步扩大原生轨迹部分。

2.4 MidTool-Mix 分析

MidTool-Mix。 我们最终的训练混合数据集由三个部分组成：(1) 跨越过滤后的网页、代码和 PDF 语料库的高质量来源混合数据；(2) 从这些来源派生的上下文基础轨迹，包括问答；以及 (3) 原生智能体轨迹，包括从真实语料库构建的合成轨迹、收集的交互 rollout 和过滤后的 Nemotron Agentic 数据集。遵循 16，我们将所有轨迹规范化为纯聊天风格的模板，没有特殊的控制标记（如 <im_start>）。

表 2 总结了由此产生的组成。MidTool-Mix 总共包含 20.3B token 和 11.22M 个样本。对于网页、PDF 和代码，我们使用斜杠分隔的计数分别报告保留的来源 token 和相关的上下文基础增强。整体混合数据集在网页（42%）、代码（26%）和 PDF（23%）来源之间有意保持平衡，而原生智能体轨迹贡献了总预算的额外 9%。这种分配保留了对从自然文档进行基础的广泛技术覆盖，同时为可执行智能体监督保留了不可忽视的一部分混合数据。附录 A.4 提供了按增强类型、轨迹形状和工具清单的更细粒度细分。

3 实验

3.1 设置

基线和训练设置。 与之前主要将工具使用作为后训练目标进行研究的工作不同，我们的流水线从预训练的基础模型开始，并通过中期训练更早地注入工具使用能力。我们研究了两个基础模型，Qwen3-4B-Base 和 Qwen3-8B-Base，并为每个规模比较了四种训练方案：带有 SFT 和可选 RL 的原始基础模型；使用 MidTool-Mix 进行中期训练的基础模型，随后是 SFT 和可选 RL。对于 SFT，我们在从 TOUCAN (33) 采样的 100K 工具使用子集上微调模型。中期训练和 SFT 均使用 ArcticTraining (22) 在 32 个 H200 GPU 上进行。我们采用 AWM 设置 (29)，使用 526 个合成工具使用环境进行智能体 RL 训练，使用 8 个 B200 GPU。详细的超参数见附录 B。我们还与后训练的 Qwen3-4B 和 Qwen3-8B 模型进行了比较，并禁用了思考以与我们的设置保持一致。

基准测试。 我们在三个互补的基准测试上评估通用智能体工具使用能力：BFCL v3 分割 (BFCLv3) (17)、验证过的 $\tau^{2}$-Bench (1; 3) 和 MCP-Universe (14)。BFCL 在单轮和多轮设置中衡量函数调用质量，对于隔离有根据的工具选择、参数构建和幻觉行为特别有用。$\tau^{2}$-Bench 强调在航空、零售和电信等现实垂直领域中的交互式任务完成，使其成为多步执行和恢复的有用探针。MCP-Universe 评估在跨越浏览器自动化、金融、位置和网页搜索等领域的真实 MCP 服务器上的执行情况，因此可作为分布外工具泛化的更难测试。我们遵循 29 开发的评估工具。

3.3 消融研究

为了研究数据设计的效果，我们固定 4B SFT 方案，仅改变中期训练语料库。我们以累加方式分解 MidTool-Mix：仅处理后的原始来源、在其上添加的每个合成分支以及完整混合数据集。我们与预算匹配的通用中期训练基线 Dolmino-20BT (16) 进行比较，并以无中期训练设置作为参考。

两个 MidTool 子集扮演不同但互补的角色。 仅处理后的原始来源已经提供了积极的独立信号：在完全没有合成数据的情况下，它们在无中期训练的基础上将 BFCLv3 整体提高了 +2.6，将 MCP-Universe 通过率提高了 +1.4，并在 BFCL 整体和 $\tau^{2}$-Bench Pass@4 上与 Dolmino-20BT 保持竞争力，同时向 MCP-Universe 的迁移要好得多。我们注意到 Dolmino-20BT 本身并不是一个纯粹的非合成基线，因为发布的混合数据集也包含模型生成的组件。完整混合数据集比无中期训练有显著改善，甚至仅添加上下文基础增强的变体也远高于无中期训练和 Dolmino-20BT。与 Dolmino-20BT 相比，该变体仅在实时子集上略弱，但在非实时、多轮和整体上更强。在 $\tau^{2}$-Bench 上，情况类似：仅上下文基础变体超过了无中期训练和 Dolmino-20BT。值得注意的是，原生智能体轨迹子集是唯一包含由专有模型合成的轨迹的子集。该变体在 BFCLv3 和 $\tau^{2}$-Bench 上仍然显著优于无中期训练，并在几乎所有指标上超过 Dolmino-20BT，这一事实表明 MidTool-Mix 的收益并非完全由专有模型合成的轨迹驱动。尽管如此，该分支仍然是模型合成的，具有开放权重的教师；严格的非蒸馏贡献被上面的过滤数据分割所隔离。

这两个分支的贡献也是不对称的。 仅添加原生智能体轨迹会产生更大的 BFCLv3 收益（整体 +7.9 对 +4.9），表明可执行轨迹对于精确的函数调用尤为重要。仅添加上下文基础增强在 $\tau^{2}$-Bench 和 MCP-Universe 上是两者中更强的，表明面向基础的监督对于迁移尤为重要。在 BFCL 非实时上，仅原生变体甚至略高于完整混合数据集（68.21% 对 66.38%），但它在多轮、$\tau^{2}$-Bench 和 MCP-Universe 上放弃了很大的优势；结合两个分支是唯一能在所有八个指标上比无中期训练有所改善的配置。MCP-Universe 使互补性尤为明显：两个单分支变体都低于无中期训练，但仍优于 Dolmino-20BT，这表明每个子集都贡献了有意义但不完整的智能体先验。更广泛地说，Dolmino-20BT 相对具有竞争力的 BFCL 结果，与其在 $\tau^{2}$-Bench 和 MCP-Universe 上弱得多的迁移形成对比，表明通用的指令遵循式中期训练可能有助于简单的函数调用行为，但向更智能体设置的迁移效果很差。

4 相关工作

面向智能体能力的中期训练
前沿模型不断进步的智能体能力强调，强大的智能体行为不是仅仅从后训练中获得的，而是从将强大的预训练基础与用于长范围中期训练的额外大规模能力塑造相结合而获得的 (15; 32)。例如，GLM 团队描述了他们在长上下文设置的推理和智能体数据以及用于软件工程任务的存储库级代码数据方面的中期训练努力 (37; 36)。通义深度研究提出了用于深度研究基础的具有可扩展智能体数据流水线的智能体中期训练 (24; 26)。34 和 38 提出了以 SWE 为中心的智能体中期训练数据流水线。虽然 16 披露了中期训练方案，但它主要关注通用领域的高质量数据，其混合数据集强调数学和科学等推理任务。与先前的工作 (28) 不同，我们通过专门的流水线构建了一个用于智能体工具使用的开源中期训练语料库。

用于工具使用的后训练数据集
早期关于工具使用数据的工作侧重于从工具定义或模型自标注构建。Toolformer (21) 表明，语言模型可以在自我监督下将 API 调用插入文本中，而 ToolLLM (20) 和 APIGen (13) 将这一方向扩展到大量真实 API 和可验证的函数调用实例。后来的工作从单轮调用转向更丰富的智能体交互轨迹。AgentBank (23) 收集了用于通用智能体微调的多样化交互痕迹，而 ToolACE (12) 表明，大规模、精心策划的函数调用监督对于后训练工具使用对齐仍然非常有效。最近的工作强调大规模的多轮、环境基础数据合成。APIGen-MT (19) 通过模拟智能体-人类交互生成多轮轨迹，TOUCAN (33) 从真实世界的 MCP 环境合成 150 万个工具智能体示例，而 Simia (10) 专注于合成环境，并进一步探索了用于交互式智能体的模拟器支持训练数据。这些努力大大提高了工具调用和智能体交互的后训练监督的可用性。我们的重点与这一工作线是互补和平行的：我们研究用于智能体中期训练的开源语料库和数据流水线，它可以为工具使用行为提供更广泛的先验，进而与下游后训练数据集和目标协同工作。

5 结论

在这项工作中，我们研究了通用工具使用是否受益于专门的中期训练，而不是完全留给后训练。我们介绍了 MidTool，一个可扩展的语料库构建流水线，以及 MidTool-Mix，一个 20.3B token 的混合数据集，它将过滤后的来源语料库与上下文基础增强和原生智能体轨迹配对。在 4B 和 8B 基础模型中，在 MidTool-Mix 上进行中期训练在 SFT 和 RL 下持续提高了 BFCL、$\tau^{2}$-Bench 和 MCP-Universe 上的下游性能，在多轮和交互式设置中收益尤为明显。这些收益是对更强后训练的补充，而不是替代：下游方案在我们的整个实验过程中保持固定，我们将扩大后训练监督和加强工具使用中期训练视为应该共同前进的两个轴。消融表明，这些改进源于混合数据集的结构：移除任一合成分支都会降低性能，这表明面向基础和面向执行的监督是互补的。我们的结果还浮现了一个有意义的能力边界：虽然 MidTool-Mix 改善了对未见工具和 MCP 领域的广泛迁移，但它对深度搜索式的探索行为贡献微乎其微。这表明通用工具使用中期训练为模式基础和工作流组合提供了可重用的先验，而高度探索性的领域需要专门的轨迹数据。未来的工作包括扩大原生轨迹收集、拓宽工具生态系统覆盖范围，以及为特定领域的智能体行为构建专门的中期训练混合数据集。

附录 A MidTool 流水线的更多细节

A.1 数据收集期间的基准排除

为了减少 GitHub 存储库切片的基准泄露，我们在存储库爬取和预处理之前明确排除已知的基准和评估存储库。在实践中，我们的代码数据流水线加载一个存储库名称黑名单，并在数据集构建期间完全跳过匹配的存储库。该黑名单包括与 BFCL 相关基准、$\tau$-Bench / $\tau^{2}$-Bench、MCP-Universe 和相关 MCP 评估套件相关的存储库，以及其他广泛使用的智能体和工具使用基准。这种基于黑名单的排除被集成到数据流水线中，而不是作为临时的后处理步骤应用。随着新的公共智能体基准的出现，我们积极维护和更新此列表，以便未来流水线的运行可以在数据收集期间继续执行相同的基准排除策略。

A.2 网页和 PDF 过滤流水线

对于网页和 PDF 中期训练来源，我们使用单独的四阶段流水线，包括关键词/URL 过滤、fastText 分类、质量过滤和基于 MinHash 的去重。

阶段 1：高召回率预筛选。 第一阶段作为高召回率预筛选器。它将针对软件开发术语的精选词汇表的匹配与与文档和技术参考站点相关的 URL 模式相结合，并对包含类似代码结构的文档给予额外权重。此阶段旨在保留广泛相关的技术内容，如 API 参考、SDK 或库文档、CLI 风格的帮助页面、平台文档、故障排除页面和开发人员问答，同时删除大多数通用的网页噪声。

阶段 2：fastText 分类。 第二阶段是一个轻量级的 fastText (7) 分类器，由 LLM 标记的种子数据训练而成。为了构建种子集，我们从 100 万网页文档和 300 万 PDF 文档中采样。然后我们使用 Qwen2.5-7B-Instruct 来标注种子集。我们的标注提示定义了正例（包括文档、教程、配置、调试跟踪和以代码为中心的技术讨论）和负例（对于工具使用目的而言是非技术性或低价值的材料）。然后将这些标记的示例转换为 fastText 的正负训练集。我们对 PDF 数据应用更严格的分类阈值，因为 PDF 提取比网页文本噪声更大、更异构。

阶段 3：质量过滤。 第三阶段应用文档级质量控制。对于网页和 PDF 数据，我们根据语言置信度、长度、字数、符号密度和估计的代码比率进行过滤。目标是删除低质量的提取工件、极短或嘈杂的文档，以及以无法解释的符号或原始代码转储为主的文档。对于 PDF 数据，我们还应用 OCR 质量过滤器以解决提取噪声。

阶段 4：去重。 最后，我们使用 MinHash LSH 来减少跨来源和分片的重复内容。

A.3 事后污染分析

上述黑名单防止基准存储库进入代码切片，但它不能限制可能通过网页、PDF 或模型合成监督到达的泄露。因此，我们使用 DeCon (16) 额外审计完成的混合数据集，使用其默认配置并降低 token 长度阈值，以便也覆盖短的基准项。我们针对本文使用的所有三个评估基准（BFCLv3、$\tau^{2}$-Bench 和 MCP-Universe）扫描网页和 PDF 切片以及教师合成的数据。DeCon 总共标记了不到 20 个候选，全部来自网页切片且全部针对 BFCLv3，没有针对 $\tau^{2}$-Bench 或 MCP-Universe 的。手动检查确认每个标记项都是误报：通用的函数调用和 API 文档文本与基准项共享表面 n-gram，但不包含基准实例和参考答案。因此，我们没有发现实际基准泄露到 MidTool-Mix 中的证据。由于 DeCon 通过表面 n-gram 匹配进行操作，此分析限制了逐字重叠，而不是语义或模式级别的相似性，这对于与 MCP 相关的工具定义尤为相关。我们将对此类重叠的更深层语义审计留给未来的工作。

C.1 SFT 收敛分析

我们进一步使用与先前关于智能体持续预训练工作 (24) 相同的比较损失视角来分析 SFT 训练过程。在这里，我们询问 MidTool-Mix 是否比原始基础模型或通用持续预训练基线为下游智能体后训练产生更好的初始化。我们在相同的 SFT 设置和下游语料库下比较三个 4B 初始化：Qwen3-4B-Base、在 Dolmino 上持续的 Qwen3-4B-Base 和在 MidTool-Mix 上持续的 Qwen3-4B-Base。图 4 报告了 SFT 步骤的训练损失轨迹，包括原始的每步损失和为了可读性而绘制的平滑趋势曲线。由于下游数据、优化器设置和训练方案保持固定，收敛性的差异主要反映了先前中期训练阶段引起的初始化质量。

图 4： 三个 Qwen3-4B 初始化在相同下游工具使用语料库上的 SFT 损失轨迹。与原始基础模型和 Dolmino 中期训练基线相比，MidTool-Mix 从更低的损失开始，收敛更快，并在整个训练过程中保持最佳损失。

中期训练提高了后训练优化效率。 图 4 显示了 SFT 训练损失。在三个初始化中，MidTool-Mix 以最低的损失进入 SFT，在早期阶段下降最快，并在几乎整个训练过程中保持最佳损失。这种模式很重要，因为所有三个模型都在相同的下游语料库上使用相同的优化器和调度进行微调，因此差距最好由初始化的质量来解释，而不是后训练方案本身的差异。然而，我们注意到 SFT 损失衡量的是下游语料库上的下一个 token 预测，其本身并不是工具使用能力的衡量标准：达到相似损失的初始化在模式基础、工具选择和多轮执行方面仍然可能存在很大差异 (11; 6)。因此，我们将这些曲线解读为关于优化行为的证据，并依赖正文基准测试结果来支持能力声明。

与 Dolmino 的比较特别具有启发性。通用的中期训练确实比原始基础模型有所改善，但它的收敛速度仍然比 MidTool-Mix 慢，且损失更差。这表明该益处不仅仅是额外训练 token 或额外计算的结果。相反，MidTool-Mix 的智能体和以工具为中心的组成似乎为下游工具使用监督提供了更好的归纳偏置，使后续的 SFT 和 RL 更容易优化。这一观察与正文结果一致：在后训练后表现最好的模型也是那些从更有利的优化景观开始 SFT 的模型。

C.2 RL 奖励分析

我们接下来检查 RL 训练动态，以了解 MidTool-Mix 带来的收益是否在强化学习期间也持续存在。在这里，核心问题不仅是训练环境中达到的最终奖励，还有模型在 RL 期间适应的效率，以及这种环境内的改进是否转化为更广泛的下游泛化。

图 5： 4B（左）和 8B（右）模型训练期间的平均 RL 奖励。在两种规模中，MidTool-Mix 从更强的点开始，并在 RL 的早期阶段改进更快，而未进行中期训练的基线后来在相同的训练环境中逐渐赶上。

中期训练的模型在 RL 中适应更快，而其主要优势出现在环境外泛化中。 图 5 显示了 4B 和 8B 之间一致的模式。MidTool-Mix 模型从明显更高的奖励开始 RL，并在早期阶段改进得快得多，而相应的基础模型从明显更低的奖励开始，需要更多的步骤才能达到相似的水平。这表明中期训练不仅为 SFT 提供了更有利的初始化，也为后续的策略优化提供了更有利的初始化，使模型在 RL 开始后能够更有效地适应。同时，奖励曲线也显示了环境内训练奖励作为最终智能体质量代理的一个重要局限性。在后来的 RL 步骤中，两条曲线在两种模型规模下都更加接近，这表明原始基础模型最终可以学习到该特定 RL 环境所需的大部分策略。但这种缩小的差距并不意味着两个训练流水线是等效的。在主要结果中，中期训练的模型在 RL 后仍在 BFCL、$\tau^{2}$-Bench 和 MCP-Universe 上取得了明显更强的性能，即使训练内奖励变得相似。总而言之，这些结果表明 RL 奖励主要反映了对训练环境的适应，因此其收敛并不意味着两个流水线在下游表现等效。我们对此的证据是持续存在的 RL 后基准差距，而不是奖励曲线本身。换句话说，中期训练的主要价值不仅仅是 RL 期间更快的奖励获取，而是 RL 后更强的泛化能力。

附录 D 局限性与未来工作

MidTool 是将通用工具使用视为为中期训练问题的第一步，在我们看来，它留下的未解问题是这个方向中最有趣的部分。

中期训练和后训练的协同设计。 我们的实验有意固定下游方案，以便可以隔离中期训练语料库的效果，而且我们的计算预算不允许我们也对后训练轴进行扫描研究。因此，两个阶段之间的关系在很大程度上尚未探索，我们认为这是最有希望的下一步：SFT 语料库的组成如何与中期训练混合数据集相互作用，更强或更大的后训练监督是替代还是与工具使用先验复合，以及 RL 环境的选择和奖励设计如何改变先验的价值。每一个都值得自己的消融，我们将它们视为中期训练研究的核心问题，而不是本研究的细节。

在匹配预算下映射混合设计空间。 表 6 中的消融在固定方案下改变混合数据集，这已经将原始来源信号与合成监督分离开来。更完整的说明将在各变体之间保持 token 预算恒定，并添加控制，例如没有其起源上下文的合成问答对、等量计算的通用技术文档混合数据集，以及扩展到完整预算的仅原生轨迹混合数据集。最后一个本身就是一项巨大的工程，因为它需要在数百亿 token 的规模上进行可执行工具环境、交互生成和验证，我们将其本身视为一个有趣的系统和数据挑战。

减少对强教师的依赖。 MidTool 的两个合成分支目前都依赖教师模型。随着开放权重的智能体模型不断改进，相同的流水线可以用逐渐变小或自我生成的教师来实例化，而模型何时能够有用地合成自己的工具使用中期训练数据，将成为衡量智能体成熟度的一个有意义的指标。我们期望这个问题在更大的学生规模下最有意义，因为自我生成足够多样和可靠，能够维持流水线的验证要求。

超越通用工具使用。 最后，我们的结果定位的是一个边界而不是上限：通用工具使用先验在未见过的模式和 MCP 领域中广泛迁移，而以搜索为主和其他探索性行为似乎需要自己的监督。将中期训练视图扩展到深度搜索、软件工程和垂直智能体工作流，并理解哪些先验在它们之间共享，是我们希望这项工作有助于开启的更广泛议程。
