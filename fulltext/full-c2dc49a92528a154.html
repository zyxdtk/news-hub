Anthropic推出“做梦”系统，让AI智能体从自身错误中学习

Michael Nuñez
2026年5月7日，太平洋时间下午5:09

图片来源：VentureBeat 使用 Midjourney 制作

Anthropic 于周二在旧金山举行的第二届年度 Code with Claude 开发者大会 上，为其 Claude Managed Agents 平台发布了一系列更新，推出了一项名为 “做梦” 的新功能，该功能允许 AI 智能体从过去的会话中学习并随时间不断改进——这是迈向企业所要求的那种自我纠正、自我改进的 AI 系统的一步，企业需要这种系统才能放心地将生产工作负载交给智能体。
该公司还将之前处于实验阶段的两个功能——结果 和 多智能体编排——从研究预览版移至公开测试版，使其面向在 Claude 平台上进行开发的开发者广泛可用。这三项功能共同解决了 Anthropic 所说的大规模运行 AI 智能体时面临的最棘手问题：保持准确性、帮助它们学习，以及防止它们在复杂的多步骤工作中成为瓶颈。
早期采用者已经报告了显著的成果。法律 AI 公司 Harvey 在实施“做梦”功能后，任务完成率提高了约 6 倍。医疗文件审查公司 Wisedocs 使用“结果”功能将文件审查时间缩短了 50%。而 Netflix 现在正使用多智能体编排同时处理来自数百次构建的日志。
这些发布正值 Anthropic 发展势头异常强劲之际。首席执行官 Dario Amodei 在大会的炉边谈话中透露，公司的增长甚至超出了其激进的内部预期。
在 2026 年第一季度，Anthropic 实现了 Amodei 所描述的 80 倍的年收入和使用量增长——远超公司计划的 10 倍的年增长。Claude 平台上的 API 量同比增加了近 70 倍，使用 Claude Code 的开发者平均每周花费 20 小时使用该工具。
“我们试图为一个每年增长 10 倍的世界做好规划，”Amodei 说。“然而我们看到了 80 倍的增长。这就是我们在算力方面遇到困难的原因。”

Anthropic 在 2026 年第一季度的实际增长远超其内部计划。该公司曾预计 10 倍的年增长；而年化收入和使用量却增长了 80 倍。（图片来源：Michael Nunez / VentureBeat）

Anthropic 的“做梦”功能如何教导 AI 智能体从自身历史中学习

“做梦” 是这三项功能中最具创新性的，也是 Anthropic 最渴望与传统记忆系统区分开来的功能。虽然该公司今年早些时候推出了智能体记忆——允许 Claude 在单个会话内和跨会话保留偏好和上下文——但“做梦”在更高的抽象层面上运作。它是一个预定的进程，负责审查智能体过去的会话和记忆存储，提取其中的模式，并策划这些记忆，以便智能体随着时间的推移不断改进。它揭示了任何单个智能体会话都无法单独看到的洞察：反复出现的错误、多个智能体独立趋同的工作流，以及智能体团队共享的偏好。
Alex Albert 是 Anthropic 负责研究产品管理的负责人，他在大会的采访中解释了这一概念。他将“做梦”比作组织内的人员在完成一项任务后创建技能的过程。“他们可能与 Claude 进行了一个工作流，在该工作流结束时，经过反复迭代和曲折，他们想记录下从 A 到 B 的路径，”Albert 说。“‘做梦’也发生了非常相似的事情——不是你根据与 Claude 合作的经验手动创建技能，而是模型在做这件事，因此它在未来的会话中拥有相同的上下文。”
关键是，“做梦”不会修改底层的模型权重。“我们不是通过做梦来改变模型本身——它没有对权重进行更新或类似操作，”Albert 说。相反，智能体将学习到的内容写成纯文本笔记和结构化的“行动手册”，供未来的会话参考，这使得整个过程对人类来说是可观察和可审计的。当被问及智能体整合自身知识的信任影响时，Albert 承认“你需要给予一定程度的信任”，但他指出所有的记忆都是可检查的，而且更聪明的模型在管理这一过程方面正变得越来越出色。“它们正在学习为未来的自己写下更好的笔记，”他说。

现场演示显示 AI 智能体在无人指导下隔夜改进

在主题演讲中，Anthropic 团队在舞台上使用一家名为“Lumara”的虚构航空航天初创公司现场演示了这三项功能，该公司需要自主将无人机降落在月球上进行资源开采。团队配置了一个包含三个专家的多智能体系统——一个负责整体任务成功的指挥智能体，一个识别高质量着陆点的探测智能体，以及一个处理安全无人机飞行和降落的导航智能体——并定义了成功标准，要求软着陆、地面清晰，以及有足够的燃料储备返回地球。
对六个假设着陆点的初步模拟产生了强劲但不完美的结果。为了改进，演示者直接从 Claude 开发者控制台 触发了一个“做梦”会话。一夜之间，“做梦”智能体审查了所有过去的模拟会话，并编写了一份详细的下降行动手册——这是一套从多次任务运行的模式中得出的综合启发式规则。当团队第二天早上在记忆中加载了源自“做梦”的行动手册运行新的模拟时，之前表现不佳的站点有了显著改善。
“我们所要做的就是让 Caitlin 按下一个按钮，”Claude 平台产品负责人 Angela Jiang 在谈到台上的同事时说。“全靠‘做梦’。”
该演示说明了这三项功能在实践中是如何组合的。多智能体编排 将复杂任务分配给具有独立上下文窗口的专家。结果 提供了一个评估标准，由一个单独的评分智能体根据该标准评估每次运行。而“做梦” 从这些运行中提取教训以改善未来的表现——形成了 Anthropic 所描述的持续改进循环，在迭代之间无需人工干预。

为什么 Anthropic 构建了一个单独的“评分”智能体来检查 Claude 的工作

现已进入公开测试阶段的“结果”功能，为开发者提供了一种使用评分标准来定义成功样貌的方法——结构框架、展示标准、品牌声音或任何其他标准集——然后让智能体自主地向该标准迭代。使“结果”在架构上独具特色的是其关注点的分离。当一个智能体完成其工作时，一个单独的评分智能体会根据开发者定义的评分标准，在其独立的上下文窗口中评估输出。因为评分器在全新的上下文中运作，它不会受到工作智能体的推理或会话中累积偏见的影响。
当评分器发现输出与评分标准之间的差距时，它会具体指出需要改变的地方，然后工作智能体会再进行一次尝试。这个循环会一直持续，直到满足评分标准——而无需人工审查每次尝试。
Albert 将 Anthropic 更广泛的验证策略描述为采用“更多的测试时计算，更多的模型花更长时间思考问题，以检查另一个模型的工作”。他承认让模型检查自己的工作会引发合理的问题，但他表示，用一个全新的上下文窗口审查已完成的工作，始终优于让同一个长运行线程来识别自身的错误。“如果你把输出交给一个全新的 Claude 并问‘你看到了什么错误？’，你会获得更高的成功率，”他说。“在非常长的会话中，注意力仍然会出现某种程度的下降”——他说 Anthropic 正在积极努力在未来的模型中修复这一限制。
这种方法反映了 GitHub 已经在使用的策略。Mario Rodriguez 是 GitHub 的首席产品官，他在大会的另一场演讲中描述了 Copilot 如何使用与 Claude 模型类似的顾问模式——将一个更小、更便宜的模型作为执行者，与一个更大的模型作为导师配对。当较小的模型遇到超出其能力的问题时，它会调用较大的模型寻求指导，然后继续自行执行。Rodriguez 说，这种方法以显著更低的成本提供了接近 Opus 级别的智能，并且 GitHub 在编码工作流的三个特定点插入了批评模型：在起草计划之后，在复杂实现之后，以及在编写测试之后、运行测试之前。

并行 AI 智能体现在可以处理对单个模型线程来说过于复杂的任务

多智能体编排 是进入公开测试阶段的第三个功能，它允许一个主导智能体将大型任务分解为子任务，并将每个子任务委托给一个专家智能体——每个智能体都有自己的模型、系统提示、工具和独立的上下文窗口。过程中的每一步都可以在 Claude 控制台中追踪，显示哪个智能体做了什么、以什么顺序做以及为什么做。
该设计为每个子智能体提供了一个隔离的上下文，Anthropic 表示，这比让单个智能体试图在一个线程中容纳所有复杂性能产生更好的结果。“每个子智能体都有自己独立的线程和上下文窗口，”主题演讲者解释道。“这是非常刻意的——我们发现通过拆分工作然后合并结果，我们能得到更好的结果。”
Albert 提供了自己的经验法则，说明何时多智能体架构有意义，何时坚持使用单线程。“并行智能体更适合调查工作，”他说——即存在大量最终将被丢弃的上下文的情况。“如果你试图回答一个特定的问题，你不需要那些没有找到答案的区域的搜索结果。你只需要答案。”他描述了为特定的检索任务启动一次性子智能体，并仅将结果带回主线程。他说，模型本身将越来越多地决定何时进行并行化。“在未来，你不会真正关心它是一个智能体还是多智能体或者正在发生什么。你只有一个正在与之交谈的 Claude，它会自动部署正确的架构。”

Anthropic 更大的赌注：缩小 AI 能力与现实世界采用之间的差距

这三项功能作为更广泛平台推动的一部分推出，Anthropic 在整个大会期间将其定位为缩小“AI 能做什么和它实际在为人们做什么之间的差距”。Ami Vora 是 Anthropic 的首席产品官，她在开幕主题演讲中设定了这一主题，她指出，虽然模型能力正在呈指数曲线增长，但大多数组织仍在线性路径上采用 AI。
Dianne Penn 是 Anthropic 研究团队的产品负责人，她将公司衡量进步的标准描述为“任务范围”——即 AI 智能体在提高交付物质量的同时可以自主工作多长时间。“去年这个时候，模型可以工作几分钟，”她说。“现在，我们大多数人的智能体都在连续运行数小时。明天，我们将拥有主动的、始终在线的智能体，它们知道该做什么而不会迷失方向。”
大会还包括几项旨在帮助开发者跟上步伐的基础设施公告。Anthropic 表示，它将 Pro、Max、Team 和 Enterprise 计划的五小时速率限制翻倍，并大幅提高了 API 速率限制。该公司宣布与 SpaceX 合作，利用其 Colossus 数据中心的全部容量来扩展计算可用性——这是对 Amodei 所描述的需求紧缩的直接回应。
这三项功能都内置于 Claude Managed Agents 中，该平台于 4 月 8 日以公开测试版推出，是一个捆绑了包括记忆、工具集成和操作处理等最佳实践的自带主见的框架。Anthropic 表示，使用 Managed Agents 的团队比那些从头开始构建自己的智能体基础设施的团队交付速度快了 10 倍。Albert 用操作系统的比喻来描述该平台：“有了托管智能体，你不需要考虑如何设置周围系统的所有技术细节，”他说。“你正在为 Mac 构建应用程序——你不想去重新实现 macOS 的每一个细节。”

“做梦”、“结果”和多智能体编排对企业 AI 的未来意味着什么

竞争影响是深远的。随着来自 OpenAI、Google 等公司的 AI 智能体平台争夺开发者的采用，Anthropic 押注于生产可靠性——而不仅仅是原始模型智能——将决定哪个平台赢得企业预算。特别是“做梦”功能开辟了新领域：虽然其他平台提供记忆和工具使用，但智能体系统性地审查自身历史以提取可重用知识的想法，进一步迈向了企业在委托高风险工作之前所需的持续改进系统。
大会展示了已经在该规模上运营的公司。Mercado Libre 是拉丁美洲最大的电子商务平台，拥有 23,000 名运行 Claude Code 的工程师，在人工监督下审查了超过 500,000 个拉取请求，并目标在今年第三季度实现 90% 的自主编码。Shopify 不仅在工程领域，还在设计、产品和数据科学团队中部署了 Claude Code。
但 Dario Amodei 阐述了所有这些发展方向的最宏大愿景。他描述了从单个智能体到多个智能体再到整个组织智能的演进——从“房间里的一个聪明人团队”到他所谓的“数据中心里的天才之国”。他重申了大约一年前做出的预测：2026 年将出现第一家由单人运营的十亿美元公司。“还没有完全发生，”他说。“但我们还有七个月的时间。”
“做梦” 现已在研究预览版中提供。“结果” 和 多智能体编排 处于公开测试阶段，面向 Claude 平台上的所有开发者提供。七个月的时间是否足以让单人创始人建立一家十亿美元的业务仍然是一个悬而未决的问题——但在周二之后，他们有了更多的工具来尝试。
