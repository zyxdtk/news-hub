过去每项发现都需要单独、持续调查的安全研究，如今越来越可以作为系统化流程来运行。本文探讨了我们在这一领域的一项工作。

漏洞发现正变得更容易规模化，但优先级排序和验证仍是运营瓶颈。我们在受控研究环境中构建了一个用于在 Linux 内核中寻找安全缺陷的原型。该原型识别并分析了 2,308 项 Linux 内核候选发现，动态复现了 1,724 个漏洞，并产出了 948 个本地权限提升（LPE）利用程序，可使无特权的本地用户获得 root 权限。

我们利用这些证据对漏洞报告进行优先级排序，并开发了候选补丁供维护者审查。根据 Linux 内核社区的指导，我们从严重漏洞入手，并正在与 Patch the Planet 合作伙伴一起推进后续报告和补丁。

今年 6 月，作为 Patch the Planet 计划的一部分，我们分享了 GPT-5.5 Cyber 识别 Linux 内核漏洞并开发 24 个本地权限提升利用程序以验证和报告这些漏洞的成果。我们将这项工作扩展为一条流水线，由即将推出的网络安全模型驱动，涵盖漏洞发现、动态验证、可利用性评估和补丁生成。流水线运行结束后，人类研究员审查了输出结果，并将发现的漏洞连同补丁一并报告。

摘要

方法论

从宏观层面看，我们的流水线工作流程如下：首先识别 Linux 内核中与安全相关的部分，对这些审计目标进行静态扫描以获得候选发现，在隔离环境中动态复现这些发现，创建概念验证（PoC）利用程序以证明可利用性，生成补丁，最后由人类安全研究员审查结果。

流水线的输出包括根因分析、最小化崩溃概念验证、候选补丁以及完整利用程序，以协助人类研究员评估漏洞严重程度并将修复补丁提交至上游。

发现

在 2026 年 10 月中旬的一次运行中，我们使用即将推出的网络安全模型的流水线动态复现了 1,724 个漏洞，并针对一个常用 Linux 发行版生成了 291 个信息泄露漏洞的 PoC 和 948 个可用的本地权限提升（LPE）利用程序。整次运行耗资 1,213,430 美元的 API 额度，即每个 LPE 利用程序平均 1,279 美元。

目标虚拟机运行的是原装桌面操作系统，而非被削弱的目标，采用的威胁模型与网络安全竞赛（例如 Pwn2Own（在新窗口中打开）、TyphoonPWN（在新窗口中打开））相同。历史上，Pwn2Own 和 TyphoonPWN 为 Linux 内核 LPE 利用程序分别提供 20,000 美元和 70,000 美元的漏洞赏金。将这些历史赏金金额套用到 948 个利用程序上，可得出 1,890 万至 6,630 万美元的假设估值，约为我们流水线成本的 16 至 55 倍。

在经过适配的 kernelCTF（在新窗口中打开）环境（一个缩小了攻击面的 Linux 内核版本）上，我们的流水线获得了 25 个信息泄露 PoC 和 21 个 LPE 利用程序。作为对比，截至本文撰写时，kernelCTF 在 2026 年已接受 26 个经确认的 0-day LPE 利用程序。

该次行动耗资约 32,936 美元的 API 额度。如果这 21 个漏洞被该计划接受，将带来约 150 万美元的赏金奖励，约为扫描成本的 45 倍。

据我们所知，该流水线中的智能体发现并使用了至少 10 种新颖的 Linux 利用技术。

思考

Linux 维护者和安全社区正在努力快速发现和修复漏洞。在扫描运行的 10 天内，我们观察到超过 100 个 Linux LPE 已被修补或已有其他贡献者提交了暂存补丁，另有约 300 个正在被公开讨论。

鉴于前沿模型的漏洞发现速度，我们认为自动化补丁生成对于按所需节奏保障软件安全、限制漏洞利用窗口期至关重要。在人类专家指导下的迭代中，我们相信 AI 生成的补丁可以在功能上正确、符合现有编码风格，并能抵御攻击变体。这是进一步研究的重要领域。

更强大的模型能够在现有代码中发现新漏洞，其中往往包括存在时间更长、更难识别的漏洞。我们 10 月中旬使用较新网络安全模型的分析流水线发现的新颖 LPE 数量是 7 月份 GPT-5.6 Sol 一次运行的 5 倍以上，尽管两次扫描之间代码已经历了三个月的加固。

大型复杂软件项目可能需要多轮漏洞扫描与修复才能将潜在漏洞"清理见底"。理想情况下，这一过程应随每一代后续前沿模型的推出而重复。这适用于专有软件和开源软件。

在近期和中期内，对于资源充足的威胁行为者而言，在一个未及时更新最新可用补丁的操作系统上拥有低权限账户，应被视为在功能上等同于拥有 root 权限。使用沙箱以及 Firecracker 和 gVisor 等隔离方案的纵深防御，对于限制漏洞被利用后的波及范围非常重要。

我们相信，在未来几年内，如果一个软件项目中存在漏洞，前沿模型很可能能够发现它们，而一旦漏洞被披露，能力较弱的模型甚至也能开发出利用程序。在一个不存在未知漏洞的世界里，构建和维护高保障软件将至关重要，尤其是操作系统、浏览器、图像解析库、TCP/IP 协议栈等核心软件。除了发现和修复现有漏洞之外，投资于训练模型默认编写安全代码、通过移除不必要的功能来最小化攻击面以及形式化验证，都是有效规模化软件安全的有前景的未来研究方向。

为什么选择 Linux 内核

Linux 内核支撑着 Android 设备、云基础设施、超级计算机以及数十亿人使用的其他系统。内核拥有超过 4,000 万行代码，通过系统调用、网络、文件系统和设备驱动程序暴露出广泛的攻击面。我们选择 Linux 来研究前沿模型在这种规模和重要性的代码库中发现漏洞并展示其安全影响的有效性。

初始漏洞发现阶段产生了数千项候选发现，数量太多，安全研究员无法手动审查和分类。我们的漏洞发现流水线面临的运营挑战不在于发现本身，而在于确定哪些发现可以复现、它们跨越了什么安全边界，以及哪些发现最值得维护者优先关注。

成本分析

OpenAI 网络安全团队的使命是帮助保障世界所依赖的软件的安全。

我们报告每个阶段的 API 成本，以帮助研究者评估复现和扩展这项工作所需的资源。这些成本反映了本次评估中使用的模型、目标配置和工作流程。我们更宏大的目标是帮助防御者发现和修复漏洞，减少攻击者可乘之机，并提高他们利用软件的成本。

最后请注意，本研究中我们关注的是方法论和模型能力测量，而非成本。我们预计，充分的测试框架工程可以显著降低每个阶段的成本；因此，我们报告的成本更像是一个上限。

漏洞研究流水线

我们的漏洞研究原型是一条五阶段流水线，其核心使用一个即将推出的网络安全模型：

  • 漏洞发现：智能体识别代码库中与安全相关的部分，并对其进行扫描以获得候选发现。
  • 动态验证：智能体尝试在隔离环境中复现每个候选漏洞，并保留运行时证据。此步骤输出已复现并验证的漏洞。
  • 可利用性评估：智能体测试已验证的漏洞是否可能导致信息泄露或本地权限提升。
  • 补丁生成：智能体生成针对每个已识别漏洞的补丁。
  • 人工审查：安全研究员在向维护者报告之前审查利用程序、补丁和建议的严重程度。

在流水线末端，系统将根因分析、最小化崩溃概念验证、候选补丁和完整利用程序打包在一起，以协助人类研究员评估漏洞严重程度并将修复补丁提交至上游。

漏洞发现

并非 Linux 内核中的每一行代码都与安全相关。我们的流水线使用一组 Scout 智能体来识别高价值审计目标，然后将其传递给 Analyst 智能体进行漏洞扫描。

Scout 智能体

Scout 智能体通读每个文件夹和文件，根据可达性（可被低权限用户触达）和安全相关性确定审计目标。

该阶段识别出 5,034 个审计目标，约 280 万行代码，约占整个 Linux 内核代码库的 7%，与全代码库分析相比显著降低了安全审计成本。此步骤耗资 3,426 美元的 API 额度。

Analyst 智能体

接下来，分析智能体对每个审计目标进行分析，并使用与 Codex Security 插件（在新窗口中打开）类似的工作流产生候选发现。宏观而言，分析智能体会阅读所分配审计目标的代码以理解其工作原理，识别其威胁模型，并从中寻找漏洞。

在 12 小时内，分析智能体在去重后产生了 2,308 项候选发现。该阶段耗资 316,549 美元的 API 额度。

漏洞验证

候选发现并不等同于已验证的漏洞。在这种规模下，我们的研究团队手动调查每一份报告是不切实际的。

因此，我们专注于验证符合以下条件的发现：a) 可被低权限用户触达；b) 不需要特殊能力；c) 产生可度量的内存损坏证据。

对于每个候选漏洞，一个分诊智能体会生成概念验证程序，并在运行带有内核地址消毒器（KASAN）的 Linux 内核的隔离虚拟机中执行它。智能体同时观察程序输出和系统控制台，然后迭代改进概念验证程序，直到复现所报告的行为或穷尽所有可能的触发方式。

在 30 小时内，我们的系统复现了 1,724 个漏洞，约占 2,308 项候选发现的 74.7%。仅靠静态代码审查容易出现误报，因此分析智能体的准确率以及分诊智能体为近四分之三的候选发现自主创建可用概念验证程序的有效性给我们留下了深刻印象。

大多数剩余发现要么需要提升的权限，要么因难以触发的竞态条件、特定触发条件（例如需要在特定代码行发生分配失败）或耗时的验证（例如引用计数回绕）而未能在时间预算内复现。只有 3.1% 反映了模型的分析错误，即所报告的漏洞假设了一个不可能存在的条件。

验证阶段总计耗资 73,330 美元的 API 额度。我们观察到，在我们的验证流水线中，需要生成概念验证程序来确认候选漏洞是否为真实漏洞，这一过程比仅基于静态分析给出建议更昂贵，而且验证真阳性与假阳性的成本相近。因此，在流水线早期剔除误报可以显著提升成本效率。

可利用性评估

验证确立了漏洞的真实性，但并未确定其处理的紧迫程度。例如，一个可能导致本地权限提升的漏洞，比一个只能造成本地拒绝服务的漏洞更值得优先处理。面对 1,724 个已验证的漏洞，下一项任务是识别具有最大潜在安全影响的发现。

一个初始筛选智能体静态审查了每份报告、崩溃日志和相关源代码。它被刻意设计得较为宽松，以避免丢弃潜在严重的发现，同时过滤掉没有合理利用路径的情况。这将结果缩小到 313 个信息泄露候选和 1,238 个本地权限提升候选。

随后，漏洞利用开发智能体在隔离虚拟机中测试这些候选漏洞，这些虚拟机配置了标准 Linux 发行版默认启用的防护措施，包括管理模式执行防护（SMEP）、管理模式访问防护（SMAP）、内核地址空间布局随机化（KASLR）和 HARDENED_USERCOPY。这有助于防止产生依赖于关闭防护措施的不切实际的评估。

智能体产出了 291 个信息泄露概念验证程序和 1,169 个可用的本地权限提升利用程序，后者可使无特权本地用户获得 root 权限。

我们进行了变体分析，并为这些利用程序背后的漏洞开发了 948 个不同的补丁。我们使用该数字来确定唯一 LPE 的总数。成功利用程序的平均开发成本为 359 美元额度。这使得防御者测试已发现漏洞的可利用性相对廉价。

初始漏洞筛选智能体耗资 44,194 美元的 API 额度。利用阶段总计耗资 775,929 美元的 API 额度，其中处理信息泄露候选耗资 84,929 美元，处理本地权限提升候选耗资 691,000 美元。

平均而言，处理一个本地权限提升候选（558 美元）的成本约为处理一个信息泄露候选（271 美元）的两倍。这是因为信息泄露 PoC 从验证阶段延续而来，只需较少修改即可用于利用程序。另一方面，从 LPE 候选开发利用程序需要许多额外步骤，例如利用策略规划、识别可用的脆弱对象、绕过缓解措施等。我们还注意到，失败的利用尝试（69 例，平均 3,922 美元）成本远高于成功的尝试（1,169 例，平均 360 美元）。这是由少数难以利用的漏洞（例如竞态条件）造成的。定义合理的放弃条件（例如一小时无进展即停止尝试），本可显著降低 ExploitDev 的成本。

补丁生成

对于每个已验证的漏洞，系统还会生成补丁。我们向模型提供相关源代码，并提示补丁编写的最佳实践，例如对补丁执行静态检查、遵循邻近代码所使用的软件开发实践，以及执行变体分析以确保补丁完整。

根据 Linux 内核社区的建议，我们已经发出了数百份严重漏洞的报告和补丁，并正在与 Patch the Planet 合作伙伴合作，逐步发出其余漏洞的补丁。

这项工作是我们支持开源项目的更广泛的 Daybreak 承诺的一部分。

发现

在本节中，我们分享从这项研究中获得的经验、思考和补充分析。

维护者正在快速修补漏洞

在这项研究期间，我们观察到 Linux 维护者正在快速修复漏洞以保护用户。扫描于 2026 年 10 月中旬在最新版 Linux 内核上进行。当自主扫描和手动分析在 10 天后完成时，已有 61 个 LPE 在上游被修补，43 个已有暂存补丁，299 个正在被公开报告和讨论。

我们非常感谢紧急修补已识别问题的 Linux 维护者，以及贡献其发现的安全社区。这种集体响应正是保障世界软件安全所需要的。漏洞披露和修补的快速节奏也凸显了用户和企业保持软件及时更新的重要性。

要点：自动化分诊应考虑快速修补周期。根据最新代码（包括原始扫描之后合入的新代码）重新验证发现，有助于避免重复或过时的报告。这使注意力集中于未解决的漏洞，并为维护者提供可据以行动的证据，而不会增加不必要的审查负担。

更强的模型能发现更多漏洞

在我们开发流水线期间，2026 年 7 月下旬，GPT-5.6 Sol 发现并利用了 166 个唯一 LPE 漏洞，端到端耗资 513,690 美元的 API 额度。

在 2026 年 10 月中旬的第二次扫描中，较新的网络安全模型发现并利用了 948 个唯一 LPE 漏洞，端到端耗资 1,213,430 美元的 API 额度。两次行动中，我们扫描的都是当时的最新 Linux 内核 master 分支。

要点：随着模型能力的提升，应重新扫描此前审计过的代码。更强大的模型可能会发现早期模型遗漏的漏洞，即使使用相同的研究框架也是如此。

新颖的利用技术

我们抽样了智能体开发的 166 个利用程序，并分析了其中使用的利用技术。据我们所知，智能体在抽样的利用程序中使用了 10 种新的利用技术。我们与第三方内核利用专家分享了这些利用技术，这些技术对他们而言同样是新的。

在这 10 种技术中，两种是新的持久弹性对象，模型用它们在目标内核缓存中喷射对象；两种是新的页整理技术，用于提高利用程序的可靠性；五种是新的纯数据技术，用于直接或通过任意写入获得权限提升；另一种技术涉及任意类型混淆。出于安全原因，我们在本文中省略这些新利用技术的完整技术细节。

要点：前沿模型不仅仅是模式匹配已知的脆弱代码模式或仅使用已知的利用技术；它们展现出了创造力和新颖的方法。

防御者可以从利用成本中学到什么

我们团队使命的重要组成部分是衡量发现和利用漏洞的成本，并利用这些证据指导防御投资。我们的目标是帮助防御者在攻击者利用漏洞之前修复它们，并使攻击者利用软件的成本高到望而却步。衡量利用成本有助于我们评估这一挑战如何随模型能力的提升而变化。在本节中，我们将流水线运行的成本与已识别漏洞的漏洞赏金计划奖励进行比较。

我们实验中的目标虚拟机运行的是原装桌面操作系统，而非被削弱的目标，采用的威胁模型与网络安全竞赛（例如 Pwn2Own（在新窗口中打开）、TyphoonPWN（在新窗口中打开））所使用的相同。历史上，Pwn2Own 和 TyphoonPWN 为 Linux 内核本地权限提升利用程序分别提供 20,000 美元和 70,000 美元的漏洞赏金。将这些历史赏金金额套用到 948 个利用程序上，可得出 1,890 万至 6,630 万美元的假设估值，约为我们流水线成本的 16 至 55 倍。

我们还针对 Google 的 kernelCTF（在新窗口中打开）漏洞奖励计划测试了我们的流水线，该计划以缩小了攻击面的加固 Linux 内核为目标。

我们在 kernelCTF 环境下对最新版本的 Linux 内核运行了该流水线（与 kernelCTF 中的 SLAB_VIRTUAL 缓解措施不兼容，因此我们从配置中移除了该选项），获得了 25 个信息泄露概念验证程序和 21 个本地权限提升利用程序。作为对比，截至本文撰写时，kernelCTF 在 2026 年已接受 26 个经确认的 0-day LPE 利用程序。整次行动共持续 112 小时，耗资约 32,936 美元的 API 额度，其中漏洞发现占 API 成本的 83.7%。如果这 21 个漏洞被该计划接受，将带来约 150 万美元的赏金奖励，约为成本的 45 倍。

要点：根据公开的支付金额，使用当前具备网络安全能力的模型，我们的漏洞研究流水线在本研究开展时是净盈利的。防御者应主动分析其软件，使攻击者的利用成本高到望而却步。

用错了 0-day 漏洞

在可利用性评估期间，ExploitDev 智能体会收到一份漏洞报告，并被要求创建一个完整可用的利用程序。如果成功获得了 root shell，我们的流水线就会将该漏洞标记为已利用。在一次早期运行中，利用阶段报告了 200 个成功的本地权限提升利用程序。然而，经人工审查后，我们发现其中 20 个是通过与所分配漏洞不同的另一个 0-day 漏洞获得 root 权限的。这表明即使是智能体的成功利用也需要适当的验证。

随后，我们收紧了任务约束，并增加了一项独立检查，以确认每个最终利用程序使用的都是其被分配的漏洞。

要点：对于自主安全研究，除了验证结果本身之外，还要验证达成结果的路径；隔离、监控和独立检查是必要的控制手段。

更强大的模型可能只需更轻量的编排

在这项研究的早期，我们探索了一个设计决策：是否围绕智能体构建重型编排来提升其网络安全能力。我们的结果表明，更强的模型需要更轻量的编排和引导，而边际改进不足以抵偿维护成本。因此，我们决定移除重型编排。

该实验比较了 GPT-5.5 Cyber 和 GPT-5.6 Cyber。在我们的观察中，GPT-5.5 Cyber 不能一致地识别何时以及如何应用现有的 Linux 内核利用技术。随后，我们以对模型友好的格式整理了 103 种技术，将其提供给智能体环境，并提示智能体使用它们。在 63 个利用候选中，这将成功率从 76.2% 提高到了 88.9%。

当我们对 GPT-5.6 Cyber 重复这一实验时，该模型能够更好地自主查找、选择和应用相关技术。我们移除了技术/技能编排，这个轻量编排的 GPT-5.6 Cyber 工作流的表现优于脚手架更重的 GPT-5.5 Cyber 工作流。为 GPT-5.6 Cyber 重新加回额外的技术层仅带来了 1.5 个百分点的边际改进。

要点：随着基础模型能力的变化，重新评估你的编排和测试框架。对某一代模型有实质性改进的脚手架，对更强的模型可能价值甚微，应就维护权衡进行评估。

迭代改进补丁生成

最初，当被直接提示生成候选补丁时，模型会创建在功能上正确、能够缓解概念验证的补丁，但偶尔会引入其他问题：代码多于必要、引入潜在的性能权衡、偏离编码规范，或未能检查相关代码中同一漏洞的变体，导致补丁不完整。

对补丁生成过程的额外指令和迭代提高了补丁质量，这表明通过适当处理，AI 生成的安全补丁有可能做到正确、精简并与现有代码规范一致。这是一个活跃的研究领域，我们相信随着未来模型的出现，这将变得更容易、更有效。在少数案例中，我们的研究原型还能够识别人类专家所写补丁中的问题，这些问题在补丁合入之前得到了修复。

要点：模型可以加速补丁流程，但补丁技能和框架可能需要迭代，以确保补丁可靠地满足功能性和非功能性需求。此外，我们建议使用模型对人类和 AI 生成的补丁进行对抗性审查，这可以识别诸如补丁可被绕过、遗漏其他攻击路径或变体等问题。

测试基础设施中的漏洞

在我们的 kernelCTF 运行中，除了 21 个 Linux 内核 0-day 利用程序之外，我们的研究原型还发现并利用了一个 QEMU TCG 漏洞。分析智能体被分配去分析系统调用入口代码，在编写程序试验权限转换时，它遇到了意外的内核崩溃。它对崩溃进行了分诊，并在无法访问 QEMU 源代码的情况下将问题追溯到 QEMU TCG，并将该漏洞纳入报告。随后，ExploitDev 智能体成功为该漏洞开发了一个本地权限提升利用程序。我们在手动分析利用程序时发现了这个 QEMU 漏洞，并确认该漏洞已在上游 QEMU 中修复，但在实验期间使用的发布版本中尚未修复。

要点：具备前沿网络安全能力的模型可以在测试基础设施中发现漏洞。我们建议在开展攻击性漏洞研究之前，对基础设施的每个部分进行测试。我们已主动测试了我们的基础设施，披露并修补了 Kata、Moby/Docker、gVisor 及其他项目中的许多漏洞。

结论

我们的目标是将不断增长的模型能力转化为保障互联网安全的人们的持久优势。这项研究表明，前沿模型日益增强的网络安全能力可用于有效地在复杂软件（如 Linux 内核）中寻找漏洞。加固 Linux 和其他开源项目等关键软件项目可以保护许多下游系统和用户。

通过 Daybreak 计划下的 Patch the Planet，我们旨在将这项研究扩展到更多关键软件项目，并与维护者和安全合作伙伴一起开发可靠的自动化补丁机制。我们希望稳步减少攻击者可乘之机，提高发现和利用漏洞的成本，直到预期收益不再值得发动攻击。

每一代模型都应帮助我们构建下一代更难攻破的软件。我们将继续努力构建一个任何人都可以安心构建其上的安全互联网。
