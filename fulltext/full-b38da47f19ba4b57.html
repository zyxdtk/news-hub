摘要
测试时扩展的兴起显著提升了大型语言模型（LLMs）的推理和代理能力。然而，标准Transformer在扩展推理计算效率方面面临挑战，因为传统循环策略存在高计算开销，且KV缓存随模型深度增加而膨胀。我们提出通用YOCO（YOCO-U），结合YOCO解码器-解码器架构与递归计算，实现协同效应。基于YOCO框架，YOCO-U实现通用自解码器，通过参数共享进行多次迭代，同时将迭代过程限制在浅层高效注意力层。这种组合实现了优于单独YOCO或递归的性能-效率权衡。YOCO架构提供恒定的全局KV缓存和线性预填充，而部分递归在有限开销下增强表示深度。YOCO-U在保持高效推理的同时，提升了token利用率和扩展行为。实证结果表明，YOCO-U在通用和长上下文基准测试中保持高度竞争力，证明了高效注意力架构与递归计算结合是可扩展LLMs的有前景方向。

1 引言
大型语言模型（LLMs）从根本上改变了人工智能格局，特别是通过测试时扩展[16,12]。这些技术显著增强了模型的推理能力，使其能够解决以前无法触及的复杂多步问题。通过在推理阶段转向更密集的计算，LLMs在现实环境中展示了更强的自主规划和执行复杂任务的能力。这一范式转变凸显了有效扩展计算的重要性。

尽管取得进展，当前LLM架构在高效支持此类计算扩展方面仍面临显著限制。首先，从推理扩展角度看，仅依赖后训练策略效率较低，因为它往往未能充分利用预训练阶段固有的基础知识和表达深度。其次，虽然在标准Transformer中实现循环机制理论上可以扩展计算深度，但成本高昂，计算复杂度仍高，且Key-Value（KV）缓存的内存占用随深度增加而线性增长。

本文提出通用YOCO（YOCO-U），结合YOCO解码器-解码器架构与递归计算，证明两者具有协同效应，其收益超过各自单独提供。YOCO-U基于“You Only Cache Once”（YOCO）框架[30]，将模型分为自解码器和交叉解码器。自解码器使用高效注意力（如滑动窗口注意力）处理输入token并生成紧凑的全局KV缓存。交叉解码器则通过跨注意力重用此共享缓存，避免了标准Transformer的每层KV缓存，实现显著内存节省。在YOCO-U中，静态自解码器被通用自解码器替代，通过共享参数进行多步迭代计算，在不增加参数量的情况下通过递归深度增强表示能力。

YOCO-U的架构创新相较于标准通用Transformer[8]具有明显优势。通用Transformer将递归应用于整个网络，导致冗余开销和潜在优化困难，而YOCO-U仅将递归限制在浅层自解码器模块。这种部分递归设计允许模型在固定FLOP预算内通过多次迭代显著增强表达能力。关键的是，通过在递归自解码器中使用高效注意力（如滑动窗口注意力），YOCO-U消除了额外KV缓存内存的需求，避免了全注意力循环相关的高时间复杂度。因此，YOCO-U不仅保持了强大的长上下文建模能力，还保留了“单块”KV缓存优势，为递归计算提供了比前辈更可扩展和高效的路径。

广泛基准测试验证了我们的方法有效性。我们的扩展实验表明，YOCO-U实现了有利的性能-效率权衡：通过将额外计算投入递归高效注意力块，提升了token利用率，在相同FLOP预算下实现竞争性或更优性能，且KV缓存开销可忽略。此外，与其他Transformer变体相比，YOCO-U在通用和长上下文场景下表现出相当的能力。YOCO-U保留了非递归YOCO的推理优势，如线性预填充和减少内存占用。这些结果表明，在基于高效注意力的模块中进行部分递归，是开发下一代高性能、低成本大型语言模型的有前景方向。

2 相关工作
计算扩展
扩展计算与模型参数比率的努力集中在几个关键方面。通用Transformer[8]等方法通过在深度维度共享参数显著降低参数成本并增强模型容量。通过选择性扩展某些层的深度可进一步提升模型性能[1,19,2]。然而，深度扩展通常引入挑战，如延迟增加和更大的KV缓存需求。相比之下，平行扩展方法[3,34,33]在较小延迟开销下增加计算，但通常性能不如深度扩展技术。

推理扩展
在推理阶段增加计算已展示出强大能力，尤其在复杂推理任务中[16,12]。此外，显式思维链推理可有效压缩为连续表示[13]。关键的是，推理扩展带来的增强能力源于预训练后建立的内在容量，而非直接惠及预训练过程本身。因此，预训练阶段的计算扩展策略与这些推理扩展技术是正交的。

图1：YOCO-U架构概览。
通用自解码器（底部）使用高效自注意力（局部窗口）进行递归计算（T次迭代，由红色虚线表示）以精炼表示。关键的是，为跨注意力生成的全局KV缓存仅生成一次，且与T无关，而仅局部窗口KV缓存随迭代增长，保持整体缓存开销可忽略。
交叉解码器（顶部）通过跨注意力重用此共享全局KV缓存进行自回归token预测。

3 方法
所提出的YOCO-U架构是自回归建模（如大型语言模型）的递归基础架构。YOCO-U的设计继承自YOCO[30]，其中解码器-解码器架构包含两个部分，即自解码器和交叉解码器，将整个模型分为两个L/2层模块。在YOCO-U中，非递归自解码器被通用自解码器替代，其计算迭代T步。

与通用Transformer相比，YOCO-U仅对模型部分层应用递归。因此，它保留了关键推理优势，包括线性复杂度预填充和单块KV缓存。

3.1 YOCO-U架构
给定输入序列x = x₁⋯x_|x|，输入嵌入打包为X⁰ = [x₁,⋯,x_|x|] ∈ ℝ^{|x|×d_model}，其中d_model是隐藏维度。自解码器由L/2层模块组成：
Self-Decoder^{L/2}(X) = L_{S_{L/2}} ∘⋯∘ L_{S₁} (X)
(1)
通用自解码器在自解码器模块上进行T次递归计算：
USD(X) = Self-Decoder^{L/2} ∘⋯∘ Self-Decoder^{L/2} (X)
USD(X)用于生成交叉解码器的KV缓存K̂, V̂。交叉解码器也由L/2层模块组成：
Cross-Decoder^{L/2}(X, K̂, V̂) = L_{C_{L/2}} ∘⋯∘ L_{C₁} (X, K̂, V̂)
最终输出通过将交叉解码器应用于USD(X)生成：Y = Cross-Decoder(USD(X))。

3.2 通用自解码器
自解码器层利用高效自注意力（ESA）实现O(1)推理内存和恒定数量的KV缓存：
Y^l = ESA(LN(X^l)) + X^l, X^{l+1} = SwiGLU(LN(Y^l)) + Y^l
(2)
其中ESA(·)表示高效自注意力，即次二次、状态高效的因果模块，适用于递归浅层块。SwiGLU(X) = (swish(XW_G) ⊙ XW₁)W₂，RMSNorm[38]用于LN(·)。我们采用滑动窗口注意力（SWA）[4]作为默认，因其简单性和工程稳定性。来自三代次二次建模的线性注意力变体，如RetNet[29]、Mamba[11]和门控DeltaNet[36]，也兼容，但在混合架构中表现与SWA相似。

通用自解码器采用通用Transformer[8]的递归计算模式，其中输出在相同模型参数内迭代多次。递归计算在不增加参数的情况下增强模型表示能力。仅循环Transformer的浅层模块已被证明可提供改进的计算效率[1]，此设计与YOCO中自解码器的位置一致。

3.3 交叉解码器
首先，通用自解码器的输出生成交叉解码器的全局KV缓存K̂, V̂：
K̂ = LN(USD(X))W_K, V̂ = LN(USD(X))W_V
(3)
KV缓存K̂, V̂被所有交叉解码器层重用，查询按层计算为Q̂^l = LN(X^l)W_Q^l：
Y^l = Attention(Q̂^l, K̂, V̂) + X^l, X^{l+1} = SwiGLU(LN(Y^l)) + Y^l
(4)
其中Attention(·)是标准多头注意力[32]，W_Q^l ∈ ℝ^{d×d}是可学习矩阵。我们在交叉解码器中使用NoPE位置嵌入[35]以增强全局检索能力。获得Y后，softmax分类器执行下一个token预测。

从YOCO继承的推理优势
YOCO-U保留了YOCO的关键推理优势，因为整体计算布局不变，通用自解码器生成单组全局KV缓存，交叉解码器无需重新计算即可重用。

因此，当序列较长时，计算和内存成本主要由全局注意力组件主导。在YOCO-U中，递归更新仅应用于浅层块中的高效注意力模块，其开销与全局注意力相比可忽略。更重要的是，KV缓存仍只需生成一次，总体内存成本为O(N)而非标准Transformer解码器的O(NL)。因此，YOCO-U在固定GPU内存预算下保留了YOCO处理超长上下文的能力。

YOCO-U与Transformer中的循环
YOCO中的循环与标准Transformer解码器中的循环的关键区别在于递归如何与全局注意力和KV缓存交互。

在Transformer中，引入循环计算需要重新运行所有层，从而重新生成KV缓存并重复执行全局注意力，导致内存使用和计算成本显著增加。

相比之下，YOCO-U仅在基于高效注意力的模块内应用递归，而交叉解码器及其全局注意力保持不变。

因此，全局KV缓存仅生成一次并在迭代中重用，且不引入额外的全局注意力计算。

递归步骤因此仅产生高效注意力的小开销，而非Transformer层的全部成本。

总体上，我们观察到三个关键点，影响我们的最终设计：
• 在底层块扩展FLOPs比在所有块更有效。
基于标准Transformer，RINS应用早期层递归，性能优于vanilla UT，展示了YOCO-U在布局层面的合理性。我们将进一步展示，扩展深层层会导致收益递减。
• 递归扩展比平行扩展更有效，
因为平行扩展方法（如ParScale）不增加建模深度，通常在相同FLOPs下比递归扩展改进更少。
• 扩展高效注意力块同样有效。
YOCO-U的性能与RINS（具有早期层递归的标准Transformer）相当。这些发现表明，递归计算与高效注意力结合能够在不按比例增加计算成本和KV缓存的情况下扩展模型能力。

预填充吞吐量
在预填充阶段，虽然Transformer需要O(N²)时间并行编码所有token，YOCO仅需O(N)时间在自解码器中完成。如图7(a)所示，尽管YOCO-U带来额外深度，它仍通过复杂度优势将预填充吞吐量提升10×于vanilla Transformer和20×于RINS。即使在相对较短的上下文如16K时，YOCO-U仍比非递归Transformer快1.15×。线性复杂度保证了预填充成本在整体推理流程中可忽略。

解码吞吐量
在自回归吞吐量期间，全注意力层决定了整体吞吐量。结果如图7(b)所示。基于标准Transformer的递归计算引入额外全注意力层，RINS由于更多注意力计算和更小批大小仅实现40%吞吐量。然而，YOCO-U仅引入额外高效注意力层，因此比非递归YOCO仅牺牲5%吞吐量。与非递归Transformer相比，YOCO-U在16K长度下实现1.1×加速，在256K长度下实现2.21×加速。

KV缓存内存
我们报告单序列的KV缓存。由于带Paged Attention的推理引擎通常动态调整批大小，KV缓存内存决定了每个解码步骤的数据并行度。如图7(c)所示，YOCO-U由于高效注意力中的恒定KV缓存，仅带来可忽略的额外内存成本。然而，RINS的内存成本随模型深度增加，RINS需要38×的内存，几乎与层数成正比。

5 结论
我们引入通用YOCO（YOCO-U），一种将深度扩展与内存开销解耦的递归架构。YOCO-U通过参数共享和递归计算实现高效深度扩展，且不增加KV缓存占用。YOCO-U显著增强了参数利用率，展现出优越的扩展行为。实证结果证实，YOCO-U在各种基准测试中优于基线，同时保持线性预填充效率，为大型语言模型提供了一种可扩展且成本效益高的架构。

附录E
第4.2节的实验细节
所有基线模型标准化为1.3B参数、20层和2560隐藏维度。我们用1M批大小训练每个模型20k步（总计20B token）。为确保公平比较，所有变体的总计算预算（FLOPs）对齐到标准20层Transformer的约2×。

各基线的具体配置如下：
• 通用Transformer（UT）[8]：我们采用权重共享递归机制，循环整个20层块2次。这导致每次前向传递计算40层，有效加倍深度同时保持相同参数量。
• RINS[1]：具有早期层递归的标准解码器仅Transformer。遵循递归中间网络的精神，我们将20层分为两段，一个10层非递归块和一个10层递归块。后10层循环3次。此配置也导致40层总计算（10+10×3），与YOCO-U的块布局对齐，以便直接比较递归策略。
• ParScale[3]：我们遵循原始设置，使用不同的KV缓存前缀表示不同的并行组。通过在多个并行分支中处理token，ParScale实现2×计算扩展因子，匹配其他递归基线的FLOPs，同时保持其独特的并行化架构特性。

模型在各种基准上评估。表3使用的数据集包括WikiText-103（Wiki.）用于长文本语言建模，LAMBADA（LMB.）用于基于长上下文预测单词，物理交互QA（PIQA）用于物理常识，OpenBookQA（OBQA）用于基于事实的推理，HellaSwag（Hella.）用于日常事件延续，Winogrande（Wino.）用于指代消解，以及AI2推理挑战（ARC-E/ARC-C）用于易和挑战级科学问题。评估指标定义如下：
• 困惑度（ppl）↓：衡量模型预测下一个token的不确定性；值越低表示语言建模性能越好。
• 准确率（acc）↑：正确预测实例占总测试样本的比例。
• 归一化准确率（acc_n）↑：一种长度归一化准确率指标，调整候选答案的长度，以确保多项选择任务中的公平比较。
