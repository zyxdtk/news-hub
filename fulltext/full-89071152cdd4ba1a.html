原标题：Meituan releases the open weights of its LongCat-2.5 LLM with vision under a permissive MIT License

中文摘要： 美团以 MIT 许可证在 Hugging Face 开源 LongCat-2.5 视觉大模型权重。该模型总参数 1.6 万亿，每 token 激活约 480 亿，可检查截图视频、处理代码库并多步编写软件。基准测试显示其较前代大幅提升，Terminal Bench v2.1 得分接近 GPT-5.6 Sol 和 Claude Opus 5，而 API 价格显著更低。文章分析了竞品对比、定价优势、自托管需求（权重约需 3.2TB 存储），并提醒美国企业关注中国 AI 模型面临的监管审查风险。

太平洋时间 2026 年 11 月 9 日下午 3:04

美团于 11 月 9 日发布了 LongCat-2.5 的权重，距该模型首次亮相已过去一周。这家中国外卖和电商公司在 Hugging Face 上以 MIT 许可证发布了该检查点，为开发者提供了另一种运行该模型的方式——该模型能够检查截图和视频、通读代码库，并通过多个步骤编写或修改软件。

测试 LongCat-2.5 最有力的场景是既需要视觉判断又需要编程的任务。设想一位开发者将一张损坏的结账流程截图交给智能体，要求它在代码仓库中找到相关组件，让它提出补丁并在浏览器中检查结果。

美团的托管 API 定价让这类实验的成本相对低廉。对买家而言更有价值的问题是：它能否以折扣后的 API 费率处理足够多的视觉和编程工作，从而将高端模型留给更难的任务。在私有网络中运行完整模型则涉及另一番考量。

对于考虑采用该模型的美国和西方企业，有一点需要特别注意：中国 AI 模型正面临华盛顿方面日益严格的审查。今年 10 月，美国国土安全部披露了一项命令，指示联邦文职机构将 DeepSeek 排除在采购之外，并将其技术从受覆盖系统中移除，包括第三方提供的实施方案。该命令针对的是 DeepSeek 及其关联公司。

截至 11 月 9 日，VentureBeat 未发现任何公开披露的美国联邦采购或使用限制明确点名美团或 LongCat-2.5。但规则可能迅速变化。

正如 VentureBeat 今年 2 月报道的那样，国防部长皮特·黑格塞斯（Pete Hegseth）于 2 月 27 日宣布，他正指示五角大楼将 Anthropic 列为“国家安全供应链风险”。他于 3 月 3 日正式确立了这一认定。这两个案例表明，一场争端或一项供应链决策可以多快地改变各机构及其供应商能够使用的产品。

视觉理解发挥价值之处

在其技术报告中，美团描述了一个将视觉信息表示为 token 并与文本一同处理的模型。其 API 指南展示了开发者如何提交截图、图表、图像和视频。图像可以嵌入请求中或通过 URL 提供。文档记载的视频接口仅接受 URL，这对处理内部屏幕录像的团队而言是一个不容忽视的限制。

对于前端和产品工程，一个不错的初始任务是修复一个已知解决方案的视觉回归问题。给智能体提供出错的截图、测试仓库的访问权限，以及渲染修补后页面的方法。检查它是否能找到原因、做出有针对性的修改，并保留键盘导航和响应式行为。类似的工作流可以将设计参考转化为原型，但测试应检查输出是否遵循团队的组件库和交互规则，以及外观是否正确。

美团重点展示了开发者演示，包括 Tasihi 的汽车发布网站、AI Maverick Frank 的奇幻游戏界面，以及 Aigc Lancet 的商店管理网站。该公司自己的示例包括一个交互式流体模拟和一个 3D 展览。这些是构建演示或内部工具的团队的良好参考。店面原型与生产环境店面有着不同的验收标准。对于后者，生成的代码仍然必须通过与人工编写代码相同的功能、可访问性和维护性检查。

LongCat 较前代进步明显，但更新的对手设定了更高标准

美团评估中最清晰的对比是与前代模型的比较。LongCat-2.5 在 Terminal Bench v2.1 上得分为 88.4 对 70.8，在 DeepSWE v1.1 上为 64.6 对 9.7，在 SWE Atlas 代码库问答测试上为 58.3 对 33.1。这些结果为在代码仓库任务上重新测试 LongCat 提供了依据，尤其是对那些此前排除了 2.0 版本的团队。

美团发布材料中的竞品对比则更为复杂。LongCat-2.5 在 Terminal Bench v2.1 上与 GPT-5.6 Sol 和 Claude Opus 5 的差距在一分以内。在 v4.0 上，它得分为 38.5，而 Claude Opus 5 为 53.9。DeepSeek-V4.1-Flash 在 DeepSWE 上领先于下列四个模型。LongCat 在 3DCodeBench 上领先该组，而 Claude Opus 5 在 Vision2Web 上领先。对软件团队而言，这种分化很重要，因为终端操作、代码仓库修复和将截图转换为网页界面是不同的任务。

美团选择 GPT-5.6 Sol 和 Claude Opus 5 作为其两个专有参考基准。在美团发布 LongCat-2.5 时，它们的直接继任者已经上市。OpenAI 于 9 月 29 日发布了 GPT-6.1 Sol，Anthropic 于 9 月 22 日发布了 Claude Opus 5.5。选择较旧的基准表明美团为 LongCat-2.5 采取的是“次前沿”定位：在选定任务上与前一代高端模型性能相当，而 token 价格低得多。这是对美团选择公布证据的一种解读。仅凭这一选择无法确定 LongCat 与当今最佳模型相比的排名。

下表将美团基准报告中的得分与 Terminal-Bench 4.0 排行榜上的得分区分开来。美团将自测结果与已发布的结果相结合。GPT-6.1 Sol 和 Opus 5.5 的排行榜得分使用了最大努力模式及其各自的编程工具 Codex 和 Claude Code。应将它们视为同一基准版本在不同测试设置下的参考点。破折号表示该对比没有可展示的已验证结果。API 价格为每百万非缓存输入和输出 token 的美元价格。

美团将基准条目标记为 DeepSeek-V4.1-Flash。DeepSeek 的 API 文档称其托管的 Flash 端点服务于 1017 检查点，但美团的表格未指明检查点后缀。

较新的 Terminal-Bench 结果改变了人们对美团 v4.0 表格中 LongCat-2.5 与 GPT-5.6 Sol 几乎打平的解读。GPT-6.1 Sol 和 Opus 5.5 在排行榜上的得分均高于 LongCat 报告的 38.5，尽管设置上的差异使人无法得出干净的直接对比结论。

这使得较新的 Sol 和 Opus 成为企业编程试验中更有用的专有对照组。对于已经为困难任务的前沿性能付费的团队，GPT-6 Astra 和 Anthropic 于 11 月 9 日发布的 Claude Fable 5.2 是升级选项，可在 LongCat 难以完成的案例上进行测试。

实际对比应保持工具和预算不变。给每个模型相同的仓库状态、浏览器、测试套件、工具权限和时间限制。重复几个任务，观察每个模型的成功频率。

对于截图转代码，应分别对渲染结果和代码进行评分。对于错误修复，测试补丁是否解决了根本原因，以及审查者是否需要重做。一个看似完美的答案可能隐藏着失败的工具调用或破坏无关功能的更改。

定价和许可让托管试用更容易

美团的费率表列出了每百万缓存输入 token $0.006 的限时费率，以及非缓存输入 $0.30 和输出 $1.20 的价格。按此费率，一次包含 20 万非缓存输入 token 和 10 万计费输出 token 的运行，模型 token 成本为 $0.18。

相同的 token 数量在 DeepSeek 的非高峰费率下成本为 $0.09，GPT-6.1 Sol 为 $1.40，Opus 5.5 为 $2.80，GPT-6 Astra 为 $7，Fable 5.2 按上述费率为 $5.60。

该示例保持 token 数量固定，并低于 OpenAI 对 GPT-6.1 Sol 收取更高费率的门槛。在实践中，模型在推理上可能消耗不同数量的 token、重复调用工具，或需要第二次尝试。

较新的模型本身也改变了成本对比。按基础费率，GPT-6.1 Sol 的输入和输出费用是 GPT-5.6 Sol 列出的促销费率的一半，Opus 5.5 的每 token 成本低于 Opus 5。即使面对更便宜的继任者，LongCat 仍保持着可观的价格优势。

DeepSeek 的非高峰价格是一个更严格的标准，衡量企业为具有可下载权重和有竞争力编程得分的模型应支付的预期费用。

在采购决策中，应跟踪每个被接受结果的成本。包括重试、浏览器或沙箱时间、对其他模型的任何回退调用，以及工程师审查补丁所花费的时间。

缓存费率对于反复发送稳定提示前缀或大量仓库上下文的智能体很重要。应在开发者使用的工具中测量实际命中率。仅凭上下文窗口的大小无法判断账单金额。

美团权重上的 MIT 许可证允许商业使用、修改和再分发，但须遵守其声明要求。

托管服务是一个单独的采购决策。对于涉及专有代码或截图的试用，在上传公司数据之前，应确认该服务如何处理保留、访问和删除。使用公共或合成产物的沙箱足以了解该模型是否值得更深入的评估。

自托管取决于服务技术栈

根据美团的模型卡，LongCat-2.5 总参数量为 1.6 万亿，每个 token 激活约 480 亿参数。该模型将每个 token 路由到其专家子集，但为其提供服务仍需提供完整的检查点。

按每个参数两字节计算，在假设的统一 16 位表示下，1.6 万亿参数仅权重就需要约 3.2 TB。

这一计算仅作说明之用。它没有计入运行时缓冲区以及跨请求保留上下文所占用的内存，也不描述实际的检查点占用空间。

Hugging Face 仓库快照的元数据显示为 1.8T，而美团的技术描述为 1.6T。请使用实际文件和确切的服务格式来评估部署规模。

美团提供了一个面向神经处理单元的 SGLang-FluentLLM 部署指南。其技术博客描述了在中国产加速器上将专家权重和激活的精度降至 4 位。

这些优化反映了美团的测试设置。对于拥有其他加速器集群的团队，需验证服务运行时能否加载检查点并保持模型的视觉和工具使用行为。然后测量集群可并发处理多少长请求、这些请求需要多长时间，以及负载下性能如何变化。

当视觉编程工作负载足够大或足够敏感、值得运维该技术栈时，私有部署值得研究。偶尔运行原型的团队通过托管评估有更简单的路径。

对于以文本为主的维护工作，鉴于其公布的编程得分和较低的非高峰价格，DeepSeek 是一个有用的首选对比对象。对于审查时间或失败后果占成本主导的更改，应在相关内部测试中保留一个更强的模型作为后备。

第一个决策是 LongCat-2.5 是否能改进团队已有的工作流。从截图驱动的错误修复、设计转代码任务，以及作为对照的纯文本仓库任务开始。如果它能以更低的总成本让更多视觉工作通过审查，就把这类工作分配给它。集群采购可以等到试验确定了这种优势出现的频率及其价值之后再做决定。

对于考虑采用 LongCat-2.5 的企业，尤其是那些服务或计划服务美国政府客户的企业，模型在哪里运行以及合同是否允许使用它是两个不同的问题。

自托管或在企业控制的美国云中运行权重，可以让团队更好地控制提示和日志的去向、运行的模型版本以及它可使用的工具。但限制仍可能跟随技术进入第三方部署，正如 DeepSeek 命令所显示的那样。

即使没有公开披露的命令点名 LongCat-2.5，供应商在将其用于面向政府的工作之前，也应检查合同条款和适用的联邦供应链命令。保留一个在相同任务上测试过的第二模型，这样资格的变化就不会迫使重建。
