摘要
测试时扩展通常使用外部验证器（例如编程中的编译器和测试用例，或机器人应用中训练的价值函数）来获取高质量的展开。无验证器测试时扩展（VF-TTS）作为一种增强大型语言模型（LLM）推理的机制正受到广泛关注，主要是因为在许多实际应用中我们无法获得此类高质量的验证器。在现有的 VF-TTS 方法中，基于置信度的 VF-TTS 方法仅通过计算和对展开进行置信度排序，显得尤为有效。这类方法在样本评估中引入了近零开销，并且对模型内部状态的访问需求极低，使其在跨模型和任务时具有极高的灵活性。

在本文中，我们指出了现有基于置信度的 VF-TTS 方法的一个关键局限性：此类方法在复杂任务上会出现灾难性失效。我们观察到一个非常有趣的现象：均匀的高置信度通常表明未能进行探索，从而偏向于“自信但错误”的答案。为了解决这个问题，我们的核心洞察是，稳健的认知搜索需要一种特定的置信度轨迹模式：这类方法在开始时进行探索性分支（表现为初始低置信度），并最终收敛到高置信度的解决方案。为了实现这一洞察，我们引入了“共识性”，这是一个新颖的选择框架，明确评估推理过程中置信度的时间不对称性。我们通过一个组合度量指标将其操作化，该指标主动惩罚高初始置信度，同时严格要求最终的确定性。涵盖研究生级数学问题和自由形式代码生成的大量实验表明，共识性有效地优于现有基线，验证了我们对完成置信度的新视角。

1 引言
推理模型在各个领域展现出了卓越的能力。在准确性至关重要的推理密集型场景中，并行测试时扩展（TTS）已成为提高模型性能的一种高效方法——在推理过程中生成多条推理路径并选择最优输出 [34, 43, 3]。然而，从这些并行轨迹中选择最优输出的主流机制严重依赖外部验证器 [34, 33, 46, 21] 或模型 [25, 43]。为了在自由形式代码生成和中间智能体步骤等不可验证的场景中普遍扩展测试时计算，研究界最近开始探索完全依赖模型自包含内部信号（如 token 级对数概率）的选择机制，以获取高质量的展开。

现有的基于对数概率的方法计算并选择最大置信度的完成 [17, 11]。这些方法背后的关键洞察是：置信度越高，展开正确的概率就越大。在图 1（左）中，我们绘制了平均序列置信度的直方图，发现正确答案的分布均值高于错误答案，这与上述洞察一致。然而，我们发现这种简单的最大化在复杂任务上会灾难性地失效（即模型在这些问题的正确率较低）。它忽略了解决复杂问题所需的一个关键认知因素：过程多样性。为了研究这一洞察，在图 1（中）中，我们绘制了相同的直方图，但仅包含模型正确率 <20% 的问题。在这些困难任务中，模式发生了逆转，分布变得不可分离。这一结果表明，置信度最大化在解决模型有良好答案的问题时是有用的，但在模型必须探索多条路径以确定正确解决方案时效果较差。

在本文中，我们通过“共识性”的视角研究了困难问题的有效 TTS 问题——共识性原则是指，只有当模型知道解决问题的多种路径并且所有路径都收敛到相同的解决方案时，结论才是可靠的 [38, 6]。然而，在置信度最大化中，答案和推理的置信度都被最大化了。也就是说，选中的完成不仅在答案上收敛，而且在推理阶段早期就收敛了。这种选择盲目地坚持单一的思路，而模型内部并未承认其他替代方案。因此，会发生“自信但错误”的选择，因为置信度最大化迫使系统仅专注于快速得出结论或收敛，同时抑制了了解多种路径的重要性，破坏了共识性原则。幸运的是，这一观察自然为如何执行该原则提供了启示：如果高置信度代表收敛，我们可以用低置信度来识别必要的过程多样性。如果一个推理过程展示了对问题的稳健理解，它对替代解决方案的意识会迫使概率质量分裂，自然表现为早期置信度的下降。因此，一个具有共识性的轨迹应该表现出上升的轨迹：它以具有较低置信度的探索阶段开始（因为模型识别出各种有效的方法），然后收敛到一个高度确定的结论。

为了实现这种结构特征，我们引入了共识性度量，这是一个新颖的、无验证器的选择框架，明确量化了有效推理的这种时间置信度不对称性。我们的方法不是均匀地最大化序列级置信度，而是通过一个组合度量评估轨迹，该度量惩罚高初始置信度，同时仍鼓励高最终置信度。使用我们的度量，我们可以在图 1（右）中重新绘制困难问题的度量直方图，并表明共识性可以成功恢复区分正确和错误响应的模式。在复杂数学 (HMMT)、研究生级知识 (GPQA) 和开放式代码生成 (LiveCodeBench-V6, 智能体 Swe-Bench) 上的大量实验证明了该方法的有效性。最值得注意的是，共识性在基于投票的技术不适用的自由形式编码领域解锁了显著的边际收益；在 LiveCodeBench 上，我们的度量将 GPT-OSS-120B 模型的准确率提升至 69.7%，大幅优于 Pass@1 (65.7%)。在其他推理密集型数据集上也观察到了类似的系统性收益。

2 相关工作
测试时扩展 (TTS) 致力于投入更多测试时计算以获得更好的性能。与以思考模型为标志的顺序 TTS [29] 不同，本文专注于并行 TTS。并行 TTS 最初是有效的，但依赖严格的环境依赖（如外部验证器 [34, 33]），导致了严重的延迟和泛化问题。为了将效用扩展到更广泛的任务，诸如自洽性 [38] 之类的方法对采样的答案进行多数投票，但这对答案格式（多项选择、整数）施加了严格的约束，不适用于自由形式生成。另一条工作线使用 LLM 本身提供反馈——通过基于 LLM 的评估器、过程奖励模型或自我精炼 [6, 25, 26]——但这引入了显著的聚合开销。与我们最接近的是，几种方法使用 token 级对数概率作为正确性的直接代理，以实现高效的无验证器选择 [17, 11]。我们的工作建立在这些内部信号的计算优势之上，但在使用上有所不同：我们不是假设置信度应该被全局最大化，而是表明均匀的高置信度是过早收敛的症状，并引入共识性轨迹来明确奖励早期阶段的探索。关于基于验证器的 TTS、搜索以及校准和强化学习中的熵/置信度的更广泛讨论见附录 F。

前缀和时间置信度。
越来越多的工作——其中大部分是并行的——研究置信度在推理过程中如何演变，而不是其整体水平，我们的发现与这些文献一致。在“惩罚早期置信度”方面，Gai 等人 [12] 表明过早的自信（早期承诺加随后的合理化）预示着有缺陷的推理，并通过强化学习奖励缓解了这一问题；Wang 等人 [39] 发现正确的轨迹表现出上升的置信度，并使用这种“置信度增益”来重新加权多数投票；Keramati 等人 [18] 发现早期 token 置信度可以预测多智能体辩论中的推理质量；相关工作表明初始推理步骤对结果产生不成比例的影响 [24]，每步置信度带有时间信号 [27]，推理模型在表达置信度方面校准得更好 [44]，尽管如此，推理即使在错误时也会膨胀置信度 [10]。看似对立的是，Otth 等人 [30] 报告称最大化前缀置信度可以改善数学推理；我们通过注意到这种效果依赖于难度来调和这一点——在简单问题上，Pass@1 已经很高，高前缀置信度是一个可靠的信号，共识性实际上是中性的，而在困难问题上，均匀的置信度标志着过早收敛，初始惩罚变得有益（第 4.5 节，图 3）。我们将这种独立发现的趋同视为对底层洞察的验证，而我们的贡献在表述和适用性上都是独特的。首先，我们不仅仅是观察模式或使用它来重新加权投票，而是将其操作化为一个主动选择目标，惩罚高初始置信度同时奖励最终收敛。其次，由于无需训练且仅从 logits 计算，共识性直接适用于投票不适用的自由形式生成（代码生成、智能体编辑）——这是上述方法均未涉及的领域，因为投票需要可提取的答案，而强化学习方法需要训练。第三，也是独一无二的，我们在评分前将推理阶段与最终答案阶段隔离，去除了人为自信的摘要 token，这些 token 会稀释信号。

3 方法
3.1 预备知识：Token 级置信度
为了理解和评估生成的置信度，我们遵循先前工作 [11, 17] 的表述并定义 token 级置信度。对于给定的提示 x 和生成的序列 y=(y_{1},y_{2},\dots,y_{L})，模型在每个时间步 t 输出词汇表上的概率分布。我们不仅仅依赖单个解码 token y_{t} 的概率，而是收集前 K 个候选 token 的 token 置信度。token 级置信度 c_{y,t} 为这些前 K 个 token 的负平均对数概率：
c_{y,t}=-\frac{1}{K}\sum_{j=1}^{K}\log P_{\theta}(v_{t,j}|y_{<t},x), (1)
其中 v_{t,j} 表示在步骤 t 词汇表中第 j 个最可能的 token。集中的分布会导致该值很高，表示高置信度，而平坦的分布则导致低置信度。

3.2 为什么置信度不足：困难问题的长尾陷阱
为了在不依赖外部验证器或精确匹配共识的情况下扩展测试时计算，最近的方法在一组采样序列中最大化内部置信度指标。这些通常实现为生成序列上的平均 token 级置信度 [17, 11]：
y=\operatorname*{arg\,max}{y}\frac{1}{L}\sum{t=1}^{L}c_{y,t},. (2)
这些方法基于一个简单的原则运行：最大化模型的置信度即可最大化正确性。这个方向特别有价值，主要有两个原因。
灵活性。它只需要 token 级 logits 且无需训练，使其可直接应用于开放权重模型和通过 API 暴露对数概率的闭权重企业 LLM（例如 Google Gemini）。
效率和延迟。它在评估每个完成时引入了近零的计算开销。所有完成都可以并行采样，提供比顺序扩展更好的延迟。
为了验证置信度最大化的有效性和局限性，我们分析了 GPT-OSS-120B 在 LiveCodeBench-V6 (LCB) 数据集（一个自由形式代码生成任务）上完成的平均置信度分布。在图 1 左图中，在整个数据集上，较高的平均置信度与正确性强烈相关。这证实了驱动现有基于置信度指标的基础直觉：在宏观层面上，自信的生成通常更准确，现有方法正确地解释了这一全局信号。
然而，这种方法在复杂任务上变得适得其反。当孤立地看“困难”问题（正确率 <20%，图 1 中）时，置信度动态反转了：错误答案表现出比正确答案更高的平均置信度。至关重要的是，困难问题上的错误分布不仅仅是发生了偏移——它变得高度过度分散，在最高置信度百分位上形成了一个沉重的“长尾”。在精确匹配多数投票不适用的自由形式生成中，无验证器测试时扩展通常依赖 argmax 选择（从池中挑选得分最高的单个完成）。由于这种右偏的尾部，简单地最大化平均置信度保证了算法将系统地采样“自信但错误”的幻觉。

3.3 通过共识性理解置信度
为了理解不同任务难度下这种矛盾的行为，我们引入了共识性的概念。在科学认识论中，共识性原则规定，当一个结论从多条不同且多样的探究路线中产生，而不是从单一孤立的路径中产生时，它要可靠得多。在 LLM 研究中，这一基础思想已被广泛且成功地采用——最著名的是通过自洽性 [38, 6] 等方法。当我们通过这个视角评估全局置信度最大化的失败时，其缺点变得明显。通过奖励从最初几个 token 就表现出均匀高置信度的轨迹，这些指标仅优化了收敛，并倾向于以最快的方式收敛到明确单一路径的完成。同时，这种策略抑制了承认多种路径的完成。这在结构上导致选择了具有过度自信推理过程的完成。
为了将这一洞察建立在 LLM 的实际机制中，我们检查了置信度是如何计算的。在自回归语言模型中，给定提示 x 和先前生成的序列 y_{<t}，生成第 t 个 token y_{t} 的置信度与其条件概率 P_{\theta}(y_{t}|y_{<t},x) 耦合。至关重要的是，token 的置信度并不衡量未来序列的客观正确性；相反，它衡量的是过去的推理努力 (y_{<t}) 在多大程度上严格推导出了当前 token。因此，置信度的含义是阶段依赖的：
最终阶段（大 t）：现有置信度最大化背后的直觉根植于推理的最后阶段。随着模型成功沿着其选择的路径前进，逻辑约束应该收紧。如果置信度在推理轨迹的末尾很高，这表明之前冗长的思维链已经成功且系统地收敛，详尽的推理步骤不可避免地推导出了最终结论。
初始阶段（小 t）：在生成的早期步骤中，高置信度仍然是收敛的症状。然而，这意味着一个非常短的前缀已经将概率空间坍缩到单一路径。对于复杂的推理任务，这是非常有害的；它标志着模型未能认识到问题的难度或细微差别，绕过了必要的探索，并过拟合到一个局部的、通常是有缺陷的解决方案。这种盲目承诺直接导致了在长尾中观察到的“自信但错误”的幻觉。相反，如果模型对复杂问题（需要探索多种可能性的问题）具有稳健的理解，它自然会承认存在多条可行的路线来到达解决方案，这与共识性原则一致。这种对替代策略的内部意识迫使自回归概率质量分裂，反映出必要的认知分歧。因此，这种必要的探索阶段本质上表现为低初始置信度。
因此，对复杂问题的真正推理不是一条平坦的确定线；它是一个动态轨迹。它要求时间上的不对称性：低初始置信度解决为高最终置信度。通过将推理轨迹剖析为初始和最终置信度阶段，我们可以将模型的生成分类为表 1 所示的四个不同类别。
先前的研究正确认识到了置信度的预测能力，有效地利用它来过滤掉未能达到逻辑收敛的轨迹（类别 2 和 4）。然而，他们对这一信号的应用仍然很粗糙。通过依赖简单的最大化，现有方法无意中优化了类别 1，同时主动忽略——或在数学上惩罚——低-高类别 3（代表共识性）所需的必要初始不确定性。这种结构性盲点是现有机制在复杂推理任务上系统性表现不佳的原因。
在以下章节中，我们将形式化如何将共识性实现为一个选择度量，专门设计用于针对并识别这一最佳共识类别内的生成。

3.4 共识性得分公式
在定义了 token 级度量 c_{y,t} 后，我们量化了长度为 L 的生成序列 y 的共识性轨迹。根据第 3.2 节，一个正确的、充分探索的推理路径应该表现出低初始置信度（反映主动路径探索），最终收敛到高最终置信度（反映逻辑共识）。为了捕捉这一原则，我们使用大小为 W 的边界窗口来捕捉初始和最终置信度：
C_{initial}=\frac{1}{W}\sum_{t=P+1}^{W+P}c_{t},\quad C_{final}=\frac{1}{W}\sum_{t=L-W+1}^{L}c_{t} (3)
初始和最终置信度由前 W 个和后 W 个 token 的平均 token 置信度量化。注意，我们也跳过了前 P 个 token，因为初始 token 将具有非常相似的置信度（例如，给定相同的提示，第一个 token 将具有相同的置信度），这将稀释置信度信号。
最后，我们为给定的推理轨迹定义共识性得分 (S)，以明确奖励高最终置信度同时惩罚高初始置信度。
S=C_{final}-\alpha C_{initial}, (4)
其中 \alpha\geq 0 是一个平衡因子。
在测试时扩展期间，我们为给定的提示采样多个完成，为每个序列计算 S，并选择最大化 S 的完成。通过最小化初始置信度和最大化最终置信度，该目标主动选择具有真正共识性特征的多样探索和稳健收敛。我们在图 1 中绘制了相同困难问题集上的共识性直方图，正确响应的共识性均值显著高于错误响应。更重要的是，错误分布没有表现出过度分散的长尾分布，使得共识性最大化成为自由形式生成问题的稳定度量。

3.5 推理阶段隔离
将置信度度量应用于使用思维链 或显式 <think> token 训练的模型时的一个关键细微差别在于生成序列的结构组成。这种范式下的自回归输出通常由两个不同的语义阶段组成：主动推理阶段 (Y_{reason}) 和最终答案表述 (Y_{answer})。具体来说，Y_{answer} 中的 token 不反映主动解决问题或认知搜索。这些 token 主要用于总结或模仿 Y_{reason} 中已经建立的逻辑结论。因此，Y_{answer} token 的对数概率可能表现出人为的高置信度，而与实际的推理质量无关。在序列级评估中包含这些最后的 token 因此起到了噪声因子的作用，掩盖了模型真实的认知轨迹。
为了提取底层思维动态的更纯粹信号，我们提出了一种针对全序列共识性的推理阶段隔离变体。对于任何生成的完成 y，我们解析序列以识别语义转换边界，并仅提取生成的推理部分。这种隔离的成本可以忽略不计，并且没有实际障碍：所有主流思考模型都暴露了一个易于识别的分隔符——例如，DeepSeek-R1、Qwen3、Mistral 和 Llama 使用 </think>，而 GPT-OSS 使用 <|channel|>final——因此分割只是一个简单的字符串操作。即使没有专用的分隔符，-full 变体仍然是该原则的有效实例（表 2），并且任何非思考模型都可以被提示发出一个“Final Answer”标记以恢复统一的边界。所有后续的边界窗口计算 (W) 和置信度聚合都严格限制在隔离的推理轨迹 Y_{reason} 上，确保共识性得分仅反映真实的认知搜索和解决过程。对于非思考模型，全序列或“Final Answer”部分之前的片段都是适用的，因为它们包含了实际的推理过程。

4.1 实验设置
模型。我们利用了多样化的开源权重大型语言模型套件：DeepSeek-R1-Qwen-7B-Distill (DS-R1) [14]、Qwen3-80B-Next-Instruct-FP8 (Qwen) [41]、Qwen3-80B-Coder-Next-Instruct-FP8 [4] (Qwen3-Coder-Next) 和 GPT-OSS-120B/20B (OSS-120B/20B) [28]。我们对 GPT-OSS-20B 使用高思考模式，对 120B 模型使用中等思考模式。这种选择旨在覆盖广泛的参数规模。此外，它涵盖了显式推理架构（Deepseek 和 GPT-OSS）和标准指令微调模型，确保我们的发现能推广到不同的生成范式。
数据集。我们在四个具有挑战性的、推理密集型的基准上评估测试时扩展性能：用于代码生成的 LiveCodeBench-v6 (LCB) [15]、用于智能体应用的 SWE-bench [16]、用于高级数学推理的 HMMT25 [2] 和用于研究生级问答的 GPQA-Diamond [31]。这一选择提供了跨不同认知领域的全面覆盖。至关重要的是，LCB-v6 和 SWE-bench 需要生成富有表现力的、自由形式的程序化解决方案。在这些环境中，像共识性这样依赖内部信号的方法 readily 适用，而依赖多数投票的方法应用有限。
实验设置。为了评估模型在一般设置中的扩展能力，我们采用了 Best-of-n 选择范式，其中我们采样 n 个完成，并使用测试时扩展方法对 Top-1 完成进行排名和选择作为最终答案。对于单轮数据集（LCB、GPQA、HMMT），我们采用共享池评估策略。对于每个查询，我们首先生成一个包含 256 个独立完成的公共池。在评估期间，我们从这个公共池中随机抽取大小为 n 的子集，并应用每个 top-1 选择方法。我们将实验重复 10 次。对于智能体情况（SWE-bench），我们将每种方法应用于单个步骤，并且我们仅将测试时扩展应用于编辑步骤以节省计算成本。详细的智能体设置见附录 I。我们还注意到共识性适用于基于投票的方案，并在附录 C 中展示了基于投票的结果，其中我们展示了共识性作为正确性信号的稳健性。
基线和共识性实现。我们的主要基线是 Self-Certainty [17]，它计算整个生成序列的平均置信度并选择最大化置信度的完成；以及 Deep-Conf [11]，它提出仅使用最后 2048 个 token 的置信度 (DeepConf-2K)。我们还加入了 Deep-conf-20%，它使用最后 20% token 的平均置信度。为了与基线对齐，我们还使用两种变体，绝对 token 和动态百分比，来确定共识性计算的初始和最终窗口大小 (W)。如第 3.4 节所述，我们总是跳过前 5% 的 token 以专注于置信度计算。为了计算 token 级置信度，我们使用 K=5 的 top 对数概率。我们选择较小的 K 有两个原因：(i) 商业推理 API 通常只暴露 top-20 的对数概率，因此小 K 估计量使得共识性可在此类模型上部署；(ii) 候选 token 已经携带了大部分概率质量——在 GPT-OSS-20B/LCB 上，top-5 token 捕获了每步 93.9% 的质量——因此 K=5 就足够了，同时避免了全词汇表评分的大量对数概率负载。

4.2 共识性性能
为了回答 Q1，表 2 展示了 LiveCodeBench、HMMT 和 GPQA 数据集上的 top-1 选择准确率。我们使用固定惩罚乘数 \alpha=3 从公式 2 计算共识性得分。边界窗口本身被动态评估为序列长度的 20% (Cns) 或 2048 个 token 的绝对阈值 (Cns-2K)，以与基线对齐。-think 变体将此计算专门应用于隔离的推理轨迹，而 -full 评估整个生成的输出作为消融研究，思考隔离细节可在附录 B 中找到。对于 GPQA 上的 Qwen，因为 Y_{answer} 只是一个框选字符，我们只报告完整版本。
简单最大化的失败。最令人惊讶的结果在经验上验证了我们关于仅最大化置信度指标的“长尾陷阱”的分析。在多个模型和数据集上，在没有投票的情况下应用这些指标通常会导致与随机选择 Pass@1 相比灾难性的性能下降。例如，在 HMMT 基准上，将 Self-Certainty 应用于 OSS-20B 将性能从 76.5% 降至 68.0%。类似地，在 OSS-120B 的 LCB 上，Pass@1 达到 65.7%，而 DeepConf-20% 降至 61.9%。在没有外部验证器保障的情况下，简单地最大化序列级置信度使得选择自信的幻觉、过拟合的轨迹变得不可避免。
共识性的一致优越性。形成鲜明对比的是，共识性框架成功中和了这种退化，在所有数据集上始终优于 Pass@1 和所有置信度基线。值得注意的是，共识性在开放式 LCB 代码生成基准上表现出色——这是一个传统的精确匹配多数投票不适用的关键领域。在 LCB 上，我们的 Cns-think 将 OSS-120B 提升至 69.7%，将 Qwen 从 55.3% (Pass@1) 提升至 60.4%，显示了早期低置信度的必要性。我们在附录 G 中提供了一个比较共识性和过度自信示例的案例研究，提供了对低初始置信度影响的直观理解。
消融：推理隔离的必要性。-full 和 -think 变体之间的比较旨在说明如何最大限度地集中共识性信号。重要的是，这两个变体都依赖于相同的底层逻辑——评估置信度的时间不对称性——并且都代表了我们框架的有效实现。例如，我们观察到全序列变体对于 Qwen 模型在 LiveCodeBench 任务上非常强大。定性调查表明，发生这种情况是因为 Qwen 经常通过在最终代码块中直接将推理步骤作为注释写入来继续其主动解决问题，这意味着 -full 轨迹仍然捕获了关于模型置信度的丰富信息。这次消融的核心要点是，隔离推理阶段 (-think) 可靠地提升了更广泛模型范围内的性能。通过剥离最终答案中通常确定性的摘要，隔离方法从轨迹中提取真实的推理模式。因此，虽然 -full 仍然是共识性原则的稳健应用，但我们推荐 -think 作为通用最佳实践，以实现测试时选择的最集中信号。

4.4 共识性调查
扩展稳健性。为了回答 Q2，图 2 说明了随着样本大小 (n) 增加到 128 时的准确率扩展行为。与 mean-conf (Self-Certainty) 或 last-20% (DeepConf-20%) 相比，共识性通常表现出更优越、更一致的扩展特性。在 GPQA (OSS-20B) 上，虽然共识性和 last-20% 都呈正向扩展，但共识性的扩展速度明显更快。这种优势在自由形式生成任务 (LCB) 上最为明显。使用 Qwen 时，只有共识性呈正向扩展。使用 OSS-20B 时，虽然 mean-conf 基线最初扩展良好，但它很快陷入长尾陷阱，随着 n 的增加遭受严重退化，这与 Chen 等人 [5] 观察到的趋势相似。相比之下，共识性稳步扩展到 n=128。虽然共识性在 HMMT 上对 OSS-20B 偶尔表现出轻微退化，但它始终将性能保持在 Pass@1 底线之上。
时间置信度轨迹。为了回答 Q3 并验证共识性原则，图 3 将每个问题内的置信度归一化，将置信度轨迹重采样到相同长度，绘制了 Pass@1 率 < 50% 的困难问题上的平均差异轨迹（正确 - 错误）。在所有评估的模型和数据集中，差异在序列开始时为负或最低，并在结尾稳步上升。这在经验上证实了正确的推理轨迹本质上具有较低的初始置信度和较高的相对最终置信度。在某些环境中，正确的轨迹保持较低的绝对置信度，进一步证明了未受惩罚的高置信状态主动与过度自信而非推理相关。
统计显著性。这种轨迹差异在统计上是可靠的，而不是均值的伪影。在困难问题（Pass@1 < 20%）上，共识性以 AUROC 0.61–0.62（不重叠的 95% 置信区间）区分正确和错误的完成，而平均置信度处于随机水平（0.47–0.50）。问题内上升 \Delta=C_{final}-C_{initial} 的配对检验在两个 LiveCodeBench 面板上均显著 (p=0.011, 0.018; d_{z}\approx 0.35)，在 GPQA 上为正（Wilcoxon p=0.042）。完整的表格和测试细节见附录 D。
难度分层。轨迹分析预测共识性应该恰好在平均置信度最大化失败的地方提供帮助。我们通过将每个数据集按 Pass@1 率分为三个等大小的难度层级，并在表 5 中报告平均置信度与共识性选择准确率来验证这一点。在简单问题上，Pass@1 已经接近完美，共识性是中性的——与置信度基线匹配（Qwen 为 99.9 对 99.9；GPT-OSS-120B 为 99.1 对 100.0），因为池中的所有完成都表现出类似的高初始置信度，没有信号可惩罚。收益集中在中等和困难问题上（中等上高达 +13.7），这正是过早收敛是主要失败模式的地方。这证实了初始置信度惩罚在置信度最大化已经成功的地方是无害的，而在它不成功的地方是有益的，直接解决了何时应该奖励而不是惩罚高前缀置信度的问题。

4.5 共识性的稳健性
我们通过证明共识性代表了一种根本稳健的测试时扩展范式来回答 Q4。我们分析了它对其两个主要超参数的敏感性：边界窗口大小和惩罚乘数 \alpha。
窗口大小稳健性。虽然我们在第 3.4 节中使用了相同的窗口大小，但共识性自然可以扩展到不同的初始和最后窗口大小。我们在图 4 中评估了使用我们的共识性得分与使用相应的 last-k% 在不同初始和最终窗口百分比下的性能差异。由此产生的热图表明，在大量的百分比组合范围内，引入初始置信度惩罚始终产生正向的性能提升。跨模型和数据的通用稳健范围是 20% 到 30%。
惩罚乘数 (\alpha)。我们还在图 5 中将惩罚乘数 \alpha 从 0 扫描到 8。结果表明，应用适当的 \alpha>0 会产生持续优于 pass@1 基线的正向收益。根据我们的经验分析，我们建议标准操作范围为 \alpha\in[2,5]。这种 >1 的加权在结构上是必要的，因为自回归置信度自然开始低、结束高；需要更大的乘数来适当平衡初始探索惩罚与最终收敛得分的幅度。
至关重要的是，我们观察到一个普遍趋势，即如果 \alpha 变得过大，性能开始下降。这种退化完美地说明了我们理论的双重性：虽然早期探索是必要的，但最终的逻辑收敛同样关键。过度惩罚置信度忽略了最终收敛的影响，并使框架从表 1 中的类别 3（共识性）和 4（完全混乱）中进行选择，导致性能下降。
选择协议和迁移。为了使选择协议明确并排除每个基准的调整，我们在评估任何其他基准之前，在单一开发设置（Qwen 在 LiveCodeBench 上）上固定了 \alpha=3，窗口 k=20% 和 5% 跳过的 前缀；这些冻结值是表 2 中报告的 Cns 配置。为了确认这些没有过度调整，我们额外运行了网格搜索（\alpha\in{1,\dots,5}, k\in{5\%,\dots,30\%}），在 5 折交叉验证下——在训练折上选择超参数并在留出的折上评估——以及跨数据集迁移，其中在 GPT-OSS-20B/LCB 上选择的参数原封不动地应用于 HMMT（表 5）。冻结配置捕获了每集最优增益的 72–78%，并在无需重新调整的情况下跨数据集迁移（在 HMMT 上比 Pass@1 高 +2.2）， suggesting a practical recipe: curate a small seed set per model to fix hyperparameters, then apply them to unseen data.

5 结论、局限性和未来工作
在这项工作中，我们引入了共识性，一个新颖的无验证器测试时扩展框架，它将评估从简单的置信度最大化转变为结构化的时间信号。大量评估证明了其在中和自信但错误选择方面的稳健性，实现了优于现有基线的显著边际收益——特别是在传统精确匹配多数投票不适用的开放式代码生成任务上。更广泛地说，我们不仅将共识性视为一种选择度量，而是视为一般测试时扩展原则的一个实例：即探索应该被重视而不是被惩罚。我们基于置信度的得分是这一原则的一种高效的、零开销的实例化，它是一种固定的启发式方法，而不是通用规则——设置可能允许多种有效的置信度轨迹。这开启了几个方向。一个学习的或基于评判者的选择器可以评估推理过程本身的探索多样性，而不仅仅是最终答案共识，从而推广超越我们的闭式得分。该原则还扩展到树状结构搜索：在固定预算下运行多个浅层树并使用共识性选择最可信的根轨迹，提供了一种缓解此类方法中早期采样过大影响的方法。最后，尽管有效，共识性目前以简单的方式应用于智能体设置，这限制了效率；我们计划用更智能的框架来提升它。因为共识性提供了推理质量的完全内部衡量，我们还计划探索其在测试时扩展之外作为智能体强化学习的内在奖励的用途，为以无验证器方式训练复杂推理智能体提供可扩展的途径。

虽然共识性度量的主要重点是在精确匹配共识不可能的开放领域实现无验证器选择，但它也可以在结构化任务上与传统多数投票技术无缝集成。为了评估这一点，我们在 HMMT、GPQA 和 AIME 数据集上将置信度度量与投票相结合，在这些数据集中答案可以被严格提取和匹配。
因为不同的置信度度量（例如 DeepConf 与共识性）在完全不同的数学尺度和分布上运行，直接聚合它们的原始分数是不稳定的。为了确保公平和稳健的比较，我们利用 Borda Count 投票。在这种方案下，每个度量对 N 个采样完成进行排名，而不是聚合原始分数。对于 N 个候选的池，排名最高的完成获得 N 分，第二名获得 N-1 分，依此类推。一个超参数 p 控制聚合期间排名加权的指数。
具体来说，对于给定提示的一组 N 个采样完成 {y_{1},y_{2},\dots,y_{N}}，令 R(y_{i})\in{1,\dots,N} 表示基于所选选择度量的完成 y_{i} 的排名（其中 1 代表最高度量分数）。令 A(y_{i}) 表示从完成 y_{i} 中提取的最终答案。唯一答案候选 a 的总 Borda 得分 B(a) 计算如下：
B(a)=\sum_{i=1}^{N}\mathbb{I}(A(y_{i})=a)\cdot(N-R(y_{i})+1)^{p} (5)
其中 \mathbb{I} 是指示函数。最终选择的答案只是最大化此分数的候选：
\operatorname*{arg\,max}_{a}B(a)。
表 7 中的结果表明，在投票方案下，几乎所有的测试时扩展方法都成功且大幅优于贪婪 Pass@1 基线。因为标准的自洽性基线在这些结构化、闭式任务上已经异常高（例如，在 OSS-20B 的 AIME 上为 96.7%），各种置信度度量之间的边际自然被压缩。
尽管存在这种天花板效应，共识性度量仍然设法略微优于基线，在几乎所有模型-数据集对上都取得了峰值分数。这表明，即使精确匹配共识可用，共识性评估的时间轨迹也提供了更优越的、附加的推理质量信号。然而，我们强调，虽然共识性在这些环境中仍然具有竞争力，但其主要结构优势仍然是它在自由形式、不可投票领域（如 LiveCodeBench 和 SWE-bench）中解锁这些确切类型的扩展边际的能力。

附录 F 更多相关工作
基于验证器和基于搜索的 TTS。除了正文中讨论的基于置信度的方法外，大量并行 TTS 工作依赖外部信号。程序化验证器（如编译器 [46, 21] 和形式化证明检查器）提供真值反馈，搜索算法结合顺序和并行展开以选择有前途的部分轨迹 [43, 37]。在聚合方面，带有早停的自洽性 [23]、验证中间步骤的过程奖励模型 [36]、递归/集成自聚合 [35, 19] 和自我验证 [32] 提高了稳健性，但代价是可提取的答案、训练的验证器或大量的聚合开销。相反，共识性只需要模型自己的 logits，并适用于自由形式生成。
在 LLM 中使用熵和置信度。在输出校准的邻近领域，置信度和熵也被广泛认为是确定输出质量的重要信号 [13, 9, 8]。熵的使用也在强化学习研究中被采用，因为该信号经常作为有效的强化学习优化目标。利用这一点，像测试时强化学习 [47] 这样的工作利用内部指标来提升对外部验证器的依赖，通常最小化序列熵 [1] 以驱动高置信度共识。另一方面，在具有可验证奖励的强化学习中，研究人员利用熵最大化作为一种主动的全局训练扰动；诸如 DACE [22]、UCAS [40] 和 Reasoning with Exploration [7] 之类的框架明确集成了熵奖励以惩罚收敛并强制进行多样化的搜索路径。Zeng 等人 [45] 使用熵来量化 LLM 生成中的惊喜以有效地整理数据。我们的共识性框架通过利用相同的内部概率分布与这些努力相联系，但在应用和概念化上都有显著分歧。共识性不是作为引导中间训练程序进行探索的全局训练扰动，而是作为导致稳健推理过程的零样本推理签名。此外，我们证明了探索的价值是阶段依赖的：高熵在初始假设分支期间是非常有益的，但整个序列中均匀的高熵标志着完全混乱而不是稳健的探索。
