用 OpenAI 模型推进芯片设计

OpenAI 的模型正在快速改进为 AI 提供动力的芯片。

今年八月，我们分享了 OpenAI 工程师如何使用我们的前沿模型来加速我们首款定制推理芯片 Jalapeño 的开发。在本文中，我们将更深入地探讨 Jalapeño 性能提升背后的专家级设计改进，以及我们如何将相同的方法应用于 AMD 的第三方硬件，以实现显著收益。

为了衡量我们的模型在端到端芯片设计任务上的能力，我们在两个开源处理器设计上对连续几代模型进行了评估，并得到了有趣的发现。为了将能力发展建立在可信的评估体系之上，我们正在与 Synopsys 合作，将前沿智能与工程师已经在使用的电子设计自动化（EDA）工具相集成，用于设计和验证芯片。

改进 Jalapeño 的计算模块

我们于 2025 年初开始使用 GPT-4o 帮助设计 Jalapeño。即使是那个早期模型也找到了实现实质性 PPA 改进的方法，例如：

在向量单元中（负责管理和执行并行计算任务），节省来自浮点加法器和乘法器、转换函数、归约逻辑以及特殊功能单元。模型探索了替代的逻辑实现以及如何将计算分配到流水线各个阶段，找到了共享硬件和减少中间存储的机会。

在矩阵单元中（一个算术组件），改进累积于浮点加法器、乘法器和低精度点积电路。一项乘法器重新设计在综合中使用了约 15% 更少的单元面积，同时将延迟从两个时钟周期减少到一个。另一项加法器重新设计将单元面积减少了约 15%，同时保持其两周期延迟。对点积逻辑和流水线组织的进一步改进为整个模块带来了额外的节省。

在整个 Jalapeño 设计工作中，团队估计模型提出的更改将向量单元的标准单元面积减少了约 13%，矩阵单元减少了 10%。这些优化在 Jalapeño 的硅片点亮过程中得到了硅片验证。

我们与 AMD 的合作

我们与 AMD 在 PPA 改进方面进行了合作，在旗舰 GPU IP 上相对于经过深度优化的基线实现了高达 14% 的改进。我们的模型通过重写描述芯片电路的代码（SystemVerilog RTL）识别出进一步的改进。这相当于在不到 5 个月内取得了大约一年的进展——在芯片设计前沿前所未有的成果。AMD 已经将其中一些更改纳入其最近送去制造的设计中，并将其他更改添加到其生产设计文件中，以供未来版本使用。

我们观察到该模型能够以专家微架构师的水平对 RTL 进行推理。

该模型可以重写执行计算、控制操作或移动数据的电路。它使用 Synopsys 工具验证每次重写是否保持了模块的行为，并评估功耗、性能和面积方面的权衡。

AMD 还使用我们的模型编写的设计，在其即将推出的下一代旗舰 CPU 的关键模块上验证了个位数百分比的 PPA 提升。展望未来，我们预计相对于最优化基线，GPU 和 CPU 还会有进一步的 PPA 改进。

优化 RISC-V 核心

我们在 Jalapeño 和 AMD 芯片上的结果表明，模型可以对生产设计进行改进。为了衡量芯片设计能力从一代模型到下一代模型的进展，我们在两个开源 32 位 RISC-V 核心上测试了每个模型。PicoRV32 是为称为 FPGA 的可重编程芯片设计的紧凑型核心。OpenTitan 使用 Ibex 作为其安全芯片中的嵌入式处理器。每一个都是面向嵌入式、微控制器级工作负载的完整处理器核心。

我们给每个模型提供了每个核心的原始硬件描述，并要求其提高吞吐量（即核心每秒可执行的指令数）。例如，某项更改可能让核心在更少的时钟周期内完成一条指令，但使每个周期耗时更长。测量吞吐量可以同时捕捉这两种效应。

我们在仿真中检查了每个设计的输出。如果设计未通过检查或使用的面积超过原始核心的 16 倍，则得分为零。对于通过检查的设计，我们在对模型隐藏的工作负载上测量每时钟周期指令数。我们取这些工作负载的几何平均值，并将其乘以用 Yosys 估计的最大时钟频率，从而得到每秒指令数的估计值。对于每个核心，我们将相同约束下观察到的最佳吞吐量设为 1.0 分。图表显示了多次运行的平均得分，包括得分为零的运行。

在每次运行约 112,000 个 token 的可比预算下，GPT-6.2 Astra 在两个核心上均获得最高平均得分。GPT-6.1 Sol 在两个核心上也超过了 GPT-5.6 Sol。

在现有的 PicoRV32 核心上，GPT-6.2 Astra 在较大的可比预算下具有最高平均得分。在约 112,000 个 token 时，其得分约为 GPT-6 Astra 的两倍。

在现有的 Ibex 核心上，GPT-6.2 Astra 的平均得分在其达到的更高预算范围内持续攀升。GPT-6 Astra 和 GPT-6.1 Sol 则较为接近。

从规范出发设计 RISC-V 核心

对于第二个任务，我们给每个模型提供了书面需求和开源代码中的模板，展示核心如何与系统其余部分连接。模型自行选择数据如何流经核心以及如何将工作划分为各个阶段。对于每个核心，我们保持正确性检查、内存和缓存设置以及吞吐量目标与 RTL 优化任务中相同。

在每次运行约 112,000 个 token 时，所有五个模型在从书面需求设计核心时的得分都高于尝试改进现有设计时的得分。这一结论在 PicoRV32 和 Ibex 上均成立。GPT-6.2 Astra 在 Ibex 上的提升比在 PicoRV32 上更大。完整评估包括两项任务、两个核心和所有 token 预算下的 9,881 次评分运行。

从 PicoRV32 规范出发，GPT-6.2 Astra 在接近 112,000 个 token 时平均得分达到 0.7，并在接下来观察到的两个预算上得分更高。

在 Ibex 上，GPT-6.2 Astra 在从规范设计时，接近 112,000 个 token 的平均得分约为 0.75。在更大的共享预算下，其曲线保持在其他模型之上。

从书面需求出发，给了模型省略原始核心中某些功能的空间，例如性能计数器和附加指令。这些功能可能对测试工作负载上的吞吐量提升作用不大，这可以解释部分得分优势。要求包含这些功能、对电路面积设置更严格的限制以及在物理综合后检查时序，将使测试更能代表生产芯片设计。

下一步

我们已经证明，我们的模型可以在 RISC-V 评估中探索新的处理器架构，并在 Jalapeño 以及 AMD 下一代旗舰 GPU 和 CPU 等复杂生产设计之上贡献了全新的改进。为了将模型开发建立在可信的评估体系之上，并拓宽所解决的设计挑战范围，我们正在与 Synopsys 合作训练 GPT-Synopsys（在新窗口中打开）——这是一个新模型，能够像专家芯片设计师那样使用 Synopsys 电子设计自动化（EDA）工具。
