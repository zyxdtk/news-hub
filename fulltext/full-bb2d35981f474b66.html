摘要
事实性问答（QA）通常假设存在唯一的规范答案，这掩盖了大型语言模型（LLMs）是否保留了长尾事实的不同说法。为了填补这一空白，我们引入了 ElephantBench，这是一个闭卷知识探测基准，包含通过可审计的基于图的流水线生成的 1,094 个问题。该流水线从低曝光率的网络语料库中检索相关文档，识别自然发生的分歧，并将其转化为多说法的 QA 记录。每个答案都会与原始文档和权威的公共网络来源进行核对，然后由人工标注员进行审查。在 32 个模型中，即使是最强的模型也仅在 52.4% 的问题上恢复了两种说法，而在几乎所有剩余的问题上，它只召回了一种说法而忽略了另一种。扩大模型规模和推理时间的推理可以提高召回率，但无法消除这种不完整性。语料库分析进一步表明，曝光率不平衡有利于占主导地位的说法，而少数派说法的曝光率越高，召回的完整性就越高。这些发现确立了 ElephantBench 作为一个可复现的知识探测基准，用于诊断参数化记忆中的认知短视。更广泛地说，我们基于图的基准构建流水线提供了一种高效且可扩展的方法，可将长尾语料库转化为来源可追溯的知识探测基准，支持评估和提升下一代 LLMs 的认知严谨性。

引言
前沿的大型语言模型（LLMs）越来越倾向于对常见的事实性问题给出标准答案，这使得传统的问答（QA）任务的区分度变低 [39, 12, 14, 6]。为了解决这个问题，我们将目光转向知识长尾，其中低曝光率的事实对参数化记忆提出了更严峻的测试。为了大规模挖掘此类事实，我们颠倒了通常的数据选择过程，并在过滤后的剩余部分 D_low D_{\mathrm{low}} 中搜索具有挑战性的候选者 [13, 22, 42]。在这种情况下，相关证据通常分布在多个文档中，并且异构来源可能对同一底层事实报告不同的说法 [43]。
模型可能保留了占主导地位的说法而忽略了不太普遍的说法 [15]，表现出盲人摸象比喻所说明的认知短视（图 1）。
因此，我们的研究问题是：LLM 能否召回一个长尾事实，以及它能从其参数化记忆中多完整地恢复该事实的不同已验证说法？
现有的基准只解决了这个问题的一部分。长尾 QA 测试模型是否能召回罕见的事实，但通常假设只有一个标准答案 [17, 11, 47]，使得记忆的完整性未经测试。知识冲突基准检查分歧，但通常采用开卷设置：它们在推理时提供冲突的段落，并测试模型在所提供证据上的多跳推理能力 [37, 32, 27]。两者都没有直接提供一个闭卷测试，来检验 LLMs 的参数化记忆是否保留了一个长尾事实的不同已验证说法。
因此我们引入了 ElephantBench，一个从低曝光率网络语料库中挖掘出的包含 1,094 个问题的闭卷基准。每个条目都可追溯至其源文档，经过外部验证，并由人工审查。在没有源文档、检索或外部工具的情况下，模型必须从其参数化记忆中恢复不同的事实说法。
我们的贡献是：
•
参数化记忆的诊断探针。
我们的指标没有将模型性能 collapsing 为单一的准确率得分，而是分别诊断模型是否记得低曝光率事实，以及它是否召回了这些事实的所有已验证说法。
•
高效且可复用的知识探针构建流水线。
我们基于图的两阶段流水线使用知识点聚类和实体提取来缩小候选空间，然后利用 LLMs 识别支持和冲突边。这种设计降低了图构建的成本，并提供了一种可复用的方式，将任何低曝光率语料库转化为评估 LLMs 对长尾事实记忆的知识探针。
•
基于语料库的记忆完整性分析。
通过计算支持分歧每一方的文档数量，我们揭示了一个明显的曝光不对称性：对更普遍说法的曝光有助于模型召回事实，而对其不太普遍说法的曝光则更密切地与该记忆的完整性相关。这将语料库分布的可测量属性与记忆失败模式联系起来，使得探针能够为数据整理提供信息，而不仅仅是对模型进行排名。
2
相关工作
长尾知识评估与过滤数据回收。
长尾基准使用实体流行度 [17] 或语料库频率 [11] 来定义长尾。LPFQA [47] 和 MINTQA [9] 将评估扩展到专业论坛、近期知识和不太流行的事实。然而，这些基准通常对单一的标准答案进行评分，测试是否能召回罕见事实，而不是模型是否完整地召回了其不同的已验证说法。另外，WRAP [16] 重写原始文档，而 ReWire [22]、RePro [42] 和 SynPro [41] 回收过滤后的文档用于预训练。WRAP++ [46] 结合了跨文档关系，但仍然针对训练数据合成。相比之下，ElephantBench 从过滤后的剩余部分挖掘自然的跨来源分歧，并将其转化为关于不同说法是否在参数化记忆中共存的闭卷探针。
参数化记忆与检索证据中的知识冲突。
知识冲突基准在推理时提供证据，以研究涉及参数化知识、检索证据、错误信息或时间变化的冲突 [4, 37, 32, 40]。WikiContradict、ConfRAG 和 WhoQA 评估基于证据的检测或调和 [10, 43, 27]，而 DYNAMICQA 从维基百科编辑历史中推导出有争议的事实，以探查记忆内冲突和上下文适应 [18]。虽然这些基准使用开卷设置并主要测试阅读理解或在提供的上下文上进行多跳推理，但 ElephantBench 隐瞒了源文档，要求模型从参数化记忆中恢复不同的说法。
多答案问答与来源分歧。
AmbigQA 枚举不明确问题的合理解释 [19]，SituatedQA 根据时间或地点等上下文变量为答案设定条件 [45]，而 NATCONFQA 通过答案枚举和成对一致性分类来评估分歧 [21]。这些任务以查询歧义、上下文依赖或候选答案之间的关系为中心。在 ElephantBench 中，所有说法都涉及相同的主体-属性对，可追溯到自然发生的网络来源，并在推理时被隐瞒。这种设计测试了参数化记忆是否保留了不同的已验证说法，而没有将一种说法作为唯一的真实基准。

追踪大象
图 2 说明了 ElephantBench 如何将自然发生的来源分歧转化为受控的闭卷探针。该设计将两个问题分开：模型是否根本能够召回低曝光率事实，如果能，它是否能够恢复为该事实报告的所有已验证说法。
3.1
任务表述
令 D_all D_{\mathrm{all}} 表示一个网络语料库。给定一个质量分类器 Q Q（如 DCLM fastText [13]）和一个阈值 τ \tau，我们将语料库划分为
D_high \displaystyle D_{\mathrm{high}} =
{ z ∈ D all : Q ⁡ ( z ) ≥ τ } ,
\displaystyle={z\in D_{\mathrm{all}}:Q(z)\geq\tau},
(1)
D_low \displaystyle D_{\mathrm{low}} =
{ z ∈ D all : Q ⁡ ( z ) < τ } .
\displaystyle={z\in D_{\mathrm{all}}:Q(z)<\tau}.
D_high D_{\mathrm{high}} 包含被标准质量过滤保留的文档，而 D_low D_{\mathrm{low}} 包含被过滤器移除的文档。
通过使用 D_low D_{\mathrm{low}}，我们保留了包含被标准质量过滤移除的罕见事实的文档，使得 ElephantBench 成为参数化记忆的敏感探针。
专注于仅由少数网络文档支持的事实，使得低曝光率记忆失败更容易被检测到，因为这些事实不太可能在预训练期间通过有针对性的上采样获得额外的曝光。
除了模型是否根本保留了低曝光率知识之外，我们刻意寻找经过独立验证的来源报告了不兼容说法的跨文档案例。这些案例允许探针测试参数化记忆是否保留了条目中呈现的所有已验证说法，而不仅仅是一个。
因此，我们将 D_low D_{\mathrm{low}} 表示为一个文档图：支持边连接关于同一事实的文档，而冲突边识别针对同一主体-属性对的不兼容说法。
经过验证的冲突边随后被用作子图采样和问答（QA）对合成的种子。每个生成的 QA 对采用以下形式
x = ( q , 𝒜 ) , 𝒜 = { v i } i = 1 k ,
x=(q,\mathcal{A}),\qquad\mathcal{A}={v_{i}}{i=1}^{k},
(2)
其中 q q 是关于目标主体的问题，𝒜 \mathcal{A} 是相应的已验证答案集合（k ≥ 2 k\geq 2）。每个 v_i v{i} 必须可追溯至保留用于审计但对被评估模型隐藏的来源。
3.2
文档图构建
为了大规模构建此图，我们将 D_low D_{\mathrm{low}} 中的每个文档表示为一个节点：
G_D = ( V_D , E_sup , E_conf ) ,
G_{D}=(V_{D},E_{\mathrm{sup}},E_{\mathrm{conf}}),
(3)
其中 V_D V_{D} 是节点集，|V_D| = |D_low| |V_{D}|=|D_{\mathrm{low}}|，并且 T : V_D → D_low T:V_{D}\rightarrow D_{\mathrm{low}} 将每个节点映射到其完整文档。支持边 E_sup E_{\mathrm{sup}} 连接关于同一特定事实的文档，而冲突边 E_conf E_{\mathrm{conf}} 识别针对同一主体-属性对的不兼容说法。该图用作离线构建和审计结构：它将分散的证据汇集在一起，隔离分歧以进行问答生成，并且从不展示给被评估的模型。
检索候选对。
一种朴素的方法是使用 LLM 评判器检查 O ⁡ ( n 2 ) O(n^{2}) 个文档对，其中 n = |V_D| n=|V_{D}|。相反，我们使用轻量级的知识点和基于实体的检索来识别候选对，并仅验证这些候选对之间的关系。
首先，LLM 根据其文本 T ⁡ ( d ) T(d) 为每个节点 d d 分配一个知识点标签 K ⁡ ( d ) K(d)，遵循 SuperGPQA 分类法 [5]。然后，我们将分配给相同标签的节点配对：
𝒞_K = ⋃ k { { d_i , d_j } : d_i , d_j ∈ B_k , i < j } ,
\mathcal{C}{K}=\bigcup{k}{{d_{i},d_{j}}:d_{i},d_{j}\in B_{k},\ i<j},
(4)
其中 B_k = { d ∈ V_D : K ⁡ ( d ) = k } B_{k}={d\in V_{D}:K(d)=k} 是知识集群 k k 的文档集。这产生了 ∑ k ( |B_k| 2 ) \sum_{k}\binom{|B_{k}|}{2} 次集群内比较，而不是详尽地检查所有 ( |V_D| 2 ) \binom{|V_{D}|}{2} 个文档对。
然而，相关的文档可能被分配不同的知识点标签，从而落入不同的集群。为了解决这个问题，我们使用命名实体识别（NER）来检索共享规范化实体或事件提及的跨集群对。令 N ⁡ ( d ) N(d) 表示从 T ⁡ ( d ) T(d) 中提取的规范化实体和事件提及的集合。我们使用倒排索引实现此检索：
𝒞_N = { { d_i , d_j } : N ( d_i ) ∩ N ( d_j ) ≠ ∅ , K ( d_i ) ≠ K ( d_j ) } .
\mathcal{C}{N}={{d{i},d_{j}}:N(d_{i})\cap N(d_{j})\neq\emptyset,\;K(d_{i})\neq K(d_{j})}.
(5)
这两种机制生成候选对，而不是直接确定图边。它们的并集 𝒞 = 𝒞_K ∪ 𝒞_N \mathcal{C}=\mathcal{C}{K}\cup\mathcal{C}{N} 将关系分类限制为共享知识点标签或规范化实体提及的对，从而避免了对所有文档对的详尽比较。
诱导图边。
令 f_ζ f_{\zeta} 表示基于 LLM 的边分类器。给定候选对 { d_i , d_j } ∈ 𝒞 {d_{i},d_{j}}\in\mathcal{C} 的全文和单一分类提示 P P，它预测一个关系标签 r_ij r_{ij}：
r_ij = f_ζ ​ ( T ⁡ ( d_i ) , T ⁡ ( d_j ) , P ) ,
r_{ij}=f_{\zeta}!\left(T(d_{i}),T(d_{j}),P\right),
(6)
其中 r_ij ∈ { 𝚗𝚘𝚗𝚎 , 𝚜𝚞𝚙𝚙𝚘𝚛𝚝 , 𝚌𝚘𝚗𝚏𝚕𝚒𝚌𝚝 } r_{ij}\in{\mathtt{none},\mathtt{support},\mathtt{conflict}}。提示 P P 为所有三个标签提供指令和示例。none 标签表示文档没有讨论同一特定事实。support 表示它们讨论了相同的主体-属性对且其报告的说法一致，而 conflict 表示它们讨论了相同的对但报告了不兼容的说法。标记为 support 和 conflict 的对分别形成支持边集 E_sup E_{\mathrm{sup}} 和冲突边集 E_conf E_{\mathrm{conf}}。因为每个候选对只分类一次，图诱导只需要 |𝒞| |\mathcal{C}| 次边分类器调用。
3.3
问题生成与过滤
合成 QA 记录。
如图 2 所示，对于每个冲突边 e ∈ E_conf e\in E_{\mathrm{conf}}，我们提取一个以冲突为中心的局部子图 H_e = ( V_e , E_e ) H_{e}=(V_{e},E_{e})，包含两个端点及其支持邻居。生成的子图汇集了两种不兼容的说法以及支持每一方的文档。LLM 接收图结构和每个节点 d ∈ V_e d\in V_{e} 的全文 T ⁡ ( d ) T(d)，并生成一个 QA 记录，由问题 q_e q_{e} 和参考答案集 𝒜_e \mathcal{A}{e} 组成：
( q_e , 𝒜_e ) = f_θ ​ ( e , H_e , { T ⁡ ( d ) } d ∈ V_e ) .
\left(q{e},\mathcal{A}{e}\right)=f{\theta}!\left(e,H_{e},{T(d)}{d\in V{e}}\right).
(7)
生成的问题 q_e q_e 查询 e e 端点产生分歧的属性。随附的参考集 𝒜_e = { v_i } i = 1 k \mathcal{A}{e}={v{i}}{i=1}^{k} 列出了每个不同的已验证答案，每个答案都基于子图中文档的证据片段，如图 1 所示。我们生成两种匹配形式的 q_e q_e：一种明确陈述目标的命名实体问题，以及一种使用至少两个相关属性识别目标的线索对应问题。两种形式共享 𝒜_e \mathcal{A}{e}，允许它们的得分差异分离间接识别的影响。
生成后验证。
我们分三个阶段验证每个合成的记录。首先，LLM 阅读所有文档 d ∈ V_e d\in V_{e} 的全文，并验证每个 v_i ∈ 𝒜_e v_{i}\in\mathcal{A}{e} 都得到其中至少一个文档的明确支持。其次，配备 WebSearch 和 WebFetch 的网络代理独立搜索支持每个候选 QA 对中每个答案的公共证据。只有当双方都得到独立于种子文档的权威来源（如维基百科）的支持时，记录才会被保留。第三，人工审查员检查原始文档和检索到的证据，拒绝实体不匹配、不受支持的答案、答案泄露以及问题与事实不匹配的情况。未通过任何阶段的记录将被丢弃。
3.4
闭卷评估与评分
给定 x_e = ( q_e , 𝒜_e ) x{e}=(q_{e},\mathcal{A}{e})，目标模型仅接收 q_e q{e} 并产生 y_e = M ⁡ ( q_e ) y_{e}=M(q_{e})，不提供来源、图结构、参考答案或外部工具。这种闭卷设计将 ElephantBench 变成了参数化知识的探针：它测试模型是否记得低曝光率事实，以及它们是否能恢复与这些事实相关的所有已验证说法。
因为自由形式的响应可能以不同的方式表达相同的事实内容，我们使用 LLM 作为评判器进行语义评估。给定 ( q_e , 𝒜_e , y_e ) (q_{e},\mathcal{A}{e},y{e})，它分配三种结果之一： 当 y_e y_{e} 包含所有参考答案且没有错误答案时为完全召回； 当它包含至少一个但不是全部参考答案时为部分召回； 当它不包含参考答案或包含错误答案时为召回失败。令 N_C N_{C}、N_P N_{P} 和 N_F N_{F} 表示 N N 个响应中相应的计数。我们报告
C = N_C N , P = N_P N , F = N_F N .
C=\frac{N_{C}}{N},\qquad P=\frac{N_{P}}{N},\qquad F=\frac{N_{F}}{N}.
(8)
因此，C + P + F = 1 C+P+F=1。较高的 C C 表示更好的性能，而 P P 将不完整但无错误的召回与 F F 区分开来。为了在召回至少一个已验证答案的响应中分离出完整性，我们报告条件完整性 K K。较高的 K K 值表示更好的性能：
K = N_C N_C + N_P = C C + P .
K=\frac{N_{C}}{N_{C}+N_{P}}=\frac{C}{C+P}.
(9)

5
分析
5.1
影响模型性能的因素
由于特定于模型的预训练语料库通常未公开，我们从我们的低曝光率网络语料库中近似估计竞争说法的相对曝光率。预训练数据处理流水线通常对精选的高质量和特定领域数据进行上采样或以其他方式重新加权 [13, 38]，而低曝光率网络文档可能受到较少的有针对性重新加权。因此，我们使用该语料库中的相对说法频率作为观察代理，来分析来源曝光与模型性能之间的关联。
图 7

按来源曝光率划分的召回结果，按 N_maj − N_min N_{\mathrm{maj}}-N_{\mathrm{min}}（上）和 N_min N_{\mathrm{min}}（下）分箱。黄色片段中的数字报告部分召回 P P (%)。
具体而言，对于每次冲突，我们计算支持两种已验证说法的文档数量，并分别用 N_maj N_{\mathrm{maj}} 和 N_min N_{\mathrm{min}} 表示较大和较小的计数。
图 7 揭示了两种互补的模式。随着 N_maj − N_min N_{\mathrm{maj}}-N_{\mathrm{min}} 的增长，支持文档的计数变得更加不平衡，部分召回率通常会增加，表明模型更经常地只召回主导说法。相反，较大的 N_min N_{\mathrm{min}} 与较高的 C C 和较低的 P P 相关，这与当不太普遍的说法获得更大曝光率时召回更完整是一致的。
我们进一步使用附录 G 和表 4 中报告的联合回归来理清双方曝光的作用。估计揭示了明显的不对称性。对更频繁报告的说法的曝光每增加一个标准差，与 P P 增加 14.18 个百分点和 F F 下降 10.17 个百分点相关，表明多数方曝光主要跟踪模型是否根本记得该事实。相比之下，对不太频繁报告的说法的相同增加与 C C 增加 15.13 个百分点和 P P 下降 15.41 个百分点相关，表明少数方曝光更密切地跟踪是否召回了两种已验证说法。

6
结论
ElephantBench 揭示了被单答案事实 QA 隐藏的认知短视：即使是最强的模型也仅对略多于一半的问题召回了所有已验证说法。完全召回与对不太普遍说法的曝光更密切相关，而不是与事实的整体频率。扩大模型规模和增加推理时间的推理努力可以提高对长尾事实的召回，但两者都不能消除跨已验证说法的不完整召回。
通过在闭卷设置中将长尾事实与自然发生的来源分歧相结合，ElephantBench 区分了未能召回低曝光率事实与对其记录在案的说法召回不完整的情况。
局限性
我们的研究有三个主要局限性。首先，由于被评估的模型通常不披露其预训练语料库，我们依赖公开可用的预训练语料库来构建基准，并使用语料库级别的频率作为事实曝光的观察代理。其分布可能不同于用于训练任何特定模型的数据混合物和采样策略。因此，我们与曝光相关的发现应被解释为关联，而不是对特定模型训练数据的直接测量。其次，尽管基准包含跨越 22 个知识领域的 1,094 个问题，但它不能详尽地代表长尾知识的广度或来源可能产生分歧的各种方式。未来的工作可以扩大其规模和领域覆盖范围，同时纳入更广泛的分歧类型。第三，我们评估了跨开放权重和专有家族的 32 个代表性模型。因此，我们的评估不涵盖本研究之后发布的模型、每种可用的模型规模或每种推理配置。
伦理声明
每个保留的说法都独立得到权威公共网络证据的支持，但仍可能反映来源错误或错误信息。人工审查删除了不必要的个人信息、敏感属性、有害指控和令人反感的内容。附录 K 和 L 记录了发布和筛选程序。ElephantBench 仅用于事实知识研究和模型评估，而不是用于监视、分析、骚扰或其他有害用途。AI 助手被用于语言编辑和代码调试。作者验证了所有辅助材料，并对最终工作负责。

阅读完整文档并准确选择一个标签——所提供的 SuperGPQA 学科-领域-子领域层次结构中最具体的适用标签。以 JSON 格式返回这三个级别；不要仅凭导航和样板文件编造标签或进行分类。

比较两份完整文档。仅当它们涉及相同的实体、事件、方法或问题时，才标记为支持。仅当它们为同一主体的同一属性分配了不能同时无条件成立的值时，才标记为冲突。返回关系、主体、属性、值以及每一方的逐字证据片段。共享实体或宽泛的主题是不够的。
问题生成
给定一个候选冲突边、其局部子图和完整文档，生成一个既不泄露答案也不宣布冲突的问题。列出由逐字片段支持的每个不同说法。不要引入外部知识。返回包含问题、值、证据文档和证据片段的严格 JSON。
代理外部验证
分别搜索每个候选值，优先考虑维基百科和可靠的公共来源。验证打开的页面是否支持确切的主体-属性-值声明；拒绝实体冲突、循环转发以及仅从种子来源获得的支持。返回 URL、证据摘录、各方支持决定以及最终的保留/拒绝决定。如果任何一方缺乏独立支持，则拒绝该实例。
