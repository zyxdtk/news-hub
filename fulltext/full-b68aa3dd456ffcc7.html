学习使用工具：用于工具集成数学推理的强化学习

原标题：Learning to Use Tools: Reinforcement Learning for Tool-Integrated Mathematical Reasoning

中文摘要： 本文研究了在Countdown数学推理任务中，通过强化学习（RL）集成计算器工具以提升大型语言模型（LLM）性能的方法。研究构建了工具集成的SFT数据集，并应用了RLOO、RLOO++、GRPO和DAPO等在线RL方法。结果表明，工具集成显著减少了算术错误，而RL增加了正确推理轨迹的概率。其中，Tool-DAPO表现最佳，将pass@1从35.8%提升至66.0%。分析指出，RL在模型已能采样到正确轨迹时效果最佳，未来需结合更强的规划机制以解决零正确样本的难题。

摘要
当前的大型语言模型（LLM）越来越受益于外部工具的集成，尤其是在需要可靠计算和验证的任务中。受此启发，我们研究了计算器工具调用在改进 Countdown 任务数学推理方面的作用。我们首先分析了推理失败的原因，发现计算错误在错误回答中占了很大比例。然后，我们构建了监督微调数据集，以教会模型有用的工具使用模式以及如何解释返回的输出。在此工具格式化策略的基础上，我们应用了几种在线策略强化学习方法，包括 RLOO、RLOO++、GRPO 和 DAPO，并使用可自动验证的最终答案奖励。

为了实现更可靠的评估，我们构建了一个全新的 1024 题的 Countdown 留出基准测试，与训练数据没有完全重叠。我们的结果表明，计算器工具集成持续改进了 SFT 和 RL 基线，在 pass@k 上产生了大约 10 个百分点的提升。在 RL 方法中，Tool-DAPO 取得了最佳性能，将 pass@1 从 Tool-SFT 的 35.8% 提高到了 66.0%。进一步的分析表明，即使仅提供最终答案奖励，RL 也能鼓励更有效的工具使用。这些发现表明，工具集成减少了算术和验证错误，而 RL 增加了正确推理轨迹的概率。

1 引言
大型语言模型（LLM）在编程和数学推理方面的能力越来越强，尤其是在被提示或训练生成中间推理步骤时。然而，即使是面向推理的 LLM 仍然会犯算术和逻辑错误，特别是在需要精确数值计算的多步骤问题中。这种限制部分源于分词和自回归的下一词元预测，它们没有提供可靠计算或验证的显式机制。因此，集成外部工具已成为提高 LLM 在需要精确计算任务上可靠性的重要方向 (Schick et al., 2023; Yao et al., 2023)。

在这项工作中，我们研究了 Countdown 任务上的工具集成数学推理，在该任务中，模型必须使用算术运算组合一组给定数字以达到目标值，如图 1 所示。Countdown 是一个有用的测试平台，因为成功需要组合推理和精确算术，并且最终答案可以自动验证。在 LLM 数学推理过程中，如果它给出了正确答案，那么它将首先通过计算器验证，然后输出最终答案。如果数学推理出现算术错误，它将使用计算器进行纠正，并基于正确答案继续数学推理，防止模型偏离正确解。我们使用一系列无工具和工具集成的训练流程来研究这个问题。我们首先构建监督微调（SFT）基线，然后应用几种在线策略强化学习（RL）方法，包括 RLOO (Ahmadian et al., 2024)、RLOO++ (Hu, 2025)、GRPO (Shao et al., 2024) 和 DAPO (Yu et al., 2026)，使用来自 Countdown 验证器自动计算的奖励 (Ahmadian et al., 2024; Shao et al., 2024; Yu et al., 2026)。对于工具增强模型，展开可能包含由 <tool> ... </tool> 标签包围的计算器调用；环境执行表达式并在生成继续之前将结果作为 <obs> 观察插入。我们在原始的 50 题公开测试集和一个更大的全新 1024 题留出基准上评估所有方法，该基准旨在消除与训练数据的完全重叠。

我们的主要贡献是：
• 我们构建了一个工具集成的 Countdown 训练和评估流程，在模型展开期间进行实时计算器执行。
• 我们表明工具集成持续改进 SFT 和 RL 模型，并且 Tool-DAPO 在测试方法中取得了最佳性能。
• 我们分析了错误类别、工具调用动态和正确性分布，以解释 RL 和工具使用何时改进数学推理以及它们在何处仍然失败。

2 相关工作
除了监督微调之外，偏好优化和在线 RL 提供了序列级别的训练信号。最近的工作表明，强化学习可以大幅提高大型语言模型的推理能力。诸如 OpenAI o1 (OpenAI, 2024) 和 DeepSeek-R1 (Guo et al., 2025) 之类的模型表明，大规模 RL 可以鼓励长链推理。身份偏好优化（IPO）(Azar et al., 2023) 提供了 DPO 风格偏好学习的替代方案，而最近基于 REINFORCE 风格的方法（如 RLOO (Ahmadian et al., 2024)）通过避免学习评论家来简化在线策略优化。这些方法对于最终答案可以自动验证的推理任务特别相关。

工具增强推理也成为提高 LLM 可靠性的重要方向。早期的方法（如 ReAct (Yao et al., 2023)）将自然语言推理与外部操作交错。最近的工作（如 ReTool (Feng et al., 2025) 和 In-Context Reinforcement Learning for Tool Use (Ye et al., 2026)）开始通过强化学习训练工具调用。

最近的研究表明，具有可验证奖励的强化学习（RLVR）带来的增益可能更多源于概率重分配，而非推理覆盖范围的真正扩展。Yue 等人 Yue et al. (2025) 表明，经过 RLVR 训练的模型通常能提高 pass@1，但在较大的 pass@k 下却未能提高，甚至不如基座模型，这表明 RL 主要增加了基座模型分布中已存在的正确轨迹的采样概率。同样，Liu 等人 Liu et al. (2025) 认为，类似 R1-Zero 的训练强烈依赖于基座模型现有的探索能力和预训练引起的推理行为。总之，这些发现表明 RLVR 可以锐化模型现有的解决方案分布，但不一定创造大量新的推理能力。

3 方法
3.1 工具集成 SFT 数据集的构建
基础 Countdown 任务要求模型在 <answer> ... </answer> 标签内生成一个表达式。只有当表达式在语法上有效、准确使用了提供的数字并计算为目标值时，回答才会获得满分奖励；格式错误或不正确的表达式获得较低奖励。该验证器使该任务非常适合强化学习，因为可以在没有人工标签的情况下计算最终答案奖励。

对于工具设置，我们转换了提示和补全格式，以便模型可以在生成最终答案之前调用计算器。工具调用写为 <tool> 表达式 </tool>，环境返回一个观察，例如 <obs>= 44</obs>。在 SFT 期间，这种格式教会模型将可执行的算术检查放在何处以及如何根据返回的观察进行条件化。基于原始 SFT 数据，首先检测计算错误。然后将正确答案连同先前的推理上下文一起提供给 SFT 参考模型，并由 SFT 参考模型生成后续推理过程。然后将先前的推理和后续推理上下文连接在一起。在这两个推理上下文之间，以上述格式注入工具集成，构建用于 Tool-SFT 模型的工具集成数据。整个过程在算法 1 中给出。在 RL 期间，工具观察被视为环境输出而不是模型生成的词元，因此策略损失仅应用于轨迹中由模型控制的部分。

算法 1 工具集成 Countdown SFT 数据构建
1: 原始 SFT 数据 𝒟；训练好的 SFT 模型 π；每行样本数 K
2: 工具增强数据集 𝒟′
3: 阶段 A：构建纠正前缀
4: for 𝒟 中的每一行 (q, c) do
5: if 推理包含错误的算术步骤 then
6: prefix ← 直到该步骤的推理，并更正值
7: else if 最终答案错误 then
8: prefix ← 完整推理 + 标记它的计算器检查
9: end if
10: end for
11: 阶段 B：模型续写 (GPU)
12: for 每个 prefix do
13: 从 π 中采样 K 个完成推理和回答的续写
14: end for
15: 阶段 C：组装补全
16: for 𝒟 中的每一行 (q, c) do
17: 将工具指令添加到查询 q 中
18: if q 是错误行 then

22: else if 原始答案已经正确 then

24: else

26: end if
27: end for

29: train ← 所有行； test ← 小型留出监控集
30: return 𝒟′

这种设置让我们可以分开两个问题。Tool-SFT 测试单独的计算器使用演示是否会改进基线。Tool-RL 方法测试当唯一的优化信号是最终答案正确性时，在线 RL 是否能进一步提高工具调用的频率和有用性。

3.2 RLOO
RLOO (Ahmadian et al., 2024) 是一种基于 REINFORCE 的策略梯度估计器，它使用留一法基线来减少方差。对于每个提示 x，我们采样 k 个回答，并计算回答 y_i 的优势函数，作为其相对于其他 k-1 个回答平均奖励的奖励。在我们的实现中，为了提高效率，使用 vLLM 对轨迹进行采样，同时使用从 SFT 检查点初始化的可训练 HuggingFace 策略计算策略梯度更新。

总训练损失为
ℒ = -𝔼[w(y_i, x) A_i log π_θ(y_i ∣ x)] - β_ent ℋ(π_θ) + β_KL D_KL(π_θ ∥ π_ref),
其中 A_i 是留一法 RLOO 优势，w(y_i, x) 是截断的序列级重要性权重，π_θ 是可训练策略，π_ref 是冻结的 SFT 参考策略。我们将 RLOO 损失报告为策略梯度分量，并在训练期间单独跟踪熵和 KL 项。我们使用默认值 β_ent = 10^-3 和 β_KL = 10^-3。

3.3 RLOO++
RLOO++ (Hu, 2025) 保留了相同的留一法奖励基线，但改变了在策略更新前优势函数的缩放方式。我们没有直接使用原始的留一法优势，而是应用了全局优势归一化，减去批次均值并除以批次标准差，
A^norm_{q,o_t} = (A_{q,o_t} - mean(A ∣ A ∈ 𝒟_batch)) / (std(A ∣ A ∈ 𝒟_batch) + ε),
并将它们重新缩放至 0.3 的目标标准差。此修改旨在在奖励稀疏且许多采样组不包含正确回答或大部分是正确回答时稳定更新，因为跨整个批次 𝒟_batch 进行归一化而不是小的留一法组，即使组内奖励几乎均匀，也能保持分母稳定。

我们仅在工具集成设置中评估 RLOO++。

3.4 GRPO
组相对策略优化（GRPO）(Shao et al., 2024) 是一种策略梯度方法，它放弃了 PPO 中使用的价值模型，而是直接从组分数估计基线以减少内存和计算成本。对于每个提示 x，我们采样一组 G 个回答，并通过将回答 y_i 的奖励相对于组进行归一化来计算其优势函数：减去组均值并除以组标准差。由于采样的轨迹与行为策略对数概率相关联，我们应用词元级重要性加权，其中当前策略和行为策略之间的比率在对数空间中计算并截断以保持稳定性。

总训练损失为
ℒ = -𝔼[1/G ∑{i=1}^G 1/|y_i| ∑{t=1}^{|y_i|} min(ρ_{i,t} Â_{i,t}, clip(ρ_{i,t}, 1-ε, 1+ε) Â_{i,t})] + β_KL D_KL(π_θ ∥ π_ref),
其中 ρ_{i,t} = π_θ(y_{i,t} ∣ x, y_{i,<t}) / π_θ_old(y_{i,t} ∣ x, y_{i,<t}) 是截断的词元级重要性权重，Â_{i,t} 是分配给回答 y_i 所有词元的组归一化优势，π_θ 是可训练策略，π_ref 是冻结的 SFT 参考策略。与 PPO 不同，GRPO 将 KL 惩罚直接添加到损失中，而不是词元级奖励中。我们将截断代理报告为策略梯度分量，并在训练期间单独跟踪 KL 项。我们在工具集成训练中使用值 ε = 10^-3 和 β_KL = 0.01。

3.5 DAPO
Tool-DAPO (Yu et al., 2026) 主要通过两种方式修改策略更新。首先，它应用组归一化优势，因此在更新模型之前，在每个采样的提示组内对奖励进行归一化，即对于第 i 个回答，优势计算为
Â_{i,t} = (R_i - mean({R_i}{i=1}^G)) / std({R_i}{i=1}^G).
其次，它使用动态采样：在更新之前过滤掉采样回答全对或全错的提示组，因为它们提供的组内偏好信号很少，这对应于强制约束 0 < |{o_i ∣ is_equivalent(a, o_i)}| < G。在我们的运行中，60.7% 的生成提示组被过滤，增加了训练批次中信息组的密度。

Tool-DAPO 还使用非对称策略比率截断，下限和上限分别为 1-0.2 和 1+0.28。具体来说，策略通过词元级目标进行优化
𝒥_DAPO(θ) = 𝔼_{(q,a)∼𝒟, {o_i}{i=1}^G∼π_θ_old(⋅∣q)} [ 1/∑{i=1}^G |o_i| ∑{i=1}^G ∑{t=1}^{|o_i|} min(r_{i,t}(θ) Â_{i,t}, clip(r_{i,t}(θ), 1-ε_low, 1+ε_high) Â_{i,t}) ],
其中 r_{i,t}(θ) = π_θ(o_{i,t} ∣ q, o_{i,<t}) / π_θ_old(o_{i,t} ∣ q, o_{i,<t}) 且 (ε_low, ε_high) = (0.2, 0.28)。与 Tool-RLOO 相比，这给出了一个更受约束的更新规则，同时仍然允许策略增加高奖励工具使用轨迹的概率。

4 实验设置
我们在 Countdown 算术推理任务上进行评估。每个示例包含一个目标和三个或四个数字。只有当 <answer> ... </answer> 内的最终表达式在允许的算术运算下准确使用每个提供的数字一次并计算为目标值时，模型回答才是正确的。我们报告 pass@k，它是根据每个问题采样的 k 个回答计算的。

我们的主要比较是无工具 SFT、Tool-SFT、无工具 RLOO、Tool-RLOO、Tool-RLOO++、Tool-GRPO 和 Tool-DAPO。无工具模型直接生成推理轨迹和最终答案。允许工具模型在生成期间发出计算器调用，并在生成最终答案之前接收观察。除非另有说明，RLOO 和 Tool-RLOO 使用相同的 RL 超参数、批次大小、组大小、采样温度、熵系数和 KL 系数；主要区别在于展开期间是否启用了实时工具执行。

原始公开测试集仅包含 50 个示例，这使得 pass@k 估计有噪声。为了更可靠地量化工具集成对数学推理的影响，我们构建了一个额外的 1024 题的全新 Countdown 留出测试集。留出的问题在 (target, sorted(numbers)) 键下与训练数据没有完全重叠，使我们能够以比原始 50 题公开测试集低得多的统计不确定性评估同一任务分布中新问题上的性能。所有报告的置信区间都是问题实例上 95% 的自举区间。

5 结果
5.1 无工具 SFT 模型的评估
为了诊断 SFT 模型的失败模式，我们将不正确的回答分解为计算错误、目标/规划错误和其他最终答案有效性错误。计算错误是在整个推理轨迹上评估的，而目标/规划、数字使用和格式错误是从最终答案中识别的。这种区别允许我们将局部算术错误与推理和解决方案构建中更广泛的失败区分开来。

如图 2 所示，结果揭示了两种互补的失败模式。计算错误在两种难度级别下都频繁发生，这促使了使用外部算术工具或验证器。相比之下，目标/规划错误在 4 位数问题中变得更为常见，这表明更难的实例不仅需要更可靠的计算，还需要更强的目标感知规划。

图 2：按难度划分的 SFT 回答结果。条形图显示了 3 位数和 4 位数 Countdown 问题的回答百分比，按正确答案、计算错误、目标/规划错误、它们的重叠部分以及其他数字使用/格式错误进行分组。

5.2 工具集成
如图 3 所示，我们比较了无工具 SFT、工具增强 SFT、无工具 RLOO 和工具增强 RLOO 变体。误差线表示在问题实例上计算的 95% 自举置信区间。

右侧面板中的 50 题小测试集表现出宽且大部分重叠的置信区间，尤其是在较大的 k 时，使得细粒度比较变得困难。相比之下，左侧面板中较大的留出集提供了更清晰的比较。RLOO 在低 k 时比 SFT 基线有显著提高，在没有工具使用的情况下将 pass@1 从 26.4% 提高到 50.6%，在工具使用的情况下从 35.8% 提高到 56.6%。

图 3：Countdown 推理上的 Pass@k 比较。左图报告了我们 1024 题全新留出基准的结果，而右图报告了原始 50 题公开测试集的结果。

在高 k 时，RLOO 的增益变小，这可能是因为一旦模型可以从多次尝试中采样至少一条正确轨迹，pass@k 就接近饱和。因此，轨迹质量或采样概率的改进可能只会导致高 k 性能的微小变化。我们在 6.1 节中通过正确性分布分析重新审视了这种行为，这表明强化学习从已经包含一些正确采样回答的提示组中获益最多，因为这些组提供了有用的策略更新信号。相比之下，零正确样本的提示组仍然具有挑战性，因为它们几乎没有提供用于强化正确推理轨迹的直接信号。

工具集成改进了 SFT 和 RLOO 设置。在匹配的训练预算下，Tool-RLOO 将 pass@1 从 50.6% 提高到 56.6%，将 pass@16 从 66.6% 提高到 74.0%。将 Tool-RLOO 训练扩展到 200 步，性能进一步提高到 60.7% 的 pass@1 和 76.5% 的 pass@16，相当于比无工具 RLOO 提高了大约 10 个百分点的 pass@1。总之，这些结果提供了强有力的证据，表明 RLOO 在 SFT 基础上改进了可验证的数学推理，而工具增强的 RLOO 通过减少计算和验证错误带来了进一步的好处。

代表性的 RLOO 和 Tool-RLOO 回答记录在 A 节中供定性分析。

5.3 不同强化学习方法的比较
我们还在工具集成下比较了不同的强化学习方法，如图 4 和表 1 所示。Tool-RLOO 和 Tool-RLOO++ 都在 Tool-SFT 基线上大幅提高了 pass@1。然而，Tool-RLOO++ 并没有持续提高高 k 性能，甚至与 Tool-RLOO 相比降低了 pass@16，这与 Yue et al. (2025) 中的观察结果一致，即强化学习可能会提高低 k 性能，而不一定会扩大整体的 pass@k 覆盖范围。对于 Tool-GRPO，在 50 个样本的测试集上，它表现出比 Tool-SFT 模型更好的性能，如图 4 中更高的 pass@1 准确率所示，但在多次采样时表现较弱，这可能是由于小测试集的方差造成的。在 1024 个样本的测试集上进一步测试，Tool-GRPO 模型持续超过基线 Tool-SFT 模型，如图 4 所示。尽管 Tool-GRPO 表现出比其他 RL 算法相对较弱的性能，但它达到了首个最高的 pass@16 准确率。对这种行为应谨慎解释，因为 Tool-GRPO 仅训练了 30 步，随后偏离了 Tool-SFT 参考模型。虽然所有四种方法都为每个提示采样一组回答，因此当组内奖励均匀时产生消失的优势，但不稳定性仅限于 Tool-GRPO，因为它如何缩放和过滤这些组。Tool-GRPO 既保留了这些零梯度组，又除以不稳定的组内标准差，因此产生的噪声更新将策略推离 SFT 初始化，直到奖励和工具使用崩溃——这里大约在 30 步之后，而其他方法为 100 步。

图 4：工具集成下强化学习方法的比较。曲线显示了 Tool-SFT、Tool-RLOO、Tool-RLOO++ 和 Tool-DAPO 在 1024 题全新测试集和 50 题公开测试集上的 pass@k。

相比之下，Tool-DAPO 进一步提高了 RL 性能，比 Tool-RLOO 提高了 9.3 个百分点的 pass@1。Pass@16 也有所提高，这表明 DAPO 不仅增加了早期采样正确回答的概率，而且适度改善了更广泛的采样分布。这种改进可能与 DAPO 的动态采样策略有关，该策略在策略更新之前过滤掉零方差提示组。在我们的运行中，60.7% 的生成提示组被过滤，通过移除全对或全错组，大大增加了信息训练批次的密度。尽管这种过滤引入了额外的重采样开销，但 Tool-DAPO 在 100 步和 6.29 小时内达到了更高的 pass@1，而 200 步的扩展 Tool-RLOO 基线需要 16.15 小时，如 B 节中所述。

6 讨论
6.1 RL 在哪里改进
为了更好地理解强化学习在何处改进了模型行为，我们检查了训练检查点中每个提示 16 个采样回答中正确回答的分布。

如图 5 和图 6 所示，RL 主要增加了完全正确回答集附近的质量，这表明训练强化了已经包含正确推理轨迹的轨迹。相比之下，零正确回答的示例仍然具有挑战性：当模型在采样回答中未能产生任何正确的轨迹时，RL 对改进该示例的信号有限。

图 7 中的 Tool-DAPO 分布以较少的优化步骤增加了完全正确示例的比例。它还减少了零正确样本示例的比例，这是令人鼓舞的，因为这些示例代表了策略改进中最困难的情况。

6.2 强化学习鼓励工具使用
如图 8 所示，从 Tool-SFT 模型开始，Tool-RLOO 将每个采样展开的平均可执行工具调用从不到一次增加到每次展开大约一次，同时还提高了 Countdown 准确率。这表明强化学习不仅保留了 SFT 期间获得的工具使用行为；相反，当工具使用有利于解决任务时，它进一步鼓励了工具调用。

图 5：RLOO 训练期间的正确性分布。每条曲线显示了在 16 个采样回答中具有给定数量正确回答的示例比例。
图 6：Tool-RLOO 训练期间的正确性分布。工具增强模型显示出向高正确性示例的类似转变，随着训练的延长，进一步增加了大多数采样回答都正确的示例比例。
图 7：Tool-DAPO 训练期间的正确性分布。与基于 RLOO 的基线相比，Tool-DAPO 大大增加了 16 个采样回答中有 16 个正确的示例比例，同时更有效地减少了 16 个采样回答中有 0 个正确的示例比例。
图 8：Tool-RLOO 训练期间的工具使用和准确率动态。

7 结论
本项目表明，强化学习和计算器工具使用在 Countdown 数学推理中是互补的。RLOO 通过增加正确推理轨迹的概率在 SFT 基础上取得了显著改进，而工具集成通过减少算术和验证失败进一步改进了 SFT 和 RL。Tool-DAPO 在测试的 RL 变体中提供了最佳结果，这表明当许多提示组提供的有用策略梯度信号很少时，动态采样和截断更新可以使训练更高效。

该分析还指出了一个重要的局限性。当模型已经在一个组内采样到至少一条正确的轨迹时，RL 的帮助最大；零正确样本的提示仍然很困难，因为它们几乎没有提供积极的信号。因此，未来的工作应该将工具执行与更强的规划或搜索机制结合起来，以便模型能够发现困难提示的正确轨迹，而不是仅仅在它已经能够采样的轨迹中重新分配概率质量。
